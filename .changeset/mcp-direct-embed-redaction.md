Hide embed start URLs and their tickets from direct MCP tool results when they are nested in another URL, used as an object key, or sit beside a `ticket` field, including a ticket beside `_agentImages`, and in error messages, action links and image notes. Direct results are read as JSON before anything else, so a `toJSON` method or getter cannot add a start URL after the check. When anything a call produced holds a start URL, including a proxied tool's `_meta` or a URL an action's link builds, the call's text and `structuredContent` drop every `ticket` field and replace any whole string that echoes that ticket, raw or escaped, and `_meta` leaves out any entry that carries it other than the widget's embed start and source. A result the check cannot fully read, because it is not JSON data (such as one holding a BigInt) or holds a string escaped more deeply than the check reads, is withheld whole. A write, told by its effect rather than by whether it sends change events, still reports success and records its change, as it does when building its response fails after it ran, and its widget still gets any session it minted; a read fails, and a result its upstream already reported as an error stays an error. Error text from after the action ran is checked against the call's result, images are sent from the checked copy, leaving out one that carried a credential, and a `ticket` field is read in any escaping the check decodes. Shared MCP action calls hide echoed tickets the same way, and report an unreadable result as a `result`-stage failure. App-only tools such as `create_embed_session` now return their start URL in `_meta["agent-native/embedStart"]` instead of `structuredContent`, and the embed widget reads it from there.
