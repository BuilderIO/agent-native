Hide embed start URLs and their tickets from direct MCP tool results when they are nested in another URL, used as an object key, or sit beside a `ticket` field, including a ticket beside `_agentImages`, and in error messages, action links and image notes. Direct results are read as JSON before anything else, so a `toJSON` method or getter cannot add a start URL after the check. When anything a call produced holds a start URL, including a proxied tool's `_meta` or a URL an action's link builds, the call's text and `structuredContent` drop every `ticket` field and replace any whole string that echoes that ticket, raw or escaped, and `_meta` leaves out any entry that carries it other than the widget's embed start and source. A result the check cannot fully read, because it is not JSON data (such as one holding a BigInt) or holds a string escaped more deeply than the check reads, is withheld whole. A write, told by its effect rather than by whether it sends change events, still reports success and records its change, as it does when building its response fails after it ran, and its widget still gets any session it minted; a read fails. A widget write that produced nothing is still flagged `isError`, so the host mounts no empty widget, but it says its change was saved and records it. A proxied tool keeps the failure its upstream reported, read before anything else can fail, whether its flag is its own or inherited; a JSON copy or a directory projector cannot clear it. A write whose status cannot be read says so and still records its change. A failure after the action ran is described once, checked whole, its error code included, against everything the call had built by then, directory projections and links included. That one description goes to the response and, when the call is recorded as an error, to MCP analytics. One that cannot be checked becomes a fixed sentence, which for a result that is not JSON data says so, and only that is sent to error capture. An action's link is built from the result as the action returned it, and checked with the rest of the response. Images are checked against everything the call built, and one that carries a credential is left out whole. A `ticket` field is read in any escaping the check decodes. Shared MCP action calls hide echoed tickets the same way, and report an unreadable result as a `result`-stage failure. App-only tools such as `create_embed_session` now return their start URL in `_meta["agent-native/embedStart"]` instead of `structuredContent`, and the embed widget reads it from there.
