Hide embed start URLs and their tickets from direct MCP tool results when they are nested in another URL, used as an object key, or sit beside a `ticket` field, including a ticket beside `_agentImages`, and in error messages, action links and image notes. Direct results are read as JSON before anything else, so a `toJSON` method or getter cannot add a start URL after the check. When a direct result is not JSON data, such as one holding a BigInt, a read fails as before, and a write still reports success and records its change, with text saying its result is not shown. When anything a call produced holds a start URL, including a proxied tool's `_meta` or a URL an action's link builds, the call's text and `structuredContent` drop every `ticket` field and hide that ticket wherever it is echoed, and `_meta` leaves out any entry that carries it other than the widget's embed start and source. Shared MCP action calls hide echoed tickets the same way. App-only tools such as `create_embed_session` now return their start URL in `_meta["agent-native/embedStart"]` instead of `structuredContent`, and the embed widget reads it from there.
