Add live copies to `@agent-native/core/collab`: a collab document whose Yjs state is the only writable copy of a body, with its text derived from that state on every commit. `defineLiveCopy` declares, under a `name` that a later definition replaces (work the replaced or released binding started commits nothing unless its transaction was already committing), which documents are live copies, the bounded task runner that does their Yjs work, and an optional `persist` hook that writes the app's own rows in the same transaction; `persist` may return `{ derived: false, reason }` to leave them alone. `applyUpdate` commits client updates through it, and once a binding is defined the update route's ack carries `liveCopy` (`derived`, `not_derived` or `unchanged`) and `liveCopyReason`. `mutateLiveCopy` applies a named edit, retries on version conflicts, and can write the caller's own rows in the same transaction through its `persist` option. On a changed edit, an attempt a peer overtook stops before that persist runs, exactly so when the binding's `persist` takes a lock every commit of the document shares; for an edit that changes nothing, the persist runs first, so it can compare the exported `loadYDocVersion` with `change.version` and return without writing to have the edit redone. Live-copy commits also require the row's stored bytes, not only its version, to be the ones the edit read. `seedLiveCopy` seeds an absent or empty copy, and `readLiveCopy` tells absent, empty and malformed state apart; all three throw `not_live_copy` for a document the binding does not cover or a binding that was released or replaced; an update or edit that would empty the field is refused, so a seed never refills what a user deleted. These writers, and `applyUpdate` on a live copy, refuse to run inside a caller's transaction, whether opened with `getDbExec().transaction()` or Drizzle's `transaction()`, with `write_refused` / `caller_transaction`. Failures are a typed `LiveCopyError`; other collab write paths refuse live copies with `write_refused`, and `getDoc`, `getText` and `getJson` refuse them with `read_refused`.

A live copy's Yjs merge, derive, seed and edits run only in `createBoundedTaskRunner`: worker threads with a terminable deadline, a heap limit, input and output size limits, and a bounded queue. Where worker threads do not exist, runs fail with `unavailable` instead of running inline. Writes waiting on one live copy are bounded by the binding's `maxWaitingWrites` (default 16); past it a write fails with `build_failed` / `queue_full` instead of holding its payload. Readers of a row an instance has not cached share one runner task, so a burst of editors opening a page does not fill the runner's queue, and the row's derived text is cached with its bytes, so `readLiveCopy` of a cached row runs no task. The runner's module exports `defineLiveCopyTasks(...)` from `@agent-native/core/collab/live-copy-tasks`; import it as `./tasks.ts?bounded-task` to bundle it at build time. The Vite, server and `@agent-native/core/vitest-config` builds all resolve that import, so app tests load modules that use it.

Passing `onContentSync` to `createCollabPlugin` now throws at startup. The option was declared but never called; use a `liveCopy` binding to derive a document's text instead. `createCollabPlugin` takes that binding and maps live-copy failures to HTTP 409, 413, 422, 500 or 503. The state route answers 400 only for a `stateVector` that does not read as a Yjs state vector; other read failures keep their own status instead of being reported as a bad vector.
