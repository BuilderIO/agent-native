Draw Settings from the headless model. Toolkit's own part set gains `settings.nav`, `settings.nav-group` and `settings.nav-item`, which the shared Settings navigation now renders from a model of its pages and app sections, and `settings.group` and `settings.row` with toggle, link, action and info rows and a slot for custom controls. Model rows can carry an `anchor`, the DOM id settings search scrolls to. Rows can also name app content for a part's regions (`regions`: a settings row's `label`, `description`, `status` and `detail`), hide a group's label visually (`labelHidden`), and carry `label` or `count` badges, and `settings.content` places app content (a skeleton, an empty state, a notice) among a group's rows without changing its markup. `rowIdSegment` turns app data such as an email into a valid row id segment, and `combineFragments` lets a row built in one component join a group drawn by another. Toolkit's core settings pages (account, organization, integrations, models, infrastructure, usage, API keys, labs and audit) now draw from the model too, and `SettingsEmpty` and `ErrorRow` accept root attributes. Settings looks and behaves as before. SettingsPanel's collapsible sections draw from a new `settings.section` part, and Usage's load errors and groups from `settings.notice` and `settings.report`. Rows can mark a finished setup (`complete`), carry an `attention` badge, and declare the rows their slot hosts (`hosts`); a surface nested in a slot that does not host its rows throws `UndeclaredNestedSurfaceError`.
