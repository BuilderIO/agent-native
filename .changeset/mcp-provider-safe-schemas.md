Advertise MCP tool input schemas that pass the Anthropic, OpenAI and Gemini schema rules Core pins. A root `anyOf`, `oneOf` or `allOf` is flattened into one object, and the schema description lists the argument sets it combined. Hand-written JSON schemas get the same keyword stripping as Zod schemas. A typeless `const` or `enum` gets an explicit type taken from its values, so Codex no longer narrows `{ "const": 1 }` to a string. A string `const` is advertised as a one-value `enum`, which Gemini honors, and `maxItems` moves into the description, because Gemini refuses a forced call to a large bounded array. Over MCP every rewrite only widens what the schema accepts, boolean subschemas included. The in-app copy does too, except that it admits no array directly inside an array, because the in-app Gemini adapter drops `$ref`, so nothing there can recurse. Actions still validate calls against their own schema.

A schema reference that does not resolve, including one that names an inherited property such as `#/$defs/__proto__`, now fails with a named error instead of disappearing when its branch is flattened. References spelled as encoded pointers or `$anchor` names are rewritten to plain pointers first; an `$id` below the root, a non-local `$ref` and `$dynamicRef` are refused. In the in-app agent, an app action with such a reference throws. A remote MCP tool with one is held back when its server's tools are listed: the server stays connected with its other tools, and its integration status names the unusable tool and why. Reconnecting the server from Integrations lists its tools again over the same connection, so calls already running on it are not interrupted.
