Collab docs can open from a copy saved in the browser. `useCollaborativeDoc({ localCopy: { onEditsDisplaced } })` keeps each doc's acknowledged Yjs state in IndexedDB, per account, cleared on sign-out or account change and bounded by size. A doc opened again is ready from that copy at once (`fromLocalCopy`) and takes edits, which are sent once the server's diff shows its doc covers the copy; a copy the server's doc does not cover, or that an unreadable answer cannot vouch for, is thrown away and the doc reopens from the server. Typing on the copy that the server's state leaves out (the copy was thrown away, the server deleted the block it went into, or the doc is gone) is passed to `onEditsDisplaced` as the doc stood with it, so the app can keep it; it is never written back into the doc. None of that typing is sent, then or by the next open; a doc the server refuses or no longer has sends nothing until it is retried. A boot read is used only for the session it was made under, and is dropped when a sign-out or organization switch starts. `subscribeSessionInvalidation(listener)`, from `@agent-native/core/client/hooks`, calls `listener` when a sign-out or organization switch starts, in this tab or another, before the session is read again. `GET /_agent-native/collab/:docId/state?stateVector=` now also returns the server's state vector (older clients ignore it). `prefetchCollabState(docId)`, from the new `@agent-native/core/client/collab/prefetch` entry, starts that read at page boot.
