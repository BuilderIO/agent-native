Add `sessionReadIdentity()` and `sessionReadIdentityStatus()` to `use-session`, so a request can record whom it was sent as (the session read open when it left, and the transport it went out on) and be checked against the session the tab accepts before its answer is shown. A routine session re-check holds requests sent while it is out until it answers, and keeps what it already accepted shown unless it finds another account. The embed auth interceptor and the MCP host runtime announce a change of fetch transport (`FETCH_TRANSPORT_CHANGED_EVENT`), and the session is read again over the new one. The backend and demo-mode fetch wrappers pass the transport of the fetch underneath through, so an embed token change under them still reads as a new transport. A session answer taken from the shell's bootstrap read ages from when that read answered. A session read that hangs past the retry budget is abandoned without invalidating what is accepted, and the session keeps being read in the background, backing off, until the read it was waiting on answers.
