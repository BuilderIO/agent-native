A foreground data program in an org can now have a scheduled refresh. Saved with `scheduledRefresh: true`, the server reruns it with its default params every `refreshTtlMs` from the framework's once-a-minute recurring sweep, so the org's shared run is fresh before anyone opens a panel and no browser has to be open. The scheduled run is the org-shared run with all its rules: org credentials only, reads only, and served to a viewer only when their own run would read the same credentials. A run that isn't shareable is saved as a refusal and tried again a day later, never followed by a run with someone's own key. It runs as the program's owner, checked first the way automations check theirs; an owner who has left the org gets a failed `schedule_owner_invalid` run, checked again after `refreshTtlMs`. A run is refreshed three minutes before it would go stale, and a failed refresh is tried again five minutes later. A scheduled run gets only what's left of the sweep, so one that runs out of time is saved as `schedule_timed_out`, which doesn't hold back viewers' shared runs, and is tried again after `refreshTtlMs`. `get-data-program` now returns `scheduledRefresh` and an `orgSharedRun` summary with no rows or row count. The setting needs an org, `refreshMode: "ttl"` and a `refreshTtlMs` of at least 15 minutes, and background programs can't have it yet.
