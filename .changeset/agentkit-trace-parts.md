"@agent-native/toolkit": minor
---

AgentKit React exports Trace parts (`Trace`, `TraceLine`, `TraceIcon`, `TraceTitle`, `TraceDescription`, `TraceCollapsible`, `TraceCollapsibleTrigger`, `TraceCollapsibleContent`) and Code Block parts (`CodeBlock`, `CodeBlockHeader`, `CodeBlockTitle`, `CodeBlockActions`, `CodeBlockCopyButton`, `CodeBlockContent`, `CodeBlockLine`, `CodeBlockFooter`, `useHighlightedCode`) for building custom renderers that match the default transcript. Every default step row (the live working row, work groups, activities, work steps, reasoning, tasks, and agent messages) now renders through Trace, and failed agent messages use the amber warning triangle. Fenced code in replies is syntax highlighted and labeled by language name. Tool input and results are highlighted code blocks with a copy button, and a tool that runs code or a command shows that source instead of escaped JSON. A message's citations render as one "Used N sources" step. `StackTrace` and `parseStackTrace` show a V8 or Python stack in a tool result as an error title with the caller's frames first and framework frames folded. `Terminal` shows a shell command with its streaming output, exit code, and duration; coding-tool command calls render through it, and a failed command uses the amber warning color instead of red. The composer's context ring and its usage panel are AgentKit parts (`ContextUsageRing`, `ContextUsagePanel`) styled with AgentKit tokens; the `context-ui` names still work, segments take a CSS `color` as well as a `colorClass`, and the ring fill reads `--agent-kit-progress-color`. `FileChange` shows a file the agent edited or created: an edit's diff with +/− lines, or a new file highlighted with line numbers. Chat's Files changed summary and edit and write cells render through it, a long path keeps its file name visible, line counts come from the diff, and an unchanged line after an edit now shows as unchanged instead of removed and re-added. Diff colors read `--agent-kit-diff-added-color` and `--agent-kit-diff-removed-color`. Sending a message now holds it near the top of the transcript, with a sliver of the previous turn above it, while the reply streams in below; once the reply fills the view, the transcript follows it as before. Pass `anchorTurns={false}` to `AgentKitChat` to follow the bottom from the moment a message is sent. AgentKit now uses one radius scale set by element size instead of the theme's `--radius`: 4px for anything 24px tall or less (icon buttons, chips, inline code, menu items), 8px for 32px buttons, the user bubble, code blocks, cards and popovers, 12px for dialogs and large previews, and 16px for the composer, so nested corners stay concentric. The Send, Stop, voice and scroll-to-bottom buttons are rounded squares instead of circles, and chips are no longer pills. Hosts can override the steps with `--agent-kit-radius-xs`, `-sm`, `-md` and `-lg`. The composer's model menu is now just the models, More models and Effort: the model details card, the printed 1-9 numbers (the digit keys still pick a model and are announced to screen readers) and the Recommended badges are gone, and the menu uses the shared composer popover surface. Keyboard and screen-reader fixes: each message's actions are one tab stop with the arrow keys, Home and End moving inside (a `toolbar`), and a "Skip to message box" link comes before the transcript. Regenerate, Fork and the branch arrows stay focusable with `aria-busy` while they run, and the branch arrows use `aria-disabled` at either end. Scroll to bottom, Stop and Regenerate pressed from the keyboard hand focus to the composer instead of dropping it to the page. The status region now also announces a run that is waiting for approval or input and one that was stopped. The @ and / menus are a labeled listbox the editor points to with `aria-controls` and `aria-activedescendant`, so the highlighted row is announced. The pasted-text Remove is a real button beside the preview, and removing any attachment returns focus to the editor. The running shimmer sweeps between two readable text colors instead of fading toward the background, and with reduced motion it shows plain text. The @ menu translates a mention provider's section label through the app's catalog, so Chat, Analytics and Clips show "Conversations", "Dashboards" and "Recordings" instead of the raw `composerSources.group` key; a plain label still shows as written. More accessibility fixes: counts, pending steps, diff counts, menu headers and error text now reach 4.5:1 (hosts get `--agent-kit-danger-text`, since a theme's `--destructive` is sized as a fill), and composer load failures are amber instead of red. The focused composer border reaches 3:1. A failed agent chip is amber with a triangle and says "Failed" to screen readers, a rejected command shows a triangle, and the context caption shows one past 80%. A failed context chip's reason is read with the chip and shown in Retry's tooltip, approval menu hints are a second line, unavailable message actions stay focusable and show their reason, an open step shows its full title, and a queued message shows in full while its row has focus. Code, terminal and stack trace copy buttons show on touch screens, the transcript scrollbar shows on hover, and the inline disclosure row and a failed attachment's Remove have 24px targets. Copies are announced, a failure is announced once, step names are announced at most every 10 seconds, each turn has a hidden heading, code blocks and tables are named groups instead of landmarks, queued thumbnails are named, and each composer paragraph takes its own text direction. One visual system: AgentKit and composer borders use one hairline (`border-border`) instead of five strengths, with the composer the one deliberate exception. Composer, mode, queue and approval menus share the 8px popover surface with 4px items; the shared `ui/dropdown-menu` primitive is unchanged. Every chip (composer mentions, file and skill references, context chips, sent mentions, agent chips) is 20px tall with 4px corners and 12px text. Failures are amber with a triangle everywhere, including a run failure that cannot be retried, command and feedback errors, connection notices and the render-error card, which drops its tinted fill; red is kept for destructive choices. AgentKit's stylesheet reads the caption, supporting, density and new `--agent-kit-body-font-size` type tokens instead of raw sizes. Approval, connection and widget cards share one frame: hairline border, 8px corners, no shadow and 12px padding. Queued messages are 32px rows with 8px corners at an 8px inset, and the queue's unused component CSS is gone. Each delegated agent is one collapsible Subagent step instead of separate "delegated", "working", "sent a message" and "finished" rows mixed with other agents': the row names the agent, says whether it is working, finished, paused or needs attention, and shows its task, latest progress, how long it worked and why it failed. Inside are its own tool calls (which no longer disappear from the transcript), its messages and its reply. A delegated agent's task moves into its step, and an agent still marked working when its run ends shows as finished. `formatAgentInteractionDetail` on `AgentKitProvider` and `AgentKitRoot` supplies an interaction's detail text; Chat uses it for its localized delegation failure reasons instead of a custom failed-row renderer. The Agent tasks summary says "2 of 5 done" instead of a bare count, and a task's own progress reads the same way. `QuestionCard` shows the agent's questions above the composer in the composer's frame and type scale: a "Question 1/3" header, one-line numbered options with Recommended first, a written-response field that takes the composer's focus border, the composer's dictation mic beside it (`renderResponseControl`), and Skip and Next, then Send, which delivers every answer in one message. Number keys and arrows pick options, focus follows each step, and a required question cannot be skipped. Chat renders the agent's questions through it with the new `GuidedQuestionCard`, while `GuidedQuestionFlow` keeps its full-panel layout for Analytics and Slides; Chat now shows a question as soon as the agent asks it instead of after a reload or a window refocus. `VoiceButton` takes `showShortcut={false}` for a mic outside the composer, whose ⌘⇧M shortcut it does not own. `QuestionCard` also asks color questions (a swatch on each one-line option), slider questions (one row showing the value that will be sent, starting at the midpoint) and file questions (a "Choose files…" button, dropping onto the card, and 20px chips), and takes `submitLabel` and `skipLabel`. The /chat route now localizes every AgentKit string the sidebar chat does (agent, task, feedback, queue, usage and branch copy was English there in other locales); both share `agentKitChatLabels`. Activity and tool rows say Running, Failed or Stopped to screen readers, since their title is the step's name. An unavailable message action's reason is its accessible description, and pressing it opens the reason's tooltip on touch screens. A failed tool call inside a Subagent step keeps its row instead of showing only its error text.
