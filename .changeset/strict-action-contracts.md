"@agent-native/core": minor
---

Make action results a typed, enforced contract. An action that declares `outputSchema` now defaults to `outputErrorStrategy: "strict"`: a result that does not match fails with `ActionOutputContractError` (`errorCode: "output_contract_violation"`) instead of logging a warning and returning the unchecked value. Pass `outputErrorStrategy: "warn"` to keep the old behavior while you fix a schema. `defineAction` now infers the action's return type from `outputSchema`, and its `run` must return a value the schema accepts, so a drifting result is a compile error. `outputErrorStrategy: "fallback"` and `outputFallback` are deprecated, because a fallback hides a broken result behind a plausible one. New `defineActionErrors(...codes)` declares an action's closed set of error codes; its `fail` and `noWrite` accept only those codes, and passing it to `defineAction` as `errors` publishes them as `errorCodes` on the definition. The CLI sources are now type-checked under `strict`, which fixes `agent-native agents list --app` and `--capabilities` throwing a `ReferenceError`. The shared `tsconfig.base.json` and the scaffolded workspace base now turn on `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, and `noFallthroughCasesInSwitch`. An app that extends `@agent-native/core/tsconfig.base.json` gets them on upgrade; set any of them to `false` in the app's own `tsconfig.json` to keep compiling while you fix the errors they report.
