Scripts on the MCP script catalog can now call actions that change data, once an app turns on `AGENT_NATIVE_MCP_SCRIPT_WRITES`. An action opts in with `mcpScript: "write"` and an `mcpScriptWrite` contract in `defineAction`: an upper bound on the rows one call can change, the receipt it commits with its change, a `reconcile` function that says whether that receipt exists, and a `fence` function that closes the receipt's key unless the write already committed. Before a write runs, its rows are reserved against the script's budget (`AGENT_NATIVE_MCP_SCRIPT_WRITE_ROW_BUDGET`, 200 by default) and a row is written to a new script ledger; a write whose ledger row cannot be written does not run. Each write is then settled as committed, not applied, or unknown, and a recurring sweep settles the unclear ones from their receipts. From 2 minutes after a write starts (`AGENT_NATIVE_MCP_SCRIPT_WRITE_RECOVERY_MS`), the sweep fences a write that left no receipt, so it can never commit, and records it as not applied. Audit rows and change markers for committed writes are delivered through the ledger's outbox and retried until they land. A new `get-script-run` tool shows a run's writes and refused calls to the person who ran it, and to an admin of their organization without their arguments, and `run-script` is no longer marked read-only where writes are on.
