Every action core shares with all apps now decides its MCP exposure. Review comments, suggestions, version history, sharing reads, Creative Context, user groups, `upload-image`, `manage-automations`, `navigate` (in Dispatch too) and `view-screen` are served to outside agents with `mcpTool: "search"`: `tool-search` finds them and `call-tool` runs them, but they stay out of `tools/list`. Credential, account-connection, workspace-settings, staged-dataset, personal-preference and admin-review actions are `mcpTool: false`, and so is Dispatch's `view-screen`, which summarizes its run-debugging, vault and audit screens. It and the `view-screen`s of Calendar, Clips, Content and Forms now declare `readOnly: true`. Deleting someone else's review comment, deciding a suggestion or proposal, restoring a version, unsharing, Creative Context imports, purges, memberships and governance, archiving a context pack, and user-group writes now ask outside agents (MCP, HTTP, CLI, A2A and automation calls) for approval through `isOutsideAgentCall`, which `@agent-native/core/action` now re-exports. The app's UI and its own agent don't ask, though the agent calls those actions directly rather than from sandbox code or parallel batches. An action marked `"search"` stays listed where an app's `mcp.connectorCatalog` or `mcpApp.compactCatalog` already lists it.
