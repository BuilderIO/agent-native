MCP OAuth connections now report where people drop off. Serving the authorize page (the sign-in page or the consent page) sends `$mcp_oauth_authorize_opened` (with whether the visitor was already signed in), and serving the sign-in page also sends `$mcp_oauth_login_wall_shown`. Silent `prompt=none` checks, requests answered with an error or redirect, and the deploy's setup-required page serve no sign-in or consent page and are not counted. Both events carry the connecting client's name, the redirect host, `$mcp_oauth_route` (`directory` or `mcp`) and the same app label as `agent_connected`, so a client's starts and finished connections can be compared. `$mcp_vendor_client` comes from a known redirect host when there is one (`chatgpt.com`, `openai.com`, `claude.ai` and their subdomains, never a substring) and `$mcp_vendor_verified` is `true`; otherwise it falls back to the client's own name, which the client chooses, and `$mcp_vendor_verified` is `false`. The events never include PKCE values, state, client ids or the redirect path. Measurement only: the authorize flow behaves exactly as before, and a tracking failure is logged instead of failing the sign-in.
