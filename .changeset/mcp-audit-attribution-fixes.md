Keep MCP audit rows and attribute them correctly. A NUL or other control character in an MCP client's self-reported name or version, or a NUL in any other audit value, is now stored as U+FFFD instead of failing the insert and losing the row, and a failed audit write is logged and reported through `captureError` while the audited action still completes. Writes made through `/_agent-native/actions/<action>` with a verified MCP OAuth or connect token now record as `mcp` by the agent, with the credential's OAuth client id, even when the request also sends the frontend header. An approved A2A tool call that runs after its pause now records the paused task's run, thread, turn and network ids. The audit-log event details show the self-reported client, the OAuth client and the approval, with `mcp-client-accepted` labeled as unverified.

Breaking: the signatures of `recordActionAudit` and `recordOrgAdminAuditEvent` changed. Both now require an `attribution`, made only by `auditAttribution(ctx)` inside an action or `routeAuditAttribution(event)` in a Nitro route, and a call without one throws `AuditAttributionError` instead of losing its row. To migrate, move `caller`, `threadId`, `turnId` and `runId` out of `ctx` (which keeps only `actionName`, `userEmail` and `orgId`) and pass `attribution: auditAttribution(ctx)` with the action's run context, or `attribution: routeAuditAttribution(event)` from a route. Admin changes recorded by hand, such as Restrict personal API keys and the service provider choice, now keep the MCP client, OAuth client and approval instead of storing nulls.

An A2A call approved on its review page now records `approval: "a2a-review"`, shown as "Approved on the agent action review page", instead of the agent-chat label. Its replay runs outside the paused task's journal again, so an earlier identical call in that task cannot stand in for it; the task ids reach only its audit row. The approval pause's denied row now carries the run id.
