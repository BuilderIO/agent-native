A tab opening a shared document no longer deletes another tab's unsaved text. When an editor using `useCollabReconcile` sets the new `discoverCollabPeers` and `flushCollabUpdates` options (with `requestCollabSync`) and opens onto a live document that differs from the stored body, it learns who else is open, records their reports, and then catches up with the server, catching up again whenever a report changes meanwhile. It keeps the document if a collaborator reported holding the stored revision or a newer one. Each such client reports its revision in awareness as `reconciledRevision`, but only after the server has every update behind it. Without a report, or without the options, the editor applies the stored body as before. From the moment it seeds until the document holds the stored body, kept on such a report or applied, the editor is read-only, reports no update to save and returns `isJoinPending()` as true, which a host calls before saving the document by any other path. If it cannot learn who else is open, or the stored body has not reached the document 20 seconds after it learned, it stays that way, leaves the document as it is and returns `joinEvidenceFailed: true` with a `retryJoinEvidence()` to try again; the failure clears, and the stored body becomes the editor's base, once the document and the stored body match. A waiting editor checks again when a collaborator's report changes, so it finishes once the lead merges the stored body into a document that also holds unsaved text. Until the document holds a stored body, the editor applies the newest one instead of merging against the one it opened on, ignores older snapshots, and fails the join, instead of reporting the body as held, when a plugin refuses the transaction that applies it. `reconcileDocAgainstBase` likewise returns `failed` when a plugin refuses its transaction. `useCollaborativeDoc` gains `discoverPeers()`: one presence request that resolves `ready`, `failed` (including an unreadable answer) or `unavailable`, and that runs even in a hidden tab. A presence poll whose answer has no list of states now fails instead of reading as an empty list, which removed every collaborator the client knew.
