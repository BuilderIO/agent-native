Resource uploads and workspace file appends no longer write over another save. `POST /_agent-native/resources/upload` used to replace whatever was at the path; now an upload onto a taken name is stored under the next free one (`notes.md` becomes `notes-2.md`), and the response is the resource it made, with its `revision` for text files. Resending a text file that's already there unchanged, at its own path or at the numbered name it was given, counts as done (200, that resource). In an organization, a shared file from before organizations at the path counts as taken. Free names also skip the names that shared files from before organizations hold, counting only the ones the organization can see. When no name comes free the upload is refused with `name_taken` and a suggested name, and `useUploadResource` now throws the server's message, `errorCode` and `details` instead of only the status. The workspace files `append` adds its text onto the version it read and writes only if nothing changed since, reading again when another save landed first, so two appends at once both land; an append onto an organization file from before organizations that changed meanwhile takes its write back and starts over, and after five tries it fails with nothing appended.
