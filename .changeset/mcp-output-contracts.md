Add opt-in MCP output contracts. An action with `outputErrorStrategy: "strict"` and `mcpOutputSchema: true` advertises its `outputSchema` to MCP clients in the shape they receive (array roots wrapped as `{ items }`, open-link fields for linked actions, embed credentials removed, and embed start URLs masked in place as `"[hidden embed URL]"`), and each `structuredContent`, including its formats, is validated against it. Schemas whose constraints redaction or the open-link fields could break are refused when the action is defined. Actions without the opt-in advertise no output schema, as before. A strict output mismatch, an output validator that throws, or a contracted result that cannot be serialized now raises `ActionOutputContractError` (`errorCode: "output_contract_violation"`). A connection request or stop signal raised while a result is checked stays that signal under any output strategy, but with a framework message that never includes returned values. Both carry `effect: "none"` for read-only calls and `effect: "committed"` for writes that already applied, classified from the call's validated arguments, and a nested call's failure is reported as committed when the write that called it already ran. Committed failures still refresh other sessions over MCP, HTTP, and the in-app agent, and the in-app agent reports them as completed side effects instead of unknown outcomes.
