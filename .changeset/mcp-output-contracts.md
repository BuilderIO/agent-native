Add opt-in MCP output contracts. An action with `outputErrorStrategy: "strict"` and `mcpOutputSchema: true` advertises its `outputSchema` to MCP clients in the shape they receive (array roots wrapped as `{ items }`, open-link fields for linked actions, embed credentials removed, and embed start URLs masked in place as `"[hidden embed URL]"`), and each `structuredContent`, including its formats, is validated against it. Schemas whose constraints redaction or the open-link fields could break are refused when the action is defined. Actions without the opt-in advertise no output schema, as before. A strict output mismatch, an output validator that throws, or a contracted result that cannot be serialized now raises `ActionOutputContractError` (`errorCode: "output_contract_violation"`). A connection request or stop signal raised while a result is checked stays that signal under any output strategy, but with a framework message that never includes returned values. Both carry `effect: "committed"` once a write entered its handler, in the call or in one nested in it (even under a read-only action), and `effect: "none"` otherwise; writes are classified from the call's validated arguments. Committed failures still refresh other sessions over MCP, HTTP, and the in-app agent. The in-app agent reports them as completed side effects, keeps them in the replay journal so a continued turn replays the failure instead of running the write again, and the single-tool result used by A2A carries `completedSideEffect` on failures too. A connection request raised this way keeps its provider, reason, app, and source in its fields, its message, and HTTP `details`. The in-app agent, the plan-mode action registry, HTTP action routes, and MCP now prepare each call once, validating its arguments and classifying it, and run exactly that preparation through `runPreparedActionCall`, which accepts only a call `actionCallIntent` prepared: approval, plan mode, the unknown-write block, parallel batching, read caching, replay, and the action itself all see the validated arguments, defaults applied, without parsing them again. Preparation stops with the run's abort signal and the tool's deadline. A call whose arguments are invalid fails before any gate, never reaches its handler, and is still audited and tracked, discovered actions included. `needsApproval` now receives the validated arguments, in the in-app agent and over MCP, and an approval binds to an exact, type-tagged encoding of them (a Date by its time): the approval card still shows the call as the model sent it, but a pending approval stores an `arguments_hash` (a new nullable column on `agent_tool_approvals`), so one recorded before this release is asked for again, and the `approval_required` event carries `argumentsHash` for transports that echo the approval key back. A call that needs approval with a value that has no exact encoding, such as a `Map` or a class instance, is refused instead. Each `tool_done` now carries the `argumentsHash` its call ran with, and a continued turn replays a call only when it recorded a committed effect for that same hash; ordinary reads, and calls recorded before this release, run again. A read is held back only when its own run recorded an unknown outcome, and cached reads are dropped after any committed or unknown effect. Post-turn autosave (`onAgentTurnComplete`) also runs after a call that failed once its changes were saved.
