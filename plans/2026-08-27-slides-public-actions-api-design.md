# Slides Public Actions API Design

## Approved scope

Expose the selected Slides actions through the existing `/_agent-native/actions/<action-id>` HTTP router, strengthen the external action contract, and preserve the existing agent/MCP behavior. No UI, webhooks, share links, token minting, or permission model changes are included.

## Export artifacts

`export-pptx` and `export-html` write generated bytes through the framework private-blob provider and return exactly:

```ts
{ downloadUrl: string; filename: string; expiresAt: string }
```

A single named TTL constant controls both the short-lived token and `expiresAt`; the latter is authoritative for callers. The generated URL targets a narrow public binary-download route. It validates a resource-bound short-lived token, reads the opaque private blob, and uses attachment/no-store/nosniff response headers. This is the sole action-API exception because authenticated JSON action routes cannot serve a plain unauthenticated binary download. Consumers must fetch the binary promptly and must not forward the download URL to people.

Export records contain opaque blob handles and expiry metadata in SQL. On a subsequent export or download request, expired artifacts are collected: the blob is deleted before its row. If deletion fails, the row remains so a later request can retry; failures never appear as successful cleanup.

## Deck URL contract

Every deck-returning response in `create-deck`, `get-deck`, `duplicate-deck`, `save-deck`, and non-light `list-decks` items adds `appUrl`, derived from the server-aware canonical Slides base URL. `appUrl` is the canonical URL to give a signed-in human. Existing `url` and `deepLink` fields remain legacy-compatible and are not renamed or removed. Integrators should map human-open links to `appUrl`.

## List polling contract

`list-decks` preserves its current full-list `{ count, decks }` return exactly when no new parameters are passed. When `updatedSince`, `limit`, or `cursor` is supplied, it filters to `updatedAt` strictly greater than `updatedSince`, uses a stable `updatedAt` + `id` order, limits at the database boundary, and returns an opaque `nextCursor` only when another result exists.

## HTTP parity and validation

`create-deck` and `add-slide` switch only from `http: false` to the standard POST action projection. Schemas, generated IDs, and agent/MCP behavior remain unchanged. Duplicate title accepts `null` as omitted. Deck title errors state that callers must provide a descriptive, human-readable title and that slug-like titles are rejected.

## Verification

Focused Slides action tests cover artifact persistence/download/expiry cleanup, action exposure, return shapes, app URLs, legacy list behavior, list cursors, and nullable duplicate titles. The template typecheck and relevant Slides test suite validate integration. Documentation records the versioned public contract, TTL behavior, legacy link status, and the binary-route exception.
