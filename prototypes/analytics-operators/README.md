# Analytics operators

New Analytics surfaces from the operators plan (`docs/plans/2026-10-13-analytics-operators`), drawn on the shipped Analytics shell for sign-off before they're built.

Artifact: https://claude.ai/artifact/Pcc3JnQmk4KVrAXi1tP5nf

The review strip's Screen menu groups its screens by flow. Each group lists the flow's starting screen and the states clicking can't reach quickly; every other state is a click away from those.

- Dashboards: **Product Overview** and **Insert between rows** (PR 1.9). The header reads Add (secondary, with Chart…, SQL query… and Section), the Share split button in the primary fill (Share and a joined copy link button), ⋯, and the agent toggle, all at the compact 32px size. Hovering or focusing a gap between dashboard rows shows an insert bar that opens the same menu and inserts there. Views live in the filter bar as its first control, a View picker that reads "· Edited" with Save and Reset when the filters change. Share opens People and Agents tabs at the compact panel density every app's share panel moves to (a 320px popover, 24px controls, 12px text, 28px rows); People has no Share link row, since the split button's link segment copies it. Agents copies an agent prompt or opens the dashboard in Claude, Claude Code or Codex. The ⋯ menu is text-only in three groups, and Dashboard history starts with Created and Updated.
- Tables and charts: **Column menu**, **The agent adds a filter**, and **Resize and reorder columns** (PR 1.1). A table panel's column header menu has Sort, Format (Number, Currency, Percent, plus Change on a change column), Decimal places (0 to 3), Hide column, Add as filter, and Show hidden columns. Add as filter opens the agent with the request written and the column attached; once sent, the agent adds the filter, rewrites the panel SQL, and shows its changes with Undo. Drag a header edge to resize, or drag a header to reorder.
- Tables and charts: **Edit a chart** (PR 1.2). Edit chart on a line, area, or bar panel turns its header into a title field and Done, with a toolbar for chart type, series colors, and the Y axis format (Number, Currency, Percent, and Decimal places).
- Notebooks: **Notebooks**, **Signup drop-off**, **The agent adds cells**, and **Published app**, with Ask: **Open as notebook** (Phase 7). Notebooks have their own sidebar section and list page. A saved analysis becomes ordered input, SQL, chart, and text cells. A SQL cell can read an earlier cell's result. The agent's cell edits come with a change summary and Undo, an Ask answer opens as a notebook, and Publish as app in the notebook's ⋯ menu turns input cells into filters on a read-only page. Re-run is the one header button, at the dashboard header's compact size.
- Notebooks: **Review the agent's edits**, **Pivot cell**, **Map cell**, and **SQL typeahead and schema** (8.4). Clicking a chart bar opens a text-only menu: Filter to and Exclude add a Filter cell below, Drill into adds a chart cell broken down by another column, Top N keeps the top bars with the rest as Other, and Ask the agent about this point attaches the point to the composer; the agent's breakdown lands as a cell with Undo. Every drilled cell links back to its parent. A result with number columns has Top N and Calculation, a formula field with typeahead and a live preview. Add a cell offers SQL, Python (later, pending a security sign-off), Chart, Pivot, Filter, Map, Text and Input. Filter, Pivot and Map cells are built from pickers, read an earlier cell, and show their generated SQL; the pivot has subtotals per group, collapsible groups and a grand total, and the map shades countries, US states or points (drawn here as an equal-area tile grid). Each cell shows what it reads, including the inputs its SQL uses; changing an input or a cell reruns only what depends on it, and the cells below say what they are waiting for. Graph view in the ⋯ menu floats a non-modal graph of the cells. When the agent edits cells, each one shows its diff with Undo and Keep, a bar offers Keep all, and Notebook history lists the version each agent thread saved before its first edit. The SQL editor completes cells, tables, columns and `{{inputs}}`, shows cell references as chips, runs with ⌘↵, shows row count and time, and opens a searchable schema beside the editor. Schedule… in the ⋯ menu sets the day, time, time zone, recipients and whether to notify on every run or only on a change, and the header shows the schedule. A published app has a small composer that answers from the app's own cells and names the cell it used.
- Funnels and alerts: **Activation funnel**, **Conversion alert**, and **Event alert in Settings** (Phase 4). The funnel draws every step in one color with the amber drop-off and the conversion between steps, and each step opens the matching replays in Sessions. The retention panel is a weekly cohort grid. The bell on a conversion line sets an alert on that step-to-step conversion rate, with live freshness and a preview of when it would have fired over the last 7 days. The plain event alert stays in Settings.
- Investigations: **Alert fires**, **Watch the run**, **Evidence notebook**, and **Why did this change?** (Phase 8, bet A: 8.1, with a bet B preview from 8.2). The conversion alert dialog has Investigate when it fires. When the Activation funnel alert fires, a toast, a notifications bell in the header (the toolkit `NotificationsBell`, new in Analytics) and the alert's conversion line read "Investigating…" with live progress. Watch opens the run in the agent sidebar: the plan (7 checks within 5 minutes and $0.50), then each check with what it read and what it found, and Stop. The result is an evidence notebook with a plain-language answer and a confidence label, five numbered findings with their evidence line and query (segment breakdown, the matching release and timeline, the error spike, five replay cards that open Sessions filtered to them, affected accounts with MRR), What I could not check, and Next steps. Next steps open the agent with the request written; the results come back as drafts (Mail drafts, a Jira issue that is created only after a confirm dialog, a Slides deck). Notebooks lists Investigations first with their status (Investigating…, Complete, Partial). Why did this change?… in a metric or chart panel's menu opens a small dialog (the change it read, Compare, Budget) and starts the same investigation for that panel.
- Design apps: **Pick outputs**, **The draft in Design**, **Published**, and **The dashboard shows the app** (Phase 8, 8.3a to 8.3d). Make an app in Design… in the dashboard and notebook ⋯ menus opens a dialog that lists the query cells with an output name for each (checked by default, validated as you type, up to 12) and an optional What should it do?. The agent names the outputs, asks Design to build the app, and ends with an App draft in Design card. The draft opens in an illustrative Design frame: the generated app's screens (Overview, Accounts, Account detail) with live numbers, Data from Analytics listing the bound outputs, and Publish. Publish asks for a Builder account first, then takes an app name and id, reports Publishing started with the branch, and the top bar turns to Published with the link and who can open it. Back in Analytics, the header shows the app by name and each bound panel carries a small marker.
- Dashboard filters: **Dashboard filters**, **Applies to**, and **A new dashboard's date filter** (user feedback on dashboard filters). Filters become dashboard objects: Add filter picks a type (Date, Category or list, Number, Text) and a field by meaning, and one compiler turns each type into SQL per source, so panel queries carry no `{{variables}}`. The date filter has presets and a Custom pane with Last N hours to years, Current and Previous periods, Between, Since and All time. A non-modal filter window shows Applies to (mapped automatically, a column pick where several match, and the panels it can't filter with the reason), the Default that views override, and the read-only Definition. A panel's SQL editor shows the filters it inherits as chips and a Compiled SQL toggle. A legacy dashboard offers Convert…, which the agent does as one change with Undo and a SQL diff; the View picker keeps working on the new filters.
- Investigations: **No change found** and **Approve the HubSpot update**; Ask: **Next-step chips** and **Chips in the agent sidebar**; Slack: **Thread reply** (Phase 8: 8.1d, 8.1g, 8.2a, 8.2c). A seeded past investigation in Notebooks, Why weekly active users dropped, found no change: the answer carries "No change found" in place of a confidence label, then the weekly change against its 12-week range and the -5% alert line, the segments that all fell by the same amount, the checks that ran and found nothing, What I could not check, and Adjust the alert…, which comes back as an alert change to apply. An Ask answer and an agent sidebar answer that found something actionable end in two or three small next-step chips; a chip writes its request into the composer, and sending it plays the run and returns the draft, the replays or the new alert. Update CRM fields… in the notebook's Next steps drafts 8 HubSpot updates with before and after; Apply in HubSpot… asks the agent, the chat shows the toolkit approval card listing every company and value, and Approve applies them and reads them back, while Deny leaves the draft. The Slack screen is an illustration of the thread an investigation was asked in: the question, the Investigating… reply with its link, and the finished answer with its confidence and Open notebook.

Below 768px the shell follows the shipped `MobileNav`: a 44px bar with the menu button, the brand and New chat on Ask; the sidebar opens in a 280px left sheet, and the agent sidebar opens as an overlay at 85% of the width over a backdrop. The page header stays as a compact row under the bar (the shipped header hides there), with its actions wrapping under a long title.

Every edit, by hand or by the agent, shows the same Saved toast with Undo and joins the dashboard's or notebook's undo stack (⌘Z). Controls the shipped code doesn't have carry a New badge, in the controls themselves or in their tooltips and menus.

The sidebar draws 1.8's section pattern: each section header (Ask, Dashboards, Notebooks) holds the filter, a "+" for New chat, New dashboard or New notebook, and the collapse chevron, and a long list ends in one "Show N more" row. The alpha badge sits beside the brand, as `EnvironmentBadge` draws it.

The shell (sidebar, header, Ask, dashboards, agent sidebar, menus, dialogs, Settings) is copied from `prototypes/analytics` without its Data Sources page. Sessions is drawn only as the replay list a funnel step opens.

```bash
node prototypes/kit/build.ts analytics-operators
```

Open `dist/index.html?screen=<id>` to land on a screen directly, for example `?screen=alert`, `?screen=notebooks`, `?screen=inv-notebook`, `?screen=dapp-design` or `?screen=ff-applies`.

## Testing with new users

`node prototypes/kit/build.ts analytics-operators --test` builds `dist/test.html` from the same source, for usability sessions. It has no review strip, no New badges and no illustration labels, follows the system theme, and opens on Product Overview with the Dashboard conversion dropped alert already investigated in the bell. State lives in memory, so a reload starts the next tester over. Publish it as its own artifact. [test-tasks.md](test-tasks.md) is the moderator's sheet: ten tasks to read aloud, each with what done looks like and the click path.
