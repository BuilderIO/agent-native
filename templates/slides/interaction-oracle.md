# Google Slides interaction oracle

Measured in a live Google Slides desktop-web tab on 2026-10-07 (scratch deck, two
sessions: selection/drag/snap and text-box fitting). Every entry below is MEASURED
unless marked otherwise. This is a reference ledger for `interaction-parity.md`
and the editor implementation, not a tutorial. Lengths are page CSS px unless
"pt"; conf = confidence (high, medium, low).

## Method and calibration

- Real events via the browser `computer` tool; exact numbers and mid-drag state via
  synthetic `MouseEvent`s dispatched from page JS (`mousedown`, `mousemove`s,
  `mouseup`, optional shift/meta/alt/ctrl). Google Slides accepts them like real
  events (cross-checked: real and synthetic border drags moved a box by the same
  delta). Synthetic `clientX/Y` are integers, so every threshold carries +-0.5 px.
  Keyboard shortcuts were real keys.
- Viewport 1600x841 CSS px, devicePixelRatio 1.8. Slide 720x405 pt; on screen
  1.4025 or 1.521 CSS px per pt depending on the bottom chip or side panel
  (the slide rect shifts when a chip, panel or toast appears). Re-derive the scale
  from the slide rect before converting.
- Oracle channels, all under `#workspace > svg`:
  - Cursor: class on `#workspace` = `cursor-default|text|move|nw-resize|n-resize|ne-resize|e-resize|se-resize|s-resize|sw-resize|w-resize|crosshair`. Updates only while the tab is visible.
  - Selection chrome: `path stroke=#1a73e8` outline plus handle paths. Caret: `rect.docs-text-ui-cursor-blink`. Text highlight: `rect.sketchy-text-selection-overlay`. Hover outline: `path stroke=#747775`. Drag ghost: `path stroke=#999999`.
  - Hit testing: each text box or unfilled shape owns an invisible path (`fill-opacity=0`, `pointer-events=visiblePainted`) over its whole box; its text owns a second `visiblePainted` path equal to the text bbox. Filled shapes paint their own fill.
  - During a drag the real object does not move; chrome stays at the origin, a ghost follows the snapped pointer, guides and ruler ticks are drawn, and the position commits on mouseup.
- Screenshots lag one action behind; DOM reads are the source of truth.
- Text-fit numbers were taken at 18 pt Arial; other fonts and sizes were not sampled.

## Gaps / unmeasurable

- Hover cursors for image, shape text, unfilled-shape interior and group (tab hidden froze the cursor class); hover outline colour and timing only partly confirmed (1.10).
- Shift-snap of rotation, and the Size & rotation panel (angle range, wrap of a negative or full-turn entry, behaviour for a rotated group).
- Escape-in-drag used a real key with synthetic mouse; a pure real-mouse hold is not possible with the tool. Plain click on a multi-selection member (6.4) is synthetic only.
- Fractional pointer positions are impossible: every threshold carries +-0.5 px. Pt conversions derive from slide width, not Google's UI.
- Text fitting: very narrow widths (H.11), Shift/Alt on a fit box (H.9, H.10) and the second Cmd+A (P.6) are few-sample synthetic. Empty-box persistence (E.1) was not checked across a reload.
- Edge slop (1.5, 2.4, 2.13, 7.9-7.11): not measured for partially transparent or gradient fills, non-rectangular shapes, word art, video, charts, diagrams or rotated objects; whether the tolerance differs per object type (all measured types fit a single 4.4-5 px constant).
- Not measured: other fonts and sizes, rotated boxes, placeholders with fixed width, step-by-step typing under "Shrink", undo grouping of typing vs auto-fit, click-created width at 200% zoom.
