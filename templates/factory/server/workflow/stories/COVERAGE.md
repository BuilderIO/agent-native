# Story coverage

What the ten stories exercise when their scripts run through the real engine. Generated by `pnpm stories:update`; the coverage spec fails when this file is out of date, or when a node kind, End outcome, Wait kind, loop, source type, AI use, Builder operation or catalog operation has no story.

A dot means the story's scenarios reach it: a node kind or source type moved items, an operation was called (or, for the read-only repository tools of an AI node, offered to the model), a Wait woke an item, an End finished one.

Stories: 1 bug-report-to-builder, 2 builder-to-merge, 3 morning-digest, 4 hot-lead-routing, 5 after-every-customer-call, 6 support-ticket-routing, 7 incident-to-postmortem, 8 security-alert-to-safe-fix, 9 activation-nudge, 10 cloud-cost-spike.

## Follow-ups

- A model's answer checked against a lookup result: Story 6 sends a billing answer on the model's own `supported` and `confidence` flags, which came out `supported: true, confidence: high` in nine of nine real-model runs, so any digit in the answer sends it to finance instead. Sending an amount or a date safely needs a check that every one in the answer appears in the Stripe lookup result (cents read as dollars), which no node kind or rule does today.
