# Preview acceptance

Use this checklist for creation, extension, and preview-to-publish handoffs.
Record the revision, preview environment, workspace role, and run date.
Keep fixture values and evidence free of personal data and credentials.

- **Creation entry.** From a signed-in ordinary workspace member, submit the
  brief through the normal entry point. Record whether the host starts a
  branch, hands off to a local build, or directs the member to New app in its
  managed workspace. Follow that path and record each status through actual
  registration. A branch acknowledgment or workspace link leaves acceptance
  pending.
- **Resolved destination.** Record the app identity, workspace registry
  entry, resolved mount and home, and the rendered domain screen. Confirm
  the preview and published destination by identity when both are in scope.
  For extensions record the host app and slot or route.
- **Visual review.** Attach the [scored rubric](visual-review.md), screenshot
  references, automatic-fail results, and the independent scores.
- **Independent user task.** Give a reviewer the user goal and preview link.
  For a new app, complete a domain task and save an edit, then open the
  registered app from a fresh thread and verify the value in the UI and
  through an app action. For an extension, perform a host task, save a
  change, reopen the slot from a fresh thread, and verify the saved result.
  Record the entry point, task, observed route and UI outcome, read-back
  result, and evidence links for each.
- **Handoff.** Attach the interactive walkthrough and both receipts. Report
  missing screenshots, live proof, or independent review as pending. Carry
  these same results into the host preview and publish checklist.
