# Native shader foreground validation boundary

The agent-facing validation actions accept one to four exact native effect instances in a live Design HTML file. A request pins the collaborative source version, instance/node IDs, definition version, and execution hash. A mounted case calls the editor runtime's strict `renderAt(time)` and reads authenticated same-window status. A clean-fixture case resolves the exact saved definition plus optional document/built-in preset and parameter overrides, then returns executable source only in an authenticated transient prepare-action response. The foreground client reuses one hidden native thumbnail renderer/device to render each case serially at a fixed 60 fps frame from 0–2 seconds. It checks the strict 160×100 straight-sRGB pixel result, stores only its SHA-256 and nontransparent-pixel count, and discards RGBA bytes. The action reports `validation-complete` only after every requested case has a distinct result. A completed run may still contain `error`, `last-good`, or `unavailable` cases. Canceled, expired, and stale-source states remain distinct. No WGSL source, pixels, or Blob bodies enter application state.

The mounted path tests the selected scene as it exists. Its result includes a bounded `sceneProfile`: `available` carries the runtime's rolling maximum 120 render-wall and rAF samples, preview quality/target/effective pixel ratio, scalar texture accounting, and a separate typed GPU timestamp state; `unavailable` reports why the runtime profile could not be read. GPU `gpuPassSumMs`, when ready, is the sum of measured pass spans, not total frame time. The profile is a snapshot of the mounted scene at `capturedAt`; sampling cadence, browser and hardware context, and a controlled benchmark remain separate evidence. An agent can request another mounted validation to obtain a later snapshot.

The clean path supports explicit generated, owned-image, or editable-text source; landscape, portrait, or square aspect; opaque, partially transparent, or zero-alpha source; rounded or square boundary; seed, frame-aligned time, and bounded parameter overrides. It retains the saved instance placement and accepts generated/text for a fill or image/text for a layer or backdrop. Coverage is recorded for every clean case; callers may explicitly require `zero` or `nonzero`, and a mismatch fails that case. Without such an assertion, zero coverage remains a measured result because a shader can legitimately output transparent pixels. This does **not** enumerate or validate every registered preset by itself. An agent must request every exact `{definitionId, version, presetId, executionHash}` recipe and variant in batches of at most four, with unsupported and unavailable counted as failures. The 160×100 case is a small source/edge test, not a full-size export or performance benchmark. `renderWallMs` is measured wall time, not GPU time.

The action ledger holds one foreground request per editor tab. The 45-second claimed lease and one-device serial work bound each batch; larger registries require separate exact-version requests. The clean renderer does not claim screenshot fidelity for the original Design scene, and optional contact-sheet artifacts have not been implemented in this action family.

Shader Lab draft preview remains a separate parity gap. `get-shader`, `validate-native-shader`, and `edit-native-shader` cover saved source/schema operations, while the editor's live draft bridge carries ephemeral WGSL and last-good diagnostics only inside the current tab. A future agent-facing draft request must use an authenticated foreground context and a short-lived source handle or direct trusted response. It must never put raw WGSL drafts into application state or report a CPU schema pass as a WebGPU preview pass.
