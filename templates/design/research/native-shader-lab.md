# Native Shader Lab integration checkpoint

The inspector opens Shader Lab only for an existing mounted native v2 instance. The editor reads `get-shader` twice: a source-free summary for the selected stack and an exact `(definitionId, definitionVersion, includeSource:true)` read for WGSL. It pins the canonical `versionHash`, the exact definition execution hash, the selected instance, and the runtime epoch. The draft changes one or more render-pass WGSL sources and explicitly changed instance parameters; the authored document is not changed during preview.

`validate-native-shader` checks the draft manifest on the CPU. A debounced parent helper then posts `native-shader-draft-preview` to the exact same-origin Design iframe. It selects the screen iframe by file ID, or the unique board-surface iframe when the authoritative `get-shader` path is `__board__.html`; missing or ambiguous frames fail explicitly. The runtime rechecks the mounted base execution hash, draft hash, schema and graph, then compiles and renders at current preview density. The helper accepts only matching window, origin, request ID, epoch and instance ID, and waits past a pending reply. Later requests supersede earlier work. Draft display, previous successful draft, and published display are distinct results. Compiler diagnostics include pass/line/column when supplied; compile/render measurements are wall time, not GPU time. Preview and before/after controls do not save source or grant execution approval.

Apply uses the canonical `edit-native-shader` `revise-definition` operation with the pinned source version. The selected-instance command changes only that instance's definition pin; the shared command changes every instance currently pinned to the old `(id,version)`. Both atomically save the newly versioned WGSL definition and only explicitly changed parameter overrides. A source change before Apply fails the expected-version check. Revert clears the ephemeral preview. Published custom WGSL still follows the separate exact-hash approval workflow; a successful source edit is not an execution approval.

The selected shader focus in `view-screen` exposes bounded identity and `labOpen`, without WGSL drafts. The agent can inspect source with the exact `get-shader` read, validate with `validate-native-shader`, and publish through `edit-native-shader`; there is no duplicate draft SQL store. The `native-shader-draft-foreground` action now accepts an explicit editor-scoped preview or clear request for an existing mounted instance. It checks the live source version, unique authored node, base executable hash, edit access, and CPU draft validity. The draft definition, parameters, seed, and time are put in a user-scoped private attachment; application state holds only its opaque reference, payload hash, execution hash, identity, lease, and bounded terminal diagnostics. The registered Design editor claims the request in its own tab, resolves the attachment transiently, and calls the same Lab iframe bridge. A canceled in-flight preview remains `cancel-requested` until a fresh clear control is acknowledged; failed cleanup cannot be reported as canceled. Agent Apply still uses `edit-native-shader` with the original expected version hash; ephemeral preview success does not publish or approve source.

Focused CPU/action/transport tests and TypeScript checks pass at this checkpoint. The browser runtime listener has mock-GPU proof for success, compile failure, last-good display and clear. The root previously observed a live Gaussian Blur Lab draft render, a source-located WGSL error retaining last-good pixels, and Revert returning to published output. The new external-agent foreground attachment path has not yet had an actual browser or storage-provider acceptance run. This checkpoint does not establish a completed native shader library or catalog.
