# 8.4a2 Top N and calculated fields (ratio, weighted average)

Lane E (Holy-shit features). Size M. Gated: the Top control and the Add
calculation dialog in the chart toolbar are new UI; build only after the
"Chart: top N" and "Chart: add calculation" screens in
`prototypes/analytics-operators/` are signed off. Where the signed-off
prototype differs from this brief, the prototype wins.

Depends on: 1.2 (chart toolbar, `panel-edits.ts`, `applyPanelEdit`), 8.4a1
(`planPanelRender` transform hook). Blocks: 8.4a3 (subtotals reuse the
calculation evaluator).

Paths are relative to `templates/analytics/` unless they start with
`packages/`.

## 1. Goal

An editor turns "every plan" into "the top 5 plans by MRR, plus Other" from
the chart toolbar, without SQL. They also add a calculated field: a ratio
("ARPA = MRR / accounts") or a weighted average ("average discount weighted
by seats"). A calculation stays correct wherever rows are combined: the Other
bucket, and later 8.4a3's subtotals, recompute the ratio from summed parts
instead of averaging per-row ratios. The agent sets the same two settings
through the same action.

## 2. What the code does today

- `config.limit` (`app/pages/adhoc/sql-dashboard/types.ts:92`) is honored only
  by tables, as "first N rows" (`app/components/dashboard/SqlChart.tsx:1884-1887`)
  and by email reports (`server/lib/dashboard-report-render.ts:624`). There is
  no top N by value and no Other bucket in the SQL dashboard code; the closest
  is the explorer page bucketing series into Other
  (`app/pages/adhoc/explorer/ExplorerChart.tsx:306`, `:311`).
- Charts keep at most 400 rows: `limitChartRows`
  (`shared/panel-render-contract.ts:612-640`) keeps the newest for line, area,
  combo and heatmap and the first for the rest.
- No calculated fields exist anywhere in the template (no ratio or weighted
  average in `app/`, `shared/`, `server/` or `actions/`). Today a ratio is
  written into the panel SQL.
- `PANEL_CONFIG_KEYS` (`shared/panel-render-contract.ts:45-68`) uses
  `satisfies Record<keyof SqlPanelConfig, PanelConfigKeyInfo>`, so a new
  config key must be registered there or the build fails.
- Rendering of every chart goes through `planPanelRender`
  (`shared/panel-render-contract.ts:690-749`); 8.4a1 applies the drill there.
- `formatYValue` (`SqlChart.tsx:179-189`) and `formatMetricValue` (`:279`)
  format by `yFormatter`; 1.1a moves cell formatting to
  `shared/table-cell-format.ts` (brief `tasks/1.1a-table-column-menu.md`).
- 1.2 builds the chart toolbar (`ChartEditToolbar.tsx`) and the pure helpers
  in `panel-edits.ts` (brief `tasks/1.2-click-to-edit-charts.md`); neither
  exists on the integration branch yet.

## Plan corrections

- Top N on the browser side only sees the rows the query returned. When the
  result is truncated, Top N is computed over a partial result; the chart says
  so (amber) rather than presenting it as the true top N. For a full top N on
  large tables the agent rewrites the SQL with `ORDER BY ... LIMIT`.

## 3. Build

1. **Config.** Add to `SqlPanelConfig` (`types.ts`) and register in
   `PANEL_CONFIG_KEYS` with value checks:
   - `topN?: { n: number; by: string; other: boolean }` (n 1 to 50; `by` a
     value column or a calculation id). `onlyFor`: bar, pie, table, combo.
   - `calcs?: PanelCalc[]`, at most 8, where `PanelCalc` is
     `{ id: string; label: string; kind: "ratio"; numerator: string; denominator: string; format?: "number" | "currency" | "percent"; decimals?: number }`
     or `{ id; label; kind: "weightedAverage"; value: string; weight: string; format?; decimals? }`.
     Ids match `^calc_[a-z0-9_]{1,40}$` so they never collide with result
     columns.
2. **Evaluator.** New `shared/panel-calcs.ts`:
   - `applyCalcs(rows, calcs): { rows; issues }` adds one column per calc per
     row. A ratio with a zero or missing denominator is `null` (rendered as an
     empty cell), and the issue list counts those rows; a missing column is a
     typed issue naming the column, surfaced by verification, never a column
     of zeros.
   - `combineRows(rows, groupKeys, valueKeys, calcs)`: sums value columns and
     recomputes each calc from the summed parts (ratio = sum(num) /
     sum(den); weighted average = sum(value * weight) / sum(weight)). 8.4a3's
     subtotals call this.
   - `applyTopN(rows, topN, xKey, calcs)`: sorts by `by` descending, keeps
     `n`, and when `other` is set folds the rest into one row whose x value is
     the localized Other label passed in by the caller, through `combineRows`.
     Returns `{ rows; partial }` with `partial` true for a truncated result.
   - `planPanelRender` applies `applyCalcs` first, then 8.4a1's drill, then
     `applyTopN`, then pivot and `limitChartRows`. One order, one place.
3. **Report and verification.** `server/lib/dashboard-report-render.ts` renders
   through the same plan, so emails match. In
   `server/lib/dashboard-panel-verification.ts`, calc issues (missing column)
   become `render-error` with the column name; zero denominators are not an
   error.
4. **Edit helpers.** In `panel-edits.ts` (1.2): `setTopN(panel, topN | null)`
   and `upsertCalc(panel, calc)` / `removeCalc(panel, id)`, each one
   `updatePanelPath` op (`topN`, `calcs`) and no op when nothing changes.
5. **Toolbar UI** (`ChartEditToolbar.tsx`, for bar, pie, combo; and the table
   header area 1.1a uses for tables):
   - Top: a `DropdownMenu` trigger showing "All" or "Top {{n}}", text-only
     radio items All, Top 5, Top 10, Top 20, a By submenu listing value
     columns and calcs, and a checkbox item Group the rest as Other.
   - Add calculation: a ghost button `+ Calculation` opening a shadcn `Dialog`
     (title only, no subtitle): Name (`Input`), Type (`Select`: Ratio,
     Weighted average), the two column `Select`s (Numerator and Denominator,
     or Value and Weight, number columns only), Format and Decimal places
     reusing `valueFormat.*` from 1.1a. Primary Save at the compact size.
     Saved calcs appear as series or columns with their label; editing opens
     the same dialog from the series color menu (1.2) or the column menu
     (1.1a) through an Edit calculation item; Delete calculation is in the
     same menu, red because it removes the field.
   - Every change saves through `applyPanelEdit` with the Saved toast and Undo.
   - When `partial` is true, an amber `IconAlertTriangle` chip under the
     toolbar: "Top {{n}} of the first {{count}} rows", tooltip explaining.
6. **Application state.** No new key. A selected series or column that is a
   calc carries `seriesKey` / `columnKey` = the calc id (1.1a and 1.2 already
   publish them).
7. **Agent.** No new action: `mutate-dashboard` `updatePanelPath` with
   `topN` or `calcs`. Add one sentence to the `mutate-dashboard`
   `operationsHelp` naming the two keys.
8. **Skills.** In `.agents/skills/dashboard-management/SKILL.md` click-edits
   subsection: `topN` and `calcs` shapes, that ratio and weighted average
   recompute from parts when rows combine, that Top N works on returned rows
   and a truncated result needs an SQL `ORDER BY ... LIMIT` instead. Do not
   grow `AGENTS.md`.
9. **Changelog.** `agent-native changelog add "Show the top N of a chart with an Other bucket, and add ratio and weighted average calculations" --type added`.

## 8. Defaults for open questions

- [Decided by the owner, 2026-10-14] Calculated columns use a free-form formula with typeahead (prototype screen `nb-calc`) in place of the Ratio and Weighted average dialog. A subtotal of a formula column evaluates the formula over the group's aggregates instead of summing row values.
- [Default] Two calculation kinds in v1: ratio and weighted average. Others
  (difference, percent of total) are agent SQL.
- [Default] Top N choices 5, 10 and 20 in the menu; the agent may set 1 to 50.
- [Default] Calculations run in the browser plan on returned rows; nothing is
  pushed into SQL.

## 9. Do not

- Do not change how `config.limit` behaves on tables.
- Do not average per-row ratios anywhere rows are combined.
- No behavior changes outside the unit; additive-only schema; no new /api
  routes for app data (use actions); no raw fetch from client code; no
  process.env reads for provider credentials; no catch or default that turns a
  failure into a normal-looking value; no large payloads in SQL.
