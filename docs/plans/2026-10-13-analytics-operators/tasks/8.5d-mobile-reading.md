# 8.5d Mobile reading: dashboards, notebooks and published apps at phone width

Lane E (Holy-shit features). Size M. Gated: the phone header bar, the Filters
sheet and the phone layouts are new UI; build only after the "Mobile:
dashboard", "Mobile: notebook" and "Mobile: published app" screens in
`prototypes/analytics-operators/` (drawn at 375 px) are signed off. Where the
signed-off prototype differs from this brief, the prototype wins.

Depends on: 1.9 (header actions and the filter bar's View picker), 7.1b
(notebook page), 7.5 (app view). Merge after 7.5. Blocks: 8.5c2 (embeds are
often narrow).

Paths are relative to `templates/analytics/` unless they start with
`packages/`.

## 1. Goal

A founder opens a dashboard link on their phone and can read it: the title
is on screen, Share and the page's few actions are one tap away, charts and
tables fit the width (tables scroll sideways with the first column held),
filters open in a sheet instead of wrapping into a wall of controls, and
Save view is reachable without hover. Notebooks read as one column with SQL
tucked away, and published apps show their inputs in the same Filters sheet.
This is about reading and light interaction, not editing on a phone.

## 2. What the code does today

- On phones, `MobileNav` is the only top bar: a menu button, the brand text
  and a New chat button on Ask (`app/components/layout/MobileNav.tsx:25-58`).
  The app `Header` is `hidden ... md:flex` (`app/components/layout/Header.tsx:56`),
  so on phones there is **no page title and no header action**: a dashboard's
  Share, Views, Add panel and ⋯ menu (set with `useSetHeaderActions`,
  `app/pages/adhoc/sql-dashboard/index.tsx:1974`), and the legacy analysis
  page's actions (`app/pages/analyses/AnalysisDetail.tsx:198`) are
  unreachable.
- Main content is `p-6 pt-2` at every width (`app/components/layout/Layout.tsx:258`);
  the repo's phone gutter is 16 px.
- The dashboard grid stacks panels full width below a 768 px container width
  through a container query (`app/global.css:545`, `:551-562`, `:656-665`).
  This part already works.
- The filter bar wraps (`app/pages/adhoc/sql-dashboard/DashboardFilterBar.tsx:193`,
  `:198`) with fixed control widths (`w-40` `:446`, `w-[140px]` `:596`,
  `w-[160px]` `:711`), opens expanded by default (`:103`), and its Save view
  and Reset buttons only appear on hover while open (`:212`), so touch users
  cannot see them.
- Tables scroll sideways (`overflow-x-auto`, `app/components/dashboard/SqlChart.tsx:1967`)
  with `whitespace-nowrap` cells (`:1985`, `:2031`, `:2063`) and no sticky
  column; charts are 250 px tall in `ChartFrame` (`:874`); the legend popover
  is capped at the viewport (`:798`).
- `useIsMobile()` (`matchMedia("(max-width: 767px)")`) is in the toolkit
  (`packages/toolkit/src/hooks/use-mobile.tsx:3-21`, exported from
  `packages/toolkit/src/hooks/index.ts:1`); Analytics does not use it.
- Analytics has no mobile or viewport tests (`templates/analytics/tests/`
  holds only `redirects.test.ts`).

## 3. Build

1. **Phone header bar.** Add a header menu registry beside
   `useSetHeaderActions`: `useSetHeaderMenuItems(items: { id; label; onSelect; disabled?; destructive? }[])`.
   Below `md`, `Layout` renders a second row under `MobileNav` with the page
   title (`useHeaderTitle`, truncated) and, when the page registered items, a
   ⋯ `DropdownMenu` (text-only items). The dashboard page registers Share
   (opens the share panel as a bottom `Sheet`), Views (the 1.9 View picker in
   a sheet), Dashboard history and Refresh; notebooks register Re-run,
   Publish settings or Open app (7.5); published apps register Open notebook
   for editors and Ask about this app (8.4g2, when built). Desktop headers are
   unchanged. No new page title on desktop (the header already has one).
2. **Gutter.** `Layout.tsx:258` becomes `p-4 pt-2 md:p-6 md:pt-2`.
3. **Filters sheet.** Below `md`, `DashboardFilterBar` renders one outline
   Filters button at the compact size with the count of active filters
   ("Filters · 2"), opening a bottom `Sheet` with every control full width
   (`w-full` replacing the fixed widths below `sm`), the View picker, and
   always-visible Save view and Reset. Above `md` it is unchanged except that
   Save view and Reset are always visible on devices without hover
   (`@media (hover: none)`), which also fixes tablets.
4. **Tables.** On narrow containers, the first column is `sticky` on the
   inline start (logical, so RTL works) with the card background; pagination
   collapses to Previous, page count and Next.
5. **Charts.** Below a 480 px container width: chart height 220 px, the
   legend becomes one horizontally scrolling row, axis tick count halves
   (`interval="preserveStartEnd"`). Tooltips already open on tap through
   recharts; check they do not cover the tapped point.
6. **Notebooks (7.1b).** Cells are full width with 16 px gutters; cell
   toolbars, which show on hover, are always visible on devices without hover;
   SQL areas stay collapsed for viewers; text cells use the same type scale.
   The Graph sheet (8.4c) opens full screen.
7. **Published apps (7.5).** The input bar uses the Filters sheet from step 3;
   cells stack; hidden-in-app cells stay hidden.
8. **Application state.** None new. The Filters sheet open state is local UI
   state.
9. **Skills.** `.agents/skills/frontend-design` is the framework skill; add
   one line to the template's `.agents/skills/dashboard-management/SKILL.md`
   that phone layouts come from container queries and the header menu
   registry, so the agent does not add per-panel mobile config.
10. **Changelog.** `agent-native changelog add "Dashboards, notebooks and published apps read well on a phone" --type improved`.

## 8. Defaults for open questions

- [Default] Phones are for reading: no panel editing, no SQL editing, no
  drag on phones.
- [Default] One ⋯ menu for page actions on phones; no bottom tab bar.
- [Default] Breakpoint is the toolkit's 768 px; charts adapt by container
  width.

## 9. Do not

- Do not change desktop layouts or the dashboard grid's container query.
- Do not add per-panel mobile settings.
- No behavior changes outside the unit; additive-only schema; no new /api
  routes for app data (use actions); no raw fetch from client code; no
  process.env reads for provider credentials; no catch or default that turns a
  failure into a normal-looking value; no large payloads in SQL.
