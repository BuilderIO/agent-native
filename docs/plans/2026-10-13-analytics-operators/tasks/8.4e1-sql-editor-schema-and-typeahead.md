# 8.4e1 SQL editor: schema browser and typeahead

Lane E (Holy-shit features). Size M. Gated: the schema browser and the
completion list are new UI; build only after the "SQL editor: schema" and
"SQL editor: typeahead" screens in `prototypes/analytics-operators/` are
signed off. Where the signed-off prototype differs from this brief, the
prototype wins.

Depends on: 2.1b (built: Postgres schema snapshot), 2.3a (built: imports),
7.1b (notebook SQL cells use the same editor). Merge after 7.1b and 7.2b.
Blocks: 8.4e2 (templating completions ride on this editor).

The plan's 8.4e is split in two: 8.4e1 (this unit) swaps the editor and adds
the schema browser and table and column completion; 8.4e2 adds templating
(filter and input tokens) on top.

Paths are relative to `templates/analytics/` unless they start with
`packages/`.

## 1. Goal

Someone writing a SQL cell or panel sees the tables and columns of the source
they picked in a side list they can search, and gets completions as they
type: table names after `FROM` and `JOIN`, columns after a table alias and a
dot, and SQL keywords. Clicking a table or column inserts it at the cursor.
No guessing table names, no switching to another tab to look them up, and the
agent's schema tools and the browser show the same tables.

## 2. What the code does today

- `SqlEditor` is a plain `<textarea>` over a highlighted `<pre>`
  (`app/components/SqlEditor.tsx:13-57`, textarea `:41-53`, overlay
  `:34-40`), highlighted by a home-grown tokenizer
  (`app/components/SqlHighlight.tsx`, `tokenize` `:154`, `SqlHighlight` `:275`).
  It has no completion and no schema awareness. `package.json` has no
  CodeMirror, Monaco, Prism or Shiki.
- It is used in `PanelEditorDialog.tsx:769-775` (with the
  `panelEditor.filterInterpolation` hint at `:776-780`) and
  `ViewSqlPopover.tsx:221-231` (read-only for viewers). 7.1b adds notebook SQL
  cells with the same component.
- Schema sources:
  - BigQuery: `search-bigquery-schema` (`actions/search-bigquery-schema.ts:607-640`,
    GET, read-only): datasets, tables, a table's columns (`flattenBigQueryFields`,
    `server/lib/bigquery.ts:251-273`), or a search, `limit` up to 200 with
    `nextPage`.
  - Postgres: the stored snapshot `readPostgresSchemaSnapshot(ctx)`
    (`server/lib/postgres-schema.ts:456`, tables with columns, at most 400
    tables and 80 columns each, `:24-25`). No action returns columns today;
    `refresh-postgres-schema` only returns counts
    (`actions/refresh-postgres-schema.ts:7-27`).
  - Imports: `get-data-import` returns one import's columns and types
    (`actions/get-data-import.ts:17-20`); `list-data-imports` lists them.
  - First-party: the documented `analytics_events` and rollup tables
    (`.agents/skills/data-querying/SKILL.md:24-29`).
  - Cells (7.2b): earlier cells' result columns are known in the browser from
    their query results.
- The dictionary (`list-data-dictionary`, `actions/list-data-dictionary.ts:29`)
  carries `table` and a comma-joined `columnsUsed` string, not structured
  columns.

## Plan corrections

- There is no single "list schema" read across sources; each has its own
  shape and some (Postgres) have no action at all. This unit adds one bounded
  read action that adapts each source, so the editor, the browser and the
  agent call the same thing.

## 3. Build

1. **Dependencies.** `pnpm view @codemirror/view version`,
   `@codemirror/state`, `@codemirror/lang-sql`, `@codemirror/autocomplete`,
   `@codemirror/commands`; pin current versions. CodeMirror loads only inside
   the editor through a dynamic import, so pages without an editor do not pay
   for it (read `.agents/skills/performance` first; check the dashboard
   route's chunk size before and after in the PR).
2. **Editor.** Rebuild `SqlEditor` on CodeMirror 6 with the same props
   (`value`, `onChange` of a string, `readOnly`, `disabled`, `placeholder`,
   `rows` as min height, `id`, aria label) so both call sites keep working.
   Theme from CSS variables (`--background`, `--foreground`, `--muted`,
   `--primary`), no raw colors. `SqlHighlight` stays for read-only display
   elsewhere. Cmd/Ctrl+Enter is passed through for 7.1b's run shortcut. The
   textarea fallback renders while CodeMirror loads, with the same geometry.
3. **Schema read action.** `actions/list-source-schema.ts` (read-only,
   `http: { method: "GET" }`, `grounding: true`):
   `{ source, search?, table?, limit?, nextPage? }` returning
   `{ source, tables: { name; kind: "table" | "view"; columns?: { name; type?: string }[] }[]; truncated; nextPage?; status: "available" | "not-connected" | "stale" | "unavailable"; error? }`.
   Adapters: BigQuery through the `search-bigquery-schema` library calls;
   Postgres from `readPostgresSchemaSnapshot` (status `stale` passes through,
   `not-configured` becomes `not-connected`); imports from the data imports
   library; first-party from a fixed list kept next to the first-party
   catalog; demo from the demo dataset's tables. Program and Prometheus
   sources return `unavailable` with a reason, not an empty list. The caller's
   credential context is used, exactly as `query-dashboard-panel` uses it.
   Cap 200 tables per page, 200 columns per table.
4. **Completion.** A CodeMirror `sql()` language with `schema` built from
   `list-source-schema` for the panel's source (React Query, `staleTime`
   5 minutes, keyed by source), plus for `cells` panels (7.2b) the upstream
   cells' column names keyed by cell id. Keywords from the dialect: BigQuery
   (`StandardSQL`), Postgres (`PostgreSQL`), DuckDB for cells (`StandardSQL`
   plus the 7.2a dialect name in the placeholder). Columns load lazily: a
   table's columns are fetched with `table` when its completion first opens.
5. **Schema browser (gated UI).** A Schema toggle button (`IconDatabase`,
   tooltip) at the editor's top edge opens a resizable side list
   (`react-resizable-panels`, already a dependency) in the panel editor and a
   collapsible list under the editor in a notebook SQL cell: search `Input`,
   tables with a chevron to expand columns and their types, a Copy name menu
   (text-only, `DropdownMenu`) and click to insert at the cursor. Loading uses
   row-shaped `Skeleton`s. `not-connected` shows "Connect {{source}} to see its
   tables" with a link to Data sources; `stale` shows an amber "Schema read
   {{ago}}" with Refresh for Postgres (calls `refresh-postgres-schema`);
   `unavailable` shows its reason. Never an empty list for an error.
6. **Application state.** None new. The editor's source is already on the
   panel selection.
7. **Skills.** `.agents/skills/data-querying/SKILL.md`: one line that
   `list-source-schema` is the schema read for every source and what its
   statuses mean, so the agent prefers it to per-source guesses. Read
   `.agents/skills/writing-agent-instructions`. Do not grow `AGENTS.md`.
8. **Changelog.** `agent-native changelog add "The SQL editor lists your tables and columns and completes them as you type" --type added`.

## 8. Defaults for open questions

- [Default] CodeMirror 6, loaded lazily. Monaco is too large for this page.
- [Default] Completions come from the stored or cached schema, never from a
  live warehouse call per keystroke.
- [Default] Sources without a table list say so instead of completing nothing.

## 9. Do not

- Do not change how panel SQL is saved or validated.
- Do not read provider credentials outside the request's credential context.
- No behavior changes outside the unit; additive-only schema; no new /api
  routes for app data (use actions); no raw fetch from client code; no
  process.env reads for provider credentials; no catch or default that turns a
  failure into a normal-looking value; no large payloads in SQL.
