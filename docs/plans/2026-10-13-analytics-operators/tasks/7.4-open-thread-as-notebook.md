# 7.4 Open an ask thread as a notebook

Lane C (Notebook). Size M. **Gated: the "Open as notebook" header button needs
prototype sign-off.** The action and agent path are not gated. Depends on 7.1a
(and uses 7.1b to show the result; 7.2b optional, see step 5).

Paths are relative to `templates/analytics/` unless they start with
`packages/` or `docs/`.

## 1. Goal

After asking a question in Ask, the user clicks "Open as notebook" (or tells
the agent "turn this into a notebook") and gets a notebook whose cells are the
queries the conversation ran, in order, with the question and the answer as
text cells. The user can then edit, re-run and share it instead of re-asking.

## 2. What the code does today

- `/ask` and `/ask/:threadId` render one `AskPage`
  (`app/routes/ask.tsx:13-16`, `app/routes/ask.$threadId.tsx:1`), which mounts
  `AgentChatHome` with the chat header hidden (`app/pages/Ask.tsx:58-89`).
  The app header still renders on Ask on medium and wider screens and shows
  page header actions (`app/components/layout/Header.tsx:46-71`; it is
  `hidden md:flex`, so it does not show on phones).
- Threads are stored in core: `chat_threads.thread_data` holds the message
  repository as JSON (`packages/core/src/chat-threads/schema.ts:8`). Core
  exports `getThread` from `@agent-native/core/server`
  (`packages/core/src/server/index.ts:321-330`); `hasThreadAccess` and
  `resolveThreadAccess` (`packages/core/src/chat-threads/store.ts:922-949`)
  are not exported there. `resolveAccess("chat_thread", id, ctx, { skipResourceBody: true })`
  from `@agent-native/core/sharing` is what `hasThreadAccess` uses.
- The template already parses thread data on the server: Memory capture walks
  `messages` from `headId` back through `parentId`, then reads `content` parts
  (`server/lib/analytics-memory-capture.ts:52-135`), and it fails loudly on
  invalid thread data (`:53-60`).
- Tool calls are stored as `tool-call` parts with `toolName` and the input as
  `args`/`argsText` or `input`/`inputText` depending on the writer
  (`packages/core/src/client/chat/runtime.ts:86-91`,
  `packages/core/src/client/chat/agentkit-protocol.ts:966-974`).
- Query tools the agent uses and their SQL argument:
  `bigquery` `{ sql }` (`actions/bigquery.ts:177-179`),
  `query-agent-native-analytics` `{ sql }` (first-party,
  `actions/query-agent-native-analytics.ts:60-66`), and
  `run-data-program` `{ programId, params }` (core data programs).
- Charts in answers are `embed` fences with
  `src: /chart?panel=<base64url panel JSON>`
  (`.agents/skills/data-querying/SKILL.md:98-108`), decoded by
  `app/routes/chart.tsx` (`decodePanel`, sources at `:24`, chart types at
  `:13`). Each carries `source`, `sql`, `chartType` and `config`.
- Revisions can carry a chat link: `AnalyticsRevisionChatContext { threadId, runId, turnId }`
  (`server/lib/dashboards-store.ts:173-177`).

## Plan corrections

- None on intent. Detail the plan leaves out: the notebook is built from what
  the thread **stored** (tool-call inputs and chart embeds), not by re-running
  the conversation, so no model call is involved and the button is fast.

## 3. Build

1. **Parser** `server/lib/thread-to-notebook.ts` (pure, no I/O):
   `threadToNotebookCells(threadData: string): { cells, skipped, truncated }`.
   - Walk the head branch exactly as `analytics-memory-capture.ts` does. Share
     the walker: move it into `server/lib/thread-lineage.ts` and import it in
     both places, rather than copying it.
   - For each turn, in order: the user's text becomes a text cell
     `### <question>`; each `tool-call` part for `bigquery` or
     `query-agent-native-analytics` with a string `sql` becomes a SQL cell
     (`chartType: "table"`, source `bigquery` or `first-party`); each
     `run-data-program` call becomes a SQL cell with source `program` and the
     program descriptor; each `/chart` embed in assistant text becomes a chart
     cell from the decoded panel; the turn's last assistant text, with embed
     fences removed, becomes a text cell (20,000-character cap from 7.1a).
   - Read the input from `args`, else `input`, else parse `argsText` or
     `inputText`. An unparseable input is counted in `skipped` with reason
     `unreadable`, never dropped silently.
   - Skip calls whose matching `tool-result` has `isError: true`, counted as
     `failed`. Collapse an exact repeat of `(source, sql)` to the first cell,
     counted as `duplicate`.
   - Cap at 40 cells; set `truncated: true` and count the rest.
   - Throw a typed error on invalid thread JSON (same stance as memory
     capture). Zero query cells returns `{ cells: [] }`; the action turns that
     into `no_queries`.
2. **Action** `actions/create-notebook-from-thread.ts` (`defineAction`):
   input `{ threadId?: string, name?: string }`. Default `threadId` to the
   current run's thread (`getRequestRunContext().threadId`, `packages/core/src/server/request-context.ts:74`) so the agent can call it
   with no arguments.
   - Access: `resolveAccess("chat_thread", threadId, { userEmail, orgId },
     { skipResourceBody: true })` must grant at least viewer; then `getThread`.
     No access and not found both return the same `thread_not_found` error so
     ids cannot be probed.
   - Parse, then create through 7.1a's `create-notebook` store path. Name
     defaults to the thread title, else the first question clipped to 80
     characters. Set `config.sourceThreadId` and the revision chat context
     `{ threadId }`.
   - Return `{ dashboardId, url, cellCount, skipped: [{ reason, count }],
     truncated, verified, unverified[] }`. Agent callers get the same
     `verifyPanelWrite` gate as `create-notebook`.
   - `link` builder pointing at the new notebook (pattern in
     `actions/save-analysis.ts:218-234`).
3. **Header button (gated).** In `app/pages/Ask.tsx`, when `threadId` is set,
   add an outline "Open as notebook" button through `useSetHeaderActions`
   (same pattern as `AnalysisDetail.tsx:196-235`). It calls the action with
   `useActionMutation`, shows a pending state within 100 ms, then navigates to
   the notebook. On success with skips, show a toast with the counts; on
   `no_queries`, show the no-queries toast and stay on the thread.
4. **Mobile.** The app header is hidden on phones, so phones use the agent
   path ("turn this into a notebook"). Do not add a second mobile button.
5. **Charts that repeat a query.** If 7.2b has landed and a chart embed's SQL
   equals an earlier SQL cell's, emit the chart as a `cells` panel reading
   that cell instead of repeating the SQL. Without 7.2b, keep the chart's own
   SQL.
6. **Skills.** Add "From a conversation" to `.agents/skills/notebooks/SKILL.md`:
   call `create-notebook-from-thread` when the user asks to keep, save or
   reuse this analysis as a notebook; report skipped counts plainly. Update
   `.agents/skills/adhoc-analysis/SKILL.md` Step 6 to mention it.
7. **Application state.** None new. Navigation already reports
   `view: "ask"` with the thread in the URL.
8. **Changelog.** `agent-native changelog add "Open any Ask conversation as a notebook of its queries" --type added`.

## 8. Defaults for open questions

- **[Default] Built from stored tool calls and embeds, no model call.**
- **[Default] Query tools covered: `bigquery`, `query-agent-native-analytics`,
  `run-data-program`, `/chart` embeds.** Provider API calls and other actions
  are not cells in v1; they are not SQL a cell can re-run.
- **[Default] One question cell and one answer cell per turn.** Intermediate
  assistant text is left out.
- **[Default] Failed and duplicate queries are skipped and counted.**
- **[Default] 40-cell cap.**
- **[Default] Viewer access to the thread is enough**; the notebook is owned by
  the caller and private.

## 9. Do not

- No behavior changes outside this unit; Ask and Memory capture behave as
  before.
- Additive-only schema (none needed).
- No new `/api` routes for app data; the button calls the action.
- No raw `fetch` from client code.
- No `process.env` reads for provider credentials.
- No `catch` or default that turns a failure into a normal-looking value: an
  unreadable tool call is counted, invalid thread data throws, and "no
  queries" is its own result.
- No large payloads in SQL: never copy tool results or rows into the notebook
  config; cells re-run their queries.
- Do not export new thread internals from core for this; use the exported
  `getThread` and `resolveAccess`.
