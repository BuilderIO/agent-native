# 3.2: Seeded company dashboard on first connect

Lane B. Size M. Needs 2.1 and 3.1b.

## 1. Goal

The first time someone connects a source, Analytics builds one "Company
overview" dashboard from whatever is connected: revenue from Stripe, pipeline
from HubSpot, usage from first-party events or a connected Postgres. The user
sees their own numbers on day one without writing a prompt, and the dashboard
grows when they connect the next source, as long as they have not edited it.

## 2. What the code does today

- One seed-on-connect precedent exists: saving a GA4 credential copies the
  `google-analytics` seed into the scoped setting `sql-dashboard-google-analytics`
  if it is missing (`templates/analytics/actions/update-data-source-credentials.ts:142-161`).
  A failure there is logged with `console.warn` and the save still reports
  success (`update-data-source-credentials.ts:154-159`).
- The same action knows when a provider goes from not connected to connected,
  and tracks `connector_added` for that transition
  (`update-data-source-credentials.ts:123-133`, `update-data-source-credentials.ts:163-181`).
  It is UI-only (`agentTool: false`, `update-data-source-credentials.ts:90`),
  and only covers pasted credentials. Workspace OAuth sources (Notion,
  HubSpot, Jira, Sentry, `templates/analytics/app/lib/data-source-status.ts:83-88`)
  connect through core workspace connections and never reach it.
- Shipped dashboard seeds are JSON under `templates/analytics/seeds/dashboards/`
  loaded by `loadDashboardSeed` (`templates/analytics/server/lib/dashboard-seeds.ts:11-60`).
  Seeded content (names, panel titles) is stored English content, not catalog
  strings (`templates/analytics/seeds/dashboards/google-analytics.json:1-30`).
- Programmatic dashboards are written with `upsertDashboard(id, "sql", config, ctx)`
  (`templates/analytics/server/lib/dashboards-store.ts:1856-1871`), as the
  Risk Meeting installer does with program panels
  (`templates/analytics/actions/ensure-risk-meeting-dashboard.ts:98-172`).
- Panel sources today: bigquery, ga4, amplitude, first-party, demo,
  prometheus, program (`templates/analytics/app/pages/adhoc/sql-dashboard/types.ts:1-8`).
  No HubSpot, Stripe or Postgres panel source; 2.1 adds Postgres, and 3.1b
  provides the Stripe program.
- First-party SQL can read the daily rollups `analytics_event_daily_rollups`
  and `analytics_user_days` as well as raw `analytics_events`
  (`templates/analytics/server/lib/first-party-analytics-backend.ts:1298-1303`).
  The shipped first-party seed reads the raw table
  (`templates/analytics/seeds/dashboards/agent-native-templates-first-party.json:122-180`).
- `hubspot-metrics` is a read-only action that returns computed win rate,
  ACV and pipeline value (`templates/analytics/actions/hubspot-metrics.ts:10-25`),
  so a data program can call it through `appAction`.

## Plan corrections

- "On first connect" has three entry points, not one: pasted credentials
  (the action above), workspace OAuth (no template hook today), and 2.2's
  Stripe OAuth. Put the seeding in one idempotent server function and call it
  from each path, plus a client call after the Data Sources page sees a
  source become ready.
- Usage panels should read `analytics_user_days`, not raw events, so the
  seeded dashboard does not add to the raw-table read cost 1.4 is cutting.
- PostHog has no panel source. Leave it out of the seed (see section 8).

## 3. Build

1. Server function `templates/analytics/server/lib/company-dashboard.ts`:
   `ensureCompanyDashboard(ctx, { reason })`:
   - Read the scoped setting `company-dashboard` (`resolveRequestScope` /
     `getScopedSettingRecord`, same helpers as the GA seed). Shape:
     `{ dashboardId, seededAt, seededUpdatedAt, sections: string[], dismissed: boolean }`.
   - If `dismissed` is true, return `{ status: "dismissed" }`.
   - Detect connected sources with the same checks `data-source-status` uses
     (Stripe, HubSpot, Postgres from 2.1, first-party with any row in
     `analytics_user_days` in the last 30 days). A check that errors is
     `unknown`, not "not connected"; skip that section and return it in
     `unknownSources`.
   - Build sections for connected sources only:
     - Revenue (Stripe): call `ensure-stripe-revenue-metrics` (3.1b) server
       function; panels "MRR" (line, `view: "monthly"`, `xKey: month`,
       `yKey: mrr`, currency formatter), "MRR movements" (stacked bar of
       new, expansion, contraction, churned), "Cohort retention" (heatmap,
       `view: "cohorts"`). The two monthly panels share one params object so
       they share one cached run.
     - Pipeline (HubSpot): new program seed
       `templates/analytics/seeds/data-programs/hubspot-pipeline-summary.js`
       that calls `appAction("hubspot-metrics", {})` and emits stage rows;
       panels "Open pipeline by stage" (bar) and "Win rate" (metric).
     - Usage (first-party): "Weekly active users" (line) from
       `analytics_user_days`; (Postgres from 2.1a): "New users per week"
       (bar, `source: "postgres"`) only when 2.1b's snapshot
       (`readPostgresSchemaSnapshot`, status `available`) has a table with an
       email-like column and a created timestamp. Otherwise no Postgres panel,
       and a `stale` or `unavailable` snapshot is reported in
       `unknownSources`.
   - New dashboard: id `company-overview`; if that id exists and is not
     accessible to the caller, use `company-overview-<6 random chars>`.
     Name "Company overview". Write with `upsertDashboard`.
   - Existing dashboard: add only missing sections, and only when the
     dashboard's `updatedAt` equals `seededUpdatedAt` (nobody edited it).
     Otherwise return `{ status: "edited", missingSections }` and change
     nothing.
   - Save the setting with the new `seededUpdatedAt`. Return
     `{ status: "created" | "updated" | "unchanged" | "edited" | "dismissed" | "nothing_connected", dashboardId?, sections, unknownSources }`.
2. Action `templates/analytics/actions/ensure-company-dashboard.ts`
   (`defineAction`, not read-only, with a `link` to the dashboard like
   `ensure-risk-meeting-dashboard.ts:206-224`). Agent-callable and used by the
   UI.
3. Action `templates/analytics/actions/dismiss-company-dashboard.ts`: sets
   `dismissed: true` (called when the user archives or deletes the seeded
   dashboard from the menu, see step 5, and by the agent on request).
4. Entry points:
   - `update-data-source-credentials.ts`: after the `connector_added`
     transition for stripe, hubspot or postgresql, call
     `ensureCompanyDashboard`. Return its result as `companyDashboard` in the
     action result. A seeding failure is returned as
     `companyDashboard: { status: "failed", errorCode }`; it does not fail
     the credential save and is not hidden in a log line.
   - 2.2b's OAuth completion path calls the same function. Whichever of
     3.2 and 2.2b lands second adds the call.
   - 2.1b's `refresh-postgres-schema` calls it after storing a snapshot,
     because the Postgres section needs the snapshot and the credential save
     returns before the schema is read.
   - `templates/analytics/app/pages/DataSources.tsx`: when a source's status
     changes to ready during this page session (including workspace OAuth
     returns), call `useActionMutation("ensure-company-dashboard")` once per
     source, then show a toast with an Open button when the status is
     `created` or `updated`.
5. Archiving or deleting the seeded dashboard marks it dismissed so it is
   not rebuilt. Do this server-side in `templates/analytics/actions/archive-dashboard.ts`
   and `templates/analytics/actions/delete-sql-dashboard.ts` (both the UI,
   from `app/components/layout/Sidebar.tsx` and
   `app/pages/adhoc/sql-dashboard/index.tsx`, and the agent call these), only
   when the id matches the stored `dashboardId`. Unarchiving clears
   `dismissed`.
6. Skills and instructions:
   - `templates/analytics/.agents/skills/dashboard-management/SKILL.md`:
     a short "Company overview" section: what it contains, that the agent may
     call `ensure-company-dashboard` after the user connects a source, and
     that it never re-adds sections to an edited dashboard.
   - `templates/analytics/.agents/skills/data-programs/SKILL.md`: list the
     `hubspot-pipeline-summary` program.
7. Application state: none new. The existing `navigation` state already
   carries `dashboardId` when the user opens it
   (`templates/analytics/app/hooks/use-navigation-state.ts:39-47`).
8. Changelog: `agent-native changelog add "Connecting Stripe, HubSpot or a database now builds a Company overview dashboard with your own numbers." --type added`.

## 8. Defaults for open questions

- DECISION: seed only sections for connected sources; no "connect X" filler
  panels.
- DECISION: never modify a dashboard after a user edit; report `edited`.
- DECISION: PostHog is not seeded until it has a panel source or program.
- DECISION: the seeded dashboard is private to the user who connected the
  source; sharing stays a user choice.
- DECISION: dashboard name and panel titles are stored English content,
  matching existing seeds.

## 9. Do not

- No behavior changes outside this unit; the GA4 seed path stays as is.
- Additive-only schema; the state lives in an existing scoped setting.
- No new `/api` routes for app data; use actions.
- No raw `fetch` from client code; use `useActionMutation`.
- No `process.env` reads for provider credentials.
- No `catch` or default that turns a failure into a normal-looking value: an
  unknown source status is `unknown`, a seeding failure is `failed`, never
  silently "nothing connected".
- No large payloads in SQL.
- Do not seed on page load or server boot; only after a connect event or an
  explicit agent call.
