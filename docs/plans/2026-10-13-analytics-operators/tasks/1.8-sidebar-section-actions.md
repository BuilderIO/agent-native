# 1.8 Sidebar section actions: "+" in the header, one "Show N more"

Lane A (Reliability). Size M. **Gated: build only after the sidebar screens in
`prototypes/analytics-operators/` are signed off.** Depends on nothing.

Paths are relative to `templates/analytics/` unless they start with
`packages/`, `prototypes/` or `docs/`.

## 1. Goal

Every sidebar section (Ask, Dashboards, and Notebooks from 7.1b) works one
way. The section header holds its actions: the label link, then the
hover-revealed filter, a "+" that creates a new item (New chat, New
dashboard, New notebook), and the collapse chevron. The chevron is the only
control that collapses or expands a section, and it does nothing else. A long
list ends with one ghost row, "Show N more", that expands in place and becomes
"Show less". Nothing is added below the list, so a new item never pushes the
create control further down.

The owner's report: the Ask section has an expand chevron beside "+ New chat",
which makes odd expand and collapse states next to the header's own chevron,
and "New" at the bottom of a list "feels like stuff will just get pushed right
off".

## 3. Build

1. **Toolkit rail: drop the footer, add the "Show N more" row.** In
   `ChatHistoryRail.tsx`, remove the footer's New chat `ActionButton` and the
   chevron `IconButton`. When `canExpand`, render one ghost text row after the
   list: a `<button type="button">` with class
   `an-chat-history-rail__more`, `aria-expanded`, and the text
   `railLabels.showMore(hiddenCount)` or `railLabels.showLess`, where
   `hiddenCount = min(items.length, expandedLimit) - collapsedLimit` (the
   controller returns it). Clicking it calls `toggleExpanded`. Change
   `ChatHistoryRailLabels` to `{ showMore: (count: number) => string;
   showLess: string }` and remove `onNewChat` and `newChat` from the rail and
   controller, so every caller fails to compile until it is moved (the
   change is loud, not silently ignored). Keep `previewCount`,
   `expandedCount`, `renderRail` and the controller's `resetExpanded`.
2. **Toolkit "+" button.** Export `ChatHistoryNewChatButton({ label,
   onNewChat, className })` from `@agent-native/toolkit/chat-history`: an
   `IconButton` with `IconPlus` (14px, stroke 1.8), `label` as its accessible
   name and tooltip. Hosts place it in their section header or nav item
   `actions` and own its reveal.
3. **Toolkit CSS** (`packages/toolkit/src/chat-history.css`): delete the
   footer, new-chat and disclosure rules (`:114-160`). Add
   `.an-chat-history-rail__more` matching the Analytics row: full width, start
   aligned, `padding: 4px 10px`, `margin: 0 4px` (so it lines up with chat
   titles), 11px, `muted-foreground / 0.7`, hover `primary`, a focus-visible
   ring. Style `.an-chat-history-rail .an-chat-history__state` (when not
   empty) as the same muted 11px start-aligned line, so a rail empty label
   reads like the Dashboards "No dashboards" line.
4. **Other rail apps** (Plan, Brain, Assets, Factory): pass
   `onNewChat` into `ChatHistoryNewChatButton` in the chat `AppSidebarNavItem`
   `actions`, revealed with `opacity-0 group-hover:opacity-100
   group-focus-within:opacity-100 focus-visible:opacity-100`, and pass real
   labels: `showMore: (count) => t("sidebar.showMore", { count })` and
   `showLess: t("sidebar.showLess")`, adding those two keys to each app's
   catalogs where missing. Their rails keep opening only on the chat route.
5. **Analytics section header, one helper.** In `Sidebar.tsx` add a local
   `SidebarSectionAddButton({ label, onClick, empty, ...props })`: a 28px
   `button` with the chevron's classes (`h-7 w-7 rounded-md
   text-muted-foreground/70 hover:bg-sidebar-accent hover:text-foreground`),
   `IconPlus` `h-3.5 w-3.5`, a right-side `Tooltip` with `label`, and the
   reveal `opacity-0 group-hover/section:opacity-100
   group-focus-within/header:opacity-100 focus-visible:opacity-100`, or
   always visible when `empty`. Give each header row `group/header`. Order in
   every header: label link, settings popover, "+", chevron. Also add
   `group-focus-within/header:opacity-100` to the settings trigger (`:355`),
   so tabbing into the header shows both actions.
6. **Ask.** Lift `handleNewChat` (navigate to `analyticsAskThreadPath(null)`)
   into `Sidebar` and wire it to the Ask header's "+" (`chat.newChat`).
   `AnalyticsChatsSection` passes the new labels (step 1), reads
   `threadsLoadError`, and renders `SidebarLoadError` with Retry
   (`sidebar.chatsLoadFailed`, `refreshThreads`) on a failed list,
   `sidebar.noChats` as the rail `emptyLabel` when loaded and empty, and
   skeletons while loading, as today. In `layout-route-policy.ts`, drop the
   `"toggle"` outcome: the Ask label navigates to `/ask` (or lets the browser
   handle a modified click) and never collapses the section. In
   `handleAskClick`, stop forcing the section open.
7. **Dashboards.** Remove `<NewDashboardDialog />` from the list (`:2630`).
   Give `NewDashboardDialog` an optional `trigger?: ReactNode`, rendered

## 8. Defaults for open questions

- **[Owner decision, 2026-10-14] Toolkit-wide: all five apps match.**
  `ChatHistoryRail` changes in the toolkit, so Analytics, Plan, Brain, Assets
  and Factory get the same pattern in this PR, with a toolkit `minor`
  changeset. There is no Analytics-only path.
- **[Default] "+" is always visible on an empty section**, and hover or focus
  revealed otherwise.
- **[Default] The Ask label never toggles the section and no longer forces it
  open on navigation.** The chevron owns open state. A section still opens on
  its own route until the user has picked, as today.
- **[Default] The four other apps keep their rail closed off the chat
  route**; only their New chat moves to the nav item's "+".

## 9. Do not

- No behavior changes beyond where the controls live and the Ask label
  toggle: New chat, New dashboard and New notebook do exactly what their
  rows did.
- Do not add a second "show more" control or a chevron to the rail.
- Do not keep the old footer for some apps: no Analytics-only `renderRail`
  list and row, and no prop that brings the footer back.
- Do not build a custom popover for New dashboard; reuse
  `NewDashboardDialog`'s `Popover`.
- No `catch` or default that turns a failure into a normal-looking value: a
  failed thread list is an error with Retry, never "No chats".
- No page or section descriptions, no counts in headers, no leading icons in
  menus, no em dashes in copy.
- No new routes or raw `fetch`.
