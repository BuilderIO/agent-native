# 7.2a Cell engine: pick, package and wrap

Lane C (Notebook). Size M. Not gated (server only). Depends on nothing; can run
in parallel with 7.1a. Blocks 7.2b.

Paths are relative to `templates/analytics/` unless they start with
`packages/` or `docs/`.

## 1. Goal

A server-side engine that runs one SQL statement over a few in-memory tables
(earlier cells' rows) safely and fast, packaged so it ships in the hosted
serverless function without breaking other hosts. Users do not see this unit;
it is what makes "query the cell above" in 7.2b possible. The unit ends with a
written measurement and one engine module with tests.

## 2. What the code does today

- No SQL engine runs over in-memory rows. Panel queries go straight to a source
  through `runDashboardPanelQuery` (`server/lib/dashboard-panel-query.ts:404-516`).
- The hosted function is Netlify with a 75 s timeout for all functions and 4 GB
  for the agent background function (`netlify.toml`, `[functions."*"]` and
  `[functions.server-agent-background]`).
- Native packages do not reach the serverless bundle on their own. The deploy
  build copies `@resvg/resvg-js` and its linux platform packages into the
  server output by hand (`packages/core/src/deploy/build.ts:3079-3080`,
  `:3163-3169` `isServerlessNativePlatformPackage`, `:5074-5090`
  `copyInstalledResvgPackages`, called for Netlify, Vercel and AWS presets at
  `:6211-6222`). Cloudflare builds stub native modules
  (`CLOUDFLARE_MODULE_STUB_MODULES`, `:5828-5840`).
- `@electric-sql/pglite` `^0.5.8` is already a runtime dependency of this
  template (`package.json:30`), used for local development databases
  (`package.json:7`).
- Data program results cap at 10,000 rows and 4 MB (`packages/core/src/data-programs/store.ts:28-29`).
- The performance skill says to keep heavy runtimes out of modules ordinary
  requests load and to inspect the deployed bundle when adding one
  (`.agents/skills/performance/SKILL.md`, "Protect startup and the first paint").

## Plan corrections

- The plan names DuckDB. DuckDB is the best dialect fit, but it is a 64 to 71
  MB native binary that needs build-time copying like resvg, a core change with
  a changeset, and a stub on Cloudflare. PGlite costs no new bytes. The spike
  decides on measurements, not on the plan's wording.
- `@duckdb/duckdb-wasm` is ruled out by default: its `latest` dist-tag is a dev
  build and the package is the largest option.

## 3. Build

1. **Measure the baseline.** From the repo root, build the hosted bundle:
   `NITRO_PRESET=netlify pnpm --filter analytics build`. Record the unzipped
   and zipped size of each function under
   `templates/analytics/.netlify/functions-internal/` (`du -sh`, and `zip -qr`
   to a temp file in `.tmp/`). The documented AWS Lambda limit is 250 MB
   unzipped; confirm Netlify's current limit in its docs and write the source
   in the result.
2. **Try DuckDB in a scratch branch of the build.** Add
   `@duckdb/node-api@<latest checked>` to `templates/analytics/package.json`,
   install, and extend `packages/core/src/deploy/build.ts` with a
   `copyInstalledDuckDbPackages` step modeled on `copyInstalledResvgPackages`
   (scope `@duckdb`, packages `node-api` and `node-bindings` plus the linux
   platform packages). Add `@duckdb/node-api` and `@duckdb/node-bindings` to
   `CLOUDFLARE_MODULE_STUB_MODULES` and the worker externals, with a stub that
   throws a named `CellEngineUnavailableError`. Rebuild and record sizes again.
   Check `pruneServerlessFunctionDeadWeight` and
   `SERVERLESS_FUNCTION_PACKAGE_DENYLIST` do not strip the binding.
3. **Measure the engine on the same inputs for both candidates** with a script
   in `.tmp/cell-engine-spike/` (not committed): load three tables of 1,000,
   10,000 and 100,000 rows of mixed types, run a join plus group-by and a
   window function, and record first-call time in a fresh Node process (cold),
   warm call time, peak RSS, and the SQL features that fail. Run it in the
   `public.ecr.aws/lambda/nodejs` container image at the Node version the
   function uses, as a local stand-in for the serverless runtime.
4. **Decide** with this rule, and write the decision and numbers to
   `docs/plans/2026-10-13-analytics-operators/spikes/7.2a-cell-engine.md`:
   - DuckDB if the analytics server function stays under 200 MB unzipped with
     it, cold first call is under 1.5 s, and it passes the security lockdown
     in step 6.
   - Otherwise PGlite in memory.
5. **Wrap the chosen engine** in `server/lib/notebook-cell-engine.ts`:

   ```ts
   export interface CellEngineInput {
     name: string;              // table name, a validated identifier
     schema: { name: string; type: string }[];
     rows: Record<string, unknown>[];
   }
   export interface CellEngineResult {
     rows: Record<string, unknown>[];
     schema: { name: string; type: string }[];
     truncated: boolean;
   }
   export async function runCellSql(args: {
     sql: string;
     inputs: CellEngineInput[];
     maxRows: number;
     timeoutMs: number;
     signal?: AbortSignal;
   }): Promise<CellEngineResult>;
   ```

   - Load the engine with a dynamic `import()` inside `runCellSql` only, never
     at module scope, so ordinary requests never load it.
   - One fresh in-memory database per call; closed in `finally`.
   - Load rows with the engine's bulk path (DuckDB appender, or PGlite
     `COPY FROM` a generated buffer), never by concatenating values into SQL.
     Map source types to engine types; unknown types load as text.
   - Typed errors, never empty results on failure: `CellEngineUnavailableError`,
     `CellEngineTimeoutError`, `CellEngineInputTooLargeError` (over 100,000
     rows or 25 MB of JSON across inputs), `CellEngineSqlError` (the engine's
     message, clipped).
   - `truncated: true` when the result exceeds `maxRows`; never a silent cut.
6. **Security lockdown** (required for either engine; the cell SQL is user and
   agent authored):
   - DuckDB: before loading data run `SET enable_external_access = false`,
     `SET autoload_known_extensions = false`,
     `SET autoinstall_known_extensions = false`,
     `SET allow_community_extensions = false`, a `memory_limit` (default
     512 MB), `threads` (default 2), then `SET lock_configuration = true`.
     Reject statements that are not a single read query (no `ATTACH`, `COPY`,
     `INSTALL`, `LOAD`, `PRAGMA`, `SET`, `EXPORT`) using the engine's own
     statement parsing (DuckDB `extractStatements` and statement type), not a
     regex.
   - PGlite: no extensions loaded, run the query inside a read-only
     transaction after loading, reject multiple statements, and confirm
     `COPY ... TO`/`FROM` a file path and `pg_read_file` fail in the spike.
   - The spike result lists each escape attempt and its outcome.
7. **Timeout.** Abort with the engine's interrupt (DuckDB
   `connection.interrupt()`; PGlite close) when `timeoutMs` passes or `signal`
   aborts.
8. **Four areas.** UI: none (7.2b). Actions: none (7.2b adds the source).
   Skills: add a short "Chained cells engine" note to
   `.agents/skills/performance/SKILL.md` in this template only if the engine
   adds bundle weight, naming the size. Application state: none.
9. **Changeset.** If `packages/core/src/deploy/build.ts` changes, add
   `.changeset/<name>.md` for `@agent-native/core` (patch): "Copy DuckDB native
   packages into serverless bundles and stub them on Cloudflare."

## 4. Copy

No user-facing strings. Error messages here are server errors that 7.2b maps
to localized copy.

## 5. Tests

- `server/lib/notebook-cell-engine.spec.ts`: join and group-by over two inputs;
  types round-trip (number, string, boolean, null, date string); `maxRows`
  sets `truncated`; oversize input throws `CellEngineInputTooLargeError`;
  timeout throws `CellEngineTimeoutError`; each blocked statement (`ATTACH`,
  `COPY`, `INSTALL`, `read_csv('/etc/hosts')` or the PGlite equivalents) throws
  `CellEngineSqlError` and touches no file; a second call does not see the first
  call's tables.
- If `build.ts` changes: extend `packages/core/src/deploy/build.spec.ts` with
  the DuckDB copy and the Cloudflare stub, next to the resvg cases.

## 8. Defaults for open questions

- **[Default] Decision rule in step 4** (200 MB unzipped, 1.5 s cold, lockdown
  passes). Reviewer can change the thresholds.
- **[Default] Input caps 100,000 rows and 25 MB per call; memory 512 MB;
  2 threads.**
- **[Default] Dialect is whatever the chosen engine speaks** (DuckDB or
  PostgreSQL); 7.2b's editor and the notebooks skill name it.
- **[Default] Harness lives in `.tmp/` and is pasted into the result doc**, so a
  root `scripts/` change does not force a full CI run.

## 9. Do not

- No behavior changes outside this unit.
- Additive-only schema (none needed).
- No new `/api` routes.
- No raw `fetch` from client code.
- No `process.env` reads for provider credentials.
- No `catch` or default that turns a failure into a normal-looking value: an
  engine failure is a typed error, never `{ rows: [] }`.
- No large payloads in SQL: the engine is in memory per call; nothing persists.
- Do not import the engine at module scope or from any file loaded at boot.
- Do not use `pnpm patch` or vendor binaries into the repo.
