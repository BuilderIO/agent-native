# 3.4a: Evidence panel on every answer

Lane B. Size M. Split from 3.4 (show the work and save definitions); 3.4b
covers definitions.

## 1. Goal

Every answer that ran a query ends with a small "How this was answered"
disclosure: for each query, the source, time window, filters, row count
(marked partial when truncated), when the data is from, and the query itself
with a copy button. Failed queries are listed too. The panel is built from
the tool calls that actually ran in that turn, not from the agent's own
description of them, so a reader can check a number without asking.

## 2. What the code does today

- The agent is told to write the evidence in prose: "source, window,
  filters, sample size, join method, and caveats"
  (`templates/analytics/AGENTS.md:17`), and the cross-source skill asks for a
  written methodology footer (`templates/analytics/.agents/skills/cross-source-analysis/SKILL.md:142-166`).
  Nothing renders it from the real calls, so the footer can drift from what
  ran.
- Per-tool chat renderers exist: `registerActionChatRenderer` in the toolkit
  (`packages/toolkit/src/app/chat/chat/tool-render-registry.tsx:81-85`),
  used by Analytics for single-number results
  (`templates/analytics/app/lib/register-analysis-result-renderer.tsx:69-73`,
  imported from `templates/analytics/app/root.tsx`). They render one tool's
  result, not a per-answer summary.
- The agentkit message view has a per-message supplement slot rendered after
  the message parts (`packages/toolkit/src/app/agentkit/react/components.tsx:3791`,
  `components.tsx:3859-3861`). The toolkit fills it with its own
  `AgentKitMessageSupplement` (`packages/toolkit/src/app/chat/AgentKitAssistantChat.tsx:1474-1490`,
  `AgentKitAssistantChat.tsx:6164-6215`), which only shows integration
  suggestions and run warnings for completed assistant messages
  (`AgentKitAssistantChat.tsx:6191-6194`). Apps cannot add to it.
- Each tool call in thread state carries `name`, `input`, `output`, `status`,
  `runId` and `messageId` (`packages/agentkit/src/protocol/index.ts:277-288`;
  thread state `tools` at `packages/agentkit/src/client/state.ts:66`).
- Analytics renders chat through the toolkit's `AgentChatHome`
  (`templates/analytics/app/pages/Ask.tsx:7`, `Ask.tsx:59`).
- Data actions are flagged `grounding: true` (for example
  `templates/analytics/actions/stripe.ts:75`,
  `templates/analytics/actions/account-deep-dive.ts:422`,
  `templates/analytics/actions/query-agent-native-analytics.ts:97`), and the
  set is derived at boot (`templates/analytics/server/plugins/agent-chat.ts:49-50`).
- Panel queries contain template placeholders such as `{{timeRange}}`
  (`templates/analytics/seeds/dashboards/agent-native-templates-first-party.json:129`),
  so the raw `sql` argument does not show the window that ran.

## Plan corrections

- The plan says "an evidence panel on every answer" as if the chat had a
  place for it. It needs a small toolkit extension point first (publishable
  package, needs a changeset).
- Tool outputs stored in a thread can be truncated text, so some fields
  cannot be recovered from the output alone. The panel must show "Not
  recorded" for those, and the few actions whose args do not carry the
  window should put a compact `evidence` object at the top of their result.

## 3. Build

1. Toolkit extension point (`packages/toolkit`):
   - New `packages/toolkit/src/app/chat/chat/message-supplement-registry.tsx`:
     `registerAssistantMessageSupplement({ id, Component })` returning an
     unregister function, same shape as `registerActionChatRenderer`.
   - `AgentKitMessageSupplement` renders registered components after its
     existing content, only for `role: "assistant"`, `status: "complete"`,
     no active run, and only on the last assistant message of its run. Props:
     `{ message, threadId, runToolCalls }`, where `runToolCalls` are the
     thread's tool calls with the message's `runId` (fall back to
     `messageId` when `runId` is missing), in call order.
   - Export it from `packages/toolkit/src/app/chat/chat/index.ts` and the
     public `@agent-native/toolkit/app/chat` entry.
   - Changeset `.changeset/assistant-message-supplements.md` for
     `@agent-native/toolkit` (fixed group with core): "Apps can add a
     supplement under completed assistant answers."
2. Evidence model `templates/analytics/shared/answer-evidence.ts` (pure, no
   React, no server imports):
   - `AnswerEvidenceItem = { tool, status: "ok" | "failed", source, sourceLabel, window, filters, rowCount, truncated, asOf, query, queryLanguage, link? }`
     where each optional field is either a value or `{ unknown: true }`.
   - `answerEvidenceFromToolCall({ name, input, output, status })`: one
     mapper per tool: `bigquery`, `query-agent-native-analytics`,
     `inspect-dashboard-panel`, `run-data-program`, `query-staged-dataset`,
     `provider-api-request`, `db-admin-federated-read`, `hubspot-deals`,
     `hubspot-metrics`, `stripe`, `account-deep-dive`, `run-code` (query is
     the code; source "Custom code"), and 2.1's Postgres query action and
     3.1b's program by name when they exist. Prefer `output.evidence` when
     present. Unknown tools return `null`. Unparseable output gives
     `rowCount: { unknown: true }`, never `0`.
   - `summarizeAnswerEvidence(items)`: query count, distinct source labels,
     total known rows, `anyPartial`, `anyFailed`.
3. Self-describing results for actions whose args do not show what ran:
   helper `withAnswerEvidence(result, evidence)` in
   `templates/analytics/server/lib/answer-evidence.ts` puts a compact
   `evidence` key first in the result (cap the query text at 4,000 chars and
   say so with `queryTruncated: true`). Apply to:
   - `templates/analytics/actions/inspect-dashboard-panel.ts`: it already
     returns the resolved SQL and filter values; add the time scope, cache
     state and `asOf` (reuse 1.4a's fields when it has landed). Do not put
     evidence on `query-dashboard-panel`: it is `agentTool: false`
     (UI rendering only), so it never appears in a turn's tool calls.
   - `templates/analytics/actions/hubspot-deals.ts`: resolved date range,
     pipelines and stage filters.
   - `templates/analytics/actions/stripe.ts`: mode, customer ids, months, and
     3.1a's `truncated`.
   Leave other actions as they are; their args carry what the panel needs.
4. UI `templates/analytics/app/components/chat/AnswerEvidence.tsx`,
   registered in `templates/analytics/app/lib/register-answer-evidence.tsx`
   and imported from `templates/analytics/app/root.tsx` next to the analysis
   result renderer:
   - Renders nothing when no item maps.
   - Collapsed: a `Collapsible` trigger row in muted text: "How this was
     answered" then the summary ("2 queries · BigQuery, Stripe · 1,204
     rows"), with Tabler `IconChevronDown`. When `anyPartial`, add "Partial"
     with Tabler `IconAlertTriangle` in amber; when `anyFailed`, "1 query
     failed".
   - Expanded: one block per item in call order: source label; a compact
     definition list (Window, Filters, Rows, Data as of) where unknown values
     read "Not recorded"; the query in the existing `SqlHighlight` component
     for SQL or a plain `pre` otherwise, max height with scroll; a ghost
     "Copy query" button; "Open panel" link when the item has a dashboard
     link. Failed items show the error message from the tool result.
   - Use `useFormatters` for numbers and times. RTL-safe logical spacing.
   - Works in read-only shared threads (1.7) because it reads thread state.
5. Agent instructions:
   - `templates/analytics/AGENTS.md:17`: replace the prose list with "Each
     answer shows an evidence panel built from the queries you ran (source,
     window, filters, rows, query). In the answer, state the window and any
     caveats, partial coverage or gaps in one or two lines; do not repeat the
     panel."
   - `templates/analytics/.agents/skills/cross-source-analysis/SKILL.md`
     section 6: keep match quality and gaps in prose; drop the per-source
     methodology list the panel now shows.
6. Application state: not applicable. The evidence comes from the thread the
   agent already has, and opening the disclosure changes nothing the agent
   needs to know.
7. Actions: no new action. Step 3 changes three action results additively.
8. Changelog: `agent-native changelog add "Answers now show how they were produced: source, time window, filters, row count and the query." --type added`.

## 8. Defaults for open questions

- DECISION: build the panel from thread tool calls on the client, not from a
  new evidence table. No schema change. Reviewer may prefer server-side
  capture later for MCP callers.
- DECISION: the panel is collapsed by default and only on the final
  assistant message of a run.
- DECISION: failed queries are listed, so the reader sees what was tried.
- DECISION: no guard forces the agent to mention evidence; the panel is
  automatic.
- DECISION: query text capped at 4,000 characters in `evidence`, with a
  visible "shortened" note.

## 9. Do not

- No behavior changes outside this unit; the three action result changes are
  additive keys only.
- Additive-only schema; none expected.
- No new `/api` routes for app data.
- No raw `fetch` from client code.
- No `process.env` reads for provider credentials.
- No `catch` or default that turns a failure into a normal-looking value:
  unknown is "Not recorded", never 0 or blank; a failed query is shown as
  failed.
- No large payloads in SQL or app state; nothing new is stored.
- Do not let the agent author the panel's contents.
- No red for warnings; partial uses amber with a triangle.
