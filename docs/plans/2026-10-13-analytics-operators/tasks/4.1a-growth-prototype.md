# 4.1a Growth surfaces prototype

Lane D (Growth). Size S. Gated: this unit is the gate. 4.1c, 4.1d, 4.2c and
4.3 do not start their UI until the plan owner signs off on it.

## 1. Goal

A product or growth lead can click through every new growth surface before any
of it is built: a funnel built from steps instead of SQL, a retention grid, a
funnel step that opens replays of the people who dropped off, the Sessions page
filtered to those people, and an alert that fires when a funnel's conversion
drops. The plan owner signs off (or asks for changes) on one link instead of
four separate reviews.

## 3. Build

1. Folder: `prototypes/analytics-operators/` (it now has `prototype.json`).
   Do not create a third Analytics prototype. Extend its existing growth
   screens in place rather than adding a parallel flow, and reconcile them
   with the briefs: either change the screens to the brief copy and
   behavior, or, where the drawn version is the better design, change the
   brief's Copy and Build sections in the same change and say so in the
   sign-off request (a choice between a drawn design and a brief is a plan
   owner decision, not a silent pick).
2. Draw these screens and states in `source.html`, using the kit
   (`prototypes/kit/ui.ts` menus, toasts, `ic()`; Tabler icons via
   `node prototypes/kit/add-icons.ts`). Mark every control the code lacks as
   new.
   1. Panel editor, Funnel chart type, First-party Analytics source: the step
      builder from 4.1c (step rows with event picker, optional label, filters,
      move up, move down, remove; Add step; Count select; Converted within).
      States: loading events (skeleton rows), events failed to load (inline
      error with free-text fallback), fewer than two steps (save disabled with
      reason), dashboard without a time range filter (inline error with the
      Add time range filter button), and the Edit as SQL confirm dialog.
   2. Panel editor, Retention chart type: the fields from 4.1d (First event,
      Return event with Any event, Period, Periods).
   3. A dashboard with a funnel panel and a retention panel. Retention grid:
      cohort rows, a People column, Day N or Week N columns, cells shaded by
      percent with token colors, and blank cells with a tooltip for periods
      that have not finished yet.
   4. Funnel step menu (4.3): clicking a step row opens a text-only dropdown
      with "Watch replays of people who dropped off here" and "Watch replays
      of people who reached this step" (4.3 Copy). The first step shows only
      the second item.
   5. Sessions filtered by a funnel step (4.3): a removable filter chip
      "Dropped off before Signed up" (`sessions.funnelFilterDropped`), the
      coverage tooltip, the empty state, and the truncated state.
   6. The conversion bell on the line between two steps (4.2c), opening the
      conversion alert dialog (drawn: "Funnel: conversion alert"). Keep its
      copy in step with 4.2c's Copy section.
   7. The event alert dialog in Settings with the growth conditions from
      4.2b (Fire when select, Change, Compared with, Minimum baseline count).
      The drawn "Event alert in Settings" screen still shows the shipped
      Condition select with Fewer than.
3. Use the copy from the Copy sections of 4.1c, 4.1d, 4.2b, 4.2c and 4.3
   verbatim. If the prototype review changes a string, update that brief's Copy
   section in the same change.
4. Add a dated, past-tense entry at the top of the prototype's `changes.json`
   (create it if the folder has none), for example
   `{ "date": "2026-10-14", "text": "Added funnel, retention and funnel-to-replay screens" }`.
5. Build with `node prototypes/kit/build.ts <folder>`, load
   `<folder>/dist/index.html` headlessly in light and dark, fix console errors,
   and look at screenshots of each new state.
6. Publish or republish the artifact (keep the existing link for an existing
   prototype) and post the link for sign-off.

Four areas: this unit is a prototype, so actions, skills and application state
do not apply. They are specified in 4.1b to 4.3.

## 8. Defaults for open questions

- [Default, reviewer can change] One prototype covers all growth surfaces, so
  sign-off happens once.
- [Default] Funnel step actions open from a click on the step row, not a hover
  button, so they work on touch.
- [Default] The retention grid shades cells by absolute percent, not by a
  per-column z-score like the current heatmap.

## 9. Do not

- No changes under `templates/`.
- Do not restyle unrelated parts of an existing prototype.
- No behavior changes outside the unit; additive-only schema; no new /api
  routes for app data (use actions); no raw fetch from client code; no
  process.env reads for provider credentials; no catch or default that turns a
  failure into a normal-looking value; no large payloads in SQL. (These apply
  to the code units this prototype specifies.)
