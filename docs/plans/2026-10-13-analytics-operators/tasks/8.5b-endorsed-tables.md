# 8.5b Endorsed tables: admins mark trusted sources, answers say when they used others

Lane E (Holy-shit features). Size M. Gated: the Endorse control, the
Endorsed badge and the evidence label are new UI; build only after the "Data:
endorse a table" and "Answer: unendorsed sources" screens in
`prototypes/analytics-operators/` are signed off. Where the signed-off
prototype differs from this brief, the prototype wins.

Depends on: 3.4a (built: answer evidence), 8.5a (history records
endorsements), 8.4e1 (`list-source-schema` lists the tables to endorse).
Blocks: nothing.

Paths are relative to `templates/analytics/` unless they start with
`packages/`.

## 1. Goal

An org admin marks the tables the company trusts (the cleaned
`analytics.accounts`, not `raw.accounts_tmp`) and the imported datasets that
are the source of record. The agent reaches for endorsed tables first, and
every answer's evidence says plainly when it used a table nobody endorsed, so
a buyer can let the whole team ask questions without wondering which numbers
came from a scratch table.

## 2. What the code does today

- Dashboards can be certified, and that is the only trust mark on data
  objects: `dashboards.certification` (`server/db/schema.ts:23`),
  `{ status: "certified", certifiedAt, certifiedBy, certifiedForUpdatedAt }`
  (`server/lib/dashboard-certification.ts:1-6`), stale after any edit
  (`isDashboardCertified`, `:50-58`), set by the admin-only
  `certify-dashboard` (`actions/certify-dashboard.ts:12-39`) from the
  "Certify for AI queries" item in the dashboard menu
  (`app/pages/adhoc/sql-dashboard/index.tsx:2136-2149`).
- Certification steers the agent: +60 score for certified dashboards and
  panels in the query catalog (`server/lib/analytics-query-catalog.ts:234-247`,
  `:873-880`), +12 for approved dictionary entries (`:974`), trust tiers
  (`candidateTrustTier` `:1100-1108`, `dataDictionaryTrustRank` in
  `server/lib/analytics-term-matcher.ts:151-163`), and a prompt rule to prefer
  certified over favorite (`server/lib/analytics-prompt-rules.ts:32`).
- Nothing marks a table, a dataset or an import as trusted. "Endorse" does not
  exist in the code.
- Answer evidence (3.4a) records per tool call the source, window, filters,
  row count and query, with an explicit `EvidenceUnknown` when a fact cannot
  be read (`shared/answer-evidence.ts:10-86`; built in
  `server/lib/answer-evidence.ts`, rendered by
  `app/components/chat/AnswerEvidence.tsx`).
- Data dictionary context labels entries `approved/canonical`,
  `unreviewed/human` or `ai-suggestion` (`server/lib/data-dictionary-context.ts:35-106`).
- Admin checks use `requireAnalyticsAdminContext`
  (`server/lib/db-admin-connections.ts:85-111`).

## 3. Build

1. **Schema (additive), migration 194.** Table `analytics_endorsements`
   (`version: 194`, `name: "analytics-endorsements-table"`; 176 to 189 are 8.1
   to 8.3, 190 to 193 are 8.4d, 8.4f2, 8.4g1, 8.5a): `id TEXT PRIMARY KEY, org_id TEXT NOT NULL, source TEXT NOT NULL, object_ref TEXT NOT NULL, note TEXT, endorsed_by TEXT NOT NULL, endorsed_at TEXT NOT NULL, revoked_at TEXT, revoked_by TEXT`.
   Unique `(org_id, source, object_ref)` among unrevoked rows (enforce in the
   action). `object_ref` is normalized: BigQuery `project.dataset.table`,
   Postgres `schema.table`, import id, first-party table name. At most 500
   active endorsements per org. Run `pnpm guard:additive-migrations`.
2. **Library.** `server/lib/endorsements.ts`: `listEndorsements(ctx)` (org
   scoped, cached per request), `isEndorsed(ctx, source, ref)`,
   `normalizeObjectRef(source, raw)`, and `extractTableRefs(sql, source)`:
   a best-effort reader of `FROM` and `JOIN` targets that returns
   `{ refs: string[] } | { unknown: true }` (CTE names excluded; anything it
   cannot parse is `unknown`, never "no tables").
3. **Actions.** `endorse-source` and `revoke-source-endorsement` (admin,
   `requireAnalyticsAdminContext`), `list-endorsements` (read-only, any org
   member). Each write records into 8.5a's history as `endorsed` /
   `unendorsed` when the table has a dictionary entry.
4. **Agent preference.** In `analytics-query-catalog.ts`, candidates whose
   table (dictionary `table`, or a panel's `extractTableRefs`) is endorsed get
   the same +12 an approved entry gets and a trust tier step; in
   `data-dictionary-context.ts` endorsed tables render with an "endorsed"
   label. Add one clause to the existing prompt rule at
   `analytics-prompt-rules.ts:32`: prefer endorsed tables, and say so when an
   answer uses a table that is not endorsed. Keep it one clause.
5. **Evidence label.** In `server/lib/answer-evidence.ts`, add
   `endorsement: { endorsed: string[]; notEndorsed: string[] } | EvidenceUnknown`
   to each item for SQL sources, from `extractTableRefs` and the org's
   endorsements. Orgs with no endorsements at all skip the field (nothing to
   compare against), shown as absent, not as "all endorsed".
   `AnswerEvidence.tsx` shows an amber line "Used tables that aren't
   endorsed: {{tables}}" when `notEndorsed` is not empty, and "Couldn't tell
   which tables this used" for unknown.
6. **UI (gated).** In 8.4e1's schema browser, admins get Endorse and Remove
   endorsement in each table's text-only menu, and every endorsed table shows
   an `IconRosetteDiscountCheck` badge with a tooltip "Endorsed by {{name}}
   on {{date}}". Imports (`app/pages/DataSources.tsx` import rows) get the
   same menu item and badge. A Settings, Data section gets an "Endorsed
   tables" list (table, source, by, when, Remove) for admins. No count strip.
7. **Application state.** None new.
8. **Skills.** `.agents/skills/data-querying/SKILL.md`: endorsed tables come
   first; check `list-endorsements` when choosing between similar tables; say
   when the answer used a non-endorsed table. Do not grow `AGENTS.md`.
9. **Changelog.** `agent-native changelog add "Admins can endorse trusted tables, and answers say when they used one that isn't" --type added`.

## 8. Defaults for open questions

- [Default] Endorsement is per table or dataset, not per column.
- [Default] Endorsements do not go stale on schema changes (unlike dashboard
  certification); an admin removes them.
- [Default] Non-endorsed tables stay usable; answers are labeled, not
  blocked.

## 9. Do not

- Do not block queries on non-endorsed tables.
- Do not change dashboard certification.
- No behavior changes outside the unit; additive-only schema; no new /api
  routes for app data (use actions); no raw fetch from client code; no
  process.env reads for provider credentials; no catch or default that turns a
  failure into a normal-looking value; no large payloads in SQL.
