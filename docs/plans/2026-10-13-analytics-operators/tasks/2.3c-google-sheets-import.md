# 2.3c Import from Google Sheets

Lane B (Founders). Size M. Not gated (one button and one small dialog inside
the 2.3b panel).

Paths starting with `packages/` are repo-relative; everything else is relative
to `templates/analytics/`.

## 1. Goal

A founder whose numbers live in a Google Sheet clicks "Import from Google
Sheets", picks the file in Google's own picker, chooses a tab, and gets the
same kind of import as a CSV: queryable by the agent, chartable, shareable.
Clicking Refresh pulls the current rows again, and every import shows when it
was last read. Large spreadsheets that are over the 4 MB upload limit come in
this way.

## 2. What the code does today

- A Google Sheets workspace connection exists. Catalog entry
  `packages/core/src/connections/catalog.ts:270-282` requests only
  `drive.file` plus identity, under its own OAuth provider name so the grant
  stays isolated. The provider API definition
  (`packages/core/src/provider-api/index.ts:1266-1295`) requires a workspace
  connection and notes that `drive.file` reaches only "files created by this
  app or explicitly selected by the user" (`:1291`). It rejects a connection
  without the `drive.file` scope (`:4770-4782`).
- Analytics uses it only to export a panel to a new Sheet
  (`server/lib/google-sheets-export.ts:98-160`, through
  `executeProviderApiRequest({ provider: "google_sheets", ... })`). Data
  sources shows its connection state with `getGoogleSheetsConnection`
  (`app/lib/data-source-status.ts:169-176`) and the Connect button
  (`app/pages/DataSources.tsx:2264-2298`, `WorkspaceOAuthView` at `:570-604`).
- Because of `drive.file`, Analytics cannot read a Sheet the user only pasted a
  link to. Google Picker is the supported way to grant per-file access. The
  repo has a picker for Slides in Creative Context: server session action
  `packages/creative-context/src/actions/get-google-picker-session.ts:8-45`
  (returns a short-lived OAuth access token for the connection plus
  `GOOGLE_PICKER_API_KEY` and `GOOGLE_PICKER_APP_ID` from `resolveSecret`,
  `agentTool: false`, `toolCallable: false`) and client loader
  `packages/creative-context/src/client/google-slides-picker.ts` (loads
  `https://apis.google.com/js/api.js` with timeouts, validates file ids at
  `:5` and `:21-44`). The loader is not exported from
  `@agent-native/creative-context/client` (`packages/creative-context/src/client/index.ts`
  has no picker export). `GOOGLE_PICKER_APP_ID` is a known deploy secret
  (`packages/core/src/deploy/build.ts:266`).
- Import storage and the import pipeline come from 2.3a
  (`analytics_data_imports` already has `spreadsheetId` and `sheetRange`).

### Plan corrections

- The plan says "Google GA4 and Sheets through the existing workspace
  connection" under 2.2 and "CSV and Sheets import" under 2.3. The Sheets
  connection already exists; reading an existing Sheet additionally needs
  Google Picker and two deployment secrets (section 7).

## 3. Build

1. **Picker session action** `actions/get-google-sheets-picker-session.ts`:
   `http: { method: "GET" }`, `readOnly`, `requiresAuth`, `agentTool: false`,
   `toolCallable: false`. Resolve the user's Google Sheets connection
   (`resolveWorkspaceConnectionForApp({ appId: "analytics", provider: "google_sheets", requireConnected: true })`),
   then `resolveProviderApiOAuthAccessToken({ provider: "google_sheets", connectionId }, { appId: "analytics", providerIds: ["google_sheets"], getCredentialContext })`,
   and `resolveSecret("GOOGLE_PICKER_API_KEY")`, `resolveSecret("GOOGLE_PICKER_APP_ID")`.
   Typed failures with `fail(...)`: `sheets_not_connected`,
   `sheets_needs_reauth`, `picker_not_configured`. Returns
   `{ accessToken, apiKey, appId, connectionId }`. This is the one place a
   token reaches the browser, as in Creative Context; it is the `drive.file`
   token only (D2).
2. **Status.** `actions/data-source-status.ts` adds
   `googleSheetsImport: { pickerConfigured: boolean }` (two `resolveSecret`
   presence checks, no values) so the UI can hide the button on a deployment
   that cannot finish the flow.
3. **Client picker** `app/lib/google-picker.ts` (new): a generic
   `chooseGoogleDriveFile({ accessToken, apiKey, appId, viewId: "SPREADSHEETS", mimeType: "application/vnd.google-apps.spreadsheet" })`
   modeled on the Creative Context loader: same script URL, same load and
   selection timeouts, same file-id validation, single selection, returns
   `{ fileId, name } | null` (null only when the user cancels; load failure
   and timeout throw typed errors). Note the duplication in the PR as a
   follow-up to move both loaders into `@agent-native/toolkit` (D5).
4. **Shared tabular builder.** Split the type inference and header handling
   from 2.3a's `server/lib/csv.ts` into `buildTabularRows(header, rows)` and use
   it for both CSV and Sheets so the two never infer types differently.
5. **Import action** `actions/import-google-sheet.ts` (agent-callable):
   `{ spreadsheetId: string (validated id), sheetTitle?: string, name?: string }`.
   - Read metadata:
     `GET https://sheets.googleapis.com/v4/spreadsheets/{id}?fields=properties.title,sheets.properties(title,gridProperties)`
     through `executeProviderApiRequest({ provider: "google_sheets", ... })`.
     When `sheetTitle` is absent and the file has one tab, use it; with
     several tabs and none given, fail with `sheet_tab_required` listing the
     tab titles so the UI or agent can ask.
   - Read values:
     `GET .../values/{quoted tab}?valueRenderOption=UNFORMATTED_VALUE&dateTimeRenderOption=FORMATTED_STRING&majorDimension=ROWS`.
     Row 1 is the header. Same caps as CSV: 50,000 data rows (`truncated`,
     `sourceRowCount`), 200 columns.
   - A 403 or 404 from Google for a file the user never picked is
     `sheet_not_picked`; 401 is `sheets_needs_reauth`. Never retry with a
     different account.
   - Store through 2.3a's service with `kind: "google_sheet"`,
     `spreadsheetId`, `sheetRange` (the tab title), `fileRef: null`,
     `lastSyncedAt`. Returns the same shape as `import-csv`.
6. **Refresh action** `actions/refresh-data-import.ts`: `{ importId }`.
   For `google_sheet` imports, re-read with the caller's own Sheets connection
   and replace the staged rows; for `csv` imports, return `not_refreshable`.
   Owner only in this unit (D3). On failure keep the previous rows and set
   `lastErrorCode`; the result says the refresh failed, the rows stay marked
   with their old `lastSyncedAt`.
7. **UI** in `app/components/data-imports/DataImportsPanel.tsx` (from 2.3b):
   - An outline `Button` "Import from Google Sheets" next to Upload file, shown
     when `pickerConfigured`. If Sheets is not connected, the click starts the
     existing connect flow (`startWorkspaceOAuth("google_sheets", "/data-sources?source=uploaded-files")`)
     instead of opening the picker.
   - After a pick: call `import-google-sheet` with a pending row. On
     `sheet_tab_required`, open a small shadcn `Dialog` with a `Select` of the
     returned tab titles and a primary "Import" button; no other content.
   - Sheet rows show a Google Sheets logo (`SourceLogo id="google-sheets-export"`, which `DATA_SOURCE_LOGO_IDS` in `app/lib/data-sources.ts:84-90` maps to the shared Sheets logo),
     "As of {{time}}", and a "Refresh" item in the row menu (owner only).
     Refresh is a short mutation with a `Spinner` in the row.
8. **Application state.** None new; `importId` navigation comes from 2.3b.
   `view-screen`'s `imports.focused` adds `kind` and `lastSyncedAt`.
9. **Skills.** `.agents/skills/data-querying/SKILL.md` "Imported data":
   imports are snapshots; check `lastSyncedAt` and call `refresh-data-import`
   when the user asks for current numbers; a pasted Sheets link cannot be read
   until the user picks the file with "Import from Google Sheets", so navigate
   them to `/data-sources?source=uploaded-files` and say why; never ask for the
   Sheet to be made public.
10. **Changelog.** `agent-native changelog add "Import a Google Sheet tab as data you can chart and ask about, and refresh it later" --type added`.

## 5. Tests

- `actions/get-google-sheets-picker-session.spec.ts`: typed failures for not
  connected, reauth and missing picker config; never returns a value when the
  config is missing.
- `actions/import-google-sheet.spec.ts` with a mocked `executeProviderApiRequest`:
  single tab auto-selected; several tabs give `sheet_tab_required` with
  titles; 403 maps to `sheet_not_picked`; 50,000-row cap; types match the CSV
  path for the same data (shared builder).
- `actions/refresh-data-import.spec.ts`: success replaces rows and updates
  `lastSyncedAt`; failure keeps old rows and records `lastErrorCode`; non-owner
  is refused; CSV is `not_refreshable`.
- `app/lib/google-picker.spec.ts`: selection parsing rejects bad ids and
  returns null on cancel (pure function tests, like
  `packages/creative-context/src/client/google-slides-picker.spec.ts`).
- No source-reading tests.

Local, with a Google OAuth client and Picker secrets for a test project:

1. Data sources, Uploaded files, Import from Google Sheets; connect Sheets if
   asked; pick a two-tab spreadsheet; choose a tab; the row appears with the
   right count.
2. Edit the Sheet, click Refresh; the count changes and "As of" updates.
3. `pnpm action import-google-sheet --spreadsheetId <an unpicked file id>`
   returns `sheet_not_picked`.
4. Ask the agent to chart the imported tab; the panel renders; no console
   errors or failed requests.
5. Without picker secrets, the button is hidden.

Cannot be verified locally without Google test credentials: the picker grant
itself. The action tests cover everything after the pick.

## 8. Defaults for open questions

- **D1** Google Picker with the existing `drive.file` Sheets connection; no
  broader Drive or Sheets scope.
- **D2** The picker session returns the `drive.file` access token to the
  signed-in browser, the same reviewed pattern as Creative Context; it is
  never exposed to the agent (`agentTool: false`, `toolCallable: false`).
- **D3** Refresh is owner-only and manual; no scheduled sync yet.
- **D4** One tab per import; header in row 1.
- **D5** The picker loader is copied into Analytics now; unifying it with
  Creative Context's in `@agent-native/toolkit` is a follow-up.
- **D6** A Sheets import stores no file; the Sheet is the source and the
  staged rows are the snapshot.

## 9. Do not

- No behavior changes outside this unit: the Sheets export and its connection
  card keep working as they do.
- Additive-only schema; none needed beyond 2.3a.
- No new `/api` routes.
- No raw `fetch` from client code for app data; the only browser network call
  outside actions is Google's own picker script.
- No `process.env` reads for provider credentials; picker secrets come from
  `resolveSecret`, the token from the workspace connection.
- No `catch` or default that turns a failure into a normal-looking value: a
  failed refresh keeps and labels the old rows; an unpicked file is
  `sheet_not_picked`, not an empty import.
- No large payloads in SQL beyond the staged rows 2.3a already caps.
- Do not request `spreadsheets.readonly` or `drive.readonly`.
