# 1.1a Click to edit tables: column menu and the shared click-edit write path

Lane A (Reliability). Size M. **Gated:** build only after the column menu in
the prototype (`prototypes/analytics-operators/`) is signed off. Where the
signed-off prototype's copy or layout differs from this brief, the prototype
wins.

The plan's PR 1.1 is split in two. This unit (1.1a) adds the column header
menu and the write path every click edit uses (1.1b and 1.2 build on it).
1.1b adds pointer resize and drag reorder.

## 1. Goal

A person looking at a table panel can open a menu on any column header and,
without writing a prompt: set a number column's format (Number, Currency,
Percent, or Change on a percent change column) and its decimal places, hide
it, bring hidden columns back, move it left or right, sort by it, and hand
"add this column as a filter" to the agent. Each choice shows on the table at once, saves through
`mutate-dashboard` (the same action the agent uses), survives reload, shows
up in email reports, and is visible to the agent as the selected column.

## 2. What the code does today

All paths relative to `templates/analytics/`.

- `ColumnFormat` and `TableColumnConfig` exist at
  `app/pages/adhoc/sql-dashboard/types.ts:49-64`. A column config has `key`,
  `label`, `format` (`number | currency | percent | date | link | text |
  delta`), `linkKey` and `hidden`. There is no decimals field, no width and no
  explicit order field; order is array order.
- The table header only sorts. `TableRenderer`
  (`app/components/dashboard/SqlChart.tsx:1751`) renders each `<th>` with an
  `onClick` that toggles sort (`:1869-1906`, handler `:1793-1817`); shift-click
  adds a sort. Sort state is local React state (`:1782`) and is never saved.
  There is no menu, no hide control and no format control anywhere in the UI.
- `config.columns` is a whitelist. When it is set, only configured, non-hidden
  columns present in the rows render (`SqlChart.tsx:1766-1775`); when it is
  empty, every result column renders in result order. A result column missing
  from a non-empty `config.columns` never shows. The email renderer applies
  the same rule (`server/lib/dashboard-report-render.ts:600-605`).
- Cell formatting is implemented twice: `formatCell` in
  `SqlChart.tsx:1623-1654` (handles numeric strings) and a separate private
  `formatCell` in `server/lib/dashboard-report-render.ts:277-300` (numbers
  only). Currency is a hardcoded `$` prefix and percent is fixed at 2 decimals
  in both.
- The dashboard page saves every UI edit as a full config through
  `update-dashboard` (`app/pages/adhoc/sql-dashboard/index.tsx:601-611`),
  serialized by `createDashboardSaveQueue`
  (`app/pages/adhoc/sql-dashboard/dashboard-save-queue.ts:5-28`) and fenced
  with `expectedUpdatedAt` from `dashboardUpdatedAtRef` (`index.tsx:696`,
  `:1213-1232`). `persist` (`:1236-1291`) applies the change optimistically
  and invalidates queries on settle; `handleSavePanel` (`:1502-1512`) replaces
  one panel. `update-dashboard` with `config` re-validates the SQL of every
  panel on every save (`validatePanelSql(args.config)` at
  `actions/update-dashboard.ts:908`, defined at `:548`).
- `mutate-dashboard` (`actions/mutate-dashboard.ts`) applies typed operations
  to the latest stored config with retry (`upsertDashboardWithRetryOutcome`,
  `:594-623`), so it merges with concurrent edits instead of rejecting them.
  Relevant details for UI use:
  - `updatePanelPath` (`:128-133`, applied by `setConfigPath` in
    `actions/dashboard-mutation-api.ts:834-892`) walks object keys only; it
    cannot address an array element, so a column edit must write the whole
    `config.columns` array.
  - `sqlValidationScope` (`mutate-dashboard.ts:377-414`) re-validates a
    panel's SQL for every `updatePanelPath` and for any `updatePanel` whose
    patch has `config`. A format change on a panel whose SQL is currently
    failing would be refused, and a BigQuery panel pays a dry run on every
    click. Only `config.timeScope` actually changes how SQL is validated or
    interpolated (`app/pages/adhoc/sql-dashboard/interpolate.ts:36-56`).
  - Render verification runs only for agent callers (`:505`, `:508-521`), so
    UI calls skip it.
  - It tags every collab sync as `"agent"` (`:650-655`), unlike
    `update-dashboard`, which passes `agentCaller ? "agent" : undefined`
    (`actions/update-dashboard.ts:961-966`). A UI write through
    `mutate-dashboard` would be attributed to the agent.
  - The result carries no `updatedAt` (`:683-737`); `savedUpdatedAt` is only
    used for collab sync. The page cannot advance its fence after a
    `mutate-dashboard` write, so its next `update-dashboard` save would 409.
- Panel selection reaches application state through
  `useDashboardChatContext` (`app/hooks/use-dashboard-chat-context.ts:137-192`):
  it writes `selected-object` (`type: "dashboard-panel"`, panel id, title,
  kind, chart type, source) with `setClientAppState` (`:185-188`) and stages a
  chat context chip. It only publishes while the agent sidebar is open or when
  asked to open it (`:143`). `view-screen` returns `selected-object` as-is
  (`actions/view-screen.ts:171-178`). The card calls it on click
  (`app/pages/adhoc/sql-dashboard/SqlChartCard.tsx:262-276`) and the page
  builds the panel args in `PanelCell` (`index.tsx:343-365`). Nothing carries
  a column.
- `PANEL_CONFIG_KEYS` (`shared/panel-render-contract.ts:45-68`) registers
  top-level config keys; `columns` is there. Column entries are checked only
  for `key` and `linkKey` binding (`:519-522`).
- The `dashboard-management` skill has no section on click edits; its
  "Reading Panel State" section (`.agents/skills/dashboard-management/SKILL.md:510-527`)
  is the only place it discusses table `columns[]`.
- Available primitives: `app/components/ui/dropdown-menu.tsx` (no
  context-menu primitive in this template), `tooltip.tsx`.

**Plan corrections**

- The plan says the menu "writes through `mutate-dashboard`". Today no UI path
  calls `mutate-dashboard`; the page writes full configs through
  `update-dashboard`. Calling `mutate-dashboard` from the page needs the three
  fixes above (scoped SQL validation, collab origin, `updatedAt` in the
  result) plus a save-queue change so the two write kinds share one fence.
- The plan lists "decimal" as a format. There is no `decimal` format; this
  brief models it as `format: "number"` plus a new `decimals` field.
- "Add as filter" cannot be a pure click edit: a dashboard filter only works
  when the panel SQL consumes it (`{{id}}` interpolation), which means
  rewriting SQL. This brief hands that step to the agent (see section 8).
- `config.columns` is a whitelist, so the first click edit on a table without
  `config.columns` must write every current result column, and later SQL
  columns stay hidden until shown. The menu's "Show columns" list makes that
  visible instead of silent.

## 3. Build

1. **One cell formatter.** Move `formatCell`, `numericTableValue` and the
   delta helper out of `SqlChart.tsx` into `shared/table-cell-format.ts`, add
   a `decimals?: number` argument (0 to 3; absent means today's output), and
   make both `SqlChart.tsx` and `server/lib/dashboard-report-render.ts` import
   it. Delete the duplicate in the report renderer. Keep `formatCell`
   re-exported from `SqlChart.tsx` so existing imports and tests keep working.
   This fixes the report renderer ignoring numeric strings too; call that out
   in the PR.
2. **Types and contract.** In `app/pages/adhoc/sql-dashboard/types.ts`, add
   `decimals?: number` to `TableColumnConfig` (1.1b adds `width`). No new
   top-level config key, so `PANEL_CONFIG_KEYS` does not change. In
   `shared/panel-render-contract.ts`, add a value-shape check for
   `config.columns` entries (array of objects with a string `key`; `format`
   one of `ColumnFormat`; `decimals` an integer 0 to 3) so a bad agent write
   is refused with a reason instead of rendering oddly.
3. **Pure edit helpers.** Create `app/pages/adhoc/sql-dashboard/panel-edits.ts`
   with pure functions that take the panel and the current result column keys
   and return `{ panel: SqlPanel; operations: DashboardMutationOperation[] }`
   (import the operation type with `import type` from
   `actions/dashboard-mutation-api.ts`):
   - `materializeColumns(panel, rowKeys)`: returns `config.columns` if set,
     else one `{ key }` entry per result column in result order.
   - `setColumnFormat(panel, rowKeys, key, format, decimals?)`,
     `hideColumn`, `showColumn`, `showAllColumns`, `moveColumn(panel,
     rowKeys, key, direction)`.
   - Each emits exactly one `{ op: "updatePanelPath", panelId, path:
     "columns", value: nextColumns }`. Never emit an op when nothing changes.
   - `hideColumn` refuses to hide the last visible column (returns null).
   1.2 adds chart helpers to this same file.
4. **`mutate-dashboard` fixes** (`actions/mutate-dashboard.ts`):
   - Replace the key test in `sqlValidationScope` with one rule: a panel is in
     scope when the ops change what it runs, judged by comparing the panel
     before and after the ops (after `normalizeDashboardConfig`), not by
     inspecting op keys: its `sql`, `source`, `chartType`,
     `config.timeScope`, or `config.growth` differ. `config.growth` is added
     by 4.1b, and normalization recompiles `sql` from it, so a growth edit
     arrives as a config path but changes the SQL; an op-key test would skip
     validating it. If 4.1b has not landed, the before/after compare still
     covers it the day it does. Insert, duplicate and `setDashboard` rules
     stay. Agent callers still get render verification, which is where
     config binding is checked.
   - Pass `agentCaller ? "agent" : undefined` to `queueDashboardCollabSync`,
     matching `update-dashboard`.
   - Add `updatedAt: savedUpdatedAt` to the result when saved (additive).
5. **Save queue.** Change `createDashboardSaveQueue` to queue a
   discriminated item: `{ kind: "config"; config }` or `{ kind: "ops";
   operations }`. In `index.tsx`, the queue's save function sends `config`
   items to `update-dashboard` (today's behavior) and `ops` items to
   `callAction("mutate-dashboard", { dashboardId, operations, returnConfig:
   true })`. Both set `dashboardUpdatedAtRef` from the result's `updatedAt`.
   For an `ops` item that is the latest in the queue, adopt the returned
   `config` (it may include a concurrent edit) through the same
   `setDashboard` and `updateCachedDashboardConfig` calls `persist` uses.
6. **`applyPanelEdit` in the page.** Add `applyPanelEdit(edit: { panel;
   operations })` next to `persist` in `index.tsx`: if `canEdit` is false,
   show the existing `sqlDashboard.viewOnly` toast; otherwise
   `resetRevisionNavigation()`, `holdDashboardConfig()`, replace the panel in
   local state optimistically, enqueue the `ops` item, and on failure roll
   back by invalidating the dashboard query and showing
   `sqlDashboard.saveFailedWithMessage` with a plain message (not the raw
   `Action mutate-dashboard failed:` prefix; use `error.actionMessage` when
   present). Pass it down through `PanelCell` and `SqlChartCard` to
   `SqlChart` as `onPanelEdit` (only when `editable`).
7. **Column header menu** (`app/components/dashboard/SqlChart.tsx`,
   `TableRenderer`). Extract the header cell into
   `app/components/dashboard/TableColumnHeader.tsx`:
   - The label keeps today's click-to-sort and shift-click behavior.
   - A trailing icon button (`IconChevronDown`, 16px, visible on header
     hover and focus, always visible while its menu is open) opens a shadcn
     `DropdownMenu`. Right-click (`onContextMenu`) on the header opens the
     same menu. Mark the header `data-no-panel-chat-select` so opening the
     menu does not also trigger the card's click selection.
   - Items are text-only (no leading icons): Sort ascending, Sort descending,
     separator, Format submenu, Decimal places submenu, Move left, Move
     right, Hide column, Add as filter, then a separator and the Show columns
     submenu (one item per hidden or unconfigured result column, then Show
     all columns) when any column is hidden. This matches the signed-off
     prototype.
   - Format is a `DropdownMenuSub` with a `DropdownMenuRadioGroup`: Number,
     Currency, Percent, plus Change only when the column is already
     `delta`. There is no Decimal format: decimals are a setting on the
     format. Text columns get the item disabled with the
     `tableColumns.formatTextColumn` tooltip. Absent `format` on a numeric
     column checks Number.
   - Decimal places is a second `DropdownMenuSub` with a radio group 0, 1, 2,
     3, writing `decimals`. Enabled for Number, Currency and Percent; disabled
     for Change (`tableColumns.decimalsChange`) and text columns. With no
     saved `decimals` the column renders as today and no item is checked.
   - Viewers who cannot edit see only the sort items.
   - Formatting uses `useFormatters()` for the decimal place labels.
   - Menu actions call `onPanelEdit(setColumnFormat(...))` and so on; sort
     items set the existing local sort state.
   - "Move left" and "Move right" move toward the visual side; in an RTL
     document the array direction flips.
   - Add as filter hands the change to the agent and saves nothing itself,
     because a dashboard filter only works once the panel SQL reads it
     (decision D1). It calls `sendToAgentChat` (already used by
     `SqlChartCard.tsx:247`) with `submit: false`, `message` set to the
     localized `tableColumns.addAsFilterPrompt`, `context` set to machine
     context (dashboard id, panel id, column key, distinct values if the
     result has them) and `contextLabel` set to `tableColumns.addAsFilterChip`.
     That opens the agent sidebar with the prompt written and the column as a
     context chip; the person sends it. The agent then adds the filter and
     rewrites the panel SQL in one `mutate-dashboard` call, and the edit
     summary card with Undo (1.3b) reports both changes.
   - Add as filter is enabled for text columns. It is disabled, with a
     tooltip, for number columns (`tableColumns.addAsFilterNumber`) and when
     the dashboard already has a filter whose id is the column key
     (`tableColumns.addAsFilterExists`).
8. **Application state.** In `app/hooks/use-dashboard-chat-context.ts`, add
   `column?: { key: string; label?: string; format?: ColumnFormat }` to
   `DashboardPanelChatContextArgs`. When present, the `selected-object` value
   gains `columnKey`, `columnLabel` and `columnFormat`, and the chat context
   lines gain `Selected column: <key>` and its format. Opening a column menu
   calls `selectPanelForChat({ ...panelArgs, column }, { focus: false })`
   through a new `onSelectColumn` prop on `SqlChart`, wired in `PanelCell`
   (`index.tsx:343`). Selecting the panel elsewhere replaces the object and
   drops the column. Keep the existing sidebar-open gate (`:143`). No new
   app-state key: `selected-object` is the key the plan names.
9. **Skills and instructions.**
   - `.agents/skills/dashboard-management/SKILL.md`: add a short "Table
     column edits" subsection under "Existing Dashboard Edits": the column
     menu sets `config.columns[].format`, `decimals`, `hidden` and order
     through `mutate-dashboard` `updatePanelPath` with path `columns`; send
     the whole array; when a user asks to format, hide or reorder a column,
     make the edit and mention they can do it from the column menu next time;
     `selected-object.columnKey` is the column "this" refers to. Read
     `.agents/skills/writing-agent-instructions` first.
   - `templates/analytics/AGENTS.md:34`: mention `columnKey` on
     `selected-object`.
   - The `mutate-dashboard` action description does not change.
10. **Changelog.** From `templates/analytics`, run
    `agent-native changelog add "Format, hide, show and reorder table columns from the column header menu" --type added`.

## 8. Defaults for open questions

Each is a decision a reviewer can change.

- **D1. Add as filter goes to the agent. Decided by the owner on
  2026-10-13.** A filter needs the SQL to consume it, so the menu item
  writes the prompt into the agent chat (not sent) with the column as a
  context chip, and the agent adds the filter and rewrites the panel SQL.
  The item never writes a filter directly.
- **D2. Sort stays per viewer and unsaved**, as today. Persisting sort is a
  separate change.
- **D3. Currency stays a `$` prefix.** No currency code picker in this unit.
- **D4. Whitelist semantics stay.** The first click edit writes every current
  result column; columns added to the SQL later appear under Show columns,
  not automatically.
- **D5. Decimal places are 0 to 3, on Number, Currency and Percent.
  Decided by the owner on 2026-10-13.** There is no Decimal format and no
  Automatic item; a column with no saved `decimals` renders as today.
- **D6. No column rename** in the menu. `label` stays agent-only for now.
- **D7. Menu opens from a chevron and from right-click**; header click keeps
  sorting.
- **D8. Config-only edits skip SQL validation for every caller**, since agent
  callers are still render-verified and UI callers see the result.

## 9. Do not

- No behavior changes outside this unit: do not restyle the existing panel
  menu, do not change sort behavior, do not change how tables without click
  edits render.
- Schema changes are additive only. This unit adds no table or column.
- No new `/api` routes for app data; use actions.
- No raw `fetch` from client code; use `callAction`.
- No `process.env` reads for provider credentials.
- No `catch` or default that turns a failure into a normal-looking value: a
  failed save rolls back and says so; a missing `updatedAt` after a saved
  write is an error, not a skipped fence update.
- No large payloads in SQL.
- No leading icons in the new menu; no em dashes in copy; no browser
  `confirm`.
