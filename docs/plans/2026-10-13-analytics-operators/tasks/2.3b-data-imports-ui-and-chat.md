# 2.3b Import files from Data sources and from chat

Lane B (Founders). Size M. Not gated (a new entry and list inside the existing
Data sources page, built from existing primitives).

Paths are relative to `templates/analytics/`.

## 1. Goal

On Data sources, a founder clicks Upload file, picks a CSV, and sees it listed
with its row count a moment later, ready to ask about or chart. They can
rename, share or delete it from the row's menu. In chat, they can drop a CSV
and say "import this and tell me which plan has the most churn"; the agent
imports it through the same action and answers from it. The agent always knows
which import the user is looking at.

## 2. What the code does today

- Data sources is one page of source entries rendered in a side sheet
  (`app/pages/DataSources.tsx:170-181` `SourceEntry`, `:2322-2327` the entry
  list, `:2330-2333` `openEntry`). Non-catalog entries already exist as local
  objects: Google Sheets export (`:2264-2298`) and Custom API (`:2300-2320`).
- A catalog key `dataSources.uploadFile: "Upload file"` already exists
  (`app/i18n/en-US.ts:1062`) and is used for credential JSON uploads
  (`DataSources.tsx:339`, `:919`).
- Shared sharing UI: `ShareButton` from `@agent-native/toolkit/app/sharing`
  (used in `app/pages/analyses/AnalysisDetail.tsx:201-207`).
- Navigation state: `/data-sources` maps to `{ view: "data-sources" }` with no
  detail (`app/hooks/use-navigation-state.ts:107-108`, command path `:169`);
  the `NavigationState` interface is at `:8-21`. `actions/view-screen.ts:741-759`
  reports only first-party key info for that page.
- Chat requests pass through `prepareRequest` in `server/plugins/agent-chat.ts:1216-1238`,
  which today only prefetches references and returns early for trivial,
  background-dispatch or anonymous turns (`:1223-1229`). Core calls it before
  attachment pre-upload (`packages/core/src/agent/production-agent.ts:10968`
  versus `:11184`), so attachment bytes are still present there. Its return
  type `PreparedAgentRequest` accepts `attachments` and `contextNote`
  (`production-agent.ts:1705-1711`).
- Slides is the precedent for turning a chat attachment into a private ref:
  `templates/slides/server/lib/chat-attachments.ts:396-414` stamps the saved
  ref on the attachment and drops the forwarded bytes, and
  `templates/slides/actions/_uploaded-files.ts:22-38` resolves a name the model
  saw back to the stamped ref.
- Core pre-upload sends document attachments to the configured file upload
  provider and injects a 24,000-character spreadsheet preview
  (`packages/core/src/file-upload/pre-upload-attachments.ts:59`, `:139-160`).
  For a CSV, that means a customer file can land in public upload storage and
  the model sees only a partial preview.

## 3. Build

1. **Entry.** In `app/pages/DataSources.tsx`, add `uploadedFilesEntry:
   SourceEntry` (`id: "uploaded-files"`, category `database`, logo
   `IconFileSpreadsheet` already imported, `connected` when at least one import
   exists) and include it in `entries`. Detail component
   `app/components/data-imports/DataImportsPanel.tsx` (new).
2. **Upload.** In the panel, a primary `Button` "Upload file" (`IconUpload`)
   opens a hidden `<input type="file" accept=".csv,.tsv,text/csv,text/tab-separated-values">`.
   On pick: acknowledge immediately with a pending row (name, `Spinner`) at the
   top of the list; read the file as base64; if larger than 4 MB, remove the
   pending row and show the over-limit message inline (no network call);
   otherwise `useActionMutation("import-csv")`. On success replace the pending
   row with the real one; on error remove it and show the mapped error under
   the button. No modal. Drag and drop onto the panel uses the same handler.
3. **List.** `useActionQuery("list-data-imports")`; shadcn `Table` with Name,
   Rows, Updated (`useFormatters()` relative time). Truncated imports show
   "50,000 of 61,234" in the Rows cell with a `Tooltip` explaining the limit.
   Loading uses `Skeleton` rows of the same height. Empty state is the upload
   button alone (no explanatory paragraph).
4. **Row menu.** `DropdownMenu`, text-only items: "Ask about this" (hands off
   to the agent sidebar with the import id via the existing delegate helper,
   see `.agents/skills/delegate-to-agent`), "Rename" (inline `Input` in the
   row), "Share" (`ShareButton resourceType="data-import"`), "Delete" (shadcn
   `AlertDialog`, destructive). Rename and delete are optimistic with rollback.
5. **Chat attachments.** New `server/lib/data-import-chat-attachments.ts`
   exporting `prepareDataImportAttachments({ ownerEmail, attachments })`:
   - For each attachment that is CSV or TSV by content type or extension and
     has `data`: decode, cap at 20 MB, `mintAttachmentRef` (private, request
     org), stamp `analyticsImportRef` on the attachment, and delete `data` so
     core does not forward the bytes to the public upload provider.
   - Return the updated attachments plus a `contextNote` listing, per file,
     the name, the ref, the first 20 lines, and the instruction "Call
     import-csv with attachmentRef when the user wants to analyze this file."
   - Mint failures leave the attachment untouched and add a note that the
     file could not be stored, so the model does not claim it was imported.
   Call it at the top of `prepareRequest` in `server/plugins/agent-chat.ts`
   before the early return, and merge its `attachments` and `contextNote` into
   whatever the prefetch path returns. Verify that a turn dispatched to a
   background run still carries the stamped attachments (D6).
6. **Resolve names.** In `actions/import-csv.ts` (from 2.3a), when
   `attachmentRef` is not a ref but matches the name of an attachment on this
   turn (`ActionRunContext.attachments`), use that attachment's
   `analyticsImportRef`, as Slides does (`_uploaded-files.ts:22-38`).
7. **Application state.**
   - `app/hooks/use-navigation-state.ts`: add `importId?: string` and
     `dataSourceId?: string` to `NavigationState`; set them from
     `?import=` and `?source=` on `/data-sources`; `getCommandPath` writes them
     back.
   - `DataSources.tsx` opens the uploaded-files sheet and highlights the row
     when `?import=` is set.
   - `actions/navigate.ts`: accept `importId` for `view: "data-sources"`.
   - `actions/view-screen.ts:741-759`: add `imports: { count, focused? }` where
     `focused` is `{ id, name, rowCount, truncated, columns }` (no rows).
8. **Panel editor.** Choosing source "Imported data" in
   `PanelEditorDialog.tsx` shows a `Select` of imports from
   `list-data-imports` and fills `{"importId": "..."}` into the descriptor;
   advanced users can still edit the JSON. Same pattern as the program picker
   already in that file.
9. **Skills.** `.agents/skills/data-querying/SKILL.md` "Imported data" section
   (from 2.3a): when a chat turn lists a CSV with `analyticsImportRef`, call
   `import-csv` before answering; never answer from the 20-line preview alone;
   after importing, `navigate` to `/data-sources?import=<id>` only if the user
   asked to see it.
10. **Changelog.** `agent-native changelog add "Upload a CSV on Data sources or drop one in chat, then ask questions or chart it" --type added`.

## 8. Defaults for open questions

- **D1** The entry lives on Data sources, not a new route or nav item.
- **D2** No modal for upload; the pending row is the feedback.
- **D3** 4 MB browser cap until a chunked upload exists; the message points to
  Google Sheets (2.3c).
- **D4** Chat-attached CSVs are minted privately and their bytes are not
  forwarded to the public upload provider.
- **D5** "Ask about this" hands off to the agent sidebar; there is no second
  prompt box.
- **D6** If core does not carry prepared attachments into background runs,
  stamp them anyway and file a core follow-up; do not mint twice.

## 9. Do not

- No behavior changes outside this unit: other attachment types keep core's
  current handling.
- Additive-only schema; none needed beyond 2.3a.
- No new `/api` routes; upload goes through `import-csv`.
- No raw `fetch` from client code; use `useActionQuery` / `useActionMutation`.
- No `process.env` reads for provider credentials.
- No `catch` or default that turns a failure into a normal-looking value: a
  failed upload never leaves a row that looks imported; a mint failure is
  stated in the agent's context.
- No large payloads in SQL, `application_state` or the agent context: no file
  bytes, base64 or `data:` URLs; the preview is 20 lines.
- No browser `alert`, `confirm` or `prompt`; no custom absolutely positioned
  menus.

## Reviewer notes

- `dataImports.tooLargeInline` points to Google Sheets, which only exists
  after 2.3c and only on deployments with the Picker secrets. Show that
  wording only when `data-source-status` reports
  `googleSheetsImport.pickerConfigured` (2.3c); otherwise show "Files over 4
  MB can't be uploaded here yet." Add that second key to the catalog set.
- Chat attachments reach `prepareRequest` inside the chat request body, so
  the hosted request body limit applies to them too. Measure the largest
  CSV that survives a hosted chat send before the skill tells users to
  attach large files in chat.
