# 1.2 Click to edit charts

Lane A (Reliability). Size M. **Gated:** build only after the chart toolbar
in the prototype (`prototypes/analytics-operators/`, "Chart: edit from the
toolbar" and "Chart: Y axis format") is signed off. Where the signed-off prototype differs from this brief, the
prototype wins.

## 1. Goal

A person editing a chart panel can change its chart type, the color of each
series, the number format and decimal places of each axis, and its title
from a toolbar on the panel itself,
without a prompt and without opening the full panel editor. Each change shows
at once, saves through `mutate-dashboard` (the same action the agent uses),
survives reload, and is visible to the agent as the selected panel and
series.

## 2. What the code does today

All paths relative to `templates/analytics/`.

- The chart card header (`app/pages/adhoc/sql-dashboard/SqlChartCard.tsx:607-769`)
  shows the title (`CardTitle`, `:608-610`), an optional time range badge, a
  View SQL button (`:624-639`), the panel options menu (`:640-759`) and the
  drag handle (`:760-767`). The options menu has Chat with panel, a per-chart
  time range override, Full screen, table exports, Edit, Refresh and Delete.
  Nothing in it changes chart type, colors or formats.
- Chart type, title and description are editable only in
  `PanelEditorDialog` (`app/pages/adhoc/sql-dashboard/PanelEditorDialog.tsx:54-65`
  for the type list, `:148-235` for the form model), which saves the whole
  panel through `handleSavePanel` and `update-dashboard`
  (`app/pages/adhoc/sql-dashboard/index.tsx:1502-1512`, `:601-611`). Colors
  and formatters are not in that form; only the agent sets them.
- Rendering (`app/components/dashboard/SqlChart.tsx`):
  - Series colors come from `config.colors ?? DEFAULT_COLORS`
    (`:1277`, palette at `:96-105`) and are positional: series `i` gets
    `colors[i % colors.length]` (for example `:2389`, `:2172`). The default
    palette mixes two CSS variables with six raw hex values.
  - Axis format is `config.yFormatter` (`number | currency | percent`,
    `:1278`), with `config.rightYFormatter` for the right axis when
    `config.rightYKeys` splits the series (`app/pages/adhoc/sql-dashboard/dual-axis.ts:34-46`).
    Absent means plain numbers.
  - Chart type `table`, `metric`, `pie`, `bar`, `combo`, `line` and `area`
    all render from the same rows (`SqlChart.tsx:1371-1459`); `funnel`,
    `heatmap` and `callout` need their own config, and `section` and
    `extension` have no query.
  - The legend already has a per-series popover with view-only Filter and
    Hide (`SqlChart.tsx:681-858`); those are not saved.
- Color tokens available in `app/global.css:37-48` (light) and `:85-94`
  (dark): `--brand-blue`, `--brand-teal`, `--brand-green`, `--brand-orange`,
  `--brand-purple`, `--brand-red` and `--chart-1` to `--chart-5`.
- Panel selection reaches `selected-object` through
  `useDashboardChatContext` (`app/hooks/use-dashboard-chat-context.ts:137-192`);
  1.1a extends it with a column. Nothing carries a series.
- The write path for click edits (`applyPanelEdit`, the `ops` save-queue item,
  `panel-edits.ts`, and the `mutate-dashboard` fixes for SQL validation scope,
  collab origin and `updatedAt`) is built in 1.1a.

**Plan corrections**

- The plan says "from the panel toolbar". The card has no toolbar today; it
  has a header with icon buttons and one menu. This brief adds the toolbar
  the signed-off prototype draws: an Edit chart button turns the card header
  into a title field and Done, with a toolbar row under it for chart type,
  series colors and Y axis format (decided by the owner on 2026-10-13, in
  place of a single format menu).
- Changing chart type is not always safe: `funnel`, `heatmap`, `callout`,
  `section` and `extension` need config or have no data, and `pie`,
  `metric` and `table` change what the toolbar edits, so the toolbar only
  switches between line, area and bar (and combo, see D3). Other types stay
  in the panel editor and the agent.
- Axis decimals have no config today: `yFormatter` is only `number |
  currency | percent` and `formatYValue` (`SqlChart.tsx:193-203`) rounds by
  format. This brief adds `yDecimals` and `rightYDecimals`, the axis
  counterpart of 1.1a's column `decimals`.

## 3. Build

1. **Pure edit helpers** in `app/pages/adhoc/sql-dashboard/panel-edits.ts`
   (file from 1.1a), each returning `{ panel, operations }` with no op when
   nothing changes:
   - `setChartType(panel, type)`: one `{ op: "updatePanel", panelId, patch:
     { chartType } }`. Allowed: `line`, `area`, `bar`, and `combo` for a panel
     that is already combo. Leaving combo keeps `config.barKeys` (harmless on
     other types) so switching back restores the split.
   - `setSeriesColor(panel, seriesKeys, seriesIndex, color | null)`:
     materializes `config.colors` from the swatch palette up to the series
     count, sets index `i`, and emits one `updatePanelPath` with path
     `colors`. Null restores that slot's default.
   - `setAxisFormat(panel, axis: "left" | "right", format)`: writes
     `yFormatter` or `rightYFormatter` with `updatePanelPath`. Format is
     `number`, `currency` or `percent`; an absent key reads as Number.
   - `setAxisDecimals(panel, axis, decimals)`: writes `yDecimals` or
     `rightYDecimals` (integer 0 to 3) with `updatePanelPath`.
   - `setPanelTitle(panel, title)`: trims; refuses empty; one `updatePanel`
     with `{ title }`.
2. **Config and render.** Add `yDecimals?: number` and
   `rightYDecimals?: number` to the panel config type in
   `app/pages/adhoc/sql-dashboard/types.ts` and append both to
   `PANEL_CONFIG_KEYS` in `shared/panel-render-contract.ts` with a value
   check (integer 0 to 3). `formatYValue` takes the decimals and formats
   through 1.1a's `shared/table-cell-format.ts`, so an axis and a table
   column with the same format and decimals print the same text. Pass the
   decimals everywhere `formatYValue` gets `yFormatter` today (axes,
   tooltips, metric value) and to `formatTick` in
   `server/lib/report-chart-svg.ts`, so email reports match.
3. **Swatch palette.** Add `CHART_SERIES_SWATCHES` next to `DEFAULT_COLORS`
   in `SqlChart.tsx`: token values only (`var(--brand-blue)`,
   `var(--brand-teal)`, `var(--brand-green)`, `var(--brand-orange)`,
   `var(--brand-purple)`, `hsl(var(--chart-5))`, `hsl(var(--muted-foreground))`),
   each with an i18n name key. Seven swatches, no red, so a series color
   never reads as an error state (owner decision, 2026-10-14). Do not touch
   `DEFAULT_COLORS` (existing charts must not change color).
4. **Edit chart button.** In `SqlChartCard.tsx`, for editable `line`,
   `area`, `bar` and `combo` panels, add an icon button before View SQL:
   `IconAdjustmentsHorizontal` (Tabler), same size and classes as the View
   SQL button, with the `chartEdit.trigger` tooltip. Viewers never see it.
5. **The toolbar** (new `app/pages/adhoc/sql-dashboard/ChartEditToolbar.tsx`).
   Clicking Edit chart puts the card in edit mode, as the prototype draws it:
   - The header swaps `CardTitle` for an `Input` of the same height (title
     field, `chartEdit.titleLabel`) followed by a primary extra-small Done
     `Button`. The card gets a 1px focus outline.
   - Under the header, a toolbar row (`role="toolbar"`, accessible name
     `chartEdit.trigger`) holds, separated by vertical `Separator`s:
     - Chart type: a shadcn `ToggleGroup` (`type="single"`) with Line, Area
       and Bar (Combo as a fourth item only on a combo panel), labels reused
       from `panelEditor.chartType*`.
     - Series colors: one button per series, a 12px color dot plus the
       series label (`formatSeriesLabelForPanel`), each opening a
       `DropdownMenu` radio group of swatches (dot plus color name) and
       Default. Series keys come from the rendered plan; pass them up with
       an `onSeriesKeysChange` callback from `SqlChart` the same way
       `onExportCsvChange` works (`SqlChart.tsx:1150-1156`).
     - Y axis: a "Y axis" label and a `DropdownMenu` trigger showing the
       current format, plus `valueFormat.decimalPlacesCount` when decimals
       are saved (for example "Currency · 1 decimal place"). The menu is a
       `DropdownMenuRadioGroup` with Number, Currency and Percent, a
       separator, and a Decimal places `DropdownMenuSub` with a radio group
       0, 1, 2, 3, the same model as 1.1a's column menu. No Decimal format.
       When `config.rightYKeys` splits the series, show Left axis and Right
       axis triggers instead of one.
   - Every control saves as soon as it is used, through
     `applyPanelEdit(...)`, and shows the same Saved toast with Undo as any
     dashboard edit; each change is one step on the dashboard's undo stack.
     The toolbar holds no pending state.
   - The title saves on Enter, on blur and on Done through
     `applyPanelEdit(setPanelTitle(...))`; an empty title keeps the old one
     and shows `chartEdit.titleRequired`. Done (or Escape with no menu open)
     leaves edit mode; Escape in the title field restores the old title
     without a call. The card click handler already ignores clicks inside
     inputs (`SqlChartCard.tsx:262-276`).
   - Tables keep their column menu from 1.1a. Pie, metric and table panels
     get no Edit chart button.
6. **Wire the write.** Pass `applyPanelEdit` from `index.tsx` through
   `PanelCell` to `SqlChartCard` as `onPanelEdit` (1.1a already threads it to
   `SqlChart`). Agent and UI write the same keys through the same
   `mutate-dashboard` operations, so an agent edit and a toolbar edit are
   indistinguishable in the stored config.
7. **Application state.** Extend `DashboardPanelChatContextArgs` in
   `app/hooks/use-dashboard-chat-context.ts` with `series?: { key: string;
   label?: string }`. Entering edit mode publishes the panel selection;
   opening a series color menu publishes `selected-object` with `seriesKey`
   and `seriesLabel` and adds `Selected series: <key>` to the chat context.
   No new app-state key.
8. **Skills and instructions.**
   - `.agents/skills/dashboard-management/SKILL.md`: extend the click-edits
     subsection from 1.1a: the chart toolbar (Edit chart) writes
     `chartType`, `colors` (positional, token values like
     `var(--brand-teal)`), `yFormatter`, `rightYFormatter`, `yDecimals`,
     `rightYDecimals` and `title` through `mutate-dashboard`; decimals are a
     setting on Number, Currency and Percent, never a format; prefer token
     colors over hex; `selected-object.seriesKey` is the series "this"
     refers to. Read `.agents/skills/writing-agent-instructions` first.
   - `templates/analytics/AGENTS.md:34`: mention `seriesKey`.
9. **Changelog.** `agent-native changelog add "Change a chart's type, series colors, axis format and title from the chart itself" --type added`
   from `templates/analytics`.

Four-area check: UI (steps 3 to 6), actions (no new action; the write uses
`mutate-dashboard`, and step 2 registers the two config keys), skills
(step 8), application state (step 7).

## 8. Defaults for open questions

Reviewer-changeable decisions:

- **D1. Colors stay positional** (`config.colors`), no new keyed config. A
  pivoted chart whose series order changes will shift colors, as it does
  today. Alternative: a new `seriesColors` map keyed by series, which needs
  a renderer and contract change.
- **D2. Swatches are seven theme tokens**, no free color picker and no red
  (red reads as an error on a dashboard).
- **D3. Toolbar chart types: Line, Area and Bar, as drawn.** A combo panel
  also shows Combo so its current type is visible. Pie, metric and table
  change type through the panel editor or the agent.
- **D4. Chart editing is the header toolbar. Decided by the owner on
  2026-10-13**, in place of a single format menu. The title is edited in
  the toolbar's title field; the panel editor keeps working as today.
- **D5. Legend popover is unchanged.** Its Filter and Hide stay view-only.
  Adding color swatches there is a prototype question.
- **D6. Stacking, legend visibility and series labels are out of scope**;
  the agent still sets them.
- **D7. Axis decimals are 0 to 3**, the same Decimal places model as 1.1a's
  columns (decided by the owner on 2026-10-13). No Decimal format.

## 9. Do not

- No behavior changes outside this unit: existing charts keep their colors
  and formats until someone edits them; the panel options menu and the panel
  editor are not restyled.
- Schema changes are additive only; this unit adds no table or column.
- No new `/api` routes for app data; use actions.
- No raw `fetch` from client code.
- No `process.env` reads for provider credentials.
- No `catch` or default that turns a failure into a normal-looking value: a
  failed save rolls back and says so.
- No large payloads in SQL.
- No raw hex in new code (`pnpm guard:no-raw-colors`); no leading icons in
  the new menu; no em dashes in copy.
