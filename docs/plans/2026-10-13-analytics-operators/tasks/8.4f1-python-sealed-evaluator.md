# 8.4f1 Python runtime: a sealed child-process evaluator in core

Lane E (Holy-shit features). Size M. Not gated by a prototype (no UI). **Gated
on the 7.6 spike's five go conditions** (section 3, step 0): do not start
until every one is met and recorded in the spike file.

Depends on: 7.6 (built: spike result), the five conditions below. Blocks:
8.4f2 (Python cells).

The plan's 8.4f is split in two: 8.4f1 (this unit) adds the Python runtime to
`packages/core`; 8.4f2 adds Python cells to Analytics notebooks.

Paths start at the repo root.

## 1. Goal

Core can run one Python program with pandas against one input table and get
one output table back, in a sealed child process that cannot reach the host's
environment, files, processes or network, is killed when it runs too long or
uses too much memory, and ships only in the agent background function. Apps
opt in. Nothing user-facing changes in this unit.

## 2. What the code does today

- Production `run-code` uses the QuickJS `run` evaluator:
  `SandboxCodeEvaluator = "node" | "run"`
  (`packages/core/src/coding-tools/run-code.ts:93`); `executeSandboxCode`
  (`:289`) branches on `evaluator === "run"` (`:296`) into
  `executeRunSandboxCode` (`:949`). The runner has a 64 MB memory limit and
  bridge caps (`:78-89`). Production picks `run` at
  `packages/core/src/server/agent-chat-plugin.ts:2018-2019`; Analytics sets
  `AGENT_PROD_CODE_EXECUTION = "sandboxed"` (`templates/analytics/netlify.toml:12`).
- `SandboxAdapter` (`packages/core/src/coding-tools/sandbox/adapter.ts:41-44`,
  selected in `sandbox/index.ts:48-55`) only drives the `node` child-process
  evaluator. It is not a Python seam.
- The deploy build copies native packages once into the server output before
  any clone, so every function cloned from `server` inherits them: the copy
  block at `packages/core/src/deploy/build.ts:6368-6382` (resvg `:6374`,
  DuckDB `:6376`), then the background function is cloned from that output
  (the `server-agent-background` emitter at `:4226`,
  `cloneServerBundleForFunction` at `:4243`, from
  `packages/core/src/deploy/function-bundle.ts:14`).
- `server-agent-background` gets 4 GB (`templates/analytics/netlify.toml:25-26`)
  and a 15 minute background budget.
- No Pyodide anywhere in code or `package.json`.
- The 7.6 result (`docs/plans/2026-10-13-analytics-operators/spikes/7.6-python-pyodide.md`
  on the integration branch): **no-go for a worker thread** (Python reached
  host files, the host environment through `ps`, child processes and the
  network); **a sealed child process (variant E) passed all 21 isolation
  attempts**: `env: {}`, `--permission` with `--allow-fs-read` for the
  Pyodide directory only, `--disallow-code-generation-from-strings`, an empty
  `js` module with `pyodide_js` unregistered, a `module.registerHooks` resolve
  hook that turns `ws` into a throwing stub, `WebSocket` and `fetch` removed
  after load, and a `process.binding` shim for `NODEFS.staticInit`. Columnar
  JSON is the fastest channel (100,000 rows: 176 ms in, 184 ms out). The
  interrupt buffer cannot stop C code; SIGKILL took 20 ms. WebAssembly memory
  is not bounded by `resourceLimits` (a 1.5 GB array allocated under a 256 MB
  heap cap). A socket `listen()` crashes the interpreter in variant E.
  `pyodide@314.0.7` was current at the spike.

## 3. Build

0. **Entry criteria. All five must hold, each recorded in the spike file
   with evidence, before any code:**
   1. Cold start in the container: the harness's `timings-sealed` section in
      `public.ecr.aws/lambda/nodejs:24` on x86_64 has a median under 8 s.
   2. Security sign-off on the boundary (the two process flags, the empty
      `js` module, the resolve hook) from whoever owns security, or an outside
      review they ask for.
   3. Node 25 or later on the deployed functions, preferred: with it,
      `--permission` alone also denies network at the Node layer. If the
      owner accepts Node 24, write that decision down.
   4. A memory watchdog in the parent that polls the child's RSS and SIGKILLs
      over a cap (this unit builds it; the condition is that the cap is
      agreed: default 1.5 GB).
   5. Bundle scoping: Pyodide is copied only into `server-agent-background`,
      not into every function cloned from `server` (this unit builds it).
   If any is missing, stop and report which one; do not ship a partial
   boundary.
   As of 2026-10-14 the owner has not decided conditions 2 (who signs off
   the boundary) and 3 (Node 25, or accepting Node 24). Both stay open.
1. **Dependency.** `pnpm view pyodide version` and its lockfile's numpy and
   pandas wheels; pin exact versions. Add `pyodide` as an optional peer of
   `@agent-native/core`, declared by apps that opt in (as `@duckdb/node-api`
   is declared by Analytics).
2. **Child entry.** `packages/core/src/coding-tools/python/child.ts`: loads
   Pyodide from disk, loads numpy and pandas from the vendored wheels,
   applies variant E exactly (the resolve hook through
   `module.registerHooks`, `pyodide_js` unregistered, an empty `js` module,
   `WebSocket` and `fetch` deleted, the `process.binding` shim), then reads one
   request from stdin: `{ code, input: { columns: string[]; data: unknown[][] } | null, maxOutputRows }`,
   binds `df` (a pandas DataFrame built from the columnar JSON) and runs the
   code. The program's result is the value of a variable named `result`
   (a DataFrame). It writes one response to stdout: `{ ok: true, output: { columns, data }, truncated, stdout }`
   or `{ ok: false, error: { kind: "python_error" | "no_result" | "bad_result"; message; traceback } }`.
   Only strings cross. No bridge in v1: the one channel is the input table in
   and the output table out (no `agent_bridge`, no provider calls, no
   network).
3. **Parent runner.** `packages/core/src/coding-tools/python/run-python.ts`:
   `runPython({ code, input, timeoutMs, memoryCapBytes, maxOutputRows, signal })`:
   - spawns `process.execPath` with `env: {}`, `--permission`,
     `--allow-fs-read=<vendored pyodide dir>`,
     `--disallow-code-generation-from-strings`, the hook, the child entry;
   - polls the child's RSS every 100 ms and SIGKILLs over `memoryCapBytes`;
   - SIGKILLs on `timeoutMs` or abort;
   - caps stdout and stderr bytes;
   - returns a typed result; a killed, crashed or silent child is a failed
     run with `reason: "timeout" | "memory" | "crashed" | "aborted" | "output_too_large"`,
     never empty output. The `listen()` crash surfaces as `crashed`.
   Cold start is paid per run in v1 (no warm pool); record it in the result
   as `coldStartMs`.
4. **Evaluator wiring.** `SandboxCodeEvaluator` gains `"python"`;
   `run-code` takes an optional `language: "javascript" | "python"` and
   dispatches to `runPython` with `input: null` when `python` is asked for
   and the app opted in, and fails with a typed `python_unavailable` error
   otherwise (never a silent fallback to JavaScript). Not exposed to the
   agent's prompt or tool description in this unit; 8.4f2 decides that.
5. **Opt-in and host check.** A core config field (read with
   `getAppConfig()`, per the configuration skill) `python.enabled`, default
   false. `runPython` also checks it is running inside the background function
   (`isInBackgroundFunctionRuntime`,
   `packages/core/src/agent/durable-background.ts:201`) on hosted runtimes and
   fails with `python_wrong_function` elsewhere, so a `server` call can never
   try to load files that are not there.
6. **Bundle scoping.** In `packages/core/src/deploy/build.ts`, add
   `copyInstalledPyodidePackages` and call it **after** the
   background function is cloned (`:4243`), into that function's directory
   only, and only when the app declares `pyodide`. Not in the shared copy
   block at `:6368-6382`. Exclude it from `pruneServerlessFunctionDeadWeight`
   (`:5698`) for that function. Record the background function's unzipped
   size before and after in the PR (spike: 42.4 MB to about 64 MB, about
   138 MB with DuckDB).
7. **Changeset.** `.changeset/<name>.md`, `minor` for `@agent-native/core`:
   optional Python evaluator for apps that opt in.
8. **Skills and docs.** None user-facing yet. Update
   `docs/plans/2026-10-13-analytics-operators/spikes/7.6-python-pyodide.md`
   (plan docs, not product docs) with the measured cold start from step 3.
   Four areas: UI none, actions none (core function only), skills none until
   8.4f2, application state none.

## 8. Defaults for open questions

- [Default] No bridge in v1; the input table is the only data channel.
- [Default] Memory cap 1.5 GB, timeout 60 s, output 100,000 rows.
- [Default] No warm pool; cold start per run.
- [Default] Off unless the app opts in.
- [Needs the owner] Condition 2, the security sign-off, and condition 3,
  Node 25 or accepting Node 24. Asked on 2026-10-14; the owner has not
  decided.

## 9. Do not

- Do not run Pyodide in a worker thread or in the agent function's own
  process.
- Do not copy Pyodide into `server` or any other cloned function.
- Do not pass environment variables, credentials or file paths to the child.
- No behavior changes outside the unit; additive-only schema; no new /api
  routes for app data (use actions); no raw fetch from client code; no
  process.env reads for provider credentials; no catch or default that turns a
  failure into a normal-looking value; no large payloads in SQL.
