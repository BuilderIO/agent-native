# 7.6 Python spike: Pyodide on the agent's server path

Lane C (Notebook). Size M. Not gated (no UI). Depends on nothing. The output is
a written result, not a feature.

Paths are relative to `templates/analytics/` unless they start with
`packages/`, `docs/` or `.tmp/`.

## 1. Goal

Decide, with numbers, whether Python cells (and Python in the agent's
`run-code`) can run on Pyodide inside the hosted serverless functions the
agent already uses, or must wait for a remote runner. The owner gets a short
document: bundle cost, cold start, pandas import and a real groupby, memory,
isolation, and a go or no-go with the conditions under which it would flip.
Nothing ships to users from this unit.

## 2. What the code does today

- Production `run-code` uses a hardened QuickJS runtime from the `run` package
  (`packages/core/src/coding-tools/run-code.ts:35`, `createRunner` at `:75`,
  description at `:125-127`), chosen when production code execution is
  `sandboxed` or `trusted` (`packages/core/src/server/agent-chat-plugin.ts:1955-1971`).
  The hosted Analytics deploy sets `AGENT_PROD_CODE_EXECUTION = "sandboxed"`
  (`netlify.toml`, `[build.environment]`).
- The QuickJS path calls the bridge directly in process
  (`run-code.ts:293-307`, `executeRunSandboxCode` at `:944-1000`). The
  `SandboxAdapter` seam (`packages/core/src/coding-tools/sandbox/adapter.ts`,
  `registerSandboxAdapter` and `AGENT_NATIVE_SANDBOX` in
  `sandbox/index.ts:47-54`) applies only to the `node` child-process evaluator
  (`run-code.ts:309-...`), not to the production QuickJS path.
- QuickJS has no WebAssembly, so Pyodide cannot run inside the existing
  sandbox; it needs the host Node runtime (a worker thread or child process).
- Agent work runs in `server-agent-background` with 4 GB of memory; every
  function has a 75 s timeout (`netlify.toml`, `[functions."*"]` and
  `[functions.server-agent-background]`). Background `run-code` gets a longer
  durable budget (`.agents/skills/analysis-workspace/SKILL.md:39-46`).
- Native or large packages reach the serverless bundle only through explicit
  copying in `packages/core/src/deploy/build.ts` (resvg precedent at
  `:5074-5090`).

Package facts from `npm view` on 2026-10-13 (re-check before installing):
`pyodide` `latest` is 314.0.7 (published 2026-09-14, 13.9 MB unpacked);
`stable-0.29` is 0.29.5 (12.6 MB). The npm package does not include pandas or
numpy wheels; by default `loadPackage` downloads them from a CDN at run time.

## Plan corrections

- Section 4 of the plan names the `SandboxAdapter` as the way in for full
  Python. That seam does not cover the production QuickJS path. A Pyodide
  runner would be a new evaluator next to `run`, or a remote runner behind a
  new seam; the spike should say which.
- "On the server path the agent uses" means the agent background function,
  not the page server. Measure there.

## 3. Build

All spike code lives in `.tmp/pyodide-spike/` (gitignored) and is pasted into
the result document. Do not add `pyodide` to any workspace `package.json`.

1. **Install in isolation.** `mkdir -p .tmp/pyodide-spike && cd .tmp/pyodide-spike && npm init -y && npm install pyodide@<latest checked>`.
   Download the numpy and pandas wheels that version's lockfile
   (`pyodide-lock.json`) names into `.tmp/pyodide-spike/wheels/` and load them
   from disk (`loadPackage` with local URLs or `indexURL` pointing at the
   folder), so no CDN fetch happens at run time.
2. **Bundle cost.** Record the bytes Pyodide core plus numpy plus pandas would
   add to a function (sum the files actually loaded; `fs.statSync`). Compare
   with the analytics function size measured in 7.2a (or measure it the same
   way: `NITRO_PRESET=netlify pnpm --filter analytics build`, then `du -sh`
   under `templates/analytics/.netlify/functions-internal/`).
3. **Timings.** In a fresh Node process, at the Node version the function uses,
   inside the `public.ecr.aws/lambda/nodejs` container image, record:
   `loadPyodide()` cold; `loadPackage(["numpy","pandas"])` cold; `import
   pandas`; a groupby plus merge over 100,000 rows passed in from JS; the same
   on a warm second call in the same process; peak RSS for each. Run each five
   times; report median and worst.
4. **Data in and out.** Measure passing 10,000 and 100,000 rows from JS to a
   DataFrame and back (JSON string versus `pyodide.toPy`), since cells and
   `run-code` would do this on every call.
5. **Isolation.** Python in Pyodide can reach JavaScript through `import js`
   and `pyodide.ffi`. Run Pyodide in a `worker_threads` Worker with
   `env: {}` and `resourceLimits`, and record whether Python code can read
   `process.env`, `require` modules, open sockets, or read files outside the
   Pyodide file system. List each attempt and its outcome. Note what a bridge
   to `providerFetch`/`appAction` would need (message passing to the parent,
   like the QuickJS host functions) without giving Python the parent's
   globals.
6. **Timeouts.** Confirm a runaway loop can be stopped (`worker.terminate()`,
   or Pyodide's interrupt buffer) within one second, and record memory after
   termination.
7. **Write the result** to
   `docs/plans/2026-10-13-analytics-operators/spikes/7.6-python-pyodide.md`
   with: versions; method; the tables from steps 2 to 6; the harness source;
   a decision (go, no-go, or go with conditions) using the rule in section 8;
   if go, the outline of a `python` evaluator next to `run` and its bridge;
   if no-go, what a remote runner must provide (the plan's section 4
   questions). Keep it free of internal names, URLs and figures beyond the
   measurements.
8. **Four areas.** UI: none. Actions: none. Skills: none until a Python
   feature exists; do not tell the agent Python is available. Application
   state: none. Say this in the result document.

## 8. Defaults for open questions

- **[Default] Decision rule:** go only if (a) Pyodide plus numpy plus pandas
  keep the agent function under 200 MB unzipped, (b) cold load plus pandas
  import is under 8 s median in the Lambda container, (c) a 100,000-row groupby
  finishes under 5 s warm, and (d) the isolation check finds no path from
  Python to `process.env`, Node modules, the network or the host file system.
  Any miss is no-go for the in-function path. Reviewer can change thresholds.
- **[Default] Wheels are vendored from disk**, never fetched from a CDN at run
  time.
- **[Default] Worker thread, not child process**, for the measurement; note the
  child-process cost if the worker fails isolation.
- **[Default] No Python UI or agent instructions** until a follow-up unit is
  approved on the result.
