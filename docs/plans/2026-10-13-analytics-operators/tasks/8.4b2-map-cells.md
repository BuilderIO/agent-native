# 8.4b2 Map cells and map panels

Lane E (Holy-shit features). Size M. Gated: the map panel, its settings and
the Map item in the add-cell menu are new UI; build only after the
"Notebook: map cell" and "Map: settings" screens in
`prototypes/analytics-operators/` are signed off. Where the signed-off
prototype differs from this brief, the prototype wins.

Depends on: 8.4b1 (the no-code spec and normalization boundary), 7.2b. Merge
after 8.4b1. Blocks: nothing.

Paths are relative to `templates/analytics/` unless they start with
`packages/`.

## 1. Goal

A founder with signups by country, or MRR by US state, or accounts with a
latitude and longitude, adds a Map cell under the result and sees a shaded
map (or dots) with a legend and a hover value, without writing code. The same
map works as a dashboard panel. The map draws from boundaries shipped with
the app, so no third-party tile server sees the user's data or their viewers.

## 2. What the code does today

- No map exists. `templates/analytics/package.json` has no leaflet, maplibre,
  mapbox, d3 or d3-geo, topojson or react-simple-maps; the only chart library
  is `recharts ^3.8.1` (`package.json:107`), plus `chart.js` and
  `chartjs-node-canvas` in devDependencies (`:90-91`).
- No code in the template handles countries, geo columns or GeoJSON.
- `PANEL_CHART_TYPES` (`app/pages/adhoc/sql-dashboard/types.ts:5-18`) has no
  map type, and new types are appended (plan README section 7, conflict
  table).
- Heavy client code is expected to load lazily, off the first paint
  (`.agents/skills/performance/SKILL.md`, "Protect startup and the first
  paint"); the dashboard page is already lazy-loaded through `AdhocRouter`.
- Email reports render charts server-side as SVG
  (`server/lib/report-chart-svg.ts`, used by
  `server/lib/dashboard-report-render.ts`).
- 8.4b1 defines `config.noCode` and compiles it once in
  `normalizeDashboardConfig` (brief `tasks/8.4b1-no-code-cells.md`).

## 3. Build

1. **Dependencies.** Read the repo rule on versions: run `pnpm view d3-geo
   version`, `pnpm view topojson-client version`, `pnpm view world-atlas
   version` and `pnpm view us-atlas version` and pin what is current. Check
   each license (the boundary data is Natural Earth and US Census derived;
   record the license names in the PR). No tile service and no API key.
2. **Assets.** The two TopoJSON files (world countries at 110m, US states at
   10m) are static assets served from the app's public directory and loaded
   with the app's asset helper on first map render. Never stored in SQL or
   application state. Add an ISO-3166 lookup (`shared/geo-codes.ts`) mapping
   alpha-2, alpha-3 and English names to the atlas ids, and US state codes and
   names to FIPS.
3. **Type and config.** Append `"map"` to `PANEL_CHART_TYPES` and the chart
   type lists. Add `map?: { kind: "countries" | "us-states" | "points"; locationKey?: string; valueKey?: string; latKey?: string; lngKey?: string; format?: "number" | "currency" | "percent" }`
   to `SqlPanelConfig`, registered with `onlyFor: ["map"]` and a value check.
   Add `{ kind: "map"; input: string; map: <same shape> }` to 8.4b1's
   `NoCodeSpec`; it compiles to `SELECT <location or lat, lng>, <value> FROM input`.
4. **Renderer.** `MapRenderer` in a lazy module
   `app/components/dashboard/MapRenderer.tsx` (dynamic import from the
   `SqlChart.tsx` dispatch, `:1471-1565`, with a map-shaped `Skeleton` while
   loading):
   - Countries and US states: SVG paths with `d3-geo` (Equal Earth for the
     world, Albers USA for states), fill on a sequential scale built from
     theme tokens only (`hsl(var(--chart-1))` at stepped opacity; no raw
     colors, `no-raw-colors` guard), missing locations in `hsl(var(--muted))`.
   - Points: dots on the same projection sized by value (capped radius), no
     basemap beyond the country outlines.
   - Legend with the scale's min and max formatted with
     `shared/table-cell-format.ts`. Hover tooltip with location and value.
     Keyboard: each shaded region is focusable with its label.
   - Unmatched locations: an amber note "{{count}} rows didn't match a
     location" with the first few values in a tooltip. Never drop them
     silently.
   - Click a region calls 8.4a1's `onDrillRequest` with the location value.
5. **Report render.** `server/lib/report-chart-svg.ts` renders the same
   projection and fills from the same pure `buildMapModel(rows, config)`
   (`shared/map-model.ts`), so email reports show the map.
6. **Settings (gated UI).** The Map cell's settings row (8.4b1's pattern):
   Reads from, Map type (`Select`: Countries, US states, Points), Location
   column, or Latitude and Longitude columns, Value column, Format. On a
   dashboard, the same controls appear in 1.2's toolbar for `map` panels.
7. **Verification.** `dashboard-panel-verification.ts`: missing columns are
   `missing-columns`; every row unmatched is `render-error` "None of these
   values match a country" (or state).
8. **Agent.** `mutate-dashboard` with `chartType: "map"` and `config.map`, or
   a no-code `map` spec in a notebook. No new action.
9. **Application state.** A clicked region publishes 8.4a1's `pointKey` and
   `pointValue`. No new key.
10. **Skills.** `.agents/skills/dashboard-management/SKILL.md` (a "Maps"
    subsection) and `.agents/skills/notebooks/SKILL.md` (map spec): accepted
    location formats, points need numeric lat and lng, and that unmatched rows
    are reported.
11. **Changelog.** `agent-native changelog add "Map panels and map cells for countries, US states and points" --type added`.

## 4. Copy

New namespace `mapPanel`. Add each key to `app/i18n/en-US.ts` and all ten
other catalogs in the same change: `app/i18n/ar-SA.ts`, `de-DE.ts`,
`es-ES.ts`, `fr-FR.ts`, `hi-IN.ts`, `ja-JP.ts`, `ko-KR.ts`, `pt-BR.ts`,
`zh-CN.ts`, `zh-TW.ts`. Plurals use i18next suffixes (`_one`, `_other` in
English; Arabic needs `_zero`, `_one`, `_two`, `_few`, `_many`, `_other`).

| Key | English |
| --- | --- |
| `panelEditor.chartTypeMap` | Map |
| `notebook.noCode.map` | Map |
| `mapPanel.type` | Map type |
| `mapPanel.countries` | Countries |
| `mapPanel.usStates` | US states |
| `mapPanel.points` | Points |
| `mapPanel.location` | Location column |
| `mapPanel.latitude` | Latitude |
| `mapPanel.longitude` | Longitude |
| `mapPanel.value` | Value column |

| `mapPanel.unmatched_one` | {{count}} row didn't match a location |
| `mapPanel.unmatched_other` | {{count}} rows didn't match a location |

is out of scope and listed in section 8. Run `pnpm guard:i18n-catalogs` and
`pnpm guard:i18n-changed-copy`. No em dashes.

## 8. Defaults for open questions

- [Default] Countries, US states and points only. Other subdivisions later.
- [Default] Boundaries ship with the app; no tile server and no basemap.
- [Default] Region names render in English from the atlas data.

## 9. Do not

- Do not call a third-party map or geocoding service.
- Do not geocode free-text addresses.
- No behavior changes outside the unit; additive-only schema; no new /api
  routes for app data (use actions); no raw fetch from client code; no
  process.env reads for provider credentials; no catch or default that turns a
  failure into a normal-looking value; no large payloads in SQL.
