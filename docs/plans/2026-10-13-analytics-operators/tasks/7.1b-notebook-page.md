# 7.1b Notebook page

Lane C (Notebook). Size M. **Gated: build only after the notebook prototype is
signed off.** Depends on 7.1a and 1.8 (the sidebar section pattern).

Paths are relative to `templates/analytics/` unless they start with
`packages/`, `prototypes/` or `docs/`.

## 1. Goal

Opening a notebook shows one readable column of cells in order: text, then a
query result, then a chart, and so on. Editors add a cell from a menu, edit SQL
inline, write Markdown, move cells up and down, and delete them, and every
change saves with history and undo like a dashboard edit. A legacy saved
analysis has an "Open as notebook" button. Notebooks have their own
Notebooks section in the sidebar and a Notebooks list page, and the
Dashboards section and list no longer show them.

## 2. What the code does today

- `/dashboards/:id` renders `AdhocRouter`, which lazy-loads the SQL dashboard
  page (`app/routes/dashboards.$id.tsx`, `app/pages/adhoc/AdhocRouter.tsx`).
  The page is one 2,730-line component
  (`app/pages/adhoc/sql-dashboard/index.tsx`). Its body renders the filter bar
  (`:2536-2544`), an empty state with `AddPanelPopover` (`:2547-2563`), then a
  drag-and-drop grid of `SqlChartCard`s grouped by sections (`:2565-2640`).
- Header actions are set with `useSetHeaderActions`
  (`app/pages/analyses/AnalysisDetail.tsx:196-235`; the dashboard page at
  `app/pages/adhoc/sql-dashboard/index.tsx:2029`).
- `SqlChartCard` owns the per-panel menu, edit and delete confirmation, and the
  section rendering (`app/pages/adhoc/sql-dashboard/SqlChartCard.tsx:160-175`,
  `:330-390`). `SqlChart` runs the query through `query-dashboard-panel`
  (`app/lib/sql-query.ts:152-160`).
- Panel SQL is edited in `PanelEditorDialog` with the shared `SqlEditor`
  (`app/pages/adhoc/sql-dashboard/PanelEditorDialog.tsx:15`, `:673`).
- Panel saves go through the dashboard save queue with optimistic updates and
  revision history (`app/pages/adhoc/sql-dashboard/dashboard-save-queue.ts`,
  `DashboardHistoryPanel`).
- `Markdown` renders escaped Markdown (`app/components/Markdown.tsx:6-27`).
- The legacy analysis page fetches with a helper that turns every failure into
  "not found" (`app/pages/analyses/AnalysisDetail.tsx:83-93`: `catch { return null }`).
  A network error therefore reads as "This analysis may have been deleted."
- The sidebar lists dashboards from `list-sql-dashboards`
  (`app/components/layout/Sidebar.tsx:1210`, rows built at `:1795-1812`) in
  the Dashboards section (`:2452`, header link to `/dashboards` with
  `IconChartBar`, filter popover, collapse chevron, "Show N more" after
  `SIDEBAR_PREVIEW_COUNT` rows). The collapsed sidebar draws
  `collapsedNavItems` (`:2180`); its Dashboards item and the section header
  are active through `isAdhocActive` (`:2163-2166`), which matches every
  `/dashboards` path. The Ask section (`AnalyticsChatsSection`, `:1367`) is
  the other section built this way.
- `/dashboards` renders `DashboardOverview` (`app/routes/dashboards._index.tsx`,
  `app/pages/DashboardOverview.tsx`): search, then Personal and Shared groups
  (`dashboardOverview.personal`, `dashboardOverview.shared`) with folders.
- Navigation state maps paths to views in `app/hooks/use-navigation-state.ts`
  (`:26-60`; `/dashboards/:id` is `view: "adhoc"`), and
  `commandPathForNavigation` (`:129`) maps the `navigate` action's views back
  to paths. `actions/navigate.ts:55-59` lists the views the agent can open;
  there is no notebooks view.
- Dashboard header actions (`app/pages/adhoc/sql-dashboard/index.tsx:2029-2235`)
  are all 32px. Views is `Button variant="ghost" size="sm"` with
  `className="text-xs gap-1.5"` and a 14px icon
  (`app/pages/adhoc/sql-dashboard/ViewsMenu.tsx:181-184`); Share is the
  toolkit `ShareTrigger`, an outline `ActionButton` `size="compact"`
  (`packages/toolkit/src/sharing/SharePrimitives.tsx:31-48`), which maps to
  `Button size="sm"` (`packages/toolkit/src/design-system/default-adapter.tsx:88-89`);
  Add panel is `Button size="sm" variant="outline"` with a 16px icon
  (`index.tsx:2086-2089`); the actions menu trigger is `Button size="sm"
  variant="ghost"` (`:2098-2106`). `size="sm"` renders `h-8 px-3`, or
  `px-2.5` with a direct icon child, at the base `text-sm` and a 16px icon
  (`packages/toolkit/src/ui/button.tsx:20`, `:43`). So Share and Add panel
  are 32px with 14px text, and Views is the compact treatment, 32px with
  12px text and a 14px icon. The actions menu (`:2090-2235`) holds Undo,
  Redo, Email reports, Dashboard history (`dashboard.historyTitle`), Archive
  and Delete permanently. The legacy analysis page puts a primary
  `size="sm"` Re-run in its header (`app/pages/analyses/AnalysisDetail.tsx:220-228`).
- The notebook prototype is `prototypes/analytics-operators/` (screens
  "Notebooks", "Notebook" and the other notebook screens in its Screen
  switch).

## Plan corrections

- Beyond 7.1a's, none in the data model: the page renders a dashboard whose
  `config.layout` is `notebook`, and notebook pages stay at
  `/dashboards/:id`. Only navigation changes: notebooks get their own
  sidebar section and list route (decided by the owner on 2026-10-13), and
  the list filters dashboard summaries by that layout.
- Fix found in passing and in scope because this unit adds a button to that
  page: `fetchAnalysis` must stop mapping errors to "not found". Absent and
  unreadable are different states.

3. **`app/pages/adhoc/notebook/NotebookBody.tsx`** (new): a centered single

   `NotebookCell`:
   - Text cell: `Markdown` when not editing; a `Textarea` (shadcn) when the
     editor clicks into it; save on blur and on Cmd/Ctrl+Enter. Empty text in
     view mode renders nothing for viewers; editors see the placeholder.
   - SQL cell: result table first via `SqlChartCard` with `chartType: "table"`;
     a collapsible SQL area below using `SqlEditor`, collapsed by default for
     viewers, expanded for the cell being edited. Run with the
     `IconPlayerPlay` button or Cmd/Ctrl+Enter.
   - Chart cell: the chart via `SqlChartCard`; SQL collapsed; chart type and
     source edited through the existing `PanelEditorDialog`.
   - Every cell has a hover toolbar: drag handle (`IconGripVertical`) and an
     options button (`IconDots`) opening a `DropdownMenu` with text-only items:
     Move up, Move down, Duplicate, Delete. Delete asks with an `AlertDialog`.
   - Between cells and at the end, an add button (`IconPlus`) opens a
     `DropdownMenu`, text-only items: SQL, Chart, Text. (7.5 adds Input.)
4. **Writes.** All edits go through the page's existing save path (the same
   path `SqlChartCard` edits use), so they are optimistic, roll back on error,
   and record revisions. Reorder writes the new panel order through the same

5. **Text cells on grid dashboards.** `SqlChartCard` renders a `text` panel

6. **Loading.** Cell skeletons use `DashboardPanelSkeleton` geometry for query

## 8. Defaults for open questions

- **[Default] Single column, no widths.** A notebook ignores `width`.
- **[Default] SQL collapsed for viewers, expanded while editing.**
- **[Default] Inline text editing is a Textarea with Markdown preview on blur**,
  not a rich-text editor.
- **[Default] "New notebook" creates a blank notebook directly**; asking the
  agent to build one stays available through chat.
- **[Decided by the owner, 2026-10-13] Notebooks get their own sidebar
  section and list page**, separate from Dashboards. They stay SQL
  dashboards with `layout: "notebook"` (7.1a) and keep their
  `/dashboards/:id` pages.
- **[Default] Move up and Move down in the menu as well as drag**, so reorder
  works by keyboard and on touch.

## 9. Do not

- No behavior changes outside this unit. Grid dashboards look and behave the
  same, except that `text` panels now render.
- Additive-only schema (none needed here).
- No new `/api` routes for app data; use actions and the existing save path.
- No raw `fetch` from client code; use `useActionQuery` / `useActionMutation`.
- No `process.env` reads for provider credentials.
- No `catch` or default that turns a failure into a normal-looking value.
- No large payloads in SQL or application state.
- No page title that repeats the route, no subtitle under the title, no
  count strip, no leading icons in menus, no em dashes, no browser `confirm`.
- Do not build custom dropdowns or modals; use shadcn primitives.
