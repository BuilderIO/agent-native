# 2.1a Postgres as a query source

Lane B (Founders). Size M. Not gated (no new surface; adds an option to existing pickers).

Paths are relative to `templates/analytics/` unless they start with `packages/`.

## 1. Goal

A founder who pastes their production Postgres URL on Data sources can ask the
agent a question and get an answer computed from that database, and can put a
panel on a dashboard whose source is that database. Every query runs read-only,
stops after a fixed time, and returns at most a fixed number of rows, with an
honest "truncated" flag when the cap cut the result. Nothing the agent or a
panel sends can write to the connected database.

## 2. What the code does today

- The only runtime reader of `POSTGRES_URL` is the connection test:
  `server/routes/api/test-connection.post.ts:149-154` resolves the credential
  and calls `testConnection()` from `server/lib/postgres.ts`. The other
  references are declarations: `server/lib/credential-keys.ts:62` (key),
  `:195-199` (provider `postgresql`), `:320-321` (aliases `postgres`,
  `postgresql`), and the Data sources card in `app/lib/data-sources.ts:357-383`.
- `server/lib/postgres.ts`:
  - `:11-16` resolves `POSTGRES_URL` through the request credential context.
  - `:24-41` imports `postgres` dynamically and, on any failure, throws
    "postgres package not installed. Run: pnpm add postgres". The comment at
    `:26-28` calls it an optional dependency. It is not:
    `package.json:41` lists `"postgres": "^3.4.9"`. The catch also turns every
    construction error (bad URL, bad option) into the same misleading message.
  - `:44-53` `runQuery` calls `client.unsafe(sql)` with no transaction, no
    `statement_timeout`, no row cap. With no params, postgres.js uses the
    simple query protocol (`node_modules/.pnpm/postgres@3.4.9/node_modules/postgres/src/index.js:119-125`
    sets `simple: args.length === 0`), which runs every statement in the text.
    Core already documents this trap in
    `packages/core/src/scripts/db/postgres-client.ts:95-102` and passes
    `{ simple: false }` to force one statement.
  - `:55-66` `testConnection` runs `SELECT 1`.
- Panel sources are a closed list in `server/lib/dashboard-panel-query.ts:21-29`
  (`bigquery`, `ga4`, `amplitude`, `first-party`, `demo`, `prometheus`,
  `program`). `runDashboardPanelQuery` (`:404-516`) dispatches by source and
  ends with `throw new Error("Unsupported source")` at `:515`.
  `missingCredential` (`:123-138`) returns the typed `missing_api_key` shape.
- The same list is copied by hand in six more places, so adding a source today
  means editing seven lists:
  - `actions/mutate-dashboard.ts:94-103` (zod enum on panel ops)
  - `actions/update-dashboard.ts:396-404` (`validSources`)
  - `app/pages/adhoc/sql-dashboard/types.ts:1-8` (`DataSourceType`)
  - `app/pages/adhoc/sql-dashboard/PanelEditorDialog.tsx:68-76` (`SOURCES` with labels)
  - `app/routes/chart.tsx:24-31` (`VALID_SOURCES` for `/chart` embeds)
  - `app/components/AnalyticsReviewArtifactPreview.tsx:29-37` (`DATA_SOURCES`)
  `actions/query-dashboard-panel.ts:15` and
  `server/lib/dashboard-panel-source-resolver.ts:55-56` already derive from
  `DASHBOARD_PANEL_SOURCES`.
- Dashboard filter interpolation: `app/pages/adhoc/sql-dashboard/interpolate.ts:47-56`
  enables custom date ranges only for `bigquery` and `first-party`, and picks
  GoogleSQL escaping only for `bigquery`; everything else gets standard
  doubled-quote escaping (`:1`), which is correct for Postgres.
- Write verification (`server/lib/dashboard-panel-verification.ts`): `program`
  panels are skipped as unverified (`:513-519`); BigQuery gets a dry run
  (`:547-550`); every other source executes through `runResolvedPanel` with
  `timeoutMs` and an abort `signal` (`:571-578`). A Postgres panel will execute
  here, so it must honor both.
- Existing read-only precedent in this template:
  `server/lib/read-only-sql.ts:121-144` `assertReadOnlySql` (single
  `SELECT`/`WITH`, no `INTO`, no row locks, no mutating words) and
  `server/lib/db-admin-federated-read.ts:415-418` (wrap in
  `SELECT * FROM (...) LIMIT cap+1`) plus `:436-440` (`SET TRANSACTION READ ONLY`
  inside a transaction). That path serves admin-connected agent-native app
  databases, not the user's `POSTGRES_URL`, and should not be reused for it.
- Agent answer path for BigQuery: `actions/bigquery.ts:174-185` (description,
  `readOnly`, `toolCallable`, `grounding: true`), typed stops for missing
  config (`:36-50`), repeated failed SQL (`:122-170`), and `sql_run` tracking
  (`:87-104`). `bigquery` is in the starter tool list
  `server/lib/agent-chat-plan-mode.ts:1-22`. `grounding: true` is what makes
  the final-response guard count a call as a real data query
  (`server/lib/real-data-actions.ts:80-93`).
- SSRF helper exists: `packages/core/src/extensions/url-safety.ts:87-106`
  (`isBlockedExtensionUrl`) and `:116` (`isBlockedExtensionUrlWithDns`); both
  accept only http(s) URLs, so a Postgres host has to be checked by building an
  `https://<host>` URL from it. `getDatabaseUrl()` is at
  `packages/core/src/db/client.ts:102`.

### Plan corrections

- The plan cites `server/lib/dashboard-panel-query.ts:416` for the source list.
  The list is at `:21-29`; `:404-516` is the dispatcher.
- The plan says only `test-connection.post.ts` uses `POSTGRES_URL`. That is
  right for runtime reads; `credential-keys.ts` and `app/lib/data-sources.ts`
  also declare it.
- The plan does not mention the simple-protocol trap. A read-only transaction
  alone is not enough: with `client.unsafe(sql)` a string like
  `SELECT 1; COMMIT; DELETE FROM t` ends the read-only transaction and runs the
  delete. The fix is `{ simple: false }` (one statement per call) plus the
  parser check plus the read-only transaction.
- The plan's 2.1 bundles schema reading. That is split into 2.1b so this unit
  stays M.

2. **Rewrite `server/lib/postgres.ts`** (keep the file, keep `getPostgresClient`
   cache keyed by credential scope and URL hash):
   - Static `import postgres from "postgres"`; delete the try/catch and the
     "not installed" message at `:24-41`.
   - Client options: `max: 3`, `idle_timeout: 30`, `connect_timeout: 10`,
     `prepare: false` (works through PgBouncer), `ssl` from the URL's
     `sslmode`; when the URL has none and the host is not local, use
     `"require"` (see Defaults).
   - Host check before connecting, in a pure helper
     `assertPostgresHostAllowed(url, { hosted })`: on a hosted runtime
     (`isProductionServerlessRuntime()` from
     `server/lib/production-serverless-runtime.ts`), reject private, loopback,
     link-local and metadata hosts using `isBlockedExtensionUrlWithDns` on
     `https://<host>`, and reject a URL whose host, port and database match
     `getDatabaseUrl()` (the app's own database). Local dev allows localhost.
     Throw a typed `PostgresSourceError` with `code: "host_not_allowed"`.
   - New `runReadOnlyQuery(sql, { timeoutMs, maxRows, signal })`:
     `assertReadOnlySql(sql)` from `server/lib/read-only-sql.ts`; then
     `client.begin(async (tx) => { await tx.unsafe("SET TRANSACTION READ ONLY"); await tx.unsafe(\`SET LOCAL statement_timeout = ${ms}\`); await tx.unsafe("SET LOCAL idle_in_transaction_session_timeout = ...") ; const rows = await tx.unsafe(wrapped, [], { simple: false }); ... })`
     where `wrapped` is `SELECT * FROM (<sql without trailing ;>) AS "__analytics_pg_source" LIMIT <maxRows + 1>`.
     End the transaction with a rollback (throw a sentinel and catch it, as
     `packages/core/src/scripts/db/query.ts:115-130` does), never commit.
     Wire `signal` to postgres.js query `.cancel()`.
   - Map result columns to `schema: { name, type }[]` from postgres.js
     `result.columns` type OIDs: int2/int4/float4/float8 to `number`; int8 and
     numeric to `number` only when every value in the column converts without
     loss (`Number.isSafeInteger` for int8, finite and string round-trip for
     numeric), otherwise the column stays `string`; bool to `boolean`;
     date/timestamp/timestamptz to `string` (ISO); json/jsonb to `json`;
     everything else `string`. Clip any cell longer than 2,000 characters and
     return `truncatedCells`. Return
     `{ rows, schema, truncated, truncatedCells, durationMs }`.
   - Typed errors: `PostgresSourceError` with `code` in
     `not_configured | host_not_allowed | invalid_sql | timeout | cancelled | permission | connection | query_failed`.
     Classify from the postgres.js error `code` (SQLSTATE `57014` timeout,
     `42501` permission, `25006` read-only violation becomes `invalid_sql`,
     connection errors by `errno`), not by message text. Redact the URL from
     any message.
   - Keep `testConnection()` but run it through the same host check and
     return the typed code on failure.

## 8. Defaults for open questions

Each is a decision a reviewer can change.

- **D1** Action name `postgres`, matching `bigquery` and `prometheus`.
- **D2** Row cap 5,000 for both panels and the agent; panel timeout 25 s
  (inside the 25 s panel budget data programs use), agent timeout 30 s.
- **D3** Any member who can resolve the `POSTGRES_URL` credential can query it,
  the same model BigQuery uses. No extra role gate.
- **D4** Hosted runtimes block private and loopback hosts and the app's own
  database; local dev allows localhost.
- **D5** SSL: honor `sslmode` in the URL; if absent and the host is not
  local, require TLS. No silent fallback to plaintext.
- **D6** int8 and numeric columns become numbers only when lossless.
- **D7** Postgres panels are embeddable in `/chart` (they run with the viewer's
  credential, like BigQuery).
- **D8** Source label is the provider name, not translated.
- **D9** The grandfathered `/api/test-connection` route stays as is; migrating
  it to an action is a separate task.

## 9. Do not

- No behavior changes outside this unit (do not touch BigQuery, first-party or
  db-admin read paths beyond importing the shared source list).
- Schema changes: none expected; if any appear, additive only.
- No new `/api` routes for app data; everything goes through actions.
- No raw `fetch` from client code.
- No `process.env` reads for provider credentials; `POSTGRES_URL` comes only
  from `resolveCredential` in the request context.
- No `catch` or default that turns a failure into a normal-looking value:
  a timeout, permission error or blocked host is never `{ rows: [] }`, and a
  truncated result always says `truncated: true`.
- No large payloads in SQL; do not cache result rows in settings or
  `application_state`.
- Do not call `client.unsafe(sql)` without `{ simple: false }` anywhere.
- Do not reuse `db-admin-connections` for the user's database.
