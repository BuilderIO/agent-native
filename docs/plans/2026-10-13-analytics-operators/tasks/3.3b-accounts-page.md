# 3.3b: Accounts page to review and edit the account map

Lane B. Size M. Needs 3.3a.

## 1. Goal

An Accounts page lists every account in the map with its Stripe customers,
HubSpot companies and product users. A person can find an account, see why
records were matched, confirm or reject a match, move a record to another
account, merge two accounts and run a sync, all by clicking. The agent sees
which account is open and can make the same edits through the same actions.

## 2. What the code does today

- No accounts surface exists. The sidebar has two nav lists: the collapsed
  rail `collapsedNavItems` (`templates/analytics/app/components/layout/Sidebar.tsx:2180-2224`,
  Semantic Layer at `Sidebar.tsx:2218-2223`) and the expanded list (Semantic
  Layer link at `Sidebar.tsx:2438-2448`).
- Routes are file-based (`templates/analytics/app/routes.ts:1-6`); a page
  route is a thin wrapper with a `meta` title from the catalog
  (`templates/analytics/app/routes/semantic-layer.tsx:1-10`).
- The closest list-plus-detail page is Semantic Layer: search, infinite list
  through `useActionQuery` and `useInfiniteQuery`, a side panel for one entry
  (`templates/analytics/app/pages/SemanticLayer.tsx:1-30`,
  `templates/analytics/app/components/semantic-layer/DefinitionPanel.tsx`).
- Navigation state is written by `useNavigationState`
  (`templates/analytics/app/hooks/use-navigation-state.ts:8-21` for the
  shape, `use-navigation-state.ts:30-80` for path parsing). The `navigate`
  action validates views and aliases (`templates/analytics/actions/navigate.ts:44-60`),
  and `view-screen` describes each view (`templates/analytics/actions/view-screen.ts:760-761`
  for Semantic Layer; selection read at `view-screen.ts:173`).
- shadcn primitives available: table, sheet, dropdown-menu, dialog, command,
  input, button, badge, skeleton, tooltip, toggle-group
  (`templates/analytics/app/components/ui/`).
- Navigation copy lives in `navigation.*` and route titles in
  `routeTitles.*` (`templates/analytics/app/i18n/en-US.ts:147-169`,
  `en-US.ts:547`).

## 3. Build

1. Route `templates/analytics/app/routes/accounts.tsx` (title from
   `routeTitles.accounts`). The selected account is a search param
   `?account=<id>` so links are shareable and Cmd-click works; no second
   route.
2. Page `templates/analytics/app/pages/Accounts.tsx`:
   - Toolbar: search `Input` (debounced, server-side via `list-accounts`
     `search`), a `ToggleGroup` with "All" and "Needs review", and an
     outline `Button` "Sync accounts" with the last sync time beside it
     ("Synced {{time}}" using `useFormatters` relative time). While a sync is
     running per provider, show a `Spinner` in the button and the provider
     names in a `Tooltip`.
   - `Table` with columns Account (name, domain below in muted text), Stripe,
     HubSpot, Product users (counts), and a "Needs review" `Badge` when
     flagged. No page title (the nav item names the page). Rows are links to
     `?account=<id>` using the app's native link component so Cmd-click and
     middle-click open a new tab (read `native-navigation`).
   - Infinite scroll with `nextCursor`; `Skeleton` rows matching the table
     geometry while loading.
   - Empty states: no sync yet and at least one of Stripe or HubSpot
     connected: "No accounts yet" with a primary "Sync accounts" button.
     Nothing connected: "Connect Stripe or HubSpot to build your account
     map." with a link to Data Sources. Search with no results: "No accounts
     match your search."
3. Detail `Sheet` (`templates/analytics/app/components/accounts/AccountSheet.tsx`):
   - Header: account name and domain; a `DropdownMenu` (text-only items):
     "Rename…", "Merge into…".
   - Links grouped by provider. Each link row: label, email or domain, how it
     matched ("Same domain", "Same email", "Set by hand"), decision, and when
     stale "Not seen in the latest sync". Row `DropdownMenu`: "Confirm
     match", "Not this account", "Move to another account…", "Move to a new
     account".
   - "Move to another account…" and "Merge into…" open a `Dialog` with a
     `Command` search over `list-accounts`.
   - "Rename…" opens a `Dialog` with name and domain inputs.
   - All edits are optimistic through `useActionMutation`, roll back on
     error with a toast mapped from the action's `errorCode`. Merge shows a
     toast with Undo that calls `unmerge-accounts`.
4. Sidebar: add an "Accounts" item with Tabler `IconBuilding` after
   Data sources and before Semantic Layer in both nav lists in
   `templates/analytics/app/components/layout/Sidebar.tsx` (the lists are
   Ask, Dashboards, Sessions, Monitoring, Agents, Data sources, Semantic
   Layer; there is no Analyses item, `/analyses` redirects to
   `/dashboards`). Check that
   `MobileNav.tsx` renders the same list; if it keeps its own, add it there
   too.
5. Application state:
   - `navigation`: `view: "accounts"`, `accountId` when the sheet is open
     (`use-navigation-state.ts`).
   - `selected-object`: `{ type: "account", id, name }` while the sheet is
     open; cleared on close.
   - `navigate` (`templates/analytics/actions/navigate.ts`): accept
     `view: "accounts"` and `accountId`; update the view list in the
     description.
   - `view-screen` (`templates/analytics/actions/view-screen.ts`): for
     `accounts`, report the search, the filter, and, when open, the account's
     name, domain and link counts by provider (read through `get-account`,
     not the whole list).
6. Skills and instructions:
   - `templates/analytics/.agents/skills/context-awareness/SKILL.md`: the
     `accounts` view and `selected-object` type `account`.
   - `templates/analytics/.agents/skills/cross-source-analysis/SKILL.md`
     "Account map" section (from 3.3a): point users to the Accounts page for
     reviewing matches; when the user says "this account", read
     `selected-object`.
7. Actions: none new; uses 3.3a's `list-accounts`, `get-account`,
   `sync-account-map`, `update-account-link`, `merge-accounts`,
   `unmerge-accounts`, `rename-account`.
8. Changelog: `agent-native changelog add "New Accounts page shows each customer across Stripe, HubSpot and your product, with matches you can confirm, move or merge." --type added`.

## 8. Defaults for open questions

- DECISION: the nav item is "Accounts" and sits after Data sources,
  before Semantic Layer.
- DECISION: the selected account lives in `?account=` rather than a nested
  route.
- DECISION: no bulk edit in v1; one link or one merge at a time.
- DECISION: the page builds directly without an HTML prototype, per the plan's
  section 7 list. Reviewer may ask for one.

## 9. Do not

- No behavior changes outside this unit.
- Additive-only schema; none expected here.
- No new `/api` routes for app data; use 3.3a's actions.
- No raw `fetch` from client code; use `useActionQuery` / `useActionMutation`.
- No `process.env` reads for provider credentials.
- No `catch` or default that turns a failure into a normal-looking value: a
  failed list load shows the error state, never an empty table.
- No large payloads in SQL or app state; `selected-object` carries ids and a
  name only.
- No custom positioned popovers, no browser `confirm`; use shadcn dialogs.
- No subtitle under the page, no count strip, no leading icons in menus.
