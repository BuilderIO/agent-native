# 2.2c Google Analytics (GA4) with one-click Google sign-in

Lane B (Founders). Size M. Not gated.

Paths starting with `packages/` are repo-relative; everything else is relative
to `templates/analytics/`. Changes `packages/core`; needs a `.changeset/*.md`.

## 1. Goal

A founder connects Google Analytics by clicking Connect, signing in with
Google, and picking their GA4 property from a list. No Google Cloud project, no
service account, no JSON key. GA4 panels, the seeded Google Analytics
dashboard, the agent and data programs all use that connection. The service
account path keeps working for teams that already use it.

## 2. What the code does today

- GA4 auth is service-account only. `server/lib/google-analytics.ts:22-64`
  signs a JWT from `GOOGLE_APPLICATION_CREDENTIALS_JSON` with scope
  `analytics.readonly` and exchanges it at Google's token endpoint; the token is
  cached per credential scope (`:66-78`). The property comes from the
  `GA4_PROPERTY_ID` credential (`:15-20`). `runReport` posts to
  `/properties/{id}:runReport` (`:110-152`).
- The Data sources card walks through creating a Cloud project, enabling the
  API, creating a service account, granting it in GA4 Admin and uploading the
  JSON (`app/lib/data-sources.ts:94-151`, six steps).
- Panels require both credentials: `server/lib/dashboard-panel-query.ts:429-443`
  returns `missing_api_key` when either `GA4_PROPERTY_ID` or
  `GOOGLE_APPLICATION_CREDENTIALS_JSON` is absent. Test connection does the
  same (`server/routes/api/test-connection.post.ts:70-80`).
- Provider status: `server/lib/credential-keys.ts:160-164` requires both keys
  for `google-analytics`.
- Saving GA credentials seeds the Google Analytics dashboard once
  (`actions/update-data-source-credentials.ts:143-161`). That action is
  `agentTool: false` (`:90`), so the agent cannot set a property today.
- Core provider API `ga4` uses `type: "google-service-account"`
  (`packages/core/src/provider-api/index.ts:874-909`) with
  `allowedHostSuffixes: ["googleapis.com"]`; auth dispatch for that type is at
  `:4018-4031`.
- Google workspace OAuth already exists for Gmail, Calendar, Docs, Drive,
  Sheets and Slides. Sheets is the precedent for an isolated grant: its catalog
  entry uses its own OAuth provider name so its scope is not merged with other
  Google grants (`packages/core/src/connections/catalog.ts:270-282`), the
  provider API resolves it through `workspaceProvider: "google_sheets"`
  (`provider-api/index.ts:1266-1295`), refresh dispatch lists it
  (`:4855-4860`) and the background refresher lists it
  (`packages/core/src/oauth-tokens/google-refresh.ts:71`).
- The Google provider predicate is duplicated:
  `packages/core/src/server/workspace-provider-oauth.ts:99-108`
  (`isGoogleWorkspaceOAuthProvider`) and
  `packages/core/src/server/auth.ts:3335-3352`
  (`isWorkspaceGoogleOAuthProvider`).
- One-click sources in the UI are a fixed set
  (`app/lib/data-source-status.ts:83-88`) without Google Analytics.

### Plan corrections

- The plan groups GA4 and Sheets as one OAuth job. Sheets OAuth already exists
  (`google_sheets`, `drive.file` scope, used by the panel export at
  `server/lib/google-sheets-export.ts:98-117` and shown on Data sources at
  `app/pages/DataSources.tsx:2270-2297`). Only GA4 needs new OAuth. Reading an
  existing Sheet for import is 2.3c, and it needs Google Picker because
  `drive.file` only reaches files the user picks or the app created.

## 3. Build

### Core (`packages/core`)

1. **Provider.** After 2.2b exports `WORKSPACE_OAUTH_PROVIDERS`, add
   `"google_analytics"`. Make `isGoogleWorkspaceOAuthProvider` include it and
   delete the duplicate predicate in `server/auth.ts:3335-3352` in favor of
   importing the one from `workspace-provider-oauth.ts`.
2. **Catalog entry** in `connections/catalog.ts`, next to `google_sheets`:
   `id: "google_analytics"`, `label: "Google Analytics"`,
   `credentialKeys: GOOGLE_CREDENTIAL_KEYS`, `capabilities: ["search"]`,
   `recommendedTemplateUses: ["analytics"]`,
   `oauth: googleOAuth([...GOOGLE_IDENTITY_SCOPES, "https://www.googleapis.com/auth/analytics.readonly"], "google_analytics")`.
3. **Refresh.** Add `google_analytics` to the Google branch of the refresh
   dispatch (`provider-api/index.ts:4855-4860`) and to the background list in
   `oauth-tokens/google-refresh.ts:71`. Better: export one
   `ISOLATED_GOOGLE_OAUTH_PROVIDERS` constant and use it in both places.
4. **Provider API auth.** Add auth type
   `oauth-bearer-or-google-service-account` with `oauthProvider`,
   `workspaceProvider`, `tokenLabel`, `scopes`. Change `ga4` to
   `{ type: "oauth-bearer-or-google-service-account", oauthProvider: "google_analytics", workspaceProvider: "google_analytics", tokenLabel: "Google Analytics OAuth token", scopes: [analytics.readonly] }`.
   In auth dispatch, try a granted workspace connection first and fall back to
   the service account. Teach `describeAuth` (`:3483-3495`) and
   `resolveProviderApiOAuthAccessToken` (`:2217-2251`) the new type. That
   function already maps three dual types by hand; replace the ternary with one
   `oauthBearerPart(auth)` helper that covers all four.
5. **Changeset**: `@agent-native/core` minor: "Add Google Analytics as an
   isolated Google workspace OAuth connection".

### Analytics (`templates/analytics`)

6. **Token.** In `server/lib/google-analytics.ts`, `getCachedToken` first calls
   `resolveProviderApiOAuthAccessToken({ provider: "ga4" }, { appId: ANALYTICS_APP_ID, providerIds: ["ga4"], getCredentialContext: () => ctx })`
   when a `google_analytics` connection is granted to Analytics
   (`resolveWorkspaceConnectionForApp`), else uses the service account. Key
   the token cache and the report cache (`:120-123`) by credential source and
   connection id. A connection that needs reauthorization surfaces as that
   state, never as falling back to a different account's service key.
7. **Readiness helper** `resolveGa4Readiness(ctx)` in the same file, returning
   `{ status: "ready", via: "oauth" | "service_account" } | { status: "needs_property" } | { status: "not_connected" } | { status: "needs_reauth" }`.
   Use it in `dashboard-panel-query.ts:429-443` (replace the two
   `missingCredential` calls; `needs_property` and `not_connected` return the
   same `missing_api_key` shape with the existing keys, `GA4_PROPERTY_ID` or
   `GOOGLE_APPLICATION_CREDENTIALS_JSON`, and
   `settingsPath: "/data-sources?source=google-analytics"`; do not invent a new
   key name, the UI keys off it), in
   `server/routes/api/test-connection.post.ts:70-80`, and in
   `actions/data-source-status.ts` for the `google-analytics` provider.
8. **Property list action** `actions/list-ga4-properties.ts`: `readOnly`,
   agent-callable, `grounding: false`. Calls
   `GET https://analyticsadmin.googleapis.com/v1beta/accountSummaries` through
   `executeProviderApiRequest({ provider: "ga4", ... })` (host is allowed by
   `googleapis.com`). Returns `[{ propertyId, displayName, accountName }]`,
   capped at 200 with `truncated`. Errors are typed: not connected, needs
   reauth, API not enabled (Google's `SERVICE_DISABLED`).
9. **Set property action** `actions/set-ga4-property.ts`: agent-callable;
   validates the id is in `list-ga4-properties`, saves `GA4_PROPERTY_ID`
   through `saveCredential` with `resolveCredentialSaveScope`, then runs the
   same one-time dashboard seed. Move the seed out of
   `update-data-source-credentials.ts:143-161` into
   `server/lib/dashboard-seeds.ts` (`seedGoogleAnalyticsDashboardOnce`) and call
   it from both actions; keep its existing warn-and-continue behavior and do
   not change when it runs for the key path.
10. **Status mapping.** `app/lib/data-source-status.ts`: map
    `"google-analytics"` to `"google_analytics"` in
    `dataSourceWorkspaceProviderIds` and add it to `workspaceOAuthSourceIds`.
    Gate the button on `oauthAvailable` (field added by 2.2b) from
    `hasWorkspaceProviderOAuthCredentials("google_analytics")`.
11. **UI** in the Google Analytics source detail of `app/pages/DataSources.tsx`:
    - When OAuth is available: `WorkspaceOAuthView` with Connect. After
      connect, a shadcn `Select` of properties from
      `useActionQuery("list-ga4-properties")` (Skeleton row while loading) and
      a primary `Button` "Use this property" that calls `set-ga4-property`
      through `useActionMutation` with an optimistic selected state and
      rollback on error.
    - The six service-account steps move behind a ghost `Button` disclosure
      "Use a service account instead" (`Collapsible`). Shown expanded when the
      service account is already configured.
    - When OAuth is not available on the deployment, the card is unchanged.
12. **Onboarding.** Register an optional `google-analytics` step with
    `isAvailable: () => hasWorkspaceProviderOAuthCredentials("google_analytics")`,
    link to `/_agent-native/connections/oauth/google_analytics/start?scope=organization&appId=analytics&return=/data-sources?source=google-analytics`,
    complete when `resolveGa4Readiness` is `ready`. Same module as 2.2b's
    Stripe step.
13. **Application state.** None new; `?source=google-analytics` focuses the
    card. `view-screen` for data sources adds `ga4: { status, via }` so the
    agent knows whether to call `list-ga4-properties` next.
14. **Skills.** Template `.agents/skills/provider-api/SKILL.md` GA4 notes:
    prefer the Google Analytics connection; if `data-source-status` shows
    `needs_property`, call `list-ga4-properties` and ask the user which one,
    then `set-ga4-property`. Template `.agents/skills/data-querying/SKILL.md`:
    one line under sources.
15. **Changelog.** Only when the deployment's Google client has the scope
    approved (D4). Then:
    `agent-native changelog add "Connect Google Analytics with Google sign-in and pick your property from a list" --type added`.

## 8. Defaults for open questions

- **D1** Isolated grant `google_analytics`, like Sheets, so connecting GA4
  never widens another Google connection's scopes.
- **D2** OAuth wins over a service account when both exist.
- **D3** The property id stays in the `GA4_PROPERTY_ID` credential (one
  resolver per key); `set-ga4-property` writes it.
- **D4** No changelog entry until the shared Google client is verified for
  `analytics.readonly`.
- **D5** One property per scope, as today. Multi-property is out of scope.
- **D6** Default connection scope is organization.

## 9. Do not

- No behavior changes outside this unit: the service-account path, its seed
  timing and its cache must behave as before.
- Additive-only schema; none expected.
- No new `/api` routes; OAuth uses the core framework routes.
- No raw `fetch` from client code.
- No `process.env` reads for provider credentials; Google client credentials
  come from the managed client through core.
- No `catch` or default that turns a failure into a normal-looking value: a
  connection that needs reauthorization is reported as such; an empty property
  list says why.
- No large payloads in SQL.
- Do not request any Google scope beyond identity and `analytics.readonly`.
