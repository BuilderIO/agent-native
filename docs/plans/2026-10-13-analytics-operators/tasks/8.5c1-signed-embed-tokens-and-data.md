# 8.5c1 Signed embedding: embed keys, signed tokens and scoped panel data

Lane E (Holy-shit features). Size M. Not gated by a prototype (server only;
8.5c2 carries the UI). **Needs the owner's call on whose credentials an embed
runs with (section 8) before building.**

Depends on: 7.5 (published apps), 1.7b (built: share surfaces). Blocks: 8.5c2.

The plan's 8.5c is split in two: 8.5c1 (this unit) adds embed keys, token
verification and the public data read; 8.5c2 adds the embed page, frame
policy and the Embed tab.

Paths are relative to `templates/analytics/` unless they start with
`packages/`. Read `.agents/skills/sharing`, `.agents/skills/security` and
`.agents/skills/secrets` first.

## 1. Goal

A company that uses Analytics can show a dashboard or a published notebook
app inside its own product. Its server signs a short-lived token naming the
embed and the viewer's scope ("customer = acme"), and the embedded view shows
only that customer's rows. Without a valid, unexpired token, nothing loads.
The host never gets an Analytics login, a provider key or the panel SQL.

## 2. What the code does today

- Sharing has `private`, `org` and `public` visibility; `public` still means
  a signed-in user with the link, and anonymous URLs are "a different axis and
  are NOT controlled by the sharing system" (`.agents/skills/sharing/SKILL.md:28-32`,
  `:52-54`). The security skill allows a custom route for "public
  unauthenticated resources" with its own checks (`.agents/skills/security/SKILL.md:50-53`).
- Signed, scoped, expiring tokens already exist: `createScopedAgentAccessGrant`,
  `signScopedAgentAccessToken` and `verifyScopedAgentAccessToken`
  (`packages/core/src/server/agent-access.ts:40`, `:55`, `:69`), with the
  shared secret chain in `packages/core/src/server/short-lived-token.ts:34-43`.
  Analytics uses them for dashboard agent links
  (`server/routes/api/dashboard-agent-context.json.get.ts`: `no-store` and
  `no-referrer` at `:66-68`, verify at `:78-83`, a reviewed unscoped read at
  `:85`) and replay links (`server/lib/session-replay-agent-context.ts:661-708`).
  Those tokens are minted by Analytics itself; nothing lets a host server mint
  one.
- Core MCP embed sessions (`packages/core/src/server/embed-session.ts`) act as
  the user who minted them; they are for MCP hosts, not anonymous viewers.
- Unauthenticated paths are listed in `server/plugins/auth.ts:19-48`
  (`publicPaths`, `publicPathsWithQueryToken`), including one public action,
  `/_agent-native/actions/get-public-status-page`
  (`actions/get-public-status-page.ts`, read-only GET).
- `query-dashboard-panel` runs raw SQL from the client with the caller's
  credentials and checks no dashboard access (`actions/query-dashboard-panel.ts:36-44`,
  `:62-66`); `/chart` decodes a whole panel, SQL included, from the URL
  (`app/routes/chart.tsx:30-71`). Neither may become an embed path.
- There is no row-level scoping or locked filter on dashboards: filters are
  URL params (`app/pages/adhoc/sql-dashboard/filter-vars.ts:4`, `:163-221`).
- App secrets: `writeAppSecret` and `readAppSecret`
  (`packages/core/src/secrets/storage.ts:93`, `:333`).
- Highest migration on the integration branch is 173; 176 to 189 belong to
  8.1 to 8.3; 190 to 194 to 8.4d, 8.4f2, 8.4g1, 8.5a, 8.5b.

## Plan corrections

- Row-level scoping is new: it becomes "locked filters", dashboard filters
  whose values come only from the token and that the viewer cannot change.
  Panels must read them through the existing `{{id}}` interpolation, and a
  panel that does not read a locked filter is not embeddable (it would show
  every customer's rows).

## 3. Build

1. **Schema (additive), migration 195.** Table `analytics_embeds`
   (`version: 195`, `name: "analytics-embeds-table"`; 176 to 189 are 8.1 to
   8.3, 190 to 194 are 8.4d, 8.4f2, 8.4g1, 8.5a, 8.5b): `id TEXT PRIMARY KEY, org_id TEXT NOT NULL, dashboard_id TEXT NOT NULL, allowed_origins TEXT NOT NULL DEFAULT '[]', locked_filters TEXT NOT NULL DEFAULT '[]', secret_ref TEXT NOT NULL, created_by TEXT NOT NULL, created_at TEXT NOT NULL, rotated_at TEXT, revoked_at TEXT`.
   `secret_ref` points at the signing secret in the app secret store; the
   secret is never in this table. At most 50 active embeds per org. Run
   `pnpm guard:additive-migrations`.
2. **Keys.** `actions/create-embed.ts` (dashboard editor and org admin):
   `{ dashboardId, allowedOrigins: string[] (1 to 10, https origins only, no
   wildcards), lockedFilters: string[] }`. Validates that each locked filter
   exists and that every embeddable panel reads all locked filters
   (`panelUsesFilters`); panels that don't are listed and the action refuses
   with "These panels would show everyone's rows: {{panels}}. Make them use
   {{filters}} or hide them from the embed." Generates a 32-byte secret,
   stores it with `writeAppSecret`, and returns the secret once with the embed
   id. `rotate-embed-secret` (returns the new secret once), `revoke-embed`,
   and `list-embeds` (no secrets) complete the set. All are `needsApproval`
   for agent callers (publishing outward, per the security skill).
3. **Token format.** The host signs a compact token with HMAC-SHA256 over the
   embed secret: payload `{ embedId, exp, filters: { [lockedFilterId]: string | string[] }, sub? }`,
   `exp` at most 10 minutes ahead. `server/lib/embed-token.ts`:
   `verifyEmbedToken(token)`: parse, look up the embed (revoked is invalid),
   read the secret, `timingSafeEqual`, check `exp` with 30 s skew, check every
   locked filter has a value, and return a typed result
   (`expired | bad_signature | revoked | missing_filter | malformed | ok`).
   Document the format with a Node and a Python signing snippet in the skill.
4. **Public data read.** `actions/get-embed-data.ts`, read-only, exposed at
   `/_agent-native/actions/get-embed-data` through `publicPaths` in
   `server/plugins/auth.ts` (as `get-public-status-page` is):
   `{ token, filters?: Record<string,string> }`.
   - Verifies the token; on failure returns the typed reason with a 401, not
     an empty dashboard.
   - Checks the `Origin` header against `allowed_origins` (403 otherwise).
   - Loads the dashboard by id (a reviewed unscoped read with the
     `guard:allow-unscoped` pragma and a reason, as
     `dashboard-agent-context.json.get.ts:85` does) and requires the org to
     match the embed's.
   - Builds each panel's query from the stored config only; the request never
     carries SQL. Locked filter values come only from the token and override
     anything in `filters`; other filters accept viewer values validated
     against the filter's options.
   - Runs panels through `runDashboardPanelQuery` with the credential context
     decided in section 8 (default: the org's credentials, `credentialScope:
     "org"`, never the author's personal keys). A panel whose source has no
     org credential returns `missing_api_key`, shown as unavailable.
   - Returns per panel `{ panelId, title, chartType, config, rows, schema, truncated, status }`
     and the filter definitions minus locked ones. `Cache-Control: no-store`,
     `Referrer-Policy: no-referrer`. Program and `cells` sources are run on the
     server the same way; Python cells (8.4f2) are read from their stored run.
   - Rate limit per embed (default 60 reads a minute) with a typed `rate_limited`.
5. **Audit.** Every read records `{ embedId, sub, at, status }` in the audit
   log (`.agents/skills/audit-log`), not row data.
6. **Agent.** The agent can create, list, rotate and revoke embeds through the
   actions above, with approval. It never sees a secret after creation.
7. **Skills.** New `.agents/skills/embedding/SKILL.md`: what an embed is, the
   token format with signing snippets, locked filters and why panels must read
   them, origins, rotation, and that `/chart` and `query-dashboard-panel` are
   never embed paths. Read `.agents/skills/writing-agent-instructions` and
   `create-skill` first.
8. **Changelog.** With 8.5c2 (one entry for the pair).

## 5. Tests

- `server/lib/embed-token.spec.ts` (new): valid; expired; skew; bad
  signature; revoked; missing locked filter; malformed; timing-safe compare
  used.
- `actions/create-embed.spec.ts` (new): permissions; origins validated;
  panels missing a locked filter refused with their names; secret stored via
  the secret store and returned once; never in the table.
- `actions/get-embed-data.spec.ts` (new): no SQL accepted; locked values come
  from the token and override request filters; wrong origin 403; wrong org
  refused; personal credentials never used; rate limit; failures are typed,
  never empty success.
- `server/plugins/auth.spec.ts` (extend if present): the public path is exactly
  the one action.

No source-reading tests.

## 6. Verify

```bash
cd templates/analytics
pnpm exec vitest --run server/lib/embed-token.spec.ts actions/create-embed.spec.ts actions/get-embed-data.spec.ts
pnpm typecheck
cd ../.. && pnpm guards && pnpm guard:additive-migrations
cd templates/analytics
pnpm action create-embed --dashboardId <id> --allowedOrigins '["https://localhost:5174"]' --lockedFilters '["customer"]'
```

Sign a token with the skill's Node snippet and call the public action with
curl and an `Origin` header: valid token returns only that customer's rows;
an expired one, a wrong origin, a tampered filter and a revoked embed each
return their typed failure. Stop the server afterwards.

Cannot verify locally: CDN behavior of the public action (it is `no-store`).

## 8. Defaults for open questions

- [Needs the owner] Whose credentials run embedded panels. Default: the org's
  shared connections only; panels on personal keys are unavailable in embeds.
- [Default] Host-signed HMAC tokens, at most 10 minutes, one secret per embed.
- [Default] Locked filters are the only row scoping; every embedded panel
  must read them.
- [Default] No chat, no SQL, no export in embeds in v1.

## 9. Do not

- Do not accept SQL or a panel definition from the embed request.
- Do not reuse `/chart` or `query-dashboard-panel` for embeds.
- Do not store the signing secret in SQL or return it after creation.
- No behavior changes outside the unit; additive-only schema; no new /api
  routes for app data (use actions); no raw fetch from client code; no
  process.env reads for provider credentials; no catch or default that turns a
  failure into a normal-looking value; no large payloads in SQL.
