# 8.2d Insight to action: decks with live Analytics charts in Slides

Lane E (Holy-shit features). Size M. Gated: the chart caption on a slide and
the "Refresh charts" item in the Slides editor's More menu are new UI; build
only after the "Investigation: make a deck" screen (drawn) and a "Slides: deck
with live charts" screen (not drawn yet) in `prototypes/analytics-operators/`
are signed off. Where the signed-off
prototype differs from this brief, the prototype wins.

Depends on: 8.2a (the deck kind and handoff). Merge after 8.2a; independent
of 8.2b and 8.2c. Blocks: nothing.

Paths are relative to `templates/analytics/` unless they start with
`packages/` or `templates/`.

## 1. Goal

"Make a deck…" from an investigation now builds a deck whose charts are the
investigation's own charts, not numbers retyped into slide markup. Each
chart on a slide is an image Analytics rendered from the panel, with a small
caption "As of 10:42, Oct 14" that links back to the panel. Analytics serves
that image only to someone who can open the panel's dashboard or notebook,
unless that dashboard is public; anyone else who opens the deck sees the
caption and the alt text, never the chart. In Slides, More,
"Refresh charts" asks Analytics to render every chart again with today's
data, and the captions move to the new time. A chart Analytics can no
longer read keeps its last image and says why, instead of going blank.

## 2. What the code does today

- **Slides cannot embed a live chart.** The slide sanitizer drops `iframe`,
  `svg`, `object` and `embed` with their children
  (`templates/slides/app/lib/sanitize-slide-html.ts:66-80`). It keeps `img`,
  `figure` and `figcaption` (`:12-64`), any `data-` attribute (`:400-412`)
  and any http or https image URL (`:158-209`).
- Slides edits slides safely with `patch-deck`, which needs each slide's
  `contentHash` as `baseContentHash`
  (`templates/slides/actions/patch-deck.ts:1328-1331`), read with `get-deck`
  `compact=false` (`templates/slides/actions/get-deck.ts:221-222`). The
  editor's More menu is in `templates/slides/app/components/editor/EditorToolbar.tsx:987-1050`.
- Slides already routes data questions to Analytics and must not query
  sources itself (`templates/slides/.agents/skills/analytics-data-for-decks/SKILL.md:18-31`).
- **Analytics renders panel charts to PNG on the server** for report emails:
  `fetchReportPanelData` runs panels under the owner's identity
  (`server/lib/dashboard-report-render.ts:128-215`), `renderChartBlock`
  draws a panel (`:842`) and `rasterizeChartPng` turns the SVG into PNG with
  `@resvg/resvg-js` (`:491-492`). Supported static chart types are `bar`,
  `line`, `area`, `pie`, `funnel` (`server/lib/report-chart-svg.ts:5`).
- Panels run through `buildPanelQuery` and `runResolvedPanel`, which return
  rows plus freshness or a typed failure (`server/lib/dashboard-panel-runner.ts:17-26`,
  `:80-125`). Read cost is attributed by caller
  (`server/lib/panel-read-tracking.ts:14-29`).
- `generate-chart` writes to a local media directory and builds URLs from
  `process.env.APP_ORIGIN` (`actions/generate-chart.ts:51-58`); it is for
  legacy analyses and is not reused here. The live `/chart` route decodes a
  whole panel, SQL included, from the URL (`app/routes/chart.tsx:30-71`),
  and cannot be framed in Slides anyway.
- Files go to configured storage with `uploadFile`
  (`packages/core/src/file-upload/registry.ts:126`), which returns no result
  when no provider is configured and gives a URL that anyone holding it can
  load. Private bytes go through `putPrivateBlob` and `readPrivateBlob`
  (`packages/core/src/private-blob/registry.ts:417`, `:427`), which return
  and take an opaque handle, with readiness from
  `getPrivateBlobStorageReadinessForRequest` (`:393`).
- Access checks: `resolveAccess` and `assertAccess`
  (`packages/core/src/sharing/access.ts:596-616`, `:844-870`) admit the
  owner, explicit shares, `org` visibility and, by id, `public` rows; with
  no signed-in user only `public` passes. The `sharing` skill
  (`.agents/skills/sharing/SKILL.md`, "Three visibility levels") is the
  authority. A route that serves a private blob after its own check exists
  in Clips (`templates/clips/server/routes/api/media/organization-logo/[organizationId].get.ts`).

## Plan corrections

- "Live charts" are refreshable images, not embedded live charts: Slides
  strips iframes and SVG by design. Each image carries the panel reference
  and as-of time, so the deck can be refreshed and every chart links home.
- **Chart images are access checked, not public files.** A chart shows
  the source's data, so an image URL that works for anyone who holds it
  would leak the dashboard to everyone the deck reaches. The image is
  stored privately and served only through one Analytics path that checks
  the viewer can read the source dashboard or notebook, unless its
  visibility is `public`. No unguessable URL grants access on its own.

## 3. Build

1. **Analytics library** (`server/lib/panel-chart-image.ts`, new): extract
   the panel-to-PNG path from `renderChartBlock` and `rasterizeChartPng`
   into `renderPanelChartPng({ panel, data, theme, width })`, and make
   reports call it (no change to report output). Add `"slides"` to
   `PANEL_READ_CALLERS` so these reads show up in 1.4b's cost numbers.
2. **Analytics action** `actions/render-panel-image.ts`: input `{ dashboardId,
   panelId, theme: "light" | "dark", width? (640 to 1600, default 1280),
   filters? }`. Loads the dashboard with `getDashboard` for the caller (no
   access and deleted are both `panel_not_found`), runs the one panel with
   `buildPanelQuery` and `runResolvedPanel` under the caller's credentials,
   renders the PNG, stores it with `putPrivateBlob` (never `uploadFile`),
   and records one `analytics_panel_images` row (step 3). Returns `{
   status: "ok", imageId, imageUrl, width, height, title, asOf, panelUrl }`,
   where `imageUrl` is the access-checked path from step 3 on the absolute
   base from `analyticsWebAddress()`, or a typed failure: `panel_not_found`,
   `unsupported_chart_type` (tables, metrics and text), `missing_credential`,
   `query_failed`, `no_rows`, `storage_unavailable` (private blob storage
   not ready). `readOnly: true` (it writes no app data; the image
   is a derived file), `http: { method: "GET" }`, and `publicAgent: {
   expose: true, readOnly: true, requiresAuth: true }` so Slides can call it
   as a direct read. No rows in the result.
3. **Access-checked image path (Analytics).**
   - Schema (additive), migration 182 (`version: 182`, `name:
     "analytics-panel-images-table"`): `analytics_panel_images` with `id`
     (`pimg_` plus 16 characters), `dashboard_id TEXT NOT NULL`, `panel_id
     TEXT NOT NULL`, `blob_handle TEXT NOT NULL` (the opaque handle),
     `mime_type`, `width`, `height`, `theme`, `as_of`, `created_by`,
     `created_at`; an index on `(dashboard_id, panel_id)`. The row has no
     access of its own: access always comes from its dashboard. Run
     `pnpm guard:additive-migrations`.
   - Route `server/routes/panel-images/[imageId].get.ts`. A PNG is a
     non-JSON response, which the architecture rules allow as a route; it
     is not an action twin. On every request: establish the request
     context from the session (signed out is allowed, as no user), load
     the row, then `resolveAccess("dashboard", row.dashboard_id)` at
     `viewer`. Only when that passes, read the bytes with `readPrivateBlob`
     and send them. A missing row, a deleted dashboard and a refused
     viewer all return the same 404, so the response says nothing about
     what exists. Headers: `Cache-Control: private, no-store` unless the
     dashboard is `public`; never a shared-cache header for a private
     dashboard.
   - The route is listed in the auth public paths only so a public
     dashboard's chart loads signed out; the check above still runs on
     every request, and nothing else under that path is public.
4. **Deck artifact (Analytics).** A `deck` item may now be a chart reference
   `{ type: "chart", dashboardId, panelId, title }`, at most 8, each checked
   against the source in `buildInsightArtifact`. The handoff objective tells
   Slides to place each chart with `insert-analytics-chart`, never to redraw
   it from numbers.
5. **Slides actions** (both `defineAction`):
   - `insert-analytics-chart`: input `{ deckId, slideId, dashboardId,
     panelId, theme? }`. `assertAccess` on the deck as editor; calls
     Analytics `render-panel-image` with `invokeAgentAction` (target
     `analytics`, the caller's user identity from `resolveA2ACallerAuth`
     bound to Analytics' audience); on `ok`, writes one `figure` with
     `data-analytics-chart`, `data-analytics-dashboard-id`,
     `data-analytics-panel-id`, `data-analytics-as-of`, an `img` whose
     `src` is the access-checked `imageUrl` and whose alt text comes from
     the title, and a `figcaption` with the as-of time linking to
     `panelUrl`, through `patch-deck` with the slide's `baseContentHash`.
     Slides never copies the image bytes into its own storage, so the
     deck's sharing cannot widen who sees the chart. A failure returns the typed code and writes nothing.
   - `refresh-analytics-charts`: input `{ deckId, slideIds? }`. Reads the
     deck, finds every `data-analytics-chart` figure, renders each again
     (at most 4 at a time), and replaces the image URL and as-of in one
     `patch-deck` call per slide. A chart that fails keeps its last image
     and gets `data-analytics-error="<code>"`, shown as an amber caption.
     Returns `{ refreshed, failed: [{ slideId, panelId, code }] }`; never a
     success when any chart failed without saying which.
6. **UI (gated, Slides).** In `EditorToolbar.tsx`'s More menu, "Refresh
   charts" shows only when the deck has Analytics charts; it calls
   `refresh-analytics-charts` with a brief spinner and a toast with counts
   ("Refreshed 6 charts. 1 couldn't be read."). The caption is part of the
   slide markup; its amber failure state uses the slide's design system
   text color plus an amber triangle glyph from the deck CSS. No other new
   controls.
7. **Application state.** None new. The chart's panel reference lives in
   the slide markup, so the Slides agent finds it with `get-deck`.
8. **Skills.** Extend `templates/slides/.agents/skills/analytics-data-for-decks/SKILL.md`:
   charts from Analytics go in with `insert-analytics-chart`; refresh with
   `refresh-analytics-charts`; never type chart numbers into slide markup;
   never download a chart image into the deck, since the image is access
   checked per viewer.
   Extend Analytics' `.agents/skills/insight-actions/SKILL.md` with the
   chart reference shape and the 8-chart cap.
9. **Changelog.** From `templates/slides`: `agent-native changelog add "Decks from Analytics carry live charts you can refresh" --type added`.
   From `templates/analytics`: `agent-native changelog add "Make a deck now places the investigation's own charts in Slides" --type improved`.

## 4. Copy

Slides copy goes in a new `analyticsCharts` namespace in
`templates/slides/app/i18n/en-US.ts` and all ten other Slides catalogs in
the same change: `ar-SA.ts`, `de-DE.ts`, `es-ES.ts`, `fr-FR.ts`, `hi-IN.ts`,
`ja-JP.ts`, `ko-KR.ts`, `pt-BR.ts`, `zh-CN.ts`, `zh-TW.ts` (all present in
`templates/slides/app/i18n/`). Plurals use i18next suffixes (`_one`,
`_other` in English; Arabic needs `_zero`, `_one`, `_two`, `_few`, `_many`,
`_other`).

| Key | English |
| --- | --- |
| `analyticsCharts.refresh` | Refresh charts |
| `analyticsCharts.refreshed_one` | Refreshed {{count}} chart. |
| `analyticsCharts.refreshed_other` | Refreshed {{count}} charts. |
| `analyticsCharts.failed_one` | {{count}} couldn't be read. |
| `analyticsCharts.failed_other` | {{count}} couldn't be read. |
| `analyticsCharts.asOf` | As of {{time}} |
| `analyticsCharts.notRefreshed` | Not refreshed: {{reason}} |
| `analyticsCharts.reasonNotFound` | the chart was deleted or you no longer have access |
| `analyticsCharts.reasonCredential` | its data source isn't connected |
| `analyticsCharts.reasonNoRows` | no rows for this chart |

The caption is written into slide markup in the deck's language at insert
time from these keys. Analytics adds no UI copy. Run
`pnpm guard:i18n-catalogs` and `pnpm guard:i18n-changed-copy`. No em dashes.

## 8. Defaults for open questions

- [Default] Charts refresh only when someone chooses Refresh charts; not
  on open or present.
- [Default] Tables, metrics and text cells are not charts in v1; the agent
  writes their numbers as slide text with the as-of time.
- [Decided by the owner, 2026-10-14] Chart images and live charts in decks
  are access checked: each viewer must be able to read the source
  dashboard or notebook, unless it is public. An unguessable URL alone is
  never access.
- [Default] A viewer who can open the deck but not the dashboard sees the
  alt text and the caption, whose link leads to the panel and its Request
  access (1.7b).
- [Default] The image uses the deck's theme (light or dark) at insert time.

## 9. Do not

- Do not put SQL, rows or panel config into slide markup or the image URL.
- Do not store chart images with `uploadFile` or anywhere a URL alone
  grants access, and do not serve one without the dashboard access check.
- Do not render charts in Slides from numbers.
- Do not frame Analytics pages in slides.
- No behavior changes outside the unit; additive-only schema; no new /api
  routes for app data (use actions); no raw fetch from client code; no
  process.env reads for provider credentials; no catch or default that turns a
  failure into a normal-looking value; no large payloads in SQL.

## Reviewer notes

- `render-panel-image` is marked read-only although it stores a derived
  image and its row, so Slides can call it as a direct read. If the
  reviewer rejects that, the alternative is message delegation for every
  chart, which is slower and less exact.
- Settle before building: whether a viewer's Analytics session reaches the
  image request when Slides and Analytics are on different hosted origins.
  If it does not, Slides serves the image through its own route that calls
  Analytics as the viewer over A2A, and the same dashboard check runs in
  Analytics; never fall back to a public URL.
- Settle before building: Slides' PDF and PPTX export. If export fetches
  image URLs on the server, it must fetch as the exporting user through the
  same check, or the export shows the alt text and caption.
