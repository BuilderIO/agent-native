# 7.5 Publish a notebook as an app

Lane C (Notebook). Size M. **Gated: input cells, the app view and the publish
control need prototype sign-off.** Depends on 7.1a and 7.1b; works with 7.2b
when present.

Paths are relative to `templates/analytics/` unless they start with
`packages/` or `docs/`.

## 1. Goal

A notebook author adds input cells (a date range, a plan picker, a search box)
and publishes the notebook as an app. People the notebook is shared with open
a clean read-only page: the inputs at the top, then the charts, tables and
text, with no SQL and no edit controls. Changing an input re-runs the cells
that use it. Editors can switch between the app and the notebook.

## 2. What the code does today

- Dashboard filters already are inputs: `config.filters[]` with types `date`,
  `date-range`, `select`, `multi-select`, `toggle`, `text`, `toggle-date`
  (`app/pages/adhoc/sql-dashboard/types.ts:25-47`), interpolated into panel SQL
  as `{{id}}`, `{{idStart}}`/`{{idEnd}}` and `{{id:list}}`
  (`.agents/skills/dashboard-management/SKILL.md:326-357`). They render in one
  `DashboardFilterBar` above the panels
  (`app/pages/adhoc/sql-dashboard/index.tsx:2536-2544`,
  `DashboardFilterBar.tsx:104-116`) and live in the URL as `f_<id>` params
  (`actions/view-screen.ts:180-189`).
- There is no UI to create a filter; the agent writes them. `?view=` is already
  taken by saved views (`app/pages/adhoc/sql-dashboard/ViewsMenu.tsx:114`,
  `:133`).
- Sharing: dashboards are a registered shareable resource with `private`,
  `org` and `public` visibility (`server/db/index.ts:37-47`). Per the sharing
  skill, `public` means any signed-in user with the link; anonymous public URLs
  are a separate axis the sharing system does not provide
  (`.agents/skills/sharing/SKILL.md`, "Three visibility levels" and
  "Anonymous public URLs stay separate").
- Viewers run panel queries with their own request context:
  `query-dashboard-panel` calls `getCredentialContext()`
  (`actions/query-dashboard-panel.ts:23-38`), and a missing key returns
  `missing_api_key` (`server/lib/dashboard-panel-query.ts:122-135`). Org-level
  credentials therefore work for viewers in the same org; personal credentials
  of the author do not.
- Viewers without edit rights already get a read-only dashboard (`canEdit`
  gates editing throughout `index.tsx`, for example `:705`, `:2570-2625`).
- Navigation state carries `view`, `dashboardId` and `filters`
  (`app/hooks/use-navigation-state.ts:8-21`), and the `navigate` action builds
  dashboard paths (`:130`).

## Plan corrections

- "Shared read-only page" cannot mean an anonymous public page without a new
  trust model: panel queries run with the viewer's credentials, and an
  anonymous viewer has none. Running them with the author's credentials would
  let anyone with the link query the author's sources. **v1 publishes to the
  people the notebook is already shared with** (explicit grants, org or
  signed-in public link). Anonymous apps are out of scope.
- "Input cells" are new as cells, but they should be the existing filters, not
  a parallel input system: an input cell renders one `config.filters` entry in
  place.

## 3. Build

1. **Input cell type.** Add `"input"` to `PANEL_CHART_TYPES`; config key
   `filterId: { onlyFor: ["input"] }` in `PANEL_CONFIG_KEYS`. 7.1a's
   `panelRunsQuery` returns false for `input`. Validation in
   `collectDashboardConfigIssues`: `filterId` must name an existing filter; at
   most one input cell per filter; `cells` inputs (7.2b) may not name an input
   cell.
2. **Hide in app.** Add `hideInApp?: boolean` to `SqlPanelConfig`, allowed on
   every chart type.
3. **App flag.** Add `app?: { published: boolean; publishedAt?: string;
   publishedBy?: string }` to `SqlDashboardConfig`.
4. **Action** `actions/publish-notebook-app.ts` (`defineAction`): input
   `{ dashboardId, published: boolean }`. `assertAccess("dashboard", id,
   "editor")`; fail with a clear error if `layout` is not `notebook`; write
   through the normal dashboard store write so a revision is recorded; return
   `{ dashboardId, published, appUrl, visibility }`. `appUrl` is the notebook
   URL with `?mode=app`. UI and agent both use it.
5. **App view.** In `NotebookBody` (7.1b), render app mode when the URL has
   `mode=app`, or when `config.app.published` is true and the viewer cannot
   edit:
   - One `DashboardFilterBar` at the top with the filters bound to input
     cells, in cell order, followed by any unbound filters.
   - Then every non-input cell that is not `hideInApp`, in order: text,
     tables, charts. No SQL areas, no cell toolbars, no add buttons, no
     history or edit header actions.
   - Editors see an "Open notebook" header button that drops `mode=app`
     (`Button variant="outline" size="sm" className="text-xs gap-1.5"`, the
     dashboard header's compact Views size; see 7.1b). In the notebook they
     reach the app from the actions menu's "Open app" (step 8).
   - Use `?mode=app`, not a new route: `?view=` belongs to saved views and the
     dashboard path pattern (`use-navigation-state.ts:24`) expects
     `/dashboards/:id`.
6. **Notebook view of input cells.** An input cell renders its filter's
   control inline (a `DashboardFilterBar` with that single filter) so the
   author sees inputs where they apply. Unbound filters keep the top bar.
7. **Create an input cell (gated UI).** The add-cell menu (7.1b) gains
   "Input". It opens a `Popover` form: Label (`Input`), Type (`Select`: Text,
   Pick one, Pick several, Date range, On or off), Options (`Textarea`, one per
   line, for the pick types), Default. Save writes the new filter and the input
   cell in one save through the page's save path. The filter id is a slug of
   the label made unique, and the form shows the token to use in SQL
   (`{{id}}`). Editing an input cell edits its filter; deleting it asks whether
   to keep the filter (cells may still use it) with keep as the default.
8. **Publish control (gated UI).** No header button (decided by the owner,
   2026-10-14: publishing is a tertiary action next to Re-run). The entry
   point is the notebook's actions menu (the dashboard actions
   `DropdownMenu`, `app/pages/adhoc/sql-dashboard/index.tsx:2090-2235`, as
   7.1b sets it up for notebooks). Its first item is "Publish as app" when
   unpublished, or "Publish settings" when published, both opening the same
   publish dialog (prefilled when published); a published notebook's menu
   then has "Open app" and "Unpublish". "Notebook history", Archive and
   Delete permanently follow. Menu items are text with the menu's existing
   icon treatment; the prototype's New badge marks Publish as app for review
   only. After publishing a private notebook with no grants, open the
   existing `ShareButton` popover so the author picks who sees it. Cell menus
   gain "Hide in app" / "Show in app".
9. **Missing credentials for viewers.** A cell that returns `missing_api_key`
   in app mode shows the 1.5 plain-language state, worded for a viewer: ask
   the owner to connect the source for the team. No connect button for
   viewers who cannot connect.
10. **Application state.** Add `notebookMode?: "notebook" | "app"` to
    `NavigationState` (`use-navigation-state.ts:8-21`) from `mode=app`. Add an
    optional `notebookMode` to the `navigate` action and its path builder
    (`:130`) so the agent can open the app view.
11. **Skills.** Extend `.agents/skills/notebooks/SKILL.md` with "Inputs and
    apps": input cells are filters; create them with `mutate-dashboard`
    `setDashboard` (filters) plus `insertPanel` (`chartType: "input"`,
    `config.filterId`) in one call; publish with `publish-notebook-app`;
    published apps are visible only to people the notebook is shared with;
    sharing goes through `share-resource` / `set-resource-visibility`. Add a
    line to the "Sharing" section of
    `.agents/skills/dashboard-management/SKILL.md:625`.
12. **Changelog.** `agent-native changelog add "Publish a notebook as a read-only app with inputs" --type added`.

## 8. Defaults for open questions

- **[Default] Audience is the notebook's existing share list.** No anonymous
  apps.
- **[Default] Viewers' own request context runs the queries**, as dashboards do
  today.
- **[Default] Non-editors open published notebooks in app mode by default.**
- **[Default] `?mode=app` instead of a new route.**
- **[Default] Input types offered in the form: text, pick one, pick several,
  date range, on or off.** `date` and `toggle-date` stay agent-only.
- **[Default] Deleting an input cell keeps its filter unless the author picks
  otherwise.**

## 9. Do not

- No behavior changes outside this unit; grid dashboards and their filter bar
  behave as before.
- Additive-only schema (none needed; flags live in the config JSON).
- No new `/api` routes for app data; publish goes through the action.
- No raw `fetch` from client code.
- No `process.env` reads for provider credentials, and never run a viewer's
  cells with the author's credentials.
- No `catch` or default that turns a failure into a normal-looking value: a
  missing credential is a visible state, not an empty chart.
- No large payloads in SQL or application state.
- Do not add an anonymous public route or change the sharing registration's
  `allowPublic` for dashboards.
