# 6.2b: Demo company dashboard and first run

Lane B. Size M. Not gated: it reuses the existing dashboard, Alert and chat
home surfaces with new content, and adds no new kind of surface. Needs 6.2a.

Paths are relative to `templates/analytics/` unless they start with
`packages/` or `docs/`.

## 1. Goal

A new user signs in and already has an "Acme Cloud (demo)" dashboard with
MRR, MRR movements, the accounts at risk (Stripe revenue, product usage and
HubSpot renewals joined by domain), pipeline and weekly active users. The
dashboard says plainly that it is demo data from a made-up company and offers
"Connect your data". Until the user connects a source, the Ask page offers
three demo questions that produce a cross-tool answer in one click. The demo
replaces the Node Exporter dashboard as what new users get; people who
already have the Node Exporter demo keep it.

## 2. What the code does today

- Demo install: `DEMO_DASHBOARDS` has one entry, `demo-node-exporter` from
  seed `node-exporter-full` (`server/lib/demo-dashboards.ts:15-21`).
  `ensureDemoDashboardsForUser` installs every entry per user under a hashed
  id (`:112-121`, `:214-285`), skips ones the user deleted (`:218-238`), and
  re-upserts when the stored `demo.version` differs from the single global
  `DEMO_DASHBOARD_VERSION` (`:9`, `:240-267`). It returns the first active
  dashboard as `defaultDashboardId` (`:300-306`).
- The seed transform is Node Exporter specific: `applyDemoMetadata` rewrites
  the `instance` and `job` filter defaults, switches `prometheus` panels to
  `demo`, and hard-codes the Node Exporter name and description
  (`server/lib/demo-dashboards.ts:134-184`). The default path pins the
  "App / Overview" tab (`:13`, `:57-62`).
- It runs on every app open from `DemoDashboardInstaller`
  (`app/root.tsx:123-131`, mounted at `:175`) through
  `ensure-demo-dashboards` (`actions/ensure-demo-dashboards.ts:12-57`).
  Deletion is remembered by `markDemoDashboardDeleted`
  (`server/lib/demo-dashboards.ts:309-345`, called from
  `actions/delete-sql-dashboard.ts:31`).
- Seeds must be statically imported to ship in the server bundle
  (`server/lib/dashboard-seeds.ts:5-19`); the file-system fallback
  (`:30-60`) is for local development.
- The `demo` source only understands Prometheus descriptors:
  `parseDemoDescriptor` wraps `parsePanelDescriptor`
  (`server/lib/demo-source.ts:47-58`, `server/lib/prometheus.ts:229-250`),
  and `runDemoPanel` fetches the demo Prometheus host
  (`server/lib/demo-source.ts:226-228`), dispatched from
  `server/lib/dashboard-panel-query.ts:497-499`. `update-dashboard`
  validates demo panels with the same parser
  (`actions/update-dashboard.ts:613-621`).
- Client code treats every `demo` panel as Prometheus for series labels
  (`app/components/dashboard/SqlChart.tsx:527-529`). Daily partial-day
  splitting applies to `demo` like any non-Prometheus source
  (`SqlChart.tsx:450-457`).
- Protections that already cover anything on the `demo` source: catalog
  search hides demo panels unless the question mentions the demo
  (`server/lib/analytics-query-catalog.ts:789-793`), review previews skip
  them (`app/components/AnalyticsReviewArtifactPreview.tsx:35`, `:81`), and
  the observability review preview rejects them
  (`actions/query-observability-review-panel.ts:85-96`).
- The demo intro banner shows only for `demo-node-exporter` and only with
  `?demoIntro=1` (`app/pages/adhoc/sql-dashboard/index.tsx:745-747`,
  `:2428-2445`). Nothing in the app adds that parameter: the helpers in
  `app/lib/demo-dashboard-path.ts:3-21` have no callers. So the banner is
  never seen today.
- The banner uses raw cyan utility classes (`index.tsx:2430`); the shared
  `Alert` has `default` and `destructive` variants
  (`packages/toolkit/src/ui/alert.tsx:9-17`).
- The Ask page passes `suggestions={[]}` to `AgentChatHome`
  (`app/pages/Ask.tsx:74-75`). The sidebar chat already passes four static
  suggestions from the catalog (`app/components/layout/Layout.tsx:308-313`,
  keys at `app/i18n/en-US.ts:493-496`).
- Data source status comes from `useActionQuery("data-source-status")`
  (`app/pages/DataSources.tsx:2120-2134`), which already distinguishes
  loading, error and unknown (`statusUnknown`, `DataSources.tsx:2128-2133`).
  Provider rows carry `configured: boolean | null`
  (`app/lib/data-source-status.ts:33-42`).
- Agent prompts embedded in the new-dashboard and panel editors describe the
  `demo` source as Node Exporter only
  (`app/components/layout/NewDashboardDialog.tsx:21`, `:30`;
  `app/pages/adhoc/sql-dashboard/PanelEditorDialog.tsx:387`, `:396`), and the
  panel editor labels the source "Demo Prometheus"
  (`PanelEditorDialog.tsx:73`).

## Plan corrections

- The Node Exporter intro banner is unreachable today (no caller sets
  `demoIntro`). This unit does not fix that banner; the new demo gets its own
  always-visible label instead (section 3, step 7). Removing the dead helper
  and the unreachable banner is a separate cleanup; note it in the PR.
- A version bump on the global `DEMO_DASHBOARD_VERSION` re-upserts every
  user's demo dashboard over their edits (`demo-dashboards.ts:240-267`).
  Adding a second demo must not bump it. Versions become per demo.

## 3. Build

1. Demo source dispatch (fix at the boundary, not per call site):
   - `server/lib/demo-source.ts`: `parseDemoDescriptor(raw)` returns a
     discriminated value: `{ kind: "company", query }` when the parsed JSON
     has `dataset: "company"` (validated with 6.2a's
     `DemoCompanyQuerySchema`), else `{ kind: "prometheus", descriptor }`
     through the existing Prometheus path and its existing error text.
     `runDemoPanel` switches on `kind`; the company branch calls
     `queryDemoCompany` (6.2a) with the descriptor's `limit` or 2,000 and
     returns `{ rows, schema, truncated }` (schema from the result's
     `columns`, typed by the first rows like the Prometheus path's fixed
     schema). The Prometheus cache is untouched.
   - `shared/demo-company.ts` (from 6.2a): add `demoDescriptorKind(sql:
     string): "company" | "prometheus"`, a cheap JSON check shared by the
     server parser and the client.
   - `app/components/dashboard/SqlChart.tsx:527-529`: `usesPrometheusPresentation`
     is true for `prometheus`, and for `demo` only when
     `demoDescriptorKind(panel.sql) === "prometheus"`.
   - `actions/update-dashboard.ts:613-621`: no new branch; the parser now
     accepts both kinds. Make sure the error text names the descriptor kind
     it tried.
2. Seed `seeds/dashboards/demo-company.json` and register it in
   `server/lib/dashboard-seeds.ts` `shippedSeeds` with a static import. All
   panels use `source: "demo"` and a `sql` descriptor with
   `"dataset": "company"`. No filters. Panels (title, chart, descriptor):
   - "MRR", metric: `mrr_by_month`, `orderBy: "month"`, `orderDir: "desc"`,
     `limit: 1`; `yKey: ending_mrr`, `yFormatter: currency`.
   - "Active customers", metric: same descriptor (identical JSON, so one
     cached result), `yKey: active_customers`.
   - "MRR by month", line: `mrr_by_month`, `orderBy: "month"`; `xKey: month`,
     `yKey: ending_mrr`, currency.
   - "MRR movements", stacked bar: same descriptor as "MRR by month";
     `yKeys: [new_mrr, expansion_mrr, contraction_mrr, churned_mrr]`,
     `stacked: true`, currency. 6.2a emits contraction and churn as negative
     numbers so the bars read below zero.
   - "Accounts at risk", table, full width: `accounts`, `where` status
     equals active and `wau_change_pct` lte -40, `select` company_name,
     domain, mrr, wau_change_pct, open_deal_type, open_deal_close_date,
     owner, `orderBy: "mrr"`, desc; column formats currency for `mrr` and
     percent for `wau_change_pct` through the existing `ColumnFormat`
     config (`app/pages/adhoc/sql-dashboard/types.ts:49`).
   - "Open pipeline by stage", bar: `pipeline_by_stage`; `xKey: dealstage`,
     `yKey: amount`, currency.
   - "Weekly active users", line: `app_weekly_activity`, `groupBy:
     ["week_start"]`, `aggregate: [{ column: "active_users", op: "sum", as:
     "active_users" }]`, `orderBy: "week_start"`.
   - "Expansion by reports usage", bar: `accounts`, where status equals
     active, `groupBy: ["uses_reports"]`, aggregate sum
     `expansion_mrr_12m`; currency.
   Seeded names and titles are stored English content, like every other
   seed (`seeds/dashboards/google-analytics.json:1-30`). No panel
   descriptions (surface density rule).

## 8. Defaults for open questions

- DECISION: new users get only the company demo. Existing Node Exporter
  installs stay and keep updating; nobody loses a dashboard. Reviewer may
  auto-install both.
- DECISION: the demo label is permanent on the demo dashboard and has no
  dismiss. It is a truth label, and archiving the dashboard removes it.
- DECISION: demo suggestions show on Ask only when status is known to be
  "nothing connected". The sidebar chat's existing four suggestions are not
  changed.
- DECISION: no dashboard filters on the demo; every view has a fixed window.
- DECISION: the demo is not added to `dashboardCatalogEntries`
  (`server/lib/dashboard-catalog.ts:915`); no catalog UI renders today (the
  `catalog.*` strings have no component using them), and catalog search
  already hides demo panels.
- DECISION: the panel editor source label becomes "Demo" for both demos.
- DECISION: names and panel titles are stored English content.

## 9. Do not

- No behavior changes outside this unit: the Prometheus demo path, the Node
  Exporter seed, and existing users' demo dashboards stay as they are. Do
  not bump `DEMO_DASHBOARD_VERSION` or the Node Exporter entry's version.
- Additive-only schema; nothing new in SQL (the install state lives in the
  existing `analytics-demo-dashboards` user setting).
- No new `/api` routes for app data; use actions and the panel query path.
- No raw `fetch` from client code; use `useActionQuery` and `callAction`.
- No `process.env` reads for provider credentials.
- No `catch` or default that turns a failure into a normal-looking value:
  an unknown data source status shows no demo suggestions and is not
  treated as "nothing connected"; a failed demo panel shows its error.
- No large payloads in SQL.
- No raw color classes, no emoji icons, no custom popovers; shadcn `Alert`
  and `Button`, Tabler icons.
- Do not include demo panels in any real-data dashboard or report.
