# 8.4a1 Drillable charts: click a point to filter, exclude or break down

Lane E (Holy-shit features). Size M. Gated: the drill menu on a chart mark and
the drill chips above the chart are new UI; build only after the "Chart:
drill menu" and "Chart: drilled" screens in `prototypes/analytics-operators/`
are signed off. Where the signed-off prototype differs from this brief, the
prototype wins.

Depends on: 1.1a (Add as filter hand-off and `applyPanelEdit`), 1.2 (the chart
edit toolbar the drill chips sit under), prototype sign-off. Merge after 1.2
and 1.1b. Blocks: 8.4a2 (Top N reuses the drill transform helper), 8.4a3.

The plan's 8.4a is split in three: 8.4a1 (this unit) makes chart marks
drillable; 8.4a2 adds Top N and ratio and weighted-average calculations;
8.4a3 adds pivot table panels with subtotals.

Paths are relative to `templates/analytics/` unless they start with
`packages/`.

## 1. Goal

A person looking at a bar, line, area or pie chart clicks a bar, a point or a
slice and gets a short menu: Filter to that value, Exclude it, Break down by
another column, Show rows, or (for editors) Add as filter. The chart narrows at
once, a chip above the chart says what it is drilled to, and the chip's x
undoes it. The drill lives in the URL, so a copied link opens the same drilled
view and the agent can read it and set it. Nothing is saved to the panel; a
drill is a way to look, not an edit.

## 2. What the code does today

  `Line`, `Area`, `Pie` or `Cell`, and every `dot` is `dot={false}`. The only
  click handlers are the legend button (`app/components/dashboard/SqlChart.tsx:770`),
  the legend popover's Filter and Hide (`:810`, `:825`), the table header
  (`:1990`) and pagination (`:2121`, `:2130`).
- Renderers: `PieRenderer` `:2142-2199` (`Cell` at `:2177`, recharts' own
  `Legend` at `:2193`), `BarRenderer` `:2201-2292` (`BarChart` at `:2244`,
  `Bar` at `:2274-2286`), `ComboRenderer` `:2294-2397` (`ComposedChart` at
  `:2338`), `TimeSeriesRenderer` `:2399-2631` (`LineChart` at `:2461`,
  `AreaChart` at `:2539`). Dispatch by chart type is at `:1471-1565`.
- The legend already has view-only Filter and Hide per series:
  `SeriesLegend` (`:667-842`) over `useSeriesVisibility` (`:618-665`), whose
  state is local `useState` and never saved; `filterSeries` (`:657-662`) hides
  every other series. That is a series filter, not a row filter: it cannot
  narrow a bar chart to one category.
- `config.pivot` (`app/pages/adhoc/sql-dashboard/types.ts:61-65`) reshapes long
  rows to one series per value of `seriesKey` through `pivotRows`
  (`app/pages/adhoc/sql-dashboard/pivot.ts:104`), applied in `planPanelRender`
  (`shared/panel-render-contract.ts:690-749`, pivot at `:697-703`) and in email

  (`shared/panel-render-contract.ts:612-640`). Query results carry
  `truncated` (`server/lib/dashboard-panel-query.ts:57`).
- Dashboard filters live in the URL as `f_<id>` (`FILTER_PARAM_PREFIX`,
  `app/pages/adhoc/sql-dashboard/filter-vars.ts:4`; `resolveFilterVars`
  `:163-221`), feed `vars` (`app/pages/adhoc/sql-dashboard/index.tsx:1524-1532`)
  and the per-panel `resolvedSql` (`:351-359`). `view-screen` reads `f_`
  params into `activeFilters` (`actions/view-screen.ts:258-268`), and the agent

  description says (`actions/navigate.ts:56`).
- Panel selection reaches `selected-object` through
  `DashboardPanelChatContextArgs` (`app/hooks/use-dashboard-chat-context.ts:32-42`,
  written as `type: "dashboard-panel"` at `:187`).
- `SqlChartCard` already hands panel context to the agent with
  `sendToAgentChat` (`app/pages/adhoc/sql-dashboard/SqlChartCard.tsx:339`).
- Not built yet: 1.1a's column menu, Add as filter hand-off and `applyPanelEdit`,
  and 1.2's chart edit toolbar (briefs `tasks/1.1a-table-column-menu.md`,
  `tasks/1.2-click-to-edit-charts.md`). `panel-edits.ts` and
  `ChartEditToolbar.tsx` do not exist on the integration branch.

## Plan corrections

- "Click a point to drill, pivot, filter" mixes two kinds of change. Filter to,
  Exclude and Break down on rows the query already returned are views and run
  in the browser with no new query. Breaking down by a column the result does
  not contain needs new SQL, so that item hands the request to the agent the
  way 1.1a's Add as filter does (decision D1 there), instead of guessing SQL.
- Pivot, Top N and the calculations are split into 8.4a2 and 8.4a3 so each
  unit stays M.

## 3. Build

1. **Drill state, one shape.** Add `shared/panel-drill.ts`:
   - `PanelDrill = { filters: { key: string; op: "in" | "notIn"; values: string[] }[]; breakdownKey?: string }`.
   - `parsePanelDrill(raw: string): PanelDrill` and `serializePanelDrill(drill)`:
     a compact JSON string, at most 8 filters and 20 values each, values at
     most 200 characters. Bad input throws a typed `PanelDrillParseError`; the
     card shows the chip row's "This drill link is invalid" state with Clear,
     never a silently undrilled chart that looks drilled.
   - `applyPanelDrill(rows, panel, drill): { rows; breakdown?: PivotConfig; partial: boolean }`:
     filters rows by value (string comparison after the same `pivotKey`
     normalization `pivot.ts` uses), and for a breakdown returns a
     `PivotConfig` of `{ xKey, seriesKey: breakdownKey, valueKey }` that
     `planPanelRender` applies through `pivotRows`. A breakdown is refused (a
     typed error) when the panel already has `config.pivot` with a different
     `seriesKey` or when the chart is a pie. `partial` is true when the result
     was `truncated` or when `limitChartRows` dropped rows.
   - Call `applyPanelDrill` inside `planPanelRender` (one place), so the chart,
     the card's Show rows table and any future server render see the same rows.
2. **URL state.** The drill for a panel lives in the URL as
   `d_<panelId>=<serialized drill>`, next to `f_` filters. Add
   `DRILL_PARAM_PREFIX = "d_"` beside `FILTER_PARAM_PREFIX` in
   `filter-vars.ts`. `PanelCell` (`index.tsx:279`) reads its own param and
   passes `drill` to `SqlChartCard` and `SqlChart`. Setting a drill uses the
   same `setSearchParams` path `DashboardFilterBar` uses
   (`DashboardFilterBar.tsx:129-142`), with history `replace`.
3. **Marks become clickable.** In `BarRenderer`, `ComboRenderer`,
   `TimeSeriesRenderer` and `PieRenderer`, add `onClick` on the chart (recharts
   reports `activeLabel` and `activePayload`) and on `Pie` `Cell`s. Each click
   resolves `{ xKey, xValue, seriesKey?, seriesValue? }` from the row and calls
   a new `onDrillRequest` prop. Keyboard: recharts' accessibility layer moves
   the active index with the arrow keys; Enter on the active point opens the
   same menu (check `accessibilityLayer` is on in recharts 3.8 and turn it on
   where a renderer disables it). Heatmap, funnel, callout, metric and table
   are out of scope (funnel steps already open replays in 4.3; tables have
   1.1a's column menu).
4. **The drill menu.** New `app/components/dashboard/ChartDrillMenu.tsx`: a
   shadcn `Popover` anchored at the clicked mark through `PopoverAnchor` (no
   hand-positioned menu), with text-only menu items, `role="menu"`:
   - Filter to {{value}}
   - Exclude {{value}}
   - Break down by (a submenu of the result's other text columns, excluding
     the x key and current series key; disabled with a tooltip when there are
     none, and replaced by "Ask the agent to break this down" for editors)
   - Show rows (opens the card's existing full-screen view on the table of
     drilled rows)
   - separator, then Add as filter for editors when the clicked column is a
     text column that is not already a dashboard filter (reuse 1.1a's
     hand-off: `sendToAgentChat` with `submit: false`, the prompt, and the
     column chip).
   For a series point the value is the x value; a second group offers Filter
   to and Exclude for the series value when the panel has `config.pivot`.
5. **Drill chips.** Under the card header (and under 1.2's toolbar when it is
   open), one row of chips, one per drill filter ("Plan is Pro", "Plan is not
   Free", "By region"), each with an x (`IconX`, 14px, aria label
   `chartDrill.removeChip`), then a ghost Clear drill button when there are two
   or more. When `partial` is true, an amber `IconAlertTriangle` chip
   "Drilled from the first {{count}} rows" with a tooltip that the query
   returned more rows than the chart holds. No chip row when there is no drill.
6. **Agent parity.** The agent reads the drill from `view-screen` and sets it
   with `set-search-params`:
   - `actions/view-screen.ts:258-268`: also collect `d_` params, parsed with
     `parsePanelDrill`, into `screen.panelDrills` keyed by panel id. A parse
     failure is reported as `{ panelId, error }`, not dropped.
   - The chart's data the agent reads through `get-sql-dashboard` and
     `query-dashboard-panel` is undrilled; the dashboard skill tells the agent
     to apply the same filters in its own SQL or say which drill it ignored.
7. **Application state.** Extend `DashboardPanelChatContextArgs`
   (`use-dashboard-chat-context.ts:32-42`) with `point?: { key: string; value: string; seriesKey?: string; seriesValue?: string }`.
   Opening the drill menu publishes `selected-object` with `pointKey`,
   `pointValue` and the series fields, and adds `Selected point: <key> = <value>`
   to the chat context lines. A later panel-only selection clears them. No
   new app-state key.
8. **Skills.** Read `.agents/skills/writing-agent-instructions` first. In
   `.agents/skills/dashboard-management/SKILL.md`, under the click-edits
   subsection 1.1a creates, add "Chart drills": drills are URL view state
   `d_<panelId>`, never saved to the panel; read them from
   `view-screen.panelDrills`; set them with `set-search-params`; "this point"
   means `selected-object.pointKey` and `pointValue`; a breakdown by a column
   the SQL does not return needs an SQL edit through `mutate-dashboard`. Do not
   add to `AGENTS.md` (4,890 characters on the integration branch).
9. **Changelog.** `agent-native changelog add "Click a chart bar, point or slice to filter to it, exclude it or break it down" --type added`.

## 8. Defaults for open questions

- [Default] Drills are per-viewer URL state and never saved to the panel.
  Saving a filter is Add as filter (agent) or 8.4a2's saved transforms.
- [Default] Drills run on the rows the query returned; a truncated result
  shows the amber partial chip rather than re-querying.
- [Default] Bar, line, area, combo and pie only.
- [Default] Breaking down by a column the result lacks goes to the agent.

## 9. Do not

- Do not change the legend's Filter and Hide, which stay series visibility.
- Do not re-run the panel query for a drill.
- No behavior changes outside the unit; additive-only schema; no new /api
  routes for app data (use actions); no raw fetch from client code; no
  process.env reads for provider credentials; no catch or default that turns a
  failure into a normal-looking value; no large payloads in SQL.
