# 8.5c2 Signed embedding: the embed page, frame policy and the Embed tab

Lane E (Holy-shit features). Size M. Gated: the embedded view and the Embed
tab in the share panel are new UI; build only after the "Embed: in a host
page" and "Share: embed" screens in `prototypes/analytics-operators/` are
signed off. Where the signed-off prototype differs from this brief, the
prototype wins.

Depends on: 8.5c1, 1.9 (share panel tabs), 8.5d (phone-width reading, since
embeds are often narrow). Blocks: nothing.

Paths are relative to `templates/analytics/` unless they start with
`packages/`.

## 1. Goal

A host page puts one iframe on its page pointing at
`https://<analytics>/embed/<embedId>#token=<signed token>`. The frame shows
the dashboard or app, clean, with no Analytics chrome, filtered to the
token's scope, with only the unlocked filters as controls. It loads only on
the origins the embed allows. In Analytics, the Share panel's Embed tab is
where an author creates the embed, copies the snippet and secret once, sets
origins and locked filters, rotates the secret and revokes it.

## 2. What the code does today

- SSR is one impersonal, public, CDN-cached shell for every visitor
  (CLAUDE.md, Frontend And UX; enforced by `guard:ssr-cache-shell`,
  `scripts/guard-ssr-cache-shell.mjs:33-106`, and
  `packages/core/src/server/ssr-handler.spec.ts`, including "ignores an
  embed-token credential and renders SSR impersonally" at `:1009`).
  `requestForAnonymousSsr` strips cookies and authorization
  (`packages/core/src/server/ssr-handler.ts:171-185`); the handler removes any
  document CSP a route sets (`removeDocumentCsp`, `:405-408`, applied at
  `:489`).
- No frame header is set globally: "`X-Frame-Options` is intentionally not set
  globally" (`packages/core/src/server/security-headers.ts:54-57`). The
  precedent for a per-path frame policy is a Nitro `response` hook in Design
  that sets `Content-Security-Policy: frame-ancestors <allowlist>`
  (`templates/design/server/plugins/builder-host-embed-headers.ts:11-36`),
  which must be a response hook because core sets its headers later.
- Public pages are client-side decisions: `AppProviders isPublicPath`
  (`packages/core/docs/content/authentication.mdx:492`). Analytics already has
  a chrome-less, session-less frame mode for signed replay links
  (`app/root.tsx:143-163`) and bare routes (`BARE_ROUTES`,
  `app/components/layout/Layout.tsx:51`, rendered at `:234-240`).
- There is no `/embed` route in `app/routes/`.
- The sharing skill allows an app-specific share tab for "an embed-code
  editor" that keeps the shared trigger, copy row and spacing
  (`.agents/skills/sharing/SKILL.md:228-230`). 1.9 (brief) moves the share
  panel to People and Agents tabs at the compact density.
- Mobile layout: panels stack below a 768px container width
  (`app/global.css:551-562`, `:656-665`); 8.5d makes narrow frames read well.

## 3. Build

1. **Route.** `app/routes/embed.$embedId.tsx`, a client-only page (no loader
   data, so the SSR shell stays the same bytes for every visitor). Add
   `/embed/` to the public paths `AppProviders` gets in `app/root.tsx`, next
   to the replay frame mode, and to `BARE_ROUTES`. The token is read from the
   URL fragment (`#token=`), which never reaches the server, the CDN cache key
   or a referrer; the page then clears the fragment with `history.replaceState`.
2. **Data.** The page calls 8.5c1's `get-embed-data` through a named client
   helper in `app/lib/embed-client.ts` (no raw `fetch` in components; if
   `callAction` already works for public actions use it inside the helper).
   It renders panels with the existing `SqlChart` given `resultOverride` rows
   (no client query), in the stored order, with the dashboard grid or the
   notebook app layout (7.5). Unlocked filters render in `DashboardFilterBar`;
   changing one re-requests data with the same token. Locked filters do not
   render.
3. **Token refresh.** The host is expected to reload the frame with a new
   token before `exp`. On `expired` the page posts
   `{ type: "agent-native-embed", event: "token-expired", embedId }` to
   `window.parent` (targeting the allowed origin only) and shows "This view
   expired. Reload the page to continue." Other failures show one plain line
   each (invalid link, not allowed on this site, unavailable). Never a blank
   or a half-rendered dashboard.
4. **Frame policy.** `server/plugins/embed-frame-headers.ts`, a Nitro
   `response` hook following Design's: for `/embed/<id>` only, set
   `Content-Security-Policy: frame-ancestors <allowed origins of that embed>`
   (or `'none'` when the embed is unknown or revoked) and
   `Referrer-Policy: no-referrer`. It reads only the path, never cookies, so
   the response stays an impersonal shell (no `private`, `no-store` or
   `Vary: Cookie`; run `pnpm guard:ssr-cache-shell`). Because the CDN caches
   the shell with its headers, an origin change takes effect when the cached
   shell expires; state the TTL from `resolveSsrCacheHeaders` in the Embed tab
   ("Changes to allowed sites can take up to {{time}}").
5. **Embed tab (gated UI).** In the dashboard and notebook share panel (1.9's
   tabs, compact density), an Embed tab for editors: when no embed exists, a
   short form (Allowed sites as a list of origins with Add; Locked filters as
   a multi-select of the dashboard's filters) and a primary Create embed at
   the compact size. After creating: the iframe snippet in `ShareCopyRow`, the
   secret in a second copy row shown once with an amber note "Copy this
   secret now. You won't see it again.", and links to the signing guide in the
   skill. Existing embeds show origins, locked filters, Rotate secret (an
   `AlertDialog`: old tokens stop working) and Revoke embed (red, an
   `AlertDialog`, since it breaks every host page using it). Refusals from
   `create-embed` (panels that don't read a locked filter) list the panels.
6. **Application state.** None new; the share panel's tab is local state.
7. **Skills.** Extend 8.5c1's `.agents/skills/embedding/SKILL.md` with the
   iframe snippet, the fragment token, the expiry message to the parent, and
   the origin TTL.
8. **Changelog.** `agent-native changelog add "Embed a dashboard or notebook app in your own product with signed, expiring links scoped to each customer" --type added`.

## 8. Defaults for open questions

- [Default] Token in the URL fragment, not the query string.
- [Default] No Analytics chrome, chat or export inside an embed in v1.
- [Default] Origin changes follow the shell's CDN TTL rather than bypassing
  the cache.

## 9. Do not

- Do not read cookies, add `private`, `no-store` or `Vary: Cookie` to the SSR
  path, or put embed data in the SSR shell.
- Do not set a global frame policy.
- No behavior changes outside the unit; additive-only schema; no new /api
  routes for app data (use actions); no raw fetch from client code; no
  process.env reads for provider credentials; no catch or default that turns a
  failure into a normal-looking value; no large payloads in SQL.
