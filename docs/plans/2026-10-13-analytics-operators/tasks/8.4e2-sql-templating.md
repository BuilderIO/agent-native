# 8.4e2 SQL templating: inputs in SQL, completion, lint and resolved preview

Lane E (Holy-shit features). Size M. Gated: the Insert input menu, the token
warnings and the Resolved SQL preview are new UI; build only after the "SQL
editor: inputs" screen in `prototypes/analytics-operators/` is signed off.
Where the signed-off prototype differs from this brief, the prototype wins.

Depends on: 8.4e1 (CodeMirror editor), 7.5 (input cells are filters). Merge
after 8.4e1. Blocks: nothing.

Paths are relative to `templates/analytics/` unless they start with
`packages/`.

## 1. Goal

When writing SQL, the author types `{{` and picks a dashboard filter or
notebook input from a list that shows each one's forms (`{{plan}}`,
`{{plan:list}}`, `{{createdStart}}` and `{{createdEnd}}`, an optional block
`{{?plan}} ... {{/plan}}`). A token that names nothing is underlined amber
with "No filter or input is called this", instead of silently running as an
empty string. A Resolved SQL toggle shows exactly what will run with the
current filter values. Saving a panel whose SQL names a missing token is
refused with a plain reason, for the UI and the agent alike.

## 2. What the code does today

- Interpolation is `interpolateDashboardPanelSql(sql, vars, panel)`
  (`app/pages/adhoc/sql-dashboard/interpolate.ts:36-40`) over
  `interpolate` (`:139-213`):
  - `{{name}}` and `{{name:list}}` in one pass (`:192-212`); `:list` splits on
    commas into quoted items, empty becomes `__empty_list_filter__` (`:196-201`).
  - Optional blocks `{{?name}}...{{/name}}` kept only when the value is
    non-empty (`:179-186`).
  - Time variables (`timeRange`, names ending `Start` or `End`, `:61-63`) fail
    closed to `__missing_dashboard_time_filter__` (`:202-208`); custom ranges
    are validated (`:147-177`).
  - **Any other unknown token becomes an empty string** (`:209`:
    `if (value == null) return "";`). A typo like `{{pln}}` runs as `''` and
    returns plausible wrong rows.
- Values come from `config.filters` and `config.variables` through
  `resolveFilterVars` (`app/pages/adhoc/sql-dashboard/filter-vars.ts:163-221`)
  and the `vars` memo (`app/pages/adhoc/sql-dashboard/index.tsx:1524-1532`).
  `panelSqlTokenNames` and `panelUsesFilters` read a panel's tokens
  (`filter-vars.ts:254`).
- The panel editor shows one static hint about `{{varName}}`
  (`panelEditor.filterInterpolation`, `PanelEditorDialog.tsx:776-780`).
- 7.5 (brief) makes notebook input cells render `config.filters` entries and
  shows "Use {{token}} in SQL" in the input form.
- 8.4e1 rebuilds `SqlEditor` on CodeMirror with completion.

## Plan corrections

- The unknown-token fallback at `interpolate.ts:209` is a silent coercion.
  Changing it at run time could break saved panels that rely on it, so this
  unit catches it at the edges instead: lint in the editor, a validation
  issue on save for panels whose SQL changed, and a verification note for
  existing panels. Run-time behavior for unchanged saved panels stays.

## 3. Build

1. **Token catalog.** New `shared/sql-tokens.ts`:
   - `availableTokens(config): { name; label; forms: string[]; kind: "filter" | "variable" | "input" }[]`
     from `config.filters` (with `Start`/`End` for date ranges and `:list`
     for multi-select) and `config.variables`.
   - `findTokens(sql): { name; form: "value" | "list" | "block"; from; to }[]`
     using the same regexes as `interpolate.ts` (export them from there so the
     two can never disagree).
   - `unknownTokens(sql, config)`: tokens that are not available and are not
     framework time variables.
2. **Save validation.** In `collectDashboardConfigIssues`
   (`actions/update-dashboard.ts`) and the `mutate-dashboard` SQL validation
   scope, a panel whose `sql` changed in this write and names an unknown
   token is an issue: "{{panel}} uses {{token}}, but no filter or input is
   called that. Add the filter or fix the name." Panels whose SQL did not
   change are not blocked.
3. **Verification note.** In `server/lib/dashboard-panel-verification.ts`, a
   verified panel with unknown tokens gets a `notes` entry
   `unknown_tokens:<names>` so the agent reports it, and the panel card shows
   1.5a's amber warning state for editors.
4. **Editor completion (gated UI).** In 8.4e1's CodeMirror setup, typing
   `{{` opens completions from `availableTokens`: label, kind, and each form
   as its own option; `{{?` offers the block form and inserts both tags with
   the cursor between. An Insert input `DropdownMenu` (text-only) at the
   editor's top edge lists the same tokens for mouse users.
5. **Lint.** A CodeMirror lint source marks `unknownTokens` with an amber
   underline and the tooltip "No filter or input is called {{name}}". A
   `:list` form on a single-value filter is linted too ("{{name}} holds one
   value. Use {{form}}.").
6. **Resolved SQL preview.** A Resolved SQL toggle (`Switch`, compact) at the
   editor's top edge swaps in a read-only view of
   `interpolateDashboardPanelSql(sql, vars, panel)` with the page's current
   `vars`, recomputed as filters change. When interpolation yields one of the
   sentinel strings (`__missing_dashboard_time_filter__`,
   `__invalid_custom_date_range__`, `__empty_list_filter__`), the preview
   shows the matching plain message above it instead of only the sentinel.
7. **Agent.** `get-sql-dashboard` already returns filters; add
   `availableTokens` to its compact output for SQL dashboards (names and
   forms only). The `mutate-dashboard` issue in step 2 tells the agent what to
   fix. No new action.
8. **Application state.** None new.
9. **Skills.** `.agents/skills/dashboard-management/SKILL.md` "Filters And
   Variables" (`:348`): the token forms, that unknown tokens are refused on
   save and flagged on old panels, and how to read `availableTokens`. Keep it
   in the skill; do not grow `AGENTS.md`.
10. **Changelog.** `agent-native changelog add "Pick filters and inputs while writing SQL, see the SQL that will run, and catch misspelled inputs" --type improved`.

## 8. Defaults for open questions

- [Default] Unknown tokens are refused only on panels whose SQL changes;
  existing panels get a warning, not a block.
- [Default] No new template syntax (no loops or expressions); the existing
  forms only.

## 9. Do not

- Do not change `interpolate.ts` run-time output for saved panels.
- Do not add a second token parser; share the regexes.
- No behavior changes outside the unit; additive-only schema; no new /api
  routes for app data (use actions); no raw fetch from client code; no
  process.env reads for provider credentials; no catch or default that turns a
  failure into a normal-looking value; no large payloads in SQL.
