# 1.6b Time budget for questions: Analytics adopts the cap, shows progress in plain words, and logs time to answer

Lane A (Reliability). Size M. Not gated.

Second half of the plan's PR 1.6. 1.6a adds the framework budget, the
closeout and the "Partial answer" label. This unit turns it on for
Analytics, replaces tool names with plain words while the agent works, keeps
the Analytics answer guard from fighting the closeout, and records how long
each question took and how it ended.

## 1. Goal

An Analytics question gets an answer within five minutes: complete, or
clearly labeled partial with what is missing. While it works, the chat shows
what it is doing in plain words ("Find the right data", "Query BigQuery",
"Check the panel") instead of action ids ("query agent native analytics",
"search bigquery schema"), next to the existing "Working for 1m 20s". Every
finished question records its time to answer and whether it was complete,
partial, stopped or failed, so the team can watch median time to answer
(the plan's Phase 1 metric).

## 2. What the code does today

All paths relative to `templates/analytics/` unless they start with
`packages/`.

- **Run limits.** Analytics sets a 13 minute chunk timeout and a 3 minute
  no-progress timeout and opts into durable background runs
  (`server/plugins/agent-chat.ts:52-53`, `:1229-1263`, options at
  `:1244-1249`). With the framework's 20 chained continuations and 90 minute
  turn wall clock (see 1.6a section 2), one question can run far past the
  five minutes the comparison product needed; the reported 25 minute run
  that ended in an error fits inside these limits.
- **Progress copy.** A tool row's text is `toolLabel(t, toolName)`
  (`packages/toolkit/src/app/chat/chat/tool-call-display.tsx:946`), which
  looks up `agentChat.toolLabels.<tool-name>` and falls back to the
  humanized id (`packages/core/src/client/tool-display.ts:7-37`). No app,
  including Analytics, defines any `toolLabels` key (`rg toolLabels` finds
  only the lookup). App catalogs are merged over the toolkit's
  (`packages/toolkit/src/app/i18n.ts:48-80`), so an Analytics catalog entry
  overrides the fallback. The run header already reads "Working" and
  "Working for {{duration}}"
  (`packages/toolkit/src/app/i18n/catalogs/en-US.ts:1398-1399`).
- **Answer guard.** `realDataFinalGuard` (`server/plugins/agent-chat.ts:860`
  on) retries drafts that make data claims without a query, with
  `maxRetries: 2` and `expandToolSurface: true` (for example `:1110-1140`).
  During a time-budget closeout the model has no tools, so those retries can
  only produce the fallback text. It already recognizes explicit partial
  wording through `hasExplicitPartialDisclosure`
  (`server/lib/real-data-actions.ts:1167-1169`) in the incomplete-evidence
  branch (`agent-chat.ts:961-974`).
- **Run telemetry.** `onAgentRunComplete` tracks
  `analytics_agent_run_outcome` once per chunk with tool, catalog and query
  counts and `first_query_errored` (`agent-chat.ts:1231-1262`,
  `server/lib/analytics-agent-context.ts:77-157`). It ignores the
  `turnContinues` outcome argument, so it cannot tell a finished question
  from a chunk, and it records no duration. Core records per-chunk
  `duration_ms` in `agent_run_terminal` (`packages/core/src/agent/run-manager.ts:602-660`),
  which is not time to answer for a question that spans chunks.
- **Prompt budget.** `ANALYTICS_PROMPT_RULES` is counted by
  `server/plugins/agent-chat-baseline.spec.ts` (`agent-chat.ts:273-275`), so
  adding a rule costs tokens on every turn.
- **Catalogs.** `app/i18n/en-US.ts` plus `zh-CN`, `zh-TW`, `es-ES`, `fr-FR`,
  `de-DE`, `ja-JP`, `ko-KR`, `pt-BR`, `hi-IN`, `ar-SA` (`app/i18n/index.ts:5-18`).

## 3. Build

1. **Turn it on.** Pass `answerTimeBudgetMs: ANALYTICS_ANSWER_TIME_BUDGET_MS`
   (5 minutes, D1) to `createAgentChatPlugin` in `server/plugins/agent-chat.ts`
   next to `runSoftTimeoutMs`. Leave the chunk and no-progress timeouts as
   they are; the budget is shorter, so it ends the question first.
2. **Guard and closeout agree.** At the top of `realDataFinalGuard`, when
   `context.closeout === "answer_budget"` (1.6a), return a guard only for the
   one case the closeout can fix without tools: the draft makes metric
   claims and lacks a partial disclosure. Return
   `{ retryMessage, maxRetries: 0, exhaustedDraftPrefix }` so core shows the
   prefix, never a retry. Prefix (agent-generated text is shown to the user,
   so keep it short and plain): reuse the existing unverified wording
   pattern, "Unverified: some numbers below came from steps that did not
   finish." Everything else returns `null` during closeout.
3. **Plain-word tool labels.** Add an `agentChat.toolLabels` block to
   `app/i18n/en-US.ts` and all ten locale files for the tools a data
   question uses (table in section 4). First add a test that proves an app
   catalog key overrides the toolkit fallback through
   `createToolkitI18nCatalog` (the catalogs are flat dotted keys in the
   toolkit; check how `normalizeMessages` treats a nested app object and use
   the shape that resolves). Provider and product names stay untranslated
   (`internationalization` skill).
4. **Time to answer.** Change the `onAgentRunComplete` handler
   (`agent-chat.ts:1231`) to take the outcome argument. When
   `outcome.turnContinues` is false, add to `analytics_agent_run_outcome`:
   `turn_complete: true`, `time_to_answer_ms` (`Date.now() -
   outcome.turnStartedAtMs`; omit when `turnStartedAtMs` is null),
   `turn_start_source` (`turn`, `run` or `unreadable`), `answer_status`
   (`complete`, `partial` when the terminal reason is `answer_time_budget`,
   `out_of_time` for `answer_time_budget_exhausted`, `stopped`, `failed`),
   `answer_budget_ms`, and `question_kind` from the tools used
   (`dashboard_edit` if any `DASHBOARD_EDIT_TOOLS` ran, `data` if a query
   tool ran, else `other`; reuse the sets in `analytics-agent-context.ts`).
   When it is true, add `turn_complete: false` only, so chunk events can be
   filtered out. Put the derivation in `summarizeAnalyticsRun` (pure,
   testable), not inline in the plugin.
5. **Where to read it.** Find where `track` delivers in this app
   (`packages/core/src/tracking/registry.ts`). If it lands in the app's own
   first-party events, add one saved query example to the data dictionary
   seed or `find-data` catalog (whichever already holds query examples) for
   "median time to answer by day and answer status", and one line to
   `.agents/skills/data-querying/SKILL.md` pointing to it. If it lands only
   in an external provider, say so in the PR and skip the example.
6. **Instructions.** No new prompt rule (D3). In
   `.agents/skills/adhoc-analysis/SKILL.md` (or whichever analytics skill owns
   long multi-source questions; check `cross-source-analysis` too), add two
   sentences: questions have a five minute budget; start with the one bounded
   query that answers the core of the question, then widen, so a partial
   answer still has the main number.
7. **Changelog.** `agent-native changelog add "Questions now answer within five minutes, and an answer that hit the limit is labeled partial and says what is missing." --type improved`.

Four areas: **UI** (step 3, labels; the partial label itself is 1.6a),
**actions** (none; plugin options and telemetry), **skills and
instructions** (steps 2 and 6), **application state** (does not apply: run
progress is already streamed to the chat and time to answer is telemetry).

## 5. Tests

- `server/lib/analytics-agent-context.spec.ts`: `summarizeAnalyticsRun`
  with a final-chunk outcome returns `time_to_answer_ms`, `answer_status`
  for each terminal reason and `question_kind`; with
  `turnStartedAtMs: null` it omits `time_to_answer_ms` and sets
  `turn_start_source: "unreadable"`; a continuing chunk returns only
  `turn_complete: false`.
- `server/plugins/agent-chat.spec.ts`: during `closeout: "answer_budget"`,
  `realDataFinalGuard` never returns `maxRetries > 0` or
  `expandToolSurface`, and returns the prefix for an undisclosed metric
  claim.
- `server/plugins/agent-chat-baseline.spec.ts`: unchanged budget (no new
  rule).
- `app/i18n` test (beside an existing catalog spec, or
  `app/lib/register-analysis-result-renderer.spec.tsx`'s setup): the
  Analytics catalog resolves `agentChat.toolLabels.find-data` to the app
  string through `toolLabel`.
- No source-reading tests.

## 7. Dependencies

- Needs: 1.6a (option, closeout context, outcome fields, label).
- Hotspots: `server/plugins/agent-chat.ts` (1.3a), `app/i18n/*.ts` (every UI
  unit), `server/lib/analytics-agent-context.ts`.

## 8. Defaults for open questions

- **D1.** Five minutes for every interactive Analytics turn, including
  dashboard builds; a build that hits it reports what it saved and offers to
  continue. The plan's comparison point was under five minutes.
  *Reviewer may change.*
- **D2.** `question_kind` comes from the tools that ran, not from
  classifying the request text, because the request text is not passed to
  `onAgentRunComplete`. *Reviewer may change.*
- **D3.** No new always-on prompt rule; the closeout carries the instruction
  when it matters and the skill carries the planning advice.
  *Reviewer may change.*
- **D4.** Labels cover the 21 tools above; others keep the humanized
  fallback. *Reviewer may change.*

## 9. Do not

- No behavior changes outside this unit: do not change the chunk timeout,
  no-progress timeout or durable background setting.
- Schema: none.
- No new `/api` routes.
- No raw `fetch` from client code.
- No `process.env` reads for provider credentials, and no `process.env` read
  for the budget either; it is a constant passed as a plugin option.
- No `catch` or default that turns a failure into a normal-looking value: an
  unreadable turn start omits `time_to_answer_ms`, never records 0.
- No large payloads in SQL or telemetry: no prompt text, SQL or results in
  `analytics_agent_run_outcome`.
