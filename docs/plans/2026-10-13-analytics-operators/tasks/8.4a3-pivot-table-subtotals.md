# 8.4a3 Pivot table panels with subtotals

Lane E (Holy-shit features). Size M. Gated: the pivot table panel and its
Rows, Columns and Values controls are new UI; build only after the "Pivot
table" and "Pivot table: fields" screens in `prototypes/analytics-operators/`
are signed off. Where the signed-off prototype differs from this brief, the
prototype wins.

Depends on: 8.4a2 (`combineRows` and calcs), 1.1a (`shared/table-cell-format.ts`,
`applyPanelEdit`), 1.2 (chart toolbar). Blocks: 8.4b1 (the Pivot cell renders
with this panel type).

Paths are relative to `templates/analytics/` unless they start with
`packages/`.

## 1. Goal

A RevOps lead turns a long result (region, plan, month, MRR, accounts) into a
pivot table: regions down the side, months across the top, MRR and ARPA in the
cells, with a subtotal per region group and a grand total, by picking fields
instead of writing a `GROUP BY ROLLUP`. Clicking a cell drills like a chart
point (8.4a1). Email reports show the same table.

## 2. What the code does today

- There is no pivot table chart type. `PANEL_CHART_TYPES`
  (`app/pages/adhoc/sql-dashboard/types.ts:5-18`) is line, area, bar, combo,
  metric, table, pie, section, funnel, heatmap, callout, extension.
- `config.pivot` (`types.ts:61-65`, `PivotConfig { xKey, seriesKey, valueKey }`)
  is a long-to-wide reshape for chart series, through `pivotRows`
  (`app/pages/adhoc/sql-dashboard/pivot.ts:104`), used by `planPanelRender`
  (`shared/panel-render-contract.ts:697-703`) and the report renderer
  (`server/lib/dashboard-report-render.ts:443`). It has one row key, one
  column key, one value and no totals.
- `TableRenderer` (`app/components/dashboard/SqlChart.tsx:1858`) renders flat
  rows with `config.columns`, sortable headers (`:1990`) and pagination
  (`:2121`, `:2130`); no grouping, no totals.
- No subtotal code exists in the template.
- 8.4a2 adds `combineRows` (sums parts, recomputes ratio and weighted average)
  in `shared/panel-calcs.ts`; 1.1a adds `shared/table-cell-format.ts`.
- New chart types are append-only to `PANEL_CHART_TYPES` (plan README section
  7, conflict table: `text` 7.1a, `retention` 4.1d, `input` 7.5).

## Plan corrections

- The name `pivot` is taken by the series reshape config. The new chart type
  is `pivot-table` with config `pivotTable`, and `config.pivot` keeps its
  meaning.

## 3. Build

1. **Type and config.** Append `"pivot-table"` to `PANEL_CHART_TYPES`, the
   panel editor's `CHART_TYPES` (`PanelEditorDialog.tsx:54-67`) and the chart
   type lists the conflict table names (`app/routes/chart.tsx`,
   `AnalyticsReviewArtifactPreview.tsx`, `NewDashboardDialog.tsx`). Add
   `pivotTable?: { rows: string[]; columns: string[]; values: { key: string; agg: "sum" | "avg" | "min" | "max" | "count" }[]; subtotals: boolean; grandTotal: boolean }`
   to `SqlPanelConfig` and register it in `PANEL_CONFIG_KEYS` with
   `onlyFor: ["pivot-table"]` and a value check (rows and columns at most 3
   keys each, values at most 6, keys are result columns or 8.4a2 calc ids).
2. **Builder.** New `shared/pivot-table.ts`:
   `buildPivotTable(rows, spec, calcs): PivotTableModel` returning row header
   tree, column header tree, cell values, subtotal rows per row group (when
   `subtotals`), and grand total row and column (when `grandTotal`). Every
   combined cell goes through 8.4a2's `combineRows`, so a ratio subtotal is
   sum over sum. `avg` is computed from sum and count, never as an average of
   averages; `min`, `max`, `count` combine directly. Caps: at most 200 row
   leaves and 50 column leaves; beyond that the model returns
   `{ capped: { rows, columns } }` and the renderer says so, it does not drop
   them silently.
3. **Renderer.** `PivotTableRenderer` in `SqlChart.tsx` (dispatch beside
   `TableRenderer`, `:1471-1565`): sticky row headers, a header row per column
   level, subtotal rows in `font-medium` with a `bg-muted/50` token background,
   grand total last. Numbers format through `shared/table-cell-format.ts` with
   the value's format (or the calc's). Horizontal overflow scrolls inside the
   card. Clicking a cell calls 8.4a1's `onDrillRequest` with the row and
   column path, so Filter to and Exclude work on pivot cells. Amber note when
   capped or when the result was truncated.
4. **Fields control.** In 1.2's toolbar, for `pivot-table` panels, three
   controls: Rows, Columns, Values. Rows and Columns are `Popover` + `Command`
   multi-select lists of text columns (order is pick order; drag to reorder is
   out of scope, Move up and Move down in each chip's menu). Values is a list
   of value chips, each with an aggregation `DropdownMenu` (Sum, Average,
   Minimum, Maximum, Count) and Remove; Add value lists number columns and
   calcs. Two `Switch`es: Subtotals and Grand total. Every change saves through
   `applyPanelEdit` with one `updatePanelPath` on `pivotTable`.
5. **Report render.** `server/lib/dashboard-report-render.ts` renders
   `pivot-table` from the same `buildPivotTable` model as an HTML table, capped
   the same way, with the cap note.
6. **Verification.** `dashboard-panel-verification.ts`: a pivot spec naming a
   missing column is `missing-columns` with the column; an empty result is
   `empty` as for tables.
7. **Application state.** No new key; a clicked cell publishes 8.4a1's
   `pointKey` and `pointValue` for the row path and the column path.
8. **Agent.** `mutate-dashboard` `insertPanel` or `updatePanel` with
   `chartType: "pivot-table"` and `config.pivotTable`; no new action.
9. **Skills.** `.agents/skills/dashboard-management/SKILL.md`: a "Pivot
   tables" subsection with the config shape, when to use it instead of SQL
   `ROLLUP` (results under the caps), and that subtotals recompute calcs from
   parts. Do not grow `AGENTS.md`.
10. **Changelog.** `agent-native changelog add "Pivot table panels with subtotals and grand totals" --type added`.

## 8. Defaults for open questions

- [Default] Up to 3 row levels, 3 column levels and 6 values; 200 by 50 leaf
  cap.
- [Default] Pivoting runs on returned rows in the browser plan and in the
  report renderer; large pivots are SQL `ROLLUP` by the agent.
- [Default] Subtotals are per first row level only.

## 9. Do not

- Do not change `config.pivot`, which stays the series reshape.
- No behavior changes outside the unit; additive-only schema; no new /api
  routes for app data (use actions); no raw fetch from client code; no
  process.env reads for provider credentials; no catch or default that turns a
  failure into a normal-looking value; no large payloads in SQL.
