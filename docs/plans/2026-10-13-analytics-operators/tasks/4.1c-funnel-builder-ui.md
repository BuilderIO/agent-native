# 4.1c Funnel step builder in the panel editor

Lane D (Growth). Size M. Gated: build only after the 4.1a prototype is signed
off.

## 1. Goal

A growth lead opens Add panel, picks the Funnel chart type and First-party
Analytics, and builds the funnel by choosing events from a list, reordering
steps and setting a conversion window. No SQL. The preview updates as they
edit, the saved panel is the same `config.growth` definition the agent writes
(4.1b), and anyone who wants raw SQL can switch to it explicitly.

## 2. What the code does today

- `PanelEditorDialog` (`app/pages/adhoc/sql-dashboard/PanelEditorDialog.tsx`)
  keeps one `form` state (`:270`) and shows one body per panel kind: a custom
  block picker for extensions, nothing for sections, a data program picker
  when `source === "program"` (`:288`, `:604-655`), and otherwise the SQL
  editor (`:656-684`). The chart type list includes Funnel
  (`:53-66`, `:61`); sources are listed at `:68-76`. Describe and Manual are
  tabs (`:742-771`).
- Funnels render from rows only (`app/components/dashboard/SqlChart.tsx:2526-2579`);
  there is no step model in the UI.
- 4.1b adds `config.growth` (funnel definition), `compileGrowthPanelSql`,
  `panelRunnableSql`, the `list-analytics-event-names` action and the
  `panel_growth_*` validation rules.
- Available primitives: `app/components/ui/` has `command`, `popover`,
  `select`, `input`, `button`, `alert-dialog`, `tooltip`, `skeleton`,
  `toggle-group`.
- Dashboard filters change through `mutate-dashboard`'s `setDashboard` op
  (`actions/mutate-dashboard.ts:146-149`). The first-party time range filter
  shape is `FIRST_PARTY_DASHBOARD_FILTERS[0]`
  (`server/lib/first-party-metric-catalog.ts:259-273`), currently server-only.

## 3. Build

1. Prototype gate: confirm the 4.1a prototype's funnel builder screens are
   signed off. If the prototype changed any string, use the prototype's
   string and update section 4 of this brief.
2. Create `app/pages/adhoc/sql-dashboard/FunnelStepsEditor.tsx`:
   - Props: `value: FunnelDefinition`, `onChange`, `events` query state.
   - One row per step: an event combobox (shadcn `Popover` + `Command`, with
     search; free text allowed when the typed name is not in the list), a
     label `Input`, an Add filter button, and icon buttons for move up
     (`IconArrowUp`), move down (`IconArrowDown`) and remove (`IconX`), each
     with an `aria-label` and a `Tooltip`. Controls are 24px high (match the
     existing editor).
   - Filter rows under a step: property `Input` (validated against the 4.1b
     field pattern), operator `Select` (Is, Is not, Contains, Is set), value
     `Input` (hidden for Is set), remove icon button.
   - Below the steps: Add step button (`IconPlus`, outline variant), Count
     `Select` (People, Sessions), Converted within: number `Input` plus unit
     `Select` (Hours, Days).
   - States: events loading uses `Skeleton` rows in the combobox list; events
     failed or `status: "unavailable"` shows the inline error
     `funnelEventsUnavailable` and leaves free text working; fewer than two
     steps disables Save with `funnelNeedsTwoSteps` as the reason.
3. Wire it into `PanelEditorDialog.tsx`:
   - Show `FunnelStepsEditor` in place of the SQL editor when
     `form.chartType === "funnel"`, `form.source === "first-party"`, and the
     panel either has `config.growth` or is new. An existing hand-written SQL
     funnel keeps the SQL editor.
   - Keep the definition in `form` (add `growth?: FunnelDefinition` to
     `PanelFormValues` and `panelToForm`). On save, send `config.growth` and
     let the server compile `sql` (4.1b step 4). Do not compile client-side
     for saving.
   - Edit as SQL: a ghost button under the builder. It opens an
     `AlertDialog` (`funnelEditAsSqlTitle`, `funnelEditAsSqlDescription`,
     confirm `funnelEditAsSqlConfirm`). Confirm copies
     `compileGrowthPanelSql(form.growth)` into `form.sql`, removes
     `form.growth`, and switches to the SQL editor.
   - Time range filter: the dialog needs the dashboard's filters. If there is
     no `timeRange` select filter, show the inline error
     `funnelNeedsTimeRange` with an outline button `funnelAddTimeRange`. The
     button calls a new `onAddTimeRangeFilter` prop that the dashboard page
     implements with `mutate-dashboard` `setDashboard` (append the filter).
     Move the filter definition into `shared/first-party-time-filter-sql.ts`
     (created in 4.1b) as `FIRST_PARTY_TIME_RANGE_FILTER` and import it from
     the metric catalog so the two never differ.
   - Preview: run the compiled, interpolated SQL through the existing panel
     query hook 800 ms after the last edit, cancelling the previous request.
     Show the existing chart loading state, not a spinner.
4. Events: call `list-analytics-event-names` with `useActionQuery`
   (pattern: `app/pages/settings/AlertRulesSettingsCard.tsx:282-291`), with
   `query` from the combobox input and `staleTime: 60_000`.
5. Application state: while the dialog is open on a growth panel, the existing
   `selected-object` selection (with `growthKind: "funnel"` from 4.1b) is
   enough for the agent. Do not add a new key. Write the in-progress
   definition to nothing; it is not saved until Save.
6. Agent parity: the agent already creates the same definition through
   `mutate-dashboard` (4.1b). Update `.agents/skills/dashboard-management/SKILL.md`
   (the section 4.1b adds) with one sentence: users can build funnels in the
   panel editor, so point them there for step edits they want to make by hand.
7. Changelog: `agent-native changelog add "Build funnel panels by choosing events in the panel editor" --type added`.

Four areas: UI (this unit), actions (4.1b's `list-analytics-event-names` and
`mutate-dashboard`), skills (step 6), application state (step 5, no new key).

## 8. Defaults for open questions

- [Default, reviewer can change] Preview runs automatically 800 ms after the
  last edit. Alternative: a Run preview button, if BigQuery cost is a worry.
- [Default] Free-text event names are allowed, so a team can build a funnel
  for an event before it first fires.
- [Default] Existing hand-written SQL funnels are not converted to the
  builder.
- [Default] Step reordering uses move up and move down buttons, not drag and
  drop, so it works with a keyboard and on touch.

## 9. Do not

- Do not add a breakdown or comparison control (not in v1).
- Do not change the non-funnel editor paths.
- No behavior changes outside the unit; additive-only schema; no new /api
  routes for app data (use actions); no raw fetch from client code; no
  process.env reads for provider credentials; no catch or default that turns a
  failure into a normal-looking value; no large payloads in SQL.
