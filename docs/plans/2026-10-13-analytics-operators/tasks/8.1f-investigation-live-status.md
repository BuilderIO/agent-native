# 8.1f Live investigation status

Lane E (Holy-shit features). Size M. Gated: the notifications bell in
Analytics, the alert toast, the run card in the agent sidebar, the funnel
chip and the alert row status are new UI covered by the 8.1 prototype
sign-off ("Investigation: alert fires" and "Investigation: watch the run"
screens).
Depends on: 8.1a, 8.1c, sign-off; 4.2c for the funnel chip. Blocks: none.

Split from 8.1c so the trigger work and the live status UI each stay at size
M. Paths are relative to `templates/analytics/` unless they start with
`packages/`, `prototypes/` or `docs/`. Code facts were read on the
integration branch `claude/analytics-template-competitor-3faa16` at
`e61df04eaa`; re-check line numbers before editing.

## 1. Goal

While an investigation runs, people can see it and step in, wherever they
are. When the "Dashboard conversion dropped" alert fires:

- a toast says "Dashboard conversion dropped · Investigating why" with Watch;
- the header bell (new in Analytics) shows the alert notification, and under
  it "Investigating… step 2 of 7" with a progress bar and Watch, which
  becomes "Investigation complete", the confidence and the one-line summary
  with Open investigation when it ends;
- Watch opens the run in the agent sidebar as a card: the plan ("Plan: 7
  checks within 5 minutes and $0.50, stopping early if they agree."), each
  step with what it checked and its result, time and spend against the
  budget, and Stop;
- the funnel's conversion line shows "Investigating… 2 of 7", then "Why it
  fell" linking to the notebook;
- the alert's row in Settings, Alerts reads "Investigating…".

## 2. What the code does today

- The toolkit `NotificationsBell` (`packages/toolkit/src/app/notifications/NotificationsBell.tsx`)
  takes only `pollMs`, `className`, `browserNotifications`, `emptyTitle`,
  `emptyDescription` and `onOpenChange` (`:20-27`), polls every 10 s (`:30`),
  and renders each row as title, severity, body and time, opening
  `metadata.link` on click (`:265-330`). Its strings are hard-coded English
  ("No app notifications yet." `:37`, "Notifications" `:206`, "Dismiss
  notification" `:316`) and its loading state is a "Loading…" row with a
  spinner. The unread count badge is `bg-destructive`
  (`NotificationsBell.tsx:217`). Analytics does not mount it: the header shows page actions,
  `RunsTray` and `AgentToggleButton` (`app/components/layout/Header.tsx:66-71`).
- `RunsTray` (`packages/toolkit/src/app/progress/RunsTray.tsx`) reads
  `/_agent-native/agent-chat/runs/list`, which includes agent-team
  background runs (`packages/core/src/server/agent-chat-plugin.ts:6560-6585`).
  With `pollMs={0}`, as the header passes it, it polls only while it already
  knows of an active run (`RunsTray.tsx:97-172`), so a run the server started
  stays invisible until something refreshes it.
- Actions pick a chat renderer with `chatUI: { renderer, when }`
  (`actions/query-agent-native-analytics.ts:88-93`), and the app registers the
  component with `registerActionChatRenderer` (`app/lib/register-analysis-result-renderer.tsx:69-73`,
  imported in `app/root.tsx:25-27`).
- `requestAgentTaskOpen` opens a task's thread in the sidebar
  (`packages/core/src/client/agent-chat.ts:825`).
- A background notifier pattern exists: `ProviderCorpusJobNotifier` polls an
  action with `useActionQuery` and toasts with `sonner`
  (`app/components/ProviderCorpusJobNotifier.tsx:26-40`).
- The alert row's status line is a dot plus `statusLabel(rule.lastStatus)`
  (`app/pages/settings/AlertRulesSettingsCard.tsx:618-626`).
- 4.2c (brief) draws the conversion line between funnel steps with the bell;
  8.1c (brief) puts `investigationId` or `investigationError` on alert
  notifications and sends `analytics_investigation` notifications on finish.

## Plan corrections

- **Analytics has no notifications surface yet.** The prototype draws the
  toolkit bell as new in Analytics. Mounting it means the toolkit bell needs
  a slot for app content under a row, localized strings and a skeleton
  instead of "Loading…"; those are toolkit changes with a changeset, and
  every app that mounts the bell gets them.
- **RunsTray needs a nudge.** It does not poll on its own in Analytics, so
  the header passes a poll interval while an investigation runs.

## 3. Build

1. **Toolkit** (`packages/toolkit`, changeset
   `.changeset/notifications-bell-item-extra.md`, minor for
   `@agent-native/toolkit`):
   - `NotificationsBell` gains `renderItemExtra?: (notification:
     NotificationDto) => ReactNode`, rendered under the row's body; clicks
     inside it do not trigger the row's link. Export `NotificationDto`.
   - Move its strings into the toolkit catalogs
     (`packages/toolkit/src/app/i18n/catalogs/*.ts`, append rule) and
     replace the "Loading…" row with three row-shaped `Skeleton`s.
   - Draw the unread count badge in solid blue, `bg-blue-500` with
     `text-white`, the blue Design uses (for example
     `templates/design/app/pages/design-editor/view/visual-edit-apply-toolbar.tsx:82`),
     instead of `bg-destructive` (`:217`). Not primary, not red: an unread
     count destroys nothing. Every app that mounts the bell gets it.
     `guard:no-raw-colors` flags the literal, so the line carries its
     `guard:allow-raw-color` pragma with that reason.
2. **Header** (`app/components/layout/Header.tsx:66-71`): mount
   `<NotificationsBell renderItemExtra={renderInvestigationExtra} />` between
   `RunsTray` and `AgentToggleButton`, as the prototype draws. Pass
   `RunsTray` `pollMs={3000}` while the investigation notifier (step 3) knows
   of a queued or running investigation, else `0`.
3. **Notifier** `app/components/investigations/InvestigationNotifier.tsx`,
   mounted next to `ProviderCorpusJobNotifier`: `useActionQuery` on
   `list-investigations` (`status: ["queued", "running"]`), refetched every
   30 s while the tab is visible and every 3 s while one is running (read
   `.agents/skills/real-time-sync` first; use its realtime option instead if
   it covers rows written by a server job). It exposes "any running" to the
   header through a small context and toasts:
   - a new alert investigation: the alert name in bold, "Investigating why",
     and a Watch action that calls `requestAgentTaskOpen({ threadId })`;
   - an investigation that finished while the tab was open: "Investigation
     complete: <title>" (or partial, or failed) with an Open action to the
     notebook.
   Each toast shows once per investigation and state.
4. **Bell rows** `app/components/investigations/InvestigationNotificationExtra.tsx`:
   for an `analytics_alert` or `analytics_investigation` notification with an
   `investigationId`, read `get-investigation` (only while the popover is
   open; every 2 s while running). Running: `IconLoader2` spinning,
   "Investigating… step <n> of <total>", Watch (outline, xs), and a thin
   progress bar. Finished: `IconCircleCheck`, or the amber `IconAlertTriangle`
   for partial and failed, "Investigation complete", "Investigation partial"
   or "Investigation failed", the confidence chip (step 5), the summary line,
   and Open investigation (outline, xs) linking to the notebook. An
   `investigationError` shows the amber triangle and "Couldn't start the
   investigation." A failed read shows "Couldn't read the investigation.",
   never nothing.
5. **Run card** `app/components/investigations/InvestigationRunCard.tsx`,
   registered in `app/lib/register-investigation-renderers.tsx` (imported in
   `app/root.tsx`) as `analytics.investigation-run`. Declare `chatUI` on
   `start-investigation` (the chat where it was asked) and on
   `run-investigation-check` with `when: args.step === "confirm"` (the
   investigator's own thread); later step calls render nothing because the
   card above shows them. The card polls `get-investigation` every 2 s while
   running and visible:
   - Header: spinning `IconLoader2` and "Investigating…", or "Investigation
     complete", "Investigation partial", "Investigation failed"; at the right
     "<elapsed> of <budget> · <spent> of <cap>", or "<elapsed> of <budget> ·
     Spend not recorded" when spend is unknown.
   - Plan line: "Plan: <count> checks within <minutes> minutes and <amount>,
     stopping early if they agree."
   - Steps in order: `IconCircleCheck` (emerald) done, `IconAlertTriangle`
     (amber) couldn't check, `IconLoader2` spinning for the running step,
     `IconCircleDashed` at half opacity for waiting ones; the step label from
     the catalog, the `checked` line small and muted, then the result (amber
     text for couldn't check).
   - Footer: running, "Step <n> of <total>" and Stop (outline, xs,
     `IconPlayerStop`), which calls `cancel-investigation` optimistically and
     rolls back on error; finished, "<count> checks couldn't run" and Open
     notebook (`variant="default"`, xs, `IconNotebook`).
   - Confidence chip (shared with step 4 and 8.1d,
     `app/components/investigations/ConfidenceChip.tsx`): a 20px pill, a 6px
     dot (emerald for High, amber for Medium and Low), "<level> confidence",
     with the confidence reason as its tooltip. "No change found" when the
     outcome is `no_change`.
6. **Funnel chip** (4.2c's conversion line in `FunnelRenderer`,
   `app/components/dashboard/SqlChart.tsx`): when the line's rule has a
   latest investigation, a chip after the drop-off count: running,
   "Investigating… <n> of <total>" (spinner, tooltip "Watch the
   investigation", opens the run); finished, "Why it fell" or "Why it rose"
   (`IconZoomQuestion`, tooltip = the summary, a router `Link` to the
   notebook so Cmd or Ctrl click opens a new tab). `list-analytics-alert-rules`
   adds `latestInvestigation: { id, status, step, total, summary, notebookId,
   direction } | null` per rule (one indexed read for all rules).
7. **Alert row** (`AlertRulesSettingsCard.tsx:618-626`): while the rule's
   latest investigation is queued or running, the status line shows a
   spinning `IconLoader2`, "Investigating…" and a Watch link; otherwise it is
   unchanged.
8. **Application state:** none. Watch opens the thread through the chat's own
   state.
9. **Skills:** one sentence in `.agents/skills/investigations/SKILL.md`: people
   can watch and stop a run from the bell, the toast, the run card or the
   funnel, and Stop keeps what was found as a partial notebook.
10. **Changelog:** `agent-native changelog add "Watch an investigation as it runs from notifications, the agent sidebar and the funnel, and stop it any time" --type improved`.

## 8. Defaults for open questions

- [Default] The bell sits between RunsTray and the agent toggle in the
  desktop header, as drawn. The mobile header has no bell in v1.
- [Decided by the owner, 2026-10-14] The bell's unread count is solid blue
  (`bg-blue-500`, as in Design), not primary or red.
- [Default] The run card renders once per thread (on `start-investigation`
  in the asking chat, on the confirm step in the investigator's thread).
- [Default] The notifier polls `list-investigations` every 30 s while the tab
  is visible, every 3 s while one runs.

## 9. Do not

- Do not add a second notifications surface or an Analytics-only bell; extend
  the toolkit bell.
- Do not hide a failed read or a failed start; show it in place.
- No behavior changes outside the unit; additive-only schema; no new /api
  routes for app data (use actions); no raw fetch from client code; no
  process.env reads for provider credentials; no catch or default that turns a
  failure into a normal-looking value; no large payloads in SQL.
