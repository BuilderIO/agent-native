# Delegated framework registry diff: executed main versus companion

## Result and scope

The 96 comparable delegated loops preserve all 15,008 observed non-prefix main app-binding occurrences, with **zero non-prefix app-binding losses, zero unresolved ownership flags, zero retained identity-fact changes, and zero route-availability differences**. There are 7,726 removed name occurrences: 427 intentional prefix removals and 7,299 framework runtime removals. No names were added in these captured maps. Counts are occurrences across routes and surfaces, not unique action implementations.

This compares the actual `runOptions.actions` supplied to the delegated loops on separately executed exact main and the companion. The companion current pre-filter registry is diagnostic only; it is neither the main baseline nor a proxy for it. The result concerns served names and captured binding facts, not identical function bodies or approval readiness.

The counts below belong to the recorded capture snapshots. Subsequent visibility hardening reapplies the app-agent `agentTool` and `uiOnly` restrictions after request-scoped actions merge, including approval replay and marked automation runs. Current dispatch regressions cover those restrictions while retaining app-owned `mcpTool: false` and SQL actions; the historical matrix has not been rerun for that change.

## Preserved app actions and static reader

Ownership is classified from each execution’s actual served entry/run facts, with main construction snapshots where available. Generated filenames alone are not ownership evidence. No supplied app binding is lost outside the required prefixes. No observed retained binding changed its four comparable identity facts (`explicitAppSupplied`, `matchesAppEntry`, `matchesAppRun`, `matchesGeneratedRun`), and no app-binding restoration case occurs in this shipped-template corpus. The separate bounded collision tests cover restoration behavior; this inventory does not invent a shipped collision.

On Analytics production and dev, `bigquery`, `search-bigquery-schema`, and `query-agent-native-analytics` survive on all three routes, appear in first-request and available-tool maps, remain callable through tool-search, and dispatch through the real loop to the selected spied leaf. The `mcpTool:false` app policy is preserved. This report does not change raw-SQL policy.

The delegated static `docs-search` reader survives all 96 reached maps. Its bounded corpus is bundled docs and app/workspace-authored instructions/skills; it is not a general file, memory, resource or SQL reader. A genuine app name collision preserves that exact app entry and selects eager skill text instead of claiming the custom reader is static. Existing filesystem/SQL negative controls and caller/prompt/approval checks accompany the [test expectation changes](https://github.com/BuilderIO/agent-native/pull/8140#test-expectation-changes). This exception belongs only to delegated maps; direct MCP eligibility and its allowlist remain unchanged.

## Harness limits and follow-up boundary

Each template runs in a separate process to avoid the process-global package action registry contaminating later apps. Both production and dev use an empty temporary cwd, so loose dev scripts, coding factories and workspace peer routing are outside these inventories; the separate delegated-runtime matrix covers those factories. Labs are forced enabled. The real plugin builds the action maps, and actual A2A/MCP loop options are captured before model/provider execution. MCP calls use the real in-memory server/client. Cleanup hooks remain enforced. No live model or provider result is claimed.

Approval/provenance changes are limited to the covered Core automation/trigger/run seams, Factory create/run/save/restore actions and their scoped helpers, Analytics scheduling, and marked background-run per-write approval. This catalog report does not prove all automation writers are gated. **Not in this PR:** a store-wide stamping/retention invariant, which is planned as a separate follow-up. This report covers registry captures; action and agent-loop tests cover authorization behavior.
