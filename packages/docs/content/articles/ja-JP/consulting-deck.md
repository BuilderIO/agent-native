コンサルティング資料は、クライアントの問いへの答えを最初に示し、その後に論拠と根拠を続ける資料です。1枚のスライドで伝えることは1つに絞ります。スライドを作る前に、まず言葉で組み立てます。問い、答え、そしてすべてのスライドタイトルを完全な文で書きます。このガイドでは架空の案件を1つ取り上げ、クライアントの問いから完成したスライドまでを順に説明します。

## 用意するもの

- クライアントの問い
- クライアントへのインタビューのメモ
- 分析とそのデータ
- 意思決定者と、答えが影響するチーム

## コンサルティング資料の作り方

### 1. クライアントの問いと意思決定を書く

コンサルティング資料が答える問いは1つです。そのため、**クライアントの問いを一文で書きます**。その下に、答えが関わる意思決定と、それを決める人を書きます。問いが一文に収まらない場合、その案件には複数の問いがあり、それぞれに別のセクションか別の資料が必要です。

このガイドを通して使う例は、40店舗を展開する架空のジムチェーンTidewater Fitnessで、会員が減り続けています。問いは「会員の退会を止めるために、会費を値下げすべきか？」です。意思決定は、CEOが来年度の予算に値下げを盛り込むかどうかです。

### 2. 答えを先に書く

資料は答えから始めます。経営層は冒頭を読み、そこで読むのをやめることもあるからです。インタビューのメモと分析を読んで、そこから何が言えるかを考え、**意思決定者がそのまま行動に移せる一文で答えを書きます**。その下に、答えを支える3つの理由を書きます。これは、バーバラ・ミントが著書『_The Pyramid Principle_』で示した、答えを先に置く構成です。

Tidewaterの答えは「会費は据え置き、代わりに入会後90日間の体験を改善する」です。これを3つの理由が支えます。会員の大半はその90日以内に退会していること、退会の主な理由は価格ではないこと、そして最初の1か月でクラスに通う習慣がついた会員は継続することです。

理由どうしは重ならず、合わせると答えを漏れなく支える必要があります。コンサルタントはこれをMECE（漏れなく、ダブりなく）と呼びます。

分析が終わっていなければ、予想される答えを書きます。[ステップ4](#4-ゴーストデッキを作る)のゴーストデッキで、まだ足りない根拠がわかります。

### 3. ストーリーラインをスライドタイトルとして書く

すべてのスライドに**アクションタイトル**を付けます。アクションタイトルとは、そのスライドから読み手が何を結論づけるべきかを伝えるタイトルです。「退会」では、スライドで扱う内容を示しているだけです。「退会の61%は入会後90日以内に起きている」なら、データが何を示しているかがわかります。

**どのスライドを作るよりも先に、すべてのタイトルを書きます**。各タイトルは、それが支える理由の下に置きます。

| セクション   | スライドタイトル                                                          |
| ------------ | ------------------------------------------------------------------------- |
| 答え         | 会費は据え置き、入会後90日間の体験を改善する                              |
| 理由1        | 退会の61%は入会後90日以内に起きている                                     |
| 理由2        | 割引で入会した会員も、ほかの会員と同じ割合で退会している                  |
| 理由2        | 退会理由で価格は4位にとどまり、「何から始めればいいかわからない」を下回る |
| 理由3        | 最初の1か月でクラスを3回予約した会員は、1年継続する割合が約2倍            |
| 次のステップ | すべての新規会員にクラスを3回予約してもらう。まず8店舗で試験導入する      |

タイトルだけを上から順に読めば、論旨全体が伝わります。

### 4. ゴーストデッキを作る

**ゴーストデッキ**とは、タイトルだけが入っていて中身はまだない状態の資料です。タイトルごとに白紙のスライドを1枚作り、**各スライドに、それを裏付けるグラフを書き込みます**。あわせて、データの出どころと、そのデータがすでに手元にあるかも書きます。分析の途中段階でのTidewaterのゴーストデッキは次のとおりです。

| スライドタイトル                                                          | 必要な根拠                    | データ             | 手元にあるか |
| ------------------------------------------------------------------------- | ----------------------------- | ------------------ | ------------ |
| 退会の61%は入会後90日以内に起きている                                     | 在籍期間別の退会数            | 会員管理システム   | あり         |
| 退会理由で価格は4位にとどまり、「何から始めればいいかわからない」を下回る | 退会の主な理由のランキング    | 退会時アンケート   | まだ         |
| 最初の1か月でクラスを3回予約した会員は、1年継続する割合が約2倍            | 最初の1か月の予約数別の継続率 | 予約と会員のデータ | まだ         |

「まだ」の行が、残りの分析です。データがタイトルと矛盾する場合は、タイトルを書き直し、答えがまだ成り立つかを確認します。

### 5. 各タイトルを1つのグラフで裏付ける

各スライドの本文では、1つのグラフか表でタイトルを裏付けます。**タイトルが述べている数値をアクセントカラーで強調し**、ほかは目立たない色にします。グラフは、タイトルが何を比べているかで選びます。

| タイトルが比べているもの        | 使うグラフ        |
| ------------------------------- | ----------------- |
| 時間の経過による変化            | 折れ線グラフ      |
| 大きさの順に並べた項目          | 横棒グラフ        |
| 全体に占める内訳                | 積み上げ棒グラフ  |
| 2つのグループ、または前後の比較 | 横に並べた2本の棒 |
| 読み手が参照する正確な数値      | 表                |

すべてのスライドの下部に**出典の行**を入れます。データの名前、期間、絞り込みの条件を書きます。たとえば「Tidewater会員管理システム、2024〜2025年の退会、40店舗」です。どのスライドでも、タイトルは上部、出典は下部に置きます。主張を示すのにグラフが2つ必要なら、タイトルを2つに分け、スライドも2枚にします。

### 6. エグゼクティブサマリーは最後に書く

エグゼクティブサマリーは本文のスライドを書き終えてから書き、**タイトルスライドのすぐ後に置きます**。ストーリーラインを短くまとめたもので、まず答え、次に各理由を一文ずつ、いちばん強い数値とともに書きます。このスライドだけを読んだ人にも、何を提言しているのか、なぜなのかが伝わるようにします。

Tidewaterのサマリーは「値下げをしても退会は止まりません」で始まり、3行が続きます。

- 退会の61%は入会後90日以内に起きている。
- 割引で入会した会員も同じ割合で退会しており、会員は価格を退会理由の4位に挙げている。
- 最初の1か月でクラスを3回予約した会員は74%が1年継続しており、予約がそれより少ない会員では41%にとどまる。

### 7. 提言と次のステップで締めくくる

答えを行動に落とし込み、**それぞれに担当者と期日を付けます**。Tidewaterの提言は、すべての新規会員に最初の1か月でクラスを3回予約してもらうことで、まず8店舗で試験導入します。会員体験の責任者が4月1日に開始します。コンサルタントは入会後90日以内の退会数を残りの32店舗と比較して7月15日に報告し、CEOが8月1日までに全店展開を判断します。

論旨を支えてはいても、論旨を動かすわけではない内容は、すべてこのスライドの後の付録に移します。手法、データの全表、インタビュー対象者の一覧などです。

### 8. タイトルだけを読み、すべての数値を確認する

資料は2回に分けて確認します。1回目は、**スライドタイトルだけを順番に読みます**。論旨が途切れるなら、タイトルが抜けているか、順番が違っています。2回目は、すべてのスライドのすべての数値を、出典の行に書いた期間と定義に沿って出典と照らし合わせます。

そのうえで、各スライドに「だから何？」と問いかけます。クライアントが信じるべきことや取るべき行動を変えないスライドは、付録に移します。

### 9. ミーティングの前に根回しをする

**ミーティングの前に、意思決定者に資料を一通り説明します**。答えが影響するチームの責任者にも同じように説明します。コンサルタントはこれをプリワイヤリング、つまり根回しと呼びます。まだ対応できるうちに反対意見を見つけられるので、ミーティングでは答えへの最初の反応ではなく、意思決定そのものについて話し合えます。

資料は事前資料として先に送ります。クライアントはコンサルティング資料を、その場にいなかった人にも転送します。完全な文のタイトルと出典の行があれば、あなたがいなくても資料が論旨を伝えてくれます。

## Agent-Native Slidesでコンサルティング資料を作る方法

[Agent-Native Slides](https://www.agent-native.com/apps/slides/)は、[ストーリーライン](#3-ストーリーラインをスライドタイトルとして書く)とインタビューのメモからスライドを作成します。問い、答え、分析を決めるのはあなたです。Slidesは渡された情報をもとに作業し、数値の確認はしません。Slidesはアルファ版です。

### 1. ストーリーラインを貼り付け、メモを添付する

Slidesのホーム画面で、クライアント、問い、答え、スライドタイトルを順に書いて、作りたい資料を説明します。インタビューのメモと、PDFとして保存したグラフや表を添付します。SlidesはPDF、Word、PowerPointのファイルを読み込めます。

クライアントへのインタビューを[Agent-Native Clips](https://www.agent-native.com/use-cases/ai-meeting-notes/)で録音している場合は、そのミーティングメモを貼り付けてください。Slidesのエージェントは、メモから目標、反対意見、数値、未解決の問いを抜き出します。名前や数値は正確にそのまま使い、それらをつなぐために主張を作り出すことはありません。

![Tidewaterのストーリーラインが入力されたSlidesのプロンプトボックス。インタビューのメモと分析資料のPDFの2つのファイルが添付されています。](https://cdn.builder.io/api/v1/image/assets%2FYJIGb4i01jvw0SRdL5Bt%2F25e1746e6f8d42b0a39c425fc5921305)

### 2. エージェントが各スライドを作る様子を確認する

エージェントは1枚につき伝えることが1つになるよう資料を設計し、エディター上でスライドを1枚ずつ作成します。その様子はリアルタイムで確認できます。1枚に内容が多すぎる場合、エージェントは文字を小さくするのではなく、スライドを2枚に分けます。

![タイトルスライド、エグゼクティブサマリー、最初の調査結果のスライドが完成し、次のスライドを生成中のSlidesエディター。エージェントのチャットには、エージェントが組み立てたアウトラインが表示されています。](https://cdn.builder.io/api/v1/image/assets%2FYJIGb4i01jvw0SRdL5Bt%2F902e145f05b740df819d139460a4625c)

### 3. スライドを修正し、経営層向けの版を作る

テキストはその場で編集できます。スライド全体を変えたいときは、スライドを選んでエージェントに依頼します。たとえば、表を棒グラフに変えるといった依頼です。CEOに短い版を渡したい場合は、資料を複製し、コピーをタイトル、サマリー、提言だけに絞るようエージェントに依頼します。どちらの版も、共有する前に**すべての数値を分析と照らし合わせてください**。

## よくある問題

### タイトルを積み上げても答えにならない

ストーリーラインに抜けがあるか、余計な論点があります。答えの下に3つの理由を書き出し、各タイトルがちょうど1つの理由に属しているかを確認します。根拠のない理由にはタイトルを追加し、どの理由も支えていないタイトルは付録に移します。

### データがスライドタイトルと矛盾する

分析の結果が、予想していた答えと違っていたケースです。データが示すとおりにタイトルを書き直し、ストーリーラインを読み直します。理由の1つが成り立たなくなったら、スライドをさらに作る前に答えを変えます。

### ミーティングでクライアントが答えに反発する

意思決定者やそのチームが、その場で初めて答えを目にしたケースです。次の版では、反対した人それぞれに根回しをします。ミーティングでは、疑問を持たれた点を裏付けるスライドを開き、出典の行を一緒に確認します。

### 資料がミーティングには長すぎる

論旨に必要のない詳細まで資料に入っています。メインの資料にはタイトル、サマリー、理由ごとに1枚のスライド、提言だけを残し、残りは付録に移します。発表はサマリーから始め、ほかのスライドは求められたときだけ開きます。

## よくある質問

### コンサルティング資料はどう構成しますか？

コンサルティング資料は、次の5つの部分をこの順に並べます。

1. 答えを示すタイトルスライド
2. 答えとその理由をまとめたエグゼクティブサマリー
3. 理由ごとのセクション（各スライドで1つのアクションタイトルを裏付ける）
4. 担当者と期日つきの提言
5. 手法とデータの全体をまとめた付録

### コンサルティング資料とは何ですか？

コンサルティング資料とは、コンサルタントがクライアントに示すプレゼンテーション資料で、クライアントの問いへの答え、その背景にある調査結果、提言をまとめたものです。答えから始め、各スライドに完全な文のタイトルを付け、すべての主張を出典のあるデータで裏付けます。発表するだけでなく、読まれることも想定して書きます。

### コンサルティングでいうゴーストデッキとは何ですか？

ゴーストデッキとは、スライドタイトルだけが入っていて中身のない、コンサルティング資料の下書きです。各スライドには、アクションタイトルと、それを裏付けるグラフやデータのメモが入っています。コンサルタントはゴーストデッキを使って、早い段階でストーリーラインについて合意し、どの分析がまだ足りないかを確認します。

### コンサルティング資料のスライドは何枚にすべきですか？

論旨を伝えるのに必要な枚数にし、1枚で伝えることは1つに絞ります。多くのクライアントの問いには、10〜20枚のメイン資料で対応できます。内訳は、タイトル、エグゼクティブサマリー、調査結果、提言です。手法、データの全表、インタビュー対象者の一覧は提言の後の付録に入れ、メイン資料を短く保ちます。

### コンサルティング資料と会社紹介資料の違いは何ですか？

コンサルティング資料は、1社のクライアントの問いに調査結果と提言で答えるものです。会社紹介資料は、ファームが自社のサービス、チーム、過去の実績をまとめたもので、新しいクライアントを獲得するために使います。エージェンシーやコンサルティングファームは、段階に応じて両方を使い分けます。会社紹介資料は仕事を始める前に、コンサルティング資料は仕事の最中と後に使います。

1社の見込み客に提案する場合は、[ヒアリングで聞いた内容をもとに営業プレゼン資料を作りましょう](https://www.agent-native.com/articles/sales-presentation/)。すでに取引のあるクライアントとの定例レビューについては、[四半期の数値からQBR資料を作る方法](https://www.agent-native.com/articles/qbr-presentation/)をご覧ください。

### ピラミッド原則とは何ですか？

ピラミッド原則とは、結論を最初に置き、次にそれを支える理由、さらに各理由の根拠を続ける、論旨の組み立て方です。バーバラ・ミントがマッキンゼーで考案し、書籍として出版しました。コンサルティング資料はこの原則に従い、最初のスライドに答え、その後に調査結果を置き、各スライドに根拠を載せます。
