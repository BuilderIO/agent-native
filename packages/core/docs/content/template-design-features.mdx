# Features

Every core Design feature: how it works, and how to set it up. See
[Design](/docs/template-design) for the overview and [Talk to the
Agent](/docs/template-design-agent) for the full list of prompts. Features
are grouped by the real screens in the app: **Designs**, **Edit a Design**,
**Templates**, and **Design Systems**.

## Designs {#designs}

The `/home` list page. Every design you can access lives here, and this is
where you start a new one.

### View designs {#view-designs}

Designs show as a grid of cards: a live thumbnail, the title, and the last
updated date. Switching to the **All** filter (instead of **Mine**) also
shows who owns each one.

- **Search** filters the grid by title as you type.
- The grid pages at 11 designs per page, with the "New design" tile always
  first.
- Select one or more cards (hover to reveal a checkbox) to get a bulk
  toolbar: select/clear all visible, add to a creative context, or delete
  the selection.
- An empty account shows four starter prompts to click instead of a blank
  grid (a SaaS page, a dashboard, a mobile app, a pricing page).

### Create a design {#create-a-design}

Both "New design" entry points, the header button and the grid's dashed
tile, open the same popover. You can type a prompt, and pick a starting
template, a design system, and a creative context, all before the editor
even opens. Click **Skip** instead to get a blank design (or an
un-prompted copy of the picked template) with no AI generation involved.

Submitting takes you straight to the new design's editor with an "Opening
design" overlay while any generation finishes in the background.

### Manage a design {#manage-a-design}

The "⋯" menu on a design card has four items:

- **Rename**: a small dialog with a text field.
- **Duplicate**: makes a copy immediately and opens it, no confirmation.
- **Add to context**: attaches the design to a creative context.
- **Delete**: asks for confirmation first.

## Edit a Design {#edit-a-design}

Everything below applies once you've clicked into a design.

### File settings {#file-settings}

Screens and layers live in one combined tree, not two separate panels.
Every screen in the design (each is its own HTML file) is a top-level
entry, with that screen's layers nested underneath.

- **Add, rename, duplicate, delete, and reorder** work the same way for
  screens and for layers.
- **Lock** a layer to keep it fixed. This is the same "locked layer"
  concept templates and template copies preserve.
- **Show or hide** any layer without deleting it.

### Agent {#agent-in-editor}

The same agent chat every Agent-Native app has sits in the editor too, not
a Design-specific chat surface. Ask it to generate a screen, compare
variants, tune details, or check quality and accessibility, the same way
you'd ask for any other change. It also runs an automatic quality and
accessibility check on its own before calling a design ready, with no
action needed from you. See [Talk to the Agent](/docs/template-design-agent)
for prompts by task.

#### Modes

A separate three-way switch next to the tools:

- **Edit**: the normal mode. Move, Frame, Shapes, Pen, and Text all work
  in this mode.
- **Annotate**: the mode Draw and Pin Comment need to be active in.
- **Interact**: a distinct mode for the canvas, kept separate from Edit
  and Annotate.

### Design tab {#design-tab}

The main properties panel for whatever's selected. Sections appear only
when they apply to the current selection:

- **Fill** and **Stroke**: color, gradient, or image paint, with a
  document color palette to reuse existing colors.
- **Effects**: drop shadow, layer blur, background blur, and a
  code-backed shader effect with named sliders (speed, color, center
  point) and a Code panel for the raw GLSL.
- **Position & layout**, **Typography**, **Appearance** (corner radius,
  blend mode, visibility): the standard per-element property groups.
- **Layout** and **Auto layout**: flex-style arrangement for a frame's
  children.
- **Layout grid**: a layout guide overlay for a frame.
- **Component**: once an element is a component instance, this section
  shows its variants and props. Changing a prop previews instantly and
  applies to that one instance. There's no separate stored component
  definition, every instance is its own independent copy of the markup,
  so "Go to main component" jumps back to the earliest instance as a
  reference point, not a canonical template.

### Comments tab {#comments-tab}

A real tab next to Design, with an unread-count badge. Anyone with access
can pin a comment to a specific element instead of leaving a generic note.
A comment can stay a plain note, or get sent straight to the agent. When
the agent works through one, it edits the exact part of the design the
comment points at, checks the change actually landed, then either resolves
the thread with a one-line note of what changed, or replies asking the
person to decide when it isn't something the agent should resolve on its
own.

### Code & Measurements tab {#code-tab}

Shows, for whatever's selected: exact position and size in pixels, computed
styles (display, position, font, color), and the underlying HTML with a
one-click **Copy** button. This is a read-only inspector, not an editor.

### Design Preview {#design-preview}

The header's play-button menu. **Design Preview** opens the current
screen's real rendered HTML in a new browser tab, exactly as it will look
outside the editor. It's disabled until the screen has content.

state, including any applied tweaks, not the first generated version.
Duplicate the design first if you want to keep iterating on a copy after

### Version history {#version-history}

In that same left-side rail menu, **Version history** opens a panel that
lists saved snapshots of the design with a relative timestamp ("Just now,"
"5m ago," and so on). Selecting one shows a preview of its screens, and
**Restore this version** brings the design back to that exact state.

## Templates {#templates}

Two ways to start faster than a blank canvas.

### View templates {#view-templates}

The Templates page has two sections, **Your templates** and **Built-in
templates**, plus a search box that filters by title, description, and
category. Each template card shows a live preview, its category (ad,
one-pager, landing page, social, presentation, or other), its dimensions,
and how many layers on it are locked. Your own templates (not the built-in
ones) get a "⋯" menu with **Share** (viewer, editor, or admin access) and
**Delete**.

### Use a template {#use-a-template}

Clicking **Use template** opens a small dialog: an optional prompt, a
design system to apply (or a link to create one), and a **Use as is**
button to skip straight to a copy with no prompt. Either way, a new design
is created and you're taken straight into its editor.

### Save as template {#save-as-template}

This isn't on the Templates page itself. While editing a design, open the
same left-side rail menu used for Export and Version history, and choose
**Save as template**. Its dimensions, files, and locked layers carry over
the same way a built-in template's do.

<Callout tone="info">

Templates can currently be saved from inline Design projects only. A design
backed by `/visual-edit` or Full App Building can't be saved as a template.

</Callout>

### Open a design {#open-a-design}

There's no separate "open" step. Using a template, like generating a new
design from a prompt, always ends by opening that design's editor
automatically.

## Design Systems {#design-systems}

A design system is the brand identity, its colors, fonts, spacing, and
logos, that Design applies to every prototype linked to it.

### View and share design systems {#view-and-share}

The Design Systems page is a grid: a "New design system" card first, then
one card per system with a color-swatch preview, a **Default** badge on
whichever one is your default, and a visibility badge (private, org, or
public). Every card has a real **Share** button with viewer, editor, or
admin roles, the same sharing model templates use. A header **Select**
toggle enables multi-select with bulk delete.

### New design system {#new-design-system}

Creating one starts with a source picker:

- **Figma**: upload a `.fig` file.
- **Company/brand**: a website URL.
- **Code**: a connected GitHub repository.
- **Design.md**: a written design-guidance document.
- **Design files**: upload files directly.
- **Import existing**: reuse a design system or project you already have.
- **Notes**: describe your brand from scratch, or start from a real,
  maintained public system, like Material 3, Carbon, or Primer, instead of
  recreating one from memory.

<Callout tone="info">

Each public system ships real semantic tokens, a type scale, spacing, and
attribution. Design won't let a prompt quietly turn one into a lookalike
with different data underneath. Every design system also carries an
optional set of custom instructions and a described image style, so
generated photography and illustration stay in the same visual language as
the rest of the brand.

</Callout>
