# Sharing Kit

The Sharing Kit makes user-authored resources private by default, then gives
users and agents the same controlled ways to share them: specific people, the
active organization, public links when allowed, and agent-readable resource
links.

## Pieces {#pieces}

| Piece                             | Purpose                                                                                |
| --------------------------------- | -------------------------------------------------------------------------------------- |
| `ownableColumns()`                | Adds owner, organization, visibility, and timestamps to the resource table.            |
| `createSharesTable()`             | Creates the per-resource grants table.                                                 |
| `registerShareableResource()`     | Registers the resource type so framework share actions know how to read and mutate it. |
| `<ShareButton>` / `<ShareDialog>` | Renders the standard share control and calls the share actions.                        |
| `<VisibilityBadge>`               | Shows private, shared, org, or public state in lists and headers.                      |
| `share-resource`                  | Grants a user or organization role.                                                    |
| `unshare-resource`                | Removes a grant.                                                                       |
| `list-resource-shares`            | Reads current visibility, grants, and policy.                                          |
| `set-resource-visibility`         | Changes private, org, or public visibility when policy allows it.                      |

## API {#api}

Make every shareable table ownable, register it at server startup, and guard
reads and writes with the same access helpers the UI and agent actions use.

```ts filename="server/db/schema.ts"
import { ownableColumns, createSharesTable } from "@agent-native/core/sharing";
import { registerShareableResource } from "@agent-native/core/sharing";

export const dashboards = table("dashboards", {
  id: text("id").primaryKey(),
  title: text("title").notNull(),
  ...ownableColumns(),
});

export const dashboardShares = createSharesTable(
  "dashboard_shares",
  dashboards,
);

registerShareableResource({
  type: "dashboard",
  displayName: "Dashboard",
  table: dashboards,
  sharesTable: dashboardShares,
});
```

Render the standard controls where users decide access:

```tsx
import {
  ShareButton,
  VisibilityBadge,
} from "@agent-native/toolkit/app/sharing";

<VisibilityBadge visibility={dashboard.visibility} />;
<ShareButton resourceType="dashboard" resourceId={dashboard.id} />;
```

## UX Standard {#ux-standard}

- Every resource header should show a visibility badge and a share button.
- Lists should make private vs shared state scannable.
- Public access must be an explicit policy choice, not an accidental URL leak.
- Agents use the same share actions as the UI and cannot bypass resource policy.

`<ShareButton>`, `<ShareDialog>`, and `<VisibilityBadge>` are exported from
`@agent-native/toolkit/app/sharing`. They use Core client hooks, the shared
sharing actions, and the app's localized text. When building custom sharing UI,
import `useShareButtonController` and `useShareDialogController` from
`@agent-native/core/client/sharing`.

The presentational pieces in `@agent-native/toolkit/sharing` take their text
from the app. `VisibilityBadge` there accepts a `labels` object with `private`,
`org`, and `public` text. Any label you leave out falls back to the legacy
English default ("Private", "Org", "Public"), so existing callers keep their
text. `OwnershipFilter` requires labels for `all`, `mine`, and `shared`. The
`@agent-native/toolkit/app/sharing` versions always fill those labels from the
app's localized text, so use them unless you supply the copy yourself.

Moving a resource from Private to Organization in `<ShareButton>` or
`<ShareDialog>` opens a confirmation first. Nothing is saved until the user
confirms, and Cancel or Escape keeps the current access. The confirmation is UI
intent only. The share actions and their policy checks are unchanged for the
agent. For chat threads, both components refresh mounted chat lists after they
save.

Custom surfaces get the same confirmation through
`useShareButtonController().visibilityTransition` (`request`, `confirm`,
`cancel`) and render it with `ShareVisibilityConfirmDialog`. `request` returns a
promise that resolves once the change is saved. A direct change rejects with
the save's error. A held change whose confirmation fails keeps the error and
the retry in the dialog and its promise stays pending until a retry succeeds,
or rejects with `ShareVisibilityNotSavedError` when it is cancelled or
invalidated, so a held change is never reported as saved. The
older `handleVisibilityChange` is a deprecated alias for `request` and never
skips the confirmation. Requests from a closed surface are ignored, and a
pending change is dropped when the resource changes.

### Toolkit vs Core {#toolkit-vs-core}

Toolkit sharing UI renders badges, rows, base dialogs, and role pickers when
data and callbacks are injected. Core sharing code owns SQL, permissions,
request context, org membership lookups, share tables, resource registration,
access filters, visibility changes, invites, roles, and the private access
tokens that back agent-readable public surfaces.

## Shared chat history {#shared-chat-history}

`@agent-native/toolkit/chat-history` renders the chat sidebar. Core supplies the
rows and Toolkit renders them, so an app can show My chats and Shared with you
as separate sections. See [Sharing & Privacy](/docs/sharing#shared-chats) for
the `ownership` filter and the `ownerEmail` and `accessBasis` fields.

`<ChatHistoryRail>` accepts `sections` as well as a flat `items` list. Each
section previews five rows and has its own **Show all** and **Show less**
control, loading, error, and empty states, and optional load-more:

```tsx
import { ChatHistoryRail } from "@agent-native/toolkit/chat-history";
import { useChatThreadList } from "@agent-native/core/client";

const mine = useChatThreadList({ ownership: "mine" });
const shared = useChatThreadList({ ownership: "shared" });

<ChatHistoryRail
  onNewChat={startChat}
  railLabels={{
    newChat: t("newChat"),
    showMore: t("showMore"),
    showLess: t("showLess"),
    sections: {
      showAll: t("showAll"),
      showLess: t("showLess"),
      loadMore: t("loadMore"),
      loadingMore: t("loadingMore"),
      retry: t("retry"),
    },
  }}
  sections={[
    { id: "mine", label: t("myChats"), items: toItems(mine.threads) },
    {
      id: "shared",
      label: t("sharedWithYou"),
      items: toItems(shared.threads),
      hasMore: shared.hasMore,
      loadingMore: shared.loadingMore,
      onLoadMore: shared.loadMore,
      loading: shared.loading,
      error: shared.error ? t("loadFailed") : undefined,
      onRetry: shared.refresh,
    },
  ]}
/>;
```

With `sections`, `railLabels.sections` is required and has no defaults. Pass
`showAll`, `showLess`, `loadMore`, `loadingMore`, and `retry` as translated text,
and override them per section with `section.labels` when needed.

Show all reveals the rows already loaded. When the server has more, a disclosed
section also offers Load more. A failed load shows above the rows that already
loaded, so it never reads as an empty section.

Rows can show who owns a chat and why the viewer can see it. Set `ownerLabel`,
`accessLabel`, and `accessBasis` on a `ChatHistoryItem`. The app passes
translated text, because the Toolkit list ships none. Shared rows should show a
direct grant over organization access when both apply, which is how Core
reports `accessBasis`.
