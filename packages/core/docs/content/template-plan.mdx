# Visual Plans

Agent-Native Plans is visual plan mode for coding agents. It turns an ordinary
Codex, Claude Code, Markdown, or pasted implementation plan into a structured
review surface with rich text, diagrams, wireframes, annotated code
walkthroughs and file trees, comments, and shareable links.

It comes down to two commands. `/visual-plan` builds a plan **before** the
agent writes code. `/visual-recap` turns a change that **already happened** —
a PR, commit, branch, or git diff — into a high-altitude visual code review.
Both open the same review surface, so you annotate, comment, and hand
feedback back to the agent the same way either time.

## What it replaces

<Comparison>

### Before

- A plan lives as a wall of prose in chat or a Markdown file, and reviewing
  it means reading start to finish to find the one paragraph you disagree
  with.
- Feedback happens in a Slack thread or scattered comments, disconnected
  from the plan itself.
- Reviewing a finished PR means reading a raw diff line by line to
  reconstruct what changed and why.

### After

- The plan renders as diagrams, wireframes, annotated code, and an Open
  Questions form you can react to directly.
- Comments pin to the exact text, image, or wireframe location, and target
  either the agent or a human reviewer.
- `/visual-recap` turns a PR, commit, or diff into the same visual review
  instead of a raw diff.

</Comparison>

Export the result as HTML, Markdown, or JSON for a source-control-friendly
copy, or keep it off the hosted database entirely with local-files mode. See
[Reviewing and Commenting on Plans](/docs/template-plan-review-workflow) and
[Local-Files Mode and Desktop Sync](/docs/template-plan-local-and-desktop)
for each of those in depth.

## Get started {#get-started}

<Steps>

### Install the skill {#install}

Most people install Plan as a **skill** for their existing coding agent, not
as a scaffolded app. This one command installs the skill instructions,
registers the hosted Plans MCP connector, and signs it in:

```bash
npx @agent-native/core@latest skills add visual-plan
```

This installs three slash commands — `/visual-plan`, `/visual-recap`, and
`/visualize-repo` — plus the `plan` MCP connector (a remote tool server your
agent talks to) at `https://plan.agent-native.com/mcp`. For the full flag
reference, the plugin/marketplace install routes for Claude Code and Codex,
and the VS Code extension, see
[Plan plugin and marketplace → Install routes](/docs/plan-plugin#install).

Customizing the Plan template itself — self-hosting it, or building on it
directly — is a separate, secondary path covered in
[Extending Plan](/docs/template-plan-developers). Most people never need it.

### Ask your agent for the command that fits the work

- "Use `/visual-plan` before changing the auth flow."
- "Create a `/visual-plan` for the new onboarding screen with mobile and
  desktop states."
- "Run `/visual-recap` on this PR so I can review the shape of the change
  first."
- "Use `/visual-recap` on the diff between `main` and this branch."
- "Run `/visualize-repo` and start with our public API actions and schema."

`/visual-plan` pulls in diagrams, wireframes, mockups, clickable prototypes,
and annotated code as the work calls for them. The agent inspects the
codebase first, then the returned link opens the review UI in your browser
or VS Code.

### Review as a guest, no account needed

People you share a plan with don't need to install anything. They open the
Plans editor and **create and edit with no sign-up** — they work as a
guest. Signing in is only required to **save or share** your own work, and
if a guest signs in later, every plan they created as a guest is **claimed**
into their account.

</Steps>

When a Codex, Claude Code, Markdown, or pasted plan already exists, use
`/visual-plan`; the agent preserves that source plan and builds the richer
review surface from it instead of starting over. If the first pass still has
open decisions, the agent can add an **Open Questions** form at the bottom
of the plan — answering it and sending it back starts a revision turn.

<Callout tone="info">

**Guest vs. signed-in, at a glance**

- **As a guest** you can open a shared link, create a new plan, edit prose,
  and use review annotation mode — no account needed.
- **Signing in** additionally lets you save your own plans permanently,
  publish a plan to a shareable link, grant viewer/editor/admin access to
  others, post comments that notify people by email, and delete or restore
  plans you own.

</Callout>

## Cost and model choice

Generating a plan or recap runs a full agentic session against your coding
agent's LLM, not a lightweight template fill — cost scales with the size of
the diff or plan and the model you choose.

- The app's default chat model is GPT-5.6 Luna. Direct Anthropic connections
  keep Claude Sonnet 5 as their default. Change models any time in
  **Settings**; Haiku is the cheaper Claude option.
- Automated PR recaps from the GitHub Action run separately from the
  interactive app and have their own model and cost knobs — see
  [PR Visual Recap](/docs/pr-visual-recap) for `VISUAL_RECAP_MODEL`,
  `VISUAL_RECAP_AGENT`, and `VISUAL_RECAP_REASONING`.

## Requesting access to a private plan {#request-access}

If someone opens a plan link they don't have permission to view, Plans
doesn't just show a dead end. The page tells them the plan is private and
offers a **Request access** action, which:

- Requires being signed in (a guest is prompted to sign in first).
- Records the request against the plan and, when the deployment has email
  configured, messages the plan owner with the requester's name and a link
  to open the plan and share it back if approved.
- Is safe to click more than once — Plans checks whether you already have
  access first, so a second request from the same person doesn't spam the
  owner with duplicate emails.

If the plan's visibility is set to **org** rather than fully private, and
your account already has a pending invitation to that organization or an
email domain that matches it, Plans offers to join the organization
directly instead of sending a request.

<Callout tone="warning">

If a Plans tool ever returns `needs auth`, `Unauthorized`, or `Session
terminated`, don't keep retrying it. Re-authenticate with
`npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex`,
or re-run `/mcp` → **Authenticate** for an OAuth-capable host. Start a new
Codex thread or restart/reload the client afterward — the tool registry
only picks up the change on a fresh session.

</Callout>
