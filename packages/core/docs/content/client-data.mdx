# Data & Sync

The primary way to read and write app data from client application is through [action](/docs/actions) hooks. By embedding requests into actions, both your client and agent can interact with your application in the same way.

In the example below, a ticket is assigned to the current user manually through a dropdown, and then through the chat agent. Both the UI and agent access the same action.

### Action hooks {#action-hooks}

There are two action hooks you are most likely to use: `useActionQuery()` and `useActionMutation()`. These two hooks provide access to your app's actions.

#### useActionQuery {#use-action-query}

This hook is intended to be used for read-only actions. It is a thin wrapper around the [useQuery()](https://tanstack.com/query/latest/docs/framework/react/reference/useQuery) function. `useActionQuery()` accepts three arguments:

- **actionName**: the action's registered name.
- **params**: the action's input, typed from its `defineAction()` schema.
- **options**: everything from the [useQuery options](https://tanstack.com/query/latest/docs/framework/react/reference/useQuery) except `queryKey` and `queryFn`, which the hook
  sets itself.

In the example below, the `list-tickets` action is called. This is similar to making a GET request for all tickets.

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery("list-tickets", {});
```

The following example shows a request to fetch a single ticket, through the `get-ticket` action. A `ticketId` is provided to scope the query to only return a specific ticket. The additional `enabled` option is provided to ensure the query does not automatically run, and instead only runs when a `ticketId` is present.

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery(
  "get-ticket",
  { ticketId: ticketId ?? "" },
  { enabled: Boolean(ticketId) },
);
```

Results are cached under `["action", name, params]` and refetch automatically whenever a mutating action completes, with no manual invalidation needed.

#### useActionMutation {#use-action-mutation}

This hook is intended to be used for actions that change data, like creating, updating, or sending something. It is a thin wrapper around the [useMutation()](https://tanstack.com/query/latest/docs/framework/react/reference/useMutation) function. `useActionMutation()` accepts two arguments:

- **actionName**: the action's registered name.
- **options**: everything from the [useMutation options](https://tanstack.com/query/latest/docs/framework/react/reference/useMutation) except `mutationFn`, which the hook sets itself. Two extra options are available. `method` overrides the default `POST` request. `skipActionQueryInvalidation` opts out of the automatic cache refresh described below.

Unlike `useActionQuery()`, the action's input is not passed to the hook itself. It is passed to `mutate()` or `mutateAsync()` when you are ready to run the mutation.

In the example below, the `send-ticket-reply` action is called to post a reply to a ticket. Call `mutate()` from an event handler, such as a button's `onClick`.

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply");

mutate({ ticketId, body: draft });
```

The following example shows the same mutation with an `onSuccess` option. Cache invalidation happens automatically after every mutation, so `onSuccess` is only needed for local side effects, like clearing the reply composer once the reply is sent.

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply", {
  onSuccess: () => setDraft(""),
});

mutate({ ticketId, body: draft });
```

On success, the hook emits a change event with `source: "action"`, so every `useActionQuery` reading affected data refetches automatically. No manual invalidation is needed.

### callAction {#call-action}

This function is for imperative one-off action calls outside of a React render flow, such as a plain event handler, a script, or any other non-React code path. It returns a promise directly instead of a hook result. `callAction()` accepts three arguments:

- **actionName**: the action's registered name.
- **params**: the action's input, typed from its `defineAction()` schema.
- **options**: `method` overrides the default `POST` request. `signal` accepts an `AbortSignal`. `timeoutMs` overrides the default 60 second timeout.

In the example below, the `update-ticket` action is called from a keyboard shortcut handler outside of React's render flow, assigning the ticket to a rep.

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction("update-ticket", {
  ticketId,
  assignedToEmail: "jordan@example.com",
});
```

The following example shows the same call with a `timeoutMs` option, useful for actions that legitimately take longer than the default 60 second timeout.

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction(
  "update-ticket",
  { ticketId, assignedToEmail: "jordan@example.com" },
  { timeoutMs: 120_000 },
);
```

Unlike the hooks above, `callAction()` has no cache and no automatic refetch. Pair it with a manual invalidation if other UI depends on the result.

Every `useActionQuery()`, `useActionMutation()`, and `callAction()` request is bounded by a 60 second timeout, and timeouts surface as errors instead of retrying silently. `useActionQuery()` also cancels superseded requests automatically, using React Query's abort signal.

## useDbSync {#usedbsync}

This hook is intended to keep the UI in sync with database changes that happen outside of your own actions, like an agent write, a webhook, or a change made from another browser tab. It listens for changes over server-sent events, and falls back to polling when server-sent events are unavailable. `useDbSync()` accepts a single options argument. The full list of options is in the table below.

```ts
import { useDbSync } from "@agent-native/core/client/hooks";
import { useQueryClient } from "@tanstack/react-query";

function App() {
  const queryClient = useQueryClient();

  useDbSync({
    queryClient,
    pollUrl: "/_agent-native/poll",
    onEvent: (data) => console.log("Data changed:", data),
  });

  return <div>...</div>;
}
```

### Options {#usedbsync-options}

| Option             | Type               | Description                                                                                                                                                  |
| ------------------ | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `queryClient`      | `QueryClient?`     | React-query client for cache invalidation                                                                                                                    |
| `queryKeys`        | `string[]?`        | Deprecated and ignored. Kept for old call sites                                                                                                              |
| `pollUrl`          | `string?`          | Poll endpoint URL. Default: `"/_agent-native/poll"`                                                                                                          |
| `sseUrl`           | `string \| false?` | SSE endpoint URL. Default: `"/_agent-native/events"`. Pass `false` to use polling only                                                                       |
| `interval`         | `number?`          | Polling interval in ms. Default: `2000`                                                                                                                      |
| `fallbackInterval` | `number?`          | Fallback polling interval when SSE is unavailable. Default: `60000`                                                                                          |
| `pauseWhenHidden`  | `boolean?`         | Pause polling when the browser tab is hidden. Default: `false`. Hidden tabs keep SSE connected and poll no faster than every 10s while active, 60s once idle |
| `ignoreSource`     | `string?`          | Per-tab request source to ignore so a tab does not refetch from its own writes                                                                               |
| `onEvent`          | `(data) => void`   | Optional callback when SSE/polling receives a change event                                                                                                   |

For normal CRUD, prefer `useActionQuery()` and `useActionMutation()`. Mutating actions emit `source: "action"`, so those hooks refetch right away. Changes from the agent, a webhook, or another tab arrive through `useDbSync()` instead, over SSE or the polling fallback. If a raw `useQuery()` call needs to sync on a custom key, see [Sync Internals](/docs/client-sync-internals). If you need to write to `application_state` directly, see [Advanced](/docs/client-advanced).
