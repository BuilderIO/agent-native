# Upgrade existing apps to Core 0.198.0

Use this runbook to move an existing app to the Core 0.198.0 release. Run the
commands from the app or workspace root. Keep a reviewable source-control diff
before starting, and check remote deployment settings separately: the CLI can
read local environment files, but it cannot inspect remote environments or
database-backed feature settings.

## 1. Preview the upgrade and import codemods

Use the CLI shipped with Core 0.198.0 so it loads that release's migration
manifest:

    npx @agent-native/core@0.198.0 upgrade --codemods --dry-run

After Core 0.198.0 is installed in the app, the same preview is available from
its local CLI binary:

    npx agent-native upgrade --codemods --dry-run

The `--codemods` command uses `ts-morph`. If it is not already resolvable in the app, install it as a development dependency first: `pnpm add -D ts-morph`.

Add `--dry-run` to preview the upgrade, dependency changes, source diff, and
warnings without writing files. Without that flag, `--codemods` applies
supported rewrites.

The codemod uses the active Core and Toolkit migration manifests. For import
and re-export analysis, it scans only `.ts` and `.tsx` source files (excluding
declaration files and generated or dependency directories). When named exports
move to different modules, it can split a declaration by symbol while retaining
aliases and type-only imports. It also rewrites simple CSS `@import` paths and
adds a missing package dependency when a resolved rewrite crosses a package
boundary.

The diagnostics also detect CommonJS `require()` and dynamic `import()` forms,
but the codemod does not rewrite those call expressions. Replace them using the
reported new home, then rerun Vite or `agent-native doctor`. CSS `@import
url(...)` paths are codemodded with or without quotes.

It does not change call sites or move your files. It leaves unresolved and
planned moves alone with warnings. It cannot split default, namespace,
side-effect, or star imports/exports, or split symbol-level CSS imports. Review
these cases manually. Removed exports may need a code change; follow the
migration guide named in the CLI warning.

The preview covers the full upgrade plan too: it reports framework overrides
or patches that block an upgrade, pending @agent-native/\* version bumps,
feature dependencies inferred from local configuration, the package-manager
install, scaffold skill refresh, and typecheck when the root package has that
script. The command upgrades package specs to the registry's current latest,
then pins the versions the install resolved. Run it while 0.198.0 is the
intended current release; if you require an exact version later, verify the
resolved pins before accepting the diff.

## 2. Confirm Toolkit and optional packages

Imports moved to @agent-native/toolkit/\* require @agent-native/toolkit.
The codemod adds Toolkit when a supported, resolvable import or export moves
there. If your app uses a Toolkit export and no dependency was added, install
the Toolkit release that matches Core 0.198.0:

    pnpm add @agent-native/toolkit@0.198.0
    # or: npm install @agent-native/toolkit@0.198.0
    # or: yarn add @agent-native/toolkit@0.198.0

checks match. For PGlite, it checks the normalized app-specific
`${APP_NAME}_DATABASE_URL` first, then `DATABASE_URL`; it selects PGlite when
the chosen URL is absent or starts with `pglite:`. It cannot inspect remote
environments or database-backed feature settings, so confirm production and
preview configuration yourself.

For first-party template source search, add the matching corpus package as a development dependency: `pnpm add -D @agent-native/core-corpus@0.198.0`.

## 3. Apply the upgrade

After reviewing the preview and confirming feature packages, apply the plan
with the same versioned CLI. This matters when the app still has Core 0.196 or
another older CLI installed: an older CLI carries an older migration manifest.

    npx @agent-native/core@0.198.0 upgrade --codemods

Once Core 0.198.0 is installed, the same command is available from the app's
local CLI:

    npx agent-native upgrade --codemods

Either invocation updates eligible @agent-native/\* dependency specs, aligns
detected feature dependencies, runs the package manager, pins resolved
Agent-Native versions, applies supported codemods, refreshes scaffold skills,
and runs the root typecheck script when one exists. Do not run a second
upgrade command just to apply the codemods. Resolve warnings and app-level
errors in app code; do not add framework overrides or patches.

## 4. Verify the result

Review the complete diff, especially skipped codemod warnings and dependency
versions, then run:

    npx @agent-native/core@0.198.0 upgrade check
    npx agent-native doctor
    pnpm typecheck

Doctor runs the `migration-manifest` and `feature-dependencies` checks by
default. It reports stale imports and optional peers missing for features
detected from local configuration. It cannot inspect remote deployment
settings or database-backed feature settings, so confirm those separately.

Use the equivalent typecheck command for npm or Yarn. Run the app's test and
build scripts when present, usually `pnpm test` and `pnpm build`. Confirm that
local and deployed feature settings are covered by the optional-peer table.
Search for old imports shown in the table below; remaining matches should be
intentional, unsupported by the manifest, or called out by a warning.
