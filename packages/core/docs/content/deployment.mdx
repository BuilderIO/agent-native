# Deployment

Agent-Native apps run on [Nitro](https://nitro.build), so the same app can
deploy to Node.js, serverless functions, edge workers, or a managed host. Pick
the path that matches what you are shipping:

<Cards columns={2}>

### :server: [Deploy an app](/docs/deploy-an-app)

Build and launch one standalone app, or deploy one app from a workspace on its
own domain.

### :network: [Deploy a workspace](/docs/workspace-deployment)

Build several apps behind one origin with shared login and same-origin app to
app communication.

</Cards>

## Before you deploy: choose a persistent database {#persistent-database}

Every deployed app needs a persistent SQL database. Local development can use
the SQLite file at `data/app.db`, but container, preview, and serverless
filesystems can be reset at any time.

<Steps>

### Choose a provider

Use any Drizzle-compatible SQL backend, such as Postgres, Neon, Supabase,
Railway, RDS, Turso, or libSQL. The framework detects the database dialect from
the connection URL.

### Set the connection string

Set `DATABASE_URL` in the deployment environment before the first production
deploy. Use `DATABASE_AUTH_TOKEN` too when the provider requires a separate
token, such as Turso or libSQL.

### Add production secrets

Set a stable `BETTER_AUTH_SECRET` for a standalone app. A workspace also needs
`A2A_SECRET` when it uses signed cross-app requests or background handoffs. The
[deployment environment reference](/docs/deployment-environment-variables)
covers the rest of the production configuration.

</Steps>

<Callout tone="info">

In a workspace, every app inherits the root `DATABASE_URL` by default. Set
`<APP_NAME>_DATABASE_URL` only when one app needs a different database.

</Callout>

## Advanced deployment

Start with the path above. Use these pages when you need provider-specific
settings or production controls:

- [**Node.js**](/docs/node-js) - run the default Nitro server preset
- [**Docker**](/docs/docker) - package the Node.js server in a container
- [**Vercel**](/docs/vercel), [**Netlify**](/docs/netlify), [**Cloudflare Pages**](/docs/cloudflare#cloudflare-pages), and [**Cloudflare Workers**](/docs/cloudflare#cloudflare-workers) - configure hosted targets
- [**AWS Lambda**](/docs/aws-lambda) and [**Deno Deploy**](/docs/deno-deploy) - deploy to function and Deno runtimes
- [**Azure Static Web Apps**](/docs/azure-static-web-apps), [**Koyeb**](/docs/koyeb), and [**Render**](/docs/render) - use additional Nitro providers
- [Nitro's provider list](https://nitro.build/deploy/providers) - see the broader set of presets Nitro supports
- [**SSR Caching**](/docs/ssr-caching) - configure the public shell cache
- [**Deployment Environment Variables**](/docs/deployment-environment-variables) - production secrets, runtime flags, and workspace inheritance
- [**Production Agent Access**](/docs/actions-agent-tools) - control framework tools and code execution
- [**Updating UI in Production**](/docs/updating-ui-in-production) - understand the managed visual-editing workflow
