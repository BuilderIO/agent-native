# Anonymous Clips intake

Anonymous intake lets a customer submit one private Clips recording without signing in to Clips. The product that creates the intake URL still needs an authenticated Clips session or an authenticated backend action caller.

The intake URL is a narrow upload capability. It is not a share link, a library session, or an agent access token.

## Capability boundaries

<!-- i18n-copy-ignore: oxfmt table column alignment only; wording unchanged. -->

| Capability         | Allows                                                                                                               | Does not allow                                                                                    | Lifetime                                |
| ------------------ | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | --------------------------------------- |
| Intake URL         | Create one private recording, upload its chunks, finalize it, or abort it                                            | List recordings, read media, open the library, or use normal agent APIs                           | One hour by default. Four hours maximum |
| Agent context link | Read the completed recording through the normal scoped Clips agent surface after an authenticated host-side exchange | Be minted by the anonymous intake bearer, read any other recording, or act as the recording owner | Seven days for bug-report completions   |
| Clips session      | Mint intake URLs and use the normal authenticated Clips UI                                                           | Nothing is added to the anonymous visitor's browser                                               | Controlled by normal Clips auth         |

The intake token is signed with the existing scoped-token mechanism. The token is never stored in SQL. The database stores only the intake id, owner and organization binding, recording id, status, and expiry.

## End-to-end flow

1. Your authenticated product backend calls `create-recording-intake-link`.
2. Clips returns a short-lived `/bug-report` URL.
3. Your product opens that URL in an iframe or popup.
4. The unsigned visitor fills in the report and records the screen.
5. Clips creates one private recording and sends the media through its existing chunk and finalize pipeline.
6. The completion page posts the recording id to the host window. It does not mint read access with the anonymous bearer.
7. Your authenticated host backend exchanges the completed intake for a separate read-only agent context link.

The browser never receives the Clips workspace session. If the create response is lost after Clips attaches the recording, retrying the same signed create request returns that recording's upload URLs instead of creating a second row. Expired or terminal intake URLs remain unusable.

## Mint an intake URL

`create-recording-intake-link` is a UI and HTTP action. It is not exposed as an agent tool because minting a bearer upload capability is an explicit integration operation.

Call it from an authenticated same-origin browser or from an authenticated backend caller:

```ts
const response = await fetch(
  "https://clips.example.com/_agent-native/actions/create-recording-intake-link",
  {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    credentials: "include",
    body: JSON.stringify({ ttlSeconds: 3600 }),
  },
);

if (!response.ok) throw new Error("Could not create the Clips intake URL");

const { result } = await response.json();
// result.url is safe to give to the unsigned visitor.
```

`ttlSeconds` is optional. It must be between 60 seconds and four hours. The default is one hour. The response also includes `intakeId`, `expiresAt`, and `ttlSeconds`.

The create request is safe to retry with the same `intakeId` and `intakeToken` if its response is lost. Clips returns the existing recording after attachment; it never creates a second recording for the same intake. Do not retry with a different intake token or reuse the upload URLs after an abort.

Do not mint this URL in an anonymous browser. Do not put a long-lived Clips session or a service credential into the customer-facing page.

## Embed the intake page

Pass the returned URL directly to an iframe. The URL already contains the signed `clip_intake_id` and `clip_intake` query parameters.

```tsx
<iframe
  src={result.url}
  allow="display-capture; camera; microphone"
  title="Report a problem"
  style={{ width: 420, height: 560, border: 0 }}
/>
```

The recorder opens a top-level popup when the visitor starts capture. Browser media permissions and screen capture require a user gesture in a top-level browsing context. If popups are blocked, the page falls back to navigating the current window.

## Receive the completed recording

The done page posts `agent-native.clips.bug-report.submitted` to the opener and the embedding parent. For anonymous intake, the message intentionally contains `agentAccessStatus: "unavailable"` and no agent link. Retain the `intakeId` from the mint response on the trusted host, then exchange it server-side after receiving the `recordingId`. Validate both the Clips origin and the message source before using the payload.

```ts
const clipsOrigin = "https://clips.example.com";
let recorderWindow: Window | null = null;

window.addEventListener("message", (event) => {
  if (event.origin !== clipsOrigin) return;
  if (recorderWindow && event.source !== recorderWindow) return;
  if (event.data?.type !== "agent-native.clips.bug-report.submitted") return;

  if (event.data.agentAccessStatus !== "unavailable") return;
  // Send event.data.recordingId and the retained intakeId to your trusted
  // backend. Do not send the anonymous clip_intake token from this page.
});
```

The payload includes `recordingId`, `recordingUrl`, `embedUrl`, `agentShareUrl`, `agentContextUrl`, `agentAccessExpiresAt`, and `agentAccessStatus`. For anonymous intake, `agentAccessStatus: "unavailable"` is expected until the trusted host performs the exchange. Do not treat it as an empty recording result or let the visitor call the exchange action.

Use the authenticated `create-intake-agent-link` action from the trusted host backend. Keep the `intakeId` returned by `create-recording-intake-link` with the host's authenticated Clips session, and pass the completed `recordingId` from the message:

```ts
const response = await fetch(
  "https://clips.example.com/_agent-native/actions/create-intake-agent-link",
  {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    credentials: "include",
    body: JSON.stringify({ intakeId, recordingId }),
  },
);

if (!response.ok) throw new Error("Could not create the Clips agent link");
const { result } = await response.json();
// Send result.contextUrl to the support agent or backend here.
```

The exchange verifies the authenticated owner, organization, intake expiry, completed state, and recording binding before delegating to the normal scoped agent-link implementation. If the host already has an authenticated Clips session with access to the recording, it can also call `create-recording-agent-link` with the `recordingId`.

## Self-hosting requirements

Anonymous intake uses the same storage and database prerequisites as an authenticated recording:

- A persistent `DATABASE_URL`.
- A configured Builder.io or S3-compatible video storage provider.
- The normal production auth and scoped-token configuration from [Deployment](/docs/deployment).
- A public `BETTER_AUTH_URL`, such as `https://clips.example.com`, when the intake URL is minted outside a browser request.

The intake action creates the recording with private visibility regardless of the organization's default recording visibility. The normal Clips access checks still protect the recording after intake completes.

## Security checklist

- Use HTTPS for the Clips app and the host product.
- Treat the intake URL as a bearer credential. Keep it out of logs, analytics events, referrer data, screenshots, and support tickets.
- Use the shortest useful TTL. One hour is the default.
- Validate `event.origin` and `event.source` in the completion listener.
- Keep the intake id and the authenticated exchange on the trusted host. Store the resulting `agentContextUrl` only where the support agent or backend needs it. It is also a bearer credential.
- Never expose `/api/uploads/:recordingId/chunk` or `/api/uploads/:recordingId/abort` directly to anonymous users. Intake traffic goes through the signed `/api/clip-intake` transport, which checks the intake id, token, recording binding, owner binding, status, and expiry on every request.

## Troubleshooting

**The recorder opens a sign-in page.** Make sure the intake URL includes both `clip_intake_id` and `clip_intake`. The `/record` route is public for the intake handoff, while normal recording creation remains session protected.

**The recording says the intake URL is unavailable.** The URL may have expired, been aborted, or be mid-creation. Retry the original create request once if its response was lost; otherwise mint a new intake URL. Each intake URL still creates at most one recording.

**The completion has no agent link.** That is expected for anonymous intake: the visitor's bearer is write-only. Have the authenticated host exchange the retained `intakeId` and completed `recordingId` with `create-intake-agent-link`. A 409 means the recording is still being verified; retry from the trusted host after it becomes ready.

**The page has no storage setup control.** Anonymous visitors cannot configure a Clips storage provider. Configure storage before minting intake URLs.
