# Add a Page

This is part three of the Getting Started series. In [Add an Action](/docs/getting-started-actions)
you created `analyze-text`. Here you'll call that same action from a route. No
database is needed yet: Chat already includes the SQL runtime for when you need
to persist domain data.

## Create the route {#add-a-page}

Route files in `app/routes/` are picked up automatically. Create
`app/routes/text-analyses.tsx`; it will be available at
`http://localhost:8080/text-analyses`.

```tsx filename="app/routes/text-analyses.tsx"
import { useActionQuery } from "@agent-native/core/client/hooks";

type TextAnalysis = {
  summary: {
    characters: number;
    words: number;
    sentences: number;
    paragraphs: number;
  };
};

export default function TextAnalysesRoute() {
  const { data: analysis, isLoading } = useActionQuery<TextAnalysis>(
    "analyze-text",
    { text: "Hello world. How are you today?" },
  );

  return (
    <main className="mx-auto flex max-w-3xl flex-col gap-6 p-6">
      <header>
        <h1 className="text-2xl font-semibold">Text analyses</h1>
        <p className="text-muted-foreground">The same action, on a page.</p>
      </header>
      <section className="grid gap-3 sm:grid-cols-2">
        {isLoading && <p className="text-muted-foreground">Analyzing...</p>}
        {analysis &&
          Object.entries(analysis.summary).map(([label, value]) => (
            <article key={label} className="rounded-lg border p-4">
              <p className="text-sm capitalize text-muted-foreground">
                {label}
              </p>
              <p className="text-2xl font-semibold">{value}</p>
            </article>
          ))}
      </section>
    </main>
  );
}
```

`useActionQuery` calls the same read-only action the agent uses. The page does
not need a custom API route, a second data layer, or SQL yet.

Open `http://localhost:8080/text-analyses`, or ask the agent:

> Navigate to `/text-analyses`.

The route is enough for this tutorial. Add a sidebar entry later if this becomes
a primary workflow. For the full `view-screen`, `navigate`, and application-state
patterns, see [Context Awareness](/docs/context-awareness).
