# Auth, Context & Incremental Migration

`@agent-native/actions` never forces you to replace your auth provider, database, or router. One `createContext()` function in `actions/context.ts` bridges your existing auth into every caller — browser cookies, MCP bearer tokens, Server Components, and CLI sessions — so you can migrate an existing app one route at a time.

## Unified Auth & Typed Context (`actions/context.ts`) {#auth-context}

Define `createContext()` once in `actions/context.ts`, and export a typed `defineAction` helper via `createActionBuilder<AppContext>()` so `ctx.user` and `ctx.orgId` are strongly typed inside every action file.

### Per-Action Authorization, Approvals & Structured Errors

`authorize(input, ctx)` runs after input validation and **before** `needsApproval` or `run` — unauthorized callers never execute side effects. Use `fail()` or `defineActionErrors()` for structured caller-readable errors (matching `@agent-native/core`):

```ts
// actions/delete-todo.ts
import { defineActionErrors } from "@agent-native/actions";
import { z } from "zod";
import { db } from "../lib/db";
import { defineAppAction } from "./context";

const errors = defineActionErrors("not_found");

export default defineAppAction({
  description: "Permanently delete a todo item",
  schema: z.object({ id: z.string().describe("Todo ID") }),
  destructive: true,
  needsApproval: true,
  authorize: (_input, ctx) => Boolean(ctx.user),
  run: async ({ id }, ctx) => {
    const deleted = await db.todos.delete({
      where: { id, userId: ctx.user?.id },
    });
    if (!deleted) {
      errors.fail("Todo not found.", "not_found", {
        statusCode: 404,
        details: { id },
      });
    }
    return { deletedId: id };
  },
});
```

- **UI callers** receive HTTP 404 and render `actionErrorMessage(err)` in a toast.
- **Agents & MCP callers** receive `(errorCode: not_found)` plus `details` so they can recover instead of retrying blindly.
- **Post-commit failures** (e.g. `outputSchema` mismatch after `run()` already wrote) raise `ActionPostCommitError` with `committed: true`, preventing callers from blindly retrying a write that already landed.

<Callout tone="warning">

**Protect remote MCP endpoints explicitly.** On production routes, pass `mcp: { authenticate: (request) => verifyBearerToken(request), include: [...] }` to `createNextHandler()` / `actions.createHandler()` so remote MCP clients can only discover and invoke explicitly permitted actions.

</Callout>

## Incremental Adoption Playbook {#incremental-migration}

You never need a big-bang rewrite. `@agent-native/actions` runs alongside your existing REST endpoints, tRPC routers, or Server Actions so you can migrate one feature slice at a time.

<Sequence>

### Run `npx @agent-native/actions init`

### Move 2–3 key operations into `actions/`

### Swap those screens to typed action hooks

---

### Turn on MCP & CLI for instant agent access

</Sequence>

### Let Your Coding Agent Refactor Legacy Routes

Paste this into **Claude Code** or **Codex** (or add it to your repo's `AGENTS.md`):

```md
Migrate the routes under `app/api/todos/` to `@agent-native/actions`:

1. Create one file per operation in `actions/<verb>-<noun>.ts` using `defineAppAction()`.
2. Add a Zod `schema` with `.describe()` on every field.
3. Mark read-only actions with `http: { method: "GET" }` and `readOnly: true`.
4. Replace manual JSON error responses with `fail(msg, { statusCode, errorCode })`.
5. Update the matching UI components from `fetch()` to `useActionQuery` / `useActionMutation`.
6. Verify with `pnpm action --list` and typecheck before removing the old routes.
```

## FAQ {#faq}

<Accordion>

### Does `@agent-native/actions` require PostgreSQL, Drizzle, or Better Auth?

No. Your `run()` function is plain TypeScript — use Prisma, Drizzle, Kysely, Supabase, MongoDB, external APIs, or in-memory state with whatever auth library your app already uses.

### Can I use Zod v3, Zod v4, Valibot, or ArkType?

Yes. `defineAction()` accepts any validator implementing the Standard Schema specification. For MCP or AI SDK tool export, use a validator with Standard JSON Schema support (such as Zod v4) or pass an explicit `toolSchema`.

### Can I hide UI-only actions from MCP and AI agents?

Yes. Set `mcpTool: false` to hide an action from MCP clients, or `agentTool: false` to keep it strictly UI/HTTP-only while still getting typed hooks and validation.

### Will it bloat my browser bundle?

No. Client entrypoints (`@agent-native/actions/react`, `/solid`, `/vue`, `/svelte`, `/client`) only import `type AppActions` — zero server code, database drivers, or Zod schemas enter the browser bundle.

</Accordion>
