# Auth, Context & Incremental Migration

Define one `createContext()` function in `actions/context.ts` to bridge your existing auth provider across browser sessions, MCP bearer tokens, Server Components, and CLI invocations.

## 1. Define Typed Context (`actions/context.ts`) {#auth-context}

Export `createContext` and a typed action builder via `createActionBuilder<AppContext>()`. Codegen detects `actions/context.ts` automatically.

## 2. Authorization, Approvals & Structured Errors {#errors}

Execution runs in a fixed order: input schema validation → `authorize(input, ctx)` → `needsApproval(input, ctx)` → `run(input, ctx)` → `outputSchema` validation. Unauthorized callers never reach `needsApproval` or `run`.

Use `fail(message, { statusCode, errorCode, details })` or `defineActionErrors()` for structured errors shared with `@agent-native/core`:

```ts
// actions/delete-todo.ts
import { defineActionErrors } from "@agent-native/actions";
import { z } from "zod";
import { db } from "../lib/db";
import { defineAppAction } from "./context";

const errors = defineActionErrors("not_found");

export default defineAppAction({
  description: "Permanently delete a todo item",
  schema: z.object({ id: z.string().describe("Todo ID") }),
  destructive: true,
  needsApproval: true,
  authorize: (_input, ctx) => Boolean(ctx.user),
  run: async ({ id }, ctx) => {
    const deleted = await db.todos.delete({
      where: { id, userId: ctx.user?.id },
    });
    if (!deleted) {
      errors.fail("Todo not found.", "not_found", {
        statusCode: 404,
        details: { id },
      });
    }
    return { deletedId: id };
  },
});
```

- **UI callers** receive HTTP `404` and read a display-safe message with `actionErrorMessage(err)`.
- **MCP and agent callers** receive `isError: true` with `errorCode: "not_found"` and `details`.
- **Post-commit failures** (for example, `outputSchema` failing after `run()` already wrote) throw `ActionPostCommitError` with `committed: true` so callers avoid blind retries.

<Callout tone="warning">

**Authenticate remote MCP mounts.** In production, configure `mcp: { authenticate: (request) => verifyBearerToken(request), include: [...] }` on `createNextHandler()` or `actions.createHandler()` so remote MCP clients can only discover and invoke permitted actions.

</Callout>

## 3. Incremental Migration {#incremental-migration}

Mount `@agent-native/actions` alongside existing REST routes, tRPC routers, or Server Actions and move one feature slice at a time:

<Steps>

### Initialize in the existing repo

Run `npx @agent-native/actions init` and wire `actions/context.ts` to your current auth helper.

### Move one resource slice into `actions/`

Create one file per operation (`actions/<verb>-<noun>.ts`) with `defineAppAction()`, Zod `.describe()` annotations, `http: { method: "GET" }` + `readOnly: true` for reads, and `fail(message, { statusCode, errorCode })` for errors.

### Swap matching screens to action hooks

Replace `fetch()` calls in those components with `useActionQuery` / `useActionMutation` (or your framework's binding), verify with `pnpm action --list` and typecheck, then delete the superseded legacy route.

</Steps>

### Coding-Agent Migration Prompt

Paste this into Claude Code or Codex to migrate a legacy route folder mechanically:

```text
Migrate the routes under `app/api/todos/` to `@agent-native/actions`:
1. Create one file per operation in `actions/<verb>-<noun>.ts` using `defineAppAction()`.
2. Add a Zod `schema` with `.describe()` on every field.
3. Mark read-only actions with `http: { method: "GET" }` and `readOnly: true`.
4. Replace manual JSON error responses with `fail(msg, { statusCode, errorCode })`.
5. Update matching UI components from `fetch()` to `useActionQuery` / `useActionMutation`.
6. Verify with `pnpm action --list` and typecheck before removing the old routes.
```

## FAQ {#faq}

<Accordion>

### Does `@agent-native/actions` require PostgreSQL, Drizzle, or Better Auth?

No. `run()` is plain TypeScript — use Prisma, Drizzle, Kysely, Supabase, MongoDB, external APIs, or in-memory state with your existing auth stack.

### Which schema libraries are supported?

`defineAction()` accepts any validator implementing Standard Schema (Zod v3/v4, Valibot, ArkType). For MCP or AI SDK tool export, use a validator with Standard JSON Schema support (such as Zod v4) or provide `toolSchema`.

### How do I hide UI-only actions from MCP or AI agents?

Set `mcpTool: false` to hide an action from MCP clients, or `agentTool: false` to exclude it from AI SDK tool exporters while keeping typed UI hooks and HTTP endpoints.

### Does importing hooks pull server code into the browser bundle?

No. Client entrypoints (`@agent-native/actions/react`, `/solid`, `/vue`, `/svelte`, `/client`) only import `type AppActions` — no server code, database drivers, or Zod schemas enter the client bundle.

</Accordion>
