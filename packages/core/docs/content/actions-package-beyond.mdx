# Going Beyond Actions

Think of the split like **React → Next.js** (or **Vercel AI SDK → a full app framework**):

- **`@agent-native/actions`** is the **portable operations layer** — one typed contract shared by your UI hooks, HTTP API, CLI, MCP server, and AI SDK tools in any existing app.
- **The full Agent-Native framework** (`@agent-native/core` + `@agent-native/toolkit`) gives you the **structure, UI toolkit, in-app agent, and multi-app A2A architecture** built directly on top of the same actions contract (`@agent-native/actions/contract`).

<Comparison>

### :blue: `@agent-native/actions` (Standalone Package)

- Drops into any existing Next.js, Vite, SolidJS, Vue, SvelteKit, or Node app
- Bring your own auth, database, and UI
- Typed UI hooks, HTTP API, CLI, MCP server, and AI SDK tool exports
- Schema validation, `authorize`, `needsApproval`, and structured `fail()` errors

### :green: Full Agent-Native Framework

- Everything in `@agent-native/actions`, plus:
- **In-app Agent Sidebar & Chat UI** (`AgentKit`) with streaming tool cards & voice dictation
- **Live UI ↔ Agent sync** — the agent sees what's on screen and UI updates in real time
- **Approvals UI, Audit Logs & Write Receipts**
- **Built-in Auth, Orgs, Sharing, Secrets Vault, Automations & A2A**

</Comparison>

## Shared UI & Collaboration Kits (`@agent-native/toolkit`) {#toolkit}

In addition to the backend runtime, [`@agent-native/toolkit`](/docs/agent-native-toolkit) ships polished, ejectable UI kits for full Agent-Native apps:

- **Real-time collaborative editing** — Yjs CRDT sync with live cursors, presence bars, and recent-edit highlights when humans and agents edit the same document simultaneously
- **Review & history UI** — inline comments, threaded review, and version history snapshots
- **App chrome** — Settings shell, Org & Team management, Command palette (`⌘K`), Onboarding setup cards, and Notifications

## Moving from `@agent-native/actions` to `@agent-native/core` {#upgrading}

`@agent-native/core` shares `@agent-native/actions/contract` under the hood and **natively discovers actions defined with `@agent-native/actions`** inside `actions/`:

- `description`, `schema`, `outputSchema`, `http`, `readOnly`, `retrySafe`, `mcpTool`, `agentTool`, `mcpOutputSchema`, `authorize(input, ctx)`, `needsApproval(input, ctx)`, `fail()`, and `defineActionErrors()` share the same contract and error identity.
- You can drop an existing `@agent-native/actions` file straight into a `@agent-native/core` app's `actions/` folder and it runs through Core's full runtime (HTTP, MCP, CLI, audit log, write observation) automatically — then switch the import to `@agent-native/core/action` whenever you want Core-only features like `audit`, `access`, `chatUI`, `mcpApp`, or `publicAgent`.
