# Agent Chat

Your application's client can talk to the agent through a small set of client helpers. These cover sending a prompt, staging hidden context, asking the user a blocking question, and opening the agent panel.

In the example below, a **Draft response** button prompts the agent to ask the user a question. Once the user answers, the agent goes about drafting a response keeping the current page context and the user's response in mind.

## How it works

By using the client helper methods provided by Agent-Native, your UI can prompt the agent to interact with the user in a variety of ways. The diagram below demonstrates how a "Draft response" button can be clicked by the user, which then prompts the agent to interact with the user before generating a response.

The user experience is as follows:

1. The user clicks the **Draft response** button, which causes the `askUserQuestion()` function to get called. The question is answered inline in the agent panel.

1. The user picks **Offer a refund**, which causes `sendDraftRequest()` to send the prompt and ticket context to the agent.

1. The agent calls the `draft-ticket-reply` [action](http://localhost:3000/docs/actions), and the drafted reply appears in the reply composer.

This function asks the user a multiple-choice question from app code, renders it inline in the agent panel, and awaits their answer. Use it when the UI needs one small decision with two to four options before it kicks off agent work, instead of building a custom modal.

In the example below, a "Draft Response" button on a ticket page asks the rep how they'd like to respond before it sends anything to the agent:

```ts
import { askUserQuestion } from "@agent-native/core/client/agent-chat";

const answer = await askUserQuestion({
  question: "How would you like to respond to this ticket?",
  header: "Response", // optional short chip/heading (≈12 chars)
  options: [
    { label: "Offer a refund", value: "refund" },
    { label: "Offer a reprint", value: "reprint" },
  ],
});
```

This React hook wraps `sendToAgentChat()` with loading state tracking.

1. The first argument, `isGenerating`, turns true when you call it, then resets to false when the agent finishes generating.

1. The second argument, `send()`, mirrors the `sendToAgentChat()` function.

## sendToAgentChat(opts) {#sendtoagentchat}

Send a message to the agent chat via `postMessage`. This is the lower-level primitive `useAgentChatGenerating()` above wraps, useful when a UI interaction doesn't need loading-state tracking of its own. Pass `context` for hidden model context, and `submit: true` to send immediately or `submit: false` to prefill a draft the user reviews first.

```ts
import { sendToAgentChat } from "@agent-native/core/client/agent-chat";
// Auto-submit a prompt with hidden context
sendToAgentChat({
  message: "Generate alt text for this image",
  context: "Image path: /api/projects/hero.jpg",
  submit: true,
});

// Prefill without submitting (user reviews first)
sendToAgentChat({
  message: "Rewrite this in a conversational tone",
  context: selectedText,
  submit: false,
});
```

### AgentChatMessage {#agentchatmessage}

| Option        | Type       | Description                                             |
| ------------- | ---------- | ------------------------------------------------------- |
| `message`     | `string`   | The visible prompt sent to the chat                     |
| `context`     | `string?`  | Hidden context appended (not shown in chat UI)          |
| `submit`      | `boolean?` | true = auto-submit, false = prefill only                |
| `newTab`      | `boolean?` | Create a separate chat thread for this prompt           |
| `openSidebar` | `boolean?` | Set false to submit/prefill without opening the sidebar |

Running this from inside an MCP App embed, or backgrounding the run without opening the sidebar, are both covered in [Advanced](/docs/client-advanced#background-send).

## Dynamic Suggestions {#dynamic-suggestions}

Before a conversation starts, `<AgentSidebar>`, `<AgentPanel>`, and `<AssistantChat>` show prompt chips on the empty chat. By default those aren't just your fixed `suggestions` list: the framework reads `navigation`, `selection`, `pending-selection-context`, and the current URL from application state, and merges in chips that match what's actually on screen.

It does this with two checks. If something is selected, it adds generic chips like "Summarize this selection". Separately, it looks at `navigation` for field names common apps already use, such as `threadId`/`emailId` for an email thread or `dashboardId`/`chartId` for a chart, and adds chips tailored to that kind of screen, like "Draft a reply" for a thread or "Find anomalies in this data" for a chart. Whatever it comes up with is merged with your static `suggestions`, deduplicated, and capped at `max`.

```tsx
<AgentSidebar
  suggestions={["Summarize my inbox"]}
  dynamicSuggestions={{ max: 4 }}
>
  <App />
</AgentSidebar>
```

If the current screen doesn't match anything the heuristic recognizes and nothing is selected, it contributes no chips, and the empty chat falls back to your static `suggestions` alone. Set `dynamicSuggestions={false}` to keep only static chips. If your app's navigation shape doesn't match the built-in heuristic, or you want fully deterministic app-specific chips, see [Advanced](/docs/client-advanced#custom-suggestions).

## openAgentSettings(section?) {#openagentsettings}

Use `openAgentSettings()` when an app settings page or setup card should open
the agent sidebar's Settings tab. Pass a section id such as `"llm"`, `"secrets"`,
`"automations"`, `"voice"`, or `"limits"` to open a specific section.

```ts
import { openAgentSettings } from "@agent-native/core/client/navigation";
openAgentSettings();
openAgentSettings("secrets");
```

Prefer this helper over dispatching `agent-panel:open-settings` directly.
