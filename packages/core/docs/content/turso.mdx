# libSQL / Turso

Turso is a supported hosted libSQL provider. It uses the SQLite dialect, not
the Postgres dialect.

## Configure the app

Set the database URL and auth token in the server environment:

```bash
DATABASE_URL=libsql://example-org-example.turso.io
DATABASE_AUTH_TOKEN=YOUR_TURSO_DATABASE_TOKEN
```

The `libsql://` URL selects the remote libSQL driver. Keep
`DATABASE_AUTH_TOKEN` server-side and provide it through the deployment
environment. Do not use a local `file:` URL for production data.

## Schema and migrations

Use the framework's schema helpers and Drizzle actions. Keep SQL compatible
with SQLite and libSQL. Run production migrations in the release or
deployment step using the guidance in the [database guide](/docs/server-database#migrations).

If your app requires Postgres-specific extensions or SQL, use [Neon](/docs/neon),
[Supabase](/docs/supabase), or another [Postgres provider](/docs/postgres)
instead.
