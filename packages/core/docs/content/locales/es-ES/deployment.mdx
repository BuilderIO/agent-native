# Implementación

Las aplicaciones Agent-Native se ejecutan sobre [Nitro](https://nitro.build), así que la misma aplicación
se puede implementar en Node.js, funciones sin servidor, workers en el edge o un host administrado. Elige
la ruta que corresponda a lo que vas a publicar:

<Cards columns={2}>

### :server: [Implementar una aplicación](/docs/deploy-an-app)

Compila y lanza una aplicación independiente en Node.js, Docker, Vercel, Netlify o
Cloudflare Workers.

### :network: [Implementar un espacio de trabajo](/docs/workspace-deployment)

Compila varias aplicaciones bajo un mismo origen, con inicio de sesión compartido y comunicación entre
aplicaciones desde el mismo origen.

</Cards>

## Antes de implementar: elige una base de datos persistente {#persistent-database}

Cada aplicación implementada necesita una base de datos PostgreSQL persistente. El desarrollo local puede usar
la base de datos PGlite en `data/pglite`, pero los sistemas de archivos de contenedores, vistas previas y entornos sin servidor
pueden restablecerse en cualquier momento.

<Steps>

### Elige un proveedor

Usa un proveedor de PostgreSQL alojado, como [Neon](/docs/neon),
[Supabase](/docs/supabase), Railway, Render, [Amazon RDS for PostgreSQL](/docs/aws-rds),
[Cloud SQL for PostgreSQL](/docs/cloud-sql) o [Azure Database for PostgreSQL](/docs/azure-postgresql).
Consulta la guía [Plain Postgres](/docs/postgres) para otros servicios administrados y
servidores PostgreSQL autohospedados. El framework configura PostgreSQL a partir de la
URL de conexión.

### Define la cadena de conexión

Define `DATABASE_URL` en la configuración de variables de entorno o de secretos del proveedor de alojamiento
antes del primer despliegue de producción. Un `.env` local solo configura tu
máquina y el comando de despliegue no lo sube.

### Añade los secretos de producción

Genera un secreto de firma estable con `openssl rand -hex 32` y defínelo como
`BETTER_AUTH_SECRET` en una aplicación independiente. Un espacio de trabajo también necesita `A2A_SECRET`
cuando usa solicitudes firmadas entre aplicaciones o traspasos en segundo plano. La [referencia de variables de
entorno de implementación](/docs/deployment-environment-variables) cubre el resto
de la configuración de producción.

### Ejecuta las migraciones

Ejecuta `pnpm migrate:production` contra la base de datos de producción antes de la primera
visita. Crea las tablas que la aplicación necesita. Vuelve a ejecutarlo después de cada actualización,
antes de que la nueva versión entre en producción. Cada guía de alojamiento muestra dónde encaja este paso.

</Steps>

<Callout tone="info">

En un espacio de trabajo, cada aplicación hereda la `DATABASE_URL` raíz de forma predeterminada. Define
`<APP_NAME>_DATABASE_URL` solo cuando una aplicación necesite otra base de datos.

</Callout>

## El envío de correo es opcional, pero recomendable {#email-provider}

Un proveedor de correo no es necesario para la autenticación con correo y contraseña. Sin
uno, una aplicación implementada usa el registro y el inicio de sesión con correo y contraseña, omite la verificación del correo al registrarse
y no ofrece autenticación mediante enlaces mágicos.

Agent-Native no incluye una cuenta de envío de correo. Conecta Resend o
SendGrid antes del despliegue si quieres enlaces mágicos, verificación del correo,
restablecimiento de contraseñas, invitaciones o notificaciones de uso compartido. Define
`RESEND_API_KEY` o `SENDGRID_API_KEY` en el entorno de implementación. SendGrid
también necesita `EMAIL_FROM`. Consulta [Autenticación](/docs/authentication) para conocer los
modos de autenticación disponibles.

### Personalizar los correos del framework {#email-templates}

Cada correo que envía el framework tiene una plantilla predeterminada. Para usar tu propio
diseño, registra un override desde un plugin de servidor. El framework sigue eligiendo
el destinatario y el remitente y entrega el mensaje. Tu override decide qué
dice el mensaje y cómo se ve.

```ts
// server/plugins/email-templates.ts
import {
  escapeEmailHtml,
  overrideTransactionalEmail,
} from "@agent-native/core/server";

export default function registerEmailTemplates(): void {
  overrideTransactionalEmail("core.resource-shared", (props) => ({
    subject: `${props.sender.name} shared "${props.resource.title}"`,
    html: `<p>${escapeEmailHtml(props.sender.name)} invited you to
      <a href="${escapeEmailHtml(props.resource.url)}">${escapeEmailHtml(props.resource.title)}</a>
      in ${escapeEmailHtml(props.app.name)}.</p>`,
  }));
}
```

| ID del correo                    | Props                                                                              |
| -------------------------------- | ---------------------------------------------------------------------------------- |
| `core.verify-signup`             | `email`, `verifyUrl`                                                               |
| `core.reset-password`            | `email`, `resetUrl`                                                                |
| `core.magic-link`                | `email`, `magicLinkUrl`                                                            |
| `core.change-email-confirmation` | `email`, `newEmail`, `confirmationUrl`                                             |
| `core.change-email-verification` | `email`, `verifyUrl`                                                               |
| `core.organization-invite`       | `invitee`, `orgName`, `inviter`, `acceptUrl`                                       |
| `core.builder-credit-limit`      | `subject`, `heading`, `body`, `upgradeLabel`, `upgradeUrl`                         |
| `core.resource-shared`           | `recipientEmail`, `sender`, `resource` (`type`, `title`, `url`), `role`, `message` |

Cada override también recibe `app` (`name`, `logoUrl`). El segundo argumento contiene
el renderizado predeterminado, para que puedas reutilizar su asunto o su texto.

- Las props son valores sin escapar. Escápalas con `escapeEmailHtml` antes de insertarlas
  en una cadena HTML.
- Devuelve `react` con un elemento de React en lugar de `html` para renderizar un componente.
  React escapa las props por ti.
- Omite `subject` para conservar el asunto predeterminado. Omite `text` para derivar
  el cuerpo de texto plano de tu HTML.
- Si un override lanza un error, el envío falla. El framework no vuelve
  al diseño predeterminado. La vista previa de correos transaccionales renderiza tu override,
  así que revísalo ahí.

## Destinos de implementación compatibles {#supported-deployment-targets}

Cada destino tiene una guía paso a paso. El código de la aplicación y la base de datos son los mismos
sea cual sea el destino que elijas. Solo cambian el preset de compilación y el comando de
despliegue.
