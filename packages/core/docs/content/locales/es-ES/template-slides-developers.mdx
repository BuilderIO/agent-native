# Guía para desarrolladores

Esta página es para cualquiera que personalice la plantilla de Diapositivas
o la extienda: el modelo de datos SQL, cómo se protege a los escritores
concurrentes, todas las acciones que puede llamar el agente, el mapa de
rutas y dónde hacer los cambios habituales.

## Inicio rápido

```bash
npx @agent-native/core@latest create my-slides --standalone --template slides
```

Consulta [Primeros pasos](/docs/getting-started) para el resto de la configuración (`cd`, `pnpm install`, `pnpm dev`) y los fundamentos del framework.

## Modelo de persistencia

Cada presentación es un único blob JSON en `decks.data`. Cada escritura pasa por una acción de lectura-modificación-escritura en el servidor que mantiene un bloqueo por presentación, así que escritores concurrentes, un humano y el agente, o dos humanos, que tocan diapositivas distintas de la misma presentación nunca se sobrescriben el trabajo mutuamente.

- **Las acciones del agente** (`add-slide`, `update-slide`) usan sus propias acciones dedicadas y granulares, y comparten ese mismo bloqueo.
- **El editor del navegador** encola operaciones granulares (`patch-slide`, `delete-slide`, `reorder-slides`, `add-slide`, `patch-deck-fields`) a través de `patch-deck` en lugar de un PUT de la presentación completa.

<Callout id="doc-block-slides10" tone="warning">

Si estás extendiendo la ruta de guardado del editor, encola una nueva operación a través de `patch-deck`. No añadas un nuevo PUT de la presentación completa. Eso reintroduciría la carrera de "gana la última escritura" que el bloqueo existe para evitar.

</Callout>

Las tablas de recursos compartidos del framework (`deck_shares`, `design_system_shares`) asignan principales, usuarios u organizaciones, a roles de lector/editor/administrador por recurso, y se crean mediante el helper compartido `createSharesTable` en lugar de escribirse a mano.

#### Estructura de diapositiva

Cada diapositiva dentro de `decks.data` es:

```json
{
  "id": "slide-1",
  "layout": "title",
  "content": "<div class=\"fmd-slide\" style=\"...\">...</div>"
}
```

`content` es HTML sin procesar. El renderizador se encarga de la relación de aspecto fija y del fondo, y el HTML se encarga de todo lo que hay dentro. También se admite la incrustación enriquecida: los diagramas dibujados a mano y los gráficos renderizados en vivo pueden convivir dentro de una diapositiva junto con HTML normal.

## Inventario de acciones

### Ciclo de vida de la presentación

- `create-deck` — presentación nueva, opcionalmente prepoblada con diapositivas, o un reemplazo masivo atómico de las diapositivas de una presentación existente. Omite `slides` o pasa `[]` para una presentación vacía. La acción abre la nueva presentación a través del estado de la aplicación.
- `get-deck` — el JSON completo de la presentación, o una vista resumida y compacta de las diapositivas
- `list-decks` — todas las presentaciones que el que llama puede ver, con proyecciones ligera/compacta/diapositivas completas para sondeos económicos
- `duplicate-deck` — copia una presentación con ids de diapositiva nuevos
- `update-deck-aspect-ratio` — 16:9, 1:1, 9:16 o 4:5

`add-deck`, `save-deck` y `delete-deck` respaldan los flujos de creación optimista, deshacer/rehacer y eliminación del editor del navegador. El agente usa en su lugar `create-deck`, `add-slide`/`update-slide`/`patch-deck`, y las propias acciones de uso compartido del framework.

### Solicitudes de acceso

- `request-deck-access`, `approve-deck-access-request`, `get-deck-access-status` — el flujo de solicitud de acceso para presentaciones privadas: un visitante sin acceso lo solicita, el propietario aprueba o rechaza desde la app o desde la ruta `/access-request/approve`, y cualquiera de los dos lados puede sondear el estado actual

### Ediciones de diapositivas

- `add-slide` — añade (o inserta en una posición) una diapositiva. Llámala secuencialmente después de un `create-deck` vacío para que el editor pueda mostrar el progreso.
- `update-slide` — edición quirúrgica de buscar/reemplazar, o edición de contenido completo de la diapositiva
- `patch-deck` — la cola de operaciones granulares que usa el editor del navegador en lugar de un PUT de la presentación completa
- `get-layout-overflows` — lee los resultados de ajuste de diapositiva medidos por el navegador, para que una edición que ya no encaja en su diseño se pueda detectar y corregir

### Historial

- `list-deck-versions`, `get-deck-version`, `restore-deck-version` — cada escritura guarda primero una instantánea, así que cualquier momento en el tiempo se puede listar y restaurar

### Comentarios

- `list-slide-comments`, `add-slide-comment`, `update-slide-comment`, `delete-slide-comment`

### Importación

- `import-pptx`, `import-docx`, `import-google-doc` — importadores dedicados para un solo formato
- `import-google-slides-reference` — importa una presentación de Google Slides como una presentación de referencia reutilizable, en lugar de traer su contenido a la presentación de trabajo
- `import-file` — un único punto de entrada para PPTX, DOCX o PDF, o un archivo `.fig` de Figma (que se dirige a la indexación de sistemas de diseño de Builder en lugar de a una importación de diapositivas)
- `extract-pdf` — volcado de texto sin procesar de un PDF, solo por CLI, sobre todo para depuración local

### Exportación

- `export-pptx` — PowerPoint nativo y editable
- `export-google-slides` — genera el mismo PPTX más un enlace de importación de Google Slides listo para usar
- `export-html` — un archivo HTML independiente y autocontenido con navegación por teclado integrada

### Sistemas de diseño

- `create-design-system`, `update-design-system`, `delete-design-system`, `get-design-system`, `list-design-systems`, `set-default-design-system`, `apply-design-system` (vincula uno a una presentación)
- `get-workspace-defaults`, `set-workspace-defaults` — la presentación y el sistema de diseño predeterminados a nivel de espacio de trabajo. Establecer uno es solo para administradores
- `analyze-brand-assets`, `import-document`, `import-from-url`, `import-code` — recopilan señales de marca sin procesar (CSS/fuentes del sitio web, contenido de documentos o archivos de código subidos) para un sistema de diseño **local**, redactado por el agente
- `index-design-system-with-builder`, `sync-design-system-with-builder`, `import-design-project` — la ruta indexada por Builder para archivos de Figma, repositorios de código/GitHub conectados y `design.md`. `import-design-project` empieza a partir de un sistema de diseño existente en lugar de una fuente sin procesar

### Creative Context

- `clone-context-slide` — inserta una diapositiva fijada de la Library en una presentación sin cambios, sin regenerar su HTML/CSS
- `clone-creative-context-deck` — recrea una versión exacta y gobernada de una presentación
- `get-deck-reference-context` — extrae el lenguaje visual de una presentación existente como una biblioteca de patrones reutilizable
- La recuperación y el envío a la Library (buscar, obtener un elemento de contexto, gestionar la pertenencia a la Library) son acciones compartidas del framework que el agente llama de la misma forma en cualquier app que admita Creative Context. Consulta el skill `creative-context` para conocer el procedimiento de recuperación y la escala de reutilización.

### Escalado y datos preparados

- `provider-api-catalog`, `provider-api-docs`, `provider-api-request` — acceso directo a la API de Google Drive sin procesar cuando una acción de importación/exportación predefinida es demasiado limitada. Diapositivas resuelve la autenticación a partir de la cuenta de Google Docs conectada del usuario
- `list-staged-datasets`, `query-staged-dataset`, `delete-staged-dataset` — agrega un resultado grande y preparado del proveedor sin volver a obtenerlo

### Navegación y contexto

- `view-screen` — lo que el usuario está viendo en este momento: la presentación abierta, la diapositiva actual y cualquier selección visual activa
- `navigate` — mueve la interfaz a una presentación, diapositiva o vista

## Personalizarla

La plantilla de Diapositivas es totalmente personalizable. Lugares clave donde mirar al extenderla:

#### Actions — `templates/slides/actions/`

Cada operación que el agente puede llamar vive aquí como un archivo TypeScript, montado automáticamente en `POST /_agent-native/actions/:name` y que se puede invocar desde la CLI como `pnpm action <name>`. Añade un nuevo archivo aquí para darle al agente una nueva capacidad.

  code={
    'import { defineAction, fail } from "@agent-native/core/action";\nimport { assertAccess } from "@agent-native/core/sharing";\nimport { eq } from "drizzle-orm";\nimport { z } from "zod";\n\nimport { getDb, schema } from "../server/db/index.js";\nimport { notifyClients } from "../server/handlers/decks.js";\nimport { withDeckLock } from "./patch-deck.js";\n\nexport default defineAction({\n  description:\n    "Surgically edit a slide\'s content using search-replace or full replacement. " +\n    "Syncs live to open editors. Prefer this over full deck rewrites.",\n  schema: z.object({\n    deckId: z.string(),\n    slideId: z.string(),\n    find: z.string().optional(),\n    replace: z.string().optional(),\n    fullContent: z.string().optional(),\n  }),\n  run: async ({ deckId, slideId, find, replace, fullContent }) => {\n    await assertAccess("deck", deckId, "editor");\n    return withDeckLock(deckId, async () => {\n      const db = getDb();\n      const [row] = await db\n        .select()\n        .from(schema.decks)\n        .where(eq(schema.decks.id, deckId));\n      if (!row) {\n        fail(`Deck ${deckId} not found`, { errorCode: "deck_not_found", statusCode: 404 });\n      }\n\n      const deck = JSON.parse(row.data);\n      const slide = deck.slides.find((s: { id: string }) => s.id === slideId);\n      if (!slide) {\n        fail(`Slide ${slideId} not found`, { errorCode: "slide_not_found", statusCode: 404 });\n      }\n\n      if (fullContent) {\n        slide.content = fullContent;\n      } else if (find) {\n        const idx = slide.content.indexOf(find);\n        if (idx === -1) {\n          fail("Text not found", { errorCode: "slide_find_no_match" });\n        }\n        slide.content =\n          slide.content.slice(0, idx) +\n          (replace ?? "") +\n          slide.content.slice(idx + find.length);\n      }\n\n      deck.updatedAt = new Date().toISOString();\n      await db\n        .update(schema.decks)\n        .set({ data: JSON.stringify(deck), updatedAt: deck.updatedAt })\n        .where(eq(schema.decks.id, deckId));\n\n      notifyClients(deckId, { slideId, actor: "agent" });\n      return { ok: true, deckId, slideId };\n    });\n  },\n});'

La acción real también valida que se proporcionó exactamente un modo de edición, guarda una instantánea de versión antes de escribir, y escribe con una comprobación de concurrencia optimista para que una lectura obsoleta nunca pueda sobrescribir en silencio una más reciente, además de registrar la procedencia de reutilización de Creative Context y esperar brevemente a que el editor informe de una medición de desbordamiento de diseño. Este ejemplo reduce todo eso a la forma esencial de acceso, bloqueo, lectura-modificación-escritura y notificación.

La mayor parte de la personalización de la interfaz del editor ocurre bajo `app/components/editor/`: el lienzo de diapositivas, la barra de herramientas, la barra lateral, el menú de burbujas, el menú de barra diagonal y el panel de historial.

#### Skills — `templates/slides/.agents/skills/`

Skills del agente que explican patrones cuando necesita modificar código:

- `create-deck` — cómo crear una presentación nueva, con las plantillas HTML exactas de diapositivas para cada diseño
- `slide-editing` — cómo editar diapositivas individuales
- `deck-management` — cómo se almacenan y se accede a las presentaciones
- `design-systems` — la forma de los datos de un sistema de diseño y cómo se aplican los tokens a las diapositivas generadas
- `creative-context` — la escala de reutilización, el procedimiento de recuperación y el envío a la Library

#### AGENTS.md

`templates/slides/AGENTS.md` es el enrutador corto que el agente lee en cada conversación. Apunta a los skills bajo `.agents/skills/` y establece las reglas básicas, el modelo de persistencia y el contrato de estado de la aplicación. Actualiza el skill correspondiente cada vez que añadas o cambies un diseño de diapositiva o una fuente de sistema de diseño.
