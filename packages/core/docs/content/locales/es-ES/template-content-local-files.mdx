# Content: Fuentes de carpetas locales

Content tiene un único modelo de datos: cada página vive en SQL, pertenece a un
**espacio** y es miembro de la base de datos **Files** del sistema de ese
espacio. Una carpeta local de Markdown o MDX es una fuente conectada a Files,
junto con la colaboración, el uso compartido, los comentarios, el historial, la
búsqueda, las propiedades de base de datos y la misma superficie de acciones
que usa cualquier otra página.

## Espacios, Files y Workspaces

Content aprovisiona:

- un espacio personal para cada usuario
- un espacio de organización para cada organización a la que el usuario tiene acceso
- una base de datos del sistema **Files** en cada espacio
- un catálogo personal **Workspaces** que hace referencia a los espacios que se muestran en la aplicación

Cada página ordinaria pertenece exactamente a un espacio y exactamente a una
base de datos Files. Files es una base de Content normal: puede añadir
propiedades, guardar vistas, filtrar, ordenar o agrupar. Su vista de barra
lateral representa esas mismas filas como navegación. Agrupar una vista de
barra lateral crea secciones plegables, y las vistas guardadas pueden
convertirse en pestañas alternativas de la barra lateral.

El catálogo Workspaces aplica la misma idea un nivel más arriba. Controla qué
espacios personales, de organización y respaldados por carpetas participan en
la barra lateral de la aplicación.

## Conectar una carpeta

<Steps>

### Abrir la pantalla de carpeta local

Elija una carpeta mediante la API File System Access del navegador o
Agent-Native Desktop. Content guarda en SQL únicamente un identificador de
conexión opaco, rutas relativas, hashes y metadatos de origen. Nunca guarda
ahí la ruta absoluta, el identificador del navegador ni el cuerpo bruto de los
archivos.

### Elegir dónde se conecta la carpeta

Conéctela a la base de datos Files de un espacio personal u organización
existente, o cree un espacio privado respaldado por carpeta con su propia
base de datos Files.

### Elegir una política de verdad

| Política                 | Comportamiento                                                          |
| ------------------------ | ------------------------------------------------------------------------ |
| `database_primary`       | Content es la fuente autorizada; los cambios en la carpeta se revisan antes de usarse |
| `source_primary`         | La carpeta es la fuente autorizada cuando no existe una edición simultánea en Content |
| `reviewed_bidirectional` | Los cambios en cualquier dirección requieren revisión ante conflictos   |

</Steps>

La sincronización inicial materializa los archivos como páginas SQL normales y
registra su identidad de origen. Una sincronización repetida es idempotente.
Si un archivo y su página de Content cambian a la vez, Content registra un
conjunto de cambios entrante en lugar de sobrescribir silenciosamente alguno
de los lados. Desconectar conserva tanto las páginas SQL como los archivos
locales.

## Iniciar Content para un repositorio

Desde un repositorio o carpeta, ejecute:

```bash
npx @agent-native/core@latest content .
```

También puede apuntar a un solo archivo:

```bash
npx @agent-native/core@latest content docs/getting-started.mdx
```

El comando inicia la aplicación Content normal respaldada por base de datos,
registra la carpeta como fuente local y abre la pantalla de conexión.

## Configuración del manifiesto

`agent-native.json` declara las raíces de carpetas y sus metadatos de
adaptador:

```json
{
  "version": 1,
  "apps": {
    "content": {
      "roots": [
        {
          "name": "Docs",
          "path": "docs",
          "kind": "docs",
          "extensions": [".md", ".mdx"],
          "source": {
            "type": "local-folder",
            "connectionId": "local-folder:<opaque-id>",
            "truthPolicy": "source_primary"
          }
        }
      ],
      "components": "components",
      "extensions": "extensions",
      "hide": ["**/_*.md", "**/_*.mdx"]
    }
  }
}
```

El identificador de conexión es deliberadamente opaco. El puente de confianza
del navegador o de Desktop lo asocia de nuevo a una referencia de carpeta de
forma local.

## Formato de archivo e identidad

Content lee `.md` y `.mdx`. El frontmatter puede conservar el ID estable de la
página de Content, el título, el padre, el orden y otros metadatos admitidos.
Conservar el ID permite que los renombrados y los movimientos mantengan la
identidad de la página en lugar de crear duplicados.

Las herramientas que editan el origen deben conservar el frontmatter
desconocido, los imports, JSX y el MDX personalizado. Los componentes locales
permanecen en la carpeta `components/` configurada y solo se cargan a través
del puente local de confianza. Las extensiones locales permanecen aisladas
bajo `extensions/`.

## Migrar desde el modo de archivos locales

<Callout tone="info">

Omita esta sección si está configurando una carpeta local por primera vez.
Solo se aplica a un manifiesto anterior al modelo de fuentes actual.

</Callout>

Un manifiesto anterior puede contener `mode: "local-files"`, y un flujo de
inicio anterior puede definir `AGENT_NATIVE_MODE=local-files`. Elimine ambos.
Conserve las raíces configuradas, añada `source.type`, `source.connectionId` y
`source.truthPolicy`, y luego inicie con `agent-native content
<archivo-o-carpeta>`.

Tras la primera conexión y sincronización, confirme que:

- La carpeta aparece como fuente en la base de datos Files prevista.
- Cada página importada pertenece al espacio previsto.
- Las propiedades personalizadas y las vistas guardadas de la barra lateral funcionan con normalidad.
- Las ediciones simultáneas aparecen como conjuntos de cambios revisables.
- Desconectar conserva las páginas de la base de datos y los archivos en disco.
