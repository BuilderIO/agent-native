# Plugin y marketplace de Plan

La app Agent-Native **Plan** se distribuye como un único paquete instalable. Una sola instalación añade las skills de comandos de barra diagonal de Plan **y** conecta el conector alojado de Plan MCP (un servidor de herramientas remoto con el que habla tu agente), de modo que el agente puede generar planes y publicarlos directamente en la app Plan en un solo paso. Esta página es para quien esté eligiendo una vía de instalación, solucionando un problema de instalación, o decidiendo si enviar Plan a un catálogo de plugins curado — consulta [Plans visuales](/docs/template-plan) para saber qué hacen realmente las skills.

## Qué obtienes {#what-you-get}

Una sola instalación te da:

- **Tres skills** — `/visual-plan` (el punto de entrada canónico), `/visual-recap` y `/visualize-repo`.
- **El conector MCP de Plan** — registrado contra la app alojada en `https://plan.agent-native.com` (endpoint MCP `https://plan.agent-native.com/mcp`, nombre de servidor `plan`).

De forma predeterminada, `/visual-plan` y `/visual-recap` publican en la app Plan alojada:
crean un plan a través del conector MCP y te entregan un enlace o un plan en línea para
revisar. Nunca vuelcan un plan Markdown/ASCII en línea en el chat como entregable. Si una
herramienta de Plan devuelve `needs auth`, `Unauthorized` o `Session terminated`, vuelve a
autenticar el conector en lugar de recurrir a la salida en línea. Los tokens de acceso son de
larga duración (30 días por defecto, con renovación deslizante de 365 días), así que esto
debería ser poco frecuente; cuando ocurre, la solución rápida es:

```bash
npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex
```

`reconnect` encuentra y renueva el conector por URL para el cliente local seleccionado, sin
necesidad de reinstalar. Inicia un nuevo hilo de Codex después de reconectar para que el
registro de herramientas se recargue. En Claude Code, el equivalente es `/mcp` →
**Authenticate / Reconnect**, o el mismo comando con `--client claude-code`.

La excepción es el **modo explícito de privacidad de archivos locales**. Cuando pides que no
haya escrituras en la base de datos, o estableces `AGENT_NATIVE_PLANS_MODE=local-files`, las
skills no deben llamar al conector MCP de Plan. Escriben `plans/<slug>/plan.mdx` más,
opcionalmente, `canvas.mdx`, `prototype.mdx` y `.plan-state.json`, y luego previsualizan en
local con:

```bash
npx @agent-native/core@latest plan local serve --dir plans/<slug> --kind plan --open
```

Esto inicia un pequeño puente localhost y abre la interfaz de Plan contra la carpeta local.
(`plan local preview` ejecuta en su lugar una ruta local de servidor de desarrollo de Plan, y
`plan local preview --out preview.html` es una vía de escape heredada que escribe un archivo
HTML estático independiente. `plan serve` se acepta como alias corto de `plan local serve`.)

Algunos detalles a tener en cuenta sobre el modo de archivos locales:

- **Usa un navegador Chromium.** Safari bloquea que la página HTTPS alojada de Plan lea el
  puente localhost `http://127.0.0.1` (contenido mixto / red privada), por lo que la página se
  queda colgada en "Loading plan." En macOS, `--open` ya prefiere Chrome/Chromium/Edge/Brave;
  si Safari se abre de todos modos, vuelve a abrir la URL impresa en un navegador Chromium.
- **La URL servida se escribe en `plans/<slug>/.plan-url`** (puedes anularlo con
  `--url-file`). Un agente en segundo plano o sin interfaz puede leer ese archivo en lugar de
  analizar el stdout de larga duración de `serve`. Trátalo como un archivo de token local y no
  lo confirmes en el control de versiones.
- **Verifica sin interfaz** cuando no hay ningún navegador disponible:
  `npx @agent-native/core@latest plan local verify --dir plans/<slug>` inicia el puente,
  comprueba el preflight de red privada y el payload JSON, imprime diagnósticos y termina con
  código distinto de cero si falla; no hace falta que lo revise una persona.
- **Ejecuta primero `plan local check`.** Valida el MDX contra el esquema de bloques del
  renderizador de Plan (incluidos campos obligatorios como `id`/`label` del elemento
  `checklist` y `id`/`title`/`mode` de la pregunta `question-form`), de modo que los errores de
  redacción salgan a la luz antes de pasar al navegador, en lugar de manifestarse como un
  loader atascado.

Para carpetas del repositorio actual, la ruta local directa incluye `?path=...` de modo que la
app Plan local pueda seguir guardando las ediciones del navegador en la carpeta del
repositorio. La app Plan usa `apps.plan.roots[0].path` en `agent-native.json` como lugar
predeterminado para guardar los planes locales promovidos, recurriendo a `plans/` si no está
definido.

Esto mantiene el contenido del plan fuera de la base de datos de Agent-Native Plan. El uso
compartido alojado, los comentarios, las capturas de pantalla y el historial del plan no están
disponibles hasta que publiques explícitamente más adelante.

Agent-Native Desktop tiene una vía de sincronización de archivos locales aparte para los
planes alojados: la app Desktop puede reflejar un plan alojado en archivos MDX locales e
importar de vuelta las ediciones, sin clonar la app Plan ni ejecutar una CLI. Ese flujo de
trabajo mantiene la base de datos alojada de Plan como fuente de verdad; usa el modo de
privacidad de archivos locales cuando el objetivo sea que no haya escrituras en la base de
datos de Plan.

> El plugin (`agent-native-visual-plans`) lleva el app id `visual-plans`, por lo que el nombre del plugin de Claude Code y el del plugin de Codex son ambos `agent-native-visual-plans`. El nombre visible de la app Plan es "Agent-Native Plan".

## Rutas de instalación {#install}

Hay tres formas de entrar. La **vía de la CLI universal** es la que recomendamos por defecto, porque instala las skills **y** te permite elegir el modo alojado, de archivos locales o autoalojado en un mismo flujo. Las vías de plugin son para hosts con un sistema de plugins/marketplace de primera clase y usan Plans alojado de forma predeterminada.

### Vía universal de skill (cualquier host MCP) {#universal}

Funciona con cualquier host — Claude Code, Codex, Cursor, Cline, Goose, apps MCP personalizadas de ChatGPT, Claude Cowork y cualquier otro compatible con MCP. La CLI de Agent-Native instala las skills de Plan, registra el conector MCP alojado de Plan **y ejecuta la autenticación para los clientes locales seleccionados en el mismo paso**, de modo que tu primera llamada a una herramienta no choque con un muro de OAuth:

```bash
npx @agent-native/core@latest skills add visual-plan
```

Esto instala `visual-plan` más las skills complementarias `visual-recap` y `visualize-repo`, luego registra el conector `plan`, y después ejecuta la autenticación (aviso OAuth para el uso compartido alojado/respaldado por cuenta). Flags útiles:

- `--client codex|claude-code|claude-code-cli|cowork|all` — para qué agentes locales escribir la configuración MCP (por defecto `all`).
- `--no-connect` — registra el conector sin autenticar; ejecuta más tarde `npx @agent-native/core@latest connect https://plan.agent-native.com --client all`, o elige un `--client` más específico.
- `--mode hosted|local-files|self-hosted` — elige uso compartido alojado, archivos MDX totalmente locales o tu propia app Plan.
- `--mcp-url <url>` — apunta el conector a un origen personalizado (un túnel ngrok, un servidor de desarrollo local o un despliegue autoalojado) en lugar del valor predeterminado alojado.
- `--with-github-action` — también escribe la GitHub Action de Resumen visual de PR (consulta [Resumen visual de PR](/docs/pr-visual-recap)).

Las instalaciones interactivas también ofrecen la Action de Resumen visual de PR cuando no existe ningún flujo de trabajo. Responde que sí para añadirla durante la configuración de la skill, o ejecuta el comando anterior más tarde con `--with-github-action`. Después de escribir el flujo de trabajo, ejecuta:

```bash
npx @agent-native/core@latest recap setup
npx @agent-native/core@latest recap doctor
```

`recap setup` configura los secrets y variables de la GitHub Action cuando es posible, y `recap doctor` verifica el flujo de trabajo, el token de publicación local, el acceso al repositorio de GitHub y la configuración necesaria de Actions. Cuando termine la instalación, reinicia o recarga el cliente del agente para que se carguen las nuevas skills y herramientas, y luego ejecuta `/visual-plan`.

> Nota: el comando `npx skills@latest add BuilderIO/agent-native --skill visual-plan` a secas (CLI abierta de Skills/Vercel) instala **solo las instrucciones**: no registra el conector MCP. Usa la CLI de Agent-Native anterior cuando también quieras que el conector quede conectado.

### Claude Code (plugin) {#claude-code}

El repositorio público `BuilderIO/agent-native` es en sí mismo un marketplace de plugins de Claude Code, así que lo añades directamente, sin ningún paso de build. Dentro de Claude Code:

```text
/plugin marketplace add BuilderIO/agent-native
/plugin install agent-native-visual-plans@agent-native-apps
/reload-plugins
/mcp        # authenticate the Plan connector (one OAuth approval)
```

`/plugin install` añade las skills de Plan y una configuración MCP **solo con URL** (sin secrets en el paquete); `/mcp` → **Authenticate** completa el intercambio OAuth. Usa en su lugar la vía de la CLI universal cuando quieras el modo de archivos locales o autoalojado.

> El catálogo del marketplace se llama `agent-native-apps` y el plugin de Plan es `agent-native-visual-plans`, así que el objetivo de instalación siempre es `agent-native-visual-plans@agent-native-apps`.

### Codex (plugin) {#codex}

El mismo repositorio es un marketplace de plugins de Codex. Añádelo, instala el plugin y luego autentica el conector:

```bash
codex plugin marketplace add BuilderIO/agent-native
codex plugin add agent-native-visual-plans@agent-native-apps
codex mcp login plan   # OAuth in the browser
```

Tras la instalación, **inicia un nuevo hilo de Codex** para que las skills y las herramientas MCP se carguen en la sesión. El plugin incluye un conector solo con URL (`[mcp_servers.plan]` → `https://plan.agent-native.com/mcp`); `codex mcp login plan` ejecuta el flujo OAuth. La vía de la CLI universal de arriba también funciona para Codex (`npx @agent-native/core@latest skills add visual-plan --client codex`) si prefieres un único comando que instale y autentique a la vez, o cuando quieras el modo de archivos locales o autoalojado.

<Callout tone="info">

**Instalaciones antiguas:** si tu configuración todavía tiene una entrada `agent-native-plans` que apunta a la misma URL, ejecutar `npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex` para Codex, o el mismo comando con tu `--client` de destino, la consolida bajo el nombre canónico `plan`.

</Callout>

## Actualizaciones {#updates}

Las vías de plugin se actualizan automáticamente: no necesitas volver a empaquetar ni volver a añadir el marketplace para cambios rutinarios de las skills:

- **Claude Code** — la entrada del marketplace establece `autoUpdate: true` y el plugin usa versionado por SHA de commit, así que Claude Code descarga versiones nuevas del repositorio al arrancar; ejecuta `/reload-plugins` para activarlas. Cada push a la rama predeterminada del repositorio llega automáticamente a los usuarios que lo tienen instalado.
- **Codex** — la `version` del plugin incorpora un hash de contenido de las skills incluidas y del endpoint MCP (por ejemplo, `1.0.0+codex.<hash>`), así que cualquier cambio en una skill o en el endpoint genera una versión nueva. La actualización automática de arranque de Codex reinstala por su cuenta los marketplaces de git configurados; basta con **iniciar un hilo nuevo** para recoger el cambio. No hace falta ejecutar manualmente `codex plugin marketplace upgrade` para las actualizaciones rutinarias.
- **Vía de la CLI universal** — ejecuta `npx @agent-native/core@latest skills status visual-plan` para comprobar las carpetas de skills copiadas, o `npx @agent-native/core@latest skills update visual-plan` para actualizarlas en el mismo sitio. Volver a ejecutar `skills add visual-plan` sigue funcionando cuando también quieres volver a registrar/autenticar el conector. `@latest` siempre trae las skills actuales del paquete `@agent-native/core` publicado.

El conector apunta a una app **alojada**, así que las actions de la app Plan y la superficie de herramientas en vivo siempre reflejan la versión desplegada, sin importar cuándo instalaste; solo las instrucciones de la skill incluida siguen los mecanismos de actualización anteriores.

<Callout tone="info">

**Mantenedores:** el paquete del marketplace (`.claude-plugin/`, `.agents/plugins/`) se genera a partir de las skills canónicas de plan mediante `pnpm sync:plan-marketplace` y se verifica en CI con `pnpm guard:plan-marketplace`, de modo que el marketplace publicado siempre coincide con las skills canónicas. Edita la skill, ejecuta `pnpm sync:plan-marketplace` y confirma el cambio.

</Callout>

## ¿Necesitas enviar algo? {#submission}

**No se necesita ningún envío ni revisión para distribuir o instalar esto.** `BuilderIO/agent-native` es un marketplace de git público y autoalojado, así que los usuarios lo añaden directamente con los comandos anteriores, **tanto en Claude Code como en Codex**, sin solicitud ni aprobación. La vía de la CLI universal no necesita ningún marketplace en absoluto.

Descubribilidad opcional, si quieres un listado público:

- **Claude Code** tiene un marketplace comunitario al que puedes enviar tu plugin _opcionalmente_ para aparecer listado (envío más una revisión automatizada). El marketplace oficial, curado por Anthropic, se lista a discreción de Anthropic; no existe una solicitud abierta de autoservicio. Ninguno de los dos es necesario para usar los comandos de instalación anteriores.
- **Codex** tiene un catálogo de plugins curado por OpenAI (una lista de permitidos cerrada, que se obtiene mediante acuerdos de colaboración y no mediante envío de autoservicio). Los marketplaces de git autoalojados y la vía de la CLI no necesitan ningún envío para funcionar.

En resumen: publícalo como un marketplace de git autoalojado/público y los usuarios lo instalan directamente; envíalo a un catálogo curado solo si quieres que aparezca listado para que se pueda descubrir.

## Plugin frente a skill {#plugin-vs-skill}

Una **skill** es un único archivo de instrucciones `SKILL.md` que el agente lee cuando una tarea coincide. Un **plugin** (plugin de marketplace de Claude Code o plugin de Codex) es un paquete que empaqueta una o más skills **más** un conector MCP y metadatos, de modo que un host puede instalarlo todo en un solo paso.

Por debajo, las tres vías se generan a partir de la misma fuente mediante la CLI `npx @agent-native/core@latest app-skill`: `app-skill pack` construye los adaptadores de marketplace/plugin, y `skills add` es el instalador amigable de un solo paso que además registra y autentica el conector MCP. Consulta la [Guía de Skills](/docs/skills-guide) para el formato del manifiesto de app-skill, y [Agentes externos](/docs/external-agents) para conectar cualquier host MCP y el flujo de `npx @agent-native/core@latest connect`.
