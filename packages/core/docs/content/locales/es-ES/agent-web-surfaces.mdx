# Web del agente público

La web pública de agentes facilita que los agentes rastreen, lean, citen y llamen las rutas públicas Agent-Native. El objetivo no es hacer públicos todos los puntos finales de las aplicaciones. El objetivo es publicar una superficie pública limpia para las páginas que ya son públicas, manteniendo al mismo tiempo los datos privados y el acceso a las herramientas detrás de controles explícitos.

El sitio de documentos es la implementación de referencia. Hoy se envía:

- `/robots.txt` con una política de rastreador que permite la recuperación pero no permite el entrenamiento de forma predeterminada.
- `/sitemap.xml` como índice de sitemaps que apunta a un `/sitemap-<locale>.xml` por idioma, con URL canónicos absolutos y `lastmod` cuando el archivo fuente lo expone.
- `/llms.txt` y `/llms-full.txt` para un descubrimiento de contenido fácil de usar para los agentes.
- Espejos Markdown como `/docs/getting-started.md`.
- Respuestas `Accept: text/markdown` para páginas de documentos públicos después de una compilación de producción.
- JSON-LD para metadatos de página, sitio web y organización base.
- Una auditoría CLI (`npx @agent-native/core@latest audit-agent-web`) que comprueba todo lo anterior.

Publicar estos archivos nunca expone una acción. Una acción solo llega a agentes externos mediante su propia activación de `publicAgent`; consulta [Exponer a agentes públicos](/docs/actions-access-control#public-agent).

## Configuración {#config}

`createAgentWebVitePlugin` de `@agent-native/core/vite` escribe estos archivos durante una compilación de producción. Añádelo a tu configuración de Vite con las páginas que deben leer los agentes:

```ts
// vite.config.ts
import { defineConfig } from "vite";
import { createAgentWebVitePlugin } from "@agent-native/core/vite";

export default defineConfig({
  plugins: [
    // ...your existing plugins
    createAgentWebVitePlugin({
      siteName: "My Agent-Native App",
      siteUrl: "https://example.com",
      pages: [
        {
          path: "/pricing",
          title: "Pricing",
          description: "Plans and limits.",
          markdown: "Plans and limits.\n",
        },
      ],
      agentWeb: { crawlerPolicy: "discoverable-no-training" },
    }),
  ],
});
```

El plugin publica las páginas que indicas y nada más. No lee la configuración de acceso a rutas ni lee `agentWeb` de `package.json` a menos que se lo pases. Para mantener la configuración en `package.json` bajo `agent-native.workspaceApp.agentWeb`, pasa `agentWeb: agentWebConfigFromPackageJson(pkg)`, importado de `@agent-native/core/agent-web`.

| Opción          | Predeterminado                        | Qué hace                                                                                                                                                      |
| --------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `discoverable`  | Activado cuando `pages` no está vacío | `false` no escribe ningún archivo.                                                                                                                            |
| `llmsTxt`       | `true`                                | Escribe `/llms.txt` y `/llms-full.txt`.                                                                                                                       |
| `markdownTwins` | `true`                                | Escribe una copia `.md` de cada página que tenga `markdown`.                                                                                                  |
| `crawlerPolicy` | `"discoverable-no-training"`          | Define las reglas de `robots.txt`: `"discoverable-no-training"`, `"allow-all"` o `"disallow-all"`.                                                            |
| `crawlers`      | Ninguno                               | Anula categorías de rastreadores individuales: `training`, `search`, `userTriggered`, `codingAgents` o `autonomousAgents`, cada una `"allow"` o `"disallow"`. |

La política de rastreo predeterminada es "descubrible, no entrenable": se permiten la búsqueda, la recuperación iniciada por el usuario, los agentes de programación y los agentes de navegación autónomos; los rastreadores de entrenamiento no se permiten.

`jsonLd`, `publicAgentCard` y `publicMcp` se aceptan, pero todavía nada los lee. Para JSON-LD, renderiza tú mismo `buildBaseJsonLd` y `buildPageJsonLd` de `@agent-native/core/agent-web` en tus páginas.

## Ruta fuente de la verdad {#route-source}

La lista de páginas es la fuente de verdad: los agentes reciben las páginas que pasas, y solo esas. Créala a partir de páginas que ya son públicas:

- En una app pública, todas las rutas excepto `protectedPaths`.
- En una app interna, solo `publicPaths`.
- Páginas públicas de compartir y de formularios que los agentes deban poder leer.
- Nunca datos privados enviados, paneles autenticados ni estado de usuario u organización, aunque una página cercana sea pública.

Para partir de tu configuración de acceso, `deriveAgentWebPublicRoutes` de `@agent-native/core/agent-web` recibe `audience`, `publicPaths`, `protectedPaths` y `routes` de tu app y devuelve las rutas que esa configuración hace públicas. Cada página sigue necesitando su propio título y su propio Markdown.

Esto mantiene naturales las aplicaciones mixtas. Una aplicación de formularios puede exponer una página de formulario pública y mantener los envíos privados. Una aplicación de contenido puede exponer publicaciones publicadas y mantener la privacidad del editor. Un sitio de documentos puede exponer todo excepto las herramientas de administración.

## Las páginas públicas no son herramientas públicas {#public-tools}

El acceso a la página pública y el acceso a las herramientas públicas están separados. Que una ruta sea pública únicamente significa que los agentes pueden leer esa ruta como HTML, Markdown, entradas de mapas del sitio, entradas de llms y datos estructurados.

<Callout id="doc-block-s50w8y" tone="warning">

**Una página pública no es una herramienta pública.** Hacer que una ruta sea rastreable nunca expone una acción. El acceso a herramientas requiere una activación explícita de `publicAgent.expose` en la acción.

</Callout>

Para exponer una acción a través de un protocolo de agente público, la acción debe optar por:

## Archivos en tiempo de compilación {#build-time}

Las utilidades de Framework en `@agent-native/core/agent-web` generan los archivos comunes a partir de una lista de páginas:

```ts
import {
  buildAgentWebStaticFiles,
  normalizeAgentWebConfig,
} from "@agent-native/core/agent-web";

const config = normalizeAgentWebConfig(
  { crawlerPolicy: "discoverable-no-training" },
  { hasPublicRoutes: true },
);

const files = buildAgentWebStaticFiles({
  siteName: "My Agent-Native App",
  siteUrl: "https://example.com",
  description: "Public docs for my app.",
  config,
  pages: [
    {
      path: "/docs",
      title: "Docs",
      description: "Start here.",
      markdown: "# Documentos\n\nStart aquí.\n",
      markdownPath: "/docs/getting-started.md",
      lastmod: new Date(),
    },
  ],
});
```

`createAgentWebVitePlugin` llama a `buildAgentWebStaticFiles` por ti y escribe los archivos en las carpetas que existan de entre `public`, `dist`, `dist/client`, `dist/server/public` y `build/client`. Con otra herramienta de compilación, llama a las utilidades directamente.

Ninguno de los dos responde a `Accept: text/markdown` en la URL propia de una página: la copia en Markdown solo está en su URL `.md`. Para responder a ese encabezado, añade una ruta de servidor que devuelva el Markdown de la página con los encabezados de `buildMarkdownResponseHeaders`, como hace el sitio de documentación. Sin esa ruta, la auditoría de abajo falla su comprobación de `Accept: text/markdown`.

Pasa `sitemapGroup` a `buildAgentWebStaticFiles` o `createAgentWebVitePlugin` para dividir un sitemap grande. La opción asigna cada página a una clave de grupo, como su idioma, y `sitemap.xml` pasa a ser un índice de sitemaps con un `sitemap-<group>.xml` por grupo.

## Auditar un sitio {#audit}

Utilice la auditoría CLI en un sitio implementado o en un servidor de producción local:

```bash
npx @agent-native/core@latest audit-agent-web --url https://www.agent-native.com
```

La auditoría comprueba:

- SSR-visible HTML.
- URL canónicos.
- JSON-LD.
- Política `robots.txt` y mapa del sitio absoluto URL.
- Entradas absolutas del mapa del sitio.
- `/llms.txt` y `/llms-full.txt`.
- Espejos Markdown.
- `Accept: text/markdown`.
- No se permiten bloqueos 401/403 accidentales para agentes de usuario de recuperación de agentes comunes.

La auditoría finaliza con un valor distinto de cero si falta una superficie pública requerida.
