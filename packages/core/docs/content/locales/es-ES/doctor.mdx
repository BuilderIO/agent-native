# Doctor

Las apps y los workspaces generados contienen código fuente que puede cambiarse mediante el flujo de desarrollo del repositorio, incluso por un frame de agente al que se hayan concedido intencionalmente herramientas de workspace y escritura. `agent-native doctor` examina el código fuente para verificar invariantes de seguridad críticos. Es de solo lectura: nunca edita el código, solo informa.

`agent-native doctor` comprueba problemas de seguridad y migración. `migration-manifest` encuentra imports incluidos en el `migration-manifest.json` instalado y no se puede desactivar. `feature-dependencies` detecta funciones configuradas cuyo paquete peer opcional no se puede resolver.

Ejecuta la comprobación previa de migración:

```bash
agent-native doctor --only migration-manifest
```

Previsualiza la actualización y el diff del codemod sin escribir archivos:

```bash
npx agent-native upgrade --codemods --dry-run
```

Aplica las reescrituras de imports compatibles:

```bash
npx agent-native upgrade --codemods
```

`--codemods` aplica las reescrituras compatibles de forma predeterminada; añade `--dry-run` para previsualizar sin escribir archivos. Revisa el diff y las advertencias antes de aplicar. `--yes` se acepta por compatibilidad y no cambia el comportamiento. `migration-manifest` no se puede desactivar. Las entradas `planned` solo son advertencias y no se reescriben. Las entradas activas son hallazgos; el codemod solo las reescribe si el export de destino está instalado. Los exports eliminados requieren una migración manual. Sigue la guía enlazada en el hallazgo o la [guía de migración de Core 0.198.0](/docs/upgrading-core-ui), que enumera `ts-morph` y los paquetes opcionales de funciones. `guardsRun` en la salida JSON enumera las guardas ejecutadas.

El CLI añade a cada app y workspace nuevo los comandos `pnpm doctor` y `pnpm agent-native:doctor`. Desde la raíz de un workspace, comprueba cada app en `apps/<name>`. Las builds fallan ante hallazgos de forma predeterminada; usa `failOnBuild: false` solo como excepción revisada.

Las entradas marcadas como `planned` solo se muestran como advertencias y no se reescriben. Las entradas activas son hallazgos; el codemod solo las reescribe cuando el export de destino está instalado.
