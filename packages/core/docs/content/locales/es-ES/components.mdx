# Componente API

Agent-Native incluye una barra lateral completa, pero la barra lateral no es el contrato. El
el contrato es el tiempo de ejecución: transmisión del chat, estado del hilo, actions, contexto,
adjuntos, selección de modelo, ejecuciones y sincronización respaldada por SQL. Usa la acción
componentes cuando puedas y desplegar una capa cuando necesites un producto personalizado UI.

Importar navegador UI desde subrutas de cliente enfocadas:

```tsx
import { AgentSidebar } from "@agent-native/core/client/agent-chat";
import { PromptComposer } from "@agent-native/core/client/composer";
import { AgentConversation } from "@agent-native/core/client/conversation";
import { usePresence } from "@agent-native/core/client/collab";
import { SharedRichEditor } from "@agent-native/core/client/editor";
import { ResourcesPanel } from "@agent-native/core/client/resources";
```

Evite importar componentes UI desde el paquete básico `@agent-native/core`. Usar
`@agent-native/core/client` o una subruta `@agent-native/core/client/*` enfocada
para que los paquetes elijan la entrada segura para el navegador.

Use `@agent-native/toolkit` para piezas reutilizables de construcción de aplicaciones que no forman parte del contrato fundacional del runtime: primitivas UI estilo shadcn, hooks compartidos, ayudantes simples de shell de aplicación y otros módulos para componer plantillas. Core conserva reexports de compatibilidad durante la transición.

Los paquetes reutilizables pueden importar módulos de Toolkit directamente:

```tsx
import { Button } from "@agent-native/toolkit/ui/button";
import { Toaster } from "@agent-native/toolkit/ui/sonner";
import { useToast } from "@agent-native/toolkit/hooks/use-toast";
import { useSetHeaderActions } from "@agent-native/toolkit/app-shell";
```

Dentro de las apps de plantilla, prefiera adaptadores locales de la app para que los equipos puedan sustituir primitivas una vez y hacer que cada superficie reutilizada de Toolkit use la implementación local:

```tsx
import { Button } from "@/components/ui/button";
import { useToast } from "@/hooks/use-toast";
```

## Inicio con prompt y bibliotecas de plantillas {#prompt-home}

`PromptHome`, `PromptHomeLibrary`, `TemplateLibraryGrid` y `TemplateLibraryCard` se exportan desde `@agent-native/toolkit/app-shell`. Comparten el espaciado, un compositor centrado de 700 px y una biblioteca adaptable de cuatro columnas. El contenedor de la app conserva el punto de referencia main. Las apps aportan datos reales, etiquetas traducidas, vistas previas, acciones y rutas.

`PromptHome` acepta `title`, `composer`, los opcionales `mobileToolbar`, `connection`, `quickActions` y `children` para la biblioteca. `PromptHomeLibrary` recibe `value` controlado (`templates` o `recent`), `onValueChange`, `labels`, `showRecent`, `templates` y los opcionales `recent`, `browseAll`, `recentActions`. Sin elementos recientes muestra plantillas sin una pestaña artificial. La app aporta un enlace real en `browseAll`. El espacio semántico `Tabs.headerActions` mantiene las acciones activas junto a las pestañas.

```tsx
import { PromptHome, PromptHomeLibrary } from "@agent-native/toolkit/app-shell";
import { Link } from "react-router";

<PromptHome
  title={labels.create}
  composer={composer}
  quickActions={quickActions}
>
  <PromptHomeLibrary
    value={tab}
    onValueChange={setTab}
    labels={labels.library}
    showRecent={hasOwnedWork}
    browseAll={<Link to="/templates">{labels.browseAll}</Link>}
    templates={templateGrid}
    recent={recentItems}
  />
</PromptHome>;
```

`TemplateLibraryGrid` acepta `items` tipados con `id`, `title`, `description` almacenada y `disabled` opcionales, además de `renderPreview`. Admite `selectedId`, `pendingId`, `disabled`, `loading`, `error`, `onRetry`, `empty` opcional y `labels` para carga, vacío y reintento. Se elige `onSelect(item, element)` o `renderLink(item, children)`, nunca ambos. La imagen y el título comparten un objetivo de activación. `renderActions` queda fuera del objetivo de activación, en línea junto al título y la descripción opcional. Las tarjetas comparten dimensiones fijas de vista previa y leyenda; la activación directa usa o copia la plantilla, mientras que Vista previa solo aparece en el menú de la leyenda. Los elementos cargados permanecen visibles tras un error de actualización. `TemplateLibraryCard` ofrece el mismo comportamiento para un `item`, con `preview` y los opcionales `actions`, `selected`, `pending`, `disabled`.

```tsx
import { TemplateLibraryGrid } from "@agent-native/toolkit/app-shell";

<TemplateLibraryGrid
  items={templates}
  labels={labels.grid}
  renderPreview={renderTemplatePreview}
  onSelect={selectTemplate}
  selectedId={selectedId}
  pendingId={pendingId}
  loading={loading}
  error={error}
  onRetry={reloadTemplates}
/>;
```

`TemplatePreviewDialog`, exportado desde el mismo punto de entrada, utiliza el `Dialog` semántico con `size="viewport"` de forma predeterminada o `size="large"`. Recibe `open`, `onOpenChange`, `title` y `children` renderizados por la aplicación; el encabezado no incluye una acción de uso. Las `thumbnails` opcionales contienen `{ id, title, preview, disabled? }` y requieren `selectedId` y `onSelectedIdChange`. La tira pasa a horizontal en pantallas estrechas y admite flechas, Home y End.

El tamaño `viewport` es un modal centrado con márgenes: 90dvh de alto, un máximo de 96rem de ancho y márgenes laterales de 1rem en móviles y 1.5rem en pantallas más anchas. Conserva el borde, el radio, la sombra y el fondo del diálogo estándar. Los menús de la leyenda aparecen al pasar el puntero sobre la tarjeta o con el foco del teclado en dispositivos compatibles y permanecen visibles en dispositivos táctiles; su espacio reservado no cambia.

Pasa `labels` localizadas (`close`, `loading`, `empty`, `retry`, `thumbnails`) y, opcionalmente, `loading`, `error`, `empty` y `onRetry` para estados de disponibilidad excluyentes. `initialFocusRef` y `restoreFocusRef` controlan el foco. Abre el visor desde el menú de la leyenda cuando termine de cerrarse; las lecturas, la cancelación, la autorización y el renderizado aislado seguro siguen siendo responsabilidad de la aplicación.

```tsx
import { TemplatePreviewDialog } from "@agent-native/toolkit/app-shell";

<TemplatePreviewDialog
  open={previewOpen}
  onOpenChange={setPreviewOpen}
  title={template.title}
  labels={labels.preview}
  loading={previewLoading}
  error={previewError}
  empty={!pages.length}
  onRetry={reloadPreview}
  restoreFocusRef={menuTriggerRef}
  thumbnails={pages.map((page) => ({
    id: page.id,
    title: page.title,
    preview: renderThumbnail(page),
  }))}
  selectedId={selectedPageId}
  onSelectedIdChange={setSelectedPageId}
>
  {renderSelectedPage(selectedPageId)}
</TemplatePreviewDialog>;
```

Los estilos de Toolkit incluyen la geometría compartida. `@agent-native/toolkit/app-shell/prompt-home.css` exporta la hoja de estilos específica. La unidad de extracción existente `toolkit/app-shell` incluye el diseño y esa hoja. La carga de datos, la autorización, la importación y el estado del compositor siguen siendo responsabilidad de la app.

`AgentChatRuntime` es el contrato de agente BYO para el shell de chat estándar. Pase
`runtime` a `<AssistantChat>` cuando un agente externo debe alimentar el
conversación mientras Agent-Native mantiene el compositor, la transcripción, las tarjetas de herramientas y
renderizado de widgets nativos. Los conectores de arriba son la superficie API; el tiempo de ejecución
Las formas de contratos y eventos se enseñan en
[Native Interfaz de chat — BYO agent runtimes](/docs/native-chat-ui#byo-agent-runtimes).
Si elige entre agentes sin cabeza, chat enriquecido, sidecar integrado y

La ruta personalizada más corta sigue siendo una superficie precableada:

```tsx
import { AgentChatSurface } from "@agent-native/core/client/chat";

export default function ChatRoute() {
  return <AgentChatSurface mode="page" className="h-screen" />;
}
```

Para Chrome personalizado en torno al tiempo de ejecución estándar:

```tsx
import { AssistantChat, useChatThreads } from "@agent-native/core/client/chat";

function CustomChat({ projectSlug }: { projectSlug: string }) {
  const threads = useChatThreads(undefined, projectSlug);
  const threadId = threads.activeThreadId ?? undefined;

  return (
    <section className="grid h-full grid-cols-[260px_1fr]">
      <ThreadList
        threads={threads.threads}
        activeThreadId={threadId}
        onSelect={threads.switchThread}
      />
      <AssistantChat threadId={threadId} />
    </section>
  );
}
```

Para un punto final de "traiga su propio agente", cree un `AgentChatRuntime` con uno de los
conectores de arriba y páselo a `<AssistantChat runtime={...} />`. Ver
[Native Interfaz de chat — BYO agent runtimes](/docs/native-chat-ui#byo-agent-runtimes)
para el uso del conector, el flujo de eventos normalizado y cuándo alcanzarlo
`createHttpAgentChatRuntime()` frente a un conector específico de protocolo.

## Campo de chat y compositor {#composer}

Usa `@agent-native/core/client/composer` cuando necesites el mismo campo de chat
que usa la barra lateral en una UI personalizada. `@agent-native/toolkit/composer`
ofrece la implementación portátil y sin integración de Tiptap y UI; para servicios del framework,
envuélvela con `ComposerRuntimeAdaptersProvider` y proporciona los servicios. Core es la capa ya conectada para adjuntos, menciones, habilidades, voz y selección de modelos.

| API                               | Usar cuando                                                                                                                                                                                          |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `<PromptComposer>`                | Necesita un campo de chat listo para enviar con archivos adjuntos, comandos de barra diagonal, referencias, manejo de texto pegado, persistencia de borradores, entrada de voz y semántica de envío. |
| `<AgentComposerFrame>`            | Quieres el shell visual estándar alrededor de un cuerpo de compositor personalizado.                                                                                                                 |
| `<TiptapComposer>`                | Necesita el campo de chat enriquecido de nivel más bajo. Debe renderizarse dentro de un tiempo de ejecución de asistente-ui `ThreadPrimitive.Root`/compositor.                                       |
| `buildPromptComposerSubmission()` | Necesita el mismo archivo adjunto y la normalización del texto pegado antes de llamar a su propio controlador de envío.                                                                              |
| `formatPromptWithAttachments()`   | Necesita representar los metadatos del archivo adjunto oculto en una cadena de mensaje.                                                                                                              |

La mayoría de los UI personalizados deben comenzar con `PromptComposer`:

```tsx
import { PromptComposer } from "@agent-native/core/client/composer";

<PromptComposer
  placeholder="Ask the agent..."
  onSubmit={async (text, files, references, options) => {
    await sendMessageToYourRuntime({ text, files, references, options });
  }}
/>;
```

Utilice `TiptapComposer` solo si ya está cableando primitivas de interfaz de usuario del asistente
tú mismo. Es el campo, no todo el tiempo de ejecución del chat.

### Contexto preparado en el compositor {#composer-context}

`PromptComposer` y `TiptapComposer` aceptan `submissionDisabled` para bloquear el envío sin impedir preparar el borrador, los archivos y el contexto. La falta de configuración del proveedor bloquea el envío, no la preparación. `disabled` sigue desactivando todo el compositor.

`PromptComposer`, `TiptapComposer` y `AgentKitComposer` aceptan `contextItems` y `contextMenuItems`. Las aplicaciones gestionan las lecturas de fuentes y las etiquetas traducidas.

Cada `AgentChatContextItem` tiene `key`, `title` y `context`. El campo opcional `status` es `ready`, `pending` o `error`. `statusMessage` explica los fallos. `onRemoveContextItem`, `onInspectContextItem` y `onRetryContextItem` reciben la clave. `removable: false` oculta la eliminación. Los elementos pendientes o fallidos bloquean el envío salvo que `blocksSubmission: false` los marque explícitamente como informativos.

El host puede preparar contexto ya autorizado y recibir una instantánea inmutable al enviar:

```tsx
<PromptComposer
  contextItems={contextItems}
  onRemoveContextItem={removeContext}
  onSubmit={(text, files, references, options) =>
    submitPrompt({
      text,
      files,
      references,
      contextItems: options.contextItems,
    })
  }
/>
```

Las fuentes de contexto registran `picker` en un `ComposerContextMenuItem`. `ComposerContextMenu` controla submenús conectados en cascada de shadcn/Radix, no paneles que sustituyen al anterior: la raíz ofrece subir archivos y después Añadir contexto → categorías del anfitrión → selectores de fuentes. Añadir contexto se omite si no hay entradas del anfitrión. Las flechas y Escape recorren la jerarquía. Volver dentro de un selector de enlaces solo regresa de los resultados a la entrada del enlace en el mismo submenú. El selector compartido controla búsqueda, filas, estados de carga, vacío y error, reintentos, paginación y entrada de enlaces. Las aplicaciones proporcionan datos autorizados y callbacks de selección, no su propio JSX de selector.

La configuración del selector acepta:

- `searchPlaceholder` y, opcionalmente, `emptyMessage` como textos localizados de la aplicación. `selectedIds` marca las filas seleccionadas. Cada elemento tiene `id`, `title` y, opcionalmente, `disabled` y `url`.
- O bien `items` locales con `loading`, `error` y `onRetry()` opcionales, o bien `load(request)` remoto. Los modos no se pueden combinar.
- `load(request)` recibe `search`, `page` empezando en uno, `cursor` y `url` opcionales, y un `AbortSignal`. Devuelve `{ items, hasMore?, nextCursor? }`. Los fallos deben rechazar la promesa, no devolver un resultado vacío.
- `onSelect(item, request)` prepara la fuente y puede ser asíncrono. Devolver `false` mantiene abierto el selector. Lanzar un error muestra la opción de reintentar. El `clearSelection` opcional proporciona un `label` localizado y un callback `onSelect()`.
- El `link` opcional proporciona textos localizados para `placeholder` y `submitLabel`. `validate(url)` puede devolver un mensaje de error. El formulario compartido gestiona la entrada del enlace y la navegación.
- `scopeKey` restablece todo el estado del selector cuando cambia la identidad o el ámbito de acceso. `refreshKey` invalida la consulta actual al cambiar un token de fuente/versión sin restablecer la URL. Cambiar la búsqueda vuelve a la página uno. Las aplicaciones actualizan los tokens cuando el agente modifica los datos de origen.

Una aplicación puede registrar opciones ya autorizadas. Aquí `labels` contiene textos localizados y `stageReference` actualiza el contexto preparado del anfitrión:

```tsx
import type { ComposerContextMenuItem } from "@agent-native/core/client/composer";
import { Link } from "react-router";

const contextMenuItems: ComposerContextMenuItem[] = [
  {
    id: "references",
    label: labels.references,
    picker: {
      searchPlaceholder: labels.searchReferences,
      items: authorizedReferences,
      selectedIds,
      onSelect: stageReference,
      footerAction: {
        label: labels.createReference,
        renderLink: (children) => (
          <Link to={createReferenceHref}>{children}</Link>
        ),
      },
    },
  },
];
```

Para una fuente con búsqueda o enlaces, la aplicación proporciona un cargador autenticado. `loadAuthorizedReferences` implementa el contrato de solicitud/resultado anterior, conserva los controles de acceso y transmite la señal de cancelación a su función cliente:

```tsx
const contextMenuItems: ComposerContextMenuItem[] = [
  {
    id: "references",
    label: labels.references,
    picker: {
      searchPlaceholder: labels.searchReferences,
      scopeKey: accessScope,
      refreshKey: sourceVersion,
      load: loadAuthorizedReferences,
      presentation: {
        type: "dialog",
        mode: "multiple",
        onAttach: stageReferences,
      },
      link: {
        label: labels.referenceUrl,
        placeholder: labels.referenceLink,
        submitLabel: labels.findReferences,
        validate: validateReferenceLink,
      },
    },
  },
];
```

`presentation` usa `"submenu"` de forma predeterminada. Con `{ type: "dialog", mode: "multiple", onAttach }`, un elemento normal del menú abre un diálogo compartido cuyo título es la etiqueta del elemento. `link.label` etiqueta el campo URL. Continuar valida una URL HTTP(S) sin credenciales antes de cargar resultados. Una entrada vacía o no válida nunca llama al proveedor. `link.validate()` permite aplicar reglas del proveedor. Los botones del diálogo usan etiquetas compartidas traducidas, no `link.submitLabel`.

`presentation.onAttach(items, request)` recibe un único lote congelado de elementos recién marcados. Este modo excluye `onSelect`. La selección se conserva al buscar o cambiar de página. Los `selectedIds` aparecen marcados y deshabilitados, y se excluyen del lote. Los identificadores deben distinguir archivos de origen diferentes. Devolver `false` mantiene el diálogo abierto. Un rechazo muestra un error que permite reintentar. Cancelar o cambiar `scopeKey` aborta el trabajo pendiente e ignora respuestas tardías. Al volver a abrir se restablece la URL. El anfitrión debe respetar `request.signal` antes de confirmar cambios de callbacks asíncronos. `footerAction` y `clearSelection` siguen siendo controles del submenú.

`{ type: "dialog", mode: "url" }` usa Adjuntar directamente, sin cargar una lista de resultados. `onSelect(item, request)` recibe `{ id: url, title: url, url }` y `request.url`:

```tsx
const websiteContextItem: ComposerContextMenuItem = {
  id: "website",
  label: labels.attachWebsite,
  picker: {
    searchPlaceholder: labels.searchReferences,
    scopeKey: accessScope,
    presentation: { type: "dialog", mode: "url" },
    link: {
      label: labels.websiteUrl,
      placeholder: labels.websiteUrl,
      submitLabel: labels.attach,
      validate: validateWebsiteUrl,
    },
    onSelect: stageWebsiteReference,
  },
};
```

`readComposerWebsiteSource(url, extractCallback)` de `@agent-native/core/server` crea referencias web mediante el extractor del anfitrión que ya protege frente a SSRF. `composerSourceRequestSchema` de `@agent-native/core/shared` acepta `source: "website"` solo con `operation: "read"` y una `url` HTTP(S) sin credenciales de hasta 2048 caracteres. La función devuelve `{ id, title, url, context }` con un identificador estable derivado del hash de la URL y hasta 20 000 caracteres de contexto. El estado de extracción, las advertencias, la procedencia del renderizado y cualquier marcador `[truncated]` permanecen en el texto del contexto. La extracción parcial se indica explícitamente. Una extracción fallida o la ausencia de `designMd` utilizable produce un fallo tipado. La autorización sigue correspondiendo a la [acción](/docs/actions-overview) del anfitrión.

Las entradas de selector no definen además `render` ni `onSelect` a nivel de entrada. Las categorías usan `children`. La raíz y cada categoría conservan un campo de búsqueda en la cabecera. Las categorías pueden proporcionar un `searchPlaceholder` localizado; si no lo hacen, usan el texto compartido de búsqueda de contexto. `picker.searchPlaceholder` etiqueta el campo de búsqueda de la lista de fuentes. El registro no concede acceso a la fuente. El selector compartido ignora las respuestas de carga sustituidas por solicitudes más recientes.

El `footerAction` opcional permanece debajo de los resultados incluso durante la carga, los errores o una lista vacía. Acepta un `label` localizado, `icon` y `disabled` opcionales, y bien `onSelect()` o bien `renderLink(children)`. Use un callback para un modal u otro flujo con estado: `false` mantiene el menú abierto, `true` o `void` lo cierra, y un rechazo muestra un error con reintento. Para navegación simple, `renderLink` devuelve un `Link` real de React Router o un enlace HTML; el menú compartido proporciona la fila mediante `asChild`, conservando su `href` y la navegación del navegador. Conecte flujos existentes y autorizados, no acciones ficticias.

Al pasar `addAttachment` a `ComposerContextMenu`, la acción estándar de carga aparece primero y conserva el callback de archivos del anfitrión.

`PromptComposer` y `AgentKitComposer` aceptan `attachmentAdapter`, con el tipo público `AttachmentAdapter` de `@assistant-ui/react`. Proporcione mediante este adaptador las reglas del anfitrión para archivos aceptados, validación de tamaño y preparación; omítalo para conservar los adaptadores predeterminados. El compositor compartido sigue controlando la carga, el selector de archivos, el selector de contexto y las fichas de adjuntos. No sustituya estos controles para personalizar la preparación de archivos.

`inlineTextAttachments` es `true` por defecto en `PromptComposer` y `AgentKitComposer`. Use `false` cuando el anfitrión ya extraiga los archivos de texto ordinarios: el compositor entrega los archivos originales al anfitrión sin leer ni añadir su contenido al prompt. Los adjuntos sintéticos de texto pegado siguen convirtiéndose en texto del prompt. Esta opción no cambia los archivos admitidos ni los controles compartidos.

```tsx
<PromptComposer
  contextItems={contextItems}
  contextMenuItems={contextMenuItems}
  attachmentAdapter={hostAttachmentAdapter}
  onRetryContextItem={retryContext}
  onSubmit={submitPrompt}
/>
```

La instantánea distingue `undefined` de un array vacío explícito. Rechaza más de 32 elementos o 64 KiB de datos UTF-8 serializados sin truncarlos. Se espera a `AgentKitComposer.beforeSend(submission)` antes de enviar o encolar. Recibe contexto, referencias, archivos cargados y opciones inmutables. Un rechazo conserva el borrador. El contexto se incluye en el texto y los metadatos.

`composerRef.current.submitWithText(text)` usa la misma ruta con los archivos y el modelo actuales sin sustituir primero el editor. Devuelve `true` tras la aceptación o `false` si se bloquea o rechaza. Seleccionar contexto no concede acceso. Las acciones autenticadas deben volver a comprobar el acceso a las fuentes.

| API                                                                   | Usar cuando                                                                                        |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `<ResourcesPanel>`                                                    | Quieres la pestaña Espacio de trabajo completa como una página, un cajón o un panel personalizado. |
| `<ResourceTree>`                                                      | Quiere representar su propio navegador de recursos en torno a los datos del marco.                 |
| `<ResourceEditor>`                                                    | Quieres el editor de marco para un recurso seleccionado.                                           |
| `useResourceTree()`                                                   | Necesita un árbol con ámbito para recursos personales, compartidos o de espacio de trabajo.        |
| `useResource()`                                                       | Necesita el contenido y los metadatos de un recurso seleccionado.                                  |
| `useCreateResource()` / `useUpdateResource()` / `useDeleteResource()` | Necesita controles personalizados en torno al ciclo de vida de los recursos.                       |

El panel completo no necesita accesorios:

```tsx

```

Para Chrome de recursos personalizados, mantenga los ganchos y las primitivas juntos:

```tsx
import { useState } from "react";
import {
  ResourceEditor,
  ResourceTree,
  useResource,
  useResourceTree,
  useUpdateResource,
} from "@agent-native/core/client/resources";

function WorkspaceResources() {
  const tree = useResourceTree("workspace");
  const updateResource = useUpdateResource();
  const [selectedId, setSelectedId] = useState<string | null>(null);
  const resource = useResource(selectedId);

  return (
    <div className="grid h-full grid-cols-[260px_1fr]">
      <ResourceTree
        tree={tree.data ?? []}
        selectedId={selectedId}
        onSelect={(item) => setSelectedId(item.id)}
        onCreateFile={() => {}}
        onCreateFolder={() => {}}
        onDelete={() => {}}
        onRename={() => {}}
        onDrop={() => {}}
      />
      {resource.data ? (
        <ResourceEditor
          resource={resource.data}
          onSave={(content) =>
            updateResource.mutate({ id: resource.data.id, content })
          }
        />
      ) : null}
    </div>
  );
}
```

## Completación de texto única {#one-off-text-completion}

Si realmente necesitas entrada y salida de texto sin formato, mantenlo en el lado del servidor y úsalo
`completeText()` de `@agent-native/core/server`. Envuelva el uso de cara al usuario en un
acción para que UI y el agente compartan la misma capacidad.

<Callout id="doc-block-11d6llv" tone="warning">

`completeText()` is the escape hatch, not the default. Reach for it only for true text-in/text-out (a label, a one-line rewrite). Anything needing tools, state, auditability, or steering belongs in an action plus `sendToAgentChat({ background: true })`.

</Callout>

```ts
import { defineAction } from "@agent-native/core/action";
import { completeText } from "@agent-native/core/server";
import { z } from "zod";

export default defineAction({
  description: "Classify a short message",
  schema: z.object({ body: z.string() }),
  run: async ({ body }) => {
    const result = await completeText({
      systemPrompt: "Return exactly one label.",
      input: body,
      maxOutputTokens: 12,
      temperature: 0,
    });
    return { label: result.text.trim() };
  },
});
```

Utilice `sendToAgentChat({ background: true, openSidebar: false })` en su lugar cuando
el trabajo necesita herramientas, estado, auditabilidad, dirección del usuario o varios pasos
razonamiento.
