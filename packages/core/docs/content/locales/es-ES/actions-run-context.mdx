# Contexto de ejecución

`run` recibe un segundo argumento opcional, `ctx`, que lleva la identidad resuelta de la petición y la superficie que invocó la acción. Léelo en lugar de llamar a mano a `getRequestUserEmail()` / `getRequestOrgId()`, y pasa el `ctx` completo al seguimiento:

```ts
export default defineAction({
  description: "Log an audit entry for the current request.",
  schema: z.object({ event: z.string() }),
  run: async (args, ctx) => {
    // ctx is undefined-safe: a 1-arg `run(args)` is still valid.
    const actor = ctx?.userEmail ?? "system";
    if (ctx?.caller === "frontend") {
      // tighter rules for browser-initiated calls, looser for "tool"/"cli"
    }
    await db.insert(audit).values({
      actor,
      orgId: ctx?.orgId ?? null,
      source: ctx?.caller ?? "unknown",
      event: args.event,
    });
    return { ok: true };
  },
});
```

La mayoría de las acciones solo llegan a leer `ctx?.userEmail` y `ctx?.orgId`, el [alcance de control de acceso](/docs/actions-access-control#access-control) usado en casi cualquier acción real. El resto de esta página cubre preocupaciones transversales como el seguimiento y la atribución de automatizaciones, que necesitan menos acciones.

## El argumento `ctx` {#ctx}

`ctx` lleva dos tipos de información: la identidad resuelta de la petición (`userEmail`, `orgId`), presente en casi todas las llamadas, y metadatos sobre la superficie que invocó la acción (`caller`, más campos específicos de superficie como `threadId` o `automation` que solo se rellenan para ciertos invocadores). `run()` se mantiene retrocompatible: los manejadores existentes de un solo argumento y los que solo desestructuran `{ send }` siguen funcionando sin cambios.

### La unión `caller` {#caller}

`caller` es la unión `"tool" | "http" | "frontend" | "cli" | "mcp" | "a2a" | "automation"`:

| `caller`       | Se establece cuando…                                                                                                                                                     |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `"tool"`       | El bucle del agente dentro de la app, un subagente o equipo de agentes, o una delegación A2A entre apps en lenguaje natural, que impulsa el mismo bucle del agente, así que sus llamadas a herramientas son `"tool"`. |
| `"frontend"`   | Una llamada desde el navegador mediante `useActionMutation()`, `useActionQuery()` o `callAction()` (etiquetada con la cabecera `X-Agent-Native-Frontend: 1`).             |
| `"http"`       | Un `POST` o `GET` programático simple a `/_agent-native/actions/<name>` sin la marca de frontend.                                                                        |
| `"cli"`        | `pnpm action <name>` (el ejecutor de la CLI).                                                                                                                             |
| `"mcp"`        | Un agente externo a través del endpoint `tools/call` de MCP.                                                                                                             |
| `"a2a"`        | Una llamada HTTP directa a `/_agent-native/actions/<name>` que lleva un token de delegación A2A firmado. Es un despacho entre apps expuesto explícitamente, distinto de la ruta `"tool"` en lenguaje natural de arriba. |
| `"automation"` | Una automatización activada por evento, despachada desde un disparador de workspace almacenado. `ctx.automation` lleva la procedencia del disparador. Consulta [Automatizaciones](/docs/automations). |
