# Koyeb

<Badge label="Beta" color="orange" icon="rocket" />

Koyeb aloja tu aplicación como un servicio web, así que no hay ningún servidor que configurar ni mantener en ejecución.
Koyeb ejecuta el mismo servidor Node.js que se describe en la
[guía de Node.js](/docs/node-js), lo compila desde tu repositorio de GitHub y le da
a la aplicación una dirección pública con HTTPS.

Esta guía explica cómo implementar una aplicación independiente desde cero. Vas a
crear la aplicación y subirla a GitHub, darle una base de datos de producción
y un secreto de autenticación, preparar la base de datos y, después, crear un servicio web de Koyeb
que la compile y la ejecute.

<Callout tone="info">

Se requiere Node.js `22.22+`.

</Callout>

También necesitas una cuenta de Koyeb y un repositorio de GitHub.
Ejecuta los comandos de esta guía en tu propio equipo. Koyeb compila y ejecuta la
aplicación desde tu repositorio.

## Paso 1: Crea la aplicación {#step-1-create-the-app}

Crea tu nueva aplicación independiente. El siguiente ejemplo crea una aplicación a partir de la plantilla Chat,
pero puedes empezar desde cualquier plantilla. Entra en la carpeta de la aplicación e
instala sus dependencias. `corepack enable` activa la versión de `pnpm` que la aplicación
espera, así que no necesitas instalar `pnpm` por tu cuenta.

```bash
npx --yes @agent-native/core@latest create my-app --standalone --template chat

cd my-app

corepack enable

pnpm install
```

Si quieres, reemplaza `my-app` por el nombre de tu aplicación. El resto de esta guía
supone que estás dentro de la carpeta de la aplicación.

Koyeb compila la aplicación desde GitHub, así que sube la carpeta de la aplicación a un nuevo
repositorio de GitHub antes de continuar. Incluye también el archivo `pnpm-lock.yaml`
en el commit. Koyeb lo usa, junto con el campo `packageManager` de `package.json`, para instalar
la aplicación con `pnpm`. También lee la versión de Node.js del campo `engines`
de `package.json`. Una aplicación nueva ya define ambos campos.

## Paso 2: Configura los secretos del entorno {#step-2-configure-environment-secrets}

La aplicación lee su configuración de producción desde variables de entorno:

| Variable             | Obligatoria | Propósito                                                                      |
| -------------------- | ----------- | ------------------------------------------------------------------------------ |
| `DATABASE_URL`       | Sí          | Conecta la aplicación con su base de datos PostgreSQL                          |
| `BETTER_AUTH_SECRET` | Sí          | Firma las sesiones de los usuarios                                             |
| `BETTER_AUTH_URL`    | No          | Define la dirección pública que usan las personas para acceder a tu aplicación |

Las exportaciones siguientes hacen que los comandos posteriores funcionen en esta terminal. Antes de
implementar, guarda estas mismas variables en la configuración del entorno del proyecto o servicio de tu host.
El paso 4 muestra cómo guardarlas en Koyeb.

### URL de la base de datos {#database-url}

Durante el desarrollo local, la aplicación guarda los datos en una base de datos local cuando
`DATABASE_URL` no está definida. Una aplicación implementada necesita una base de datos PostgreSQL real que
conserve sus datos entre implementaciones. Koyeb reemplaza los archivos del servicio en cada
implementación y reinicio, así que la base de datos debe estar fuera del servicio web. Copia la
cadena de conexión de tu proveedor y expórtala:

```bash
export DATABASE_URL='your-postgres-url-string'
```

Las [guías de proveedores de bases de datos](/docs/neon) muestran dónde encontrar la cadena de conexión
de cada proveedor.

<Callout tone="warning">

Elige un proveedor de PostgreSQL persistente, como Neon, Supabase o Amazon RDS.

</Callout>

### Secreto de autenticación {#auth-secret}

Genéralo una sola vez y mantenlo igual en todas las implementaciones.

La aplicación usa `BETTER_AUTH_SECRET` para firmar las sesiones de los usuarios. Si cambia, se cierra la sesión de
todos los usuarios que la tenían iniciada. El siguiente comando genera un valor aleatorio:

```bash
export BETTER_AUTH_SECRET="$(openssl rand -hex 32)"
```

Guarda el valor generado en un lugar seguro, como un gestor de contraseñas. Usa el
mismo valor cada vez que implementes.

### URL pública {#public-url}

Es opcional. Defínela cuando uses un dominio personalizado, un proxy inverso o un flujo de autenticación u OAuth
que necesite un origen público fijo.

`BETTER_AUTH_URL` es la dirección pública que usan las personas para acceder a tu aplicación. Sin
ella, la aplicación deduce su dirección a partir de cada solicitud entrante. Eso suele
funcionar bien con la dirección que te da Koyeb, pero defínela cuando conectes un dominio
personalizado para que los enlaces de inicio de sesión y las redirecciones de OAuth usen ese dominio.

```bash
export BETTER_AUTH_URL='https://your-domain.example'
```

## Paso 3: Ejecuta las migraciones {#step-3-migrate}

Las migraciones crean y actualizan las tablas que la aplicación necesita en tu base de datos. Ejecuta
esto antes de la primera implementación:

```bash
pnpm migrate:production
```

El comando se ejecuta en tu equipo y se conecta a la base de datos de producción con
la `DATABASE_URL` que exportaste en el paso 2. Vuelve a ejecutarlo después de actualizar la
aplicación y antes de implementar la nueva versión.

## Paso 4: Crea el servicio web {#step-4-create-the-web-service}

En el panel de control de Koyeb, crea un nuevo **Web Service**, elige **GitHub** como
método de implementación y selecciona el repositorio y la rama del paso 1. Mantén
el compilador **Buildpack** y, después, reemplaza los comandos de compilación y ejecución por estos
valores:

| Configuración | Valor                           |
| ------------- | ------------------------------- |
| Build command | `NITRO_PRESET=koyeb pnpm build` |
| Run command   | `node .output/server/index.mjs` |

`NITRO_PRESET=koyeb` compila el mismo servidor Node.js que la guía de Node.js, configurado
para servir sus propios archivos estáticos. El comando de ejecución inicia ese servidor. Koyeb
expone el puerto `8000` de forma predeterminada y define la variable de entorno `PORT` con ese
valor, y el servidor lee `PORT` automáticamente, así que no necesitas cambiar
la configuración del puerto.

En **Environment variables**, agrega `DATABASE_URL` y `BETTER_AUTH_SECRET`.
Para valores como estos, Koyeb recomienda guardar cada uno como un **Secret** y
hacer referencia a él desde la variable. Por ejemplo, guarda la cadena de conexión como un
Secret llamado `DATABASE_URL` y, después, define el valor de la variable como
`{{ secret.DATABASE_URL }}`. Si defines `BETTER_AUTH_URL`, agrégala de la misma forma.

## Paso 5: Implementa {#step-5-deploy}

<Steps>

### Elige un tipo de instancia

Elige el tipo de instancia del servicio web. El tipo de instancia Free sirve para
probar la aplicación. Elige un tipo de instancia de pago si la aplicación necesita responder
de inmediato.

### Crea el servicio web

Ponle nombre al servicio y a la aplicación y, después, implementa. Koyeb compila la aplicación desde tu
repositorio y la inicia. La primera compilación tarda unos minutos, y puedes
seguirla en los registros de compilación y de ejecución del servicio.

### Abre la aplicación

Cuando termina la implementación, el panel de control muestra la dirección de la aplicación, que termina
en `koyeb.app`. Ábrela y crea la primera cuenta.

</Steps>

En el tipo de instancia Free, Koyeb reduce el servicio a cero después de una hora
sin tráfico. La siguiente visita espera entonces mientras el servicio vuelve a iniciarse. Cada
organización puede ejecutar una instancia Free.

## Implementa actualizaciones {#deploy-updates}

Koyeb vuelve a implementar la aplicación cada vez que subes cambios a la rama que elegiste en el paso 4. Para
publicar una nueva versión, ejecuta primero las migraciones y después sube los cambios:

```bash
pnpm migrate:production

git push
```

La configuración del servicio y las variables guardadas se mantienen, así que no necesitas
repetir el paso 4.
