# Definir acciones

Toda acción empieza con una llamada a `defineAction()`. Agrupa una descripción para el agente, un esquema que valida la entrada y una función `run` que hace el trabajo, de modo que la UI y el agente llaman exactamente al mismo código.

## Opciones de esquema {#schemas}

`schema` acepta cualquier librería compatible con [Standard Schema](https://standardschema.dev):

- **Zod** (v4): la opción más común, con la mejor inferencia de tipos y conversión automática a JSON Schema.
- **Valibot**: una buena opción cuando el tamaño del bundle importa.
- **ArkType**: una buena opción si prefieres su sintaxis.

El esquema cumple dos funciones. Se convierte en JSON Schema para la definición de herramienta de la API de Claude, y valida la entrada en tiempo de ejecución antes de que se dispare `run()`. La entrada inválida nunca llega a tu manejador.

## Validar el valor de retorno {#output-schema}

`schema` valida las _entradas_. Para validar también lo que **devuelve** una acción, pasa un `outputSchema` (cualquier esquema compatible con Standard Schema: Zod, Valibot, ArkType, la misma superficie que `schema`). El framework valida la entrada antes de `run()` y valida el resultado después de que `run()` se resuelva.

```ts
export default defineAction({
  description: "Summarize a thread.",
  schema: z.object({ threadId: z.string() }),
  outputSchema: z.object({
    summary: z.string(),
    messageCount: z.number(),
  }),
  outputErrorStrategy: "warn", // default
  run: async ({ threadId }) => {
    /* ...returns { summary, messageCount } ... */
  },
});
```

`outputErrorStrategy` controla qué ocurre ante una discrepancia:

| Estrategia   | Comportamiento ante una discrepancia                                                                                      |
| ------------ | ------------------------------------------------------------------------------------------------------------------------- |
| `"warn"`     | **Predeterminado.** Hace `console.warn` de los problemas y devuelve el resultado **original** sin cambios. No rompe nada. |
| `"strict"`   | Lanza un error claro, para que un bug en la acción sea fácil de notar.                                                    |
| `"fallback"` | Devuelve el valor `outputFallback` proporcionado en lugar del resultado inválido.                                         |

Cuando `run()` tiene éxito, el framework devuelve el valor validado, así que cualquier valor por defecto o coerción de `outputSchema` surte efecto, igual que ocurre con la entrada. Cuando no pasas un `outputSchema`, el valor de retorno queda sin cambios.

## Configuración HTTP {#http}

Por defecto, cada acción se expone como `POST /_agent-native/actions/<name>`. Sobrescríbelo con la opción `http`:

```ts
export default defineAction({
  description: "Get details for a lead.",
  schema: z.object({ leadId: z.string() }),
  http: { method: "GET" },
  run: async ({ leadId }) => {
    return await db.select().from(leads).where(eq(leads.id, leadId));
  },
});
```

Para una acción `GET`, `leadId` se pasa como parámetro de consulta: `/_agent-native/actions/get-lead?leadId=abc`.

POST es el valor por defecto, y `http: { method: "GET" }` la convierte en GET. Los hooks de React y `callAction()` siempre llaman a esta ruta por nombre, sin importar ninguna sobrescritura de `http.path`. Los sistemas externos pueden llamar a la misma ruta con un bearer token de larga duración. Consulta [API HTTP](/docs/http-api).

</Endpoint>

- **`http: { method: "GET" | "POST" | "PUT" | "DELETE" }`**: por defecto es `POST`. Las acciones `GET` se marcan automáticamente como `readOnly`, así que una llamada exitosa no dispara un refresco por sondeo de la UI.
- **`http: { path: "..." }`**: sobrescribe la URL montada bajo `/_agent-native/actions/`. Por defecto es el nombre del archivo. Esta sobrescritura solo cambia la URL para invocadores HTTP directos. `useActionQuery()`, `useActionMutation()` y `callAction()` siempre llaman a `/_agent-native/actions/<name>`, sin importar esta sobrescritura, así que sobrescribir la ruta hace que esos hooks devuelvan 404. Usa una sobrescritura de ruta solo para invocadores HTTP externos. Ten en cuenta también que los segmentos de ruta `:param` en la ruta sobrescrita no se analizan como argumentos de `run()`. Solo se analizan los parámetros de query string y los campos del cuerpo JSON.
- **`http: false`**: desactiva por completo el endpoint HTTP. Solo el agente y la CLI pueden llamar a la acción.
- **`readOnly: true`**: omite explícitamente el refresco por sondeo, incluso para acciones POST que no mutan nada. Esto no es control de acceso. No restringe quién puede llamar a la acción, y no afecta a `useActionQuery()`, `useActionMutation()` ni a ningún hook de cliente. Sus únicos efectos son suprimir el evento de refresco posterior a la llamada y excluir la acción de la auditoría de escritura. Para ocultar una acción del modelo, usa `agentTool: false`. Para controlar quién puede llamarla, usa las opciones de autenticación y acceso en [Acceso y autorización](/docs/actions-access-control).
- **`parallelSafe: true`**: permite que una acción mutante se ejecute al mismo tiempo que otras llamadas a herramientas del mismo turno. Actívalo solo cuando la acción sea segura para ejecutarse de forma concurrente y no dependa del orden. Las acciones mutantes se serializan por defecto.

## Mantén pequeña la superficie de acciones {#small-surface}

Cada acción que el agente puede ver ocupa una plaza en la lista de herramientas del modelo, y una lista larga y solapada le dificulta al modelo elegir la herramienta correcta. Diseña la superficie de acciones como una API que mantienes, no como una acción por cada botón de la UI:

- Prefiere **una única acción `update` de estilo CRUD** que reciba un parche de campos opcionales, en lugar de muchas acciones por campo como `update-name`, `update-order` y `update-color`. El invocador solo envía los campos que cambiaron.
- Antes de añadir una nueva acción de lectura para cada consulta o filtro, considera primero una opción más general: el [trío de API de proveedor](/docs/template-dispatch-vault-integrations#provider-api) (`provider-api-catalog`, `provider-api-docs` y `provider-api-request`) para datos de proveedores, o la herramienta de desarrollo `db-query` para datos de la app.
- Marca las acciones solo de UI o programáticas como [`agentTool: false`](/docs/actions-access-control#agent-tool). Siguen siendo invocables desde el frontend o por HTTP, sin ocupar una plaza en la lista de herramientas del modelo.
- Elimina u oculta las acciones que la UI ya no usa, en lugar de dejarlas expuestas al modelo.

El repo incluye un ayudante consultivo, `node scripts/audit-template-actions.mjs [template ...]` (alias `pnpm actions:audit`). Escanea la carpeta `actions/` de una plantilla y señala acciones que la UI puede haber dejado de usar, junto con grupos de acciones por campo que podrían combinarse en una sola. Siempre termina con código 0 y nunca hace fallar el CI, y sus heurísticas son conservadoras, así que trata su salida como una sugerencia, no como un error.
