# Telemetría

Las herramientas de línea de comandos `@agent-native/core` y `@agent-native/skills` recopilan datos de uso anónimos. Nos muestran qué partes de la CLI funcionan y dónde se atasca la gente, para saber qué arreglar.

Nada de esto te identifica a ti, a tu proyecto ni a tu código, y puedes desactivarlo con un comando. Esta página cubre las dos CLI y enumera todo lo que pueden enviar. La analítica dentro de una app que construyes es una decisión aparte que configuras tú; consulta [Seguimiento](/docs/tracking).

## Desactivarlo {#turn-it-off}

```bash
npx @agent-native/core telemetry disable
```

Esto cubre las dos CLI en este equipo. También detiene los informes de fallos.

| Comando                                    | Qué hace                                                        |
| ------------------------------------------ | --------------------------------------------------------------- |
| `npx @agent-native/core telemetry status`  | Muestra si la telemetría está activa y qué ajuste la desactivó. |
| `npx @agent-native/core telemetry disable` | Desactiva la telemetría en este equipo.                         |
| `npx @agent-native/core telemetry enable`  | La vuelve a activar.                                            |
| `npx @agent-native/core telemetry reset`   | Sustituye el ID aleatorio de este equipo por uno nuevo.         |

El ajuste se guarda en `~/.agent-native/telemetry.json`, junto al ID aleatorio en `~/.agent-native/installation-id`.

También puedes desactivarla con cualquiera de estas variables de entorno, que tienen prioridad sobre el ajuste. Úsalas en CI o en un perfil de shell compartido:

```bash
DO_NOT_TRACK=1
AGENT_NATIVE_TELEMETRY_DISABLED=1
```

## Ver qué enviaría un comando {#see-what-a-command-would-send}

Define `AGENT_NATIVE_TELEMETRY_DEBUG=1` para imprimir cada evento en stderr, cada uno en una línea que empieza por `[telemetry]`, sin enviar nada. Funciona también con la telemetría desactivada y no crea ningún ID de equipo.

```bash
AGENT_NATIVE_TELEMETRY_DEBUG=1 npx @agent-native/core --version
```

## El aviso {#the-notice}

La primera vez que un comando fuera a enviar algo en un equipo, imprime esto en stderr:

```text
▶ Agent-Native collects anonymous usage data.
  It shows us which parts of the CLI work and where people get stuck.
  Run "npx @agent-native/core telemetry disable" to opt out.
  https://www.agent-native.com/docs/telemetry
```

Se imprime una vez por equipo. No se imprime en CI ni con la telemetría desactivada. Las ejecuciones de CI siguen enviando eventos salvo que esté definida una de las variables anteriores, y van marcadas con `ci`.

## Qué se envía {#what-is-sent}

Los eventos van al servicio de analítica propio de Agent-Native en `analytics.agent-native.com`, con una clave de solo escritura que es pública en el código fuente de la CLI. El envío nunca retrasa un comando: se abandona al poco tiempo si la red va lenta.

Cada evento tiene un nombre, una marca de tiempo, el ID del equipo y el ID de la ejecución, además de estas propiedades. La prueba de `packages/core/src/cli/telemetry.spec.ts` falla si a la versión en inglés de esta página le falta una propiedad que la CLI pueda enviar.

### En cada evento {#on-every-event}

| Propiedad     | Qué es                                                                                                             |
| ------------- | ------------------------------------------------------------------------------------------------------------------ |
| `cli`         | Qué CLI lo envió: `core` o `skills-installer`.                                                                     |
| `cliVersion`  | La versión de la CLI.                                                                                              |
| `command`     | El nombre del comando, como `dev`. Lo que no sea un comando, como una errata o un prompt, se envía como `unknown`. |
| `node`        | La versión de Node.js.                                                                                             |
| `platform`    | El sistema operativo: `darwin`, `linux` o `win32`.                                                                 |
| `ci`          | Si el comando se ejecuta en CI.                                                                                    |
| `interactive` | Si el comando se ejecuta en una terminal.                                                                          |
| `installId`   | El ID del equipo: un valor aleatorio creado en este equipo y no vinculado a nada más.                              |
| `runId`       | Un valor aleatorio para esta ejecución del comando.                                                                |

Algunos eventos se envían también con un segundo nombre más reciente, y `canonical_event_name` y `legacy_event_name` registran ambos nombres.

### Comandos {#commands}

| Evento                      | Cuándo                                        | Propiedades |
| --------------------------- | --------------------------------------------- | ----------- |
| `cli.run`                   | Empieza un comando.                           | Ninguna.    |
| `cli.crash`                 | Un comando falla de forma inesperada.         | `error`     |
| `cli.scaffold.import_error` | No se puede cargar el generador de proyectos. | `error`     |

`error` es la pista breve del mensaje descrita en [Informes de fallos](#crash-reports).

### Instalar skills {#installing-skills}

Estos eventos siguen a `skills add` y `npx @agent-native/skills`, para ver dónde se detiene una instalación. Las skills del catálogo propio de Agent-Native se envían por su nombre. Una skill de cualquier otro origen, como un manifiesto local u otro repositorio, se envía como `custom`.

| Evento                                                       | Cuándo                                            | Propiedades                                               |
| ------------------------------------------------------------ | ------------------------------------------------- | --------------------------------------------------------- |
| `skills_cli started`                                         | Empieza el comando.                               | Ninguna.                                                  |
| `skills_cli skills listed`, `skills_cli skills prompted`     | Se muestran las skills disponibles.               | `available`, `availableCount`                             |
| `skills_cli skills selected`                                 | Se eligen skills.                                 | `selected`, `selectedCount`, `selectedAll`, `preselected` |
| `skills_cli plan mode selected`                              | Se elige un modo de plan.                         | `mode`                                                    |
| `skills_cli clients selected`                                | Se eligen agentes de programación.                | `clients`, `clientCount`                                  |
| `skills_cli scope selected`                                  | Se elige la instalación en el proyecto o global.  | `scope`                                                   |
| `skills_cli install completed`                               | Se escriben los archivos de las skills.           | `skills`, `clients`, `scope`, `dryRun`, `writtenCount`    |
| `skills_cli instructions updated`                            | Se actualizan los archivos de instrucciones.      | `fileCount`                                               |
| `skills_cli mcp registered`                                  | Se registra un conector MCP.                      | `skills`, `serverName`, `clients`, `authenticated`        |
| `skills_cli github action added`                             | Se añade el flujo de trabajo PR Visual Recap.     | Ninguna.                                                  |
| `skills_cli connect started`, `skills_cli connect completed` | Empieza o termina el inicio de sesión en una app. | Ninguna.                                                  |
| `skills_cli connect failed`                                  | Falla el inicio de sesión en una app.             | `error`                                                   |
| `skills_cli cancelled`                                       | Se cancela la instalación.                        | `step`                                                    |
| `skills_cli completed`                                       | Termina el comando.                               | `skills`, `clients`, `scope`, `dryRun`, `durationMs`      |
| `skills_cli failed`                                          | El comando falla.                                 | `command`, `error`, `durationMs`                          |

### Informes de fallos {#crash-reports}

Cuando un comando falla, el evento `$exception` informa de qué se rompió en el código de Agent-Native, y nada sobre tu código:

| Propiedad          | Qué es                                                                                                                                                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `exceptionType`    | El tipo de error, como `TypeError`.                                                                                                                                                                                            |
| `exceptionCode`    | El código del error, como `ENOENT`, si lo tiene.                                                                                                                                                                               |
| `exceptionMessage` | Una pista breve. Los errores conocidos de Agent-Native envían su texto fijo. Cualquier otro mensaje envía como máximo sus primeros 20 caracteres, cortados en el primer carácter que no sea una letra, un dígito o un espacio. |
| `exceptionStack`   | Los marcos de pila de los archivos propios de Agent-Native, con rutas relativas al paquete. Se eliminan todos los demás marcos.                                                                                                |
| `handled`          | `false` cuando el error detuvo el comando.                                                                                                                                                                                     |
| `level`            | La gravedad.                                                                                                                                                                                                                   |
| `occurredAt`       | Cuándo ocurrió.                                                                                                                                                                                                                |
| `release`          | La versión de la CLI.                                                                                                                                                                                                          |
| `app`              | Siempre `agent-native-cli`.                                                                                                                                                                                                    |
| `template`         | Siempre `cli`.                                                                                                                                                                                                                 |
| `runtime`          | Siempre `cli`.                                                                                                                                                                                                                 |
| `source`           | Siempre `cli`.                                                                                                                                                                                                                 |
| `exceptionTags`    | Dónde ocurrió el fallo; consulta más abajo.                                                                                                                                                                                    |
| `exceptionExtra`   | Cómo terminó el fallo; consulta más abajo.                                                                                                                                                                                     |

Esos dos campos solo contienen estos valores:

- `exceptionTags`: `source` (la parte de la CLI que falló), `buildStep` (uno de nuestros nombres de pasos de compilación), `template` (solo uno de nuestros nombres de plantilla), `command` y `handled` (una etiqueta de la comprobación que lo notificó).
- `exceptionExtra`: `exitCode` y `signal` (cómo terminó un paso de compilación), `stage` y `durationMs`.

La pista es el principio del mensaje, así que un mensaje que empiece con una palabra tuya podría llevar hasta 20 caracteres de ella. Una ruta no puede pasar, porque la pista termina en la primera barra.

### Sentry {#sentry}

Si `@sentry/node` está instalado junto a `@agent-native/core`, los fallos y las compilaciones fallidas también van al proyecto de Sentry de Agent-Native, igual que dos avisos del servidor de desarrollo del workspace. Los comandos de skills fallidos no. Estos informes siguen todos los ajustes de esta página y llevan el mismo tipo de error, pista y marcos de pila, con estas etiquetas: los campos de `exceptionTags` anteriores, el `code` del error, el nombre de `command`, `nodeVersion` y `platform`. El entorno es siempre `production`. La CLI no envía el nombre de host, líneas de código fuente, la salida de consola ni tu lista de dependencias.

## Qué no se envía nunca {#what-is-never-sent}

- Variables de entorno
- Rutas de archivos, contenido de archivos o código fuente
- Nombres de proyectos, repositorios o apps, y remotos de git
- Registros o salida de comandos
- Argumentos de línea de comandos o prompts
- Correos electrónicos, nombres de usuario o nombres de host
- Mensajes de error sin procesar o marcos de pila de tu código
- Ningún ID de tu proyecto

El único límite de esta lista es la pista de fallo descrita arriba, que puede llevar la primera palabra de un mensaje de error.

El servicio que recibe un evento puede ver la dirección IP de la solicitud, como cualquier servidor web. La CLI no la incluye en ningún evento.
