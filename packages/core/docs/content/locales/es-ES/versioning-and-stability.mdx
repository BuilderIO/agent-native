# Versiones y estabilidad

Los paquetes de Agent-Native son anteriores a 1.0. El proceso ofrece snapshots nightly, versiones estables, herramientas de migración y comprobaciones de doctor. Una versión alpha o beta no es una garantía de soporte de producción.

## Canales de lanzamiento

Las fusiones en `main` publican snapshots nightly bajo la etiqueta npm `nightly`. No mueven `latest`. Las versiones estables se coordinan con Changesets. Las ejecuciones programadas preparan versiones patch de lunes a jueves al mediodía, hora del Pacífico. No todas las ejecuciones garantizan una versión.

## Compatibilidad antes de 1.0

Las versiones patch buscan corregir errores y ofrecer mejoras compatibles. Las versiones minor pueden añadir funciones y cambiar comportamientos o API que aún estén en alpha o beta. Las versiones major se reservan para cambios amplios incompatibles. Revisa las notas y los pasos de migración antes de actualizar.

`migration-manifest.json` registra cambios de importación y nombres cuando existe una migración compatible. Previsualiza el codemod, revisa el diff y aplícalo:

```bash
npx @agent-native/core@latest upgrade --codemods
npx @agent-native/core@latest upgrade --codemods --yes
agent-native doctor --only migration-manifest
```

Las rutas eliminadas pueden permanecer temporalmente como módulos tombstone con instrucciones. No existe un plazo fijo de retención.

## Versiones de plantillas y objetivos

La CLI fija `@agent-native/core` en la versión exacta que proporcionó la plantilla. Actualiza con las herramientas de migración, no cambiando manualmente a `latest`.

El objetivo actual es beta a mediados de octubre de 2026 y 1.0 a finales de 2026. Son objetivos, no compromisos. Informa errores reproducibles con la versión del paquete, el proveedor de base de datos y la salida de migración.
