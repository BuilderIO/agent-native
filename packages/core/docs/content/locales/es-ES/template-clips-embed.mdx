# Incrustar Clips

Usa Clips alojado como backend de grabación para tu producto. Una persona puede grabar desde un iframe sin iniciar sesión en Clips. Tu backend usa un token de servicio de la organización para crear una URL de admisión de corta duración, y Clips almacena la grabación resultante en el almacenamiento configurado de esa organización.

Esta guía cubre el flujo de incrustación alojado. No requiere que la persona que grabe tenga una cuenta de Clips.

## Cómo funciona la integración

La integración tiene cuatro partes:

1. Un administrador de la organización configura el almacenamiento de vídeo en Clips.
2. Tu backend almacena el token de servicio de la organización y solicita una URL de admisión.
3. Tu producto pasa solo la URL de admisión de corta duración a un iframe.
4. Clips sube la grabación al almacenamiento de la organización y envía un mensaje de finalización a tu producto.

El token de servicio de la organización nunca debe estar en el iframe. Está vinculado a la organización que lo generó, así que el propio token proporciona el contexto de la organización. Un ID de organización es útil para tu propio mapeo de inquilinos, pero no es una credencial por sí solo.

## Configura la organización de Clips

Crea o selecciona la organización de Clips que debería ser propietaria de las grabaciones. Un administrador de la organización configura después el almacenamiento de vídeo a través de la incorporación de Clips o de Clips Settings:

- **Builder.io Connect** proporciona almacenamiento de vídeo gestionado y créditos de IA.
- **El almacenamiento compatible con S3** usa el endpoint, el bucket, la clave de acceso, la clave secreta y, opcionalmente, la región o la URL base pública configurados por la organización. Cloudflare R2 y DigitalOcean Spaces usan los mismos ajustes de almacenamiento con sus nombres específicos de proveedor.

La configuración del almacenamiento está delimitada por organización. Cada grabación creada a través del token de servicio de esa organización usa el almacenamiento ya conectado a esa organización. El producto que incrusta Clips no necesita las credenciales de Builder.io ni de S3.

El vídeo se almacena en el almacenamiento de objetos configurado. Clips almacena los metadatos de la grabación, la propiedad, el estado de procesamiento y la referencia de almacenamiento en su base de datos.

## Crea un token de servicio de la organización

Ejecuta el comando `connect` existente como propietario o administrador de la organización. El comando abre un inicio de sesión en el navegador, crea un token de servicio con nombre para la organización activa e imprime el token una sola vez:

```bash
npx @agent-native/core@latest connect https://clips.agent-native.com \
  --service-token support-desk --ttl-days 365
```

Copia el token impreso directamente en el gestor de secretos del lado del servidor de tu producto. El token es propiedad de la organización, así que sigue funcionando aunque la persona que lo generó abandone la organización o revoque sus tokens personales. Nunca se escribe en una configuración de cliente local. Usa un nombre de servicio diferente para cada integración, de modo que se pueda revocar a un solicitante sin romper otro.

`--ttl-days` acepta de 1 a 365 días y usa 365 por defecto. El token actúa como un miembro de la organización. No puede crear ni revocar otros tokens de servicio, ni cambiar la configuración de la organización.

## Solicita una URL de admisión

Tu backend de confianza llama a la acción de admisión de Clips. Usa el origen de Clips alojado para cuentas alojadas, o tu propio origen de Clips cuando autoalojas.

```ts
const clipsBaseUrl = "https://clips.agent-native.com";
const clipsServiceToken = process.env.CLIPS_SERVICE_TOKEN;

const response = await fetch(
  `${clipsBaseUrl}/_agent-native/actions/create-recording-intake-link`,
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${clipsServiceToken}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      ttlSeconds: 3600,
    }),
  },
);

if (!response.ok) {
  throw new Error("Could not create a Clips intake URL");
}

const intake = await response.json();
// intake.url is safe to pass to the recording iframe.
```

El contexto de organización firmado del token de servicio determina qué organización es propietaria de la admisión. La respuesta de la acción es el objeto intake en el nivel superior. La duración predeterminada de la admisión es una hora. El máximo es cuatro horas. Cada URL de admisión puede crear una grabación.

No hagas esta solicitud desde un navegador anónimo. No devuelvas el token de servicio, las credenciales de almacenamiento ni una sesión de Clips de larga duración al navegador.

## Incrusta la grabadora

Pasa la URL devuelta directamente a un iframe. La URL contiene la capacidad firmada y acotada que permite al visitante crear y subir una grabación privada.

```tsx
<iframe
  data-clips-recorder
  src={intake.url}
  allow="display-capture; camera; microphone"
  title="Report a problem"
  style={{ width: 420, height: 560, border: 0 }}
/>
```

Puedes añadir valores de contexto pequeños y no sensibles a la URL de admisión antes de renderizarla, como un ID de proyecto, un título de página, una versión de la aplicación o un entorno. No pongas contraseñas, claves de API, registros de clientes ni otros valores sensibles en la URL. Las URL pueden aparecer en el historial del navegador, registros, analítica y referrers.

La grabadora abre una ventana emergente de nivel superior cuando el visitante inicia la captura. Los permisos de medios del navegador y la captura de pantalla requieren un gesto del usuario en un contexto de navegación de nivel superior. Permite ventanas emergentes para el producto anfitrión durante las pruebas.

## Recibe el mensaje de finalización

Cuando la grabación se guarda, la página de finalización envía `agent-native.clips.bug-report.submitted` al padre que la incrusta. Valida el origen de Clips y la fuente del mensaje antes de usar el payload.

```ts
const clipsOrigin = new URL(clipsBaseUrl).origin;
const recorderFrame = document.querySelector<HTMLIFrameElement>(
  "iframe[data-clips-recorder]",
);

window.addEventListener("message", (event) => {
  if (event.origin !== clipsOrigin) return;
  if (recorderFrame && event.source !== recorderFrame.contentWindow) return;
  if (event.data?.type !== "agent-native.clips.bug-report.submitted") return;

  const { recordingId, recordingUrl, embedUrl, agentAccessStatus } = event.data;
  if (!recordingId) return;

  // Send recordingId to your trusted backend and attach it to the support case.
  console.log({ recordingId, recordingUrl, embedUrl, agentAccessStatus });
});
```

El payload de finalización puede incluir `recordingId`, `recordingUrl`, `embedUrl`, `agentShareUrl`, `agentContextUrl`, `agentAccessExpiresAt` y `agentAccessStatus`. Trata `recordingId` como el identificador duradero del caso de soporte. Una admisión de solo escritura puede reportar `agentAccessStatus: "unavailable"` hasta que tu backend autenticado cree un enlace de agente limitado por separado. Ese estado no significa que la grabación esté vacía.

El mensaje del navegador es una notificación, no una concesión de autorización. Tu backend debería usar su propia conexión autenticada a Clips cuando necesite leer o compartir la grabación completada.

## Dónde se almacenan las grabaciones

Las grabaciones creadas a través del token de servicio pertenecen a la organización asociada a ese token. Clips envía el archivo multimedia a través de su canalización normal de carga y finalización. Esa canalización usa el almacenamiento de Builder.io o compatible con S3 configurado para esa organización.

El iframe no sube directamente a tu bucket, y no necesita las credenciales del bucket. Tu producto recibe identificadores de grabación y URL limitadas de Clips. Almacena en tu propio sistema de soporte solo los identificadores o URL que necesites.

## Autoalojar Clips

El autoalojamiento usa el mismo contrato de organización:

1. Despliega Clips con una base de datos persistente y un `BETTER_AUTH_URL` público.
2. Crea la organización que será propietaria de las grabaciones incrustadas.
3. Configura Builder.io Connect o almacenamiento compatible con S3 una vez en esa organización.
4. Ejecuta `connect` contra el origen de Clips autoalojado para crear el token de servicio de la organización.
5. Proporciona ese token una vez a tu backend de incrustación como un valor de despliegue o de gestor de secretos.
6. Usa el origen de Clips autoalojado cuando tu backend solicite URL de admisión.

```bash
npx @agent-native/core@latest connect https://clips.example.com \
  --service-token support-desk --ttl-days 365
```

Por ejemplo, el backend que incrusta Clips puede mantener estos valores en su configuración del lado del servidor:

```text
CLIPS_BASE_URL=https://clips.example.com
CLIPS_SERVICE_TOKEN=<secret>
```

El token se proporciona una sola vez al backend. Cada visitante sigue recibiendo una nueva URL de admisión de corta duración. No se añade ningún token ni credencial de almacenamiento al iframe, y no se necesita ningún cambio de código en el iframe cuando se rota el token.

Consulta [Implementación](/docs/deployment) para conocer los requisitos generales de autoalojamiento.

## Lista de comprobación de seguridad

- Mantén el token de servicio de la organización en un gestor de secretos del lado del servidor.
- Usa HTTPS tanto para el producto anfitrión como para Clips.
- Trata cada URL de admisión como una credencial portadora. Mantenla fuera de los registros y de los datos de referrer.
- Usa la duración de admisión más corta que sea útil.
- Valida tanto `event.origin` como `event.source` en el listener de finalización.
- Nunca expongas directamente a usuarios anónimos los endpoints de carga de Clips delimitados por propietario.
- Rota el token de servicio creando uno de reemplazo con `connect`, desplegándolo, verificando el flujo y luego revocando el token antiguo con `revoke-org-service-token`.
- Mantén el ID de organización y el ID de admisión en el backend de confianza en lugar de confiar en los valores proporcionados por el visitante.

## Solución de problemas

**La solicitud de admisión no está autorizada.** Confirma que el backend está usando un token de servicio no caducado y no revocado, generado para el origen de Clips previsto. La vinculación del token a la organización determina dónde se crea la admisión.

**El iframe abre una página de inicio de sesión.** Asegúrate de que el iframe usa la URL de corta duración devuelta por `create-recording-intake-link`. No incrustes `/record` ni una URL normal de la biblioteca de Clips para un visitante anónimo.

**La grabación no termina.** Comprueba que la organización tiene configurado el almacenamiento de Builder.io o compatible con S3. Un visitante anónimo no puede configurar el almacenamiento desde el iframe.

**La finalización no tiene enlace de agente.** Eso es lo esperado para una admisión de solo escritura. Haz que tu backend autenticado cree un enlace de agente limitado por separado si el flujo de soporte necesita datos de transcripción y fotogramas legibles por agentes.
