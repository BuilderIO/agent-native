# Plans visuales

Agent-Native Plans es el modo de plan visual para agentes de codificación.
Convierte un plan de implementación normal de Codex, Claude Code, Markdown o
pegado en una superficie de revisión estructurada con texto enriquecido,
diagramas, wireframes, recorridos de código anotado y árboles de archivos,
comentarios y enlaces para compartir.

Se reduce a dos comandos. `/visual-plan` construye un plan **antes** de que el
agente escriba código. `/visual-recap` convierte un cambio que **ya ocurrió** —
un PR, commit, rama o diff de git — en una revisión de código visual de alto
nivel. Ambos abren la misma superficie de revisión, así que anotas, comentas y
le devuelves feedback al agente de la misma manera en ambos casos.

## Lo que sustituye

<Comparison>

### Antes

- Un plan vive como un muro de prosa en el chat o en un archivo Markdown, y
  revisarlo significa leerlo de principio a fin para encontrar el único
  párrafo con el que no estás de acuerdo.
- El feedback ocurre en un hilo de Slack o en comentarios dispersos,
  desconectados del plan en sí.
- Revisar un PR terminado significa leer un diff sin formato línea por línea
  para reconstruir qué cambió y por qué.

### Después

- El plan se renderiza como diagramas, wireframes, código anotado y un
  formulario de Preguntas abiertas al que puedes reaccionar directamente.
- Los comentarios se fijan al texto, la imagen o la ubicación exacta del
  wireframe, y se dirigen al agente o a un revisor humano.
- `/visual-recap` convierte un PR, commit o diff en la misma revisión visual
  en lugar de un diff sin formato.

</Comparison>

Exporta el resultado como HTML, Markdown o JSON para obtener una copia
compatible con el control de versiones, o mantenlo completamente fuera de la
base de datos alojada con el modo de archivos locales. Consulta [Revisar y
comentar Plans](/docs/template-plan-review-workflow) y [Modo de archivos
locales y sincronización con Desktop](/docs/template-plan-local-and-desktop)
para profundizar en cada uno de ellos.

## Para empezar {#get-started}

<Steps>

### Instala la skill {#install}

La mayoría de las personas instala Plan como una **skill** para su agente de
codificación existente, no como una aplicación con scaffolding propio. Este
único comando instala las instrucciones de la skill, registra el conector MCP
alojado de Plans y le inicia sesión:

```bash
npx @agent-native/core@latest skills add visual-plan
```

Esto instala tres comandos de barra diagonal — `/visual-plan`, `/visual-recap`
y `/visualize-repo` — además del conector MCP `plan` (un servidor de
herramientas remoto con el que habla tu agente) en
`https://plan.agent-native.com/mcp`. Para la referencia completa de flags, las
rutas de instalación por plugin/marketplace para Claude Code y Codex, y la
extensión de VS Code, consulta [Plugin y marketplace de Plan → Rutas de
instalación](/docs/plan-plugin#install).

Personalizar la propia plantilla Plan — autoalojarla, o construir directamente
sobre ella — es un camino aparte y secundario, cubierto en [Ampliar
Plan](/docs/template-plan-developers). La mayoría de las personas nunca lo
necesita.

### Pide a tu agente el comando adecuado para el trabajo

- "Usa `/visual-plan` antes de cambiar el flujo de autenticación."
- "Crea un `/visual-plan` para la nueva pantalla de onboarding con estados de
  escritorio y móvil."
- "Ejecuta `/visual-recap` en este PR para poder revisar primero la forma del
  cambio."
- "Usa `/visual-recap` en el diff entre `main` y esta rama."
- "Ejecuta `/visualize-repo` y empieza por nuestras actions públicas de la API
  y el esquema."

`/visual-plan` incorpora diagramas, wireframes, mockups, prototipos
interactivos y código anotado según lo requiera el trabajo. El agente
inspecciona primero el código base, y luego el enlace devuelto abre la
interfaz de revisión en tu navegador o en VS Code.

### Revisa como invitado, sin necesidad de cuenta

Las personas con las que compartes un plan no necesitan instalar nada. Abren
el editor de Plans y **crean y editan sin necesidad de registro** — trabajan
como invitados. Iniciar sesión solo es necesario para **guardar o compartir**
tu propio trabajo, y si un invitado inicia sesión más tarde, cada plan que
creó como invitado queda **reclamado** en su cuenta.

</Steps>

Cuando ya existe un plan de Codex, Claude Code, Markdown o pegado, usa
`/visual-plan`; el agente conserva ese plan de origen y construye a partir de
él la superficie de revisión más completa en lugar de empezar de cero. Si la
primera pasada todavía tiene decisiones abiertas, el agente puede añadir un
formulario de **Preguntas abiertas** al final del plan — responderlo y
devolverlo inicia un turno de revisión.

<Callout tone="info">

**Invitado frente a con sesión iniciada, de un vistazo**

- **Como invitado** puedes abrir un enlace compartido, crear un plan nuevo,
  editar prosa y usar el modo de anotación de revisión — sin necesidad de
  cuenta.
- **Iniciar sesión** además te permite guardar tus propios planes de forma
  permanente, publicar un plan en un enlace para compartir, conceder acceso de
  espectador/editor/administrador a otras personas, publicar comentarios que
  notifiquen a la gente por correo electrónico, y eliminar o restaurar los
  planes que posees.

</Callout>

## Coste y elección de modelo

Generar un plan o un resumen ejecuta una sesión agéntica completa contra el
LLM de tu agente de codificación, no un simple relleno de plantilla ligero —
el coste depende del tamaño del diff o del plan y del modelo que elijas.

- El modelo de chat predeterminado de la app es GPT-5.6 Luna. Las conexiones
  directas a Anthropic mantienen Claude Sonnet 5 como su valor predeterminado.
  Cambia de modelo cuando quieras en **Configuración**; Haiku es la opción más
  económica de Claude.
- Los resúmenes automáticos de PR desde la GitHub Action se ejecutan por
  separado de la app interactiva y tienen sus propios controles de modelo y
  coste — consulta [Resumen visual de PR](/docs/pr-visual-recap) para
  `VISUAL_RECAP_MODEL`, `VISUAL_RECAP_AGENT` y `VISUAL_RECAP_REASONING`.

## Solicitar acceso a un plan privado {#request-access}

Si alguien abre un enlace de un plan para el que no tiene permiso de
visualización, Plans no se limita a mostrar un callejón sin salida. La página
le indica que el plan es privado y ofrece una acción de **Solicitar acceso**,
que:

- Requiere haber iniciado sesión (a un invitado se le pide que inicie sesión
  primero).
- Registra la solicitud contra el plan y, cuando el despliegue tiene el
  correo electrónico configurado, envía un mensaje al propietario del plan
  con el nombre de quien lo solicita y un enlace para abrir el plan y
  compartirlo de vuelta si se aprueba.
- Es seguro hacer clic más de una vez — Plans comprueba primero si ya tienes
  acceso, así que una segunda solicitud de la misma persona no satura al
  propietario con correos duplicados.

Si la visibilidad del plan está configurada como **organización** en lugar de
completamente privada, y tu cuenta ya tiene una invitación pendiente a esa
organización o un dominio de correo electrónico que coincide con ella, Plans
te ofrece unirte a la organización directamente en lugar de enviar una
solicitud.

<Callout tone="warning">

Si alguna herramienta de Plans devuelve alguna vez `needs auth`,
`Unauthorized` o `Session terminated`, no sigas reintentándolo. Vuelve a
autenticarte con
`npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex`,
o vuelve a ejecutar `/mcp` → **Authenticate** para un host compatible con
OAuth. Inicia un nuevo hilo de Codex o reinicia/recarga el cliente después —
el registro de herramientas solo recoge el cambio en una sesión nueva.

</Callout>
