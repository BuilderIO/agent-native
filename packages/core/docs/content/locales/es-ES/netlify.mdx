# Netlify

Netlify aloja tu aplicación por ti, así que no hay ningún servidor que configurar ni mantener en ejecución.
La compilación convierte la aplicación en archivos estáticos que Netlify sirve directamente y en funciones que
Netlify ejecuta bajo demanda. Además, Netlify le da a la aplicación una dirección pública con HTTPS.

Esta guía explica cómo implementar una aplicación independiente desde cero. Vas a
crear la aplicación, darle una base de datos de producción y un secreto de autenticación, crear un
sitio de Netlify para ella, preparar la base de datos y, después, compilarla e implementarla.

<Callout tone="info">

Se requiere Node.js `22.22+`.

</Callout>

También necesitas una cuenta de Netlify. Ejecuta los comandos de esta guía en tu propio
equipo. La Netlify CLI sube la compilación terminada a Netlify por ti.

## Paso 1: Crea la aplicación {#step-1-create-the-app}

Crea tu nueva aplicación independiente. El siguiente ejemplo crea una aplicación a partir de la plantilla Chat,
pero puedes empezar desde cualquier plantilla. Entra en la carpeta de la aplicación e
instala sus dependencias. `corepack enable` activa la versión de `pnpm` que la aplicación
espera, así que no necesitas instalar `pnpm` por tu cuenta.

```bash
npx --yes @agent-native/core@latest create my-app --standalone --template chat

cd my-app

corepack enable

pnpm install
```

Si quieres, reemplaza `my-app` por el nombre de tu aplicación. El resto de esta guía
supone que estás dentro de la carpeta de la aplicación.

## Paso 2: Configura los secretos del entorno {#step-2-configure-environment-secrets}

La aplicación lee su configuración de producción desde variables de entorno:

| Variable             | Obligatoria | Propósito                                                          |
| -------------------- | ----------- | ------------------------------------------------------------------ |
| `DATABASE_URL`       | Sí          | Conecta la aplicación con su base de datos PostgreSQL              |
| `BETTER_AUTH_SECRET` | Sí          | Firma las sesiones de los usuarios                                 |
| `BETTER_AUTH_URL`    | No          | Define la dirección pública que usan las personas para acceder a tu aplicación |

Las exportaciones siguientes hacen que los comandos posteriores funcionen en esta terminal. Antes de
implementar, guarda estas mismas variables en la configuración del entorno del proyecto o servicio de tu host.
El siguiente paso muestra cómo guardarlas en Netlify.

### URL de la base de datos {#database-url}

Durante el desarrollo local, la aplicación guarda los datos en una base de datos local cuando
`DATABASE_URL` no está definida. Una aplicación implementada necesita una base de datos PostgreSQL real que
conserve sus datos entre implementaciones. Netlify no conserva archivos entre solicitudes, así que
la base de datos debe estar fuera de las funciones de Netlify. Copia la cadena de conexión
de tu proveedor y expórtala:

```bash
export DATABASE_URL='your-postgres-url-string'
```

Las [guías de proveedores de bases de datos](/docs/neon) muestran dónde encontrar la cadena de conexión
de cada proveedor.

<Callout tone="warning">

Elige un proveedor de PostgreSQL persistente, como Neon, Supabase o Amazon RDS.

</Callout>

### Secreto de autenticación {#auth-secret}

Genéralo una sola vez y mantenlo igual en todas las implementaciones.

La aplicación usa `BETTER_AUTH_SECRET` para firmar las sesiones de los usuarios. Si cambia, se cierra la sesión de
todos los usuarios que la tenían iniciada. El siguiente comando genera un valor aleatorio:

```bash
export BETTER_AUTH_SECRET="$(openssl rand -hex 32)"
```

Guarda el valor generado en un lugar seguro, como un gestor de contraseñas. Usa el
mismo valor cada vez que implementes.

### URL pública {#public-url}

Es opcional. Defínela cuando uses un dominio personalizado, un proxy inverso o un flujo de autenticación u OAuth
que necesite un origen público fijo.

`BETTER_AUTH_URL` es la dirección pública que usan las personas para acceder a tu aplicación. Sin
ella, la aplicación deduce su dirección a partir de cada solicitud entrante. Eso suele
funcionar bien con la dirección que te da Netlify, pero defínela cuando conectes un dominio
personalizado para que los enlaces de inicio de sesión y las redirecciones de OAuth usen ese dominio.

```bash
export BETTER_AUTH_URL='https://your-domain.example'
```

## Paso 3: Vincula el sitio y guarda los secretos {#step-3-link-the-site-and-save-the-secrets}

Inicia sesión en Netlify desde la línea de comandos y, después, crea un sitio nuevo para la aplicación.
Por ahora puedes dejar el nombre del proyecto predeterminado y dejar vacío el repositorio de GitHub.

```bash
npx netlify login

npx netlify sites:create --name my-app
```

`sites:create` crea el sitio y lo vincula a la carpeta de la aplicación, para que los comandos posteriores
sepan qué sitio usar. El nombre también se convierte en la dirección del sitio, por ejemplo
`my-app.netlify.app`. Los nombres de sitio se comparten en todo Netlify, así que elige
otro nombre si `my-app` ya está ocupado. No necesitas un repositorio de GitHub,
porque implementas la aplicación desde tu equipo en el paso 5.

Guarda las dos variables obligatorias en el entorno del sitio:

```bash
npx netlify env:set DATABASE_URL "$DATABASE_URL"

npx netlify env:set BETTER_AUTH_SECRET "$BETTER_AUTH_SECRET"
```

Cada comando lee el valor que exportaste en el paso 2 y lo guarda en Netlify, así que
no tienes que pegar los secretos a mano. Si defines `BETTER_AUTH_URL`, guárdala
de la misma forma. También puedes ver y cambiar estos valores más adelante en la configuración
del sitio en el panel de Netlify.

## Paso 4: Ejecuta las migraciones {#step-4-migrate}

Las migraciones crean y actualizan las tablas que la aplicación necesita en tu base de datos. Ejecuta
esto antes de la primera implementación:

```bash
pnpm migrate:production
```

El comando se ejecuta en tu equipo y se conecta a la base de datos de producción con
la `DATABASE_URL` que exportaste en el paso 2. Vuelve a ejecutarlo después de actualizar la
aplicación y antes de implementar la nueva versión.

## Paso 5: Implementa {#step-5-deploy}

Compila la aplicación para Netlify:

```bash
NITRO_PRESET=netlify pnpm build
```

`NITRO_PRESET=netlify` compila la aplicación en el formato que Netlify espera. La compilación
escribe los archivos estáticos de la aplicación en la carpeta `dist` y sus funciones de servidor en
la carpeta `.netlify/functions-internal`.

Sube la compilación y publícala:

```bash
npx netlify deploy --prod --dir=dist --functions=.netlify/functions-internal
```

`--dir` y `--functions` le indican a la CLI dónde encontrar los archivos estáticos y las
funciones que acabas de compilar. `--prod` los publica en tu dirección de producción
en lugar de en una vista previa de borrador.

Cuando el comando termina, muestra la dirección de producción de la aplicación. Ábrela y
crea la primera cuenta.

## Implementa actualizaciones {#deploy-updates}

Para publicar una nueva versión, vuelve a ejecutar los comandos de migración, compilación e implementación desde
la carpeta de la aplicación:

```bash
pnpm migrate:production

NITRO_PRESET=netlify pnpm build

npx netlify deploy --prod --dir=dist --functions=.netlify/functions-internal
```

El vínculo del sitio y las variables guardadas se mantienen, así que no necesitas
repetir el paso 3.

## Keep-warm y bases de datos con escalado a cero {#netlify-keep-warm}

Tras un periodo de inactividad, la primera solicitud puede tardar mientras Netlify inicia la
función y una base de datos con escalado a cero, como el nivel gratuito de Neon, se activa.
Agent-Native puede reducir esa espera con keep-warm. Cuando está activado, la
compilación añade una función programada de Netlify que llama al endpoint
`/_agent-native/health` de la aplicación **cada minuto**, lo que mantiene activas la función
del servidor y su base de datos.

Keep-warm está **desactivado de forma predeterminada**. Mantener activa la base de datos impide que
se suspenda, lo que consume la cuota de cómputo en los planes gratuitos o medidos. Si la cuota
se agota, la base de datos rechaza **todas** las lecturas y la aplicación deja de funcionar. Define
`AGENT_NATIVE_ENABLE_KEEP_WARM=1` cuando una primera visita más rápida compense el tiempo extra
de base de datos.

Estas variables controlan keep-warm. La programación y la configuración en segundo plano solo
se aplican después de activar `AGENT_NATIVE_ENABLE_KEEP_WARM`:

| Variable                                    | Efecto                                                                                                                                                                          |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AGENT_NATIVE_ENABLE_KEEP_WARM`             | Activa el calentamiento programado de la función del servidor y la base de datos. No está definida de forma predeterminada.                                                      |
| `AGENT_NATIVE_DISABLE_KEEP_WARM`            | Desactiva keep-warm incluso cuando `AGENT_NATIVE_ENABLE_KEEP_WARM` está definida. Se mantiene por compatibilidad con configuraciones antiguas.                                   |
| `AGENT_NATIVE_KEEP_WARM_SCHEDULE`           | Cambia la frecuencia del calentamiento con una expresión cron de 5 campos, como `*/5 * * * *`. El valor predeterminado es `* * * * *`, cada minuto. Un valor que no sea un cron válido **hace fallar la compilación**. |
| `AGENT_NATIVE_DISABLE_KEEP_WARM_BACKGROUND` | Omite el calentamiento de la función en segundo plano y sigue calentando la función del servidor. Calentar el servidor es una sola solicitud. Calentar la función en segundo plano inicia un contenedor nuevo que vuelve a comprobar el esquema de la base de datos. |

Si tu base de datos está en un plan gratuito o limitado de otra forma, deja
`AGENT_NATIVE_ENABLE_KEEP_WARM` sin definir. Si lo activas, elige una programación más lenta
o define `AGENT_NATIVE_DISABLE_KEEP_WARM_BACKGROUND=1` para omitir el calentamiento en segundo plano,
que es más costoso.

La compilación lee estas variables, no la aplicación en ejecución. Como compilas en tu
propio equipo en el paso 5, defínelas en la misma terminal antes de compilar. Guardarlas
en la configuración del sitio de Netlify no tiene efecto en una compilación que se ejecuta en local. Por
ejemplo, para activar keep-warm con una programación de cinco minutos:

```bash
export AGENT_NATIVE_ENABLE_KEEP_WARM=1

export AGENT_NATIVE_KEEP_WARM_SCHEDULE='*/5 * * * *'

NITRO_PRESET=netlify pnpm build
```

Después, implementa como de costumbre.
