# Datos y sincronización

La forma principal de leer y escribir datos de la app desde el cliente es a través de los hooks de [acciones](/docs/actions). Al incorporar las solicitudes en acciones, tanto tu cliente como el agente pueden interactuar con tu aplicación de la misma manera.

En el ejemplo siguiente, un ticket se asigna al usuario actual manualmente a través de un desplegable, y luego a través del agente de chat. Tanto la UI como el agente acceden a la misma acción.

### Hooks de acciones {#action-hooks}

Hay dos hooks de acciones que probablemente usarás más: `useActionQuery()` y `useActionMutation()`. Estos dos hooks dan acceso a las acciones de tu app.

#### useActionQuery {#use-action-query}

    },
  ]}
  returns={{
    type: "UseQueryResult<TResult>",
    description:
      'Almacenado en caché bajo `["action", name, params]`. Se vuelve a obtener automáticamente cada vez que se completa una acción mutante, sin necesidad de invalidación manual.',
  }}
/>

Este hook está pensado para usarse con acciones de solo lectura. Es un envoltorio ligero alrededor de la función [useQuery()](https://tanstack.com/query/latest/docs/framework/react/reference/useQuery).

En el ejemplo siguiente, se llama a la acción `list-tickets`. Esto es similar a hacer una solicitud GET para todos los tickets.

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery("list-tickets", {});
```

El siguiente ejemplo muestra una solicitud para obtener un único ticket, a través de la acción `get-ticket`. Se pasa un `ticketId` para limitar la consulta a un ticket específico. La opción adicional `enabled` se proporciona para asegurar que la consulta no se ejecute automáticamente, y en su lugar solo se ejecute cuando haya un `ticketId` presente.

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery(
  "get-ticket",
  { ticketId: ticketId ?? "" },
  { enabled: Boolean(ticketId) },
);
```

/>

Este hook está pensado para usarse con acciones que cambian datos, como crear, actualizar o enviar algo. Es un envoltorio ligero alrededor de la función [useMutation()](https://tanstack.com/query/latest/docs/framework/react/reference/useMutation).

A diferencia de `useActionQuery()`, la entrada de la acción no se pasa al propio hook. Se pasa a `mutate()` o `mutateAsync()` cuando estás listo para ejecutar la mutación.

En el ejemplo siguiente, se llama a la acción `send-ticket-reply` para publicar una respuesta a un ticket. Llama a `mutate()` desde un manejador de eventos, como el `onClick` de un botón.

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply");

mutate({ ticketId, body: draft });
```

El siguiente ejemplo muestra la misma mutación con una opción `onSuccess`. La invalidación de la caché ocurre automáticamente después de cada mutación, así que `onSuccess` solo se necesita para efectos secundarios locales, como limpiar el compositor de respuesta una vez enviada.

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply", {
  onSuccess: () => setDraft(""),
});

mutate({ ticketId, body: draft });
```

Esta función es para llamadas imperativas puntuales a acciones fuera de un flujo de renderizado de React, como un manejador de eventos simple, un script, o cualquier otra ruta de código que no sea React. Devuelve una promesa directamente en lugar de un resultado de hook.

En el ejemplo siguiente, se llama a la acción `update-ticket` desde un manejador de atajo de teclado fuera del flujo de renderizado de React, asignando el ticket a un representante.

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction("update-ticket", {
  ticketId,
  assignedToEmail: "jordan@example.com",
});
```

El siguiente ejemplo muestra la misma llamada con una opción `timeoutMs`, útil para acciones que legítimamente tardan más que el tiempo de espera predeterminado de 60 segundos.

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction(
  "update-ticket",
  { ticketId, assignedToEmail: "jordan@example.com" },
  { timeoutMs: 120_000 },
);
```

Cada solicitud de `useActionQuery()`, `useActionMutation()` y `callAction()` está acotada por un tiempo de espera de 60 segundos, y los tiempos de espera se muestran como errores en lugar de reintentarse silenciosamente. `useActionQuery()` también cancela automáticamente las solicitudes reemplazadas, usando la señal de aborto de React Query.

Este hook está pensado para mantener la UI sincronizada con cambios en la base de datos que ocurren fuera de tus propias acciones, como una escritura del agente, un webhook o un cambio hecho desde otra pestaña del navegador. Escucha cambios a través de eventos enviados por el servidor, y recurre al sondeo cuando los eventos enviados por el servidor no están disponibles.

```ts
import { useDbSync } from "@agent-native/core/client/hooks";
import { useQueryClient } from "@tanstack/react-query";

function App() {
  const queryClient = useQueryClient();

  useDbSync({
    queryClient,
    pollUrl: "/_agent-native/poll",
    onEvent: (data) => console.log("Data changed:", data),
  });

  return <div>...</div>;
}
```

Para operaciones CRUD normales, prefiere `useActionQuery()` y `useActionMutation()`. Las acciones mutantes emiten `source: "action"`, así que esos hooks se recuperan de inmediato. Los cambios provenientes del agente, un webhook u otra pestaña llegan a través de `useDbSync()` en su lugar, por SSE o el respaldo de sondeo. Si una llamada `useQuery()` sin procesar necesita sincronizarse con una clave personalizada, consulta [Sincronización interna](/docs/client-sync-internals). Si necesitas escribir directamente en `application_state`, consulta [Avanzado](/docs/client-advanced).
