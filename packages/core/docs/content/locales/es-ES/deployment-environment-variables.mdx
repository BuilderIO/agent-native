# Implementación: variables de entorno

Para la referencia a nivel de todo el repositorio, incluidas las variables de
plantilla, proveedor, locales y de CI, consulta
[Variables de entorno](/docs/environment-variables). Las siguientes tablas
siguen siendo la guía de implementación autorizada para los valores de
producción y el comportamiento de alojamiento.

## Compilación / Tiempo de ejecución {#env-runtime}

| Variable                                    | Descripción                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PORT`                                      | Puerto del servidor (solo Node.js)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `NITRO_PRESET`                              | Anula el ajuste preestablecido de compilación en el momento de la compilación                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `APP_BASE_PATH`                             | Monta la aplicación bajo un prefijo (por ejemplo, `/mail`). Se establece automáticamente mediante `npx @agent-native/core@latest deploy`. Déjala sin definir para una implementación independiente.                                                                                                                                                                                                                                                                                                                                           |
| `APP_URL`                                   | Origen público canónico opcional. Se comprueba antes que `BETTER_AUTH_URL` al resolver la audiencia del JWT de A2A, el origen público de OAuth, los destinos de webhook de autodespacho y los enlaces de recursos generados. Establécelo explícitamente en implementaciones de vista previa/staging donde el host de la solicitud no sea fiable.                                                                                                                                                                                              |
| `AGENT_PROD_CODE_EXECUTION`                 | Modo opcional de ejecución de código en producción: `off` (predeterminado), `sandboxed` o `trusted`. Consulta [Ejecución de código en producción](/docs/actions-agent-tools#production-code-execution).                                                                                                                                                                                                                                                                                                                                       |
| `AGENT_NATIVE_SSR_CACHE`                    | Política de caché del shell SSR para toda la implementación: sin configurar/`on` mantiene la caché estricta predeterminada, `off` envía `no-store`, o una duración como `30s` / `5m` establece una frescura más corta. Consulta [Caché SSR](/docs/ssr-caching).                                                                                                                                                                                                                                                                               |
| `AGENT_NATIVE_ENABLE_KEEP_WARM`             | Activa la función programada de keep-warm de Netlify. No está definida de forma predeterminada. Consulta [Keep-warm](/docs/netlify#netlify-keep-warm).                                                                                                                                                                                                                                                                                                                                                                                        |
| `AGENT_NATIVE_DISABLE_KEEP_WARM`            | Interruptor de compatibilidad para la función programada de keep-warm de Netlify. Consulta [Keep-warm](/docs/netlify#netlify-keep-warm).                                                                                                                                                                                                                                                                                                                                                                                                      |
| `AGENT_NATIVE_KEEP_WARM_SCHEDULE`           | Sobrescribe la cadencia de keep-warm con una expresión cron de 5 campos (predeterminado `* * * * *` cuando está habilitado). Un valor no analizable hace fallar la compilación. Consulta [Keep-warm](/docs/netlify#netlify-keep-warm).                                                                                                                                                                                                                                                                                                        |
| `AGENT_NATIVE_DISABLE_KEEP_WARM_BACKGROUND` | Descarta solo el calentamiento de la función en segundo plano y mantiene caliente el servidor. Consulta [Keep-warm](/docs/netlify#netlify-keep-warm).                                                                                                                                                                                                                                                                                                                                                                                         |
| `AGENT_NATIVE_DISABLE_INPROCESS_SWEEPS`     | Desactiva los temporizadores de barrido de respaldo en proceso (redespacho de automatizaciones, reconciliación de agent-teams, recuperación de ejecuciones en sandbox). En serverless, estos se ejecutan por contenedor caliente, así que su tasa de consultas escala con el número de instancias. Actívalo **solo** donde un planificador durable ya impulse la misma recuperación, o el trabajo en cola no se reintentará.                                                                                                                  |
| `AGENT_NATIVE_SKIP_ENSURE_TABLES`           | Omite el DDL de esquema bajo demanda en implementaciones que la omisión automática en serverless no cubre. Requiere que tu esquema ya esté migrado. Consulta [Configuración automática del esquema](/docs/deployment#skip-ensure-tables).                                                                                                                                                                                                                                                                                                     |
| `AGENT_NATIVE_BUILDER_RELAY_SECRET`         | Secreto HMAC compartido y dedicado de 32 o más caracteres para la retransmisión segura de la autorización de Builder en vistas previas. Establece el mismo valor en la implementación de devolución de llamada corporativa aprobada y en las implementaciones de vista previa solo cuando la autorización deba almacenarse en una base de datos de vista previa aislada.                                                                                                                                                                      |
| `AGENT_NATIVE_BUILDER_RELAY_TARGET_ORIGINS` | Lista de permitidos, separada por comas y solo para la devolución de llamada corporativa, de orígenes de vista previa exactos y de confianza (por ejemplo, `https://0123456789abcdef01234567--content.netlify.app`). Establécela únicamente en la implementación de devolución de llamada corporativa. Los orígenes de Netlify deben usar un enlace permanente inmutable y específico de la implementación con un ID hexadecimal de 24 caracteres. Se rechazan los alias mutables `deploy-preview-*`, los comodines y los sufijos de dominio. |

Las variables de conexión de la base de datos (`DATABASE_URL`, `DATABASE_AUTH_TOKEN`, `<APP_NAME>_DATABASE_URL` por aplicación) se encuentran en [Base de datos](/docs/server-database#production).

## Configuración sensible para producción {#env-required-prod}

Estos ajustes cubren el comportamiento sensible para producción. Una
aplicación independiente que usa la autenticación del framework necesita un
`BETTER_AUTH_SECRET` estable y una base de datos persistente. La URL pública
de autenticación se infiere de la solicitud, la plantilla conocida o la
plataforma de alojamiento cuando no está configurada. Los ajustes de espacio
de trabajo y A2A dependen de esas funciones. Los valores faltantes fallan de
forma segura o recurren a un comportamiento más débil con una advertencia
clara.

| Variable                                    | Descripción                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BETTER_AUTH_SECRET`                        | Cadena aleatoria de 32 o más caracteres. Firma las cookies de sesión y es el valor de respaldo para `OAUTH_STATE_SECRET` y los valores cifrados locales de la aplicación. También es un candidato de lectura heredado para el texto cifrado existente de la bóveda compartida. Obligatorio de forma estricta: el framework lanza un error al arrancar si falta en producción.                                                                                                   |
| `BETTER_AUTH_URL`                           | Anulación opcional del origen público de esta aplicación (por ejemplo, `https://mail.example.com`). El framework lo infiere del contexto de la solicitud, la plantilla conocida y la plataforma de alojamiento cuando no está configurada.                                                                                                                                                                                                                                      |
| `ANTHROPIC_API_KEY`                         | Clave de API para el agente de producción integrado. **En implementaciones multiinquilino**, el framework se niega a recurrir a esta cuando el usuario no tiene una clave por usuario. Es obligatorio traer tu propia clave. Las instalaciones autoalojadas de un solo inquilino la usan como clave global.                                                                                                                                                                     |
| `OAUTH_STATE_SECRET`                        | Clave HMAC dedicada para los sobres de estado de OAuth (Google, Atlassian, Zoom). Recurre a `BETTER_AUTH_SECRET` cuando no está configurada, pero se recomienda un valor dedicado para que rotar una no invalide la otra. Genérala con `openssl rand -hex 32`.                                                                                                                                                                                                                  |
| `A2A_SECRET`                                | HMAC compartido para JSON-RPC A2A entre aplicaciones y traspasos firmados en segundo plano. Obligatorio para implementaciones alojadas de espacios de trabajo y funciones A2A. Sin ella, esos endpoints fallan de forma cerrada en producción. Cuando no se establece una clave de bóveda de espacio de trabajo dedicada, el texto cifrado de la bóveda compartida usa una clave derivada de este valor para ese propósito, así que rotarla también rota la clave de la bóveda. |
| `WORKSPACE_SECRETS_ENCRYPTION_KEY`          | Clave AES-256-GCM estable y preferida para la bóveda de secretos compartida cifrada en reposo. Establece el mismo valor en cada aplicación que lea la bóveda. Es independiente del cifrado local de OAuth/credenciales de la aplicación, de modo que la confianza A2A puede rotar sin dejar filas de la bóveda inaccesibles. El texto cifrado existente de A2A, Better Auth y claves de aplicación se migra en las lecturas exitosas.                                           |
| `WORKSPACE_SECRETS_ENCRYPTION_KEY_PREVIOUS` | Clave anterior opcional de la bóveda de espacio de trabajo, usada solo durante una ventana de rotación. Impleméntala junto con la nueva `WORKSPACE_SECRETS_ENCRYPTION_KEY`, deja que las lecturas exitosas vuelvan a cifrar las filas, y elimínala después de la migración.                                                                                                                                                                                                     |
| `SECRETS_ENCRYPTION_KEY`                    | Clave combinada heredada para el cifrado local de la aplicación y la bóveda compartida. Sigue siendo compatible, pero las nuevas implementaciones multiaplicación deberían usar `WORKSPACE_SECRETS_ENCRYPTION_KEY` para la bóveda compartida, de modo que cambiar el cifrado del espacio de trabajo no cambie el texto cifrado de OAuth local de la aplicación.                                                                                                                 |

## Autenticación e identidad {#env-auth}

Las credenciales del proveedor OAuth (Google, GitHub), los valores de
respaldo estáticos de portador MCP (`ACCESS_TOKEN` / `ACCESS_TOKENS`) y los
interruptores de verificación de correo electrónico están documentados en
[Autenticación](/docs/authentication). Configúralos allí según el modo de
autenticación que elijas.

## Webhooks entrantes {#env-webhooks}

Cada integración de mensajería requiere su propio secreto de firma en
producción (los manejadores fallan de forma cerrada ante solicitudes
falsificadas cuando falta el secreto). Las variables por integración se
enumeran en [Mensajería](/docs/messaging) y [Seguridad](/docs/security). Solo
para desarrollo local, `AGENT_NATIVE_ALLOW_UNVERIFIED_WEBHOOKS=1` vuelve a
optar por "advertir y aceptar". Nunca la establezcas en producción.

## Configuración de seguridad (opcional) {#security-config}

Los valores predeterminados son estrictos. Un puñado de flags opcionales
relajan el comportamiento (trazas de pila de depuración, webhooks no
verificados, respaldo de clave con alcance de espacio de trabajo, el
interruptor multiorganización del hub MCP, escrituras de variables de entorno
en tiempo de ejecución). Están documentados con sus compensaciones de
seguridad en [Seguridad](/docs/security). No los establezcas a menos que
quieras específicamente la ruta relajada.

## Herencia del `.env` del espacio de trabajo {#env-inheritance}

Dentro de un espacio de trabajo, el `.env` raíz se carga automáticamente en
cada aplicación, así que las claves compartidas como `ANTHROPIC_API_KEY`,
`A2A_SECRET`, `BETTER_AUTH_SECRET` y `OAUTH_STATE_SECRET` solo necesitan
establecerse una vez. El `apps/<name>/.env` de cada aplicación prevalece en
caso de conflicto.

## Generación de secretos robustos {#env-generate-secrets}

Para cualquier secreto marcado como "32 o más caracteres aleatorios"
(`BETTER_AUTH_SECRET`, `OAUTH_STATE_SECRET`, `A2A_SECRET`,
`WORKSPACE_SECRETS_ENCRYPTION_KEY`, `SECRETS_ENCRYPTION_KEY`,
`AGENT_NATIVE_BUILDER_RELAY_SECRET`), genera valores nuevos con:

```bash
openssl rand -hex 32
```

Rota las claves de firma/sesión reemplazando la variable de entorno en cada
instancia y volviendo a implementar. Las sesiones y los sobres de estado de
OAuth firmados con la clave anterior dejan de ser válidos, así que es posible
que los usuarios deban iniciar sesión de nuevo. Rota
`WORKSPACE_SECRETS_ENCRYPTION_KEY` con la ventana `..._PREVIOUS` descrita
anteriormente para que las filas cifradas de la bóveda sigan siendo legibles
mientras se migran.
