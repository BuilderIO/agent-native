# Tu primera función

Esta página es para desarrolladores que amplían la [plantilla de Chat](/docs/template-chat). Cubre el único archivo que renderiza la pantalla de chat inicial, y luego recorre todo lo que el agente suele tocar cuando pides una función real.

## Primer código a inspeccionar {#first-code}

- `actions/hello.ts` es el comportamiento inicial que el agente puede llamar.
  Reemplázalo o agrega acciones junto a él.
- `app/routes/_index.tsx` renderiza la superficie de chat de página completa.
  Ajusta aquí las sugerencias, el estado vacío, el composer o el diseño
  circundante.
- `AGENTS.md` le indica al agente integrado cómo trabajar dentro de esta app.

## Primeras ediciones {#first-edits}

La mayoría de las primeras funciones siguen la misma forma: una tabla, una o dos acciones, una ruta, una entrada de navegación y una actualización de `AGENTS.md`. Pídele al agente:

> Agrega un modelo de datos para `notes`. Una nota tiene un id, título, cuerpo y propietario. Renderiza una página de notas en `/notes`, agrega acciones de crear/listar, y mantén al chat capaz de crear notas.

Chat no incluye ningún `server/db/schema.ts` (consulta [Qué incluye](/docs/template-chat#what-ships)), así que el primer cambio es un archivo nuevo, siguiendo la misma forma `table`/`text`/`ownableColumns` que usan todas las demás plantillas:

El resto de la función se deriva de ahí:

- `actions/create-note.ts`: un `defineAction` con un esquema Zod (`title`, `body`), con la misma forma que `actions/hello.ts`.
- `actions/list-notes.ts`: una acción de solo lectura (`readOnly: true`, como `actions/view-screen.ts`) que consulta la nueva tabla a través de `accessFilter`.
- `app/routes/notes.tsx`: una ruta nueva; la app usa enrutamiento por sistema de archivos (`flatRoutes()` en `app/routes.ts`), así que agregar el archivo basta para montar `/notes`.
- Una entrada nueva en el array `navItems` de `app/components/layout/Sidebar.tsx` que apunte a `/notes`.
- Una adición a `AGENTS.md` que le indique al agente que notes existen y qué acciones las gestionan.

Una acción nueva es llamable por el chat en cuanto existe: cada `defineAction` es una herramienta por defecto a menos que establezca `agentTool: false`. Sin embargo, no necesariamente estará en la primera solicitud del modelo: `server/plugins/agent-chat.ts` define `INITIAL_TOOL_NAMES = ["view-screen", "navigate", "hello"]`, que controla solo qué esquemas de herramientas se envían en el primer turno. Todo lo demás, incluida una `create-note` recién creada, sigue siendo alcanzable a través de `tool-search` y se carga según demanda; agrega un nombre a esa lista solo si quieres que esté en el conjunto de herramientas por defecto del modelo desde el primer mensaje.

## Usa tu propio backend de agente {#own-agent-backend}

La plantilla usa el bucle app-agent integrado por defecto. Para conectar un backend personalizado, cambia el runtime de chat detrás del plugin de chat del agente en lugar de reescribir el UI. La ruta de Chat debe seguir siendo un renderizador delgado alrededor de la superficie de chat compartida; la elección del backend pertenece al plugin de servidor/adaptador de runtime.

Usa esto cuando la orquestación de tu modelo ya viva en otro lugar, pero aún quieras una app con autenticación, hilos, acciones, estado de UI y páginas desplegables.
