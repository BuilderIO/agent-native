# Chat

Chat es el punto de partida más sencillo de Agent-Native: un shell al estilo
ChatGPT con el chat en el centro, una lista de hilos, autenticación y una
acción de ejemplo, sin nada específico de dominio. Está pensado para
desarrolladores que quieren una app real y desplegable sobre la que construir
su propio agente y sus propias pantallas, no un producto terminado para un
trabajo concreto.

Si quieres una forma de producto de dominio ya terminada, empieza con
[Calendario](/docs/template-calendar), [Mail](/docs/template-mail),
[Content](/docs/template-content), [Forms](/docs/template-forms),
[Analytics](/docs/template-analytics), u otra plantilla de dominio. Si de
verdad todavía no necesitas un UI de navegador, consulta [Automation-First
Apps](/docs/pure-agent-apps).

## Empieza {#get-started}

```bash
npx @agent-native/core@latest create my-chat-app --standalone --template chat
```

Consulta [Chat: Guía para desarrolladores](/docs/template-chat-developers#quick-start)
para la instalación, la primera ejecución y cómo conectar un LLM. Para
trabajo automation-first sin ningún UI de navegador, crea el andamiaje con
`--headless` en su lugar:

```bash
npx @agent-native/core@latest create my-agent --headless
```

Úsalo para jobs programados, colas, bucles de CLI o workflows de agentes
externos donde el chat y las páginas de app todavía no son útiles. La
invariante clave sigue siendo la misma: las acciones son la superficie
compartida para el chat, el UI, HTTP, MCP, A2A y CLI. Consulta
[Automation-First Apps](/docs/pure-agent-apps) para profundizar en ese camino.

## Qué incluye {#what-ships}

<Comparison>

### :green: Incluido

- Chat de página completa en `/` usando la superficie de chat del framework e
  hilos de chat duraderos
- Lista de hilos en la barra lateral de la app para crear, reabrir, renombrar,
  fijar y archivar chats
- El bucle app-agent integrado, preconfigurado para el plugin de chat
- Autenticación mediante Better Auth: inicio de sesión, registro, sesiones,
  organizaciones
- Un directorio de acciones con un ejemplo (`actions/hello.ts`) además de las
  acciones estándar `view-screen` y `navigate`
- Las tablas principales del framework para hilos de chat, estado de la
  aplicación, configuración, sesiones, recursos e historial de ejecuciones,
  además de una página de administración de Database y un panel de
  Observability, montados los abras o no
- Sincronización en vivo (`useDbSync`) ya conectada para que el UI se
  actualice cuando el agente escribe en SQL
- Rutas de Extensions montadas por defecto, para mini-apps aisladas que tus
  usuarios construyan dentro del chat más adelante
- AGENTS.md con guía chat-first para agregar acciones, rutas, skills y estado
  de la aplicación

### :red: No incluido

- Tablas de dominio o datos iniciales
- Paneles, listas, gráficos, formularios o integraciones de proveedores
- Acciones específicas de dominio más allá del stub de ejemplo

</Comparison>

Chat es un shell delgado y útil por defecto para tu propio
agente, no un producto de dominio que finge ser genérico.

## Cuándo elegirlo {#when-to-pick}

- **Quieres una app básica con la que los usuarios puedan hablar de
  inmediato** y luego ampliarla con acciones y UI.
- **Quieres la vía de entrada por defecto de Agent-Native**: primero el chat,
  luego acciones, resultados nativos y páginas de app.
- **Quieres conectar el backend de tu propio agente a un UI de chat
  familiar** mientras conservas la forma de acciones, estado, autenticación y
  despliegue de Agent-Native.
- **Estás prototipando una herramienta interna personalizada** que no
  coincide con ninguna plantilla de dominio.
