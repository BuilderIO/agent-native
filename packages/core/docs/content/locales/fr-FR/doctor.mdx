# Doctor

Les apps et workspaces générés contiennent du code source modifiable dans le workflow de développement du dépôt, y compris par un frame d’agent auquel les outils de workspace et d’écriture ont été accordés intentionnellement. `agent-native doctor` analyse le code source pour vérifier les invariants de sécurité critiques. Il est en lecture seule : il ne modifie jamais le code, il signale seulement les résultats.

`agent-native doctor` vérifie les problèmes de sécurité et de migration. `migration-manifest` détecte les imports répertoriés dans le `migration-manifest.json` installé et ne peut pas être désactivé. `feature-dependencies` détecte les fonctionnalités configurées dont le package peer optionnel est introuvable.

Lancez le contrôle préalable de migration :

```bash
agent-native doctor --only migration-manifest
```

Prévisualiser la mise à niveau et le diff du codemod sans écrire de fichiers :

```bash
npx agent-native upgrade --codemods --dry-run
```

Appliquer les réécritures d’imports prises en charge :

```bash
npx agent-native upgrade --codemods
```

`--codemods` applique les réécritures prises en charge par défaut. Ajoutez `--dry-run` pour prévisualiser sans écrire de fichiers. Vérifiez le diff et les avertissements avant l’application. `--yes` est accepté par compatibilité et ne change pas le comportement. `migration-manifest` ne peut pas être désactivé. Les entrées `planned` sont uniquement des avertissements et ne sont pas réécrites. Les entrées actives sont des constats ; le codemod ne les réécrit que si l’export de destination est installé. Les exports supprimés nécessitent une migration manuelle. Suivez le guide lié au constat ou le [guide de migration Core 0.198.0](/docs/upgrading-core-ui), qui répertorie `ts-morph` et les packages optionnels des fonctionnalités. `guardsRun` dans la sortie JSON liste les contrôles réellement exécutés.

Le CLI ajoute à chaque nouvelle app et à chaque workspace les commandes `pnpm doctor` et `pnpm agent-native:doctor`. Depuis la racine d'un workspace, chaque app sous `apps/<name>` est vérifiée. Les builds échouent par défaut en présence de constats; utilisez `failOnBuild: false` uniquement comme exception revue.

Les entrées marquées `planned` sont uniquement signalées comme avertissements et ne sont pas réécrites. Les entrées actives sont des constats; le codemod ne les réécrit que si l'export de destination est installé.
