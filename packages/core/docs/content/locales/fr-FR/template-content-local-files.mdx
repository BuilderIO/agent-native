# Content : Sources de dossiers locaux

Content a un seul modèle de données : chaque page est stockée en SQL,
appartient à un **espace** et figure dans la base système **Files** de cet
espace. Un dossier Markdown ou MDX local est une source connectée à Files, au
même titre que la collaboration, le partage, les commentaires, l'historique,
la recherche, les propriétés de base de données et la même surface d'actions
que toute autre page.

Chaque utilisateur possède un espace personnel, chaque organisation accessible
possède son espace, et le catalogue personnel **Workspaces** détermine les
espaces affichés. Files est une base Content normale : ses propriétés, filtres,
tris, groupes et vues enregistrées peuvent aussi rendre la barre latérale.

## Connecter un dossier

<Steps>

### Ouvrir l'écran de dossier local

Choisissez un dossier via l'API File System Access du navigateur ou via
Agent-Native Desktop. Content ne conserve dans SQL que l'identifiant opaque de
connexion, les chemins relatifs, les empreintes et les métadonnées de source.
Il n'y stocke jamais le chemin absolu, le handle du navigateur ou le corps brut
des fichiers.

### Choisir où le dossier se rattache

Rattachez-le à la base Files d'un espace personnel ou organisationnel
existant, ou créez un espace privé associé au dossier avec sa propre base
Files.

### Choisir une stratégie de vérité

| Politique                | Comportement                                                             |
| ------------------------ | ------------------------------------------------------------------------ |
| `database_primary`       | Content fait autorité ; les modifications du dossier sont examinées avant d'être appliquées |
| `source_primary`         | Le dossier fait autorité tant qu'aucune modification Content concurrente n'existe |
| `reviewed_bidirectional` | Les modifications dans les deux sens nécessitent un examen en cas de conflit |

</Steps>

La synchronisation matérialise les fichiers comme des pages SQL ordinaires. En
cas de modifications concurrentes, elle crée un changement à examiner au lieu
d'écraser un côté. La déconnexion conserve les pages et les fichiers locaux.

## Démarrer depuis un dépôt

```bash
npx @agent-native/core@latest content .
```

La commande démarre l'application Content normale, enregistre le dossier
comme source et ouvre l'écran de connexion.

## Configuration

```json
{
  "version": 1,
  "apps": {
    "content": {
      "roots": [
        {
          "name": "Docs",
          "path": "docs",
          "kind": "docs",
          "extensions": [".md", ".mdx"],
          "source": {
            "type": "local-folder",
            "connectionId": "local-folder:<opaque-id>",
            "truthPolicy": "source_primary"
          }
        }
      ],
      "components": "components",
      "extensions": "extensions"
    }
  }
}
```

Les identifiants de frontmatter préservent l'identité d'une page lors d'un
renommage ou déplacement. Les composants et extensions locaux continuent de
passer par le pont local de confiance.

## Migrer depuis Local File Mode

<Callout tone="info">

Ignorez cette section si vous configurez un dossier local pour la première
fois. Elle ne s'applique qu'à un manifeste antérieur au modèle de source
actuel.

</Callout>

Pour migrer, supprimez `mode: "local-files"` et
`AGENT_NATIVE_MODE=local-files`, conservez les racines et ajoutez la section
`source`.

Après la première connexion et synchronisation, vérifiez que :

- Le dossier apparaît comme source sur la base Files prévue.
- Chaque page importée appartient à l'espace prévu.
- Les propriétés personnalisées et les vues de barre latérale enregistrées
  fonctionnent normalement.
- Les modifications concurrentes apparaissent comme des changements à
  examiner.
- La déconnexion préserve les pages de la base de données et les fichiers sur
  le disque.
