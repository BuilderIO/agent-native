# Guide développeur

Cette page est destinée à toute personne qui personnalise le modèle Calendrier ou l'étend : le démarrage rapide, chaque action, le modèle de données, la surface de routes, et comment y ajouter des éléments. Consultez [Calendrier](/docs/template-calendar) pour ce que fait l'application.

## Démarrage rapide

Ceci vous guide pour exécuter Calendrier depuis rien d'installé jusqu'à un
Google Calendar connecté. Les commandes sont identiques que vous soyez dans Terminal sur
macOS ou PowerShell/Command Prompt sur Windows, ce sont de simples outils Node.js.

<Steps>

### Créer l'application

```bash
npx @agent-native/core@latest create my-calendar --standalone --template calendar
cd my-calendar
pnpm install
```

Cela nécessite [Node.js](https://nodejs.org) 22 ou une version plus récente, et
[pnpm](https://pnpm.io) installé au préalable. Consultez
[Bien démarrer](/docs/getting-started) si vous n'avez installé ni l'un ni l'autre
encore, ou si vous n'avez pas de connexion LLM (Builder.io, une clé Anthropic/OpenAI,
ou Ollama en local) configurée.

### Démarrer le serveur de développement

```bash
pnpm dev
```

L'application s'ouvre à `http://localhost:8082`. Si elle ne s'ouvre pas automatiquement,
visitez cette URL dans votre navigateur. Calendrier fonctionne entièrement avec Google
déconnecté. Vous ne rencontrerez une erreur que si vous essayez une action qui en a besoin
avant de vous connecter.

### Connecter Google Calendar

Dans l'application, ouvrez **Paramètres**, et dans l'onglet **Général** trouvez la carte
**Google Calendar**, puis cliquez sur **Connecter Google Calendar**. Cela ouvre un
assistant de configuration :

1. **Créer un projet Google Cloud**, si vous n'en avez pas déjà un à utiliser :
   dans la [Console Google Cloud](https://console.cloud.google.com/), cliquez sur le
   menu déroulant de projet près du haut de la page, puis **Nouveau projet**. Donnez-lui
   un nom, cliquez sur **Créer**, et attendez la notification indiquant qu'il est
   prêt. Assurez-vous qu'il est sélectionné dans ce même menu déroulant avant de continuer.
2. **Activer l'API** : avec votre projet sélectionné, allez dans **APIs & Services
   → Bibliothèque**, recherchez « Google Calendar API », ouvrez-la, et cliquez sur
   **Activer**.
3. **Configurer l'écran de consentement** : sous **APIs & Services → Écran de
   consentement OAuth**, configurez-en un (« Externe » convient pour le développement).
4. **Créer des identifiants** : sous **APIs & Services → Identifiants**, créez
   un ID client OAuth de type « Application Web », et ajoutez
   `http://localhost:8082/_agent-native/google/callback` comme URI de
   redirection autorisée (8082 est le port de développement par défaut de Calendrier).
5. **Ajouter les identifiants** : téléchargez le fichier JSON des identifiants et importez-le dans
   l'assistant, ou activez « Saisir manuellement » et entrez l'ID client et le secret
   client directement.

Calendrier enregistre ces informations dans son propre coffre-fort de secrets, pas dans un fichier `.env`,
si bien que cette étape est identique sur Windows et macOS. Les jetons se rafraîchissent automatiquement une fois
connectés.

### Connecter Zoom (facultatif)

Contrairement à Google, Zoom n'a pas de formulaire dans Paramètres. Créez un fichier `.env` à la
racine du projet (ou ajoutez-le à celui qui existe déjà) avec :

```text
ZOOM_CLIENT_ID=your-client-id
ZOOM_CLIENT_SECRET=your-client-secret
```

Obtenez un ID client et un secret depuis une [application OAuth Zoom](https://marketplace.zoom.us/)
(Zoom Marketplace → Develop → Build App → OAuth), avec
`/_agent-native/zoom/callback` comme URI de redirection, puis redémarrez `pnpm dev`
pour qu'il prenne en compte les nouvelles valeurs. Sans Zoom connecté, les liens de réservation peuvent
toujours proposer Google Meet, mais pas Zoom.

</Steps>

<Callout tone="warning">

Sur Windows, certains éditeurs ajoutent une extension `.txt` cachée quand vous enregistrez un fichier
nommé `.env`, laissant un `.env.txt` que Calendrier ne lit jamais. Dans l'Explorateur de
fichiers, activez « Extensions de noms de fichiers » (onglet Affichage) et confirmez que le fichier
enregistré s'appelle exactement `.env`, sans rien après.

</Callout>

<Callout tone="info">

**Les événements vivent dans Google Calendar, pas dans SQL.** Chaque action d'événement appelle directement l'API Google Calendar, il n'existe pas de table d'événements locale. Seuls les liens de réservation, les réservations, la disponibilité et l'état de connexion sont stockés localement. Ne lisez et n'écrivez jamais de données d'événement en SQL brut.

</Callout>

## Inventaire des actions

Chaque opération est un fichier TypeScript dans `templates/calendar/actions/`, monté automatiquement sur `POST /_agent-native/actions/:name`.

### Événements et invités

Les données d'événement vivent dans Google Calendar, jamais en SQL.

| Action | Ce qu'elle fait |
| --- | --- |
| `list-events` | Lister les événements sur une plage de dates |
| `search-events` | Rechercher des événements par requête |
| `get-event` | Lire un événement par son id |
| `create-event` | Créer un événement, incluant la récurrence (RRULE), les lieux de travail, et les types de statut (`outOfOffice`, `focusTime`) |
| `update-event` | Mettre à jour un événement, incluant la récurrence, les lieux de travail, et les types de statut |
| `delete-event` | Supprimer un événement |
| `manage-event-draft` | Mettre en scène une invitation non envoyée pour révision par l'utilisateur avant que quoi que ce soit ne soit écrit ou que les invités ne soient notifiés |
| `rsvp-event` | Accepter, décliner, ou marquer comme provisoire sur une invitation |
| `get-attendee-timezones` | Lire les substitutions de fuseau horaire par invité |
| `set-attendee-timezone` | Définir une substitution de fuseau horaire par invité pour que son heure locale continue de s'afficher correctement |

### Disponibilité et recherche de créneaux

| Action | Ce qu'elle fait |
| --- | --- |
| `get-availability` | Lire l'emploi du temps hebdomadaire, le fuseau horaire, le tampon, le préavis, et les paramètres de fenêtre d'anticipation |
| `update-availability` | Mettre à jour l'emploi du temps hebdomadaire, le fuseau horaire, le tampon, le préavis, et les paramètres de fenêtre d'anticipation |
| `check-availability` | Trouver les créneaux libres pour une date |
| `find-a-time` | Recherche de créneau libre partagé entre un organisateur et des participants nommés, combinant le libre/occupé Google avec les conflits locaux |

### Liens de réservation et réservations

| Action | Ce qu'elle fait |
| --- | --- |
| `create-booking-link` | Créer un lien de réservation |
| `update-booking-link` | Mettre à jour un lien de réservation |
| `duplicate-booking-link` | Dupliquer un lien de réservation, incluant les co-hôtes (`hosts`) |
| `list-booking-links` | Lister les liens de réservation accessibles |
| `list-bookings` | Lister les rendez-vous confirmés |

### Calendriers externes

Flux ICS en lecture seule.

| Action | Ce qu'elle fait |
| --- | --- |
| `add-external-calendar` | S'abonner à un flux ICS/webcal en lecture seule |
| `list-external-calendars` | Lister les flux abonnés |
| `remove-external-calendar` | Retirer un flux abonné |
| `update-external-calendars` | Mettre à jour les flux abonnés |

### Personnes et superpositions

| Action | Ce qu'elle fait |
| --- | --- |
| `search-people` | Rechercher dans les contacts Google et l'annuaire Workspace |
| `get-overlay-people` | Lire les autres personnes dont les calendriers sont épinglés dans votre vue |
| `update-overlay-people` | Mettre à jour les autres personnes dont les calendriers sont épinglés dans votre vue |

### Zoom

| Action | Ce qu'elle fait |
| --- | --- |
| `get-zoom-status` | Lire le statut de connexion Zoom de l'utilisateur actuel. Connecter et déconnecter se passent via les routes `/_agent-native/zoom/*`, pas une action, puisque OAuth a besoin de la session navigateur connectée |

### Connexion et synchronisation Google Calendar

| Action | Ce qu'elle fait |
| --- | --- |
| `connect-google-calendar` | Retourner l'URL de connexion OAuth pour la session navigateur connectée |
| `sync-google-calendar` | Forcer une resynchronisation |

### Paramètres et préférences

| Action | Ce qu'elle fait |
| --- | --- |
| `get-settings` | Lire les paramètres au niveau utilisateur |
| `update-settings` | Mettre à jour les paramètres au niveau utilisateur |
| `update-calendar-visual-preferences` | Mettre à jour les préférences d'affichage locales uniquement (couleurs d'événement, week-ends masqués). Ne touche jamais Google Calendar |

### Navigation et état de l'interface

| Action | Ce qu'elle fait |
| --- | --- |
| `navigate` | Déplacer l'interface vers une vue, une date, ou un événement |
| `view-screen` | Lire la vue actuelle pour l'agent |

### Escalade vers l'API fournisseur

L'API brute Google Calendar (et CRM connecté), pour quand les actions ci-dessus sont trop étroites.

| Action | Ce qu'elle fait |
| --- | --- |
| `provider-api-catalog` | Lister les API fournisseur brutes disponibles à appeler directement |
| `provider-api-docs` | Lire la documentation d'un point de terminaison d'API fournisseur brut |
| `provider-api-request` | Appeler directement l'API brute Google Calendar (ou CRM connecté) |
| `list-staged-datasets` | Lister les grands balayages mis en scène pour être interrogés plutôt que de retourner des résultats bruts |
| `query-staged-dataset` | Interroger un jeu de données mis en scène |
| `delete-staged-dataset` | Supprimer un jeu de données mis en scène |

## Une action passée en revue

`create-booking-link` montre des modèles qui valent la peine d'être réutilisés dans n'importe quelle action : valider l'entrée avant qu'elle ne touche la base de données, appliquer une règle à travers deux tables, résoudre en sécurité l'utilisateur connecté, et normaliser une forme d'entrée flexible une seule fois plutôt que dans chaque lecteur.

String(body.description).trim() : null,\n        duration: durationInput.duration,\n        durations: durationInput.durations\n          ? JSON.stringify(durationInput.durations)\n          : null,\n        hosts: serializeBookingHosts(body.hosts, ownerEmail),\n        customFields: body.customFields\n          ? JSON.stringify(body.customFields)\n          : null,\n        conferencing: body.conferencing\n          ? JSON.stringify(body.conferencing)\n          : null,\n        color: body.color ? String(body.color).trim() : null,\n        isActive: body.isActive ?? true,\n        ownerEmail,\n        orgId: getRequestOrgId(),\n        createdAt: now,\n        updatedAt: now,\n      });\n\n    const created = await getDb()\n      .select()\n      .from(schema.bookingLinks)\n      .where(eq(schema.bookingLinks.id, id));\n    return rowToBookingLink(created[0]);\n  },\n});'

      path: "shared/api.ts",
      note: "types TypeScript partagés utilisés par le serveur et le client",
    },
  ]}
/>

Deux routes héritées restent montées pour les liens partagés avant qu'un schéma d'URL ne change : `book.$slug.tsx` (sans segment de nom d'utilisateur) et `meet.$username.$slug.tsx`, qui se canonicalisent toutes les deux vers `/book/:username/:slug`. `_app.team.tsx` redirige vers `/settings/organization`, la gestion d'équipe vit dans Paramètres, pas dans une page séparée.

## Le personnaliser

Chaque partie de l'application est une source modifiable. Commencez ici :

- `templates/calendar/actions/` — ajoutez un nouveau fichier avec `defineAction` pour exposer une nouvelle capacité à la fois à l'agent et au frontend.
- `templates/calendar/app/routes/` — l'interface, listée ci-dessus.
- `templates/calendar/server/db/schema.ts` — ajoutez des colonnes ou des tables avec Drizzle. Gardez le code indépendant du dialecte pour que le modèle s'exécute sur SQLite, Postgres, Turso, D1 et Neon.
- `templates/calendar/server/lib/` — intégrations fournisseur : `google-calendar.ts`, `zoom.ts`, `people-search.ts`, `ical-fetcher.ts`, `find-time.ts`, `provider-api.ts`.
- `templates/calendar/AGENTS.md` — instructions pour l'agent. Mettez ceci à jour quand vous enseignez à l'agent de nouvelles capacités ou conventions.
- `templates/calendar/.agents/skills/` — modèles détaillés que l'agent suit. Skills pertinents : `event-management`, `availability-booking`, `real-time-sync`, `storing-data`, `delegate-to-agent`, `frontend-design`.
- `templates/calendar/shared/api.ts` — les types TypeScript partagés (`CalendarEvent`, `BookingLink`, `ExternalCalendar`, `ConferencingConfig`, etc.) utilisés à la fois par le serveur et le client.

Si vous ajoutez une fonctionnalité, n'oubliez pas de mettre à jour les quatre zones : interface, action, skill ou entrée AGENTS.md, et tout état d'application dont l'agent a besoin. C'est ce qui maintient l'agent et l'interface en parité.
