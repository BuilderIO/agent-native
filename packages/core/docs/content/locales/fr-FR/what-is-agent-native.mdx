# Qu’est-ce qu’Agent-Native ?

Agent-Native est un framework TypeScript open source pour créer des agents
autonomes avec des interfaces intuitives. Vous définissez chaque capacité une
seule fois sous forme d’[action](/docs/actions-overview) : une fonction typée que
l’agent utilise comme outil et que l’UI appelle depuis le code.

## Pourquoi créer des agents avec des UI


Les agents de programmation peuvent donner l’impression qu’un champ de texte
suffit. Mais ce champ n’est qu’une partie de leur environnement de travail. Le
code fournit le contexte, les outils leur donnent des moyens d’agir clairement,
et les fichiers, tests et aperçus rendent les résultats visibles.

La plupart des activités intellectuelles ne disposent pas de cette structure.
Face à un champ de texte vide, les personnes doivent deviner ce que l’agent peut
faire, le contexte dont il dispose et ce qu’elles doivent lui demander.

Une UI apporte ce qui manque au champ de texte. Elle rend les capacités de
l’agent visibles, intègre le contexte et les workflows à l’expérience, et permet
de voir et de façonner le travail au fil de son avancement.

Agent-Native permet de créer des agents de cette manière. L’UI offre des points
de départ clairs sans réduire l’agent à un workflow figé. Comme l’agent et l’UI
utilisent les mêmes capacités, les personnes peuvent déléguer du travail à
l’agent, l’examiner ou le modifier dans l’UI, puis passer de l’un à l’autre sans
perdre leur progression.

Agent-Native relie l’agent et l’UI grâce à trois fondations partagées :

- **[Actions partagées](/docs/actions-overview).** Chaque capacité est définie
  une seule fois. L’agent l’appelle comme un outil et l’UI l’appelle depuis le
  code. Les deux chemins utilisent la même validation, les mêmes autorisations
  et la même implémentation.
- **[Données partagées](/docs/server-database).** Les actions lisent et mettent à
  jour les mêmes données. Le travail de l’agent apparaît donc dans l’UI, et le
  travail effectué dans l’UI reste accessible à l’agent.
- **[État partagé de l’application](/docs/context-awareness).** L’état de
  l’application décrit ce qui se passe dans l’UI, comme la page en cours,
  l’enregistrement sélectionné ou la vue active. Agent-Native fournit l’état
  pertinent à l’agent comme contexte pour qu’il comprenne sur quoi la personne
  travaille.

L’agent ne clique pas dans l’UI. Il passe par la même couche d’actions que l’UI.

Par exemple, une personne peut attribuer un ticket de support dans l’UI ou
demander à l’agent de le faire. Les deux chemins exécutent la même action et
mettent à jour le même ticket. La personne peut examiner le résultat dans l’UI,
le modifier, puis laisser l’agent poursuivre.

## Quand utiliser Agent-Native ?

Agent-Native convient lorsque :

- l’agent doit effectuer un véritable travail, pas seulement répondre ;
- les personnes ont besoin d’une UI pour voir ce que l’agent peut faire et pour
  examiner, modifier, approuver ou partager son travail ;
- les personnes doivent pouvoir passer de l’agent à l’UI sans perdre la
  progression ni le contexte.

Pour une seule réponse générée, appelez directement un modèle. Pour un flux fixe
et prévisible, une logique d’application ou une automatisation classique est plus
simple. Utilisez Agent-Native lorsque l’agent et l’UI ont tous deux un rôle
continu dans le même travail.
