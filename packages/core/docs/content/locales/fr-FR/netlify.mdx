# Netlify

Le préréglage Nitro `netlify` fonctionne bien et, en pratique, nous a donné des démarrages à froid rapides (~200ms TTFB) pour les templates qui communiquent avec un Postgres externe (Neon). Pour une configuration minimale en dehors du scaffold généré, définissez le préréglage dans `vite.config.ts` :

```ts filename="vite.config.ts"
export default defineConfig({
  plugins: [agentNative({ nitro: { preset: "netlify" } })],
});
```

Dans le scaffold Chat généré, l’import reste `agentNative`. La configuration l’assigne à un alias
local `agentNativePlugins` avec une assertion de type, puis étale le tableau de plugins renvoyé
pour aligner les types des paquets Vite. Il accepte les mêmes options que l’exemple `agentNative`
ci-dessus. Pour déployer ce scaffold sur Netlify, ajoutez `nitro: { preset: "netlify" }` aux
options de l’appel `agentNativePlugins({ ... })` existant. Conservez les autres plugins, options et
alias propres à Chat.

…soit définissez `NITRO_PRESET=netlify` au moment du build.

Pour une application autonome, construisez la sortie Netlify puis déployez les assets et les fonctions :

```bash
NITRO_PRESET=netlify pnpm build
npx netlify deploy --prod --dir=dist --functions=.netlify/functions-internal
```

Avant le premier déploiement en production, définissez `DATABASE_URL` et un `BETTER_AUTH_SECRET` stable dans les variables d’environnement du site Netlify. Ne vous fiez pas à la base PGlite locale ; `DATABASE_URL` doit pointer vers une base PostgreSQL persistante accessible par la fonction déployée.

Pour un workspace, déployez chaque application depuis un seul site Netlify en exécutant :

```bash
npx @agent-native/core@latest deploy --preset netlify
```

Le build de workspace écrit les assets statiques sous `dist/_workspace_static/` et achemine chaque application vers sa propre fonction Netlify sans redirections d'assets forcées, de sorte que des fichiers comme `/mail/assets/...` sont servis statiquement avant que la fonction serveur ne traite les routes de l'application.

## Maintien à chaud et bases de données scale-to-zero {#netlify-keep-warm}

Lorsqu'elle est activée, le build Netlify émet une fonction planifiée qui demande `/_agent-native/health` **chaque minute**. Cela maintient au chaud la fonction serveur et sa base de données pour que le prochain visiteur après une période d'inactivité ne paie pas un démarrage à froid (1 à 5s sur Neon).

Le maintien à chaud est **désactivé par défaut** car un réveil une fois par minute empêche l'auto-suspension sur les bases de données scale-to-zero facturées à l'usage. Sur un Neon en offre gratuite, cela peut épuiser le quota de calcul, et la base de données rejette alors **toutes** les lectures en cours de session. Le symptôme est une application morte, pas une application lente. Définissez `AGENT_NATIVE_ENABLE_KEEP_WARM=1` quand la latence réduite pour le prochain visiteur vaut le temps de veille de la base de données.

Le planning de maintien à chaud et le maintien à chaud de la fonction d'arrière-plan ne s'appliquent qu'après l'activation du drapeau principal de maintien à chaud :

| Variable                                    | Effet                                                                                                                                                                                                                           |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AGENT_NATIVE_ENABLE_KEEP_WARM`             | Active le maintien à chaud planifié du serveur/de la base de données. Non défini par défaut.                                                                                                                                    |
| `AGENT_NATIVE_DISABLE_KEEP_WARM`            | Interrupteur de compatibilité qui l'emporte sur le drapeau d'activation quand il est défini.                                                                                                                                    |
| `AGENT_NATIVE_KEEP_WARM_SCHEDULE`           | Remplace la cadence par une expression cron à 5 champs, par ex. `*/5 * * * *`. La cadence par défaut une fois activée est `* * * * *`. Une valeur non interprétable **fait échouer le build**.                                  |
| `AGENT_NATIVE_DISABLE_KEEP_WARM_BACKGROUND` | Supprime uniquement le maintien à chaud de la fonction d'arrière-plan, en gardant le serveur au chaud. Réchauffer `server` est une seule requête. Réchauffer `-background` démarre un nouveau conteneur qui re-sonde le schéma. |

Si vous êtes sur un niveau de base de données gratuit ou autrement limité en quota, laissez `AGENT_NATIVE_ENABLE_KEEP_WARM` non défini. Si vous l'activez, utilisez une cadence plus lente ou définissez `AGENT_NATIVE_DISABLE_KEEP_WARM_BACKGROUND=1` pour supprimer le réchauffement d'arrière-plan plus coûteux.
