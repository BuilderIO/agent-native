# Démarrage

Agent-Native est un framework TypeScript open source pour créer des agents
autonomes avec des interfaces intuitives. Vous définissez la
fonctionnalité de votre application une seule fois sous forme
d’[actions](/docs/actions-overview) : des fonctions typées que votre interface
utilisateur React appelle depuis le code et que les agents utilisent comme outils.

Dans ce guide, vous allez créer une application Chat et appeler son action
`hello` incluse depuis l’agent et l’interface utilisateur.

<GettingStartedPaths />

## Prérequis

- [Node.js](https://nodejs.org) 22 ou version ultérieure
- [pnpm](https://pnpm.io)
- Une connexion LLM pour l’agent : Builder.io, une clé API Anthropic ou OpenAI,
  ou un modèle Ollama local

## Créer une application

Dans un nouveau répertoire, créez une application Chat :

```bash
npx @agent-native/core@latest create my-app --standalone --template chat
cd my-app
pnpm install
```

Le modèle comprend une application navigateur, l’authentification, des
conversations persistantes, la synchronisation en direct, le contexte de
l’application et un répertoire `actions/`. Il comprend aussi une petite action
`hello` que vous utiliserez tout au long de ce guide.

## Démarrer le serveur de développement

Démarrez l’application :

```bash
pnpm dev
```

L’application s’ouvre sur `http://localhost:8080`. Si elle ne s’ouvre pas
automatiquement, accédez à cette URL dans votre navigateur.

<Callout tone="info">

Sur l’écran d’accueil, sélectionnez **Continue as local dev**. Vous n’avez pas
besoin de saisir d’adresse e-mail ni de mot de passe pour le développement local.

</Callout>

Connectez ensuite un LLM. Sélectionnez **Connect Builder.io** pour utiliser des
crédits gratuits, ou sélectionnez **Custom keys**, choisissez un fournisseur et
saisissez les informations de connexion demandées.

## Exécuter l’action depuis l’agent

Une action est une fonction typée que votre interface utilisateur React peut
appeler depuis le code et que les agents peuvent utiliser comme outil. Le modèle
Chat comprend une action `hello` simple afin que vous puissiez essayer ce modèle
avant d’en écrire une vous-même.

Dans l’application, demandez :

> Call the hello action for Alex.

L’agent trouve `hello` grâce à sa description et à son schéma d’entrée, transmet
`Alex` comme entrée `name`, puis répond :

```text
Hello, Alex!
```

## Examiner l’action

Ouvrez `actions/hello.ts` :

```ts filename="actions/hello.ts"
import { defineAction } from "@agent-native/core/action";
import { z } from "zod";

export default defineAction({
  description: "Return a friendly greeting.",
  schema: z.object({
    name: z.string().default("world").describe("Name to greet"),
  }),
  http: { method: "GET" },
  run: async ({ name }) => {
    return { message: `Hello, ${name}!` };
  },
});
```

Pour le moment, concentrez-vous sur quatre éléments :

- `description` indique à l’agent quand utiliser l’action.
- `schema` valide l’entrée et fournit à l’agent une définition d’outil typée.
- `http` expose cette action en lecture seule via `GET`, ce qui permet à
  `useActionQuery` de l’appeler depuis React.
- `run` contient la logique de l’application partagée par l’agent et l’interface
  utilisateur.

Consultez [Définir des actions](/docs/actions-defining) pour connaître l’API
complète.

## Appeler l’action depuis React

Ajoutez une route dans `app/routes/hello.tsx` :

```tsx filename="app/routes/hello.tsx"
import { useActionQuery } from "@agent-native/core/client/hooks";
import { useState } from "react";

import { Input } from "@/components/ui/input";
import { Label } from "@/components/ui/label";

export default function HelloRoute() {
  const [name, setName] = useState("Alex");
  const { data } = useActionQuery("hello", { name });

  return (
    <main className="mx-auto grid w-full max-w-xl gap-6 p-6">
      <h1 className="text-2xl font-semibold">Hello action</h1>
      <div className="grid gap-2">
        <Label htmlFor="name">Name</Label>
        <Input
          id="name"
          value={name}
          onChange={(event) => setName(event.target.value)}
        />
      </div>
      <p className="text-xl font-medium">{data?.message}</p>
    </main>
  );
}
```

<Callout tone="warning">

Redémarrez le serveur de développement afin qu’il détecte la nouvelle route,
puis ouvrez `http://localhost:8080/hello`.

</Callout>

Pendant que vous saisissez un nom, `useActionQuery` appelle `hello` et affiche le
résultat. Il déduit les types d’entrée et de résultat de l’action ; la page n’a
donc besoin ni d’une route API personnalisée ni d’une seconde implémentation du
message d’accueil.

## Modifier l’action

Dans `actions/hello.ts`, modifiez la valeur de retour :

```ts
return { message: `Welcome, ${name}.` };
```

Actualisez `/hello`, puis demandez à nouveau à l’agent d’appeler `hello`. Les
deux renvoient le message d’accueil mis à jour, car ils appellent la même action.

## Appeler les actions d’autres façons

Vous avez appelé la même action depuis l’agent et l’interface utilisateur. La
même action peut aussi être appelée depuis :

| Appeler depuis                          | Utilisez-le pour                                                                                       |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| [HTTP API](/docs/http-api)              | appeler une action depuis un script, un backend ou une intégration.                                    |
| [CLI](/docs/actions-other-surfaces#cli) | exécuter ou tester une action depuis un terminal.                                                      |
| [MCP](/docs/actions-other-surfaces#mcp) | laisser un client d’IA externe découvrir et appeler des actions comme outils.                          |
| [A2A](/docs/actions-other-surfaces#a2a) | permettre à une autre application Agent-Native de demander à cette application d’effectuer un travail. |

Chaque appelant utilise la même définition d’action. Vous n’avez pas besoin
d’une implémentation distincte pour chacun. Ce modèle d’actions partagées est au
cœur d’Agent-Native : le comportement, la validation et les autorisations
restent alignés dans l’interface utilisateur, les agents et les intégrations à
mesure que l’application évolue.

## Ce que vous avez créé

Vous avez créé une application Agent-Native, appelé son action `hello` depuis
l’agent et une interface utilisateur React, puis modifié le message d’accueil
une seule fois et constaté la mise à jour des deux. Chaque action que vous
écrirez à partir de maintenant suivra ce même modèle.
