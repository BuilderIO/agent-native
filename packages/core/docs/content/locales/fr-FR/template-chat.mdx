# Discussion

Discussion est le point de départ agent-natif le plus simple : un shell de style ChatGPT
avec le chat au centre, une liste de fils de discussion, l'authentification, et un
exemple d'action, rien de spécifique à un domaine. Elle s'adresse aux développeurs qui
veulent une véritable application déployable sur laquelle construire leur propre agent
et leurs propres écrans, pas un produit fini pour un métier particulier.

Si vous voulez une forme de produit de domaine fini, partez de
[Calendrier](/docs/template-calendar), [Courrier](/docs/template-mail),
[Contenu](/docs/template-content), [Formulaires](/docs/template-forms),
[Analyses](/docs/template-analytics), ou un autre modèle de domaine. Si vous
n'avez vraiment pas encore besoin d'une UI navigateur, consultez
[Automation-First Apps](/docs/pure-agent-apps).

## Ce qui est livré {#what-ships}

<Comparison>

### :green: Inclus

- Chat en pleine page sur `/` utilisant la surface de chat du framework et des
  fils de discussion durables
- Liste de fils de discussion dans la barre latérale de l'application pour
  créer, rouvrir, renommer, épingler et archiver des discussions
- La boucle application-agent intégrée, préconfigurée pour le plugin de chat
- Authentification via Better Auth : connexion, inscription, sessions,
  organisations
- Un répertoire actions avec un exemple (`actions/hello.ts`) plus les actions
  standards `view-screen` et `navigate`
- Les tables principales du framework pour les fils de discussion, l'état de
  l'application, les paramètres, les sessions, les ressources et l'historique
  d'exécution, plus une page d'administration Base de données et un tableau
  de bord Observabilité, montées que vous les ouvriez ou non
- Synchronisation en direct (`useDbSync`) déjà câblée pour que l'interface
  s'actualise quand l'agent écrit dans SQL
- Routes Extensions montées par défaut, pour les mini-apps sandboxées que vos
  utilisateurs créent plus tard à l'intérieur du chat
- AGENTS.md avec des conseils axés sur le chat pour ajouter des actions, des
  routes, des skills, et de l'état de l'application

### :red: Non inclus

- Tables de domaine ou données d'amorçage
- Tableaux de bord, listes, graphiques, formulaires ou intégrations
  fournisseur
- Actions spécifiques à un domaine au-delà de l'exemple fourni

</Comparison>

C'est exactement le but. Discussion est un shell par défaut mince et utile pour
votre propre agent, pas un produit de domaine qui prétend être générique.

## Quand le choisir {#when-to-pick}

- **Vous voulez une application de base à laquelle les utilisateurs peuvent
  parler immédiatement**, puis l'étendre avec des actions et une interface.
- **Vous voulez le point d'entrée par défaut d'Agent-Native** : le chat
  d'abord, puis les actions, les résultats natifs, et les pages
  d'application.
- **Vous voulez brancher votre propre backend d'agent sur une interface de
  chat familière** tout en conservant la forme actions, état,
  authentification et déploiement d'Agent-Native.
- **Vous prototypez un outil interne personnalisé** qui ne correspond à
  aucun modèle de domaine.

## Commencer {#get-started}

```bash
npx @agent-native/core@latest create my-chat-app --standalone --template chat
```

Consultez [Discussion : Guide développeur](/docs/template-chat-developers#quick-start)
pour l'installation, la première exécution, et la connexion d'un LLM. Pour un
travail automation-first sans aucune UI navigateur, échafaudez plutôt avec
`--headless` :

```bash
npx @agent-native/core@latest create my-agent --headless
```

Utilisez-le pour les jobs planifiés, les files d'attente, les boucles CLI, ou
les workflows d'agents externes là où le chat et les pages d'application ne
sont pas encore utiles. L'invariant clé reste le même : les actions sont la
surface partagée pour le chat, l'UI, HTTP, MCP, A2A, et CLI. Consultez
[Automation-First Apps](/docs/pure-agent-apps) pour approfondir ce chemin.
