# Plugin et marketplace Plan

L'application Agent-Native **Plan** est livrée comme un seul pack
installable. Une seule installation ajoute les compétences des commandes
slash Plan **et** relie le connecteur MCP Plan hébergé (un serveur d'outils
distant avec lequel votre agent dialogue), si bien que l'agent peut générer
des plans et les publier directement dans l'application Plan en une seule
étape. Cette page s'adresse à quiconque choisit une route d'installation,
dépanne une installation, ou envisage de soumettre Plan à un catalogue de
plugins organisé — voir [Plans visuels](/docs/template-plan) pour ce que
font réellement les compétences.

## Ce que vous obtenez {#what-you-get}

Une installation vous donne :

- **Trois compétences** — `/visual-plan` (le point d'entrée canonique), `/visual-recap` et `/visualize-repo`.
- **Le connecteur MCP Plan** — enregistré contre l'application hébergée à `https://plan.agent-native.com` (point de terminaison MCP `https://plan.agent-native.com/mcp`, nom de serveur `plan`).

Par défaut, `/visual-plan` et `/visual-recap` publient dans l'application
Plan hébergée — elles créent un plan via le connecteur MCP et vous
remettent un lien ou un plan en ligne à consulter. Elles ne déversent
jamais un plan Markdown/ASCII en ligne dans le chat comme livrable. Si un
outil Plan renvoie `needs auth`, `Unauthorized`, ou `Session terminated`,
réauthentifiez le connecteur plutôt que de vous replier sur une sortie en
ligne. Les jetons d'accès sont longue durée (30 jours par défaut, avec un
renouvellement glissant de 365 jours), donc cela devrait être rare ; quand
cela arrive, la solution légère est :

```bash
npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex
```

`reconnect` retrouve et rafraîchit le connecteur par URL pour le client
local sélectionné — aucune réinstallation nécessaire. Démarrez un nouveau
fil Codex après la reconnexion pour que le registre d'outils se recharge.
Dans Claude Code, l'équivalent est `/mcp` → **Authenticate / Reconnect**,
ou la même commande avec `--client claude-code`.

L'exception est le **mode explicite de confidentialité fichiers locaux**.
Quand vous demandez qu'aucune écriture en base ne soit faite, ou que vous
définissez `AGENT_NATIVE_PLANS_MODE=local-files`, les compétences ne
doivent pas appeler le connecteur MCP Plan. Elles écrivent
`plans/<slug>/plan.mdx` ainsi que, optionnellement, `canvas.mdx`,
`prototype.mdx`, et `.plan-state.json`, puis prévisualisent localement
avec :

```bash
npx @agent-native/core@latest plan local serve --dir plans/<slug> --kind plan --open
```

Cela démarre un petit pont localhost et ouvre l'UI Plan contre le dossier
local. (`plan local preview` exécute plutôt une route de serveur de
développement Plan local, et `plan local preview --out preview.html` est
une échappatoire héritée qui écrit un fichier HTML statique autonome.
`plan serve` est accepté comme alias court de `plan local serve`.)

Quelques pièges du mode fichiers locaux à connaître :

- **Utilisez un navigateur Chromium.** Safari bloque la page Plan HTTPS
  hébergée de lire le pont localhost `http://127.0.0.1` (contenu mixte /
  réseau privé), si bien que la page reste bloquée sur « Loading plan. ».
  Sur macOS, `--open` préfère déjà Chrome/Chromium/Edge/Brave ; si Safari
  s'ouvre quand même, rouvrez l'URL affichée dans un navigateur Chromium.
- **L'URL servie est écrite dans `plans/<slug>/.plan-url`** (remplaçable
  avec `--url-file`). Un agent en arrière-plan ou sans tête peut lire ce
  fichier au lieu de récupérer la sortie standard du `serve` de longue
  durée. Traitez-le comme un fichier de jeton local et ne le committez pas.
- **Vérifiez sans navigateur** quand aucun n'est disponible :
  `npx @agent-native/core@latest plan local verify --dir plans/<slug>`
  démarre le pont, vérifie le préflight réseau privé et la charge JSON,
  affiche des diagnostics, et sort avec un code non nul en cas d'échec —
  aucun regard humain requis.
- **Exécutez `plan local check` en premier.** Cela valide le MDX par
  rapport au schéma de blocs du moteur de rendu Plan (y compris les champs
  requis comme `id`/`label` d'un item `checklist`, et
  `id`/`title`/`mode` d'une question `question-form`), si bien que les
  erreurs de rédaction apparaissent avant la remise au navigateur plutôt
  que sous la forme d'un chargeur bloqué.

Pour les dossiers du dépôt courant, la route locale directe inclut
`?path=...` afin que l'application Plan locale puisse continuer à
enregistrer les modifications du navigateur vers le dossier du dépôt.
L'application Plan utilise `apps.plan.roots[0].path` dans
`agent-native.json` comme emplacement par défaut pour enregistrer les
plans locaux promus, avec `plans/` comme repli.

Cela garde le contenu du plan hors de la base de données Agent-Native
Plan. Le partage hébergé, les commentaires, les captures d'écran et
l'historique des plans sont indisponibles tant que vous ne publiez pas
explicitement plus tard.

Agent-Native Desktop dispose d'un chemin de synchronisation de fichiers
locaux séparé pour les plans hébergés : l'application Desktop peut
synchroniser un plan hébergé vers des fichiers MDX locaux et réimporter
les modifications sans cloner l'application Plan ni exécuter de CLI. Ce
flux de travail garde la base de données Plan hébergée comme source de
vérité ; utilisez le mode de confidentialité fichiers locaux lorsque
l'objectif est de n'avoir aucune écriture dans la base Plan.

> Le plugin (`agent-native-visual-plans`) porte l'id d'application
> `visual-plans`, ce qui explique pourquoi le nom du plugin Claude Code et
> le nom du plugin Codex sont tous deux `agent-native-visual-plans`. Le
> nom d'affichage de l'application Plan est « Agent-Native Plan ».

## Routes d'installation {#install}

Il existe trois façons d'y accéder. La **route CLI universelle** est celle
que nous recommandons par défaut, car elle installe les compétences **et**
vous permet de choisir le mode hébergé, fichiers locaux, ou auto-hébergé
en un seul flux. Les routes par plugin s'adressent aux hôtes dotés d'un
système de plugin/marketplace de première classe et utilisent Plans
hébergé par défaut.

### Route de compétence universelle (tout hôte MCP) {#universal}

Fonctionne pour tout hôte — Claude Code, Codex, Cursor, Cline, Goose, les
applications MCP personnalisées ChatGPT, Claude Cowork, et tout autre
élément compatible MCP. La CLI Agent-Native installe les compétences Plan,
enregistre le connecteur MCP Plan hébergé, **et exécute l'authentification
pour le ou les clients locaux sélectionnés en une seule étape**, si bien
que votre premier appel d'outil ne se heurte pas à un mur OAuth :

```bash
npx @agent-native/core@latest skills add visual-plan
```

Cela installe `visual-plan` ainsi que les compétences compagnes
`visual-recap` et `visualize-repo`, enregistre ensuite le connecteur
`plan`, puis exécute l'authentification (invite OAuth pour le partage
hébergé/lié à un compte). Options utiles :

- `--client codex|claude-code|claude-code-cli|cowork|all` — quels agents
  locaux recevoir la configuration MCP (`all` par défaut).
- `--no-connect` — enregistre le connecteur sans authentifier ; exécutez
  plus tard `npx @agent-native/core@latest connect https://plan.agent-native.com --client all`,
  ou choisissez un `--client` plus restreint.
- `--mode hosted|local-files|self-hosted` — choisissez le partage hébergé,
  des fichiers MDX entièrement locaux, ou votre propre application Plan.
- `--mcp-url <url>` — pointez le connecteur vers une origine personnalisée
  (un tunnel ngrok, un serveur de développement local, ou un déploiement
  auto-hébergé) au lieu de l'origine hébergée par défaut.
- `--with-github-action` — écrit aussi l'Action GitHub PR Visual Recap
  (voir [Récapitulatif visuel de PR](/docs/pr-visual-recap)).

Les installations interactives proposent aussi l'Action PR Visual Recap
quand aucun workflow n'est présent. Répondez oui pour l'ajouter pendant la
configuration de la compétence, ou exécutez la commande ci-dessus plus
tard avec `--with-github-action`. Une fois le workflow écrit, exécutez :

```bash
npx @agent-native/core@latest recap setup
npx @agent-native/core@latest recap doctor
```

`recap setup` configure les secrets et variables de l'Action GitHub
quand c'est possible, et `recap doctor` vérifie le workflow, le jeton de
publication local, l'accès au dépôt GitHub, et la configuration Actions
requise. Une fois l'installation terminée, redémarrez ou rechargez le
client agent pour que les nouvelles compétences et les nouveaux outils se
chargent, puis exécutez `/visual-plan`.

> Remarque : le simple `npx skills@latest add BuilderIO/agent-native --skill visual-plan`
> (CLI Skills Vercel/ouverte) installe **uniquement les instructions** — il
> n'enregistre pas le connecteur MCP. Utilisez la CLI Agent-Native
> ci-dessus quand vous voulez aussi que le connecteur soit relié.

### Claude Code (plugin) {#claude-code}

Le dépôt public `BuilderIO/agent-native` est lui-même une marketplace de
plugins Claude Code, donc vous l'ajoutez directement — sans étape de
build. Dans Claude Code :

```text
/plugin marketplace add BuilderIO/agent-native
/plugin install agent-native-visual-plans@agent-native-apps
/reload-plugins
/mcp        # authenticate the Plan connector (one OAuth approval)
```

`/plugin install` ajoute les compétences Plan et une configuration MCP
**URL uniquement** (aucun secret dans le paquet) ; `/mcp` →
**Authenticate** termine la poignée de main OAuth. Utilisez plutôt la
route CLI universelle quand vous voulez le mode fichiers locaux ou
auto-hébergé.

> Le catalogue marketplace se nomme `agent-native-apps` et le plugin Plan
> est `agent-native-visual-plans`, donc la cible d'installation est
> toujours `agent-native-visual-plans@agent-native-apps`.

### Codex (plugin) {#codex}

Le même dépôt est une marketplace de plugins Codex. Ajoutez-le, installez
le plugin, puis authentifiez le connecteur :

```bash
codex plugin marketplace add BuilderIO/agent-native
codex plugin add agent-native-visual-plans@agent-native-apps
codex mcp login plan   # OAuth in the browser
```

Après l'installation, **démarrez un nouveau fil Codex** pour que les
compétences et les outils MCP se chargent dans la session. Le plugin est
livré avec un connecteur URL uniquement (`[mcp_servers.plan]` →
`https://plan.agent-native.com/mcp`) ; `codex mcp login plan` exécute le
flux OAuth. La route CLI universelle ci-dessus fonctionne aussi pour
Codex (`npx @agent-native/core@latest skills add visual-plan --client codex`)
si vous préférez une seule commande qui installe et authentifie ensemble,
ou quand vous voulez le mode fichiers locaux ou auto-hébergé.

<Callout tone="info">

**Anciennes installations :** si votre configuration a encore une entrée
`agent-native-plans` pointant vers la même URL, exécuter
`npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex`
pour Codex, ou la même commande avec votre `--client` cible, la consolide
vers le nom canonique `plan`.

</Callout>

## Mises à jour {#updates}

Les routes par plugin se mettent à jour automatiquement — vous n'avez pas
à reconditionner ni à réajouter la marketplace pour des changements de
compétence de routine :

- **Claude Code** — l'entrée marketplace définit `autoUpdate: true` et le
  plugin utilise un versionnage par SHA de commit, si bien que Claude Code
  récupère les nouvelles versions depuis le dépôt au démarrage ; exécutez
  `/reload-plugins` pour activer. Chaque push sur la branche par défaut du
  dépôt atteint automatiquement les utilisateurs installés.
- **Codex** — le `version` du plugin intègre un hachage de contenu des
  compétences groupées et du point de terminaison MCP (par exemple
  `1.0.0+codex.<hash>`), si bien que tout changement de compétence ou de
  point de terminaison produit une nouvelle version. La mise à niveau
  automatique au démarrage de Codex réinstalle seule les marketplaces git
  configurées ; il suffit de **démarrer un nouveau fil** pour prendre en
  compte le changement. Aucun `codex plugin marketplace upgrade` manuel
  n'est nécessaire pour les mises à jour de routine.
- **Route CLI universelle** — exécutez
  `npx @agent-native/core@latest skills status visual-plan` pour vérifier
  les dossiers de compétences copiés, ou
  `npx @agent-native/core@latest skills update visual-plan` pour les
  actualiser sur place. Réexécuter `skills add visual-plan` fonctionne
  toujours quand vous voulez aussi réenregistrer/authentifier le
  connecteur. `@latest` récupère toujours les compétences actuelles depuis
  le package `@agent-native/core` publié.

Le connecteur pointe vers une application **hébergée**, si bien que les
actions et la surface d'outils en direct de l'application Plan reflètent
toujours la version déployée quel que soit le moment de votre
installation ; seules les instructions de compétences groupées suivent
les mécanismes de mise à jour ci-dessus.

<Callout tone="info">

**Mainteneurs :** le pack marketplace (`.claude-plugin/`, `.agents/plugins/`)
est généré à partir des compétences plan canoniques par
`pnpm sync:plan-marketplace` et vérifié en CI par
`pnpm guard:plan-marketplace`, si bien que la marketplace publiée
correspond toujours aux compétences canoniques. Modifiez la compétence,
exécutez `pnpm sync:plan-marketplace`, et committez.

</Callout>

## Devez-vous soumettre quoi que ce soit ? {#submission}

**Aucune soumission ni revue n'est requise pour distribuer ou installer
ceci.** `BuilderIO/agent-native` est une marketplace git publique
auto-hébergée, donc les utilisateurs l'ajoutent directement avec les
commandes ci-dessus, sur **Claude Code et Codex** — sans candidature ni
approbation. La route CLI universelle n'a besoin d'aucune marketplace du
tout.

Découvrabilité optionnelle, si vous voulez une inscription publique :

- **Claude Code** dispose d'une marketplace communautaire à laquelle vous
  pouvez _optionnellement_ soumettre votre plugin pour être répertorié
  (soumission plus une revue automatisée). La marketplace officielle,
  organisée par Anthropic, est répertoriée à la discrétion d'Anthropic —
  il n'y a pas de candidature libre-service. Aucune des deux n'est requise
  pour utiliser les commandes d'installation ci-dessus.
- **Codex** dispose d'un catalogue de plugins organisé par OpenAI (une
  liste fermée, obtenue via un partenariat plutôt qu'une soumission
  libre-service). Les marketplaces git auto-hébergées et la route CLI
  n'ont besoin d'aucune soumission pour fonctionner.

En bref : livrez-le comme marketplace git auto-hébergée/publique et les
utilisateurs l'installent directement ; ne soumettez à un catalogue
organisé que si vous voulez qu'il soit répertorié pour la découvrabilité.

## Plugin contre compétence {#plugin-vs-skill}

Une **compétence** est un unique fichier d'instructions `SKILL.md` que
l'agent lit quand une tâche correspond. Un **plugin** (plugin marketplace
Claude Code ou plugin Codex) est un paquet qui regroupe une ou plusieurs
compétences **plus** un connecteur MCP et des métadonnées, si bien qu'un
hôte peut tout installer en une seule étape.

Sous le capot, les trois routes sont produites à partir de la même source
par la CLI `npx @agent-native/core@latest app-skill` : `app-skill pack`
construit les adaptateurs marketplace/plugin, et `skills add` est
l'installeur convivial en une étape qui enregistre et authentifie aussi
le connecteur MCP. Voir [Guide Skills](/docs/skills-guide) pour le format
du manifeste app-skill, et [Agents externes](/docs/external-agents) pour
connecter n'importe quel hôte MCP et le flux
`npx @agent-native/core@latest connect`.
