# Conserver les données dans SQL

Cette page constitue la quatrième partie facultative de la série Premiers pas. Dans [Ajouter une page](/docs/getting-started-pages),
vous avez utilisé `analyze-text` directement depuis une route. Ici, vous allez
ajouter des données SQL propres à l’application lorsque les résultats doivent
survivre aux conversations.

## Ajouter une table {#persist-data}

Chat inclut déjà l’environnement SQL, les tables du framework et un fichier
SQLite local par défaut. Vous n’avez pas besoin d’installer une base de données,
de définir `DATABASE_URL` ou d’ajouter une migration pour les tables intégrées
de Chat. Pour une nouvelle table propre à l’application, ajoutez ces trois
fichiers côté serveur :

1. `server/plugins/db.ts` crée la table avec une migration additive.
2. `server/db/schema.ts` décrit la table pour les requêtes typées.
3. `server/db/index.ts` crée le client de base de données typé de l’application.

Créez `server/plugins/db.ts` :

```ts filename="server/plugins/db.ts"
import { runMigrations } from "@agent-native/core/db";

export default runMigrations(
  [
    {
      version: 1,
      name: "create-text-analyses",
      sql: `CREATE TABLE IF NOT EXISTS text_analyses (
        id TEXT PRIMARY KEY,
        input TEXT NOT NULL,
        char_count INTEGER NOT NULL,
        word_count INTEGER NOT NULL,
        sentence_count INTEGER NOT NULL,
        paragraph_count INTEGER NOT NULL,
        owner_email TEXT NOT NULL,
        created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
      )`,
    },
  ],
  { table: "text_analyses_migrations" },
);
```

Créez `server/db/schema.ts` :

```ts filename="server/db/schema.ts"
import { integer, now, table, text } from "@agent-native/core/db/schema";

export const textAnalyses = table("text_analyses", {
  id: text("id").primaryKey(),
  input: text("input").notNull(),
  charCount: integer("char_count").notNull(),
  wordCount: integer("word_count").notNull(),
  sentenceCount: integer("sentence_count").notNull(),
  paragraphCount: integer("paragraph_count").notNull(),
  ownerEmail: text("owner_email").notNull(),
  createdAt: text("created_at").notNull().default(now()),
});
```

Créez `server/db/index.ts` :

```ts filename="server/db/index.ts"
import { createGetDb } from "@agent-native/core/db";
import * as schema from "./schema.js";

export const getDb = createGetDb(schema);
export { schema };
```

Redémarrez `pnpm dev` une fois pour exécuter la migration. Gardez les
migrations futures additives et donnez à chacune une nouvelle `version` et un
nouveau `name`.

## Ajouter les actions d’enregistrement et de liste

Gardez `analyze-text` en lecture seule et rendez l’enregistrement explicite
avec une action distincte. Créez `actions/save-text-analysis.ts` :

```ts filename="actions/save-text-analysis.ts"
import { defineAction } from "@agent-native/core/action";
import { z } from "zod";

import { getDb, schema } from "../server/db/index.js";

export default defineAction({
  description: "Save a text analysis result to the database.",
  schema: z.object({
    input: z.string().min(1),
    charCount: z.number(),
    wordCount: z.number(),
    sentenceCount: z.number(),
    paragraphCount: z.number(),
  }),
  run: async (
    { input, charCount, wordCount, sentenceCount, paragraphCount },
    ctx,
  ) => {
    const ownerEmail = ctx?.userEmail;
    if (!ownerEmail) throw new Error("Sign in before saving analyses.");

    const id = crypto.randomUUID();
    await getDb().insert(schema.textAnalyses).values({
      id,
      input,
      charCount,
      wordCount,
      sentenceCount,
      paragraphCount,
      ownerEmail,
    });

    return { id };
  },
});
```

Créez `actions/list-text-analyses.ts` :

```ts filename="actions/list-text-analyses.ts"
import { defineAction } from "@agent-native/core/action";
import { desc, eq } from "drizzle-orm";
import { z } from "zod";

import { getDb, schema } from "../server/db/index.js";

export default defineAction({
  description: "List the signed-in user's saved text analyses, newest first.",
  schema: z.object({}),
  http: { method: "GET" },
  readOnly: true,
  run: async (_, ctx) => {
    const ownerEmail = ctx?.userEmail;
    if (!ownerEmail) throw new Error("Sign in before listing analyses.");

    return getDb()
      .select({
        id: schema.textAnalyses.id,
        input: schema.textAnalyses.input,
        charCount: schema.textAnalyses.charCount,
        wordCount: schema.textAnalyses.wordCount,
        sentenceCount: schema.textAnalyses.sentenceCount,
        paragraphCount: schema.textAnalyses.paragraphCount,
        createdAt: schema.textAnalyses.createdAt,
      })
      .from(schema.textAnalyses)
      .where(eq(schema.textAnalyses.ownerEmail, ownerEmail))
      .orderBy(desc(schema.textAnalyses.createdAt));
  },
});
```

Les actions utilisent le client Drizzle typé pour les lectures et écritures de
l’application. Le SQL brut n’est nécessaire ici que pour la migration additive.
Ignorez cette page tant que votre action n’a pas besoin de données métier
durables.

## Essayer

Dans le chat, demandez à l’agent d’effectuer tout le parcours :

> Run analyze-text on "Hello world", save the result with save-text-analysis, then list my saved text analyses.

La ligne enregistrée est maintenant disponible pour l’agent et pour toute page qui
lit `list-text-analyses`.

## Pour continuer

Vous disposez maintenant de données durables pour l’application. Poursuivez avec
[Concepts clés](/docs/key-concepts) pour comprendre comment les actions, SQL et
les pages s’articulent.
