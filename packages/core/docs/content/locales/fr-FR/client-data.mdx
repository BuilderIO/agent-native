# Données et synchronisation

Le principal moyen de lire et d'écrire des données d'application depuis le client est d'utiliser les hooks d'[action](/docs/actions-overview). En intégrant les requêtes dans des actions, votre client et votre agent peuvent tous deux interagir avec votre application de la même manière.

Dans l'exemple ci-dessous, un ticket est assigné à l'utilisateur actuel manuellement via une liste déroulante, puis via l'agent de chat. L'UI et l'agent accèdent tous deux à la même action.

### Hooks d'action {#action-hooks}

Il y a deux hooks d'action que vous êtes le plus susceptible d'utiliser : `useActionQuery()` et `useActionMutation()`. Ces deux hooks donnent accès aux actions de votre application.

#### useActionQuery {#use-action-query}

<Signature

      description:
        "Tout ce qui vient des [options de useQuery](https://tanstack.com/query/latest/docs/framework/react/reference/useQuery) sauf `queryKey` et `queryFn`, que le hook définit lui-même.",
    },
  ]}
  returns={{
    type: "UseQueryResult<TResult>",
    description:
      'Mis en cache sous `["action", name, params]`. Se relance automatiquement chaque fois qu\'une action de mutation se termine, sans invalidation manuelle nécessaire.',
  }}
/>

Ce hook est destiné à être utilisé pour les actions en lecture seule. C'est un wrapper léger autour de la fonction [useQuery()](https://tanstack.com/query/latest/docs/framework/react/reference/useQuery).

Dans l'exemple ci-dessous, l'action `list-tickets` est appelée. C'est similaire à effectuer une requête GET pour tous les tickets.

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery("list-tickets", {});
```

L'exemple suivant montre une requête pour récupérer un seul ticket, via l'action `get-ticket`. Un `ticketId` est fourni pour restreindre la requête à un ticket spécifique. L'option supplémentaire `enabled` est fournie pour garantir que la requête ne s'exécute pas automatiquement, et ne s'exécute que lorsqu'un `ticketId` est présent.

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery(
  "get-ticket",
  { ticketId: ticketId ?? "" },
  { enabled: Boolean(ticketId) },
);
```

  }}
/>

Ce hook est destiné à être utilisé pour les actions qui modifient des données, comme la création, la mise à jour ou l'envoi de quelque chose. C'est un wrapper léger autour de la fonction [useMutation()](https://tanstack.com/query/latest/docs/framework/react/reference/useMutation).

Contrairement à `useActionQuery()`, l'entrée de l'action n'est pas transmise au hook lui-même. Elle est transmise à `mutate()` ou `mutateAsync()` lorsque vous êtes prêt à exécuter la mutation.

Dans l'exemple ci-dessous, l'action `send-ticket-reply` est appelée pour publier une réponse à un ticket. Appelez `mutate()` depuis un gestionnaire d'événement, comme l'`onClick` d'un bouton.

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply");

mutate({ ticketId, body: draft });
```

L'exemple suivant montre la même mutation avec une option `onSuccess`. L'invalidation du cache se produit automatiquement après chaque mutation, donc `onSuccess` n'est nécessaire que pour des effets de bord locaux, comme vider le composeur de réponse une fois la réponse envoyée.

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply", {
  onSuccess: () => setDraft(""),
});

mutate({ ticketId, body: draft });
```

    type: "Promise<TResult>",
    description:

  }}
/>

Cette fonction est destinée aux appels d'action impératifs ponctuels hors d'un flux de rendu React, comme un simple gestionnaire d'événement, un script, ou tout autre chemin de code non React. Elle renvoie directement une promesse plutôt qu'un résultat de hook.

Dans l'exemple ci-dessous, l'action `update-ticket` est appelée depuis un gestionnaire de raccourci clavier hors du flux de rendu de React, pour assigner le ticket à un représentant.

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction("update-ticket", {
  ticketId,
  assignedToEmail: "jordan@example.com",
});
```

L'exemple suivant montre le même appel avec une option `timeoutMs`, utile pour les actions qui prennent légitimement plus de temps que le délai d'expiration par défaut de 60 secondes.

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction(
  "update-ticket",
  { ticketId, assignedToEmail: "jordan@example.com" },
  { timeoutMs: 120_000 },
);
```

Chaque requête `useActionQuery()`, `useActionMutation()`, et `callAction()` est limitée par un délai d'expiration de 60 secondes, et les délais d'expiration apparaissent comme des erreurs plutôt que de relancer silencieusement. `useActionQuery()` annule aussi automatiquement les requêtes remplacées, en utilisant le signal d'abandon de React Query.

`useDbSync()` traite les fins d'outils du flux de chat local et actualise les données à la fin de l'exécution. Les modifications d'un agent seul restent ainsi à jour sans requête en arrière-plan. La synchronisation des changements venant d'autres onglets, personnes, webhooks ou tâches reste désactivée, sauf si cette page l'active avec une courte raison. Chaque onglet partage un transport, le met en pause lorsqu'il est masqué et espace les interrogations à vide à 1, 2 puis 5 minutes.

```ts
import { useDbSync } from "@agent-native/core/client/hooks";
import { useQueryClient } from "@tanstack/react-query";

function App() {
  const queryClient = useQueryClient();

  useDbSync({
    queryClient,
    realtime: { reason: "teammates can edit this shared record" },
    pollUrl: "/_agent-native/poll",
    onEvent: (data) => console.log("Data changed:", data),
  });

  return <div>...</div>;
}
```

N'activez le temps réel que si les données peuvent changer sans action de l'utilisateur actuel et si celui-ci doit voir le changement avant d'actualiser. L'édition collaborative dans Slides et la boîte de réception Mail sont de bons exemples. Laissez désactivés les pages publiques, Docs, paramètres, formulaires, listes rarement modifiées et changements d'un agent seul ; actualisez au retour du focus ou à la navigation. Chaque onglet ouvert abonné ajoute une interrogation par intervalle à vide.
