# Définir des actions

Chaque action commence par un appel à `defineAction()`. Il regroupe une description pour l’agent, un schéma qui valide l’entrée, et une fonction `run` qui effectue le travail, de sorte que l’UI et l’agent appellent exactement le même code.

## Options de schéma {#schemas}

`schema` accepte toute bibliothèque compatible [Standard Schema](https://standardschema.dev) :

- **Zod** (v4) : le choix le plus courant, avec la meilleure inférence de types et une conversion automatique en JSON Schema.
- **Valibot** : un bon choix quand la taille du bundle compte.
- **ArkType** : un bon choix si vous préférez sa syntaxe.

Le schéma remplit deux rôles. Il se convertit en JSON Schema pour la définition d’outil de l’API Claude, et il valide l’entrée à l’exécution avant que `run()` ne se déclenche. Une entrée invalide n’atteint jamais votre gestionnaire.

## Valider la valeur de retour {#output-schema}

`schema` valide les _entrées_. Pour aussi valider ce qu’une action **renvoie**, passez un `outputSchema` (n’importe quel schéma compatible Standard Schema : Zod, Valibot, ArkType, la même surface que `schema`). Le framework valide l’entrée avant `run()` et valide le résultat après la résolution de `run()`.

```ts
export default defineAction({
  description: "Summarize a thread.",
  schema: z.object({ threadId: z.string() }),
  outputSchema: z.object({
    summary: z.string(),
    messageCount: z.number(),
  }),
  outputErrorStrategy: "warn", // default
  run: async ({ threadId }) => {
    /* ...returns { summary, messageCount } ... */
  },
});
```

`outputErrorStrategy` contrôle ce qui se passe en cas de décalage :

| Stratégie    | Comportement en cas de décalage                                                                         |
| ------------ | ------------------------------------------------------------------------------------------------------- |
| `"warn"`     | **Par défaut.** `console.warn` les problèmes et renvoie le résultat **original** inchangé. Non cassant. |
| `"strict"`   | Lève une erreur claire, pour qu’un bug dans l’action soit facile à remarquer.                           |
| `"fallback"` | Renvoie la valeur `outputFallback` fournie à la place du résultat invalide.                             |

Quand `run()` réussit, le framework renvoie la valeur validée, de sorte que les valeurs par défaut ou les coercions de `outputSchema` s’appliquent, de la même manière que pour l’entrée. Quand vous ne passez pas de `outputSchema`, la valeur de retour reste inchangée.

## Configuration HTTP {#http}

Par défaut, chaque action est exposée en tant que `POST /_agent-native/actions/<name>`. Remplacez avec l’option `http` :

```ts
export default defineAction({
  description: "Get details for a lead.",
  schema: z.object({ leadId: z.string() }),
  http: { method: "GET" },
  run: async ({ leadId }) => {
    return await db.select().from(leads).where(eq(leads.id, leadId));
  },
});
```

Pour une action `GET`, `leadId` est transmis comme paramètre de requête : `/_agent-native/actions/get-lead?leadId=abc`.

POST est la valeur par défaut, et `http: { method: "GET" }` en fait un GET. Les hooks React et `callAction()` appellent toujours ce chemin par nom, quel que soit un éventuel remplacement de `http.path`. Un système externe peut appeler la même route avec un jeton porteur longue durée. Voir [API HTTP](/docs/http-api).

</Endpoint>

- **`http: { method: "GET" | "POST" | "PUT" | "DELETE" }`** : la valeur par défaut est `POST`. Les actions `GET` sont automatiquement marquées `readOnly`, de sorte qu’un appel réussi ne déclenche pas de rafraîchissement par interrogation de l’UI.
- **`http: { path: "..." }`** : remplace l’URL montée sous `/_agent-native/actions/`. Elle vaut par défaut le nom du fichier. Ce remplacement ne change l’URL que pour les appelants HTTP directs. `useActionQuery()`, `useActionMutation()`, et `callAction()` appellent toujours `/_agent-native/actions/<name>`, quel que soit ce remplacement, donc remplacer le chemin fait échouer ces hooks avec un 404. N’utilisez un remplacement de chemin que pour les appelants HTTP externes. Notez aussi que les segments de route `:param` dans le chemin de remplacement ne sont pas analysés en arguments de `run()`. Seuls les paramètres de chaîne de requête et les champs du corps JSON le sont.
- **`http: false`** : désactive entièrement le point de terminaison HTTP. Seuls l’agent et la CLI peuvent appeler l’action.
- **`readOnly: true`** : désactive explicitement le rafraîchissement par interrogation, même pour des actions POST qui ne modifient rien. Ce n’est pas un contrôle d’accès. Cela ne restreint pas qui peut appeler l’action, et cela n’affecte ni `useActionQuery()`, ni `useActionMutation()`, ni aucun hook client. Ses seuls effets sont de supprimer l’événement de rafraîchissement post-appel et de faire sortir l’action de l’audit des écritures. Pour masquer une action au modèle, utilisez `agentTool: false`. Pour restreindre qui peut l’appeler, utilisez les options d’authentification et d’accès sur [Accès et autorisation](/docs/actions-access-control).
- **`parallelSafe: true`** : autorise une action de mutation à s’exécuter en même temps que d’autres appels d’outil du même tour. Ne définissez ceci que lorsque l’action est sûre à exécuter en parallèle et ne dépend pas de l’ordre. Les actions de mutation se sérialisent par défaut.

## Garder la surface d’actions restreinte {#small-surface}

Chaque action visible par l’agent prend une place dans la liste d’outils du modèle, et une liste longue et redondante rend plus difficile pour le modèle de choisir le bon outil. Concevez la surface d’actions comme une API que vous maintenez, pas une action par bouton de l’UI :

- Préférez **une seule action `update` de style CRUD** qui prend un patch de champs optionnels, plutôt que de nombreuses actions par champ comme `update-name`, `update-order`, et `update-color`. L’appelant n’envoie que les champs qui ont changé.
- Avant d’ajouter une nouvelle action de lecture pour chaque requête ou filtre, envisagez d’abord une option plus générale : le [trio d’API fournisseur](/docs/template-dispatch-vault-integrations#provider-api) (`provider-api-catalog`, `provider-api-docs`, et `provider-api-request`) pour les données fournisseur, ou l’outil dev `db-query` pour les données d’application.
- Marquez les actions réservées à l’UI ou programmatiques [`agentTool: false`](/docs/actions-access-control#agent-tool). Elles restent appelables depuis le frontend ou via HTTP, sans prendre de place dans la liste d’outils du modèle.
- Supprimez ou masquez les actions que l’UI n’utilise plus, plutôt que de les laisser exposées au modèle.

Le dépôt inclut un utilitaire consultatif, `node scripts/audit-template-actions.mjs [template ...]` (alias `pnpm actions:audit`). Il scanne le dossier `actions/` d’un template et signale les actions que l’UI n’utilise peut-être plus, ainsi que des groupes d’actions par champ qui pourraient être combinées en une seule. Il sort toujours avec le code 0 et ne fait jamais échouer la CI, et ses heuristiques sont prudentes, donc traitez sa sortie comme une suggestion, pas comme une erreur.
