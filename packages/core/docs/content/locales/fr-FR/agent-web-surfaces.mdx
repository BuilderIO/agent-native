# Web des agents publics

Le Web public des agents permet aux agents d'explorer, de lire, de citer et d'appeler facilement les routes Agent-Native publiques. L’objectif n’est pas de rendre public chaque point de terminaison d’une application. L'objectif est de publier une surface publique propre pour les pages déjà publiques, tout en conservant l'accès aux données privées et aux outils derrière des contrôles explicites.

Le site de documentation est l'implémentation de référence. Aujourd'hui, il est expédié :

- `/robots.txt` avec une stratégie de robot d'exploration qui autorise la récupération mais interdit l'entraînement par défaut.
- `/sitemap.xml` sous forme d'index de sitemaps qui pointe vers un `/sitemap-<locale>.xml` par langue, avec URL canoniques absolus et `lastmod` lorsque le fichier source l'expose.
- `/llms.txt` et `/llms-full.txt` pour une découverte de contenu conviviale pour les agents.
- Miroirs Markdown tels que `/docs/getting-started.md`.
- Réponses `Accept: text/markdown` pour les pages de documentation publique après une version de production.
- JSON-LD pour les métadonnées de l'organisation de base, du site Web et de la page.
- Un audit CLI (`npx @agent-native/core@latest audit-agent-web`) qui vérifie tout ce qui précède.

Publier ces fichiers n'expose jamais une action. Une action n'atteint les agents externes que par sa propre activation `publicAgent` ; voir [Exposer aux agents publics](/docs/actions-access-control#public-agent).

## Configuration {#config}

`createAgentWebVitePlugin` de `@agent-native/core/vite` écrit ces fichiers pendant un build de production. Ajoutez-le à votre configuration Vite avec les pages que les agents doivent lire :

```ts
// vite.config.ts
import { defineConfig } from "vite";
import { createAgentWebVitePlugin } from "@agent-native/core/vite";

export default defineConfig({
  plugins: [
    // ...your existing plugins
    createAgentWebVitePlugin({
      siteName: "My Agent-Native App",
      siteUrl: "https://example.com",
      pages: [
        {
          path: "/pricing",
          title: "Pricing",
          description: "Plans and limits.",
          markdown: "Plans and limits.\n",
        },
      ],
      agentWeb: { crawlerPolicy: "discoverable-no-training" },
    }),
  ],
});
```

Le plugin publie les pages que vous listez, et rien d'autre. Il ne lit ni vos paramètres d'accès aux routes, ni `agentWeb` dans `package.json`, sauf si vous le lui transmettez. Pour garder les paramètres dans `package.json` sous `agent-native.workspaceApp.agentWeb`, transmettez `agentWeb: agentWebConfigFromPackageJson(pkg)`, importé de `@agent-native/core/agent-web`.

| Option          | Par défaut                          | Effet                                                                                                                                                             |
| --------------- | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `discoverable`  | Activé quand `pages` n'est pas vide | `false` n'écrit aucun fichier.                                                                                                                                    |
| `llmsTxt`       | `true`                              | Écrit `/llms.txt` et `/llms-full.txt`.                                                                                                                            |
| `markdownTwins` | `true`                              | Écrit une copie `.md` de chaque page qui a un `markdown`.                                                                                                         |
| `crawlerPolicy` | `"discoverable-no-training"`        | Définit les règles de `robots.txt` : `"discoverable-no-training"`, `"allow-all"` ou `"disallow-all"`.                                                             |
| `crawlers`      | Aucun                               | Remplace des catégories de robots individuelles : `training`, `search`, `userTriggered`, `codingAgents` ou `autonomousAgents`, chacune `"allow"` ou `"disallow"`. |

La politique d'exploration par défaut est « découvrable, pas entraînable » : la recherche, la récupération déclenchée par l'utilisateur, les agents de code et les agents de navigation autonomes sont autorisés ; les robots d'entraînement ne le sont pas.

`jsonLd`, `publicAgentCard` et `publicMcp` sont acceptés, mais rien ne les lit encore. Pour le JSON-LD, rendez vous-même `buildBaseJsonLd` et `buildPageJsonLd` de `@agent-native/core/agent-web` dans vos pages.

## Itinéraire source de vérité {#route-source}

La liste de pages fait foi : les agents reçoivent les pages que vous transmettez, et seulement celles-là. Construisez-la à partir de pages déjà publiques :

- Dans une app publique, toutes les routes sauf `protectedPaths`.
- Dans une app interne, uniquement `publicPaths`.
- Les pages publiques de partage et de formulaire que les agents doivent pouvoir lire.
- Jamais de données privées soumises, de tableaux de bord authentifiés ni d'état d'utilisateur ou d'organisation, même quand une page voisine est publique.

Pour partir de vos paramètres d'accès, `deriveAgentWebPublicRoutes` de `@agent-native/core/agent-web` prend `audience`, `publicPaths`, `protectedPaths` et `routes` de votre app et renvoie les routes que ces paramètres rendent publiques. Chaque page a toujours besoin de son propre titre et de son propre Markdown.

Cela permet aux applications mixtes de rester naturelles. Une application de formulaires peut exposer une page de formulaire publique et garder les soumissions privées. Une application de contenu peut exposer les publications publiées et garder l'éditeur privé. Un site de documentation peut tout exposer, sauf les outils d'administration.

## Les pages publiques ne sont pas des outils publics {#public-tools}

L'accès aux pages publiques et l'accès aux outils publics sont distincts. Un itinéraire public signifie uniquement que les agents peuvent lire cet itinéraire en tant que HTML, Markdown, entrées de plan de site, entrées LLMS et données structurées.

<Callout id="doc-block-s50w8y" tone="warning">

**Une page publique n'est pas un outil public.** Rendre une route explorable n'expose jamais une action. L'accès aux outils exige une activation explicite de `publicAgent.expose` sur l'action.

</Callout>

## Fichiers au moment de la construction {#build-time}

Les utilitaires Framework dans `@agent-native/core/agent-web` génèrent les fichiers communs à partir d'une liste de pages :

```ts
import {
  buildAgentWebStaticFiles,
  normalizeAgentWebConfig,
} from "@agent-native/core/agent-web";

const config = normalizeAgentWebConfig(
  { crawlerPolicy: "discoverable-no-training" },
  { hasPublicRoutes: true },
);

const files = buildAgentWebStaticFiles({
  siteName: "My Agent-Native App",
  siteUrl: "https://example.com",
  description: "Public docs for my app.",
  config,
  pages: [
    {
      path: "/docs",
      title: "Docs",
      description: "Start here.",
      markdown: "# Documents\n\nStart ici.\n",
      markdownPath: "/docs/getting-started.md",
      lastmod: new Date(),
    },
  ],
});
```

`createAgentWebVitePlugin` appelle `buildAgentWebStaticFiles` pour vous et écrit les fichiers dans ceux des dossiers `public`, `dist`, `dist/client`, `dist/server/public` et `build/client` qui existent. Avec un autre outil de build, appelez directement les utilitaires.

Aucun des deux ne répond à `Accept: text/markdown` sur l'URL propre d'une page : la copie Markdown n'existe qu'à son URL `.md`. Pour répondre à cet en-tête, ajoutez une route serveur qui renvoie le Markdown de la page avec les en-têtes de `buildMarkdownResponseHeaders`, comme le fait le site de documentation. Sans cette route, l'audit ci-dessous échoue à sa vérification `Accept: text/markdown`.

Passez `sitemapGroup` à `buildAgentWebStaticFiles` ou `createAgentWebVitePlugin` pour découper un sitemap volumineux. L'option associe chaque page à une clé de groupe, comme sa langue, et `sitemap.xml` devient un index de sitemaps avec un `sitemap-<group>.xml` par groupe.

## Auditer un site {#audit}

Utilisez l'audit CLI sur un site déployé ou un serveur de production local :

```bash
npx @agent-native/core@latest audit-agent-web --url https://www.agent-native.com
```

L'audit vérifie :

- SSR-HTML visible.
- URL canoniques.
- JSON-LD.
- Politique `robots.txt` et plan de site absolu URL.
- Entrées absolues du plan du site.
- `/llms.txt` et `/llms-full.txt`.
- Miroirs Markdown.
- `Accept: text/markdown`.
- Aucun bloc 401/403 accidentel pour les agents utilisateurs de récupération d'agent commun.

L'audit sort non nul si une surface publique requise est manquante.
