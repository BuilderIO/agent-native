# Votre première fonctionnalité

Cette page s'adresse aux développeurs qui étendent le [modèle Chat](/docs/template-chat). Elle présente les fichiers qui affichent les écrans de démarrage, puis parcourt tout ce que l'agent touche généralement quand vous demandez une vraie fonctionnalité.

## Premier code à inspecter {#first-code}

- `actions/hello.ts` est le comportement de départ que l'agent peut appeler.
  Remplacez-le ou ajoutez des actions à côté.
- `app/components/chat/ChatRouteContent.tsx` affiche la surface de chat pleine
  page à `/chat/<threadId>`. Ajustez ici l'état vide, le composer ou les slots
  de messages.
- `app/components/home/HomePage.tsx` est la page Commencer modifiable affichée
  sur `/home` en développement. En production, `/home` démarre un nouveau chat.
- `AGENTS.md` indique à l'agent intégré comment travailler dans cette app.

## Premières modifications {#first-edits}

La plupart des premières fonctionnalités suivent la même forme : une table, une ou deux actions, une route, une entrée de navigation, et une mise à jour d'`AGENTS.md`. Demandez à l'agent :

> Ajoutez un modèle de données pour `notes`. Une note a un id, un titre, un corps, et un propriétaire. Affichez une page de notes à `/notes`, ajoutez des actions de création/liste, et gardez la possibilité pour le chat de créer des notes.

Discussion est livrée sans aucun `server/db/schema.ts` (voir [Ce qui est livré](/docs/template-chat#what-ships)), donc le premier changement est un nouveau fichier, suivant la même forme `table`/`text`/`ownableColumns` que tous les autres modèles utilisent :

Le reste de la fonctionnalité suit à partir de là :

- `actions/create-note.ts` — un `defineAction` avec un schéma Zod (`title`, `body`), sur le modèle de `actions/hello.ts`.
- `actions/list-notes.ts` — une action en lecture seule (`readOnly: true`, comme `actions/view-screen.ts`) qui interroge la nouvelle table via `accessFilter`.
- `app/routes/notes.tsx` — une nouvelle route ; l'application utilise le routage par système de fichiers (`flatRoutes()` dans `app/routes.ts`), donc ajouter le fichier suffit à monter `/notes`.
- Un lien dans `app/components/layout/Sidebar.tsx`, ajouté avant `ChatThreadsSection` et pointant vers `/notes`.
- Un ajout à `AGENTS.md` indiquant à l'agent que les notes existent et quelles actions les gèrent.

Une nouvelle action est appelable par le chat dès qu'elle existe — chaque `defineAction` est un outil par défaut, sauf s'il définit `agentTool: false`. Elle ne sera pas nécessairement dans la toute première requête du modèle, cependant : `server/plugins/agent-chat.ts` définit `INITIAL_TOOL_NAMES = ["view-screen", "navigate", "hello", "provider-api-request"]`, qui contrôle uniquement les schémas d'outils envoyés au premier tour. Tout le reste, y compris un tout nouveau `create-note`, reste accessible via `tool-search` et se charge à la demande — n'ajoutez un nom à cette liste que si vous le voulez dans le jeu d'outils par défaut du modèle dès le premier message.

## Utilisez votre propre backend d'agent {#own-agent-backend}

Le modèle utilise par défaut la boucle application-agent intégrée. Pour connecter un backend personnalisé, remplacez le runtime de chat derrière le plugin de chat d'agent au lieu de réécrire l'UI. La route Discussion doit rester un simple moteur de rendu autour de la surface de chat partagée ; le choix du backend appartient à l'adaptateur de plugin/runtime du serveur.

Utilisez cette approche quand votre orchestration de modèle réside déjà ailleurs, mais que vous voulez encore une application avec authentification, fils de discussion, actions, état d'UI, et pages déployables.
