# Überblick

`app/` ist der Ort, an dem Sie die eigentliche Darstellung einer agentennativen App bauen: Seiten, Layout, Komponenten, Styles. `public/` enthält die statischen Assets, die daneben ausgeliefert werden – Icons, Manifest, Markenzeichen. Dies ist eine typische React Router v8 App, keine spezielle Nur-Agenten-Oberfläche, und hier fließt der Großteil der Entwicklungszeit.

Der eine architektonische Unterschied zu einem typischen Frontend: Diese Schicht hat kein eigenes Backend-for-Frontend. Sie liest und schreibt Daten über dieselben Actions, die auch der Agent aufruft, sodass alles, was hier verkabelt wird, automatisch etwas ist, das der Agent auch tun kann.

## Wo der Client hineinpasst {#role}

Browseranfragen, die Agentenschleife und externe API-Clients lösen sich alle zu denselben Actions und derselben SQL-Datenbank auf – es gibt kein separates "App-Backend", das diese Schicht anspricht und das der Agent nicht auch erreichen kann. Eine Funktion hier zu bauen bedeutet, eine UI über einer Operation zu bauen, die der Agent bereits hat, oder eine neue Action zu definieren und gleichzeitig eine UI dafür zu bekommen. Siehe [Actions](/docs/actions) für die Operationsseite dieses Vertrags.

Diese Seite behandelt die Verzeichnisse, in denen Sie bauen, und die Teile der Browser-Laufzeitumgebung, die sonst nirgendwo dokumentiert sind (`root.tsx`, `public/`). Die React-Hooks, die Ihre Komponenten mit Actions und dem Agenten verbinden, leben auf ihren eigenen fokussierten Seiten:

| Seite                                            | Was sie behandelt                                                                                                                 |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| **[Daten & Sync](/docs/client-data)**            | `useActionQuery`, `useActionMutation`, `callAction` und `useDbSync`                                                               |
| **[Agent Chat](/docs/client-agent-chat)**        | `sendToAgentChat`, `askUserQuestion`, `openAgentSettings`, dynamische Vorschläge und bereitgestellter Agent-Chat-Kontextstatus    |
| **[Fortgeschritten](/docs/client-advanced)**     | Direkter `application_state`-Zugriff, Hintergrund-Chat-Sendungen, benutzerdefinierte Vorschlags-Chips und die MCP-App-Host-Bridge |
| **[Sync-Interna](/docs/client-sync-internals)**  | `useChangeVersion`/`useChangeVersions` zur Synchronisierung eines rohen `useQuery`                                                |
| **[Einstiegspunkte](/docs/client-entry-points)** | `app/entry.client.tsx`/`app/entry.server.tsx` und SSR-Anpassung                                                                   |

## Die Browser-Hülle: root.tsx und AppProviders {#app-shell}

`app/root.tsx` ist die Spitze des React-Baums: die HTML-Dokumenthülle (`<html>`, `<head>`, `<Meta>`, `<Links>`, `<Scripts>`) plus der Provider-Stack, in dem jede Route rendert.

```tsx filename="app/root.tsx"
import {
  AppProviders,
  createAgentNativeQueryClient,
} from "@agent-native/core/client/hooks";
import { useState } from "react";
import { Outlet } from "react-router";
import { i18nCatalog } from "./i18n";

export default function Root() {
  const [queryClient] = useState(() => createAgentNativeQueryClient());

  return (
    <AppProviders queryClient={queryClient} i18n={{ catalog: i18nCatalog }}>
      <Outlet />
    </AppProviders>
  );
}
```

`AppProviders` ist der einzelne Wrapper, der Folgendes verkabelt:

- Den React-Query-Client, den `useActionQuery`/`useActionMutation` verwenden (siehe [Daten & Sync](/docs/client-data#fetching-mutating)).
- Den i18n-Katalog, übergeben als `i18n.catalog` (siehe [Internationalization](/docs/internationalization)).
- Clientseitige Sitzungsprüfungen: Auf einem privaten Pfad wird ein anonymer Besucher zur Anmeldung umgeleitet, bevor private UI überhaupt mountet. Übergeben Sie `isPublicPath` für öffentliche/SEO-Routen oder `sessionBypass` für eine Oberfläche, die sich anders authentifiziert, etwa über ein MCP-Embed-Token. Siehe [Authentication](/docs/authentication).

Die meisten Apps mounten hier auch `<AgentSidebar>` oder `<AgentPanel>`, damit jede Route das Agent-Panel kostenlos erhält. Siehe [Drop-in Agent](/docs/drop-in-agent#sidebar).

## Statische Assets: public/ {#public-directory}

Alles in `public/` wird unverändert am Site-Root ausgeliefert, unverarbeitet vom Build. Jede Vorlage liefert:

```text
public/
  favicon.svg           -> Browser-Tab-Symbol
  icon-180.svg           -> apple-touch-icon
  icon-192.svg, icon-512.svg -> PWA-Symbole, referenziert aus manifest.json
  manifest.json          -> Web-App-Manifest (Name, Themenfarbe, Symbole)
  *-logo-*.svg, *-icon-*.svg -> Markenzeichen in der Standard-UI
```

`manifest.json` steuert, was angezeigt wird, wenn ein Besucher die App auf einem Homescreen oder App-Dock installiert – Name, Kurzname, Theme-/Hintergrundfarbe und der Symbolsatz:

```json filename="public/manifest.json"
{
  "name": "My App",
  "short_name": "My App",
  "theme_color": "#18181B",
  "icons": [
    { "src": "icon-192.svg", "sizes": "192x192", "type": "image/svg+xml" }
  ]
}
```

Rebranden Sie eine App, indem Sie diese Dateien ersetzen und `manifest.json` sowie die `<link rel="icon">`/`<link rel="apple-touch-icon">`-Tags in `root.tsx`, die darauf verweisen, aktualisieren – es gibt keinen separaten Registrierungsschritt. Um ein vollständiges Markensystem (Farben, Schriften, Favicon) von einer bestehenden Website zu übernehmen, statt diese Dateien von Hand zu bearbeiten, siehe [Brand Systems and Figma](/docs/template-design-brand-and-figma).

## Utilities: cn {#utilities}

```ts
import { cn } from "@agent-native/toolkit/utils";

<div className={cn(
  "px-4 py-2 rounded",
  isActive && "bg-primary text-primary-foreground",
  className
)} />
```

`cn` führt Klassennamen zusammen (clsx + tailwind-merge) und ist die Standardmethode, um bedingte Tailwind-Klassen über `app/components/` hinweg zu komponieren.
