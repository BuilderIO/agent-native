# Mit dem Agent sprechen

Alles in Design steht dem Agenten über dieselben Aktionen zur Verfügung, die
auch die Oberfläche verwendet. Alles, was Sie anklicken können, können Sie
also auch in einfacher Sprache erfragen. Diese Seite behandelt, wie der Agent
Ihren Bildschirm sieht, und dann nützliche Eingabeaufforderungen nach
Aufgabe. Einen Überblick finden Sie unter [Design](/docs/template-design).

## Wie der Agent Ihren Bildschirm sieht

Bevor er irgendetwas tut, prüft der Agent, was Sie gerade betrachten: welches
Design oder welche Vorlage geöffnet ist, auf welcher Ansicht Sie sich
befinden (die Designliste, Vorlagen, der Editor, Designsysteme oder eine
öffentliche Präsentationsansicht), welcher Bildschirm und welches Element
ausgewählt sind, welcher Inspektor-Tab aktiv ist (Design, Kommentare oder
Code & Messungen), und welches linke Seitenleisten-Panel geöffnet ist
(Datei, Agent, Assets, Import, Werkzeuge oder Tokens). Deshalb löst sich
„mach das dichter“ oder „behebe den Kontrastfehler bei diesem Button“
korrekt auf, ohne dass Sie den Bildschirm oder das Element benennen. Der
Agent weiß bereits, worauf sich „das“ bezieht.

Ein paar Situationen ändern, was der Agent als Nächstes tut:

- **Eine vage Eingabeaufforderung.** Wenn Ihre Anfrage dem Agenten nicht
  genug zum Weiterarbeiten gibt, zeigt er statt zu raten ein
  bildschirmfüllendes Overlay mit klärenden Fragen und wartet im Chat auf
  Ihre Antwort, bevor er etwas generiert.
- **Ein aus einer Vorlage erstelltes Design.** Der Agent kennt bereits die
  gesperrten Abmessungen und Schriften der Vorlage und verfeinert die
  vorhandenen Bildschirme an Ort und Stelle, statt sie neu zu generieren
  oder in der Größe zu ändern.
- **Eine Variante, zwischen der Sie gerade vergleichen.** Wenn Sie zwischen
  ein paar vorgeschlagenen Anpassungen wählen, weiß der Agent, welche noch
  offen sind und welche Sie bereits ausgewählt haben, sodass sich „nimm die
  zweite“ korrekt auflöst.
- **Offene Review-Kommentare.** Der Agent weiß, wie viele offene Kommentare
  auf dem aktuellen Bildschirm existieren und welche bereits in seiner
  Warteschlange zur Bearbeitung stehen, sodass ihm kein von Ihnen
  hinterlassenes Feedback verloren geht.

## Nützliche Eingabeaufforderungen nach Aufgabe

Jede Eingabeaufforderung unten wird zu einer echten Aktion gegen Ihr
tatsächliches Design, dasselbe, aus dem auch die Oberfläche liest und in das
sie schreibt. Hier ist ein durchgerechnetes Beispiel:

<Comparison>

### :blue: Sie fragen

„Gibt es offene Kommentare auf diesem Bildschirm?“

### :green: Was passiert

Das ist eine reine Leseabfrage. Der Agent prüft die echte Anzahl der
Kommentar-Threads für den Bildschirm, auf dem Sie sich befinden, und
antwortet direkt im Chat, zum Beispiel „2 offene Kommentare, 1 bereits in
meiner Warteschlange.“ Auf Ihrem Bildschirm ändert sich nichts, da nichts
erstellt oder bearbeitet wurde.

### Generieren und verfeinern

- **„Erstelle drei Landingpage-Richtungen für ein technisches Analyseprodukt.“** Ein paar wirklich unterschiedliche Varianten erscheinen zum Vergleichen und Auswählen.
- **„Mach dieses Dashboard dichter und für ein Betriebsteam leichter überblickbar.“** Der ausgewählte Bildschirm aktualisiert sich live.
- **„Verwandle diese wiederholte Karte in eine wiederverwendbare Komponente.“** Künftige Änderungen an einer Instanz bleiben von den anderen getrennt, sofern Sie nicht bitten, alle zu aktualisieren.
- **„Füge diesem Button eine Hover-Animation hinzu.“** Eine Bewegungsspur wird erstellt, ohne dass Sie selbst das Motion-Dock öffnen müssen.
- **„Füge dem Hero-Hintergrund einen Wellen-Shader hinzu.“** Wendet den Effekt direkt an, ohne den Auswahldialog des Effekte-Menüs zu durchlaufen.

### Qualität prüfen

- **„Führe eine Barrierefreiheitsprüfung für diesen Bildschirm durch.“** Der Agent prüft ihn und berichtet, was er gefunden hat.
- **„Behebe das Kontrastproblem, das du gerade gefunden hast.“** Die Korrektur wird direkt am Design vorgenommen.

### Externe Inhalte einbringen

- **„Importiere diesen Figma-Frame: [Link].“** Der Frame erscheint als neuer, bearbeitbarer Bildschirm.
- **„Füge dieses HTML als neuen Bildschirm ein.“** Fügt es hinzu, ohne dass Sie selbst das Import-Panel öffnen müssen.
- **„Bring unsere Preisseite aus Figma mit und übernimm sie exakt.“** Pixelgenauer Import, mit einem Genauigkeitsbericht zu allem, was strukturell nicht übernommen werden konnte.

### Marke und Designsysteme

- **„Wende unser gespeichertes Designsystem an und vereinfache das mobile Layout.“** Jede Generierung danach bleibt markenkonform.
- **„Starte ein Designsystem aus unserem GitHub-Repo.“** Indiziert Ihre echten, eingesetzten Tokens, statt zu raten.
- **„Erstelle ein Designsystem basierend auf Material 3.“** Startet von einem echten, gepflegten öffentlichen System statt einer bloßen Nachbildung.

### Vorlagen

- **„Starte ein neues Design aus der Landingpage-Vorlage.“** Kopiert deren Dateien, Abmessungen und gesperrte Ebenen in ein neues Design.
- **„Speichere das als Vorlage namens 'Produkteinführung'.“** Ab sofort in Vorlagen verfügbar, für Sie oder jeden, dem Sie es freigeben.

### Navigieren und organisieren

- **„Wechsle zur Übersichts-Arbeitsfläche.“** Springt aus der Einzelbildschirm-Ansicht heraus.
- **„Öffne den Tab Kommentare.“** Fokussiert diesen Tab im Inspektor.
- **„Benenne dieses Design in 'Q3-Launch-Seite' um.“** Aktualisiert sich sofort, überall, wo das Design aufgelistet ist.

### Export und Verlauf

- **„Exportiere das als ZIP.“** Lädt herunter, ohne dass Sie selbst das Projektmenü öffnen müssen.
- **„Kopiere eine Coding-Handoff-Eingabeaufforderung für diesen Bildschirm.“** Fertig zum Einfügen in einen externen Coding-Agenten.
- **„Stelle die Version von vor einer Stunde wieder her.“** Bringt das Design genau in diesen gespeicherten Zustand zurück.

</Cards>

## Erweiterungen

Design unterstützt Erweiterungen: kleine, isolierte Widgets, die Sie oder
der Agent bauen und in den Editor einfügen können. Die linke Seitenleiste
des Inspektors stellt einen Slot bereit, in dem eine Erweiterung rendern
kann, wobei ihr bereits die ID und der Titel des geöffneten Designs, der
Dateiname und Inhalt des aktiven Bildschirms, der aktuelle Ansichtsmodus und
Zoom, der ausgewählte Bildschirm und das ausgewählte Element sowie das
aktive Werkzeug zur Verfügung stehen. Die Asset-Bibliothek, der
Shader-Füllungs-Picker, der Marken-Token-Prüfer und die Bewegungsvorlagen,
die Sie heute im Editor sehen, sind alle auf demselben Slot aufgebaut. Wie
Sie eine solche bauen, erfahren Sie unter [Erweiterungen](/docs/extensions).
