# Design in einem Multi-App-Arbeitsbereich

Design ist eine App unter vielen in einem
[Dispatch](/docs/template-dispatch)-Arbeitsbereich, und es ist auch direkt
für Agenten erreichbar, die vollständig außerhalb dieses Arbeitsbereichs
leben. Diese Seite behandelt beides: wie die Verbindung zu Dispatch
funktioniert, und wie ein externer Agent die eigenen Aktionen von Design
über MCP aufrufen kann. Einen Überblick finden Sie unter
[Design](/docs/template-design).

## Wie Design sich mit Dispatch verbindet

Ob dies automatisch geschieht, hängt davon ab, wie Design und Dispatch
gemeinsam eingerichtet wurden, nicht davon, ob eine der beiden Apps gehostet
wird oder lokal läuft.

### Gleicher Arbeitsbereich: automatisch

Wenn Design und Dispatch gemeinsam in einen Agent-Native-Arbeitsbereich
generiert oder hinzugefügt (über `create` oder `add-app`) und als eine
Einheit bereitgestellt wurden, teilen sie sich bereits eine `.env`, ein
`A2A_SECRET` und eine Arbeitsbereichsregistrierung. Erkennung und
authentifizierte A2A-Aufrufe funktionieren beide einfach, ohne dass etwas
eingerichtet werden muss, egal ob dieser Arbeitsbereich auf Ihrem Rechner
oder in Produktion läuft.

### Getrennte Deployments: ein manueller Schritt

Wenn Design und Dispatch zwei unabhängig erstellte Agent-Native-Projekte
sind, teilen sie sich kein Secret und können sich noch nicht gegenseitig
aufrufen. Sie zu verbinden erfordert einen manuellen Schritt auf jeder
Seite: Fügen Sie eine `remote-agents/<id>.json`-Ressource mit einem
gemeinsamen Secret hinzu, über Settings → Agent → Sub-agents (Connect agent), oder Dispatch → Agents → Add external agent.
Die vollständige Anleitung finden Sie unter
[A2A-Protokoll](/docs/a2a-protocol).

Um zu prüfen, in welcher Situation Sie sich befinden, fragen Sie den Agenten
einer der beiden Apps: „Welche Apps kannst du sehen?“ Wenn Design in der
Antwort von Dispatch fehlt, befinden Sie sich im zweiten Fall.

## Design von außerhalb des Arbeitsbereichs aufrufen

Design läuft außerdem als gehosteter MCP-Server, mit dem sich andere
Agenten direkt verbinden können, unabhängig davon, ob sie Teil Ihres
Dispatch-Arbeitsbereichs sind oder nicht. Claude, Claude Code, Claude
Desktop, Codex und andere MCP-kompatible Hosts können sich alle verbinden
mit:

```
https://design.agent-native.com/mcp
```

Claude und Claude Desktop fügen dies als benutzerdefinierten Connector
hinzu und melden sich an, um den Zugriff zu genehmigen. Claude Code fügt
dieselbe URL hinzu und führt dann `/mcp` aus, um sich zu authentifizieren.
Codex und andere CLI- oder stdio-Clients führen stattdessen `npx
@agent-native/core@latest connect https://design.agent-native.com` aus, was
einen Browser-Tab zur Autorisierung öffnet und ein pro Benutzer
widerrufbares Token ausstellt, ganz ohne gemeinsames Secret.

Sobald verbunden, erhält der externe Agent denselben Kernworkflow, der unter
[Mit dem Agent sprechen](/docs/template-design-agent) behandelt wird: ein
Design erstellen, ein paar Richtungen zum Vergleichen generieren, den
aktuellen Zustand eines Bildschirms abrufen, eine begrenzte Änderung
vornehmen und ein Coding-Handoff-Paket exportieren, wenn es Zeit ist, das
Ergebnis in echten Code umzuwandeln. Der Agent zeigt eine Inline-Vorschau
oder einen Link „Design öffnen“ zurück in den echten Editor an, statt
rohes HTML in die Konversation einzufügen.

<Callout tone="info">

Wenn ein Design-Tool-Aufruf in Ihrem externen Agenten anfängt, einen
Sitzungs- oder Authentifizierungsfehler zurückzugeben, versuchen Sie es
nicht immer wieder erneut. Führen Sie `/mcp` in Claude Code aus und
verbinden Sie sich erneut, oder führen Sie `npx -y @agent-native/core@latest
reconnect https://design.agent-native.com` in einem beliebigen Terminal
aus. Beide authentifizieren sich neu, ohne irgendetwas neu zu installieren.

</Callout>

## Delegation an Design über Dispatch

Eine Schwester-App braucht keine spezielle Integration, um mit Design
zusammenzuarbeiten. Sie kann dem Agenten von Design eine Anfrage in
einfacher Sprache übergeben, wie „erstelle mir eine Landingpage für dieses
neue Feature“, genauso wie Sie es im Chat tun würden, und Design beantwortet
sie oder handelt direkt danach.

Design muss dafür nie die Zugangsdaten der anfragenden App kennen, oder
umgekehrt. Es muss nur eine echte Anfrage beantworten. Es muss nicht wissen,
wer fragt, oder warum.
