# Folien in einem Multi-App-Arbeitsbereich

Folien ist eine App unter vielen in einem [Dispatch](/docs/template-dispatch)-Arbeitsbereich. Diese Seite behandelt, was das in der Praxis tatsächlich bedeutet: wie die Verbindung funktioniert und auf welche konkreten Arten andere Apps auf Ihre Decks einwirken oder das wiederverwenden können, was darin steckt. Einen Überblick finden Sie unter [Folien](/docs/template-slides).

## Wie Folien sich mit Dispatch verbindet

Ob dies automatisch geschieht, hängt davon ab, wie Folien und Dispatch gemeinsam eingerichtet wurden, nicht davon, ob eine der beiden Apps gehostet wird oder lokal läuft.

### Gleicher Arbeitsbereich: automatisch

Wenn Folien und Dispatch gemeinsam in einen Agent-Native-Arbeitsbereich generiert oder hinzugefügt (über `create` oder `add-app`) und als eine Einheit bereitgestellt wurden, teilen sie sich bereits eine `.env`, ein `A2A_SECRET` und eine Arbeitsbereichsregistrierung. Erkennung und authentifizierte A2A-Aufrufe funktionieren beide einfach, ohne dass etwas eingerichtet werden muss, egal ob dieser Arbeitsbereich auf Ihrem Rechner oder in Produktion läuft. Das ist die erwartete Einrichtung für ein echtes Multi-App-Produkt, das auf Folien aufbaut.

### Getrennte Deployments: ein manueller Schritt

Wenn Folien und Dispatch zwei unabhängig erstellte Agent-Native-Projekte sind, teilen sie sich kein Secret und können sich noch nicht gegenseitig aufrufen. Sie zu verbinden erfordert einen manuellen Schritt auf jeder Seite: Fügen Sie eine `remote-agents/<id>.json`-Ressource mit einem gemeinsamen Secret hinzu, über Settings → Agent → Sub-agents (Connect agent), oder Dispatch → Agents → Add external agent. Die vollständige Anleitung finden Sie unter [A2A-Protokoll](/docs/a2a-protocol).

Um zu prüfen, in welcher Situation Sie sich befinden, fragen Sie den Agenten einer der beiden Apps: „Welche Apps kannst du sehen?“ Wenn Folien in der Antwort von Dispatch fehlt, befinden Sie sich im zweiten Fall.

## Integrationsstrategien

**Decks über die Creative Context Library teilen.** Das Einreichen eines Decks friert eine exakte Version in der gemeinsamen Creative Context Library ein, und jede App im Arbeitsbereich, nicht nur Folien, kann diese Folien später suchen und wiederverwenden. Eine Meeting-Notizen-App könnte eine freigegebene Kennzahlen-Folie in ihre eigene Ausgabe übernehmen, statt sie in einer Eingabeaufforderung zu beschreiben.

**Delegation in natürlicher Sprache über Dispatch.** Eine Schwester-App braucht keine spezielle Integration, um mit Folien zusammenzuarbeiten. Sie kann dem Agenten von Folien eine Anfrage in einfacher Sprache übergeben, wie „erstelle eine 5-Folien-Zusammenfassung der Zahlen dieses Quartals“, genauso wie Sie es im Chat tun würden, und Folien beantwortet sie oder handelt direkt danach. Das ist der eigentliche Mechanismus hinter so etwas wie einer Berichtsanfrage, die in Mail eingeht und zu einem fertigen Deck wird: Dispatch (oder die App, die die Nachricht empfangen hat) delegiert die Anfrage an den Agenten von Folien, und Folien behandelt sie wie jede andere Eingabeaufforderung.

**Entkoppelt bleiben.** Folien muss dafür nie die Zugangsdaten einer Schwester-App kennen, oder umgekehrt. Das A2A-Protokoll und die gemeinsame Creative Context Library sitzen zwischen den Apps, sodass Folien nur eine echte Anfrage beantworten oder eine echte gemeinsame Ressource bereitstellen muss. Es muss nicht wissen, wer anruft oder wie.
