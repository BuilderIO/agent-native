# Design

Design ist ein agentennatives Prototyping-Studio. Statt einer geschichteten
Zeichenfläche generiert der Agent vollständige, eigenständige Alpine- und
Tailwind-HTML-Prototypen, zeigt sie in einer Live-Vorschau und verfeinert das
Ergebnis über Eingabeaufforderungen und Anpassungssteuerelemente. Es ersetzt
ein statisches Mockup-Tool und die Übergabe, die darauf folgt, denn was Sie in
der Vorschau sehen, ist bereits echter, funktionierender Code.

Jede Generierung, jede Anpassung und jeder Export liest und schreibt dieselbe
HTML-Datei, sodass zwischen der Vorschau und dem, was Sie herunterladen,
nichts verloren geht.

## Was ersetzt wird

<Comparison>

### Vorher

- Figma oder ein ähnliches Tool für statische Mockups, dann ein separater Entwickler, der sie in echtes Markup umsetzt
- Raten, wie sich ein Design verhält, indem man ein Artboard in der Größe ändert, statt ein Live-Browser-Rendering zu sehen
- Eine langsame Übergabe zwischen exportierten Spezifikationen und jemandem, der sie von Hand nachbaut
- Die Design-Datei und der ausgelieferte Code driften mit der Zeit auseinander

### Nachher

- Ein HTML-Prototyp, den der Agent generiert, in der Vorschau zeigt und verfeinert, ganz ohne separaten Build-Schritt
- Echtes Alpine- und Tailwind-Markup, das Sie bei jedem Breakpoint live in der Vorschau sehen können
- Bitten Sie den Agenten um eine Layout-, Text- oder Interaktionsänderung, und sehen Sie, wie dieselbe Datei sich aktualisiert
- Exportieren Sie direkt als HTML, ZIP, PDF oder ein Coding-Handoff-Paket, sodass Design und Code ein einziges Artefakt bleiben

</Comparison>

## Design in einem Multi-App-Arbeitsbereich

Wenn Sie Design zusammen mit anderen Apps in
[Dispatch](/docs/template-dispatch) betreiben, ist das nicht der einzige Weg,
es zu erreichen. Design läuft auch als gehostetes Tool, das andere Agenten
direkt aufrufen können, darunter Claude Code und Claude Desktop, über
denselben Verbindungspunkt, den eine Arbeitsbereich-App bereits offenlegt.
Unter [Design in einem Multi-App-Arbeitsbereich](/docs/template-design-integrations)
erfahren Sie, wie die Verbindung tatsächlich funktioniert und welche
Mechanismen wirklich dahinterstecken.

## Was Sie damit machen können

- **Vollständige Prototypen generieren.** Beschreiben Sie den Bildschirm oder die Seite, die Sie brauchen, und der Agent schreibt ein funktionierendes HTML-Dokument mit Tailwind-Styling und Alpine-Interaktionen.
- **Varianten vergleichen.** Generieren Sie ein paar unterschiedliche Richtungen, wählen Sie die stärkste aus und verfeinern Sie weiter, statt von vorne zu beginnen.
- **Eine Marke anwenden.** Verknüpfen Sie ein Designsystem, importieren Sie die Marke von einer Website oder einer Codebasis, oder bringen Sie einen Figma-Frame für einen pixelgenauen Ausgangspunkt mit. Siehe [Funktionen](/docs/template-design-features).
- **Qualität konsistent halten.** Der Agent führt eine Barrierefreiheits- und Sichtprüfung durch, bevor er einen Prototyp für fertig erklärt, und wiederkehrende Muster können zu wiederverwendbaren Komponenten werden. Siehe [Funktionen](/docs/template-design-features).
- **Echte Dateien exportieren.** Exportieren Sie HTML, ZIP, PDF oder ein echtes vektorbasiertes Figma-SVG, oder übergeben Sie den Prototyp mit einem fertigen Handoff-Paket an einen Coding-Agenten. Siehe [Funktionen](/docs/template-design-features).
