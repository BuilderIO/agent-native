# Vorhandene Apps auf Core 0.198.0 aktualisieren

Verwenden Sie diese Anleitung, um eine vorhandene App auf Core 0.198.0 zu
aktualisieren. Führen Sie die Befehle im Stammverzeichnis der App oder des
Workspaces aus und halten Sie vor dem Start einen prüfbaren Quellcode-Diff
bereit. Prüfen Sie entfernte Deployment-Einstellungen separat: Die CLI kann
lokale Umgebungsdateien lesen, aber keine entfernten Umgebungen oder in der
Datenbank gespeicherten Feature-Einstellungen.

## 1. Upgrade und Import-Codemods vorab prüfen

Verwenden Sie die CLI aus Core 0.198.0, damit sie das Migrationsmanifest dieses
Releases lädt:

    npx @agent-native/core@0.198.0 upgrade --codemods --dry-run

Sobald Core 0.198.0 in der App installiert ist, ist dieselbe Vorschau über das lokale CLI-Binary verfügbar:

    npx agent-native upgrade --codemods --dry-run

Der Befehl `--codemods` verwendet `ts-morph`. Falls das Paket im Projekt noch nicht auflösbar ist, installieren Sie es zuerst als Entwicklungsabhängigkeit: `pnpm add -D ts-morph`.

`--codemods` wendet unterstützte Importänderungen standardmäßig an. Fügen Sie `--dry-run` hinzu,
um geplante Dependency-Änderungen, Datei-Diffs und Warnungen vor dem Fortfahren zu prüfen.
`--yes` ist nicht mehr erforderlich.

Das Codemod verwendet die aktiven Core- und Toolkit-Migrationsmanifeste. Es
durchsucht ausschließlich .ts- und .tsx-Dateien (ohne Deklarationsdateien sowie generierte
Dateien und Dependency-Verzeichnisse) und schreibt unterstützte Import- und
Re-Export-Spezifizierer um. Wenn benannte Exporte in verschiedene Module
wandern, kann es eine Deklaration nach Symbolen aufteilen und Aliase sowie
Type-only-Imports erhalten. Einfache CSS-@import-Pfade werden ebenfalls
aktualisiert; bei einem aufgelösten Paketwechsel wird die fehlende Dependency
hinzugefügt.

Die Diagnose erkennt auch CommonJS-Formen mit `require()` und dynamische `import()`-Formen. Das Codemod schreibt literale `import()`-Aufrufe um, wenn das alte Modul genau ein neues Ziel hat. `require()` und dynamische Imports, die eine Aufteilung nach Symbolen erfordern, bleiben unverändert und erzeugen eine Warnung. Ersetzen Sie diese anhand des gemeldeten neuen Importziels und starten Sie anschließend Vite oder `agent-native doctor` erneut. CSS-Pfade in `@import url(...)` werden unabhängig davon umgeschrieben, ob der Pfad in Anführungszeichen steht.

Aufrufstellen und Dateien werden nicht geändert oder verschoben. Nicht
aufgelöste und geplante Moves bleiben mit Warnungen unverändert. Default-,
Namespace-, Side-effect- und Star-Imports oder -Exports lassen sich nicht
aufteilen. symbolbasierte CSS-Imports lassen sich ebenfalls nicht aufteilen. Prüfen Sie diese Fälle
manuell. Entfernte Exporte können eine Codeänderung erfordern; folgen Sie dem
im CLI-Hinweis genannten Migrationsleitfaden.

Die Vorschau zeigt auch den vollständigen Upgradeplan: blockierende
Framework-Overrides oder -Patches, ausstehende Versionsanhebungen für
@agent-native/\*, anhand lokaler Konfiguration erkannte Feature-Dependencies,
Paketinstallation, Aktualisierung der Scaffold-Skills und ein Typecheck, falls
das Root-Paket dieses Skript enthält. Der Befehl setzt Paketversionen auf das
aktuelle latest im Registry und pinnt anschließend die tatsächlich installierten
Versionen. Führen Sie ihn aus, wenn 0.198.0 das gewünschte aktuelle Release ist;
prüfen Sie die aufgelösten Pins, wenn Sie später eine exakte Version benötigen.

## 2. Toolkit und optionale Pakete bestätigen

Zu `@agent-native/toolkit/*` verschobene Imports benötigen `@agent-native/toolkit`. Das Codemod ergänzt Toolkit, wenn ein unterstützter, auflösbarer Import oder Export dorthin verschoben wird. Nutzt die App einen Toolkit-Export, ohne dass eine Dependency ergänzt wurde, installieren Sie die Toolkit-Version passend zu Core 0.198.0:

    pnpm add @agent-native/toolkit@0.198.0
    # npm install @agent-native/toolkit@0.198.0
    # yarn add @agent-native/toolkit@0.198.0

### Vom Upgrade-CLI ausgewählte Dependencies

Das CLI ergänzt diese Dependencies, wenn die lokale Umgebung seine Prüfungen erfüllt. Für PGlite prüft es zuerst `${APP_NAME}_DATABASE_URL` mit normalisiertem App-Namen und danach `DATABASE_URL`; PGlite wird gewählt, wenn keine URL gesetzt ist oder sie mit `pglite:` beginnt. Remote-Umgebungen und datenbankgestützte Feature-Einstellungen kann es nicht prüfen. Kontrollieren Sie deshalb Produktion und Vorschau selbst.

## 3. Upgrade anwenden

Wenden Sie den Plan nach Prüfung der Vorschau und der Feature-Pakete mit der
versionierten CLI an. Das ist wichtig, wenn die App noch Core 0.196 oder eine
ältere CLI verwendet: Sie enthält ein älteres Migrationsmanifest.

    npx @agent-native/core@0.198.0 upgrade --codemods

Nach der Installation von Core 0.198.0 in der App ist derselbe Befehl über die
lokale CLI verfügbar:

    npx agent-native upgrade --codemods

Beide Aufrufe aktualisieren geeignete @agent-native/\*-Dependency-Angaben,
gleichen erkannte Feature-Dependencies ab, starten den Paketmanager, pinnen die
aufgelösten Agent-Native-Versionen, wenden unterstützte Codemods an, aktualisieren
Scaffold-Skills und führen das Root-Typecheck-Skript aus, falls vorhanden. Starten
Sie upgrade nicht noch einmal, nur um die Codemods anzuwenden. Beheben Sie
Warnungen und App-Fehler im App-Code; fügen Sie keine Framework-Overrides oder
-Patches hinzu.

## 4. Ergebnis prüfen

Prüfen Sie den gesamten Diff, besonders übersprungene Codemod-Warnungen und
Dependency-Versionen, und führen Sie anschließend aus:

    npx @agent-native/core@0.198.0 upgrade check
    npx agent-native doctor
    pnpm typecheck

Doctor führt standardmäßig die Prüfungen `migration-manifest` und
`feature-dependencies` aus. Sie melden veraltete Imports und fehlende optionale
Peers für Funktionen, die anhand der lokalen Konfiguration erkannt werden.
Remote-Deployment-Einstellungen und datenbankgestützte Feature-Einstellungen
kann Doctor nicht prüfen. Bestätigen Sie diese separat.

Verwenden Sie für npm oder Yarn den entsprechenden Typecheck-Befehl. Führen Sie
die Test- und Build-Skripte der App aus, sofern vorhanden, meist `pnpm test` und
`pnpm build`. Stellen Sie sicher, dass lokale und entfernte Feature-Einstellungen
in der Tabelle der optionalen Peer-Pakete berücksichtigt sind. Suchen Sie nach
alten Imports aus der folgenden Tabelle. Verbleibende Treffer sollten
beabsichtigt, vom Manifest nicht unterstützt oder durch eine Warnung erklärt
sein.
