# Eine UI zu Ihrem Agenten hinzufügen

Agent-Native gibt einem vorhandenen Agenten einen Workspace für Chat, Genehmigungen, Workflowstatus und Berechtigungen. Der Anbieter behält Reasoning, Tools, Kontext und lange Ausführungen.

Diese Seite beschreibt **eine UI für Microsoft Foundry, Gemini Enterprise, Anthropic Managed Agents oder OpenAI**.

## Verbindung auswählen {#choose-a-connection-path}

| Backend                  | Verbindung in Agent-Native       | Konfiguration                              |
| ------------------------ | -------------------------------- | ------------------------------------------ |
| Microsoft Foundry        | A2A 1.0                          | Agent-Card-URL und Entra-Secret            |
| Gemini Enterprise        | A2A                              | Agent-Card-URL und Google-Secret           |
| Anthropic Managed Agents | Managed Agents API               | Agent-ID, Umgebungs-ID und Vault-Schlüssel |
| OpenAI Agents API        | Benutzerdefinierter A2A-Endpunkt | Agent-Card-URL und Anbieter-Secret         |
| Jeder A2A-Agent          | A2A                              | Agent-Card-URL und optionale Zugangsdaten  |

Öffnen Sie **Settings → Agent → Sub-agents** und wählen Sie **Connect agent** (Owner und Admins). Die Connect-Schaltflächen öffnen das Verbindungsformular mit dem passenden Anbieter. Secrets bleiben im Workspace-Vault; gespeichert wird nur eine Referenz.

## Microsoft Foundry {#microsoft-foundry}

Fügen Sie die A2A-v1.0-Agent-Card-URL ein und wählen Sie die Entra-Zugangsdaten. Für Dienst-zu-Dienst-Zugriff verwenden Sie `https://ai.azure.com/.default` und die Rolle **Foundry Agent Consumer**.

## Gemini Enterprise {#gemini-enterprise}

Fügen Sie die benutzerdefinierte A2A-Card-URL ein und wählen Sie das Bearer-Secret. Agent-Native prüft Card und JSON-RPC-Schnittstelle vor dem Speichern.

## Anthropic Managed Agents {#anthropic-managed-agents}

Wählen Sie **Anthropic Managed Agents**, geben Sie Agent- und Umgebungs-ID ein und wählen Sie den API-Schlüssel. Sessions und Genehmigungen bleiben bei Anthropic und werden im Agent-Native-Chat angezeigt.

## Benutzerdefinierter A2A-Agent {#custom-a2a}

Verwenden Sie **Add by URL** für interne oder selbst gehostete Agents. A2A-0.3- und 1.0-Cards werden geprüft; Fehler und abgelehnte Authentifizierung erscheinen als klare Statuswerte.

Wenn Streaming nicht verfügbar ist, verwendet die Verbindung `message/send`.

## Registries {#registries}

Über die [Global A2A Registry](https://www.a2a-registry.org) können Sie entdecken. Prüfen Sie Card, Host und Authentifizierung und fügen Sie einen Agenten ausdrücklich hinzu, bevor ein Secret verwendet wird.

## UI-Schicht {#ui-layer}

[A2A](/docs/a2a-protocol) überträgt delegierte Aufgaben, während der Agent-Native-Workspace den Nutzerstatus besitzt. Siehe [Connected agents](/docs/agent-mentions#mentioning-agents) und [External agents](/docs/external-agents).
