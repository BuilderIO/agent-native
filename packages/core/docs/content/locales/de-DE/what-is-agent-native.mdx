# Was ist Agent-Native?

Agent-Native ist ein Open-Source-TypeScript-Framework zum Entwickeln autonomer
Agenten mit intuitiven Benutzeroberflächen. Sie definieren jede Fähigkeit einmal
als [Aktion](/docs/actions-overview) – eine typisierte Funktion, die der Agent als
Tool verwendet und die UI aus Code aufruft.

## Warum Agenten mit UIs bauen


Coding-Agenten können den Eindruck erwecken, ein Textfeld reiche aus. Doch das
Textfeld ist nur ein Teil ihrer Arbeitsumgebung. Die Codebasis liefert Kontext,
Tools geben ihnen klare Handlungsmöglichkeiten und Dateien, Tests und
Vorschauen machen die Ergebnisse sichtbar.

Für die meisten Wissensaufgaben gibt es diese Struktur nicht. In einem leeren
Textfeld müssen Menschen erraten, was der Agent kann, welchen Kontext er hat
und was sie ihn fragen sollen.

Eine UI liefert, was dem Textfeld fehlt. Sie macht die Fähigkeiten des Agenten
sichtbar, bringt Kontext und Workflows in die Nutzung und ermöglicht es
Menschen, die Arbeit während ihrer Entstehung zu sehen und zu gestalten.

Mit Agent-Native bauen Sie Agenten auf diese Weise. Die UI bietet klare
Einstiegspunkte, ohne den Agenten auf einen festen Workflow zu beschränken. Da
Agent und UI dieselben Fähigkeiten nutzen, können Menschen Arbeit an den
Agenten delegieren, sie in der UI prüfen oder ändern und zwischen beiden
wechseln, ohne Fortschritt zu verlieren.

Agent-Native verbindet Agent und UI über drei gemeinsame Grundlagen:

- **[Gemeinsame Aktionen](/docs/actions-overview).** Jede Fähigkeit wird einmal
  definiert. Der Agent ruft sie als Tool auf, die UI aus dem Code. Beide Wege
  verwenden dieselbe Validierung, dieselben Berechtigungen und dieselbe
  Implementierung.
- **[Gemeinsame Daten](/docs/server-database).** Aktionen lesen und aktualisieren
  dieselben Daten. So erscheint die Arbeit des Agenten in der UI, und Arbeit aus
  der UI steht dem Agenten zur Verfügung.
- **[Gemeinsamer Anwendungszustand](/docs/context-awareness).** Der
  Anwendungszustand beschreibt, was in der UI geschieht, etwa die aktuelle
  Seite, den ausgewählten Datensatz oder die aktive Ansicht. Agent-Native stellt
  dem Agenten den relevanten Zustand als Kontext bereit, damit er versteht,
  woran die Person arbeitet.

Der Agent klickt sich nicht durch die UI. Er arbeitet über dieselbe
Aktionsschicht wie die UI.

Beispielsweise kann eine Person über die UI ein Support-Ticket zuweisen oder
den Agenten darum bitten. Beide Wege führen dieselbe Aktion aus und aktualisieren
dasselbe Ticket. Die Person kann das Ergebnis in der UI prüfen oder ändern und
den Agenten anschließend von dort aus weiterarbeiten lassen.

## Wann sollten Sie Agent-Native verwenden?

Agent-Native eignet sich gut, wenn:

- der Agent echte Arbeit erledigen soll, statt nur Fragen zu beantworten;
- Menschen eine UI brauchen, um zu sehen, was der Agent tun kann, und um seine
  Arbeit zu prüfen, zu bearbeiten, freizugeben oder zu teilen;
- Menschen zwischen Agent und UI wechseln können sollen, ohne Fortschritt oder
  Kontext zu verlieren.

Wenn Sie nur eine einzelne generierte Antwort benötigen, rufen Sie ein Modell
direkt auf. Folgt der Ablauf einer festen, vorhersehbaren Reihenfolge, sind
gewöhnliche Anwendungslogik oder Automatisierung einfacher. Verwenden Sie
Agent-Native, wenn Agent und UI beide dauerhaft an derselben Arbeit beteiligt
sein sollen.
