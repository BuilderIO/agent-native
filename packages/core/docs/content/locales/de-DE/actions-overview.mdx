# Überblick

Actions sind die einzige Quelle der Wahrheit für alles, was Ihre App tut. Definieren Sie eine mit `defineAction()` und legen Sie sie in `actions/` ab. Jede Oberfläche unten übernimmt sie automatisch. Sie schreiben die Logik einmal. Keine Oberfläche bekommt eine eigene Kopie, und keine kann aus dem Takt der anderen geraten.

<Cards columns={2}>

### :robot: [Agent-Tool](/docs/agent-surfaces)

Der Agent liest die Beschreibung und das Schema als aufrufbares Tool. Fragen Sie im Chat danach, etwa „reply to this ticket" oder „summarize this thread".

### :components: [UI-Hooks](/docs/client-data)

`useActionQuery()`, `useActionMutation()` und `callAction()` rufen dieselbe Action aus React auf. Ein Klick und eine Chat-Nachricht führen exakt dieselbe Operation aus.

### :server: [Framework-Transport](/docs/http-api)

Wird beim Start automatisch unter `/_agent-native/actions/<name>` eingebunden. Die UI-Hooks rufen diese Route im Hintergrund auf, und ein externer HTTP-Client kann sie ebenfalls direkt aufrufen.

### :plug: [MCP-Tool](/docs/actions-other-surfaces#mcp)

Erscheint als Tool für jeden MCP-Host: Claude, Claude Desktop, Cursor, Codex. Verwenden Sie es, wenn ein anderer KI-Client Ihre App steuern soll.

### :network: [A2A-Tool](/docs/actions-other-surfaces#a2a)

Andere agentennative Apps entdecken es und rufen es über A2A auf. Verwenden Sie es, wenn eine zweite App in Ihrem Arbeitsbereich diese hier stellvertretend handeln lassen muss.

### :terminal: [CLI-Befehl](/docs/actions-other-surfaces#cli)

`pnpm action <name>` führt sie von einem Terminal aus. Verwenden Sie sie für Skripte, Cron-Jobs und schnelle manuelle Tests.

</Cards>

Die meisten Apps bauen eine separate API-Schicht zwischen Frontend und Datenbank, die nur der Browser aufrufen kann. Ein Agent, der dieselbe Fähigkeit haben möchte, braucht eine eigene, separate Integration, die erneut geschrieben und gepflegt werden muss. Agentennative Apps überspringen diese Trennung. Die UI und der Agent rufen exakt dieselbe Action auf, sodass es nur eine Implementierung zu schreiben gibt und nur einen Ort, an dem sich ein Bug verstecken kann.

Wenn sowohl die UI als auch der Agent etwas tun müssen, greifen Sie zu einer Action statt zu einer benutzerdefinierten Route. Für den seltenen Fall, dass ein routenförmiges Protokoll die richtige Wahl ist, besuchen Sie [Actions für App-Operationen bevorzugen](/docs/server-overview#actions-first).

## Wo Actions hineinpassen {#role}

`app/` (siehe [Client-Überblick](/docs/client-overview#role)) und der Agent lösen sich beide zu denselben Actions und derselben SQL-Datenbank auf. Es gibt kein separates „App-Backend", das diese Schicht anspricht und das der Agent nicht auch erreichen kann. Eine Funktion zu bauen bedeutet, hier eine Operation zu definieren und gleichzeitig eine UI, ein Agent-Tool und jede andere Oberfläche dafür zu erhalten.

`actions/` selbst ist ein flacher Ordner. Jede Datei ist eine Action: ein `defineAction()`-Aufruf, exportiert als Default-Export der Datei. Das Framework durchsucht diesen Ordner beim Start und bindet jede gefundene Datei ein. Es gibt keinen Registrierungsschritt und keine Index-Datei, die aktuell gehalten werden muss.

Der `run()`-Rumpf einer Action ist regulärer Servercode, daher greift er häufig in ein paar andere Verzeichnisse:

Nichts außerhalb von `actions/` sollte die `run`-Funktion einer Action direkt importieren. Rufen Sie sie stattdessen über eine der obigen Oberflächen auf: das Agent-Tool, einen UI-Hook, HTTP, MCP, A2A oder die CLI. Jeder dieser Pfade durchläuft dieselbe Schemavalidierung, dieselben Zugriffsprüfungen und denselben Audit-Trail.

## Mit einer Action beginnen {#hello-action}

Die erste Operation in einer Chat-first-App kann winzig sein. Ersetzen Sie im Chat-Template
`actions/hello.ts` oder fügen Sie eine neue Datei daneben hinzu:

```ts
// actions/hello.ts
import { defineAction } from "@agent-native/core/action";
import { z } from "zod";

export default defineAction({
  description: "Say hello from the local agent.",
  schema: z.object({
    name: z.string().default("world"),
  }),
  http: { method: "GET" },
  readOnly: true,
  run: async ({ name }) => {
    return { message: `Hello, ${name}!` };
  },
});
```

Führen Sie sie aus demselben Ordner aus:

```bash
pnpm action hello '{"name":"Steve"}'
```

Die CLI akzeptiert ein JSON-Objekt als Action-Eingabe, was den strukturierten
Tool-Aufrufen entspricht, die Agenten bereits machen. Einfache Flags funktionieren
weiterhin für schnelle manuelle Läufe:

```bash
pnpm action hello --name Steve
```

Führen Sie dann die App-Agent-Schleife gegen den Ordner aus:

```bash
npx agent-native agent "Call hello for Steve and explain the result"
```

Das ist dieselbe App-Agent-Schleife, die Ihre geplanten Jobs, Ihre Chat-UI, externe MCP-Tools
und zukünftige Bildschirme verwenden werden. Chat- und Domänen-Templates dienen dazu, UI um Actions
herum hinzuzufügen, nicht als notwendige Voraussetzung für die Action selbst.
