# Organisationen, Teams und Berechtigungen

Eine Organisation definiert Teammitgliedschaft und Mandantengrenze. Ein Workspace bündelt Apps und Bereitstellungskonfiguration, ersetzt aber keine Organisation. Der Server muss Berechtigungen prüfen. Das Ausblenden einer Schaltfläche ist keine Zugriffskontrolle.

## Drei Rollenumfänge

- Organisationsrollen `owner`, `admin` und `member` steuern die Teamverwaltung. Inhaber und Admins verwalten den automatischen Beitritt per E-Mail-Domain; das App-übergreifende A2A-Secret verwaltet nur der Inhaber.
- App-Rollen steuern Funktionen innerhalb einer einzelnen App. Ein Mitglied kann mehrere App-Rollen haben.
- Ressourcenrollen `viewer`, `editor` und `admin` steuern Zugriff auf einen Datensatz.

Die App deklariert Rollen und Berechtigungsschlüssel im Code. Admins können Mitgliederrollen ersetzen und Code-Berechtigungen im Team-Bereich Rollen zuordnen. Ohne Überschreibung gelten die Standardwerte der App. Einladungen können App-Rollen vorab enthalten. App-Admins werden dadurch nicht zu Organisations-Admins.

Für verwaltete Einladungen und die Konfiguration siehe [Verwaltete Bereitstellungen](/docs/administered-deployments). Für Datenzugriff siehe [Security → Data Scoping](/docs/security#data-scoping).

## Benutzergruppen {#user-groups}

Organisationen können wiederverwendbare Benutzergruppen aus ihren aktuellen Mitgliedern anlegen. Inhaber und Administratoren verwalten die Mitgliedschaft, und eine Person kann mehreren Gruppen angehören. Apps können eine Gruppe nutzen, um eine Ressource freizugeben, die Gruppenfreigaben unterstützt, oder den Zugriff auf eine Workspace-Verbindung einzuschränken.

Eine Gruppe ist eine Zugriffsliste, kein Unterteam. Sie hat keine eigenen Organisations- oder App-Rollen, keine separate Datengrenze und keine teamspezifischen Einstellungen, Anweisungen, Kontexte, Skills, Erinnerungen oder Arbeitsansicht. Eine Gruppenfreigabe gewährt allen aktuellen Gruppenmitgliedern dieselbe Ressourcenrolle. Der Zugriff setzt weiterhin die Mitgliedschaft in der Organisation der Ressource voraus.

Details stehen unter [Teilen und Datenschutz → Gruppenfreigaben](/docs/sharing#group-grants) und [Workspace-Verbindungen](/docs/workspace-connections).
