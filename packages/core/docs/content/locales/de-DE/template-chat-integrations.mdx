# Chat in einem Multi-App-Arbeitsbereich

Chat ist eine App unter vielen in einem [Dispatch](/docs/template-dispatch)-Arbeitsbereich. Diese Seite behandelt, was das in der Praxis bedeutet: wie die Verbindung funktioniert und wie der Agent von Chat die anderen Apps in seiner Umgebung erreichen kann. Einen Überblick finden Sie unter [Chat](/docs/template-chat).

## Wie Chat sich mit Dispatch verbindet

Ob dies automatisch geschieht, hängt davon ab, wie Chat und Dispatch gemeinsam eingerichtet wurden, nicht davon, ob eine der beiden Apps gehostet wird oder lokal läuft.

### Gleicher Arbeitsbereich: automatisch

Wenn Chat und Dispatch gemeinsam in einen Agent-Native-Arbeitsbereich generiert oder hinzugefügt (über `create` oder `add-app`) und als eine Einheit bereitgestellt wurden, teilen sie sich bereits eine `.env`, ein `A2A_SECRET` und eine Arbeitsbereichsregistrierung. Erkennung und authentifizierte A2A-Aufrufe funktionieren beide einfach, ohne dass etwas eingerichtet werden muss, egal ob dieser Arbeitsbereich auf Ihrem Rechner oder in Produktion läuft.

### Getrennte Deployments: ein manueller Schritt

Wenn Chat und Dispatch zwei unabhängig erstellte Agent-Native-Projekte sind, teilen sie sich kein Secret und können sich noch nicht gegenseitig aufrufen. Sie zu verbinden erfordert einen manuellen Schritt auf jeder Seite: Fügen Sie eine `remote-agents/<id>.json`-Ressource mit einem gemeinsamen Secret hinzu, über Settings → Agent → Sub-agents (Connect agent), oder Dispatch → Agents → Add external agent. Die vollständige Anleitung finden Sie unter [A2A-Protokoll](/docs/a2a-protocol).

Um zu prüfen, in welcher Situation Sie sich befinden, fragen Sie den Agenten einer der beiden Apps: „Welche Apps kannst du sehen?“ Wenn Chat in der Antwort von Dispatch fehlt, befinden Sie sich im zweiten Fall.

## Integrationsstrategien

**Andere Apps um Hilfe bitten.** Der Agent von Chat kann nachschlagen, welche Apps sich im Arbeitsbereich befinden und was jede davon kann. Er kann dann eine von ihnen bitten, eine bestimmte Aktion auszuführen, und die Antwort in der Konversation verwenden. In einem Arbeitsbereich mit Kalender könnten Sie Chat zum Beispiel fragen „was steht morgen in meinem Kalender?“, und der Agent reicht diese Frage an Kalender weiter, statt zu raten. Chat muss die Verbindung von Kalender zu Google nicht selbst halten. Kalender hat sie bereits.

**Chat als Eingangstür.** Da der Agent jeder App auf dieselbe Weise erreichbar ist, ist eine Konversation in Chat ein natürlicher Ort, um Arbeit anzustoßen, die in anderen Apps liegt. Sie beschreiben an einer Stelle, was Sie möchten, und der Agent entscheidet, welche App es übernehmen soll. Chat eignet sich hierfür gut, weil es keine eigene Domäne hat, die im Weg stünde.

**Entkoppelt bleiben.** Chat braucht nie die Zugangsdaten einer anderen App, und keine andere App braucht die von Chat. Jede App behält ihre eigenen Verbindungen und ihre eigenen Daten. Chat gibt nur eine Anfrage weiter und erhält eine Antwort.
