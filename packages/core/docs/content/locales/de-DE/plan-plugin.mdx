# Plan-Plugin und Marketplace

Die Agent-Native-**Plan**-App wird als ein installierbares Bundle
ausgeliefert. Eine einzige Installation fügt die Plan-Slash-Befehl-Skills
**und** verdrahtet den gehosteten Plan-MCP-Connector (ein entfernter
Tool-Server, mit dem Ihr Agent kommuniziert), sodass der Agent Pläne
generieren und sie in einem Schritt direkt in die Plan-App veröffentlichen
kann. Diese Seite richtet sich an alle, die einen Installationsweg wählen,
eine Installation beheben oder entscheiden, ob Plan bei einem kuratierten
Plugin-Katalog eingereicht werden soll — siehe [Visual Plans](/docs/template-plan)
für das, was die Skills tatsächlich tun.

## Was Sie bekommen {#what-you-get}

Eine Installation gibt Ihnen:

- **Drei Skills** — `/visual-plan` (der kanonische Einstiegspunkt), `/visual-recap` und `/visualize-repo`.
- **Den Plan-MCP-Connector** — registriert gegen die gehostete App unter `https://plan.agent-native.com` (MCP-Endpunkt `https://plan.agent-native.com/mcp`, Servername `plan`).

Standardmäßig veröffentlichen `/visual-plan` und `/visual-recap` in die
gehostete Plan-App — sie erstellen einen Plan über den MCP-Connector und
geben Ihnen einen Link oder Inline-Plan zum Überprüfen. Sie geben nie
einen Inline-Markdown-/ASCII-Plan als Ergebnis in den Chat aus. Wenn ein
Plan-Tool `needs auth`, `Unauthorized` oder `Session terminated`
zurückgibt, authentifizieren Sie den Connector erneut, statt auf
Inline-Ausgabe zurückzufallen. Zugriffstoken sind langlebig
(30-Tage-Standard, gleitende 365-Tage-Erneuerung), sodass dies selten
vorkommen sollte; wenn es passiert, ist die leichtgewichtige Lösung:

```bash
npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex
```

`reconnect` findet und erneuert den Connector anhand der URL für den
ausgewählten lokalen Client — keine Neuinstallation nötig. Starten Sie
nach dem erneuten Verbinden einen neuen Codex-Thread, damit die
Tool-Registry neu lädt. In Claude Code ist das Äquivalent `/mcp` →
**Authentifizieren / Erneut verbinden**, oder derselbe Befehl mit
`--client claude-code`.

Die Ausnahme ist der explizite **Local-Files-Datenschutzmodus**. Wenn
Sie keine DB-Schreibvorgänge wünschen oder
`AGENT_NATIVE_PLANS_MODE=local-files` setzen, dürfen die Skills den
Plan-MCP-Connector nicht aufrufen. Sie schreiben
`plans/<slug>/plan.mdx` plus optional `canvas.mdx`, `prototype.mdx` und
`.plan-state.json`, und zeigen dann lokal eine Vorschau an mit:

```bash
npx @agent-native/core@latest plan local serve --dir plans/<slug> --kind plan --open
```

Dies startet eine kleine lokale Bridge und öffnet die Plan-UI gegen den
lokalen Ordner. (`plan local preview` führt stattdessen eine lokale
Plan-Dev-Server-Route aus, und `plan local preview --out preview.html`
ist ein veraltetes Notventil, das eine eigenständige statische
HTML-Datei schreibt. `plan serve` wird als kurzes Alias für
`plan local serve` akzeptiert.)

Ein paar Local-Files-Modus-Stolperfallen, die Sie kennen sollten:

- **Verwenden Sie einen Chromium-Browser.** Safari blockiert, dass die
  gehostete HTTPS-Plan-Seite die lokale `http://127.0.0.1`-Bridge liest
  (Mixed-Content / privates Netzwerk), sodass die Seite bei „Loading
  plan.“ hängen bleibt. Unter macOS bevorzugt `--open` bereits
  Chrome/Chromium/Edge/Brave; wenn Safari trotzdem geöffnet wird, öffnen
  Sie die ausgegebene URL erneut in einem Chromium-Browser.
- **Die bereitgestellte URL wird in `plans/<slug>/.plan-url`
  geschrieben** (mit `--url-file` überschreibbar). Ein im Hintergrund
  laufender oder headless Agent kann diese Datei lesen, statt die
  langlaufende `serve`-Standardausgabe zu scrapen. Behandeln Sie sie
  wie eine lokale Token-Datei und committen Sie sie nicht.
- **Headless verifizieren**, wenn kein Browser verfügbar ist:
  `npx @agent-native/core@latest plan local verify --dir plans/<slug>`
  startet die Bridge, prüft das Preflight für private Netzwerke und die
  JSON-Nutzlast, gibt Diagnosen aus und beendet sich bei einem Fehler
  mit einem Exit-Code ungleich null — keine menschlichen Augen
  erforderlich.
- **Führen Sie zuerst `plan local check` aus.** Es validiert das MDX
  gegen das Blockschema des Plan-Renderers (einschließlich
  erforderlicher Felder wie `checklist`-Element `id`/`label` und
  `question-form`-Frage `id`/`title`/`mode`), sodass Autorenfehler
  auffallen, bevor sie zur Browserübergabe kommen, statt als
  festhängender Loader.

Für Ordner im aktuellen Repo enthält der direkte lokale Weg
`?path=...`, damit die lokale Plan-App Browser-Bearbeitungen weiterhin
im Repo-Ordner speichern kann. Die Plan-App verwendet
`apps.plan.roots[0].path` in `agent-native.json` als Standardort zum
Speichern hochgestufter lokaler Pläne, mit Rückfall auf `plans/`.

Dies hält Plan-Inhalte aus der Agent-Native-Plan-Datenbank heraus.
Gehostetes Teilen, Kommentare, Screenshots und Plan-Verlauf sind nicht
verfügbar, bis Sie später explizit veröffentlichen.

Agent-Native Desktop hat einen separaten lokalen Dateisynchronisierungsweg
für gehostete Pläne: Die Desktop-App kann einen gehosteten Plan in lokale
MDX-Dateien spiegeln und Bearbeitungen zurück importieren, ohne die
Plan-App zu klonen oder eine CLI auszuführen. Dieser Workflow behält die
gehostete Plan-Datenbank als Source of Truth bei; verwenden Sie den
Local-Files-Datenschutzmodus, wenn das Ziel keine Plan-DB-Schreibvorgänge
sind.

> Das Plugin (`agent-native-visual-plans`) trägt die App-ID
> `visual-plans`, weshalb der Claude-Code-Plugin-Name und der
> Codex-Plugin-Name beide `agent-native-visual-plans` lauten. Der
> Anzeigename der Plan-App ist „Agent-Native Plan“.

## Installationswege {#install}

Es gibt drei Wege hinein. Der **Weg über die universelle CLI** ist der,
den wir standardmäßig empfehlen, weil er die Skills installiert **und**
Ihnen erlaubt, in einem Durchgang zwischen gehostetem, Local-Files- oder
selbst gehostetem Modus zu wählen. Die Plugin-Wege sind für Hosts mit
einem erstklassigen Plugin-/Marketplace-System gedacht und verwenden
standardmäßig gehostete Plans.

### Universeller Skill-Weg (jeder MCP-Host) {#universal}

Funktioniert für jeden Host — Claude Code, Codex, Cursor, Cline, Goose,
ChatGPT-Custom-MCP-Apps, Claude Cowork und alles andere
MCP-Kompatible. Die Agent-Native-CLI installiert die Plan-Skills,
registriert den gehosteten Plan-MCP-Connector **und führt im selben
Schritt die Authentifizierung für den/die ausgewählten lokalen
Client(s) aus**, sodass Ihr erster Tool-Aufruf nicht an einer
OAuth-Wand scheitert:

```bash
npx @agent-native/core@latest skills add visual-plan
```

Dies installiert `visual-plan` plus die begleitenden Skills
`visual-recap` und `visualize-repo`, registriert dann den
`plan`-Connector und führt anschließend die Authentifizierung aus
(OAuth-Aufforderung für gehostetes, kontogestütztes Teilen). Nützliche
Flags:

- `--client codex|claude-code|claude-code-cli|cowork|all` — für welche
  lokalen Agenten die MCP-Konfiguration geschrieben wird (Standard
  `all`).
- `--no-connect` — registriert den Connector ohne Authentifizierung;
  führen Sie später
  `npx @agent-native/core@latest connect https://plan.agent-native.com --client all`
  aus, oder wählen Sie einen engeren `--client`.
- `--mode hosted|local-files|self-hosted` — wählen Sie gehostetes
  Teilen, vollständig lokale MDX-Dateien oder Ihre eigene Plan-App.
- `--mcp-url <url>` — richtet den Connector auf einen benutzerdefinierten
  Ursprung (einen ngrok-Tunnel, einen lokalen Dev-Server oder eine
  selbst gehostete Bereitstellung) statt auf den gehosteten Standard.
- `--with-github-action` — schreibt außerdem die PR-Visual-Recap-GitHub-Action
  (siehe [PR Visual Recap](/docs/pr-visual-recap)).

Interaktive Installationen bieten auch die PR-Visual-Recap-Action an,
wenn kein Workflow vorhanden ist. Sagen Sie während der
Skill-Einrichtung Ja, um sie hinzuzufügen, oder führen Sie den obigen
Befehl später mit `--with-github-action` aus. Nachdem der Workflow
geschrieben wurde, führen Sie aus:

```bash
npx @agent-native/core@latest recap setup
npx @agent-native/core@latest recap doctor
```

`recap setup` konfiguriert die GitHub-Action-Secrets und -Variablen,
wo möglich, und `recap doctor` überprüft den Workflow, das lokale
Publish-Token, den GitHub-Repo-Zugriff und die erforderliche
Actions-Konfiguration. Starten Sie nach Abschluss der Installation den
Agenten-Client neu oder laden Sie ihn neu, damit die neuen Skills und
Tools geladen werden, und führen Sie dann `/visual-plan` aus.

> Hinweis: Das bloße
> `npx skills@latest add BuilderIO/agent-native --skill visual-plan`
> (Vercel-/Open-Skills-CLI) installiert **nur Anweisungen** — es
> registriert den MCP-Connector nicht. Verwenden Sie die obige
> Agent-Native-CLI, wenn Sie möchten, dass der Connector ebenfalls
> verdrahtet wird.

### Claude Code (Plugin) {#claude-code}

Das öffentliche Repo `BuilderIO/agent-native` ist selbst ein
Claude-Code-Plugin-Marketplace, sodass Sie es direkt hinzufügen — kein
Build-Schritt. In Claude Code:

```text
/plugin marketplace add BuilderIO/agent-native
/plugin install agent-native-visual-plans@agent-native-apps
/reload-plugins
/mcp        # authenticate the Plan connector (one OAuth approval)
```

`/plugin install` fügt die Plan-Skills und eine **reine URL**-MCP-Konfiguration
hinzu (keine Geheimnisse im Paket); `/mcp` → **Authentifizieren** schließt
den OAuth-Handshake ab. Verwenden Sie stattdessen den universellen
CLI-Weg, wenn Sie den Local-Files- oder selbst gehosteten Modus
möchten.

> Der Marketplace-Katalog heißt `agent-native-apps` und das Plan-Plugin
> heißt `agent-native-visual-plans`, sodass das Installationsziel immer
> `agent-native-visual-plans@agent-native-apps` lautet.

### Codex (Plugin) {#codex}

Dasselbe Repo ist ein Codex-Plugin-Marketplace. Fügen Sie es hinzu,
installieren Sie das Plugin und authentifizieren Sie dann den
Connector:

```bash
codex plugin marketplace add BuilderIO/agent-native
codex plugin add agent-native-visual-plans@agent-native-apps
codex mcp login plan   # OAuth in the browser
```

Starten Sie nach der Installation **einen neuen Codex-Thread**, damit
die Skills und MCP-Tools in die Sitzung geladen werden. Das Plugin
liefert einen reinen URL-Connector (`[mcp_servers.plan]` →
`https://plan.agent-native.com/mcp`); `codex mcp login plan` führt den
OAuth-Flow aus. Der obige universelle CLI-Weg funktioniert auch für
Codex
(`npx @agent-native/core@latest skills add visual-plan --client codex`),
wenn Sie einen einzigen Befehl bevorzugen, der installiert und
gleichzeitig authentifiziert, oder wenn Sie den Local-Files- oder
selbst gehosteten Modus möchten.

<Callout tone="info">

**Ältere Installationen:** Wenn Ihre Konfiguration noch einen Eintrag
`agent-native-plans` hat, der auf dieselbe URL zeigt, konsolidiert das
Ausführen von
`npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex`
für Codex, oder derselbe Befehl mit Ihrem Ziel-`--client`, diesen zum
kanonischen Namen `plan`.

</Callout>

## Updates {#updates}

Die Plugin-Wege aktualisieren sich automatisch — Sie packen die
Marketplace nicht neu und fügen sie nicht erneut hinzu für routinemäßige
Skill-Änderungen:

- **Claude Code** — der Marketplace-Eintrag setzt `autoUpdate: true`,
  und das Plugin verwendet Commit-SHA-Versionierung, sodass Claude Code
  beim Start neue Versionen aus dem Repo zieht; führen Sie
  `/reload-plugins` aus, um zu aktivieren. Jeder Push auf den
  Default-Branch des Repos erreicht installierte Nutzer automatisch.
- **Codex** — die Plugin-`version` bettet einen Inhalts-Hash der
  gebündelten Skills und des MCP-Endpunkts ein (z. B.
  `1.0.0+codex.<hash>`), sodass jede Skill- oder Endpunktänderung eine
  neue Version ergibt. Codex' Start-Auto-Upgrade installiert
  konfigurierte Git-Marketplaces von selbst neu; **starten Sie einfach
  einen neuen Thread**, um die Änderung zu übernehmen. Für
  routinemäßige Updates ist kein manuelles
  `codex plugin marketplace upgrade` nötig.
- **Weg über die universelle CLI** — führen Sie
  `npx @agent-native/core@latest skills status visual-plan` aus, um
  kopierte Skill-Ordner zu prüfen, oder
  `npx @agent-native/core@latest skills update visual-plan`, um sie an
  Ort und Stelle zu aktualisieren. Ein erneutes Ausführen von
  `skills add visual-plan` funktioniert weiterhin, wenn Sie den
  Connector auch neu registrieren/authentifizieren möchten. `@latest`
  zieht immer die aktuellen Skills aus dem veröffentlichten
  `@agent-native/core`-Paket.

Der Connector zeigt auf eine **gehostete** App, sodass die Actions und
die Live-Tool-Oberfläche der Plan-App immer die bereitgestellte Version
widerspiegeln, unabhängig davon, wann Sie installiert haben; nur die
gebündelten Skill-Anweisungen folgen den obigen
Update-Mechanismen.

<Callout tone="info">

**Maintainer:** Das Marketplace-Bundle (`.claude-plugin/`,
`.agents/plugins/`) wird aus den kanonischen Plan-Skills von
`pnpm sync:plan-marketplace` generiert und in CI von
`pnpm guard:plan-marketplace` verifiziert, sodass der veröffentlichte
Marketplace immer mit den kanonischen Skills übereinstimmt. Bearbeiten
Sie den Skill, führen Sie `pnpm sync:plan-marketplace` aus, und
committen Sie.

</Callout>

## Müssen Sie etwas einreichen? {#submission}

**Es ist keine Einreichung oder Überprüfung erforderlich, um dies zu
verteilen oder zu installieren.** `BuilderIO/agent-native` ist ein
selbst gehosteter, öffentlicher Git-Marketplace, sodass Nutzer ihn mit
den obigen Befehlen direkt hinzufügen — sowohl auf **Claude Code als
auch auf Codex** — ohne Antrag oder Genehmigung. Der Weg über die
universelle CLI benötigt überhaupt keinen Marketplace.

Optionale Auffindbarkeit, falls Sie einen öffentlichen Eintrag möchten:

- **Claude Code** hat einen Community-Marketplace, bei dem Sie sich
  _optional_ für eine Auflistung bewerben können (Einreichung plus
  eine automatisierte Überprüfung). Der offizielle,
  Anthropic-kuratierte Marketplace wird nach Anthropics eigenem
  Ermessen gelistet — es gibt keine offene Self-Service-Bewerbung.
  Keines von beidem ist erforderlich, um die obigen
  Installationsbefehle zu verwenden.
- **Codex** hat einen von OpenAI kuratierten Plugin-Katalog (eine
  geschlossene Zulassungsliste, die eher als Partnerschaft entsteht
  denn als Self-Service-Einreichung). Selbst gehostete
  Git-Marketplaces und der CLI-Weg benötigen keine Einreichung, um zu
  funktionieren.

Kurz gesagt: Liefern Sie es als selbst gehosteten/öffentlichen
Git-Marketplace aus, und Nutzer installieren direkt; reichen Sie es nur
bei einem kuratierten Katalog ein, wenn Sie es zur Auffindbarkeit
gelistet haben möchten.

## Plugin vs. Skill {#plugin-vs-skill}

Ein **Skill** ist eine einzelne `SKILL.md`-Anweisungsdatei, die der
Agent liest, wenn eine Aufgabe passt. Ein **Plugin**
(Claude-Code-Marketplace-Plugin oder Codex-Plugin) ist ein Paket, das
einen oder mehrere Skills **plus** einen MCP-Connector und Metadaten
bündelt, sodass ein Host alles in einem Schritt installieren kann.

Unter der Haube werden alle drei Wege aus derselben Quelle von der CLI
`npx @agent-native/core@latest app-skill` erzeugt: `app-skill pack`
baut die Marketplace-/Plugin-Adapter, und `skills add` ist der
freundliche Einzelschritt-Installer, der den MCP-Connector auch
registriert und authentifiziert. Siehe [Skills Guide](/docs/skills-guide)
für das App-Skill-Manifestformat, und [External Agents](/docs/external-agents)
für die Verbindung zu einem beliebigen MCP-Host und den
`npx @agent-native/core@latest connect`-Flow.
