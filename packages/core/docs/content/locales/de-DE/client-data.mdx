# Daten & Sync

Der primäre Weg, App-Daten aus dem Client zu lesen und zu schreiben, führt über [Action](/docs/actions-overview)-Hooks. Indem Anfragen in Actions eingebettet werden, können sowohl Ihr Client als auch der Agent auf dieselbe Weise mit Ihrer Anwendung interagieren.

Im folgenden Beispiel wird ein Ticket manuell über ein Dropdown und dann über den Chat-Agenten dem aktuellen Benutzer zugewiesen. Sowohl die UI als auch der Agent greifen auf dieselbe Action zu.

### Action-Hooks {#action-hooks}

Es gibt zwei Action-Hooks, die Sie am wahrscheinlichsten verwenden werden: `useActionQuery()` und `useActionMutation()`. Diese beiden Hooks bieten Zugriff auf die Actions Ihrer App.

#### useActionQuery {#use-action-query}

<Signature

    {

      optional: true,
      description:
        "Alles aus den [useQuery-Optionen](https://tanstack.com/query/latest/docs/framework/react/reference/useQuery) außer `queryKey` und `queryFn`, die der Hook selbst setzt.",
    },
  ]}
  returns={{
    type: "UseQueryResult<TResult>",
    description:
      'Zwischengespeichert unter `["action", name, params]`. Ruft automatisch erneut ab, sobald eine mutierende Action abschließt, ohne manuelle Invalidierung.',
  }}
/>

Dieser Hook ist für schreibgeschützte Actions gedacht. Es ist ein dünner Wrapper um die Funktion [useQuery()](https://tanstack.com/query/latest/docs/framework/react/reference/useQuery).

Im folgenden Beispiel wird die Action `list-tickets` aufgerufen. Dies ähnelt einer GET-Anfrage für alle Tickets.

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery("list-tickets", {});
```

Das folgende Beispiel zeigt eine Anfrage, um ein einzelnes Ticket über die Action `get-ticket` abzurufen. Eine `ticketId` wird übergeben, um die Abfrage auf ein bestimmtes Ticket zu beschränken. Die zusätzliche Option `enabled` sorgt dafür, dass die Abfrage nicht automatisch läuft, sondern nur, wenn eine `ticketId` vorhanden ist.

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery(
  "get-ticket",
  { ticketId: ticketId ?? "" },
  { enabled: Boolean(ticketId) },
);
```

  }}
/>

Dieser Hook ist für Actions gedacht, die Daten ändern, wie Erstellen, Aktualisieren oder Senden. Es ist ein dünner Wrapper um die Funktion [useMutation()](https://tanstack.com/query/latest/docs/framework/react/reference/useMutation).

Im Gegensatz zu `useActionQuery()` wird die Eingabe der Action nicht dem Hook selbst übergeben. Sie wird `mutate()` oder `mutateAsync()` übergeben, wenn Sie bereit sind, die Mutation auszuführen.

Im folgenden Beispiel wird die Action `send-ticket-reply` aufgerufen, um eine Antwort auf ein Ticket zu posten. Rufen Sie `mutate()` aus einem Event-Handler auf, etwa dem `onClick` einer Schaltfläche.

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply");

mutate({ ticketId, body: draft });
```

Das folgende Beispiel zeigt dieselbe Mutation mit einer `onSuccess`-Option. Die Cache-Invalidierung erfolgt nach jeder Mutation automatisch, daher wird `onSuccess` nur für lokale Nebeneffekte benötigt, etwa das Leeren des Antwort-Composers, nachdem die Antwort gesendet wurde.

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply", {
  onSuccess: () => setDraft(""),
});

mutate({ ticketId, body: draft });
```

### callAction {#call-action}

  returns={{
    type: "Promise<TResult>",
    description:
      "Im Gegensatz zu den obigen Hooks gibt es keinen Cache und kein automatisches erneutes Abrufen. Kombinieren Sie es mit einer manuellen Invalidierung, wenn andere UI vom Ergebnis abhängt.",
  }}
/>

Diese Funktion ist für imperative Einzelaufrufe von Actions außerhalb eines React-Render-Flows gedacht, etwa einen einfachen Event-Handler, ein Skript oder einen anderen Nicht-React-Codepfad. Sie gibt direkt ein Promise zurück statt eines Hook-Ergebnisses.

Im folgenden Beispiel wird die Action `update-ticket` aus einem Tastenkürzel-Handler außerhalb des Render-Flows von React aufgerufen, um das Ticket einem Mitarbeiter zuzuweisen.

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction("update-ticket", {
  ticketId,
  assignedToEmail: "jordan@example.com",
});
```

Das folgende Beispiel zeigt denselben Aufruf mit einer `timeoutMs`-Option, nützlich für Actions, die berechtigterweise länger als das Standard-Timeout von 60 Sekunden dauern.

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction(
  "update-ticket",
  { ticketId, assignedToEmail: "jordan@example.com" },
  { timeoutMs: 120_000 },
);
```

Jede Anfrage von `useActionQuery()`, `useActionMutation()` und `callAction()` ist durch ein 60-Sekunden-Timeout begrenzt, und Timeouts erscheinen als Fehler statt stillschweigend erneut zu versuchen. `useActionQuery()` bricht außerdem automatisch überholte Anfragen ab, mithilfe des Abort-Signals von React Query.

Dieser Hook ist dafür gedacht, die UI mit Datenbankänderungen synchron zu halten, die außerhalb Ihrer eigenen Actions passieren, wie ein Agent-Schreibvorgang, ein Webhook oder eine Änderung aus einem anderen Browser-Tab. Er lauscht auf Änderungen über Server-Sent Events und greift auf Polling zurück, wenn Server-Sent Events nicht verfügbar sind.

```ts
import { useDbSync } from "@agent-native/core/client/hooks";
import { useQueryClient } from "@tanstack/react-query";

function App() {
  const queryClient = useQueryClient();

  useDbSync({
    queryClient,
    pollUrl: "/_agent-native/poll",
    onEvent: (data) => console.log("Data changed:", data),
  });

  return <div>...</div>;
}
```

Für normales CRUD bevorzugen Sie `useActionQuery()` und `useActionMutation()`. Mutierende Actions geben `source: "action"` aus, sodass diese Hooks sofort erneut abrufen. Änderungen vom Agenten, einem Webhook oder einem anderen Tab kommen stattdessen über `useDbSync()` an, per SSE oder dem Polling-Fallback. Wenn ein roher `useQuery()`-Aufruf auf einem benutzerdefinierten Schlüssel synchronisiert werden muss, siehe [Sync-Interna](/docs/client-sync-internals). Wenn Sie direkt in `application_state` schreiben müssen, siehe [Fortgeschritten](/docs/client-advanced).
