# Entwicklerhandbuch

Diese Seite richtet sich an alle, die die Folien-Vorlage anpassen oder erweitern: das SQL-Datenmodell, wie gleichzeitige Schreibvorgänge sicher bleiben, jede vom Agenten aufrufbare Aktion, die Routenübersicht und wo Sie häufige Änderungen vornehmen.

## Schnellstart

```bash
npx @agent-native/core@latest create my-slides --standalone --template slides
```

Den Rest der Einrichtung (`cd`, `pnpm install`, `pnpm dev`) und die Grundlagen des Frameworks finden Sie unter [Erste Schritte](/docs/getting-started).

## Persistenzmodell

Jedes Deck ist ein einzelner JSON-Blob in `decks.data`. Jeder Schreibvorgang läuft über eine serverseitige Lesen-Ändern-Schreiben-Aktion, die eine Sperre pro Deck hält, sodass gleichzeitige Schreiber, ein Mensch und der Agent, oder zwei Menschen, die verschiedene Folien desselben Decks bearbeiten, sich niemals gegenseitig die Arbeit überschreiben.

- **Agenten-Aktionen** (`add-slide`, `update-slide`) verwenden eigene, dedizierte, granulare Aktionen und teilen sich dieselbe Sperre.
- **Der Browser-Editor** reiht granulare Operationen (`patch-slide`, `delete-slide`, `reorder-slides`, `add-slide`, `patch-deck-fields`) über `patch-deck` ein, statt ein vollständiges Deck-PUT durchzuführen.

<Callout id="doc-block-slides10" tone="warning">

Wenn Sie den Speicherpfad des Editors erweitern, reihen Sie eine neue Operation über `patch-deck` ein. Fügen Sie kein neues vollständiges Deck-PUT hinzu. Das würde das Last-Write-Wins-Rennen wieder einführen, das die Sperre gerade verhindern soll.

</Callout>

Framework-Freigabetabellen (`deck_shares`, `design_system_shares`) ordnen Prinzipale, Nutzer oder Organisationen, Betrachter-/Bearbeiter-/Admin-Rollen pro Ressource zu und werden über den gemeinsamen `createSharesTable`-Helper erstellt, statt handgeschrieben zu sein.

#### Folienstruktur

Jede Folie innerhalb von `decks.data` sieht so aus:

```json
{
  "id": "slide-1",
  "layout": "title",
  "content": "<div class=\"fmd-slide\" style=\"...\">...</div>"
}
```

`content` ist rohes HTML. Der Renderer stellt das feste Seitenverhältnis und den Hintergrund bereit, und das HTML stellt alles bereit, was sich darin befindet. Auch umfangreiche Einbettung wird unterstützt: handgezeichnete Diagramme und live gerenderte Grafiken können neben einfachem HTML in einer Folie enthalten sein.

## Aktionsinventar

### Deck-Lebenszyklus

- `create-deck` — neues Deck, optional mit vorbefüllten Folien, oder ein atomarer Massenaustausch der Folien eines bestehenden Decks. Lassen Sie `slides` weg oder übergeben Sie `[]` für ein leeres Deck. Die Aktion öffnet das neue Deck über den Anwendungsstatus.
- `get-deck` — vollständiges Deck-JSON oder eine kompakte Folien-Zusammenfassungsansicht
- `list-decks` — jedes Deck, das der Aufrufer sehen kann, mit leichten/kompakten/vollständigen Folien-Projektionen für günstiges Polling
- `duplicate-deck` — ein Deck mit neuen Folien-IDs kopieren
- `update-deck-aspect-ratio` — 16:9, 1:1, 9:16 oder 4:5

`add-deck`, `save-deck` und `delete-deck` unterstützen die optimistischen Erstellungs-, Rückgängig-/Wiederholen- und Löschabläufe des Browser-Editors. Der Agent verwendet stattdessen `create-deck`, `add-slide`/`update-slide`/`patch-deck` sowie die eigenen Freigabe-Aktionen des Frameworks.

### Zugriffsanfragen

- `request-deck-access`, `approve-deck-access-request`, `get-deck-access-status` — der Zugriffsanfrage-Ablauf für private Decks: ein Besucher ohne Zugriff fordert ihn an, der Eigentümer genehmigt oder verweigert dies über die App oder die Route `/access-request/approve`, und beide Seiten können den aktuellen Status abfragen

### Folienbearbeitungen

- `add-slide` — eine Folie anhängen (oder an einer Position einfügen). Rufen Sie sie nacheinander nach einem leeren `create-deck` auf, damit der Editor den Fortschritt anzeigen kann.
- `update-slide` — chirurgisches Suchen/Ersetzen oder vollständige Inhaltsbearbeitung einer Folie
- `patch-deck` — die granulare Operationswarteschlange, die der Browser-Editor statt eines vollständigen Deck-PUT verwendet
- `get-layout-overflows` — vom Browser gemessene Folien-Passgenauigkeitsergebnisse lesen, sodass eine Bearbeitung, die nicht mehr in ihr Layout passt, erkannt und überarbeitet werden kann

### Verlauf

- `list-deck-versions`, `get-deck-version`, `restore-deck-version` — jeder Schreibvorgang erstellt zuerst einen Snapshot, sodass jeder Zeitpunkt aufgelistet und wiederhergestellt werden kann

### Kommentare

- `list-slide-comments`, `add-slide-comment`, `update-slide-comment`, `delete-slide-comment`

### Import

- `import-pptx`, `import-docx`, `import-google-doc` — dedizierte Importer für jeweils ein Format
- `import-google-slides-reference` — ein Google Slides-Deck als wiederverwendbares Referenz-Deck importieren, statt dessen Inhalt in das Arbeits-Deck zu übernehmen
- `import-file` — ein einziger Einstiegspunkt für PPTX, DOCX oder PDF, oder eine Figma-`.fig`-Datei (die statt in einen Folienimport in die Builder-Designsystem-Indizierung geleitet wird)
- `extract-pdf` — reiner Textauszug eines PDFs, nur über die CLI, hauptsächlich für lokales Debugging

### Export

- `export-pptx` — natives, bearbeitbares PowerPoint
- `export-google-slides` — generiert dasselbe PPTX sowie einen fertigen Google Slides-Import-Link
- `export-html` — eine eigenständige, in sich geschlossene HTML-Datei mit integrierter Tastaturnavigation

### Designsysteme

- `create-design-system`, `update-design-system`, `delete-design-system`, `get-design-system`, `list-design-systems`, `set-default-design-system`, `apply-design-system` (eines mit einem Deck verknüpfen)
- `get-workspace-defaults`, `set-workspace-defaults` — das arbeitsbereichsweite Standard-Deck und -Designsystem. Das Festlegen ist nur Admins vorbehalten
- `analyze-brand-assets`, `import-document`, `import-from-url`, `import-code` — sammeln rohe Markensignale (Website-CSS/-Schriften, hochgeladene Dokument- oder Code-Dateiinhalte) für ein **lokales**, vom Agenten entworfenes Designsystem
- `index-design-system-with-builder`, `sync-design-system-with-builder`, `import-design-project` — der Builder-indizierte Pfad für Figma-Dateien, verbundene Code-/GitHub-Repos und `design.md`. `import-design-project` startet von einem bestehenden Designsystem aus, statt von einer Rohquelle

### Creative Context

- `clone-context-slide` — eine angepinnte Library-Folie unverändert in ein Deck einfügen, ohne deren HTML/CSS neu zu generieren
- `clone-creative-context-deck` — eine exakte, verwaltete Deck-Version nachbilden
- `get-deck-reference-context` — die visuelle Sprache eines bestehenden Decks als wiederverwendbare Musterbibliothek extrahieren
- Abruf und Library-Einreichung (Suche, Abrufen eines Kontextelements, Verwalten der Library-Mitgliedschaft) sind gemeinsame Framework-Aktionen, die der Agent in jeder App, die Creative Context unterstützt, auf dieselbe Weise aufruft. Das Abrufverfahren und die Wiederverwendungsleiter finden Sie im Skill `creative-context`.

### Eskalation und bereitgestellte Daten

- `provider-api-catalog`, `provider-api-docs`, `provider-api-request` — roher Google-Drive-API-Zugriff, wenn eine vorgefertigte Import-/Export-Aktion zu eng ist. Folien löst die Authentifizierung über das verbundene Google Docs-Konto des Nutzers auf
- `list-staged-datasets`, `query-staged-dataset`, `delete-staged-dataset` — ein großes bereitgestelltes Provider-Ergebnis aggregieren, ohne es erneut abzurufen

### Navigation und Kontext

- `view-screen` — was der Nutzer sich gerade ansieht: geöffnetes Deck, aktuelle Folie und jede aktive visuelle Auswahl
- `navigate` — die Oberfläche zu einem Deck, einer Folie oder einer Ansicht bewegen

## Anpassen

Die Folien-Vorlage ist vollständig anpassbar. Wichtige Stellen, die Sie beim Erweitern beachten sollten:

#### Actions — `templates/slides/actions/`

Jede vom Agenten aufrufbare Operation befindet sich hier als TypeScript-Datei, automatisch eingebunden unter `POST /_agent-native/actions/:name` und von der CLI aus aufrufbar als `pnpm action <name>`. Fügen Sie hier eine neue Datei hinzu, um dem Agenten eine neue Fähigkeit zu geben.

  code={
    'import { defineAction, fail } from "@agent-native/core/action";\nimport { assertAccess } from "@agent-native/core/sharing";\nimport { eq } from "drizzle-orm";\nimport { z } from "zod";\n\nimport { getDb, schema } from "../server/db/index.js";\nimport { notifyClients } from "../server/handlers/decks.js";\nimport { withDeckLock } from "./patch-deck.js";\n\nexport default defineAction({\n  description:\n    "Surgically edit a slide\'s content using search-replace or full replacement. " +\n    "Syncs live to open editors. Prefer this over full deck rewrites.",\n  schema: z.object({\n    deckId: z.string(),\n    slideId: z.string(),\n    find: z.string().optional(),\n    replace: z.string().optional(),\n    fullContent: z.string().optional(),\n  }),\n  run: async ({ deckId, slideId, find, replace, fullContent }) => {\n    await assertAccess("deck", deckId, "editor");\n    return withDeckLock(deckId, async () => {\n      const db = getDb();\n      const [row] = await db\n        .select()\n        .from(schema.decks)\n        .where(eq(schema.decks.id, deckId));\n      if (!row) {\n        fail(`Deck ${deckId} not found`, { errorCode: "deck_not_found", statusCode: 404 });\n      }\n\n      const deck = JSON.parse(row.data);\n      const slide = deck.slides.find((s: { id: string }) => s.id === slideId);\n      if (!slide) {\n        fail(`Slide ${slideId} not found`, { errorCode: "slide_not_found", statusCode: 404 });\n      }\n\n      if (fullContent) {\n        slide.content = fullContent;\n      } else if (find) {\n        const idx = slide.content.indexOf(find);\n        if (idx === -1) {\n          fail("Text not found", { errorCode: "slide_find_no_match" });\n        }\n        slide.content =\n          slide.content.slice(0, idx) +\n          (replace ?? "") +\n          slide.content.slice(idx + find.length);\n      }\n\n      deck.updatedAt = new Date().toISOString();\n      await db\n        .update(schema.decks)\n        .set({ data: JSON.stringify(deck), updatedAt: deck.updatedAt })\n        .where(eq(schema.decks.id, deckId));\n\n      notifyClients(deckId, { slideId, actor: "agent" });\n      return { ok: true, deckId, slideId };\n    });\n  },\n});'

Die meisten UI-Anpassungen des Editors finden unter `app/components/editor/` statt: die Folien-Leinwand, die Symbolleiste, die Seitenleiste, das Blasenmenü, das Schrägstrichmenü und das Verlaufspanel.

#### Skills — `templates/slides/.agents/skills/`

Agent-Skills, die Muster erklären, wenn der Agent Code ändern muss:

- `create-deck` — wie man ein neues Deck erstellt, mit exakten HTML-Folienvorlagen für jedes Layout
- `slide-editing` — wie man einzelne Folien bearbeitet
- `deck-management` — wie Decks gespeichert und abgerufen werden
- `design-systems` — die Datenform von Designsystemen und wie Tokens auf generierte Folien angewendet werden
- `creative-context` — die Wiederverwendungsleiter, das Abrufverfahren und die Library-Einreichung

#### AGENTS.md

`templates/slides/AGENTS.md` ist der kurze Router, den der Agent bei jeder Konversation liest. Er verweist auf die Skills unter `.agents/skills/` und legt die Kernregeln, das Persistenzmodell und den Anwendungsstatus-Vertrag fest. Aktualisieren Sie den jeweiligen Skill, wann immer Sie ein Folienlayout oder eine Designsystem-Quelle hinzufügen oder ändern.
