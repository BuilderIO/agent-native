# Ihre erste Funktion

Diese Seite richtet sich an Entwickler, die die [Chat-Vorlage](/docs/template-chat) erweitern. Sie behandelt die Dateien, die die Startbildschirme rendern, und führt dann durch alles, was der Agent typischerweise berührt, wenn Sie nach einer echten Funktion fragen.

## Erster zu prüfender Code {#first-code}

- `actions/hello.ts` ist das Starterverhalten, das der Agent aufrufen kann.
  Ersetzen Sie es oder fügen Sie Aktionen daneben hinzu.
- `app/components/chat/ChatRouteContent.tsx` rendert die ganzseitige
  Chat-Oberfläche unter `/chat/<threadId>`. Passen Sie hier den Empty State,
  den Composer oder die Nachrichten-Slots an.
- `app/components/home/HomePage.tsx` ist die Seite „Loslegen“, die `/home`
  unter `pnpm dev` zeigt. Produktions-Builds lassen sie weg, und wenn Sie
  `SHOW_HOME_PAGE` in `app/lib/chat-paths.ts` auf `false` setzen, ist sie auch
  in der Entwicklung ausgeschaltet.
- `AGENTS.md` teilt dem integrierten Agenten mit, wie er innerhalb dieser App
  arbeiten soll.

## Erste Änderungen {#first-edits}

Die meisten ersten Funktionen folgen derselben Form: eine Tabelle, ein oder zwei Aktionen, eine Route, ein Nav-Eintrag und eine Aktualisierung von `AGENTS.md`. Fragen Sie den Agenten:

> Füge ein Datenmodell für `notes` hinzu. Eine Notiz hat eine ID, einen Titel, einen Text und einen Besitzer. Rendere eine Notizenseite unter `/notes`, füge Erstellen-/Auflisten-Aktionen hinzu und stelle sicher, dass der Chat weiterhin Notizen erstellen kann.

Chat wird ganz ohne `server/db/schema.ts` ausgeliefert (siehe [Was enthalten ist](/docs/template-chat#what-ships)), daher ist die erste Änderung eine neue Datei, die derselben `table`/`text`/`ownableColumns`-Form folgt, die jede andere Vorlage verwendet:

Der Rest der Funktion ergibt sich von dort aus:

- `actions/create-note.ts` — eine `defineAction` mit einem Zod-Schema (`title`, `body`), geformt wie `actions/hello.ts`.
- `actions/list-notes.ts` — eine schreibgeschützte Aktion (`readOnly: true`, wie `actions/view-screen.ts`), die die neue Tabelle über `accessFilter` abfragt.
- `app/routes/notes.tsx` — eine neue Route; die App verwendet dateisystembasiertes Routing (`flatRoutes()` in `app/routes.ts`), sodass das Hinzufügen der Datei ausreicht, um `/notes` einzubinden.
- Ein Link in `app/components/layout/Sidebar.tsx`, vor `ChatThreadsSection` eingefügt, der auf `/notes` verweist.
- Eine Ergänzung in `AGENTS.md`, die dem Agenten mitteilt, dass es Notizen gibt und welche Aktionen sie verwalten.

Eine neue Aktion ist vom Chat aus aufrufbar, sobald sie existiert — jede `defineAction` ist standardmäßig ein Tool, sofern sie nicht `agentTool: false` setzt. Sie steckt aber nicht unbedingt schon in der allerersten Anfrage des Modells: `server/plugins/agent-chat.ts` setzt `INITIAL_TOOL_NAMES = ["view-screen", "navigate", "hello", "provider-api-request"]`, was nur steuert, welche Tool-Schemas in der ersten Runde gesendet werden. Alles andere, einschließlich eines brandneuen `create-note`, bleibt über `tool-search` erreichbar und wird bei Bedarf nachgeladen — fügen Sie dieser Liste nur dann einen Namen hinzu, wenn Sie ihn von der ersten Nachricht an im Standard-Toolset des Modells haben möchten.

## Verwenden Sie Ihr eigenes Agenten-Backend {#own-agent-backend}

Die Vorlage verwendet standardmäßig die integrierte App-Agent-Schleife. Um ein eigenes Backend anzubinden, tauschen Sie die Chat-Laufzeit hinter dem Agent-Chat-Plugin aus, statt die Oberfläche neu zu schreiben. Die Chat-Route sollte ein schlanker Renderer rund um die gemeinsame Chat-Oberfläche bleiben; die Wahl des Backends gehört in das Server-Plugin bzw. den Laufzeit-Adapter.

Nutzen Sie dies, wenn Ihre Modell-Orchestrierung bereits an anderer Stelle lebt, Sie aber trotzdem eine App mit Authentifizierung, Threads, Aktionen, UI-Status und bereitstellbaren Seiten möchten.
