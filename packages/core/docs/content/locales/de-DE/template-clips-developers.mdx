# Entwicklerhandbuch

Diese Seite richtet sich an alle, die die Clips-Vorlage anpassen oder erweitern: der Schnellstart, jede Aktion, das Datenmodell, die Routenoberfläche und wie Sie sie ergänzen. Was die App tut, erfahren Sie unter [Clips](/docs/template-clips).

## Schnellstart

<Steps>

### Die App erstellen

```bash
npx @agent-native/core@latest create my-clips --standalone --template clips
cd my-clips
pnpm install
```

Dafür müssen zuerst [Node.js](https://nodejs.org) 22.22 oder neuer und [pnpm](https://pnpm.io) installiert sein. Siehe [Erste Schritte](/docs/getting-started), wenn Sie noch keines von beiden installiert haben oder keine LLM-Verbindung (Builder.io, ein Anthropic-/OpenAI-Schlüssel oder lokales Ollama) eingerichtet ist.

### Den Entwicklungsserver starten

```bash
pnpm dev
```

Die App öffnet sich automatisch in Ihrem Browser. Die Aufnahme funktioniert ohne zusätzliche Einrichtung, da der Browser oder die Desktop-App lokal aufzeichnet. Sie stoßen erst auf einen Fehler bei einer Aktion, die Dateispeicher oder KI-Guthaben benötigt, bevor eines der beiden konfiguriert ist.

</Steps>

<Callout tone="info">

Aufnahme, Transkription und KI-Titel/-Zusammenfassungen brauchen konfigurierten Dateispeicher und KI-Guthaben, um durchgängig zu funktionieren. Verbinden Sie Builder.io über **Einstellungen**, um beides auf einmal zu erhalten (der kostenlose Tarif enthält verwaltete KI-Guthaben), oder verbinden Sie S3-kompatiblen Speicher separat und bringen Sie Ihren eigenen Groq-Schlüssel für die Transkription mit. Siehe [Transkription und KI-Metadaten](/docs/template-clips-features#transcription-and-ai-metadata).

</Callout>

## Aktionsinventar

Jeder Vorgang ist eine TypeScript-Datei in `templates/clips/actions/`, automatisch gemountet unter `POST /_agent-native/actions/:name`.

### Bibliothek & Aufnahmen

| Aktion                                                                                    | Was sie tut                                                                         |
| ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `list-recordings`, `search-recordings`                                                    | Bibliothek-, Für-mich-freigegeben-, Papierkorb- und bereichsbezogene Auflistung     |
| `create-recording`, `finalize-recording`                                                  | Zeile erstellen; Upload abschließen                                                 |
| `import-loom-recording`                                                                   | Ein Loom-Video oder eine direkte MP4/WebM-URL importieren                           |
| `update-recording`                                                                        | Titel, Beschreibung, Passwort, Ablauf, Sichtbarkeit                                 |

| `archive-recording`, `trash-recording`, `restore-recording`, `delete-recording-permanent` | Lebenszyklus: ausblenden, weiches Löschen, rückgängig machen oder endgültig löschen |

## Datenmodell

Definiert in `templates/clips/server/db/schema.ts`.

<Callout tone="warning">

Team-, Mitglieds- und Einladungszeilen liegen in den eigenen Framework-Tabellen `organizations`, `org_members` und `org_invitations`, nicht in einer Clips-spezifischen. `organization_settings` ist die eigene Sidecar-Tabelle von Clips: Markenfarbe, Logo und Standardsichtbarkeit, eine Zeile pro Organisation. Ein älteres Paar `workspaces`/`workspace_members` existiert nur noch, damit eine einmalige Startmigration die Framework-Tabellen bei einem bestehenden Deployment nachträglich befüllen kann. Bauen Sie keine neuen Funktionen darauf auf.

</Callout>

## Eine Aktion im Detail

`create-recording-agent-link` zeigt Muster, die sich in jeder Aktion lohnen, die einen gescopten Zugangsnachweis prägt: den tatsächlichen Zustand der Ressource prüfen, bevor irgendetwas herausgegeben wird, das eigentliche Prägen des Tokens an einen gemeinsamen Framework-Helper delegieren, statt eine eigene Lösung zu bauen, und jede URL, die ein Aufrufer braucht, aus genau diesem einen Grant ableiten.

The URL is scoped to that recording and expires after two hours.",\n  schema: z.object({\n    recordingId: z.string().describe("Recording ID"),\n    agentLabel: z\n      .string()\n      .trim()\n      .min(1)\n      .max(60)\n      .optional()\n      .describe(\n        "Name of the agent that will read this link (e.g. \'Fusion\', \'Claude Code\'). Recorded against every read the link produces, so the owner sees a name instead of an unidentified agent.",\n      ),\n    ttlSeconds: z\n      .number()\n      .int()\n      .positive()\n      .max(BUG_REPORT_AGENT_ACCESS_TTL_SECONDS)\n      .optional()\n      .describe(\n        "Optional scoped-link lifetime in seconds, capped at seven days. Defaults to two hours.",\n      ),\n  }),\n  readOnly: true,\n  run: async (args) => {\n    const access = await resolveAccess("recording", args.recordingId);\n    if (!access) {\n      throw new ForbiddenError(`No access to recording ${args.recordingId}`);\n    }\n\n    const recording = access.resource as {\n      id: string;\n      archivedAt?: string | null;\n      trashedAt?: string | null;\n    };\n    if (recording.archivedAt || recording.trashedAt) {\n      throw new ForbiddenError(\n        `Recording ${args.recordingId} is not shareable`,\n      );\n    }\n\n    const grant = createScopedAgentAccessGrant({\n      resourceKind: CLIP_AGENT_ACCESS_TOKEN_PREFIX,\n      resourceId: recording.id,\n      viewerEmail: getRequestUserEmail() || undefined,\n      agentLabel: args.agentLabel,\n      ttlSeconds: args.ttlSeconds ?? CLIPS_AGENT_ACCESS_TTL_SECONDS,\n    });\n    const origin = appOrigin();\n    const basePath = getServerAppBasePath();\n    const pageUrl = buildAgentAccessUrl({\n      path: `/share/${encodeURIComponent(recording.id)}`,\n      origin,\n      basePath,\n      token: grant.token,\n    });\n    const api = buildAgentApiUrls(recording.id, {\n      origin,\n      basePath,\n      token: grant.token,\n    });\n\n    return {\n      recordingId: recording.id,\n      url: pageUrl,\n      contextUrl: api.contextUrl,\n      expiresAt: grant.expiresAt,\n      ttlSeconds: grant.ttlSeconds,\n    };\n  },\n});\n'

## Anpassen

Jeder Teil der App ist bearbeitbarer Quellcode. Fangen Sie hier an:

- `templates/clips/actions/` — fügen Sie eine neue Datei mit `defineAction` hinzu, um sowohl dem Agenten als auch dem Frontend eine neue Fähigkeit verfügbar zu machen.
- `templates/clips/app/routes/` — die Oberfläche, oben aufgelistet.
- `templates/clips/server/db/schema.ts` — fügen Sie Spalten oder Tabellen mit Drizzle hinzu. Halten Sie das Schema PostgreSQL-kompatibel, damit die Vorlage sowohl mit lokalem PGlite als auch mit gehostetem Postgres läuft.
- `templates/clips/server/lib/` — Anbieter-Integrationen: `google-calendar-client.ts`, `s3-upload-provider.ts`, `slack-oauth.ts`, `video-remux.ts`, `video-filmstrip-sprite.ts`.
- `templates/clips/AGENTS.md` — Agentenanweisungen. Aktualisieren Sie diese, wenn Sie dem Agenten neue Fähigkeiten oder Konventionen beibringen.
- `templates/clips/.agents/skills/` — detaillierte Muster, denen der Agent folgt. Relevante Skills: `recording`, `ai-video-tools`, `video-editing`, `video-sharing`, `screen-memory`.
- `templates/clips/shared/api.ts` — die gemeinsamen TypeScript-Typen, die sowohl vom Server als auch vom Client verwendet werden.
- `templates/clips/desktop/` und `templates/clips/chrome-extension/` — separate Pakete für die nativen Aufnahmeoberflächen, jeweils mit eigener `package.json` und eigenem Build.

Wenn Sie eine Funktion hinzufügen, denken Sie daran, alle vier Bereiche zu aktualisieren: Oberfläche, Aktion, Skill- oder AGENTS.md-Eintrag, und jeden Anwendungsstatus, den der Agent sehen muss. Das hält den Agenten und die Oberfläche in Parität.
