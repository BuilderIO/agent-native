# Public Agent Web

Das öffentliche Agenten-Web erleichtert Agenten das Crawlen, Lesen, Zitieren und Anrufen öffentlicher Agent-Native-Routen. Das Ziel besteht nicht darin, jeden App-Endpunkt öffentlich zu machen. Ziel ist es, eine saubere öffentliche Oberfläche für bereits öffentliche Seiten zu veröffentlichen und gleichzeitig den Zugriff auf private Daten und Tools einer expliziten Kontrolle zu unterziehen.

Die Dokumentationsseite ist die Referenzimplementierung. Heute wird Folgendes ausgeliefert:

- `/robots.txt` mit einer Crawler-Richtlinie, die den Abruf erlaubt, aber das Training standardmäßig nicht zulässt.
- `/sitemap.xml` als Sitemap-Index, der auf eine `/sitemap-<locale>.xml` pro Sprache verweist, mit absolut kanonischen URLs und `lastmod`, wenn die Quelldatei es verfügbar macht.
- `/llms.txt` und `/llms-full.txt` für agentenfreundliche Inhaltserkennung.
- Markdown spiegelt wie `/docs/getting-started.md` wider.
- `Accept: text/markdown`-Antworten für öffentliche Dokumentseiten nach einem Produktions-Build.
- JSON-LD für Basisorganisation, Website und Seitenmetadaten.
- Ein Audit CLI (`npx @agent-native/core@latest audit-agent-web`), das alle oben genannten Punkte überprüft.

Das Veröffentlichen dieser Dateien macht nie eine Aktion verfügbar. Eine Aktion erreicht externe Agenten nur über ihr eigenes `publicAgent`-Opt-in; siehe [Für öffentliche Agenten freigeben](/docs/actions-access-control#public-agent).

## Konfiguration {#config}

`createAgentWebVitePlugin` aus `@agent-native/core/vite` schreibt diese Dateien während eines Produktions-Builds. Fügen Sie es mit den Seiten, die Agenten lesen sollen, zu Ihrer Vite-Konfiguration hinzu:

```ts
// vite.config.ts
import { createAgentWebVitePlugin } from "@agent-native/core/vite";

export default defineConfig({
  plugins: [
    // ...your existing plugins
    createAgentWebVitePlugin({
      siteName: "My Agent-Native App",
      siteUrl: "https://example.com",
      pages: [
        {
          path: "/pricing",
          title: "Pricing",
          description: "Plans and limits.",
          markdown: "Plans and limits.\n",
        },
      ],
      agentWeb: { crawlerPolicy: "discoverable-no-training" },
    }),
  ],
});
```

Das Plugin veröffentlicht die Seiten, die Sie auflisten, und sonst nichts. Es liest weder Ihre Routenzugriffseinstellungen noch `agentWeb` aus `package.json`, solange Sie es nicht übergeben. Um die Einstellungen in `package.json` unter `agent-native.workspaceApp.agentWeb` zu behalten, übergeben Sie `agentWeb: agentWebConfigFromPackageJson(pkg)`, importiert aus `@agent-native/core/agent-web`.

| Option          | Standard                        | Wirkung                                                                                                                                                  |
| --------------- | ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `discoverable`  | An, wenn `pages` nicht leer ist | `false` schreibt keine Dateien.                                                                                                                          |
| `llmsTxt`       | `true`                          | Schreibt `/llms.txt` und `/llms-full.txt`.                                                                                                               |
| `markdownTwins` | `true`                          | Schreibt eine `.md`-Kopie jeder Seite, die `markdown` hat.                                                                                               |
| `crawlerPolicy` | `"discoverable-no-training"`    | Legt die Regeln in `robots.txt` fest: `"discoverable-no-training"`, `"allow-all"` oder `"disallow-all"`.                                                 |
| `crawlers`      | Keiner                          | Überschreibt eine Crawler-Kategorie: `training`, `search`, `userTriggered`, `codingAgents` oder `autonomousAgents`, jeweils `"allow"` oder `"disallow"`. |

Die Standard-Crawler-Richtlinie ist „erkennbar, nicht trainierbar“: Suche, vom Benutzer ausgelöster Abruf, Codierungsagenten und autonome Browsing-Agenten sind zulässig; Trainings-Crawler sind nicht zulässig.

`jsonLd`, `publicAgentCard` und `publicMcp` werden akzeptiert, aber noch von nichts gelesen. Für JSON-LD rendern Sie `buildBaseJsonLd` und `buildPageJsonLd` aus `@agent-native/core/agent-web` selbst in Ihre Seiten.

## Quelle der Wahrheit weiterleiten {#route-source}

Die Seitenliste ist die Quelle der Wahrheit: Agenten erhalten die Seiten, die Sie übergeben, und nur diese. Stellen Sie sie aus Seiten zusammen, die bereits öffentlich sind:

- In einer öffentlichen App jede Route außer `protectedPaths`.
- In einer internen App nur `publicPaths`.
- Öffentliche Freigabe- und Formularseiten, die Agenten lesen können sollen.
- Niemals übermittelte private Daten, authentifizierte Dashboards oder Benutzer- bzw. Organisationsstatus, auch wenn eine Seite in der Nähe öffentlich ist.

Um von Ihren Zugriffseinstellungen auszugehen, nimmt `deriveAgentWebPublicRoutes` aus `@agent-native/core/agent-web` `audience`, `publicPaths`, `protectedPaths` und `routes` Ihrer App entgegen und gibt die Routen zurück, die diese Einstellungen öffentlich machen. Jede Seite braucht trotzdem ihren eigenen Titel und ihr eigenes Markdown.

Dadurch bleiben gemischte Apps natürlich. Eine Formular-App kann eine öffentliche Formularseite verfügbar machen und Übermittlungen privat halten. Eine Content-App kann veröffentlichte Beiträge offenlegen und den Herausgeber privat halten. Eine Dokumentenseite kann alles außer Verwaltungstools offenlegen.

## Öffentliche Seiten sind keine öffentlichen Tools {#public-tools}

Der Zugriff auf öffentliche Seiten und der Zugriff auf öffentliche Tools sind getrennt. Eine öffentliche Route bedeutet nur, dass Agenten diese Route als HTML, Markdown, Sitemap-Einträge, LMS-Einträge und strukturierte Daten lesen können.

<Callout id="doc-block-s50w8y" tone="warning">

**Eine öffentliche Seite ist kein öffentliches Tool.** Eine Route crawlbar zu machen, macht nie eine Aktion verfügbar. Für den Tool-Zugriff ist ein ausdrückliches `publicAgent.expose`-Opt-in an der Aktion nötig.

</Callout>

## Dateien zur Erstellungszeit {#build-time}

Framework-Dienstprogramme in `@agent-native/core/agent-web` generieren die gemeinsamen Dateien aus einer Seitenliste:

```ts
import {
  buildAgentWebStaticFiles,
  normalizeAgentWebConfig,
} from "@agent-native/core/agent-web";

const config = normalizeAgentWebConfig(
  { crawlerPolicy: "discoverable-no-training" },
  { hasPublicRoutes: true },
);

const files = buildAgentWebStaticFiles({
  siteName: "My Agent-Native App",
  siteUrl: "https://example.com",
  description: "Public docs for my app.",
  config,
  pages: [
    {
      path: "/docs",
      title: "Docs",
      description: "Start here.",
      markdown: "# Dokumente\n\nStart hier.\n",
      markdownPath: "/docs/getting-started.md",
      lastmod: new Date(),
    },
  ],
});
```

`createAgentWebVitePlugin` ruft `buildAgentWebStaticFiles` für Sie auf und schreibt die Dateien in diejenigen der Ordner `public`, `dist`, `dist/client`, `dist/server/public` und `build/client`, die existieren. Mit einem anderen Build-Tool rufen Sie die Dienstprogramme direkt auf.

Keines von beiden beantwortet `Accept: text/markdown` unter der eigenen URL einer Seite: Die Markdown-Kopie liegt nur unter ihrer `.md`-URL. Um diesen Header zu beantworten, fügen Sie eine Server-Route hinzu, die das Markdown der Seite mit den Headern aus `buildMarkdownResponseHeaders` zurückgibt, wie es die Dokumentationsseite tut. Ohne diese Route schlägt die Prüfung `Accept: text/markdown` im Audit unten fehl.

Übergeben Sie `sitemapGroup` an `buildAgentWebStaticFiles` oder `createAgentWebVitePlugin`, um eine große Sitemap aufzuteilen. Die Option ordnet jede Seite einem Gruppenschlüssel zu, etwa ihrer Sprache, und `sitemap.xml` wird zu einem Sitemap-Index mit einer `sitemap-<group>.xml` pro Gruppe.

## Eine Website prüfen {#audit}

Verwenden Sie die CLI-Prüfung für einen bereitgestellten Standort oder einen lokalen Produktionsserver:

```bash
npx @agent-native/core@latest audit-agent-web --url https://www.agent-native.com
```

Die Prüfung prüft auf:

- SSR-sichtbares HTML.
- Kanonische URLs.
- JSON-LD.
- `robots.txt`-Richtlinie und absolute Sitemap URL.
- Absolute Sitemap-Einträge.
- `/llms.txt` und `/llms-full.txt`.
- Markdown Spiegel.
- `Accept: text/markdown`.
- Keine versehentlichen 401/403-Blockierungen für allgemeine Agentenabruf-Benutzeragenten.

Die Prüfung endet mit einem Wert ungleich Null, wenn eine erforderliche öffentliche Oberfläche fehlt.
