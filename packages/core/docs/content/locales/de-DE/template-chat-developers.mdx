# Entwicklerhandbuch

Diese Seite richtet sich an Entwickler, die die Chat-Vorlage ausführen oder erweitern. Sie behandelt den Schnellstart, jede integrierte Aktion, das Datenmodell, eine Aktion im Detail, die Routen und wie Sie Ihre erste Funktion hinzufügen. Was die App tut, erfahren Sie unter [Chat](/docs/template-chat).

## Schnellstart {#quick-start}

Dies führt Sie durch das Ausführen von Chat, von nichts Installiertem bis zu einer Live-Konversation mit dem Agenten. Die Befehle sind identisch, egal ob Sie im Terminal auf macOS oder in PowerShell/Command Prompt auf Windows arbeiten, es handelt sich um reines Node.js-Tooling.

<Steps>

### Die App erstellen

```bash
npx --yes @agent-native/core@latest create my-chat-app --standalone --template chat
cd my-chat-app
corepack enable
pnpm install
```

Dafür benötigen Sie [Node.js](https://nodejs.org) 22.22 oder neuer. Wenn `pnpm` nicht in Ihrem `PATH` liegt, führen Sie `corepack enable` in der generierten App aus. Wenn Sie Node.js noch nicht installiert haben, lesen Sie [Erste Schritte](/docs/getting-started).

### Den Entwicklungsserver starten

```bash
pnpm dev
```

Die App öffnet sich unter der lokalen URL, die `pnpm dev` ausgibt. Wenn sie sich nicht automatisch öffnet, rufen Sie diese URL in Ihrem Browser auf. Der Port kann abweichen, wenn 8080 bereits belegt ist.

### Anmelden und ein LLM verbinden

Wählen Sie auf dem Willkommensbildschirm **Als lokaler Entwickler fortfahren**. Für die lokale Entwicklung sind weder E-Mail noch Passwort nötig. Verbinden Sie dann ein LLM: Wählen Sie **Builder.io verwenden** für kostenlose Credits oder **Eigene Schlüssel hinzufügen**, um einen eigenen Schlüssel eines Modellanbieters zu verwenden. Chat wird ohne Domänendaten zum Befüllen ausgeliefert. Sobald ein LLM verbunden ist, müssen Sie also nichts weiter einrichten, bevor Sie chatten können.

</Steps>

Chat ist für eine Browseroberfläche gebaut. Wenn Sie einen Agenten ganz ohne Bildschirm möchten, für geplante Jobs, Warteschlangen, CLI-Schleifen oder Workflows mit externen Agenten, erstellen Sie das Gerüst stattdessen mit `--headless`:

```bash
npx --yes @agent-native/core@latest create my-agent --headless
```

Die Kernidee bleibt dieselbe. Aktionen sind die gemeinsame Oberfläche für Chat, UI, HTTP, MCP, A2A und CLI. Diesen Weg behandelt [Automatisierungsorientierte Apps](/docs/pure-agent-apps) ausführlich.

## Aktionsinventar {#actions}

Jede Operation ist eine TypeScript-Datei in `actions/`, die automatisch unter `POST /_agent-native/actions/:name` eingebunden wird, sofern die Aktion nicht `http: false` setzt.

| Aktion                 | Was sie tut                                                                                         |
| ---------------------- | --------------------------------------------------------------------------------------------------- |
| `hello`                | Beispielaktion. Gibt eine Begrüßung zurück. Ersetzen Sie sie oder fügen Sie Aktionen daneben hinzu. |
| `view-screen`          | Standard-Kontextaktion. Liest die aktuelle Ansicht für den Agenten zurück.                          |
| `navigate`             | Standard-Navigationsaktion. Bewegt die UI zu einer Route.                                           |
| `provider-api-request` | Ruft die Slack Web API über einen verbundenen Slack-Arbeitsbereich auf.                             |

### Die Chat-Laufzeit {#chat-runtime}

In `server/plugins/agent-chat.ts` wird die Chat-Laufzeit konfiguriert. Sie erledigt vier Dinge:

- Sie registriert jede Aktion in `actions/` als aufrufbares Werkzeug, mit
  `loadActionsFromStaticRegistry`.
- Sie löst die aktuelle Organisation für die Zugriffsbegrenzung auf, mit `resolveOrgId`.
- Sie legt den System-Prompt fest.
- Sie deklariert, welche Werkzeuge das Modell im ersten Zug sieht, mit
  `initialToolNames`.

### Wie Aktionen zu Werkzeugen werden {#actions-as-tools}

Jede `defineAction` ist standardmäßig ein Werkzeug. Setzen Sie `agentTool: false`, damit eine Aktion für Ihre Bildschirme verfügbar bleibt, aber vor dem Agenten verborgen ist.

### Was das Modell zuerst sieht {#initial-tools}

`INITIAL_TOOL_NAMES` listet `view-screen`, `navigate`, `hello` und `provider-api-request` auf. Das sind die einzigen Werkzeuge, die im ersten Zug gesendet werden. Alles andere, auch eine Aktion, die Sie hinzufügen, bleibt über `tool-search` erreichbar und wird bei Bedarf geladen.

Fügen Sie dieser Liste nur dann einen Namen hinzu, wenn die Aktion ab der ersten Nachricht im Standard-Werkzeugsatz des Modells sein soll.

## Datenmodell {#data-model}

Chat definiert keine eigenen Tabellen. Es gibt keine `server/db/schema.ts`, bis Sie eine hinzufügen. Die App läuft auf den Kerntabellen des Frameworks für Chat-Threads und Nachrichten, Anwendungsstatus, Einstellungen, Sitzungen, Ressourcen und Laufverlauf. Diese gehören dem Framework, bearbeiten Sie sie also nicht. Das Verbindungsmodell und wo neue Daten abgelegt werden sollten, erfahren Sie unter [Datenbank](/docs/server-database).

`useDbSync()` ist bereits in die App-Shell eingebunden. Wenn der Agent oder jemand anderes in SQL schreibt, erhält der Client die Änderung über SSE oder den 2-Sekunden-Polling-Fallback und invalidiert die passenden React-Query-Caches. Die vollständige Hook-API finden Sie unter [`useDbSync`](/docs/client-data#usedbsync).

Ihre erste Tabelle ist eine neue Datei. Siehe [Ihre erste Funktion hinzufügen](#first-feature).

## Authentifizierung {#auth}

Die Authentifizierung läuft über Better Auth: Login, Registrierung, Sitzungen und Organisationen, konfiguriert in `server/plugins/auth.ts` über `createAuthPlugin`. Derselbe Ablauf läuft lokal und in Produktion, nur dass die Entwicklung die E-Mail-Verifizierung überspringt, damit Sie sich sofort registrieren und mit dem Bauen beginnen können. `createAuthPlugin` nimmt auch den Marketingtext der Login-Seite (App-Name, Slogan und Funktionsstichpunkte) als einfache Konfiguration in derselben Datei entgegen. Das vollständige Authentifizierungsmodell (Sitzungen, Organisationen, geschützte Routen) finden Sie unter [Authentifizierung](/docs/authentication).

**Datenbank** (`/database`) ist dieselbe `DbAdminPage`, die jede Vorlage erhält. Sie ist ein direkter Tabellenbrowser und -editor über die SQL-Datenbank der App. Das dahinterliegende Verbindungsmodell finden Sie unter [Datenbank](/docs/server-database).

**Beobachtbarkeit** (`/observability`) ist dasselbe konfigurationsfreie `ObservabilityDashboard`, das jede Vorlage erhält. Es zeigt Traces, Kosten, Evals und Feedback für jeden Agentenlauf, berechnet aus Daten, die bereits in Ihrer eigenen Datenbank liegen. Siehe [Agent-Observability](/docs/observability).

**Erweiterungen** sind isolierte Alpine.js-Mini-Apps. Chat bindet die Routen ein, die sie anzeigen und ausführen (`/extensions/:id`), und leitet `/extensions` auf die Seite Erweiterungen in den Einstellungen weiter. Der Agent kann sie erst erstellen, wenn Sie `frameworkTools.extensions` in `server/plugins/agent-chat.ts` aktivieren, was Chat ausgeschaltet lässt. Was sie können und was nicht, erfahren Sie unter [Erweiterungen](/docs/extensions).

## Anpassen {#customizing}

Jeder Teil der App ist bearbeitbarer Quellcode. Beginnen Sie hier:

- `actions/`: Fügen Sie eine neue Datei mit `defineAction` hinzu, um eine neue Aktion sowohl dem Agenten als auch dem Frontend zur Verfügung zu stellen.
- `app/routes/`: die Oberfläche. Fügen Sie eine Routendatei hinzu, um eine Seite einzubinden.
- `server/db/schema.ts`: Fügen Sie mit Drizzle eigene Tabellen hinzu, sobald Ihnen die Kerntabellen nicht mehr genügen. Halten Sie den Code PostgreSQL-spezifisch, damit lokales PGlite und gehostetes Postgres dieselbe Semantik verwenden.
- `AGENTS.md`: Agentenanweisungen. Aktualisieren Sie dies, wenn Sie dem Agenten neue Aktionen oder Konventionen beibringen.
- `.agents/skills/`: detaillierte Muster, denen der Agent folgt.

Wenn Sie eine Funktion hinzufügen, denken Sie daran, alle vier Bereiche zu aktualisieren: UI, Aktion, Skill- oder `AGENTS.md`-Eintrag und jeden Anwendungsstatus, den der Agent sehen muss. Das ist es, was den Agenten und die Oberfläche in Einklang hält.

### Ein eigenes Agent-Backend verwenden {#own-agent-backend}

Die Vorlage verwendet standardmäßig die integrierte App-Agent-Schleife. Um ein eigenes Backend anzubinden, tauschen Sie die Chat-Laufzeit hinter dem Agent-Chat-Plugin aus, statt die UI neu zu schreiben. Die Chat-Route sollte ein schlanker Renderer um die gemeinsame Chatoberfläche bleiben, und die Wahl des Backends gehört in das Server-Plugin und den Laufzeitadapter.

Nutzen Sie dies, wenn Ihre Modellorchestrierung bereits anderswo liegt, Sie aber trotzdem eine App mit Authentifizierung, Threads, Aktionen, UI-Status und bereitstellbaren Seiten möchten. Die Laufzeitoptionen finden Sie unter [Native Chat-UI](/docs/native-chat-ui#byo-agent-runtimes).

## Ihre erste Funktion hinzufügen {#first-feature}

Die meisten ersten Funktionen folgen derselben Form: eine Tabelle, eine oder zwei Aktionen, eine Seite, ein Navigationseintrag und eine Aktualisierung von `AGENTS.md`. Dieser Abschnitt baut eine Notizfunktion in vier Teilen auf, mit dem vollständigen Code für jede Datei. Sie können den Agenten auch bitten, alles zu erledigen:

> Add a data model for `notes`. A note has an id, title, body, and owner. Render a notes page at `/notes`, add create/list actions, and keep chat able to create notes.

### 1. Die Datenschicht hinzufügen

Chat wird ohne Ordner `server/db` ausgeliefert, daher sind alle drei Dateien hier neu.

Das Schema definiert die Tabellen. `ownableColumns()` fügt die Spalten für Eigentümer, Organisation und Sichtbarkeit hinzu, und `createSharesTable()` fügt eine passende Tabelle für die Freigabe hinzu.

```ts filename="server/db/schema.ts"
import { sql } from "drizzle-orm";
import { pgTable, text } from "drizzle-orm/pg-core";
import {
  createSharesTable,
  ownableColumns,
} from "@agent-native/core/db/schema";

export const notes = pgTable("notes", {
  id: text("id").primaryKey(),
  title: text("title").notNull(),
  body: text("body").notNull(),
  createdAt: text("created_at")
    .notNull()
    .default(sql`now()`),
  ...ownableColumns(),
});

export const noteShares = createSharesTable("note_shares");
```

Der Datenbank-Client stellt Ihren Aktionen `getDb()` bereit und registriert Notizen im Freigabesystem.

```ts filename="server/db/index.ts"
import { createGetDb } from "@agent-native/core/db";
import { registerShareableResource } from "@agent-native/core/sharing";

import * as schema from "./schema.js";

export const getDb = createGetDb(schema);
export { schema };

registerShareableResource({
  type: "note",
  resourceTable: schema.notes,
  sharesTable: schema.noteShares,
  displayName: "Note",
  titleColumn: "title",
  getResourcePath: (note) => `/notes/${note.id}`,
  getDb,
});
```

Die Migration erstellt die Tabellen beim Start der App. Fügen Sie für spätere Änderungen neue Einträge hinzu und bearbeiten Sie niemals einen, der bereits gelaufen ist.

### 2. Die Aktionen hinzufügen

Jede Aktion ist eine Datei in `actions/`, und der Dateiname wird zum Werkzeugnamen. Der Agent und Ihre Seite rufen dieselben zwei Aktionen auf.

`create-note` hält den angemeldeten Nutzer als Eigentümer fest. Die Notiz ist für die Organisation sichtbar, wenn eine aktiv ist, andernfalls nur für ihren Ersteller.

```ts filename="actions/create-note.ts"
import { defineAction, fail } from "@agent-native/core/action";
import { z } from "zod";

import { getDb, schema } from "../server/db/index.js";

export default defineAction({
  description:
    "Create a note with a title and body. It is visible to the organization when one is active, otherwise only to its creator.",
  schema: z.object({
    title: z.string().min(1).describe("Short title for the note"),
    body: z.string().describe("Full text of the note"),
  }),
  run: async (args, ctx) => {
    const ownerEmail =
      ctx?.userEmail ?? fail("Sign in to create notes.", { statusCode: 401 });
    const orgId = ctx?.orgId ?? null;
    const note = {
      id: crypto.randomUUID(),
      title: args.title,
      body: args.body,
      ownerEmail,
      orgId,
      visibility: orgId ? ("org" as const) : ("private" as const),
    };
    await getDb().insert(schema.notes).values(note);
    return { id: note.id, title: note.title };
  },
});
```

`list-notes` ist schreibgeschützt, und `accessFilter` beschränkt die Ergebnisse auf Notizen, die der aktuelle Nutzer sehen darf.

```ts filename="actions/list-notes.ts"
import { defineAction } from "@agent-native/core/action";
import { accessFilter } from "@agent-native/core/sharing";
import { desc } from "drizzle-orm";
import { z } from "zod";

import { getDb, schema } from "../server/db/index.js";

export default defineAction({
  description: "List the notes the current user can see, newest first.",
  schema: z.object({}),
  http: { method: "GET" },
  readOnly: true,
  run: async () => {
    const { notes, noteShares } = schema;
    const rows = await getDb()
      .select({
        id: notes.id,
        title: notes.title,
        body: notes.body,
        createdAt: notes.createdAt,
      })
      .from(notes)
      .where(accessFilter(notes, noteShares))
      .orderBy(desc(notes.createdAt))
      .limit(200);
    return { notes: rows };
  },
});
```

Eine neue Aktion ist für den Chat aufrufbar, sobald sie existiert. Siehe [Was das Modell zuerst sieht](#initial-tools), wenn Sie sie im Standard-Werkzeugsatz des Modells haben möchten.

### 3. Die Seite und den Seitenleisten-Link hinzufügen

Die App verwendet dateisystembasiertes Routing, sodass das Hinzufügen dieser Datei `/notes` einbindet. Die Seite ruft mit `useActionQuery()` und `useActionMutation()` dieselben Aktionen auf wie der Agent, und eine erfolgreiche Mutation aktualisiert die Liste von selbst.

```tsx filename="app/routes/notes.tsx"
import {
  useActionMutation,
  useActionQuery,
} from "@agent-native/core/client/hooks";
import { useSetPageTitle } from "@agent-native/toolkit/app-shell";
import { useState, type FormEvent } from "react";
import { toast } from "sonner";

import { Button } from "@/components/ui/button";
import { Input } from "@/components/ui/input";
import { Skeleton } from "@/components/ui/skeleton";
import { APP_TITLE } from "@/lib/app-config";

export function meta() {
  return [{ title: `Notes - ${APP_TITLE}` }];
}

export default function NotesRoute() {
  useSetPageTitle("Notes");
  const { data, isLoading } = useActionQuery("list-notes");
  const createNote = useActionMutation("create-note", {
    onError: (error) => toast.error(error.message),
  });
  const [title, setTitle] = useState("");
  const [body, setBody] = useState("");

  function handleSubmit(event: FormEvent) {
    event.preventDefault();
    createNote.mutate(
      { title, body },
      {
        onSuccess: () => {
          setTitle("");
          setBody("");
        },
      },
    );
  }

  return (
    <div className="mx-auto flex h-full max-w-2xl flex-col gap-6 overflow-auto p-6">
      <form onSubmit={handleSubmit} className="flex flex-col gap-2">
        <Input
          value={title}
          onChange={(event) => setTitle(event.target.value)}
          placeholder="Title"
          required
        />
        <Input
          value={body}
          onChange={(event) => setBody(event.target.value)}
          placeholder="Write a note"
        />
        <Button type="submit" disabled={createNote.isPending}>
          Add note
        </Button>
      </form>
      <ul className="flex flex-col gap-2">
        {isLoading && (
          <>
            <Skeleton className="h-16 w-full" />
            <Skeleton className="h-16 w-full" />
          </>
        )}
        {data?.notes.map((note) => (
          <li key={note.id} className="rounded-lg border p-3">
            <p className="font-medium">{note.title}</p>
            <p className="text-sm text-muted-foreground">{note.body}</p>
          </li>
        ))}
      </ul>
    </div>
  );
}
```

```tsx filename="app/components/layout/Sidebar.tsx"
          : "h-10 w-full gap-3 rounded-lg px-3 text-sm font-medium",
      )}
    >
      <IconNotes className="size-4 shrink-0" strokeWidth={1.8} />
      <span className={collapsed ? "sr-only" : "truncate"}>Notes</span>
    </Link>
  );

  if (collapsed) {
    return (
      <Tooltip>
        <TooltipTrigger asChild>{link}</TooltipTrigger>
        <TooltipContent side="right">Notes</TooltipContent>
      </Tooltip>
    );
  }

  return <div className="px-2">{link}</div>;
}
```

Rendern Sie sie dann im `<nav>` der Seitenleiste, vor der Thread-Liste:

```diff filename="app/components/layout/Sidebar.tsx"
 <HomeNavLink collapsed={collapsed} />
+<NotesNavLink collapsed={collapsed} />
 <ChatThreadsSection collapsed={collapsed} />
```

Die eigenen Beschriftungen von Chat stammen aus Übersetzungsdateien, daher ist das Literal „Notes“ eine Abkürzung. Wenn Ihre App lokalisiert ist, fügen Sie Schlüssel zu `app/i18n/en-US.ts` hinzu und lesen Sie sie stattdessen mit `useT()`. Siehe [Internationalisierung](/docs/internationalization).

### 4. Dem Agenten davon erzählen

Hängen Sie einen kurzen Abschnitt an `AGENTS.md` an, damit der Agent weiß, dass es Notizen gibt und welche Aktionen sie verwalten. Halten Sie ihn kurz, denn der Laufzeit-Prompt schneidet die Datei bei 6.000 Zeichen ab.

```md filename="AGENTS.md"
## Notes

Notes live at `/notes`. Each note has a title and a body. A note is visible to
the organization when one is active and private to its creator otherwise.

| Action        | Purpose                             |
| ------------- | ----------------------------------- |
| `list-notes`  | List the notes the user can see     |
| `create-note` | Create a note with a title and body |
```

Starten Sie `pnpm dev` neu, damit die neuen Aktionen und die Migration geladen werden. Fügen Sie dann auf der Seite **Notes** eine Notiz hinzu und bitten Sie einen Chat: „Create a note called Groceries with milk and eggs“. Beide Notizen stehen in der Liste.
