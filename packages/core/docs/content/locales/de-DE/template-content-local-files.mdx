# Content: Lokale Ordnerquellen

Content verwendet nur noch ein Datenmodell: Jede Seite liegt in SQL, gehört zu
einem **Bereich** und ist Mitglied der Systemdatenbank **Files** dieses Bereichs.
Ein lokaler Markdown- oder MDX-Ordner ist eine mit Files verbundene Quelle –
neben Zusammenarbeit, Freigabe, Kommentaren, Verlauf, Suche,
Datenbankeigenschaften und derselben Aktionsoberfläche, die jede andere Seite
nutzt.

Jeder Benutzer erhält einen persönlichen Bereich, jede zugängliche Organisation
einen Organisationsbereich. Der persönliche **Workspaces**-Katalog bestimmt,
welche Bereiche erscheinen. Files ist eine normale Content-Datenbank; ihre
Eigenschaften, Filter, Sortierungen, Gruppen und gespeicherten Ansichten können
auch die Seitenleiste darstellen.

## Ordner verbinden

<Steps>

### Bildschirm für lokale Ordner öffnen

Wählen Sie einen Ordner über die File System Access API des Browsers oder
Agent-Native Desktop. Content speichert in SQL nur eine undurchsichtige
Verbindungs-ID, relative Pfade, Hashes und Quellmetadaten. Der absolute Pfad,
das Browser-Handle oder Dateiinhalte werden dort nie gespeichert.

### Auswählen, wo der Ordner angehängt wird

Hängen Sie ihn an die Files-Datenbank eines vorhandenen persönlichen oder
Organisationsbereichs an, oder erstellen Sie einen privaten ordnergestützten
Bereich mit eigener Files-Datenbank.

### Eine Wahrheitsrichtlinie wählen

| Richtlinie               | Verhalten                                                          |
| ------------------------ | ------------------------------------------------------------------ |
| `database_primary`       | Content ist maßgeblich; Änderungen im Ordner werden vor der Übernahme geprüft |
| `source_primary`         | Der Ordner ist maßgeblich, wenn keine gleichzeitige Content-Änderung vorliegt |
| `reviewed_bidirectional` | Änderungen in beide Richtungen erfordern bei Konflikten eine Prüfung |

</Steps>

Die Synchronisierung materialisiert Dateien als normale SQL-Seiten.
Gleichzeitige Änderungen werden zur Prüfung erfasst, statt eine Seite zu
überschreiben. Beim Trennen bleiben Seiten und Dateien erhalten.

## Aus einem Repository starten

```bash
npx @agent-native/core@latest content .
```

Der Befehl startet die normale datenbankgestützte Content-App, registriert den
Ordner als lokale Ordnerquelle und öffnet den Verbindungsbildschirm.

## Konfiguration

```json
{
  "version": 1,
  "apps": {
    "content": {
      "roots": [
        {
          "name": "Docs",
          "path": "docs",
          "kind": "docs",
          "extensions": [".md", ".mdx"],
          "source": {
            "type": "local-folder",
            "connectionId": "local-folder:<opaque-id>",
            "truthPolicy": "source_primary"
          }
        }
      ],
      "components": "components",
      "extensions": "extensions"
    }
  }
}
```

Frontmatter-IDs bewahren die Seitenidentität bei Umbenennungen und
Verschiebungen. Lokale Komponenten und Erweiterungen verwenden weiter die
vertrauenswürdige lokale Bridge.

## Migration aus dem Local File Mode

<Callout tone="info">

Überspringen Sie diesen Abschnitt, wenn Sie einen lokalen Ordner zum ersten Mal
einrichten. Er gilt nur für ein Manifest, das älter ist als das aktuelle
Quellenmodell.

</Callout>

Ein älteres Manifest kann `mode: "local-files"` enthalten, und ein älterer
Start-Workflow kann `AGENT_NATIVE_MODE=local-files` setzen. Entfernen Sie
beides. Behalten Sie die konfigurierten Roots bei, ergänzen Sie `source.type`,
`source.connectionId` und `source.truthPolicy`, und starten Sie dann mit
`agent-native content <file-or-folder>`.

Prüfen Sie nach der ersten Verbindung und Synchronisierung, dass:

- Der Ordner als Quelle auf der vorgesehenen Files-Datenbank erscheint.
- Jede importierte Seite zum vorgesehenen Bereich gehört.
- Benutzerdefinierte Eigenschaften und gespeicherte Seitenleisten-Ansichten normal funktionieren.
- Gleichzeitige Änderungen als prüfbare Änderungssätze erscheinen.
- Das Trennen sowohl die Datenbankseiten als auch die Dateien auf der Festplatte erhält.
