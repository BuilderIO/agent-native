# Entwicklerhandbuch

Diese Seite richtet sich an alle, die die Kalender-Vorlage anpassen oder erweitern: der Schnellstart, jede Aktion, das Datenmodell, die Routenoberfläche und wie Sie sie erweitern. Was die App tut, erfahren Sie unter [Kalender](/docs/template-calendar).

## Schnellstart

Dies führt Sie durch das Ausführen von Kalender, von nichts Installiertem bis zu einem verbundenen Google Calendar. Die Befehle sind identisch, egal ob Sie im Terminal auf macOS oder in PowerShell/Command Prompt auf Windows arbeiten, es handelt sich um reines Node.js-Tooling.

<Steps>

### Die App erstellen

```bash
npx @agent-native/core@latest create my-calendar --standalone --template calendar
cd my-calendar
pnpm install
```

Dafür benötigen Sie zunächst [Node.js](https://nodejs.org) 22 oder neuer und [pnpm](https://pnpm.io). Wenn Sie noch keines von beiden installiert haben oder keine LLM-Verbindung (Builder.io, ein Anthropic/OpenAI-Schlüssel oder lokales Ollama) eingerichtet haben, lesen Sie [Erste Schritte](/docs/getting-started).

### Den Entwicklungsserver starten

```bash
pnpm dev
```

Die App öffnet sich unter `http://localhost:8082`. Wenn sie sich nicht automatisch öffnet, rufen Sie diese URL in Ihrem Browser auf. Kalender funktioniert vollständig auch ohne verbundenes Google-Konto. Sie stoßen nur auf einen Fehler, wenn Sie eine Aktion versuchen, die es benötigt, bevor Sie verbunden sind.

### Google Calendar verbinden

Öffnen Sie in der App **Einstellungen**, und suchen Sie im Tab **Allgemein** die Karte **Google Calendar**, klicken Sie dann auf **Google Calendar verbinden**. Dies öffnet einen Einrichtungsassistenten:

1. **Ein Google Cloud-Projekt erstellen**, falls Sie noch keines zur Verwendung haben: Klicken Sie in der [Google Cloud Console](https://console.cloud.google.com/) oben auf der Seite auf das Projekt-Dropdown, dann auf **Neues Projekt**. Geben Sie ihm einen beliebigen Namen, klicken Sie auf **Erstellen** und warten Sie auf die Benachrichtigung, dass es fertig ist. Stellen Sie sicher, dass es im selben Dropdown ausgewählt ist, bevor Sie fortfahren.
2. **Die API aktivieren**: Gehen Sie bei ausgewähltem Projekt zu **APIs & Dienste → Bibliothek**, suchen Sie nach „Google Calendar API“, öffnen Sie es und klicken Sie auf **Aktivieren**.
3. **Den Zustimmungsbildschirm konfigurieren**: Richten Sie unter **APIs & Dienste → OAuth-Zustimmungsbildschirm** einen ein („Extern“ reicht für die Entwicklung).
4. **Anmeldedaten erstellen**: Erstellen Sie unter **APIs & Dienste → Anmeldedaten** eine OAuth-Client-ID vom Typ „Webanwendung“ und fügen Sie `http://localhost:8082/_agent-native/google/callback` als autorisierte Weiterleitungs-URI hinzu (8082 ist der Standard-Entwicklungsport von Kalender).
5. **Die Anmeldedaten hinzufügen**: Laden Sie die Anmeldedaten-JSON herunter und laden Sie sie im Assistenten hoch, oder aktivieren Sie „Manuell einfügen“ und geben Sie die Client-ID und das Client-Secret direkt ein.

Kalender speichert diese in seinem eigenen Secret-Speicher, nicht in einer `.env`-Datei, sodass dieser Schritt auf Windows und macOS identisch ist. Tokens werden nach dem Verbinden automatisch erneuert.

### Zoom verbinden (optional)

Anders als Google hat Zoom kein Formular in den Einstellungen. Erstellen Sie eine `.env`-Datei im Projektstammverzeichnis (oder ergänzen Sie die bestehende) mit:

```text
ZOOM_CLIENT_ID=your-client-id
ZOOM_CLIENT_SECRET=your-client-secret
```

Holen Sie sich eine Client-ID und ein Secret von einer [Zoom OAuth-App](https://marketplace.zoom.us/) (Zoom Marketplace → Develop → Build App → OAuth), mit `/_agent-native/zoom/callback` als Weiterleitungs-URI, und starten Sie dann `pnpm dev` neu, damit die neuen Werte übernommen werden. Ohne verbundenes Zoom können Buchungslinks weiterhin Google Meet anbieten, nur kein Zoom.

</Steps>

<Callout tone="warning">

Unter Windows fügen manche Editoren beim Speichern einer Datei namens `.env` eine versteckte `.txt`-Erweiterung hinzu, sodass eine `.env.txt` entsteht, die Kalender niemals liest. Aktivieren Sie im Explorer „Dateinamenerweiterungen“ (Tab Ansicht) und prüfen Sie, dass die gespeicherte Datei exakt `.env` heißt, ohne etwas danach.

</Callout>

<Callout tone="info">

**Termine leben in Google Calendar, nicht in SQL.** Jede Termin-Aktion ruft direkt die Google Calendar API auf. Es gibt keine lokale Termine-Tabelle. Nur Buchungslinks, Buchungen, Verfügbarkeit und Verbindungsstatus werden lokal gespeichert. Lesen oder schreiben Sie Termindaten niemals mit rohem SQL.

</Callout>

## Aktionsinventar

Jede Operation ist eine TypeScript-Datei in `templates/calendar/actions/`, automatisch eingebunden unter `POST /_agent-native/actions/:name`.

### Termine & Gäste

Termindaten leben in Google Calendar, niemals in SQL.

| Action | Was sie tut |
| --- | --- |
| `list-events` | Termine in einem Datumsbereich auflisten |
| `search-events` | Termine per Suchanfrage durchsuchen |
| `get-event` | Einen Termin per ID lesen |
| `create-event` | Einen Termin erstellen, einschließlich Wiederholung (RRULE), Arbeitsorten und Statustypen (`outOfOffice`, `focusTime`) |
| `update-event` | Einen Termin aktualisieren, einschließlich Wiederholung, Arbeitsorten und Statustypen |
| `delete-event` | Einen Termin löschen |
| `manage-event-draft` | Eine ungesendete Einladung zur Prüfung durch den Nutzer bereitstellen, bevor etwas geschrieben oder Gäste benachrichtigt werden |
| `rsvp-event` | Eine Einladung annehmen, ablehnen oder als vorläufig markieren |
| `get-attendee-timezones` | Zeitzonen-Überschreibungen pro Gast lesen |
| `set-attendee-timezone` | Eine Zeitzonen-Überschreibung pro Gast setzen, damit dessen Ortszeit weiterhin korrekt angezeigt wird |

### Verfügbarkeit & Terminsuche

| Action | Was sie tut |
| --- | --- |
| `get-availability` | Den wöchentlichen Zeitplan, die Zeitzone, den Puffer, die Vorlaufzeit und die Einstellungen für das Vorlauffenster lesen |
| `update-availability` | Den wöchentlichen Zeitplan, die Zeitzone, den Puffer, die Vorlaufzeit und die Einstellungen für das Vorlauffenster aktualisieren |
| `check-availability` | Freie Slots für ein Datum finden |
| `find-a-time` | Gemeinsame Freie-Slot-Suche über einen Organisator und genannte Teilnehmer, die Google Frei/Belegt mit lokalen Konflikten kombiniert |

### Buchungslinks & Buchungen

| Action | Was sie tut |
| --- | --- |
| `create-booking-link` | Einen Buchungslink erstellen |
| `update-booking-link` | Einen Buchungslink aktualisieren |
| `duplicate-booking-link` | Einen Buchungslink duplizieren, einschließlich Co-Hosts (`hosts`) |
| `list-booking-links` | Zugängliche Buchungslinks auflisten |
| `list-bookings` | Bestätigte Termine auflisten |

### Externe Kalender

Schreibgeschützte ICS-Feeds.

| Action | Was sie tut |
| --- | --- |
| `add-external-calendar` | Einen schreibgeschützten ICS-/webcal-Feed abonnieren |
| `list-external-calendars` | Abonnierte Feeds auflisten |
| `remove-external-calendar` | Einen abonnierten Feed entfernen |
| `update-external-calendars` | Abonnierte Feeds aktualisieren |

### Personen & Overlays

| Action | Was sie tut |
| --- | --- |
| `search-people` | Google-Kontakte und das Workspace-Verzeichnis durchsuchen |
| `get-overlay-people` | Die anderen Personen lesen, deren Kalender in Ihre Ansicht eingebunden sind |
| `update-overlay-people` | Die anderen Personen aktualisieren, deren Kalender in Ihre Ansicht eingebunden sind |

### Zoom

| Action | Was sie tut |
| --- | --- |
| `get-zoom-status` | Den Zoom-Verbindungsstatus des aktuellen Nutzers lesen. Verbinden und Trennen erfolgen über `/_agent-native/zoom/*`-Routen, nicht über eine Aktion, da OAuth die angemeldete Browser-Sitzung benötigt |

### Google Calendar-Verbindung & Synchronisierung

| Action | Was sie tut |
| --- | --- |
| `connect-google-calendar` | Die OAuth-Verbindungs-URL für die angemeldete Browser-Sitzung zurückgeben |
| `sync-google-calendar` | Eine erneute Synchronisierung erzwingen |

### Einstellungen & Präferenzen

| Action | Was sie tut |
| --- | --- |
| `get-settings` | Einstellungen auf Nutzerebene lesen |
| `update-settings` | Einstellungen auf Nutzerebene aktualisieren |
| `update-calendar-visual-preferences` | Nur lokale Anzeigepräferenzen aktualisieren (Terminfarben, ausgeblendete Wochenenden). Berührt niemals Google Calendar |

### Navigation & UI-Status

| Action | Was sie tut |
| --- | --- |
| `navigate` | Die Oberfläche zu einer Ansicht, einem Datum oder einem Termin bewegen |
| `view-screen` | Die aktuelle Ansicht für den Agenten zurücklesen |

### Provider-API-Eskalation

Die rohe Google Calendar-(und verbundene CRM-)API, für wenn die obigen Aktionen zu eng sind.

| Action | Was sie tut |
| --- | --- |
| `provider-api-catalog` | Die verfügbaren rohen Provider-APIs zum direkten Aufruf auflisten |
| `provider-api-docs` | Dokumentation für einen rohen Provider-API-Endpunkt lesen |
| `provider-api-request` | Die rohe Google Calendar-(oder verbundene CRM-)API direkt aufrufen |
| `list-staged-datasets` | Große Scans auflisten, die zur Abfrage bereitgestellt wurden, statt Rohergebnisse zurückzugeben |
| `query-staged-dataset` | Ein bereitgestelltes Dataset abfragen |
| `delete-staged-dataset` | Ein bereitgestelltes Dataset löschen |

## Eine Aktion im Detail betrachtet

`create-booking-link` zeigt Muster, die sich in jeder Aktion wiederverwenden lassen: Eingaben validieren, bevor sie die Datenbank berühren, eine Regel über zwei Tabellen hinweg erzwingen, den angemeldeten Nutzer sicher auflösen und eine flexible Eingabeform einmal normalisieren statt in jedem Leser.

      note: "gemeinsame TypeScript-Typen, die von Server und Client verwendet werden",
    },
  ]}
/>

Zwei Legacy-Routen bleiben für Links eingebunden, die geteilt wurden, bevor sich ein URL-Schema änderte: `book.$slug.tsx` (kein Username-Segment) und `meet.$username.$slug.tsx`, die beide zu `/book/:username/:slug` kanonisiert werden. `_app.team.tsx` leitet auf `/settings/organization` weiter. Die Teamverwaltung befindet sich in den Einstellungen, nicht auf einer eigenen Seite.

## Anpassen

Jeder Teil der App ist bearbeitbarer Quellcode. Beginnen Sie hier:

- `templates/calendar/actions/` — fügen Sie eine neue Datei mit `defineAction` hinzu, um neue Funktionen sowohl dem Agenten als auch dem Frontend zur Verfügung zu stellen.
- `templates/calendar/app/routes/` — die Oberfläche, oben aufgelistet.
- `templates/calendar/server/db/schema.ts` — fügen Sie Spalten oder Tabellen mit Drizzle hinzu. Halten Sie den Code dialektunabhängig, damit die Vorlage auf SQLite, Postgres, Turso, D1 und Neon läuft.
- `templates/calendar/server/lib/` — Provider-Integrationen: `google-calendar.ts`, `zoom.ts`, `people-search.ts`, `ical-fetcher.ts`, `find-time.ts`, `provider-api.ts`.
- `templates/calendar/AGENTS.md` — Agentenanweisungen. Aktualisieren Sie dies, wenn Sie dem Agenten neue Fähigkeiten oder Konventionen beibringen.
- `templates/calendar/.agents/skills/` — detaillierte Muster, denen der Agent folgt. Relevante Skills: `event-management`, `availability-booking`, `real-time-sync`, `storing-data`, `delegate-to-agent`, `frontend-design`.
- `templates/calendar/shared/api.ts` — die gemeinsam genutzten TypeScript-Typen (`CalendarEvent`, `BookingLink`, `ExternalCalendar`, `ConferencingConfig` usw.), die sowohl vom Server als auch vom Client verwendet werden.

Wenn Sie eine Funktion hinzufügen, denken Sie daran, alle vier Bereiche zu aktualisieren: UI, Aktion, Skill- oder AGENTS.md-Eintrag und jeden Anwendungsstatus, den der Agent sehen muss. Das ist es, was den Agenten und die Oberfläche in Einklang hält.
