# Chat

Chat ist der schlichteste agentennative Ausgangspunkt: eine Shell im ChatGPT-Stil mit Chat im Zentrum, einer Thread-Liste, Authentifizierung und einer Beispiel-Aktion, nichts Domänenspezifisches. Sie richtet sich an Entwickler, die eine echte, bereitstellbare App wollen, auf der sie ihren eigenen Agenten und ihre eigenen Bildschirme aufbauen können, kein fertiges Produkt für eine bestimmte Aufgabe.

Wenn Sie eine fertige Domänenproduktform möchten, beginnen Sie mit
[Calendar](/docs/template-calendar), [Mail](/docs/template-mail),
[Content](/docs/template-content), [Forms](/docs/template-forms),
[Analytics](/docs/template-analytics) oder einer anderen Domänenvorlage. Wenn
Sie wirklich noch keine Browser-Oberfläche brauchen, lesen Sie
[Automation-First Apps](/docs/pure-agent-apps).

## Was enthalten ist {#what-ships}

<Comparison>

### :green: Enthalten

- Ganzseitiger Chat unter `/` über die Chat-Oberfläche des Frameworks und
  dauerhafte Chat-Threads
- Thread-Liste in der App-Seitenleiste zum Erstellen, erneuten Öffnen,
  Umbenennen, Anheften und Archivieren von Chats
- Die integrierte App-Agent-Schleife, vorkonfiguriert für das Chat-Plugin
- Authentifizierung über Better Auth: Anmeldung, Registrierung, Sitzungen,
  Organisationen
- Ein Aktionen-Verzeichnis mit einem Beispiel (`actions/hello.ts`) plus den
  Standardaktionen `view-screen` und `navigate`
- Die Kerntabellen des Frameworks für Chat-Threads, Anwendungsstatus,
  Einstellungen, Sitzungen, Ressourcen und Ausführungsverlauf, sowie eine
  Datenbank-Admin-Seite und ein Observability-Dashboard, eingebunden ganz
  gleich, ob Sie sie je öffnen
- Live-Synchronisierung (`useDbSync`) bereits verkabelt, sodass sich die
  Oberfläche aktualisiert, wenn der Agent in SQL schreibt
- Standardmäßig eingebundene Erweiterungsrouten für sandboxed Mini-Apps, die
  Ihre Nutzer später innerhalb des Chats bauen
- AGENTS.md mit chat-orientierter Anleitung zum Hinzufügen von Aktionen,
  Routen, Skills und Anwendungsstatus

### :red: Nicht enthalten

- Domänentabellen oder Seed-Daten
- Dashboards, Listen, Diagramme, Formulare oder Anbieterintegrationen
- Domänenspezifische Aktionen über den Beispiel-Stub hinaus

</Comparison>

Genau das ist der Punkt. Chat ist eine schlanke, nützliche Standard-Shell für
Ihren eigenen Agenten, kein Domänenprodukt, das sich als generisch ausgibt.

## Wann Sie es wählen sollten {#when-to-pick}

- **Sie möchten eine einfache App, mit der Nutzer sofort sprechen können** und
  die Sie dann mit Aktionen und Oberflächen erweitern.
- **Sie möchten den Standard-Einstieg von Agent-Native**: zuerst Chat, dann
  Aktionen, native Ergebnisse und App-Seiten.
- **Sie möchten Ihr eigenes Agenten-Backend an eine vertraute Chat-Oberfläche
  anschließen** und dabei die Aktionen, den Status, die Authentifizierung und
  die Bereitstellungsform von Agent-Native behalten.
- **Sie prototypisieren ein individuelles internes Tool**, das zu keiner
  Domänenvorlage passt.

## Einstieg {#get-started}

```bash
npx @agent-native/core@latest create my-chat-app --standalone --template chat
```

Siehe [Chat: Entwicklerhandbuch](/docs/template-chat-developers#quick-start)
für Installation, ersten Start und die Anbindung eines LLM. Für
automation-first Arbeit ganz ohne Browser-Oberfläche erstellen Sie das Gerüst
stattdessen mit `--headless`:

```bash
npx @agent-native/core@latest create my-agent --headless
```

Nutzen Sie dies für geplante Jobs, Queues, CLI-Schleifen oder
externe-Agent-Workflows, in denen Chat und App-Seiten noch nicht nützlich
sind. Die zentrale Invariante bleibt gleich: Aktionen sind die gemeinsame
Oberfläche für Chat, UI, HTTP, MCP, A2A und CLI. Siehe
[Automation-First Apps](/docs/pure-agent-apps) für diesen Weg im Detail.
