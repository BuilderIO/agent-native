# 部署

Agent-Native 应用运行在 [Nitro](https://nitro.build) 上，因此同一个应用可以部署到
Node.js、无服务器函数、边缘 worker 或托管主机。请选择适合你要发布内容的路径：

<Cards columns={2}>

### :server: [部署应用](/docs/deploy-an-app)

构建并发布一个独立应用，运行在 Node.js、Docker、Vercel、Netlify 或
Cloudflare Workers 上。

### :network: [部署工作区](/docs/workspace-deployment)

在同一个来源下构建多个应用，共享登录状态，并支持同源的应用间通信。

</Cards>

## 部署前：选择持久数据库 {#persistent-database}

每个已部署的应用都需要持久的 PostgreSQL 数据库。本地开发可以使用位于 `data/pglite`
的 PGlite 数据库，但容器、预览和无服务器环境的文件系统随时可能被重置。

<Steps>

### 选择提供商

请使用托管的 PostgreSQL 提供商，例如 [Neon](/docs/neon)、
[Supabase](/docs/supabase)、Railway、Render、[Amazon RDS for PostgreSQL](/docs/aws-rds)、
[Cloud SQL for PostgreSQL](/docs/cloud-sql) 或 [Azure Database for PostgreSQL](/docs/azure-postgresql)。
其他托管服务和自托管 PostgreSQL 服务器请参阅 [Plain Postgres](/docs/postgres) 指南。
框架会根据连接 URL 配置 PostgreSQL。

### 设置连接字符串

在首次生产部署之前，请在托管提供商的环境变量或密钥设置中设置 `DATABASE_URL`。
本地 `.env` 只配置你自己的电脑，部署命令不会上传它。

### 添加生产密钥

使用 `openssl rand -hex 32` 生成一个稳定的签名密钥，然后在独立应用中将它设置为
`BETTER_AUTH_SECRET`。如果工作区使用签名的跨应用请求或后台交接，还需要设置
`A2A_SECRET`。[部署环境变量参考](/docs/deployment-environment-variables)介绍了
其余的生产配置。

### 运行迁移

在首次访问之前，针对生产数据库运行 `pnpm migrate:production`。它会创建应用所需的表。
每次升级之后、新版本上线之前，请再次运行它。每篇托管指南都会说明这一步在流程中的位置。

</Steps>

<Callout tone="info">

在工作区中，每个应用默认继承根目录的 `DATABASE_URL`。只有当某个应用需要不同的数据库时，
才需要设置 `<APP_NAME>_DATABASE_URL`。

</Callout>

## 邮件发送是可选的，但建议配置 {#email-provider}

电子邮件提供商不是邮箱和密码身份验证的必需项。没有提供商时，已部署的应用会使用邮箱和密码
注册及登录，跳过注册时的邮箱验证，也不会提供魔法链接身份验证。

Agent-Native 不包含邮件发送账户。如果需要魔法链接、邮箱验证、密码重置、邀请或共享通知，
请在部署前连接 Resend 或 SendGrid。在部署环境中设置 `RESEND_API_KEY` 或
`SENDGRID_API_KEY`。SendGrid 还需要 `EMAIL_FROM`。有关可用的身份验证模式，请参阅
[身份验证](/docs/authentication)。

### 自定义框架邮件 {#email-templates}

框架发送的每封邮件都有默认模板。要使用你自己的设计，请在服务器插件中注册一个 override。
收件人、发件人和投递仍由框架负责。邮件的内容和外观由你的 override 决定。

```ts
// server/plugins/email-templates.ts
import {
  escapeEmailHtml,
  overrideTransactionalEmail,
} from "@agent-native/core/server";

export default function registerEmailTemplates(): void {
  overrideTransactionalEmail("core.resource-shared", (props) => ({
    subject: `${props.sender.name} shared "${props.resource.title}"`,
    html: `<p>${escapeEmailHtml(props.sender.name)} invited you to
      <a href="${escapeEmailHtml(props.resource.url)}">${escapeEmailHtml(props.resource.title)}</a>
      in ${escapeEmailHtml(props.app.name)}.</p>`,
  }));
}
```

| Email id                         | Props                                                                              |
| -------------------------------- | ---------------------------------------------------------------------------------- |
| `core.verify-signup`             | `email`, `verifyUrl`                                                               |
| `core.reset-password`            | `email`, `resetUrl`                                                                |
| `core.magic-link`                | `email`, `magicLinkUrl`                                                            |
| `core.change-email-confirmation` | `email`, `newEmail`, `confirmationUrl`                                             |
| `core.change-email-verification` | `email`, `verifyUrl`                                                               |
| `core.organization-invite`       | `invitee`, `orgName`, `inviter`, `acceptUrl`                                       |
| `core.builder-credit-limit`      | `subject`, `heading`, `body`, `upgradeLabel`, `upgradeUrl`                         |
| `core.resource-shared`           | `recipientEmail`, `sender`, `resource` (`type`, `title`, `url`), `role`, `message` |

每个 override 还会收到 `app`（`name`、`logoUrl`）。第二个参数是默认渲染结果，便于复用其主题或文本。

- Props 是未转义的原始值。放入 HTML 字符串前，请用 `escapeEmailHtml` 转义。
- 返回带 React 元素的 `react`（而不是 `html`）即可渲染组件。React 会自动转义 props。
- 省略 `subject` 会保留默认主题。省略 `text` 会从你的 HTML 生成纯文本正文。
- 如果 override 抛出错误，发送会失败。框架不会回退到默认设计。事务邮件预览会渲染你的
  override，请在那里检查。
