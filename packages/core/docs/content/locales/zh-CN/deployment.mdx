## 部署前：选择持久数据库 {#persistent-database}

每个已部署应用都需要持久 PostgreSQL 数据库。在首次生产部署前，将 `DATABASE_URL` 设置到部署环境中。托管 PostgreSQL 提供商包括 [Neon](/docs/neon)、[Supabase](/docs/supabase)、Railway、Render、[Amazon RDS for PostgreSQL](/docs/aws-rds)、[Cloud SQL for PostgreSQL](/docs/cloud-sql) 和 [Azure Database for PostgreSQL](/docs/azure-postgresql)。其他托管服务和自托管 PostgreSQL 服务器请参阅 [Plain Postgres](/docs/postgres) 指南。

独立应用需要稳定的 `BETTER_AUTH_SECRET`。使用签名跨应用请求的工作区需要 `A2A_SECRET`。

请将这些值保存到托管提供商的环境设置中，而不只是本地 `.env`。使用 `openssl rand -hex 32` 生成身份验证密钥。Agent-Native 不包含邮件发送账户；请单独连接 Resend 或 SendGrid。

## 邮件发送是可选的，但建议配置 {#email-provider}

电子邮件提供商不是邮箱和密码身份验证的必需项。没有提供商时，已部署的应用会使用邮箱和密码注册及登录，跳过注册时的邮箱验证，也不会提供魔法链接身份验证。

如果需要魔法链接、邮箱验证、密码重置、邀请或共享通知，请在部署前连接 Resend 或 SendGrid。在部署环境中设置 `RESEND_API_KEY` 或 `SENDGRID_API_KEY`；SendGrid 还需要 `EMAIL_FROM`。有关身份验证模式，请参阅[身份验证](/docs/authentication)。

### 自定义框架邮件 {#email-templates}

框架发送的每封邮件都有默认模板。要使用你自己的设计，请在服务器插件中注册一个 override。收件人、发件人和投递仍由框架负责；邮件内容和外观由你的 override 决定。

```ts
// server/plugins/email-templates.ts
import {
  escapeEmailHtml,
  overrideTransactionalEmail,
} from "@agent-native/core/server";

export default function registerEmailTemplates(): void {
  overrideTransactionalEmail("core.resource-shared", (props) => ({
    subject: `${props.sender.name} shared "${props.resource.title}"`,
    html: `<p>${escapeEmailHtml(props.sender.name)} invited you to
      <a href="${escapeEmailHtml(props.resource.url)}">${escapeEmailHtml(props.resource.title)}</a>
      in ${escapeEmailHtml(props.app.name)}.</p>`,
  }));
}
```

| 邮件 ID | Props |
| --- | --- |
| `core.verify-signup` | `email`, `verifyUrl` |
| `core.reset-password` | `email`, `resetUrl` |
| `core.magic-link` | `email`, `magicLinkUrl` |
| `core.change-email-confirmation` | `email`, `newEmail`, `confirmationUrl` |
| `core.change-email-verification` | `email`, `verifyUrl` |
| `core.organization-invite` | `invitee`, `orgName`, `inviter`, `acceptUrl` |
| `core.builder-credit-limit` | `subject`, `heading`, `body`, `upgradeLabel`, `upgradeUrl` |
| `core.resource-shared` | `recipientEmail`, `sender`, `resource` (`type`, `title`, `url`), `role`, `message` |

每个 override 还会收到 `app`（`name`、`logoUrl`）。第二个参数是默认渲染结果，便于复用其主题或文本。

- Props 是未转义的原始值。放入 HTML 字符串前，请用 `escapeEmailHtml` 转义。
- 返回带 React 元素的 `react`（而不是 `html`）即可渲染组件。React 会自动转义 props。
- 省略 `subject` 会保留默认主题。省略 `text` 会从你的 HTML 生成纯文本正文。
- 如果 override 抛出错误，发送会失败。框架不会回退到默认设计。事务邮件预览会渲染你的 override，请在那里检查。

## 支持的部署目标

Agent-Native 支持 [Node.js](/docs/node-js)、[Docker](/docs/docker)、[Vercel](/docs/vercel)、[Netlify](/docs/netlify)、[Cloudflare Workers](/docs/cloudflare#cloudflare-workers)、[AWS Amplify](/docs/aws-amplify)、[AWS Lambda](/docs/aws-lambda)、[Deno Deploy](/docs/deno-deploy)、[Azure Static Web Apps](/docs/azure-static-web-apps)、[Koyeb](/docs/koyeb) 和 [Render](/docs/render)。

有关高级设置、密钥和生产值，请参阅[部署环境变量参考](/docs/deployment-environment-variables)。
