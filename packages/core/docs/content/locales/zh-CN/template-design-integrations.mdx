# 多应用工作区中的 Design

Design 是 [Dispatch](/docs/template-dispatch) 工作区中众多应用中的一个，同时它也可以被完全在该工作区之外运行的代理直接触达。本页会同时介绍这两方面：Dispatch 连接是如何运作的，以及一个外部代理如何通过 MCP 调用 Design 自身的 actions。有关概览，请参阅 [Design](/docs/template-design)。

## Design 如何与 Dispatch 连接

这是否自动完成，取决于 Design 和 Dispatch 是如何被一起搭建起来的，而不取决于两者中任何一个是托管运行还是本地运行。

### 同一工作区：自动完成

如果 Design 和 Dispatch 是通过 `create` 或 `add-app` 一起生成或添加到同一个 Agent-Native 工作区中，并作为一个整体部署的，那么它们已经共享同一个 `.env`、同一个 `A2A_SECRET` 和同一个工作区注册表。无论该工作区运行在您的本机还是生产环境中，发现和经过身份验证的 A2A 调用都会自动生效，无需任何额外设置。

### 独立部署：需要一步手动操作

如果 Design 和 Dispatch 是两个独立创建的 Agent-Native 项目，它们不会共享密钥，因此还无法互相调用。连接它们需要在双方各执行一步手动操作：添加一个带有共享密钥的 `remote-agents/<id>.json` 资源，可以从Settings → Agent → Sub-agents（Connect agent），或 Dispatch → 代理 → 添加外部代理来完成。完整的操作步骤请参阅 [A2A 协议](/docs/a2a-protocol)。

要检查您属于哪种情况，可以问任意一个应用的代理"你能看到哪些应用？"。如果 Design 没有出现在 Dispatch 的回答中，那么您就属于第二种情况。

## 从工作区之外调用 Design

Design 也可以作为一个托管的 MCP 服务器，供其他代理直接连接，无论它们是否属于您的 Dispatch 工作区。Claude、Claude Code、Claude Desktop、Codex 以及其他兼容 MCP 的主机，都可以连接到：

```
https://design.agent-native.com/mcp
```

Claude 和 Claude Desktop 会将其添加为一个自定义连接器，并通过登录来批准访问。Claude Code 添加同一个 URL，然后运行 `/mcp` 完成身份验证。Codex 以及其他 CLI 或 stdio 客户端则运行 `npx @agent-native/core@latest connect https://design.agent-native.com`，这会打开一个浏览器标签页来完成授权，并生成一个按用户区分、可随时撤销的令牌，不涉及任何共享密钥。

连接完成后，外部代理会获得与[与 Agent 对话](/docs/template-design-agent)中介绍的相同核心工作流：创建一个设计、生成几个方向进行比较、读取某个屏幕的当前状态、进行一次有边界的编辑，并在需要把结果转化为真实代码时导出一个编码交接包。代理会展示一个内嵌预览，或一个返回真实编辑器的"打开设计"链接，而不是把原始 HTML 粘贴到对话中。

<Callout tone="info">

如果您的外部代理中某次 Design 工具调用开始返回会话或身份验证错误，不要一
直重试。请在 Claude Code 中运行 `/mcp` 并重新连接，或者在任意终端中运
行 `npx -y @agent-native/core@latest reconnect
https://design.agent-native.com`。两者都会重新完成身份验证，而无需重
新安装任何东西。

</Callout>

## 通过 Dispatch 委托给 Design

一个同级应用不需要任何特殊集成就能与 Design 协同工作。它可以像您在聊天中那样，向 Design 的代理提交一条用简单易懂的语言表达的请求，例如"帮我为这个新功能做一个着陆页"，Design 会直接回答或据此执行操作。

对于以上所有这一切，Design 都不需要知道请求方应用的凭证，反过来也一样。它只需要回答一个真实的请求即可，它不需要知道是谁在请求，也不需要知道原因。
