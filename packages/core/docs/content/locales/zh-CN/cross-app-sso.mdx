# 跨应用 SSO

浏览器中的“Sign in with Agent-Native”选项和自动浏览器跳转已移除。对于
Web 用户，每个应用独立登录仍是默认方式。本页只介绍剩余的显式 Desktop
流程和服务端联邦协议。

## 保留的功能

### Desktop 工作区

工作区登录是 Desktop 设置中的显式操作。启用后，Desktop 可以通过专用
broker 为符合条件且已注册的应用配置登录。每个目标应用仍然拥有自己的
用户存储、会话和访问检查。Desktop 不会拦截浏览器前往应用登录页的匿名
导航。

应用必须同时满足以下条件才符合要求：

- Desktop 为该应用启用工作区 SSO。
- 生产 URL 是精确的 HTTPS 地址。
- Dispatch 为该应用保存了精确的服务端注册信息。
- <code>desktop.workspace-sso</code> 发布标志已启用。

设备级偏好 <code>desktopSsoEnabled</code> 默认启用。显式设置为 false 仍然
表示退出。如果标志、偏好、注册信息或资格检查不可用，普通的应用登录
仍然可用。

### 服务端联邦

剩余的 broker 和服务端调用方使用短时、服务端验证的协议。它不会作为
浏览器登录控件提供：

1. 调用方请求一个精确的已注册应用绑定。
2. Dispatch 验证工作区身份并返回短时的一次性授权码。
3. 目标应用服务器使用 PKCE 验证器兑换代码。
4. 目标应用验证签名断言、精确应用绑定、回调、范围、nonce 和过期时间。
5. 目标应用按已验证邮箱关联或创建本地用户，并签发自己的普通会话。

断言只通过服务端到服务端交换返回。它不会出现在浏览器 URL 中，也不是
可重复使用的 bearer token。

## 组织联邦

<code>organization.cross-app-federation</code> 标志默认关闭。启用后，源应用 向
Dispatch 注册本地组织，并保存精确的
<code>(identity_authority, identity_id)</code> 映射。目标应用只接受来自
服务端验证断言的规范组织 ID、名称和已验证成员角色。

组织名称、邮箱域名和浏览器 Cookie 不是关联键。没有映射的本地组织在显式
迁移前保持不变。已关联的成员关系仍使用目标应用的普通访问检查。

组织联邦为每个已注册源应用使用独立凭据：

- 在源应用设置 <code>AGENT_NATIVE_IDENTITY_FEDERATION_SECRET</code>。
- 在 Dispatch 设置匹配的
  <code>AGENT_NATIVE_IDENTITY_FEDERATION_SECRET_&lt;NORMALIZED_APP_ID&gt;</code>
  。
- 不要为此权限边界重复使用 <code>A2A_SECRET</code>。

应用 ID 后缀会将每段非字母数字字符替换为下划线，并将结果转换为大写。
例如，应用 ID <code>workspace-reports</code> 使用

<code>AGENT_NATIVE_IDENTITY_FEDERATION_SECRET_WORKSPACE_REPORTS</code>。

身份和组织写入只会添加数据。相同邮箱的现有用户会原样复用。新的已验证
邮箱会创建本地用户。关闭联邦不会删除数据。

## 配置

<code>AGENT_NATIVE_IDENTITY_HUB_URL</code> 仅用于剩余的服务端和 Desktop
路径。当自托管应用需要指定 Dispatch 部署时才设置它。它不会添加浏览器
登录选项或自动浏览器跳转。

对于自托管 Dispatch，请通过

<code>IDENTITY_SSO_APP_REGISTRY_JSON</code> 为每个自定义应用注册精确的应用
ID、客户端 ID、HTTPS 来源、回调路径和 <code>identity-sso</code> 能力。

生产注册必须使用 HTTPS 和精确的回调路径。Localhost 只允许用于本地开发。
未知子域、不匹配的应用 ID、任意路径和跨来源回调都会被拒绝。

## 验证和回滚

部署后：

1. 验证浏览器中的邮箱、密码、魔法链接和已配置的提供商登录仍然有效。
2. 验证浏览器认证页面不提供 Agent-Native 登录选项。
3. 如果启用了 Desktop SSO，从 Desktop 设置中的显式操作验证一个精确注册的应用。
4. 如果启用了组织联邦，验证目标应用中的精确组织 ID 和成员角色。

要回滚剩余路径，请关闭相应功能标志，并从自托管部署中移除

<code>AGENT_NATIVE_IDENTITY_HUB_URL</code>，然后重新部署。已添加的身份和
组织记录会保留，可继续用于普通本地认证。
