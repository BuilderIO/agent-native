# 将现有应用升级到 Core 0.197.0

按照本指南将现有应用升级到 Core 0.197.0。请在应用或 workspace 根目录运行
命令，并在开始前保留可审阅的源代码差异。请单独检查远程部署配置：CLI
可以读取本地环境文件，但无法查看远程环境或保存在数据库中的功能设置。

## 1. 预览升级和 import codemod

使用 Core 0.197.0 随附的 CLI，以加载该版本的 migration manifest：

    npx @agent-native/core@0.197.0 upgrade --codemods --dry-run

在应用中安装 Core 0.197.0 后，也可以通过本地 CLI 二进制文件运行相同的预览：

    npx agent-native upgrade --codemods --dry-run

`--codemods` 命令使用 `ts-morph`。如果应用尚不能解析该包，请先将其安装为开发依赖：`pnpm add -D ts-morph`。

`--codemods` 默认会应用受支持的 import 修改。添加 `--dry-run` 可预览计划中的依赖变更、
文件差异和警告。现在不再需要 `--yes`。

codemod 使用当前生效的 Core 和 Toolkit migration manifest。它仅扫描 .ts 和
.tsx 文件（跳过声明文件、生成文件和依赖目录），并重写受支持的 import
和 re-export specifier。如果具名 export 移至不同模块，它可以按 symbol
拆分声明，同时保留别名和 type-only import。它还会重写简单的 CSS
@import 路径，并在已解析的重写跨越 package 边界时添加缺失依赖。

诊断也会检测 CommonJS `require()` 和动态 `import()` 形式，但 codemod 不会重写这些调用表达式。请根据报告中的新位置替换它们，然后重新运行 Vite 或 `agent-native doctor`。CSS `@import url(...)` 路径无论是否带引号，codemod 都会重写。

codemod 不会改动调用位置，也不会移动文件。未解析或 planned 的迁移会保留
原样并显示警告。它无法拆分 default、namespace、side-effect 或 star
import/export；也不能按 symbol 拆分 CSS import。
请手动检查这些情况。已移除的 export 可能需要修改代码；请按 CLI 警告中
给出的 migration guide 处理。

预览还会展示完整升级计划：阻止升级的 framework override 或 patch、待
更新的 @agent-native/\* 版本、根据本地配置推断的功能依赖、package manager
安装、scaffold skill 更新，以及根 package 存在 typecheck script 时的
typecheck。命令会将 package spec 更新为 registry 当前的 latest，然后固定
安装解析出的版本。请在 0.197.0 是预期当前版本时运行；如果之后需要精确
版本，请确认解析后的 pin。

## 2. 确认 Toolkit 和可选软件包

迁移到 `@agent-native/toolkit/*` 的导入需要安装 `@agent-native/toolkit`。codemod 会在将受支持且可解析的导入或导出迁移到 Toolkit 时添加该依赖。如果应用使用了 Toolkit 导出但未添加依赖，请安装与 Core 0.197.0 对应的 Toolkit 版本：

    pnpm add @agent-native/toolkit@0.197.0
    # npm install @agent-native/toolkit@0.197.0
    # yarn add @agent-native/toolkit@0.197.0

### 由升级 CLI 选择的依赖

本地环境检查符合条件时，CLI 会添加以下依赖。对于 PGlite，它先检查规范化应用名对应的 `${APP_NAME}_DATABASE_URL`，再检查 `DATABASE_URL`；如果没有 URL 或 URL 以 `pglite:` 开头，就会选择 PGlite。CLI 无法检查远程环境或存储在数据库中的功能设置，请单独确认生产和预览环境。

| 功能                         | 可选软件包                   | 版本                | CLI 检查的本地配置                                                                    |
| ---------------------------- | ---------------------------- | ------------------- | ------------------------------------------------------------------------------------- |
| PGlite 数据库                | @electric-sql/pglite         | ^0.5.8              | 规范化的 `${APP_NAME}_DATABASE_URL`，然后是 `DATABASE_URL`；未设置或以 `pglite:` 开头 |
| 服务端 Sentry                | @sentry/node                 | ^10.60.0 或 ^11.0.0 | `SENTRY_SERVER_DSN`、`SENTRY_DSN` 或 Sentry 密钥组                                    |

如需搜索第一方模板源码，请将对应版本的 corpus 包作为开发依赖添加：`pnpm add -D @agent-native/core-corpus@0.197.0`。

## 3. 应用升级

检查预览并确认功能包后，应用计划：

    npx agent-native upgrade --codemods

这一条命令会更新符合条件的 @agent-native/\* dependency spec，对齐检测到的
功能依赖，运行 package manager，固定解析出的 Agent-Native 版本，应用受
支持的 codemod，刷新 scaffold skill，并在根目录存在 typecheck script 时
执行它。无需再运行第二次 upgrade 来应用 codemod。请在应用代码中处理
警告和应用级错误；不要添加 framework override 或 patch。

## 4. 验证结果

检查完整差异，特别是跳过的 codemod 警告和依赖版本，然后运行：

    npx @agent-native/core@0.197.0 upgrade check
    pnpm typecheck

使用 npm 或 Yarn 对应的 typecheck 命令，并运行应用相关的测试和构建。确认
可选 peer 表覆盖了本地及已部署的功能设置。搜索下表列出的旧 import；
剩余结果应是有意保留、manifest 不支持，或已由警告说明。
