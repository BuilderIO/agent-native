# 功能

表单的每一项核心功能：它是如何运作的，以及如何进行设置。有关概览，请参阅 [表单](/docs/template-forms)；有关完整的提示列表，请参阅 [与 Agent 对话](/docs/template-forms-agent)。

## 创建表单

每个表单都从一组字段开始。向代理描述您想要的内容，它就会为您构建表单；您也可以从空白开始，自己在可视化构建器中添加字段。这两种方式编辑的是同一个表单，因此在两者之间切换永远不会导致不同步。表单一旦创建，它的构建器就有四个标签页：编辑、回复、设置和集成，供您在需要比在聊天中描述更直接的控制时，手动调整标签、占位符、必填字段、选项和字段顺序。

### 字段类型 {#field-types}

表单开箱即用地内置了 11 种字段类型。您可以按名称向代理请求任意一种，或者直接描述您想问的问题，让它来选择合适的类型。

每个字段都需要一个标签和一个类型。像 `select`、`multiselect` 和 `radio` 这样的字段还需要一份供人选择的选项列表。您可以把任意字段标记为必填，添加最小值或最大值之类的校验规则，并选择它是占满表单整行宽度，还是与另一个字段并排显示。

### 条件字段

一个字段可以保持隐藏，直到前面某个回答符合您设置的规则为止。例如，您可以把一个“详细说明”文本字段隐藏起来，除非有人在前面的问题中选择了“其他”。

您用来做判断依据的字段，必须排在表单中更靠前的位置。一条指向后面字段、或指向不存在字段的规则，会在保存之前就被拒绝。您可以判断前面的回答是否等于某个值、不等于某个值，或者包含某个值，这对可以多选的问题同样适用。如果某个字段最终因条件而被隐藏，它的回答就永远不会被存储或发送到任何地方，因此一个隐藏字段不会在您的数据中留下过期或默认的值。

想直接通过脚本创建表单，而不是在聊天中描述？请参阅 [开发者指南](/docs/template-forms-developers#data-model) 中的字段和设置 JSON 参考。

## 发布表单

一个表单会经历三种状态：

| 状态        | 含义                 | 公开访问                 |
| ----------- | -------------------- | ------------------------ |
| `draft`     | 正在编辑中，尚未公开 | 否                        |
| `published` | 已上线，正在接收回复 | 是                        |
| `closed`    | 不再接收回复         | 显示已关闭的提示信息      |

如果表单没有任何字段、任意字段缺少标签，或者某个 `select`、`multiselect` 或 `radio` 字段没有设置选项，表单就无法发布。如果发布被拒绝，系统会告诉您具体原因。

公开 URL 的格式类似 `/f/<slug>`，其中 slug 由标题加上一个简短的唯一后缀生成，例如 `beta-signup-a1b2c3`。只要标题发生变化，它就会自动重新生成，除非您设置了自定义 slug。

### 收集回复

对一个已发布表单的每一次提交，都会成为一条回复：包含答案、到达时间，以及——除非表单是匿名的——是谁在什么地方提交的。打开任意表单的**回复**标签页即可查看每一条的详情，或者直接问代理：

- “Beta 注册表单有多少条回复？”
- “今天谁提交了？”
- “给我看看客户反馈表单的回复。”

如果一条回复是通过嵌入在另一个应用中的反馈按钮提交的，而不是来自公开表单页面本身，回复表格中还会显示它来自哪个页面、哪个应用。只有当至少有一条回复实际携带这类信息时，这些列才会显示出来。

## 设置

每个表单在构建器的**设置**标签页中都有自己的一套设置，用来控制它的行为方式以及受访者会看到什么。

- **提交按钮文本。** 把提交按钮上的默认文字“Submit”改成更具体的内容，比如“发送反馈”或“预留名额”。
- **成功消息。** 选择受访者提交后立即看到的内容，替代默认的确认信息。
- **重定向 URL。** 让受访者提交后跳转到另一个页面，而不是在表单本身上显示成功消息。
- **进度条。** 在较长表单的顶部显示一条进度条，让受访者能看到还剩多少。
- **匿名模式。** 关闭对回复者身份的所有追踪，让提交内容永远不会记录 IP 地址、邮箱或位置信息。
- **有新回复时给我发邮件。** 每当有人提交时，通过您配置好的邮件服务商收到一封邮件。

## 保护并为公开表单添加品牌标识

### 垃圾信息防护

公开提交可以要求先通过 [Cloudflare Turnstile](https://www.cloudflare.com/products/turnstile/) 验证才能通过。在设置中填写 site key 和 secret key 即可开启此功能。即使不使用 Turnstile，也始终有两项防护在生效：一个会悄悄丢弃机器人提交的隐藏字段，以及一项会拒绝提交速度快于正常人填写表单所需时间的检查。

<Callout tone="warning">

两个 Turnstile 密钥（site key 和 secret key）需要一起设置。公开表单页面只有在设置了 site key 时才会显示验证组件，而服务器只有在两个密钥都设置好后才会进行校验。只设置 secret key 什么也验证不了，而只设置 site key 只会显示一个服务器实际上从不校验的组件。

</Callout>

### 品牌标识

每个独立的公开表单角落都会显示一个小小的“Built with Agent-Native”标识。这不是您可以按表单单独开关的选项。只有当表单被嵌入到另一个页面中时（比如一个反馈弹出框），它才会自动隐藏，因为那个页面已经带有自己的品牌标识。

### 限制可提交的来源

默认情况下，表单的提交链接接受来自任何地方的提交，这也是一个普通公开表单链接本应有的行为。如果您把表单的提交链接嵌入到另一个网站的小组件中，并希望确保只有那个网站可以使用它，您可以把提交范围限制在一份特定的网站来源列表中。

目前构建器中还没有针对这项功能的开关。请让代理帮您设置，例如“只允许从 https://example.com 提交这个表单”。请为每个允许的网站提供准确的来源（协议加域名，例如 `https://example.com`，不带末尾路径）。

## 回复洞察 {#response-insights}

与其翻看一行行数据，不如直接请求趋势或摘要。试试“按天统计提交量”“本周有多少条回复”或“总结本周的反馈”，代理会给您一张图表、一张表格，或者两者兼有，而不是一堆原始数据。

如果您没有指名具体的表单，代理会转而查看您最近更新的表单，默认最多 50 个，最多不超过 100 个。这对于类似“这个月我所有表单的提交趋势如何？”这样的问题很有用。每个回答都会告诉您它展示的是全部数据还是抽样数据，以及覆盖了多少行，这样您就始终清楚自己看到的是什么。

## 导出

在表单的**回复**标签页中，点击**导出 CSV** 即可立即下载当前屏幕上显示的内容（包括您已应用的任何搜索或排序）的 CSV 文件。这项功能可以立即使用，无需任何设置。

您也可以让代理帮您导出“这个表单的 CSV”或“所有回复的 JSON 导出”。这种方式始终导出全部回复，而不只是当前筛选出的内容，并且需要先连接一个文件存储服务商。如果还没有连接，代理会告诉您，并引导您前往设置 → 文件上传，那里一个免费的 Builder.io 账号就是一个快捷的选择。一旦存储连接完成，代理会把文件链接返回给您，而不是直接下载文件。每次导出都会使用您的字段标签作为列标题（CSV 格式），如果有人在某个字段中选择了多个选项，这些选项会被合并到同一个单元格中。任何看起来像电子表格公式的答案都会先被处理掉，这样可以保护您在打开文件时，不会被某条试图执行代码的提交内容影响。

## 路由提交

开启自动投递，让新回复直接出现在您团队已经在使用的工具中，而不必有人专门去查看**回复**标签页。这是一个按表单单独设置的选项，在构建器的**集成**标签页中配置。

| 目的地        | 所需内容                                                          |
| ------------- | ------------------------------------------------------------------- |
| Slack         | 您想要的频道的 Incoming Webhook URL                                  |
| Discord       | 您想要的频道的 webhook URL                                           |
| Google Sheets | 一个配置好用于接收提交内容的 Google Apps Script URL。普通的电子表格链接无法使用。 |
| Webhook       | 任何可以接收提交数据的网址                                           |

这与连接 Slack 以便代理直接在其中发帖是两回事，后者在 [Messaging](/docs/messaging) 中有介绍。如果您希望代理本身能向 Slack 发布更新，请先完成那项连接。每个目的地地址都会被检查，确保它没有指向私有网络或内部地址，在您保存时以及每次有回复到达时都会检查，这样表单就不会被用作探测您自身网络的手段。

您还可以开启邮件通知，让表单所有者在每次有新回复时都收到一封邮件，邮件会通过已配置好的邮件服务发送。发送这封邮件是尽力而为的：即使通知邮件发送失败，提交本身仍然会正常完成。
