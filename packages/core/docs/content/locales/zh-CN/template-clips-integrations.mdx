# 多应用工作区中的剪辑

剪辑只是 [Dispatch](/docs/template-dispatch) 工作区中众多应用之一。本页介绍这在实践中究竟意味着什么：连接是如何运作的，以及其他应用和代理可以对你的剪辑采取哪些具体操作，或对剪辑上发生的事情做出哪些具体反应。有关概览，请参阅 [剪辑](/docs/template-clips)。

## 剪辑如何与 Dispatch 连接

这是否是自动完成的，取决于剪辑和 Dispatch 是如何被一起搭建起来的，而不取决于两者中任何一个是托管运行还是本地运行。

### 同一工作区：自动完成

如果剪辑和 Dispatch 是通过 `create` 或 `add-app` 一起生成或添加到同一个 Agent-Native 工作区中，并作为一个整体部署的，那么它们已经共享同一个 `.env`、同一个 `A2A_SECRET` 和同一个工作区注册表。无论该工作区运行在你的本机还是生产环境中，发现和经过身份验证的 A2A 调用都会自动生效，无需任何额外设置。这是基于剪辑构建真正的多应用产品时应有的搭建方式。

### 独立部署：需要一步手动操作

如果剪辑和 Dispatch 是两个独立创建的 Agent-Native 项目，它们不会共享密钥，因此还无法互相调用。连接它们需要在双方各执行一步手动操作：添加一个带有共享密钥的 `remote-agents/<id>.json` 资源，可以从Settings → Agent → Sub-agents（Connect agent），或 Dispatch → 代理 → 添加外部代理来完成。完整的操作步骤请参阅 [A2A 协议](/docs/a2a-protocol)。

要检查你属于哪种情况，可以问任意一个应用的代理“你能看到哪些应用？”。如果剪辑没有出现在 Dispatch 的回答中，那么你就属于第二种情况。

## 集成策略

### 代理可读的剪辑

把一个公开的剪辑分享链接粘贴给一个代理，或者对于一个私密剪辑，在**与代理分享**这一行使用**分享 → 复制**。无论哪种方式，代理都可以读取转录文本并查看关键帧，而无需下载视频，使用的链接会在两小时后过期。

大多数能查看图像的代理都可以自行处理这一点，包括 ChatGPT、Claude Code、Cursor 和 Codex。少数纯文本聊天可以读取转录文本但无法读取画面帧，对于这些情况，请在一个支持图像的代理中打开该剪辑。

| 端点                                              | 代理可以获得什么                                                          |
| ------------------------------------------------- | ------------------------------------------------------------------------- |
| `/api/agent-context.json?id=<recordingId>`        | 剪辑元数据、转录状态、章节、CTA、推荐帧，以及指向转录/帧 API 的链接       |
| `/api/agent-transcript.json?id=<recordingId>`     | 带有 `startMs`、`endMs`、可读时间戳、文本和可选来源标签的带时间戳转录片段 |
| `/api/agent-frame.jpg?id=<recordingId>&atMs=<ms>` | 在原始视频时间戳处从视频中提取的一帧 JPEG 图像                            |

这些端点遵循与分享页面相同的公开/密码/过期规则，或者接受来自临时代理链接的、限定范围的 `agent_access` 令牌。受密码保护的剪辑需要输入一次密码；成功的响应会返回短期有效的令牌化链接，因此下游代理不需要明文密码。

如果转录文本还没有准备好，一个行为得当的代理会稍等一下再重试，而不是立刻放弃。较长的录制内容可能需要几分钟。如果转录因为 Builder 额度用尽而失败，代理应该说明这一点，并指向[转录和 AI 元数据](/docs/template-clips-features#transcription-and-ai-metadata)。

### 导出到 Brain

一旦你的工作区连接了 Brain，剪辑就会在每段录制内容完成后自动把准备好的转录文本发送过去。你也可以请代理回填更早的录制内容，比如最近 28 天内的所有内容，而不是等待新内容慢慢积累。它会汇报有多少份转录文本被导出、跳过，或被标记出来。

### CRM 通话证据

CRM 工具有时需要证明一次通话确实发生过，而不需要完整的录制内容。剪辑只会交出一个不透明的剪辑 ID 和一个持久链接，绝不会交出视频或转录文本。这只对你已经能看到的一段录制内容有效，并且只在你主动要求，或一个已批准的自动化触发时才会发生。

### 通过 Dispatch 进行自然语言委托

一个同级应用不需要任何特殊集成就能与剪辑协同工作。它可以像你在聊天中那样，向剪辑的代理提交一条用简单易懂的语言表达的请求，比如“找到我们讨论定价的剪辑”，剪辑会直接回答或据此执行操作。

### 保持解耦

剪辑永远不需要知道 Brain 或某个 CRM 的凭证，反过来也一样。`clip.created` 事件和代理可读的链接位于各应用之间，因此剪辑只需要发出事件、回答请求，而不需要知道是谁在监听。
