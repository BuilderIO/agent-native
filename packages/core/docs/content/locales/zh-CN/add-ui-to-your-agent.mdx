# 为代理添加 UI

Agent-Native 为现有代理提供聊天、审批、工作流状态和权限工作区。推理、工具、上下文和长时间执行仍由提供商负责。

本页介绍如何**为 Microsoft Foundry、Gemini Enterprise、Anthropic Managed Agents 或 OpenAI 代理添加 UI**。

## 选择连接方式 {#choose-a-connection-path}

| 后端                     | Agent-Native 连接  | 配置                           |
| ------------------------ | ------------------ | ------------------------------ |
| Microsoft Foundry        | A2A 1.0            | Agent Card URL 和 Entra 密钥   |
| Gemini Enterprise        | A2A                | Agent Card URL 和 Google 密钥  |
| Anthropic Managed Agents | Managed Agents API | 代理 ID、环境 ID 和 Vault 密钥 |
| OpenAI Agents API        | 自定义 A2A 端点    | Agent Card URL 和提供商凭据    |
| 任意 A2A 代理            | A2A                | Agent Card URL 和可选凭据      |

打开 **Settings → Agent → Sub-agents** 并选择 **Connect agent**（所有者和管理员）搜索提供商。Connect 按钮会打开已选中对应提供商的连接表单。密钥只保存在工作区 Vault 中。

## Microsoft Foundry {#microsoft-foundry}

粘贴 A2A v1.0 Agent Card URL 并选择 Entra 凭据。服务间调用使用 `https://ai.azure.com/.default` 作用域和 **Foundry Agent Consumer** 角色。

## Gemini Enterprise {#gemini-enterprise}

粘贴自定义 A2A 卡片 URL 并选择 Vault 中的 bearer 密钥。保存前会验证卡片和 JSON-RPC 接口。

## Anthropic Managed Agents {#anthropic-managed-agents}

选择 **Anthropic Managed Agents**，输入代理和环境 ID 并选择 API 密钥。会话和审批留在 Anthropic，并显示在 Agent-Native 聊天中。

## 自定义 A2A {#custom-a2a}

内部或自托管代理使用 **Add by URL**。系统验证 A2A 0.3 和 1.0 卡片，并将错误显示为明确状态。

如果未提供流式传输，连接会使用 `message/send`。

## 注册表 {#registries}

浏览 [Global A2A Registry](https://www.a2a-registry.org)。添加代理和使用密钥前，请检查卡片、主机和认证要求。

## UI 层 {#ui-layer}

[A2A](/docs/a2a-protocol) 传递委托任务，Agent-Native 工作区管理用户状态。参阅 [Connected agents](/docs/agent-mentions#mentioning-agents) 和 [External agents](/docs/external-agents)。
