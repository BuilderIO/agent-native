# 可视化 Plans

Agent-Native Plans 是面向编码代理的可视化计划模式。它把一份普通的
Codex、Claude Code、Markdown 或粘贴进来的实施计划，变成一个结构化的
审阅界面——包含富文本、图表、线框图、带注释的代码演练和文件树、评论，
以及可共享链接。

它归结为两个命令。`/visual-plan` 会在代理**编写代码之前**构建一份计划。
`/visual-recap` 会把**已经发生**的变更——一个 PR、提交、分支或
git diff——变成一次高空视角的可视化代码审查。两个命令打开的是
同一个审阅界面，因此无论哪种方式，你都以同样的方式添加注释、评论，
并把反馈交回给代理。

## 它取代了什么

<Comparison>

### 之前

- 计划以聊天记录或 Markdown 文件中的一整墙文字存在，审阅它意味着必须
  从头读到尾，才能找到你不同意的那一段。
- 反馈发生在 Slack 线程或散落的评论中，与计划本身脱节。
- 审阅一个已完成的 PR，意味着要逐行阅读原始 diff，才能重新拼凑出
  改了什么、为什么改。

### 之后

- 计划会渲染成图表、线框图、带注释的代码，以及一个可以直接回应的
  Open Questions 表单。
- 评论会固定到具体的文字、图片或线框图位置上，并可以指定给代理或
  人类审阅者。
- `/visual-recap` 会把一个 PR、提交或 diff 变成同样的可视化审阅，而
  不是一份原始 diff。

</Comparison>

把结果导出为 HTML、Markdown 或 JSON，得到一份对源代码管理友好的
副本，或者使用本地文件模式让它完全不进入托管数据库。关于这两者的
详细说明，参见[审阅与评论 Plan](/docs/template-plan-review-workflow)
和[本地文件模式与桌面同步](/docs/template-plan-local-and-desktop)。

## 开始使用 {#get-started}

<Steps>

### 安装 skill {#install}

大多数人会把 Plan 作为**skill**安装到自己现有的编码代理中，而不是
安装成一个搭建好的应用。这一条命令会安装 skill 说明、注册托管的
Plans MCP 连接器，并完成登录：

```bash
npx @agent-native/core@latest skills add visual-plan
```

这会安装三个 slash 命令——`/visual-plan`、`/visual-recap` 和
`/visualize-repo`——以及位于 `https://plan.agent-native.com/mcp` 的
`plan` MCP 连接器（一个你的代理会与之通信的远程工具服务器）。完整的
参数说明、Claude Code 和 Codex 的插件/市场安装路线，以及 VS Code
扩展，请参见
[Plan 插件与市场 → 安装路线](/docs/plan-plugin#install)。

自定义 Plan 模板本身——自托管它，或者直接在它之上构建——是一条
独立的、次要的路径，详见[扩展 Plan](/docs/template-plan-developers)。
大多数人从不需要它。

### 向你的代理请求适合当前工作的命令

- “在修改身份验证流程之前，先使用 `/visual-plan`。”
- “为新的入门屏幕创建一份 `/visual-plan`，包含移动端和桌面端状态。”
- “对这个 PR 运行 `/visual-recap`，让我先看看这次改动的整体形状。”
- “对 `main` 与这个分支之间的 diff 使用 `/visual-recap`。”
- “运行 `/visualize-repo`，从我们的公共 API actions 和 schema 开始。”

`/visual-plan` 会根据工作需要引入图表、线框图、模型图、可点击原型
和带注释的代码。代理会先检查代码库，然后返回的链接会在你的浏览器
或 VS Code 中打开审阅界面。

### 以访客身份审阅，无需账号

与你共享计划的人不需要安装任何东西。他们打开 Plans 编辑器，就可以
**无需注册地创建和编辑**——以访客身份工作。登录只有在你想要
**保存或分享**自己的成果时才是必需的，而且如果访客之后登录，他们
以访客身份创建的每一份计划都会被**认领**到自己的账号下。

</Steps>

当已经存在一份 Codex、Claude Code、Markdown 或粘贴进来的计划时，
使用 `/visual-plan`；代理会保留那份源计划，并在它的基础上构建更
丰富的审阅界面，而不是从头开始。如果第一遍处理后仍有待定的决策，
代理可以在计划底部添加一个**Open Questions**表单；回答并发回后，
就会开始一轮修订。

<Callout tone="info">

**访客与登录用户对比一览**

- **作为访客**，你可以打开一个共享链接、创建新计划、编辑正文，并
  使用审阅注释模式——无需账号。
- **登录**之后还可以永久保存自己的计划、把计划发布为可共享链接、
  向其他人授予查看者/编辑者/管理员权限、发表会通过邮件通知他人的
  评论，以及删除或恢复你拥有的计划。

</Callout>

## 成本与模型选择

生成一份计划或回顾，会针对你的编码代理的 LLM 运行一次完整的代理式
会话，而不是一次轻量级的模板填充——成本会随 diff 或计划的大小，
以及你选择的模型而变化。

- 该应用默认的聊天模型是 GPT-5.6 Luna。直接连接 Anthropic 时，默认
  模型仍是 Claude Sonnet 5。你可以随时在**设置**中更改模型；Haiku
  是更便宜的 Claude 选项。
- 来自 GitHub Action 的自动化 PR 回顾与交互式应用分开运行，拥有
  各自的模型和成本调节项——`VISUAL_RECAP_MODEL`、
  `VISUAL_RECAP_AGENT` 和 `VISUAL_RECAP_REASONING` 参见
  [PR Visual Recap](/docs/pr-visual-recap)。

## 请求访问一份私密计划 {#request-access}

如果有人打开了一个他们没有权限查看的计划链接，Plans 不会只显示
一个死胡同。页面会告诉他们该计划是私密的，并提供一个**请求访问**
操作，它会：

- 要求先登录（访客会先被提示登录）。
- 把该请求记录在这份计划下，并且——当部署配置了邮件功能时——向
  计划所有者发送一条消息，包含请求者的姓名，以及一个用于打开该
  计划、并在批准后把它共享回去的链接。
- 可以安全地多次点击——Plans 会先检查你是否已经拥有访问权限，因此
  同一个人的第二次请求不会向所有者重复发送邮件轰炸。

如果该计划的可见性设置为**组织内可见**而非完全私密，并且你的账号
已经拥有该组织的待处理邀请，或者你的邮箱域名与该组织匹配，Plans
会直接提供加入该组织的选项，而不是发送请求。

<Callout tone="warning">

如果某个 Plans 工具返回了 `needs auth`、`Unauthorized` 或
`Session terminated`，不要不断重试。使用
`npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex`
重新进行身份验证，或者对支持 OAuth 的主机重新运行 `/mcp` →
**Authenticate**。之后新建一个 Codex 会话，或者重启/重新加载
客户端——工具注册表只会在全新的会话中获取这个变更。

</Callout>
