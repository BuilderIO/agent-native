# 什么是 Agent-Native？

Agent-Native 是一个开源 TypeScript 框架，用于构建配备直观 UI 的自主型智能体。你只需将每项能力定义一次，作为一个[动作](/docs/actions-overview)——一种由智能体用作工具、由 UI 从代码中调用的类型化函数。

编码智能体会让人觉得文本框已经足够。但文本框只是其工作环境的一部分。代码库提供上下文，工具提供明确的行动方式，文件、测试和预览则让结果可见。

大多数知识工作没有这样的结构。面对空白文本框，人们只能猜测智能体能做什么、拥有什么上下文，以及该提出什么要求。

UI 提供了文本框所缺少的东西。它让智能体的能力可见，将上下文和工作流带入体验，并让人们随着工作推进查看和调整结果。

Agent-Native 让你能以这种方式构建智能体。UI 提供明确的起点，而不会将智能体限制在固定工作流中。由于智能体和 UI 使用相同的能力，人们可以把工作委派给智能体，在 UI 中检查或修改结果，并在两者之间切换而不会丢失进度。

## Agent-Native 如何工作

Agent-Native 通过三个共享基础连接智能体和 UI：

- **[共享动作](/docs/actions-overview)。** 每项能力只定义一次。智能体将其作为工具调用，UI 则从代码中调用。两条路径使用相同的验证、权限和实现。
- **[共享数据](/docs/server-database)。** 动作读取并更新相同的数据，因此智能体完成的工作会显示在 UI 中，而 UI 中完成的工作也可供智能体使用。
- **[共享应用状态](/docs/context-awareness)。** 应用状态描述 UI 中正在发生的事情，例如当前页面、选定记录或活动视图。Agent-Native 将相关状态作为上下文提供给智能体，使其理解人正在处理什么。

智能体不会通过点击 UI 来操作。它通过与 UI 相同的动作层工作。

例如，一个人可以通过 UI 分配支持工单，也可以要求智能体完成此事。两条路径都会运行同一个动作并更新同一张工单。该人可以在 UI 中检查或修改结果，然后让智能体从那里继续。

## 何时应使用 Agent-Native？

以下情况适合使用 Agent-Native：

- 智能体应完成实际工作，而不仅仅是回答问题。
- 人们需要 UI 来了解智能体能做什么，并检查、编辑、审批或共享它的工作。
- 人们应能在智能体和 UI 之间切换，而不会丢失进度或上下文。

如果你只需要一次生成的回答，直接调用模型即可。如果工作遵循固定且可预测的顺序，普通应用逻辑或自动化会更简单。当智能体和 UI 都需要在同一项工作中持续发挥作用时，请使用 Agent-Native。
