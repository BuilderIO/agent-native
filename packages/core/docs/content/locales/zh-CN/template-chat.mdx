# 聊天

聊天是最朴素的 agent-native 起点：一个 ChatGPT 风格的外壳，聊天位于中心，配有线程列表、身份验证和一个示例 action，不包含任何特定领域的内容。它面向那些想要一个真正可部署的应用、并在其之上构建自己的代理和界面的开发者，而不是面向某个具体场景的成品产品。

如果你想要成品的领域产品形态，请从 [日历](/docs/template-calendar)、[邮件](/docs/template-mail)、[Content](/docs/template-content)、[表格](/docs/template-forms)、[分析](/docs/template-analytics) 或其他领域模板开始。如果你确实还不需要浏览器 UI，请参阅
[Automation-First Apps](/docs/pure-agent-apps)。

## 包含哪些内容 {#what-ships}

<Comparison>

### :green: 已包含

- 使用框架聊天界面和持久聊天线程，在 `/` 上实现整页聊天
- 应用侧边栏中的线程列表，可以创建、重新打开、重命名、固定和存档聊天
- 内置的应用代理循环，已针对聊天插件预先配置
- 通过 Better Auth 实现的身份验证：登录、注册、会话、组织
- 一个 actions 目录，包含一个示例（`actions/hello.ts`）以及标准的 `view-screen` 和 `navigate` actions
- 框架的核心表，用于聊天线程、应用状态、设置、会话、资源和运行历史，还挂载了一个数据库管理页面和一个可观测性仪表板，无论你是否打开过它们
- 已接好的实时同步（`useDbSync`），当代理写入 SQL 时界面会自动刷新
- 默认挂载的扩展路由，供你的用户之后在聊天中构建沙盒化的小应用
- AGENTS.md 中包含以聊天为先的指南，用于添加 actions、路由、skills 和应用状态

### :red: 未包含

- 领域表或种子数据
- 仪表板、列表、图表、表单或 provider 集成
- 除示例存根之外的特定领域 actions

</Comparison>

## 何时选择它 {#when-to-pick}

- **你想要一个用户可以立即与之对话的基础应用**，然后再用 actions 和 UI 进行扩展。
- **你想要默认的 Agent-Native 入门路径**：先有聊天，然后是 actions、原生结果和应用页面。
- **你想把自己的代理后端接入一个熟悉的聊天 UI**，同时保留 Agent-Native 的 actions、状态、身份验证和部署形态。
- **你正在为一个不匹配任何领域模板的自定义内部工具制作原型**。

## 开始使用 {#get-started}

```bash
npx @agent-native/core@latest create my-chat-app --standalone --template chat
```

请参阅 [聊天：开发者指南](/docs/template-chat-developers#quick-start) 了解安装、首次运行和连接 LLM 的方法。如果是完全没有浏览器 UI 的 automation-first 工作，请改用 `--headless` 来搭建脚手架：

```bash
npx @agent-native/core@latest create my-agent --headless
```

适用于计划任务、队列、CLI 循环，或聊天和应用页面尚无用处的外部代理工作流。关键的不变量保持不变：actions 是聊天、UI、HTTP、MCP、A2A 和 CLI 共用的界面。有关这条路径的详细说明，请参阅 [Automation-First Apps](/docs/pure-agent-apps)。
