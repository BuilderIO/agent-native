# Plan 插件与市场

Agent-Native **Plan** 应用以一个可安装的 bundle 形式发布。一次安装会
同时添加 Plan 的 slash 命令 skill，**并**接好托管的 Plan MCP 连接器
（一个你的代理会与之通信的远程工具服务器），这样代理就能一步生成
计划并直接发布到 Plan 应用中。本页面适合任何需要选择安装路线、
排查安装问题，或决定是否要把 Plan 提交到某个精选插件目录的人——
skill 实际做了什么，参见[可视化 Plans](/docs/template-plan)。

## 你会得到什么 {#what-you-get}

一次安装会给你：

- **三个 skill** — `/visual-plan`（规范入口）、`/visual-recap` 和 `/visualize-repo`。
- **Plan MCP 连接器** — 注册到位于 `https://plan.agent-native.com` 的托管应用（MCP 端点为 `https://plan.agent-native.com/mcp`，服务器名称为 `plan`）。

默认情况下，`/visual-plan` 和 `/visual-recap` 会发布到托管的 Plan
应用——它们通过 MCP 连接器创建一份计划，并把链接或内联的计划交给你
审阅。它们绝不会把内联的 Markdown/ASCII 计划当作最终交付物直接扔进
聊天里。如果某个 Plan 工具返回 `needs auth`、`Unauthorized` 或
`Session terminated`，请重新对连接器进行身份验证，而不是退回到内联
输出。访问令牌的有效期很长（默认 30 天，滑动式 365 天刷新），所以
这种情况应该很少见；一旦发生，轻量级的修复方法是：

```bash
npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex
```

`reconnect` 会按 URL 为选定的本地客户端查找并刷新连接器——无需重新
安装。重新连接后新建一个 Codex 会话，让工具注册表重新加载。在
Claude Code 中，等效操作是 `/mcp` → **Authenticate / Reconnect**，
或者使用同一条命令并加上 `--client claude-code`。

唯一的例外是明确的**本地文件隐私模式**。当你要求不写入数据库，或者
设置了 `AGENT_NATIVE_PLANS_MODE=local-files` 时，skill 不得调用 Plan
MCP 连接器。它们会写入 `plans/<slug>/plan.mdx`，以及可选的
`canvas.mdx`、`prototype.mdx` 和 `.plan-state.json`，然后用以下命令
进行本地预览：

```bash
npx @agent-native/core@latest plan local serve --dir plans/<slug> --kind plan --open
```

这会启动一个小型的本地主机桥，并针对本地文件夹打开 Plan UI。
（`plan local preview` 改为运行一个本地的 Plan 开发服务器路由，而
`plan local preview --out preview.html` 是一个遗留的应急方案，会
写出一个独立的静态 HTML 文件。`plan serve` 被接受作为
`plan local serve` 的简写别名。）

一些值得了解的本地文件模式注意事项：

- **使用 Chromium 系浏览器。** Safari 会阻止托管的 HTTPS Plan 页面
  读取 `http://127.0.0.1` 本地主机桥（混合内容/私有网络限制），
  导致页面卡在“Loading plan.”上。在 macOS 上，`--open` 已经优先
  选择 Chrome/Chromium/Edge/Brave；如果 Safari 仍然被打开，请在
  Chromium 系浏览器中重新打开打印出来的 URL。
- **提供服务的 URL 会写入 `plans/<slug>/.plan-url`**（可用
  `--url-file` 覆盖）。后台运行或无头模式的代理可以直接读取该文件，
  而不必抓取长时间运行的 `serve` 标准输出。请把它当作本地令牌文件，
  不要提交它。
- **在没有浏览器可用时进行无头验证**：
  `npx @agent-native/core@latest plan local verify --dir plans/<slug>`
  会启动网桥，检查私有网络预检和 JSON 负载，打印诊断信息，并在
  失败时以非零状态退出——不需要人工查看。
- **先运行 `plan local check`。** 它会依据 Plan 渲染器的区块 schema
  校验 MDX（包括 `checklist` 条目的 `id`/`label`、`question-form`
  问题的 `id`/`title`/`mode` 等必填字段），这样编写错误会在交给
  浏览器之前就暴露出来，而不是表现为卡住的加载动画。

对于当前仓库内的文件夹，直接本地路由会带上 `?path=...`，这样本地
Plan 应用就能持续把浏览器中的编辑保存到该仓库文件夹。Plan 应用会
使用 `agent-native.json` 中的 `apps.plan.roots[0].path` 作为保存
升级后本地计划的默认位置，默认回退到 `plans/`。

这样可以让计划内容不进入 Agent-Native Plan 数据库。在你之后明确
发布之前，托管共享、评论、截图和计划历史记录都不可用。

Agent-Native Desktop 为托管计划提供了另一条独立的本地文件同步路径：
Desktop 应用可以把一份托管计划镜像为本地 MDX 文件，并把编辑导入
回去，全程不需要克隆 Plan 应用或运行 CLI。这条工作流仍然以托管的
Plan 数据库为事实来源；当目标是完全不写入 Plan 数据库时，请使用
本地文件隐私模式。

> 该插件（`agent-native-visual-plans`）携带的应用 id 是
> `visual-plans`，这也是为什么 Claude Code 插件名称和 Codex 插件
> 名称都是 `agent-native-visual-plans`。Plan 应用的显示名称是
> “Agent-Native Plan”。

## 安装路线 {#install}

共有三种安装方式。**通用 CLI 路线**是我们默认推荐的方式，因为它会
安装 skill，**并且**让你在同一个流程中选择托管、本地文件或自托管
模式。插件路线适用于拥有一流插件/市场系统的主机，并默认使用托管的
Plans。

### 通用 skill 路线（任意 MCP 主机） {#universal}

适用于任何主机——Claude Code、Codex、Cursor、Cline、Goose、ChatGPT
自定义 MCP 应用、Claude Cowork，以及其他任何兼容 MCP 的主机。
Agent-Native CLI 会安装 Plan 的 skill，注册托管的 Plan MCP 连接器，
**并在同一步中为选定的本地客户端运行身份验证**，这样你的第一次
工具调用就不会撞上 OAuth 墙：

```bash
npx @agent-native/core@latest skills add visual-plan
```

这会安装 `visual-plan`，以及配套的 `visual-recap` 和
`visualize-repo` skill，然后注册 `plan` 连接器，接着运行身份验证
（针对托管/账号支持的共享，会出现 OAuth 提示）。一些有用的参数：

- `--client codex|claude-code|claude-code-cli|cowork|all` — 为哪些本地代理写入 MCP 配置（默认是 `all`）。
- `--no-connect` — 只注册连接器而不进行身份验证；之后运行 `npx @agent-native/core@latest connect https://plan.agent-native.com --client all`，或者选择更小范围的 `--client`。
- `--mode hosted|local-files|self-hosted` — 选择托管共享、全本地 MDX 文件，还是你自己的 Plan 应用。
- `--mcp-url <url>` — 让连接器指向一个自定义源（比如 ngrok 隧道、本地开发服务器或自托管部署），而不是默认的托管地址。
- `--with-github-action` — 同时写入 PR Visual Recap GitHub Action（参见 [PR Visual Recap](/docs/pr-visual-recap)）。

在没有工作流存在时，交互式安装还会主动提供添加 PR Visual Recap
Action 的选项。在 skill 设置过程中选择“是”即可添加它，或者之后带上
`--with-github-action` 重新运行上面的命令。写入工作流之后，运行：

```bash
npx @agent-native/core@latest recap setup
npx @agent-native/core@latest recap doctor
```

`recap setup` 会在可能的情况下配置 GitHub Action 的 secrets 和
变量，`recap doctor` 会验证工作流、本地发布令牌、GitHub 仓库访问
权限以及所需的 Actions 配置。安装完成后，重启或重新加载代理客户端，
让新的 skill 和工具生效，然后运行 `/visual-plan`。

> 注意：单独运行
> `npx skills@latest add BuilderIO/agent-native --skill visual-plan`
> （Vercel/开放 Skills CLI）只会安装**说明文件**——它不会注册 MCP
> 连接器。当你也想把连接器一起接好时，请使用上面的 Agent-Native
> CLI。

### Claude Code（插件） {#claude-code}

公开的 `BuilderIO/agent-native` 仓库本身就是一个 Claude Code 插件
市场，因此你可以直接添加它——不需要任何构建步骤。在 Claude Code
中：

```text
/plugin marketplace add BuilderIO/agent-native
/plugin install agent-native-visual-plans@agent-native-apps
/reload-plugins
/mcp        # authenticate the Plan connector (one OAuth approval)
```

`/plugin install` 会添加 Plan 的 skill，以及一个**仅含 URL** 的
MCP 配置（安装包里不包含任何 secrets）；`/mcp` → **Authenticate**
会完成 OAuth 握手。当你想要本地文件模式或自托管模式时，请改用
通用 CLI 路线。

> 该市场目录名为 `agent-native-apps`，Plan 插件名为
> `agent-native-visual-plans`，因此安装目标始终是
> `agent-native-visual-plans@agent-native-apps`。

### Codex（插件） {#codex}

同一个仓库也是一个 Codex 插件市场。添加它、安装插件，然后对连接器
进行身份验证：

```bash
codex plugin marketplace add BuilderIO/agent-native
codex plugin add agent-native-visual-plans@agent-native-apps
codex mcp login plan   # OAuth in the browser
```

安装之后，**新建一个 Codex 会话**，让 skill 和 MCP 工具加载到会话
中。该插件自带一个仅含 URL 的连接器（`[mcp_servers.plan]` →
`https://plan.agent-native.com/mcp`）；`codex mcp login plan` 会
运行 OAuth 流程。如果你更喜欢用一条命令同时完成安装和身份验证，
或者想要本地文件模式/自托管模式，上面的通用 CLI 路线在 Codex 上
同样适用（`npx @agent-native/core@latest skills add visual-plan --client codex`）。

<Callout tone="info">

**旧版安装：** 如果你的配置中仍有一个指向同一 URL 的
`agent-native-plans` 条目，对 Codex 运行
`npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex`，
或者用你的目标 `--client` 运行同一条命令，就会把它整合为规范的
`plan` 名称。

</Callout>

## 更新 {#updates}

插件路线会自动更新——对于常规的 skill 变更，你不需要重新打包或
重新添加市场：

- **Claude Code** — 市场条目设置了 `autoUpdate: true`，插件使用
  基于 commit SHA 的版本管理，因此 Claude Code 会在启动时从仓库
  拉取新版本；运行 `/reload-plugins` 即可激活。每一次推送到仓库
  默认分支的改动，都会自动送达已安装的用户。
- **Codex** — 插件的 `version` 中嵌入了所打包 skill 与 MCP 端点的
  内容哈希（例如 `1.0.0+codex.<hash>`），因此任何 skill 或端点的
  变更都会产生一个新版本。Codex 启动时的自动升级会自行重新安装
  已配置的 git 市场；只需**新建一个会话**即可获取变更。常规更新
  不需要手动运行 `codex plugin marketplace upgrade`。
- **通用 CLI 路线** — 运行
  `npx @agent-native/core@latest skills status visual-plan` 检查
  已复制的 skill 文件夹，或运行
  `npx @agent-native/core@latest skills update visual-plan` 就地
  刷新它们。当你还想重新注册/验证连接器时，重新运行
  `skills add visual-plan` 依然有效。`@latest` 始终会从已发布的
  `@agent-native/core` 包中拉取当前的 skill。

连接器指向的是一个**托管**应用，因此 Plan 应用的 actions 和实时
工具接口始终反映的是已部署的版本，与你何时安装无关；只有打包的
skill 说明会遵循上面的更新机制。

<Callout tone="info">

**维护者须知：** 市场打包内容（`.claude-plugin/`、`.agents/plugins/`）
是由 `pnpm sync:plan-marketplace` 根据规范的 plan skill 生成的，
并由 CI 中的 `pnpm guard:plan-marketplace` 进行校验，因此发布的
市场内容始终与规范 skill 保持一致。编辑 skill、运行
`pnpm sync:plan-marketplace`，然后提交即可。

</Callout>

## 你需要提交什么吗？ {#submission}

**分发或安装这个插件都不需要任何提交或审核流程。**
`BuilderIO/agent-native` 是一个自托管的公开 git 市场，因此用户可以
在 **Claude Code 和 Codex 上**直接用上面的命令添加它——不需要申请，
也不需要批准。通用 CLI 路线则完全不需要市场。

如果你想要一个公开的列表，还有一些可选的可发现性方式：

- **Claude Code** 有一个社区市场，你可以*选择性地*提交上去以获得
  列表展示（需要提交并经过一次自动化审核）。由 Anthropic 精选的
  官方市场是否收录，由 Anthropic 自行决定——没有开放的自助申请
  渠道。使用上面的安装命令都不需要经过这两者中的任何一个。
- **Codex** 有一个由 OpenAI 精选的插件目录（一个封闭的允许列表，
  来源是合作关系，而不是自助提交）。自托管的 git 市场和 CLI 路线
  都不需要提交任何内容即可正常工作。

简而言之：以自托管/公开 git 市场的形式发布，用户就可以直接安装；
只有当你希望它出现在精选目录中以便被发现时，才需要提交审核。

## 插件与 skill 的区别 {#plugin-vs-skill}

**skill** 是一个单独的 `SKILL.md` 说明文件，当任务与之匹配时代理
就会读取它。**插件**（Claude Code 市场插件或 Codex 插件）是一个
打包了一个或多个 skill **加上** MCP 连接器和元数据的软件包，这样
主机就可以一步安装所有内容。

在底层，这三条路线都是由 `npx @agent-native/core@latest app-skill`
CLI 从同一份源生成的：`app-skill pack` 负责构建市场/插件适配器，而
`skills add` 是那个友好的一步式安装程序，同时还会注册并验证 MCP
连接器。app-skill manifest 格式参见
[Skills Guide](/docs/skills-guide)；连接任意 MCP 主机以及
`npx @agent-native/core@latest connect` 流程参见
[External Agents](/docs/external-agents)。
