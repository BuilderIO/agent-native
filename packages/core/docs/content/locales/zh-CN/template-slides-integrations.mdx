# 多应用工作区中的幻灯片

幻灯片只是 [Dispatch](/docs/template-dispatch) 工作区中众多应用之一。本页
介绍这在实践中究竟意味着什么：连接是如何运作的，以及其他应用可以对您的
演示文稿采取哪些具体操作，或复用其中的内容。有关概览，请参阅
[幻灯片](/docs/template-slides)。

## 幻灯片如何与 Dispatch 连接

这是否是自动完成的，取决于幻灯片和 Dispatch 是如何被一起搭建起来的，而不
取决于两者中任何一个是托管运行还是本地运行。

### 同一工作区：自动完成

如果幻灯片和 Dispatch 是通过 `create` 或 `add-app` 一起生成或添加到同一个
Agent-Native 工作区中，并作为一个整体部署的，那么它们已经共享同一个
`.env`、同一个 `A2A_SECRET` 和同一个工作区注册表。无论该工作区运行在您的
本机还是生产环境中，发现和经过身份验证的 A2A 调用都会自动生效，无需任何
额外设置。这是基于幻灯片构建真正的多应用产品时应有的搭建方式。

### 独立部署：需要一步手动操作

如果幻灯片和 Dispatch 是两个独立创建的 Agent-Native 项目，它们不会共享密
钥，因此还无法互相调用。连接它们需要在双方各执行一步手动操作：添加一个
带有共享密钥的 `remote-agents/<id>.json` 资源，可以从Settings → Agent → Sub-agents（Connect agent），或 Dispatch → 代理 → 添加外部代理来完成。完
整的操作步骤请参阅 [A2A 协议](/docs/a2a-protocol)。

要检查您属于哪种情况，可以问任意一个应用的代理“你能看到哪些应用？”。如
果幻灯片没有出现在 Dispatch 的回答中，那么您就属于第二种情况。

## 集成策略

**通过 Creative Context Library 共享演示文稿。** 提交一份演示文稿会在共
享的 Creative Context Library 中冻结一个确切的版本，工作区中的任何应用，
而不只是幻灯片本身，之后都可以搜索并复用这些幻灯片。一个会议记录应用可
以把一张已获批准的指标幻灯片直接拉入自己的输出中，而不必用提示描述它。

**通过 Dispatch 进行自然语言委托。** 一个同级应用不需要任何特殊集成就能
与幻灯片协同工作。它可以像您在聊天中那样，向幻灯片的代理提交一条用简单
易懂的语言表达的请求，例如“把这个季度的数字做成一份 5 页的回顾演示文
稿”，幻灯片会直接回答或据此执行操作。这正是诸如邮件中收到的一条报告请求
最终变成一份完成的演示文稿背后的真实机制：Dispatch（或接收到该消息的应
用）把请求委托给幻灯片的代理，幻灯片就像处理任何其他提示一样处理它。

**保持解耦。** 对于以上所有这一切，幻灯片都不需要知道同级应用的凭证，反
过来也一样。A2A 协议以及共享的 Creative Context Library 位于各应用之间，
因此幻灯片只需要回答一个真实的请求，或暴露一个真实的共享资源即可，它不
需要知道是谁在调用，也不需要知道调用的方式。
