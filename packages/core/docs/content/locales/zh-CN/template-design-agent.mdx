# 与 Agent 对话

Design 中的一切，代理都可以通过与界面相同的 actions 来访问，因此任何您能点击完成的事，也都能用简单易懂的语言请求代理完成。本页介绍代理如何查看您的屏幕，然后是按任务分类的实用提示。有关概览，请参阅 [Design](/docs/template-design)。

## 代理如何查看您的屏幕

在做任何事之前，代理会先检查您正在查看的内容：打开的是哪个设计或模板、您所在的是哪个视图（设计列表、模板、编辑器、设计系统，还是一个公开的展示视图）、您选中了哪个屏幕和元素、当前激活的是哪个检查器标签页（设计、评论，还是代码与测量），以及左侧边栏打开的是哪个面板（文件、代理、资源、导入、工具，还是令牌）。这就是为什么"让这个更密集一些"或者"修正这个按钮的对比度问题"这样的说法，即使您不指名具体的屏幕或元素也能正确解析。代理早已知道"这个"指的是哪一个。

有几种情况会改变代理接下来的做法：

- **一个模糊的提示。** 如果您的请求没有给代理提供足够的信息，它会显示一个全画布的澄清问题浮层，而不是靠猜测，并等待您在聊天中回答之后再开始生成任何内容。
- **一个由模板创建的设计。** 代理已经知道该模板锁定的尺寸和字体，会在原有屏幕的基础上完善它们，而不是重新生成或调整它们的尺寸。
- **您正处于比较阶段的一个版本。** 如果您正在几个提议的调整之间做选择，代理知道哪些仍待定、哪些您已经选定，因此"用第二个"能够正确解析。
- **有未处理的评论。** 代理知道当前屏幕上有多少条未处理的评论，以及其中哪些已经在它的处理队列里，因此它不会遗漏您留下的反馈。

## 按任务分类的实用提示

下面的每一条提示都会转化为针对您真实设计的真实 action，与界面读写的是同一个设计。这里有一个具体示例：

<Comparison>

### :blue: 您的请求

"这个屏幕上有未处理的评论吗？"

### :green: 发生的事情

这是一个只读的问题。代理会检查当前屏幕真实的评论讨论串数量，然后直接
在聊天中回答，例如"有 2 条未处理评论，其中 1 条已经在我的处理队列
里"。您屏幕上的内容不会发生任何变化，因为没有创建或编辑任何东西。

</Comparison>

<Cards columns={2}>

### 生成与完善

- **"为一个技术分析类产品创建三个着陆页方向。"** 会出现几个真正不同的版本供您比较和挑选。
- **"让这个仪表板更密集一些，方便运营团队快速浏览。"** 所选屏幕会实时更新。
- **"把这个重复出现的卡片变成一个可复用的组件。"** 之后对某一个实例的编辑会保持独立，除非您要求同步更新所有实例。
- **"给这个按钮加一个悬停动画。"** 会创建一条动效轨道，无需您自己打开动效面板。
- **"给英雄区背景加一个波浪着色器。"** 会直接应用该效果，无需通过效果菜单的选择器操作。

### 检查质量

- **"对这个屏幕做一次无障碍审查。"** 代理会检查它并报告发现的问题。
- **"修复你刚才发现的对比度问题。"** 修复会直接应用到设计上。

### 引入外部内容

- **"导入这个 Figma 画框：[链接]。"** 该画框会作为一个新的、可编辑的屏幕出现。
- **"把这段 HTML 粘贴为一个新屏幕。"** 无需您自己打开导入面板即可添加。
- **"从 Figma 引入我们的定价页面，并完全匹配它。"** 像素级精确的导入，并针对任何在结构上无法还原的部分附带一份保真度报告。

### 品牌与设计系统

- **"应用我们保存的设计系统，并简化移动端布局。"** 从此之后的每一次生成都会保持在品牌规范之内。
- **"从我们的 GitHub 仓库启动一个设计系统。"** 会索引您真实的、已部署的令牌，而不是靠猜测。
- **"基于 Material 3 创建一个设计系统。"** 从一个真实的、有人维护的公开系统开始，而不是一个仿制品。

### 模板

- **"从着陆页模板开始一个新设计。"** 会把它的文件、尺寸和锁定图层复制到一个新设计中。
- **"把这个另存为一个名为‘产品发布’的模板。"** 之后在模板中可用，供您或您共享给的任何人使用。

### 导航与整理

- **"切换到概览画布。"** 跳出单屏视图。
- **"打开评论标签页。"** 让检查器聚焦到该标签页。
- **"把这个设计重命名为‘Q3 发布页面’。"** 会立即更新，无论该设计在哪里被列出。

### 导出与历史

- **"把这个导出为一个 ZIP。"** 无需您自己打开项目菜单即可下载。
- **"为这个屏幕复制一段编码交接提示词。"** 可以直接粘贴给外部编码代理。
- **"恢复一小时前的版本。"** 会把设计恢复到那个确切的已保存状态。

</Cards>

## 扩展

Design 支持扩展：小型的沙盒化组件，您或代理都可以构建它们，并放入编辑器
中。检查器的左侧边栏提供了一个插槽，供扩展渲染，该插槽已经可以获取打
开的设计的 id 和标题、当前屏幕的文件名和内容、当前的视图模式和缩放级
别、所选屏幕和元素，以及当前激活的工具。您如今在编辑器中看到的资源
库、着色器填充选择器、品牌令牌审核工具和动效预设，全都构建在这同一个
插槽之上。有关如何构建扩展，请参阅[扩展](/docs/extensions)。
