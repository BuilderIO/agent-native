# Koyeb

<Badge label="Beta" color="orange" icon="rocket" />

Koyeb 会把你的应用作为 Web 服务托管，因此无需搭建或维护服务器。Koyeb 运行的是
[Node.js 指南](/docs/node-js)中介绍的同一个 Node.js 服务器，它会从你的 GitHub 仓库
构建应用，并为应用提供一个支持 HTTPS 的公共地址。

本指南将从零开始演示如何部署一个独立应用。你将创建应用并把它推送到 GitHub，
为它配置生产数据库和身份验证密钥，准备好数据库，然后创建一个负责构建和运行它的
Koyeb Web 服务。

<Callout tone="info">

需要 Node.js `22.22+`。

</Callout>

你还需要一个 Koyeb 账户和一个 GitHub 仓库。请在你自己的电脑上运行本指南中的命令。
Koyeb 会从你的仓库构建并运行应用。

## 第 1 步：创建应用 {#step-1-create-the-app}

创建新的独立应用。下面的示例基于 Chat 模板创建应用，但你可以从任何模板开始。
进入应用的文件夹并安装依赖。`corepack enable` 会启用应用所需的 `pnpm` 版本，
因此你无需自己安装 `pnpm`。

```bash
npx --yes @agent-native/core@latest create my-app --standalone --template chat

cd my-app

corepack enable

pnpm install
```

如果愿意，可以把 `my-app` 替换为你自己的应用名称。本指南的其余部分假定你位于
应用的文件夹中。

Koyeb 会从 GitHub 构建应用，因此在继续之前，请把应用的文件夹推送到一个新的 GitHub
仓库。也请提交 `pnpm-lock.yaml` 文件。Koyeb 会结合它和 `package.json` 中的
`packageManager` 字段，使用 `pnpm` 安装应用。它还会从 `package.json` 的 `engines`
字段读取 Node.js 版本。新应用已经设置了这两个字段。

## 第 2 步：配置环境密钥 {#step-2-configure-environment-secrets}

应用从环境变量中读取其生产设置：

| 变量                 | 必填 | 用途                                 |
| -------------------- | ---- | ------------------------------------ |
| `DATABASE_URL`       | 是   | 将应用连接到它的 PostgreSQL 数据库   |
| `BETTER_AUTH_SECRET` | 是   | 为用户会话签名                       |
| `BETTER_AUTH_URL`    | 否   | 设置用户访问你的应用时使用的公共地址 |

下面的 export 命令让后续命令能在当前 shell 中正常运行。部署之前，请把这些变量
同样保存到主机的项目或服务环境设置中。第 4 步会介绍如何在 Koyeb 中保存它们。

### 数据库 URL {#database-url}

在本地开发期间，如果未设置 `DATABASE_URL`，应用会把数据存储在本地数据库中。
已部署的应用需要一个真正的 PostgreSQL 数据库，在各次部署之间保留数据。Koyeb
会在每次部署和重启时替换服务的文件，因此数据库必须位于 Web 服务之外。从你的
提供商处复制连接字符串并导出它：

```bash
export DATABASE_URL='your-postgres-url-string'
```

[数据库提供商指南](/docs/neon)介绍了在每个提供商处查找连接字符串的位置。

<Callout tone="warning">

请选择持久的 PostgreSQL 提供商，例如 Neon、Supabase、Amazon RDS 等。

</Callout>

### 身份验证密钥 {#auth-secret}

只需生成一次，并在各次部署之间保持不变。

应用使用 `BETTER_AUTH_SECRET` 为用户会话签名。如果它发生变化，所有已登录的用户
都会被登出。下面的命令会生成一个随机值：

```bash
export BETTER_AUTH_SECRET="$(openssl rand -hex 32)"
```

请把生成的值保存在安全的地方，例如密码管理器。每次部署时都使用相同的值。

### 公共 URL {#public-url}

可选。在使用自定义域名、反向代理，或需要固定公共源的身份验证/OAuth 流程时设置它。

`BETTER_AUTH_URL` 是用户访问你的应用时使用的公共地址。如果不设置，应用会根据
每个传入请求推断自己的地址。在 Koyeb 为你提供的地址上，这通常没有问题，但当你
连接自定义域名时，请设置它，以便登录链接和 OAuth 重定向使用该域名。

```bash
export BETTER_AUTH_URL='https://your-domain.example'
```

## 第 3 步：迁移 {#step-3-migrate}

迁移会在你的数据库中创建和更新应用所需的表。请在首次部署之前运行此命令：

```bash
pnpm migrate:production
```

该命令在你的电脑上运行，并使用你在第 2 步中导出的 `DATABASE_URL` 连接到生产
数据库。升级应用之后、部署新版本之前，请再次运行它。

## 第 4 步：创建 Web 服务 {#step-4-create-the-web-service}

在 Koyeb 控制面板中，创建一个新的 **Web Service**，选择 **GitHub** 作为部署方式，
并选择第 1 步中的仓库和分支。保留 **Buildpack** 构建器，然后用以下值覆盖构建命令
和运行命令：

| 设置          | 值                              |
| ------------- | ------------------------------- |
| Build command | `NITRO_PRESET=koyeb pnpm build` |
| Run command   | `node .output/server/index.mjs` |

`NITRO_PRESET=koyeb` 会构建与 Node.js 指南中相同的 Node.js 服务器，并将其设置为
自行提供静态文件。运行命令会启动这个服务器。Koyeb 默认开放 `8000` 端口，并相应地
设置 `PORT` 环境变量，而服务器会自动读取 `PORT`，因此你无需更改端口设置。

在 **Environment variables** 下，添加 `DATABASE_URL` 和 `BETTER_AUTH_SECRET`。
对于这类值，Koyeb 建议把每个值存储为 **Secret**，并在变量中引用它。例如，把连接
字符串保存为名为 `DATABASE_URL` 的 Secret，然后把变量的值设置为
`{{ secret.DATABASE_URL }}`。如果你设置了 `BETTER_AUTH_URL`，请用同样的方式添加它。

## 第 5 步：部署 {#step-5-deploy}

<Steps>

### 选择实例类型

为 Web 服务选择实例类型。Free 实例类型适合试用应用。如果应用需要立即响应，请选择
付费实例类型。

### 创建 Web 服务

为服务和应用命名，然后部署。Koyeb 会从你的仓库构建应用并启动它。首次构建需要
几分钟，你可以在服务的构建日志和运行时日志中跟踪进度。

### 打开应用

部署完成后，控制面板会显示应用的地址，该地址以 `koyeb.app` 结尾。打开它并创建
第一个账户。

</Steps>

在 Free 实例类型上，如果服务一小时内没有流量，Koyeb 会将其缩减到零。之后的下一次
访问需要等待服务重新启动。每个组织可以运行一个 Free 实例。

## 部署更新 {#deploy-updates}

每次你推送到第 4 步中选择的分支时，Koyeb 都会重新部署。要发布新版本，请先运行
迁移，然后推送：

```bash
pnpm migrate:production

git push
```

服务设置和已保存的变量会保持不变，因此你无需重复第 4 步。
