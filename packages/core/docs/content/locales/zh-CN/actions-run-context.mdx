# 运行上下文

`run` 接受一个可选的第二个参数 `ctx`,携带解析后的请求身份,以及调用该 action 的界面。用它来代替手动调用 `getRequestUserEmail()` / `getRequestOrgId()`,并把整个 `ctx` 传给追踪逻辑:

```ts
export default defineAction({
  description: "Log an audit entry for the current request.",
  schema: z.object({ event: z.string() }),
  run: async (args, ctx) => {
    // ctx is undefined-safe: a 1-arg `run(args)` is still valid.
    const actor = ctx?.userEmail ?? "system";
    if (ctx?.caller === "frontend") {
      // tighter rules for browser-initiated calls, looser for "tool"/"cli"
    }
    await db.insert(audit).values({
      actor,
      orgId: ctx?.orgId ?? null,
      source: ctx?.caller ?? "unknown",
      event: args.event,
    });
    return { ok: true };
  },
});
```

大多数 action 只会读取 `ctx?.userEmail` 和 `ctx?.orgId`,这就是几乎每个真实 action 都会用到的[访问控制范围界定](/docs/actions-access-control#access-control)。本页剩下的内容涵盖追踪和自动化归因这类横切关注点,只有较少的 action 会用到它们。

## `ctx` 参数 {#ctx}

`ctx` 携带两类信息:几乎每次调用都存在的、解析后的请求身份(`userEmail`、`orgId`),以及关于调用该 action 的界面的元数据(`caller`,加上只对特定调用者才会填充的界面专属字段,比如 `threadId` 或 `automation`)。作为 `run()` 的第二个参数,它的完整形状是:

`run()` 保持向后兼容:已有的单参数处理函数,以及只解构 `{ send }` 的处理函数,都可以照常继续工作。

### `caller` 联合类型 {#caller}

`caller` 是联合类型 `"tool" | "http" | "frontend" | "cli" | "mcp" | "a2a" | "automation"`:

| `caller`       | 何时被设置…                                                                                                                                               |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `"tool"`       | 应用内代理循环、一个子代理或代理团队,或者驱动同一个代理循环的自然语言跨应用 A2A 委托,它们的工具调用都是 `"tool"`。                                        |
| `"frontend"`   | 通过 `useActionMutation()`、`useActionQuery()` 或 `callAction()` 发起的浏览器调用(带有 `X-Agent-Native-Frontend: 1` 请求头标记)。                         |
| `"http"`       | 对 `/_agent-native/actions/<name>` 发起的、没有前端标记的裸程序化 `POST` 或 `GET`。                                                                       |
| `"cli"`        | `pnpm action <name>`(CLI 运行器)。                                                                                                                        |
| `"mcp"`        | 外部代理通过 MCP 的 `tools/call` 端点发起的调用。                                                                                                         |
| `"a2a"`        | 携带一个签名的 A2A 委托令牌、直接发往 `/_agent-native/actions/<name>` 的 HTTP 调用。这是一次显式暴露的跨应用调用,不同于上面那种自然语言的 `"tool"` 路径。 |
| `"automation"` | 从一个已存储的工作区触发器分发出来的事件驱动自动化。`ctx.automation` 携带触发器的来龙去脉。参阅[自动化](/docs/automations)。                              |
