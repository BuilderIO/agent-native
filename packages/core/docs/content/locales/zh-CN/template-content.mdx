# Content

Content 是 MDX 的开源 Obsidian：一个对本地文件友好的文档工作区，代理可以在其中为你读取、写入、重新组织并发布页面。打开一篇文档，说“把这段改写得更简洁一些”，或者“创建一个名为第四季度规划的页面，并添加目标、指标和风险几个子页面”，无论是你自己动手，还是让代理来做，结果都是一样的。

## 它取代了什么

<Comparison>

### Before

- Obsidian，或者一个本地 Markdown 文件夹，用于记录私人笔记
- 一个独立的 Notion 工作区，用于团队共同浏览的文档
- 一个无头 CMS，用于发布到线上网站的任何内容
- 每当某一处内容落后时，需要在这三者之间手动复制内容

### After

- 一个工作区，同时容纳私人页面、团队文档和已发布的内容
- 同一份文档可以同步到本地文件、Notion 或 Builder CMS，而不必在每一处重新输入
- 代理通过与你相同的 actions 和相同的页面进行读写
- 来自外部来源的更改会生成一个可供审核的变更集，而不会被悄悄覆盖

</Comparison>

文档默认是私有的，提供查看者、编辑者和管理员三种共享角色，并可在需要公开时开启只读的公开模式。多个人（以及代理）可以同时编辑同一份页面，而不会互相覆盖对方的修改。关于这三者的详细说明，请参见[编写与组织文档](/docs/template-content-editing)、[数据库、属性与表单](/docs/template-content-databases)和[本地文件、Notion 与 Builder CMS 同步](/docs/template-content-sync)。

## 开始使用 {#get-started}

```bash
npx @agent-native/core@latest create my-content --standalone --template content
```

如需了解安装、首次运行和连接 LLM 的详细说明，请参见[Content：开发者指南](/docs/template-content-developers#quick-start)。

打开应用后，点击侧边栏中的 **+ 新建页面**，为它取一个标题，然后开始写作；或者直接让代理来做：

- “创建一个名为 Onboarding 的页面，并在下面添加三个子页面。”
- “把这段文字改写得更简洁一些。”（打开页面时）
- “从 Notion 拉取最新内容。”（链接 Notion 页面后）

选中文字并按 Cmd+I，可以让代理聚焦在这段已预先加载的选中内容上——这样一来，“让这段更有力”这样的指令就会精确作用于你选中的内容。
