# 嵌入剪辑

把托管的剪辑用作你产品的录制后端。一个人可以在一个 iframe 中进行录制，而不需要登录剪辑。你的后端使用一个组织服务令牌来创建一个短期有效的接入 URL，剪辑会把生成的录制内容存储到该组织配置好的存储中。

本指南介绍的是托管的嵌入流程。它不要求进行录制的人拥有一个剪辑账户。

## 集成是如何运作的

这个集成分为四个部分：

1. 一位组织管理员在剪辑中配置视频存储。
2. 你的后端存储组织服务令牌，并请求一个接入 URL。
3. 你的产品只把这个短期有效的接入 URL 传给一个 iframe。
4. 剪辑把录制内容上传到该组织的存储中，并向你的产品发送一条完成消息。

组织服务令牌永远不应该出现在 iframe 中。它绑定到生成它的那个组织，因此令牌本身就提供了组织上下文。一个组织 ID 对你自己的租户映射很有用，但它本身并不是一个凭证。

## 配置剪辑组织

创建或选择应该拥有这些录制内容的剪辑组织。然后由一位组织管理员通过剪辑的引导流程或剪辑设置来配置视频存储：

- **Builder.io Connect** 提供托管的视频存储和 AI 额度。
- **S3 兼容存储**使用该组织配置的端点、bucket、access key、secret key，以及可选的 region 或公共基础 URL。Cloudflare R2 和 DigitalOcean Spaces 使用同样的存储设置，只是用各自提供方特定的名称。

存储配置是按组织划分范围的。通过该组织的服务令牌创建的每一段录制内容，都会使用已经连接到该组织的存储。嵌入方的产品不需要 Builder.io 或 S3 的凭证。

视频存储在配置好的对象存储中。剪辑会把录制内容的元数据、归属关系、处理状态和存储引用保存在它自己的数据库中。

## 创建一个组织服务令牌

以组织所有者或管理员的身份运行现有的 `connect` 命令。该命令会打开一个浏览器登录页面，为当前活跃的组织创建一个具名的服务令牌，并把令牌打印出来一次：

```bash
npx @agent-native/core@latest connect https://clips.agent-native.com \
  --service-token support-desk --ttl-days 365
```

把打印出来的令牌直接复制到你产品的服务器端密钥管理器中。该令牌归属于组织，因此即使生成它的那个人离开了组织，或撤销了自己的个人令牌，它仍会继续有效。它永远不会被写入本地客户端配置。为每个集成使用一个不同的服务名称，这样撤销一个调用方就不会影响到另一个。

`--ttl-days` 接受 1 到 365 天，默认值为 365。该令牌的行为如同一位组织成员。它不能创建或撤销其他服务令牌，也不能更改组织设置。

## 请求一个接入 URL

你受信任的后端会调用剪辑的接入 action。托管账户请使用托管剪辑的源，自托管时请使用你自己的剪辑源。

```ts
const clipsBaseUrl = "https://clips.agent-native.com";
const clipsServiceToken = process.env.CLIPS_SERVICE_TOKEN;

const response = await fetch(
  `${clipsBaseUrl}/_agent-native/actions/create-recording-intake-link`,
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${clipsServiceToken}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      ttlSeconds: 3600,
    }),
  },
);

if (!response.ok) {
  throw new Error("Could not create a Clips intake URL");
}

const intake = await response.json();
// intake.url is safe to pass to the recording iframe.
```

服务令牌中签名的组织上下文决定了哪个组织拥有这个接入。该 action 的响应在顶层就是这个接入对象。默认的接入有效期是一小时，最长为四小时。每个接入 URL 只能创建一段录制内容。

不要从一个匿名浏览器发起这个请求。不要把服务令牌、存储凭证，或一个长期有效的剪辑会话返回给浏览器。

## 嵌入录制工具

把返回的 URL 直接传给一个 iframe。这个 URL 包含了一个范围狭窄、经过签名的能力，让访客可以创建并上传一段私密的录制内容。

```tsx
<iframe
  data-clips-recorder
  src={intake.url}
  allow="display-capture; camera; microphone"
  title="Report a problem"
  style={{ width: 420, height: 560, border: 0 }}
/>
```

在渲染这个接入 URL 之前，你可以为它添加一些小型、非敏感的上下文值，比如项目 ID、页面标题、应用版本，或环境。不要把密码、API 密钥、客户记录，或其他敏感值放进这个 URL 中。URL 可能会出现在浏览器历史记录、日志、分析工具和引荐来源中。

当访客开始捕获时，录制工具会打开一个顶层弹出窗口。浏览器的媒体权限和屏幕捕获要求在一个顶层浏览上下文中有一次用户手势。测试期间请为宿主产品允许弹出窗口。

## 接收完成消息

当录制内容保存完成后，完成页面会向嵌入方的父窗口发送一条 `agent-native.clips.bug-report.submitted` 消息。在使用这个负载之前，请先验证剪辑的源和消息来源。

```ts
const clipsOrigin = new URL(clipsBaseUrl).origin;
const recorderFrame = document.querySelector<HTMLIFrameElement>(
  "iframe[data-clips-recorder]",
);

window.addEventListener("message", (event) => {
  if (event.origin !== clipsOrigin) return;
  if (recorderFrame && event.source !== recorderFrame.contentWindow) return;
  if (event.data?.type !== "agent-native.clips.bug-report.submitted") return;

  const { recordingId, recordingUrl, embedUrl, agentAccessStatus } = event.data;
  if (!recordingId) return;

  // Send recordingId to your trusted backend and attach it to the support case.
  console.log({ recordingId, recordingUrl, embedUrl, agentAccessStatus });
});
```

完成负载可以包含 `recordingId`、`recordingUrl`、`embedUrl`、`agentShareUrl`、`agentContextUrl`、`agentAccessExpiresAt` 和 `agentAccessStatus`。把 `recordingId` 当作这个支持工单的持久标识符。一个只写的接入在你经过身份验证的后端创建一个单独的限定范围代理链接之前，可能会报告 `agentAccessStatus: "unavailable"`。这个状态并不意味着这段录制内容是空的。

这个浏览器消息只是一个通知，不是一个授权凭证。当你的后端需要读取或分享这段已完成的录制内容时，应该使用它自己经过身份验证的剪辑连接。

## 录制内容存储在哪里

通过服务令牌创建的录制内容，归属于该令牌关联的组织。剪辑会通过它常规的上传和终结流水线来处理这些媒体。这个流水线使用为该组织配置的 Builder.io 或 S3 兼容存储。

这个 iframe 不会直接上传到你的 bucket，也不需要 bucket 凭证。你的产品会从剪辑那里收到录制内容标识符和限定范围的 URL。只需要在你自己的支持系统中存储你需要的标识符或 URL。

## 自托管剪辑

自托管使用相同的组织契约：

1. 部署剪辑，配备一个持久化数据库和一个公开的 `BETTER_AUTH_URL`。
2. 创建将拥有这些嵌入式录制内容的组织。
3. 在该组织中一次性配置好 Builder.io Connect 或 S3 兼容存储。
4. 针对自托管的剪辑源运行 `connect`，创建该组织的服务令牌。
5. 把该令牌以部署值或密钥管理器值的形式，一次性提供给你的嵌入后端。
6. 当你的后端请求接入 URL 时，使用自托管的剪辑源。

```bash
npx @agent-native/core@latest connect https://clips.example.com \
  --service-token support-desk --ttl-days 365
```

例如，嵌入方的后端可以把这些值保存在它的服务器端配置中：

```text
CLIPS_BASE_URL=https://clips.example.com
CLIPS_SERVICE_TOKEN=<secret>
```

该令牌只需一次性提供给后端。每个访客仍然会收到一个新的短期有效接入 URL。iframe 中不会添加任何令牌或存储凭证，并且在令牌轮换时，也不需要修改任何 iframe 代码。

有关一般的自托管要求，请参阅[部署](/docs/deployment)。

## 安全检查清单

- 把组织服务令牌保存在一个服务器端密钥管理器中。
- 宿主产品和剪辑都使用 HTTPS。
- 把每个接入 URL 都当作一个持有者凭证。让它远离日志和引荐来源数据。
- 使用能满足需求的最短接入有效期。
- 在完成消息的监听器中，同时验证 `event.origin` 和 `event.source`。
- 永远不要把剪辑中所有者范围的上传端点直接暴露给匿名用户。
- 通过用 `connect` 创建一个替代令牌来轮换服务令牌，部署它，验证流程，然后用 `revoke-org-service-token` 撤销旧令牌。
- 把组织 ID 和接入 ID 留在受信任的后端，而不要相信访客提供的值。

## 故障排查

**接入请求未获授权。** 确认后端使用的是一个未过期、未被撤销、并且是为目标剪辑源生成的服务令牌。令牌的组织绑定决定了接入会在哪里被创建。

**iframe 打开了一个登录页面。** 确保这个 iframe 使用的是 `create-recording-intake-link` 返回的短期有效 URL。不要为一个匿名访客嵌入 `/record` 或一个普通的剪辑库 URL。

**录制没有完成。** 检查该组织是否已经配置了 Builder.io 或 S3 兼容存储。一个匿名访客无法从 iframe 中配置存储。

**完成结果中没有代理链接。** 对于一个只写的接入来说，这是预期行为。如果支持工作流需要代理可读的转录文本和帧数据，请让你经过身份验证的后端创建一个单独的限定范围代理链接。
