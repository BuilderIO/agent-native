# 定义 Actions

每个 action 都从一次 `defineAction()` 调用开始。它把面向代理的 description、用于校验输入的 schema,以及执行实际工作的 `run` 函数打包在一起,所以 UI 和代理调用的是完全相同的代码。

## Schema 选项 {#schemas}

`schema` 接受任何兼容 [Standard Schema](https://standardschema.dev) 的库:

- **Zod**(v4):最常见的选择,拥有最好的类型推断,并能自动转换为 JSON Schema。
- **Valibot**:当包体积是关键考量时的不错选择。
- **ArkType**:如果你偏好它的语法,这是个不错的选择。

这份 schema 承担两项职责。它会转换为供 Claude API 工具定义使用的 JSON Schema,并在 `run()` 触发前对运行时输入进行校验。无效输入永远不会到达你的处理函数。

## 校验返回值 {#output-schema}

`schema` 校验的是*输入*。要同时校验一个 action **返回**的内容,传入一个 `outputSchema`(任何兼容 Standard Schema 的 schema:Zod、Valibot、ArkType,与 `schema` 相同的接口)。框架会在 `run()` 之前校验输入,并在 `run()` 解析完成之后校验结果。

```ts
export default defineAction({
  description: "Summarize a thread.",
  schema: z.object({ threadId: z.string() }),
  outputSchema: z.object({
    summary: z.string(),
    messageCount: z.number(),
  }),
  outputErrorStrategy: "warn", // default
  run: async ({ threadId }) => {
    /* ...returns { summary, messageCount } ... */
  },
});
```

`outputErrorStrategy` 控制不匹配时会发生什么:

| 策略         | 不匹配时的行为                                                                |
| ------------ | ----------------------------------------------------------------------------- |
| `"warn"`     | **默认值。**用 `console.warn` 记录问题,并原样返回**原始**结果。不会中断运行。 |
| `"strict"`   | 抛出一个明确的错误,让 action 中的 bug 容易被发现。                            |
| `"fallback"` | 返回提供的 `outputFallback` 值,代替无效的结果。                               |

当 `run()` 成功时,框架会返回校验后的值,所以 `outputSchema` 上的任何默认值或类型转换都会生效,和输入的处理方式一样。如果你没有传入 `outputSchema`,返回值不会有任何变化。

## HTTP 配置 {#http}

默认情况下,每个 action 都会以 `POST /_agent-native/actions/<name>` 的形式暴露。用 `http` 选项覆盖它:

```ts
export default defineAction({
  description: "Get details for a lead.",
  schema: z.object({ leadId: z.string() }),
  http: { method: "GET" },
  run: async ({ leadId }) => {
    return await db.select().from(leads).where(eq(leads.id, leadId));
  },
});
```

对于 `GET` action,`leadId` 会作为查询参数传入:`/_agent-native/actions/get-lead?leadId=abc`。

POST 是默认方法,`http: { method: "GET" }` 会让它变成 GET。React 钩子和 `callAction()` 总是按名称调用这个路径,不受任何 `http.path` 覆盖的影响。外部系统可以用一个长期有效的 bearer token 调用同一个路由。参阅 [HTTP API](/docs/http-api)。

</Endpoint>

- **`http: { method: "GET" | "POST" | "PUT" | "DELETE" }`**:默认为 `POST`。`GET` action 会被自动标记为 `readOnly`,因此一次成功的调用不会触发 UI 的轮询刷新。
- **`http: { path: "..." }`**:覆盖挂载在 `/_agent-native/actions/` 下的 URL。它默认为文件名。这个覆盖只会改变直接 HTTP 调用者所使用的 URL。`useActionQuery()`、`useActionMutation()` 和 `callAction()` 始终调用 `/_agent-native/actions/<name>`,不受这个覆盖的影响,所以覆盖路径会让这些钩子返回 404。只在面向外部 HTTP 调用者时才使用路径覆盖。另外要注意,覆盖路径中的 `:param` 路由片段不会被解析进 `run()` 的参数,只有查询字符串参数和 JSON 请求体字段才会。
- **`http: false`**:彻底禁用 HTTP 端点。只有代理和 CLI 可以调用该 action。
- **`readOnly: true`**:显式跳过轮询刷新,即便是那些实际上不做任何变更的 POST action 也一样。这不是访问控制。它不限制谁可以调用该 action,也不影响 `useActionQuery()`、`useActionMutation()` 或任何客户端钩子。它唯一的效果是抑制调用后的刷新事件,并让该 action 不参与写入审计。要在模型面前隐藏一个 action,使用 `agentTool: false`。要限制谁可以调用它,使用 [访问与授权](/docs/actions-access-control) 中的鉴权和访问选项。
- **`parallelSafe: true`**:允许一个变更类 action 与同一轮次里的其他工具调用同时运行。只有在该 action 确实可以安全并发、且不依赖调用顺序时才设置它。变更类 action 默认是串行执行的。

## 让 action 界面保持精简 {#small-surface}

代理能看到的每一个 action,都会占用模型工具列表中的一个位置,而一份又长又重叠的列表会让模型更难选对工具。把 action 界面当作一套你在维护的 API 来设计,而不是 UI 里每个按钮配一个 action:

- 优先选择**一个 CRUD 风格的 `update` action**,它接受一份包含可选字段的补丁,而不是 `update-name`、`update-order`、`update-color` 这样按字段拆分的许多 action。调用者只需要发送发生变化的字段。
- 在为每一种查询或过滤条件新增一个读取类 action 之前,先考虑更通用的方案:面向 provider 数据的 [provider API 三件套](/docs/template-dispatch-vault-integrations#provider-api)(`provider-api-catalog`、`provider-api-docs` 和 `provider-api-request`),或者面向应用数据的开发用 `db-query` 工具。
- 把仅供 UI 使用或程序化调用的 action 标记为 [`agentTool: false`](/docs/actions-access-control#agent-tool)。它们仍然可以从前端或通过 HTTP 调用,但不会占用模型工具列表中的位置。
- 删除或隐藏 UI 已经不再使用的 action,而不是继续把它们暴露给模型。

仓库内置了一个仅供参考的辅助工具 `node scripts/audit-template-actions.mjs [template ...]`(别名 `pnpm actions:audit`)。它会扫描某个模板的 `actions/` 文件夹,标记出 UI 可能已经不再使用的 action,以及那些可以合并为一个的、按字段拆分的 action 组。它总是以退出码 0 结束,从不会让 CI 失败,而且它的启发式规则是保守的,所以请把它的输出当作建议,而不是错误。
