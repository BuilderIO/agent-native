# 公共代理网络

公共代理网络使公共 Agent-Native 路由易于代理抓取、阅读、引用和调用。目标不是公开每个应用程序端点。目标是为已经公开的页面发布一个干净的公共界面，同时将私有数据和工具访问保留在显式控制之下。

文档站点是参考实现。今天发货：

- `/robots.txt` 的爬虫策略默认允许检索但不允许训练。
- `/sitemap.xml` 作为站点地图索引，为每个语言区域指向一个 `/sitemap-<locale>.xml`；当源文件公开它时，具有绝对规范的 URL 和 `lastmod`。
- `/llms.txt` 和 `/llms-full.txt` 用于代理友好的内容发现。
- Markdown 镜像，例如 `/docs/getting-started.md`。
- 生产构建后公共文档页面的 `Accept: text/markdown` 响应。
- JSON-LD 用于基础组织、网站和页面元数据。
- 审核 CLI (`npx @agent-native/core@latest audit-agent-web`)，检查上述所有内容。

发布这些文件永远不会公开任何操作。操作只能通过自己的 `publicAgent` 选择加入才能被外部代理访问；参见[对公共代理暴露](/docs/actions-access-control#public-agent)。

## 配置 {#config}

`@agent-native/core/vite` 中的 `createAgentWebVitePlugin` 会在生产构建期间写出这些文件。把它连同代理应读取的页面一起加入你的 Vite 配置：

```ts
// vite.config.ts
import { createAgentWebVitePlugin } from "@agent-native/core/vite";

export default defineConfig({
  plugins: [
    // ...your existing plugins
    createAgentWebVitePlugin({
      siteName: "My Agent-Native App",
      siteUrl: "https://example.com",
      pages: [
        {
          path: "/pricing",
          title: "Pricing",
          description: "Plans and limits.",
          markdown: "Plans and limits.\n",
        },
      ],
      agentWeb: { crawlerPolicy: "discoverable-no-training" },
    }),
  ],
});
```

插件只发布你列出的页面，不会发布其他内容。它不会读取你的路由访问设置；除非你传入，它也不会读取 `package.json` 中的 `agentWeb`。要把设置保留在 `package.json` 的 `agent-native.workspaceApp.agentWeb` 下，请传入 `agentWeb: agentWebConfigFromPackageJson(pkg)`，它从 `@agent-native/core/agent-web` 导入。

| 选项            | 默认值                       | 作用                                                                                                                              |
| --------------- | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `discoverable`  | `pages` 非空时开启           | 设为 `false` 时不写出任何文件。                                                                                                   |
| `llmsTxt`       | `true`                       | 写出 `/llms.txt` 和 `/llms-full.txt`。                                                                                            |
| `markdownTwins` | `true`                       | 为每个带有 `markdown` 的页面写出一份 `.md` 副本。                                                                                 |
| `crawlerPolicy` | `"discoverable-no-training"` | 设置 `robots.txt` 规则：`"discoverable-no-training"`、`"allow-all"` 或 `"disallow-all"`。                                         |
| `crawlers`      | 无                           | 单独覆盖一类爬虫：`training`、`search`、`userTriggered`、`codingAgents` 或 `autonomousAgents`，每类取 `"allow"` 或 `"disallow"`。 |

默认爬虫策略是“可发现，不可训练”：允许搜索、用户触发的检索、编码代理和自主浏览代理；不允许训练爬虫。

`jsonLd`、`publicAgentCard` 和 `publicMcp` 会被接受，但目前没有任何代码读取它们。如需 JSON-LD，请自己把 `@agent-native/core/agent-web` 中的 `buildBaseJsonLd` 和 `buildPageJsonLd` 渲染到页面中。

## 路由真相来源 {#route-source}

页面列表就是事实来源：代理只会得到你传入的页面。请用已经公开的页面来构建它：

- 在公共应用中，除 `protectedPaths` 之外的所有路由。
- 在内部应用中，只有 `publicPaths`。
- 代理应能读取的公开分享页和表单页。
- 绝不包含提交的私有数据、需要认证的仪表板或用户/组织状态，即使附近的页面是公开的。

要从访问设置出发，`@agent-native/core/agent-web` 中的 `deriveAgentWebPublicRoutes` 接收应用的 `audience`、`publicPaths`、`protectedPaths` 和 `routes`，并返回这些设置公开的路由。每个页面仍需要自己的标题和 Markdown。

这使混合应用程序保持自然。表单应用程序可以公开公共表单页面并保持提交的私密性。内容应用程序可以公开已发布的帖子并保持编辑者的私密性。文档网站可以公开除管理工具之外的所有内容。

## 公共页面不是公共工具 {#public-tools}

公共页面访问和公共工具访问是分开的。路线仅公开意味着代理可以将该路线读取为 HTML、Markdown、站点地图条目、llms 条目和结构化数据。

<Callout id="doc-block-s50w8y" tone="warning">

**公共页面不是公共工具。** 让路由可被爬取永远不会公开任何操作。工具访问需要在操作上明确选择加入 `publicAgent.expose`。

</Callout>

要通过公共代理协议公开操作，该操作必须选择加入：

## 构建时文件 {#build-time}

`@agent-native/core/agent-web` 中的框架实用程序从一页列表生成通用文件：

```ts
import {
  buildAgentWebStaticFiles,
  normalizeAgentWebConfig,
} from "@agent-native/core/agent-web";

const config = normalizeAgentWebConfig(
  { crawlerPolicy: "discoverable-no-training" },
  { hasPublicRoutes: true },
);

const files = buildAgentWebStaticFiles({
  siteName: "My Agent-Native App",
  siteUrl: "https://example.com",
  description: "Public docs for my app.",
  config,
  pages: [
    {
      path: "/docs",
      title: "Docs",
      description: "Start here.",
      markdown: "# 文档\n\n从这里开始。\n",
      markdownPath: "/docs/getting-started.md",
      lastmod: new Date(),
    },
  ],
});
```

`createAgentWebVitePlugin` 会替你调用 `buildAgentWebStaticFiles`，并把文件写入 `public`、`dist`、`dist/client`、`dist/server/public` 和 `build/client` 中实际存在的目录。使用其他构建工具时，请直接调用这些工具函数。

两者都不会在页面自身的 URL 上响应 `Accept: text/markdown`：Markdown 副本只在它的 `.md` URL 上。要响应这个请求头，请像文档站点那样添加一个服务器路由，用 `buildMarkdownResponseHeaders` 的响应头返回页面的 Markdown。没有这个路由，下面的审计会在 `Accept: text/markdown` 检查上失败。

向 `buildAgentWebStaticFiles` 或 `createAgentWebVitePlugin` 传入 `sitemapGroup` 即可拆分大型站点地图。它将每个页面映射到一个分组键（例如语言区域），`sitemap.xml` 随即成为站点地图索引，每个分组对应一个 `sitemap-<group>.xml`。

## 审核网站 {#audit}

对已部署站点或本地生产服务器使用 CLI 审核：

```bash
npx @agent-native/core@latest audit-agent-web --url https://www.agent-native.com
```

审核检查：

- SSR-可见HTML。
- 规范 URL。
- JSON-LD。
- `robots.txt` 政策和绝对站点地图 URL。
- 绝对站点地图条目。
- `/llms.txt` 和 `/llms-full.txt`。
- Markdown 镜子。
- `Accept: text/markdown`.
- 公共代理检索用户代理不会出现意外的 401/403 阻塞。

如果缺少所需的公共表面，审核将以非零值退出。
