# 隐私与数据权利

Agent-Native 在默认的账户设置中提供隐私请求界面。已登录的用户可以请求获取个人数据副本，或请求删除个人数据。

这是实现基线，不是法律建议或合规认证。运营应用的组织需要确定自身的法律角色，并发布适合其部署的通知和流程。

## 用户可以做什么

打开 **设置 > 账户 > 安全**，在 **您的数据** 分组中可以：

- 请求个人数据副本，用于访问或可携带性审查；
- 请求删除个人数据，用于删除审查；
- 通过现有的个人资料和电子邮件控件更正账户信息。

请求会持久保存、幂等处理并接受审计。请求操作只保存请求类型、状态和时间戳。它不会返回数据转储，不接受其他人的电子邮件或用户 ID，也不会立即删除数据。

## 代理无法做什么

隐私请求通过账户设置界面提交。`request-privacy-right` 已进行身份验证，不会出现在代理工具和 MCP/A2A 发现中，会被工具桥接阻止，并且只允许前端调用方使用。

核心 `offboard-member` 操作也具有相同的 UI-only 边界。移除成员是组织级操作，会转移其拥有的行并撤销访问权限，并不等同于删除账户。删除组织也仍然需要所有者在界面中确认。

人工审批提示不是安全边界。对于会删除数据、撤销身份、修改成员资格或认证的自定义操作，请使用明确的 UI-only 边界，并从经过验证的请求上下文中获取身份。

## 运营方履行请求

框架会记录请求。部署运营方必须：

1. 验证请求者身份，并确定适用的组织和法律范围；
2. 收集部署所控制的数据，通过私密且受访问控制的渠道交付；
3. 删除或匿名化应用行和私有文件，在适当时撤销会话和凭据，并与连接的提供方和处理方协调；
4. 对备份、安全与审计日志、欺诈防护记录及已记录的例外应用保留计划；
5. 记录完成、部分履行或阻塞原因，并向请求者告知结果。

不要因为删除了一个组织行或一个设置，就声称请求已完成。托管提供方、上传文件、连接的服务、缓存、备份和不可变审计记录可能有独立的保留和删除路径。

## 默认隐私状态

新的可共享资源默认是私有的。浏览器分析默认关闭 DOM 和网络自动采集；如果配置了会话回放，它默认是选择加入且仅限已登录用户。这些默认设置不能替代隐私通知、合法依据分析、保留政策或同意和退出控制。

如果部署会出售或共享个人信息，则必须提供适用的 CCPA 退出机制并处理 Global Privacy Control。框架不会为应用创建出售或共享计划。

## 部署清单

- 发布隐私通知，说明数据类别、用途、接收方、保留期限、权利和联系渠道。
- 确定并记录合法依据、同意要求、敏感数据限制和年龄要求。
- 为访问、更正、删除、可携带性、反对和退出请求指定负责人和流程。
- 梳理每个应用表、私有文件、分析提供方、连接服务、邮件系统、缓存、日志、备份和子处理方。
- 定义身份验证、响应期限、保留例外、删除证据和申诉处理。
- 让高影响操作仅能从 UI 发起，并测试代理、MCP、A2A、CLI、HTTP 和工具 iframe 调用方无法执行。
