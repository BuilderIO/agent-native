# 数据与同步

从客户端应用读取和写入应用数据的主要方式是通过 [action](/docs/actions-overview) 钩子。通过将请求封装进 actions，您的客户端和代理都能以相同的方式与应用交互。

在下面的示例中，一个工单先通过下拉菜单手动分配给当前用户，然后再通过聊天代理分配。UI 和代理访问的是同一个 action。

### Action 钩子 {#action-hooks}

您最可能用到的两个 action 钩子是：`useActionQuery()` 和 `useActionMutation()`。这两个钩子提供对您应用中 actions 的访问。

#### useActionQuery {#use-action-query}

<Signature
  id="doc-block-client-data-1"
  name="useActionQuery"
  params={[
    {
      name: "actionName",
      type: "TName",
      description: "该 action 注册时使用的名称。",
    },
    {
      name: "params",
      type: "ActionParams<TName>",
      optional: true,
      description: "该 action 的输入，类型来自其 `defineAction()` schema。",
    },
    {
      name: "options",
      type: "UseQueryOptions",
      optional: true,
      description:
        "[useQuery 选项](https://tanstack.com/query/latest/docs/framework/react/reference/useQuery) 中除 `queryKey` 和 `queryFn`（由该钩子自行设置）之外的所有内容。",
    },
  ]}
  returns={{
    type: "UseQueryResult<TResult>",
    description:
      '缓存于 `["action", name, params]` 下。每当有变更类 action 完成时会自动重新获取，无需手动失效。',
  }}
/>

该钩子用于只读 actions，是围绕 [useQuery()](https://tanstack.com/query/latest/docs/framework/react/reference/useQuery) 函数的一层轻量封装。

在下面的示例中，调用了 `list-tickets` action，这类似于对所有工单发起一次 GET 请求。

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery("list-tickets", {});
```

下面的示例展示了通过 `get-ticket` action 获取单个工单的请求。提供 `ticketId` 用于将查询限定为只返回特定工单。额外提供的 `enabled` 选项确保该查询不会自动运行，而是只在存在 `ticketId` 时才运行。

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery(
  "get-ticket",
  { ticketId: ticketId ?? "" },
  { enabled: Boolean(ticketId) },
);
```

#### useActionMutation {#use-action-mutation}

<Signature

    },
    {
      name: "options",

      optional: true,
      description:
        "[useMutation 选项](https://tanstack.com/query/latest/docs/framework/react/reference/useMutation) 中除 `mutationFn`（由该钩子自行设置）之外的所有内容。",
      fields: [
        {
          name: "method",
          type: '"POST" | "PUT" | "DELETE"',
          optional: true,
          default: '"POST"',
          description: "覆盖默认的请求方法。",
        },
        {
          name: "skipActionQueryInvalidation",
          type: "boolean",
          optional: true,
          default: "false",

        },
      ],
    },
  ]}
  returns={{
    type: "UseMutationResult",
    description:
      '成功后会发出一个 `source: "action"` 的变更事件，因此每个读取了受影响数据的 `useActionQuery()` 都会自动重新获取，无需手动失效。',
  }}
/>

该钩子用于会改变数据的 actions，例如创建、更新或发送某些内容，是围绕 [useMutation()](https://tanstack.com/query/latest/docs/framework/react/reference/useMutation) 函数的一层轻量封装。

与 `useActionQuery()` 不同，action 的输入不会传给钩子本身，而是在您准备运行该变更时传给 `mutate()` 或 `mutateAsync()`。

在下面的示例中，调用 `send-ticket-reply` action 来为工单发布一条回复。从事件处理函数（例如按钮的 `onClick`）中调用 `mutate()`。

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply");

mutate({ ticketId, body: draft });
```

下面的示例展示了带有 `onSuccess` 选项的同一个变更。每次变更后缓存失效都会自动发生，所以 `onSuccess` 只在需要处理本地副作用时才用到，例如回复发送后清空回复输入框。

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply", {
  onSuccess: () => setDraft(""),
});

mutate({ ticketId, body: draft });
```

### callAction {#call-action}

<Signature

    {

            "覆盖默认的 60 秒超时，用于那些确实需要更长时间的 actions。",
        },
      ],
    },
  ]}
  returns={{
    type: "Promise<TResult>",
    description:
      "与上面的钩子不同，这里没有缓存也没有自动重新获取。如果其他 UI 依赖该结果，请配合手动失效一起使用。",
  }}
/>

该函数用于 React 渲染流程之外的一次性命令式 action 调用，例如普通的事件处理函数、脚本，或任何其他非 React 代码路径。它直接返回一个 promise，而不是一个钩子结果。

在下面的示例中，`update-ticket` action 在 React 渲染流程之外，从一个键盘快捷键处理函数中被调用，将工单分配给一名客服。

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction("update-ticket", {
  ticketId,
  assignedToEmail: "jordan@example.com",
});
```

下面的示例展示了带有 `timeoutMs` 选项的同一个调用，适用于那些确实需要比默认 60 秒超时更长时间的 actions。

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction(
  "update-ticket",
  { ticketId, assignedToEmail: "jordan@example.com" },
  { timeoutMs: 120_000 },
);
```

每个 `useActionQuery()`、`useActionMutation()` 和 `callAction()` 请求都受 60 秒超时限制，超时会以错误的形式呈现，而不会静默重试。`useActionQuery()` 还会使用 React Query 的 abort signal 自动取消被替代的请求。

        },

  returns={{ type: "void" }}

该钩子用于让 UI 与发生在您自己的 actions 之外的数据库变更保持同步，例如代理写入、webhook，或来自另一个浏览器标签页的变更。它通过 server-sent events 监听变更，在 server-sent events 不可用时回退到轮询。

```ts
import { useDbSync } from "@agent-native/core/client/hooks";
import { useQueryClient } from "@tanstack/react-query";

function App() {
  const queryClient = useQueryClient();

  useDbSync({
    queryClient,
    pollUrl: "/_agent-native/poll",
    onEvent: (data) => console.log("Data changed:", data),
  });

  return <div>...</div>;
}
```

对于普通的 CRUD，优先使用 `useActionQuery()` 和 `useActionMutation()`。变更类 actions 会发出 `source: "action"`，因此这些钩子会立即重新获取。来自代理、webhook 或另一个标签页的变更，则是通过 `useDbSync()`（经由 SSE 或轮询回退）到达的。如果某个原始 `useQuery()` 调用需要基于自定义 key 同步，见 [同步内部机制](/docs/client-sync-internals)。如果您需要直接写入 `application_state`，见 [高级](/docs/client-advanced)。
