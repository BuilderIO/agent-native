# 转换为应用

`/turn-into-app` 是一个 skill，可将你已验证的工作流转换为 Agent-Native 应用。来源可以是对话、skill、电子表格，或 Claude 或 ChatGPT 项目。应用会在你的业务场景中打开，填充了与来源结构一致的示例数据，应用内的智能体在其操作对象的控件背后工作。步骤条下方的一个表单，正是该 skill 想要避免的结果。

## 安装 {#install}

```bash
npx @agent-native/skills@latest add --skill turn-into-app
```

同一个 skill 也随核心 CLI 一起提供：

```bash
npx @agent-native/core@latest skills add turn-into-app
```

在已有 Agent-Native CLI 的项目中，`agent-native skills add turn-into-app` 的效果相同。有关 skills 的安装和加载方式，请参阅 [Skills 指南](/docs/skills-guide)。

## 调用方式 {#invoke}

| 命令                               | 来源                                       |
| ---------------------------------- | ------------------------------------------ |
| `/turn-into-app`                   | 可见的项目上下文，否则为当前对话           |
| `/turn-into-app /some-skill`       | 指定的 skill，即使在对话开始时也会立即打包 |
| `/turn-into-app ./forecast.xlsx`   | 电子表格，转换为工作台                     |
| `/turn-into-app ./project-export/` | Claude 或 ChatGPT 项目导出                 |

不带参数时，skill 会构建最近一次成功且可重复的工作，并为其命名。具体的示例，例如某个账户或某笔交易，只是该工作的佐证，而不是它的数据结构。如果无法确定任何工作，它会说明缺少什么，而不是提出"你想要什么应用？"这类泛泛的问题。

## 运行位置 {#hosts}

| 宿主                                            | 发生的事情                                                                         |
| ----------------------------------------------- | ---------------------------------------------------------------------------------- |
| Claude Code、Codex、Cursor 及其他本地编码智能体 | 在你的检出目录中构建、运行并审查应用。                                             |
| 网页版 Claude 或 ChatGPT                        | 编写一份范围明确的简报，并通过 Dispatch 连接器交给 Builder。它自己不运行任何内容。 |

当宿主具有真实的工作目录、终端和工作区时，才算本地宿主。拥有 Builder 或 Dispatch 连接器并不会使宿主成为浏览器宿主。

在浏览器宿主上，skill 需要 Agent-Native Dispatch MCP 连接器（`https://dispatch.agent-native.com/mcp`，OAuth），并调用其 `start-workspace-app-creation` 操作。宿主无法运行或检查应用，因此在 Dispatch 返回的分支构建完成之前，报告会保持待处理或未验证状态。skill 只报告 Dispatch 实际返回的内容，绝不编造分支 URL。对于 ChatGPT 项目，或任何仅暴露 MCP 的宿主，请将 skill 指令放入项目指令或知识文件中。

## 来源 {#sources}

- **对话。** 最近一次具体且可重复的工作就是产品。
- **Skills。** skill 的步骤、需要人工决策的节点和只读规则会成为应用。如果 skill 保留了计划文件，这些文件将通过 Local File Mode 继续作为事实来源，且应用仅限本地。
- **电子表格。** 先盘点每个工作表。由结构决定哪些单元格是输入、哪些是输出；颜色只是一个较弱的提示。工作簿绝不会被复制到提示词、SQL 或应用状态中。只有可通过已认证的 Sheets 或 Drive 连接读取时，Google Sheets 链接才算来源；否则 skill 会要求提供导出文件。
- **Claude 和 ChatGPT 项目。** 可见的指令、知识文件以及提供的过往运行记录是来源。连接器不会读取隐藏的项目对话、私有 URL 或凭据，也没有共享链接导入功能。当上下文不可见时，请附上导出文件。

## 你将获得什么 {#what-you-get}

- **根据来源选定的形态。** skill 会从 13 种原型中选择一种，例如分诊队列、管线看板、实时工作台、日程网格、审查 diff 或监控面板。原型是用户查看的对象，而不是用户遵循的流程，因此来源中的步骤会变成对象上的状态（草稿、已检查、已批准），而不是步进器或向导。
- **命名的视觉方向。** 六种方向之一（`ledger`、`control-room`、`paper-desk`、`studio-canvas`、`tidepool`、`signal-board`），带有浅色和深色令牌，根据原型和来源所属领域选定。已有的品牌或你明确指定的方向优先。
- **已填充的首屏。** `/` 会进入一个命名的领域路由，其中包含标注为示例、与来源结构一致的合成示例数据。除非来源本身就是表单形态，否则空状态、主视觉、流程的第一步或表单都属于缺陷。
- **对象上的智能体时刻。** 每个带有 AI 标签的控件都会将一条范围明确的提示词交给智能体侧边栏。对象会立即显示工作状态，结果会带着接受、编辑和重试按钮回到该对象上。后续对话保持在同一线程中。
- **真正的 Agent-Native 应用。** 确定性的工作是 UI 和智能体都会调用的 `defineAction` 文件。应用使用标准的 Use Builder.io 或 Custom keys 设置，将当前视图和选择写入应用状态，并带有 `AGENTS.md`，向应用内智能体介绍这个新应用。

skill 会将来源简报保存为 `docs/brief.md`，并将界面设计追加到 `DESIGN.md`。

## 一次运行的流程 {#how-it-works}

1. **简报。** 读取完整来源，并编写一份简短的简报：工作内容、最多三个智能体时刻、不变量、数据风险、事实来源和假设。
2. **设计。** 确定原型、方向、外壳、首屏视口与示例数据以及智能体时刻，并将简报作为检查点发布一次。无需等待，直接继续。
3. **脚手架。** 使用 chat 模板创建真正的应用，且绝不覆盖现有应用。

   ```bash
   npx --yes @agent-native/core@latest create <slug> --standalone --template chat
   ```

   在现有的 Agent-Native 工作区内，则改为从工作区根目录运行 `pnpm exec agent-native add-app <slug> --template chat`。

4. **构建。** 同时构建操作、领域界面、示例数据、智能体时刻和智能体指令。
5. **审查。** 运行应用并审查截图。见下文。
6. **验证。** 运行 `pnpm typecheck`、`pnpm agent-native:doctor` 和 `pnpm build`，然后撰写最终报告。

skill 的目标用时约为 45 分钟。如果审查开始时已过去 35 分钟，则只运行一轮，并列出未满足的标准。

## 截图审查循环 {#review-loop}

交付之前，skill 会启动开发服务器，在桌面和手机尺寸下的浅色和深色模式中对 `/` 截图，并在点击后对主要智能体控件截图。它按照包含 12 项的评分标准给截图打分，涵盖首屏视口冲击力、领域契合度、层次结构、界面装饰克制度、示例数据、字体排印、色彩、细节打磨、智能体与 UI 的整体配合、390px 布局、深色模式和无障碍。

无论平均分多少，有些问题都会导致审查失败：步进器或向导式外壳、`/` 没有打开到领域路由、首屏为空或仅有表单、脚手架默认令牌、文字被裁切、原始 markdown、390px 下出现横向滚动，或控制台错误。skill 会一次性修复所有问题，重置点击所改变的内容，然后重新截图。默认进行两轮，只有在第二轮仍未达标且时间允许时才进行第三轮。达标线是平均分 4.0 或更高，没有任何标准低于 3，且没有自动失败项。

截图保存在应用的 `.tmp/ui-review/out/` 中，最终报告会列出它们的路径和分数。UI 中呈现的结果只有在连接了 AI 提供商时才能实际验证；未连接时，报告会说明该结果未经验证。

## 运行与部署 {#run-deploy}

为了进行本地审查，skill 会在应用被忽略的 `.env` 中设置 `AUTH_DISABLED=1`，因为全新的截图浏览器并未登录。这仅用于回环地址的开发。它会在最终的 `pnpm build` 之前被移除，绝不能提交或部署。没有它时，打开应用会显示一张 "Continue as local dev" 卡片。

要自行运行应用：

```bash
pnpm dev
```

要在本地使用你自己的模型提供商，请在同一个 `.env` 中放入诸如 `ANTHROPIC_API_KEY` 之类的密钥。否则，智能体侧边栏会显示共享的 Use Builder.io 或 Custom keys 设置。

只有在你要求部署或提供商已配置时，skill 才会部署。一次正常的本地构建仍会打印一个 "production configuration errors" 块，退出码为 0。这就是部署清单：稳定的 `BETTER_AUTH_SECRET` 和持久的 `DATABASE_URL`，以及工作区内应用所需的 `A2A_SECRET`。skill 会将这些报告为待办步骤，并且不会创建占位值。请参阅[部署应用](/docs/deploy-an-app)和[部署工作区](/docs/workspace-deployment)。

最终报告会分别标注各项证据：本地运行中、本地已验证、可构建、已部署和线上已验证是不同的状态，报告绝不会让其中一个代替另一个。

## 已知限制 {#limits}

- **开发服务器运行时编辑 `.env`。** 修改 `.env` 后原地重新加载会在本地数据库锁上陷入循环并返回 500。请停止服务器，编辑 `.env`，然后重新启动。
- **含糊不清的电子表格。** 如果在有限的审查之后，候选工作流或输入与输出的映射仍然严重含糊，skill 会提出一个简洁的问题并附上它推荐的解读。在无头运行中，它会打印该问题，在简报中记录假设，并继续构建。
- **浏览器宿主上的电子表格。** 无法附加工作簿；宿主会以文本形式传递有限的 CSV 渲染结果或有意公开的 URL，并且交接内容会说明遗漏了什么。 指向私有表格的链接不是来源；技能会要求经过认证的 Sheets 或 Drive 连接，或要求导出文件，绝不会使用公开导出 URL 来绕过访问控制。
- **单元格颜色。** 文本预览无法证明颜色，因此在本地宿主上，skill 会同时读取公式和缓存值，并将颜色视为较弱的提示。
- **Local File Mode 应用。** 事实来源是宿主文件的应用仅限本地，不会被部署。
- **浏览器宿主交接。** 在 Dispatch 返回已构建的分支之前，结果处于未验证状态。skill 无法在那里运行应用或对其截图。
