# 你的第一个功能

本页面适用于扩展 [聊天模板](/docs/template-chat) 的开发者。它介绍了渲染入门聊天屏幕的唯一文件，然后演练当你要求实现一个真实功能时，代理通常会涉及的所有内容。

## 首先要检查的代码 {#first-code}

- `actions/hello.ts` 是代理可以调用的启动行为。替换它，或在旁边
  添加新的 actions。
- `app/routes/_index.tsx` 渲染整页聊天界面。在这里调整
  建议、空状态、composer 或周围的布局。
- `AGENTS.md` 告诉内置代理如何在此应用中工作。

## 首次编辑 {#first-edits}

大多数的第一个功能都遵循相同的形态：一张表、一两个 actions、一个路由、一个导航条目，以及一次 `AGENTS.md` 更新。向代理提出：

> 为 `notes` 添加一个数据模型。一条笔记有 id、标题、正文和所有者。在 `/notes` 渲染一个笔记页面，添加创建/列出 actions，并保持聊天仍能创建笔记。

聊天默认根本没有 `server/db/schema.ts`（参见 [包含哪些内容](/docs/template-chat#what-ships)），因此第一处改动就是新增一个文件，遵循其他所有模板都使用的相同 `table`/`text`/`ownableColumns` 形态：

剩下的功能由此展开：

- `actions/create-note.ts` — 一个带有 Zod schema（`title`、`body`）的 `defineAction`，形态与 `actions/hello.ts` 相同。
- `actions/list-notes.ts` — 一个只读 action（`readOnly: true`，与 `actions/view-screen.ts` 相同），通过 `accessFilter` 查询新表。
- `app/routes/notes.tsx` — 一个新路由；该应用使用基于文件系统的路由（`app/routes.ts` 中的 `flatRoutes()`），因此添加这个文件就足以挂载 `/notes`。
- 在 `app/components/layout/Sidebar.tsx` 的 `navItems` 数组中添加一个指向 `/notes` 的新条目。
- 在 `AGENTS.md` 中添加说明，告诉代理 notes 的存在，以及由哪些 actions 管理它们。

一个新的 action 一旦存在，聊天就可以立即调用它 —— 每个 `defineAction` 默认都是一个 tool，除非它设置了 `agentTool: false`。不过它不一定会出现在模型的第一次请求中：`server/plugins/agent-chat.ts` 设置了 `INITIAL_TOOL_NAMES = ["view-screen", "navigate", "hello"]`，它只控制第一轮会发送哪些 tool schema。其他一切，包括全新的 `create-note`，仍然可以通过 `tool-search` 到达，并按需加载 —— 只有当你想让它从第一条消息起就出现在模型的默认工具集中时，才把它的名字加入这个列表。

## 使用你自己的代理后端 {#own-agent-backend}

该模板默认使用内置的应用代理循环。要连接自定义后端，请更换代理聊天插件背后的聊天运行时，而不是重写 UI。聊天路由应该始终是围绕共享聊天界面的一个精简渲染器；后端的选择属于服务器插件/运行时适配器。

当你的模型编排已经存在于别处，但你仍然想要一个具有身份验证、线程、actions、UI 状态和可部署页面的应用时，请使用这种方式。
