# Chat

Chat é o ponto de partida mais simples do agent-native: um shell no estilo
ChatGPT com o chat no centro, uma lista de threads, autenticação e uma action
de exemplo, sem nada específico de domínio. É para desenvolvedores que querem
um app real e implantável para construir seu próprio agente e telas por cima,
não um produto finalizado para uma tarefa específica.

Se você quiser um formato de produto de domínio finalizado, comece pelo
[Calendar](/docs/template-calendar), [Mail](/docs/template-mail),
[Content](/docs/template-content), [Forms](/docs/template-forms),
[Analytics](/docs/template-analytics) ou outro template de domínio. Se você
realmente ainda não precisa de uma UI de navegador, veja [Automation-First
Apps](/docs/pure-agent-apps).

## O que vem incluído {#what-ships}

<Comparison>

### :green: Incluído

- Chat em página inteira em `/` usando a superfície de chat do framework e
  threads de chat duráveis
- Lista de threads na barra lateral do app para criar, reabrir, renomear,
  fixar e arquivar chats
- O loop integrado de app-agente, pré-configurado para o plugin de chat
- Autenticação via Better Auth: login, cadastro, sessões, organizações
- Um diretório de actions com um exemplo (`actions/hello.ts`) mais as actions
  padrão `view-screen` e `navigate`
- As tabelas centrais do framework para threads de chat, estado da aplicação,
  configurações, sessões, recursos e histórico de execuções, além de uma
  página de administração do Database e um dashboard de Observability,
  montados quer você chegue a abri-los ou não
- Sincronização ao vivo (`useDbSync`) já conectada, para que a UI seja
  atualizada quando o agente grava no SQL
- Rotas de Extensões montadas por padrão, para mini-apps isolados que seus
  usuários construam dentro do chat mais adiante
- AGENTS.md com orientação centrada em chat para adicionar actions, rotas,
  skills e estado da aplicação

### :red: Não incluído

- Tabelas de domínio ou dados iniciais
- Dashboards, listas, gráficos, formulários ou integrações com provedores
- Actions específicas de domínio além do stub de exemplo

</Comparison>

Esse é o ponto. Chat é um shell padrão fino e útil para o seu próprio agente,
não um produto de domínio fingindo ser genérico.

## Quando escolhê-lo {#when-to-pick}

- **Você quer um app básico com o qual os usuários possam conversar
  imediatamente** e depois estender com actions e UI.
- **Você quer o ponto de entrada padrão do Agent-Native**: chat primeiro,
  depois actions, resultados nativos e páginas de app.
- **Você quer plugar seu próprio backend de agente em uma UI de chat
  familiar** mantendo as actions, o estado, a autenticação e o formato de
  deploy do Agent-Native.
- **Você está prototipando uma ferramenta interna personalizada** que não se
  encaixa em nenhum template de domínio.

## Comece agora {#get-started}

```bash
npx @agent-native/core@latest create my-chat-app --standalone --template chat
```

Veja [Chat: Guia do desenvolvedor](/docs/template-chat-developers#quick-start)
para instalação, primeira execução e conexão com um LLM. Para trabalhos
automation-first sem nenhuma UI de navegador, faça o scaffold com `--headless`
em vez disso:

```bash
npx @agent-native/core@latest create my-agent --headless
```

Use isso para jobs agendados, filas, loops de CLI ou fluxos de trabalho de
agentes externos onde o chat e as páginas de app ainda não são úteis. O
invariante principal permanece o mesmo: actions são a superfície
compartilhada para chat, UI, HTTP, MCP, A2A e CLI. Veja [Automation-First
Apps](/docs/pure-agent-apps) para esse caminho em profundidade.
