# Content: Fontes de pastas locais

O Content tem um único modelo de dados: cada página fica no SQL, pertence a um
**espaço** e integra o banco de sistema **Files** desse espaço. Uma pasta
Markdown ou MDX local é uma fonte conectada ao Files, ao lado de colaboração,
compartilhamento, comentários, histórico, busca, propriedades de banco de
dados e a mesma superfície de actions usada por qualquer outra página.

## Espaços, Files e Workspaces

O Content disponibiliza:

- um espaço pessoal para cada usuário
- um espaço de organização para cada organização que o usuário pode acessar
- um banco de sistema **Files** em cada espaço
- um catálogo pessoal **Workspaces** que faz referência aos espaços exibidos
  no aplicativo

Toda página comum pertence a exatamente um espaço e um banco Files. Files é um
banco normal do Content: adicione propriedades, salve visualizações, filtre,
ordene ou agrupe os dados. Sua visualização em barra lateral renderiza essas
mesmas linhas como navegação. Agrupar uma visualização na barra lateral cria
seções recolhíveis, enquanto visualizações salvas podem se tornar abas
alternativas na barra lateral.

O catálogo Workspaces aplica a mesma ideia um nível acima. Ele controla quais
espaços pessoais, de organização e baseados em pasta participam da barra
lateral do aplicativo.

## Conectar uma pasta

<Steps>

### Abra a tela de pasta local

Selecione uma pasta pela File System Access API do navegador ou pelo
Agent-Native Desktop. O Content armazena no SQL apenas um identificador opaco
de conexão, caminhos relativos, hashes e metadados da fonte. Ele nunca
armazena ali o caminho absoluto, o handle do navegador ou o conteúdo bruto dos
arquivos.

### Escolha onde a pasta se conecta

Conecte-a ao banco Files de um espaço pessoal ou de organização já existente,
ou crie um espaço privado baseado em pasta com seu próprio banco Files.

### Escolha uma política de verdade

| Política                 | Comportamento                                                             |
| ------------------------ | -------------------------------------------------------------------------- |
| `database_primary`       | O Content é a autoridade; alterações na pasta são revisadas antes de usar |
| `source_primary`         | A pasta é a autoridade quando não há edição concorrente no Content       |
| `reviewed_bidirectional` | Alterações em qualquer direção exigem revisão em caso de conflito         |

</Steps>

A sincronização inicial materializa os arquivos como páginas normais no SQL e
registra sua identidade de origem. Uma nova sincronização é idempotente. Se um
arquivo e sua página no Content mudarem ao mesmo tempo, o Content registra um
conjunto de alterações recebidas em vez de sobrescrever silenciosamente um dos
lados. Desconectar mantém tanto as páginas no SQL quanto os arquivos locais.

## Iniciar em um repositório

```bash
npx @agent-native/core@latest content .
```

O comando inicia o Content normal com banco de dados, registra a pasta como
fonte e abre a conexão.

## Configuração

```json
{
  "version": 1,
  "apps": {
    "content": {
      "roots": [
        {
          "name": "Docs",
          "path": "docs",
          "kind": "docs",
          "extensions": [".md", ".mdx"],
          "source": {
            "type": "local-folder",
            "connectionId": "local-folder:<opaque-id>",
            "truthPolicy": "source_primary"
          }
        }
      ],
      "components": "components",
      "extensions": "extensions"
    }
  }
}
```

## Migrar do modo de arquivos locais

<Callout tone="info">

Pule esta seção se você está configurando uma pasta local pela primeira vez.
Ela só se aplica a um manifesto anterior ao modelo de fonte atual.

</Callout>

Um manifesto mais antigo pode conter `mode: "local-files"`, e um fluxo de
inicialização mais antigo pode definir `AGENT_NATIVE_MODE=local-files`. Remova
os dois. Mantenha as raízes já configuradas, adicione `source.type`,
`source.connectionId` e `source.truthPolicy`, e então inicie com
`agent-native content <arquivo-ou-pasta>`.

Depois da primeira conexão e sincronização, confirme que:

- A pasta aparece como fonte no banco Files pretendido.
- Cada página importada pertence ao espaço pretendido.
- Propriedades personalizadas e visualizações salvas na barra lateral
  funcionam normalmente.
- Edições concorrentes aparecem como conjuntos de alterações revisáveis.
- Desconectar preserva as páginas no banco de dados e os arquivos no disco.

IDs no frontmatter preservam a identidade ao renomear ou mover uma página.
Componentes e extensões locais continuam usando a ponte local confiável.
