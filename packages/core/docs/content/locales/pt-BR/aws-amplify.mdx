# AWS Amplify

<Badge label="Beta" color="orange" icon="rocket" />

O AWS Amplify Hosting faz o build do seu app a partir de um repositório Git e o hospeda para você,
então não há nenhum servidor para configurar ou manter em execução. O Amplify serve os arquivos
estáticos do app pelo CloudFront, executa o servidor do app para as páginas e a API,
e dá ao app um endereço público com HTTPS.

Este guia mostra como implantar um app independente do zero. Você vai
criar o app e enviá-lo para um repositório Git, dar a ele um banco de dados de produção
e um segredo de autenticação, preparar o banco de dados, adicionar as configurações de build do Amplify e,
depois, criar o app do Amplify.

<Callout tone="info">

É necessário o Node.js `22.22+`.

</Callout>

Você também precisa de uma conta da AWS e de um repositório no GitHub, GitLab, Bitbucket ou
AWS CodeCommit. Execute os comandos deste guia no seu próprio computador. O Amplify
faz o build e executa o app a partir do seu repositório.

## Passo 1: Crie o app {#step-1-create-the-app}

Crie o seu novo app independente. O exemplo abaixo cria um app a partir do template Chat,
mas você pode começar de qualquer template. Entre na pasta do app e
instale as dependências. `corepack enable` ativa a versão do `pnpm` que o app
espera, então você não precisa instalar o `pnpm` por conta própria.

```bash
npx --yes @agent-native/core@latest create my-app --standalone --template chat

cd my-app

corepack enable

pnpm install
```

Se quiser, substitua `my-app` pelo nome do seu app. O restante deste guia
considera que você está dentro da pasta do app.

O Amplify faz o build do app a partir de um repositório Git, então envie a pasta do app para um novo
repositório antes de continuar. No Passo 4, você adiciona mais um arquivo e faz o push novamente.

<Callout tone="info">

Se esses comandos falharem com erros de dependências peer, a causa pode ser uma cópia desatualizada de um pacote no seu cache do npx. Execute `npx clear-npx-cache` para limpar o cache e depois execute os comandos novamente.

</Callout>

## Passo 2: Configure os segredos do ambiente {#step-2-configure-environment-secrets}

O app lê as configurações de produção a partir de variáveis de ambiente:

| Variável             | Obrigatória | Finalidade                                                           |
| -------------------- | ----------- | -------------------------------------------------------------------- |
| `DATABASE_URL`       | Sim         | Conecta o app ao seu banco de dados PostgreSQL                       |
| `BETTER_AUTH_SECRET` | Sim         | Assina as sessões dos usuários                                       |
| `BETTER_AUTH_URL`    | Não         | Define o endereço público que as pessoas usam para acessar o seu app |

Os exports abaixo fazem os comandos seguintes funcionarem neste shell. Antes de
implantar, salve essas mesmas variáveis nas configurações de ambiente do projeto ou serviço do seu host.
O Passo 5 mostra como salvá-las no Amplify.

<Callout tone="warning">

O Amplify passa as variáveis de ambiente para o build, mas não para o servidor em
execução. Para disponibilizá-las, o build do Agent-Native grava as variáveis
declaradas do app em um arquivo `.env` dentro do pacote do servidor. Qualquer pessoa com
acesso aos artefatos de implantação do app pode ler esse arquivo, então limite quem pode
acessá-los na sua conta da AWS.

</Callout>

### URL do banco de dados {#database-url}

Durante o desenvolvimento local, o app armazena os dados em um banco de dados local quando
`DATABASE_URL` não está definida. Um app implantado precisa de um banco de dados PostgreSQL real que
mantenha os dados entre implantações. O Amplify não mantém arquivos entre requisições,
então o banco de dados precisa ficar fora do Amplify. Copie a string de conexão do seu
provedor e exporte-a:

```bash
export DATABASE_URL='your-postgres-url-string'
```

Os [guias de provedores de banco de dados](/docs/neon) mostram onde encontrar a string de conexão
de cada provedor, incluindo o
[Amazon RDS for PostgreSQL](/docs/aws-rds).

<Callout tone="warning">

Escolha um provedor de PostgreSQL persistente, como Neon, Supabase ou Amazon RDS.

</Callout>

### Segredo de autenticação {#auth-secret}

Gere este valor uma única vez e mantenha-o igual em todas as implantações.

O app usa `BETTER_AUTH_SECRET` para assinar as sessões dos usuários. Se ele mudar, todos os
usuários conectados são desconectados. O comando abaixo gera um valor aleatório:

```bash
export BETTER_AUTH_SECRET="$(openssl rand -hex 32)"
```

Salve o valor gerado em um lugar seguro, como um gerenciador de senhas. Use o
mesmo valor sempre que implantar.

### URL pública {#public-url}

É opcional. Defina-a ao usar um domínio personalizado, um proxy reverso ou um fluxo de autenticação ou OAuth
que precise de uma origem pública fixa.

`BETTER_AUTH_URL` é o endereço público que as pessoas usam para acessar o seu app. Sem
ela, o app descobre o próprio endereço a partir de cada requisição recebida. Isso normalmente
funciona bem no endereço que o Amplify fornece, mas defina-a quando conectar um domínio
personalizado, para que os links de login e os redirecionamentos de OAuth usem esse domínio.

```bash
export BETTER_AUTH_URL='https://your-domain.example'
```

## Passo 3: Execute as migrações {#step-3-migrate}

As migrações criam e atualizam as tabelas de que o app precisa no seu banco de dados. Execute
isto antes da primeira implantação:

```bash
pnpm migrate:production
```

O comando é executado no seu computador e se conecta ao banco de dados de produção com
a `DATABASE_URL` que você exportou no Passo 2. Execute-o novamente depois de atualizar o
app e antes de implantar a nova versão.

## Passo 4: Adicione as configurações de build do Amplify {#step-4-add-amplifys-build-settings}

Crie um arquivo chamado `amplify.yml` na pasta raiz do app, ao lado do
`package.json`, e copie o seguinte conteúdo nele:

```yaml filename="amplify.yml"
version: 1
frontend:
  phases:
    preBuild:
      commands:
        - nvm install 24
        - corepack enable
        - pnpm install
    build:
      commands:
        - NITRO_PRESET=aws_amplify pnpm build
  artifacts:
    baseDirectory: .amplify-hosting
    files:
      - "**/*"
```

O arquivo informa ao Amplify como fazer o build do app:

- **preBuild** muda o build para o Node.js 24, ativa a versão do `pnpm` do
  app e instala as dependências.
- **build** faz o build do app com `NITRO_PRESET=aws_amplify`, o formato que o Amplify
  Hosting espera.
- **artifacts** diz ao Amplify para implantar a pasta `.amplify-hosting` que o
  build cria.

O build grava nessa pasta tudo de que o Amplify precisa:

    },

Faça o commit do `amplify.yml` e envie-o para o seu repositório.

## Passo 5: Crie o app do Amplify {#step-5-create-the-amplify-app}

Crie o app no [console do Amplify](https://console.aws.amazon.com/amplify/):

<Steps>

### Conecte o repositório

Escolha **Deploy an app**. Na página **Start building with Amplify**, escolha
o seu provedor Git e, depois, escolha **Next**. Na primeira vez, o Amplify pede permissão para ler
os seus repositórios.

### Escolha a branch

Na página **Add repository branch**, escolha o repositório e a branch
do Passo 1 e, depois, escolha **Next**.

### Confira as configurações de build

Na página **App settings**, o Amplify lê as configurações de build do
`amplify.yml`. Confira se **Build output directory** está definido como `.amplify-hosting`.
Escolha **Create and use a new service role**.

### Adicione as variáveis de ambiente

Em **Advanced settings**, adicione `DATABASE_URL` e `BETTER_AUTH_SECRET` com
os valores que você exportou no Passo 2. Se você definir `BETTER_AUTH_URL`, adicione-a da
mesma forma. Depois, escolha **Next**.

### Implante

Na página **Review**, escolha **Save and deploy**.

</Steps>

## Passo 6: Abra o app {#step-6-open-the-app}

O primeiro build leva alguns minutos, e você pode acompanhá-lo no console do
Amplify. Quando ele terminar, abra o endereço do app, que se parece com
`https://main.d1m7bkiki6tdw1.amplifyapp.com`, e crie a primeira conta.

Depois, confira se:

- A página inicial carrega.
- Um arquivo em `/assets/` carrega, o que mostra que os arquivos estáticos estão sendo servidos.
- Você consegue fazer login, e os dados que você cria continuam lá depois de recarregar a página.

## Implante atualizações {#deploy-updates}

O Amplify faz o build e implanta novamente sempre que você faz push para a branch que escolheu
no Passo 5. Para publicar uma nova versão, execute primeiro as migrações e depois faça o push:

```bash
pnpm migrate:production

git push
```

O build copia as variáveis de ambiente para o pacote do servidor, então uma
mudança de variável só tem efeito depois do próximo build. Depois de mudar uma
variável no console do Amplify, faça push de um commit ou implante novamente o build mais recente.

## Cache {#caching}

O Amplify serve o app pelo CloudFront. O shell de página pública do app envia
este cabeçalho `Cache-Control`, e o Amplify o respeita:

```txt
public, max-age=600, stale-while-revalidate=604800, stale-if-error=3600
```

O CloudFront mantém o shell atualizado por dez minutos, pode servir uma cópia mais antiga enquanto
busca uma nova e pode servi-la durante um erro. Os dados pessoais são carregados no
navegador depois que a página abre, então nunca acabam no shell compartilhado.
Os arquivos estáticos ficam em cache por até um ano, e cada nova implantação limpa
o cache do Amplify.

Mantenha ativada a configuração padrão **Remove cookies from cache key** do Amplify.
Não adicione uma regra global de `Cache-Control` no `customHttp.yml`, porque ela pode
sobrescrever o cabeçalho `no-store` nas rotas privadas. Para encurtar ou desativar o
cache do shell, defina `AGENT_NATIVE_SSR_CACHE`. [Cache SSR](/docs/ssr-caching)
explica a política completa.

## Faça streaming das respostas do agente {#stream-agent-responses}

O caminho do CloudFront do Amplify pode segurar pequenos pedaços de uma resposta, então as respostas
do chat do agente podem chegar em rajadas em vez de palavra por palavra. Para fazer o streaming
delas diretamente, o Agent-Native pode adicionar uma função do Lambda separada que serve apenas o
stream do chat:

```bash
npx agent-native amplify-stream \
  --amplify-app-id your-amplify-app-id \
  --branch main \
  --region us-east-1 \
  --env-file .env
```

O comando faz o build do stream do chat como uma função do Lambda com Node.js 24, com uma
URL de função com streaming e um tempo limite de 15 minutos. Ele salva o endereço da função
na branch do Amplify e inicia uma nova release. O navegador continua usando o
app do Amplify para todo o resto e envia apenas as requisições do chat para a função.

O comando lê as variáveis do app do arquivo que você passa com `--env-file`,
então esse arquivo precisa dos mesmos valores de `DATABASE_URL`, `BETTER_AUTH_SECRET` e dos outros
que o app do Amplify usa. Ele também precisa de credenciais da AWS CLI que possam gerenciar
Lambda, IAM e Amplify. Adicione `--skip-release` para salvar o endereço sem
iniciar uma release. Se a função de stream não estiver disponível, o chat volta a usar
a rota normal do Amplify.
