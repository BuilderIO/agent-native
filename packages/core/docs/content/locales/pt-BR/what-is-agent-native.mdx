# O que é Agent-Native?

Agent-Native é um framework TypeScript de código aberto para criar agentes autônomos com interfaces intuitivas. Você define cada capacidade uma vez como uma [ação](/docs/actions-overview) — uma função tipada que o agente usa como ferramenta e a UI chama pelo código.

## Por que criar agentes com UIs

Agentes de programação podem fazer uma caixa de texto parecer suficiente. Mas ela é apenas uma parte do ambiente de trabalho deles. O código fornece contexto, as ferramentas oferecem formas claras de agir, e arquivos, testes e prévias tornam os resultados visíveis.

A maior parte do trabalho do conhecimento não vem com essa estrutura. Em uma caixa de texto vazia, as pessoas precisam adivinhar o que o agente pode fazer, qual contexto ele tem e o que devem pedir.

Uma UI oferece o que falta à caixa de texto. Ela torna as capacidades do agente visíveis, incorpora contexto e fluxos de trabalho à experiência, e permite que as pessoas vejam e moldem o trabalho enquanto ele avança.

Agent-Native permite criar agentes dessa forma. A UI oferece pontos de partida claros sem reduzir o agente a um fluxo de trabalho fixo. Como o agente e a UI usam as mesmas capacidades, as pessoas podem delegar trabalho ao agente, inspecioná-lo ou alterá-lo na UI e transitar entre os dois sem perder o progresso.

Agent-Native conecta o agente e a UI por meio de três fundamentos compartilhados:

- **[Ações compartilhadas](/docs/actions-overview).** Cada capacidade é definida uma vez. O agente a chama como ferramenta e a UI a chama pelo código. Os dois caminhos usam a mesma validação, permissões e implementação.
- **[Dados compartilhados](/docs/server-database).** As ações leem e atualizam os mesmos dados. Assim, o trabalho feito pelo agente aparece na UI, e o trabalho feito na UI fica disponível para o agente.
- **[Estado compartilhado da aplicação](/docs/context-awareness).** O estado da aplicação descreve o que está acontecendo na UI, como a página atual, o registro selecionado ou a visualização ativa. Agent-Native fornece o estado relevante ao agente como contexto, para que ele entenda no que a pessoa está trabalhando.

O agente não clica pela UI. Ele trabalha pela mesma camada de ações que a UI.

Por exemplo, uma pessoa pode atribuir um ticket de suporte pela UI ou pedir ao agente que faça isso. Os dois caminhos executam a mesma ação e atualizam o mesmo ticket. A pessoa pode inspecionar ou alterar o resultado na UI e, depois, deixar o agente continuar dali.

## Quando usar Agent-Native?

Agent-Native é uma boa escolha quando:

- O agente deve realizar trabalho real, não apenas responder perguntas.
- As pessoas precisam de uma UI para ver o que o agente pode fazer e para inspecionar, editar, aprovar ou compartilhar o trabalho dele.
- As pessoas devem poder transitar entre o agente e a UI sem perder progresso ou contexto.

Se você só precisa de uma única resposta gerada, chame um modelo diretamente. Se o trabalho segue uma sequência fixa e previsível, a lógica de aplicação convencional ou uma automação é mais simples. Use Agent-Native quando o agente e a UI precisarem ter um papel contínuo no mesmo trabalho.
