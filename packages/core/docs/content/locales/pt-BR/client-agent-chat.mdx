# Chat do Agent

O cliente do seu aplicativo pode conversar com o agente através de um pequeno conjunto de auxiliares de cliente. Eles cobrem enviar um prompt, preparar contexto oculto, fazer uma pergunta bloqueante ao usuário, e abrir o painel do agente.

No exemplo abaixo, um botão **Draft response** solicita que o agente faça uma pergunta ao usuário. Depois que o usuário responde, o agente parte para redigir uma resposta levando em conta o contexto atual da página e a resposta do usuário.

## Como funciona

Usando os métodos auxiliares de cliente fornecidos pelo Agent-Native, sua UI pode fazer o agente interagir com o usuário de várias formas. O diagrama abaixo demonstra como um botão "Draft response" pode ser clicado pelo usuário, o que então leva o agente a interagir com o usuário antes de gerar uma resposta.

A experiência do usuário é a seguinte:

1. O usuário clica no botão **Draft response**, o que faz com que a função `askUserQuestion()` seja chamada. A pergunta é respondida inline no painel do agente.

1. O usuário escolhe **Offer a refund**, o que faz com que `sendDraftRequest()` envie o prompt e o contexto do ticket ao agente.

1. O agente chama a [action](/docs/actions) `draft-ticket-reply`, e a resposta redigida aparece no composer de resposta.

Esta função faz ao usuário uma pergunta de múltipla escolha a partir do código do aplicativo, renderiza-a inline no painel do agente, e aguarda a resposta. Use-a quando a UI precisar de uma pequena decisão com duas a quatro opções antes de iniciar o trabalho do agente, em vez de construir um modal personalizado.

No exemplo abaixo, um botão "Draft Response" na página de um ticket pergunta ao representante como ele gostaria de responder antes de enviar qualquer coisa ao agente:

```ts
import { askUserQuestion } from "@agent-native/core/client/agent-chat";

const answer = await askUserQuestion({
  question: "How would you like to respond to this ticket?",
  header: "Response", // chip/cabeçalho curto opcional (≈12 caracteres)
  options: [
    { label: "Offer a refund", value: "refund" },
    { label: "Offer a reprint", value: "reprint" },
  ],
});
```

## useAgentChatGenerating() {#useagentchatgenerating}

  }}
/>

Este gancho React envolve `sendToAgentChat()` com rastreamento de estado de carregamento.

1. O primeiro argumento, `isGenerating`, se torna verdadeiro quando você o chama, e volta para falso quando o agente termina de gerar.

2. O segundo argumento, `send()`, espelha a função `sendToAgentChat()`.

`isGenerating` só volta ao estado inicial quando uma execução de fato começa e reporta que parou. Uma chamada com `submit: false` preenche previamente um rascunho sem iniciar uma execução, então `isGenerating` fica `true` para sempre depois de uma dessas chamadas. Use este gancho apenas para envios com `submit: true`; chame `sendToAgentChat()` diretamente para envios apenas de preenchimento prévio.

Combinar isto com o exemplo de `askUserQuestion()` acima completa o manipulador do botão:

## sendToAgentChat(opts) {#sendtoagentchat}

Envie uma mensagem para o chat do agente via `postMessage`. Esta é a primitiva de nível mais baixo que `useAgentChatGenerating()` acima encapsula, útil quando uma interação de UI não precisa de rastreamento de estado de carregamento próprio. Passe `context` para detalhes extras que o modelo deve ver, mas o usuário não. Ele é anexado à mensagem enviada ao agente, envolvido em tags `<context>`, e é removido antes que a mensagem seja renderizada na UI do chat. Passe `submit: true` para enviar imediatamente, ou `submit: false` para preencher previamente um rascunho que o usuário revisa primeiro.

```ts
import { sendToAgentChat } from "@agent-native/core/client/agent-chat";
// Enviar automaticamente um prompt com contexto oculto
sendToAgentChat({
  message: "Generate alt text for this image",
  context: "Image path: /api/projects/hero.jpg",
  submit: true,
});

// Prefill without submitting (user reviews first)
sendToAgentChat({
  message: "Rewrite this in a conversational tone",
  context: selectedText,
  submit: false,
});
```

### AgentChatMessage {#agentchatmessage}

| Opção         | Tipo       | Descrição                                                                                         |
| ------------- | ---------- | ------------------------------------------------------------------------------------------------- |
| `message`     | `string`   | O prompt enviado ao chat, e a única parte exibida na UI do chat                                   |
| `context`     | `string?`  | Contexto visível ao modelo, anexado à mensagem antes do envio. Removido da exibição da UI do chat |
| `submit`      | `boolean?` | true = envio automático, false = apenas preenchimento prévio                                      |
| `newTab`      | `boolean?` | Cria uma thread de chat separada para este prompt                                                 |
| `openSidebar` | `boolean?` | Defina como false para enviar/preencher sem abrir a barra lateral                                 |

Executar isso de dentro de um embed de MCP App, ou colocar a execução em segundo plano sem abrir a barra lateral, ambos são cobertos em [Avançado](/docs/client-advanced#background-send).

## Sugestões dinâmicas {#dynamic-suggestions}

Antes que uma conversa comece, `<AgentSidebar>`, `<AgentPanel>` e `<AssistantChat>` mostram chips de prompt no chat vazio. Por padrão, esses não são apenas sua lista fixa de `suggestions`: a estrutura lê `navigation`, `selection`, `pending-selection-context`, e a URL atual do estado do aplicativo, e mescla chips que correspondem ao que está de fato na tela.

Ela faz isso com duas verificações. Se algo está selecionado, adiciona chips genéricos como "Summarize this selection". Separadamente, ela examina `navigation` por nomes de campo que aplicativos já usam com frequência, como `threadId`/`emailId` para uma thread de e-mail ou `dashboardId`/`chartId` para um gráfico, e adiciona chips adaptados a esse tipo de tela, como "Draft a reply" para uma thread ou "Find anomalies in this data" para um gráfico. O que quer que ela produza é mesclado com suas `suggestions` estáticas, desduplicado, e limitado a `max`.

```tsx
<AgentSidebar
  suggestions={["Summarize my inbox"]}
  dynamicSuggestions={{ max: 4 }}
>
  <App />
</AgentSidebar>
```

Se a tela atual não corresponder a nada que a heurística reconheça e nada estiver selecionado, ela não contribui com nenhum chip, e o chat vazio recorre apenas às suas `suggestions` estáticas. Defina `dynamicSuggestions={false}` para manter apenas chips estáticos. Se o formato de navegação do seu aplicativo não corresponder à heurística integrada, ou você quiser chips específicos do aplicativo totalmente determinísticos, veja [Avançado](/docs/client-advanced#custom-suggestions).

## openAgentSettings(section?) {#openagentsettings}

Use `openAgentSettings()` quando uma página de configurações do aplicativo ou um card de setup
deve abrir a aba Settings da barra lateral do agente. Passe um id de seção como `"llm"`, `"secrets"`,
`"automations"`, `"voice"`, ou `"limits"` para abrir uma seção específica.

```ts
import { openAgentSettings } from "@agent-native/core/client/navigation";
openAgentSettings();
openAgentSettings("secrets");
```

Prefira este auxiliar em vez de despachar `agent-panel:open-settings` diretamente.

## Estado de contexto do chat do agente {#agent-chat-context-state}

As APIs de estado de contexto são encanamento opcional para UI que precisa de sincronização bidirecional com chips de contexto preparado: renderizar os itens preparados atuais fora do composer, refletir se um item já está anexado, ou fornecer controles explícitos de remoção/limpeza.

Não recorra a esses auxiliares para fluxos simples de "enviar isto ao agente" ou "preencher este rascunho para revisão". Use [`sendToAgentChat()`](#sendtoagentchat) com `context` e `submit` para esses casos.

| API                               | Use quando                                                                           |
| --------------------------------- | ------------------------------------------------------------------------------------ |
| `useAgentChatContext()`           | Um componente React precisa da lista de contexto preparado em tempo real             |
| `setAgentChatContextItem(item)`   | Código imperativo deve preparar ou substituir um item de contexto identificado       |
| `listAgentChatContext()`          | Código não React precisa de uma captura pontual do contexto preparado                |
| `removeAgentChatContextItem(key)` | UI deve remover um item de contexto preparado pela sua `key` estável                 |
| `clearAgentChatContext()`         | UI deve limpar todo o contexto preparado, como após um reset de visualização ou modo |
| `refreshAgentChatContext()`       | Código imperativo deve reler o snapshot de contexto persistido mais recente          |

`useAgentChatContext()` retorna `{ items, set, remove, clear, refresh }`.

```tsx
import { useAgentChatContext } from "@agent-native/core/client/agent-chat";

function SelectedTicketContextButton({ ticket }: { ticket: { id: string } }) {
  const chatContext = useAgentChatContext();
  const contextKey = `selected-ticket:${ticket.id}`;
  const isAttached = chatContext.items.some((item) => item.key === contextKey);

  return (
    <button
      type="button"
      onClick={() => {
        if (isAttached) {
          chatContext.remove(contextKey);
          return;
        }

        chatContext.set({
          key: contextKey,
          title: "Selected Ticket",
          context: JSON.stringify(ticket, null, 2),
          openSidebar: false,
        });
      }}
    >
      {isAttached ? "Remove from prompt context" : "Add to prompt context"}
    </button>
  );
}
```

`listAgentChatContext()` é para código imperativo que só precisa inspecionar os itens preparados atuais uma vez. `clearAgentChatContext()` é deliberadamente amplo. Use `removeAgentChatContextItem(key)` quando apenas uma seleção mudou.

### AgentChatContextSetOptions {#agentchatcontextsetoptions}

| Opção         | Tipo       | Descrição                                                               |
| ------------- | ---------- | ----------------------------------------------------------------------- |
| `key`         | `string`   | Identificador estável usado para substituir um item existente           |
| `title`       | `string`   | Etiqueta curta mostrada no chip do composer                             |
| `context`     | `string`   | Contexto oculto incluído com o próximo prompt enviado                   |
| `openSidebar` | `boolean?` | Padrão verdadeiro. Passe false para preparar o contexto silenciosamente |
