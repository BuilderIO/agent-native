# Visão geral

`app/` é onde você constrói a exibição real de um aplicativo nativo do agente: páginas, layout, componentes, estilos. `public/` armazena os ativos estáticos servidos junto com ela — ícones, manifesto, elementos de marca. Este é um aplicativo React Router v8 típico, não uma superfície exclusiva para agentes, e é onde a maior parte do tempo de desenvolvimento é gasto.

A única diferença arquitetural em relação a um front-end típico: esta camada não tem seu próprio backend-for-frontend. Ela lê e grava dados através das mesmas actions que o agente chama, então qualquer coisa conectada aqui é automaticamente algo que o agente também pode fazer.

## Onde o cliente se encaixa {#role}

Solicitações do navegador, o loop do agente e clientes de API externos resolvem todos para as mesmas actions e o mesmo banco de dados SQL — não existe um "backend de aplicativo" separado com o qual esta camada conversa e que o agente não possa também alcançar. Construir um recurso aqui significa construir uma UI sobre uma operação que o agente já possui, ou definir uma nova action e ganhar uma UI para ela ao mesmo tempo. Veja [Actions](/docs/actions) para o lado da operação desse contrato.

Esta página cobre os diretórios em que você constrói e as partes do runtime do navegador que nenhum outro lugar documenta (`root.tsx`, `public/`). Os ganchos React que conectam seus componentes às actions e ao agente vivem em suas próprias páginas focadas:

| Página                                                   | O que ela cobre                                                                                                                      |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| **[Dados e sincronização](/docs/client-data)**           | `useActionQuery`, `useActionMutation`, `callAction` e `useDbSync`                                                                    |
| **[Chat do Agent](/docs/client-agent-chat)**             | `sendToAgentChat`, `askUserQuestion`, `openAgentSettings`, sugestões dinâmicas, e o estado de contexto do chat do agente preparado   |
| **[Avançado](/docs/client-advanced)**                    | Acesso direto a `application_state`, envios de chat em segundo plano, chips de sugestão personalizados, e a ponte de host do MCP App |
| **[Sincronização interna](/docs/client-sync-internals)** | `useChangeVersion`/`useChangeVersions` para sincronizar um `useQuery` bruto                                                          |
| **[Pontos de entrada](/docs/client-entry-points)**       | `app/entry.client.tsx`/`app/entry.server.tsx` e personalização de SSR                                                                |

## O Shell do Navegador: root.tsx e AppProviders {#app-shell}

`app/root.tsx` é o topo da árvore React: o shell do documento HTML (`<html>`, `<head>`, `<Meta>`, `<Links>`, `<Scripts>`) mais a pilha de provedores que toda rota renderiza dentro.

```tsx filename="app/root.tsx"
import {
  AppProviders,
  createAgentNativeQueryClient,
} from "@agent-native/core/client/hooks";
import { useState } from "react";
import { Outlet } from "react-router";
import { i18nCatalog } from "./i18n";

export default function Root() {
  const [queryClient] = useState(() => createAgentNativeQueryClient());

  return (
    <AppProviders queryClient={queryClient} i18n={{ catalog: i18nCatalog }}>
      <Outlet />
    </AppProviders>
  );
}
```

`AppProviders` é o único wrapper que conecta:

- O cliente React Query usado por `useActionQuery`/`useActionMutation` (veja [Dados e sincronização](/docs/client-data#fetching-mutating)).
- O catálogo de i18n passado como `i18n.catalog` (veja [Internacionalização](/docs/internationalization)).
- Verificações de sessão no lado do cliente: em um caminho privado, um visitante anônimo é redirecionado para o login antes que qualquer UI privada seja montada. Passe `isPublicPath` para rotas públicas/SEO, ou `sessionBypass` para uma superfície que se autentica de outra forma, como um token de embed MCP. Veja [Autenticação](/docs/authentication).

A maioria dos aplicativos também monta `<AgentSidebar>` ou `<AgentPanel>` aqui, para que toda rota ganhe o painel do agente de graça. Veja [Agente de visita](/docs/drop-in-agent#sidebar).

## Ativos estáticos: public/ {#public-directory}

Tudo em `public/` é servido como está na raiz do site, sem processamento pelo build. Todo template inclui:

```text
public/
  favicon.svg           -> ícone da aba do navegador
  icon-180.svg           -> apple-touch-icon
  icon-192.svg, icon-512.svg -> ícones PWA referenciados em manifest.json
  manifest.json          -> manifesto de web app (nome, cor do tema, ícones)
  *-logo-*.svg, *-icon-*.svg -> marcas usadas na UI padrão
```

`manifest.json` controla o que aparece se um visitante instalar o aplicativo em uma tela inicial ou dock — nome, nome curto, cor do tema/fundo, e o conjunto de ícones:

```json filename="public/manifest.json"
{
  "name": "My App",
  "short_name": "My App",
  "theme_color": "#18181B",
  "icons": [
    { "src": "icon-192.svg", "sizes": "192x192", "type": "image/svg+xml" }
  ]
}
```

Rebatize um aplicativo substituindo esses arquivos e atualizando `manifest.json` e as tags `<link rel="icon">`/`<link rel="apple-touch-icon">` em `root.tsx` que os referenciam — não há uma etapa de registro separada. Para extrair um sistema de marca completo (cores, fontes, favicon) de um site existente em vez de editar esses arquivos manualmente, veja [Sistemas de marca e Figma](/docs/template-design-brand-and-figma).

## Utilitários: cn {#utilities}

```ts
import { cn } from "@agent-native/toolkit/utils";

<div className={cn(
  "px-4 py-2 rounded",
  isActive && "bg-primary text-primary-foreground",
  className
)} />
```

`cn` mescla nomes de classe (clsx + tailwind-merge) e é a maneira padrão de compor classes Tailwind condicionais em `app/components/`.
