# Web de agente público

A web pública do agente torna as rotas Agent-Native públicas fáceis para os agentes rastrearem, lerem, citarem e ligarem. O objetivo não é tornar públicos todos os endpoints do aplicativo. O objetivo é publicar uma superfície pública limpa para páginas que já são públicas, mantendo dados privados e acesso a ferramentas sob controles explícitos.

O site de documentos é a implementação de referência. Hoje é enviado:

- `/robots.txt` com uma política de rastreador que permite a recuperação, mas não permite o treinamento por padrão.
- `/sitemap.xml` como índice de sitemaps que aponta para um `/sitemap-<locale>.xml` por idioma, com URLs canônicos absolutos e `lastmod` quando o arquivo de origem o expõe.
- `/llms.txt` e `/llms-full.txt` para descoberta de conteúdo amigável ao agente.
- Espelhos Markdown como `/docs/getting-started.md`.
- Respostas `Accept: text/markdown` para páginas de documentos públicos após uma compilação de produção.
- JSON-LD para organização base, site e metadados de página.
- Uma auditoria CLI (`npx @agent-native/core@latest audit-agent-web`) que verifica todos os itens acima.

Publicar esses arquivos nunca expõe uma action. Uma action só chega a agentes externos pela própria opção `publicAgent`; veja [Expor a agentes públicos](/docs/actions-access-control#public-agent).

## Configuração {#config}

`createAgentWebVitePlugin` de `@agent-native/core/vite` grava esses arquivos durante um build de produção. Adicione-o à sua configuração do Vite com as páginas que os agentes devem ler:

```ts
// vite.config.ts
import { createAgentWebVitePlugin } from "@agent-native/core/vite";

export default defineConfig({
  plugins: [
    // ...your existing plugins
    createAgentWebVitePlugin({
      siteName: "My Agent-Native App",
      siteUrl: "https://example.com",
      pages: [
        {
          path: "/pricing",
          title: "Pricing",
          description: "Plans and limits.",
          markdown: "Plans and limits.\n",
        },
      ],
      agentWeb: { crawlerPolicy: "discoverable-no-training" },
    }),
  ],
});
```

O plugin publica as páginas que você lista e nada mais. Ele não lê suas configurações de acesso às rotas, nem lê `agentWeb` do `package.json`, a menos que você o passe. Para manter as configurações no `package.json` em `agent-native.workspaceApp.agentWeb`, passe `agentWeb: agentWebConfigFromPackageJson(pkg)`, importado de `@agent-native/core/agent-web`.

| Opção           | Padrão                                | O que faz                                                                                                                                                 |
| --------------- | ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `discoverable`  | Ativado quando `pages` não está vazio | `false` não grava nenhum arquivo.                                                                                                                         |
| `llmsTxt`       | `true`                                | Grava `/llms.txt` e `/llms-full.txt`.                                                                                                                     |
| `markdownTwins` | `true`                                | Grava uma cópia `.md` de cada página que tem `markdown`.                                                                                                  |
| `crawlerPolicy` | `"discoverable-no-training"`          | Define as regras do `robots.txt`: `"discoverable-no-training"`, `"allow-all"` ou `"disallow-all"`.                                                        |
| `crawlers`      | Nenhum                                | Substitui uma categoria de rastreadores: `training`, `search`, `userTriggered`, `codingAgents` ou `autonomousAgents`, cada uma `"allow"` ou `"disallow"`. |

A política padrão de rastreamento é "detectável, não treinável": busca, recuperação acionada pelo usuário, agentes de programação e agentes de navegação autônomos são permitidos; rastreadores de treinamento não são.

`jsonLd`, `publicAgentCard` e `publicMcp` são aceitos, mas nada os lê ainda. Para JSON-LD, renderize você mesmo `buildBaseJsonLd` e `buildPageJsonLd` de `@agent-native/core/agent-web` nas suas páginas.

## Fonte da verdade da rota {#route-source}

A lista de páginas é a fonte da verdade: os agentes recebem as páginas que você passa, e só elas. Monte-a com páginas que já são públicas:

- Em um app público, todas as rotas exceto `protectedPaths`.
- Em um app interno, apenas `publicPaths`.
- Páginas públicas de compartilhamento e de formulário que os agentes devem conseguir ler.
- Nunca dados privados enviados, painéis autenticados ou estado de usuário ou organização, mesmo quando uma página próxima é pública.

Para partir das suas configurações de acesso, `deriveAgentWebPublicRoutes` de `@agent-native/core/agent-web` recebe `audience`, `publicPaths`, `protectedPaths` e `routes` do seu app e retorna as rotas que essas configurações tornam públicas. Cada página ainda precisa do próprio título e do próprio Markdown.

Isso mantém os aplicativos mistos naturais. Um aplicativo de formulários pode expor uma página de formulário pública e manter os envios privados. Um aplicativo de conteúdo pode expor postagens publicadas e manter o editor privado. Um site de documentos pode expor tudo, exceto ferramentas administrativas.

## Páginas públicas não são ferramentas públicas {#public-tools}

O acesso à página pública e o acesso à ferramenta pública são separados. Uma rota pública significa apenas que os agentes podem ler essa rota como HTML, Markdown, entradas de mapa do site, entradas de llms e dados estruturados.

<Callout id="doc-block-s50w8y" tone="warning">

**Uma página pública não é uma ferramenta pública.** Tornar uma rota rastreável nunca expõe uma action. O acesso a ferramentas exige uma opção explícita `publicAgent.expose` na action.

</Callout>

Para expor uma ação por meio de um protocolo de agente público, a ação deve aceitar:

## Arquivos em tempo de compilação {#build-time}

Os utilitários de estrutura em `@agent-native/core/agent-web` geram os arquivos comuns a partir de uma lista de páginas:

```ts
import {
  buildAgentWebStaticFiles,
  normalizeAgentWebConfig,
} from "@agent-native/core/agent-web";

const config = normalizeAgentWebConfig(
  { crawlerPolicy: "discoverable-no-training" },
  { hasPublicRoutes: true },
);

const files = buildAgentWebStaticFiles({
  siteName: "My Agent-Native App",
  siteUrl: "https://example.com",
  description: "Public docs for my app.",
  config,
  pages: [
    {
      path: "/docs",
      title: "Docs",
      description: "Start here.",
      markdown: "# Documentos\n\nComece aqui.\n",
      markdownPath: "/docs/getting-started.md",
      lastmod: new Date(),
    },
  ],
});
```

`createAgentWebVitePlugin` chama `buildAgentWebStaticFiles` para você e grava os arquivos nas pastas que existirem entre `public`, `dist`, `dist/client`, `dist/server/public` e `build/client`. Com outra ferramenta de build, chame os utilitários diretamente.

Nenhum dos dois responde a `Accept: text/markdown` na URL da própria página: a cópia em Markdown fica só na URL `.md`. Para responder a esse cabeçalho, adicione uma rota de servidor que retorne o Markdown da página com os cabeçalhos de `buildMarkdownResponseHeaders`, como faz o site de documentação. Sem essa rota, a auditoria abaixo falha na verificação `Accept: text/markdown`.

Passe `sitemapGroup` para `buildAgentWebStaticFiles` ou `createAgentWebVitePlugin` para dividir um sitemap grande. A opção associa cada página a uma chave de grupo, como o idioma, e `sitemap.xml` passa a ser um índice de sitemaps com um `sitemap-<group>.xml` por grupo.

## Auditar um site {#audit}

Use a auditoria CLI em um site implantado ou em um servidor de produção local:

```bash
npx @agent-native/core@latest audit-agent-web --url https://www.agent-native.com
```

A auditoria verifica:

- SSR HTML visível.
- URLs canônicos.
- JSON-LD.
- Política `robots.txt` e mapa do site absoluto URL.
- Entradas absolutas no mapa do site.
- `/llms.txt` e `/llms-full.txt`.
- Espelhos Markdown.
- `Accept: text/markdown`.
- Nenhum bloqueio 401/403 acidental para agentes comuns de recuperação de agentes.

A auditoria sai diferente de zero se uma superfície pública obrigatória estiver faltando.
