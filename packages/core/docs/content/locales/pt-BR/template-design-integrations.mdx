# Design em um workspace com múltiplos apps

O Design é um aplicativo entre muitos em um workspace
[Dispatch](/docs/template-dispatch), e também pode ser alcançado
diretamente por agentes que vivem totalmente fora desse workspace. Esta
página cobre os dois casos: como a conexão com o Dispatch funciona, e como
um agente externo pode chamar as próprias actions do Design via MCP. Veja
[Design](/docs/template-design) para a visão geral.

## Como o Design se conecta ao Dispatch

Se isso é automático depende de como o Design e o Dispatch foram
configurados juntos, não de se um deles está hospedado ou em execução
local.

### Mesmo workspace: automático

Se o Design e o Dispatch foram gerados ou adicionados juntos em um único
workspace Agent-Native (via `create` ou `add-app`) e implantados como uma
única unidade, eles já compartilham um `.env`, um `A2A_SECRET` e um
registro de workspace. A descoberta e as chamadas A2A autenticadas
simplesmente funcionam, sem nada para configurar, esteja esse workspace em
execução na sua máquina ou em produção.

### Implantações separadas: um passo manual

Se o Design e o Dispatch são dois projetos Agent-Native criados de forma
independente, eles não compartilham um segredo e ainda não podem se
chamar. Conectá-los exige um passo manual em cada lado: adicionar um
recurso `remote-agents/<id>.json` com um segredo compartilhado, a partir
de Settings → Agent → Sub-agents (Connect agent), ou
Dispatch → Agentes → Adicionar agente externo. Veja [Protocolo
A2A](/docs/a2a-protocol) para o passo a passo completo.

Para verificar em qual situação você está, pergunte ao agente de qualquer
um dos aplicativos "quais aplicativos você consegue ver?" Se o Design
estiver ausente da resposta do Dispatch, você está no segundo caso.

## Chamando o Design de fora do workspace

O Design também funciona como um servidor MCP hospedado ao qual outros
agentes podem se conectar diretamente, façam ou não parte do seu workspace
Dispatch. Claude, Claude Code, Claude Desktop, Codex e outros hosts
compatíveis com MCP podem se conectar a:

```
https://design.agent-native.com/mcp
```

Claude e Claude Desktop adicionam isso como um conector personalizado e
fazem login para aprovar o acesso. Claude Code adiciona a mesma URL e
depois executa `/mcp` para autenticar. Codex e outros clientes CLI ou
stdio, em vez disso, executam `npx @agent-native/core@latest connect
https://design.agent-native.com`, o que abre uma aba do navegador para
autorizar e gera um token revogável por usuário, sem nenhum segredo
compartilhado envolvido.

Depois de conectado, o agente externo obtém o mesmo fluxo de trabalho
essencial coberto em [Conversar com o Agent](/docs/template-design-agent):
criar um design, gerar algumas direções para comparar, obter o estado
atual de uma tela, fazer uma edição delimitada e exportar um pacote de
handoff de código quando chegar a hora de transformar o resultado em
código real. O agente exibe uma pré-visualização inline ou um link "Abrir
design" de volta para o editor real, em vez de colar HTML bruto na
conversa.

<Callout tone="info">

Se uma chamada de ferramenta do Design no seu agente externo começar a
retornar um erro de sessão ou autenticação, não fique tentando de novo
repetidamente. Execute `/mcp` no Claude Code e reconecte, ou execute `npx
-y @agent-native/core@latest reconnect https://design.agent-native.com` em
qualquer terminal. Os dois reautenticam sem reinstalar nada.

</Callout>

## Delegando ao Design pelo Dispatch

Um aplicativo irmão não precisa de uma integração especial para funcionar
com o Design. Ele pode entregar ao agente do Design uma solicitação em
linguagem natural, como "me faça uma landing page para esta nova
funcionalidade," da mesma forma que você faria no chat, e o Design
responde ou age diretamente sobre ela.

O Design nunca precisa conhecer as credenciais do aplicativo solicitante,
nem vice-versa, para nada disso. Ele só precisa responder a uma
solicitação real. Não precisa saber quem está perguntando, ou por quê.
