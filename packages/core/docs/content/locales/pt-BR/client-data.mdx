# Dados e sincronização

A principal forma de ler e gravar dados do aplicativo a partir do cliente é através dos ganchos de [action](/docs/actions). Ao incorporar solicitações em actions, tanto seu cliente quanto o agente podem interagir com seu aplicativo da mesma maneira.

No exemplo abaixo, um ticket é atribuído ao usuário atual manualmente através de um dropdown, e depois através do agente de chat. Tanto a UI quanto o agente acessam a mesma action.

### Ganchos de action {#action-hooks}

Existem dois ganchos de action que você provavelmente vai usar: `useActionQuery()` e `useActionMutation()`. Esses dois ganchos dão acesso às actions do seu aplicativo.

#### useActionQuery {#use-action-query}

<Signature

  name="useActionQuery"
  params={[

    {
      name: "params",

        "A entrada da action, tipada a partir do esquema de `defineAction()`.",

      type: "UseQueryOptions",
      optional: true,
      description:
        "Tudo das [opções de useQuery](https://tanstack.com/query/latest/docs/framework/react/reference/useQuery), exceto `queryKey` e `queryFn`, que o gancho define por conta própria.",
    },
  ]}
  returns={{
    type: "UseQueryResult<TResult>",
    description:
      'Armazenado em cache sob `["action", name, params]`. Busca novamente de forma automática sempre que uma action de mutação é concluída, sem necessidade de invalidação manual.',
  }}
/>

Este gancho é destinado a actions somente leitura. É um wrapper leve em torno da função [useQuery()](https://tanstack.com/query/latest/docs/framework/react/reference/useQuery).

No exemplo abaixo, a action `list-tickets` é chamada. Isso é semelhante a fazer uma solicitação GET para todos os tickets.

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery("list-tickets", {});
```

O exemplo a seguir mostra uma solicitação para buscar um único ticket, através da action `get-ticket`. Um `ticketId` é fornecido para restringir a consulta a retornar apenas um ticket específico. A opção adicional `enabled` é fornecida para garantir que a consulta não seja executada automaticamente, e sim apenas quando um `ticketId` estiver presente.

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery(
  "get-ticket",
  { ticketId: ticketId ?? "" },
  { enabled: Boolean(ticketId) },
);
```

  }}
/>

Este gancho é destinado a actions que alteram dados, como criar, atualizar ou enviar algo. É um wrapper leve em torno da função [useMutation()](https://tanstack.com/query/latest/docs/framework/react/reference/useMutation).

Diferente de `useActionQuery()`, a entrada da action não é passada para o gancho em si. Ela é passada para `mutate()` ou `mutateAsync()` quando você estiver pronto para executar a mutação.

No exemplo abaixo, a action `send-ticket-reply` é chamada para postar uma resposta em um ticket. Chame `mutate()` a partir de um manipulador de evento, como o `onClick` de um botão.

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply");

mutate({ ticketId, body: draft });
```

O exemplo a seguir mostra a mesma mutação com uma opção `onSuccess`. A invalidação de cache acontece automaticamente após cada mutação, então `onSuccess` só é necessário para efeitos colaterais locais, como limpar o composer de resposta depois que a resposta é enviada.

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply", {
  onSuccess: () => setDraft(""),
});

mutate({ ticketId, body: draft });
```

    description:
      "Diferente dos ganchos acima, não há cache e nenhuma nova busca automática. Combine com uma invalidação manual se outra UI depender do resultado.",
  }}
/>

Esta função é destinada a chamadas de action imperativas e pontuais fora de um fluxo de renderização React, como um manipulador de evento simples, um script, ou qualquer outro caminho de código que não seja React. Ela retorna uma promise diretamente, em vez de um resultado de gancho.

No exemplo abaixo, a action `update-ticket` é chamada a partir de um manipulador de atalho de teclado fora do fluxo de renderização do React, atribuindo o ticket a um representante.

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction("update-ticket", {
  ticketId,
  assignedToEmail: "jordan@example.com",
});
```

O exemplo a seguir mostra a mesma chamada com uma opção `timeoutMs`, útil para actions que legitimamente demoram mais do que o tempo limite padrão de 60 segundos.

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction(
  "update-ticket",
  { ticketId, assignedToEmail: "jordan@example.com" },
  { timeoutMs: 120_000 },
);
```

Toda solicitação `useActionQuery()`, `useActionMutation()` e `callAction()` é limitada por um tempo limite de 60 segundos, e os tempos limite surgem como erros em vez de tentar novamente silenciosamente. `useActionQuery()` também cancela solicitações substituídas automaticamente, usando o abort signal do React Query.

        },

Este gancho é destinado a manter a UI sincronizada com mudanças no banco de dados que ocorrem fora das suas próprias actions, como uma gravação do agente, um webhook, ou uma mudança feita em outra aba do navegador. Ele escuta mudanças por server-sent events, e recorre à pesquisa quando server-sent events não estão disponíveis.

```ts
import { useDbSync } from "@agent-native/core/client/hooks";
import { useQueryClient } from "@tanstack/react-query";

function App() {
  const queryClient = useQueryClient();

  useDbSync({
    queryClient,
    pollUrl: "/_agent-native/poll",
    onEvent: (data) => console.log("Data changed:", data),
  });

  return <div>...</div>;
}
```

Para CRUD normal, prefira `useActionQuery()` e `useActionMutation()`. Actions de mutação emitem `source: "action"`, então esses ganchos buscam novamente imediatamente. Mudanças do agente, de um webhook, ou de outra aba chegam através de `useDbSync()` em vez disso, via SSE ou o fallback de pesquisa. Se uma chamada `useQuery()` bruta precisa sincronizar em uma chave personalizada, veja [Sincronização interna](/docs/client-sync-internals). Se você precisa gravar diretamente em `application_state`, veja [Avançado](/docs/client-advanced).
