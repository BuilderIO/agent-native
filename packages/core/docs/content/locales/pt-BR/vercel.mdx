# Vercel

```ts filename="vite.config.ts"
export default defineConfig({
  plugins: [agentNative({ nitro: { preset: "vercel" } })],
});
```

Implante via Vercel CLI ou git push:

```bash
npx vercel deploy
```

Para criar uma prévia descartável sem entrar no Vercel, execute
`npx vercel deploy --temporary`. Implantações temporárias não preservam as
variáveis de ambiente do projeto. Passe o banco de dados e os segredos com
`--env` e `--build-env` quando precisar de mais que uma prévia da interface.

Para um espaço de trabalho, compile todos os apps em um único pacote da Vercel Build Output API:

```bash
npx @agent-native/core@latest deploy --preset vercel
```

Para implantações via Vercel Git, defina o comando de build como:

```bash
npx @agent-native/core@latest deploy --preset vercel --build-only
```

O build do espaço de trabalho copia a saída `vercel` do Nitro de cada app para o `.vercel/output` raiz, dá a cada função seu próprio ambiente de caminho de montagem, e grava a configuração de rota que serve os apps em `/<app-id>`.

## Trabalho agendado {#vercel-scheduled-work}

Automações agendadas, automações por evento na fila e a limpeza de execuções
interrompidas acontecem em uma varredura executada uma vez por minuto. O build
adiciona um [cron job da Vercel](https://vercel.com/docs/cron-jobs) que chama a
varredura em `/_agent-native/jobs/_process-sweep`. Um build de espaço de
trabalho adiciona um cron job por app, em
`/<app-id>/_agent-native/jobs/_process-sweep`.

Defina `CRON_SECRET` nas variáveis de ambiente do projeto antes de implantar. A
Vercel o envia como bearer token em cada requisição de cron, e a varredura
rejeita toda requisição sem ele. Gere um valor com `openssl rand -hex 32`.

- **Somente produção.** A Vercel executa cron jobs na implantação de produção,
  nunca em prévias, então os agendamentos não disparam em uma prévia. A página
  **Automations** informa isso.
- **No Hobby, uma vez por dia.** A Vercel rejeita uma implantação Hobby cujo
  cron job rode mais de uma vez por dia. Defina
  `AGENT_NATIVE_VERCEL_CRON_SCHEDULE` no ambiente de build com uma expressão
  diária, como `0 9 * * *`. No Hobby, a execução também pode acontecer a
  qualquer momento dentro dessa hora. Com uma varredura por dia, automações
  agendadas e acionadas por eventos esperam até um dia, então use o Pro ou outro
  host quando o horário importar.
- **Duração da função.** A varredura executa os trabalhos vencidos dentro da
  invocação de função do cron job, então um trabalho é interrompido ao atingir a
  duração máxima da função (300 segundos por padrão).
- **Sem novas tentativas.** A Vercel não repete uma invocação de cron que
  falhou. A varredura roda de novo no próximo horário agendado.

Veja [Como o agendador é executado](/docs/recurring-jobs#how-scheduler-runs)
para os outros hosts.
