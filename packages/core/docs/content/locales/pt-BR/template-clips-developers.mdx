# Guia do desenvolvedor

Esta página é para qualquer pessoa que esteja personalizando o template Clipes ou estendendo-o: o início rápido, todas as actions, o modelo de dados, a superfície de rotas e como adicionar a ela. Veja [Clipes](/docs/template-clips) para o que o aplicativo faz.

## Início rápido

<Steps>

### Crie o aplicativo

```bash
npx @agent-native/core@latest create my-clips --standalone --template clips
cd my-clips
pnpm install
```

Isso requer [Node.js](https://nodejs.org) 22.22 ou posterior e [pnpm](https://pnpm.io) instalados primeiro. Veja [Primeiros passos](/docs/getting-started) se você ainda não instalou nenhum dos dois, ou não tem uma conexão LLM (Builder.io, uma chave Anthropic/OpenAI, ou Ollama local) configurada.

### Inicie o servidor de desenvolvimento

```bash
pnpm dev
```

O aplicativo abre automaticamente no seu navegador. A gravação funciona sem nenhuma configuração extra, já que o navegador ou o aplicativo de desktop captura localmente. Você só vai encontrar um erro em uma action que precisa de armazenamento de arquivos ou de créditos de IA antes que um dos dois esteja configurado.

</Steps>

<Callout tone="info">

Gravação, transcrição e títulos/resumos de IA precisam de armazenamento de arquivos e créditos de IA configurados antes de funcionarem de ponta a ponta. Conecte o Builder.io em **Configurações** para os dois de uma vez (seu plano gratuito inclui créditos de IA gerenciados), ou conecte um armazenamento compatível com S3 separadamente e use sua própria chave do Groq para a transcrição. Veja [Transcrição e metadados de IA](/docs/template-clips-features#transcription-and-ai-metadata).

</Callout>

## Inventário de actions

Cada operação é um arquivo TypeScript em `templates/clips/actions/`, montado automaticamente em `POST /_agent-native/actions/:name`.

### Biblioteca e gravações

| Action                                                                                    | O que faz                                                                             |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `list-recordings`, `search-recordings`                                                    | Listagem da biblioteca, compartilhado comigo, lixeira e com escopo de espaço          |
| `create-recording`, `finalize-recording`                                                  | Cria a linha; finaliza o upload                                                       |
| `import-loom-recording`                                                                   | Importa um vídeo do Loom ou uma URL direta de MP4/WebM                                |
| `update-recording`                                                                        | Título, descrição, senha, expiração, visibilidade                                     |
| `move-recording`                                                                          | Move uma ou várias gravações para uma pasta ou para a raiz                            |
| `archive-recording`, `trash-recording`, `restore-recording`, `delete-recording-permanent` | Ciclo de vida: esconder, excluir de forma reversível, desfazer ou excluir para sempre |
| `reprocess-recording`                                                                     | Repara mídia não navegável ou congelada                                               |
| `generate-filmstrip`                                                                      | Sprite de quadros da linha do tempo do editor                                         |
| `tag-recording`, `set-thumbnail`                                                          | Marcação com tags e uma miniatura escolhida manualmente                               |

## Modelo de dados

Definido em `templates/clips/server/db/schema.ts`.

<Callout tone="warning">

As linhas de equipe, membro e convite vivem nas próprias tabelas `organizations`, `org_members` e `org_invitations` do framework, não em uma tabela específica do Clipes. `organization_settings` é o arquivo secundário do próprio Clipes: cor da marca, logotipo e visibilidade padrão, uma linha por organização. Um par `workspaces`/`workspace_members` mais antigo ainda existe apenas para que uma migração única de inicialização possa preencher retroativamente as tabelas do framework em uma implantação existente. Não construa novas funcionalidades sobre eles.

</Callout>

## Uma action explicada passo a passo

`create-recording-agent-link` mostra padrões que vale a pena reutilizar em qualquer action que gera uma credencial com escopo definido: verificar o estado real do recurso antes de entregar qualquer coisa, delegar a geração real do token a um helper compartilhado do framework em vez de criar a sua própria, e derivar toda URL que um chamador precisa a partir dessa única concessão.

<AnnotatedCode
  id="doc-block-clips-agent-link"
  title="Gerando um link de acesso de agente com escopo definido"
  filename="templates/clips/actions/create-recording-agent-link.ts"
  language="ts"
  code={
    'import { defineAction } from "@agent-native/core/action";\nimport {\n  buildAgentAccessUrl,\n  createScopedAgentAccessGrant,\n  getRequestContext,\n  getRequestUserEmail,\n} from "@agent-native/core/server";\nimport { ForbiddenError, resolveAccess } from "@agent-native/core/sharing";\nimport { z } from "zod";\n\nimport {\n  CLIPS_AGENT_ACCESS_TTL_SECONDS,\n  getServerAppBasePath,\n} from "../server/lib/public-agent-context.js";\nimport {\n  buildAgentApiUrls,\n  CLIP_AGENT_ACCESS_TOKEN_PREFIX,\n} from "../shared/agent-context.js";\nimport { BUG_REPORT_AGENT_ACCESS_TTL_SECONDS } from "../shared/bug-report.js";\n\nfunction appOrigin(): string {\n  const origin =\n    getRequestContext()?.requestOrigin ||\n    process.env.APP_URL ||\n    process.env.BETTER_AUTH_URL ||\n    "http://localhost:3000";\n  try {\n    return new URL(origin).origin;\n  } catch {\n    return "http://localhost:3000";\n  }\n}\n\nexport default defineAction({\n  description:\n    "Create a temporary private agent-readable link for one Clips recording. The URL is scoped to that recording and expires after two hours.",\n  schema: z.object({\n    recordingId: z.string().describe("Recording ID"),\n    agentLabel: z\n      .string()\n      .trim()\n      .min(1)\n      .max(60)\n      .optional()\n      .describe(\n        "Name of the agent that will read this link (e.g. \'Fusion\', \'Claude Code\'). Recorded against every read the link produces, so the owner sees a name instead of an unidentified agent.",\n      ),\n    ttlSeconds: z\n      .number()\n      .int()\n      .positive()\n      .max(BUG_REPORT_AGENT_ACCESS_TTL_SECONDS)\n      .optional()\n      .describe(\n        "Optional scoped-link lifetime in seconds, capped at seven days. Defaults to two hours.",\n      ),\n  }),\n  readOnly: true,\n  run: async (args) => {\n    const access = await resolveAccess("recording", args.recordingId);\n    if (!access) {\n      throw new ForbiddenError(`No access to recording ${args.recordingId}`);\n    }\n\n    const recording = access.resource as {\n      id: string;\n      archivedAt?: string | null;\n      trashedAt?: string | null;\n    };\n    if (recording.archivedAt || recording.trashedAt) {\n      throw new ForbiddenError(\n        `Recording ${args.recordingId} is not shareable`,\n      );\n    }\n\n    const grant = createScopedAgentAccessGrant({\n      resourceKind: CLIP_AGENT_ACCESS_TOKEN_PREFIX,\n      resourceId: recording.id,\n      viewerEmail: getRequestUserEmail() || undefined,\n      agentLabel: args.agentLabel,\n      ttlSeconds: args.ttlSeconds ?? CLIPS_AGENT_ACCESS_TTL_SECONDS,\n    });\n    const origin = appOrigin();\n    const basePath = getServerAppBasePath();\n    const pageUrl = buildAgentAccessUrl({\n      path: `/share/${encodeURIComponent(recording.id)}`,\n      origin,\n      basePath,\n      token: grant.token,\n    });\n    const api = buildAgentApiUrls(recording.id, {\n      origin,\n      basePath,\n      token: grant.token,\n    });\n\n    return {\n      recordingId: recording.id,\n      url: pageUrl,\n      contextUrl: api.contextUrl,\n      expiresAt: grant.expiresAt,\n      ttlSeconds: grant.ttlSeconds,\n    };\n  },\n});\n'

## Personalizando

Cada parte do aplicativo é código-fonte editável. Comece aqui:

- `templates/clips/actions/` — adicione um novo arquivo com `defineAction` para expor uma nova capacidade tanto ao agente quanto ao frontend.
- `templates/clips/app/routes/` — a interface, listada acima.
- `templates/clips/server/db/schema.ts` — adicione colunas ou tabelas com Drizzle. Mantenha o esquema compatível com PostgreSQL para que o template funcione com o PGlite local e o Postgres hospedado.
- `templates/clips/server/lib/` — integrações de provedor: `google-calendar-client.ts`, `s3-upload-provider.ts`, `slack-oauth.ts`, `video-remux.ts`, `video-filmstrip-sprite.ts`.
- `templates/clips/AGENTS.md` — instruções do agente. Atualize isso quando você ensinar ao agente novas capacidades ou convenções.
- `templates/clips/.agents/skills/` — padrões detalhados que o agente segue. Skills relevantes: `recording`, `ai-video-tools`, `video-editing`, `video-sharing`, `screen-memory`.
- `templates/clips/shared/api.ts` — os tipos TypeScript compartilhados usados tanto pelo servidor quanto pelo cliente.
- `templates/clips/desktop/` e `templates/clips/chrome-extension/` — pacotes separados para as superfícies de captura nativas, cada um com seu próprio `package.json` e build.

Se você adicionar um recurso, lembre-se de atualizar todas as quatro áreas: UI, action, skill ou entrada no AGENTS.md, e qualquer estado da aplicação que o agente precise ver. É isso que mantém o agente e a UI em paridade.
