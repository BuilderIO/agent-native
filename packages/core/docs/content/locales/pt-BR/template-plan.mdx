# Visual Plans

O Agent-Native Plans é o modo de plano visual para agentes de codificação. Ele
transforma um plano de implementação comum do Codex, do Claude Code, em
Markdown ou colado em uma superfície de revisão estruturada com rich text,
diagramas, wireframes, roteiros de código anotado e árvores de arquivos,
comentários e links compartilháveis.

Tudo se resume a dois comandos. `/visual-plan` cria um plano **antes** de o
agente escrever código. `/visual-recap` transforma uma mudança que **já
aconteceu** — um PR, commit, branch ou diff do Git — em uma revisão de código
visual de alto nível. Os dois abrem a mesma superfície de revisão, então você
anota, comenta e devolve feedback ao agente da mesma forma nas duas vezes.

## O que ele substitui

<Comparison>

### Antes

- Um plano existe como uma parede de texto no chat ou em um arquivo Markdown,
  e revisá-lo significa ler do início ao fim para encontrar o único
  parágrafo com o qual você discorda.
- O feedback acontece em uma thread do Slack ou em comentários dispersos,
  desconectados do próprio plano.
- Revisar um PR pronto significa ler um diff bruto linha por linha para
  reconstruir o que mudou e por quê.

### Depois

- O plano é renderizado como diagramas, wireframes, código anotado e um
  formulário de Perguntas Abertas ao qual você pode reagir diretamente.
- Os comentários se fixam no texto, imagem ou local exato do wireframe, e
  podem ser direcionados ao agente ou a um revisor humano.
- `/visual-recap` transforma um PR, commit ou diff na mesma revisão visual,
  em vez de um diff bruto.

</Comparison>

Exporte o resultado como HTML, Markdown ou JSON para uma cópia compatível com
controle de versão, ou mantenha-o totalmente fora do banco de dados hospedado
com o modo de arquivos locais. Veja
[Revisando e comentando em Plans](/docs/template-plan-review-workflow) e
[Modo de arquivos locais e sincronização com o desktop](/docs/template-plan-local-and-desktop)
para se aprofundar em cada um deles.

## Primeiros passos {#get-started}

<Steps>

### Instale a habilidade {#install}

A maioria das pessoas instala o Plan como uma **habilidade** para o agente de
codificação que já usa, não como um aplicativo scaffolded. Este único comando
instala as instruções da habilidade, registra o conector MCP hospedado do
Plans e faz login nele:

```bash
npx @agent-native/core@latest skills add visual-plan
```

Isso instala três comandos de barra — `/visual-plan`, `/visual-recap` e
`/visualize-repo` — além do conector MCP `plan` (um servidor de ferramentas
remoto com o qual o seu agente conversa) em
`https://plan.agent-native.com/mcp`. Para a referência completa de flags, as
rotas de instalação por plugin/marketplace para Claude Code e Codex, e a
extensão para VS Code, veja
[Plugin e marketplace do Plan → Rotas de instalação](/docs/plan-plugin#install).

Personalizar o próprio template do Plan — auto-hospedá-lo ou construir
diretamente sobre ele — é um caminho separado e secundário, coberto em
[Estendendo o Plan](/docs/template-plan-developers). A maioria das pessoas
nunca precisa dele.

### Peça ao seu agente o comando certo para o trabalho

- "Use `/visual-plan` antes de mudar o fluxo de autenticação."
- "Crie um `/visual-plan` para a nova tela de onboarding com estados mobile e
  desktop."
- "Rode `/visual-recap` neste PR para eu revisar o formato da mudança
  primeiro."
- "Use `/visual-recap` no diff entre `main` e esta branch."
- "Rode `/visualize-repo` e comece pelas nossas actions de API pública e pelo
  schema."

`/visual-plan` traz diagramas, wireframes, mockups, protótipos clicáveis e
código anotado conforme o trabalho exigir. O agente inspeciona o código
primeiro, e então o link retornado abre a UI de revisão no seu navegador ou
no VS Code.

### Revise como convidado, sem precisar de conta

As pessoas com quem você compartilha um plano não precisam instalar nada.
Elas abrem o editor do Plans e **criam e editam sem cadastro** — trabalham
como convidados. Fazer login só é necessário para **salvar ou compartilhar**
o próprio trabalho, e se um convidado fizer login depois, todo plano que ele
criou como convidado é **reivindicado** pela conta dele.

</Steps>

Quando já existe um plano do Codex, do Claude Code, em Markdown ou colado,
use `/visual-plan`; o agente preserva esse plano de origem e constrói a
partir dele a superfície de revisão mais rica, em vez de começar do zero. Se
a primeira passada ainda tiver decisões em aberto, o agente pode adicionar um
formulário de **Perguntas Abertas** no final do plano — respondê-lo e
enviá-lo de volta inicia uma rodada de revisão.

<Callout tone="info">

**Convidado versus conectado, em resumo**

- **Como convidado** você pode abrir um link compartilhado, criar um novo
  plano, editar texto e usar o modo de anotação de revisão — sem precisar de
  conta.
- **Fazer login** também permite salvar seus próprios planos
  permanentemente, publicar um plano em um link compartilhável, conceder
  acesso de visualizador/editor/administrador a outras pessoas, publicar
  comentários que notificam pessoas por e-mail, e excluir ou restaurar
  planos que você possui.

</Callout>

## Custo e escolha do modelo

Gerar um plano ou uma recapitulação executa uma sessão agêntica completa no
LLM do seu agente de codificação, não um preenchimento leve de template — o
custo escala com o tamanho do diff ou do plano e com o modelo escolhido.

- O modelo de chat padrão do aplicativo é o GPT-5.6 Luna. Conexões diretas
  com a Anthropic mantêm o Claude Sonnet 5 como padrão. Troque de modelo a
  qualquer momento em **Configurações**; o Haiku é a opção mais barata da
  Claude.
- Recapitulações automáticas de PR pela GitHub Action rodam separadamente do
  aplicativo interativo e têm seus próprios controles de modelo e custo —
  veja [Recapitulação Visual de PR](/docs/pr-visual-recap) para
  `VISUAL_RECAP_MODEL`, `VISUAL_RECAP_AGENT` e `VISUAL_RECAP_REASONING`.

## Solicitando acesso a um plano privado {#request-access}

Se alguém abrir um link de plano ao qual não tem permissão de acesso, o
Plans não mostra apenas um beco sem saída. A página informa que o plano é
privado e oferece uma ação de **Solicitar acesso**, que:

- Exige estar conectado (um convidado é solicitado a fazer login primeiro).
- Registra a solicitação em relação ao plano e, quando a implantação tem
  e-mail configurado, envia uma mensagem ao dono do plano com o nome de quem
  solicitou e um link para abrir o plano e compartilhá-lo de volta, se
  aprovado.
- É seguro clicar mais de uma vez — o Plans verifica primeiro se você já tem
  acesso, então uma segunda solicitação da mesma pessoa não inunda o dono
  com e-mails duplicados.

Se a visibilidade do plano estiver definida como **org** em vez de
totalmente privada, e sua conta já tiver um convite pendente para essa
organização ou um domínio de e-mail que corresponda a ela, o Plans oferece
entrar na organização diretamente em vez de enviar uma solicitação.

<Callout tone="warning">

Se uma ferramenta do Plans retornar `needs auth`, `Unauthorized` ou `Session
terminated`, não fique tentando de novo. Reautentique com
`npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex`,
ou rode novamente `/mcp` → **Authenticate** para um host compatível com
OAuth. Inicie uma nova thread do Codex ou reinicie/recarregue o cliente
depois — o registro de ferramentas só reconhece a mudança em uma sessão
nova.

</Callout>
