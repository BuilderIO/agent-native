# Netlify

A Netlify hospeda o seu app para você, então não há nenhum servidor para configurar ou manter em execução.
O build transforma o app em arquivos estáticos que a Netlify serve diretamente e em funções que a Netlify
executa sob demanda. Além disso, a Netlify dá ao app um endereço público com HTTPS.

Este guia mostra como implantar um app independente do zero. Você vai
criar o app, dar a ele um banco de dados de produção e um segredo de autenticação, criar um
site da Netlify para ele, preparar o banco de dados e, depois, fazer o build e implantá-lo.

<Callout tone="info">

É necessário o Node.js `22.22+`.

</Callout>

Você também precisa de uma conta da Netlify. Execute os comandos deste guia no seu próprio
computador. A Netlify CLI envia o build finalizado para a Netlify para você.

## Passo 1: Crie o app {#step-1-create-the-app}

Crie o seu novo app independente. O exemplo abaixo cria um app a partir do template Chat,
mas você pode começar de qualquer template. Entre na pasta do app e
instale as dependências. `corepack enable` ativa a versão do `pnpm` que o app
espera, então você não precisa instalar o `pnpm` por conta própria.

```bash
npx --yes @agent-native/core@latest create my-app --standalone --template chat

cd my-app

corepack enable

pnpm install
```

Se quiser, substitua `my-app` pelo nome do seu app. O restante deste guia
considera que você está dentro da pasta do app.

## Passo 2: Configure os segredos do ambiente {#step-2-configure-environment-secrets}

O app lê as configurações de produção a partir de variáveis de ambiente:

| Variável             | Obrigatória | Finalidade                                                   |
| -------------------- | ----------- | ------------------------------------------------------------ |
| `DATABASE_URL`       | Sim         | Conecta o app ao seu banco de dados PostgreSQL               |
| `BETTER_AUTH_SECRET` | Sim         | Assina as sessões dos usuários                               |
| `BETTER_AUTH_URL`    | Não         | Define o endereço público que as pessoas usam para acessar o seu app |

Os exports abaixo fazem os comandos seguintes funcionarem neste shell. Antes de
implantar, salve essas mesmas variáveis nas configurações de ambiente do projeto ou serviço do seu host.
O próximo passo mostra como salvá-las na Netlify.

### URL do banco de dados {#database-url}

Durante o desenvolvimento local, o app armazena os dados em um banco de dados local quando
`DATABASE_URL` não está definida. Um app implantado precisa de um banco de dados PostgreSQL real que
mantenha os dados entre implantações. A Netlify não mantém arquivos entre requisições, então
o banco de dados precisa ficar fora das funções da Netlify. Copie a string de conexão
do seu provedor e exporte-a:

```bash
export DATABASE_URL='your-postgres-url-string'
```

Os [guias de provedores de banco de dados](/docs/neon) mostram onde encontrar a string de conexão
de cada provedor.

<Callout tone="warning">

Escolha um provedor de PostgreSQL persistente, como Neon, Supabase ou Amazon RDS.

</Callout>

### Segredo de autenticação {#auth-secret}

Gere este valor uma única vez e mantenha-o igual em todas as implantações.

O app usa `BETTER_AUTH_SECRET` para assinar as sessões dos usuários. Se ele mudar, todos os
usuários conectados são desconectados. O comando abaixo gera um valor aleatório:

```bash
export BETTER_AUTH_SECRET="$(openssl rand -hex 32)"
```

Salve o valor gerado em um lugar seguro, como um gerenciador de senhas. Use o
mesmo valor sempre que implantar.

### URL pública {#public-url}

É opcional. Defina-a ao usar um domínio personalizado, um proxy reverso ou um fluxo de autenticação ou OAuth
que precise de uma origem pública fixa.

`BETTER_AUTH_URL` é o endereço público que as pessoas usam para acessar o seu app. Sem
ela, o app descobre o próprio endereço a partir de cada requisição recebida. Isso normalmente
funciona bem no endereço que a Netlify fornece, mas defina-a quando conectar um domínio
personalizado, para que os links de login e os redirecionamentos de OAuth usem esse domínio.

```bash
export BETTER_AUTH_URL='https://your-domain.example'
```

## Passo 3: Vincule o site e salve os segredos {#step-3-link-the-site-and-save-the-secrets}

Faça login na Netlify pela linha de comando e, depois, crie um site novo para o app.
Por enquanto, você pode deixar o nome do projeto padrão e deixar o repositório do GitHub em branco.

```bash
npx netlify login

npx netlify sites:create --name my-app
```

`sites:create` cria o site e o vincula à pasta do app, para que os comandos seguintes
saibam qual site usar. O nome também se torna o endereço do site, por exemplo
`my-app.netlify.app`. Os nomes de site são compartilhados em toda a Netlify, então escolha
outro nome se `my-app` já estiver em uso. Você não precisa de um repositório do GitHub,
porque você implanta o app a partir do seu computador no Passo 5.

Salve as duas variáveis obrigatórias no ambiente do site:

```bash
npx netlify env:set DATABASE_URL "$DATABASE_URL"

npx netlify env:set BETTER_AUTH_SECRET "$BETTER_AUTH_SECRET"
```

Cada comando lê o valor que você exportou no Passo 2 e o salva na Netlify, então
você não precisa colar os segredos manualmente. Se você definir `BETTER_AUTH_URL`, salve-a
da mesma forma. Você também pode ver e alterar esses valores depois nas configurações
do site no painel da Netlify.

## Passo 4: Execute as migrações {#step-4-migrate}

As migrações criam e atualizam as tabelas de que o app precisa no seu banco de dados. Execute
isto antes da primeira implantação:

```bash
pnpm migrate:production
```

O comando é executado no seu computador e se conecta ao banco de dados de produção com
a `DATABASE_URL` que você exportou no Passo 2. Execute-o novamente depois de atualizar o
app e antes de implantar a nova versão.

## Passo 5: Implante {#step-5-deploy}

Faça o build do app para a Netlify:

```bash
NITRO_PRESET=netlify pnpm build
```

`NITRO_PRESET=netlify` faz o build do app no formato que a Netlify espera. O build
grava os arquivos estáticos do app na pasta `dist` e as funções de servidor na
pasta `.netlify/functions-internal`.

Envie o build e publique-o:

```bash
npx netlify deploy --prod --dir=dist --functions=.netlify/functions-internal
```

`--dir` e `--functions` informam à CLI onde encontrar os arquivos estáticos e as
funções que você acabou de gerar. `--prod` os publica no seu endereço de produção
em vez de em uma prévia de rascunho.

Quando o comando termina, ele mostra o endereço de produção do app. Abra-o e
crie a primeira conta.

## Implante atualizações {#deploy-updates}

Para publicar uma nova versão, execute novamente os comandos de migração, build e implantação a partir
da pasta do app:

```bash
pnpm migrate:production

NITRO_PRESET=netlify pnpm build

npx netlify deploy --prod --dir=dist --functions=.netlify/functions-internal
```

O vínculo do site e as variáveis salvas continuam no lugar, então você não precisa
repetir o Passo 3.

## Keep-warm e bancos de dados com escala a zero {#netlify-keep-warm}

Depois de um período de inatividade, a primeira requisição pode demorar enquanto a Netlify inicia a
função e um banco de dados com escala a zero, como o nível gratuito do Neon, é reativado.
O Agent-Native pode reduzir essa espera com o keep-warm. Quando ele está ativado, o
build adiciona uma função agendada da Netlify que chama o endpoint
`/_agent-native/health` do app **a cada minuto**, o que mantém ativos a função
do servidor e o banco de dados dela.

O keep-warm fica **desativado por padrão**. Manter o banco de dados ativo impede que ele
seja suspenso, o que consome a cota de computação em planos gratuitos ou medidos. Se a cota
acabar, o banco de dados rejeita **todas** as leituras e o app para de funcionar. Defina
`AGENT_NATIVE_ENABLE_KEEP_WARM=1` quando uma primeira visita mais rápida valer o tempo extra
de banco de dados.

Estas variáveis controlam o keep-warm. As configurações de programação e de segundo plano só
se aplicam depois que você ativa `AGENT_NATIVE_ENABLE_KEEP_WARM`:

| Variável                                    | Efeito                                                                                                                                                                          |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AGENT_NATIVE_ENABLE_KEEP_WARM`             | Ativa o aquecimento agendado da função do servidor e do banco de dados. Não definida por padrão.                                                                                |
| `AGENT_NATIVE_DISABLE_KEEP_WARM`            | Desativa o keep-warm mesmo quando `AGENT_NATIVE_ENABLE_KEEP_WARM` está definida. Mantida para compatibilidade com configurações antigas.                                         |
| `AGENT_NATIVE_KEEP_WARM_SCHEDULE`           | Altera a frequência do aquecimento com uma expressão cron de 5 campos, como `*/5 * * * *`. O padrão é `* * * * *`, a cada minuto. Um valor que não seja um cron válido **faz o build falhar**. |
| `AGENT_NATIVE_DISABLE_KEEP_WARM_BACKGROUND` | Pula o aquecimento da função em segundo plano e continua aquecendo a função do servidor. Aquecer o servidor é uma única requisição. Aquecer a função em segundo plano inicia um container novo que verifica o schema do banco de dados novamente. |

Se o seu banco de dados estiver em um plano gratuito ou limitado de outra forma, deixe
`AGENT_NATIVE_ENABLE_KEEP_WARM` sem definir. Se você ativá-lo, escolha uma programação mais lenta
ou defina `AGENT_NATIVE_DISABLE_KEEP_WARM_BACKGROUND=1` para pular o aquecimento em segundo plano,
que é mais caro.

O build lê essas variáveis, não o app em execução. Como você faz o build no seu
próprio computador no Passo 5, defina-as no mesmo shell antes do build. Salvá-las
nas configurações do site da Netlify não tem efeito em um build executado localmente. Por
exemplo, para ativar o keep-warm com uma programação de cinco minutos:

```bash
export AGENT_NATIVE_ENABLE_KEEP_WARM=1

export AGENT_NATIVE_KEEP_WARM_SCHEDULE='*/5 * * * *'

NITRO_PRESET=netlify pnpm build
```

Depois, implante normalmente.
