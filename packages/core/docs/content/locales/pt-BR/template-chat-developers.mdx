# Guia do desenvolvedor

Esta página é para desenvolvedores que executam ou estendem o template Chat.
Ela cobre o início rápido, todas as actions integradas, o modelo de dados,
uma action explicada passo a passo, as rotas e como adicionar sua primeira
funcionalidade. Veja [Chat](/docs/template-chat) para o que o aplicativo faz.

## Início rápido {#quick-start}

Isso percorre a execução do Chat desde nada instalado até uma conversa ao
vivo com o agente. Os comandos são idênticos seja no Terminal do macOS ou no
PowerShell/Prompt de Comando do Windows, eles são apenas ferramentas
Node.js.

<Steps>

### Crie o aplicativo

```bash
npx --yes @agent-native/core@latest create my-chat-app --standalone --template chat
cd my-chat-app
corepack enable
pnpm install
```

Isso requer [Node.js](https://nodejs.org) 22.22 ou posterior. Se o `pnpm` não
estiver no seu `PATH`, execute `corepack enable` no aplicativo gerado. Veja
[Primeiros passos](/docs/getting-started) se você ainda não instalou o
Node.js.

### Inicie o servidor de desenvolvimento

```bash
pnpm dev
```

O aplicativo abre na URL local exibida pelo `pnpm dev`. Se não abrir
automaticamente, acesse essa URL no seu navegador. A porta pode mudar quando
a 8080 já estiver em uso.

### Faça login e conecte um LLM

Na tela de boas-vindas, selecione **Continuar como dev local**. Não é
necessário e-mail nem senha para o desenvolvimento local. Depois, conecte um
LLM: selecione **Usar Builder.io** para ganhar créditos gratuitos, ou
**Adicionar suas próprias chaves** para usar uma chave de provedor de modelo
sua. O Chat não vem com dados de domínio para popular, então, assim que um
LLM estiver conectado, não há mais nada para configurar antes de você poder
começar a conversar.

</Steps>

O Chat foi feito para uma interface de navegador. Se você quer um agente sem
nenhuma tela, para jobs agendados, filas, loops de CLI ou fluxos de agentes
externos, crie o projeto com `--headless`:

```bash
npx --yes @agent-native/core@latest create my-agent --headless
```

A ideia central continua a mesma. As actions são a superfície compartilhada
para chat, interface, HTTP, MCP, A2A e CLI. Veja
[Apps de automação primeiro](/docs/pure-agent-apps) para esse caminho em
profundidade.

## Inventário de actions {#actions}

Cada operação é um arquivo TypeScript em `actions/`, montado automaticamente
em `POST /_agent-native/actions/:name`, a menos que a action defina
`http: false`.

| Action                 | O que faz                                                                         |
| ---------------------- | --------------------------------------------------------------------------------- |
| `hello`                | Action de exemplo. Retorna uma saudação. Substitua-a ou adicione actions ao lado. |
| `view-screen`          | Action de contexto padrão. Lê a visualização atual de volta para o agente.        |
| `navigate`             | Action de navegação padrão. Move a interface para uma rota.                       |
| `provider-api-request` | Chama a API Web do Slack por meio de um workspace do Slack conectado.             |

### O runtime do chat {#chat-runtime}

`server/plugins/agent-chat.ts` é onde o runtime do chat é configurado. Ele
faz quatro coisas:

- Registra cada action em `actions/` como uma ferramenta chamável, com
  `loadActionsFromStaticRegistry`.
- Resolve a organização atual para delimitar o escopo, com `resolveOrgId`.
- Define o prompt do sistema.
- Declara quais ferramentas o modelo vê no primeiro turno, com
  `initialToolNames`.

### Como as actions viram ferramentas {#actions-as-tools}

Todo `defineAction` é uma ferramenta por padrão. Defina `agentTool: false`
para manter uma action disponível para as suas telas, mas oculta do agente.

### O que o modelo vê primeiro {#initial-tools}

`INITIAL_TOOL_NAMES` lista `view-screen`, `navigate`, `hello` e
`provider-api-request`. Essas são as únicas ferramentas enviadas no primeiro
turno. Todo o resto, incluindo uma action que você adicione, continua
acessível por meio de `tool-search` e é carregado sob demanda.

Adicione um nome a essa lista apenas se quiser a action no conjunto padrão de
ferramentas do modelo desde a primeira mensagem.

## Modelo de dados {#data-model}

O Chat não define tabelas próprias. Não existe `server/db/schema.ts` até você
adicionar um. O aplicativo roda sobre as tabelas centrais do framework para
threads e mensagens do chat, estado da aplicação, configurações, sessões,
recursos e histórico de execuções. Elas pertencem ao framework, então não as
edite. Veja [Banco de dados](/docs/server-database) para o modelo de conexão e
onde os novos dados devem ficar.

`useDbSync()` já está ligado ao shell do aplicativo. Quando o agente ou
qualquer outra pessoa grava no SQL, o cliente recebe a mudança por SSE, ou
pelo fallback de polling de 2 segundos, e invalida os caches correspondentes
do React Query. Veja [`useDbSync`](/docs/client-data#usedbsync) para a API
completa do hook.

Sua primeira tabela é um arquivo novo. Veja [Adicione sua primeira
funcionalidade](#first-feature).

## Autenticação {#auth}

A autenticação roda no Better Auth: login, cadastro, sessões e organizações. O
Chat a configura em `server/plugins/auth.ts` com `createToolkitAuthPlugin`. O
arquivo mantém `/` público, para que a página inicial de login possa carregar, e
define `marketing: false`, então a página de login não tem texto de marketing.
Para mostrar ali o nome do aplicativo, o slogan e os tópicos de funcionalidades,
passe um objeto `marketing`. O mesmo fluxo roda localmente e em produção,
exceto que o desenvolvimento pula a verificação de e-mail para que você possa se
cadastrar e começar a construir imediatamente. Veja
[Autenticação](/docs/authentication) para o modelo completo de autenticação
(sessões, organizações, rotas protegidas).

**Banco de dados** (`/database`) é o mesmo `DbAdminPage` que todo template
recebe. É um navegador e editor direto de tabelas sobre o banco SQL do
aplicativo. Veja [Banco de dados](/docs/server-database) para o modelo de
conexão por trás dele.

**Observabilidade** (`/observability`) é o mesmo `ObservabilityDashboard`
sem configuração que todo template recebe. Ele mostra traces, custo,
avaliações e feedback de cada execução do agente, calculados a partir de
dados que já estão no seu próprio banco. Veja
[Observabilidade do agente](/docs/observability).

**Extensões** são mini-apps Alpine.js isolados. O Chat monta as rotas que
as exibem e executam (`/extensions/:id`) e redireciona `/extensions` para
`/settings/extensions`. O Chat deixa as Extensões desligadas em dois lugares. A
página de Configurações só aparece quando `app/routes/settings.tsx` passa
`extensionTools: true` para `useAgentSettingsTabs()`. O agente só consegue criar
extensões depois que `frameworkTools.extensions` é ligado em
`server/plugins/agent-chat.ts`. Veja [Extensões](/docs/extensions) para saber o
que elas podem e não podem fazer.

## Personalizando {#customizing}

Cada parte do aplicativo é código-fonte editável. Comece aqui:

- `actions/`: adicione um novo arquivo com `defineAction` para expor uma nova
  action tanto ao agente quanto ao frontend.
- `app/routes/`: a interface. Adicione um arquivo de rota para montar uma
  página.
- `server/db/schema.ts`: adicione suas próprias tabelas com Drizzle quando as
  tabelas centrais não forem mais suficientes. Mantenha o código específico
  para PostgreSQL para que o PGlite local e o Postgres hospedado usem a mesma
  semântica.
- `AGENTS.md`: instruções do agente. Atualize-o quando ensinar ao agente
  novas actions ou convenções.
- `.agents/skills/`: padrões detalhados que o agente segue.

Se você adicionar uma funcionalidade, lembre-se de atualizar as quatro áreas:
interface, action, skill ou entrada no `AGENTS.md`, e qualquer estado da
aplicação que o agente precise ver. É isso que mantém o agente e a interface
em paridade.

### Use seu próprio backend de agente {#own-agent-backend}

O template usa por padrão o loop de agente de aplicativo integrado. Para
conectar um backend personalizado, troque o runtime de chat por trás do
plugin de chat do agente em vez de reescrever a interface. A rota de chat
deve continuar sendo um renderizador fino em torno da superfície de chat
compartilhada, e a escolha do backend pertence ao plugin de servidor e ao
adaptador de runtime.

Use isso quando a orquestração do seu modelo já vive em outro lugar, mas você
ainda quer um aplicativo com autenticação, threads, actions, estado da
interface e páginas prontas para implantar. Veja
[Interface de chat nativa](/docs/native-chat-ui#byo-agent-runtimes) para as
opções de runtime.

## Adicione sua primeira funcionalidade {#first-feature}

A maioria das primeiras funcionalidades segue o mesmo formato: uma tabela,
uma ou duas actions, uma página, uma entrada de navegação e uma atualização
do `AGENTS.md`. Esta seção constrói uma funcionalidade de notas em quatro
partes, com o código completo de cada arquivo. Você também pode pedir ao
agente para fazer tudo isso:

> Add a data model for `notes`. A note has an id, title, body, and owner. Render a notes page at `/notes`, add create/list actions, and keep chat able to create notes.

### 1. Adicione a camada de dados

O Chat não vem com uma pasta `server/db`, então os três arquivos aqui são
novos.

O schema define as tabelas. `ownableColumns()` adiciona as colunas de dono,
organização e visibilidade, e `createSharesTable()` adiciona uma tabela
correspondente para compartilhamento.

```ts filename="server/db/schema.ts"
import { sql } from "drizzle-orm";
import { pgTable, text } from "drizzle-orm/pg-core";
import {
  createSharesTable,
  ownableColumns,
} from "@agent-native/core/db/schema";

export const notes = pgTable("notes", {
  id: text("id").primaryKey(),
  title: text("title").notNull(),
  body: text("body").notNull(),
  createdAt: text("created_at")
    .notNull()
    .default(sql`now()`),
  ...ownableColumns(),
});

export const noteShares = createSharesTable("note_shares");
```

O cliente de banco de dados fornece `getDb()` às suas actions e registra as
notas no sistema de compartilhamento. As notas não têm página de detalhe, então
os links de compartilhamento apontam para a lista.

```ts filename="server/db/index.ts"
import { createGetDb } from "@agent-native/core/db";
import { registerShareableResource } from "@agent-native/core/sharing";

import * as schema from "./schema.js";

export const getDb = createGetDb(schema);
export { schema };

registerShareableResource({
  type: "note",
  resourceTable: schema.notes,
  sharesTable: schema.noteShares,
  displayName: "Note",
  titleColumn: "title",
  getResourcePath: () => "/notes",
  getDb,
});
```

A migração cria as tabelas quando o aplicativo inicia. Adicione novas
entradas para mudanças posteriores e nunca edite uma que já foi executada.


### 2. Adicione as actions

Cada action é um arquivo em `actions/`, e o nome do arquivo vira o nome da
ferramenta. O agente e a sua página chamam as mesmas duas actions.

`create-note` registra o usuário autenticado como dono. A nota fica visível
para a organização quando há uma ativa e privada para quem a criou caso
contrário.

```ts filename="actions/create-note.ts"
import { defineAction, fail } from "@agent-native/core/action";
import { z } from "zod";

import { getDb, schema } from "../server/db/index.js";

export default defineAction({
  description:
    "Create a note with a title and body. It is visible to the organization when one is active, otherwise only to its creator.",
  schema: z.object({
    title: z.string().min(1).describe("Short title for the note"),
    body: z.string().describe("Full text of the note"),
  }),
  run: async (args, ctx) => {
    const ownerEmail =
      ctx?.userEmail ?? fail("Sign in to create notes.", { statusCode: 401 });
    const orgId = ctx?.orgId ?? null;
    const note = {
      id: crypto.randomUUID(),
      title: args.title,
      body: args.body,
      ownerEmail,
      orgId,
      visibility: orgId ? ("org" as const) : ("private" as const),
    };
    await getDb().insert(schema.notes).values(note);
    return { id: note.id, title: note.title };
  },
});
```

`list-notes` é somente leitura, e `accessFilter` limita os resultados às
notas que o usuário atual pode ver.

```ts filename="actions/list-notes.ts"
import { defineAction } from "@agent-native/core/action";
import { accessFilter } from "@agent-native/core/sharing";
import { desc } from "drizzle-orm";
import { z } from "zod";

import { getDb, schema } from "../server/db/index.js";

export default defineAction({
  description: "List the notes the current user can see, newest first.",
  schema: z.object({}),
  http: { method: "GET" },
  readOnly: true,
  run: async () => {
    const { notes, noteShares } = schema;
    const rows = await getDb()
      .select({
        id: notes.id,
        title: notes.title,
        body: notes.body,
        createdAt: notes.createdAt,
      })
      .from(notes)
      .where(accessFilter(notes, noteShares))
      .orderBy(desc(notes.createdAt))
      .limit(200);
    return { notes: rows };
  },
});
```

Uma nova action pode ser chamada pelo chat assim que existe. Veja
[O que o modelo vê primeiro](#initial-tools) se você a quiser no conjunto
padrão de ferramentas do modelo.

### 3. Adicione a página e o link na barra lateral

O aplicativo usa roteamento baseado em sistema de arquivos, então adicionar
este arquivo monta `/notes`. A página chama as mesmas actions que o agente com
`useActionQuery()` e `useActionMutation()`, e uma mutação bem-sucedida
atualiza a lista sozinha.

```tsx filename="app/routes/notes.tsx"
import {
  useActionMutation,
  useActionQuery,
} from "@agent-native/core/client/hooks";
import { useSetPageTitle } from "@agent-native/toolkit/app-shell";
import { useState, type FormEvent } from "react";
import { toast } from "sonner";

import { Button } from "@/components/ui/button";
import { Input } from "@/components/ui/input";
import { Skeleton } from "@/components/ui/skeleton";
import { APP_TITLE } from "@/lib/app-config";

export function meta() {
  return [{ title: `Notes - ${APP_TITLE}` }];
}

export default function NotesRoute() {
  useSetPageTitle("Notes");
  const { data, isLoading } = useActionQuery("list-notes");
  const createNote = useActionMutation("create-note", {
    onError: (error) => toast.error(error.message),
  });
  const [title, setTitle] = useState("");
  const [body, setBody] = useState("");

  function handleSubmit(event: FormEvent) {
    event.preventDefault();
    createNote.mutate(
      { title, body },
      {
        onSuccess: () => {
          setTitle("");
          setBody("");
        },
      },
    );
  }

  return (
    <div className="mx-auto flex h-full max-w-2xl flex-col gap-6 overflow-auto p-6">
      <form onSubmit={handleSubmit} className="flex flex-col gap-2">
        <Input
          value={title}
          onChange={(event) => setTitle(event.target.value)}
          placeholder="Title"
          required
        />
        <Input
          value={body}
          onChange={(event) => setBody(event.target.value)}
          placeholder="Write a note"
        />
        <Button type="submit" disabled={createNote.isPending}>
          Add note
        </Button>
      </form>
      <ul className="flex flex-col gap-2">
        {isLoading && (
          <>
            <Skeleton className="h-16 w-full" />
            <Skeleton className="h-16 w-full" />
          </>
        )}
        {data?.notes.map((note) => (
          <li key={note.id} className="rounded-lg border p-3">
            <p className="font-medium">{note.title}</p>
            <p className="text-sm text-muted-foreground">{note.body}</p>
          </li>
        ))}
      </ul>
    </div>
  );
}
```

```tsx filename="app/components/layout/Sidebar.tsx"
  if (collapsed) {
    return (
      <Tooltip>

        <TooltipContent side="right">Notes</TooltipContent>
      </Tooltip>
    );
  }

  return <div className="px-2">{link}</div>;
}
```
