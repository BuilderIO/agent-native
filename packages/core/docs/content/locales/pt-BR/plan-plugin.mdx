# Plugin e marketplace do Plan

O aplicativo **Plan** do Agent-Native é distribuído como um único pacote
instalável. Uma única instalação adiciona as habilidades de comando de barra
do Plan **e** conecta o conector MCP hospedado do Plan (um servidor de
ferramentas remoto com o qual o seu agente conversa), para que o agente
possa gerar planos e publicá-los diretamente no aplicativo Plan em uma única
etapa. Esta página é para quem está escolhendo uma rota de instalação,
resolvendo problemas de instalação ou decidindo se deve enviar o Plan para
um catálogo de plugins com curadoria — veja
[Visual Plans](/docs/template-plan) para o que as habilidades realmente
fazem.

## O que você recebe {#what-you-get}

Uma instalação oferece:

- **Três habilidades** — `/visual-plan` (o ponto de entrada canônico), `/visual-recap` e `/visualize-repo`.
- **O conector MCP do Plan** — registrado no aplicativo hospedado em `https://plan.agent-native.com` (endpoint MCP `https://plan.agent-native.com/mcp`, nome do servidor `plan`).

Por padrão, `/visual-plan` e `/visual-recap` publicam no aplicativo Plan
hospedado — eles criam um plano pelo conector MCP e entregam a você um link
ou um plano inline para revisar. Eles nunca despejam um plano inline em
Markdown/ASCII no chat como entrega final. Se uma ferramenta do Plan
retornar `needs auth`, `Unauthorized` ou `Session terminated`, reautentique
o conector em vez de recorrer à saída inline. Os tokens de acesso têm vida
longa (30 dias por padrão, com renovação deslizante de 365 dias), então isso
deve ser raro; quando acontecer, a correção simples é:

```bash
npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex
```

O `reconnect` encontra e renova o conector pela URL para o cliente local
selecionado — sem precisar reinstalar. Inicie uma nova thread do Codex
depois de reconectar para que o registro de ferramentas recarregue. No
Claude Code, o equivalente é `/mcp` → **Authenticate / Reconnect**, ou o
mesmo comando com `--client claude-code`.

A exceção é o **modo explícito de privacidade de arquivos locais**. Quando
você pede para não gravar no banco de dados ou define
`AGENT_NATIVE_PLANS_MODE=local-files`, as habilidades não podem chamar o
conector MCP do Plan. Elas escrevem `plans/<slug>/plan.mdx` mais os arquivos
opcionais `canvas.mdx`, `prototype.mdx` e `.plan-state.json`, e depois fazem
a prévia localmente com:

```bash
npx @agent-native/core@latest plan local serve --dir plans/<slug> --kind plan --open
```

Isso inicia uma pequena ponte localhost e abre a UI do Plan sobre a pasta
local. (`plan local preview` roda uma rota local de servidor de
desenvolvimento do Plan em vez disso, e `plan local preview --out
preview.html` é uma saída de emergência legada que escreve um arquivo HTML
estático independente. `plan serve` é aceito como um alias curto para
`plan local serve`.)

Algumas pegadinhas do modo de arquivos locais que vale a pena conhecer:

- **Use um navegador baseado em Chromium.** O Safari bloqueia a página
  hospedada em HTTPS do Plan de ler a ponte localhost `http://127.0.0.1`
  (conteúdo misto / rede privada), então a página fica travada em "Loading
  plan.". No macOS, `--open` já prefere Chrome/Chromium/Edge/Brave; se o
  Safari abrir mesmo assim, reabra a URL impressa em um navegador baseado em
  Chromium.
- **A URL servida é escrita em `plans/<slug>/.plan-url`** (substitua com
  `--url-file`). Um agente em segundo plano ou headless pode ler esse
  arquivo em vez de raspar a saída de longa duração do `serve`. Trate-o como
  um arquivo de token local e não o commit.
- **Verifique de forma headless** quando nenhum navegador estiver disponível:
  `npx @agent-native/core@latest plan local verify --dir plans/<slug>` inicia
  a ponte, verifica o preflight de rede privada e o payload JSON, imprime
  diagnósticos e sai com código diferente de zero em caso de falha — sem
  precisar de olhos humanos.
- **Rode `plan local check` primeiro.** Ele valida o MDX contra o schema de
  blocos do renderizador do Plan (incluindo campos obrigatórios como o
  `id`/`label` do item de `checklist` e o `id`/`title`/`mode` da pergunta em
  `question-form`), para que erros de autoria apareçam antes da entrega ao
  navegador, em vez de como um carregador travado.

Para pastas no repositório atual, a rota local direta inclui `?path=...`
para que o aplicativo local do Plan consiga manter as edições do navegador
salvando na pasta do repositório. O aplicativo Plan usa
`apps.plan.roots[0].path` em `agent-native.json` como o lugar padrão para
salvar planos locais promovidos, recorrendo a `plans/` como alternativa.

Isso mantém o conteúdo do plano fora do banco de dados do Agent-Native Plan.
Compartilhamento hospedado, comentários, capturas de tela e histórico de
planos ficam indisponíveis até você publicar explicitamente mais tarde.

O Agent-Native Desktop tem um caminho separado de sincronização de arquivos
locais para planos hospedados: o aplicativo Desktop pode espelhar um plano
hospedado em arquivos MDX locais e importar as edições de volta sem clonar o
aplicativo Plan ou rodar um CLI. Esse fluxo mantém o banco de dados
hospedado do Plan como a fonte da verdade; use o modo de privacidade de
arquivos locais quando o objetivo for não gravar no banco de dados do Plan.

> O plugin (`agent-native-visual-plans`) carrega o id de aplicativo
> `visual-plans`, e é por isso que o nome do plugin no Claude Code e no
> Codex é, nos dois casos, `agent-native-visual-plans`. O nome de exibição
> do aplicativo Plan é "Agent-Native Plan".

## Rotas de instalação {#install}

Há três formas de entrar. A **rota do CLI universal** é a que recomendamos
por padrão, porque instala as habilidades **e** permite escolher modo
hospedado, de arquivos locais ou auto-hospedado em um único fluxo. As rotas
de plugin são para hosts com um sistema de plugin/marketplace de primeira
classe e usam o Plans hospedado por padrão.

### Rota universal de habilidade (qualquer host MCP) {#universal}

Funciona para qualquer host — Claude Code, Codex, Cursor, Cline, Goose,
aplicativos MCP personalizados do ChatGPT, Claude Cowork e qualquer outro
compatível com MCP. O CLI do Agent-Native instala as habilidades do Plan,
registra o conector MCP hospedado do Plan **e executa a autenticação para
o(s) cliente(s) local(is) selecionado(s) na mesma etapa**, para que sua
primeira chamada de ferramenta não esbarre em um muro de OAuth:

```bash
npx @agent-native/core@latest skills add visual-plan
```

Isso instala `visual-plan` mais as habilidades complementares
`visual-recap` e `visualize-repo`, depois registra o conector `plan` e, em
seguida, executa a autenticação (prompt de OAuth para compartilhamento
hospedado/vinculado a conta). Flags úteis:

- `--client codex|claude-code|claude-code-cli|cowork|all` — para quais agentes locais escrever a configuração MCP (padrão `all`).
- `--no-connect` — registra o conector sem autenticar; rode `npx @agent-native/core@latest connect https://plan.agent-native.com --client all` depois, ou escolha um `--client` mais específico.
- `--mode hosted|local-files|self-hosted` — escolha compartilhamento hospedado, arquivos MDX totalmente locais, ou seu próprio aplicativo Plan.
- `--mcp-url <url>` — aponta o conector para uma origem personalizada (um túnel ngrok, um servidor de desenvolvimento local ou uma implantação auto-hospedada) em vez do padrão hospedado.
- `--with-github-action` — também escreve a GitHub Action de Recapitulação Visual de PR (veja [Recapitulação Visual de PR](/docs/pr-visual-recap)).

Instalações interativas também oferecem a Action de Recapitulação Visual de
PR quando nenhum workflow está presente. Diga sim para adicioná-la durante a
configuração da habilidade, ou rode o comando acima depois com
`--with-github-action`. Depois que o workflow for escrito, rode:

```bash
npx @agent-native/core@latest recap setup
npx @agent-native/core@latest recap doctor
```

O `recap setup` configura os secrets e variáveis da GitHub Action quando
possível, e o `recap doctor` verifica o workflow, o token de publicação
local, o acesso ao repositório do GitHub e a configuração necessária das
Actions. Depois que a instalação terminar, reinicie ou recarregue o cliente
do agente para que as novas habilidades e ferramentas carreguem, e então
rode `/visual-plan`.

> Nota: o comando puro `npx skills@latest add BuilderIO/agent-native --skill
> visual-plan` (CLI Vercel/open Skills) instala **apenas instruções** — ele
> não registra o conector MCP. Use o CLI do Agent-Native acima quando também
> quiser o conector configurado.

### Claude Code (plugin) {#claude-code}

O repositório público `BuilderIO/agent-native` é, ele mesmo, um marketplace
de plugins do Claude Code, então você o adiciona diretamente — sem etapa de
build. Dentro do Claude Code:

```text
/plugin marketplace add BuilderIO/agent-native
/plugin install agent-native-visual-plans@agent-native-apps
/reload-plugins
/mcp        # authenticate the Plan connector (one OAuth approval)
```

`/plugin install` adiciona as habilidades do Plan e uma configuração MCP
**apenas com URL** (sem segredos no pacote); `/mcp` → **Authenticate**
completa o handshake OAuth. Use a rota do CLI universal em vez disso quando
quiser o modo de arquivos locais ou auto-hospedado.

> O catálogo do marketplace se chama `agent-native-apps` e o plugin do Plan
> é `agent-native-visual-plans`, então o alvo de instalação é sempre
> `agent-native-visual-plans@agent-native-apps`.

### Codex (plugin) {#codex}

O mesmo repositório é um marketplace de plugins do Codex. Adicione-o,
instale o plugin e depois autentique o conector:

```bash
codex plugin marketplace add BuilderIO/agent-native
codex plugin add agent-native-visual-plans@agent-native-apps
codex mcp login plan   # OAuth in the browser
```

Depois da instalação, **inicie uma nova thread do Codex** para que as
habilidades e ferramentas MCP carreguem na sessão. O plugin distribui um
conector apenas com URL (`[mcp_servers.plan]` → `https://plan.agent-native.com/mcp`);
`codex mcp login plan` executa o fluxo OAuth. A rota do CLI universal acima
também funciona para o Codex
(`npx @agent-native/core@latest skills add visual-plan --client codex`) se
você preferir um único comando que instala e autentica junto, ou quando
quiser o modo de arquivos locais ou auto-hospedado.

<Callout tone="info">

**Instalações antigas:** se sua configuração ainda tiver uma entrada
`agent-native-plans` apontando para a mesma URL, rodar
`npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex`
para o Codex, ou o mesmo comando com seu `--client` alvo, consolida isso no
nome canônico `plan`.

</Callout>

## Atualizações {#updates}

As rotas de plugin se atualizam automaticamente — você não precisa
reempacotar nem readicionar o marketplace para mudanças de rotina nas
habilidades:

- **Claude Code** — a entrada do marketplace define `autoUpdate: true` e o
  plugin usa versionamento por SHA de commit, então o Claude Code busca
  novas versões do repositório na inicialização; rode `/reload-plugins` para
  ativar. Todo push para a branch padrão do repositório chega automaticamente
  aos usuários instalados.
- **Codex** — a `version` do plugin embute um hash de conteúdo das
  habilidades empacotadas e do endpoint MCP (por exemplo,
  `1.0.0+codex.<hash>`), então qualquer mudança de habilidade ou endpoint
  gera uma nova versão. A atualização automática de inicialização do Codex
  reinstala sozinha os marketplaces git configurados; basta **iniciar uma
  nova thread** para pegar a mudança. Nenhum
  `codex plugin marketplace upgrade` manual é necessário para atualizações
  de rotina.
- **Rota do CLI universal** — rode
  `npx @agent-native/core@latest skills status visual-plan` para verificar
  as pastas de habilidade copiadas, ou
  `npx @agent-native/core@latest skills update visual-plan` para atualizá-las
  no lugar. Rodar `skills add visual-plan` de novo ainda funciona quando
  você também quer registrar/autenticar o conector novamente. `@latest`
  sempre traz as habilidades atuais do pacote publicado
  `@agent-native/core`.

O conector aponta para um aplicativo **hospedado**, então as actions e a
superfície de ferramentas ao vivo do aplicativo Plan sempre refletem a
versão implantada, independentemente de quando você instalou; apenas as
instruções de habilidade empacotadas seguem os mecanismos de atualização
acima.

<Callout tone="info">

**Mantenedores:** o pacote do marketplace (`.claude-plugin/`,
`.agents/plugins/`) é gerado a partir das habilidades canônicas do plan pelo
`pnpm sync:plan-marketplace` e verificado no CI por
`pnpm guard:plan-marketplace`, então o marketplace publicado sempre bate com
as habilidades canônicas. Edite a habilidade, rode
`pnpm sync:plan-marketplace` e faça o commit.

</Callout>

## Você precisa enviar algo? {#submission}

**Nenhum envio ou revisão é necessário para distribuir ou instalar isso.**
`BuilderIO/agent-native` é um marketplace git público e auto-hospedado,
então os usuários o adicionam diretamente com os comandos acima **tanto no
Claude Code quanto no Codex** — sem inscrição nem aprovação. A rota do CLI
universal não precisa de marketplace algum.

Visibilidade opcional, se você quiser uma listagem pública:

- O **Claude Code** tem um marketplace comunitário ao qual você pode,
  _opcionalmente_, enviar seu plugin para listagem (envio mais uma revisão
  automatizada). O marketplace oficial, com curadoria da Anthropic, é
  listado a critério da Anthropic — não há inscrição aberta e autosserviço.
  Nenhum dos dois é necessário para usar os comandos de instalação acima.
- O **Codex** tem um catálogo de plugins com curadoria da OpenAI (uma lista
  fechada de permissões, obtida por parceria em vez de envio autosserviço).
  Marketplaces git auto-hospedados e a rota do CLI não precisam de envio
  para funcionar.

Em resumo: distribua como um marketplace git público/auto-hospedado e os
usuários instalam diretamente; envie para um catálogo com curadoria apenas
se quiser que ele seja listado para descoberta.

## Plugin vs. habilidade {#plugin-vs-skill}

Uma **habilidade** é um único arquivo de instruções `SKILL.md` que o agente
lê quando uma tarefa corresponde a ele. Um **plugin** (plugin de marketplace
do Claude Code ou plugin do Codex) é um pacote que agrupa uma ou mais
habilidades **mais** um conector MCP e metadados, para que um host possa
instalar tudo em uma única etapa.

Por baixo dos panos, as três rotas são produzidas a partir da mesma fonte
pelo CLI `npx @agent-native/core@latest app-skill`: `app-skill pack`
constrói os adaptadores de marketplace/plugin, e `skills add` é o instalador
amigável de uma etapa que também registra e autentica o conector MCP. Veja
[Skills Guide](/docs/skills-guide) para o formato do manifesto app-skill, e
[External Agents](/docs/external-agents) para conectar qualquer host MCP e o
fluxo `npx @agent-native/core@latest connect`.
