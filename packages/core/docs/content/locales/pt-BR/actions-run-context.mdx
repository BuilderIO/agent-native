# Contexto de Execução

`run` recebe um segundo argumento opcional, `ctx`, carregando a identidade resolvida da requisição e a superfície que invocou a action. Leia-o em vez de chamar `getRequestUserEmail()` / `getRequestOrgId()` manualmente, e passe o `ctx` inteiro para o tracking:

```ts
export default defineAction({
  description: "Log an audit entry for the current request.",
  schema: z.object({ event: z.string() }),
  run: async (args, ctx) => {
    // ctx is undefined-safe: a 1-arg `run(args)` is still valid.
    const actor = ctx?.userEmail ?? "system";
    if (ctx?.caller === "frontend") {
      // tighter rules for browser-initiated calls, looser for "tool"/"cli"
    }
    await db.insert(audit).values({
      actor,
      orgId: ctx?.orgId ?? null,
      source: ctx?.caller ?? "unknown",
      event: args.event,
    });
    return { ok: true };
  },
});
```

A maioria das actions só lê `ctx?.userEmail` e `ctx?.orgId`, o [escopo de controle de acesso](/docs/actions-access-control#access-control) usado em quase toda action real. O restante desta página cobre preocupações transversais como tracking e atribuição de automação, que menos actions precisam.

## O argumento `ctx` {#ctx}

`ctx` carrega dois tipos de informação: a identidade resolvida da requisição (`userEmail`, `orgId`) que está presente em quase toda chamada, e metadados sobre a superfície que invocou a action (`caller`, além de campos específicos de superfície como `threadId` ou `automation` que só são preenchidos para certos chamadores). ### A union de `caller` {#caller}

`caller` é a union `"tool" | "http" | "frontend" | "cli" | "mcp" | "a2a" | "automation"`:

| `caller`       | Definido quando…                                                                                                                                                    |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `"tool"`       | O loop do agente dentro do app, um subagente ou agent team, ou a delegação A2A entre apps em linguagem natural, que conduz o mesmo loop do agente, então suas chamadas de ferramenta são `"tool"`. |
| `"frontend"`   | Uma chamada do navegador via `useActionMutation()`, `useActionQuery()`, ou `callAction()` (marcada com o header `X-Agent-Native-Frontend: 1`).                        |
| `"http"`       | Um `POST` ou `GET` programático simples para `/_agent-native/actions/<name>` sem o marcador de frontend.                                                              |
| `"cli"`        | `pnpm action <name>` (o executor da CLI).                                                                                                                             |
| `"mcp"`        | Um agente externo através do endpoint `tools/call` do MCP.                                                                                                            |
| `"a2a"`        | Uma chamada HTTP direta para `/_agent-native/actions/<name>` carregando um token de delegação A2A assinado. Este é um despacho entre apps explicitamente exposto, distinto do caminho `"tool"` em linguagem natural acima. |
| `"automation"` | Uma automação disparada por evento, despachada a partir de um trigger armazenado no workspace. `ctx.automation` carrega a linhagem do trigger. Veja [Automations](/docs/automations). |
