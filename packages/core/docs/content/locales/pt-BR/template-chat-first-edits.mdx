# Seu primeiro recurso

Esta página é para desenvolvedores que estendem o [modelo Chat](/docs/template-chat). Ela cobre os arquivos que renderizam as telas iniciais e depois percorre tudo o que o agente costuma tocar quando você pede um recurso de verdade.

## Primeiro código a inspecionar {#first-code}

- `actions/hello.ts` é o comportamento inicial que o agente pode chamar.
  Substitua-o ou adicione ações ao lado dele.
- `app/components/chat/ChatRouteContent.tsx` renderiza a superfície de chat em
  página inteira em `/chat/<threadId>`. Ajuste aqui o estado vazio, o composer
  ou os slots de mensagem.
- `app/components/home/HomePage.tsx` é a página Comece aqui editável exibida em
  `/home`. `/chat` inicia um chat novo.
- `AGENTS.md` diz ao agente integrado como trabalhar dentro deste app.

## Primeiras edições {#first-edits}

A maioria dos primeiros recursos segue o mesmo formato: uma tabela, uma ou
duas actions, uma rota, uma entrada de navegação e uma atualização no
`AGENTS.md`. Peça ao agente:

> Adicione um modelo de dados para `notes`. Uma nota tem um id, título, corpo
> e proprietário. Renderize uma página de notas em `/notes`, adicione actions
> de criar/listar, e mantenha o chat capaz de criar notas.

O Chat vem sem nenhum `server/db/schema.ts` (veja [O que vem
incluído](/docs/template-chat#what-ships)), então a primeira mudança é um
novo arquivo, seguindo o mesmo formato `table`/`text`/`ownableColumns` que
todo outro template usa:

O restante do recurso segue a partir daí:

- `actions/create-note.ts` — um `defineAction` com um esquema Zod (`title`,
  `body`), no mesmo formato de `actions/hello.ts`.
- `actions/list-notes.ts` — uma action somente leitura (`readOnly: true`,
  como `actions/view-screen.ts`) que consulta a nova tabela através de
  `accessFilter`.
- `app/routes/notes.tsx` — uma nova rota; o app usa roteamento baseado em
  sistema de arquivos (`flatRoutes()` em `app/routes.ts`), então adicionar o
  arquivo já é suficiente para montar `/notes`.
- Um link em `app/components/layout/Sidebar.tsx`, adicionado antes de `ChatThreadsSection` e apontando para `/notes`.
- Uma adição ao `AGENTS.md` dizendo ao agente que notas existem e quais
  actions as gerenciam.

Uma nova action fica chamável pelo chat assim que existe — todo
`defineAction` é uma ferramenta por padrão, a menos que defina
`agentTool: false`. Mas ela não vai necessariamente estar na primeira
solicitação do modelo: `server/plugins/agent-chat.ts` define
`INITIAL_TOOL_NAMES = ["view-screen", "navigate", "hello", "provider-api-request"]`, o que controla
apenas quais esquemas de ferramenta são enviados no primeiro turno. Tudo o
mais, incluindo uma `create-note` recém-criada, continua acessível via
`tool-search` e carrega sob demanda — adicione um nome a essa lista apenas
se você quiser que ele esteja no conjunto padrão de ferramentas do modelo
desde a primeira mensagem.

## Use seu próprio backend de agente {#own-agent-backend}

O template usa o loop de app-agente integrado por padrão. Para conectar um
backend personalizado, troque o runtime de chat por trás do plugin de chat
do agente em vez de reescrever a UI. A rota do Chat deve permanecer um
renderizador fino em torno da superfície de chat compartilhada; a escolha
de backend pertence ao plugin de servidor/adaptador de runtime.

Use isso quando a orquestração do seu modelo já vive em outro lugar, mas
você ainda quer um app com autenticação, threads, actions, estado de UI e
páginas implantáveis.
