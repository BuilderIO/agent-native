# 데이터 및 동기화

클라이언트 애플리케이션에서 앱 데이터를 읽고 쓰는 주된 방법은 [action](/docs/actions) 후크를 사용하는 것입니다. 요청을 actions에 담아 보내면 클라이언트와 에이전트가 동일한 방식으로 애플리케이션과 상호작용할 수 있습니다.

아래 예시에서는 티켓이 드롭다운을 통해 수동으로, 그리고 채팅 에이전트를 통해 현재 사용자에게 배정됩니다. UI와 에이전트는 동일한 action에 접근합니다.

### Action 후크 {#action-hooks}

가장 많이 사용하게 될 두 개의 action 후크는 `useActionQuery()`와 `useActionMutation()`입니다. 이 두 후크는 앱의 actions에 접근할 수 있게 해줍니다.

#### useActionQuery {#use-action-query}

    },

  returns={{
    type: "UseQueryResult<TResult>",
    description:
      '`["action", name, params]` 아래에 캐시됩니다. 변형 작업이 완료될 때마다 별도의 수동 무효화 없이 자동으로 다시 가져옵니다.',
  }}
/>

이 후크는 읽기 전용 actions에 사용하기 위한 것입니다. [useQuery()](https://tanstack.com/query/latest/docs/framework/react/reference/useQuery) 함수를 얇게 감싼 래퍼입니다.

아래 예시에서는 `list-tickets` action이 호출됩니다. 이는 모든 티켓에 대한 GET 요청을 보내는 것과 비슷합니다.

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery("list-tickets", {});
```

다음 예시는 `get-ticket` action을 통해 단일 티켓을 가져오는 요청을 보여줍니다. 쿼리 범위를 특정 티켓으로 좁히기 위해 `ticketId`를 전달합니다. 쿼리가 자동으로 실행되지 않고 `ticketId`가 있을 때만 실행되도록 보장하기 위해 `enabled` 옵션이 추가로 제공됩니다.

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery(
  "get-ticket",
  { ticketId: ticketId ?? "" },
  { enabled: Boolean(ticketId) },
);
```

#### useActionMutation {#use-action-mutation}

    description:
      '성공 시 `source: "action"`으로 변경 이벤트를 내보내므로, 영향을 받는 데이터를 읽는 모든 `useActionQuery()`가 자동으로 다시 가져옵니다. 수동 무효화가 필요하지 않습니다.',
  }}
/>

이 후크는 생성, 수정, 전송처럼 데이터를 변경하는 actions에 사용하기 위한 것입니다. [useMutation()](https://tanstack.com/query/latest/docs/framework/react/reference/useMutation) 함수를 얇게 감싼 래퍼입니다.

`useActionQuery()`와 달리 action의 입력값은 후크 자체에 전달되지 않습니다. 변경을 실행할 준비가 되었을 때 `mutate()` 또는 `mutateAsync()`에 전달합니다.

아래 예시에서는 `send-ticket-reply` action이 호출되어 티켓에 답글이 게시됩니다. 버튼의 `onClick`과 같은 이벤트 핸들러에서 `mutate()`를 호출합니다.

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply");

mutate({ ticketId, body: draft });
```

다음 예시는 동일한 변경 작업에 `onSuccess` 옵션을 추가한 모습을 보여줍니다. 캐시 무효화는 모든 변경 작업 후에 자동으로 일어나므로, `onSuccess`는 답글이 전송된 뒤 작성기를 비우는 것과 같은 로컬 부수 효과에만 필요합니다.

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply", {
  onSuccess: () => setDraft(""),
});

mutate({ ticketId, body: draft });
```

  }}
/>

이 함수는 React 렌더 흐름 밖에서 일회성으로 action을 명령형으로 호출하기 위한 것입니다. 일반 이벤트 핸들러, 스크립트, 그 외 React가 아닌 어떤 코드 경로에서도 사용할 수 있습니다. 후크 결과 대신 프로미스를 직접 반환합니다.

아래 예시에서는 React 렌더 흐름 밖의 키보드 단축키 핸들러에서 `update-ticket` action을 호출하여 티켓을 담당자에게 배정합니다.

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction("update-ticket", {
  ticketId,
  assignedToEmail: "jordan@example.com",
});
```

다음 예시는 동일한 호출에 `timeoutMs` 옵션을 추가한 모습입니다. 기본 60초 타임아웃보다 정당하게 더 오래 걸리는 actions에 유용합니다.

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction(
  "update-ticket",
  { ticketId, assignedToEmail: "jordan@example.com" },
  { timeoutMs: 120_000 },
);
```

모든 `useActionQuery()`, `useActionMutation()`, `callAction()` 요청은 60초 타임아웃으로 제한되며, 타임아웃은 조용히 재시도하지 않고 오류로 나타납니다. `useActionQuery()`는 React Query의 abort signal을 이용해 이전 요청이 대체될 때 자동으로 취소하기도 합니다.

이 후크는 여러분의 actions 밖에서 일어나는 데이터베이스 변경 — 에이전트의 쓰기, 웹훅, 다른 브라우저 탭에서의 변경 등 — 과 UI를 동기화하기 위한 것입니다. 서버-전송 이벤트(server-sent events)로 변경을 수신하며, 서버-전송 이벤트를 사용할 수 없을 때는 폴링으로 대체합니다.

```ts
import { useDbSync } from "@agent-native/core/client/hooks";
import { useQueryClient } from "@tanstack/react-query";

function App() {
  const queryClient = useQueryClient();

  useDbSync({
    queryClient,
    pollUrl: "/_agent-native/poll",
    onEvent: (data) => console.log("Data changed:", data),
  });

  return <div>...</div>;
}
```

일반적인 CRUD에는 `useActionQuery()`와 `useActionMutation()`을 사용하세요. 변형 actions는 `source: "action"`을 내보내므로 이 후크들은 즉시 다시 가져옵니다. 에이전트, 웹훅, 다른 탭에서 온 변경은 대신 `useDbSync()`를 통해 SSE 또는 폴링 폴백으로 도착합니다. 원시 `useQuery()` 호출을 커스텀 키로 동기화해야 한다면 [동기화 내부](/docs/client-sync-internals)를 참조하세요. `application_state`에 직접 써야 한다면 [고급](/docs/client-advanced)을 참조하세요.
