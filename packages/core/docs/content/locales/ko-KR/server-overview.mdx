# 서버

`server/` 디렉터리는 에이전트 기반 앱의 인프라 계층입니다. 시작 작업, 인증, 그리고 액션이 다루지 못하는 HTTP 표면을 처리합니다. 대부분의 제품 동작은 [Actions](/docs/actions)에 있어야 합니다. 서버는 그런 액션들을 외부에서 사용할 수 있게 만드는 역할을 합니다.

## 서버가 차지하는 위치 {#role}

전통적인 웹 앱에서는 대부분의 로직이 서버에 있습니다. 비즈니스 규칙, 데이터 접근, 화면 표현이 모두 라우트 핸들러 안에서 일어납니다. 에이전트 기반 앱은 다르게 동작합니다. 로직은 액션에 있으며, 에이전트와 UI는 이를 동등한 파트너로서 공유합니다. 서버의 역할은 조율입니다. 데이터베이스 마이그레이션을 실행하고, 인증을 구성하고, 에이전트 루프를 마운트하고, 액션 스스로 표현할 수 없는 좁은 범위의 HTTP 관심사를 처리합니다.

브라우저 요청, 에이전트 루프, 외부 API 클라이언트는 모두 동일한 Nitro 서버를 거쳐가고 동일한 SQL 데이터베이스에서 읽습니다. 에이전트 전용 백엔드나 UI 전용 백엔드는 따로 없습니다. 서버 계층이 액션을 외부 세계에 노출하는 역할을 합니다.

## server/ 디렉터리 안에는 무엇이 있는가 {#server-directory}

다음은 모든 에이전트 기반 앱이 갖추는 `server/` 내부의 디렉터리와 파일들입니다. 각 항목은 서버 계층의 특정 부분에 대응합니다. 무엇을 하는지, 언제 사용해야 하는지, 프레임워크의 나머지 부분과 어떻게 연결되는지를 다룹니다.

| 페이지                                    | 다루는 내용                                                                            |
| ----------------------------------------- | -------------------------------------------------------------------------------------- |
| **[데이터베이스](/docs/server-database)** | `table()` 도우미를 사용한 스키마 정의, `getDb`, 그리고 소유 가능한 테이블 패턴         |
| **[미들웨어](/docs/server-middleware)**   | `server/middleware/`의 인증 가드와 그것이 플러그인이 아니라 이곳에서 실행되는 이유     |
| **[플러그인](/docs/server-plugins)**      | 모든 앱이 갖추는 세 가지 시작 플러그인: DB 마이그레이션, 인증, 에이전트 채팅           |
| **[라우트](/docs/server-routes)**         | 파일 기반 라우트, SSR catch-all, 그리고 커스텀 라우트를 요청 사용자로 범위 지정하는 법 |

## Nitro {#nitro}

[Nitro](https://nitro.build)는 에이전트 기반 HTTP 계층을 지원하는 서버 툴킷입니다. `server/`에서 구성하게 될 대부분은 Nitro입니다. 파일 기반 라우트, 시작 플러그인, 미들웨어가 그것입니다.

- **파일 기반 라우팅**: 파일 이름이 등록 없이 곧바로 HTTP 메서드와 URL 경로에 매핑됩니다. `server/routes/api/health.get.ts`는 자동으로 `GET /api/health`가 됩니다. 자세한 내용은 [라우트](/docs/server-routes)를 참조하세요.
- **플러그인**: 요청이 처리되기 전, 서버 시작 시 한 번 실행되는 코드입니다. 데이터베이스 마이그레이션, 인증 구성, 에이전트 채팅 마운트가 모두 `server/plugins/`에서 일어납니다. 자세한 내용은 [플러그인](/docs/server-plugins)을 참조하세요.
- **미들웨어**: 라우트에 도달하기 전, 들어오는 모든 요청에 대해 실행되는 코드입니다. 인증 가드는 `server/middleware/`에 있습니다. 자세한 내용은 [미들웨어](/docs/server-middleware)를 참조하세요.

Nitro는 또한 배포 방식에 구애받지 않습니다. 동일한 앱이 코드 변경 없이 Node.js, Cloudflare Workers, Netlify, Vercel 및 기타 런타임에 배포됩니다. 프리셋만 설정하면 됩니다. [배포](/docs/deployment)를 참조하세요.

기반이 되는 요청/응답 API는 [H3](https://h3.unjs.io)입니다. 커스텀 라우트에서 `defineEventHandler`, `createError`, `getQuery`를 보게 된다면 그것이 H3입니다. 프레임워크가 직접 다루지 않는 모든 것에 대해서는 [Nitro 문서](https://nitro.build/guide)와 [H3 문서](https://h3.unjs.io)를 참고하세요.

## 우선 액션부터 고려하기 {#actions-first}

Agent Native 아키텍처는 다릅니다. 애플리케이션의 새 기능을 떠올릴 때마다, 먼저 그것이 액션이 될 수 있는지 고려하세요. 예를 들어 UI와 에이전트가 둘 다 어떤 작업을 해야 한다면, 커스텀 API 라우트 대신 액션을 정의하세요. 액션은 자동으로 다음이 됩니다.

- 에이전트 도구.
- 타입이 지정된 프런트엔드 후크.
- `/_agent-native/actions/:name` 아래의 HTTP 엔드포인트.
- MCP 및 A2A로 호출 가능한 도구.
- 개발용 CLI 명령.

라우트 형태의 프로토콜이나 바이너리/스트리밍 동작이 필요한 경우에만 커스텀 `/api/*` 라우트를 사용하세요. 자세한 내용은 [Actions](/docs/actions)를 참조하세요.
