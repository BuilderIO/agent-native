# 첫 번째 기능

이 페이지는 [Chat 템플릿](/docs/template-chat)을 확장하는 개발자를 위한 것입니다. 시작 화면을 렌더링하는 파일을 살펴본 다음, 실제 기능을 요청할 때 에이전트가 보통 건드리는 모든 것을 차례로 안내합니다.

## 검사할 첫 번째 코드 {#first-code}

- `actions/hello.ts`는 에이전트가 호출할 수 있는 시작 동작입니다. 교체하거나 옆에 작업을 추가하세요.
- `app/components/chat/ChatRouteContent.tsx`는 `/chat/<threadId>`에서 전체 페이지 채팅 화면을 렌더링합니다. 빈 상태, 컴포저, 메시지 슬롯은 여기서 조정하세요.
- `app/components/home/HomePage.tsx`는 `/home`에 표시되는 편집 가능한 시작하기 페이지입니다. `/chat`에서 새 채팅을 시작합니다.
- `AGENTS.md`는 내장 에이전트에게 이 앱 안에서 작업하는 방법을 알려 줍니다.

## 첫 번째 수정 {#first-edits}

대부분의 첫 기능은 같은 형태를 따릅니다: 테이블 하나, 액션 한두 개, 라우트 하나,
내비게이션 항목 하나, 그리고 `AGENTS.md` 업데이트. 에이전트에게 다음처럼
요청해 보세요.

> `notes`에 대한 데이터 모델을 추가해줘. note는 id, title, body, owner를 가져.
> `/notes`에 notes 페이지를 렌더링하고, create/list 액션을 추가하고, 채팅에서도
> note를 만들 수 있게 유지해줘.

채팅에는 `server/db/schema.ts`가 전혀 없는 상태로 제공되므로([무엇이 제공되는가](/docs/template-chat#what-ships)
참고), 첫 번째 변경은 새 파일이며, 다른 모든 템플릿이 쓰는 것과 같은
`table`/`text`/`ownableColumns` 형태를 따릅니다.

나머지 기능은 여기서부터 자연스럽게 이어집니다.

- `actions/create-note.ts` — `actions/hello.ts`와 같은 형태로, Zod 스키마
  (`title`, `body`)를 가진 `defineAction`.
- `actions/list-notes.ts` — `actions/view-screen.ts`처럼 `accessFilter`를 통해 새
  테이블을 조회하는 읽기 전용 액션(`readOnly: true`).
- `app/routes/notes.tsx` — 새 라우트. 이 앱은 파일 시스템 기반 라우팅
  (`app/routes.ts`의 `flatRoutes()`)을 사용하므로, 파일을 추가하는 것만으로
  `/notes`가 마운트됩니다.
- `app/components/layout/Sidebar.tsx`에서 `ChatThreadsSection` 앞에 추가하는, `/notes`를 가리키는 링크.
- notes가 존재한다는 사실과 이를 관리하는 액션이 무엇인지 에이전트에게 알려주는
  `AGENTS.md` 추가.

새 액션은 만들어지는 즉시 채팅에서 호출할 수 있습니다 — 모든 `defineAction`은
`agentTool: false`로 설정하지 않는 한 기본적으로 도구입니다. 다만 모델의 아주 첫
요청에 반드시 포함되지는 않습니다: `server/plugins/agent-chat.ts`는
`INITIAL_TOOL_NAMES = ["view-screen", "navigate", "hello", "provider-api-request"]`를 설정하는데, 이는
첫 턴에 어떤 도구 스키마가 전송되는지만 제어합니다. 새로 만든 `create-note`를
포함한 나머지는 모두 `tool-search`를 통해 계속 접근 가능하며 필요할 때 로드됩니다
— 첫 메시지부터 모델의 기본 도구 세트에 포함하고 싶을 때만 이 목록에 이름을
추가하세요.

## 자체 에이전트 백엔드 사용하기 {#own-agent-backend}

템플릿은 기본적으로 내장 앱-에이전트 루프를 사용합니다. 사용자 정의 백엔드를
연결하려면 UI를 다시 작성하는 대신 에이전트 채팅 플러그인 뒤에 있는 채팅 런타임을
교체하세요. 채팅 라우트는 공유 채팅 화면을 감싸는 얇은 렌더러로 남아 있어야
하며, 백엔드 선택은 서버 플러그인/런타임 어댑터에 속합니다.

모델 오케스트레이션이 이미 다른 곳에 있지만, 인증, 스레드, 액션, UI 상태, 배포
가능한 페이지를 갖춘 앱은 여전히 원할 때 이 방법을 사용하세요.
