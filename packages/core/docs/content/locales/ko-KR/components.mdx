# 구성요소 API

Agent-Native는 전체 사이드바를 제공하지만 사이드바는 계약이 아닙니다.
계약은 런타임입니다: 채팅 스트리밍, 스레드 상태, actions, 컨텍스트
첨부 파일, 모델 선택, 실행 및 SQL 지원 동기화. 주식을 활용하세요
가능한 경우 구성요소를 선택하고 맞춤형 제품 UI가 필요할 경우 레이어를 드롭다운하세요.

중점 클라이언트 하위 경로에서 브라우저 UI 가져오기:

```tsx
import { AgentSidebar } from "@agent-native/core/client/agent-chat";
import { PromptComposer } from "@agent-native/core/client/composer";
import { AgentConversation } from "@agent-native/core/client/conversation";
import { usePresence } from "@agent-native/core/client/collab";
import { SharedRichEditor } from "@agent-native/core/client/editor";
import { ResourcesPanel } from "@agent-native/core/client/resources";
```

기본 `@agent-native/core` 패키지에서 UI 구성 요소를 가져오지 마십시오. 사용
`@agent-native/core/client` 또는 집중된 `@agent-native/core/client/*` 하위 경로
따라서 번들러는 브라우저 안전 항목을 선택합니다.

`@agent-native/toolkit`은 기본 런타임 계약에 속하지 않는 재사용 가능한 앱 구축 요소에 사용하세요: shadcn 스타일 UI primitives, 공유 hooks, 단순 app shell helpers, 기타 template composition modules입니다. 전환 기간 동안 Core는 호환성 re-export를 유지합니다.

재사용 가능한 패키지는 Toolkit 모듈을 직접 가져올 수 있습니다:

```tsx
import { Button } from "@agent-native/toolkit/ui/button";
import { Toaster } from "@agent-native/toolkit/ui/sonner";
import { useToast } from "@agent-native/toolkit/hooks/use-toast";
import { useSetHeaderActions } from "@agent-native/toolkit/app-shell";
```

템플릿 앱 안에서는 앱 로컬 어댑터를 선호하세요. 그러면 팀이 primitive를 한 번 교체해도 재사용되는 모든 Toolkit surface가 로컬 구현을 사용합니다:

```tsx
import { Button } from "@/components/ui/button";
import { useToast } from "@/hooks/use-toast";
```

## 에이전트 및 채팅 UI {#agent-chat-ui}

| API                                  | 가져오기 경로                                   | 다음 경우에 사용                                                                   |
| ------------------------------------ | ----------------------------------------------- | ---------------------------------------------------------------------------------- |
| `<AgentSidebar>`                     | `@agent-native/core/client` 또는 `/client/chat` | 앱 주변에 완전한 사이드바가 필요합니다.                                            |
| `<AgentToggleButton>`                | `@agent-native/core/client` 또는 `/client/chat` | 사이드바에 헤더 버튼을 직접 렌더링합니다.                                          |
| `<AgentPanel>`                       | `@agent-native/core/client` 또는 `/client/chat` | 자신만의 레이아웃, 경로, 대화 상자 또는 측면 열에 전체 패널이 포함되기를 원합니다. |
| `<AgentChatSurface>`                 | `@agent-native/core/client` 또는 `/client/chat` | 사이드바 래퍼 없이 패널 또는 페이지 모드에서 채팅을 원합니다.                      |
| `<AssistantChat>`                    | `@agent-native/core/client` 또는 `/client/chat` | 표준 대화 및 작성기 런타임을 유지하면서 주변 크롬을 소유하고 싶습니다.             |
| `<MultiTabAssistantChat>`            | `@agent-native/core/client` 또는 `/client/chat` | `AgentPanel` 크롬이 없는 프레임워크의 스레드 탭을 원합니다.                        |
| `createHttpAgentChatRuntime()`       | `@agent-native/core/client` 또는 `/client/chat` | 정규화된 채팅 이벤트를 스트리밍하는 BYO 에이전트 엔드포인트가 있습니다.            |
| `createOpenAIAgentsChatRuntime()`    | `@agent-native/core/client` 또는 `/client/chat` | OpenAI 상담원 SDK 스트림이 있고 그 주변에 표준 채팅 UI가 있기를 원합니다.          |
| `createOpenAIResponsesChatRuntime()` | `@agent-native/core/client` 또는 `/client/chat` | OpenAI 응답 이벤트 스트림이 있고 이를 채팅 UI로 정규화하려고 합니다.               |
| `createAgUiChatRuntime()`            | `@agent-native/core/client` 또는 `/client/chat` | AG-UI 이벤트 스트림이 있고 이를 채팅 UI로 정규화하려고 합니다.                     |
| `createClaudeAgentChatRuntime()`     | `@agent-native/core/client` 또는 `/client/chat` | Claude 에이전트 SDK 스트림이 있고 이를 채팅 UI로 정규화하려고 합니다.              |
| `createVercelAiChatRuntime()`        | `@agent-native/core/client` 또는 `/client/chat` | Vercel AI SDK 스트림이 있고 이를 채팅 UI로 정규화하려고 합니다.                    |
| `createAgentChatRuntimeAdapter()`    | `@agent-native/core/client` 또는 `/client/chat` | `AgentChatRuntime`를 어시스턴트 UI에 직접 적용해야 합니다.                         |
| `createAgentChatAdapter()`           | `@agent-native/core/client` 또는 `/client/chat` | 저수준 보조 UI 어댑터로 내장된 Agent-Native SSE 전송이 필요합니다.                 |
| `useChatThreads()`                   | `@agent-native/core/client` 또는 `/client/chat` | 맞춤 스레드 목록, 기록 선택기 또는 범위 지정 채팅 UI가 필요합니다.                 |
| `sendToAgentChat()`                  | `@agent-native/core/client` 또는 `/client/chat` | 제품 작업은 상담원 채팅에서 직접 수행해야 합니다.                                  |

`AgentChatRuntime`는 표준 채팅 셸에 대한 BYO 에이전트 계약입니다. 패스
외부 에이전트가 전원을 공급해야 하는 경우 `runtime`에서 `<AssistantChat>`까지
Agent-Native가 작곡가, 대본, 도구 카드를 보관하는 동안 대화
기본 위젯 렌더링. 위의 커넥터는 API 표면입니다. 런타임
계약 및 이벤트 형태에 대해 배웁니다
[Native 채팅 UI — BYO agent runtimes](/docs/native-chat-ui#byo-agent-runtimes).
헤드리스 에이전트, 리치 채팅, 내장된 사이드카 중에서 선택하는 경우
전체 앱 형태는 [Agent Surfaces](/docs/agent-surfaces)를 참조하세요.

가장 짧은 사용자 정의 경로는 여전히 사전 배선된 표면입니다:

```tsx
import { AgentChatSurface } from "@agent-native/core/client/chat";

export default function ChatRoute() {
  return <AgentChatSurface mode="page" className="h-screen" />;
}
```

표준 런타임에 대한 맞춤 크롬의 경우:

```tsx
import { AssistantChat, useChatThreads } from "@agent-native/core/client/chat";

function CustomChat({ projectSlug }: { projectSlug: string }) {
  const threads = useChatThreads(undefined, projectSlug);
  const threadId = threads.activeThreadId ?? undefined;

  return (
    <section className="grid h-full grid-cols-[260px_1fr]">
      <ThreadList
        threads={threads.threads}
        activeThreadId={threadId}
        onSelect={threads.switchThread}
      />
      <AssistantChat threadId={threadId} />
    </section>
  );
}
```

BYOD(Bring-Your-Own) 에이전트 엔드포인트의 경우 다음 중 하나를 사용하여 `AgentChatRuntime`를 구축하세요.
커넥터를 연결하여 `<AssistantChat runtime={...} />`에 전달합니다. 참조
[Native 채팅 UI — BYO agent runtimes](/docs/native-chat-ui#byo-agent-runtimes)
커넥터 사용, 정규화된 이벤트 스트림 및 도달 시기
`createHttpAgentChatRuntime()`와 프로토콜별 커넥터 비교.

## 채팅 필드 및 작성기 {#composer}

맞춤 UI에서 사이드바와 같은 채팅 필드가 필요하면 `@agent-native/core/client/composer`를 사용하세요.
`@agent-native/toolkit/composer`는 이식 가능한 순수 Tiptap 및 UI 구현을 제공합니다. 프레임워크 서비스를
사용하려면 `ComposerRuntimeAdaptersProvider`로 감싸고 서비스를 제공해야 합니다. Core는 첨부 파일, 멘션, 스킬, 음성 및 모델 선택을 이미 연결한 래퍼입니다.

| API                               | 다음 경우에 사용                                                                                                                                 |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `<PromptComposer>`                | 첨부 파일, 슬래시 명령, 참조, 붙여넣은 텍스트 처리, 초안 지속성, 음성 입력 및 제출 의미 체계가 포함된 제출 준비가 완료된 채팅 필드가 필요합니다. |
| `<AgentComposerFrame>`            | 사용자 정의 작성기 본체 주변에 표준 시각적 셸이 필요합니다.                                                                                      |
| `<TiptapComposer>`                | 최하위 리치채팅 필드가 필요합니다. Assistant-ui `ThreadPrimitive.Root` / 작곡가 런타임 내에서 렌더링되어야 합니다.                               |
| `buildPromptComposerSubmission()` | 자신의 제출 핸들러를 호출하기 전에 동일한 첨부 파일과 붙여넣은 텍스트 정규화가 필요합니다.                                                       |
| `formatPromptWithAttachments()`   | 숨겨진 첨부 파일 메타데이터를 프롬프트 문자열로 렌더링해야 합니다.                                                                               |

대부분의 사용자 정의 UI는 `PromptComposer`로 시작해야 합니다:

```tsx
import { PromptComposer } from "@agent-native/core/client/composer";

<PromptComposer
  placeholder="Ask the agent..."
  onSubmit={async (text, files, references, options) => {
    await sendMessageToYourRuntime({ text, files, references, options });
  }}
/>;
```

이미 보조 UI 프리미티브를 연결한 경우에만 `TiptapComposer`를 사용하세요.
당신 자신. 전체 채팅 런타임이 아닌 필드입니다.

### 작성기에 준비된 컨텍스트 {#composer-context}

`PromptComposer`와 `TiptapComposer`의 `submissionDisabled`는 전송만 차단하고 초안, 파일, 컨텍스트 준비는 허용합니다. 공급자를 설정하지 않아도 준비할 수 있습니다. `disabled`는 여전히 작성기 전체를 비활성화합니다.

`PromptComposer`, `TiptapComposer`, `AgentKitComposer`는 `contextItems`와 `contextMenuItems`를 받습니다. 소스 읽기와 번역된 메뉴 이름은 앱이 관리합니다.

각 `AgentChatContextItem`에는 `key`, `title`, `context`가 있습니다. 선택적인 `status`는 `ready`, `pending`, `error`입니다. `statusMessage`는 실패 이유를 설명합니다. `onRemoveContextItem`, `onInspectContextItem`, `onRetryContextItem`은 항목 키를 받습니다. `removable: false`는 제거를 숨깁니다. 대기 중이거나 실패한 항목은 `blocksSubmission: false`로 정보용임을 명시하지 않으면 제출을 차단합니다.

호스트는 접근이 허용된 컨텍스트를 준비하고 제출 시 변경 불가능한 스냅샷을 받을 수 있습니다.

```tsx
<PromptComposer
  contextItems={contextItems}
  onRemoveContextItem={removeContext}
  onSubmit={(text, files, references, options) =>
    submitPrompt({
      text,
      files,
      references,
      contextItems: options.contextItems,
    })
  }
/>
```

컨텍스트 소스는 `ComposerContextMenuItem`의 `picker`에 등록합니다. `ComposerContextMenu`는 기존 화면을 대체하는 패널이 아니라 연결된 shadcn/Radix 계단식 하위 메뉴를 관리합니다. 루트에는 파일 업로드 다음에 컨텍스트 추가 → 호스트 카테고리 → 소스 선택기가 표시됩니다. 호스트 항목이 없으면 컨텍스트 추가를 표시하지 않습니다. 화살표 키와 Escape로 메뉴 계층을 이동합니다. 링크 선택기의 뒤로 가기는 같은 하위 메뉴 안에서 결과에서 링크 입력으로만 돌아갑니다. 공유 선택기가 검색, 목록 행, 로딩·빈 목록·오류 상태, 재시도, 페이지 이동, 링크 입력을 관리합니다. 앱은 자체 선택기 JSX 대신 접근이 확인된 데이터와 선택 콜백을 제공합니다.

선택기 설정은 다음을 받습니다.

- 앱의 번역된 문구인 `searchPlaceholder`와 선택적 `emptyMessage`. `selectedIds`는 선택된 행을 표시합니다. 항목은 `id`, `title`과 선택적 `disabled`, `url`을 가집니다.
- 로컬 `items`와 선택적 `loading`, `error`, `onRetry()` 또는 원격 `load(request)`. 두 모드는 함께 사용할 수 없습니다.
- `load(request)`는 `search`, 1부터 시작하는 `page`, 선택적 `cursor`와 `url`, `AbortSignal`을 받습니다. `{ items, hasMore?, nextCursor? }`를 반환합니다. 실패하면 빈 결과가 아니라 거부된 Promise를 반환해야 합니다.
- `onSelect(item, request)`는 소스를 준비하며 비동기로 실행할 수 있습니다. `false`를 반환하면 선택기가 열린 상태로 유지됩니다. 오류를 던지면 재시도와 함께 오류가 표시됩니다. 선택적 `clearSelection`은 번역된 `label`과 `onSelect()` 콜백을 제공합니다.
- 선택적 `link`는 번역된 `placeholder`와 `submitLabel`을 제공합니다. `validate(url)`는 오류 문자열을 반환할 수 있습니다. 공유 양식이 링크 입력과 이동을 담당합니다.
- `scopeKey`는 신원이나 접근 범위가 변경되면 선택기의 모든 상태를 초기화합니다. `refreshKey`는 소스 또는 버전 토큰이 변경되면 URL을 초기화하지 않고 현재 쿼리를 무효화합니다. 검색이 변경되면 첫 페이지로 돌아갑니다. 에이전트가 소스 데이터를 수정하면 앱은 갱신된 토큰을 전달합니다.

앱은 이미 접근이 확인된 선택지를 등록할 수 있습니다. 여기서 `labels`는 번역된 앱 문구이고 `stageReference`는 호스트의 준비된 컨텍스트를 갱신합니다.

```tsx
import type { ComposerContextMenuItem } from "@agent-native/core/client/composer";
import { Link } from "react-router";

const contextMenuItems: ComposerContextMenuItem[] = [
  {
    id: "references",
    label: labels.references,
    picker: {
      searchPlaceholder: labels.searchReferences,
      items: authorizedReferences,
      selectedIds,
      onSelect: stageReference,
      footerAction: {
        label: labels.createReference,
        renderLink: (children) => (
          <Link to={createReferenceHref}>{children}</Link>
        ),
      },
    },
  },
];
```

검색이나 링크를 사용하는 소스에는 앱이 인증된 로더를 제공합니다. `loadAuthorizedReferences`는 위 요청/결과 계약을 구현하고 접근 검사를 유지하며 중단 신호를 클라이언트 헬퍼에 전달합니다.

```tsx
const contextMenuItems: ComposerContextMenuItem[] = [
  {
    id: "references",
    label: labels.references,
    picker: {
      searchPlaceholder: labels.searchReferences,
      scopeKey: accessScope,
      refreshKey: sourceVersion,
      load: loadAuthorizedReferences,
      presentation: {
        type: "dialog",
        mode: "multiple",
        onAttach: stageReferences,
      },
      link: {
        label: labels.referenceUrl,
        placeholder: labels.referenceLink,
        submitLabel: labels.findReferences,
        validate: validateReferenceLink,
      },
    },
  },
];
```

`presentation`의 기본값은 `"submenu"`입니다. `{ type: "dialog", mode: "multiple", onAttach }`를 지정하면 일반 메뉴 항목이 공유 대화상자를 열고 항목 레이블이 제목이 됩니다. `link.label`은 URL 입력란의 레이블입니다. 계속 버튼은 결과를 불러오기 전에 자격 증명이 없는 HTTP(S) URL을 검증합니다. 비어 있거나 잘못된 입력으로는 공급자를 호출하지 않습니다. `link.validate()`로 공급자별 규칙을 적용할 수 있습니다. 대화상자 버튼은 `link.submitLabel` 대신 공유 번역 레이블을 사용합니다.

`presentation.onAttach(items, request)`는 새로 선택한 항목을 동결된 단일 배치로 받습니다. 이 모드에서는 `onSelect`를 지정할 수 없습니다. 검색하거나 페이지를 이동해도 선택이 유지됩니다. `selectedIds`는 선택된 비활성 상태로 표시되며 배치에서 제외됩니다. ID는 서로 다른 소스 파일을 구분해야 합니다. `false`를 반환하면 대화상자가 열린 상태로 유지됩니다. 거부되면 재시도 가능한 오류가 표시됩니다. 취소하거나 `scopeKey`가 변경되면 진행 중인 작업을 중단하고 늦은 응답을 무시합니다. 다시 열면 URL이 초기화됩니다. 호스트는 비동기 콜백의 변경을 확정하기 전에 `request.signal`을 확인해야 합니다. `footerAction`과 `clearSelection`은 하위 메뉴 컨트롤로 유지됩니다.

`{ type: "dialog", mode: "url" }`은 결과 목록을 불러오지 않고 바로 첨부합니다. `onSelect(item, request)`는 `{ id: url, title: url, url }`과 `request.url`을 받습니다.

```tsx
const websiteContextItem: ComposerContextMenuItem = {
  id: "website",
  label: labels.attachWebsite,
  picker: {
    searchPlaceholder: labels.searchReferences,
    scopeKey: accessScope,
    presentation: { type: "dialog", mode: "url" },
    link: {
      label: labels.websiteUrl,
      placeholder: labels.websiteUrl,
      submitLabel: labels.attach,
      validate: validateWebsiteUrl,
    },
    onSelect: stageWebsiteReference,
  },
};
```

`@agent-native/core/server`의 `readComposerWebsiteSource(url, extractCallback)`는 호스트의 기존 SSRF 방어 추출기로 웹사이트 참조를 만듭니다. `@agent-native/core/shared`의 `composerSourceRequestSchema`는 `source: "website"`에 대해 `operation: "read"`와 자격 증명이 없는 최대 2,048자의 HTTP(S) `url`만 허용합니다. 헬퍼는 안정적인 URL 해시 ID와 최대 20,000자의 컨텍스트를 포함한 `{ id, title, url, context }`를 반환합니다. 추출 상태, 경고, 렌더링 출처와 `[truncated]` 표시는 컨텍스트 텍스트에 남습니다. 부분 추출도 명시적으로 표시됩니다. 추출 실패나 사용 가능한 `designMd` 누락 시 타입이 지정된 실패를 던집니다. 권한 확인은 여전히 호스트의 [액션](/docs/actions-overview)이 담당합니다.

선택기 항목에는 `render`나 항목 수준의 `onSelect`를 함께 정의하지 않습니다. 카테고리는 `children`을 사용합니다. 루트와 각 카테고리의 헤더에는 검색 입력이 유지됩니다. 카테고리에 번역된 `searchPlaceholder`를 지정할 수 있으며, 생략하면 공유 컨텍스트 검색 자리표시자를 사용합니다. 소스 목록의 검색 입력에는 `picker.searchPlaceholder`를 사용합니다. 등록은 소스 접근 권한을 부여하지 않습니다. 공유 선택기는 새 요청으로 대체된 로드 응답을 무시합니다.

선택적 `footerAction`은 로딩 중이거나 오류 또는 빈 목록 상태여도 결과 아래에 유지됩니다. 번역된 `label`, 선택적 `icon`과 `disabled`, 그리고 `onSelect()` 또는 `renderLink(children)`를 받습니다. 모달이나 상태가 있는 흐름에는 콜백을 사용합니다. `false`는 메뉴를 열린 상태로 유지하고 `true` 또는 `void`는 닫으며, 거부된 Promise는 오류와 재시도를 표시합니다. 단순 페이지 이동에는 `renderLink`에서 실제 React Router `Link` 또는 HTML 링크를 반환합니다. 공유 메뉴가 `asChild`로 행을 제공하므로 `href`와 브라우저 탐색 동작이 유지됩니다. 임시 작업이 아닌 기존의 권한 확인된 흐름에 연결하세요.

`ComposerContextMenu`에 `addAttachment`를 전달하면 표준 업로드 작업이 맨 앞에 표시되고 호스트의 파일 콜백이 유지됩니다.

`PromptComposer`와 `AgentKitComposer`는 `@assistant-ui/react`의 공개 `AttachmentAdapter` 타입을 사용하는 `attachmentAdapter`를 받습니다. 이 어댑터로 호스트의 허용 파일, 크기 검증, 첨부 준비 정책을 제공합니다. 생략하면 기본 어댑터가 유지됩니다. 업로드 컨트롤, 파일 선택기, 컨텍스트 선택기, 첨부 칩은 계속 공유 컴포저가 관리합니다. 파일 준비를 맞춤 설정하려고 이 컨트롤을 교체하지 마세요.

`PromptComposer`와 `AgentKitComposer`의 `inlineTextAttachments` 기본값은 `true`입니다. 호스트가 일반 텍스트 파일을 이미 추출한다면 `false`로 설정하세요. 컴포저는 파일 내용을 읽어 프롬프트에 추가하지 않고 원본 파일을 호스트에 전달합니다. 붙여넣은 텍스트에서 생성된 첨부는 계속 프롬프트 텍스트가 됩니다. 이 옵션은 허용 파일이나 공유 컨트롤을 바꾸지 않습니다.

```tsx
<PromptComposer
  contextItems={contextItems}
  contextMenuItems={contextMenuItems}
  attachmentAdapter={hostAttachmentAdapter}
  onRetryContextItem={retryContext}
  onSubmit={submitPrompt}
/>
```

스냅샷은 `undefined`와 명시적인 빈 배열을 구분합니다. 32개 항목 또는 직렬화된 UTF-8 데이터 64 KiB를 넘으면 자르지 않고 거부합니다. 전송 또는 대기열 등록 전에 `AgentKitComposer.beforeSend(submission)`을 기다리며 고정된 컨텍스트, 참조, 업로드된 첨부 파일 및 실행 옵션을 전달합니다. 거부되면 초안을 유지합니다. 컨텍스트는 메시지 본문과 메타데이터에 포함됩니다.

`composerRef.current.submitWithText(text)`는 편집기를 먼저 바꾸지 않고 현재 파일과 모델 설정으로 동일한 제출 경로를 사용합니다. 수락 후에는 `true`, 차단 또는 거부 시에는 `false`를 반환합니다. 컨텍스트 선택은 접근 권한을 부여하지 않습니다. 앱은 인증된 작업을 통해 소스 접근을 다시 확인해야 합니다.

## 작업공간 리소스 {#resources}

| API                                                                   | 다음 경우에 사용                                                         |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `<ResourcesPanel>`                                                    | 전체 작업공간 탭을 페이지, 서랍 또는 사용자 정의 패널로 원합니다.        |
| `<ResourceTree>`                                                      | 프레임워크 데이터를 중심으로 자체 리소스 브라우저를 렌더링하고 싶습니다. |

| `useResourceTree()`                                                   | 개인, 공유 또는 작업 공간 리소스에 대한 범위 트리가 필요합니다.          |

전체 패널에는 소품이 필요하지 않습니다:

사용자 정의 리소스 크롬의 경우 후크와 기본 요소를 함께 유지하세요.

```tsx
import { useState } from "react";
import {
  ResourceEditor,
  ResourceTree,
  useResource,
  useResourceTree,
  useUpdateResource,
} from "@agent-native/core/client/resources";

function WorkspaceResources() {
  const tree = useResourceTree("workspace");
  const updateResource = useUpdateResource();
  const [selectedId, setSelectedId] = useState<string | null>(null);
  const resource = useResource(selectedId);

  return (
    <div className="grid h-full grid-cols-[260px_1fr]">
      <ResourceTree
        tree={tree.data ?? []}
        selectedId={selectedId}
        onSelect={(item) => setSelectedId(item.id)}
        onCreateFile={() => {}}
        onCreateFolder={() => {}}
        onDelete={() => {}}
        onRename={() => {}}
        onDrop={() => {}}
      />
      {resource.data ? (
        <ResourceEditor
          resource={resource.data}
          onSave={(content) =>
            updateResource.mutate({ id: resource.data.id, content })
          }
        />
      ) : null}
    </div>
  );
}
```

## 일회성 텍스트 완성 {#one-off-text-completion}

원시 텍스트 입력/텍스트 출력이 정말로 필요한 경우 서버측에 유지하고 사용하세요
`@agent-native/core/server`의 `completeText()`. 사용자 대상 사용법을
UI와 에이전트가 동일한 기능을 공유하도록 조치를 취하세요.

<Callout id="doc-block-11d6llv" tone="warning">

`completeText()` is the escape hatch, not the default. Reach for it only for true text-in/text-out (a label, a one-line rewrite). Anything needing tools, state, auditability, or steering belongs in an action plus `sendToAgentChat({ background: true })`.

</Callout>

```ts
import { defineAction } from "@agent-native/core/action";
import { completeText } from "@agent-native/core/server";
import { z } from "zod";

export default defineAction({
  description: "Classify a short message",
  schema: z.object({ body: z.string() }),
  run: async ({ body }) => {
    const result = await completeText({
      systemPrompt: "Return exactly one label.",
      input: body,
      maxOutputTokens: 12,
      temperature: 0,
    });
    return { label: result.text.trim() };
  },
});
```

대신 `sendToAgentChat({ background: true, openSidebar: false })`를 사용하세요
작업에 도구, 상태, 감사 가능성, 사용자 조정 또는 다단계가 필요함
추론.
