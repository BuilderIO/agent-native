# 개발자 가이드

이 페이지는 Design 템플릿을 커스터마이즈하거나 그 위에 직접 무언가를 만들려는
모든 사람을 위한 것입니다. 빠른 시작, 모든 액션, 데이터 모델, 액션 하나를
자세히 살펴보기, 라우트 구성, 그리고 기능을 추가하는 방법을 다룹니다. 앱이
무엇을 하는지는 [Design](/docs/template-design) 문서를 참고하세요.

## 빠른 시작

<Steps>

### 앱 만들기

```bash
npx @agent-native/core@latest create my-design --standalone --template design
cd my-design
pnpm install
```

먼저 [Node.js](https://nodejs.org) 22.22 이상과 [pnpm](https://pnpm.io)이
설치되어 있어야 합니다. 아직 설치하지 않았거나 LLM 연결(Builder.io,
Anthropic/OpenAI 키, 또는 로컬 Ollama)을 설정하지 않았다면 [시작하기](/docs/getting-started)
문서를 참고하세요. Design을 다른 앱과 함께 사용하는 작업 공간을 원한다면
대신 `npx @agent-native/core@latest create my-platform`을 실행하고 설정
과정에서 Design을 선택하세요.

### 개발 서버 시작하기

```bash
pnpm dev
```

앱이 Design의 기본 개발 포트인 `http://localhost:8099`에서 열립니다.
Design은 외부 연결 없이도 완전히 동작합니다. Figma 가져오기나 전체 앱
빌딩을 설정하기 전에 시도할 때만 연결 프롬프트를 보게 됩니다.

</Steps>

## 액션 목록

Design 전용 작업은 모두 `templates/design/actions/`에 있는 TypeScript
파일이며, `POST /_agent-native/actions/:name`에 자동으로 마운트되고 CLI에서
`pnpm action <name>`으로 실행할 수 있습니다.

### 디자인

| 액션                      | 동작                                                         |
| ------------------------- | ------------------------------------------------------------ |
| `create-design`           | 빈 디자인 셸 생성                                            |
| `generate-design`         | 생성된 HTML/JSX 파일 내용 작성                               |

## 데이터 모델

모든 데이터는 Drizzle ORM을 통해 SQL에 있습니다. 스키마:
`templates/design/server/db/schema.ts`. 디자인과 디자인 시스템은 표준
`ownableColumns`와 이에 대응하는 프레임워크 공유 테이블을 가지므로,
사용자별/조직별 공유 모델에 속합니다.

아래 표는 디자인, 파일, 템플릿, 버전, 디자인 시스템이라는 핵심 소유 가능
리소스를 다룹니다.

| 테이블                                   | 무엇을 담고 있는지                                                                                                                         |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |

디자인 프로젝트는 콘텐츠가 생기기 전까지는 빈 껍데기입니다. `create-design`이
빈 행(`data: "{}"`)을 만들고, 그다음 `generate-design`이 실제 독립형 HTML/JSX
파일을 작성합니다. 생성된 아티팩트, 편집 가능한 소스, 그리고 모든 내보내기는
전부 같은 HTML에서 나오므로, 따로 옮겨야 할 별도의 "AI 목업" 형식은 없습니다.
연결된 디자인 시스템은 에이전트가 모든 생성 과정에서 준수하는 토큰과
`custom_instructions`를 제공합니다.

일곱 개의 테이블이 더 있는데, 이들은 핵심 리소스 모델이 아니라 이 페이지의
다른 부분에서 다루는 기능을 뒷받침합니다. `design_localhost_connections`와
`design_localhost_write_grants`는 [로컬 앱 가져오기](/docs/template-design-features#import)를
뒷받침하고, `component_index`는 [Design 탭의 컴포넌트
섹션](/docs/template-design-features#design-tab)을 뒷받침하며,
`motion_timeline`은 각 요소의 편집 가능한 모션 타임라인(편집기의 Motion
독)을 뒷받침하고, `design_state`는 디자인의 이름 붙은 대체 상태, 정적
픽스처, 실행 중인 앱 캡처를 담고 있으며, `design_fusion_edits`는 위 [전체 앱
빌딩](#full-app-building)에서 설명한 fusion 편집 대기열을 뒷받침하고,
`design_review_snapshot`은 위 [품질](#quality)에서 설명한 `get-design-review`
뒤에 있는 접근성 검사 결과와 시각적 차이를 캐시합니다.

저장된 리뷰 댓글과 스레드(`get-review-feedback`, `resolve-review-thread`
등)는 Design 전용 테이블이 전혀 아닙니다. 어떤 앱이든 붙일 수 있는 방식으로
디자인에 범위가 지정된, `@agent-native/core/review`의 공유 프레임워크 리뷰
시스템(`agent_review_comments` / `agent_review_statuses`)입니다. 사용자에게
보이는 동작은 [댓글 탭](/docs/template-design-features#comments-tab)을
참고하세요.

## 편집기 모델

Design은 여러 화면 작업에서 개요를 우선합니다. 생성이나 광범위한 업데이트
이후 편집기는 화면 개요를 엽니다. 각 화면을 선택, 이동, 크기 조정, 드롭,
복제할 수 있는 정적 프레임으로 배치하는 무한 캔버스입니다. 한 화면에 집중된
스크롤이나 프로토타입 인터랙션이 필요할 때는 프레임의 전체 보기 버튼을
사용하세요.

단일 화면 모드는 스크롤, 프로토타입 동작과의 상호작용, 그리고 렌더링된 파일
하나 안에서 DOM/코드 레이어를 편집하는 데 사용합니다. 레이어 패널도 이
구분을 그대로 반영합니다. 화면은 최상위 프레임이고, 활성 화면 아래에 중첩된
DOM/코드 레이어가 있습니다.

모든 화면은 브레이크포인트마다 별도로 복사되는 것이 아니라, 서로 다른
너비로 렌더링되는 하나의 문서입니다. 기본(가장 넓은) 프레임이 아래로
계단식 적용되며, 더 좁은 활성 브레이크포인트에서 만든 편집은 그 위에 너비
범위가 지정된 재정의로 저장됩니다.

## 편집기 확장

편집기에는 **Tweaks** 뒤에 **Extensions** 검사기 탭이 있습니다. Design
전용 플러그인 레인처럼 동작합니다. 사용자는 **+ Extension**을 클릭해
에이전트에게 확장을 만들어 달라고 요청하거나, `design.editor.inspector`
슬롯을 선언한 확장을 설치할 수 있으며, 이때 쓰이는 것은 Design 전용
액션이 아니라 프레임워크의 `create-extension`, `add-extension-slot-target`,
`install-extension` 액션입니다.

Design 확장은 표준 확장 샌드박스를 통해 아트보드 옆에 인라인으로
렌더링됩니다. 호스트는 현재 `designId`, 활성 파일, 화면 목록, 선택된 화면
id, 선택된 요소 메타데이터, 보기 모드, 줌, 활성 도구, 조정 값을
`window.slotContext`와 `window.onSlotContext(...)` 업데이트로 전달합니다.
이를 통해 확장은 현재 선택 항목에 대한 정보를 보여주거나, 스타일 컨트롤을
제공하거나, 열려 있는 디자인 주변의 간결한 워크플로를 만들 수 있습니다.

결정적인 작업에는 확장이 확장 브리지를 통해 앱 액션을 호출할 수 있습니다.
AI 기반 변경에는 선택된 요소의 selector/source id와 요청한 변경 내용을
담아 확장이 `agentNative.chat.send(...)`를 호출하게 하세요. 에이전트는
먼저 `view-screen`을 호출한 다음, 요소의 스타일·클래스·텍스트·이동
변경에는 `apply-visual-edit`를, 아트보드 배치 변경에는 `canvasFrames`와
함께 `update-design` / `generate-design`을 사용해야 합니다. 샌드박스,
영속 상태, 브리지 API는 [확장](/docs/extensions#capabilities) 문서를
참고하세요.

## 맞춤 설정

Design은 완전하고 복제 가능한 템플릿입니다. 실용적인 확장 아이디어
몇 가지입니다.

- "우리 토큰과 샘플 컴포넌트를 사용하는 재사용 가능한 이커머스 디자인 시스템을 추가해줘."
- "ZIP을 내부 리뷰 시스템에 업로드하는 내보내기 단계를 추가해줘."
- "기존 랜딩 페이지 HTML을 붙여넣고 에이전트에게 더 강력한 버전 세 가지를 요청할 수 있게 해줘."
- "제품 페이지, 대시보드, 온보딩 화면 브리프를 위한 저장된 프롬프트 라이브러리를 추가해줘."
- "이해관계자 검토를 위한 사용자 지정 PDF 내보내기 프리셋을 추가해줘."

에이전트는 필요에 따라 라우트, 컴포넌트, 액션, SQL 기반 모델을 편집합니다.
전체 복제, 커스터마이즈, 배포 흐름은 [템플릿](/docs/cloneable-saas) 문서를
참고하고, 이것이 여러분의 첫 Agent-Native 템플릿이라면
[시작하기](/docs/getting-started) 문서를 참고하세요.
