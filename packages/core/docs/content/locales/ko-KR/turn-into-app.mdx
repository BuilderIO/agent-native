# 앱으로 전환

`/turn-into-app`은 이미 검증된 워크플로를 Agent-Native 앱으로 바꿔 주는 skill입니다. 소스는 스레드, skill, 스프레드시트 또는 Claude나 ChatGPT 프로젝트일 수 있습니다. 앱은 소스와 비슷한 형태의 샘플 데이터로 채워진 사용자의 세계에서 열리며, 앱 내 에이전트는 자신이 작업하는 객체의 컨트롤 뒤에서 동작합니다. 단계 표시줄 아래의 폼은 이 skill이 피하려는 결과물입니다.

## 설치 {#install}

```bash
npx @agent-native/skills@latest add --skill turn-into-app
```

같은 skill이 코어 CLI에도 포함되어 있습니다.

```bash
npx @agent-native/core@latest skills add turn-into-app
```

Agent-Native CLI가 이미 있는 프로젝트 안에서는 `agent-native skills add turn-into-app`이 같은 작업을 수행합니다. skills가 설치되고 로드되는 방식은 [Skills 가이드](/docs/skills-guide)를 참조하세요.

## 호출하기 {#invoke}

| 명령                               | 소스                                                    |
| ---------------------------------- | ------------------------------------------------------- |
| `/turn-into-app`                   | 보이는 프로젝트 컨텍스트, 없으면 현재 스레드            |
| `/turn-into-app /some-skill`       | 이름을 지정한 skill, 스레드 시작 시점이라도 즉시 패키징 |
| `/turn-into-app ./forecast.xlsx`   | 워크벤치로 바뀌는 스프레드시트                          |
| `/turn-into-app ./project-export/` | Claude 또는 ChatGPT 프로젝트 내보내기                   |

인수가 없으면 skill은 가장 최근에 성공한 반복 가능한 작업을 앱으로 만들고 그 이름을 밝힙니다. 계정 하나나 거래 하나 같은 구체적인 예시는 작업의 근거일 뿐 스키마가 아닙니다. 작업을 식별할 수 없으면 일반적인 "어떤 앱을 원하세요?"라는 질문 대신 무엇이 부족한지 알려 줍니다.

## 실행 환경 {#hosts}

| 호스트                                              | 동작                                                                                                                  |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Claude Code, Codex, Cursor, 기타 로컬 코딩 에이전트 | 사용자의 체크아웃에서 앱을 빌드하고 실행하며 검토합니다.                                                              |
| 웹의 Claude 또는 ChatGPT                            | 범위가 정해진 브리프를 작성하여 Dispatch 커넥터를 통해 Builder에 전달합니다. 자체적으로는 아무것도 실행하지 않습니다. |

호스트에 실제 작업 디렉터리, 터미널, 워크스페이스가 있으면 로컬 호스트로 간주합니다. Builder나 Dispatch 커넥터가 있다고 해서 브라우저 호스트가 되는 것은 아닙니다.

브라우저 호스트에서는 skill이 Agent-Native Dispatch MCP 커넥터(`https://dispatch.agent-native.com/mcp`, OAuth)를 필요로 하며 해당 커넥터의 `start-workspace-app-creation` 액션을 호출합니다. 호스트는 앱을 실행하거나 검사할 수 없으므로, Dispatch가 반환한 브랜치가 빌드될 때까지 보고서는 보류 또는 미검증 상태로 남습니다. skill은 Dispatch가 실제로 반환한 내용만 보고하며 브랜치 URL을 지어내지 않습니다. ChatGPT 프로젝트나 MCP만 노출하는 호스트에서는 skill 지침을 프로젝트 지침이나 지식 파일에 넣으세요.

## 소스 {#sources}

- **스레드.** 가장 최근의 구체적이고 반복 가능한 작업이 제품이 됩니다.
- **Skills.** skill의 단계, 사람이 결정하는 지점, 읽기 전용 규칙이 앱이 됩니다. skill이 계획 파일을 유지한다면 해당 파일은 Local File Mode를 통해 계속 기준 소스로 남고 앱은 로컬 전용이 됩니다.
- **스프레드시트.** 모든 워크시트를 먼저 목록화합니다. 어떤 셀이 입력이고 출력인지는 구조로 결정하며, 색상은 약한 힌트일 뿐입니다. 워크북은 프롬프트, SQL, 애플리케이션 상태에 복사되지 않습니다. Google Sheets 링크는 인증된 Sheets 또는 Drive 연결로 읽을 수 있을 때만 소스가 되며, 그렇지 않으면 skill이 내보내기를 요청합니다.
- **Claude 및 ChatGPT 프로젝트.** 보이는 지침, 지식 파일, 제공된 과거 실행 내역이 소스입니다. 커넥터는 숨겨진 프로젝트 채팅, 비공개 URL, 자격 증명을 읽지 않으며 공유 링크 가져오기 기능도 없습니다. 컨텍스트가 보이지 않으면 내보내기 파일을 첨부하세요.

## 결과물 {#what-you-get}

- **소스에서 선택된 형태.** skill은 분류 대기열, 파이프라인 보드, 라이브 워크벤치, 일정 그리드, 리뷰 diff, 모니터 같은 13가지 아키타입 중 하나를 고릅니다. 아키타입은 사용자가 따르는 절차가 아니라 사용자가 보는 객체이므로, 소스의 단계는 스테퍼나 마법사가 아니라 객체의 상태(초안, 확인됨, 승인됨)가 됩니다.
- **이름이 있는 시각적 방향.** 아키타입과 소스의 도메인에 따라 선택되는 여섯 가지 방향(`ledger`, `control-room`, `paper-desk`, `studio-canvas`, `tidepool`, `signal-board`) 중 하나이며 라이트 및 다크 토큰을 갖습니다. 기존 브랜드나 사용자가 명시한 방향이 우선합니다.
- **채워진 첫 화면.** `/`는 소스와 비슷한 형태의, 샘플로 표시된 합성 샘플 데이터가 있는 도메인 경로로 연결됩니다. 소스 자체가 폼 형태가 아니라면 빈 상태, 히어로, 절차의 첫 단계, 폼은 결함입니다.
- **객체 위의 에이전트 순간.** AI 라벨이 붙은 각 컨트롤은 범위가 정해진 프롬프트를 에이전트 사이드바에 전달합니다. 객체는 즉시 작업 중 상태를 표시하고, 결과는 수락, 편집, 재시도 버튼과 함께 해당 객체로 돌아옵니다. 후속 질문은 같은 스레드에서 이어집니다.
- **진짜 Agent-Native 앱.** 결정적인 작업은 UI와 에이전트가 모두 호출하는 `defineAction` 파일입니다. 앱은 표준 Use Builder.io 또는 Custom keys 설정을 사용하고, 현재 보기와 선택 항목을 애플리케이션 상태에 기록하며, 앱 내 에이전트에게 새 앱을 알려 주는 `AGENTS.md`를 갖습니다.

skill은 소스 브리프를 `docs/brief.md`로 저장하고 화면 디자인을 `DESIGN.md`에 추가합니다.

## 실행 과정 {#how-it-works}

1. **브리프.** 전체 소스를 읽고 짧은 브리프를 작성합니다. 작업, 최대 세 개의 에이전트 순간, 불변 조건, 데이터 위험, 기준 소스, 가정이 포함됩니다.
2. **디자인.** 아키타입, 방향, 셸, 첫 뷰포트와 샘플 데이터, 에이전트 순간을 결정하고 브리프를 체크포인트로 한 번 게시합니다. 기다리지 않고 계속 진행합니다.
3. **스캐폴드.** chat 템플릿으로 실제 앱을 만들며 기존 앱을 덮어쓰지 않습니다.

   ```bash
   npx --yes @agent-native/core@latest create <slug> --standalone --template chat
   ```

   기존 Agent-Native 워크스페이스 안에서는 대신 워크스페이스 루트에서 `pnpm exec agent-native add-app <slug> --template chat`을 실행합니다.

4. **빌드.** 액션, 도메인 화면, 샘플 데이터, 에이전트 순간, 에이전트 지침을 함께 빌드합니다.
5. **리뷰.** 앱을 실행하고 스크린샷을 검토합니다. 아래를 참조하세요.
6. **검증.** `pnpm typecheck`, `pnpm agent-native:doctor`, `pnpm build`를 실행한 뒤 최종 보고서를 작성합니다.

skill의 목표 소요 시간은 약 45분입니다. 리뷰를 시작할 때 이미 35분이 지났다면 한 번만 실행하고 남은 기준을 나열합니다.

## 스크린샷 리뷰 루프 {#review-loop}

인계하기 전에 skill은 개발 서버를 시작하고, 데스크톱과 휴대폰 크기의 라이트 및 다크 모드에서 `/`를 스크린샷으로 캡처하며, 클릭 후의 주요 에이전트 컨트롤도 캡처합니다. 스크린샷은 첫 뷰포트 임팩트, 도메인 적합성, 계층 구조, 크롬 절제, 샘플 데이터, 타이포그래피, 색상, 완성도, 에이전트와 UI의 조화, 390px 레이아웃, 다크 모드, 접근성을 다루는 12개 항목의 루브릭으로 채점됩니다.

일부 발견 사항은 평균 점수와 관계없이 리뷰를 실패시킵니다. 스테퍼나 마법사 셸, 도메인 경로로 열리지 않는 `/`, 비어 있거나 폼만 있는 첫 뷰포트, 스캐폴드 기본 토큰, 잘린 텍스트, 원시 마크다운, 390px에서의 가로 스크롤, 콘솔 오류가 그에 해당합니다. skill은 모든 발견 사항을 한 번에 수정하고, 클릭으로 바뀐 것을 초기화한 뒤 다시 촬영합니다. 기본은 두 번의 패스이며, 두 번째 패스도 기준에 못 미치고 시간이 허락할 때만 세 번째를 진행합니다. 기준은 평균 4.0 이상이며, 3 미만인 항목과 자동 실패 항목이 없어야 합니다.

스크린샷은 앱의 `.tmp/ui-review/out/`에 저장되며, 최종 보고서에 경로와 점수가 나열됩니다. UI에 표시되는 결과는 AI 제공자가 연결되어 있어야만 직접 확인할 수 있으며, 연결되지 않은 경우 보고서에 결과를 확인하지 못했다고 명시됩니다.

## 실행 및 배포 {#run-deploy}

로컬 리뷰를 위해 skill은 앱의 무시된 `.env`에 `AUTH_DISABLED=1`을 설정합니다. 새 스크린샷 브라우저는 로그인되어 있지 않기 때문입니다. 이는 루프백 개발 전용입니다. 최종 `pnpm build` 전에 제거되며 절대 커밋하거나 배포해서는 안 됩니다. 이 설정이 없으면 앱을 열 때 "Continue as local dev" 카드가 표시됩니다.

앱을 직접 실행하려면 다음을 사용하세요.

```bash
pnpm dev
```

로컬에서 자신의 모델 제공자를 사용하려면 같은 `.env`에 `ANTHROPIC_API_KEY` 같은 키를 넣으세요. 그렇지 않으면 에이전트 사이드바에 공유 Use Builder.io 또는 Custom keys 설정이 표시됩니다.

skill은 사용자가 요청하거나 제공자가 이미 구성된 경우에만 배포합니다. 정상적인 로컬 빌드도 종료 코드 0과 함께 "production configuration errors" 블록을 출력합니다. 이것이 배포 체크리스트이며, 안정적인 `BETTER_AUTH_SECRET`과 영구적인 `DATABASE_URL`, 그리고 워크스페이스 안의 앱에는 `A2A_SECRET`이 포함됩니다. skill은 이를 보류 중인 단계로 보고하며 자리 표시자 값을 만들지 않습니다. [앱 배포](/docs/deploy-an-app)와 [워크스페이스 배포](/docs/workspace-deployment)를 참조하세요.

최종 보고서는 증거를 구분해서 표기합니다. 로컬 실행 중, 로컬 검증됨, 빌드 준비 완료, 배포됨, 라이브 검증됨은 서로 다른 상태이며, 보고서는 하나가 다른 하나를 대신하게 두지 않습니다.

## 알려진 제한 사항 {#limits}

- **개발 서버 실행 중 `.env` 편집.** `.env`를 변경한 뒤 제자리에서 다시 로드하면 로컬 데이터베이스 잠금에서 루프가 발생하고 500 오류가 반환됩니다. 서버를 중지하고 `.env`를 편집한 뒤 다시 시작하세요.
- **모호한 스프레드시트.** 제한된 검토 후에도 후보 워크플로나 입력과 출력 매핑이 상당히 모호하면, skill은 권장 해석과 함께 간결한 질문 하나를 합니다. 헤드리스 실행에서는 질문을 출력하고, 가정을 브리프에 기록한 뒤 계속 빌드합니다.
- **브라우저 호스트의 스프레드시트.** 워크북은 첨부할 수 없습니다. 호스트가 제한된 CSV 렌더링을 텍스트로 전달하거나 공개 URL을 전달하며, 인계 시 제외된 내용을 알려 줍니다.
- **셀 색상.** 텍스트 미리 보기로는 색상을 증명할 수 없으므로, 로컬 호스트에서는 skill이 수식과 캐시된 값을 모두 읽고 색상은 약한 힌트로 취급합니다.
- **Local File Mode 앱.** 기준 소스가 호스트의 파일인 앱은 로컬 전용이며 배포되지 않습니다.
- **브라우저 호스트 인계.** Dispatch가 빌드된 브랜치를 반환할 때까지 결과는 미검증 상태입니다. skill은 그곳에서 앱을 실행하거나 스크린샷을 찍을 수 없습니다.
