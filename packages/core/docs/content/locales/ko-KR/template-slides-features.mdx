# 기능

슬라이드의 모든 핵심 기능이 어떻게 동작하고 어떻게 설정하는지 다룹니다. 전체 개요는
[슬라이드](/docs/template-slides) 문서를, 프롬프트 전체 목록은 [Agent와
대화](/docs/template-slides-agent) 문서를 참고하세요.

## 데크

하나의 데크를 만들고, 편집하고, 발표하고, 공유하는 모든 것을 다룹니다.

### 프롬프트로 데크 생성하기

<Steps>

### 사람에게 브리핑하듯 에이전트에게 브리핑하세요

"커피 구독 서비스를 위한 10장짜리 피치 데크를 생성해줘. 대상은 투자자야." 주제, 길이, 대상을 알려주면 그에 맞춰 개요를 구성합니다.

### 슬라이드가 하나씩 만들어지는 과정을 지켜보세요

에이전트는 먼저 개요를 계획한 다음, 슬라이드를 한 번에 하나씩 만들어 가므로 전체가 한꺼번에 완성되기를 기다리는 대신 편집기에 나타나는 과정을 지켜볼 수 있습니다.

### 같은 대화에서 계속 다듬으세요

"슬라이드 3 뒤에 가격 슬라이드를 추가해줘." "이 섹션을 더 짧게 만들어줘." 요청한 슬라이드만 변경됩니다.

</Steps>

새 데크는 기본적으로 16:9 와이드스크린 캔버스로 시작합니다. 다른 형태가 필요하면 에이전트에게 1:1(정사각형), 9:16(세로, 스토리 스타일), 또는 4:5(세로형)로 바꿔달라고 요청하세요. 비율을 바꾸면 편집기 캔버스, 발표 모드, PDF/PPTX 내보내기가 함께 업데이트되므로, 만든 것과 다른 내보내기 결과를 얻을 일이 없습니다.

### 슬라이드를 시각적으로 편집하기

- **인라인 텍스트 편집.** 어떤 텍스트든 두 번 클릭하면 슬라이드에서 바로 편집할 수 있습니다.
- **풍선 메뉴.** 블록, 제목, 글머리 목록, 이미지를 클릭하면 그 블록만을 위한 빠른 서식 옵션이 나타납니다.
- **슬래시 메뉴.** `/`를 입력하면 키보드에서 손을 떼지 않고 새 블록, 제목, 글머리 목록, 표, 코드 블록, 이미지 자리표시자를 삽입할 수 있습니다.
- **순서 바꾸기.** 필름스트립에서 슬라이드를 드래그해 순서를 바꿀 수 있습니다. 실행 취소와 다시 실행도 예상대로 동작합니다.
- **풍부한 임베드.** 슬라이드에는 정적인 HTML뿐 아니라, 텍스트와 이미지와 함께 손으로 그린 다이어그램이나 실시간으로 렌더링되는 차트도 담을 수 있습니다.
- **생성된 콘텐츠 이동 및 크기 조정.** 개체를 드래그해 이동하거나, 크기 조정 핸들을 드래그해 크기를 바꾸세요. 테두리로 감싸인 섹션을 이동하려면 그 안의 텍스트를 드래그하세요.

슬라이드에서 텍스트를 선택하고 풍선 메뉴의 **AI로 수정** 버튼을 클릭하면 선택한 부분을 정확히 에이전트에게 넘길 수 있습니다. 또는 슬라이드에서 여러 요소를 선택하고 **에이전트에게 보내기**를 클릭한 다음, 오른쪽 채팅창에 프롬프트를 입력하세요. 선택 인식 편집이 동작하는 방식은 [Agent와 대화](/docs/template-slides-agent) 문서를 참고하세요.

### 전체 화면으로 발표하기

**발표**를 클릭하면 데크가 전체 화면으로 열립니다. 마우스를 움직이기 전까지 컨트롤은 사라져 있으며, 발표자 노트는 여러분에게만 보입니다. 발표 중에는 다음 단축키를 사용할 수 있습니다.

| 키                     | 동작                           |
| ---------------------- | ------------------------------ |
| `→`, `↓`, 또는 `Space` | 다음 슬라이드                  |
| `←` 또는 `↑`           | 이전 슬라이드                  |
| `F`                    | 전체 화면 전환                 |
| `S`                    | 발표자 노트를 별도 창으로 열기 |
| `Esc`                  | 발표 모드 종료                 |

### 댓글 달기와 실시간 협업

툴바에서 **댓글** 패널을 열면 지금 보고 있는 슬라이드의 댓글을 보고 추가할 수 있습니다. 이 패널은 해당 슬라이드로 범위가 좁혀져 있어서, 다른 슬라이드로 전환하면 내용도 그에 맞춰 바뀝니다. 데크 전체의 댓글이 한꺼번에 표시되는 일은 없습니다. 텍스트를 먼저 선택하면 새 댓글에 인용할 수 있고, 툴바의 **댓글 고정** 도구를 사용하면 특정 요소에 직접 고정 핀을 놓을 수 있습니다.

편집 권한이 있는 사람은 누구나 스레드에서 댓글을 남기고 답할 수 있습니다. 처리가 끝난 스레드는 해결 완료로 표시하세요. 여러 사람(그리고 에이전트)이 같은 데크를 동시에 편집해도 서로의 변경 사항을 덮어쓰지 않습니다. 내부적으로 어떻게 동작하는지는 [실시간 협업](/docs/real-time-collaboration) 문서를 참고하세요.

### 데크 공유하기

데크는 다른 Agent-Native 리소스를 공유하는 것과 같은 방식으로 공유합니다. 비공개로 유지하거나, 특정 팀원에게 뷰어 또는 편집자 권한으로 공유하거나, 계정 없이 누구나 열 수 있는 공개 읽기 전용 링크를 생성할 수 있습니다. 전체 모델은 [공유](/docs/sharing) 문서를 참고하세요.

### 이전 버전 복원하기

여러분이든 에이전트든, 의미 있는 변경을 하기 전에 데크의 스냅샷이 먼저 기록되므로 아무것도 조용히 사라지지 않습니다. 버전 기록을 열면 과거 스냅샷의 타임라인을 확인하고 원하는 시점으로 복원할 수 있습니다. 복원 작업 역시 그 전에 자체 스냅샷을 남기므로, 복원한다고 해서 되돌릴 수 없는 상황에 빠지지 않습니다.

### 데크를 다른 형식으로 주고받기

| 방향     | 형식                         | 동작                                                                                                                                                         |
| -------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 가져오기 | PPTX, DOCX, PDF, Google Docs | 편집 가능한 슬라이드로 변환됩니다. PDF나 DOCX는 페이지 또는 섹션 하나가 슬라이드 하나가 되고, PPTX는 원래의 슬라이드 구성과 발표자 노트를 그대로 유지합니다. |
| 내보내기 | PPTX                         | 각 슬라이드를 이미지로 평탄화한 것이 아니라, 네이티브하고 편집 가능한 텍스트, 도형, 이미지로 내보냅니다.                                                     |
| 내보내기 | Google Slides                | Google Slides에는 "이 URL을 여세요" 방식의 직접 가져오기가 없으므로, 슬라이드가 동일한 PPTX를 생성하고 바로 사용할 수 있는 가져오기 링크를 제공합니다.       |
| 내보내기 | 독립 실행형 HTML             | 키보드 탐색이 내장된 단일 자체 완결 파일로, 어디에든 호스팅하거나 이메일로 보낼 수 있으며 보는 데 별도 앱이 필요 없습니다.                                   |

GitHub 저장소, 코드베이스, 또는 웹사이트 URL을 가져오는 것은 데크 콘텐츠를 가져오는 것과는 다른 기능입니다. 이 세 가지는 슬라이드 단위 콘텐츠 가져오기가 아니라 [디자인 시스템](#design-systems)에서 설명하는 디자인 시스템 색인화에 사용됩니다.

## 디자인 시스템 {#design-systems}

디자인 시스템은 브랜드 아이덴티티를 재사용 가능한 형태로 묶은 것입니다. 기본/강조/배경 색상, 제목과 본문 폰트, 여백, 로고, 그리고 자유 형식의 커스텀 지침("섹션 레이블은 항상 소문자로 쓴다", "스톡 사진은 절대 쓰지 않는다")을 포함합니다. 개별 데크와는 별개인 독립된 리소스입니다. 하나를 저장해두면 모든 새 데크가 일반적인 기본값 대신 이를 사용할 수 있습니다.

### 디자인 시스템 추가하기

<Steps>

### 디자인 시스템 열기

사이드바에서 **디자인 시스템**을 열고 **새 디자인 시스템**을 클릭하세요.

### 브랜드 자료 추가하기

가지고 있는 것을 입력하세요. 회사 이름과 웹사이트, GitHub 저장소, 코드 파일, 문서, 참고 이미지나 로고, 메모, 또는 커스텀 지침 등입니다.

### 생성으로 계속하기 클릭

이렇게 하면 디자인 시스템 구축이 시작됩니다. 그다음에 정확히 무슨 일이 일어나는지는 제공한 자료에 따라 달라집니다.

</Steps>

#### 그다음은 소스에 따라 달라집니다

Figma 파일을 업로드하거나 GitHub 저장소만 입력하면 디자인 시스템이 즉시 만들어집니다. 그 외의 경우에는 사이드바에서 에이전트가 열려 마무리 작업을 진행합니다. 색상 선택기나 폰트 선택기는 따로 없습니다. 브랜드 색상과 폰트는 항상 에이전트가 해석하는 소스에서 나오거나, 메모와 커스텀 지침에 직접 입력한 내용에서 나옵니다.

#### 기본값 설정하기

디자인 시스템 하나를 기본값으로 지정하면 모든 새 데크가 자동으로 이를 사용합니다. 또는 새 데크를 시작할 때 직접 선택할 수도 있습니다.

### Builder 연동

Figma 파일, 연결된 코드베이스나 GitHub 저장소, 또는 `design.md`는 실제 분석이 필요하므로, 한 번의 로컬 추측이 아니라 Builder Design System Intelligence를 거칩니다.

#### Builder 연결하기

여기에는 연결된 Builder.io 계정이 필요합니다(무료 등급을 사용할 수 있습니다). 아직 연결하지 않았다면, 필요한 시점에 에이전트가 연결하도록 안내합니다.

#### Builder가 최종 소스로 유지됩니다

소스를 색인화하고 그 결과로 나온 문서, 추출된 토큰, 사용 가이드를 소유하는 것은 슬라이드가 아니라 Builder입니다. 슬라이드는 그 결과를 가리키는 가벼운 포인터만 로컬에 보관하며, 디자인 시스템을 적용할 때마다 에이전트가 Builder에서 최신 문서를 가져옵니다.

### Figma 파일

`.fig` 파일은 놓는 즉시 색인화가 시작되는 유일한 소스로, 에이전트 채팅 단계가 필요 없습니다. 설정 대화상자의 Figma 패널에 파일을 드래그하거나, 클릭해서 찾아보세요. 슬라이드가 파일을 업로드하고 Builder Design System Intelligence 색인화 작업을 곧바로 시작하며, 색인화가 끝나면 그 결과가 어떤 데크에도 적용할 수 있는 디자인 시스템이 됩니다.

### 데크별로 적용하고 조정하기

디자인 시스템이 데크에 연결되면, **조정** 패널에서 저장된 시스템을 직접 편집하지 않고도 강조 색상 스와치, 제목 대소문자, 배경 톤 같은 항목을 즉석에서 빠르게 재정의할 수 있습니다. 유지하기로 한 변경은 디자인 시스템에 다시 저장됩니다.
