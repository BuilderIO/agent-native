# 다중 앱 작업 공간 속 클립

클립은 [Dispatch](/docs/template-dispatch) 작업 공간에 속한 여러 앱 중 하나입니다.
이 페이지는 그것이 실제로 무엇을 의미하는지, 즉 연결이 어떻게 동작하는지, 그리고
다른 앱과 에이전트가 여러분의 클립에 실제로 어떻게 작용하거나 클립에서 일어나는 일에
반응할 수 있는지를 구체적으로 다룹니다. 전체 개요는 [클립](/docs/template-clips)
문서를 참고하세요.

## 클립이 Dispatch와 연결되는 방식

이것이 자동으로 이루어지는지는 클립과 Dispatch를 어떻게 함께 설정했는지에 따라
달라지며, 둘 중 하나가 호스팅되어 있는지 로컬에서 실행 중인지와는 관련이 없습니다.

### 같은 작업 공간: 자동

클립과 Dispatch가 하나의 Agent-Native 작업 공간에 (`create` 또는 `add-app`을
통해) 함께 생성되거나 추가되어 하나의 단위로 배포되었다면, 이미 하나의 `.env`,
하나의 `A2A_SECRET`, 하나의 작업 공간 레지스트리를 공유합니다. 검색과 인증된 A2A
호출 모두 그 작업 공간이 여러분의 컴퓨터에서 실행되든 프로덕션에서 실행되든 별도로
설정할 것 없이 그대로 동작합니다. 클립을 기반으로 한 실제 다중 앱 제품이라면 이
설정이 기본적으로 예상됩니다.

### 별도 배포: 수동 단계 하나

클립과 Dispatch가 독립적으로 생성된 두 개의 Agent-Native 프로젝트라면, 시크릿을
공유하지 않으므로 아직 서로를 호출할 수 없습니다. 이들을 연결하려면 양쪽 각각에서
수동 단계 하나가 필요합니다. Settings → Agent → Sub-agents(Connect agent), 또는
Dispatch → 에이전트 → 외부 에이전트 추가에서 공유 시크릿과 함께
`remote-agents/<id>.json` 리소스를 추가하세요. 전체 과정은
[A2A 프로토콜](/docs/a2a-protocol) 문서를 참고하세요.

어느 쪽 상황인지 확인하려면 두 앱 중 어느 쪽 에이전트에게든 "어떤 앱들을 볼 수
있어?"라고 물어보세요. Dispatch의 답변에 클립이 빠져 있다면 두 번째 경우에
해당합니다.

## 통합 전략

### 에이전트가 읽을 수 있는 클립

공개 클립 공유 링크를 에이전트에 붙여넣거나, 비공개 클립이라면 **에이전트와 공유**
행의 **공유 → 복사**를 사용하세요. 어느 쪽이든 에이전트는 두 시간 뒤에 만료되는
링크를 사용해 동영상을 다운로드하지 않고도 전사를 읽고 핵심 프레임을 볼 수 있습니다.

이미지를 볼 수 있는 대부분의 에이전트는 ChatGPT, Claude Code, Cursor, Codex를
포함해 이를 스스로 처리합니다. 일부 텍스트 전용 채팅은 전사는 읽을 수 있지만
프레임은 읽지 못하므로, 이런 경우에는 이미지 지원 에이전트에서 클립을 여세요.

| Endpoint                                          | What agents get                                                                                         |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `/api/agent-context.json?id=<recordingId>`        | 클립 메타데이터, 전사 상태, 챕터, CTA, 추천 프레임, 전사/프레임 API 링크                                |
| `/api/agent-transcript.json?id=<recordingId>`     | `startMs`, `endMs`, 읽을 수 있는 타임스탬프, 텍스트, 선택적 소스 라벨이 포함된 타임스탬프 전사 세그먼트 |
| `/api/agent-frame.jpg?id=<recordingId>&atMs=<ms>` | 원본 동영상 타임스탬프에서 추출한 JPEG 프레임                                                           |

이 엔드포인트들은 공유 페이지와 동일한 공개/비밀번호/만료 규칙을 따르거나, 임시
에이전트 링크의 범위가 지정된 `agent_access` 토큰을 받습니다. 비밀번호로 보호된
클립은 비밀번호를 한 번만 요구합니다. 성공적인 응답은 단기 토큰화된 링크를 반환하므로
이후 에이전트가 평문 비밀번호를 알 필요는 없습니다.

### Brain으로 내보내기

작업 공간이 Brain을 연결하면, 클립은 모든 녹화가 끝날 때마다 준비된 전사를 자동으로 전송합니다. 새 녹화가 하나씩 들어오길 기다리는 대신, 예를 들어 지난 28일 치 전체처럼 이전 녹화를 한꺼번에 채워 넣도록 에이전트에게 요청할 수도 있습니다. 에이전트는 몇 개의 전사가 내보내졌는지, 건너뛰었는지, 플래그가 지정되었는지 보고합니다.

### Dispatch를 통한 자연어 위임

형제 앱이 클립과 함께 동작하는 데 특별한 통합이 필요하지는 않습니다. 여러분이 채팅에서 하는 것과 같은 방식으로 "가격에 대해 논의한 클립을 찾아줘" 같은 자연어 요청을 클립의 에이전트에게 그대로 건네면, 클립이 직접 답하거나 처리합니다.

### 분리된 상태 유지하기

클립은 Brain이나 CRM의 자격 증명을 알아야 할 필요가 전혀 없으며, 반대 방향도 마찬가지입니다. `clip.created` 이벤트와 에이전트가 읽을 수 있는 링크가 앱들 사이에 자리 잡고 있으므로, 클립은 누가 듣고 있는지 알 필요 없이 그저 이벤트를 발생시키고 요청에 답하기만 하면 됩니다.
