# Koyeb

<Badge label="Beta" color="orange" icon="rocket" />

Koyeb가 앱을 웹 서비스로 호스팅하므로 서버를 설정하거나 계속 실행해 둘 필요가 없습니다. Koyeb는 [Node.js 가이드](/docs/node-js)에서 설명하는 것과 같은 Node.js 서버를 실행하고, GitHub 저장소에서 이를 빌드하며, 앱에 HTTPS가 적용된 공개 주소를 제공합니다.

이 가이드는 독립 실행형 앱 하나를 처음부터 배포하는 과정을 안내합니다. 앱을 만들어 GitHub에 푸시하고, 프로덕션 데이터베이스와 인증 시크릿을 지정하고, 데이터베이스를 준비한 다음, 앱을 빌드하고 실행하는 Koyeb 웹 서비스를 만듭니다.

<Callout tone="info">

Node.js `22.22+`가 필요합니다.

</Callout>

Koyeb 계정과 GitHub 저장소도 필요합니다. 이 가이드의 명령은 자신의 컴퓨터에서 실행하세요. 앱의 빌드와 실행은 Koyeb가 저장소에서 진행합니다.

## 1단계: 앱 만들기 {#step-1-create-the-app}

새 독립 실행형 앱을 만듭니다. 아래 예시는 Chat 템플릿으로 앱을 만들지만, 어떤 템플릿으로든 시작할 수 있습니다. 앱 폴더로 이동한 뒤 의존성을 설치하세요. `corepack enable`은 앱이 기대하는 `pnpm` 버전을 활성화하므로 `pnpm`을 직접 설치할 필요가 없습니다.

```bash
npx --yes @agent-native/core@latest create my-app --standalone --template chat

cd my-app

corepack enable

pnpm install
```

원한다면 `my-app`을 원하는 앱 이름으로 바꾸세요. 이 가이드의 나머지 부분은 앱 폴더 안에 있다고 가정합니다.

Koyeb는 GitHub에서 앱을 빌드하므로, 계속하기 전에 앱 폴더를 새 GitHub 저장소에 푸시하세요. `pnpm-lock.yaml` 파일도 함께 커밋하세요. Koyeb는 이 파일과 `package.json`의 `packageManager` 필드를 함께 사용해 `pnpm`으로 앱을 설치합니다. 또한 `package.json`의 `engines` 필드에서 Node.js 버전을 읽습니다. 새 앱에는 두 필드가 이미 설정되어 있습니다.

## 2단계: 환경 시크릿 구성하기 {#step-2-configure-environment-secrets}

앱은 프로덕션 설정을 환경 변수에서 읽습니다.

| 변수                 | 필수   | 용도                                          |
| -------------------- | ------ | --------------------------------------------- |
| `DATABASE_URL`       | 예     | 앱을 PostgreSQL 데이터베이스에 연결합니다     |
| `BETTER_AUTH_SECRET` | 예     | 사용자 세션에 서명합니다                      |
| `BETTER_AUTH_URL`    | 아니요 | 사용자가 앱에 접속하는 공개 주소를 설정합니다 |

아래의 export 명령을 실행하면 이 셸에서 이후 명령이 동작합니다. 배포하기 전에 같은 변수를 호스트의 프로젝트 또는 서비스 환경 설정에도 저장하세요. Koyeb에 저장하는 방법은 4단계에서 설명합니다.

### 데이터베이스 URL {#database-url}

로컬 개발 중에는 `DATABASE_URL`이 설정되지 않으면 앱이 로컬 데이터베이스에 데이터를 저장합니다. 배포된 앱에는 배포 후에도 데이터를 유지하는 실제 PostgreSQL 데이터베이스가 필요합니다. Koyeb는 배포하거나 재시작할 때마다 서비스의 파일을 교체하므로 데이터베이스는 웹 서비스 밖에 있어야 합니다. 프로바이더에서 연결 문자열을 복사해 export하세요.

```bash
export DATABASE_URL='your-postgres-url-string'
```

[데이터베이스 프로바이더 가이드](/docs/neon)에서 프로바이더별로 연결 문자열을 찾는 위치를 확인할 수 있습니다.

<Callout tone="warning">

Neon, Supabase, Amazon RDS 등 영구적인 PostgreSQL 프로바이더를 선택하세요.

</Callout>

### 인증 시크릿 {#auth-secret}

이 값은 한 번만 생성하고 배포할 때마다 바꾸지 마세요.

앱은 `BETTER_AUTH_SECRET`을 사용해 사용자 세션에 서명합니다. 이 값이 바뀌면 로그인한 모든 사용자가 로그아웃됩니다. 아래 명령은 임의의 값을 생성합니다.

```bash
export BETTER_AUTH_SECRET="$(openssl rand -hex 32)"
```

생성한 값은 비밀번호 관리자처럼 안전한 곳에 저장하세요. 배포할 때마다 같은 값을 사용합니다.

### 공개 URL {#public-url}

선택 사항입니다. 사용자 지정 도메인, 리버스 프록시, 또는 고정된 공개 origin이 필요한 인증이나 OAuth 흐름을 사용할 때 설정하세요.

`BETTER_AUTH_URL`은 사용자가 앱에 접속하는 공개 주소입니다. 이 값이 없으면 앱은 들어오는 요청마다 자신의 주소를 판단합니다. Koyeb가 제공하는 주소에서는 대개 문제가 없지만, 사용자 지정 도메인을 연결할 때는 로그인 링크와 OAuth 리디렉션이 그 도메인을 사용하도록 이 값을 설정하세요.

```bash
export BETTER_AUTH_URL='https://your-domain.example'
```

## 3단계: 마이그레이션 {#step-3-migrate}

마이그레이션은 앱에 필요한 테이블을 데이터베이스에 만들고 업데이트합니다. 첫 배포 전에 이 명령을 실행하세요.

```bash
pnpm migrate:production
```

이 명령은 자신의 컴퓨터에서 실행되며, 2단계에서 export한 `DATABASE_URL`로 프로덕션 데이터베이스에 연결합니다. 앱을 업그레이드한 뒤에는 새 버전을 배포하기 전에 다시 실행하세요.

## 4단계: 웹 서비스 만들기 {#step-4-create-the-web-service}

Koyeb 제어판에서 새 **Web Service**를 만들고, 배포 방법으로 **GitHub**를 선택한 뒤 1단계의 저장소와 브랜치를 선택합니다. 빌더는 **Buildpack**을 그대로 두고, 빌드 명령과 실행 명령을 다음 값으로 재정의하세요.

| 설정          | 값                              |
| ------------- | ------------------------------- |
| Build command | `NITRO_PRESET=koyeb pnpm build` |
| Run command   | `node .output/server/index.mjs` |

`NITRO_PRESET=koyeb`은 Node.js 가이드와 같은 Node.js 서버를 자체 정적 파일도 제공하도록 설정해 빌드합니다. 실행 명령은 그 서버를 시작합니다. Koyeb는 기본적으로 `8000` 포트를 노출하고 이에 맞춰 `PORT` 환경 변수를 설정하며, 서버는 `PORT`를 자동으로 읽으므로 포트 설정을 바꿀 필요가 없습니다.

**Environment variables**에서 `DATABASE_URL`과 `BETTER_AUTH_SECRET`을 추가합니다. 이런 값은 각각 **Secret**으로 저장하고 변수에서 참조하는 방식을 Koyeb가 권장합니다. 예를 들어 연결 문자열을 `DATABASE_URL`이라는 이름의 Secret으로 저장한 다음, 변수 값을 `{{ secret.DATABASE_URL }}`로 설정하세요. `BETTER_AUTH_URL`을 설정했다면 같은 방법으로 추가하세요.

## 5단계: 배포 {#step-5-deploy}

<Steps>

### 인스턴스 유형 선택하기

웹 서비스의 인스턴스 유형을 고릅니다. 앱을 시험해 보는 용도라면 Free 인스턴스 유형으로 충분합니다. 앱이 즉시 응답해야 한다면 유료 인스턴스 유형을 선택하세요.

### 웹 서비스 만들기

서비스와 앱의 이름을 정한 다음 배포합니다. Koyeb가 저장소에서 앱을 빌드하고 시작합니다. 첫 빌드는 몇 분 정도 걸리며, 서비스의 빌드 로그와 런타임 로그에서 진행 상황을 확인할 수 있습니다.

### 앱 열기

배포가 끝나면 제어판에 `koyeb.app`으로 끝나는 앱 주소가 표시됩니다. 그 주소를 열고 첫 계정을 만듭니다.

</Steps>

Free 인스턴스 유형에서는 1시간 동안 트래픽이 없으면 Koyeb가 서비스를 0으로 축소합니다. 그러면 다음 방문 시 서비스가 다시 시작되는 동안 기다려야 합니다. 각 조직은 Free 인스턴스를 하나만 실행할 수 있습니다.

## 업데이트 배포하기 {#deploy-updates}

Koyeb는 4단계에서 선택한 브랜치에 푸시할 때마다 다시 배포합니다. 새 버전을 배포하려면 먼저 마이그레이션을 실행한 다음 푸시하세요.

```bash
pnpm migrate:production

git push
```

서비스 설정과 저장한 변수는 그대로 유지되므로 4단계를 반복할 필요가 없습니다.
