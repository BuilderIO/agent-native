# 레코더

레코더는 Agent-Native 앱이 방금 한 일을 민감 정보를 가린 채 메모리에 짧게 남기는 기록입니다. 모든 앱은 최근 2분 동안의 action, `application_state` 쓰기, 라우트 변경, 오류, 오류 토스트를 기록하며, 앱 코드는 필요 없습니다. 문제가 생기면 이 기록은 앱의 에이전트, Clips 녹화, Sentry 또는 직접 만든 전송 대상이 읽을 수 있는 리포트가 됩니다.

```ts
import { recorder } from "@agent-native/core/client/recorder";

const report = recorder.report();
```

리포트를 어딘가로 보내기 전까지는 서버에 아무것도 저장되지 않고 브라우저 밖으로 아무것도 나가지 않습니다. 레코더는 자체적으로 네트워크 요청을 보내지 않습니다.

## 기록하는 내용 {#captured}

| 유형     | 출처                                                                                                                 | 예시                                                                              |
| -------- | -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `action` | 모든 `useActionQuery()`, `useActionMutation()`, `callAction()` 호출. 일괄 읽기 안의 각 action은 별도의 이벤트입니다. | `200`을 반환한 일괄 요청 안에서 `list-folders`가 `403`과 `forbidden_scope`로 실패 |
| `state`  | 실패하거나 취소된 것을 포함한 모든 `application_state` 쓰기와 삭제                                                   | `design-selection`의 `state`가 `hover`에서 `focus`로 변경                         |
| `nav`    | 라우트 변경. 경로만 남깁니다.                                                                                        | `/design/d_8f2c1a`                                                                |
| `error`  | 잡히지 않은 오류와 처리되지 않은 프로미스 거부. 첫 번째 스택 프레임 포함                                             | `/app/pages/design-editor/commands/undo.ts:1715`에서 발생한 `TypeError`           |
| `toast`  | 사용자가 본 오류 및 경고 토스트                                                                                      | `This screen changed elsewhere. Your edit was not saved.`                         |
| `log`    | 앱이 `recorder.log()`로 추가하는 이벤트                                                                              | `f_1`에서 `f_9`로의 `screen.restored`                                             |

모든 이벤트에는 같은 필드가 있습니다.

| 필드        | 의미                                                                                                                 |
| ----------- | -------------------------------------------------------------------------------------------------------------------- |
| `t`         | 리포트가 만들어지기 몇 초 전인지. 음수입니다.                                                                        |
| `at`        | 에포크 밀리초. Clips 진단도 같은 시계를 씁니다.                                                                      |
| `type`      | `action`, `state`, `nav`, `error`, `toast`, `log` 중 하나                                                            |
| `name`      | action 이름, 상태 키, 라우트 경로, 오류 유형, 토스트 수준 또는 로그 이름                                             |
| `ok`        | action 또는 상태 쓰기가 성공했는지 여부                                                                              |
| `status`    | HTTP 상태(있는 경우)                                                                                                 |
| `errorCode` | action의 오류 코드. 앱이 취소한 호출이나 쓰기에는 `errorCode: "cancelled"`가 붙습니다.                               |
| `ms`        | action 또는 상태 쓰기에 걸린 시간                                                                                    |
| `requestId` | 서버의 요청 ID. 서버 로그와 해당 Sentry 이벤트에도 나타납니다                                                        |
| `data`      | 민감 정보를 가리고 크기를 제한한 세부 정보. action에는 HTTP 메서드가 들어가고, 실패한 경우 오류 메시지도 들어갑니다. |

상태 쓰기는 해당 키에 마지막으로 저장된 값 이후 바뀐 부분만 기록합니다. 키의 첫 쓰기는 `data.value`를 기록합니다. 이후 쓰기는 `data.changed`를 기록하며, 제거된 필드는 `"[removed]"`로 표시됩니다. 아무것도 바꾸지 않은 쓰기는 `data.unchanged`를, 삭제는 `data.deleted`를 기록합니다. 실패한 쓰기에는 `data.error`도 붙으며, 다음 쓰기는 계속 마지막으로 저장된 값과 비교됩니다.

## 리포트 {#reports}

리포트는 기록 구간의 이벤트에 앱이 관찰하는 값과 아직 진행 중인 작업을 더한 것입니다.

```json
{
  "app": "design",
  "build": "59929e9",
  "url": "/design/d_8f2c1a?file=[redacted]",
  "at": "2026-10-14T16:20:05.120Z",
  "reason": "user",
  "windowSeconds": 120,
  "events": [
    {
      "t": -12.4,
      "at": 1791994792720,
      "type": "state",
      "name": "design-selection",
      "ok": true,
      "ms": 41,
      "data": { "changed": { "state": "hover" } }
    },
    {
      "t": -10.9,
      "at": 1791994794220,
      "type": "action",
      "name": "update-file",
      "ok": true,
      "status": 200,
      "ms": 180,
      "requestId": "req_a1",
      "data": { "method": "POST" }
    }
  ],
  "watched": {
    "inspector": {
      "state": "focus",
      "fields": [{ "label": "Opacity", "shown": "91%" }]
    }
  },
  "pending": [],
  "dropped": 0
}
```

- **app**: 앱 ID. 없으면 `localhost:8080` 같은 페이지의 호스트를 쓰므로 비어 있는 일이 없습니다.
- **url**: 라우트 경로. 모든 쿼리 값은 가려지고 해시는 제외됩니다.
- **windowSeconds**: 리포트가 다루는 시간(초).
- **pending**: 아직 진행 중인 action과 상태 쓰기. 각각 `ageMs`가 붙습니다.
- **dropped**: 페이지가 로드되거나 사용자가 로그아웃한 이후 상한 때문에 잃어버린 이벤트. 오래되어 기록 구간을 벗어난 이벤트는 세지 않습니다.

## SDK {#sdk}

### `recorder.report()` {#report}

`recorder.report()`는 현재 리포트를 반환합니다. 동기적으로 동작합니다. 선택 사항인 객체 하나를 받습니다.

- **seconds**: 기록 구간에서 마지막 `seconds`초만 남깁니다.
- **reason**: `"user"`, `"error"`, `"test"`, `"manual"` 중 하나. 기본값은 `"manual"`입니다.

```ts
const report = recorder.report();
```

녹화가 시작되기 전 30초처럼 더 짧은 구간이 필요하면 `seconds`를 전달하세요.

```ts
const before = recorder.report({ seconds: 30 });
```

`"manual"`을 제외한 모든 이유는 리포트를 `recorder.onReport()` 리스너에게도 보냅니다. 인수 없는 `recorder.report()` 호출은 절대 보내지 않으므로, 리스너가 루프 없이 리포트를 만들 수 있습니다.

### `recorder.log()` {#log}

`recorder.log()`는 앱 자신의 말로 이벤트를 추가합니다. 이름과 선택 사항인 데이터를 받습니다. 일반 객체가 아닌 데이터는 `{ value }`로 기록됩니다.

Design은 실행 취소로 되살아난 각 화면의 새 ID를 로그로 남깁니다. 실행 취소는 삭제된 화면을 새 ID로 다시 만들기 때문입니다.

```ts
recorder.log("screen.restored", { from: file.id, to: result.id });
```

### `recorder.watch()` {#watch}

`recorder.watch()`는 모든 리포트에 실시간 값을 추가합니다. 이름과 값을 반환하는 함수를 받고, 관찰을 멈추는 함수를 반환합니다.

Design의 인스펙터는 지금 보여 주는 내용과 편집 중인 인터랙션 상태를 추가합니다. 둘 다 `application_state`에 없으므로, 이것이 없으면 리포트에 나타낼 수 없습니다.

```tsx
useEffect(
  () =>
    recorder.watch("inspector", () => ({
      state: interactionState ?? "default",
      fields: readVisualScrubInputs(),
    })),
  [interactionState],
);
```

예외를 던지는 함수는 빠지지 않고 `{ unreadable: "<message>" }`로 보고됩니다.

### `recorder.onReport()` {#on-report}

`recorder.onReport()`는 리포트를 전송 대상으로 보냅니다. 리스너를 받고, 그 리스너를 제거하는 함수를 반환합니다. 리스너는 `"manual"`이 아닌 이유로 만들어진 모든 리포트를 받습니다. 여기에는 "문제 신고"(`"user"`), 잡히지 않은 오류(`"error"`), 테스트(`"test"`)가 포함됩니다.

```ts
recorder.onReport((report) => posthog.capture("problem_report", report));
```

```ts
recorder.onReport((report) =>
  navigator.sendBeacon("/api/logs", JSON.stringify(report)),
);
```

잡히지 않은 오류는 10초에 최대 한 번 리포트를 보내므로, 오류 루프가 전송 대상을 뒤덮을 수 없습니다. 예외를 던진 리스너는 로그로 남고 나머지 리스너는 계속 실행됩니다.

### `recorder.redact()` {#redact}

`recorder.redact()`는 호출 이후 기록되는 모든 이벤트와 모든 관찰 값에서 더 많은 필드를 가립니다. 필드 이름 또는 이벤트 이름으로 시작하는 점 구분 경로를 전달하세요. `*`는 임의의 필드 하나와 일치합니다.

```ts
recorder.redact("email");
recorder.redact("compose.body", "payment.*");
```

### `recorder.pending()` {#pending}

`recorder.pending()`은 아직 진행 중인 action과 상태 쓰기를 나열합니다. 테스트는 고정된 대기 시간 대신 실제로 유휴 상태가 될 때까지 기다리는 데 이것을 씁니다. Design의 엔드투엔드 테스트는 `app.settled()`에서 이 목록이 빌 때까지 기다리고, 실패한 모든 테스트에 `recorder.json`을 첨부합니다.

```ts
await expect
  .poll(() =>
    page.evaluate(
      () => window.__agentNativeRecorder?.report({ seconds: 0 }).pending,
    ),
  )
  .toEqual([]);
```

### `recorder.disable()` {#disable}

`recorder.disable()`은 레코더를 끕니다. `configureRecorder({ enabled: false })`와 같은 동작입니다.

## `configureRecorder()` {#configure}

`configureRecorder()`는 선택 사항인 한 번의 호출입니다. 기본값은 다음과 같습니다.

```ts
import { configureRecorder } from "@agent-native/core/client/recorder";

configureRecorder({
  windowSeconds: 120,
  maxEvents: 2000,
  sentry: true,
  enabled: true,
});
```

- **windowSeconds**: 레코더가 이벤트를 얼마나 오래전까지 보관할지.
- **maxEvents**: 보관하는 최대 이벤트 수. 상한에 도달하면 가장 오래된 이벤트부터 버리고 `dropped`에 셉니다.
- **sentry**: Sentry 오류에 최근 이벤트를 붙일지 여부. 앱에 브라우저 Sentry가 있을 때만 동작합니다.
- **enabled**: 레코더를 실행할지 여부.

양수가 아닌 기록 구간이나 상한은 기본값으로 대체되지 않고 `RangeError`를 던집니다. 레코더는 `maxEvents` 값과 상관없이 전체 크기도 JSON 기준 약 512 KB로 제한하므로, 탭당 메모리는 2 MB 미만으로 유지됩니다.

## 전송 대상 {#destinations}

### 문제 신고 {#report-a-problem}

모든 앱에는 **문제 신고**가 있습니다. 사이드바 아래쪽, 에이전트 패널의 옵션 메뉴, 명령 메뉴(⌘K)에 있습니다.

- 앱이 최근 2분 동안 한 일을 첨부할지 묻고, 개수와 실패, 처음 이벤트를 미리 보여 줍니다. 매번 묻습니다.
- 사용자가 동의하면 전체 리포트는 해당 사용자만 읽을 수 있는 비공개 파일로 저장됩니다. 앱의 에이전트는 파일 참조가 포함된 짧은 요약을 받습니다.
- 에이전트는 `read-problem-report` action으로 이벤트 유형이나 시간별로 필터링해 리포트를 더 읽습니다.
- 페이지에 에이전트 채팅이 없으면 버튼이 대신 요약과 참조를 복사합니다.
- 리포트에는 파일 저장소가 필요합니다. 없으면 대화 상자에 리포트가 첨부되지 않았다고 표시되며 아무것도 전송되지 않습니다.

### Sentry {#sentry}

Agent-Native를 통해 브라우저 Sentry를 설정한 앱에서는([오류 보고](/docs/observability#sentry) 참고) 모든 Sentry 오류 이벤트에 다음이 붙습니다.

- 최근 이벤트 100개. `recorder.action`, `recorder.state` 등의 카테고리에 브레드크럼으로 붙으며, 각각 결과, 상태, 요청 ID를 포함합니다
- 전체 리포트. `recorder.json` 첨부 파일로 붙습니다

앱 코드는 필요 없습니다. `configureRecorder({ sentry: false })`로 끌 수 있습니다.

### 직접 만든 전송 대상 {#own-destination}

[`recorder.onReport()`](#on-report)로 리스너를 등록하세요.

### Clips와 브라우저 확장 프로그램 {#extensions}

페이지는 `window.__agentNativeRecorder.report()`를 노출합니다. 브라우저 확장 프로그램은 페이지의 메인 월드에서 이를 읽습니다.

개발자 로그가 켜져 있으면 Clips 확장 프로그램은 녹화가 시작될 때(최근 30초)와 끝날 때 녹화 중인 탭에서 이를 읽습니다. 이벤트는 같은 시계 기준으로 녹화의 콘솔 및 네트워크 항목과 합쳐지며, 클립의 에이전트는 실패 요약을 받습니다. [Clips 브라우저 로그](/docs/template-clips-features#chrome-extension-browser-logs)를 참고하세요.

## 개인정보 보호 {#privacy}

- **브라우저 안에 머뭅니다.** 리포트는 전송 대상이 보낼 때만 밖으로 나갑니다. 사용자가 동의한 뒤의 "문제 신고", 사용자가 시작한 Clips 녹화, Sentry, 개발자가 등록한 리스너가 그 대상입니다.
- **비밀 값은 제거됩니다.** 이름이 비밀 값처럼 보이는 필드(`password`, `token`, `secret`, `apiKey`, `authorization`, `cookie`, `session`, `card`, `cvv`)는 `"[redacted]"`로 표시됩니다. JWT, Bearer 토큰, 제공자 API 키처럼 값 안에 있는 토큰 형태의 텍스트도 `[redacted]`로 바뀝니다. core가 오류 보고에 쓰는 것과 같은 가림 처리 로직입니다.
- **값의 크기는 제한됩니다.** 문자열은 200자에서, 각 이벤트는 약 2 KB에서 잘립니다. 잘린 부분에는 무엇을 버렸는지 표시됩니다. 요청 본문과 응답 본문은 절대 기록되지 않습니다.
- **기록은 잊힙니다.** 기록 구간 안의 내용만 상한까지 보관합니다. 새로고침하거나 로그아웃하면 지워집니다.
- **새로운 접근 권한은 없습니다.** 레코더는 이미 앱을 거쳐 가는 것만 봅니다. action 호출은 원래 서버로 가고, `application_state`는 원래 저장되어 에이전트가 읽습니다.

## 끄기 {#off}

```ts
import { configureRecorder } from "@agent-native/core/client/recorder";

configureRecorder({ enabled: false });
```

비활성화된 레코더는 갖고 있던 내용을 잊고, 수신을 멈추고, 페이지에서 `window.__agentNativeRecorder`를 제거합니다. 이때 `recorder.report()`는 이벤트도 관찰 값도 반환하지 않으며, 리스너에게 아무것도 보내지 않습니다. `configureRecorder({ enabled: true })`로 다시 시작할 수 있습니다.
