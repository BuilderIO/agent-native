# 기능

양식의 모든 핵심 기능이 어떻게 동작하고 어떻게 설정하는지 다룹니다. 전체 개요는
[양식](/docs/template-forms) 문서를, 프롬프트 전체 목록은
[Agent와 대화](/docs/template-forms-agent) 문서를 참고하세요.

## 양식 만들기

모든 양식은 필드 집합에서 시작합니다. 원하는 것을 에이전트에게 설명하면 에이전트가 양식을 만들어 주고, 처음부터 직접 시작해 시각적 빌더에서 필드를 추가할 수도 있습니다. 두 방법 모두 같은 양식을 편집하므로 방식을 오가더라도 서로 어긋나는 일이 없습니다. 양식이 만들어지면 빌더에는 편집, 응답, 설정, 통합의 네 가지 탭이 있어, 채팅으로 변경 사항을 설명하는 것보다 더 직접적으로 제어하고 싶을 때 언제든 레이블, 자리표시자, 필수 여부, 옵션, 필드 순서를 손으로 조정할 수 있습니다.

모든 필드에는 레이블과 유형이 필요합니다. `select`, `multiselect`, `radio` 같은 필드는 사람들이 선택할 수 있는 옵션 목록도 필요합니다. 어떤 필드든 필수로 지정하거나 최소값·최대값 같은 유효성 검사를 추가할 수 있고, 양식 전체 너비를 차지할지 다른 필드와 나란히 배치할지도 선택할 수 있습니다.

### 조건부 필드

필드는 앞선 답변이 여러분이 설정한 규칙과 일치할 때까지 숨겨둘 수 있습니다. 예를 들어 앞선 질문에서 누군가 "기타"를 선택하지 않는 한 "자세히 알려주세요" 텍스트 필드를 숨길 수 있습니다.

확인 대상이 되는 필드는 양식에서 더 앞에 있어야 합니다. 뒤쪽 필드를 가리키거나 존재하지 않는 필드를 가리키는 규칙은 저장되기 전에 거부됩니다. 앞선 답변이 특정 값과 같은지, 같지 않은지, 또는 그 값을 포함하는지 확인할 수 있으며, 이는 하나 이상의 옵션을 선택할 수 있는 질문에도 적용됩니다. 조건에 의해 필드가 숨겨지면 그 답변은 저장되거나 어디로도 전송되지 않으므로, 숨겨진 필드가 오래되거나 기본값인 데이터를 남길 일이 없습니다.

채팅으로 설명하는 대신 직접 스크립트로 양식을 만드시나요? [개발자 가이드](/docs/template-forms-developers#data-model)에서 필드 및 설정 JSON 레퍼런스를 확인하세요.

## 양식 게시하기

양식은 세 가지 상태를 거칩니다.

| 상태        | 의미                        | 공개 접근        |
| ----------- | --------------------------- | ---------------- |
| `draft`     | 작업 진행 중, 공개되지 않음 | 아니요           |
| `published` | 게시되어 응답을 받는 중     | 예               |
| `closed`    | 더 이상 응답을 받지 않음    | 마감 메시지 표시 |

필드가 하나도 없거나, 레이블이 없는 필드가 있거나, `select`, `multiselect`, `radio` 필드에 옵션이 없으면 양식을 게시할 수 없습니다. 게시가 거부되면 구체적인 이유를 안내받습니다.

공개 URL은 `/f/<slug>` 형태이며, 슬러그는 제목에 `beta-signup-a1b2c3`처럼 짧은 고유 접미사를 붙여 생성됩니다. 사용자 지정 슬러그를 설정하지 않는 한 제목이 바뀔 때마다 자동으로 다시 생성됩니다.

### 응답 수집하기

게시된 양식에 대한 모든 제출은 하나의 응답이 됩니다. 답변 내용, 도착 시각, 그리고 양식이 익명이 아니라면 누가 어디서 보냈는지가 포함됩니다. 각 양식의 응답 탭을 열어 하나하나 자세히 확인하거나, 에이전트에게 그냥 물어보세요.

- "베타 가입 양식에 응답이 몇 개나 있어?"
- "오늘 누가 제출했어?"
- "고객 피드백 양식의 응답을 보여줘."

응답이 공개 양식 페이지 자체가 아니라 다른 앱에 내장된 피드백 버튼을 통해 들어왔다면, 응답 표에는 어떤 페이지와 어떤 앱에서 왔는지도 함께 표시됩니다. 이 열들은 실제로 그 정보를 담은 응답이 하나라도 있을 때만 나타납니다.

## 설정

각 양식은 빌더의 설정 탭에 자신만의 설정을 가지며, 양식이 어떻게 동작하고 응답자에게 무엇을 보여줄지를 결정합니다.

- **제출 버튼 텍스트.** 제출 버튼의 레이블을 기본값인 "제출" 대신 "피드백 보내기"나 "자리 예약하기"처럼 더 구체적인 문구로 바꾸세요.
- **성공 메시지.** 기본 확인 메시지 대신 응답자가 제출 직후 보게 될 내용을 선택하세요.
- **리디렉션 URL.** 양식 자체에 성공 메시지를 보여주는 대신, 제출 후 응답자를 다른 페이지로 이동시키세요.
- **진행률 표시줄.** 긴 양식의 상단에 진행률 표시줄을 표시해 응답자가 얼마나 남았는지 볼 수 있게 하세요.
- **익명 모드.** 누가 응답했는지에 대한 모든 추적을 꺼서, 제출물에 IP 주소, 이메일, 위치가 절대 기록되지 않도록 하세요.
- **새 응답 이메일 알림.** 누군가 제출할 때마다 설정된 이메일 제공업체를 통해 이메일을 받으세요.

## 공개 양식 보호 및 브랜딩

### 스팸 방지

공개 제출은 통과되기 전에 [Cloudflare Turnstile](https://www.cloudflare.com/products/turnstile/)을 통한 인증을 요구하도록 설정할 수 있습니다. 설정에서 사이트 키와 시크릿 키를 지정해 이 기능을 켜세요. Turnstile을 사용하지 않아도 두 가지 보호 기능은 항상 켜져 있습니다. 봇의 제출을 조용히 폐기하는 숨겨진 필드와, 사람이 양식을 합리적으로 작성할 수 있는 시간보다 더 빨리 제출된 것을 거부하는 검사입니다.

<Callout tone="warning">

두 Turnstile 키는 함께 설정하세요. 공개 양식 페이지는 사이트 키가 설정된 경우에만 인증 위젯을 표시하며, 서버는 두 키가 모두 설정된 경우에만 이를 검사합니다. 시크릿 키만 설정하면 아무것도 검증되지 않고, 사이트 키만 설정하면 서버가 실제로는 검사하지 않는 위젯만 표시됩니다.

</Callout>

### 브랜딩

독립적으로 공개된 모든 양식은 모서리에 작은 "Built with Agent-Native" 배지를 표시합니다. 이는 양식별로 켜거나 끌 수 있는 항목이 아닙니다. 피드백 팝오버처럼 양식이 다른 페이지 안에 내장되었을 때만 자동으로 숨겨지는데, 그 페이지가 이미 자체 브랜딩을 가지고 있기 때문입니다.

### 제출 출처 제한하기

기본적으로 양식의 제출 링크는 어디서든 제출을 받아들이며, 이는 일반적인 공개 양식 링크가 동작해야 하는 방식입니다. 양식의 제출 링크를 다른 사이트의 위젯 안에 내장하면서 그 사이트만 사용할 수 있도록 하고 싶다면, 제출을 특정 웹사이트 출처 목록으로 제한할 수 있습니다.

현재 빌더에는 이를 위한 토글이 없습니다. 에이전트에게 설정을 요청하세요. 예를 들어 "이 양식은 https://example.com에서만 제출되도록 해줘"처럼 말하면 됩니다. 허용할 각 사이트마다 정확한 출처(끝에 경로가 없는 `https://example.com` 같은 스킴과 도메인)를 에이전트에게 알려주세요.

## 내보내기

양식의 응답 탭에서 **CSV 내보내기**를 클릭하면 적용한 검색이나 정렬을 포함해 현재 화면에 있는 내용을 즉시 CSV로 다운로드할 수 있습니다. 별도의 설정 없이 바로 동작합니다.

에이전트에게 "이 양식의 CSV" 또는 "모든 응답의 JSON 내보내기"를 요청할 수도 있습니다. 이 경우 현재 필터링된 것만이 아니라 항상 모든 응답을 내보내며, 먼저 파일 저장소 제공업체가 연결되어 있어야 합니다. 아직 연결되지 않았다면 에이전트가 알려주고 설정 → 파일 업로드로 안내하며, 무료 Builder.io 계정이 빠른 옵션으로 사용됩니다. 저장소가 연결되면 에이전트는 파일을 직접 다운로드하는 대신 파일 링크를 돌려줍니다. 각 내보내기는 필드 레이블을 (CSV의 경우) 열 머리글로 사용하며, 필드에서 누군가 두 개 이상의 옵션을 선택했다면 그 선택들은 하나의 셀에 합쳐집니다. 스프레드시트 수식처럼 보이는 답변은 먼저 무력화되어, 파일을 열 때 코드가 실행되는 것을 방지합니다.

## 제출물 라우팅하기

자동 전달을 켜서, 누군가 응답 탭을 확인하는 대신 새 응답이 팀이 이미 사용하는 곳에 나타나도록 하세요. 이는 양식별 설정이며, 빌더의 통합 탭에서 구성합니다.

| 대상          | 필요한 것                                                                                  |
| ------------- | ------------------------------------------------------------------------------------------ |
| Slack         | 원하는 채널의 수신 웹훅 URL                                                                |
| Discord       | 원하는 채널의 웹훅 URL                                                                     |
| Google Sheets | 제출물을 받도록 설정된 Google Apps Script URL. 일반 스프레드시트 링크는 동작하지 않습니다. |
| 웹훅          | 제출물을 데이터로 받을 수 있는 모든 웹 주소                                                |

이것은 에이전트가 Slack에 직접 게시하도록 Slack을 연결하는 것과는 별개이며, 이는 [메시징](/docs/messaging) 문서에서 다룹니다. 에이전트가 직접 Slack에 업데이트를 게시하도록 하고 싶다면 먼저 그것을 연결하세요. 모든 대상 주소는 저장할 때와 응답이 들어올 때마다 사설 네트워크나 내부 주소를 가리키지 않는지 확인되므로, 양식이 여러분 자신의 네트워크를 탐색하는 수단으로 악용될 수 없습니다.

새 응답이 있을 때마다 양식 소유자에게 이미 설정된 이메일 서비스를 통해 이메일이 가도록 알림을 켤 수도 있습니다. 이 이메일 전송은 최선형 노력 방식입니다. 알림 이메일 전송이 실패하더라도 제출 자체는 정상적으로 처리됩니다.
