# 개요

`app/`는 에이전트 네이티브 앱의 실제 화면 — 페이지, 레이아웃, 컴포넌트, 스타일 — 을 만드는 곳입니다. `public/`은 그 옆에서 함께 제공되는 정적 자산 — 아이콘, 매니페스트, 브랜드 마크 — 을 담고 있습니다. 이것은 일반적인 React Router v8 앱이며, 에이전트 전용의 특별한 표면이 아닙니다. 대부분의 개발 시간이 여기에 쓰입니다.

일반적인 프런트엔드와의 유일한 아키텍처상 차이점은 이 레이어에는 자체적인 backend-for-frontend가 없다는 것입니다. 이 레이어는 에이전트가 호출하는 것과 동일한 actions를 통해 데이터를 읽고 쓰므로, 여기서 연결한 모든 것은 자동으로 에이전트도 수행할 수 있는 작업이 됩니다.

## 클라이언트가 맡는 역할 {#role}

브라우저 요청, 에이전트 루프, 외부 API 클라이언트는 모두 동일한 actions와 동일한 SQL 데이터베이스로 귀결됩니다. 에이전트가 접근할 수 없는 별도의 "앱 백엔드"는 이 레이어가 대화할 상대로 존재하지 않습니다. 여기서 기능을 만든다는 것은 에이전트가 이미 가지고 있는 작업 위에 UI를 얹거나, 새로운 action을 정의하면서 동시에 그 UI도 얻는다는 뜻입니다. 이 계약의 작업(operation) 쪽은 [Actions](/docs/actions)를 참조하세요.

이 페이지는 여러분이 작업하는 디렉터리와, 다른 곳에서 다루지 않는 브라우저 런타임의 부분들(`root.tsx`, `public/`)을 다룹니다. 컴포넌트를 actions 및 에이전트와 연결하는 React 후크는 각각 초점이 맞춰진 별도 페이지에 있습니다.

| 페이지                                         | 다루는 내용                                                                                              |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| **[데이터 및 동기화](/docs/client-data)**      | `useActionQuery`, `useActionMutation`, `callAction`, `useDbSync`                                         |
| **[Agent 채팅](/docs/client-agent-chat)**      | `sendToAgentChat`, `askUserQuestion`, `openAgentSettings`, 동적 제안, 단계적 에이전트 채팅 컨텍스트 상태 |
| **[고급](/docs/client-advanced)**              | `application_state` 직접 접근, 백그라운드 채팅 전송, 맞춤 제안 칩, MCP 앱 호스트 브리지                  |
| **[동기화 내부](/docs/client-sync-internals)** | 원시 `useQuery`를 동기화하기 위한 `useChangeVersion`/`useChangeVersions`                                 |
| **[엔트리 포인트](/docs/client-entry-points)** | `app/entry.client.tsx`/`app/entry.server.tsx`와 SSR 커스터마이징                                         |

| **`app/global.css`**                                | 기본 스타일과 Tailwind 진입점                                                                                            |

## 브라우저 셸: root.tsx와 AppProviders {#app-shell}

`app/root.tsx`는 React 트리의 최상단입니다: HTML 문서 셸(`<html>`, `<head>`, `<Meta>`, `<Links>`, `<Scripts>`)과, 모든 경로가 그 안에서 렌더링되는 provider 스택입니다.

```tsx filename="app/root.tsx"
import {
  AppProviders,
  createAgentNativeQueryClient,
} from "@agent-native/core/client/hooks";
import { useState } from "react";
import { Outlet } from "react-router";
import { i18nCatalog } from "./i18n";

export default function Root() {
  const [queryClient] = useState(() => createAgentNativeQueryClient());

  return (
    <AppProviders queryClient={queryClient} i18n={{ catalog: i18nCatalog }}>
      <Outlet />
    </AppProviders>
  );
}
```

`AppProviders`는 다음을 한 번에 연결해 주는 단일 래퍼입니다.

- `useActionQuery`/`useActionMutation`이 사용하는 React Query 클라이언트([데이터 및 동기화](/docs/client-data#fetching-mutating) 참조).
- `i18n.catalog`로 전달되는 i18n 카탈로그([국제화](/docs/internationalization) 참조).
- 클라이언트 측 세션 검사: 비공개 경로에서는 익명 방문자가 어떤 비공개 UI도 마운트되기 전에 로그인 화면으로 리디렉션됩니다. 공개/SEO 경로에는 `isPublicPath`를, MCP 임베드 토큰처럼 다른 방식으로 인증되는 표면에는 `sessionBypass`를 전달하세요. [Authentication](/docs/authentication) 참조.

대부분의 앱은 여기에 `<AgentSidebar>` 또는 `<AgentPanel>`도 마운트하여 모든 경로가 별도의 작업 없이 에이전트 패널을 갖게 합니다. [드롭인 에이전트](/docs/drop-in-agent#sidebar) 참조.

## 정적 자산: public/ {#public-directory}

`public/`에 있는 모든 것은 빌드에서 가공되지 않은 채로 사이트 루트에서 그대로 제공됩니다. 모든 템플릿은 다음을 포함합니다.

```text
public/
  favicon.svg           -> 브라우저 탭 아이콘
  icon-180.svg           -> apple-touch-icon
  icon-192.svg, icon-512.svg -> manifest.json에서 참조하는 PWA 아이콘
  manifest.json          -> 웹 앱 매니페스트(이름, 테마 색상, 아이콘)
  *-logo-*.svg, *-icon-*.svg -> 기본 UI에서 사용하는 브랜드 마크
```

`manifest.json`은 방문자가 앱을 홈 화면이나 앱 독에 설치할 때 표시되는 내용 — 이름, 짧은 이름, 테마/배경 색상, 아이콘 세트 — 을 제어합니다.

```json filename="public/manifest.json"
{
  "name": "My App",
  "short_name": "My App",
  "theme_color": "#18181B",
  "icons": [
    { "src": "icon-192.svg", "sizes": "192x192", "type": "image/svg+xml" }
  ]
}
```

이 파일들을 교체하고 `manifest.json`과 `root.tsx`에서 이를 참조하는 `<link rel="icon">`/`<link rel="apple-touch-icon">` 태그를 업데이트하는 것으로 앱을 리브랜딩할 수 있습니다. 별도의 등록 절차는 없습니다. 이런 파일들을 직접 편집하는 대신 기존 사이트에서 전체 브랜드 시스템(색상, 폰트, 파비콘)을 가져오려면 [브랜드 시스템과 Figma](/docs/template-design-brand-and-figma)를 참조하세요.

## 유틸리티: cn {#utilities}

```ts
import { cn } from "@agent-native/toolkit/utils";

<div className={cn(
  "px-4 py-2 rounded",
  isActive && "bg-primary text-primary-foreground",
  className
)} />
```

`cn`은 클래스 이름을 병합합니다(clsx + tailwind-merge). `app/components/` 전반에서 조건부 Tailwind 클래스를 조합하는 표준적인 방법입니다.
