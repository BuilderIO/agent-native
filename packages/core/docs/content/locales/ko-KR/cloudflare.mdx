# Cloudflare

## Cloudflare Workers {#cloudflare-workers}

Cloudflare Worker에는 Nitro의 네이티브 모듈 출력을 사용하세요. 이는 SSR을
계속 활성화한 상태로 유지하며 Worker 진입점과 정적 자산을
`.output/server` 및 `.output/public`에 생성합니다:

```ts filename="vite.config.ts"
export default defineConfig({
  plugins: [agentNative({ nitro: { preset: "cloudflare_module" } })],
});
```

생성된 Worker를 Wrangler로 빌드하고 배포하세요:

```bash
pnpm build
npx wrangler deploy --config .output/server/wrangler.json
```

`NITRO_PRESET=cloudflare_module`로 프리셋을 명시적으로 선택할 수도 있습니다.
배포 전에 내구성 있는 외부 PostgreSQL 데이터베이스를 구성하세요. Worker 파일 시스템은
영구적인 애플리케이션 저장소가 아닙니다.

## 예약 작업 {#cloudflare-scheduled-work}

예약 자동화, 대기 중인 이벤트 자동화, 중단된 실행 정리는 모두 1분에 한 번
실행되는 스윕에서 처리됩니다. 빌드는 생성된 `wrangler.json`에 `* * * * *`
[Cron Trigger](https://developers.cloudflare.com/workers/configuration/cron-triggers/)를
추가하며, 이미 선언한 Cron Trigger는 그대로 유지합니다. 트리거가 실행되면 Worker의
`scheduled` 핸들러가 `A2A_SECRET`으로 서명된 단기 토큰을 사용해 스윕을 직접
호출하므로, 배포하기 전에 이 시크릿을 설정하세요:

```bash
npx wrangler secret put A2A_SECRET --config .output/server/wrangler.json
```

- **CPU 시간.** Workers 무료 플랜에서는 각 Cron Trigger 호출에 10ms의 CPU 시간이
  주어지지만, 에이전트 작업을 실행하는 스윕에는 그보다 더 필요합니다. 예약 작업에는
  Workers 유료 플랜을 사용하세요.
- **타이밍.** Cron Trigger는 UTC 기준으로 실행되며, 새로 추가하거나 변경한 트리거는
  배포 후 실행되기 시작할 때까지 최대 15분이 걸릴 수 있습니다.
- **로컬 테스트.** 빌드된 Worker를
  `npx wrangler dev --test-scheduled --config .output/server/wrangler.json`으로
  실행한 다음, `/cdn-cgi/handler/scheduled?cron=*+*+*+*+*`를 요청하면 스윕이 한 번
  실행됩니다.

다른 호스트는 [스케줄러 실행 방법](/docs/recurring-jobs#how-scheduler-runs)을
참조하세요.
