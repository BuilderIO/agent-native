# 기존 앱을 Core 0.198.0으로 업그레이드

이 가이드를 따라 기존 앱을 Core 0.198.0으로 업그레이드하세요. 앱 또는
workspace 루트에서 명령을 실행하고 시작 전에 검토 가능한 소스 관리 diff를
남기세요. 원격 배포 설정은 별도로 확인해야 합니다. CLI는 로컬 환경 파일은
읽을 수 있지만 원격 환경이나 데이터베이스에 저장된 기능 설정을 확인할 수
없습니다.

## 1. 업그레이드와 import codemod 미리 보기

Core 0.198.0에 포함된 CLI를 사용해 해당 릴리스의 migration manifest를
불러옵니다.

    npx @agent-native/core@0.198.0 upgrade --codemods --dry-run

앱에 Core 0.198.0을 설치한 뒤에는 로컬 CLI 바이너리로 같은 미리보기를 실행할 수 있습니다:

    npx agent-native upgrade --codemods --dry-run

`--codemods` 명령은 `ts-morph`를 사용합니다. 앱에서 아직 이 패키지를 확인할 수 없다면 먼저 개발 의존성으로 설치하세요: `pnpm add -D ts-morph`.

`--codemods`는 지원되는 import 변경을 기본적으로 적용합니다. 예정된 dependency 변경,
파일 diff, 경고를 미리 확인하려면 `--dry-run`을 추가하세요. 이제 `--yes`는 필요하지 않습니다.

codemod는 활성 Core 및 Toolkit migration manifest를 사용합니다. 선언 파일,
생성 파일, dependency 디렉터리를 제외한 .ts 및 .tsx 파일만 검색해 지원되는
import와 re-export specifier를 다시 씁니다. 이름이 지정된 export가 여러
모듈로 이동하면 선언을 symbol별로 나누면서 alias와 type-only import를
유지할 수 있습니다. 간단한 CSS @import 경로도 바꾸고, 해결된 경로가 패키지
경계를 넘어가면 누락된 dependency를 추가합니다.

진단은 CommonJS `require()` 형식과 동적 `import()` 형식도 감지하지만 codemod는 이러한 호출식을 다시 쓰지 않습니다. 보고된 새 경로를 사용해 직접 바꾼 다음 Vite 또는 `agent-native doctor`를 다시 실행하세요. CSS `@import url(...)` 경로는 따옴표가 있거나 없어도 codemod가 다시 씁니다.

호출 위치를 바꾸거나 파일을 옮기지는 않습니다. 해결되지 않았거나 planned인
이동은 경고와 함께 그대로 둡니다. default, namespace, side-effect, star
import/export는 나눌 수 없습니다. symbol 단위 CSS import도 분리할 수 없습니다. 이런 경우는 직접 검토하세요. 제거된
export는 코드 변경이 필요할 수 있으므로 CLI 경고에 나온 migration guide를
따르세요.

미리 보기에는 전체 업그레이드 계획도 표시됩니다. 업그레이드를 막는
framework override 또는 patch, 대기 중인 @agent-native/\* 버전 갱신, 로컬
설정에서 추론한 기능 dependency, package manager 설치, scaffold skill 갱신,
루트 package에 typecheck script가 있을 때의 typecheck가 포함됩니다.
명령은 package spec을 registry의 현재 latest로 바꾼 뒤 설치에서 해결된
버전을 pin합니다. 0.198.0을 의도한 현재 릴리스로 사용할 시점에 실행하고,
나중에 정확한 버전이 필요하면 해결된 pin을 확인하세요.

## 2. Toolkit 및 선택적 패키지 확인

`@agent-native/toolkit/*`으로 이동한 import에는 `@agent-native/toolkit`이 필요합니다. 지원되고 해석 가능한 import 또는 export를 이동하면 codemod가 Toolkit을 추가합니다. 앱에서 Toolkit export를 사용하는데 dependency가 추가되지 않았다면 Core 0.198.0에 맞는 Toolkit 버전을 설치하세요:

    pnpm add @agent-native/toolkit@0.198.0
    # npm install @agent-native/toolkit@0.198.0
    # yarn add @agent-native/toolkit@0.198.0

### 업그레이드 CLI가 선택하는 dependency

로컬 환경 검사 조건이 맞으면 CLI가 다음 dependency를 추가합니다. PGlite는 정규화된 앱 이름의 `${APP_NAME}_DATABASE_URL`을 먼저 확인한 다음 `DATABASE_URL`을 확인하며, URL이 없거나 `pglite:`로 시작하면 선택됩니다. 원격 환경이나 데이터베이스에 저장된 기능 설정은 확인할 수 없으므로 프로덕션과 프리뷰를 따로 확인하세요.

| 기능                          | 선택적 패키지                | 버전                  | CLI가 확인하는 로컬 설정                                                          |
| ----------------------------- | ---------------------------- | --------------------- | --------------------------------------------------------------------------------- |
| PGlite 데이터베이스           | @electric-sql/pglite         | ^0.5.8                | 정규화한 `${APP_NAME}_DATABASE_URL`, 다음 `DATABASE_URL`; 없거나 `pglite:`로 시작 |
| 서버 Sentry                   | @sentry/node                 | ^10.60.0 또는 ^11.0.0 | `SENTRY_SERVER_DSN`, `SENTRY_DSN` 또는 Sentry 키 조합                             |

기본 템플릿 소스 검색을 사용하려면 같은 버전의 코퍼스 패키지를 개발 의존성으로 추가하세요: `pnpm add -D @agent-native/core-corpus@0.198.0`.

## 3. 업그레이드 적용

미리 보기를 검토하고 기능 패키지를 확인한 다음 버전을 지정한 CLI로
계획을 적용합니다. 앱이 아직 Core 0.196 또는 더 오래된 CLI를 사용하는
경우 해당 CLI에 이전 마이그레이션 manifest가 있으므로 이 단계가 중요합니다.

    npx @agent-native/core@0.198.0 upgrade --codemods

앱에 Core 0.198.0이 설치된 후에는 로컬 CLI에서 같은 명령을 실행할 수
있습니다.

    npx agent-native upgrade --codemods

두 실행 방식 모두 해당되는 @agent-native/\* dependency spec을 갱신하고
감지된 기능 dependency를 맞춘 뒤 package manager를 실행합니다. 해결된
Agent-Native 버전을 pin하고 지원되는 codemod를 적용하며 scaffold skill을
갱신합니다. 루트에 typecheck script가 있으면 실행합니다. codemod 적용만
위해 upgrade를 다시 실행하지 마세요. 경고와 앱 수준 오류는 앱 코드에서
해결하고 framework override나 patch는 추가하지 마세요.

## 4. 결과 확인

생략된 codemod 경고와 dependency 버전을 포함해 전체 diff를 검토한 뒤
실행합니다.

    npx @agent-native/core@0.198.0 upgrade check
    npx agent-native doctor
    pnpm typecheck

Doctor는 기본으로 `migration-manifest`와 `feature-dependencies` 검사를
실행합니다. 오래된 import와 로컬 설정에서 감지한 기능에 필요한 선택적
peer의 누락을 보고합니다. 원격 배포 설정과 데이터베이스에 저장된 기능
설정은 확인할 수 없으므로 별도로 점검하세요.

npm 또는 Yarn에서는 해당 typecheck 명령을 사용하세요. 앱에 테스트 및 빌드
스크립트가 있으면 실행하세요. 일반적으로 `pnpm test`와 `pnpm build`입니다.
로컬 및 배포된 기능 설정이 선택적 peer 표에 반영됐는지 확인하세요. 아래
표에 있는 이전 import를 검색하고, 남은 항목은 의도된 경우이거나 manifest가
지원하지 않거나 경고로 설명되어 있어야 합니다.
