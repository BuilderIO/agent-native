# Azure Static Web Apps

<Badge label="Beta" color="orange" icon="rocket" />

Azure Static Web Apps가 앱을 호스팅하므로 서버를 설정하거나 계속 실행해 둘 필요가 없습니다. 앱의 정적 파일을 직접 제공하고 앱의 서버를 관리형 Azure Functions로 실행하며, 앱에 HTTPS가 적용된 공개 주소를 제공합니다.

이 가이드는 독립 실행형 앱 하나를 처음부터 배포하는 과정을 안내합니다. 앱을 만들고, 프로덕션 데이터베이스와 인증 시크릿을 지정하고, 데이터베이스를 준비하고, Azure용으로 빌드하고, 정적 웹앱을 만든 다음, Static Web Apps CLI로 완성된 빌드를 업로드합니다.

<Callout tone="info">

Node.js `22.22+`가 필요합니다.

</Callout>

Azure 계정도 필요합니다. 이 가이드의 명령은 자신의 컴퓨터에서 실행하세요. 앱은 Node.js로 빌드하며, 완성된 빌드는 Static Web Apps CLI가 Azure에 업로드합니다.

## 1단계: 앱 만들기 {#step-1-create-the-app}

새 독립 실행형 앱을 만듭니다. 아래 예시는 Chat 템플릿으로 앱을 만들지만, 어떤 템플릿으로든 시작할 수 있습니다. 앱 폴더로 이동한 뒤 의존성을 설치하세요. `corepack enable`은 앱이 기대하는 `pnpm` 버전을 활성화하므로 `pnpm`을 직접 설치할 필요가 없습니다.

```bash
npx --yes @agent-native/core@latest create my-app --standalone --template chat

cd my-app

corepack enable

pnpm install
```

원한다면 `my-app`을 원하는 앱 이름으로 바꾸세요. 이 가이드의 나머지 부분은 앱 폴더 안에 있다고 가정합니다.

## 2단계: 환경 시크릿 구성하기 {#step-2-configure-environment-secrets}

앱은 프로덕션 설정을 환경 변수에서 읽습니다.

| 변수                 | 필수   | 용도                                          |
| -------------------- | ------ | --------------------------------------------- |
| `DATABASE_URL`       | 예     | 앱을 PostgreSQL 데이터베이스에 연결합니다     |
| `BETTER_AUTH_SECRET` | 예     | 사용자 세션에 서명합니다                      |
| `BETTER_AUTH_URL`    | 아니요 | 사용자가 앱에 접속하는 공개 주소를 설정합니다 |

아래의 export 명령을 실행하면 이 셸에서 이후 명령이 동작합니다. 배포하기 전에 같은 변수를 호스트의 프로젝트 또는 서비스 환경 설정에도 저장하세요. Azure에 저장하는 방법은 5단계에서 설명합니다.

### 데이터베이스 URL {#database-url}

로컬 개발 중에는 `DATABASE_URL`이 설정되지 않으면 앱이 로컬 데이터베이스에 데이터를 저장합니다. 배포된 앱에는 배포 후에도 데이터를 유지하는 실제 PostgreSQL 데이터베이스가 필요합니다. Azure Functions는 요청 사이에 파일을 유지하지 않으므로 데이터베이스는 정적 웹앱 밖에 있어야 합니다. 프로바이더에서 연결 문자열을 복사해 export하세요.

```bash
export DATABASE_URL='your-postgres-url-string'
```

[데이터베이스 프로바이더 가이드](/docs/neon)에서 [Azure Database for PostgreSQL](/docs/azure-postgresql)을 포함해 프로바이더별로 연결 문자열을 찾는 위치를 확인할 수 있습니다.

<Callout tone="warning">

Neon, Supabase, Amazon RDS 등 영구적인 PostgreSQL 프로바이더를 선택하세요.

</Callout>

### 인증 시크릿 {#auth-secret}

이 값은 한 번만 생성하고 배포할 때마다 바꾸지 마세요.

앱은 `BETTER_AUTH_SECRET`을 사용해 사용자 세션에 서명합니다. 이 값이 바뀌면 로그인한 모든 사용자가 로그아웃됩니다. 아래 명령은 임의의 값을 생성합니다.

```bash
export BETTER_AUTH_SECRET="$(openssl rand -hex 32)"
```

생성한 값은 비밀번호 관리자처럼 안전한 곳에 저장하세요. 배포할 때마다 같은 값을 사용합니다.

### 공개 URL {#public-url}

선택 사항입니다. 사용자 지정 도메인, 리버스 프록시, 또는 고정된 공개 origin이 필요한 인증이나 OAuth 흐름을 사용할 때 설정하세요.

`BETTER_AUTH_URL`은 사용자가 앱에 접속하는 공개 주소입니다. 이 값이 없으면 앱은 들어오는 요청마다 자신의 주소를 판단합니다. Azure가 제공하는 주소에서는 대개 문제가 없지만, 사용자 지정 도메인을 연결할 때는 로그인 링크와 OAuth 리디렉션이 그 도메인을 사용하도록 이 값을 설정하세요.

```bash
export BETTER_AUTH_URL='https://your-domain.example'
```

## 3단계: 마이그레이션 {#step-3-migrate}

마이그레이션은 앱에 필요한 테이블을 데이터베이스에 만들고 업데이트합니다. 첫 배포 전에 이 명령을 실행하세요.

```bash
pnpm migrate:production
```

이 명령은 자신의 컴퓨터에서 실행되며, 2단계에서 export한 `DATABASE_URL`로 프로덕션 데이터베이스에 연결합니다. 앱을 업그레이드한 뒤에는 새 버전을 배포하기 전에 다시 실행하세요.

## 4단계: 빌드 {#step-4-build}

### 앱 빌드하기 {#build-the-app}

Azure Static Web Apps용으로 앱을 빌드합니다.

```bash
NITRO_PRESET=azure-swa pnpm build
```

`NITRO_PRESET=azure-swa`는 Azure Static Web Apps가 기대하는 형식으로 앱을 빌드합니다. 빌드는 정적 파일을 `.output/public`에, 서버 함수를 `.output/server`에 씁니다. 또한 `staticwebapp.config.json` 파일을 앱 폴더에 씁니다. 이 파일은 요청을 라우팅하는 방법과 서버를 실행할 Node.js 버전을 Azure에 알려 줍니다.

### API 런타임 설정하기 {#set-the-api-runtime}

Azure는 `staticwebapp.config.json`에 지정된 Node.js 버전으로 앱의 서버를 실행합니다. 빌드는 `package.json`의 `engines` 필드에서 이 버전을 고르지만, 필드 값이 정확히 `20` 또는 `22`일 때만 그렇습니다. 새 앱은 `>=22.22.0`을 요구하므로 빌드가 대신 Node.js 18을 쓰는데, 이 버전은 앱에 너무 오래되었고 Azure에서도 더 이상 지원하지 않습니다.

빌드할 때마다 버전을 Node.js 22로 설정하세요.

```bash
node -e "const fs = require('node:fs'); const file = 'staticwebapp.config.json'; const config = JSON.parse(fs.readFileSync(file, 'utf8')); config.platform = { ...config.platform, apiRuntime: 'node:22' }; fs.writeFileSync(file, JSON.stringify(config, null, 2));"
```

이 명령은 `apiRuntime` 설정만 바꾸고 빌드가 쓴 파일의 나머지 부분은 그대로 유지합니다. 빌드할 때마다 파일이 다시 작성되므로, 빌드할 때마다 배포하기 전에 이 명령을 실행하세요.

## 5단계: 정적 웹앱 만들기 및 시크릿 저장하기 {#step-5-create-the-static-web-app-and-save-the-secrets}

Azure Portal에서 새 **Static Web App**을 만듭니다. 구독, 리소스 그룹, 이름, 플랜을 선택하세요. GitHub 저장소를 연결하는 대신 빌드를 직접 업로드하므로 **Deployment details**에서 **Other**를 선택합니다.

앱의 **Overview** 페이지에 있는 **Manage deployment token**에서 배포 토큰을 복사해 export하세요.

```bash
export SWA_CLI_DEPLOYMENT_TOKEN='your-deployment-token'
```

Static Web Apps CLI는 6단계에서 이 변수를 읽습니다. 토큰이 있으면 누구나 앱에 배포할 수 있으므로 토큰은 비공개로 유지하세요.

그런 다음 필수 변수 두 개를 저장합니다. Azure Portal에서 정적 웹앱을 열고 **Settings** > **Environment variables**로 이동한 뒤 **Production** 환경을 선택하고, 2단계에서 export한 값으로 `DATABASE_URL`과 `BETTER_AUTH_SECRET`을 추가하세요. `BETTER_AUTH_URL`을 설정했다면 같은 방법으로 추가하세요. Azure는 이 값들을 환경 변수로 앱의 서버 함수에 전달합니다.

## 6단계: 배포 {#step-6-deploy}

<Steps>

### 빌드 업로드하기

앱 폴더에서 정적 파일과 서버 함수를 프로덕션에 업로드합니다.

```bash
npx @azure/static-web-apps-cli deploy .output/public --api-location .output/server --swa-config-location . --env production
```

`.output/public`에는 정적 파일이 들어 있고, `--api-location .output/server`는 서버 함수의 위치를 지정합니다. `--swa-config-location .`은 빌드가 `staticwebapp.config.json`을 쓴 앱 폴더를 지정합니다. 이 옵션이 없으면 Azure가 4단계의 API 런타임을 인식하지 못합니다. `--env production`은 미리 보기 환경 대신 프로덕션 주소에 게시합니다.

### 앱 열기

명령이 끝나면 `azurestaticapps.net`으로 끝나는 앱 주소가 출력됩니다. 그 주소를 열고 첫 계정을 만듭니다.

</Steps>

## 업데이트 배포하기 {#deploy-updates}

새 버전을 배포하려면 마이그레이션을 실행하고, 다시 빌드한 다음, 업로드하세요.

```bash
pnpm migrate:production

NITRO_PRESET=azure-swa pnpm build

node -e "const fs = require('node:fs'); const file = 'staticwebapp.config.json'; const config = JSON.parse(fs.readFileSync(file, 'utf8')); config.platform = { ...config.platform, apiRuntime: 'node:22' }; fs.writeFileSync(file, JSON.stringify(config, null, 2));"

npx @azure/static-web-apps-cli deploy .output/public --api-location .output/server --swa-config-location . --env production
```

새 셸에서는 `SWA_CLI_DEPLOYMENT_TOKEN`을 다시 export하세요. 저장한 환경 변수는 정적 웹앱에 그대로 유지되므로 5단계를 반복할 필요가 없습니다.

## 요청 제한 {#request-limits}

Azure Static Web Apps는 앱 서버에 대한 요청을 45초 후에 종료하며 WebSockets를 지원하지 않습니다. Agent-Native는 이미 채팅 턴을 약 40초 후에 종료하고 브라우저에서 이어서 진행하므로 긴 에이전트 턴도 끝까지 완료되지만, 한 번에 실행되지 않고 여러 단계에 걸쳐 실행됩니다. 앱에 긴 요청이 필요하다면 [Node.js](/docs/node-js)나 [Docker](/docs/docker)처럼 이 제한이 없는 호스트를 사용하세요.
