# 클립 임베드

호스팅된 클립을 여러분의 제품을 위한 녹화 백엔드로 사용하세요. 사람들은 클립에 로그인하지 않고도 iframe에서 녹화할 수 있습니다. 여러분의 백엔드는 조직 서비스 토큰을 사용해 단기 수집 URL을 만들고, 클립은 그 결과로 만들어진 녹화를 해당 조직에 설정된 저장소에 저장합니다.

이 가이드는 호스팅된 임베딩 흐름을 다룹니다. 녹화하는 사람이 클립 계정을 가지고 있어야 할 필요는 없습니다.

## 통합이 동작하는 방식

이 통합은 네 부분으로 이루어집니다.

1. 조직 관리자가 클립에서 동영상 저장소를 설정합니다.
2. 여러분의 백엔드가 조직 서비스 토큰을 저장하고 수집 URL을 요청합니다.
3. 여러분의 제품은 단기 수집 URL만 iframe에 전달합니다.
4. 클립이 녹화를 조직의 저장소에 업로드하고 여러분의 제품에 완료 메시지를 보냅니다.

조직 서비스 토큰은 iframe에 들어가서는 안 됩니다. 토큰은 발급한 조직에 묶여 있으므로 토큰 자체가 조직 컨텍스트를 제공합니다. 조직 ID는 여러분의 테넌트 매핑에는 유용하지만 그 자체로 자격 증명은 아닙니다.

## 클립 조직 설정하기

녹화를 소유해야 할 클립 조직을 만들거나 선택하세요. 그런 다음 조직 관리자가 클립 온보딩이나 클립 설정을 통해 동영상 저장소를 구성합니다.

- **Builder.io Connect**는 관리형 동영상 저장소와 AI 크레딧을 제공합니다.
- **S3 호환 저장소**는 조직에 설정된 엔드포인트, 버킷, 액세스 키, 시크릿 키, 선택적으로 리전이나 공개 기본 URL을 사용합니다. Cloudflare R2와 DigitalOcean Spaces는 각 제공자별 이름으로 동일한 저장소 설정을 사용합니다.

저장소 설정은 조직 범위입니다. 해당 조직의 서비스 토큰을 통해 만들어진 모든 녹화는 이미 그 조직에 연결된 저장소를 사용합니다. 임베딩하는 제품은 Builder.io나 S3 자격 증명을 알 필요가 없습니다.

동영상은 설정된 오브젝트 저장소에 저장됩니다. 클립은 녹화 메타데이터, 소유권, 처리 상태, 저장소 참조를 자체 데이터베이스에 저장합니다.

## 조직 서비스 토큰 만들기

조직 소유자나 관리자로서 기존 `connect` 명령을 실행하세요. 이 명령은 브라우저 로그인을 열고, 현재 활성화된 조직을 위한 이름이 지정된 서비스 토큰을 만들고, 토큰을 한 번만 출력합니다.

```bash
npx @agent-native/core@latest connect https://clips.agent-native.com \
  --service-token support-desk --ttl-days 365
```

출력된 토큰을 여러분의 제품의 서버 측 시크릿 관리자에 바로 복사하세요. 토큰은 조직이 소유하므로 발급한 사람이 조직을 떠나거나 개인 토큰을 취소해도 계속 동작합니다. 로컬 클라이언트 설정에는 절대 기록되지 않습니다. 통합마다 다른 서비스 이름을 사용하면 다른 호출자를 깨뜨리지 않고 하나의 호출자만 취소할 수 있습니다.

`--ttl-days`는 1일에서 365일까지 받을 수 있으며 기본값은 365일입니다. 토큰은 조직 구성원으로서 동작합니다. 다른 서비스 토큰을 만들거나 취소할 수 없고 조직 설정을 바꿀 수도 없습니다.

## 수집 URL 요청하기

신뢰할 수 있는 백엔드가 클립 수집 액션을 호출합니다. 호스팅 계정이라면 호스팅된 클립 원본을 사용하고, 자체 호스팅이라면 여러분만의 클립 원본을 사용하세요.

```ts
const clipsBaseUrl = "https://clips.agent-native.com";
const clipsServiceToken = process.env.CLIPS_SERVICE_TOKEN;

const response = await fetch(
  `${clipsBaseUrl}/_agent-native/actions/create-recording-intake-link`,
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${clipsServiceToken}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      ttlSeconds: 3600,
    }),
  },
);

if (!response.ok) {
  throw new Error("Could not create a Clips intake URL");
}

const intake = await response.json();
// intake.url is safe to pass to the recording iframe.
```

서비스 토큰의 서명된 조직 컨텍스트가 어느 조직이 수집을 소유하는지 결정합니다. 액션 응답은 최상위 수준의 intake 객체입니다. 기본 수집 유효 기간은 1시간입니다. 최대는 4시간입니다. 각 수집 URL은 하나의 녹화를 만들 수 있습니다.

이 요청을 익명 브라우저에서 하지 마세요. 서비스 토큰, 저장소 자격 증명, 또는 장기 클립 세션을 브라우저에 반환하지 마세요.

## 레코더 임베드하기

반환된 URL을 iframe에 바로 전달하세요. 이 URL에는 방문자가 하나의 비공개 녹화를 만들고 업로드할 수 있게 하는, 좁게 제한되고 서명된 권한이 담겨 있습니다.

```tsx
<iframe
  data-clips-recorder
  src={intake.url}
  allow="display-capture; camera; microphone"
  title="Report a problem"
  style={{ width: 420, height: 560, border: 0 }}
/>
```

렌더링하기 전에 프로젝트 ID, 페이지 제목, 애플리케이션 버전, 환경 같은 작고 민감하지 않은 컨텍스트 값을 수집 URL에 추가할 수 있습니다. 비밀번호, API 키, 고객 기록, 그 외 민감한 값은 URL에 넣지 마세요. URL은 브라우저 기록, 로그, 분석, 리퍼러에 나타날 수 있습니다.

방문자가 캡처를 시작하면 레코더가 최상위 팝업을 엽니다. 브라우저 미디어 권한과 화면 캡처는 최상위 브라우징 컨텍스트에서의 사용자 제스처를 필요로 합니다. 테스트 중에는 호스트 제품에서 팝업을 허용하세요.

## 완료 메시지 받기

녹화가 저장되면 완료 페이지가 임베딩한 부모에게 `agent-native.clips.bug-report.submitted`를 전송합니다. 페이로드를 사용하기 전에 클립 원본과 메시지 소스를 검증하세요.

```ts
const clipsOrigin = new URL(clipsBaseUrl).origin;
const recorderFrame = document.querySelector<HTMLIFrameElement>(
  "iframe[data-clips-recorder]",
);

window.addEventListener("message", (event) => {
  if (event.origin !== clipsOrigin) return;
  if (recorderFrame && event.source !== recorderFrame.contentWindow) return;
  if (event.data?.type !== "agent-native.clips.bug-report.submitted") return;

  const { recordingId, recordingUrl, embedUrl, agentAccessStatus } = event.data;
  if (!recordingId) return;

  // Send recordingId to your trusted backend and attach it to the support case.
  console.log({ recordingId, recordingUrl, embedUrl, agentAccessStatus });
});
```

완료 페이로드에는 `recordingId`, `recordingUrl`, `embedUrl`, `agentShareUrl`, `agentContextUrl`, `agentAccessExpiresAt`, `agentAccessStatus`가 포함될 수 있습니다. `recordingId`를 지원 케이스의 지속적인 식별자로 취급하세요. 쓰기 전용 수집은 인증된 백엔드가 별도의 범위가 지정된 에이전트 링크를 만들기 전까지 `agentAccessStatus: "unavailable"`을 보고할 수 있습니다. 이 상태가 녹화가 비어 있다는 뜻은 아닙니다.

브라우저 메시지는 알림일 뿐 권한 부여가 아닙니다. 완료된 녹화를 읽거나 공유해야 할 때 여러분의 백엔드는 클립에 대한 자체 인증된 연결을 사용해야 합니다.

## 녹화가 저장되는 위치

서비스 토큰을 통해 만들어진 녹화는 그 토큰과 연결된 조직이 소유합니다. 클립은 미디어를 일반적인 업로드 및 완료 처리 파이프라인을 통해 전송합니다. 이 파이프라인은 해당 조직에 설정된 Builder.io 또는 S3 호환 저장소를 사용합니다.

iframe은 여러분의 버킷에 직접 업로드하지 않으며 버킷 자격 증명도 필요하지 않습니다. 여러분의 제품은 클립으로부터 녹화 식별자와 범위가 지정된 URL을 받습니다. 필요한 식별자나 URL만 여러분의 지원 시스템에 저장하세요.

## 클립 자체 호스팅하기

자체 호스팅도 동일한 조직 계약을 사용합니다.

1. 영구 데이터베이스와 공개 `BETTER_AUTH_URL`로 클립을 배포합니다.
2. 임베드된 녹화를 소유할 조직을 만듭니다.
3. 해당 조직에서 Builder.io Connect나 S3 호환 저장소를 한 번 설정합니다.
4. 자체 호스팅한 클립 원본에 대해 `connect`를 실행해 조직의 서비스 토큰을 만듭니다.
5. 배포 값이나 시크릿 관리자 값으로 그 토큰을 임베딩 백엔드에 한 번 제공합니다.
6. 백엔드가 수집 URL을 요청할 때 자체 호스팅한 클립 원본을 사용합니다.

```bash
npx @agent-native/core@latest connect https://clips.example.com \
  --service-token support-desk --ttl-days 365
```

예를 들어 임베딩 백엔드는 이런 값을 서버 측 설정에 보관할 수 있습니다.

```text
CLIPS_BASE_URL=https://clips.example.com
CLIPS_SERVICE_TOKEN=<secret>
```

토큰은 백엔드에 한 번 제공됩니다. 각 방문자는 여전히 새로운 단기 수집 URL을 받습니다. iframe에는 토큰이나 저장소 자격 증명이 전혀 추가되지 않으며, 토큰을 교체해도 iframe 코드를 바꿀 필요가 없습니다.

일반적인 자체 호스팅 요구사항은 [배포](/docs/deployment) 문서를 참고하세요.

## 보안 체크리스트

- 조직 서비스 토큰을 서버 측 시크릿 관리자에 보관하세요.
- 호스트 제품과 클립 모두에 HTTPS를 사용하세요.
- 각 수집 URL을 베어러 자격 증명처럼 취급하세요. 로그와 리퍼러 데이터에 남기지 마세요.
- 유용한 범위에서 가장 짧은 수집 유효 기간을 사용하세요.
- 완료 리스너에서 `event.origin`과 `event.source`를 모두 검증하세요.
- 클립의 소유자 범위 업로드 엔드포인트를 익명 사용자에게 직접 노출하지 마세요.
- `connect`로 대체 토큰을 만들고 배포한 다음 흐름을 확인하고, `revoke-org-service-token`으로 이전 토큰을 취소하는 방식으로 서비스 토큰을 교체하세요.
- 조직 ID와 수집 ID는 방문자가 제공한 값을 신뢰하는 대신 신뢰할 수 있는 백엔드에 보관하세요.

## 문제 해결

**수집 요청이 승인되지 않습니다.** 백엔드가 의도한 클립 원본을 위해 발급된, 만료되지 않고 취소되지 않은 서비스 토큰을 사용하는지 확인하세요. 토큰의 조직 바인딩이 수집이 만들어지는 위치를 결정합니다.

**iframe이 로그인 페이지를 엽니다.** iframe이 `create-recording-intake-link`가 반환한 단기 URL을 사용하는지 확인하세요. 익명 방문자에게 `/record`나 일반 클립 라이브러리 URL을 임베드하지 마세요.

**녹화가 끝나지 않습니다.** 조직에 Builder.io나 S3 호환 저장소가 설정되어 있는지 확인하세요. 익명 방문자는 iframe에서 저장소를 설정할 수 없습니다.

**완료에 에이전트 링크가 없습니다.** 쓰기 전용 수집에서는 예상된 동작입니다. 지원 워크플로에 에이전트가 읽을 수 있는 전사와 프레임 데이터가 필요하다면 인증된 백엔드가 별도의 범위가 지정된 에이전트 링크를 만들도록 하세요.
