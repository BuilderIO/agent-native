# 실행 컨텍스트

`run`은 선택적인 두 번째 인자 `ctx`를 받으며, 여기에는 해석된 요청 신원과 이 action을 호출한 표면이 담겨 있습니다. `getRequestUserEmail()` / `getRequestOrgId()`를 직접 호출하는 대신 이것을 읽고, 추적에는 `ctx` 전체를 전달하세요.

```ts
export default defineAction({
  description: "Log an audit entry for the current request.",
  schema: z.object({ event: z.string() }),
  run: async (args, ctx) => {
    // ctx is undefined-safe: a 1-arg `run(args)` is still valid.
    const actor = ctx?.userEmail ?? "system";
    if (ctx?.caller === "frontend") {
      // tighter rules for browser-initiated calls, looser for "tool"/"cli"
    }
    await db.insert(audit).values({
      actor,
      orgId: ctx?.orgId ?? null,
      source: ctx?.caller ?? "unknown",
      event: args.event,
    });
    return { ok: true };
  },
});
```

대부분의 action은 `ctx?.userEmail`과 `ctx?.orgId`만 읽습니다. 이는 거의 모든 실제 action에서 쓰이는 [액세스 제어 범위 지정](/docs/actions-access-control#access-control) 패턴입니다. 이 페이지의 나머지 부분은 추적이나 자동화 귀속처럼, 이보다 적은 수의 action에만 필요한 여러 표면을 아우르는 관심사들을 다룹니다.

## `ctx` 인자 {#ctx}

`ctx`는 두 종류의 정보를 담습니다. 거의 모든 호출에 존재하는 해석된 요청 신원(`userEmail`, `orgId`), 그리고 이 action을 호출한 표면에 대한 메타데이터(`caller`, 그리고 특정 호출자에게만 채워지는 `threadId`나 `automation` 같은 표면별 필드)입니다. `run()`의 두 번째 인자로서의 전체 형태는 다음과 같습니다.

`run()`은 하위 호환을 유지합니다. 기존의 1개 인자 핸들러나 `{ send }`만 구조 분해하는 핸들러도 변경 없이 계속 동작합니다.

### `caller` 유니언 {#caller}

`caller`는 `"tool" | "http" | "frontend" | "cli" | "mcp" | "a2a" | "automation"` 유니언입니다.

| `caller`       | 설정되는 경우                                                                                                                                                                    |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `"tool"`       | 앱 내 에이전트 루프, 서브 에이전트나 에이전트 팀, 또는 자연어 크로스앱 A2A 위임입니다. 이들은 모두 같은 에이전트 루프로 동작하므로 도구 호출이 `"tool"`이 됩니다.                |
| `"frontend"`   | `useActionMutation()`, `useActionQuery()`, `callAction()`을 통한 브라우저 호출입니다(`X-Agent-Native-Frontend: 1` 헤더로 표시됨).                                                |
| `"http"`       | 프런트엔드 마커 없이 `/_agent-native/actions/<name>`으로 보낸 순수한 프로그래밍 방식 `POST` 또는 `GET`입니다.                                                                    |
| `"cli"`        | `pnpm action <name>` (CLI 러너)입니다.                                                                                                                                           |
| `"mcp"`        | MCP `tools/call` 엔드포인트를 통한 외부 에이전트 호출입니다.                                                                                                                     |
| `"a2a"`        | 서명된 A2A 위임 토큰을 담아 `/_agent-native/actions/<name>`으로 보내는 직접 HTTP 호출입니다. 이는 명시적으로 노출된 크로스앱 디스패치로, 위의 자연어 `"tool"` 경로와는 다릅니다. |
| `"automation"` | 저장된 워크스페이스 트리거에서 디스패치된 이벤트 트리거 자동화입니다. `ctx.automation`이 트리거 계보를 담습니다. [자동화](/docs/automations)를 참고하세요.                       |
