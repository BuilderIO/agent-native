# Agent-Native란?

Agent-Native는 직관적인 UI를 갖춘 자율형 에이전트를 구축하기 위한 오픈 소스
TypeScript 프레임워크입니다. 각 기능을 [액션](/docs/actions-overview)으로 한 번만 정의합니다. 액션은 에이전트가 도구로 사용하고 UI가 코드에서 호출하는 타입이 지정된 함수입니다.

## UI를 갖춘 에이전트를 만드는 이유

코딩 에이전트를 보면 텍스트 상자만으로 충분해 보일 수 있습니다. 하지만 텍스트 상자는 작업 환경의 한 부분일 뿐입니다. 코드베이스가 컨텍스트를 제공하고, 도구가 명확한 실행 방법을 제공하며, 파일, 테스트, 미리보기가 결과를 보여 줍니다.

대부분의 지식 노동에는 이런 구조가 없습니다. 빈 텍스트 상자에서는 사람이 에이전트가 무엇을 할 수 있는지, 어떤 컨텍스트를 가지고 있는지, 무엇을 요청해야 하는지 추측해야 합니다.

UI는 텍스트 상자에 없는 것을 제공합니다. 에이전트의 기능을 눈에 보이게 하고, 컨텍스트와 워크플로를 경험에 포함하며, 작업이 진행되는 동안 사람이 이를 보고 다듬을 수 있게 합니다.

Agent-Native를 사용하면 이런 방식으로 에이전트를 만들 수 있습니다. UI는 에이전트를 고정된 워크플로로 제한하지 않으면서 명확한 시작점을 제공합니다. 에이전트와 UI가 같은 기능을 사용하므로, 사람은 에이전트에게 작업을 위임하고 UI에서 결과를 확인하거나 변경한 뒤 진행 상황을 잃지 않고 둘 사이를 오갈 수 있습니다.

Agent-Native는 세 가지 공유 기반을 통해 에이전트와 UI를 연결합니다.

- **[공유 액션](/docs/actions-overview).** 각 기능을 한 번만 정의합니다. 에이전트는 도구로 호출하고 UI는 코드에서 호출합니다. 두 경로 모두 같은 검증, 권한, 구현을 사용합니다.
- **[공유 데이터](/docs/server-database).** 액션은 같은 데이터를 읽고 업데이트합니다. 따라서 에이전트가 수행한 작업은 UI에 나타나고 UI에서 수행한 작업은 에이전트가 사용할 수 있습니다.
- **[공유 애플리케이션 상태](/docs/context-awareness).** 애플리케이션 상태는 현재 페이지, 선택된 레코드 또는 활성 뷰처럼 UI에서 일어나는 일을 설명합니다. Agent-Native는 관련 상태를 컨텍스트로 에이전트에 제공하므로 사람이 무엇을 작업 중인지 이해할 수 있습니다.

에이전트는 UI를 클릭해서 작업하지 않습니다. UI와 같은 액션 레이어를 통해 작업합니다.

예를 들어 사람은 UI에서 지원 티켓을 할당하거나 에이전트에게 그렇게 하도록 요청할 수 있습니다. 두 경로 모두 같은 액션을 실행하고 같은 티켓을 업데이트합니다. 사람은 UI에서 결과를 검사하거나 변경한 뒤 에이전트가 거기서 계속 작업하도록 할 수 있습니다.

## Agent-Native를 사용해야 하는 경우

다음과 같은 경우 Agent-Native가 적합합니다.

- 에이전트가 질문에만 답하는 것이 아니라 실제 작업을 해야 합니다.
- 에이전트가 무엇을 할 수 있는지 확인하고 그 작업을 검사, 편집, 승인 또는 공유할 UI가 필요합니다.
- 진행 상황이나 컨텍스트를 잃지 않고 에이전트와 UI 사이를 이동할 수 있어야 합니다.

생성된 응답 하나만 필요하다면 모델을 직접 호출하세요. 작업이 고정되고 예측 가능한 순서를 따른다면 일반 애플리케이션 로직이나 자동화가 더 단순합니다. 에이전트와 UI 모두가 같은 작업에서 지속적인 역할을 해야 할 때 Agent-Native를 사용하세요.
