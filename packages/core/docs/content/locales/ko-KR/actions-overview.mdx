# 개요

Actions는 여러분의 앱이 하는 모든 일에 대한 단일 진실 공급원입니다. `defineAction()`을 호출해 `actions/`에 넣으면 아래의 모든 표면이 이를 자동으로 인식합니다. 로직은 한 번만 작성하면 됩니다. 어떤 표면도 별도의 사본을 갖지 않으며, 서로 어긋날 수도 없습니다.

<Cards columns={2}>

### :robot: [에이전트 도구](/docs/agent-surfaces)

에이전트는 description과 schema를 읽어 호출 가능한 도구로 취급합니다. "이 티켓에 답장해줘"나 "이 스레드를 요약해줘"처럼 채팅에서 요청하세요.

### :components: [UI 후크](/docs/client-data)

`useActionQuery()`, `useActionMutation()`, `callAction()`은 React에서 동일한 action을 호출합니다. 클릭과 채팅 메시지가 정확히 같은 작업을 실행합니다.

### :server: [프레임워크 트랜스포트](/docs/http-api)

시작 시 `/_agent-native/actions/<name>`에 자동으로 마운트됩니다. UI 후크는 내부적으로 이 경로를 호출하며, 외부 HTTP 클라이언트도 이를 직접 호출할 수 있습니다.

### :plug: [MCP 도구](/docs/actions-other-surfaces#mcp)

Claude, Claude Desktop, Cursor, Codex 등 모든 MCP 호스트에 도구로 나타납니다. 다른 AI 클라이언트가 여러분의 앱을 조작해야 할 때 사용하세요.

### :network: [A2A 도구](/docs/actions-other-surfaces#a2a)

다른 에이전트 네이티브 앱이 A2A를 통해 이를 발견하고 호출합니다. 워크스페이스 안의 두 번째 앱이 이 앱을 대신 동작시켜야 할 때 사용하세요.

### :terminal: [CLI 명령](/docs/actions-other-surfaces#cli)

`pnpm action <name>`으로 터미널에서 실행합니다. 스크립트, cron 작업, 빠른 수동 테스트에 사용하세요.

</Cards>

대부분의 앱은 프런트엔드와 데이터베이스 사이에 브라우저만 호출할 수 있는 별도의 API 레이어를 만듭니다. 같은 기능을 원하는 에이전트는 다시 작성하고 유지 관리해야 하는 자신만의 별도 통합이 필요합니다. 에이전트 네이티브 앱은 이 분리를 건너뜁니다. UI와 에이전트가 정확히 같은 action을 호출하므로, 구현은 하나만 작성하면 되고 버그가 숨을 곳도 한 곳뿐입니다.

UI와 에이전트 둘 다 무언가를 해야 한다면, 커스텀 라우트 대신 action을 사용하세요. 라우트 형태의 프로토콜이 실제로 옳은 선택인 드문 경우에는 [앱 작업에는 Actions를 우선하세요](/docs/server-overview#actions-first)를 참고하세요.

## Actions의 역할 {#role}

`app/`([클라이언트 개요](/docs/client-overview#role) 참고)와 에이전트는 모두 동일한 actions와 동일한 SQL 데이터베이스로 귀결됩니다. 에이전트가 접근할 수 없는 별도의 "앱 백엔드"가 이 레이어와 대화하는 일은 없습니다. 기능을 만든다는 것은 여기서 하나의 작업을 정의하고, 동시에 UI, 에이전트 도구, 그리고 다른 모든 표면을 얻는다는 뜻입니다.

`actions/` 자체는 평평한 폴더입니다. 각 파일이 하나의 action입니다. `defineAction()` 호출을 파일의 기본 내보내기(default export)로 내보냅니다. 프레임워크는 시작 시 이 폴더를 스캔하여 찾은 모든 파일을 마운트합니다. 별도의 등록 단계도, 최신 상태로 유지해야 할 인덱스 파일도 없습니다.

action의 `run()` 본문은 일반적인 서버 코드이므로, 흔히 몇 개의 다른 디렉터리에 접근합니다.

`actions/` 바깥의 어떤 코드도 action의 `run` 함수를 직접 임포트해서는 안 됩니다. 대신 위의 표면들, 즉 에이전트 도구, UI 후크, HTTP, MCP, A2A, CLI 중 하나를 통해 호출하세요. 이 경로들은 모두 동일한 스키마 검증, 액세스 확인, 감사 기록을 거칩니다.

## 하나의 action으로 시작하기 {#hello-action}

채팅 우선 앱의 첫 작업은 아주 작아도 됩니다. Chat 템플릿에서
`actions/hello.ts`를 교체하거나 그 옆에 새 파일을 추가하세요.

```ts
// actions/hello.ts
import { defineAction } from "@agent-native/core/action";
import { z } from "zod";

export default defineAction({
  description: "Say hello from the local agent.",
  schema: z.object({
    name: z.string().default("world"),
  }),
  http: { method: "GET" },
  readOnly: true,
  run: async ({ name }) => {
    return { message: `Hello, ${name}!` };
  },
});
```

같은 폴더에서 실행하세요.

```bash
pnpm action hello '{"name":"Steve"}'
```

CLI는 action의 입력으로 JSON 객체를 받아들이며, 이는 에이전트가 이미
만드는 구조화된 도구 호출과 일치합니다. 빠른 수동 실행을 위한 단순한
플래그도 여전히 동작합니다.

```bash
pnpm action hello --name Steve
```

그런 다음 이 폴더를 대상으로 앱-에이전트 루프를 실행하세요.

```bash
npx agent-native agent "Call hello for Steve and explain the result"
```

이것이 여러분의 예약 작업(jobs), 채팅 UI, 외부 MCP 도구, 그리고 앞으로
만들 화면들이 사용할 것과 동일한 앱-에이전트 루프입니다. Chat 및 도메인
템플릿은 actions 주위에 UI를 추가하기 위한 것이지, action 자체를 위해
반드시 필요한 전제 조건은 아닙니다.
