# 시작하기

<GettingStartedPaths />

Agent-Native는 직관적인 UI를 갖춘 자율형 에이전트를 구축하기 위한 오픈 소스
TypeScript 프레임워크입니다. 각 기능을 [액션](/docs/actions-overview)으로 한 번만 정의합니다. 액션은 에이전트가 도구로 사용하고 UI가 코드에서 호출하는 타입이 지정된 함수입니다.

이 가이드에서는 채팅 UI가 있는 에이전트를 만들고, 포함된 `hello` 액션을 에이전트와 UI에서 호출합니다.

## 사전 요구 사항

- [Node.js](https://nodejs.org) 22.22 이상
- [pnpm](https://pnpm.io)이 설치되어 있고 `PATH`에서 실행 가능해야 합니다
- 에이전트용 LLM 연결: Builder.io, Anthropic 또는 OpenAI API 키, 또는 로컬 Ollama 모델

## 에이전트 만들기

새 디렉터리에서 Chat 템플릿으로 시작하세요.

```bash
npx --yes @agent-native/core@latest create my-app --standalone --template chat
cd my-app
corepack enable
pnpm install
```

템플릿은 에이전트에 브라우저 UI, 인증, 지속되는 대화, 라이브 동기화,
애플리케이션 컨텍스트와 `actions/` 디렉터리를 제공합니다. 이 가이드 전체에서
사용할 작은 `hello` 액션도 들어 있습니다.

<Callout tone="info">

이 명령이 피어 종속성 오류로 실패한다면 npx 캐시에 있는 오래된 패키지가 원인일 수 있습니다. `npx clear-npx-cache`를 실행해 캐시를 지운 다음 명령을 다시 실행하세요.

</Callout>

## 개발 서버 시작하기

개발 서버를 시작하세요.

```bash
pnpm dev
```

브라우저 UI가 자동으로 열립니다. 열리지 않으면 `pnpm dev`가 출력한 로컬 URL을 사용하세요. 8080이 사용 중이면 포트 번호가 증가합니다.

<Callout tone="info">

Welcome 화면에서 **Continue as local dev**를 선택하세요. 로컬 개발에서는 이메일이나 비밀번호를 입력할 필요가 없습니다.

</Callout>

## LLM 연결하기 {#connect-an-llm}

로컬 개발에서는 `pnpm dev`를 시작하기 전에 앱의 `.env` 파일에 프로바이더 키를 추가하세요.

```dotenv
ANTHROPIC_API_KEY=replace-with-your-key
```

로컬 서버는 이 키를 공유 fallback으로 사용하므로 로컬 앱 사용자는 UI에서 키를 추가할 필요가 없습니다. Self-hosted 프로덕션 앱은 배포 환경에 키를 설정해 앱의 공유 fallback으로 사용할 수 있습니다. 저장된 사용자 또는 조직 키가 우선합니다. Hosted-workspace 앱은 배포 프로바이더 키를 앱이나 테넌트 간에 공유하지 않습니다.

PostgreSQL을 사용하면 사용자는 **Custom keys**에서 키를 저장할 수도 있습니다. 본인 계정에만 적용하려면 Personal 범위를 선택하고, 관리자는 Organization 범위로 워크스페이스와 공유할 수 있습니다. 저장된 키는 암호화된 데이터베이스 기반 자격 증명 저장소에 보관됩니다.

Builder의 관리형 프로바이더를 사용하려면 composer에서 **Use Builder.io**를 선택하세요. 지원되는 프로바이더 키와 범위는 [환경 변수](/docs/environment-variables#optional-ai-search-and-email-fallbacks)를 참조하세요.

## 에이전트에서 액션 실행하기

액션은 React UI가 코드에서 호출하고 에이전트가 도구로 사용할 수 있는 타입이 지정된 함수입니다. Chat 템플릿에는 간단한 `hello` 액션이 있어 직접 작성하기 전에 이 패턴을 시험할 수 있습니다.

**시작하기** 페이지의 프롬프트에서 다음과 같이 요청하세요.

> Call the hello action for Alex.

에이전트는 설명과 입력 스키마에서 `hello`를 찾아 `Alex`를 `name` 입력으로 전달하고 다음과 같이 응답합니다.

```text
Hello, Alex!
```

## 액션 살펴보기

로컬 `my-app` 디렉터리에서 코드 편집기로 `actions/hello.ts`를 여세요.

```ts filename="actions/hello.ts"
import { defineAction } from "@agent-native/core/action";
import { z } from "zod";

// One action powers every app surface: UI, agent, HTTP, MCP, A2A, and CLI.
export default defineAction({
  description: "Return a friendly greeting.",
  schema: z.object({
    name: z.string().default("world").describe("Name to greet"),
  }),
  http: { method: "GET" },
  run: async ({ name }) => {
    return { message: `Hello, ${name}!` };
  },
});
```

우선 다음 네 부분에 집중하세요.

- `description`은 에이전트에게 액션을 언제 사용할지 알려 줍니다.
- `schema`는 입력을 검증하고 에이전트에 타입이 지정된 도구 정의를 제공합니다.
- `http`는 이 읽기 전용 액션을 `GET`으로 노출하여 `useActionQuery`가 React에서 호출할 수 있게 합니다.
- `run`에는 에이전트와 UI가 공유하는 애플리케이션 로직이 들어 있습니다.

전체 API는 [액션 정의하기](/docs/actions-defining)에서 확인하세요.

## React에서 액션 호출하기

템플릿에는 `actions/hello.ts`가 포함되어 있지만 해당 페이지는 없습니다.
`app/routes/hello.tsx`를 만드세요.

```tsx filename="app/routes/hello.tsx"
import { useActionQuery } from "@agent-native/core/client/hooks";
import { useState } from "react";

import { Input } from "@/components/ui/input";
import { Label } from "@/components/ui/label";

export default function HelloRoute() {
  const [name, setName] = useState("Alex");
  const { data } = useActionQuery("hello", { name });

  return (
    <main className="mx-auto grid w-full max-w-xl gap-6 p-6">
      <h1 className="text-2xl font-semibold">Hello action</h1>
      <div className="grid gap-2">
        <Label htmlFor="name">Name</Label>
        <Input
          id="name"
          value={name}
          onChange={(event) => setName(event.target.value)}
        />
      </div>
      <p className="text-xl font-medium">{data?.message}</p>
    </main>
  );
}
```

<Callout tone="info">

새 라우트를 찾을 수 있도록 개발 서버를 다시 시작한 다음 `http://localhost:<port>/hello`를 여세요.

</Callout>

이름을 입력하면 `useActionQuery`가 `hello`를 호출하고 결과를 렌더링합니다. 액션의 입력 및 결과 타입을 추론하므로 페이지에 맞춤 API 라우트나 인사말의 두 번째 구현이 필요하지 않습니다.

## 액션 변경하기

`actions/hello.ts`에서 반환 값을 변경하세요.

```ts
return { message: `Welcome, ${name}.` };
```

`/hello`를 새로 고친 다음 에이전트에게 `hello`를 다시 호출하도록 요청하세요. 같은 액션을 호출하므로 둘 다 업데이트된 인사말을 반환합니다.

## 다른 방법으로 액션 호출하기

같은 액션을 에이전트와 UI에서 호출했습니다. 이 액션은 다음에서도 호출할 수 있습니다.

| 호출 위치                               | 용도                                                         |
| --------------------------------------- | ------------------------------------------------------------ |
| [HTTP API](/docs/http-api)              | 스크립트, 백엔드 또는 통합에서 액션을 호출합니다.            |
| [CLI](/docs/actions-other-surfaces#cli) | 터미널에서 액션을 실행하거나 테스트합니다.                   |
| [MCP](/docs/actions-other-surfaces#mcp) | 외부 AI 클라이언트가 액션을 도구로 검색하고 호출하게 합니다. |
| [A2A](/docs/actions-other-surfaces#a2a) | 다른 에이전트가 내 에이전트에 작업을 위임하게 합니다.        |

모든 호출자가 같은 액션 정의를 사용합니다. 호출자별로 별도 구현이 필요하지 않습니다. 이 공유 액션 모델은 Agent-Native의 핵심입니다. 기능을 추가해도 UI, 에이전트, 통합 전반에서 동작, 검증, 권한이 일관되게 유지됩니다.

## 만든 것

채팅 UI가 있는 에이전트를 만들고 같은 `hello` 액션을 에이전트와 React UI에서 호출했으며, 인사말을 한 번 바꿔 두 곳 모두 업데이트되는 것을 확인했습니다. 앞으로 작성하는 모든 액션도 같은 패턴을 따릅니다.
