# AI 에이전트로 앱 만들기

AI 에이전트에게 Agent-Native 앱을 만들어 달라고 요청할 수 있습니다. 프롬프트 하나를 붙여넣으면 에이전트가 설정 명령을 실행하고, 끝나면 실행 중인 앱을 보여 줍니다.

명령을 직접 입력하고 싶다면 [시작하기](/docs/getting-started)를 따라 하세요.

## 시작하기 전에

- Claude Code, Codex, Cursor처럼 터미널 명령을 실행할 수 있는 AI 에이전트. ChatGPT나 웹의 Claude처럼 대화만 가능한 에이전트도 도움을 줄 수 있습니다. [명령을 실행할 수 없는 에이전트](#chat-only-agents)를 참고하세요.
- [Node.js](https://nodejs.org) 22.22 이상.
- 새 앱을 둘 빈 폴더.

앱을 만들 때는 API 키가 필요하지 않습니다. 앱 자체의 에이전트가 답변하게 하려는 경우에만 필요합니다. [LLM 연결](/docs/getting-started#connect-an-llm)을 참고하세요.

## 이 프롬프트를 붙여넣으세요

빈 폴더에서 에이전트를 열고 아래 프롬프트를 붙여넣으세요. 첫 줄의 `my-app`을 원하는 이름으로 바꾸세요. 한 번만 바꾸면 됩니다.

```markdown
my-app이라는 새 폴더에 새 Agent-Native 앱을 만들고 실행해 줘.
아래 단계에서 APP_NAME이라고 쓴 곳에는 이 이름을 사용해 줘.

1. Node.js가 22.22 이상인지, pnpm을 사용할 수 있는지 확인해 줘.
   pnpm이 없으면 `corepack enable`을 실행해 줘. corepack도 없으면
   `npm install -g pnpm`을 실행해 줘. Node.js가 너무 오래된 버전이면
   설치하지 말고 멈춰서 나에게 알려 줘.
2. 다음을 실행해 줘:
   npx --yes @agent-native/core@latest create APP_NAME \
    --standalone --template chat
3. 새로 만들어진 APP_NAME 폴더에서 `pnpm install`을 실행해 줘.
4. 앱 구조를 파악할 수 있도록 APP_NAME/AGENTS.md를 읽어 줘.
5. `pnpm dev`로 앱을 시작하고 백그라운드에서 계속 실행해 줘.
6. `pnpm dev`가 출력하는 로컬 URL을 읽어 줘. 응답하는지 예를
   들어 `curl -I <url>`로 확인해 줘. 브라우저를 열지 말고
   헤드리스 브라우저 도구도 쓰지 마. 앱은 내가 직접 열게.
7. 결과를 보여 줘. 로컬 URL과 거기서 받은 응답을 알려 줘.
   설정이 끝났다고 말만 하지 마.

규칙:

- API 키를 지어내거나 나에게 붙여넣으라고 요청하지 마. LLM 연결은
  선택 사항이며 내가 직접 할게.
- .env 파일의 비밀 값을 출력하지 마.
- 명령이 실패하면 오류와 시도한 내용을 보여 줘. 숨기지 마.
```

## 에이전트가 해야 할 일

잘 끝난 실행은 다음 결과로 마무리되며 각 항목을 직접 확인할 수 있습니다.

- `actions/`, `app/`, `AGENTS.md` 파일이 들어 있는 새 앱 폴더. 이름을 바꾸지 않았다면 `my-app`입니다.
- 오류 없이 실행 중인 `pnpm dev`.
- 에이전트가 응답하는지 확인한 로컬 URL. 보통 `http://localhost:8080`입니다.

그런 다음 본인의 브라우저에서 로컬 URL을 여세요. Welcome 화면에서 **Continue as local dev**를 선택하세요. 시작하기 페이지가 나타납니다.

이 중 빠진 것이 있다면 에이전트에게 마지막으로 실행한 명령과 그 출력을 보여 달라고 요청하세요.

<Callout tone="info">

이 명령이 피어 종속성 오류로 실패한다면 npx 캐시에 있는 오래된 패키지가 원인일 수 있습니다. 에이전트에게 `npx clear-npx-cache`를 실행한 다음 다시 시도하도록 요청하세요.

</Callout>

## 에이전트에 맞는 방식 고르기

| 에이전트 유형          | 예시                                                 | 작동 방식                                                   |
| ---------------------- | ---------------------------------------------------- | ----------------------------------------------------------- |
| 터미널 및 IDE 에이전트 | Claude Code, Codex, Cursor, VS Code의 GitHub Copilot | 프롬프트를 붙여넣으세요. 에이전트가 모든 명령을 실행합니다. |
| 대화 전용 에이전트     | ChatGPT, 웹의 Claude                                 | 명령을 알려 달라고 요청한 다음 직접 실행하세요.             |

### 명령을 실행할 수 없는 에이전트 {#chat-only-agents}

대화 전용 에이전트는 터미널을 열 수 없으므로 앱을 만들 수 없습니다. 그래도 프롬프트를 붙여넣고 맨 위에 다음 줄을 추가하세요.

```markdown
너는 명령을 실행할 수 없어. 내 터미널에서 실행할 명령을 한 번에
하나씩 알려 주고, 다음으로 넘어가기 전에 내가 결과를 알려 줄
때까지 기다려 줘.
```

에이전트가 같은 단계를 안내하고 문제가 생기면 도와줍니다.

## 내 에이전트와 앱의 에이전트

앱에서는 두 에이전트가 일할 수 있으며 각자 맡은 역할이 다릅니다.

- **내 에이전트**는 프롬프트를 붙여넣은 Claude Code, Codex, Cursor 같은 에이전트입니다. 앱 밖의 터미널이나 편집기에서 작동합니다.
- **앱의 에이전트**는 앱에 기본으로 들어 있는 채팅입니다. 앱이 실행되는 동안 브라우저에서 엽니다.

|                    | 내 에이전트 (앱 밖)                                                                                    | 앱의 에이전트 (앱 안)                                                      |
| ------------------ | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| 사용하는 곳        | 터미널 또는 편집기                                                                                     | 브라우저의 앱 채팅                                                         |
| 작업 대상          | 프로젝트 파일                                                                                          | 앱의 데이터와 지금 보고 있는 화면                                          |
| 할 수 있는 일      | 프로젝트 생성, 패키지 설치, `pnpm dev` 실행, 액션, 페이지, 데이터베이스 테이블 작성 및 변경, 배포 준비 | 앱의 액션을 도구로 호출, 앱 데이터 읽기 및 업데이트, 화면 내용에 관한 답변 |
| 앱에 LLM 연결 필요 | 아니요. 자체 모델을 사용합니다                                                                         | 예. [LLM 연결](/docs/getting-started#connect-an-llm)을 참고하세요          |
| 가장 적합한 용도   | 앱을 만들고 바꾸기                                                                                     | 앱을 사용하고 일상 업무 처리하기                                           |

내 에이전트는 앱을 만들고 앱의 에이전트는 앱을 운영합니다. 내 에이전트가 액션을 추가하면 둘 다 같은 액션을 사용하므로 앱의 에이전트가 바로 그 액션을 호출할 수 있습니다.

### 내 에이전트가 잘 만들도록 돕기

생성된 앱은 별도의 지침 없이도 내 에이전트가 잘 작업할 수 있도록 설정되어 있습니다.

- 앱 루트의 `AGENTS.md`는 에이전트에게 앱 구조와 따라야 할 규칙을 알려 줍니다.
- `.agents/skills/`에는 기능 추가나 액션 작성처럼 자주 하는 작업에 대한 짧은 가이드가 들어 있습니다.
- 사용 중인 프레임워크 버전에 맞는 문서가 앱에 함께 들어 있습니다. 에이전트는 `pnpm action docs-search --query "<topic>"`로 검색할 수 있습니다.

새로운 작업을 요청할 때 에이전트에게 이 자료를 먼저 읽으라고 말할 수 있습니다. 예를 들어 "무엇이든 변경하기 전에 AGENTS.md와 해당 스킬을 읽어 줘."라고 요청하세요.

내 에이전트가 코드 대신 실행 중인 앱의 도구를 사용하게 하려면 [외부 에이전트](/docs/external-agents)를 참고하세요.

## 첫 번째 변경 요청하기

앱이 실행 중이면 에이전트에게 작은 변경을 요청하고 작업하는 모습을 지켜보세요. 몇 가지 예시입니다.

```markdown
list-notes라는 액션을 추가해서 빈 목록을 반환하게 하고, 새 /notes
페이지에 표시해 줘.
```

```markdown
hello 액션이 "Hello" 대신 "Welcome"으로 인사하도록 바꾸고, Alex를
대상으로 호출해서 확인해 줘.
```

```markdown
앱 배포에 관한 문서를 읽고, 이 앱을 온라인에 올리려면 내가 어떤
단계를 밟아야 하는지 알려 줘.
```

에이전트는 UI와 앱 자체의 에이전트가 사용하는 것과 같은 액션을 변경합니다. 이렇게 액션 모델을 공유하기 때문에 한 번의 변경이 모든 곳에 반영됩니다. [핵심 개념](/docs/key-concepts)에서 전체 구조를 설명합니다.
