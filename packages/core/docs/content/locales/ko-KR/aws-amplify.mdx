# AWS Amplify

<Badge label="Beta" color="orange" icon="rocket" />

AWS Amplify Hosting이 Git 저장소에서 앱을 빌드하고 호스팅하므로 서버를 설정하거나 계속 실행해 둘 필요가 없습니다. Amplify는 앱의 정적 파일을 CloudFront를 통해 제공하고, 앱의 페이지와 API를 위해 앱의 서버를 실행하며, 앱에 HTTPS가 적용된 공개 주소를 제공합니다.

이 가이드는 독립 실행형 앱 하나를 처음부터 배포하는 과정을 안내합니다. 앱을 만들어 Git 저장소에 푸시하고, 프로덕션 데이터베이스와 인증 시크릿을 지정하고, 데이터베이스를 준비하고, Amplify의 빌드 설정을 추가한 다음, Amplify 앱을 만듭니다.

<Callout tone="info">

Node.js `22.22+`가 필요합니다.

</Callout>

AWS 계정과 GitHub, GitLab, Bitbucket, AWS CodeCommit 중 한 곳의 저장소도 필요합니다. 이 가이드의 명령은 자신의 컴퓨터에서 실행하세요. 앱의 빌드와 실행은 Amplify가 저장소에서 진행합니다.

## 1단계: 앱 만들기 {#step-1-create-the-app}

새 독립 실행형 앱을 만듭니다. 아래 예시는 Chat 템플릿으로 앱을 만들지만, 어떤 템플릿으로든 시작할 수 있습니다. 앱 폴더로 이동한 뒤 의존성을 설치하세요. `corepack enable`은 앱이 기대하는 `pnpm` 버전을 활성화하므로 `pnpm`을 직접 설치할 필요가 없습니다.

```bash
npx --yes @agent-native/core@latest create my-app --standalone --template chat

cd my-app

corepack enable

pnpm install
```

원한다면 `my-app`을 원하는 앱 이름으로 바꾸세요. 이 가이드의 나머지 부분은 앱 폴더 안에 있다고 가정합니다.

Amplify는 Git 저장소에서 앱을 빌드하므로, 계속하기 전에 앱 폴더를 새 저장소에 푸시하세요. 4단계에서 파일을 하나 더 추가하고 다시 푸시합니다.

## 2단계: 환경 시크릿 구성하기 {#step-2-configure-environment-secrets}

앱은 프로덕션 설정을 환경 변수에서 읽습니다.

| 변수                 | 필수   | 용도                                          |
| -------------------- | ------ | --------------------------------------------- |
| `DATABASE_URL`       | 예     | 앱을 PostgreSQL 데이터베이스에 연결합니다     |
| `BETTER_AUTH_SECRET` | 예     | 사용자 세션에 서명합니다                      |
| `BETTER_AUTH_URL`    | 아니요 | 사용자가 앱에 접속하는 공개 주소를 설정합니다 |

아래의 export 명령을 실행하면 이 셸에서 이후 명령이 동작합니다. 배포하기 전에 같은 변수를 호스트의 프로젝트 또는 서비스 환경 설정에도 저장하세요. Amplify에 저장하는 방법은 5단계에서 설명합니다.

<Callout tone="warning">

Amplify는 환경 변수를 빌드에는 전달하지만 실행 중인 서버에는 전달하지 않습니다. 변수를 사용할 수 있도록 Agent-Native 빌드는 앱이 선언한 변수를 서버 번들 안의 `.env` 파일에 기록합니다. 앱의 배포 아티팩트에 접근할 수 있는 사람은 누구나 이 파일을 읽을 수 있으므로, AWS 계정에서 아티팩트에 접근할 수 있는 사람을 제한하세요.

</Callout>

### 데이터베이스 URL {#database-url}

로컬 개발 중에는 `DATABASE_URL`이 설정되지 않으면 앱이 로컬 데이터베이스에 데이터를 저장합니다. 배포된 앱에는 배포 후에도 데이터를 유지하는 실제 PostgreSQL 데이터베이스가 필요합니다. Amplify는 요청 사이에 파일을 유지하지 않으므로 데이터베이스는 Amplify 밖에 있어야 합니다. 프로바이더에서 연결 문자열을 복사해 export하세요.

```bash
export DATABASE_URL='your-postgres-url-string'
```

[데이터베이스 프로바이더 가이드](/docs/neon)에서 [Amazon RDS for PostgreSQL](/docs/aws-rds)을 포함해 프로바이더별로 연결 문자열을 찾는 위치를 확인할 수 있습니다.

<Callout tone="warning">

Neon, Supabase, Amazon RDS 등 영구적인 PostgreSQL 프로바이더를 선택하세요.

</Callout>

### 인증 시크릿 {#auth-secret}

이 값은 한 번만 생성하고 배포할 때마다 바꾸지 마세요.

앱은 `BETTER_AUTH_SECRET`을 사용해 사용자 세션에 서명합니다. 이 값이 바뀌면 로그인한 모든 사용자가 로그아웃됩니다. 아래 명령은 임의의 값을 생성합니다.

```bash
export BETTER_AUTH_SECRET="$(openssl rand -hex 32)"
```

생성한 값은 비밀번호 관리자처럼 안전한 곳에 저장하세요. 배포할 때마다 같은 값을 사용합니다.

### 공개 URL {#public-url}

선택 사항입니다. 사용자 지정 도메인, 리버스 프록시, 또는 고정된 공개 origin이 필요한 인증이나 OAuth 흐름을 사용할 때 설정하세요.

`BETTER_AUTH_URL`은 사용자가 앱에 접속하는 공개 주소입니다. 이 값이 없으면 앱은 들어오는 요청마다 자신의 주소를 판단합니다. Amplify가 제공하는 주소에서는 대개 문제가 없지만, 사용자 지정 도메인을 연결할 때는 로그인 링크와 OAuth 리디렉션이 그 도메인을 사용하도록 이 값을 설정하세요.

```bash
export BETTER_AUTH_URL='https://your-domain.example'
```

## 3단계: 마이그레이션 {#step-3-migrate}

마이그레이션은 앱에 필요한 테이블을 데이터베이스에 만들고 업데이트합니다. 첫 배포 전에 이 명령을 실행하세요.

```bash
pnpm migrate:production
```

이 명령은 자신의 컴퓨터에서 실행되며, 2단계에서 export한 `DATABASE_URL`로 프로덕션 데이터베이스에 연결합니다. 앱을 업그레이드한 뒤에는 새 버전을 배포하기 전에 다시 실행하세요.

## 4단계: Amplify의 빌드 설정 추가하기 {#step-4-add-amplifys-build-settings}

앱의 루트 폴더에서 `package.json` 옆에 `amplify.yml`이라는 파일을 만들고 다음 내용을 복사해 넣으세요.

```yaml filename="amplify.yml"
version: 1
frontend:
  phases:
    preBuild:
      commands:
        - nvm install 24
        - corepack enable
        - pnpm install
    build:
      commands:
        - NITRO_PRESET=aws_amplify pnpm build
  artifacts:
    baseDirectory: .amplify-hosting
    files:
      - "**/*"
```

이 파일은 앱을 빌드하는 방법을 Amplify에 알려 줍니다.

- **preBuild** 단계는 빌드를 Node.js 24로 전환하고, 앱의 `pnpm` 버전을 활성화한 뒤 의존성을 설치합니다.
- **build** 단계는 Amplify Hosting이 기대하는 형식인 `NITRO_PRESET=aws_amplify`로 앱을 빌드합니다.
- **artifacts** 항목은 빌드가 만드는 `.amplify-hosting` 폴더를 배포하도록 Amplify에 지시합니다.

빌드는 Amplify에 필요한 모든 것을 그 폴더에 기록합니다.

`amplify.yml`을 커밋하고 저장소에 푸시하세요.

## 5단계: Amplify 앱 만들기 {#step-5-create-the-amplify-app}

[Amplify 콘솔](https://console.aws.amazon.com/amplify/)에서 앱을 만듭니다.

<Steps>

### 저장소 연결하기

**Deploy an app** 옵션을 선택합니다. **Start building with Amplify** 페이지에서 Git 프로바이더를 선택한 다음 **Next** 버튼을 선택하세요. 처음에는 Amplify가 저장소를 읽을 권한을 요청합니다.

### 브랜치 선택하기

**Add repository branch** 페이지에서 1단계의 저장소와 브랜치를 선택한 다음 **Next** 버튼을 선택하세요.

### 빌드 설정 확인하기

**App settings** 페이지에서 Amplify가 `amplify.yml`에서 빌드 설정을 읽습니다. **Build output directory** 값이 `.amplify-hosting`인지 확인하세요. **Create and use a new service role** 옵션을 선택합니다.

### 환경 변수 추가하기

**Advanced settings** 아래에서 2단계에서 export한 값으로 `DATABASE_URL`과 `BETTER_AUTH_SECRET`을 추가합니다. `BETTER_AUTH_URL`을 설정했다면 같은 방법으로 추가하세요. 그런 다음 **Next** 버튼을 선택합니다.

### 배포하기

**Review** 페이지에서 **Save and deploy** 버튼을 선택합니다.

</Steps>

## 6단계: 앱 열기 {#step-6-open-the-app}

첫 빌드는 몇 분 정도 걸리며, Amplify 콘솔에서 진행 상황을 확인할 수 있습니다. 빌드가 끝나면 `https://main.d1m7bkiki6tdw1.amplifyapp.com`과 같은 형태의 앱 주소를 열고 첫 계정을 만듭니다.

그런 다음 다음 사항을 확인하세요.

- 홈 페이지가 로드됩니다.
- `/assets/` 아래의 파일이 로드됩니다. 이는 정적 파일이 제공되고 있다는 뜻입니다.
- 로그인할 수 있고, 만든 데이터가 새로고침한 뒤에도 남아 있습니다.

## 업데이트 배포하기 {#deploy-updates}

Amplify는 5단계에서 선택한 브랜치에 푸시할 때마다 다시 빌드하고 배포합니다. 새 버전을 배포하려면 먼저 마이그레이션을 실행한 다음 푸시하세요.

```bash
pnpm migrate:production

git push
```

빌드가 환경 변수를 서버 번들에 복사하므로, 변수를 바꾸면 다음 빌드 이후에야 적용됩니다. Amplify 콘솔에서 변수를 바꾼 뒤에는 커밋을 푸시하거나 최신 빌드를 다시 배포하세요.

## 캐싱 {#caching}

Amplify는 CloudFront를 통해 앱을 제공합니다. 앱의 공개 페이지 셸은 다음 `Cache-Control` 헤더를 보내며, Amplify는 이를 따릅니다.

```txt
public, max-age=600, stale-while-revalidate=604800, stale-if-error=3600
```

CloudFront는 셸을 10분 동안 최신 상태로 유지하고, 새 사본을 가져오는 동안 이전 사본을 제공할 수 있으며, 오류가 발생했을 때도 이를 제공할 수 있습니다. 개인 데이터는 페이지가 열린 뒤 브라우저에서 로드되므로 공유 셸에 포함되지 않습니다. 정적 파일은 최대 1년 동안 캐시되며, 새로 배포할 때마다 Amplify의 캐시가 지워집니다.

Amplify의 기본 설정인 **Remove cookies from cache key** 옵션은 켜 둔 상태로 유지하세요. `customHttp.yml`에 전역 `Cache-Control` 규칙을 추가하지 마세요. 비공개 경로의 `no-store` 헤더를 덮어쓸 수 있기 때문입니다. 셸 캐시를 줄이거나 끄려면 `AGENT_NATIVE_SSR_CACHE`를 설정하세요. 전체 정책은 [SSR 캐싱](/docs/ssr-caching)에서 설명합니다.

## 에이전트 응답 스트리밍하기 {#stream-agent-responses}

Amplify의 CloudFront 경로는 응답의 작은 청크를 붙잡아 둘 수 있으므로, 에이전트 채팅 답장이 단어 단위로 오지 않고 한꺼번에 몰려서 도착할 수 있습니다. 답장을 직접 스트리밍하기 위해 Agent-Native는 채팅 스트림만 제공하는 별도의 Lambda 함수를 추가할 수 있습니다.

```bash
npx agent-native amplify-stream \
  --amplify-app-id your-amplify-app-id \
  --branch main \
  --region us-east-1 \
  --env-file .env
```

이 명령은 스트리밍 함수 URL과 15분 타임아웃을 갖춘 Node.js 24 Lambda 함수로 채팅 스트림을 빌드합니다. 함수의 주소를 Amplify 브랜치에 저장하고 새 릴리스를 시작합니다. 브라우저는 그 밖의 모든 작업에는 계속 Amplify 앱을 사용하고, 채팅 요청만 함수로 보냅니다.

이 명령은 `--env-file`로 전달한 파일에서 앱의 변수를 읽으므로, 그 파일에는 Amplify 앱과 같은 `DATABASE_URL`, `BETTER_AUTH_SECRET` 및 기타 값이 있어야 합니다. 또한 Lambda, IAM, Amplify를 관리할 수 있는 AWS CLI 자격 증명도 필요합니다. 릴리스를 시작하지 않고 주소만 저장하려면 `--skip-release`를 추가하세요. 스트림 함수를 사용할 수 없으면 채팅은 일반 Amplify 경로로 대체됩니다.
