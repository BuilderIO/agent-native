# 시각적 계획

Agent-Native Plans는 코딩 에이전트를 위한 시각적 계획 모드입니다. 평범한
Codex, Claude Code, Markdown, 또는 붙여넣은 구현 계획을 리치 텍스트, 다이어그램,
와이어프레임, 주석이 달린 코드 워크스루와 파일 트리, 댓글, 공유 가능한 링크를
갖춘 구조화된 검토 화면으로 바꿔줍니다.

핵심은 두 개의 명령으로 요약됩니다. `/visual-plan`은 에이전트가 코드를 작성하기
**전에** 계획을 만듭니다. `/visual-recap`은 **이미 일어난** 변경 — PR, 커밋,
브랜치, 또는 git diff — 을 고도에서 바라본 시각적 코드 리뷰로 바꿔줍니다.
두 명령 모두 동일한 검토 화면을 열기 때문에, 어느 쪽을 쓰든 같은 방식으로
주석을 달고 댓글을 남기고 에이전트에게 피드백을 전달할 수 있습니다.

## 대체하는 것

<Comparison>

### 이전에는

- 계획이 채팅이나 Markdown 파일 속 산문 더미로 존재하며, 검토하려면
  동의하지 않는 한 단락을 찾기 위해 처음부터 끝까지 읽어야 합니다.
- 피드백은 Slack 스레드나 여기저기 흩어진 댓글에서 이루어지며, 계획
  자체와는 분리되어 있습니다.
- 완성된 PR을 검토하려면 원본 diff를 한 줄씩 읽으며 무엇이 왜 바뀌었는지
  재구성해야 합니다.

### 이후에는

- 계획이 다이어그램, 와이어프레임, 주석이 달린 코드, 그리고 직접 반응할
  수 있는 Open Questions 폼으로 렌더링됩니다.
- 댓글은 정확한 텍스트, 이미지, 와이어프레임 위치에 고정되며, 에이전트나
  사람 리뷰어 중 누구를 대상으로 할지 선택할 수 있습니다.
- `/visual-recap`은 PR, 커밋, diff를 원본 diff 대신 동일한 시각적 검토로
  바꿔줍니다.

</Comparison>

결과를 소스 컨트롤 친화적인 사본으로 HTML, Markdown, JSON으로 내보내거나,
로컬 파일 모드로 호스팅된 데이터베이스에서 완전히 분리해 둘 수 있습니다.
각각에 대해 자세히 알아보려면
[계획 검토 및 댓글 작성](/docs/template-plan-review-workflow)과
[로컬 파일 모드와 데스크톱 동기화](/docs/template-plan-local-and-desktop)를
참조하세요.

## 시작하기 {#get-started}

<Steps>

### 스킬 설치하기 {#install}

대부분의 사람들은 Plan을 스캐폴딩된 앱이 아니라 기존 코딩 에이전트를 위한
**스킬**로 설치합니다. 이 명령 하나로 스킬 안내문을 설치하고, 호스팅된
Plans MCP 커넥터를 등록하고, 로그인까지 처리합니다.

```bash
npx @agent-native/core@latest skills add visual-plan
```

이 명령은 `/visual-plan`, `/visual-recap`, `/visualize-repo` 세 개의 슬래시
명령과, `https://plan.agent-native.com/mcp`에 위치한 `plan` MCP 커넥터
(에이전트가 대화하는 원격 도구 서버)를 설치합니다. 전체 플래그 참조,
Claude Code와 Codex를 위한 플러그인/마켓플레이스 설치 경로, VS Code 확장
프로그램은
[Plan 플러그인 및 마켓플레이스 → 설치 경로](/docs/plan-plugin#install)를
참조하세요.

Plan 템플릿 자체를 커스터마이징하는 것 — 직접 호스팅하거나 그 위에 직접
빌드하는 것 — 은 [Plan 확장하기](/docs/template-plan-developers)에서 다루는
별개의, 부차적인 경로입니다. 대부분의 사용자는 이 경로가 필요하지 않습니다.

### 작업에 맞는 명령을 에이전트에게 요청하세요

- "인증 흐름을 변경하기 전에 `/visual-plan`을 써줘."
- "모바일과 데스크톱 상태를 포함한 새 온보딩 화면을 위한 `/visual-plan`을
  만들어줘."
- "이 PR에 `/visual-recap`을 실행해서 변경 사항의 형태를 먼저 검토하게
  해줘."
- "`main`과 이 브랜치 사이의 diff에 `/visual-recap`을 써줘."
- "`/visualize-repo`를 실행하고 우리 공개 API 액션과 스키마부터
  시작해줘."

`/visual-plan`은 작업 내용에 따라 다이어그램, 와이어프레임, 목업, 클릭
가능한 프로토타입, 주석이 달린 코드를 끌어옵니다. 에이전트가 먼저
코드베이스를 살펴본 다음, 반환된 링크가 브라우저나 VS Code에서 검토 UI를
엽니다.

### 게스트로 검토하기, 계정 필요 없음

계획을 공유받은 사람은 아무것도 설치할 필요가 없습니다. Plans 에디터를
열고 **가입 없이 만들고 편집**합니다 — 게스트로 작업하는 것입니다. 로그인은
자신의 작업을 **저장하거나 공유**할 때만 필요하며, 게스트가 나중에
로그인하면 게스트로 만든 모든 계획이 그 계정으로 **귀속**됩니다.

</Steps>

Codex, Claude Code, Markdown, 또는 붙여넣은 계획이 이미 존재한다면
`/visual-plan`을 사용하세요. 에이전트는 처음부터 새로 시작하는 대신 그 원본
계획을 보존하고 그로부터 더 풍부한 검토 화면을 만들어냅니다. 첫 번째 결과에
아직 미결정 사항이 있다면, 에이전트는 계획 맨 아래에 **Open Questions** 폼을
추가할 수 있으며, 그것을 채워서 돌려보내면 수정 턴이 시작됩니다.

<Callout tone="info">

**한눈에 보는 게스트 대 로그인**

- **게스트로는** 공유 링크를 열고, 새 계획을 만들고, 본문을 편집하고,
  검토 주석 모드를 사용할 수 있습니다 — 계정이 필요 없습니다.
- **로그인하면** 추가로 자신의 계획을 영구히 저장하고, 계획을 공유 가능한
  링크로 게시하고, 다른 사람에게 뷰어/편집자/관리자 권한을 부여하고, 이메일로
  사람들에게 알리는 댓글을 남기고, 소유한 계획을 삭제하거나 복원할 수
  있습니다.

</Callout>

## 비용과 모델 선택

계획이나 요약을 생성하는 것은 가벼운 템플릿 채우기가 아니라 코딩 에이전트의
LLM을 대상으로 하는 완전한 에이전트 세션을 실행하는 일입니다 — 비용은 diff나
계획의 크기, 그리고 선택한 모델에 따라 달라집니다.

- 앱의 기본 채팅 모델은 GPT-5.6 Luna입니다. Anthropic에 직접 연결한 경우에는
  Claude Sonnet 5가 기본값으로 유지됩니다. **설정**에서 언제든 모델을 바꿀 수
  있으며, Haiku가 더 저렴한 Claude 옵션입니다.
- GitHub Action에서 실행되는 자동 PR 요약은 대화형 앱과 별개로 실행되며 자체
  모델과 비용 설정 노브를 가집니다 — `VISUAL_RECAP_MODEL`,
  `VISUAL_RECAP_AGENT`, `VISUAL_RECAP_REASONING`은
  [PR 시각적 요약](/docs/pr-visual-recap)을 참조하세요.

## 비공개 계획에 접근 요청하기 {#request-access}

누군가 볼 권한이 없는 계획 링크를 열면, Plans는 그냥 막다른 화면을 보여주지
않습니다. 해당 페이지는 계획이 비공개임을 알려주고 **접근 요청** 작업을
제공하며, 이 작업은 다음과 같이 동작합니다.

- 로그인이 필요합니다(게스트에게는 먼저 로그인하라는 안내가 표시됩니다).
- 요청 내역을 계획에 기록하고, 배포 환경에 이메일이 구성되어 있다면 요청자의
  이름과 계획을 열어 승인 시 다시 공유할 수 있는 링크를 담아 계획 소유자에게
  메시지를 보냅니다.
- 두 번 이상 클릭해도 안전합니다 — Plans는 먼저 이미 접근 권한이 있는지
  확인하므로, 같은 사람이 다시 요청하더라도 소유자에게 중복 이메일이 쏟아지지
  않습니다.

계획의 공개 범위가 완전 비공개가 아니라 **조직**으로 설정되어 있고, 사용자의
계정이 이미 해당 조직에 대한 대기 중인 초대를 가지고 있거나 그 조직과 일치하는
이메일 도메인을 가지고 있다면, Plans는 요청을 보내는 대신 그 조직에 바로
가입하도록 제안합니다.

<Callout tone="warning">

Plans 도구가 `needs auth`, `Unauthorized`, `Session terminated`를
반환한다면 계속 재시도하지 마세요. `npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex`로
다시 인증하거나, OAuth를 지원하는 호스트라면 `/mcp` → **Authenticate**를 다시
실행하세요. 이후에는 새 Codex 스레드를 시작하거나 클라이언트를
재시작/새로고침하세요 — 도구 레지스트리는 새 세션에서만 변경 사항을
반영합니다.

</Callout>
