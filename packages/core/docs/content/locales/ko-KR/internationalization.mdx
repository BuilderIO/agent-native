# 국제화

Agent Native 앱은 공유 `@agent-native/core/client/i18n` 런타임을 통해 프레임워크와 템플릿 UI를 현지화할 수 있습니다. 프레임워크는 사용자의 언어 선택을 SQL 설정에 저장하고 이를 actions로 노출하며, 앱이 아직 문자열을 번역하지 않은 경우 영어로 대체합니다.

## 런타임

`AppProviders`를 통해 provider를 사용합니다.

```tsx
import { AppProviders } from "@agent-native/core/client/hooks";
import { getLocaleInitScript } from "@agent-native/core/client/i18n";
import { i18nCatalog } from "./i18n";

const LOCALE_INIT_SCRIPT = getLocaleInitScript();

<script
  data-agent-native-locale-init
  dangerouslySetInnerHTML={{ __html: LOCALE_INIT_SCRIPT }}
/>;

<AppProviders queryClient={queryClient} i18n={{ catalog: i18nCatalog }}>
  <Outlet />
</AppProviders>;
```

`getLocaleInitScript()`는 React가 수화되기 전에 초기 `lang`, `dir`, `window.__AGENT_NATIVE_LOCALE__`을 설정합니다. 공개 SSR 경로는 `@agent-native/core/server`의 `resolveLocaleFromRequest()`를 호출하여 해석된 로케일/카탈로그를 그 스크립트에 전달함으로써 수화 불일치를 방지할 수 있습니다.

## 카탈로그

각 현지화된 템플릿은 `app/i18n/` 아래에 카탈로그를 보관합니다.

```ts filename="app/i18n/index.ts"
import { createAgentNativeI18nCatalog } from "@agent-native/core/client/i18n";
import enUS from "./en-US";

export const i18nCatalog = createAgentNativeI18nCatalog({
  messages: enUS,
  localeLoaders: {
    "zh-CN": () => import("./zh-CN"),
    "zh-TW": () => import("./zh-TW"),
    "es-ES": () => import("./es-ES"),
    "fr-FR": () => import("./fr-FR"),
    "de-DE": () => import("./de-DE"),
    "ja-JP": () => import("./ja-JP"),
    "ko-KR": () => import("./ko-KR"),
    "pt-BR": () => import("./pt-BR"),
    "hi-IN": () => import("./hi-IN"),
    "ar-SA": () => import("./ar-SA"),
  },
});
```

`messages`는 `en-US`를 직접 번들로 포함하므로 다른 로케일이 로드되기 전에도 항상 사용할 수 있습니다. `localeLoaders`는 그 외 모든 카탈로그를 동적 임포트하므로 사용자는 활성 로케일만 다운로드합니다. 지원되는 로케일 코드는 `en-US`, `zh-CN`, `zh-TW`, `es-ES`, `fr-FR`, `de-DE`, `ja-JP`, `ko-KR`, `pt-BR`, `hi-IN`, `ar-SA`입니다.

이 목록은 프레임워크에 의해 고정되어 있습니다. 이는 단순히 이 예제가 번들로 포함하는 로케일에 그치지 않습니다. `LocaleCode`는 정확히 이 코드들로 이루어진 TypeScript union이며, `set-localization-preference`는 런타임에 그 외의 값을 거부합니다. 각 로케일에는 오른쪽에서 왼쪽으로 쓰는 언어의 텍스트 방향처럼 프레임워크가 정리한 메타데이터도 필요합니다. 새 로케일을 추가한다는 것은 앱에 카탈로그 파일을 추가하는 일이 아니라 프레임워크 자체를 확장하는 일을 의미합니다.

`createAgentNativeI18nCatalog`는 기본값이 `en-US`인 선택적 `sourceLocale`과 선택적 `supportedLocales` 배열도 받습니다. 앱이 열 개 로케일 전부가 아니라 프레임워크가 지원하는 로케일 중 일부에 대해서만 번역을 제공한다면 `supportedLocales`를 설정하세요. 기본값은 프레임워크가 지원하는 모든 로케일입니다. `LanguagePicker`는 이 집합에 속한 로케일만 나열하며, 감지되거나 요청된 로케일이 이 집합 밖에 있으면 `sourceLocale`로 대체됩니다.

## UI

인터페이스 문자열을 번역하려면 `useT()`를 사용합니다.

```tsx
import { useT } from "@agent-native/core/client/i18n";

function Greeting({ name }: { name: string }) {
  const t = useT();
  return <p>{t("greeting.hello", { name })}</p>;
}
```

날짜, 숫자, 상대 시간, 목록에는 `useFormatters()`를 사용하세요. 로케일에 민감한 날짜/숫자 형식은 번역 문자열 안에 넣지 마세요.

앱에서 사용자가 언어를 바꿀 수 있는 위치라면 어디든 `<LanguagePicker />`를 배치하세요. 표준 설정 페이지 패턴과 `openAgentSettings()`가 그 안에서 어디에 들어맞는지는 [Toolkit: Settings](/docs/toolkit-settings)를 참조하세요.

## Actions와 지속성

모든 앱은 다음을 상속합니다.

- `get-localization-preference` — 현재 사용자의 `{ locale, timezone }` 읽기
- `set-localization-preference` — `locale` 및/또는 `timezone` 설정, 둘 다 선택적

`locale`은 `"system"` 또는 지원되는 BCP-47 로케일입니다. `timezone`은 `"system"` 또는 `America/New_York`과 같은 IANA 표준시간대입니다. 이는 예약된 작업과 자동화가 호스트가 아니라 사용자의 표준시간대에서 실행되도록 하기 위해 존재합니다. `set-localization-preference`는 기존에 저장된 값을 덮어쓰는 대신 그 위에 병합되므로, 필드를 하나만 설정하면 나머지 필드는 그대로 유지됩니다.

지속성 값은 `localization` 아래의 사용자 범위 SQL 설정에 있습니다. `localStorage`는 사전 수화 및 익명 대체용으로만 사용됩니다. 활성 로케일은 에이전트가 현재 인터페이스 언어를 볼 수 있도록 주변 컨텍스트로서 애플리케이션 상태에 미러링됩니다.

## 가드

실행:

```bash
pnpm guard:i18n-catalogs
```

앱과 템플릿 카탈로그에 대해 가드는 다음을 확인합니다.

- 로케일 파일 이름, 키 패리티, 자리 표시자 패리티, 오래된 키
- 중복 키 및 개발 전용으로 남아 있는 마커
- 잘못된 스크립트 오염, 예를 들어 아랍어 카탈로그 안에 들어 있는 중국어 텍스트
- `Intl.PluralRules`를 통한 CLDR 복수 카테고리
- 앱 소스의 `t()` 호출 중 키가 영어 카탈로그에 없는 경우

가드는 번역 품질이 아니라 구조를 확인합니다. 가시성이 높은 문자열은 여전히 사람의 검토가 필요합니다.

작업 이름, 경로, 열거형 값, 앱 상태 키, 데이터베이스 값, 프로토콜 필드, 환경 변수 이름, 공급자 이름 같은 안정적인 식별자는 번역하지 마세요.
