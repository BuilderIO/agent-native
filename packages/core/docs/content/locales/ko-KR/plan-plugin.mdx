# Plan 플러그인 및 마켓플레이스

Agent-Native **Plan** 앱은 설치 가능한 하나의 번들로 제공됩니다. 한 번의 설치로
Plan 슬래시 명령 스킬**과** 호스팅된 Plan MCP 커넥터(에이전트가 대화하는 원격
도구 서버)가 함께 연결되므로, 에이전트는 계획을 생성해서 한 단계로 곧장 Plan
앱에 게시할 수 있습니다. 이 페이지는 설치 경로를 고르거나, 설치 문제를
해결하거나, Plan을 큐레이션된 플러그인 카탈로그에 제출할지 결정하려는
사람을 위한 것입니다 — 스킬이 실제로 무엇을 하는지는
[시각적 계획](/docs/template-plan)을 참조하세요.

## 무엇을 얻게 되나요 {#what-you-get}

한 번의 설치로 다음을 얻습니다.

- **세 개의 스킬** — `/visual-plan`(정식 진입점), `/visual-recap`, `/visualize-repo`.
- **Plan MCP 커넥터** — `https://plan.agent-native.com`에서 호스팅되는 앱에
  등록됩니다(MCP 엔드포인트 `https://plan.agent-native.com/mcp`, 서버 이름
  `plan`).

기본적으로 `/visual-plan`과 `/visual-recap`은 호스팅된 Plan 앱에 게시합니다 —
MCP 커넥터를 통해 계획을 만들고 검토할 링크나 인라인 계획을 건네줍니다.
전달물로 인라인 Markdown/ASCII 계획을 채팅에 그대로 쏟아내는 일은 절대
없습니다. Plan 도구가 `needs auth`, `Unauthorized`, `Session terminated`를
반환하면, 인라인 출력으로 되돌아가는 대신 커넥터를 다시 인증하세요. 액세스
토큰은 수명이 깁니다(기본 30일, 슬라이딩 365일 갱신)이므로 이런 일은 드물게
일어날 것이며, 발생했을 때 가벼운 해결 방법은 다음과 같습니다.

```bash
npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex
```

`reconnect`는 선택한 로컬 클라이언트에 대해 URL로 커넥터를 찾아 새로 고칩니다 —
재설치가 필요 없습니다. 다시 연결한 후에는 새 Codex 스레드를 시작해서 도구
레지스트리가 다시 로드되도록 하세요. Claude Code에서는 `/mcp` →
**Authenticate / Reconnect**가 동일한 역할을 하며, 원하는 `--client claude-code`와
같은 명령으로도 가능합니다.

예외는 명시적인 **로컬 파일 프라이버시 모드**입니다. DB 쓰기를 하지 않도록
요청하거나 `AGENT_NATIVE_PLANS_MODE=local-files`를 설정하면, 스킬은 Plan MCP
커넥터를 호출해서는 안 됩니다. 대신 `plans/<slug>/plan.mdx`와 선택적인
`canvas.mdx`, `prototype.mdx`, `.plan-state.json`을 작성한 다음, 다음 명령으로
로컬에서 미리 봅니다.

```bash
npx @agent-native/core@latest plan local serve --dir plans/<slug> --kind plan --open
```

이 명령은 작은 localhost 브리지를 시작하고 로컬 폴더를 대상으로 Plan UI를
엽니다. (`plan local preview`는 대신 로컬 Plan 개발 서버 라우트를 실행하며,
`plan local preview --out preview.html`은 독립형 정적 HTML 파일을 작성하는
레거시 대체 수단입니다. `plan serve`는 `plan local serve`의 짧은 별칭으로
허용됩니다.)

로컬 파일 모드를 사용할 때 알아둘 만한 몇 가지 주의점이 있습니다.

- **Chromium 계열 브라우저를 사용하세요.** Safari는 호스팅된 HTTPS Plan
  페이지가 `http://127.0.0.1` localhost 브리지를 읽는 것을 차단합니다
  (혼합 콘텐츠/사설망 문제)이므로, 페이지가 "Loading plan."에서 멈춥니다.
  macOS에서는 `--open`이 이미 Chrome/Chromium/Edge/Brave를 우선적으로
  선택하며, 그래도 Safari가 열린다면 출력된 URL을 Chromium 계열 브라우저에서
  다시 열어보세요.
- **제공되는 URL은 `plans/<slug>/.plan-url`에 기록됩니다**(`--url-file`로
  재정의 가능). 백그라운드나 헤드리스로 실행되는 에이전트는 오래 실행되는
  `serve`의 표준 출력을 긁어내는 대신 이 파일을 읽을 수 있습니다. 이 파일을
  로컬 토큰 파일처럼 취급하고 커밋하지 마세요.
- **브라우저가 없을 때는 헤드리스로 검증하세요.**
  `npx @agent-native/core@latest plan local verify --dir plans/<slug>`는
  브리지를 시작해 사설망 사전 점검과 JSON 페이로드를 확인하고, 진단 결과를
  출력하며, 실패 시 0이 아닌 상태로 종료됩니다 — 사람이 눈으로 확인할
  필요가 없습니다.
- **먼저 `plan local check`를 실행하세요.** 이 명령은 Plan 렌더러의 블록
  스키마(필수 필드인 `checklist` 항목의 `id`/`label`, `question-form` 질문의
  `id`/`title`/`mode` 포함)에 대해 MDX를 검증하므로, 작성 실수가 브라우저로
  넘어가서 멈춰버린 로더로 나타나기 전에 미리 드러납니다.

현재 저장소 안의 폴더라면, 직접 로컬 경로에 `?path=...`가 포함되어 로컬 Plan
앱이 브라우저에서의 편집을 계속 저장소 폴더에 저장할 수 있도록 합니다. Plan
앱은 승격된 로컬 계획을 저장할 기본 위치로 `agent-native.json`의
`apps.plan.roots[0].path`를 사용하며, 없으면 `plans/`로 대체합니다.

이렇게 하면 계획 내용이 Agent-Native Plan 데이터베이스 밖에 머무릅니다.
명시적으로 나중에 게시하기 전까지는 호스팅된 공유, 댓글, 스크린샷, 계획
히스토리를 사용할 수 없습니다.

Agent-Native Desktop에는 호스팅된 계획을 위한 별도의 로컬 파일 동기화 경로가
있습니다. Desktop 앱은 호스팅된 계획을 로컬 MDX 파일로 미러링하고 Plan 앱을
클론하거나 CLI를 실행하지 않고도 편집 내용을 다시 가져올 수 있습니다. 이
워크플로는 호스팅된 Plan 데이터베이스를 정본으로 유지합니다. 목표가 Plan DB에
쓰지 않는 것이라면 로컬 파일 프라이버시 모드를 사용하세요.

> 플러그인(`agent-native-visual-plans`)은 앱 ID `visual-plans`를 가지며,
> 이것이 Claude Code 플러그인 이름과 Codex 플러그인 이름이 둘 다
> `agent-native-visual-plans`인 이유입니다. Plan 앱의 표시 이름은
> "Agent-Native Plan"입니다.

## 설치 경로 {#install}

들어가는 방법은 세 가지입니다. **범용 CLI 경로**는 스킬을 설치**하고**
호스팅, 로컬 파일, 자체 호스팅 모드 중 하나를 한 흐름에서 선택할 수 있게
해주기 때문에 기본적으로 권장하는 경로입니다. 플러그인 경로는 정식 플러그인/
마켓플레이스 시스템을 갖춘 호스트를 위한 것이며 기본적으로 호스팅된 Plans를
사용합니다.

### 범용 스킬 경로(모든 MCP 호스트) {#universal}

Claude Code, Codex, Cursor, Cline, Goose, ChatGPT 커스텀 MCP 앱, Claude
Cowork를 비롯해 MCP를 지원하는 그 외 모든 호스트에서 동작합니다. Agent-Native
CLI는 Plan 스킬을 설치하고, 호스팅된 Plan MCP 커넥터를 등록하며, **같은
단계에서 선택한 로컬 클라이언트의 인증까지 실행**하므로 첫 번째 도구 호출이
OAuth 장벽에 막히지 않습니다.

```bash
npx @agent-native/core@latest skills add visual-plan
```

이 명령은 `visual-plan`과 함께 `visual-recap`, `visualize-repo` 스킬을
설치하고, `plan` 커넥터를 등록한 다음, 인증을 실행합니다(호스팅/계정 기반
공유를 위한 OAuth 프롬프트). 유용한 플래그는 다음과 같습니다.

- `--client codex|claude-code|claude-code-cli|cowork|all` — MCP 구성을 기록할
  로컬 에이전트를 지정합니다(기본값 `all`).
- `--no-connect` — 인증 없이 커넥터만 등록합니다. 나중에
  `npx @agent-native/core@latest connect https://plan.agent-native.com --client all`을
  실행하거나 더 좁은 `--client`를 선택하세요.
- `--mode hosted|local-files|self-hosted` — 호스팅된 공유, 완전 로컬 MDX 파일,
  또는 자신의 Plan 앱 중에서 선택합니다.
- `--mcp-url <url>` — 커넥터가 기본 호스팅 origin 대신 커스텀 origin(ngrok
  터널, 로컬 개발 서버, 또는 자체 호스팅 배포)을 가리키게 합니다.
- `--with-github-action` — PR 시각적 요약 GitHub Action도 함께 작성합니다
  ([PR 시각적 요약](/docs/pr-visual-recap) 참조).

대화형 설치는 워크플로가 아직 없을 때 PR 시각적 요약 Action도 함께 제안합니다.
스킬 설정 중에 예라고 답해서 추가하거나, 나중에 위 명령을 `--with-github-action`과
함께 실행하세요. 워크플로가 작성된 후에는 다음을 실행합니다.

```bash
npx @agent-native/core@latest recap setup
npx @agent-native/core@latest recap doctor
```

`recap setup`은 가능한 경우 GitHub Action 시크릿과 변수를 구성하고,
`recap doctor`는 워크플로, 로컬 게시 토큰, GitHub 저장소 접근 권한, 필요한
Actions 구성을 검증합니다. 설치가 끝나면 새 스킬과 도구가 로드되도록 에이전트
클라이언트를 재시작하거나 새로고침한 다음 `/visual-plan`을 실행하세요.

> 참고: 순수 `npx skills@latest add BuilderIO/agent-native --skill visual-plan`
> (Vercel/open Skills CLI)은 **안내문만** 설치하며 MCP 커넥터는 등록하지
> 않습니다. 커넥터까지 연결하려면 위의 Agent-Native CLI를 사용하세요.

### Claude Code(플러그인) {#claude-code}

공개 `BuilderIO/agent-native` 저장소 자체가 Claude Code 플러그인
마켓플레이스이므로, 빌드 단계 없이 바로 추가할 수 있습니다. Claude Code
안에서 실행합니다.

```text
/plugin marketplace add BuilderIO/agent-native
/plugin install agent-native-visual-plans@agent-native-apps
/reload-plugins
/mcp        # authenticate the Plan connector (one OAuth approval)
```

`/plugin install`은 Plan 스킬과 **URL 전용** MCP 구성(패키지에 시크릿 없음)을
추가합니다. `/mcp` → **Authenticate**가 OAuth 절차를 완료합니다. 로컬 파일
모드나 자체 호스팅 모드를 원한다면 대신 범용 CLI 경로를 사용하세요.

> 마켓플레이스 카탈로그의 이름은 `agent-native-apps`이고 Plan 플러그인은
> `agent-native-visual-plans`이므로, 설치 대상은 항상
> `agent-native-visual-plans@agent-native-apps`입니다.

### Codex(플러그인) {#codex}

같은 저장소가 Codex 플러그인 마켓플레이스이기도 합니다. 추가하고, 플러그인을
설치한 다음, 커넥터를 인증하세요.

```bash
codex plugin marketplace add BuilderIO/agent-native
codex plugin add agent-native-visual-plans@agent-native-apps
codex mcp login plan   # OAuth in the browser
```

설치 후에는 **새 Codex 스레드를 시작**해서 스킬과 MCP 도구가 세션에 로드되게
하세요. 플러그인은 URL 전용 커넥터(`[mcp_servers.plan]` →
`https://plan.agent-native.com/mcp`)를 제공하며, `codex mcp login plan`이
OAuth 흐름을 실행합니다. 설치와 인증을 하나의 명령으로 함께 하고 싶거나
로컬 파일 모드 또는 자체 호스팅 모드를 원한다면, 위의 범용 CLI 경로도 Codex에
대해 동작합니다(`npx @agent-native/core@latest skills add visual-plan --client codex`).

<Callout tone="info">

**이전 설치:** 설정에 여전히 같은 URL을 가리키는 `agent-native-plans`
항목이 있다면, Codex의 경우
`npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex`를,
다른 대상의 경우 원하는 `--client`를 붙여 같은 명령을 실행하면 정식 이름인
`plan`으로 통합됩니다.

</Callout>

## 업데이트 {#updates}

플러그인 경로는 자동으로 업데이트됩니다 — 일상적인 스킬 변경을 위해 다시
패키징하거나 마켓플레이스를 다시 추가할 필요가 없습니다.

- **Claude Code** — 마켓플레이스 항목이 `autoUpdate: true`로 설정되어 있고
  플러그인이 커밋 SHA 버전 관리를 사용하므로, Claude Code는 시작할 때
  저장소에서 새 버전을 가져옵니다. 적용하려면 `/reload-plugins`를 실행하세요.
  저장소의 기본 브랜치에 대한 모든 푸시는 자동으로 설치된 사용자에게
  전달됩니다.
- **Codex** — 플러그인의 `version`은 번들된 스킬과 MCP 엔드포인트의 콘텐츠
  해시를 포함하므로(예: `1.0.0+codex.<hash>`), 스킬이나 엔드포인트가 바뀌면
  새로운 버전이 생성됩니다. Codex의 시작 시 자동 업그레이드가 구성된 git
  마켓플레이스를 알아서 다시 설치하므로, **새 스레드를 시작**하기만 하면
  변경 사항이 반영됩니다. 일상적인 업데이트에는 수동 `codex plugin
  marketplace upgrade`가 필요 없습니다.
- **범용 CLI 경로** — `npx @agent-native/core@latest skills status visual-plan`을
  실행해 복사된 스킬 폴더 상태를 확인하거나,
  `npx @agent-native/core@latest skills update visual-plan`을 실행해 제자리에서
  갱신하세요. 커넥터를 다시 등록/인증하고 싶다면 `skills add visual-plan`을
  다시 실행해도 여전히 동작합니다. `@latest`는 항상 게시된
  `@agent-native/core` 패키지의 현재 스킬을 가져옵니다.

커넥터는 **호스팅된** 앱을 가리키므로, Plan 앱의 액션과 실시간 도구 화면은
언제 설치했는지와 상관없이 항상 배포된 버전을 반영합니다. 위의 업데이트
메커니즘을 따르는 것은 번들된 스킬 안내문뿐입니다.

<Callout tone="info">

**메인테이너용:** 마켓플레이스 번들(`.claude-plugin/`, `.agents/plugins/`)은
정식 plan 스킬로부터 `pnpm sync:plan-marketplace`로 생성되며 CI에서
`pnpm guard:plan-marketplace`로 검증되므로, 게시된 마켓플레이스는 항상
정식 스킬과 일치합니다. 스킬을 편집하고, `pnpm sync:plan-marketplace`를
실행한 다음 커밋하세요.

</Callout>

## 무언가를 제출해야 하나요? {#submission}

**배포하거나 설치하는 데는 어떤 제출이나 심사도 필요하지 않습니다.**
`BuilderIO/agent-native`는 자체 호스팅되는 공개 git 마켓플레이스이므로,
사용자는 **Claude Code와 Codex 모두에서** 위의 명령으로 바로 추가합니다 —
신청도 승인도 없습니다. 범용 CLI 경로는 마켓플레이스 자체가 아예 필요 없습니다.

공개 목록에 올리고 싶다면 선택적인 발견 가능성 경로도 있습니다.

- **Claude Code**에는 목록 등재를 위해 _선택적으로_ 제출할 수 있는 커뮤니티
  마켓플레이스가 있습니다(제출과 자동화된 심사가 필요합니다). 공식적으로
  Anthropic이 큐레이션하는 마켓플레이스는 Anthropic의 재량으로 등재되며,
  공개적인 셀프서브 신청 절차는 없습니다. 위의 설치 명령을 사용하는 데는
  둘 다 필요하지 않습니다.
- **Codex**에는 OpenAI가 큐레이션하는 플러그인 카탈로그가 있습니다(셀프서브
  제출이 아니라 파트너십을 통해 확보하는 폐쇄형 허용 목록입니다). 자체
  호스팅되는 git 마켓플레이스와 CLI 경로는 동작하는 데 아무런 제출이 필요
  없습니다.

요약하면, 자체 호스팅/공개 git 마켓플레이스로 배포하면 사용자가 바로
설치할 수 있고, 발견 가능성을 위해 목록에 올리고 싶을 때만 큐레이션된
카탈로그에 제출하면 됩니다.

## 플러그인 대 스킬 {#plugin-vs-skill}

**스킬**은 작업이 일치할 때 에이전트가 읽는 단일 `SKILL.md` 안내 파일입니다.
**플러그인**(Claude Code 마켓플레이스 플러그인이나 Codex 플러그인)은 하나
이상의 스킬**과** MCP 커넥터, 메타데이터를 함께 묶은 패키지로, 호스트가
한 단계에서 모든 것을 설치할 수 있게 해줍니다.

내부적으로는 세 경로 모두 `npx @agent-native/core@latest app-skill` CLI를
통해 같은 소스로부터 만들어집니다. `app-skill pack`이 마켓플레이스/플러그인
어댑터를 빌드하고, `skills add`는 MCP 커넥터도 등록하고 인증까지 해주는
사용자 친화적인 원스텝 설치기입니다. app-skill 매니페스트 형식은
[스킬 가이드](/docs/skills-guide)를, 모든 MCP 호스트를 연결하는 방법과
`npx @agent-native/core@latest connect` 흐름은
[외부 에이전트](/docs/external-agents)를 참조하세요.
