# 다중 앱 작업 공간 속 양식

양식은 [Dispatch](/docs/template-dispatch) 작업 공간에 속한 여러 앱 중 하나입니다. 이 페이지는 그것이 실제로 무엇을 의미하는지, 즉 연결이 어떻게 동작하는지, 그리고 다른 앱이 양식에 실제로 어떻게 작용하거나 양식으로 데이터를 보낼 수 있는지를 구체적으로 다룹니다. 전체 개요는 [양식](/docs/template-forms) 문서를 참고하세요.

## 양식이 Dispatch와 연결되는 방식

이것이 자동으로 이루어지는지는 양식과 Dispatch를 어떻게 함께 설정했는지에 따라 달라지며, 둘 중 하나가 호스팅되어 있는지 로컬에서 실행 중인지와는 관련이 없습니다.

### 같은 작업 공간: 자동

양식과 Dispatch가 하나의 Agent-Native 작업 공간에 (`create` 또는 `add-app`을 통해) 함께 생성되거나 추가되어 하나의 단위로 배포되었다면, 이미 하나의 `.env`, 하나의 `A2A_SECRET`, 하나의 작업 공간 레지스트리를 공유합니다. 검색과 인증된 A2A 호출 모두 그 작업 공간이 여러분의 컴퓨터에서 실행되든 프로덕션에서 실행되든 별도로 설정할 것 없이 그대로 동작합니다. 양식을 기반으로 한 실제 다중 앱 제품이라면 이 설정이 기본적으로 예상됩니다.

### 별도 배포: 수동 단계 하나

양식과 Dispatch가 독립적으로 생성된 두 개의 Agent-Native 프로젝트라면, 시크릿을 공유하지 않으므로 아직 서로를 호출할 수 없습니다. 이들을 연결하려면 양쪽 각각에서 수동 단계 하나가 필요합니다. 설정 → 연결된 에이전트, Agent 페이지의 연결 탭, 또는 Dispatch → 에이전트 → 외부 에이전트 추가에서 공유 시크릿과 함께 `remote-agents/<id>.json` 리소스를 추가하세요. 전체 과정은 [A2A 프로토콜](/docs/a2a-protocol) 문서를 참고하세요.

어느 쪽 상황인지 확인하려면 두 앱 중 어느 쪽 에이전트에게든 "어떤 앱들을 볼 수 있어?"라고 물어보세요. Dispatch의 답변에 양식이 빠져 있다면 두 번째 경우에 해당합니다.

## 통합 전략

**Dispatch를 통한 자연어 위임.** 다른 형제 앱이 양식과 함께 동작하는 데 특별한 통합이 필요하지는 않습니다. 여러분이 채팅에서 하는 것과 같은 방식으로, "베타 가입 양식에 응답이 몇 개나 있어?" 같은 자연어 요청을 양식의 에이전트에게 그대로 건네면, 양식이 직접 답하거나 처리합니다. Slack이나 메일로 들어온 질문이 양식으로부터의 실제 답변으로 바뀌는 것 같은 일의 실제 메커니즘이 바로 이것입니다. Dispatch(또는 메시지를 받은 앱)가 요청을 양식의 에이전트에게 위임하면, 양식은 다른 프롬프트와 똑같이 그 요청을 처리합니다.

**다른 앱이 양식에 직접 제출하기.** 다른 앱이 데이터를 보내는 데 양식은 A2A나 Dispatch가 전혀 필요하지 않습니다. 어떤 앱이든 익명의 응답자가 공개 페이지를 작성하는 것과 같은 방식으로, 양식의 공개 제출 주소에 일반 웹 요청을 보낼 수 있습니다. 프레임워크 자체의 피드백 버튼도 정확히 이런 방식으로 동작합니다. 다른 앱의 사이드바 안에서, 피드백이 어떤 페이지와 어떤 앱에서 왔는지와 함께 배포된 양식 앱으로 제출을 보내면, 양식은 이를 일반 응답으로 기록합니다. 즉 작업 공간의 어떤 앱이든 A2A 연결 없이 그저 일반 웹 요청만으로 구조화된 데이터를 양식에 보낼 수 있다는 뜻입니다.

**분리된 상태 유지하기.** 위임받은 질문에 답하든 직접 제출을 받든, 양식은 호출하는 앱의 자격 증명을 알아야 할 필요가 전혀 없으며, 호출하는 앱도 양식이 데이터를 어떻게 저장하는지 알 필요가 없습니다. 위임은 다른 프롬프트와 마찬가지로 에이전트를 거치고, 직접 제출은 사람 응답자가 사용하는 것과 같은 공개 주소를 거칩니다.
