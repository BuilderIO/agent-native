# 개인정보 및 데이터 권리

Agent-Native는 기본 계정 설정에 개인정보 요청 화면을 제공합니다. 로그인한 사용자는 자신의 개인 데이터 사본이나 삭제를 요청할 수 있습니다.

이는 구현 기준이며 법률 자문이나 규정 준수 인증이 아닙니다. 앱을 운영하는 조직은 법적 역할을 정하고 배포 환경에 맞는 고지와 절차를 공개해야 합니다.

## 사용자가 할 수 있는 일

**설정 > 계정 > 보안**의 **내 데이터** 그룹에서 다음을 할 수 있습니다.

- 액세스 또는 이동성 검토를 위해 개인 데이터 사본을 요청합니다.
- 삭제 검토를 위해 개인 데이터 삭제를 요청합니다.
- 기존 프로필 및 이메일 설정으로 계정 정보를 수정합니다.

요청은 영구적으로 기록되고 중복 없이 처리되며 감사됩니다. 요청 action은 유형, 상태, 시간만 저장합니다. 데이터 덤프를 반환하거나 다른 사람의 이메일 또는 사용자 ID를 받거나 데이터를 즉시 삭제하지 않습니다.

## 에이전트가 할 수 없는 일

개인정보 요청은 계정 설정 UI에서 제출합니다. `request-privacy-right`는 인증되고 에이전트 도구와 MCP/A2A 검색에서 숨겨지며 도구 브리지에서 차단되고 프런트엔드 호출만 허용됩니다.

핵심 `offboard-member` action도 같은 UI-only 경계를 사용합니다. 멤버 오프보딩은 소유 행을 이전하고 액세스를 취소하는 조직 작업이지 계정 삭제가 아닙니다. 조직 삭제도 기존 소유자 전용 UI 확인 뒤에 있습니다.

사람의 승인 프롬프트는 보안 경계가 아닙니다. 데이터를 지우거나 ID를 취소하거나 멤버십 또는 인증을 바꾸는 사용자 지정 action에는 명시적인 UI-only 경계를 사용하고 검증된 요청 컨텍스트에서 신원을 가져오세요.

## 운영자의 처리

프레임워크는 요청을 기록합니다. 배포 운영자는 다음을 수행해야 합니다.

1. 요청자의 신원을 확인하고 조직과 법적 범위를 정합니다.
2. 배포가 관리하는 데이터를 수집하여 비공개 접근 제어 채널로 전달합니다.
3. 앱 행과 비공개 파일을 삭제 또는 익명화하고 필요하면 세션과 자격 증명을 취소하며 연결된 제공자 및 처리자와 조정합니다.
4. 백업, 보안 및 감사 로그, 사기 방지 기록과 문서화된 예외에 보존 정책을 적용합니다.
5. 완료, 부분 처리 또는 차단 사유를 기록하고 요청자에게 알립니다.

조직의 행 하나나 설정 하나를 삭제했다고 요청이 완료된 것으로 보지 마세요. 호스팅 제공자, 업로드 파일, 연결된 서비스, 캐시, 백업, 변경 불가 감사 기록에는 별도의 보존 및 삭제 경로가 있을 수 있습니다.

## 기본 개인정보 보호 방식

새로 공유할 수 있는 리소스는 기본적으로 비공개입니다. 브라우저 분석은 DOM 및 네트워크 자동 수집을 끄고, 설정된 경우에도 세션 재생은 선택 사항이며 로그인 사용자만 대상으로 합니다. 이는 개인정보 고지, 법적 근거, 보존 정책, 동의 및 옵트아웃 제어를 대신하지 않습니다.

배포가 개인 정보를 판매하거나 공유한다면 해당 CCPA 옵트아웃과 Global Privacy Control을 처리해야 합니다. 프레임워크가 판매 또는 공유 프로그램을 만들지는 않습니다.

## 배포 체크리스트

- 데이터 범주, 목적, 수신자, 보존 기간, 권리, 연락처를 담은 개인정보 고지를 게시합니다.
- 법적 근거, 동의, 민감 데이터 제한, 연령 요건을 정하고 문서화합니다.
- 액세스, 정정, 삭제, 이동성, 이의 제기, 옵트아웃 요청의 담당자와 절차를 정합니다.
- 테이블, 비공개 파일, 분석, 연결 서비스, 이메일, 캐시, 로그, 백업, 하위 처리자를 파악합니다.
- 확인 절차, 기한, 보존 예외, 삭제 증거, 이의 제기를 정의합니다.
- 영향이 큰 action을 UI-only로 유지하고 에이전트, MCP, A2A, CLI, HTTP, 도구 iframe 호출자가 실행할 수 없는지 테스트합니다.
