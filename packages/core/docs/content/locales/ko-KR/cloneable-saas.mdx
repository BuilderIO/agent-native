# 앱

에이전트 네이티브 앱에는 두 가지 형태가 있습니다: 전체 브라우저 UI를 갖춘 템플릿과, 브라우저 UI가 없는 automation-first 앱(Slack 봇, 야간 리포트, webhook 응답기 등)입니다. 이 문서에서는 템플릿을 다룹니다. 다른 형태는 [Automation-First Apps](/docs/pure-agent-apps)를 참조하세요.

템플릿은 UI, 데이터베이스, 인증, 에이전트가 이미 구축되어 연결된 완전한 SaaS 제품입니다. 템플릿을 선택하고 브랜드를 적용한 다음, 빈 비계에서 시작하는 대신 자신만의 제품으로 배포하세요. 이 모델을 Cloneable SaaS라고 부릅니다. 비계가 아니라 완성된 제품에서 시작하는 것입니다.

## 예제 앱 {#catalog}

각 앱은 오늘 바로 실행할 수 있고 자신만의 것으로 사용자 정의할 수 있는 완전한 제품입니다.

| 앱                                        | 무엇인가요                                                                                                             |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| [**Chat**](/docs/template-chat)           | 내구성 있는 스레드, actions, 인증 및 맞춤형 UI 또는 자체 백엔드에 대한 명확한 경로를 갖춘 최소한의 채팅 우선 앱입니다. |
| [**Mail**](/docs/template-mail)           | 요원 출신의 슈퍼휴먼. 받은편지함, 라벨, AI 분류, 키보드 우선, 초안 작성 및 에이전트를 통한 전송.                       |
| [**Calendar**](/docs/template-calendar)   | 에이전트 네이티브 Google Calendar. 이벤트, 동기화, 공개 예약 링크, 상담원 중심 일정.                                   |
| [**Content**](/docs/template-content)     | MDX용 오픈 소스 흑요석. 로컬 Markdown/MDX, Tiptap 편집기, Notion 동기화, 실시간 다중 사용자 공동 작업.                 |
| [**Brain**](/docs/template-brain)         | 인용된 기관의 기억, 승인된 출처, 리뷰 게이트 및 인용을 바탕으로 깔끔한 회사 채팅을 제공합니다.                         |
| [**Assets**](/docs/template-assets)       | 브랜드 라이브러리, 업로드, 참조 및 브랜드 이미지/비디오 생성을 위한 디지털 자산 관리자입니다.                          |
| [**Slides**](/docs/template-slides)       | 상담원 전용 Google 프레젠테이션. 에이전트가 직접 생성하고 편집하는 React 기반 덱입니다.                                |
| [**Analytics**](/docs/template-analytics) | 에이전트 기본 진폭/믹스패널. 데이터 소스를 연결하고, 차트를 표시하고, 대시보드에 고정하세요.                           |
| [**Clips**](/docs/template-clips)         | 비동기 화면 + 스크립트, 챕터, AI 요약이 포함된 카메라 녹화                                                             |
| [**Design**](/docs/template-design)       | 대화형 Alpine/Tailwind 디자인을 위한 에이전트 기반 HTML 프로토타이핑 스튜디오.                                         |
| [**Forms**](/docs/template-forms)         | 에이전트 기본 Typeform입니다. Slack, 스프레드시트, webhooks 또는 Discord에 제출물을 작성, 공유, 수집 및 라우팅합니다.  |
| [**Plan**](/docs/template-plan)           | 다이어그램, 와이어프레임 및 주석을 포함한 시각적 계획 및 PR 요약                                                       |
| [**Dispatch**](/docs/template-dispatch)   | 작업 공간 제어 플레인: 공유 비밀, 재사용 가능한 통합, Slack/Telegram, 예약된 작업.                                     |

이 중에 도메인에 맞는 앱이 없다면 [Chat](/docs/template-chat)로 시작해 actions, native results, screens로 확장하세요. workflow에 브라우저 UI가 필요 없다면 [Automation-First Apps](/docs/pure-agent-apps)를 사용하세요.

각 앱에는 아키텍처, actions, 사용자 정의를 다루는 자체 문서가 있습니다. [agent-native.com/apps](/apps)에서 호스팅된 실제 버전을 둘러보거나, 작업 공간 스타일 앱을 원한다면 [Dispatch](/docs/template-dispatch)로 시작하세요.

## 커뮤니티 템플릿 {#community-templates}

CLI 선택기에 이름이 표시되는 템플릿은 **퍼스트 파티**입니다. Agent
Native가 프레임워크와 함께 유지 관리하고 테스트하며 문서화하고
출시합니다. **커뮤니티 템플릿**의 유지 관리와 버전 관리는 해당
리포지토리 소유자의 책임입니다. 동일한 프레임워크 기능을 사용할 수 있지만
커뮤니티 목록에 포함된 것이 Agent Native의 보증이나 지원 약속을 의미하지는
않습니다.

`create`를 실행하고 **커뮤니티 템플릿**을 선택한 다음, 공개 GitHub
리포지토리의 단순한 URL을 붙여 넣으세요.

```bash
https://github.com/owner/repo
```

리포지토리 루트가 하나의 Agent Native 앱이면 CLI는 다른 picker 없이 직접
설치합니다. Agent Native workspace 리포지토리이면 CLI는 `apps/*`의 유효한
직접 자식을 찾고 `dispatch`를 제외한 뒤 설치할 앱을 묻습니다.

비어 있지 않은 `agent-native.workspaceCore` marker가 있으면 root package도
`@agent-native/core`에 의존하더라도 workspace로 처리합니다. 잘못된 marker는
거부됩니다.

Scripts에서는 동일한 단순 URL을 `--template`에 전달하거나 짧은
`community:` 형식을 사용하세요. 재현 가능한 시작점이 필요하면 `#` 뒤에
branch, tag 또는 commit을 고정하세요. Ref를 생략하면 CLI는 `main`,
`master` 순서로 시도합니다.

```bash
npx @agent-native/core@latest create my-app --template community:owner/repo#v1.2.0
npx @agent-native/core@latest create my-app --template https://github.com/owner/repo#v1.2.0
```

Workspace repository에서 source 앱을 비대화형으로 선택하려면
`?app=<app-name>`을 사용하세요. Selector는 선택 사항인 `#ref` 앞에 옵니다.
zsh 같은 shell은 `?`를 glob으로 처리하므로 전체 값을 따옴표로 묶으세요.

```bash
npx @agent-native/core@latest create my-app --template 'community:owner/repo?app=analytics#v1.2.0'
npx @agent-native/core@latest create my-app --template 'https://github.com/owner/repo?app=analytics#v1.2.0'
```

Workspace 밖에서 `create`는 선택한 source 앱을 standalone으로 만듭니다.
기존 workspace에 추가하려면 `add-app` picker에는 퍼스트 파티 템플릿만
표시되므로 커뮤니티 리포지토리를 명시적으로 전달하세요. Source workspace에서
대화형으로 선택하려면 `?app`을 생략하고, scriptable install에는 포함하세요.

```bash
npx @agent-native/core@latest add-app my-app --template community:owner/repo#v1.2.0
npx @agent-native/core@latest add-app my-app --template 'community:owner/repo?app=analytics#v1.2.0'
```

공개 GitHub repositories만 허용됩니다. Private repositories, GitHub가 아닌
host, GitHub tree 또는 subdirectory URL, nested app path는 지원되지 않습니다.
Root 앱에는 `dependencies`, `devDependencies` 또는 `peerDependencies`에
`@agent-native/core`를 나열하는 읽을 수 있는 `package.json`이 있어야 합니다.
Workspace repository에서는 선택 가능한 각 source 앱이
`apps/<app-name>/` 바로 아래에서 동일한 요구 사항을 충족해야 하며,
`dispatch`는 선택할 수 없습니다.

Community workspace 앱은 monorepo의 임의 조각이 아니라 portable leaf여야
합니다.

- 기본 `catalog:` dependency ref는 source repository 루트의
  `pnpm-workspace.yaml`에서 resolve됩니다. Named catalog ref는 지원되지
  않습니다.
- `@agent-native/core`, `@agent-native/dispatch`,
  `@agent-native/toolkit`에 대한 `workspace:*` ref는 published version으로
  rewrite됩니다. 다른 sibling workspace package는 복사되지 않으므로
  publish하고 concrete version을 사용하세요.
- source `workspaceCore` dependency는 제거됩니다. 상속된 canonical workspace
  auth 및 agent-chat plugin은 standalone install에서 분리되거나 destination
  workspace에 다시 연결됩니다. Source `workspaceCore` package의 다른
  import는 명확한 error를 내므로, 해당 code를 앱으로 옮기거나 concrete
  dependency로 publish하세요.

각 앱의 나머지도 해당 `package.json`과 함께 두세요. 사용하는 경우
`agent-native.json`, source, actions, 에이전트 지침 및 데이터베이스 설정이
포함됩니다. 카탈로그에 올릴 준비가 된 리포지토리에는 다음 항목도 포함해야
합니다.

- 라이선스와 메인테이너 또는 지원 링크
- 설정 단계, 필수 environment variables 및 정확한 CLI 명령이 있는 README
- placeholders만 포함하고 secret, 고객 데이터, runtime database 또는
  generated build output이 없는 `.env.example`
- 정상 작동하는 설치 및 개발 명령, typecheck, 템플릿에 적절한 tests

Installer는 확인된 `source`와 `ref`를 설치된 앱의 `package.json`에 있는
`agent-native.communityTemplate`에 기록합니다. Workspace repository에서
선택한 앱은 source 앱도 `agent-native.communityTemplate.app`에 기록합니다.
`agent-native template sync`는 계속 퍼스트 파티 템플릿 전용입니다.
커뮤니티 템플릿을 업데이트하려면 새로운 upstream ref를 검토하고 변경 사항을
직접 병합하세요.

전체 앱, action, state, security 및 publishing 체크리스트는
[Creating Templates](/docs/creating-templates)를 참고하세요.

> **Dependencies를 설치하거나 코드를 실행하기 전에 커뮤니티 코드를
> 검토하세요.** 커뮤니티 템플릿은 제3자 리포지토리에서 다운로드됩니다.
> Agent Native는 이를 sandbox, audit 또는 유지 관리하지 않습니다. CLI는
> source만 다운로드하며 dependencies를 설치하거나 template scripts를
> 실행하지 않습니다. Source, license, dependencies 및 package install
> scripts를 확인하고 고정된 신뢰할 수 있는 ref를 사용하세요.

Hosted demo는 선택 사항입니다. 제공한다면 공개 try-it 링크로 만들고 sign-in,
seed data 또는 provider 요구 사항을 문서화하세요. 설치의 source of truth는
리포지토리이며 템플릿과 demo에 대한 책임은 모두 리포지토리 소유자에게
있습니다.

목록에 추가하고 싶으신가요? 리포지토리 URL, 한 문장 설명, 메인테이너와
라이선스 세부 정보, 테스트한 CLI 명령, 선택 사항인 hosted demo URL을 포함해
[커뮤니티 템플릿을 제출하세요](https://github.com/BuilderIO/agent-native/issues/new?template=community-template.yml).

## 상자에서 꺼내는 것 {#what-you-get}

모든 예제 앱에는 다음이 포함됩니다:

- **작동하는 에이전트** — 앱에 연결되어 있고, 데이터에 대해 actions를 수행할 수 있으며, 보고 있는 내용을 인식합니다. [Messaging the agent](/docs/messaging)를 참조하세요.
- **인증** — 로그인, 세션, 조직, 다중 테넌트 격리.
- **데이터베이스** — 스키마, 쿼리, 마이그레이션이 바로 사용할 수 있게 준비되어 있습니다. 자체 SQL 데이터베이스(Postgres, SQLite, Turso, D1)를 가져오면 프레임워크가 이에 맞춰 조정됩니다.
- **실시간 UI** — 화면은 에이전트와 동기화 상태를 유지합니다. 예를 들어 채팅에서 이메일 초안을 작성하면 받은편지함이 즉시 업데이트됩니다.
- **배포 가능** — Netlify, Vercel, Cloudflare, AWS 또는 Node를 실행하는 모든 호스트에 배포합니다.
- **브랜딩 후크** — 이름, 색상, 로고, 문구를 변경합니다.

프레임워크 메인테이너는 Mail, Calendar, Analytics 앱에서 자신의 이메일, 캘린더, 분석 업무를 실제로 처리합니다.

4. **배송하세요.** 배포 명령을 실행합니다. 이제 자신의 도메인에 프로덕션 앱이 있습니다.

2~4단계는 일반적으로 며칠이 걸립니다. 3단계에는 정해진 종료 시점이 없습니다. 앱은 여러분이 계속 발전시켜 나가는 것이며, 그 사이 임베디드 에이전트는 배포된 제품을 계속 운영할 수 있고 코드 접근이 명시적으로 활성화되면 소스 변경도 도울 수 있습니다.

## 이것이 실용적인 이유 {#why}

사용자마다 별도의 코드베이스를 두는 방식은 규모가 커지면 유지되지 않습니다. 모든 사용자를 위해 앱의 포크를 유지 관리하는 일은 감당할 수 없게 됩니다. 두 가지 프레임워크 결정이 이를 피하게 해줍니다.

1. **앱이 프레임워크 계약을 유지합니다.** 소스는 도메인 동작을 소유하고 Core는 앱이 발전해도 actions, SQL, 상태, 동기화를 일관되게 유지합니다.
2. **사용자별 코드 없이 사용자별 사용자 정의.** Skills, 메모리, 지침, 연결된 MCP 서버 및 하위 에이전트는 모두 SQL에 있습니다. 모든 사용자는 자신만의 맞춤화 레이어를 갖게 됩니다. 공유 코드베이스는 이 모든 것을 한 번에 호스팅합니다.

결과: 사용자별 배포 없이 사용자별 맞춤화.

## 맞춤 설정하고 싶지 않으신가요? {#hosted}

모든 예제 앱은 `agent-native.com`(`mail.agent-native.com`, `calendar.agent-native.com` 등)에서 호스팅된 제품으로도 이용할 수 있습니다. 무료 또는 유료로 호스팅 버전을 사용하세요. 호스팅 버전이 제공하지 않는 부분을 변경하고 싶을 때는 템플릿에서 자신만의 앱을 만드세요.

## 스킬로 시도해 보세요 {#try-with-a-skill}

앱을 스캐폴딩하지 않고도 이미 사용 중인 코딩 에이전트에 에이전트 네이티브 기능을 추가할 수 있습니다. [Skills Guide](/docs/skills-guide#app-backed-skills)를 참조하세요.

## 이를 토대로 구축

- [**Getting Started**](/docs/getting-started) — chat-first app을 만들고, action을 추가하고, structured result를 렌더링한 뒤 page로 확장하기
- [**Messaging the agent**](/docs/messaging) — 사용자(및 귀하)가 각 앱과 함께 제공되는 에이전트와 대화하는 방법
- [**Multi-App Workspace**](/docs/multi-app-workspace) — 여러 앱을 인증, 브랜드 및 에이전트를 공유하는 하나의 작업 공간으로 묶습니다.
- [**Dispatch**](/docs/template-dispatch) — 작업공간 제어 평면 앱
- [**Creating Templates**](/docs/creating-templates) — 자신만의 앱 템플릿을 작성하고 게시하세요

### 개발자용 {#dev-details}

새 앱을 스캐폴딩하려면:

```bash
npx @agent-native/core@latest create my-platform
```

CLI는 먼저 **어떻게 시작하시겠습니까?**라고 묻습니다. Chat과 Dispatch가 있는 최소 작업 공간을 만들려면 **Chat**을, 다중 선택 도구를 열려면 **First-party template(s)**를 선택하세요. Community와 Headless는 독립 실행형 앱을 위한 선택지입니다. 작업 공간 앱은 인증, 브랜드, 에이전트 구성 및 데이터베이스를 공유하며 각 앱은 필요한 모든 파일과 함께 `apps/<name>/`에 스캐폴딩됩니다. 앱 UI 대신 브라우저 UI 없는 automation을 만들려면 `npx @agent-native/core@latest create my-agent --headless`를 사용하세요.

`.env`(`ANTHROPIC_API_KEY` 및 `DATABASE_URL`)를 입력한 다음 `pnpm install`과 `pnpm dev`를 실행하세요. 구현해야 할 로그인도, 자리 표시자 경로도 없습니다.

배포 대상: 모든 Nitro 호환 호스트(Node, Cloudflare, Netlify, Vercel, Deno, Lambda, Bun) 및 모든 Drizzle 호환 SQL 데이터베이스(SQLite, Postgres, Turso, D1, Supabase, Neon). 작업 공간의 경우 `npx @agent-native/core@latest deploy`는 모든 앱을 한 번에 빌드하여 단일 원본으로 제공합니다. [Deployment](/docs/deployment)를 참조하세요.

자신만의 앱 템플릿을 작성하고 게시하려면 [Creating Templates](/docs/creating-templates)를 참조하세요.
