# 개발자 가이드

이 페이지는 슬라이드 템플릿을 커스터마이즈하거나 확장하려는 모든 사람을 위한 것입니다. SQL 데이터 모델, 동시 쓰기 작업이 안전하게 유지되는 방식, 에이전트가 호출할 수 있는 모든 액션, 라우트 구성, 그리고 흔히 변경하는 위치를 다룹니다.

## 빠른 시작

```bash
npx @agent-native/core@latest create my-slides --standalone --template slides
```

나머지 설정(`cd`, `pnpm install`, `pnpm dev`)과 프레임워크 기본 원리는 [시작하기](/docs/getting-started) 문서를 참고하세요.

## 지속성 모델

각 데크는 `decks.data`에 저장된 하나의 JSON 덩어리입니다. 모든 쓰기 작업은 데크별 잠금을 유지하는 서버 측 읽기-수정-쓰기 액션을 거치므로, 사람과 에이전트든 두 사람이든, 동시에 쓰는 작업자들이 같은 데크의 다른 슬라이드를 건드려도 서로의 작업을 덮어쓰는 일이 없습니다.

- **에이전트 액션**(`add-slide`, `update-slide`)은 각자 전용의 세분화된 액션을 사용하며 같은 잠금을 공유합니다.
- **브라우저 편집기**는 전체 데크를 PUT하는 대신 `patch-deck`을 통해 세분화된 작업(`patch-slide`, `delete-slide`, `reorder-slides`, `add-slide`, `patch-deck-fields`)을 큐에 넣습니다.

<Callout id="doc-block-slides10" tone="warning">

편집기의 저장 경로를 확장한다면, `patch-deck`을 통해 새 작업을 큐에 넣으세요. 새로운 전체 데크 PUT을 추가하지 마세요. 그렇게 하면 이 잠금이 막고 있는 '마지막에 쓴 것이 이기는' 경쟁 상태가 다시 생겨납니다.

</Callout>

#### 슬라이드 구조

`decks.data` 안의 각 슬라이드는 다음과 같습니다.

```json
{
  "id": "slide-1",
  "layout": "title",
  "content": "<div class=\"fmd-slide\" style=\"...\">...</div>"
}
```

`content`는 원시 HTML입니다. 렌더러는 고정된 종횡비와 배경을 제공하고, HTML은 그 안의 모든 것을 제공합니다. 풍부한 임베딩도 지원됩니다. 손으로 그린 다이어그램과 실시간으로 렌더링되는 차트가 일반 HTML과 함께 슬라이드 안에 존재할 수 있습니다.

## 액션 목록

### 데크 생명 주기

- `create-deck` — 새 데크를 만들며, 선택적으로 슬라이드를 미리 채울 수도 있고, 기존 데크의 슬라이드를 원자적으로 일괄 교체할 수도 있습니다. 빈 데크를 만들려면 `slides`를 생략하거나 `[]`를 전달하세요. 이 액션은 애플리케이션 상태를 통해 새 데크를 엽니다.
- `get-deck` — 전체 데크 JSON, 또는 간결한 슬라이드 요약 보기
- `list-decks` — 호출자가 볼 수 있는 모든 데크를, 저비용 폴링을 위한 light/compact/full-slide 투영으로 조회
- `duplicate-deck` — 새로운 슬라이드 id로 데크를 복제
- `update-deck-aspect-ratio` — 16:9, 1:1, 9:16, 또는 4:5

`add-deck`, `save-deck`, `delete-deck`는 브라우저 편집기의 낙관적 생성, 실행 취소/다시 실행, 삭제 흐름을 뒷받침합니다. 에이전트는 대신 `create-deck`, `add-slide`/`update-slide`/`patch-deck`, 그리고 프레임워크 자체의 공유 액션을 사용합니다.

### 접근 요청

- `request-deck-access`, `approve-deck-access-request`, `get-deck-access-status` — 비공개 데크의 접근 요청 흐름입니다. 접근 권한이 없는 방문자가 요청하면, 소유자가 앱이나 `/access-request/approve` 라우트에서 승인 또는 거부하고, 양쪽 모두 현재 상태를 폴링할 수 있습니다.

### 슬라이드 편집

- `add-slide` — 슬라이드 하나를 추가(또는 특정 위치에 삽입)합니다. 편집기가 진행 상황을 보여줄 수 있도록 빈 `create-deck` 다음에 순차적으로 호출하세요.
- `update-slide` — 정밀한 찾기/바꾸기 또는 전체 콘텐츠 슬라이드 편집
- `patch-deck` — 브라우저 편집기가 전체 데크 PUT 대신 사용하는 세분화된 작업 큐
- `get-layout-overflows` — 브라우저에서 측정한 슬라이드 맞춤 결과를 읽어, 레이아웃에 더 이상 맞지 않는 편집을 감지하고 수정할 수 있게 함

### 기록

- `list-deck-versions`, `get-deck-version`, `restore-deck-version` — 모든 쓰기 작업이 먼저 스냅샷을 남기므로, 어떤 시점이든 목록으로 확인하고 복원할 수 있습니다.

### 댓글

- `list-slide-comments`, `add-slide-comment`, `update-slide-comment`, `delete-slide-comment`

### 가져오기

- `import-pptx`, `import-docx`, `import-google-doc` — 단일 형식 전용 가져오기
- `import-google-slides-reference` — Google Slides 데크를 작업 중인 데크에 콘텐츠로 가져오는 대신, 재사용 가능한 참조 데크로 가져옵니다.
- `import-file` — PPTX, DOCX, PDF, 또는 Figma `.fig` 파일을 위한 단일 진입점입니다(`.fig` 파일은 슬라이드 가져오기가 아니라 Builder 디자인 시스템 색인화로 연결됩니다).
- `extract-pdf` — CLI 전용으로 PDF의 원시 텍스트를 덤프하며, 주로 로컬 디버깅용입니다.

### 내보내기

- `export-pptx` — 네이티브하고 편집 가능한 PowerPoint
- `export-google-slides` — 동일한 PPTX와 바로 사용할 수 있는 Google Slides 가져오기 링크를 함께 생성합니다.
- `export-html` — 키보드 탐색이 내장된 독립 실행형 자체 완결 HTML 파일

### 디자인 시스템

- `create-design-system`, `update-design-system`, `delete-design-system`, `get-design-system`, `list-design-systems`, `set-default-design-system`, `apply-design-system`(데크에 하나를 연결)
- `get-workspace-defaults`, `set-workspace-defaults` — 작업 공간 전체의 기본 데크와 디자인 시스템입니다. 설정은 관리자만 가능합니다.
- `analyze-brand-assets`, `import-document`, `import-from-url`, `import-code` — **로컬**에서 에이전트가 작성하는 디자인 시스템을 위해 원시 브랜드 신호(웹사이트 CSS/폰트, 업로드된 문서나 코드 파일 내용)를 수집합니다.
- `index-design-system-with-builder`, `sync-design-system-with-builder`, `import-design-project` — Figma 파일, 연결된 코드/GitHub 저장소, `design.md`를 위한 Builder 색인화 경로입니다. `import-design-project`는 원시 소스가 아니라 기존 디자인 시스템에서 시작합니다.

### Creative Context

- `clone-context-slide` — 고정된 Library 슬라이드 하나를 HTML/CSS를 다시 생성하지 않고 그대로 데크에 삽입합니다.
- `clone-creative-context-deck` — 관리되는 데크 버전 하나를 정확히 재생성합니다.
- `get-deck-reference-context` — 기존 데크의 시각적 언어를 재사용 가능한 패턴 라이브러리로 추출합니다.
- 검색과 Library 제출(검색, 컨텍스트 항목 가져오기, Library 멤버십 관리)은 Creative Context를 지원하는 모든 앱에서 에이전트가 동일한 방식으로 호출하는 공유 프레임워크 액션입니다. 검색 절차와 재사용 단계는 `creative-context` skill을 참고하세요.

### 에스컬레이션과 스테이징된 데이터

- `provider-api-catalog`, `provider-api-docs`, `provider-api-request` — 정형화된 가져오기/내보내기 액션이 너무 제한적일 때 사용하는 원시 Google Drive API 접근입니다. 슬라이드는 사용자가 연결한 Google Docs 계정에서 인증을 해석합니다.
- `list-staged-datasets`, `query-staged-dataset`, `delete-staged-dataset` — 대규모로 스테이징된 프로바이더 결과를 다시 가져오지 않고 집계합니다.

### 내비게이션과 컨텍스트

- `view-screen` — 사용자가 현재 보고 있는 것: 열린 데크, 현재 슬라이드, 활성화된 시각적 선택
- `navigate` — UI를 특정 데크, 슬라이드, 또는 화면으로 이동

## 커스터마이즈하기

슬라이드 템플릿은 완전히 커스터마이즈할 수 있습니다. 확장할 때 살펴봐야 할 주요 위치는 다음과 같습니다.

#### Actions — `templates/slides/actions/`

에이전트가 호출할 수 있는 모든 작업은 여기에 TypeScript 파일로 존재하며, `POST /_agent-native/actions/:name`에 자동으로 마운트되고 CLI에서 `pnpm action <name>`으로 호출할 수 있습니다. 에이전트에게 새로운 기능을 부여하려면 여기에 새 파일을 추가하세요.

#### Skills — `templates/slides/.agents/skills/`

에이전트가 코드를 수정해야 할 때 패턴을 설명하는 에이전트 skills입니다.

- `create-deck` — 새 데크를 만드는 방법과, 모든 레이아웃을 위한 정확한 슬라이드 HTML 템플릿
- `slide-editing` — 개별 슬라이드를 편집하는 방법
- `deck-management` — 데크가 저장되고 접근되는 방식
- `design-systems` — 디자인 시스템 데이터 형태와 토큰이 생성된 슬라이드에 적용되는 방식
- `creative-context` — 재사용 단계, 검색 절차, Library 제출

#### AGENTS.md

`templates/slides/AGENTS.md`는 에이전트가 모든 대화에서 읽는 짧은 라우터입니다. `.agents/skills/` 아래의 skills를 가리키며 핵심 규칙, 지속성 모델, 애플리케이션 상태 계약을 정리합니다. 슬라이드 레이아웃이나 디자인 시스템 소스를 추가하거나 변경할 때마다 관련 skill을 업데이트하세요.
