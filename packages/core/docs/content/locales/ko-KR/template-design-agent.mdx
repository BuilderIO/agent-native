# Agent와 대화

Design의 모든 기능은 UI가 사용하는 것과 같은 액션을 통해 에이전트에게도
그대로 제공되므로, 클릭으로 할 수 있는 일은 말로도 요청할 수 있습니다. 이
페이지는 에이전트가 화면을 어떻게 인식하는지, 그다음 작업별로 유용한 프롬프트가
무엇인지를 다룹니다. 전체 개요는 [Design](/docs/template-design) 문서를
참고하세요.

## 에이전트가 화면을 보는 방식

무언가를 하기 전에 에이전트는 여러분이 보고 있는 것부터 확인합니다. 어떤
디자인이나 템플릿이 열려 있는지, 어떤 보기에 있는지(디자인 목록, 템플릿,
편집기, 디자인 시스템, 또는 공개 프레젠테이션 보기), 어떤 화면과 요소가
선택되어 있는지, 어떤 검사기 탭이 활성 상태인지(Design, 댓글, 코드 및
측정값), 그리고 어떤 왼쪽 레일 패널이 열려 있는지(파일, 에이전트, 에셋,
가져오기, 도구, 토큰)입니다. "이걸 더 조밀하게 만들어줘"나 "이 버튼의
대비를 고쳐줘" 같은 요청이 화면이나 요소 이름을 말하지 않아도 정확히
처리되는 이유가 바로 이것입니다. "이것"이 무엇을 가리키는지 에이전트는
이미 알고 있습니다.

몇 가지 상황은 에이전트가 다음에 할 일을 바꿉니다.

- **모호한 프롬프트.** 요청이 에이전트가 진행하기에 충분한 정보를 주지 않으면,
  추측하는 대신 전체 화면을 덮는 확인 질문 오버레이를 보여주고, 채팅에서
  답할 때까지 아무것도 생성하지 않고 기다립니다.
- **템플릿에서 만든 디자인.** 에이전트는 이미 템플릿의 고정된 크기와 글꼴을
  알고 있으며, 기존 화면을 다시 생성하거나 크기를 조정하는 대신 있는
  그대로 다듬습니다.
- **비교 중인 변형.** 몇 가지 제안된 조정 중에서 고르는 중이라면, 에이전트는
  아직 남아 있는 것과 이미 고른 것을 알고 있으므로 "두 번째 것 써줘"가
  정확하게 해석됩니다.
- **열려 있는 리뷰 댓글.** 에이전트는 현재 화면에 몇 개의 열린 댓글이 있는지,
  그리고 그중 이미 자기 작업 대기열에 있는 것이 무엇인지 알고 있으므로,
  여러분이 남긴 피드백을 놓치지 않습니다.

## 작업별 유용한 프롬프트

아래 프롬프트는 모두 실제 디자인에 대한 실제 액션이 되며, UI가 읽고 쓰는
것과 동일한 디자인을 대상으로 합니다. 실제로 동작하는 예시 하나를
살펴보겠습니다.

### :green: 일어나는 일

읽기만 하는 질문입니다. 에이전트가 여러분이 보고 있는 화면의 실제 댓글
스레드 개수를 확인한 다음 채팅에서 바로 답합니다. 예를 들면 "열린 댓글
2개, 그중 1개는 이미 제 작업 대기열에 있어요"처럼요. 아무것도 만들거나
편집하지 않았으므로 화면에는 아무 변화가 없습니다.

### 생성하고 다듬기

- **"기술 분석 제품을 위한 랜딩 페이지 방향 세 가지를 만들어줘."** 비교하고 고를 수 있는, 실제로 서로 다른 몇 가지 변형이 나타납니다.
- **"이 대시보드를 운영팀이 훑어보기 쉽게 더 조밀하게 만들어줘."** 선택한 화면이 실시간으로 업데이트됩니다.
- **"이 반복되는 카드를 재사용 가능한 컴포넌트로 만들어줘."** 이후 한 인스턴스에 대한 편집은, 모두 업데이트해 달라고 요청하지 않는 한 다른 인스턴스와 별개로 유지됩니다.
- **"이 버튼에 호버 애니메이션을 추가해줘."** Motion 독을 직접 열지 않아도 모션 트랙이 만들어집니다.
- **"히어로 배경에 웨이브 셰이더를 추가해줘."** 효과 메뉴의 선택기를 거치지 않고 효과를 바로 적용합니다.

### 품질 확인

- **"이 화면에 접근성 감사를 실행해줘."** 에이전트가 확인한 뒤 무엇을 발견했는지 알려줍니다.
- **"방금 발견한 대비 문제를 고쳐줘."** 수정 사항이 디자인에 바로 적용됩니다.

### 외부 콘텐츠 가져오기

- **"이 Figma 프레임을 가져와줘: [링크]."** 프레임이 새로운, 편집 가능한 화면으로 나타납니다.
- **"이 HTML을 새 화면으로 붙여넣어줘."** 가져오기 패널을 직접 열지 않아도 추가됩니다.
- **"우리 가격 페이지를 Figma에서 가져와서 정확히 맞춰줘."** 픽셀 단위로 정확한 가져오기이며, 구조적으로 옮겨올 수 없었던 부분에 대한 충실도 보고서가 함께 옵니다.

### 브랜드와 디자인 시스템

- **"저장된 디자인 시스템을 적용하고 모바일 레이아웃을 단순화해줘."** 이후의 모든 생성이 브랜드에 맞게 유지됩니다.
- **"우리 GitHub 저장소에서 디자인 시스템을 시작해줘."** 추측 대신 실제로 배포된 여러분의 토큰을 인덱싱합니다.
- **"Material 3를 기반으로 디자인 시스템을 만들어줘."** 겉모습만 비슷한 것이 아니라 실제로 유지 관리되는 공개 시스템에서 시작합니다.

### 템플릿

- **"랜딩 페이지 템플릿으로 새 디자인을 시작해줘."** 그 파일, 크기, 잠긴 레이어를 새 디자인으로 복사합니다.
- **"이걸 'Product launch'라는 템플릿으로 저장해줘."** 다음에 여러분이나 이 디자인을 공유받은 누구든 템플릿에서 사용할 수 있습니다.

### 탐색과 정리

- **"개요 캔버스로 전환해줘."** 단일 화면 보기에서 빠져나옵니다.
- **"댓글 탭을 열어줘."** 검사기에서 해당 탭에 초점을 맞춥니다.
- **"이 디자인 이름을 'Q3 launch page'로 바꿔줘."** 디자인이 나열되는 모든 곳에서 즉시 업데이트됩니다.

### 내보내기와 기록

- **"이걸 ZIP으로 내보내줘."** 프로젝트 메뉴를 직접 열지 않아도 다운로드됩니다.
- **"이 화면을 위한 코딩 핸드오프 프롬프트를 복사해줘."** 외부 코딩 에이전트에 바로 붙여넣을 준비가 됩니다.
- **"한 시간 전 버전으로 복원해줘."** 디자인을 그 정확한 저장 시점 상태로 되돌립니다.

</Cards>

## 확장

Design은 확장을 지원합니다. 확장은 여러분이나 에이전트가 만들어 편집기에
붙일 수 있는 작은 샌드박스 위젯입니다. 검사기의 왼쪽 레일에는 확장이
렌더링될 수 있는 슬롯이 있으며, 열려 있는 디자인의 id와 제목, 활성 화면의
파일명과 내용, 현재 보기 모드와 줌, 선택된 화면과 요소, 활성 도구가 이미
준비되어 있습니다. 오늘 편집기에서 보는 에셋 라이브러리, 셰이더 채우기
선택기, 브랜드 토큰 감사기, 모션 프리셋은 모두 같은 슬롯 위에 만들어져
있습니다. 만드는 방법은 [확장](/docs/extensions) 문서를 참고하세요.
