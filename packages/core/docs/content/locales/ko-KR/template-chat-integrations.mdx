# 다중 앱 작업 공간 속 채팅

채팅은 [Dispatch](/docs/template-dispatch) 작업 공간에 속한 여러 앱 중 하나입니다.
이 페이지는 그것이 실제로 무엇을 의미하는지, 즉 연결이 어떻게 동작하는지, 그리고
채팅의 에이전트가 주변의 다른 앱에 어떻게 닿을 수 있는지를 다룹니다. 전체 개요는
[채팅](/docs/template-chat) 문서를 참고하세요.

## 채팅이 Dispatch와 연결되는 방식

이것이 자동으로 이루어지는지는 채팅과 Dispatch를 어떻게 함께 설정했는지에 따라
달라지며, 둘 중 하나가 호스팅되어 있는지 로컬에서 실행 중인지와는 관련이 없습니다.

### 같은 작업 공간: 자동

채팅과 Dispatch가 하나의 Agent-Native 작업 공간에 (`create` 또는 `add-app`을 통해)
함께 생성되거나 추가되어 하나의 단위로 배포되었다면, 이미 하나의 `.env`, 하나의
`A2A_SECRET`, 하나의 작업 공간 레지스트리를 공유합니다. 검색과 인증된 A2A 호출 모두
그 작업 공간이 여러분의 컴퓨터에서 실행되든 프로덕션에서 실행되든 별도로 설정할 것
없이 그대로 동작합니다.

### 별도 배포: 수동 단계 하나

채팅과 Dispatch가 독립적으로 생성된 두 개의 Agent-Native 프로젝트라면, 시크릿을
공유하지 않으므로 아직 서로를 호출할 수 없습니다. 이들을 연결하려면 양쪽 각각에서
수동 단계 하나가 필요합니다. Settings → Agent → 하위 에이전트(Connect agent), 또는
Dispatch → 에이전트 → 외부 에이전트 추가에서 공유 시크릿과 함께
`remote-agents/<id>.json` 리소스를 추가하세요. 전체 과정은
[A2A 프로토콜](/docs/a2a-protocol) 문서를 참고하세요.

어느 쪽 상황인지 확인하려면 두 앱 중 어느 쪽 에이전트에게든 "어떤 앱들을 볼 수
있어?"라고 물어보세요. Dispatch의 답변에 채팅이 빠져 있다면 두 번째 경우에
해당합니다.

## 통합 전략

**다른 앱에 도움 요청하기.** 채팅의 에이전트는 작업 공간에 어떤 앱이 있고 각각이 무엇을
할 수 있는지 찾아볼 수 있습니다. 그런 다음 그중 하나에 특정 액션을 실행하도록
요청하고, 그 답을 대화에서 사용할 수 있습니다. 예를 들어 캘린더가 있는 작업
공간에서 채팅에 "내일 내 캘린더에 뭐가 있어?"라고 물으면, 에이전트가 추측하는 대신
그 질문을 캘린더에 넘깁니다. 채팅이 Google에 대한 캘린더의 연결을 가지고 있을
필요는 없습니다. 캘린더가 이미 가지고 있기 때문입니다.

**관문으로서의 채팅.** 모든 앱의 에이전트에 같은 방식으로 접근할 수 있으므로, 채팅의
대화는 다른 앱에 있는 작업을 시작하기에 자연스러운 장소입니다. 원하는 것을 한
곳에서 설명하면, 에이전트가 어떤 앱이 처리해야 할지 결정합니다. 채팅에는 방해가 될
자체 도메인이 없기 때문에 이 역할에 잘 맞습니다.

**분리된 상태 유지하기.** 채팅은 다른 앱의 자격 증명이 필요하지 않고, 다른 어떤
앱도 채팅의 자격 증명이 필요하지 않습니다. 각 앱은 자신의 연결과 자신의 데이터를
유지합니다. 채팅은 요청을 전달하고 답을 받을 뿐입니다.
