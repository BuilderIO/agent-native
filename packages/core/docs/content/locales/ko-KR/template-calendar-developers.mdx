# 개발자 가이드

이 페이지는 캘린더 템플릿을 커스터마이즈하거나 확장하려는 모든 사람을 위한 것입니다.
빠른 시작, 모든 액션, 데이터 모델, 라우트 구성, 그리고 기능을 추가하는 방법을
다룹니다. 앱이 무엇을 하는지는 [캘린더](/docs/template-calendar) 문서를 참고하세요.

## 빠른 시작

아무것도 설치되지 않은 상태에서 시작해 Google Calendar를 연결하기까지 캘린더를
실행하는 과정을 안내합니다. macOS의 터미널이든 Windows의 PowerShell/명령
프롬프트든 명령어는 동일합니다. 순수한 Node.js 도구이기 때문입니다.

<Steps>

### 앱 만들기

```bash
npx @agent-native/core@latest create my-calendar --standalone --template calendar
cd my-calendar
pnpm install
```

이를 위해서는 먼저 [Node.js](https://nodejs.org) 22 이상과 [pnpm](https://pnpm.io)이
설치되어 있어야 합니다. 아직 설치하지 않았거나 LLM 연결(Builder.io, Anthropic/OpenAI
키, 또는 로컬 Ollama)을 설정하지 않았다면 [시작하기](/docs/getting-started) 문서를
참고하세요.

### 개발 서버 시작하기

```bash
pnpm dev
```

앱이 `http://localhost:8082`에서 열립니다. 자동으로 열리지 않으면 브라우저에서 해당
URL로 직접 접속하세요. 캘린더는 Google이 연결되지 않은 상태에서도 완전히 동작합니다.
Google 연결이 필요한 액션을 연결하기 전에 시도할 때만 오류가 발생합니다.

### Google Calendar 연결하기

앱에서 **설정**을 열고, **일반** 탭에서 **Google Calendar** 카드를 찾은 다음
**Google Calendar 연결**을 클릭하세요. 설정 마법사가 열립니다.

1. **Google Cloud 프로젝트 만들기** (사용할 프로젝트가 아직 없다면):
   [Google Cloud Console](https://console.cloud.google.com/)에서 페이지 상단
   근처의 프로젝트 드롭다운을 클릭한 다음 **New Project**를 클릭하세요. 원하는
   이름을 지정하고 **Create**를 클릭한 다음, 준비되었다는 알림을 기다리세요.
   계속하기 전에 같은 드롭다운에서 해당 프로젝트가 선택되어 있는지 확인하세요.
2. **API 활성화하기**: 프로젝트를 선택한 상태에서 **APIs & Services → Library**로
   이동해 "Google Calendar API"를 검색하고, 열어서 **Enable**을 클릭하세요.
3. **동의 화면 구성하기**: **APIs & Services → OAuth consent screen**에서 동의
   화면을 설정하세요(개발용으로는 "External"이면 충분합니다).
4. **자격 증명 만들기**: **APIs & Services → Credentials**에서 "Web application"
   유형의 OAuth 클라이언트 ID를 만들고, `http://localhost:8082/_agent-native/google/callback`을
   승인된 리디렉션 URI로 추가하세요(8082는 캘린더의 기본 개발 포트입니다).
5. **자격 증명 추가하기**: 자격 증명 JSON을 다운로드해 마법사에 업로드하거나,
   "Paste manually"를 켜고 Client ID와 Client Secret을 직접 입력하세요.

캘린더는 이 값들을 `.env` 파일이 아니라 자체 시크릿 저장소에 저장하므로, 이 단계는
Windows와 macOS에서 동일합니다. 연결되면 토큰은 자동으로 갱신됩니다.

### Zoom 연결하기(선택 사항)

Google과 달리 Zoom은 설정 화면이 없습니다. 프로젝트 루트에 `.env` 파일을
만들거나(이미 있다면 기존 파일에 추가) 다음을 입력하세요.

```text
ZOOM_CLIENT_ID=your-client-id
ZOOM_CLIENT_SECRET=your-client-secret
```

[Zoom OAuth 앱](https://marketplace.zoom.us/)(Zoom Marketplace → Develop → Build
App → OAuth)에서 Client ID와 Secret을 받고, 리디렉션 URI로
`/_agent-native/zoom/callback`을 설정한 다음, 새 값을 반영하도록 `pnpm dev`를
다시 시작하세요. Zoom을 연결하지 않아도 예약 링크는 Google Meet를 제공할 수
있으며, Zoom만 제공하지 못합니다.

</Steps>

<Callout tone="warning">

Windows에서는 일부 편집기가 `.env`라는 이름으로 파일을 저장할 때 숨겨진 `.txt`
확장자를 붙여서, 캘린더가 절대 읽지 않는 `.env.txt` 파일이 만들어지는 경우가
있습니다. 파일 탐색기에서 "파일 확장명" 표시를 켜고(보기 탭), 저장된 파일 이름이
정확히 `.env`이고 뒤에 아무것도 붙지 않았는지 확인하세요.

</Callout>

<Callout tone="info">

**이벤트는 SQL이 아니라 Google Calendar에 있습니다.** 모든 이벤트 액션은 Google
Calendar API를 직접 호출합니다. 로컬 이벤트 테이블은 존재하지 않습니다. 예약
링크, 예약, 가용성, 연결 상태만 로컬에 저장됩니다. 이벤트 데이터는 원시 SQL로
읽거나 쓰지 마세요.

</Callout>

## 액션 목록

모든 작업은 `templates/calendar/actions/` 안의 TypeScript 파일이며,
`POST /_agent-native/actions/:name`에 자동으로 마운트됩니다.

### 이벤트와 게스트

이벤트 데이터는 Google Calendar에 있으며 절대 SQL에 저장되지 않습니다.

| 액션 | 동작 |
| --- | --- |
| `list-events` | 날짜 범위 내 이벤트 목록 조회 |
| `search-events` | 검색어로 이벤트 검색 |
| `get-event` | id로 이벤트 하나 조회 |
| `create-event` | 반복 규칙(RRULE), 근무 위치, 상태 유형(`outOfOffice`, `focusTime`)을 포함해 이벤트 생성 |
| `update-event` | 반복, 근무 위치, 상태 유형을 포함해 이벤트 수정 |
| `delete-event` | 이벤트 삭제 |
| `manage-event-draft` | 아무것도 기록되거나 게스트에게 알림이 가기 전에, 사용자가 검토할 미발송 초대를 임시 저장 |
| `rsvp-event` | 초대에 대해 수락, 거절, 또는 미정으로 표시 |
| `get-attendee-timezones` | 게스트별 시간대 재정의 값 조회 |
| `set-attendee-timezone` | 게스트의 현지 시간이 올바르게 표시되도록 게스트별 시간대 재정의 값 설정 |

### 가용성과 시간 찾기

| 액션 | 동작 |
| --- | --- |
| `get-availability` | 주간 일정, 시간대, 버퍼, 통보 기간, 사전 예약 기간 설정 조회 |
| `update-availability` | 주간 일정, 시간대, 버퍼, 통보 기간, 사전 예약 기간 설정 수정 |
| `check-availability` | 특정 날짜의 빈 시간대 조회 |
| `find-a-time` | 주최자와 지정된 참석자들 전체를 대상으로 하는 공용 빈 시간 검색으로, Google 프리/비지와 로컬 충돌을 결합 |

### 예약 링크와 예약

| `delete-staged-dataset` | 저장된 데이터셋 삭제 |

## 액션 하나를 자세히 살펴보기

`create-booking-link`은 어떤 액션에서든 재사용할 만한 패턴을 보여줍니다.
데이터베이스에 닿기 전에 입력을 검증하기, 두 테이블에 걸친 규칙을 강제하기,
로그인한 사용자를 안전하게 확인하기, 그리고 모든 리더에서 각각 처리하는 대신 한

## 커스터마이즈하기

앱의 모든 부분은 편집 가능한 소스입니다. 여기서부터 시작하세요.

- `templates/calendar/actions/` — 새 기능을 에이전트와 프런트엔드 모두에
  노출하려면 `defineAction`으로 새 파일을 추가하세요.
- `templates/calendar/app/routes/` — UI. 위에 나열되어 있습니다.
- `templates/calendar/server/db/schema.ts` — Drizzle로 컬럼이나 테이블을
  추가하세요. 템플릿이 SQLite, Postgres, Turso, D1, Neon에서 모두 동작하도록
  코드를 방언에 구애받지 않게 유지하세요.
- `templates/calendar/server/lib/` — 프로바이더 통합: `google-calendar.ts`,
  `zoom.ts`, `people-search.ts`, `ical-fetcher.ts`, `find-time.ts`,
  `provider-api.ts`.
- `templates/calendar/AGENTS.md` — 에이전트 지침입니다. 에이전트에게 새로운
  기능이나 규칙을 가르칠 때 이 파일을 업데이트하세요.
- `templates/calendar/.agents/skills/` — 에이전트가 따르는 세부 패턴입니다.
  관련 skills: `event-management`, `availability-booking`, `real-time-sync`,
  `storing-data`, `delegate-to-agent`, `frontend-design`.
- `templates/calendar/shared/api.ts` — 서버와 클라이언트 양쪽에서 사용하는
  공유 TypeScript 타입(`CalendarEvent`, `BookingLink`, `ExternalCalendar`,
  `ConferencingConfig` 등)입니다.

기능을 추가한다면 네 가지 영역을 모두 업데이트해야 한다는 것을 기억하세요: UI,
액션, skill 또는 AGENTS.md 항목, 그리고 에이전트가 봐야 하는 애플리케이션
상태입니다. 이것이 에이전트와 UI를 동등하게 유지하는 방법입니다.
