# AWS Amplify

<Badge label="Beta" color="orange" icon="rocket" />

AWS Amplify Hosting आपके ऐप को Git repository से build करता है और आपके लिए host
करता है, इसलिए कोई server set up करने या चालू रखने की ज़रूरत नहीं होती। Amplify
ऐप की static files CloudFront के ज़रिए serve करता है, ऐप के pages और API के लिए
उसका server चलाता है, और ऐप को HTTPS के साथ एक public address देता है।

यह guide शुरुआत से एक standalone ऐप deploy करने के चरण बताती है। आप ऐप बनाकर
उसे Git repository में push करेंगे, उसे production database और auth secret
देंगे, database तैयार करेंगे, Amplify की build settings जोड़ेंगे, और फिर Amplify
ऐप बनाएंगे।

<Callout tone="info">

Node.js `22.22+` आवश्यक है।

</Callout>

आपको एक AWS account और GitHub, GitLab, Bitbucket, या AWS CodeCommit पर एक
repository भी चाहिए। इस guide के commands अपने computer पर चलाएं। Amplify आपकी
repository से ऐप को build करके चलाता है।

## चरण 1: ऐप बनाएं {#step-1-create-the-app}

अपना नया standalone ऐप बनाएं। नीचे दिया गया उदाहरण Chat template से ऐप बनाता है,
लेकिन आप किसी भी template से शुरू कर सकते हैं। ऐप के folder में जाएं और उसकी
dependencies install करें। `corepack enable` वह `pnpm` version चालू करता है
जिसकी ऐप को ज़रूरत है, इसलिए आपको `pnpm` खुद install करने की ज़रूरत नहीं है।

```bash
npx --yes @agent-native/core@latest create my-app --standalone --template chat

cd my-app

corepack enable

pnpm install
```

चाहें तो `my-app` को अपने ऐप के नाम से बदल दें। इस guide का बाकी हिस्सा मानता है
कि आप ऐप के folder के अंदर हैं।

Amplify ऐप को Git repository से build करता है, इसलिए आगे बढ़ने से पहले ऐप के
folder को एक नई repository में push करें। चरण 4 में आप एक और file जोड़कर फिर से
push करेंगे।

## चरण 2: Environment secrets configure करें {#step-2-configure-environment-secrets}

ऐप अपनी production settings environment variables से पढ़ता है:

| Variable             | आवश्यक | उद्देश्य                                                       |
| -------------------- | ------ | -------------------------------------------------------------- |
| `DATABASE_URL`       | हां    | ऐप को उसके PostgreSQL database से connect करता है              |
| `BETTER_AUTH_SECRET` | हां    | User sessions sign करता है                                     |
| `BETTER_AUTH_URL`    | नहीं   | वह public address सेट करता है जिससे लोग आपके ऐप तक पहुंचते हैं |

नीचे दिए गए exports से आगे के commands इस shell में काम करते हैं। Deploy करने
से पहले, यही variables अपने host की project या service environment settings में
save करें। चरण 5 बताता है कि उन्हें Amplify में कैसे save करें।

<Callout tone="warning">

Amplify environment variables को build तक पहुंचाता है, लेकिन चलते हुए server तक
नहीं। उन्हें उपलब्ध कराने के लिए, Agent-Native build ऐप के declared variables को
server bundle के अंदर एक `.env` file में लिख देता है। ऐप के deployment artifacts
तक access रखने वाला कोई भी व्यक्ति वह file पढ़ सकता है, इसलिए अपने AWS account
में सीमित करें कि उन तक कौन पहुंच सकता है।

</Callout>

### Database URL {#database-url}

Local development के दौरान, `DATABASE_URL` unset होने पर ऐप data को local
database में store करता है। Deployed ऐप को एक असली PostgreSQL database चाहिए जो
deploys के बीच अपना data बनाए रखे। Amplify requests के बीच files नहीं रखता,
इसलिए database को Amplify के बाहर होना चाहिए। अपने provider से connection string
copy करें और उसे export करें:

```bash
export DATABASE_URL='your-postgres-url-string'
```

[Database provider guides](/docs/neon) बताती हैं कि हर provider के लिए connection
string कहां मिलती है, जिसमें [Amazon RDS for PostgreSQL](/docs/aws-rds) भी शामिल
है।

<Callout tone="warning">

एक persistent PostgreSQL provider चुनें: Neon, Supabase, Amazon RDS, आदि।

</Callout>

### Auth secret {#auth-secret}

इसे एक बार generate करें और सभी deploys में इसे एक जैसा रखें।

ऐप user sessions sign करने के लिए `BETTER_AUTH_SECRET` का उपयोग करता है। अगर यह
बदलता है, तो हर signed-in user sign out हो जाता है। नीचे दिया गया command एक
random value generate करता है:

```bash
export BETTER_AUTH_SECRET="$(openssl rand -hex 32)"
```

Generate की गई value को किसी सुरक्षित जगह save करें, जैसे password manager में।
हर बार deploy करते समय यही value इस्तेमाल करें।

### Public URL {#public-url}

वैकल्पिक। इसे तब सेट करें जब आप custom domain, reverse proxy, या ऐसा auth/OAuth
flow इस्तेमाल करें जिसे fixed public origin चाहिए।

`BETTER_AUTH_URL` वह public address है जिससे लोग आपके ऐप तक पहुंचते हैं। इसके
बिना, ऐप हर incoming request से अपना address पता करता है। Amplify के दिए गए
address पर आमतौर पर यह ठीक रहता है, लेकिन custom domain connect करते समय इसे सेट
करें, ताकि sign-in links और OAuth redirects उसी domain का इस्तेमाल करें।

```bash
export BETTER_AUTH_URL='https://your-domain.example'
```

## चरण 3: Migrate करें {#step-3-migrate}

Migrations आपके database में वे tables बनाती और update करती हैं जिनकी ऐप को
ज़रूरत है। पहले deploy से पहले इसे चलाएं:

```bash
pnpm migrate:production
```

यह command आपके computer पर चलता है और चरण 2 में export किए गए `DATABASE_URL` से
production database से connect करता है। ऐप upgrade करने के बाद, नया version
deploy करने से पहले इसे फिर से चलाएं।

## चरण 4: Amplify की build settings जोड़ें {#step-4-add-amplifys-build-settings}

ऐप के root folder में, `package.json` के बगल में, `amplify.yml` नाम की एक file
बनाएं, और उसमें यह copy करें:

```yaml filename="amplify.yml"
version: 1
frontend:
  phases:
    preBuild:
      commands:
        - nvm install 24
        - corepack enable
        - pnpm install
    build:
      commands:
        - NITRO_PRESET=aws_amplify pnpm build
  artifacts:
    baseDirectory: .amplify-hosting
    files:
      - "**/*"
```

यह file Amplify को बताती है कि ऐप को कैसे build करना है:

- **preBuild** build को Node.js 24 पर switch करता है, ऐप का `pnpm` version चालू
  करता है, और dependencies install करता है।
- **build** ऐप को `NITRO_PRESET=aws_amplify` के साथ build करता है, जो वह format
  है जिसकी Amplify Hosting को उम्मीद होती है।
- **artifacts** Amplify को बताता है कि build जो `.amplify-hosting` folder बनाता है,
  उसे deploy करना है।

Build वह सब कुछ उसी folder में लिखता है जिसकी Amplify को ज़रूरत होती है:

<FileTree
  id="aws-amplify-build-output"
  entries={[
    {
      path: ".amplify-hosting/static/",
      note: "ऐप की static files, जो CloudFront के ज़रिए serve होती हैं।",
    },
    {
      path: ".amplify-hosting/compute/default/server.js",
      note: "Amplify के compute पर ऐप का server start करता है।",
    },
    {
      path: ".amplify-hosting/compute/default/.env",
      note: "ऐप के declared variables, जो build के दौरान copy किए जाते हैं।",
    },
    {
      path: ".amplify-hosting/deploy-manifest.json",
      note: "Static files को static host पर और बाकी हर request को server पर भेजता है।",
    },
  ]}
/>

`amplify.yml` को commit करें और अपनी repository में push करें।

## चरण 5: Amplify ऐप बनाएं {#step-5-create-the-amplify-app}

[Amplify console](https://console.aws.amazon.com/amplify/) में ऐप बनाएं:

<Steps>

### Repository connect करें

**Deploy an app** चुनें। **Start building with Amplify** page पर, अपना Git
provider चुनें, फिर **Next** चुनें। पहली बार Amplify आपकी repositories पढ़ने की
permission मांगता है।

### Branch चुनें

**Add repository branch** page पर, चरण 1 की repository और branch चुनें, फिर
**Next** चुनें।

### Build settings जांचें

**App settings** page पर, Amplify `amplify.yml` से build settings पढ़ता है। जांचें
कि **Build output directory** `.amplify-hosting` है।
**Create and use a new service role** चुनें।

### Environment variables जोड़ें

**Advanced settings** के अंदर, `DATABASE_URL` और `BETTER_AUTH_SECRET` को चरण 2 में
export की गई values के साथ जोड़ें। अगर आपने `BETTER_AUTH_URL` सेट किया है, तो उसे
भी इसी तरह जोड़ें। फिर **Next** चुनें।

### Deploy करें

**Review** page पर, **Save and deploy** चुनें।

</Steps>

## चरण 6: ऐप खोलें {#step-6-open-the-app}

पहले build में कुछ मिनट लगते हैं, और आप Amplify console में उसे देख सकते हैं।
पूरा होने पर ऐप का address खोलें, जो
`https://main.d1m7bkiki6tdw1.amplifyapp.com` जैसा दिखता है, और पहला account
बनाएं।

फिर जांचें कि:

- Home page load होता है।
- `/assets/` के अंदर की कोई file load होती है, जिससे पता चलता है कि static files
  serve हो रही हैं।
- आप sign in कर सकते हैं, और आपका बनाया data reload के बाद भी बना रहता है।

## Updates deploy करें {#deploy-updates}

हर बार जब आप चरण 5 में चुनी गई branch पर push करते हैं, Amplify फिर से build और
deploy करता है। नया version ship करने के लिए, पहले migrations चलाएं, फिर push
करें:

```bash
pnpm migrate:production

git push
```

Build environment variables को server bundle में copy करता है, इसलिए किसी
variable का बदलाव अगले build के बाद ही लागू होता है। Amplify console में कोई
variable बदलने के बाद, एक commit push करें या latest build को redeploy करें।

## Caching {#caching}

Amplify ऐप को CloudFront के ज़रिए serve करता है। ऐप का public page shell यह
`Cache-Control` header भेजता है, और Amplify उसका पालन करता है:

```txt
public, max-age=600, stale-while-revalidate=604800, stale-if-error=3600
```

CloudFront shell को दस मिनट तक fresh रखता है, नई copy fetch करते समय पुरानी copy
serve कर सकता है, और error के दौरान भी उसे serve कर सकता है। Personal data page
खुलने के बाद browser में load होता है, इसलिए वह कभी shared shell में नहीं पहुंचता।
Static files एक साल तक cache होती हैं, और हर नया deploy Amplify का cache clear कर
देता है।

Amplify की default **Remove cookies from cache key** setting को चालू रखें।
`customHttp.yml` में global `Cache-Control` rule न जोड़ें, क्योंकि वह private
routes पर `no-store` header को override कर सकता है। Shell cache को छोटा या बंद
करने के लिए, `AGENT_NATIVE_SSR_CACHE` सेट करें। [SSR कैशिंग](/docs/ssr-caching)
पूरी policy समझाता है।

## Agent responses stream करें {#stream-agent-responses}

Amplify का CloudFront path किसी response के छोटे chunks को रोककर रख सकता है, इसलिए
agent chat replies शब्द-दर-शब्द आने के बजाय टुकड़ों में आ सकते हैं। उन्हें सीधे
stream करने के लिए, Agent-Native एक अलग Lambda function जोड़ सकता है जो सिर्फ chat
stream serve करता है:

```bash
npx agent-native amplify-stream \
  --amplify-app-id your-amplify-app-id \
  --branch main \
  --region us-east-1 \
  --env-file .env
```

यह command chat stream को Node.js 24 Lambda function के रूप में build करता है,
जिसमें streaming function URL और 15 मिनट का timeout होता है। यह function का
address Amplify branch पर save करता है और एक नया release शुरू करता है। Browser
बाकी सब कुछ के लिए Amplify ऐप ही इस्तेमाल करता रहता है और function को सिर्फ chat
requests भेजता है।

यह command ऐप के variables उस file से पढ़ता है जिसे आप `--env-file` के साथ देते
हैं, इसलिए उस file में Amplify ऐप जैसे ही `DATABASE_URL`, `BETTER_AUTH_SECRET`,
और बाकी values होने चाहिए। इसे ऐसे AWS CLI credentials भी चाहिए जो Lambda, IAM,
और Amplify को manage कर सकें। Release शुरू किए बिना address save करने के लिए
`--skip-release` जोड़ें। अगर stream function उपलब्ध नहीं है, तो chat सामान्य
Amplify route पर वापस चला जाता है।
