# Run Context

`run` को एक वैकल्पिक दूसरा argument मिलता है, `ctx`, जो resolved request पहचान और action को invoke करने वाली सतह को carry करता है। हाथ से `getRequestUserEmail()` / `getRequestOrgId()` कॉल करने के बजाय इसे पढ़ें, और पूरे `ctx` को tracking में पास करें:

```ts
export default defineAction({
  description: "Log an audit entry for the current request.",
  schema: z.object({ event: z.string() }),
  run: async (args, ctx) => {
    // ctx is undefined-safe: a 1-arg `run(args)` is still valid.
    const actor = ctx?.userEmail ?? "system";
    if (ctx?.caller === "frontend") {
      // tighter rules for browser-initiated calls, looser for "tool"/"cli"
    }
    await db.insert(audit).values({
      actor,
      orgId: ctx?.orgId ?? null,
      source: ctx?.caller ?? "unknown",
      event: args.event,
    });
    return { ok: true };
  },
});
```

अधिकतर actions कभी भी केवल `ctx?.userEmail` और `ctx?.orgId` पढ़ते हैं, [access-control scoping](/docs/actions-access-control#access-control) जो लगभग हर वास्तविक action में उपयोग होता है। इस पेज का बाकी हिस्सा tracking और automation attribution जैसे cross-cutting concerns को कवर करता है, जिनकी ज़रूरत कम actions को होती है।

## `ctx` argument {#ctx}

`ctx` दो तरह की जानकारी carry करता है: resolved request पहचान (`userEmail`, `orgId`) जो लगभग हर कॉल पर मौजूद होती है, और action को invoke करने वाली सतह के बारे में metadata (`caller`, साथ ही `threadId` या `automation` जैसे सतह-विशिष्ट फ़ील्ड जो केवल कुछ कॉलर्स के लिए भरे जाते हैं)। `run()` के दूसरे argument के रूप में पूरी संरचना:

`run()` backward compatible बना रहता है: मौजूदा 1-argument handlers और वे handlers जो केवल `{ send }` destructure करते हैं, बिना बदलाव के काम करना जारी रखते हैं।

### `caller` union {#caller}

`caller` union है `"tool" | "http" | "frontend" | "cli" | "mcp" | "a2a" | "automation"`:

| `caller`       | कब सेट होता है…                                                                                                                                                     |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `"tool"`       | in-app एजेंट लूप, कोई sub-agent या agent team, या natural-language cross-app A2A delegation, जो उसी एजेंट लूप को चलाता है, इसलिए इसके tool calls `"tool"` होते हैं।    |
| `"frontend"`   | `useActionMutation()`, `useActionQuery()`, या `callAction()` के माध्यम से एक ब्राउज़र कॉल (`X-Agent-Native-Frontend: 1` header के साथ टैग किया गया)।                 |
| `"http"`       | फ्रंटएंड मार्कर के बिना `/_agent-native/actions/<name>` पर एक साधारण प्रोग्रामेटिक `POST` या `GET`।                                                                    |
| `"cli"`        | `pnpm action <name>` (CLI runner)।                                                                                                                                     |
| `"mcp"`        | MCP `tools/call` endpoint पर एक बाहरी एजेंट।                                                                                                                           |
| `"a2a"`        | एक signed A2A delegation token carry करने वाला `/_agent-native/actions/<name>` पर सीधा HTTP कॉल। यह एक स्पष्ट रूप से एक्सपोज़्ड, cross-app dispatch है, ऊपर दिए गए natural-language `"tool"` पथ से अलग। |
| `"automation"` | किसी stored workspace trigger से dispatch किया गया event-triggered automation। `ctx.automation` trigger lineage carry करता है। [Automations](/docs/automations) देखें।  |
