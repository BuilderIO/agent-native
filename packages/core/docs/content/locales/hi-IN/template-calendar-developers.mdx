# डेवलपर गाइड

यह पेज उन सभी के लिए है जो कैलेंडर टेम्पलेट को कस्टमाइज़ या एक्सटेंड कर रहे
हैं: क्विक स्टार्ट, हर action, डेटा मॉडल, रूट सरफेस, और इसमें कुछ जोड़ने का
तरीका। ऐप क्या करता है यह जानने के लिए [कैलेंडर](/docs/template-calendar)
देखें।

## क्विक स्टार्ट

यह कुछ भी इंस्टॉल न होने से लेकर एक कनेक्टेड Google Calendar तक, कैलेंडर
चलाने का पूरा तरीका बताता है। कमांड वही रहते हैं चाहे आप macOS पर Terminal
में हों या Windows पर PowerShell/Command Prompt में, ये सादे Node.js टूलिंग
हैं।

<Steps>

### ऐप बनाएं

```bash
npx @agent-native/core@latest create my-calendar --standalone --template calendar
cd my-calendar
pnpm install
```

इसके लिए पहले [Node.js](https://nodejs.org) 22 या उसके बाद का वर्शन और
[pnpm](https://pnpm.io) इंस्टॉल होना चाहिए। अगर आपने अभी तक इनमें से कोई
इंस्टॉल नहीं किया है, या आपके पास कोई LLM कनेक्शन (Builder.io, कोई
Anthropic/OpenAI key, या लोकल Ollama) सेट अप नहीं है, तो [शुरुआत
करें](/docs/getting-started) देखें।

### डेव सर्वर शुरू करें

```bash
pnpm dev
```

ऐप `http://localhost:8082` पर खुलता है। अगर यह अपने आप न खुले, तो अपने
ब्राउज़र में वह URL खोलें। Google डिस्कनेक्ट होने पर भी कैलेंडर पूरी तरह
काम करता है। आपको एरर सिर्फ़ तब मिलेगा जब आप कनेक्ट करने से पहले कोई ऐसा
action ट्राई करें जिसे इसकी ज़रूरत हो।

### Google Calendar कनेक्ट करें

ऐप में, **Settings** खोलें, और **General** टैब में **Google Calendar** कार्ड
ढूंढें, फिर **Google Calendar कनेक्ट करें** पर क्लिक करें। इससे एक सेटअप विज़ार्ड
खुलता है:

1. **एक Google Cloud प्रोजेक्ट बनाएं**, अगर आपके पास इस्तेमाल करने के लिए
   पहले से कोई नहीं है: [Google Cloud Console](https://console.cloud.google.com/)
   में, पेज के ऊपर की तरफ़ प्रोजेक्ट ड्रॉपडाउन पर क्लिक करें, फिर **New
   Project**। इसे कोई भी नाम दें, **Create** पर क्लिक करें, और तैयार होने के
   नोटिफिकेशन का इंतज़ार करें। आगे बढ़ने से पहले पक्का कर लें कि यह उसी
   ड्रॉपडाउन में सिलेक्टेड है।
2. **API इनेबल करें**: अपना प्रोजेक्ट सिलेक्ट करके, **APIs & Services →
   Library** पर जाएं, "Google Calendar API" सर्च करें, इसे खोलें, और
   **Enable** पर क्लिक करें।
3. **कंसेंट स्क्रीन कॉन्फ़िगर करें**: **APIs & Services → OAuth consent
   screen** के तहत, एक सेट अप करें ("External" डेवलपमेंट के लिए ठीक है)।
4. **क्रेडेंशियल बनाएं**: **APIs & Services → Credentials** के तहत, "Web
   application" टाइप का एक OAuth client ID बनाएं, और
   `http://localhost:8082/_agent-native/google/callback` को authorized
   redirect URI के तौर पर जोड़ें (8082 कैलेंडर का डिफ़ॉल्ट डेव पोर्ट है)।
5. **क्रेडेंशियल जोड़ें**: credentials JSON डाउनलोड करें और विज़ार्ड में
   अपलोड करें, या "Paste manually" टॉगल करें और Client ID और Client Secret
   सीधे डालें।

कैलेंडर इन्हें अपने secret store में सेव करता है, किसी `.env` फ़ाइल में
नहीं, इसलिए यह स्टेप Windows और macOS पर एक जैसा ही है। कनेक्ट होने के बाद
टोकन अपने आप रिफ्रेश होते हैं।

### Zoom कनेक्ट करें (वैकल्पिक)

Google के उलट, Zoom का कोई Settings फ़ॉर्म नहीं है। प्रोजेक्ट रूट में एक
`.env` फ़ाइल बनाएं (या मौजूदा में जोड़ें) इसके साथ:

```text
ZOOM_CLIENT_ID=your-client-id
ZOOM_CLIENT_SECRET=your-client-secret
```

[Zoom OAuth app](https://marketplace.zoom.us/) से एक Client ID और Secret लें
(Zoom Marketplace → Develop → Build App → OAuth), redirect URI के तौर पर
`/_agent-native/zoom/callback` के साथ, फिर नई वैल्यू पिक करने के लिए
`pnpm dev` को रीस्टार्ट करें। Zoom कनेक्ट न होने पर भी, बुकिंग लिंक Google
Meet ऑफर कर सकते हैं, सिर्फ़ Zoom नहीं।

</Steps>

<Callout tone="warning">

Windows पर, कुछ एडिटर `.env` नाम की फ़ाइल सेव करते समय एक छुपा हुआ `.txt`
एक्सटेंशन जोड़ देते हैं, जिससे एक `.env.txt` बन जाती है जिसे कैलेंडर कभी
नहीं पढ़ता। File Explorer में, "File name extensions" (View टैब) ऑन करें और
पुष्टि करें कि सेव की गई फ़ाइल का नाम ठीक `.env` है, आगे कुछ भी नहीं।

</Callout>

<Callout tone="info">

**इवेंट Google Calendar में रहते हैं, SQL में नहीं।** हर इवेंट action सीधे
Google Calendar API को कॉल करता है, कोई लोकल events टेबल नहीं है। सिर्फ़
बुकिंग लिंक, बुकिंग्स, उपलब्धता, और कनेक्शन स्टेट लोकली स्टोर होते हैं। इवेंट
डेटा को कभी raw SQL से न पढ़ें और न लिखें।

</Callout>

## Actions की इन्वेंटरी

हर ऑपरेशन `templates/calendar/actions/` में एक TypeScript फ़ाइल है, जो अपने
आप `POST /_agent-native/actions/:name` पर माउंट हो जाती है।

### इवेंट्स और गेस्ट

इवेंट डेटा Google Calendar में रहता है, कभी SQL में नहीं।

| Action | यह क्या करता है |
| --- | --- |
| `list-events` | किसी डेट रेंज में इवेंट लिस्ट करें |
| `search-events` | किसी क्वेरी से इवेंट सर्च करें |
| `get-event` | id से एक इवेंट पढ़ें |
| `create-event` | एक इवेंट बनाएं, जिसमें recurrence (RRULE), working locations, और status types (`outOfOffice`, `focusTime`) शामिल हैं |
| `update-event` | एक इवेंट अपडेट करें, जिसमें recurrence, working locations, और status types शामिल हैं |
| `delete-event` | एक इवेंट डिलीट करें |
| `manage-event-draft` | कुछ भी लिखे या गेस्ट को नोटिफ़ाई किए जाने से पहले, यूज़र रिव्यू के लिए एक भेजा न गया इनवाइट स्टेज करें |
| `rsvp-event` | किसी इनविटेशन पर Accept, decline, या tentative मार्क करें |
| `get-attendee-timezones` | पर-गेस्ट टाइमज़ोन ओवरराइड पढ़ें |
| `set-attendee-timezone` | एक पर-गेस्ट टाइमज़ोन ओवरराइड सेट करें ताकि उनका लोकल टाइम सही दिखता रहे |

### उपलब्धता और समय ढूंढना

| Action | यह क्या करता है |
| --- | --- |
| `get-availability` | साप्ताहिक शेड्यूल, टाइमज़ोन, बफर, नोटिस, और advance-window सेटिंग पढ़ें |
| `update-availability` | साप्ताहिक शेड्यूल, टाइमज़ोन, बफर, नोटिस, और advance-window सेटिंग अपडेट करें |
| `check-availability` | किसी एक डेट के लिए खाली स्लॉट ढूंढें |
| `find-a-time` | किसी organizer और नामित attendees में शेयर्ड फ्री-स्लॉट सर्च, Google free/busy को लोकल कॉन्फ्लिक्ट के साथ मिलाकर |

### बुकिंग लिंक और बुकिंग्स

| Action | यह क्या करता है |
| --- | --- |
| `create-booking-link` | एक बुकिंग लिंक बनाएं |
| `update-booking-link` | एक बुकिंग लिंक अपडेट करें |
| `duplicate-booking-link` | एक बुकिंग लिंक डुप्लिकेट करें, को-होस्ट (`hosts`) के साथ |
| `list-booking-links` | एक्सेस किए जा सकने वाले बुकिंग लिंक लिस्ट करें |
| `list-bookings` | कन्फर्म्ड अपॉइंटमेंट लिस्ट करें |

### एक्सटर्नल कैलेंडर

रीड-ओनली ICS फ़ीड।

| Action | यह क्या करता है |
| --- | --- |
| `add-external-calendar` | एक रीड-ओनली ICS/webcal फ़ीड सब्सक्राइब करें |
| `list-external-calendars` | सब्सक्राइब्ड फ़ीड लिस्ट करें |
| `remove-external-calendar` | एक सब्सक्राइब्ड फ़ीड हटाएं |
| `update-external-calendars` | सब्सक्राइब्ड फ़ीड अपडेट करें |

### लोग और ओवरले

| Action | यह क्या करता है |
| --- | --- |
| `search-people` | Google Contacts और Workspace डायरेक्टरी सर्च करें |
| `get-overlay-people` | वे दूसरे लोग पढ़ें जिनके कैलेंडर आपके व्यू में पिन किए गए हैं |
| `update-overlay-people` | वे दूसरे लोग अपडेट करें जिनके कैलेंडर आपके व्यू में पिन किए गए हैं |

### Zoom

| Action | यह क्या करता है |
| --- | --- |
| `get-zoom-status` | वर्तमान यूज़र का Zoom कनेक्शन स्टेटस पढ़ें। Connect और disconnect `/_agent-native/zoom/*` रूट्स के ज़रिए होते हैं, किसी action से नहीं, क्योंकि OAuth को signed-in ब्राउज़र सेशन की ज़रूरत होती है |

### Google Calendar कनेक्शन और सिंक

| Action | यह क्या करता है |
| --- | --- |
| `connect-google-calendar` | signed-in ब्राउज़र सेशन के लिए OAuth connect URL रिटर्न करें |
| `sync-google-calendar` | एक resync फोर्स करें |

### Settings और प्रेफरेंस

| Action | यह क्या करता है |
| --- | --- |
| `get-settings` | यूज़र-लेवल सेटिंग पढ़ें |
| `update-settings` | यूज़र-लेवल सेटिंग अपडेट करें |
| `update-calendar-visual-preferences` | लोकल-ओनली डिस्प्ले प्रेफरेंस अपडेट करें (event colors, hidden weekends)। कभी Google Calendar को टच नहीं करता |

### नेविगेशन और UI स्टेट

| Action | यह क्या करता है |
| --- | --- |
| `navigate` | UI को किसी व्यू, डेट, या इवेंट पर मूव करें |
| `view-screen` | एजेंट के लिए वर्तमान व्यू पढ़ें |

### Provider API एस्केलेशन

असली Google Calendar (और कनेक्टेड CRM) API, उन मामलों के लिए जब ऊपर दिए
actions बहुत संकरे हों।

| Action | यह क्या करता है |
| --- | --- |
| `provider-api-catalog` | सीधे कॉल करने के लिए उपलब्ध असली provider APIs लिस्ट करें |
| `provider-api-docs` | किसी असली provider API endpoint के लिए डॉक्यूमेंटेशन पढ़ें |
| `provider-api-request` | असली Google Calendar (या कनेक्टेड CRM) API को सीधे कॉल करें |
| `list-staged-datasets` | असली नतीजे लौटाने के बजाय, क्वेरी के लिए स्टेज किए गए बड़े स्कैन लिस्ट करें |
| `query-staged-dataset` | किसी स्टेज्ड डेटासेट को क्वेरी करें |
| `delete-staged-dataset` | किसी स्टेज्ड डेटासेट को डिलीट करें |

## एक action को स्टेप-बाय-स्टेप समझना

`create-booking-link` कुछ ऐसे पैटर्न दिखाता है जो किसी भी action में दोबारा
इस्तेमाल करने लायक हैं: डेटाबेस को टच करने से पहले इनपुट को वैलिडेट करना, दो
टेबल के बीच एक rule लागू करना, signed-in यूज़र को सुरक्षित तरीके से resolve
करना, और हर reader में बार-बार करने के बजाय एक बार में किसी फ्लेक्सिबल इनपुट
शेप को नॉर्मलाइज़ करना।

## इसे कस्टमाइज़ करना

ऐप का हर हिस्सा एडिटेबल सोर्स है। यहां से शुरू करें:

- `templates/calendar/actions/` — एजेंट और फ्रंटएंड दोनों को नई क्षमता
  एक्सपोज़ करने के लिए `defineAction` के साथ एक नई फ़ाइल जोड़ें।
- `templates/calendar/app/routes/` — UI, जो ऊपर लिस्ट किया गया है।
- `templates/calendar/server/db/schema.ts` — Drizzle के साथ columns या
  tables जोड़ें। कोड को dialect-agnostic रखें ताकि टेम्पलेट SQLite, Postgres,
  Turso, D1, और Neon पर चले।
- `templates/calendar/server/lib/` — provider integrations: `google-calendar.ts`, `zoom.ts`, `people-search.ts`, `ical-fetcher.ts`, `find-time.ts`, `provider-api.ts`।
- `templates/calendar/AGENTS.md` — एजेंट के निर्देश। जब भी आप एजेंट को नई
  क्षमताएं या conventions सिखाएं, इसे अपडेट करें।
- `templates/calendar/.agents/skills/` — वे डिटेल्ड पैटर्न जिन्हें एजेंट
  फॉलो करता है। संबंधित skills: `event-management`, `availability-booking`,
  `real-time-sync`, `storing-data`, `delegate-to-agent`, `frontend-design`।
- `templates/calendar/shared/api.ts` — शेयर्ड TypeScript types
  (`CalendarEvent`, `BookingLink`, `ExternalCalendar`, `ConferencingConfig`,
  आदि) जो server और client दोनों इस्तेमाल करते हैं।

अगर आप कोई feature जोड़ते हैं, तो सभी चार क्षेत्रों को अपडेट करना याद रखें:
UI, action, skill या AGENTS.md एंट्री, और कोई भी application state जो एजेंट
को देखना ज़रूरी है। यही वो चीज़ है जो एजेंट और UI को parity में रखती है।
