# डेवलपर गाइड

यह पेज उन डेवलपर्स के लिए है जो चैट टेम्पलेट चला रहे हैं या उसे एक्सटेंड कर रहे हैं।
इसमें क्विक स्टार्ट, हर बिल्ट-इन action, डेटा मॉडल, एक action का वॉकथ्रू, रूट्स, और
अपना पहला फ़ीचर जोड़ने का तरीका शामिल है। ऐप क्या करता है यह जानने के लिए
[चैट](/docs/template-chat) देखें।

## क्विक स्टार्ट {#quick-start}

यह कुछ भी इंस्टॉल न होने से लेकर एजेंट के साथ लाइव बातचीत तक, चैट चलाने का पूरा
तरीका बताता है। कमांड वही रहते हैं चाहे आप macOS पर Terminal में हों या Windows पर
PowerShell/Command Prompt में, ये सादे Node.js टूलिंग हैं।

<Steps>

### ऐप बनाएं

```bash
npx --yes @agent-native/core@latest create my-chat-app --standalone --template chat
cd my-chat-app
corepack enable
pnpm install
```

इसके लिए [Node.js](https://nodejs.org) 22.22 या उसके बाद का वर्शन चाहिए। अगर `pnpm`
आपके `PATH` में नहीं है, तो जनरेट किए गए ऐप में `corepack enable` चलाएं। अगर आपने
अभी तक Node.js इंस्टॉल नहीं किया है, तो [शुरुआत
करें](/docs/getting-started) देखें।

### डेव सर्वर शुरू करें

```bash
pnpm dev
```

ऐप उस लोकल URL पर खुलता है जो `pnpm dev` प्रिंट करता है। अगर यह अपने आप न खुले, तो
अपने ब्राउज़र में वह URL खोलें। अगर 8080 पहले से इस्तेमाल में है तो पोर्ट बदल सकता है।

### साइन इन करें और एक LLM कनेक्ट करें

Welcome स्क्रीन पर **Continue as local dev** चुनें। लोकल डेवलपमेंट के लिए ईमेल या
पासवर्ड की ज़रूरत नहीं है। फिर एक LLM कनेक्ट करें: मुफ़्त क्रेडिट के लिए **Builder.io इस्तेमाल करें** चुनें, या अपनी खुद की मॉडल प्रोवाइडर key इस्तेमाल करने के लिए **अपनी कुंजियाँ जोड़ें** चुनें। चैट में सीड करने के लिए कोई डोमेन डेटा नहीं आता, इसलिए LLM कनेक्ट होते
ही बातचीत शुरू करने से पहले और कुछ सेट अप करने की ज़रूरत नहीं है।

</Steps>

चैट ब्राउज़र UI के लिए बनी है। अगर आप बिना किसी स्क्रीन वाला एजेंट चाहते हैं, यानी
शेड्यूल्ड जॉब्स, क्यू, CLI लूप, या एक्सटर्नल-एजेंट वर्कफ़्लो के लिए, तो इसके बजाय
`--headless` के साथ स्कैफ़ोल्ड करें:

```bash
npx --yes @agent-native/core@latest create my-agent --headless
```

मुख्य विचार वही रहता है। Actions चैट, UI, HTTP, MCP, A2A, और CLI की साझा सतह हैं। उस
रास्ते की पूरी जानकारी के लिए [Automation-First Apps](/docs/pure-agent-apps) देखें।

## Action इन्वेंटरी {#actions}

हर ऑपरेशन `actions/` में एक TypeScript फ़ाइल है, जो `POST
/_agent-native/actions/:name` पर अपने आप माउंट होती है, जब तक action `http: false`
सेट न करे।

| Action                 | यह क्या करता है                                                                 |
| ---------------------- | ------------------------------------------------------------------------------- |
| `hello`                | उदाहरण action। एक ग्रीटिंग लौटाता है। इसे बदलें या इसके बगल में actions जोड़ें। |
| `view-screen`          | स्टैंडर्ड कॉन्टेक्स्ट action। एजेंट के लिए मौजूदा व्यू वापस पढ़ता है।           |
| `navigate`             | स्टैंडर्ड नेविगेशन action। UI को किसी रूट पर ले जाता है।                        |
| `provider-api-request` | कनेक्टेड Slack वर्कस्पेस के ज़रिए Slack Web API को कॉल करता है।                 |

### चैट रनटाइम {#chat-runtime}

`server/plugins/agent-chat.ts` वह जगह है जहां चैट रनटाइम कॉन्फ़िगर होता है। यह चार काम
करता है:

- `actions/` में मौजूद हर action को callable टूल के रूप में रजिस्टर करता है,
  `loadActionsFromStaticRegistry` के साथ।
- स्कोपिंग के लिए मौजूदा organization को resolve करता है, `resolveOrgId` के साथ।
- सिस्टम प्रॉम्प्ट सेट करता है।
- यह घोषित करता है कि पहले टर्न पर मॉडल को कौन से टूल दिखते हैं, `initialToolNames`
  के साथ।

### Actions टूल कैसे बनते हैं {#actions-as-tools}

हर `defineAction` डिफ़ॉल्ट रूप से एक टूल है। किसी action को अपनी स्क्रीन के लिए उपलब्ध
रखने और एजेंट से छिपाने के लिए `agentTool: false` सेट करें।

### मॉडल को पहले क्या दिखता है {#initial-tools}

`INITIAL_TOOL_NAMES` में `view-screen`, `navigate`, `hello`, और `provider-api-request`
की सूची है। पहले टर्न पर सिर्फ़ यही टूल भेजे जाते हैं। बाकी सब कुछ, आपके जोड़े गए
action सहित, `tool-search` से पहुंच में रहता है और ज़रूरत पड़ने पर लोड होता है।

उस सूची में कोई नाम तभी जोड़ें जब आप चाहें कि action पहले मैसेज से ही मॉडल के डिफ़ॉल्ट
टूलसेट में हो।

## डेटा मॉडल {#data-model}

चैट अपनी कोई टेबल नहीं बनाती। जब तक आप एक नहीं जोड़ते, `server/db/schema.ts` मौजूद नहीं
होता। ऐप चैट थ्रेड्स और मैसेज, application state, settings, सेशन, resources, और रन
हिस्ट्री के लिए फ़्रेमवर्क की कोर टेबल्स पर चलता है। ये फ़्रेमवर्क की हैं, इसलिए इन्हें
एडिट न करें। कनेक्शन मॉडल और नया डेटा कहां रखें, इसके लिए [Database](/docs/server-database)
देखें।

`useDbSync()` पहले से ऐप शेल में जुड़ा हुआ है। जब एजेंट या कोई और SQL में लिखता है, तो
क्लाइंट को बदलाव SSE से, या 2 सेकंड के पोलिंग फ़ॉलबैक से मिलता है, और वह मेल खाने वाले
React Query कैश को invalidate कर देता है। पूरे हुक API के लिए
[`useDbSync`](/docs/client-data#usedbsync) देखें।

आपकी पहली टेबल एक नई फ़ाइल है। [अपना पहला फ़ीचर जोड़ें](#first-feature) देखें।

## Auth {#auth}

Auth Better Auth पर चलता है: लॉगिन, साइनअप, सेशन, और organizations। चैट इसे
`server/plugins/auth.ts` में `createToolkitAuthPlugin` से कॉन्फ़िगर करती है। यह फ़ाइल `/`
को सार्वजनिक रखती है, ताकि साइन-इन लैंडिंग लोड हो सके, और `marketing: false` सेट करती
है, इसलिए साइन-इन पेज पर कोई मार्केटिंग कॉपी नहीं होती। वहाँ ऐप का नाम, टैगलाइन, और
फ़ीचर बुलेट्स दिखाने के लिए इसकी जगह `marketing` ऑब्जेक्ट पास करें। वही फ़्लो लोकली और
प्रोडक्शन में चलता है, सिवाय इसके कि डेवलपमेंट में ईमेल वेरिफ़िकेशन छोड़ दिया जाता है
ताकि आप तुरंत साइन अप करके बनाना शुरू कर सकें। पूरे auth मॉडल (सेशन, organizations,
प्रोटेक्टेड रूट्स) के लिए [प्रमाणीकरण](/docs/authentication) देखें।

रूट फ़ाइल जोड़ना ही उसे माउंट करने के लिए काफ़ी है।

**Database** (`/database`) वही `DbAdminPage` है जो हर टेम्पलेट को मिलता है। यह ऐप के SQL
डेटाबेस पर एक सीधा टेबल ब्राउज़र और एडिटर है। इसके पीछे के कनेक्शन मॉडल के लिए
[Database](/docs/server-database) देखें।

**अवलोकनक्षमता** (`/observability`) वही zero-config `ObservabilityDashboard` है जो हर
टेम्पलेट को मिलता है। यह हर एजेंट रन के लिए ट्रेसेस, कॉस्ट, evals, और फ़ीडबैक दिखाता है,
जिसकी गणना आपके अपने डेटाबेस में पहले से मौजूद डेटा से होती है। [Agent
Observability](/docs/observability) देखें।

**एक्सटेंशन** sandboxed Alpine.js मिनी-ऐप्स हैं। चैट उन्हें देखने और चलाने वाले रूट्स
(`/extensions/:id`) माउंट करती है और `/extensions` को `/settings/extensions` पर रीडायरेक्ट
करती है। चैट एक्सटेंशन को दो जगह बंद रखती है। Settings पेज तभी दिखता है जब
`app/routes/settings.tsx` `useAgentSettingsTabs()` को `extensionTools: true` पास करे।
एजेंट एक्सटेंशन तभी बना सकता है जब `server/plugins/agent-chat.ts` में
`frameworkTools.extensions` चालू हो। ये क्या कर सकते हैं और क्या नहीं, यह जानने के लिए
[Extensions](/docs/extensions) देखें।

## इसे कस्टमाइज़ करना {#customizing}

ऐप का हर हिस्सा एडिट करने योग्य सोर्स है। यहां से शुरू करें:

- `actions/`: एजेंट और फ्रंटएंड दोनों के लिए नया action एक्सपोज़ करने के लिए
  `defineAction` के साथ नई फ़ाइल जोड़ें।
- `app/routes/`: UI। कोई पेज माउंट करने के लिए रूट फ़ाइल जोड़ें।
- `server/db/schema.ts`: जब कोर टेबल्स कम पड़ने लगें, तो Drizzle के साथ अपनी टेबल्स जोड़ें।
  कोड को PostgreSQL-specific रखें ताकि लोकल PGlite और होस्टेड Postgres में एक जैसा
  व्यवहार रहे।
- `AGENTS.md`: एजेंट के निर्देश। जब आप एजेंट को नए actions या कन्वेंशन सिखाएं, तो इसे
  अपडेट करें।
- `.agents/skills/`: विस्तृत पैटर्न जिन्हें एजेंट फ़ॉलो करता है।

अगर आप कोई फ़ीचर जोड़ते हैं, तो सभी चार क्षेत्रों को अपडेट करना याद रखें: UI, action,
skill या `AGENTS.md` एंट्री, और कोई भी application state जो एजेंट को देखना ज़रूरी है।
यही वो चीज़ है जो एजेंट और UI को parity में रखती है।

### चैट रूट {#chat-route}

`app/components/chat/ChatRouteContent.tsx` `/chat/<threadId>` पर पूरे पेज की चैट रेंडर
करता है। चैट सतह AgentKit के हिस्सों से बनी है: एक transport, एक थ्रेड रूट, और चैट
व्यू। इसकी कॉपी लिटरल स्ट्रिंग्स के बजाय i18n keys से आती है। असली फ़ाइल इससे लंबी है।
यह वह हिस्सा है जिसे आप सबसे ज़्यादा एडिट करते हैं।

### अपना खुद का एजेंट बैकएंड इस्तेमाल करें {#own-agent-backend}

टेम्पलेट डिफ़ॉल्ट रूप से बिल्ट-इन app-agent लूप इस्तेमाल करता है। कस्टम बैकएंड जोड़ने के
लिए, UI को दोबारा लिखने के बजाय agent chat plugin के पीछे का चैट रनटाइम बदलें। चैट रूट
को साझा चैट सतह के आस-पास एक पतला renderer ही रहना चाहिए, और बैकएंड का चुनाव सर्वर
प्लगइन और रनटाइम adapter में होना चाहिए।

इसका इस्तेमाल तब करें जब आपका मॉडल ऑर्केस्ट्रेशन पहले से कहीं और हो, पर आप फिर भी
auth, थ्रेड्स, actions, UI state, और डिप्लॉय करने योग्य पेजों वाला ऐप चाहते हों। रनटाइम
विकल्पों के लिए [Native Chat UI](/docs/native-chat-ui#byo-agent-runtimes) देखें।

## अपना पहला फ़ीचर जोड़ें {#first-feature}

ज़्यादातर पहले फ़ीचर एक ही ढांचे पर चलते हैं: एक टेबल, एक या दो actions, एक पेज, एक नेव
एंट्री, और एक `AGENTS.md` अपडेट। यह सेक्शन चार हिस्सों में एक नोट्स फ़ीचर बनाता है,
हर फ़ाइल के पूरे कोड के साथ। आप यह सब एजेंट से भी करवा सकते हैं:

> Add a data model for `notes`. A note has an id, title, body, and owner. Render a notes page at `/notes`, add create/list actions, and keep chat able to create notes.

### 1. डेटा लेयर जोड़ें

चैट में `server/db` फ़ोल्डर नहीं आता, इसलिए यहां की तीनों फ़ाइलें नई हैं।

स्कीमा टेबल्स को डिफ़ाइन करता है। `ownableColumns()` ओनर, organization, और visibility
कॉलम जोड़ता है, और `createSharesTable()` शेयरिंग के लिए एक मेल खाती टेबल जोड़ता है।

```ts filename="server/db/schema.ts"
import { sql } from "drizzle-orm";
import { pgTable, text } from "drizzle-orm/pg-core";
import {
  createSharesTable,
  ownableColumns,
} from "@agent-native/core/db/schema";

export const notes = pgTable("notes", {
  id: text("id").primaryKey(),
  title: text("title").notNull(),
  body: text("body").notNull(),
  createdAt: text("created_at")
    .notNull()
    .default(sql`now()`),
  ...ownableColumns(),
});

export const noteShares = createSharesTable("note_shares");
```

डेटाबेस क्लाइंट आपके actions को `getDb()` देता है और नोट्स को शेयरिंग सिस्टम में रजिस्टर
करता है। नोट्स का कोई डिटेल पेज नहीं है, इसलिए शेयर लिंक सूची पर ले जाते हैं।

```ts filename="server/db/index.ts"
import { createGetDb } from "@agent-native/core/db";
import { registerShareableResource } from "@agent-native/core/sharing";

import * as schema from "./schema.js";

export const getDb = createGetDb(schema);
export { schema };

registerShareableResource({
  type: "note",
  resourceTable: schema.notes,
  sharesTable: schema.noteShares,
  displayName: "Note",
  titleColumn: "title",
  getResourcePath: () => "/notes",
  getDb,
});
```

माइग्रेशन ऐप शुरू होने पर टेबल्स बनाता है। बाद के बदलावों के लिए नई एंट्रीज़ जोड़ें, और जो
एंट्री एक बार चल चुकी हो उसे कभी एडिट न करें।


### 2. Actions जोड़ें

हर action `actions/` में एक फ़ाइल है, और फ़ाइल का नाम ही टूल का नाम बन जाता है। एजेंट और
आपका पेज यही दो actions कॉल करते हैं।

`create-note` साइन-इन किए हुए यूज़र को ओनर के रूप में दर्ज करता है। अगर कोई organization
एक्टिव है तो नोट organization को दिखता है, वरना सिर्फ़ उसके बनाने वाले को।

```ts filename="actions/create-note.ts"
import { defineAction, fail } from "@agent-native/core/action";
import { z } from "zod";

import { getDb, schema } from "../server/db/index.js";

export default defineAction({
  description:
    "Create a note with a title and body. It is visible to the organization when one is active, otherwise only to its creator.",
  schema: z.object({
    title: z.string().min(1).describe("Short title for the note"),
    body: z.string().describe("Full text of the note"),
  }),
  run: async (args, ctx) => {
    const ownerEmail =
      ctx?.userEmail ?? fail("Sign in to create notes.", { statusCode: 401 });
    const orgId = ctx?.orgId ?? null;
    const note = {
      id: crypto.randomUUID(),
      title: args.title,
      body: args.body,
      ownerEmail,
      orgId,
      visibility: orgId ? ("org" as const) : ("private" as const),
    };
    await getDb().insert(schema.notes).values(note);
    return { id: note.id, title: note.title };
  },
});
```

`list-notes` रीड-ओनली है, और `accessFilter` नतीजों को उन नोट्स तक सीमित करता है जो
मौजूदा यूज़र देख सकता है।

```ts filename="actions/list-notes.ts"
import { defineAction } from "@agent-native/core/action";
import { accessFilter } from "@agent-native/core/sharing";
import { desc } from "drizzle-orm";
import { z } from "zod";

import { getDb, schema } from "../server/db/index.js";

export default defineAction({
  description: "List the notes the current user can see, newest first.",
  schema: z.object({}),
  http: { method: "GET" },
  readOnly: true,
  run: async () => {
    const { notes, noteShares } = schema;
    const rows = await getDb()
      .select({
        id: notes.id,
        title: notes.title,
        body: notes.body,
        createdAt: notes.createdAt,
      })
      .from(notes)
      .where(accessFilter(notes, noteShares))
      .orderBy(desc(notes.createdAt))
      .limit(200);
    return { notes: rows };
  },
});
```

नया action बनते ही चैट उसे कॉल कर सकती है। अगर आप इसे मॉडल के डिफ़ॉल्ट टूलसेट में चाहते हैं तो
[मॉडल को पहले क्या दिखता है](#initial-tools) देखें।

### 3. पेज और साइडबार लिंक जोड़ें

ऐप फ़ाइल-सिस्टम राउटिंग इस्तेमाल करता है, इसलिए यह फ़ाइल जोड़ने से `/notes` माउंट हो जाता है।
पेज `useActionQuery()` और `useActionMutation()` से वही actions कॉल करता है जो एजेंट करता है,
और सफल mutation सूची को अपने आप रिफ़्रेश कर देता है।

```tsx filename="app/routes/notes.tsx"
import {
  useActionMutation,
  useActionQuery,
} from "@agent-native/core/client/hooks";
import { useSetPageTitle } from "@agent-native/toolkit/app-shell";
import { useState, type FormEvent } from "react";
import { toast } from "sonner";

import { Button } from "@/components/ui/button";
import { Input } from "@/components/ui/input";
import { Skeleton } from "@/components/ui/skeleton";
import { APP_TITLE } from "@/lib/app-config";

export function meta() {
  return [{ title: `Notes - ${APP_TITLE}` }];
}

export default function NotesRoute() {
  useSetPageTitle("Notes");
  const { data, isLoading } = useActionQuery("list-notes");
  const createNote = useActionMutation("create-note", {
    onError: (error) => toast.error(error.message),
  });
  const [title, setTitle] = useState("");
  const [body, setBody] = useState("");

  function handleSubmit(event: FormEvent) {
    event.preventDefault();
    createNote.mutate(
      { title, body },
      {
        onSuccess: () => {
          setTitle("");
          setBody("");
        },
      },
    );
  }

  return (
    <div className="mx-auto flex h-full max-w-2xl flex-col gap-6 overflow-auto p-6">
      <form onSubmit={handleSubmit} className="flex flex-col gap-2">
        <Input
          value={title}
          onChange={(event) => setTitle(event.target.value)}
          placeholder="Title"
          required
        />
        <Input
          value={body}
          onChange={(event) => setBody(event.target.value)}
          placeholder="Write a note"
        />
        <Button type="submit" disabled={createNote.isPending}>
          Add note
        </Button>
      </form>
      <ul className="flex flex-col gap-2">
        {isLoading && (
          <>
            <Skeleton className="h-16 w-full" />
            <Skeleton className="h-16 w-full" />
          </>
        )}
        {data?.notes.map((note) => (
          <li key={note.id} className="rounded-lg border p-3">
            <p className="font-medium">{note.title}</p>
            <p className="text-sm text-muted-foreground">{note.body}</p>
          </li>
        ))}
      </ul>
    </div>
  );
}
```
