# अवलोकन

Actions आपके ऐप द्वारा की जाने वाली हर चीज़ के लिए एकमात्र सत्य स्रोत हैं। `defineAction()` के साथ एक को परिभाषित करें और उसे `actions/` में रखें। नीचे दी गई हर सतह इसे अपने आप उठा लेती है। आप लॉजिक केवल एक बार लिखते हैं। किसी भी सतह की अपनी अलग कॉपी नहीं होती, और कोई भी दूसरों से आउट-ऑफ़-सिंक नहीं हो सकती।

<Cards columns={2}>

### :robot: [एजेंट टूल](/docs/agent-surfaces)

एजेंट description और schema को एक कॉल करने योग्य टूल के रूप में पढ़ता है। इसे चैट में मांगें, जैसे "इस टिकट का जवाब दें" या "इस थ्रेड को सारांशित करें"।

### :components: [UI हुक](/docs/client-data)

`useActionQuery()`, `useActionMutation()`, और `callAction()` React से उसी action को कॉल करते हैं। एक क्लिक और एक चैट मैसेज बिल्कुल वही ऑपरेशन चलाते हैं।

### :server: [फ्रेमवर्क ट्रांसपोर्ट](/docs/http-api)

स्टार्टअप पर `/_agent-native/actions/<name>` पर ऑटो-माउंट होता है। UI हुक अंदर से इसी रूट को कॉल करते हैं, और कोई बाहरी HTTP क्लाइंट भी इसे सीधे कॉल कर सकता है।

### :plug: [MCP टूल](/docs/actions-other-surfaces#mcp)

किसी भी MCP होस्ट को एक टूल के रूप में दिखता है: Claude, Claude Desktop, Cursor, Codex। इसका उपयोग तब करें जब कोई अलग AI क्लाइंट आपके ऐप को चलाए।

### :network: [A2A टूल](/docs/actions-other-surfaces#a2a)

अन्य एजेंट-नेटिव ऐप्स इसे A2A के माध्यम से खोजते और कॉल करते हैं। इसका उपयोग तब करें जब आपके वर्कस्पेस में कोई दूसरा ऐप इसे अपनी ओर से कार्य करने के लिए चाहता हो।

### :terminal: [CLI कमांड](/docs/actions-other-surfaces#cli)

`pnpm action <name>` इसे टर्मिनल से चलाता है। इसका उपयोग स्क्रिप्ट्स, cron jobs, और त्वरित मैनुअल टेस्ट के लिए करें।

</Cards>

अधिकतर ऐप्स फ्रंटएंड और डेटाबेस के बीच एक अलग API लेयर बनाते हैं, जिसे केवल ब्राउज़र ही कॉल कर सकता है। जो एजेंट वही क्षमता चाहता है उसे अपना अलग इंटीग्रेशन चाहिए, जिसे फिर से लिखना और मेंटेन करना पड़ता है। एजेंट-नेटिव ऐप्स उस विभाजन को छोड़ देते हैं। UI और एजेंट बिल्कुल वही action कॉल करते हैं, इसलिए लिखने के लिए केवल एक इम्प्लीमेंटेशन है, और किसी बग के छुपने के लिए केवल एक जगह है।

अगर UI और एजेंट दोनों को कुछ करने की आवश्यकता है, तो एक कस्टम रूट के बजाय action का उपयोग करें। उस दुर्लभ स्थिति के लिए जहां route-shaped प्रोटोकॉल सही विकल्प है, [ऐप ऑपरेशंस के लिए Actions को प्राथमिकता दें](/docs/server-overview#actions-first) पर जाएं।

## Actions कहां फिट होते हैं {#role}

`app/` ([Client अवलोकन](/docs/client-overview#role) देखें) और एजेंट दोनों एक ही actions और एक ही SQL डेटाबेस पर रिज़ॉल्व होते हैं। यहां कोई अलग "app backend" नहीं है जिससे यह लेयर बात करती हो और जिसे एजेंट न पहुंच सके। कोई फ़ीचर बनाने का मतलब है यहां एक ऑपरेशन परिभाषित करना और उसके लिए एक साथ एक UI, एक एजेंट टूल, और हर दूसरी सतह पाना।

`actions/` स्वयं एक फ़्लैट फ़ोल्डर है। हर फ़ाइल एक action है: फ़ाइल के डिफ़ॉल्ट एक्सपोर्ट के रूप में एक्सपोर्ट किया गया `defineAction()` कॉल। फ्रेमवर्क स्टार्टअप पर इस फ़ोल्डर को स्कैन करता है और जो भी फ़ाइल मिलती है उसे माउंट करता है। कोई रजिस्ट्रेशन स्टेप नहीं है और कोई इंडेक्स फ़ाइल नहीं है जिसे अपडेट रखना पड़े।

किसी action की `run()` बॉडी सामान्य सर्वर कोड होती है, इसलिए यह आमतौर पर कुछ अन्य डायरेक्टरी में पहुंचती है:

`actions/` के बाहर किसी को भी किसी action के `run` फ़ंक्शन को सीधे इम्पोर्ट नहीं करना चाहिए। इसके बजाय इसे ऊपर दी गई किसी सतह के माध्यम से कॉल करें: एजेंट टूल, एक UI हुक, HTTP, MCP, A2A, या CLI। इनमें से हर पथ वही schema validation, access जांच, और audit trail चलाता है।

## एक action से शुरू करें {#hello-action}

चैट-फर्स्ट ऐप में पहला ऑपरेशन बहुत छोटा हो सकता है। Chat टेम्पलेट में,
`actions/hello.ts` को बदलें या उसके बगल में एक नई फ़ाइल जोड़ें:

```ts
// actions/hello.ts
import { defineAction } from "@agent-native/core/action";
import { z } from "zod";

export default defineAction({
  description: "Say hello from the local agent.",
  schema: z.object({
    name: z.string().default("world"),
  }),
  http: { method: "GET" },
  readOnly: true,
  run: async ({ name }) => {
    return { message: `Hello, ${name}!` };
  },
});
```

इसे उसी फ़ोल्डर से चलाएं:

```bash
pnpm action hello '{"name":"Steve"}'
```

CLI action input के रूप में एक JSON ऑब्जेक्ट स्वीकार करता है, जो उन structured
tool calls से मेल खाता है जो एजेंट पहले से करते हैं। त्वरित मैनुअल रन के लिए
साधारण flags भी काम करते हैं:

```bash
pnpm action hello --name Steve
```

फिर फ़ोल्डर के विरुद्ध app-agent लूप चलाएं:

```bash
npx agent-native agent "Call hello for Steve and explain the result"
```

यह वही app-agent लूप है जिसका उपयोग आपकी scheduled jobs, चैट UI, बाहरी MCP
टूल, और भविष्य की स्क्रीन करेंगी। Chat और domain टेम्पलेट actions के इर्द-गिर्द
UI जोड़ने के लिए हैं, न कि स्वयं action के लिए एक आवश्यक पूर्वापेक्षा।
