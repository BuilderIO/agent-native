# रिकॉर्डर

रिकॉर्डर इन-मेमोरी रखा गया एक छोटा रिकॉर्ड है, जिसमें संवेदनशील जानकारी छिपी रहती है। इसमें दर्ज होता है कि किसी Agent-Native ऐप ने अभी-अभी क्या किया। हर ऐप पिछले दो मिनट के अपने actions, `application_state` राइट, रूट बदलाव, त्रुटियाँ और त्रुटि toasts रिकॉर्ड करता है, और इसके लिए ऐप कोड की ज़रूरत नहीं होती। कुछ गड़बड़ होने पर वही रिकॉर्ड एक रिपोर्ट बन जाता है, जिसे ऐप का एजेंट, कोई Clips रिकॉर्डिंग, Sentry या आपका अपना डेस्टिनेशन पढ़ सकता है।

```ts
import { recorder } from "@agent-native/core/client/recorder";

const report = recorder.report();
```

जब तक कोई रिपोर्ट कहीं भेजी नहीं जाती, तब तक सर्वर पर कुछ भी स्टोर नहीं होता और कुछ भी ब्राउज़र से बाहर नहीं जाता। रिकॉर्डर खुद कोई नेटवर्क रिक्वेस्ट नहीं करता।

## यह क्या कैप्चर करता है {#captured}

| प्रकार   | स्रोत                                                                                                                    | उदाहरण                                                                                  |
| -------- | ------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| `action` | हर `useActionQuery()`, `useActionMutation()` और `callAction()` कॉल। बैच में पढ़े गए हर action का अपना अलग इवेंट होता है। | `200` लौटाने वाले बैच के अंदर `list-folders` `403` और `forbidden_scope` के साथ विफल हुआ |
| `state`  | हर `application_state` राइट और डिलीट, जिनमें विफल या रद्द हुए भी शामिल हैं                                               | `design-selection` ने `state` को `hover` से `focus` में बदला                            |
| `nav`    | रूट बदलाव। सिर्फ़ पाथ रखा जाता है।                                                                                       | `/design/d_8f2c1a`                                                                      |
| `error`  | न पकड़ी गई त्रुटियाँ और बिना हैंडल किए गए promise rejection, पहले स्टैक फ़्रेम के साथ                                    | `/app/pages/design-editor/commands/undo.ts:1715` पर `TypeError`                         |
| `toast`  | उपयोगकर्ता को दिखे त्रुटि और चेतावनी toasts                                                                              | `This screen changed elsewhere. Your edit was not saved.`                               |
| `log`    | वे इवेंट जिन्हें ऐप `recorder.log()` से जोड़ता है                                                                        | `f_1` से `f_9` तक `screen.restored`                                                     |

हर इवेंट में एक जैसे फ़ील्ड होते हैं:

| फ़ील्ड      | अर्थ                                                                                                                      |
| ----------- | ------------------------------------------------------------------------------------------------------------------------- |
| `t`         | रिपोर्ट बनने से कितने सेकंड पहले। यह ऋणात्मक होता है।                                                                     |
| `at`        | Epoch मिलीसेकंड। Clips डायग्नोस्टिक्स भी इसी घड़ी का उपयोग करते हैं।                                                      |
| `type`      | `action`, `state`, `nav`, `error`, `toast` या `log`                                                                       |
| `name`      | action का नाम, स्टेट कुंजी, रूट पाथ, त्रुटि का प्रकार, toast का स्तर या लॉग का नाम                                        |
| `ok`        | action या स्टेट राइट सफल हुआ या नहीं                                                                                      |
| `status`    | HTTP स्टेटस, अगर कोई था                                                                                                   |
| `errorCode` | action का त्रुटि कोड। ऐप ने जिस कॉल या राइट को रद्द किया, उसमें `errorCode: "cancelled"` होता है।                         |
| `ms`        | action या स्टेट राइट में कितना समय लगा                                                                                    |
| `requestId` | सर्वर की रिक्वेस्ट id, जो उसके लॉग और उसके Sentry इवेंट में भी दिखती है                                                   |
| `data`      | संवेदनशील जानकारी छिपाए गए, सीमित आकार के विवरण। action में उसका HTTP मेथड होता है, और विफल होने पर उसका त्रुटि संदेश भी। |

स्टेट राइट सिर्फ़ वही दर्ज करता है जो उस कुंजी के पिछले सेव हुए मान के बाद बदला। किसी कुंजी का पहला राइट `data.value` दर्ज करता है। बाद के राइट `data.changed` दर्ज करते हैं, जिसमें हटाया गया फ़ील्ड `"[removed]"` दिखता है। जिस राइट ने कुछ नहीं बदला, वह `data.unchanged` दर्ज करता है, और डिलीट `data.deleted` दर्ज करता है। विफल राइट में `data.error` भी होता है, और अगले राइट की तुलना फिर भी पिछले सेव हुए मान से ही होती है।

## रिपोर्ट {#reports}

एक रिपोर्ट में विंडो के इवेंट होते हैं, साथ ही वे मान जिन पर ऐप नज़र रखता है और वह काम जो अभी चल रहा है।

```json
{
  "app": "design",
  "build": "59929e9",
  "url": "/design/d_8f2c1a?file=[redacted]",
  "at": "2026-10-14T16:20:05.120Z",
  "reason": "user",
  "windowSeconds": 120,
  "events": [
    {
      "t": -12.4,
      "at": 1791994792720,
      "type": "state",
      "name": "design-selection",
      "ok": true,
      "ms": 41,
      "data": { "changed": { "state": "hover" } }
    },
    {
      "t": -10.9,
      "at": 1791994794220,
      "type": "action",
      "name": "update-file",
      "ok": true,
      "status": 200,
      "ms": 180,
      "requestId": "req_a1",
      "data": { "method": "POST" }
    }
  ],
  "watched": {
    "inspector": {
      "state": "focus",
      "fields": [{ "label": "Opacity", "shown": "91%" }]
    }
  },
  "pending": [],
  "dropped": 0
}
```

- **app**: ऐप की id। अगर यह न हो, तो पेज का होस्ट इस्तेमाल होता है, जैसे `localhost:8080`, इसलिए यह कभी खाली नहीं होती।
- **url**: रूट पाथ। हर query मान छिपाया जाता है और hash छोड़ दिया जाता है।
- **windowSeconds**: रिपोर्ट कितने सेकंड को कवर करती है।
- **pending**: अभी चल रहे actions और स्टेट राइट, हर एक के साथ उसका `ageMs`।
- **dropped**: पेज लोड होने या उपयोगकर्ता के साइन आउट करने के बाद से सीमाओं की वजह से खोए इवेंट। जो इवेंट पुराने होकर विंडो से बाहर हो गए, वे नहीं गिने जाते।

## SDK {#sdk}

### `recorder.report()` {#report}

`recorder.report()` मौजूदा रिपोर्ट लौटाता है। यह सिंक्रोनस है। यह एक वैकल्पिक ऑब्जेक्ट लेता है:

- **seconds**: विंडो के सिर्फ़ आख़िरी `seconds` सेकंड रखें।
- **reason**: `"user"`, `"error"`, `"test"` या `"manual"`। डिफ़ॉल्ट `"manual"` है।

```ts
const report = recorder.report();
```

छोटे हिस्से के लिए `seconds` पास करें, जैसे किसी रिकॉर्डिंग के शुरू होने से पहले का आधा मिनट:

```ts
const before = recorder.report({ seconds: 30 });
```

`"manual"` को छोड़कर हर कारण रिपोर्ट को `recorder.onReport()` के लिसनर को भी भेजता है। सादा `recorder.report()` कॉल ऐसा कभी नहीं करता, इसलिए कोई लिसनर बिना लूप बनाए रिपोर्ट बना सकता है।

### `recorder.log()` {#log}

`recorder.log()` ऐप के अपने शब्दों में एक इवेंट जोड़ता है। यह एक नाम और वैकल्पिक डेटा लेता है। जो डेटा सादा ऑब्जेक्ट नहीं है, वह `{ value }` के रूप में दर्ज होता है।

Design हर उस स्क्रीन की नई id लॉग करता है जिसे पूर्ववत (undo) वापस लाता है, क्योंकि पूर्ववत हटाई गई स्क्रीनों को नई ids के साथ दोबारा बनाता है:

```ts
recorder.log("screen.restored", { from: file.id, to: result.id });
```

### `recorder.watch()` {#watch}

`recorder.watch()` हर रिपोर्ट में एक लाइव मान जोड़ता है। यह एक नाम और मान लौटाने वाला फ़ंक्शन लेता है, और एक फ़ंक्शन लौटाता है जो नज़र रखना बंद कर देता है।

Design का इंस्पेक्टर वह जोड़ता है जो वह दिखा रहा है, और वह इंटरैक्शन स्टेट जिसे वह एडिट कर रहा है। इनमें से कोई भी `application_state` में नहीं है, इसलिए इसके बिना रिपोर्ट इन्हें नहीं दिखा पाती:

```tsx
useEffect(
  () =>
    recorder.watch("inspector", () => ({
      state: interactionState ?? "default",
      fields: readVisualScrubInputs(),
    })),
  [interactionState],
);
```

जो फ़ंक्शन throw करता है, उसे छोड़ा नहीं जाता, बल्कि `{ unreadable: "<message>" }` के रूप में रिपोर्ट किया जाता है।

### `recorder.onReport()` {#on-report}

`recorder.onReport()` रिपोर्ट को किसी डेस्टिनेशन पर भेजता है। यह एक लिसनर लेता है और उसे हटाने वाला फ़ंक्शन लौटाता है। लिसनर को `"manual"` के अलावा किसी भी कारण से बनी हर रिपोर्ट मिलती है। इसमें "समस्या की रिपोर्ट करें" (`"user"`), न पकड़ी गई त्रुटियाँ (`"error"`) और टेस्ट (`"test"`) शामिल हैं।

```ts
recorder.onReport((report) => posthog.capture("problem_report", report));
```

```ts
recorder.onReport((report) =>
  navigator.sendBeacon("/api/logs", JSON.stringify(report)),
);
```

न पकड़ी गई त्रुटि हर दस सेकंड में अधिकतम एक रिपोर्ट भेजती है, ताकि त्रुटियों का लूप किसी डेस्टिनेशन को भर न दे। जो लिसनर throw करता है, उसे लॉग किया जाता है और बाकी लिसनर फिर भी चलते हैं।

### `recorder.redact()` {#redact}

`recorder.redact()` कॉल के बाद दर्ज होने वाले हर इवेंट और हर देखे जा रहे मान से और फ़ील्ड छिपाता है। फ़ील्ड के नाम पास करें, या डॉट वाले पाथ जो इवेंट के नाम से शुरू होते हैं। `*` किसी भी एक फ़ील्ड से मेल खाता है।

```ts
recorder.redact("email");
recorder.redact("compose.body", "payment.*");
```

### `recorder.pending()` {#pending}

`recorder.pending()` अभी चल रहे actions और स्टेट राइट की सूची देता है। टेस्ट इसका उपयोग तय समय तक रुकने के बजाय असली idle स्थिति का इंतज़ार करने के लिए करते हैं। Design के end-to-end टेस्ट `app.settled()` में इसके खाली होने का इंतज़ार करते हैं, और हर विफल टेस्ट के साथ `recorder.json` जोड़ते हैं।

```ts
await expect
  .poll(() =>
    page.evaluate(
      () => window.__agentNativeRecorder?.report({ seconds: 0 }).pending,
    ),
  )
  .toEqual([]);
```

### `recorder.disable()` {#disable}

`recorder.disable()` रिकॉर्डर को बंद करता है। यह `configureRecorder({ enabled: false })` जैसा ही काम करता है।

## `configureRecorder()` {#configure}

`configureRecorder()` एक वैकल्पिक कॉल है। डिफ़ॉल्ट ये हैं:

```ts
import { configureRecorder } from "@agent-native/core/client/recorder";

configureRecorder({
  windowSeconds: 120,
  maxEvents: 2000,
  sentry: true,
  enabled: true,
});
```

- **windowSeconds**: रिकॉर्डर कितना पीछे तक के इवेंट रखता है।
- **maxEvents**: यह ज़्यादा से ज़्यादा कितने इवेंट रखता है। सीमा पूरी होने पर सबसे पुराने इवेंट हटा दिए जाते हैं और `dropped` में गिने जाते हैं।
- **sentry**: Sentry त्रुटियों को हाल के इवेंट मिलें या नहीं। यह तभी काम करता है जब ऐप में ब्राउज़र Sentry हो।
- **enabled**: रिकॉर्डर चले या नहीं।

अगर विंडो या सीमा धनात्मक संख्या नहीं है, तो डिफ़ॉल्ट पर लौटने के बजाय `RangeError` throw होता है। `maxEvents` चाहे जो हो, रिकॉर्डर अपना कुल आकार लगभग 512 KB JSON तक सीमित रखता है, जिससे यह हर टैब में 2 MB मेमोरी से कम रहता है।

## डेस्टिनेशन {#destinations}

### समस्या की रिपोर्ट करें {#report-a-problem}

हर ऐप में **समस्या की रिपोर्ट करें** होता है। यह साइडबार में सबसे नीचे, एजेंट पैनल के विकल्प मेनू में और कमांड मेनू (⌘K) में मिलता है।

- यह पूछता है कि क्या ऐप ने पिछले दो मिनट में जो किया उसे जोड़ना है, और गिनतियों, विफलताओं और पहले इवेंट का प्रीव्यू दिखाता है। यह हर बार पूछता है।
- उपयोगकर्ता के सहमत होने पर पूरी रिपोर्ट एक निजी फ़ाइल के रूप में सेव होती है, जिसे सिर्फ़ वही उपयोगकर्ता पढ़ सकता है। ऐप के एजेंट को फ़ाइल के संदर्भ के साथ एक छोटा सारांश मिलता है।
- एजेंट `read-problem-report` action से रिपोर्ट का और हिस्सा पढ़ता है, इवेंट प्रकार या समय के अनुसार फ़िल्टर करके।
- जब पेज पर एजेंट चैट नहीं होती, तो बटन इसके बजाय सारांश और संदर्भ कॉपी कर देता है।
- रिपोर्ट के लिए फ़ाइल स्टोरेज ज़रूरी है। उसके बिना डायलॉग बताता है कि रिपोर्ट नहीं जोड़ी गई, और कुछ भी नहीं भेजा जाता।

### Sentry {#sentry}

जब किसी ऐप में Agent-Native के ज़रिए ब्राउज़र Sentry कॉन्फ़िगर हो (देखें [त्रुटि रिपोर्टिंग](/docs/observability#sentry)), तो हर Sentry त्रुटि इवेंट को ये मिलते हैं:

- आख़िरी 100 इवेंट, `recorder.action`, `recorder.state` और ऐसी ही श्रेणियों में breadcrumbs के रूप में, हर एक के साथ उसका नतीजा, स्टेटस और रिक्वेस्ट id
- पूरी रिपोर्ट, `recorder.json` अटैचमेंट के रूप में

इसके लिए किसी ऐप कोड की ज़रूरत नहीं है। `configureRecorder({ sentry: false })` इसे बंद करता है।

### आपका अपना डेस्टिनेशन {#own-destination}

[`recorder.onReport()`](#on-report) से एक लिसनर रजिस्टर करें।

### Clips और ब्राउज़र एक्सटेंशन {#extensions}

पेज `window.__agentNativeRecorder.report()` उपलब्ध कराता है। ब्राउज़र एक्सटेंशन इसे पेज की main world से पढ़ता है।

जब डेवलपर लॉग चालू हों, तो Clips एक्सटेंशन इसे रिकॉर्ड किए गए टैब में रिकॉर्डिंग शुरू होने पर (पिछले 30 सेकंड) और रुकने पर पढ़ता है। ये इवेंट रिकॉर्डिंग की कंसोल और नेटवर्क एंट्रीज़ के साथ उसी घड़ी पर जुड़ जाते हैं, और क्लिप के एजेंट को विफलताओं का सारांश मिलता है। देखें [Clips ब्राउज़र लॉग](/docs/template-clips-features#chrome-extension-browser-logs)।

## गोपनीयता {#privacy}

- **यह ब्राउज़र में ही रहता है।** रिपोर्ट तभी बाहर जाती है जब कोई डेस्टिनेशन उसे भेजता है: उपयोगकर्ता की सहमति के बाद "समस्या की रिपोर्ट करें", उपयोगकर्ता की शुरू की गई Clips रिकॉर्डिंग, Sentry, या डेवलपर का रजिस्टर किया गया लिसनर।
- **सीक्रेट हटा दिए जाते हैं।** जिस फ़ील्ड का नाम सीक्रेट जैसा दिखता है (`password`, `token`, `secret`, `apiKey`, `authorization`, `cookie`, `session`, `card`, `cvv`), वह `"[redacted]"` दिखता है। किसी भी मान के अंदर टोकन जैसा दिखने वाला टेक्स्ट, जैसे JWT, bearer टोकन और प्रोवाइडर API कुंजियाँ, भी `[redacted]` से बदल दिया जाता है। ये वही छिपाने वाले फ़िल्टर हैं जिन्हें core त्रुटि रिपोर्ट के लिए इस्तेमाल करता है।
- **मान सीमित रहते हैं।** स्ट्रिंग 200 अक्षरों पर और हर इवेंट लगभग 2 KB पर काट दिया जाता है। हर कटौती बताती है कि क्या हटाया गया। रिक्वेस्ट और रिस्पॉन्स बॉडी कभी रिकॉर्ड नहीं होतीं।
- **यह भूल जाता है।** यह अपनी सीमाओं तक सिर्फ़ विंडो रखता है। रीलोड और साइन आउट पर यह साफ़ हो जाता है।
- **कोई नई पहुँच नहीं।** रिकॉर्डर सिर्फ़ वही देखता है जो पहले से ऐप से होकर गुज़रता है। Action कॉल पहले से सर्वर पर जाती हैं, और `application_state` पहले से स्टोर होता है और एजेंट उसे पढ़ता है।

## इसे बंद करना {#off}

```ts
import { configureRecorder } from "@agent-native/core/client/recorder";

configureRecorder({ enabled: false });
```

बंद किया गया रिकॉर्डर अपने पास रखी चीज़ें भूल जाता है, सुनना बंद कर देता है, और पेज से `window.__agentNativeRecorder` हटा देता है। उसका `recorder.report()` कोई इवेंट और कोई देखा गया मान नहीं लौटाता, और वह लिसनर को कुछ नहीं भेजता। `configureRecorder({ enabled: true })` इसे फिर से शुरू करता है।
