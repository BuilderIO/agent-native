# डेवलपर गाइड

यह पेज उन सभी के लिए है जो स्लाइड टेम्पलेट को कस्टमाइज़ या एक्सटेंड कर रहे हैं: SQL डेटा मॉडल, कॉनकर्रेंट राइटर को कैसे सुरक्षित रखा जाता है, हर एजेंट-कॉल करने योग्य action, रूट मैप, और सामान्य बदलाव कहां करें।

## क्विक स्टार्ट

```bash
npx @agent-native/core@latest create my-slides --standalone --template slides
```

बाकी सेटअप (`cd`, `pnpm install`, `pnpm dev`) और फ़्रेमवर्क की बुनियादी बातों के लिए [शुरुआत करें](/docs/getting-started) देखें।

## पर्सिस्टेंस मॉडल

हर डेक `decks.data` में एक JSON ब्लॉब है। हर राइट एक सर्वर-साइड रीड-मॉडिफ़ाई-राइट action से गुज़रता है जो एक पर-डेक लॉक होल्ड करता है, ताकि कॉनकर्रेंट राइटर, कोई इंसान और एजेंट, या दो इंसान, एक ही डेक की अलग-अलग स्लाइड को छूते हुए भी कभी एक-दूसरे का काम ओवरराइट न करें।

- **एजेंट actions** (`add-slide`, `update-slide`) अपने खुद के डेडिकेटेड, ग्रैन्युलर actions इस्तेमाल करते हैं और वही लॉक शेयर करते हैं।
- **ब्राउज़र एडिटर** पूरे डेक के PUT के बजाय `patch-deck` के ज़रिए ग्रैन्युलर ऑप्स (`patch-slide`, `delete-slide`, `reorder-slides`, `add-slide`, `patch-deck-fields`) एनक्यू करता है।

<Callout id="doc-block-slides10" tone="warning">

अगर आप एडिटर के सेव पाथ को एक्सटेंड कर रहे हैं, तो `patch-deck` के ज़रिए एक नया ऑप एनक्यू करें। कोई नया पूरे डेक का PUT न जोड़ें। इससे वह लास्ट-राइट-विंस रेस दोबारा आ जाएगी जिसे रोकने के लिए यह लॉक मौजूद है।

</Callout>

#### स्लाइड की संरचना

`decks.data` के अंदर हर स्लाइड यह होती है:

```json
{
  "id": "slide-1",
  "layout": "title",
  "content": "<div class=\"fmd-slide\" style=\"...\">...</div>"
}
```

`content` कच्चा HTML है। रेंडरर फ़िक्स्ड एस्पेक्ट रेशियो और बैकग्राउंड देता है, और HTML अंदर की हर चीज़ देता है। रिच एम्बेडिंग भी सपोर्टेड है: हाथ से बने डायग्राम और लाइव-रेंडर्ड चार्ट प्लेन HTML के साथ किसी स्लाइड के अंदर रह सकते हैं।

## Actions इन्वेंटरी

### डेक लाइफ़साइकल

- `create-deck` — नया डेक, ज़रूरत पड़े तो स्लाइड्स से पहले से भरा हुआ, या किसी मौजूदा डेक की स्लाइड्स का एटॉमिक बल्क रिप्लेस। खाली डेक के लिए `slides` छोड़ दें या `[]` पास करें। यह action application state के ज़रिए नए डेक को खोल देता है।
- `get-deck` — पूरा डेक JSON, या एक कॉम्पैक्ट स्लाइड-समरी व्यू
- `list-decks` — कॉलर जो भी डेक देख सकता है, सस्ती पोलिंग के लिए light/compact/full-slide प्रोजेक्शन के साथ
- `duplicate-deck` — नई स्लाइड ids के साथ किसी डेक की कॉपी
- `update-deck-aspect-ratio` — 16:9, 1:1, 9:16, या 4:5

`add-deck`, `save-deck`, और `delete-deck` ब्राउज़र एडिटर के ऑप्टिमिस्टिक-क्रिएट, अनडू/रीडू, और डिलीट फ़्लो को सपोर्ट करते हैं। एजेंट इसके बदले `create-deck`, `add-slide`/`update-slide`/`patch-deck`, और फ़्रेमवर्क के अपने शेयरिंग actions इस्तेमाल करता है।

### एक्सेस रिक्वेस्ट

- `request-deck-access`, `approve-deck-access-request`, `get-deck-access-status` — प्राइवेट-डेक एक्सेस-रिक्वेस्ट फ़्लो: बिना एक्सेस वाला कोई विज़िटर इसे रिक्वेस्ट करता है, ओनर ऐप से या `/access-request/approve` रूट से अप्रूव या डिनाई करता है, और दोनों तरफ़ से मौजूदा स्टेटस पोल किया जा सकता है

### स्लाइड एडिट

- `add-slide` — एक स्लाइड अपेंड करें (या किसी पोज़िशन पर इंसर्ट करें)। इसे किसी खाली `create-deck` के बाद सीक्वेंशियली कॉल करें ताकि एडिटर प्रोग्रेस दिखा सके।
- `update-slide` — सर्जिकल फ़ाइंड/रिप्लेस या फ़ुल-कॉन्टेंट स्लाइड एडिट
- `patch-deck` — वह ग्रैन्युलर ऑप क्यू जिसे ब्राउज़र एडिटर पूरे डेक के PUT के बजाय इस्तेमाल करता है
- `get-layout-overflows` — ब्राउज़र से मेज़र्ड स्लाइड-फ़िट नतीजे पढ़ें, ताकि कोई एडिट जो अपने लेआउट में फ़िट नहीं होता, पकड़ा और ठीक किया जा सके

### हिस्ट्री

- `list-deck-versions`, `get-deck-version`, `restore-deck-version` — हर राइट पहले स्नैपशॉट लेता है, ताकि किसी भी पॉइंट-इन-टाइम को लिस्ट और रीस्टोर किया जा सके

### कमेंट

- `list-slide-comments`, `add-slide-comment`, `update-slide-comment`, `delete-slide-comment`

### इम्पोर्ट

- `import-pptx`, `import-docx`, `import-google-doc` — डेडिकेटेड सिंगल-फ़ॉर्मेट इम्पोर्टर
- `import-google-slides-reference` — किसी Google Slides डेक को उसके कॉन्टेंट को वर्किंग डेक में खींचने के बजाय एक दोबारा इस्तेमाल किए जा सकने वाले रेफ़रेंस डेक के तौर पर इम्पोर्ट करें
- `import-file` — PPTX, DOCX, या PDF के लिए, या किसी Figma `.fig` फ़ाइल के लिए एक एंट्री पॉइंट (जो स्लाइड इम्पोर्ट के बजाय Builder डिज़ाइन-सिस्टम इंडेक्सिंग में जाती है)
- `extract-pdf` — किसी PDF का CLI-only कच्चा टेक्स्ट डंप, ज़्यादातर लोकल डीबगिंग के लिए

### एक्सपोर्ट

- `export-pptx` — नेटिव, एडिटेबल PowerPoint
- `export-google-slides` — वही PPTX जेनरेट करता है, साथ में एक तैयार Google Slides इम्पोर्ट लिंक
- `export-html` — बिल्ट-इन कीबोर्ड नेविगेशन के साथ एक स्टैंडअलोन, सेल्फ़-कंटेन्ड HTML फ़ाइल

### डिज़ाइन सिस्टम

- `create-design-system`, `update-design-system`, `delete-design-system`, `get-design-system`, `list-design-systems`, `set-default-design-system`, `apply-design-system` (किसी एक को डेक से लिंक करें)
- `get-workspace-defaults`, `set-workspace-defaults` — वर्कस्पेस-वाइड डिफ़ॉल्ट डेक और डिज़ाइन सिस्टम। सेट करना सिर्फ़ एडमिन के लिए है
- `analyze-brand-assets`, `import-document`, `import-from-url`, `import-code` — एक **लोकल**, एजेंट-ड्राफ़्टेड डिज़ाइन सिस्टम के लिए कच्चे ब्रांड सिग्नल इकट्ठा करें (वेबसाइट CSS/फ़ॉन्ट, अपलोडेड डॉक्यूमेंट या कोड फ़ाइल कॉन्टेंट)
- `index-design-system-with-builder`, `sync-design-system-with-builder`, `import-design-project` — Figma फ़ाइलों, कनेक्टेड कोड/GitHub रेपो, और `design.md` के लिए Builder-इंडेक्स्ड पाथ। `import-design-project` किसी कच्चे सोर्स के बजाय किसी मौजूदा डिज़ाइन सिस्टम से शुरू होता है

### Creative Context

- `clone-context-slide` — किसी पिन की हुई Library स्लाइड को बिना बदले, उसके HTML/CSS को फिर से जेनरेट किए बिना, किसी डेक में इंसर्ट करें
- `clone-creative-context-deck` — किसी एग्ज़ैक्ट गवर्न्ड डेक वर्शन को दोबारा बनाएं
- `get-deck-reference-context` — किसी मौजूदा डेक की विज़ुअल भाषा को एक दोबारा इस्तेमाल किए जा सकने वाली पैटर्न लाइब्रेरी के तौर पर एक्सट्रैक्ट करें
- रिट्रीवल और Library सबमिशन (सर्च करना, कोई कॉन्टेक्स्ट आइटम फ़ेच करना, Library मेंबरशिप मैनेज करना) शेयर्ड फ़्रेमवर्क actions हैं जिन्हें एजेंट Creative Context सपोर्ट करने वाले हर ऐप में एक जैसे तरीके से कॉल करता है। रिट्रीवल प्रोसीज़र और रीयूज़ लैडर के लिए `creative-context` skill देखें।

### एस्केलेशन और स्टेज्ड डेटा

- `provider-api-catalog`, `provider-api-docs`, `provider-api-request` — जब कोई बना-बनाया इम्पोर्ट/एक्सपोर्ट action बहुत संकरा हो, तो रॉ Google Drive API एक्सेस। स्लाइड यूज़र के कनेक्टेड Google Docs अकाउंट से ऑथ रिज़ॉल्व करता है
- `list-staged-datasets`, `query-staged-dataset`, `delete-staged-dataset` — किसी बड़े स्टेज्ड प्रोवाइडर नतीजे को दोबारा फ़ेच किए बिना एग्रीगेट करें

### नेविगेशन और कॉन्टेक्स्ट

- `view-screen` — यूज़र इस वक़्त क्या देख रहा है: खुला डेक, मौजूदा स्लाइड, और कोई भी एक्टिव विज़ुअल सिलेक्शन
- `navigate` — UI को किसी डेक, स्लाइड, या व्यू पर मूव करें

| `/agent`, `/extensions`, `/team` | संबंधित Settings पेज पर रीडायरेक्ट करें                       |

## इसे कस्टमाइज़ करना

स्लाइड टेम्पलेट पूरी तरह से कस्टमाइज़ेबल है। इसे एक्सटेंड करते समय देखने लायक मुख्य जगहें:

#### Actions — `templates/slides/actions/`

हर एजेंट-कॉल करने योग्य ऑपरेशन यहां एक TypeScript फ़ाइल के तौर पर रहता है, जो अपने आप `POST /_agent-native/actions/:name` पर माउंट हो जाती है और CLI से `pnpm action <name>` के तौर पर कॉल की जा सकती है। एजेंट को कोई नई क्षमता देने के लिए यहां एक नई फ़ाइल जोड़ें।

#### Skills — `templates/slides/.agents/skills/`

एजेंट skills जो पैटर्न एक्सप्लेन करते हैं जब एजेंट को कोड मॉडिफ़ाई करने की ज़रूरत होती है:

- `create-deck` — नया डेक कैसे बनाएं, हर लेआउट के लिए एग्ज़ैक्ट स्लाइड HTML टेम्पलेट के साथ
- `slide-editing` — अलग-अलग स्लाइड्स कैसे एडिट करें
- `deck-management` — डेक कैसे स्टोर और एक्सेस किए जाते हैं
- `design-systems` — डिज़ाइन-सिस्टम डेटा शेप और जेनरेट की गई स्लाइड्स पर टोकन कैसे लागू होते हैं
- `creative-context` — रीयूज़ लैडर, रिट्रीवल प्रोसीज़र, और Library सबमिशन

#### AGENTS.md

`templates/slides/AGENTS.md` वह छोटा राउटर है जिसे एजेंट हर कन्वर्सेशन पर पढ़ता है। यह `.agents/skills/` के तहत मौजूद skills की तरफ़ इशारा करता है और कोर नियम, पर्सिस्टेंस मॉडल, और application-state कॉन्ट्रैक्ट बताता है। जब भी आप कोई स्लाइड लेआउट या डिज़ाइन-सिस्टम सोर्स जोड़ें या बदलें, तो संबंधित skill को अपडेट करें।
