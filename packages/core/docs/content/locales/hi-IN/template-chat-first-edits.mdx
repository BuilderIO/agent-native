# आपकी पहली सुविधा

यह पेज [Chat template](/docs/template-chat) को आगे बढ़ाने वाले developers के लिए है। इसमें शुरुआती स्क्रीन रेंडर करने वाली फ़ाइलें बताई गई हैं, फिर वह सब कुछ जिसे agent आमतौर पर छूता है जब आप कोई असली feature माँगते हैं।

## निरीक्षण करने के लिए पहला कोड {#first-code}

- `actions/hello.ts` शुरुआती व्यवहार है जिसे agent कॉल कर सकता है। इसे बदलें
  या इसके साथ actions जोड़ें।
- `app/components/chat/ChatRouteContent.tsx` `/chat/<threadId>` पर पूरे पेज की
  chat surface रेंडर करता है। empty state, composer या message slots यहाँ बदलें।
- `app/components/home/HomePage.tsx` development में `/home` पर दिखने वाला
  संपादन योग्य शुरू करें पेज है। Production में `/home` नई chat शुरू करता है।
- `AGENTS.md` built-in agent को बताता है कि इस app के अंदर कैसे काम करना है।

## पहला एडिट {#first-edits}

अधिकतर पहली सुविधाएं एक जैसी शेप फॉलो करती हैं: एक table, एक या दो actions,
एक route, एक nav entry, और एक `AGENTS.md` अपडेट। एजेंट से पूछें:

> `notes` के लिए एक डेटा मॉडल जोड़ें। एक note में एक id, title, body, और
> owner होता है। `/notes` पर एक notes पेज रेंडर करें, create/list actions
> जोड़ें, और चैट को notes बनाने में सक्षम रखें।

चैट में शुरू से कोई `server/db/schema.ts` शामिल नहीं है (देखें
[क्या शामिल है](/docs/template-chat#what-ships)), इसलिए पहला बदलाव एक नई
फ़ाइल है, वही `table`/`text`/`ownableColumns` शेप फॉलो करते हुए जो हर दूसरा
टेम्पलेट इस्तेमाल करता है:

बाकी सुविधा वहां से फॉलो होती है:

- `actions/create-note.ts` — `actions/hello.ts` जैसा शेप्ड, एक Zod schema
  (`title`, `body`) वाला एक `defineAction`।
- `actions/list-notes.ts` — एक read-only action (`readOnly: true`,
  `actions/view-screen.ts` जैसा) जो `accessFilter` के ज़रिए नई table को
  क्वेरी करता है।
- `app/routes/notes.tsx` — एक नया route; ऐप file-system routing
  (`app/routes.ts` में `flatRoutes()`) इस्तेमाल करता है, इसलिए फ़ाइल जोड़ना
  ही `/notes` को माउंट करने के लिए काफ़ी है।
- `app/components/layout/Sidebar.tsx` में `ChatThreadsSection` से पहले जोड़ा गया, `/notes` की ओर इशारा करने वाला link।
- एक `AGENTS.md` addition जो एजेंट को बताता है कि notes मौजूद हैं और कौन से
  actions उन्हें मैनेज करते हैं।

एक नया action बनने के साथ ही चैट द्वारा कॉल किया जा सकता है — हर
`defineAction` डिफ़ॉल्ट रूप से एक tool है, जब तक कि वह `agentTool: false`
सेट न करे। हालांकि, यह ज़रूरी नहीं कि मॉडल की सबसे पहली रिक्वेस्ट में ही
शामिल हो: `server/plugins/agent-chat.ts`
`INITIAL_TOOL_NAMES = ["view-screen", "navigate", "hello", "provider-api-request"]` सेट करता है,
जो सिर्फ़ यह कंट्रोल करता है कि पहले turn पर कौन से tool schema भेजे जाते
हैं। बाकी सब, जिसमें एक नया `create-note` भी शामिल है, `tool-search` के
ज़रिए पहुंच योग्य रहता है और मांग पर लोड होता है — उस लिस्ट में कोई नाम
सिर्फ़ तब जोड़ें जब आप उसे पहले मैसेज से ही मॉडल के डिफ़ॉल्ट टूलसेट में
चाहते हों।

## अपना खुद का एजेंट बैकएंड इस्तेमाल करें {#own-agent-backend}

टेम्पलेट डिफ़ॉल्ट रूप से बिल्ट-इन app-agent लूप इस्तेमाल करता है। एक कस्टम
बैकएंड कनेक्ट करने के लिए, UI को फिर से लिखने के बजाय एजेंट चैट प्लगइन के
पीछे चैट रनटाइम को स्वैप करें। Chat route को शेयर्ड चैट सतह के चारों ओर एक
पतला रेंडरर ही रहना चाहिए; बैकएंड का चुनाव server plugin/runtime adapter
में होता है।

इसका इस्तेमाल तब करें जब आपका मॉडल orchestration पहले से ही कहीं और मौजूद
है, लेकिन आप फिर भी ऑथ, थ्रेड्स, actions, UI स्थिति, और डिप्लॉय करने योग्य
पेजों वाला एक ऐप चाहते हैं।
