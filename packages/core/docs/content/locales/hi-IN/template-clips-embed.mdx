# क्लिप्स एम्बेड करें

अपने प्रोडक्ट के लिए रिकॉर्डिंग बैकएंड के तौर पर होस्टेड क्लिप्स का इस्तेमाल
करें। कोई व्यक्ति क्लिप्स में साइन इन किए बिना किसी iframe से रिकॉर्ड कर सकता
है। आपका बैकएंड एक शॉर्ट-लिव्ड इनटेक URL बनाने के लिए एक org सर्विस टोकन
इस्तेमाल करता है, और क्लिप्स नतीजे में बनी रिकॉर्डिंग को उस संगठन की कॉन्फ़िगर
की गई स्टोरेज में सेव करता है।

यह गाइड होस्टेड एम्बेडिंग फ़्लो कवर करती है। इसके लिए रिकॉर्ड करने वाले
व्यक्ति के पास क्लिप्स अकाउंट होना ज़रूरी नहीं है।

## इंटीग्रेशन कैसे काम करता है

इस इंटीग्रेशन के चार हिस्से हैं:

1. संगठन का कोई Admin क्लिप्स में वीडियो स्टोरेज कॉन्फ़िगर करता है।
2. आपका बैकएंड org सर्विस टोकन स्टोर करता है और एक इनटेक URL रिक्वेस्ट करता है।
3. आपका प्रोडक्ट सिर्फ़ शॉर्ट-लिव्ड इनटेक URL को किसी iframe में पास करता है।
4. क्लिप्स रिकॉर्डिंग को संगठन की स्टोरेज में अपलोड करता है और आपके प्रोडक्ट
   को एक कम्प्लीशन मैसेज पोस्ट करता है।

org सर्विस टोकन कभी iframe में नहीं होना चाहिए। यह उस संगठन से बंधा होता है
जिसने इसे बनाया, इसलिए टोकन खुद ही संगठन का कॉन्टेक्स्ट देता है। एक संगठन ID
आपकी अपनी टेनेंट मैपिंग के लिए काम की है, लेकिन यह खुद अपने आप में कोई
क्रेडेंशियल नहीं है।

## क्लिप्स संगठन कॉन्फ़िगर करें

वह क्लिप्स संगठन बनाएं या चुनें जिसे रिकॉर्डिंग का मालिक होना चाहिए। इसके बाद
संगठन का कोई Admin क्लिप्स ऑनबोर्डिंग या क्लिप्स Settings से वीडियो स्टोरेज
कॉन्फ़िगर करता है:

- **Builder.io Connect** मैनेज्ड वीडियो स्टोरेज और AI क्रेडिट देता है।
- **S3-compatible storage** संगठन के कॉन्फ़िगर किए गए endpoint, bucket,
  access key, secret key, और वैकल्पिक region या public base URL का इस्तेमाल
  करता है। Cloudflare R2 और DigitalOcean Spaces अपने प्रोवाइडर-स्पेसिफ़िक
  नामों के साथ यही स्टोरेज सेटिंग्स इस्तेमाल करते हैं।

स्टोरेज कॉन्फ़िगरेशन org-scoped होता है। उस संगठन के सर्विस टोकन से बनी हर
रिकॉर्डिंग उस संगठन से पहले से कनेक्टेड स्टोरेज इस्तेमाल करती है। एम्बेड करने
वाले प्रोडक्ट को Builder.io या S3 क्रेडेंशियल की ज़रूरत नहीं होती।

वीडियो कॉन्फ़िगर की गई ऑब्जेक्ट स्टोरेज में सेव होता है। क्लिप्स रिकॉर्डिंग
का मेटाडेटा, ओनरशिप, प्रोसेसिंग स्टेटस, और स्टोरेज रेफ़रेंस अपने डेटाबेस में
सेव करता है।

## एक संगठन सर्विस टोकन बनाएं

मौजूदा `connect` कमांड को किसी संगठन के owner या admin के तौर पर चलाएं। यह
कमांड एक ब्राउज़र साइन-इन खोलती है, एक्टिव संगठन के लिए एक नाम वाला सर्विस
टोकन बनाती है, और टोकन को एक बार प्रिंट करती है:

```bash
npx @agent-native/core@latest connect https://clips.agent-native.com \
  --service-token support-desk --ttl-days 365
```

प्रिंट हुए टोकन को सीधे अपने प्रोडक्ट के सर्वर-साइड सीक्रेट मैनेजर में कॉपी
करें। यह टोकन संगठन का होता है, इसलिए अगर इसे बनाने वाला व्यक्ति संगठन छोड़ दे
या अपने पर्सनल टोकन रिवोक कर दे, तो भी यह काम करता रहता है। यह कभी किसी लोकल
क्लाइंट कॉन्फ़िगरेशन में नहीं लिखा जाता। हर इंटीग्रेशन के लिए एक अलग सर्विस
नाम इस्तेमाल करें ताकि एक कॉलर को दूसरे को तोड़े बिना रिवोक किया जा सके।

`--ttl-days` 1 से 365 दिन तक एक्सेप्ट करता है और डिफ़ॉल्ट रूप से 365 है। यह
टोकन एक संगठन मेंबर की तरह काम करता है। यह न तो दूसरे सर्विस टोकन बना या
रिवोक कर सकता है, न ही संगठन की सेटिंग्स बदल सकता है।

## एक इनटेक URL रिक्वेस्ट करें

आपका ट्रस्टेड बैकएंड क्लिप्स इनटेक action को कॉल करता है। होस्टेड अकाउंट के
लिए होस्टेड क्लिप्स origin इस्तेमाल करें, या सेल्फ़-होस्टिंग करते समय अपना
खुद का क्लिप्स origin।

```ts
const clipsBaseUrl = "https://clips.agent-native.com";
const clipsServiceToken = process.env.CLIPS_SERVICE_TOKEN;

const response = await fetch(
  `${clipsBaseUrl}/_agent-native/actions/create-recording-intake-link`,
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${clipsServiceToken}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      ttlSeconds: 3600,
    }),
  },
);

if (!response.ok) {
  throw new Error("Could not create a Clips intake URL");
}

const intake = await response.json();
// intake.url is safe to pass to the recording iframe.
```

सर्विस टोकन का सिग्न्ड संगठन कॉन्टेक्स्ट यह तय करता है कि इनटेक का मालिक कौन
सा संगठन है। Action का रेस्पॉन्स टॉप लेवल पर इनटेक ऑब्जेक्ट होता है। डिफ़ॉल्ट
इनटेक लाइफ़टाइम एक घंटा है। अधिकतम चार घंटे है। हर इनटेक URL एक रिकॉर्डिंग
बना सकता है।

यह रिक्वेस्ट किसी एनोनिमस ब्राउज़र से न करें। सर्विस टोकन, स्टोरेज
क्रेडेंशियल, या कोई लॉन्ग-लिव्ड क्लिप्स सेशन ब्राउज़र को वापस न भेजें।

## रिकॉर्डर एम्बेड करें

लौटाए गए URL को सीधे किसी iframe में पास करें। इस URL में वह संकरी, सिग्न्ड
क्षमता होती है जो विज़िटर को एक निजी रिकॉर्डिंग बनाने और अपलोड करने देती है।

```tsx
<iframe
  data-clips-recorder
  src={intake.url}
  allow="display-capture; camera; microphone"
  title="Report a problem"
  style={{ width: 420, height: 560, border: 0 }}
/>
```

इसे रेंडर करने से पहले आप इनटेक URL में छोटे, नॉन-सेंसिटिव कॉन्टेक्स्ट वैल्यू
जोड़ सकते हैं, जैसे कोई प्रोजेक्ट ID, पेज शीर्षक, एप्लिकेशन वर्शन, या
एनवायरनमेंट। URL में पासवर्ड, API key, कस्टमर रिकॉर्ड, या दूसरे सेंसिटिव
वैल्यू न डालें। URL ब्राउज़र हिस्ट्री, लॉग, एनालिटिक्स, और रेफ़रर में दिख सकते
हैं।

जब विज़िटर कैप्चर शुरू करता है, तो रिकॉर्डर एक टॉप-लेवल पॉपअप खोलता है।
ब्राउज़र मीडिया परमिशन और स्क्रीन कैप्चर के लिए किसी टॉप-लेवल ब्राउज़िंग
कॉन्टेक्स्ट में यूज़र जेस्चर चाहिए। टेस्टिंग के दौरान होस्ट प्रोडक्ट के लिए
पॉपअप की अनुमति दें।

## कम्प्लीशन मैसेज रिसीव करें

जब रिकॉर्डिंग सेव हो जाती है, तो done पेज एम्बेड करने वाले parent को
`agent-native.clips.bug-report.submitted` पोस्ट करता है। पेलोड इस्तेमाल करने
से पहले क्लिप्स origin और मैसेज सोर्स वैलिडेट करें।

```ts
const clipsOrigin = new URL(clipsBaseUrl).origin;
const recorderFrame = document.querySelector<HTMLIFrameElement>(
  "iframe[data-clips-recorder]",
);

window.addEventListener("message", (event) => {
  if (event.origin !== clipsOrigin) return;
  if (recorderFrame && event.source !== recorderFrame.contentWindow) return;
  if (event.data?.type !== "agent-native.clips.bug-report.submitted") return;

  const { recordingId, recordingUrl, embedUrl, agentAccessStatus } = event.data;
  if (!recordingId) return;

  // Send recordingId to your trusted backend and attach it to the support case.
  console.log({ recordingId, recordingUrl, embedUrl, agentAccessStatus });
});
```

कम्प्लीशन पेलोड में `recordingId`, `recordingUrl`, `embedUrl`,
`agentShareUrl`, `agentContextUrl`, `agentAccessExpiresAt`, और
`agentAccessStatus` शामिल हो सकते हैं। `recordingId` को सपोर्ट केस के लिए
टिकाऊ आइडेंटिफ़ायर मानें। कोई write-only इनटेक तब तक
`agentAccessStatus: "unavailable"` रिपोर्ट कर सकता है जब तक आपका
authenticated बैकएंड एक अलग स्कोप्ड एजेंट लिंक न बना ले। इस स्टेटस का मतलब
यह नहीं है कि रिकॉर्डिंग खाली है।

यह ब्राउज़र मैसेज एक नोटिफ़िकेशन है, कोई ऑथराइज़ेशन ग्रांट नहीं। जब आपके
बैकएंड को पूरी हुई रिकॉर्डिंग पढ़नी या शेयर करनी हो, तो उसे क्लिप्स से अपना
खुद का authenticated कनेक्शन इस्तेमाल करना चाहिए।

## रिकॉर्डिंग कहां स्टोर होती हैं

सर्विस टोकन से बनी रिकॉर्डिंग उस संगठन की मालिक होती हैं जो उस टोकन से जुड़ा
है। क्लिप्स मीडिया को अपनी सामान्य अपलोड और finalize पाइपलाइन से भेजता है।
यह पाइपलाइन उस संगठन के लिए कॉन्फ़िगर की गई Builder.io या S3-compatible
स्टोरेज इस्तेमाल करती है।

iframe सीधे आपके bucket में अपलोड नहीं करता, और इसे bucket क्रेडेंशियल की
ज़रूरत नहीं होती। आपके प्रोडक्ट को क्लिप्स से रिकॉर्डिंग आइडेंटिफ़ायर और
स्कोप्ड URL मिलते हैं। अपने सपोर्ट सिस्टम में सिर्फ़ वे आइडेंटिफ़ायर या URL
स्टोर करें जिनकी आपको ज़रूरत है।

## क्लिप्स को सेल्फ़-होस्ट करना

सेल्फ़-होस्टिंग वही संगठन कॉन्ट्रैक्ट इस्तेमाल करती है:

1. क्लिप्स को एक persistent डेटाबेस और एक सार्वजनिक `BETTER_AUTH_URL` के साथ
   डिप्लॉय करें।
2. वह संगठन बनाएं जो एम्बेडेड रिकॉर्डिंग का मालिक होगा।
3. उस संगठन में एक बार Builder.io Connect या S3-compatible स्टोरेज कॉन्फ़िगर
   करें।
4. संगठन का सर्विस टोकन बनाने के लिए सेल्फ़-होस्टेड क्लिप्स origin के ख़िलाफ़
   `connect` चलाएं।
5. उस टोकन को अपने एम्बेडिंग बैकएंड को एक बार डिप्लॉयमेंट या सीक्रेट-मैनेजर
   वैल्यू के तौर पर दें।
6. जब आपका बैकएंड इनटेक URL रिक्वेस्ट करे तो सेल्फ़-होस्टेड क्लिप्स origin
   इस्तेमाल करें।

```bash
npx @agent-native/core@latest connect https://clips.example.com \
  --service-token support-desk --ttl-days 365
```

उदाहरण के लिए, एम्बेडिंग बैकएंड इन वैल्यू को अपने सर्वर-साइड कॉन्फ़िगरेशन में
रख सकता है:

```text
CLIPS_BASE_URL=https://clips.example.com
CLIPS_SERVICE_TOKEN=<secret>
```

यह टोकन बैकएंड को एक बार दिया जाता है। हर विज़िटर को अभी भी एक नया
शॉर्ट-लिव्ड इनटेक URL मिलता है। iframe में कोई टोकन या स्टोरेज क्रेडेंशियल
नहीं जोड़ा जाता, और टोकन रोटेट होने पर iframe के कोड में कोई बदलाव नहीं करना
पड़ता।

सामान्य सेल्फ़-होस्टिंग ज़रूरतों के लिए [डिप्लॉयमेंट](/docs/deployment) देखें।

## सिक्योरिटी चेकलिस्ट

- संगठन सर्विस टोकन को किसी सर्वर-साइड सीक्रेट मैनेजर में रखें।
- होस्ट प्रोडक्ट और क्लिप्स दोनों के लिए HTTPS इस्तेमाल करें।
- हर इनटेक URL को एक bearer क्रेडेंशियल मानें। इसे लॉग और रेफ़रर डेटा से दूर
  रखें।
- सबसे छोटा काम का इनटेक लाइफ़टाइम इस्तेमाल करें।
- कम्प्लीशन लिसनर में `event.origin` और `event.source` दोनों वैलिडेट करें।
- क्लिप्स के owner-scoped अपलोड एंडपॉइंट को कभी एनोनिमस यूज़र को सीधे एक्सपोज़
  न करें।
- `connect` से एक रिप्लेसमेंट बनाकर, उसे डिप्लॉय करके, फ़्लो वेरिफ़ाई करके,
  फिर पुराने टोकन को `revoke-org-service-token` से रिवोक करके सर्विस टोकन
  रोटेट करें।
- विज़िटर द्वारा दी गई वैल्यू पर भरोसा करने के बजाय संगठन ID और इनटेक ID को
  ट्रस्टेड बैकएंड के पास रखें।

## ट्रबलशूटिंग

**इनटेक रिक्वेस्ट unauthorized है।** कन्फ़र्म करें कि बैकएंड एक non-expired,
non-revoked सर्विस टोकन इस्तेमाल कर रहा है जो इच्छित क्लिप्स origin के लिए
बनाया गया था। टोकन की संगठन बाइंडिंग यह तय करती है कि इनटेक कहां बनाया जाता
है।

**iframe एक साइन-इन पेज खोलता है।** सुनिश्चित करें कि iframe
`create-recording-intake-link` से मिला शॉर्ट-लिव्ड URL इस्तेमाल कर रहा है।
किसी एनोनिमस विज़िटर के लिए `/record` या कोई सामान्य क्लिप्स लाइब्रेरी URL
एम्बेड न करें।

**रिकॉर्डिंग पूरी नहीं होती।** चेक करें कि संगठन में Builder.io या
S3-compatible स्टोरेज कॉन्फ़िगर है। कोई एनोनिमस विज़िटर iframe से स्टोरेज
कॉन्फ़िगर नहीं कर सकता।

**कम्प्लीशन में कोई एजेंट लिंक नहीं है।** किसी write-only इनटेक के लिए यह
उम्मीद के मुताबिक है। अगर सपोर्ट वर्कफ़्लो को एजेंट-पठनीय ट्रांसक्रिप्ट और
फ़्रेम डेटा चाहिए, तो अपने authenticated बैकएंड से एक अलग स्कोप्ड एजेंट लिंक
बनवाएं।
