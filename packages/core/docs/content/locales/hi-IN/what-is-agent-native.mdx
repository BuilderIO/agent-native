# Agent-Native क्या है?

Agent-Native सहज UI वाले स्वायत्त एजेंट बनाने के लिए एक open-source TypeScript
framework है। आप हर capability को एक बार [action](/docs/actions-overview)—एक typed
function के रूप में define करते हैं, जिसे agent tool के रूप में use करता है और UI
code से call करता है।

## UI वाले agents क्यों बनाएं

Coding agents text box को काफ़ी बना हुआ दिखा सकते हैं। लेकिन text box उनके
working environment का सिर्फ़ एक हिस्सा है। Codebase context देता है, tools
उन्हें काम करने के साफ़ तरीके देते हैं, और files, tests और previews results को
visible बनाते हैं।

ज़्यादातर knowledge work के साथ यह structure नहीं आता। खाली text box में लोगों
को अंदाज़ा लगाना पड़ता है कि agent क्या कर सकता है, उसके पास कौन-सा context है
और उन्हें क्या पूछना चाहिए।

UI वह देती है जो text box में नहीं है। यह agent की capabilities को visible
बनाती है, context और workflows को experience में लाती है, और लोगों को काम आगे
बढ़ने के साथ देखने और आकार देने देती है।

Agent-Native आपको इस तरह agents बनाने देता है। UI agent को किसी fixed workflow
तक सीमित किए बिना लोगों को साफ़ starting points देती है। Agent और UI एक ही
capabilities use करते हैं, इसलिए लोग agent को काम delegate कर सकते हैं, UI में
उसे inspect या change कर सकते हैं, और progress खोए बिना दोनों के बीच move कर
सकते हैं।

Agent-Native agent और UI को तीन shared foundations के जरिए जोड़ता है:

- **[Shared actions](/docs/actions-overview).** आप हर capability को एक बार define
  करते हैं। Agent उसे tool के रूप में call करता है और UI उसे code से call करता
  है। दोनों paths एक ही validation, permissions और implementation का उपयोग करते
  हैं।
- **[Shared data](/docs/server-database).** Actions एक ही data को read और update
  करते हैं, इसलिए agent का किया हुआ work UI में दिखाई देता है और UI में किया
  हुआ work agent के लिए उपलब्ध रहता है।
- **[Shared application state](/docs/context-awareness).** Application state
  बताता है कि UI में क्या हो रहा है, जैसे current page, selected record या active
  view। Agent-Native relevant state को context के रूप में agent को देता है, ताकि
  वह समझ सके कि व्यक्ति किस पर काम कर रहा है।

Agent UI में click करके काम नहीं करता। वह UI के समान action layer के जरिए काम
करता है।

उदाहरण के लिए, कोई व्यक्ति UI से support ticket assign कर सकता है या agent से ऐसा करने को कह सकता है।
दोनों paths एक ही action चलाते हैं और उसी ticket को update करते हैं। व्यक्ति UI में result inspect या change
कर सकता है, फिर agent को वहीं से काम जारी रखने दे सकता है।

## Agent-Native का उपयोग कब करना चाहिए?

Agent-Native तब अच्छा fit है जब:

- Agent को असली काम करना हो, केवल सवालों के जवाब नहीं देने हों।
- लोगों को यह देखने के लिए UI चाहिए कि agent क्या कर सकता है, और उसके work को
  inspect, edit, approve या share करने के लिए।
- लोगों को progress या context खोए बिना agent और UI के बीच move कर पाना चाहिए।

अगर केवल एक generated response चाहिए, तो सीधे model को call करें। अगर workflow fixed और predictable
sequence का पालन करता है, तो सामान्य application logic या automation सरल है। Agent-Native तब उपयोग करें
जब agent और UI दोनों को एक ही work में लगातार भूमिका चाहिए।
