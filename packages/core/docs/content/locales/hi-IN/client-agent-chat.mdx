# एजेंट चैट

आपके एप्लिकेशन का क्लाइंट क्लाइंट हेल्पर्स के एक छोटे सेट के माध्यम से एजेंट से बात कर सकता है। यह प्रॉम्प्ट भेजना, छिपा हुआ कॉन्टेक्स्ट स्टेज करना, उपयोगकर्ता से एक ब्लॉकिंग प्रश्न पूछना, और एजेंट पैनल खोलना कवर करता है।

नीचे दिए गए उदाहरण में, एक **Draft response** बटन एजेंट को उपयोगकर्ता से एक प्रश्न पूछने के लिए प्रॉम्प्ट करता है। एक बार उपयोगकर्ता उत्तर दे देता है, एजेंट वर्तमान पेज कॉन्टेक्स्ट और उपयोगकर्ता के उत्तर को ध्यान में रखते हुए रिस्पॉन्स ड्राफ्ट करने लगता है।

## यह कैसे काम करता है

Agent-Native द्वारा प्रदान किए गए क्लाइंट हेल्पर मेथड का उपयोग करके, आपका UI एजेंट को उपयोगकर्ता के साथ विभिन्न तरीकों से इंटरैक्ट करने के लिए प्रॉम्प्ट कर सकता है। नीचे दिया गया डायग्राम दिखाता है कि उपयोगकर्ता द्वारा क्लिक किए गए "Draft response" बटन एजेंट को रिस्पॉन्स जनरेट करने से पहले उपयोगकर्ता के साथ इंटरैक्ट करने के लिए कैसे प्रॉम्प्ट कर सकता है।

उपयोगकर्ता का अनुभव इस प्रकार है:

1. उपयोगकर्ता **Draft response** बटन पर क्लिक करता है, जिससे `askUserQuestion()` फ़ंक्शन कॉल होता है। प्रश्न का उत्तर एजेंट पैनल में इनलाइन दिया जाता है।

1. उपयोगकर्ता **Offer a refund** चुनता है, जिससे `sendDraftRequest()` प्रॉम्प्ट और टिकट कॉन्टेक्स्ट को एजेंट को भेजता है।

1. एजेंट `draft-ticket-reply` [action](/docs/actions) को कॉल करता है, और ड्राफ्ट रिप्लाई रिप्लाई कंपोज़र में दिखाई देता है।

यह फ़ंक्शन ऐप कोड से उपयोगकर्ता से एक बहुविकल्पीय प्रश्न पूछता है, इसे एजेंट पैनल में इनलाइन रेंडर करता है, और उनके उत्तर की प्रतीक्षा करता है। इसका उपयोग तब करें जब UI को एजेंट का काम शुरू करने से पहले दो से चार विकल्पों के साथ एक छोटे निर्णय की आवश्यकता हो, कस्टम मॉडल बनाने के बजाय।

नीचे दिए गए उदाहरण में, किसी टिकट पेज पर "Draft Response" बटन कुछ भी एजेंट को भेजने से पहले रेप से पूछता है कि वे कैसे जवाब देना चाहेंगे:

```ts
import { askUserQuestion } from "@agent-native/core/client/agent-chat";

const answer = await askUserQuestion({
  question: "How would you like to respond to this ticket?",
  header: "Response", // optional short chip/heading (≈12 chars)
  options: [
    { label: "Offer a refund", value: "refund" },
    { label: "Offer a reprint", value: "reprint" },
  ],
});
```

  }}
/>

यह React हुक `sendToAgentChat()` को लोडिंग स्थिति ट्रैकिंग के साथ रैप करता है।

1. पहला आर्ग्युमेंट, `isGenerating`, जब आप इसे कॉल करते हैं तो true हो जाता है, फिर जब एजेंट जनरेट करना समाप्त कर देता है तो false पर रीसेट हो जाता है।

2. दूसरा आर्ग्युमेंट, `send()`, `sendToAgentChat()` फ़ंक्शन को दर्शाता है।

`isGenerating` केवल तब रीसेट होता है जब कोई रन वास्तव में शुरू होता है और रिपोर्ट करता है कि वह रुक गया है। एक `submit: false` कॉल एक रन शुरू किए बिना एक ड्राफ्ट को प्रीफिल करता है, इसलिए एक के बाद `isGenerating` हमेशा के लिए `true` रहता है। इस हुक का उपयोग केवल `submit: true` सेंड के लिए करें; प्रीफिल-ओनली के लिए सीधे `sendToAgentChat()` को कॉल करें।

## sendToAgentChat(opts) {#sendtoagentchat}

`postMessage` के माध्यम से एजेंट चैट पर एक मैसेज भेजें। यह वह लोअर-लेवल प्रिमिटिव है जिसे ऊपर दिया `useAgentChatGenerating()` रैप करता है, यह उपयोगी है जब किसी UI इंटरैक्शन को खुद की लोडिंग-स्टेट ट्रैकिंग की आवश्यकता नहीं होती। अतिरिक्त विवरण के लिए `context` पास करें जो मैसेज खुद नहीं बताता। यह उसी दिखने वाले मैसेज में जुड़ जाता है, `<context>` टैग में रैप्ड। यह उपयोगकर्ता से छिपा नहीं है। तुरंत भेजने के लिए `submit: true` पास करें, या एक ड्राफ्ट प्रीफिल करने के लिए `submit: false` पास करें जिसे उपयोगकर्ता पहले रिव्यू करता है।

```ts
import { sendToAgentChat } from "@agent-native/core/client/agent-chat";
// Auto-submit a prompt with appended context
sendToAgentChat({
  message: "Generate alt text for this image",
  context: "Image path: /api/projects/hero.jpg",
  submit: true,
});

// Prefill without submitting (user reviews first)
sendToAgentChat({
  message: "Rewrite this in a conversational tone",
  context: selectedText,
  submit: false,
});
```

### AgentChatMessage {#agentchatmessage}

| विकल्प        | प्रकार     | विवरण                                                                                            |
| ------------- | ---------- | ------------------------------------------------------------------------------------------------ |
| `message`     | `string`   | चैट पर भेजा गया प्रॉम्प्ट। यदि सेट है, तो `context` इसी दिखने वाले मैसेज में जुड़ जाता है        |
| `context`     | `string?`  | दिखने वाले मैसेज में जुड़ा अतिरिक्त विवरण, `<context>` टैग में रैप्ड। उपयोगकर्ता से छिपा नहीं है |
| `submit`      | `boolean?` | true = ऑटो-सबमिट, false = केवल प्रीफिल                                                           |
| `newTab`      | `boolean?` | इस प्रॉम्प्ट के लिए एक अलग चैट थ्रेड बनाएं                                                       |
| `openSidebar` | `boolean?` | साइडबार खोले बिना सबमिट/प्रीफिल करने के लिए false सेट करें                                       |

इसी रूट को MCP App के रूप में एम्बेड करने से, या साइडबार खोले बिना रन को बैकग्राउंड में ले जाने से जुड़ी बातें [उन्नत](/docs/client-advanced#background-send) में कवर की गई हैं।

## डायनामिक सुझाव {#dynamic-suggestions}

किसी बातचीत के शुरू होने से पहले, `<AgentSidebar>`, `<AgentPanel>`, और `<AssistantChat>` खाली चैट पर प्रॉम्प्ट चिप्स दिखाते हैं। डिफ़ॉल्ट रूप से वे केवल आपकी फ़िक्स्ड `suggestions` सूची नहीं हैं: फ्रेमवर्क एप्लिकेशन स्टेट से `navigation`, `selection`, `pending-selection-context`, और वर्तमान URL पढ़ता है, और स्क्रीन पर वास्तव में जो है उससे मेल खाने वाले चिप्स मर्ज करता है।

यह इसे दो जांचों के साथ करता है। यदि कुछ चुना गया है, तो यह सामान्य चिप्स जैसे "Summarize this selection" जोड़ता है। अलग से, यह `navigation` में उन कॉमन फ़ील्ड नामों को देखता है जिनका उपयोग ऐप्स पहले से करते हैं, जैसे किसी ईमेल थ्रेड के लिए `threadId`/`emailId` या किसी चार्ट के लिए `dashboardId`/`chartId`, और उस तरह की स्क्रीन के अनुरूप चिप्स जोड़ता है, जैसे थ्रेड के लिए "Draft a reply" या चार्ट के लिए "Find anomalies in this data"। यह जो भी लेकर आता है वह आपकी स्टैटिक `suggestions` के साथ मर्ज किया जाता है, डिडुप्लिकेट किया जाता है, और `max` पर कैप्ड किया जाता है।

```tsx
<AgentSidebar
  suggestions={["Summarize my inbox"]}
  dynamicSuggestions={{ max: 4 }}
>
  <App />
</AgentSidebar>
```

यदि वर्तमान स्क्रीन बिल्ट-इन हेयुरिस्टिक की पहचान की गई किसी चीज़ से मेल नहीं खाती और कुछ भी चुना नहीं गया है, तो यह कोई चिप्स नहीं जोड़ता, और खाली चैट केवल आपकी स्टैटिक `suggestions` पर वापस आ जाती है। केवल स्टैटिक चिप्स रखने के लिए `dynamicSuggestions={false}` सेट करें। यदि आपके ऐप की नेविगेशन शेप बिल्ट-इन हेयुरिस्टिक से मेल नहीं खाती, या आप पूरी तरह से नियतात्मक ऐप-विशिष्ट चिप्स चाहते हैं, तो [उन्नत](/docs/client-advanced#custom-suggestions) देखें।

## openAgentSettings(section?) {#openagentsettings}

`openAgentSettings()` का उपयोग तब करें जब किसी ऐप सेटिंग्स पेज या सेटअप कार्ड को
एजेंट साइडबार का Settings टैब खोलना चाहिए। किसी विशिष्ट सेक्शन को खोलने के लिए
`"llm"`, `"secrets"`, `"automations"`, `"voice"`, या `"limits"` जैसा एक सेक्शन id पास करें।

```ts
import { openAgentSettings } from "@agent-native/core/client/navigation";
openAgentSettings();
openAgentSettings("secrets");
```

सीधे `agent-panel:open-settings` डिस्पैच करने के बजाय इस हेल्पर को प्राथमिकता दें।

## एजेंट चैट कॉन्टेक्स्ट स्थिति {#agent-chat-context-state}

कॉन्टेक्स्ट-स्टेट APIs स्टेज्ड कॉन्टेक्स्ट चिप्स के साथ दो-तरफ़ा सिंक की आवश्यकता वाले UI के लिए वैकल्पिक प्लंबिंग हैं: कंपोज़र के बाहर वर्तमान स्टेज्ड आइटम को रेंडर करना, यह दर्शाना कि कोई आइटम पहले से अटैच है या नहीं, या स्पष्ट रिमूव/क्लियर कंट्रोल प्रदान करना।

सरल "इसे एजेंट को भेजें" या "इस ड्राफ्ट को रिव्यू के लिए प्रीफिल करें" फ्लो के लिए इन हेल्पर्स तक न पहुंचें। उनके लिए `context` और `submit` के साथ [`sendToAgentChat()`](#sendtoagentchat) का उपयोग करें।

| API                               | कब उपयोग करें                                                                     |
| --------------------------------- | --------------------------------------------------------------------------------- |
| `useAgentChatContext()`           | एक React घटक को लाइव स्टेज्ड कॉन्टेक्स्ट सूची की आवश्यकता है                      |
| `setAgentChatContextItem(item)`   | इंपेरेटिव कोड को एक keyed कॉन्टेक्स्ट आइटम को स्टेज या रिप्लेस करना चाहिए         |
| `listAgentChatContext()`          | नॉन-React कोड को स्टेज्ड कॉन्टेक्स्ट के एक बार के स्नैपशॉट की आवश्यकता है         |
| `removeAgentChatContextItem(key)` | UI को अपने स्थिर `key` से एक स्टेज्ड कॉन्टेक्स्ट आइटम हटा देना चाहिए              |
| `clearAgentChatContext()`         | UI को सभी स्टेज्ड कॉन्टेक्स्ट साफ़ करना चाहिए, जैसे किसी व्यू या मोड रीसेट के बाद |
| `refreshAgentChatContext()`       | इंपेरेटिव कोड को नवीनतम परसिस्टेड कॉन्टेक्स्ट स्नैपशॉट को फिर से पढ़ना चाहिए      |

`useAgentChatContext()`, `{ items, set, remove, clear, refresh }` लौटाता है।

```tsx
import { useAgentChatContext } from "@agent-native/core/client/agent-chat";

function SelectedTicketContextButton({ ticket }: { ticket: { id: string } }) {
  const chatContext = useAgentChatContext();
  const contextKey = `selected-ticket:${ticket.id}`;
  const isAttached = chatContext.items.some((item) => item.key === contextKey);

  return (
    <button
      type="button"
      onClick={() => {
        if (isAttached) {
          chatContext.remove(contextKey);
          return;
        }

        chatContext.set({
          key: contextKey,
          title: "Selected Ticket",
          context: JSON.stringify(ticket, null, 2),
          openSidebar: false,
        });
      }}
    >
      {isAttached ? "Remove from prompt context" : "Add to prompt context"}
    </button>
  );
}
```

`listAgentChatContext()` उस इंपेरेटिव कोड के लिए है जिसे केवल वर्तमान स्टेज्ड आइटम को एक बार निरीक्षण करने की आवश्यकता है। `clearAgentChatContext()` जानबूझकर व्यापक है। जब केवल एक सिलेक्शन बदला हो तो `removeAgentChatContextItem(key)` का उपयोग करें।

### AgentChatContextSetOptions {#agentchatcontextsetoptions}

| विकल्प        | प्रकार     | विवरण                                                                           |
| ------------- | ---------- | ------------------------------------------------------------------------------- |
| `key`         | `string`   | मौजूदा नगेट को रिप्लेस करने के लिए उपयोग किया जाने वाला स्थिर पहचानकर्ता        |
| `title`       | `string`   | कंपोज़र चिप में दिखाया गया छोटा लेबल                                            |
| `context`     | `string`   | अगले सबमिट किए गए प्रॉम्प्ट के साथ शामिल छिपा हुआ कॉन्टेक्स्ट                   |
| `openSidebar` | `boolean?` | डिफ़ॉल्ट रूप से true। कॉन्टेक्स्ट को साइलेंटली स्टेज करने के लिए false पास करें |
