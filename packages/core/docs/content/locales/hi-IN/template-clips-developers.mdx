# डेवलपर गाइड

यह पेज उन सभी के लिए है जो क्लिप्स टेम्पलेट को कस्टमाइज़ या एक्सटेंड कर रहे
हैं: क्विक स्टार्ट, हर action, डेटा मॉडल, रूट सरफ़ेस, और इसमें कुछ जोड़ने का
तरीका। ऐप क्या करता है यह जानने के लिए [क्लिप्स](/docs/template-clips) देखें।

## क्विक स्टार्ट

<Steps>

### ऐप बनाएं

```bash
npx @agent-native/core@latest create my-clips --standalone --template clips
cd my-clips
pnpm install
```

इसके लिए पहले [Node.js](https://nodejs.org) 22.22 या उसके बाद का वर्शन और
[pnpm](https://pnpm.io) इंस्टॉल होना चाहिए। अगर आपने अभी तक इनमें से कोई
इंस्टॉल नहीं किया है, या आपके पास कोई LLM कनेक्शन (Builder.io, कोई
Anthropic/OpenAI key, या लोकल Ollama) सेट नहीं है, तो
[शुरुआत करें](/docs/getting-started) देखें।

### डेव सर्वर शुरू करें

```bash
pnpm dev
```

ऐप आपके ब्राउज़र में अपने आप खुल जाता है। रिकॉर्डिंग बिना किसी एक्स्ट्रा
सेटअप के काम करती है, क्योंकि ब्राउज़र या डेस्कटॉप ऐप लोकली कैप्चर करता है।
आपको सिर्फ़ किसी ऐसे action पर एरर मिलेगी जिसे फ़ाइल स्टोरेज या AI क्रेडिट
चाहिए, जब तक इनमें से कोई कॉन्फ़िगर न हो।

</Steps>

<Callout tone="info">

रिकॉर्डिंग, ट्रांसक्रिप्शन, और AI शीर्षक/सारांश के एंड-टू-एंड काम करने से पहले
फ़ाइल स्टोरेज और AI क्रेडिट कॉन्फ़िगर होने चाहिए। दोनों के लिए एक साथ
**Settings** से Builder.io कनेक्ट करें (इसके फ़्री टियर में मैनेज्ड AI
क्रेडिट शामिल हैं), या S3-कम्पैटिबल स्टोरेज अलग से कनेक्ट करें और
ट्रांसक्रिप्शन के लिए अपनी खुद की Groq key लाएं। देखें
[ट्रांसक्रिप्शन और AI मेटाडेटा](/docs/template-clips-features#transcription-and-ai-metadata)।

</Callout>

## Action इन्वेंट्री

हर ऑपरेशन `templates/clips/actions/` में एक TypeScript फ़ाइल है, जो
`POST /_agent-native/actions/:name` पर ऑटो-माउंटेड है।

### लाइब्रेरी और रिकॉर्डिंग

| Action                                                                                    | यह क्या करता है                                                              |
| ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `list-recordings`, `search-recordings`                                                    | लाइब्रेरी, शेयर्ड-विद-मी, ट्रैश, और स्पेस-स्कोप्ड लिस्टिंग                   |
| `create-recording`, `finalize-recording`                                                  | रो बनाना; अपलोड पूरा करना                                                    |
| `import-loom-recording`                                                                   | किसी Loom वीडियो या सीधे MP4/WebM URL को इम्पोर्ट करना                       |
| `update-recording`                                                                        | शीर्षक, विवरण, पासवर्ड, एक्सपायरी, दृश्यता                                   |
| `move-recording`                                                                          | एक या कई रिकॉर्डिंग को किसी फ़ोल्डर या रूट में मूव करना                      |
| `archive-recording`, `trash-recording`, `restore-recording`, `delete-recording-permanent` | लाइफ़साइकल: छुपाना, सॉफ़्ट-डिलीट करना, अनडू करना, या हमेशा के लिए डिलीट करना |
| `reprocess-recording`                                                                     | अनसीकेबल या फ़्रोज़न मीडिया को ठीक करना                                      |
| `generate-filmstrip`                                                                      | एडिटर टाइमलाइन फ़्रेम स्प्राइट                                               |
| `tag-recording`, `set-thumbnail`                                                          | टैगिंग और हाथ से चुना गया थंबनेल फ़्रेम                                      |

## डेटा मॉडल

`templates/clips/server/db/schema.ts` में डिफ़ाइन किया गया है।

<Callout tone="warning">

टीम, मेंबर, और इनवाइटेशन रो फ़्रेमवर्क की अपनी `organizations`,
`org_members`, और `org_invitations` टेबल में रहती हैं, किसी
क्लिप्स-स्पेसिफ़िक टेबल में नहीं। `organization_settings` क्लिप्स का अपना
साइडकार है: ब्रांड कलर, लोगो, और डिफ़ॉल्ट दृश्यता, हर संगठन के लिए एक रो। एक
पुराना `workspaces`/`workspace_members` जोड़ा अभी भी सिर्फ़ इसलिए मौजूद है
ताकि एक बार चलने वाली स्टार्टअप माइग्रेशन किसी मौजूदा डिप्लॉयमेंट पर
फ़्रेमवर्क टेबल को बैकफ़िल कर सके। इनके ऊपर नई सुविधाएं मत बनाएं।

</Callout>

## एक action को समझना

`create-recording-agent-link` ऐसे पैटर्न दिखाता है जो किसी भी ऐसे action में
दोबारा इस्तेमाल करने लायक हैं जो कोई स्कोप्ड क्रेडेंशियल बनाता है: कुछ भी
देने से पहले रिसोर्स की असली स्थिति चेक करना, असली टोकन बनाने का काम खुद करने
के बजाय किसी शेयर्ड फ़्रेमवर्क हेल्पर को सौंपना, और कॉलर को चाहिए हर URL को उस
एक ग्रांट से निकालना।

## इसे कस्टमाइज़ करना

ऐप का हर हिस्सा एडिटेबल सोर्स है। यहां से शुरू करें:

- `templates/clips/actions/` — एजेंट और फ्रंटएंड दोनों को नई क्षमता एक्सपोज़
  करने के लिए `defineAction` के साथ एक नई फ़ाइल जोड़ें।
- `templates/clips/app/routes/` — UI, ऊपर लिस्ट किया गया।
- `templates/clips/server/db/schema.ts` — Drizzle के साथ कॉलम या टेबल जोड़ें।
  स्कीमा को PostgreSQL-कम्पैटिबल रखें ताकि टेम्पलेट लोकल PGlite और होस्टेड
  Postgres दोनों पर चले।
- `templates/clips/server/lib/` — प्रोवाइडर इंटीग्रेशन:
  `google-calendar-client.ts`, `s3-upload-provider.ts`, `slack-oauth.ts`,
  `video-remux.ts`, `video-filmstrip-sprite.ts`।
- `templates/clips/AGENTS.md` — एजेंट इंस्ट्रक्शन। जब आप एजेंट को नई क्षमताएं
  या कन्वेंशन सिखाएं तो इसे अपडेट करें।
- `templates/clips/.agents/skills/` — डिटेल्ड पैटर्न जिनका एजेंट पालन करता है।
  संबंधित स्किल्स: `recording`, `ai-video-tools`, `video-editing`,
  `video-sharing`, `screen-memory`।
- `templates/clips/shared/api.ts` — सर्वर और क्लाइंट दोनों द्वारा इस्तेमाल किए
  जाने वाले शेयर्ड TypeScript टाइप्स।
- `templates/clips/desktop/` और `templates/clips/chrome-extension/` — नेटिव
  कैप्चर सरफ़ेस के लिए अलग पैकेज, हर एक का अपना `package.json` और बिल्ड।

अगर आप कोई फ़ीचर जोड़ते हैं, तो सभी चार एरिया अपडेट करना याद रखें: UI, action,
skill या AGENTS.md एंट्री, और कोई भी application state जिसे एजेंट को देखने की
ज़रूरत है। यही एजेंट और UI को बराबर बनाए रखता है।
