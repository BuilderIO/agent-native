# अवलोकन

`app/` वह जगह है जहां आप एजेंट-नेटिव ऐप का वास्तविक डिस्प्ले बनाते हैं: पेज, लेआउट, घटक, स्टाइल। `public/` इसके साथ परोसी जाने वाली स्टैटिक एसेट्स रखता है - आइकन, मैनिफेस्ट, ब्रांड मार्क। यह एक सामान्य React Router v8 ऐप है, कोई विशेष एजेंट-ओनली सतह नहीं, और यहीं अधिकांश डेवलपमेंट समय व्यतीत होता है।

एक सामान्य फ्रंटएंड से यही वास्तुशिल्प अंतर है: इस लेयर का अपना कोई बैकएंड-फॉर-फ्रंटएंड नहीं है। यह उन्हीं actions के माध्यम से डेटा पढ़ता और लिखता है जिन्हें एजेंट कॉल करता है, इसलिए यहां वायर की गई कोई भी क्षमता स्वचालित रूप से वह चीज़ बन जाती है जो एजेंट भी कर सकता है।

## क्लाइंट कहां फिट होता है {#role}

ब्राउज़र रिक्वेस्ट, एजेंट लूप, और बाहरी API क्लाइंट सभी एक ही actions और एक ही SQL डेटाबेस पर रिज़ॉल्व होते हैं - यहां कोई अलग "ऐप बैकएंड" नहीं है जिससे यह लेयर बात करती हो और जिसे एजेंट न पहुंच सके। यहां कोई फ़ीचर बनाने का मतलब है ऐसे ऑपरेशन के ऊपर UI बनाना जो एजेंट के पास पहले से है, या एक नई action परिभाषित करना और उसके लिए एक साथ UI पाना। उस कॉन्ट्रैक्ट के ऑपरेशन साइड के लिए [Actions](/docs/actions-overview) देखें।

यह पेज उन डायरेक्टरी को कवर करता है जिनमें आप बनाते हैं और ब्राउज़र रनटाइम के उन हिस्सों को जिन्हें कोई और डॉक्यूमेंट नहीं करता (`root.tsx`, `public/`)। वे React हुक जो आपके घटकों को actions और एजेंट से जोड़ते हैं, अपने-अपने केंद्रित पेजों पर रहते हैं:

| पेज                                              | यह क्या कवर करता है                                                                                                |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| **[डेटा और सिंक](/docs/client-data)**            | `useActionQuery`, `useActionMutation`, `callAction`, और `useDbSync`                                                |
| **[एजेंट चैट](/docs/client-agent-chat)**         | `sendToAgentChat`, `askUserQuestion`, `openAgentSettings`, डायनामिक सुझाव, और स्टेज्ड एजेंट चैट कॉन्टेक्स्ट स्थिति |
| **[उन्नत](/docs/client-advanced)**               | सीधी `application_state` एक्सेस, बैकग्राउंड चैट सेंड, कस्टम सुझाव चिप्स, और MCP App होस्ट ब्रिज                    |
| **[सिंक इंटरनल्स](/docs/client-sync-internals)** | कच्चे `useQuery` को सिंक करने के लिए `useChangeVersion`/`useChangeVersions`                                        |
| **[एंट्री पॉइंट्स](/docs/client-entry-points)**  | `app/entry.client.tsx`/`app/entry.server.tsx` और SSR कस्टमाइज़ेशन                                                  |

## app/ और public/ में क्या है {#project-directories}

| पथ                                                  | यह क्या कवर करता है                                                                                            |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **`app/root.tsx`**                                  | HTML शेल और प्रोवाइडर स्टैक - नीचे [ब्राउज़र शेल](#app-shell) देखें                                            |
| **`app/entry.client.tsx` / `app/entry.server.tsx`** | हाइड्रेशन और SSR बूटस्ट्रैप - [एंट्री पॉइंट्स](/docs/client-entry-points) देखें                                |
| **`app/routes.ts` + `app/routes/`**                 | फ़ाइल-आधारित पेज और नेविगेशन - [रूटिंग](/docs/client-routing) देखें                                            |
| **`app/components/`**                               | आपका UI: shadcn-स्टाइल प्रिमिटिव प्लस ऐप-विशिष्ट घटक - [shadcn/ui](/docs/toolkit-ui) देखें                     |
| **`app/hooks/`**                                    | डेटा, सिंक, और एजेंट-चैट हुक - [डेटा और सिंक](/docs/client-data) और [एजेंट चैट](/docs/client-agent-chat) देखें |
| **`app/lib/`**                                      | साझा क्लाइंट यूटिलिटीज़ (ऐप कॉन्फिग, टैब आईडी, `cn`) - नीचे [यूटिलिटीज़](#utilities) देखें                     |
| **`app/design-system.ts`**                          | वैकल्पिक कस्टम डिज़ाइन सिस्टम एडाप्टर - [कस्टम डिज़ाइन सिस्टम](/docs/custom-design-system) देखें               |
| **`app/i18n/`**                                     | लोकलाइज़्ड UI कॉपी कैटलॉग - [Internationalization](/docs/internationalization) देखें                           |
| **`app/global.css`**                                | बेस स्टाइल और Tailwind एंट्री पॉइंट                                                                            |
| **`public/`**                                       | स्टैटिक एसेट्स जैसी हैं वैसी ही परोसी जाती हैं - नीचे [स्टैटिक एसेट्स](#public-directory) देखें                |

## ब्राउज़र शेल: root.tsx और AppProviders {#app-shell}

`app/root.tsx` React ट्री का शीर्ष है: HTML डॉक्यूमेंट शेल (`<html>`, `<head>`, `<Meta>`, `<Links>`, `<Scripts>`) प्लस वह प्रोवाइडर स्टैक जिसके अंदर हर रूट रेंडर होता है।

```tsx filename="app/root.tsx"
import {
  AppProviders,
  createAgentNativeQueryClient,
} from "@agent-native/core/client/hooks";
import { useState } from "react";
import { Outlet } from "react-router";
import { i18nCatalog } from "./i18n";

export default function Root() {
  const [queryClient] = useState(() => createAgentNativeQueryClient());

  return (
    <AppProviders queryClient={queryClient} i18n={{ catalog: i18nCatalog }}>
      <Outlet />
    </AppProviders>
  );
}
```

`AppProviders` एक ही रैपर है जो इसे वायर करता है:

- वह React Query क्लाइंट जिसका उपयोग `useActionQuery`/`useActionMutation` करते हैं (देखें [डेटा और सिंक](/docs/client-data#fetching-mutating))।
- `i18n.catalog` के रूप में पास किया गया i18n कैटलॉग (देखें [Internationalization](/docs/internationalization))।
- क्लाइंट-साइड सेशन जांच: किसी प्राइवेट पथ पर, एक अनाम विज़िटर को किसी भी प्राइवेट UI माउंट होने से पहले साइन-इन पर रीडायरेक्ट किया जाता है। पब्लिक/SEO रूट्स के लिए `isPublicPath` पास करें, या ऐसी सतह के लिए `sessionBypass` जो किसी और तरीके से प्रमाणित होती है, जैसे MCP एम्बेड टोकन। देखें [Authentication](/docs/authentication)।

अधिकांश ऐप्स यहां `<AgentSidebar>` या `<AgentPanel>` भी माउंट करते हैं ताकि हर रूट को मुफ़्त में एजेंट पैनल मिल जाए। देखें [ड्रॉप-इन एजेंट](/docs/drop-in-agent#sidebar)।

## स्टैटिक एसेट्स: public/ {#public-directory}

`public/` में सब कुछ जैसा है वैसा ही साइट रूट पर परोसा जाता है, बिल्ड द्वारा प्रोसेस नहीं किया जाता। हर टेम्पलेट यह शिप करता है:

```text
public/
  favicon.svg           -> ब्राउज़र टैब आइकन
  icon-180.svg           -> apple-touch-icon
  icon-192.svg, icon-512.svg -> manifest.json से रेफ़र किए गए PWA आइकन
  manifest.json          -> वेब ऐप मैनिफेस्ट (नाम, थीम रंग, आइकन)
  *-logo-*.svg, *-icon-*.svg -> डिफ़ॉल्ट UI में उपयोग किए गए ब्रांड मार्क
```

`manifest.json` यह नियंत्रित करता है कि यदि कोई विज़िटर ऐप को होम स्क्रीन या ऐप डॉक में इंस्टॉल करता है तो क्या दिखता है - नाम, शॉर्ट नेम, थीम/बैकग्राउंड रंग, और आइकन सेट:

```json filename="public/manifest.json"
{
  "name": "My App",
  "short_name": "My App",
  "theme_color": "#18181B",
  "icons": [
    { "src": "icon-192.svg", "sizes": "192x192", "type": "image/svg+xml" }
  ]
}
```

इन फ़ाइलों को बदलकर और `root.tsx` में इन्हें रेफ़र करने वाले `manifest.json` और `<link rel="icon">`/`<link rel="apple-touch-icon">` टैग को अपडेट करके किसी ऐप को रीब्रांड करें - कोई अलग रजिस्ट्रेशन स्टेप नहीं है। किसी मौजूदा साइट से पूरा ब्रांड सिस्टम (रंग, फ़ॉन्ट, फ़ेविकॉन) खींचने के लिए, इन फ़ाइलों को हाथ से एडिट करने के बजाय, देखें [Brand Systems and Figma](/docs/template-design-brand-and-figma)।

## यूटिलिटीज़: cn {#utilities}

```ts
import { cn } from "@agent-native/toolkit/utils";

<div className={cn(
  "px-4 py-2 rounded",
  isActive && "bg-primary text-primary-foreground",
  className
)} />
```

`cn` क्लास नामों को मर्ज करता है (clsx + tailwind-merge) और `app/components/` में कंडीशनल Tailwind क्लासेस को कंपोज़ करने का स्टैंडर्ड तरीका है।
