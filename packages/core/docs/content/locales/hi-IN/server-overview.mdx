# सर्वर

`server/` डायरेक्टरी एजेंट-नेटिव ऐप की इंफ्रास्ट्रक्चर परत है। यह स्टार्टअप कार्य, प्रमाणीकरण, और वे HTTP सतहें संभालती है जिन्हें Actions कवर नहीं करते। अधिकांश उत्पाद व्यवहार [Actions](/docs/actions) में रहता है। सर्वर वह है जो उन Actions को उपलब्ध बनाता है।

## सर्वर की भूमिका कहाँ है {#role}

एक पारंपरिक वेब ऐप में, अधिकांश लॉजिक सर्वर में रहता है। व्यावसायिक नियम, डेटा एक्सेस, और प्रेजेंटेशन सब कुछ रूट हैंडलर के भीतर होता है। एजेंट-नेटिव ऐप्स अलग तरीके से काम करते हैं। लॉजिक Actions में रहता है, जिसे एजेंट और UI समान भागीदारों के रूप में साझा करते हैं। सर्वर का काम समन्वय करना है: डेटाबेस माइग्रेशन चलाना, प्रमाणीकरण कॉन्फ़िगर करना, एजेंट लूप माउंट करना, और उन सीमित HTTP सरोकारों को संभालना जिन्हें Actions खुद व्यक्त नहीं कर सकते।

ब्राउज़र अनुरोध, एजेंट लूप, और बाहरी API क्लाइंट सभी एक ही Nitro सर्वर से होकर गुजरते हैं और एक ही SQL डेटाबेस से पढ़ते हैं। न कोई अलग एजेंट बैकएंड है, न कोई अलग UI बैकएंड। सर्वर परत ही वह है जो Actions को बाहरी दुनिया के सामने उजागर करती है।

## server/ डायरेक्टरी में क्या है {#server-directory}

ये वे डायरेक्टरी और फ़ाइलें हैं जो `server/` के भीतर हर एजेंट-नेटिव ऐप शिप करता है। प्रत्येक सर्वर परत के एक विशिष्ट हिस्से से मेल खाती है: यह क्या करती है, इसे कब अपनाना है, और यह फ्रेमवर्क के बाकी हिस्सों से कैसे जुड़ती है।

| पेज                                      | यह क्या कवर करता है                                                                      |
| ----------------------------------------- | ----------------------------------------------------------------------------------------- |
| **[डेटाबेस](/docs/server-database)**     | `table()` हेल्पर्स, `getDb`, और ownable टेबल पैटर्न के साथ स्कीमा परिभाषा       |
| **[मिडलवेयर](/docs/server-middleware)** | `server/middleware/` में Auth गार्ड और वे प्लगइन के बजाय वहाँ क्यों चलते हैं   |
| **[प्लगइन्स](/docs/server-plugins)**       | हर ऐप जो तीन स्टार्टअप प्लगइन शिप करता है: db माइग्रेशन, auth, और agent-chat      |
| **[रूट्स](/docs/server-routes)**         | फ़ाइल-आधारित रूट्स, SSR कैच-ऑल, और अनुरोध उपयोगकर्ता तक कस्टम रूट्स का दायरा तय करना |

## Nitro {#nitro}

[Nitro](https://nitro.build) वह सर्वर टूलकिट है जो एजेंट-नेटिव HTTP परत को शक्ति देता है। `server/` में आप जो अधिकांश चीज़ें कॉन्फ़िगर करते हैं वह Nitro ही है: फ़ाइल-आधारित रूट्स, स्टार्टअप प्लगइन्स, और मिडलवेयर।

- **फ़ाइल-आधारित रूटिंग**: फ़ाइलनाम सीधे एक HTTP मेथड और URL पथ से मैप होता है, बिना किसी रजिस्ट्रेशन की आवश्यकता के। `server/routes/api/health.get.ts` अपने आप `GET /api/health` बन जाता है। अधिक विवरण के लिए [रूट्स](/docs/server-routes) देखें।
- **प्लगइन्स**: वह कोड जो सर्वर स्टार्टअप पर एक बार चलता है, किसी भी अनुरोध को सर्व करने से पहले। डेटाबेस माइग्रेशन, auth कॉन्फ़िगरेशन, और agent-chat माउंट - ये सब `server/plugins/` में होते हैं। अधिक विवरण के लिए [प्लगइन्स](/docs/server-plugins) देखें।
- **मिडलवेयर**: वह कोड जो हर आने वाले अनुरोध पर, किसी रूट तक पहुँचने से पहले चलता है। Auth गार्ड `server/middleware/` में रहता है। अधिक विवरण के लिए [मिडलवेयर](/docs/server-middleware) देखें।

Nitro डिप्लॉयमेंट-अज्ञेयवादी भी है। बिना किसी कोड परिवर्तन के वही ऐप Node.js, Cloudflare Workers, Netlify, Vercel, और अन्य रनटाइम पर तैनात होता है। बस एक प्रीसेट सेट करें। [तैनाती](/docs/deployment) देखें।

अंतर्निहित अनुरोध/प्रतिक्रिया API [H3](https://h3.unjs.io) है। जब आप कस्टम रूट्स में `defineEventHandler`, `createError`, या `getQuery` देखते हैं, वह H3 है। [Nitro डॉक्स](https://nitro.build/guide) और [H3 डॉक्स](https://h3.unjs.io) उस किसी भी चीज़ के लिए संदर्भ हैं जिसे फ्रेमवर्क सीधे कवर नहीं करता।

## पहले Actions को डिफ़ॉल्ट मानें {#actions-first}

Agent Native आर्किटेक्चर अलग है। जब भी आप अपने एप्लिकेशन के लिए किसी नई सुविधा के बारे में सोचें, तो पहले यह विचार करें कि क्या यह एक Action हो सकती है। उदाहरण के लिए, यदि UI और एजेंट दोनों को कुछ करने की आवश्यकता है, तो कस्टम API रूट के बजाय एक Action परिभाषित करें। Actions स्वचालित रूप से बन जाते हैं:

- एजेंट टूल्स।
- टाइप किए गए फ्रंटएंड हुक्स।
- `/_agent-native/actions/:name` के तहत HTTP एंडपॉइंट्स।
- MCP और A2A-कॉल करने योग्य टूल्स।
- डेवलपमेंट के लिए CLI कमांड्स।

कस्टम `/api/*` रूट्स का उपयोग तभी करें जब आपको रूट-आकार का प्रोटोकॉल या बाइनरी/स्ट्रीमिंग व्यवहार चाहिए। अधिक विवरण के लिए [Actions](/docs/actions) देखें।

## आगे क्या है

- [**Actions**](/docs/actions): डिफ़ॉल्ट ऑपरेशन सतह। कस्टम रूट का सहारा तभी लें जब यह फ़िट न बैठे।
- [**डेटाबेस**](/docs/server-database): `getDb()`/स्कीमा पैटर्न जिसे कस्टम रूट्स और Actions दोनों इम्पोर्ट करते हैं
- [**मिडलवेयर**](/docs/server-middleware): Auth गार्ड और `server/middleware/` डायरेक्टरी
- [**प्लगइन्स**](/docs/server-plugins): माइग्रेशन, auth, और एजेंट के लिए स्टार्टअप प्लगइन्स
- [**रूट्स**](/docs/server-routes): फ़ाइल-आधारित रूट्स, अनुरोध संदर्भ, और SSR कैच-ऑल
