# डेटा और सिंक

क्लाइंट एप्लिकेशन से ऐप डेटा पढ़ने और लिखने का प्राथमिक तरीका [action](/docs/actions-overview) हुक के माध्यम से है। रिक्वेस्ट को actions में एम्बेड करके, आपका क्लाइंट और एजेंट दोनों आपके एप्लिकेशन के साथ एक ही तरीके से इंटरैक्ट कर सकते हैं।

नीचे दिए गए उदाहरण में, एक टिकट को वर्तमान उपयोगकर्ता को पहले मैन्युअल रूप से एक ड्रॉपडाउन के माध्यम से असाइन किया जाता है, और फिर चैट एजेंट के माध्यम से। UI और एजेंट दोनों एक ही action का उपयोग करते हैं।

### Action हुक {#action-hooks}

दो action हुक हैं जिनका उपयोग करने की सबसे अधिक संभावना है: `useActionQuery()` और `useActionMutation()`। ये दो हुक आपके ऐप की actions तक एक्सेस प्रदान करते हैं।

यह हुक केवल-पढ़ने योग्य actions के लिए उपयोग किए जाने का इरादा है। यह [useQuery()](https://tanstack.com/query/latest/docs/framework/react/reference/useQuery) फ़ंक्शन के इर्द-गिर्द एक पतला रैपर है।

नीचे दिए गए उदाहरण में, `list-tickets` action को कॉल किया जाता है। यह सभी टिकट के लिए GET रिक्वेस्ट बनाने जैसा है।

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery("list-tickets", {});
```

निम्नलिखित उदाहरण `get-ticket` action के माध्यम से एक ही टिकट को फ़ेच करने के लिए एक रिक्वेस्ट दिखाता है। क्वेरी को केवल एक विशिष्ट टिकट लौटाने के लिए स्कोप करने के लिए एक `ticketId` प्रदान किया जाता है। अतिरिक्त `enabled` विकल्प यह सुनिश्चित करने के लिए प्रदान किया गया है कि क्वेरी स्वचालित रूप से नहीं चलती है, और केवल तब चलती है जब कोई `ticketId` मौजूद हो।

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery(
  "get-ticket",
  { ticketId: ticketId ?? "" },
  { enabled: Boolean(ticketId) },
);
```

यह हुक उन actions के लिए उपयोग किए जाने का इरादा है जो डेटा बदलती हैं, जैसे बनाना, अपडेट करना, या कुछ भेजना। यह [useMutation()](https://tanstack.com/query/latest/docs/framework/react/reference/useMutation) फ़ंक्शन के इर्द-गिर्द एक पतला रैपर है।

`useActionQuery()` के विपरीत, action का इनपुट हुक को स्वयं पास नहीं किया जाता है। इसे `mutate()` या `mutateAsync()` को पास किया जाता है जब आप म्यूटेशन चलाने के लिए तैयार हों।

नीचे दिए गए उदाहरण में, `send-ticket-reply` action को किसी टिकट पर रिप्लाई पोस्ट करने के लिए कॉल किया जाता है। किसी इवेंट हैंडलर से, जैसे किसी बटन के `onClick` से, `mutate()` कॉल करें।

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply");

mutate({ ticketId, body: draft });
```

निम्नलिखित उदाहरण एक `onSuccess` विकल्प के साथ वही म्यूटेशन दिखाता है। कैश इनवैलिडेशन हर म्यूटेशन के बाद स्वचालित रूप से होता है, इसलिए `onSuccess` की आवश्यकता केवल लोकल साइड इफ़ेक्ट के लिए होती है, जैसे रिप्लाई भेजने के बाद रिप्लाई कंपोज़र को साफ़ करना।

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply", {
  onSuccess: () => setDraft(""),
});

mutate({ ticketId, body: draft });
```

यह फ़ंक्शन React रेंडर फ्लो के बाहर इंपेरेटिव वन-ऑफ़ action कॉल के लिए है, जैसे कोई सादा इवेंट हैंडलर, एक स्क्रिप्ट, या कोई अन्य नॉन-React कोड पथ। यह एक हुक परिणाम के बजाय सीधे एक प्रॉमिस लौटाता है।

नीचे दिए गए उदाहरण में, `update-ticket` action को एक कीबोर्ड शॉर्टकट हैंडलर से React के रेंडर फ्लो के बाहर कॉल किया जाता है, जो टिकट को एक रेप को असाइन करता है।

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction("update-ticket", {
  ticketId,
  assignedToEmail: "jordan@example.com",
});
```

निम्नलिखित उदाहरण `timeoutMs` विकल्प के साथ वही कॉल दिखाता है, जो उन actions के लिए उपयोगी है जो वैध रूप से डिफ़ॉल्ट 60 सेकंड टाइमआउट से अधिक समय लेती हैं।

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction(
  "update-ticket",
  { ticketId, assignedToEmail: "jordan@example.com" },
  { timeoutMs: 120_000 },
);
```

हर `useActionQuery()`, `useActionMutation()`, और `callAction()` रिक्वेस्ट 60 सेकंड के टाइमआउट से बंधी है, और टाइमआउट बिना साइलेंट रीट्राई के त्रुटियों के रूप में सामने आते हैं। `useActionQuery()` React Query के एबॉर्ट सिग्नल का उपयोग करते हुए सुपरसीडेड रिक्वेस्ट को भी स्वचालित रूप से कैंसल करता है।

यह हुक UI को उन डेटाबेस बदलावों के साथ सिंक में रखने के लिए है जो आपकी अपनी actions के बाहर होते हैं, जैसे कोई एजेंट राइट, कोई वेबहुक, या किसी अन्य ब्राउज़र टैब से किया गया बदलाव। यह सर्वर-सेंट इवेंट पर बदलावों को सुनता है, और सर्वर-सेंट इवेंट उपलब्ध न होने पर पोलिंग पर वापस आ जाता है।

```ts
import { useDbSync } from "@agent-native/core/client/hooks";
import { useQueryClient } from "@tanstack/react-query";

function App() {
  const queryClient = useQueryClient();

  useDbSync({
    queryClient,
    pollUrl: "/_agent-native/poll",
    onEvent: (data) => console.log("Data changed:", data),
  });

  return <div>...</div>;
}
```

सामान्य CRUD के लिए, `useActionQuery()` और `useActionMutation()` को प्राथमिकता दें। म्यूटेटिंग actions `source: "action"` उत्सर्जित करती हैं, इसलिए वे हुक तुरंत रीफ़ेच होते हैं। एजेंट, किसी वेबहुक, या किसी अन्य टैब से आने वाले बदलाव इसके बजाय `useDbSync()` के माध्यम से आते हैं, SSE या पोलिंग फ़ॉलबैक पर। यदि किसी कस्टम key पर कच्चे `useQuery()` कॉल को सिंक करने की आवश्यकता है, तो [सिंक इंटरनल्स](/docs/client-sync-internals) देखें। यदि आपको सीधे `application_state` पर लिखने की आवश्यकता है, तो [उन्नत](/docs/client-advanced) देखें।
