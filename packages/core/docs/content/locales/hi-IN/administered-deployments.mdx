# प्रशासित डिप्लॉयमेंट

एक संगठन के internal apps के लिए workspace चुनें। संगठन membership और data boundary है। Workspace एक या अधिक apps के deployment और config को साथ रखता है।

## Signup और org creation बंद करें

```dotenv
AUTH_SIGNUP=invited
ORG_CREATION=closed
AUTO_CREATE_DEFAULT_ORG=0
AUTH_BOOTSTRAP_ADMINS=admin@example.com
AUTH_REQUIRE_EMAIL_VERIFICATION=1
```

`AUTH_SIGNUP=invited` में नए account को pending invitation, verified और allowed email domain, या `AUTH_BOOTSTRAP_ADMINS` में address चाहिए। यह password, magic link और social signup पर लागू होता है। Domain join invitation नहीं है और app role assign नहीं करता।

पहला sign-in करने वाला bootstrap admin canonical org बनाकर उसका owner बनता है। यदि एक org पहले से है, तो admin उसका owner बनेगा। कई org होने पर सिस्टम चुनाव नहीं करता। फिर Team settings में allowed domain सेट करें और बाकी लोगों को आमंत्रित करें।

## कंपनी की keys और roles

Owner या admin org के लिए LLM key सहेज सकता है। सदस्य के personal key को हटाकर org key चुना जा सकता है। App roles एक app के भीतर लागू होते हैं और एक सदस्य के कई roles हो सकते हैं। Admin बिना redeploy किए code-declared permissions को roles से जोड़ सकता है।

## ईमेल और पहचान बदलना

सत्यापन के बाद उपयोगकर्ता account settings में sign-in email बदल सकता है। Admin migration के लिए हर app में `agent-native identity rekey --from old@example.com --to new@example.com` चलाएँ। `--yes` से पहले तालिकाएँ और row counts देखें। पुराने audit records नहीं बदलते। Immutable principal ID migration 1.0 के बाद की योजना है।

## संगठन SSO और डायरेक्टरी प्रोविज़निंग

संगठन SSO और SCIM वैकल्पिक सुविधाएँ हैं। Team settings में नियंत्रण दिखाने के लिए `AUTH_SSO=1` और `AUTH_SCIM=1` सेट करें। इन flags को build और runtime दोनों environment में सेट करें; deployment के बाद बदलने पर फिर से build करना होगा। पहले संगठन का ईमेल डोमेन कॉन्फ़िगर करें। OIDC या SAML प्रदाता जोड़ें। OIDC के लिए issuer, client ID और secret दें। SAML के लिए entry point, entity ID और IdP metadata XML पेस्ट करें। सेटिंग में redirect URI और SP metadata दिखेंगे। दिखाए गए मान के साथ `_better-auth-token-<provider-id>.<organization-domain>` DNS TXT रिकॉर्ड जोड़ें, DNS के प्रसार की प्रतीक्षा करें और डोमेन सत्यापित करें। इसके बाद admin Google या सत्यापित SSO प्रदाता को आवश्यक कर सकता है। SCIM कनेक्शन बनाकर एक बार दिखने वाला token और endpoint identity provider में कॉन्फ़िगर करें। Okta या Microsoft Entra ID में OIDC या SAML enterprise app बनाएं। Provisioning के लिए SCIM client कॉन्फ़िगर करें और सीमित समूह में उपयोगकर्ता बनाना, अपडेट और निष्क्रिय करना जांचें। यह apps के बीच identity federation से अलग है।

Server operations के लिए `accessFilter()` और `assertAccess()` इस्तेमाल करें। Agent SQL अस्थायी filtered views का उपयोग करता है। `pnpm guards` में unscoped-query check शामिल है। RLS अभी active नहीं है और 1.0 के बाद hardening के रूप में नियोजित है। कई internal apps के लिए workspace और एक अलग tool या prototype के लिए standalone app चुनें। [Standalone या workspace](/docs/multi-app-workspace#standalone-or-workspace) और [versioning और stability](/docs/versioning-and-stability) देखें।
