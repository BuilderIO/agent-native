# तैनाती

Agent-Native ऐप [Nitro](https://nitro.build) पर चलते हैं, इसलिए एक ही ऐप
Node.js, serverless functions, edge workers, या किसी managed host पर deploy हो
सकता है। आप जो ship कर रहे हैं, उसके अनुसार रास्ता चुनें:

<Cards columns={2}>

### :server: [ऐप deploy करें](/docs/deploy-an-app)

एक standalone ऐप build करें और उसे Node.js, Docker, Vercel, Netlify, या
Cloudflare Workers पर launch करें।

### :network: [कार्यस्थान तैनाती](/docs/workspace-deployment)

Shared login और same-origin app-to-app communication के साथ कई ऐप एक origin के
पीछे build करें।

</Cards>

## Deploy करने से पहले: persistent database चुनें {#persistent-database}

हर deployed ऐप को एक persistent PostgreSQL database चाहिए। Local development में
`data/pglite` वाला PGlite database इस्तेमाल हो सकता है, लेकिन container, preview,
और serverless filesystems कभी भी reset हो सकते हैं।

<Steps>

### Provider चुनें

कोई hosted PostgreSQL provider इस्तेमाल करें, जैसे [Neon](/docs/neon),
[Supabase](/docs/supabase), Railway, Render, [Amazon RDS for PostgreSQL](/docs/aws-rds),
[Cloud SQL for PostgreSQL](/docs/cloud-sql), या [Azure Database for PostgreSQL](/docs/azure-postgresql)।
दूसरी managed services और self-hosted PostgreSQL servers के लिए [Plain Postgres](/docs/postgres)
guide इस्तेमाल करें। Framework connection URL से PostgreSQL configure
करता है।

### Connection string सेट करें

पहले production deploy से पहले hosting provider की environment-variable या secret
settings में `DATABASE_URL` सेट करें। Local `.env` सिर्फ आपकी machine को configure
करती है और deploy command उसे upload नहीं करता।

### Production secrets जोड़ें

`openssl rand -hex 32` से एक stable signing secret बनाएं, फिर standalone ऐप के लिए
उसे `BETTER_AUTH_SECRET` के रूप में सेट करें। जब कोई workspace signed cross-app
requests या background handoffs इस्तेमाल करता है, तो उसे `A2A_SECRET` भी चाहिए।
[Deployment environment reference](/docs/deployment-environment-variables) बाकी
production configuration बताता है।

### Migrations चलाएं

पहली visit से पहले production database के against `pnpm migrate:production`
चलाएं। यह वे tables बनाता है जिनकी ऐप को ज़रूरत है। हर upgrade के बाद, नया version
live होने से पहले, इसे फिर से चलाएं। हर hosting guide बताती है कि यह चरण कहां आता है।

</Steps>

<Callout tone="info">

Workspace में हर ऐप default रूप से root `DATABASE_URL` inherit करता है।
`<APP_NAME>_DATABASE_URL` सिर्फ तब सेट करें जब किसी एक ऐप को अलग database चाहिए।

</Callout>

## ईमेल डिलीवरी वैकल्पिक है, लेकिन इसकी सलाह दी जाती है {#email-provider}

ईमेल और पासवर्ड वाले authentication के लिए ईमेल provider आवश्यक नहीं है। इसके
बिना deployed ऐप ईमेल और पासवर्ड से signup और login इस्तेमाल करता है, signup email
verification छोड़ देता है और magic-link authentication उपलब्ध नहीं कराता।

Agent-Native में email delivery account शामिल नहीं है। अगर आपको magic links,
email verification, password resets, invitations या share notifications चाहिए, तो
deploy से पहले Resend या SendGrid connect करें। Deployment environment में
`RESEND_API_KEY` या `SENDGRID_API_KEY` सेट करें। SendGrid के लिए `EMAIL_FROM` भी
चाहिए। उपलब्ध authentication modes के लिए [प्रमाणीकरण](/docs/authentication)
देखें।

### Framework emails customize करें {#email-templates}

Framework जो भी email भेजता है, उसका एक default template होता है। अपना design
इस्तेमाल करने के लिए server plugin से एक override register करें। Recipient और
sender अब भी framework तय करता है और वही message deliver करता है। Message में क्या
लिखा है और वह कैसा दिखता है, यह आपका override तय करता है।

```ts
// server/plugins/email-templates.ts
import {
  escapeEmailHtml,
  overrideTransactionalEmail,
} from "@agent-native/core/server";

export default function registerEmailTemplates(): void {
  overrideTransactionalEmail("core.resource-shared", (props) => ({
    subject: `${props.sender.name} shared "${props.resource.title}"`,
    html: `<p>${escapeEmailHtml(props.sender.name)} invited you to
      <a href="${escapeEmailHtml(props.resource.url)}">${escapeEmailHtml(props.resource.title)}</a>
      in ${escapeEmailHtml(props.app.name)}.</p>`,
  }));
}
```

| Email id                         | Props                                                                              |
| -------------------------------- | ---------------------------------------------------------------------------------- |
| `core.verify-signup`             | `email`, `verifyUrl`                                                               |
| `core.reset-password`            | `email`, `resetUrl`                                                                |
| `core.magic-link`                | `email`, `magicLinkUrl`                                                            |
| `core.change-email-confirmation` | `email`, `newEmail`, `confirmationUrl`                                             |
| `core.change-email-verification` | `email`, `verifyUrl`                                                               |
| `core.organization-invite`       | `invitee`, `orgName`, `inviter`, `acceptUrl`                                       |
| `core.builder-credit-limit`      | `subject`, `heading`, `body`, `upgradeLabel`, `upgradeUrl`                         |
| `core.resource-shared`           | `recipientEmail`, `sender`, `resource` (`type`, `title`, `url`), `role`, `message` |

हर override को `app` (`name`, `logoUrl`) भी मिलता है। दूसरे argument में default
rendering होती है, ताकि आप उसका subject या text दोबारा इस्तेमाल कर सकें।

- Props raw values हैं। HTML string में डालने से पहले उन्हें `escapeEmailHtml` से
  escape करें।
- Component render करने के लिए `html` की जगह React element के साथ `react` लौटाएं।
  React props को खुद escape करता है।
- Default subject रखने के लिए `subject` छोड़ दें। अपने HTML से plain-text body
  बनाने के लिए `text` छोड़ दें।
- अगर override error throw करता है, तो send fail हो जाता है। Framework default
  design पर वापस नहीं जाता। Transactional email preview आपका override render करता
  है, इसलिए उसे वहीं जांचें।
