# Content: लोकल फ़ोल्डर स्रोत

Content में अब एक ही डेटा मॉडल है: हर पेज SQL में रहता है, किसी **स्पेस** से
जुड़ा होता है और उस स्पेस के सिस्टम **Files** डेटाबेस का आइटम होता है। लोकल
फ़ोल्डर Files से जुड़ा एक स्रोत है, साथ ही collaboration, sharing, comments,
history, search, डेटाबेस गुण, और वही action सतह भी मिलती है जो बाकी हर पेज पर
उपलब्ध है।

हर उपयोगकर्ता का निजी स्पेस, हर उपलब्ध संगठन का संगठन स्पेस और दिखाई देने वाले
स्पेस चुनने के लिए निजी **Workspaces** कैटलॉग होता है। Files एक सामान्य Content
डेटाबेस है; उसके गुण, फ़िल्टर, क्रम, समूह और सहेजे गए व्यू साइडबार भी बना सकते हैं।

## फ़ोल्डर जोड़ें

<Steps>

### लोकल-फ़ोल्डर स्क्रीन खोलें

ब्राउज़र के File System Access API या Agent-Native Desktop के ज़रिए फ़ोल्डर
चुनें। SQL में केवल अपारदर्शी कनेक्शन ID, सापेक्ष पथ, hash और स्रोत मेटाडेटा
रहता है—absolute path, browser handle या फ़ाइल का मूल body कभी नहीं।

### फ़ोल्डर कहाँ जुड़ेगा, यह चुनें

इसे किसी मौजूदा निजी या संगठन स्पेस के Files डेटाबेस से जोड़ें, या अपने खुद के
Files डेटाबेस वाला एक निजी फ़ोल्डर-आधारित स्पेस बनाएँ।

### एक truth policy चुनें

| नीति                     | व्यवहार                                                            |
| ------------------------ | ------------------------------------------------------------------ |
| `database_primary`       | Content प्रामाणिक है; फ़ोल्डर के बदलाव उपयोग से पहले समीक्षा किए जाते हैं |
| `source_primary`         | जब कोई समवर्ती Content एडिट न हो, तब फ़ोल्डर प्रामाणिक होता है         |
| `reviewed_bidirectional` | किसी भी दिशा के बदलाव में टकराव होने पर समीक्षा ज़रूरी है              |

</Steps>

Sync फ़ाइलों को सामान्य SQL पेज बनाता है। दोनों तरफ एक साथ बदलाव होने पर किसी
को overwrite करने के बजाय समीक्षा योग्य बदलाव बनता है। Disconnect करने पर पेज
और लोकल फ़ाइलें बनी रहती हैं।

## Repository से शुरू करें

```bash
npx @agent-native/core@latest content .
```

यह सामान्य database-backed Content शुरू करता है, फ़ोल्डर को स्रोत के रूप में
दर्ज करता है और कनेक्शन स्क्रीन खोलता है।

## Configuration

```json
{
  "version": 1,
  "apps": {
    "content": {
      "roots": [
        {
          "name": "Docs",
          "path": "docs",
          "kind": "docs",
          "extensions": [".md", ".mdx"],
          "source": {
            "type": "local-folder",
            "connectionId": "local-folder:<opaque-id>",
            "truthPolicy": "source_primary"
          }
        }
      ],
      "components": "components",
      "extensions": "extensions"
    }
  }
}
```

Frontmatter ID rename या move पर पेज की पहचान बचाता है। लोकल components और
extensions trusted local bridge से ही लोड होते हैं।

## Local File Mode से माइग्रेट करें

<Callout tone="info">

यदि आप पहली बार लोकल फ़ोल्डर सेट कर रहे हैं, तो इस भाग को छोड़ सकते हैं। यह
केवल उस manifest पर लागू होता है जो मौजूदा source मॉडल से पहले का है।

</Callout>

माइग्रेट करने के लिए `mode: "local-files"` और `AGENT_NATIVE_MODE=local-files`
हटाएँ, roots रखें और `source` जोड़ें।

पहले कनेक्शन और sync के बाद, पुष्टि करें कि:

- फ़ोल्डर तय किए गए Files डेटाबेस पर एक स्रोत के रूप में दिखाई देता है।
- हर आयातित पेज तय किए गए स्पेस से संबंधित है।
- कस्टम गुण और सहेजे गए साइडबार व्यू सामान्य रूप से काम करते हैं।
- समवर्ती एडिट समीक्षा योग्य चेंज सेट के रूप में दिखाई देते हैं।
- Disconnect करने पर डेटाबेस पेज और डिस्क पर मौजूद फ़ाइलें दोनों सुरक्षित रहते
  हैं।
