# 開發者指南

本頁面適用於任何要自訂或擴充行事曆範本的人：快速入門、每個 action、資料模型、路由介面，以及如何新增內容。這個應用程式的功能說明請參閱 [行事曆](/docs/template-calendar)。

## 快速入門

這一節將完整說明如何從尚未安裝任何東西，一路走到連線 Google Calendar。無論
您使用的是 macOS 上的終端機，還是 Windows 上的 PowerShell/命令提示字元，
指令都完全相同，因為它們都是純粹的 Node.js 工具。

<Steps>

### 建立應用程式

```bash
npx @agent-native/core@latest create my-calendar --standalone --template calendar
cd my-calendar
pnpm install
```

這需要先安裝 [Node.js](https://nodejs.org) 22 或更新版本，以及
[pnpm](https://pnpm.io)。如果您還沒有安裝，或還沒有設定 LLM 連線
（Builder.io、Anthropic/OpenAI 金鑰，或本機 Ollama），請參閱
[開始使用](/docs/getting-started)。

### 啟動開發伺服器

```bash
pnpm dev
```

應用程式會在 `http://localhost:8082` 開啟。如果沒有自動開啟，請在瀏覽器中
造訪這個網址。即使尚未連線 Google，行事曆也能完全正常運作。只有在您嘗試執
行需要 Google 連線的 action，卻還沒連線時，才會遇到錯誤。

### 連線 Google Calendar

在應用程式中，開啟**設定**，在**一般**分頁找到**Google Calendar**卡片，然
後點選**連線 Google Calendar**。這會開啟一個設定精靈：

1. **建立 Google Cloud 專案**（如果您還沒有可用的專案）：在
   [Google Cloud Console](https://console.cloud.google.com/) 中，點選頁面
   頂部附近的專案下拉選單，然後選擇**新增專案**。輸入任意名稱，點選
   **建立**，然後等待通知顯示已準備完成。繼續之前，請確認它已在同一個下拉
   選單中被選取。
2. **啟用 API**：選取您的專案後，前往**APIs & Services → Library**，搜尋
   「Google Calendar API」，開啟它，然後點選**啟用**。
3. **設定同意畫面**：在**APIs & Services → OAuth consent screen**下設定
   一個同意畫面（開發階段選擇「External」即可）。
4. **建立憑證**：在**APIs & Services → Credentials**下，建立一個型別為
   「Web application」的 OAuth 用戶端 ID，並將
   `http://localhost:8082/_agent-native/google/callback` 新增為已授權的
   重新導向 URI（8082 是行事曆的預設開發連接埠）。
5. **新增憑證**：下載憑證 JSON 檔案並在精靈中上傳，或切換到「手動貼上」，
   直接輸入用戶端 ID 和用戶端密鑰。

行事曆會把這些資訊儲存到自己的密鑰儲存區，而不是 `.env` 檔案，因此這個步驟
在 Windows 和 macOS 上完全相同。連線之後，權杖會自動重新整理。

### 連線 Zoom（可選）

與 Google 不同，Zoom 沒有設定表單。請在專案根目錄建立一個 `.env` 檔案（或
加入到現有的檔案中），內容如下：

```text
ZOOM_CLIENT_ID=your-client-id
ZOOM_CLIENT_SECRET=your-client-secret
```

從一個 [Zoom OAuth 應用程式](https://marketplace.zoom.us/)取得用戶端 ID 和
密鑰（Zoom Marketplace → Develop → Build App → OAuth），並將
`/_agent-native/zoom/callback` 設為重新導向 URI，然後重新啟動 `pnpm dev`，
讓它套用新的數值。若未連線 Zoom，預訂連結仍然可以提供 Google Meet，只是
無法使用 Zoom。

</Steps>

<Callout tone="warning">

在 Windows 上，有些編輯器在儲存名為 `.env` 的檔案時，會加上隱藏的 `.txt`
副檔名，變成行事曆永遠不會讀取的 `.env.txt`。請在檔案總管中開啟「檔案名稱
副檔名」（檢視分頁），並確認儲存的檔案名稱正好是 `.env`，後面沒有任何其他
內容。

</Callout>

<Callout tone="info">

**活動存在於 Google Calendar 中，而不是 SQL。** 每一個活動 action 都會直接呼叫 Google Calendar API，本機並沒有活動資料表。只有預訂連結、預訂、可用性和連線狀態會儲存在本機。切勿使用原始 SQL 讀取或寫入活動資料。

</Callout>

## Action 清單

每一個操作都是 `templates/calendar/actions/` 目錄下的一個 TypeScript 檔案，會自動掛載到 `POST /_agent-native/actions/:name`。

### 活動與來賓

活動資料存在於 Google Calendar 中，絕不會存在 SQL 裡。

| Action                   | 功能說明                                                                                  |
| ------------------------ | ----------------------------------------------------------------------------------------- |
| `list-events`            | 列出某個日期範圍內的活動                                                                  |
| `search-events`          | 依查詢字串搜尋活動                                                                        |
| `get-event`              | 依 id 讀取一個活動                                                                        |
| `create-event`           | 建立一個活動，包括重複規則（RRULE）、工作地點，以及狀態類型（`outOfOffice`、`focusTime`） |
| `update-event`           | 更新一個活動，包括重複規則、工作地點，以及狀態類型                                        |
| `delete-event`           | 刪除一個活動                                                                              |
| `manage-event-draft`     | 在任何內容被寫入或來賓收到通知之前，先暫存一個尚未傳送的邀請供使用者審核                  |
| `rsvp-event`             | 接受、拒絕，或將邀請標記為暫定                                                            |
| `get-attendee-timezones` | 讀取個別來賓的時區覆寫設定                                                                |
| `set-attendee-timezone`  | 設定個別來賓的時區覆寫，讓對方的當地時間持續正確顯示                                      |

### 可用性與尋找時段

| Action                | 功能說明                                                                                    |
| --------------------- | ------------------------------------------------------------------------------------------- |
| `get-availability`    | 讀取每週時間表、時區、緩衝時間、通知時間，以及提前預訂範圍設定                              |
| `update-availability` | 更新每週時間表、時區、緩衝時間、通知時間，以及提前預訂範圍設定                              |
| `check-availability`  | 找出某一天的空閒時段                                                                        |
| `find-a-time`         | 針對主辦人和指名的與會者進行共用的空閒時段搜尋，結合 Google 的空閒/忙碌狀態與本機的行程衝突 |

### 預訂連結與預訂

| Action                   | 功能說明                                    |
| ------------------------ | ------------------------------------------- |
| `create-booking-link`    | 建立一個預訂連結                            |
| `update-booking-link`    | 更新一個預訂連結                            |
| `duplicate-booking-link` | 複製一個預訂連結，包括共同主持人（`hosts`） |
| `list-booking-links`     | 列出可存取的預訂連結                        |
| `list-bookings`          | 列出已確認的預約                            |

### 外部行事曆

唯讀的 ICS 訂閱來源。

| Action                      | 功能說明                   |
| --------------------------- | -------------------------- |
| `add-external-calendar`     | 訂閱唯讀的 ICS/webcal 來源 |
| `list-external-calendars`   | 列出已訂閱的來源           |
| `remove-external-calendar`  | 移除一個已訂閱的來源       |
| `update-external-calendars` | 更新已訂閱的來源           |

### 人員與疊加

| Action                  | 功能說明                                         |
| ----------------------- | ------------------------------------------------ |
| `search-people`         | 搜尋 Google 聯絡人和 Workspace 目錄              |
| `get-overlay-people`    | 讀取哪些其他人的行事曆已固定疊加到您的檢視畫面中 |
| `update-overlay-people` | 更新哪些其他人的行事曆已固定疊加到您的檢視畫面中 |

### Zoom

| Action            | 功能說明                                                                                                                                        |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `get-zoom-status` | 讀取目前使用者的 Zoom 連線狀態。連線和取消連線是透過 `/_agent-native/zoom/*` 路由進行，而不是透過 action，因為 OAuth 需要已登入的瀏覽器工作階段 |

### Google Calendar 連線與同步

| Action                    | 功能說明                                  |
| ------------------------- | ----------------------------------------- |
| `connect-google-calendar` | 傳回已登入瀏覽器工作階段的 OAuth 連線網址 |
| `sync-google-calendar`    | 強制重新同步                              |

### 設定與偏好

| Action                               | 功能說明                                                                     |
| ------------------------------------ | ---------------------------------------------------------------------------- |
| `get-settings`                       | 讀取使用者層級的設定                                                         |
| `update-settings`                    | 更新使用者層級的設定                                                         |
| `update-calendar-visual-preferences` | 更新僅限本機的顯示偏好設定（活動顏色、隱藏週末）。絕不會動到 Google Calendar |

### 導覽與 UI 狀態

| Action        | 功能說明                         |
| ------------- | -------------------------------- |
| `navigate`    | 將 UI 移動到某個檢視、日期或活動 |
| `view-screen` | 為代理讀回目前的檢視畫面         |

### 提供者 API 升級呼叫

原始的 Google Calendar（以及已連線的 CRM）API，用於上述 actions 範圍過窄的情況。

| Action                  | 功能說明                                                 |
| ----------------------- | -------------------------------------------------------- |
| `provider-api-catalog`  | 列出可直接呼叫的原始提供者 API                           |
| `provider-api-docs`     | 讀取某個原始提供者 API 端點的文件                        |
| `provider-api-request`  | 直接呼叫原始的 Google Calendar（或已連線的 CRM）API      |
| `list-staged-datasets`  | 列出已暫存供查詢用的大型掃描結果，而不是直接傳回原始結果 |
| `query-staged-dataset`  | 查詢一個暫存資料集                                       |
| `delete-staged-dataset` | 刪除一個暫存資料集                                       |

## 逐步解析一個 action

`create-booking-link` 展示了值得在任何 action 中重複使用的模式：在輸入資料碰到資料庫之前先進行驗證、跨兩個資料表強制執行一項規則、安全地解析已登入的使用者，以及只在一個地方將彈性的輸入格式標準化一次，而不是在每個讀取端都重複處理。

## 自訂它

應用程式的每個部分都是可編輯的原始碼。從這裡開始：

- `templates/calendar/actions/`，新增一個包含 `defineAction` 的檔案，即可向代理和前端同時公開新功能。
- `templates/calendar/app/routes/`，也就是上面列出的 UI。
- `templates/calendar/server/db/schema.ts`：使用 Drizzle 新增欄位或資料表。請保持程式碼與 PostgreSQL 相容，讓範本能在 PGlite 和 Postgres 上執行。
- `templates/calendar/server/lib/`，提供者整合：`google-calendar.ts`、`zoom.ts`、`people-search.ts`、`ical-fetcher.ts`、`find-time.ts`、`provider-api.ts`。
- `templates/calendar/AGENTS.md`，代理指令。當您教代理新的功能或慣例時，請更新這個檔案。
- `templates/calendar/.agents/skills/`，代理遵循的詳細模式。相關 skills：`event-management`、`availability-booking`、`real-time-sync`、`storing-data`、`delegate-to-agent`、`frontend-design`。
- `templates/calendar/shared/api.ts`，伺服器和用戶端共用的 TypeScript 型別（`CalendarEvent`、`BookingLink`、`ExternalCalendar`、`ConferencingConfig` 等）。

如果您新增一項功能，請記得更新這四個區域：UI、action、skill 或 AGENTS.md 條目，以及代理需要看到的任何 application state。這正是讓代理和 UI 保持一致的關鍵。
