# 伺服器

`server/` 目錄是 Agent-Native 應用的基礎架構層。它負責啟動時的任務、驗證，以及 actions 涵蓋不到的 HTTP 介面。大多數產品行為屬於 [Actions](/docs/actions) 的範疇；伺服器的職責是讓這些 actions 得以對外提供服務。

## 伺服器扮演的角色 {#role}

在傳統的網頁應用中，伺服器是大部分邏輯的所在地。業務規則、資料存取和呈現全都發生在路由處理常式內。Agent-Native 應用的運作方式不同：邏輯存在於 actions 中，由 agent 與 UI 以平等夥伴的關係共用。伺服器的工作是協調——執行資料庫遷移、設定驗證、掛載 agent 迴圈，並處理 actions 本身無法表達的少數 HTTP 相關事務。

瀏覽器請求、agent 迴圈與外部 API 客戶端全都透過同一個 Nitro 伺服器路由，並讀取同一個 SQL 資料庫。沒有分開的 agent 後端或 UI 後端。伺服器層正是將 actions 對外公開的部分。

## Nitro {#nitro}

[Nitro](https://nitro.build) 是驅動 Agent-Native HTTP 層的伺服器工具套件。您在 `server/` 中設定的內容大多是 Nitro：基於檔案的路由、啟動外掛，以及中間件。

- **基於檔案的路由**：檔名直接對應到 HTTP 方法與 URL 路徑，無需註冊。`server/routes/api/health.get.ts` 會自動變成 `GET /api/health`。詳情請參閱 [路由](/docs/server-routes)。
- **外掛**：僅在伺服器啟動時執行一次的程式碼，早於任何請求被服務之前。資料庫遷移、驗證設定，以及 agent-chat 的掛載都發生在 `server/plugins/` 中。詳情請參閱 [外掛](/docs/server-plugins)。
- **中間件**：在每個傳入請求抵達路由之前執行的程式碼。驗證守衛就位於 `server/middleware/` 中。詳情請參閱 [中間件](/docs/server-middleware)。

Nitro 同時也與部署平台無關。同一個應用可以無須修改程式碼就部署到 Node.js、Cloudflare Workers、Netlify、Vercel 及其他執行環境，只需設定對應的 preset。請參閱 [部署](/docs/deployment)。

底層的請求/回應 API 是 [H3](https://h3.unjs.io)。當您在自訂路由中看到 `defineEventHandler`、`createError` 或 `getQuery` 時，那就是 H3。[Nitro 文件](https://nitro.build/guide) 和 [H3 文件](https://h3.unjs.io) 是框架未直接涵蓋內容的參考來源。

## 優先預設使用 Actions {#actions-first}

Agent Native 的架構思路不同。每當您想到應用的新功能時，先考慮它能否成為一個 action。舉例來說，如果 UI 與 agent 都需要執行某件事，就定義一個 action，而不是自訂 API 路由。Actions 會自動變成：

- Agent 工具。
- 具型別的前端 hooks。
- `/_agent-native/actions/:name` 底下的 HTTP 端點。
- 可透過 MCP 與 A2A 呼叫的工具。
- 用於開發的 CLI 指令。

只有在您需要路由形式的協定或二進位／串流行為時，才使用自訂的 `/api/*` 路由。詳情請參閱 [Actions](/docs/actions)。

## 下一步是什麼 {#whats-next}

- [**Actions**](/docs/actions)：預設的操作介面。只有在不合用時才改用自訂路由。
- [**資料庫**](/docs/server-database)：自訂路由與 actions 都會匯入的 `getDb()`／架構模式
- [**中間件**](/docs/server-middleware)：驗證守衛與 `server/middleware/` 目錄
- [**外掛**](/docs/server-plugins)：用於遷移、驗證與 agent 的啟動外掛
- [**路由**](/docs/server-routes)：基於檔案的路由、請求脈絡，以及 SSR 全捕獲路由
