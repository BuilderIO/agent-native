# 隱私與資料權利

Agent-Native 在預設的帳戶設定中提供隱私要求介面。已登入的使用者可以要求取得個人資料副本，或要求刪除個人資料。

這是實作基線，不是法律建議或合規認證。營運應用程式的組織必須判定自身的法律角色，並發布適合其部署的通知與流程。

## 使用者可以做什麼

開啟 **設定 > 帳戶 > 安全性**，在 **您的資料** 群組中即可：

- 要求個人資料副本，以進行存取或可攜性審查；
- 要求刪除個人資料，以進行刪除審查；
- 透過現有的個人資料與電子郵件控制項更正帳戶資訊。

要求會持久保存、以冪等方式處理並接受稽核。要求 action 只儲存要求類型、狀態與時間戳記。它不會回傳資料傾印、不接受他人的電子郵件或使用者 ID，也不會立即刪除資料。

## 代理無法做什麼

隱私要求透過帳戶設定 UI 提交。`request-privacy-right` 已經過驗證，不會出現在代理工具與 MCP/A2A 探索中，會被工具橋接阻擋，且只允許前端呼叫者使用。

核心 `offboard-member` action 也有相同的 UI-only 邊界。移除成員是組織操作，會轉移其擁有的資料列並撤銷存取權，並不是帳戶抹除。刪除組織仍然需要擁有者在 UI 中確認。

人工核准提示不是安全邊界。對於會刪除資料、撤銷身分、修改成員資格或驗證的自訂 action，請使用明確的 UI-only 邊界，並從經過驗證的要求內容取得身分。

## 營運者履行要求

Framework 會記錄要求。部署營運者必須：

1. 驗證要求者身分，並決定適用的組織與法律範圍；
2. 收集部署所控制的資料，透過私密且受存取控制的管道提供；
3. 刪除或匿名化應用程式資料列與私有檔案，適當時撤銷工作階段和憑證，並與連線的供應商與處理者協調；
4. 對備份、安全與稽核記錄、詐欺防護和已記錄的例外套用保留政策；
5. 記錄完成、部分履行或受阻原因，並通知要求者結果。

不要因為刪除一個組織資料列或一項設定，就宣稱要求已完成。託管供應商、上傳檔案、連線服務、快取、備份和不可變的稽核記錄可能有各自的保留與刪除路徑。

## 預設隱私狀態

新的可分享資源預設為私有。瀏覽器分析預設關閉 DOM 與網路自動擷取；若有設定工作階段回放，則預設為選擇加入且只限已登入使用者。這些預設不能取代隱私通知、合法依據分析、保留政策或同意與退出控制。

若部署會販售或分享個人資訊，必須提供適用的 CCPA 退出機制並處理 Global Privacy Control。Framework 不會替應用程式建立販售或分享計畫。

## 部署清單

- 發布隱私通知，說明資料類別、用途、接收者、保留期限、權利和聯絡管道。
- 決定並記錄合法依據、同意要求、敏感資料限制與年齡要求。
- 為存取、更正、刪除、可攜性、反對和退出要求指定負責人與流程。
- 盤點應用程式資料表、私有檔案、分析供應商、連線服務、電子郵件、快取、記錄、備份和子處理者。
- 定義驗證、回應期限、保留例外、刪除證據和申訴處理。
- 讓高影響 action 僅能由 UI 發起，並測試代理、MCP、A2A、CLI、HTTP 和工具 iframe 呼叫者無法執行。
