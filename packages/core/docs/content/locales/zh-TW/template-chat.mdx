# 聊天

聊天是最基本的 Agent-Native 起點：一個 ChatGPT 風格的外殼，聊天位於中心，並附有對話串清單、驗證，以及一個範例 action，沒有任何特定領域的內容。它適合想要一個真正可部署的應用程式來建置自己代理與畫面的開發者，而不是為特定工作打造的成品。

如果您想要成品領域產品形態，請從 [行事曆](/docs/template-calendar)、[郵件](/docs/template-mail)、[Content](/docs/template-content)、[Forms](/docs/template-forms)、[Analytics](/docs/template-analytics) 或其他領域範本開始。如果您真的還不需要瀏覽器 UI，請參閱 [自動化優先應用程式](/docs/pure-agent-apps)。

## 隨附內容 {#what-ships}

<Comparison>

### :green: 已包含

- 使用框架聊天介面和持久聊天對話串，在 `/` 上進行整頁面聊天
- 應用程式側邊欄中的對話串清單，可用來建立、重新開啟、重新命名、固定和封存聊天
- 內建的 app-agent 迴圈，已預先設定給聊天外掛程式使用
- 透過 Better Auth 進行驗證：登入、註冊、工作階段、組織
- 一個 actions 目錄，內含一個範例（`actions/hello.ts`）以及標準的 `view-screen` 和 `navigate` actions
- 框架的核心資料表，用於聊天對話串、application state、設定、工作階段、resources 和執行歷史紀錄，並附上一個資料庫管理頁面和一個可觀測性儀表板，無論您是否開啟過它們，都會一併掛載
- 即時同步（`useDbSync`）已預先連接好，因此當代理寫入 SQL 時 UI 會自動重新整理
- 預設掛載的 Extensions 路由，供您的使用者之後在聊天中建置沙盒化的小型應用程式
- AGENTS.md 附有聊天優先指南，說明如何新增 actions、路由、skills 和 application state

### :red: 未包含

- 領域資料表或種子資料
- 儀表板、清單、圖表、表單或提供者整合
- 除了範例存根之外的特定領域 actions

</Comparison>

## 何時選擇它 {#when-to-pick}

- **您想要一個使用者可以立即對話的基本應用程式**，然後再用 actions 和 UI 進行擴充。
- **您想要預設的 Agent-Native 入門路徑**：先聊天，然後是 actions、原生結果和應用程式頁面。
- **您想要將自己的代理後端接入熟悉的聊天 UI**，同時保留 Agent-Native 的 actions、狀態、驗證和部署形態。
- **您正在為自訂內部工具製作原型**，該工具與任何領域範本都不吻合。

## 開始使用 {#get-started}

```bash
npx @agent-native/core@latest create my-chat-app --standalone --template chat
```

如需安裝、首次執行和連線 LLM 的說明，請參閱 [聊天：開發者指南](/docs/template-chat-developers#quick-start)。若是完全沒有瀏覽器 UI 的自動化優先工作，請改用 `--headless` 建立鷹架：

```bash
npx @agent-native/core@latest create my-agent --headless
```

用於排程工作、佇列、CLI 迴圈，或聊天和應用程式頁面尚無用處的外部代理工作流程。關鍵不變數保持不變：actions 是聊天、UI、HTTP、MCP、A2A 和 CLI 共用的介面。深入了解這條路徑，請參閱 [自動化優先應用程式](/docs/pure-agent-apps)。
