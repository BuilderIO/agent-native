# 視覺化 Plan

Agent-Native Plan 是編碼代理的視覺化計畫模式。它會把一份普通的 Codex、Claude Code、Markdown 或貼上的實作計畫，轉變成一個結構化的審閱介面，具備富文字、圖表、線框圖、帶註解的程式碼演練與檔案樹、評論以及可共用連結。

歸結起來就是兩個指令。`/visual-plan` 會在代理**動手寫程式碼之前**建立一份計畫。`/visual-recap` 則會把**已經發生**的變更 — PR、提交、分支或 git diff — 轉變成一份高空視角的視覺化程式碼審查。兩者開啟的是同一個審閱介面，因此無論用哪一個，你都能用同樣的方式標註、評論，並把意見回饋交回給代理。

## 它取代的內容

<Comparison>

### 之前

- 一份計畫以聊天或 Markdown 檔案中的一整面文字牆存在，審閱它就代表得從頭讀到尾，才能找到你不同意的那一段。
- 意見回饋發生在 Slack 討論串或零散的留言中，與計畫本身脫節。
- 審閱一個已完成的 PR，就代表得逐行閱讀原始 diff，才能重建出改了什麼、為什麼要改。

### 之後

- 計畫會渲染成圖表、線框圖、帶註解的程式碼，以及一份可以直接回應的「待解問題」表單。
- 留言會釘選在確切的文字、圖片或線框圖位置上，並可以指定給代理或人類審閱者。
- `/visual-recap` 會把 PR、提交或 diff 轉變成同一種視覺化審閱，而不是原始 diff。

</Comparison>

把結果匯出成 HTML、Markdown 或 JSON，取得一份適合放進版本控制的副本，或是用本機檔案模式讓內容完全不進入託管資料庫。詳見[審閱與評論計畫](/docs/template-plan-review-workflow)與[本機檔案模式與桌面同步](/docs/template-plan-local-and-desktop)個別的深入說明。

## 開始使用 {#get-started}

<Steps>

### 安裝技能 {#install}

大多數人是把 Plan 當作**技能**安裝到自己既有的編碼代理上，而不是安裝成一個鷹架式應用程式。這一個指令會安裝技能指示、註冊託管的 Plans MCP 連線器，並完成登入：

```bash
npx @agent-native/core@latest skills add visual-plan
```

這會安裝三個斜線指令 — `/visual-plan`、`/visual-recap` 和 `/visualize-repo` — 以及 `plan` MCP 連線器（代理與之溝通的遠端工具伺服器），位址為 `https://plan.agent-native.com/mcp`。完整的旗標參考、Claude Code 與 Codex 的外掛/市場安裝路徑，以及 VS Code 擴充功能，請見[Plan 外掛與市場 → 安裝路徑](/docs/plan-plugin#install)。

自訂 Plan 範本本身 — 自行託管它，或是直接在它之上開發 — 是另一條次要的路徑，說明於[擴充 Plan](/docs/template-plan-developers)。大多數人永遠用不到這條路徑。

### 請代理使用符合這項工作的指令

- 「在修改身分驗證流程之前先用 `/visual-plan`。」
- 「為新的新手引導畫面建立一份 `/visual-plan`，包含行動裝置與桌面版兩種狀態。」
- 「對這個 PR 執行 `/visual-recap`，讓我先審閱這次變更的整體樣貌。」
- 「對 `main` 與這個分支之間的 diff 使用 `/visual-recap`。」
- 「執行 `/visualize-repo`，從我們的公開 API actions 與 schema 開始。」

`/visual-plan` 會依工作需要，納入圖表、線框圖、視覺稿、可點擊的原型與帶註解的程式碼。代理會先檢視程式碼庫，接著傳回的連結會在你的瀏覽器或 VS Code 中開啟審閱介面。

### 以訪客身分審閱，不需要帳號

你分享計畫的對象不需要安裝任何東西。他們開啟 Plans 編輯器後，**不需要註冊就能建立與編輯** — 以訪客身分作業即可。只有要**儲存或分享**自己的作品時才需要登入；如果訪客之後才登入，他們以訪客身分建立的每份計畫都會被**認領**進他們的帳號中。

</Steps>

當已經有 Codex、Claude Code、Markdown 或貼上的計畫存在時，使用 `/visual-plan`；代理會保留這份原始計畫，並在它的基礎上建構出更豐富的審閱介面，而不是從頭開始。如果第一版仍有尚未決定的事項，代理可以在計畫底部加上一份**待解問題**表單 — 回答並送出後，就會開始一輪修訂。

<Callout tone="info">

**訪客與已登入，一覽**

- **以訪客身分**，你可以開啟共用連結、建立新計畫、編輯文字內容，並使用審閱標註模式 — 不需要帳號。
- **登入後**還能永久儲存自己的計畫、把計畫發布成可共用連結、授予他人檢視者/編輯者/管理員權限、張貼會以電子郵件通知他人的留言，以及刪除或還原自己擁有的計畫。

</Callout>

## 成本與模型選擇

產生一份計畫或回顧，會針對你的編碼代理的 LLM 執行一整個代理式工作階段，而不是輕量的範本填空 — 成本會隨著 diff 或計畫的大小，以及你選擇的模型而變化。

- 這個應用程式的預設聊天模型是 GPT-5.6 Luna。直接串接 Anthropic 的連線，預設仍是 Claude Sonnet 5。你可以隨時在**設定**中變更模型；Haiku 是比較便宜的 Claude 選項。
- 來自 GitHub Action 的自動化 PR 回顧，與互動式應用程式分開執行，並有自己的模型與成本控制項 — 關於 `VISUAL_RECAP_MODEL`、`VISUAL_RECAP_AGENT` 與 `VISUAL_RECAP_REASONING`，請見[PR 視覺回顧](/docs/pr-visual-recap)。

## 請求存取私人計畫 {#request-access}

如果有人開啟一個他們沒有檢視權限的計畫連結，Plans 不會只顯示死路一條。頁面會告訴他們這份計畫是私人的，並提供一個**請求存取**的操作，這個操作會：

- 需要先登入（訪客會先被提示登入）。
- 把這次請求記錄在計畫上，並在部署有設定電子郵件時，把請求者的姓名連同一個可開啟該計畫的連結，寄送訊息給計畫擁有者，方便在核准後把它分享回去。
- 可以放心多次點擊 — Plans 會先檢查你是否已經擁有存取權，因此同一個人的第二次請求不會用重複的電子郵件轟炸擁有者。

如果計畫的可見性設定為**組織**而非完全私人，而且你的帳號已經有該組織的待處理邀請，或電子郵件網域與該組織相符，Plans 會提供直接加入該組織的選項，而不是送出請求。

<Callout tone="warning">

如果 Plans 的工具傳回 `needs auth`、`Unauthorized` 或 `Session terminated`，不要一直重試。請用 `npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex` 重新驗證，或者對支援 OAuth 的主機重新執行 `/mcp` → **Authenticate**。之後請開啟一個新的 Codex 討論串，或重新啟動/重新載入用戶端 — 工具註冊表只會在全新的工作階段中套用這項變更。

</Callout>
