# 你的第一個功能

本頁面向擴充 [Chat 範本](/docs/template-chat) 的開發者。它介紹渲染起始畫面的檔案，接著逐步說明當您要求一項真正的功能時，代理通常會改動的所有內容。

## 要檢查的第一份程式碼 {#first-code}

- `actions/hello.ts` 是代理可以呼叫的起始行為。替換它，或在旁邊新增 action。
- `app/components/chat/ChatRouteContent.tsx` 在 `/chat/<threadId>` 渲染整頁聊天介面。在這裡調整空狀態、輸入框或訊息插槽。
- `app/components/home/HomePage.tsx` 是開發環境中顯示於 `/home` 的可編輯「開始使用」頁面。正式環境中的 `/home` 會開始新的聊天。
- `AGENTS.md` 告訴內建代理如何在這個應用程式中工作。

## 首次編輯 {#first-edits}

大多數第一項功能都遵循相同的形狀：一個資料表、一或兩個 actions、一個路由、一個導覽項目，以及一次 `AGENTS.md` 更新。請這樣詢問代理：

> 新增一個 `notes` 的資料模型。一則筆記有 id、標題、內文和擁有者。在 `/notes` 渲染一個筆記頁面，新增建立/列出 actions，並讓聊天仍然能夠建立筆記。

聊天出廠時完全沒有 `server/db/schema.ts`（請參閱 [隨附內容](/docs/template-chat#what-ships)），因此第一項變更就是新增一個檔案，遵循其他每個範本都使用的相同 `table`/`text`/`ownableColumns` 形狀：

這項功能剩下的部分，就從這裡接續下去：

- `actions/create-note.ts` — 一個帶有 Zod schema（`title`、`body`）的 `defineAction`，形狀與 `actions/hello.ts` 相同。
- `actions/list-notes.ts` — 一個唯讀 action（`readOnly: true`，就像 `actions/view-screen.ts`），透過 `accessFilter` 查詢新的資料表。
- `app/routes/notes.tsx` — 一個新路由；這個應用程式使用檔案系統路由（`app/routes.ts` 中的 `flatRoutes()`），因此只要新增這個檔案，就足以掛載 `/notes`。
- 在 `app/components/layout/Sidebar.tsx` 中 `ChatThreadsSection` 之前新增一個指向 `/notes` 的連結。
- 在 `AGENTS.md` 中新增一段內容，告訴代理 notes 的存在，以及哪些 actions 負責管理它們。

一個新的 action 一旦存在，聊天就可以呼叫它 — 每個 `defineAction` 預設都是一個工具，除非它設定了 `agentTool: false`。不過，它不一定會出現在模型的第一次請求中：`server/plugins/agent-chat.ts` 設定了 `INITIAL_TOOL_NAMES = ["view-screen", "navigate", "hello", "provider-api-request"]`，這只控制第一輪對話會傳送哪些工具 schema。其他所有 action，包括全新的 `create-note`，仍然可以透過 `tool-search` 取得，並依需求載入 — 只有當您希望某個 action 從第一則訊息開始就出現在模型的預設工具集中時，才把它的名稱加進那個清單。

## 使用您自己的代理後端 {#own-agent-backend}

這個範本預設使用內建的 app-agent 迴圈。若要連接自訂後端，請交換代理聊天外掛程式背後的聊天執行時，而不是重寫 UI。聊天路由應該保持是共用聊天介面周圍的一個輕薄渲染器；後端的選擇屬於伺服器外掛程式/執行時轉接器。

當您的模型編排已經存在於別處，但您仍想要一個具有驗證、對話串、actions、UI 狀態和可部署頁面的應用程式時，請使用這個選項。
