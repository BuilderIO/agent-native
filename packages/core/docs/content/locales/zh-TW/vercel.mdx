# Vercel

Vercel 會替你代管應用程式，因此不需要架設或維護伺服器。建置會把應用程式轉換成
Vercel 直接提供的檔案，以及 Vercel 依需求執行的函式，Vercel 也會為應用程式提供
一個支援 HTTPS 的公開網址。

本指南會從頭開始示範如何部署一個獨立應用程式。你將建立應用程式，為它設定正式環境
資料庫和驗證密鑰，將它連結到一個 Vercel 專案，準備好資料庫，然後建置並部署它。

<Callout tone="info">

需要 Node.js `22.22+`。

</Callout>

你還需要一個 Vercel 帳號。請在你自己的電腦上執行本指南中的指令。Vercel CLI 會替你
把完成的建置上傳到 Vercel。

## 步驟 1：建立應用程式 {#step-1-create-the-app}

建立新的獨立應用程式。下面的範例以 Chat 範本建立應用程式，但你可以從任何範本開始。
進入應用程式的資料夾並安裝相依套件。`corepack enable` 會啟用應用程式所需的 `pnpm`
版本，因此你不需要自行安裝 `pnpm`。

```bash
npx --yes @agent-native/core@latest create my-app --standalone --template chat

cd my-app

corepack enable

pnpm install
```

如果你想要，可以把 `my-app` 換成你自己的應用程式名稱。本指南的其餘部分假設你位於
應用程式的資料夾中。

## 步驟 2：設定環境密鑰 {#step-2-configure-environment-secrets}

應用程式會從環境變數讀取其正式環境設定：

| 變數                 | 必要 | 用途                                       |
| -------------------- | ---- | ------------------------------------------ |
| `DATABASE_URL`       | 是   | 將應用程式連線到它的 PostgreSQL 資料庫     |
| `BETTER_AUTH_SECRET` | 是   | 為使用者工作階段簽章                       |
| `BETTER_AUTH_URL`    | 否   | 設定使用者連到你的應用程式時使用的公開網址 |

下面的 export 指令讓後續指令能在目前的 shell 中正常運作。部署之前，請把這些變數
同樣儲存到主機的專案或服務環境設定中。下一個步驟會說明如何在 Vercel 中儲存它們。

### 資料庫 URL {#database-url}

在本機開發期間，如果未設定 `DATABASE_URL`，應用程式會把資料儲存在本機資料庫中。
已部署的應用程式需要一個真正的 PostgreSQL 資料庫，在每次部署之間保留資料。Vercel
不會在請求之間保留檔案，因此資料庫必須位於 Vercel 的函式之外。從你的提供者複製
連線字串並匯出它：

```bash
export DATABASE_URL='your-postgres-url-string'
```

[資料庫提供者指南](/docs/neon)說明了在各個提供者處找到連線字串的位置。

<Callout tone="warning">

請選擇持久性的 PostgreSQL 提供者，例如 Neon、Supabase、Amazon RDS 等。

</Callout>

### 驗證密鑰 {#auth-secret}

只需要產生一次，並在每次部署之間保持不變。

應用程式使用 `BETTER_AUTH_SECRET` 為使用者工作階段簽章。如果它變更了，所有已登入的
使用者都會被登出。下面的指令會產生一個隨機值：

```bash
export BETTER_AUTH_SECRET="$(openssl rand -hex 32)"
```

請把產生的值儲存在安全的地方，例如密碼管理工具。每次部署時都使用相同的值。

### 公開 URL {#public-url}

選用。在使用自訂網域、反向代理，或需要固定公開來源的驗證/OAuth 流程時設定它。

`BETTER_AUTH_URL` 是使用者連到你的應用程式時使用的公開網址。如果沒有設定，應用程式
會根據每個傳入的請求推斷自己的網址。在 Vercel 提供給你的網址上，這通常沒有問題，
但當你連接自訂網域時，請設定它，讓登入連結和 OAuth 重新導向使用該網域。

```bash
export BETTER_AUTH_URL='https://your-domain.example'
```

## 步驟 3：連結專案並儲存密鑰 {#step-3-link-the-project-and-save-the-secrets}

從命令列登入 Vercel：

```bash
npx vercel login
```

將應用程式的資料夾連結到一個 Vercel 專案。建立一個新專案即可，不需要自訂它的設定。

```bash
npx vercel link
```

CLI 會根據資料夾名稱建議一個專案名稱。接受建議的設定即可，因為你會在步驟 5 中
自行建置應用程式，Vercel 不需要它自己的建置設定。

把兩個必要變數儲存到專案的正式環境中：

```bash
printf '%s' "$DATABASE_URL" | npx vercel env add DATABASE_URL production

printf '%s' "$BETTER_AUTH_SECRET" | npx vercel env add BETTER_AUTH_SECRET production
```

每個指令都會讀取你在步驟 2 中匯出的值並儲存到 Vercel，因此你不需要手動貼上密鑰。
如果你有設定 `BETTER_AUTH_URL`，請用同樣的方式儲存它。之後你也可以在 Vercel
資訊主頁的專案設定中查看和變更這些值。

## 步驟 4：遷移 {#step-4-migrate}

遷移會在你的資料庫中建立和更新應用程式所需的資料表。請在第一次部署之前執行此指令：

```bash
pnpm migrate:production
```

這個指令會在你的電腦上執行，並使用你在步驟 2 中匯出的 `DATABASE_URL` 連線到正式
環境資料庫。升級應用程式之後、部署新版本之前，請再執行一次。

## 步驟 5：部署 {#step-5-deploy}

為 Vercel 建置應用程式：

```bash
NITRO_PRESET=vercel pnpm build
```

`NITRO_PRESET=vercel` 會依照 Vercel 預期的格式建置應用程式，並把結果寫入
`.vercel/output` 資料夾。

上傳建置並發布它：

```bash
npx vercel deploy --prebuilt --prod
```

`--prebuilt` 會上傳你剛剛完成的建置，而不是在 Vercel 上重新建置應用程式。`--prod`
會把它發布到你的正式環境網址，該網址會使用你為正式環境儲存的變數。

指令完成後，會輸出應用程式的正式環境網址。開啟它並建立第一個帳號。

## 部署更新 {#deploy-updates}

若要發布新版本，請在應用程式的資料夾中再次執行遷移、建置和部署指令：

```bash
pnpm migrate:production

NITRO_PRESET=vercel pnpm build

npx vercel deploy --prebuilt --prod
```

專案連結和已儲存的變數會保持不變，因此你不需要重複步驟 3。
