# 用 AI 代理建立應用程式

您可以請 AI 代理來建立您的 Agent-Native 應用程式。您只需貼上一則提示詞，代理就會執行設定指令，並在完成後向您展示一個正在執行的應用程式。

如果您比較想自己輸入指令，請改為依照[開始使用](/docs/getting-started)操作。

## 開始之前

- 一個能執行終端機指令的 AI 代理，例如 Claude Code、Codex 或 Cursor。只能聊天的代理，例如 ChatGPT 或網頁版 Claude，也能提供協助。請參閱[無法執行指令的代理](#chat-only-agents)。
- [Node.js](https://nodejs.org) 22.22 或更新版本。
- 一個用來存放新應用程式的空資料夾。

建立應用程式不需要 API 金鑰。只有當您希望應用程式內建的代理回答您時才需要。請參閱[連接 LLM](/docs/getting-started#connect-an-llm)。

## 貼上這則提示詞

在空資料夾中開啟您的代理，然後貼上下方的提示詞。把第一行的 `my-app` 改成您想要的名稱。只需要改這一處。

```markdown
在名為 my-app 的新資料夾中建立一個新的 Agent-Native 應用
程式，並啟動它。下面步驟中寫著 APP_NAME 的地方都使用這個
名稱。

1. 檢查 Node.js 版本是否為 22.22 或更新，以及 pnpm 是否可用。
   如果缺少 pnpm，請執行 `corepack enable`。如果 corepack 也無法使用，
   請執行 `npm install -g pnpm`。如果 Node.js 版本過舊，請停止並告訴我，
   不要自行安裝。
2. 執行：
   npx --yes @agent-native/core@latest create APP_NAME \
    --standalone --template chat
3. 在新建立的 APP_NAME 資料夾中執行 `pnpm install`。
4. 閱讀 APP_NAME/AGENTS.md，了解應用程式的結構。
5. 用 `pnpm dev` 啟動應用程式，並讓它在背景持續執行。
6. 讀取 `pnpm dev` 輸出的本機 URL。檢查它是否有回應，
   例如用 `curl -I <url>`。不要開啟瀏覽器，也不要使用無頭
   瀏覽器工具。我會自己開啟應用程式。
7. 向我展示結果。告訴我本機 URL 和您從它得到的回應。
   不要只說設定已完成。

規則：

- 不要捏造 API 金鑰，也不要要求我貼上 API 金鑰。連接 LLM 是
  選擇性的，我會自己處理。
- 不要印出任何 .env 檔案中的機密資訊。
- 如果指令失敗，請向我展示錯誤和您嘗試過的做法。不要隱瞞。
```

## 代理應該完成什麼

一次順利的執行會得到以下結果，您可以自行逐項檢查：

- 一個新的應用程式資料夾，除非您改過名稱，否則叫 `my-app`，其中包含 `actions/`、`app/` 和一個 `AGENTS.md` 檔案。
- `pnpm dev` 正常執行且沒有錯誤。
- 一個本機 URL，通常是 `http://localhost:8080`，代理已經檢查過它有回應。

然後在您自己的瀏覽器中開啟這個本機 URL。在歡迎畫面中選取 **Continue as local dev**。開始使用頁面就會出現。

如果缺少其中任何一項，請代理展示它最後執行的指令及其輸出。

<Callout tone="info">

如果這些指令因對等相依性錯誤而失敗，原因可能是 npx 快取中有過時的套件副本。請代理執行 `npx clear-npx-cache`，然後重試。

</Callout>

## 為您的代理選擇合適的方式

| 代理類型          | 範例                                                    | 運作方式                               |
| ----------------- | ------------------------------------------------------- | -------------------------------------- |
| 終端機與 IDE 代理 | Claude Code、Codex、Cursor、VS Code 中的 GitHub Copilot | 貼上提示詞。代理會替您執行每一條指令。 |
| 僅聊天的代理      | ChatGPT、網頁版 Claude                                  | 請它給出指令，然後由您自己執行。       |

### 無法執行指令的代理 {#chat-only-agents}

僅聊天的代理無法開啟終端機，所以不能建立應用程式。您仍然可以貼上這則提示詞，並在最前面加上這一行：

```markdown
您無法執行指令。請把每一條要在我終端機中執行的指令逐條給我，
並在繼續之前等我告訴您執行結果。
```

代理會帶您完成同樣的步驟，並在出現問題時提供協助。

## 您自己的代理和應用程式的代理

有兩個代理可以處理您的應用程式，它們的分工不同。

- **您自己的代理**就是您貼上提示詞的那個，例如 Claude Code、Codex 或 Cursor。它在應用程式之外，執行在您的終端機或編輯器裡。
- **應用程式的代理**是應用程式內建的聊天。應用程式執行時，您在瀏覽器中開啟它。

|                            | 您自己的代理（應用程式之外）                                                             | 應用程式的代理（應用程式之內）                                                   |
| -------------------------- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 在哪裡使用                 | 您的終端機或編輯器                                                                       | 瀏覽器中的應用程式聊天                                                           |
| 處理什麼                   | 您專案的檔案                                                                             | 應用程式的資料和您正在查看的畫面                                                 |
| 能做什麼                   | 建立專案、安裝套件、執行 `pnpm dev`、撰寫和修改 action、頁面和資料庫資料表，以及準備部署 | 把應用程式的 action 當作工具呼叫、讀取和更新應用程式資料、回答關於畫面內容的問題 |
| 是否需要為應用程式連接 LLM | 不需要，它使用自己的模型                                                                 | 需要。請參閱[連接 LLM](/docs/getting-started#connect-an-llm)                     |
| 最適合                     | 建置和修改應用程式                                                                       | 使用應用程式並完成日常工作                                                       |

您自己的代理負責建置應用程式，應用程式的代理負責執行應用程式。當您自己的代理新增了一個 action，應用程式的代理可以立刻呼叫它，因為兩者使用的是同一個 action。

### 協助您自己的代理順利建置

產生的應用程式已經設定好，您自己的代理不需額外說明就能在其中順利運作。

- 應用程式根目錄中的 `AGENTS.md` 會告訴代理應用程式的結構以及需要遵守的規則。
- `.agents/skills/` 中是針對常見工作的簡短指南，例如新增功能或撰寫 action。
- 與您所用框架版本完全對應的文件會隨應用程式一起提供。代理可以用 `pnpm action docs-search --query "<topic>"` 搜尋這些文件。

當您提出新的需求時，可以請代理先閱讀這些內容。例如：「在修改任何內容之前，先閱讀 AGENTS.md 和對應的技能。」

如果想讓您自己的代理使用正在執行的應用程式的工具，而不是它的程式碼，請參閱[外部代理](/docs/external-agents)。

## 提出您的第一個修改

應用程式執行後，請代理做一個小修改，並看著它運作。以下是幾個範例：

```markdown
新增一個名為 list-notes 的 action，讓它回傳一個空清單，然後在新的
/notes 頁面上顯示它。
```

```markdown
修改 hello action，讓它用 "Welcome" 而不是 "Hello" 來問候，然後為
Alex 呼叫它來確認。
```

```markdown
閱讀關於部署應用程式的文件，然後告訴我需要完成哪些步驟才能把這個
應用程式上線。
```

代理修改的是與 UI 和應用程式內建代理相同的 action。正是這種共用的 action 模型，讓一次修改能在所有地方生效。[核心概念](/docs/key-concepts)介紹了它們是如何組合在一起的。
