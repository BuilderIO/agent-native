# 元件 API

Agent-Native 附帶了完整的側邊欄，但側邊欄不是合同。
合約是執行時：聊天流、對話串狀態、actions、脈絡，
附件、模型選取、執行和 SQL 支援的同步。使用庫存
當你需要定制產品 UI 時，可以選取元件，並下拉一層。

從聚焦的用戶端子路徑匯入瀏覽器 UI：

```tsx
import { AgentSidebar } from "@agent-native/core/client/agent-chat";
import { PromptComposer } from "@agent-native/core/client/composer";
import { AgentConversation } from "@agent-native/core/client/conversation";
import { usePresence } from "@agent-native/core/client/collab";
import { SharedRichEditor } from "@agent-native/core/client/editor";
import { ResourcesPanel } from "@agent-native/core/client/resources";
```

避免從裸 `@agent-native/core` 包匯入 UI 元件。使用
`@agent-native/core/client` 或聚焦的 `@agent-native/core/client/*` 子路徑
因此捆綁商選取瀏覽器安全的條目。

將 `@agent-native/toolkit` 用於不屬於基礎執行階段合約的可重用應用程式建構部件：shadcn 風格 UI primitives、共享 hooks、簡單應用程式 shell helpers，以及其他範本組合模組。遷移期間 Core 會保留相容 re-export。

可重用套件可以直接匯入 Toolkit 模組：

```tsx
import { Button } from "@agent-native/toolkit/ui/button";
import { Toaster } from "@agent-native/toolkit/ui/sonner";
import { useToast } from "@agent-native/toolkit/hooks/use-toast";
import { useSetHeaderActions } from "@agent-native/toolkit/app-shell";
```

在範本應用程式中，請優先使用 app-local adapter，讓團隊只替換一次 primitive，就能讓所有重用的 Toolkit surface 採用本地實作：

```tsx
import { Button } from "@/components/ui/button";
import { useToast } from "@/hooks/use-toast";
```

## 代理並聊天 UI {#agent-chat-ui}

| API                                  | 匯入路徑                                      | 何時使用                                                    |
| ------------------------------------ | --------------------------------------------- | ----------------------------------------------------------- |
| `<AgentSidebar>`                     | `@agent-native/core/client` 或 `/client/chat` | 您希望應用程式週圍有完整的側邊欄。                          |
| `<AgentToggleButton>`                | `@agent-native/core/client` 或 `/client/chat` | 您為側邊欄渲染自己的標題按鈕。                              |
| `<AgentPanel>`                       | `@agent-native/core/client` 或 `/client/chat` | 您希望在自己的布局、路由、對話框或側欄中顯示完整面板。      |
| `<AgentChatSurface>`                 | `@agent-native/core/client` 或 `/client/chat` | 您希望在面板或頁面模式下聊天，而不需要側邊欄包裝。          |
| `<AssistantChat>`                    | `@agent-native/core/client`或`/client/chat`   | 您希望擁有週圍的鑲邊，同時保持標準對話和撰寫器執行時。      |
| `<MultiTabAssistantChat>`            | `@agent-native/core/client` 或 `/client/chat` | 您希望框架的對話串分頁沒有 `AgentPanel` chrome。            |
| `createHttpAgentChatRuntime()`       | `@agent-native/core/client` 或 `/client/chat` | 您有一個 BYO 代理端點，用於流式傳輸規範化的聊天事件。       |
| `createOpenAIAgentsChatRuntime()`    | `@agent-native/core/client` 或 `/client/chat` | 您有一個 OpenAI 代理 SDK 流，並希望圍繞它進行標準聊天 UI。  |
| `createOpenAIResponsesChatRuntime()` | `@agent-native/core/client` 或 `/client/chat` | 您有一個 OpenAI 回應事件流，並希望將其規範化到聊天 UI 中。  |
| `createAgUiChatRuntime()`            | `@agent-native/core/client`或`/client/chat`   | 您有一個 AG-UI 事件流，並希望將其規範化到聊天 UI 中。       |
| `createClaudeAgentChatRuntime()`     | `@agent-native/core/client`或`/client/chat`   | 您有一個 Claude 代理 SDK 流，並希望將其規範化到聊天 UI 中。 |
| `createVercelAiChatRuntime()`        | `@agent-native/core/client` 或 `/client/chat` | 您有一個 Vercel AI SDK 流，並希望將其規範化到聊天 UI 中。   |
| `createAgentChatRuntimeAdapter()`    | `@agent-native/core/client` 或 `/client/chat` | 需要自己將一個`AgentChatRuntime`適配成assistant-ui。        |
| `createAgentChatAdapter()`           | `@agent-native/core/client` 或 `/client/chat` | 您需要內建 Agent-Native SSE 傳輸作為低階助手 UI 轉接器。    |
| `useChatThreads()`                   | `@agent-native/core/client`或`/client/chat`   | 您需要自訂話題清單、歷史紀錄選取器或範圍聊天 UI。           |
| `sendToAgentChat()`                  | `@agent-native/core/client` 或 `/client/chat` | 產品操作應該將工作交給代理聊天。                            |

`AgentChatRuntime` 是標準聊天 shell 的 BYO 代理合約。透過
當外部代理應該為 `runtime` 到 `<AssistantChat>` 供電時
Agent-Native 保留撰寫器、文字紀錄、工具卡和
本機小工具渲染。上面的連線器是 API 面；執行時
合同和事件形狀在中教授
[Native 聊天介面 — BYO agent runtimes](/docs/native-chat-ui#byo-agent-runtimes).
如果您在無頭代理、豐富聊天、嵌入式 sidecar 之間進行選取
完整的應用形狀，請參閱 [Agent Surfaces](/docs/agent-surfaces)。

最短的自訂路由仍然是預接線表面：

```tsx
import { AgentChatSurface } from "@agent-native/core/client/chat";

export default function ChatRoute() {
  return <AgentChatSurface mode="page" className="h-screen" />;
}
```

對於標準執行時的自訂鑲邊：

```tsx
import { AssistantChat, useChatThreads } from "@agent-native/core/client/chat";

function CustomChat({ projectSlug }: { projectSlug: string }) {
  const threads = useChatThreads(undefined, projectSlug);
  const threadId = threads.activeThreadId ?? undefined;

  return (
    <section className="grid h-full grid-cols-[260px_1fr]">
      <ThreadList
        threads={threads.threads}
        activeThreadId={threadId}
        onSelect={threads.switchThread}
      />
      <AssistantChat threadId={threadId} />
    </section>
  );
}
```

對於自帶代理端點，請使用其中之一建置 `AgentChatRuntime`
上面的連線器並將其傳遞給`<AssistantChat runtime={...} />`。請參閱
[Native 聊天介面 — BYO agent runtimes](/docs/native-chat-ui#byo-agent-runtimes)
連線器使用情況、標準化事件流以及何時到達
`createHttpAgentChatRuntime()` 與特定於協議的連線器。

## 聊天欄位和撰寫器 {#composer}

當您需要在自訂 UI 中使用與側邊欄相同的聊天欄位時，請使用 `@agent-native/core/client/composer`。
`@agent-native/toolkit/composer` 提供可攜式、純粹的 Tiptap 與 UI 實作；若要使用框架服務，
請以 `ComposerRuntimeAdaptersProvider` 包裝它並提供這些服務。Core 是已連接附件、提及、技能、語音和模型選擇的包裝器。

| API                               | 何時使用                                                                                                       |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `<PromptComposer>`                | 您需要一個隨時可以提交的聊天欄位，其中包含附件、斜線指令、參考、貼上文字處理、草稿持久性、語音輸入和提交語義。 |
| `<AgentComposerFrame>`            | 您需要自訂 撰寫r 主體週圍的標準視覺外殼。                                                                      |
| `<TiptapComposer>`                | 您需要最低階別的豐富聊天欄位。它必須在 Assistant-ui `ThreadPrimitive.Root` / 撰寫r 執行時內呈現。              |
| `buildPromptComposerSubmission()` | 在呼叫您自己的提交處理常式之前，您需要相同的附件和貼上文字規範化。                                             |
| `formatPromptWithAttachments()`   | 您需要將隱藏的附件中繼資料呈現到提示字串中。                                                                   |

大多數自訂 UI 應以 `PromptComposer` 開頭：

```tsx
import { PromptComposer } from "@agent-native/core/client/composer";

<PromptComposer
  placeholder="Ask the agent..."
  onSubmit={async (text, files, references, options) => {
    await sendMessageToYourRuntime({ text, files, references, options });
  }}
/>;
```

僅當您已經連線 Assistant-ui 原語時才使用 `TiptapComposer`
你自己。這是欄位，而不是整個聊天執行時。

### 暫存的輸入框上下文 {#composer-context}

`PromptComposer` 和 `TiptapComposer` 的 `submissionDisabled` 僅阻止提交，仍允許編輯草稿、新增檔案及準備上下文。未設定供應商不會阻止準備工作。`disabled` 仍會停用整個輸入框。

`PromptComposer`、`TiptapComposer` 和 `AgentKitComposer` 接受 `contextItems` 與 `contextMenuItems`。應用程式負責讀取來源及提供在地化選單標籤。

每個 `AgentChatContextItem` 包含 `key`、`title` 和 `context`。選用的 `status` 為 `ready`、`pending` 或 `error`。`statusMessage` 說明失敗原因。`onRemoveContextItem`、`onInspectContextItem` 和 `onRetryContextItem` 接收項目鍵。`removable: false` 隱藏移除操作。等待中或失敗的項目會阻止提交，除非以 `blocksSubmission: false` 明確設為僅供參考。

宿主可暫存已獲存取授權的上下文，並在提交時接收不可變快照：

```tsx
<PromptComposer
  contextItems={contextItems}
  onRemoveContextItem={removeContext}
  onSubmit={(text, files, references, options) =>
    submitPrompt({
      text,
      files,
      references,
      contextItems: options.contextItems,
    })
  }
/>
```

內容脈絡來源透過 `ComposerContextMenuItem` 的 `picker` 註冊。`ComposerContextMenu` 管理相互連接的 shadcn/Radix 級聯子選單，而非替換目前面板：根選單先提供檔案上傳，再提供新增內容脈絡 → 宿主分類 → 來源選擇器。沒有宿主項目時，不顯示新增內容脈絡。方向鍵和 Escape 用於瀏覽選單階層。連結選擇器中的返回操作只會在同一個子選單內從結果返回連結輸入。共用選擇器負責搜尋、清單列、載入、空白與錯誤狀態、重試、分頁及連結輸入。應用程式提供已授權資料和選取回呼，而不是自行繪製選擇器 JSX。

選擇器設定支援：

- `searchPlaceholder` 與選用的 `emptyMessage` 使用應用程式的本地化文案。`selectedIds` 標記已選列。項目包含 `id`、`title`，以及選用的 `disabled` 和 `url`。
- 使用本機 `items` 及選用的 `loading`、`error`、`onRetry()`，或使用遠端 `load(request)`。兩種模式不能混用。
- `load(request)` 接收 `search`、從一開始的 `page`、選用的 `cursor` 和 `url`，以及 `AbortSignal`。傳回 `{ items, hasMore?, nextCursor? }`。失敗時必須拒絕 Promise，不能傳回空結果。
- `onSelect(item, request)` 暫存來源，可非同步執行。傳回 `false` 會保持選擇器開啟。擲出錯誤會顯示錯誤和重試操作。選用的 `clearSelection` 提供本地化 `label` 和 `onSelect()` 回呼。
- 選用的 `link` 提供本地化 `placeholder` 和 `submitLabel`。`validate(url)` 可傳回錯誤文字。共用表單負責連結輸入和導覽。
- `scopeKey` 在身分或存取範圍變更時重設選擇器的全部狀態。`refreshKey` 在來源或版本權杖變更時使目前查詢失效，但不重設 URL。搜尋變更會回到第一頁。代理程式寫入造成來源資料變更時，應用程式傳入更新的權杖。

應用程式可以註冊已獲授權的選項。此處 `labels` 包含本地化文案，`stageReference` 更新宿主暫存的內容脈絡：

```tsx
import type { ComposerContextMenuItem } from "@agent-native/core/client/composer";
import { Link } from "react-router";

const contextMenuItems: ComposerContextMenuItem[] = [
  {
    id: "references",
    label: labels.references,
    picker: {
      searchPlaceholder: labels.searchReferences,
      items: authorizedReferences,
      selectedIds,
      onSelect: stageReference,
      footerAction: {
        label: labels.createReference,
        renderLink: (children) => (
          <Link to={createReferenceHref}>{children}</Link>
        ),
      },
    },
  },
];
```

對於可搜尋或透過連結存取的來源，應用程式提供經過身分驗證的載入器。`loadAuthorizedReferences` 實作上述請求與結果契約，保留存取檢查，並將中止訊號傳給用戶端輔助函式：

```tsx
const contextMenuItems: ComposerContextMenuItem[] = [
  {
    id: "references",
    label: labels.references,
    picker: {
      searchPlaceholder: labels.searchReferences,
      scopeKey: accessScope,
      refreshKey: sourceVersion,
      load: loadAuthorizedReferences,
      presentation: {
        type: "dialog",
        mode: "multiple",
        onAttach: stageReferences,
      },
      link: {
        label: labels.referenceUrl,
        placeholder: labels.referenceLink,
        submitLabel: labels.findReferences,
        validate: validateReferenceLink,
      },
    },
  },
];
```

`presentation` 預設為 `"submenu"`。設定 `{ type: "dialog", mode: "multiple", onAttach }` 後，一般選單項目會開啟共用對話框，並以項目標籤為標題。`link.label` 是網址輸入欄的標籤。「繼續」會先驗證不含憑證的 HTTP(S) 網址，再載入結果。空白或無效輸入不會呼叫供應商。`link.validate()` 可套用供應商專屬規則。對話框按鈕使用共用的在地化標籤，而非 `link.submitLabel`。

`presentation.onAttach(items, request)` 一次接收一批已凍結的新勾選項目。此模式不允許 `onSelect`。搜尋和換頁時保留選擇。`selectedIds` 對應項目顯示為已勾選且停用，不會加入批次。ID 必須區分不同的來源檔案。傳回 `false` 會保持對話框開啟。拒絕時顯示可重試的錯誤。取消或變更 `scopeKey` 會中止待處理工作，並忽略延遲回傳的結果。重新開啟時會重設網址。非同步回呼提交變更前，主應用程式必須檢查 `request.signal`。`footerAction` 和 `clearSelection` 仍僅用於子選單。

`{ type: "dialog", mode: "url" }` 直接執行附加，不載入結果清單。`onSelect(item, request)` 接收 `{ id: url, title: url, url }` 和 `request.url`：

```tsx
const websiteContextItem: ComposerContextMenuItem = {
  id: "website",
  label: labels.attachWebsite,
  picker: {
    searchPlaceholder: labels.searchReferences,
    scopeKey: accessScope,
    presentation: { type: "dialog", mode: "url" },
    link: {
      label: labels.websiteUrl,
      placeholder: labels.websiteUrl,
      submitLabel: labels.attach,
      validate: validateWebsiteUrl,
    },
    onSelect: stageWebsiteReference,
  },
};
```

`@agent-native/core/server` 的 `readComposerWebsiteSource(url, extractCallback)` 使用主應用程式現有、防護 SSRF 的擷取器建立網站參照。`@agent-native/core/shared` 的 `composerSourceRequestSchema` 僅在 `operation: "read"` 且 `url` 是不含憑證、長度不超過 2,048 個字元的 HTTP(S) 網址時接受 `source: "website"`。輔助函式傳回 `{ id, title, url, context }`，其中 ID 是穩定的網址雜湊，context 最多為 20,000 個字元。擷取狀態、警告、轉譯來源及任何 `[truncated]` 標記都保留在上下文文字中。部分擷取結果會明確標示。擷取失敗或缺少可用的 `designMd` 會擲出具型別的失敗。授權仍由主應用程式的[動作](/docs/actions-overview)負責。

選擇器項目不能同時定義 `render` 或項目層級的 `onSelect`。分類使用 `children`。根選單與每個分類都保留頂部搜尋欄。分類可提供本地化的 `searchPlaceholder`；未提供時使用共用的內容脈絡搜尋預留文字。來源清單的搜尋欄使用 `picker.searchPlaceholder`。註冊不授予來源存取權限。共用選擇器會忽略已被新請求取代的載入回應。

選用的 `footerAction` 始終保留在結果下方，包括載入中、錯誤或清單為空時。它接受本地化的 `label`、選用的 `icon` 和 `disabled`，以及 `onSelect()` 或 `renderLink(children)` 其中之一。強制回應視窗等有狀態流程使用回呼：`false` 保持選單開啟，`true` 或 `void` 關閉選單，Promise 拒絕時顯示錯誤和重試操作。單純導覽應由 `renderLink` 傳回真正的 React Router `Link` 或 HTML 連結；共用選單透過 `asChild` 提供選單列，保留其 `href` 和瀏覽器原生導覽行為。應連接既有且經過授權的流程，不要新增占位操作。

將 `addAttachment` 傳入 `ComposerContextMenu` 會把標準上傳操作放在首位，並保留宿主的檔案處理回呼。

`PromptComposer` 和 `AgentKitComposer` 接受 `attachmentAdapter`，使用 `@assistant-ui/react` 的公開型別 `AttachmentAdapter`。透過此介面卡提供宿主的可接受檔案類型、大小驗證和附件暫存策略；省略時保留預設介面卡。上傳控制項、檔案選擇器、內容脈絡選擇器和附件標籤仍由共用編輯器管理。不要為了自訂檔案暫存行為而替換這些控制項。

`PromptComposer` 和 `AgentKitComposer` 的 `inlineTextAttachments` 預設為 `true`。如果宿主已經擷取一般文字檔，請設為 `false`：編輯器將原始檔案傳給宿主，不再讀取內容並附加至提示詞。由貼上文字產生的合成附件仍會轉為提示詞文字。此選項不會改變附件接收規則或共用控制項。

```tsx
<PromptComposer
  contextItems={contextItems}
  contextMenuItems={contextMenuItems}
  attachmentAdapter={hostAttachmentAdapter}
  onRetryContextItem={retryContext}
  onSubmit={submitPrompt}
/>
```

快照會區分 `undefined` 和明確的空陣列。超過 32 個項目或 64 KiB 的序列化 UTF-8 資料會被拒絕，不會截斷。傳送或排隊前會等待 `AgentKitComposer.beforeSend(submission)`，傳入凍結的上下文、參照、已上傳附件與執行選項。拒絕時保留草稿。上下文包含於訊息文字與中繼資料中。

`composerRef.current.submitWithText(text)` 沿用目前檔案、模型設定與提交流程，不會先取代編輯器內容。接受後回傳 `true`，被阻止或拒絕時回傳 `false`。選取上下文不會授予存取權。應用程式必須透過已驗證的操作重新檢查來源存取權。

當您想要公開相同的內容時，請使用 `@agent-native/core/client/resources`

| API                                                                   | 何時使用                                             |
| --------------------------------------------------------------------- | ---------------------------------------------------- |
| `<ResourcesPanel>`                                                    | 您希望將完整的“工作區”分頁作為頁面、抽屜或自訂面板。 |
| `<ResourceTree>`                                                      | 您想要圍繞框架資料渲染您自己的資源瀏覽器。           |
| `<ResourceEditor>`                                                    | 您需要所選資源的框架編輯器。                         |
| `useResourceTree()`                                                   | 您需要一個用於個人、共用或工作區資源的作用域樹。     |
| `useResource()`                                                       | 您需要一項選定資源的內容和中繼資料。                 |
| `useCreateResource()` / `useUpdateResource()` / `useDeleteResource()` | 您需要圍繞資源生命週期進行自訂控制。                 |
| `useUploadResource()`                                                 | 您需要將檔案上傳到框架資源儲存中。                   |

完整的面板不需要道具：

```tsx
import { ResourcesPanel } from "@agent-native/core/client/resources";

<ResourcesPanel />;
```

對於自訂資源鑲邊，請將鉤子和基元放在一起：

```tsx
import { useState } from "react";
import {
  ResourceEditor,
  ResourceTree,
  useResource,
  useResourceTree,
  useUpdateResource,
} from "@agent-native/core/client/resources";

function WorkspaceResources() {
  const tree = useResourceTree("workspace");
  const updateResource = useUpdateResource();
  const [selectedId, setSelectedId] = useState<string | null>(null);
  const resource = useResource(selectedId);

  return (
    <div className="grid h-full grid-cols-[260px_1fr]">
      <ResourceTree
        tree={tree.data ?? []}
        selectedId={selectedId}
        onSelect={(item) => setSelectedId(item.id)}
        onCreateFile={() => {}}
        onCreateFolder={() => {}}
        onDelete={() => {}}
        onRename={() => {}}
        onDrop={() => {}}
      />
      {resource.data ? (
        <ResourceEditor
          resource={resource.data}
          onSave={(content) =>
            updateResource.mutate({ id: resource.data.id, content })
          }
        />
      ) : null}
    </div>
  );
}
```

## 一次性文字完成 {#one-off-text-completion}

如果您確實需要原始文字輸入/文字輸出，請將其保留在伺服器端並使用
`completeText()` 來自 `@agent-native/core/server`。將面向使用者的用法包裝在
採取行動，使 UI 和代理共用相同的功能。

<Callout id="doc-block-11d6llv" tone="warning">

`completeText()` is the escape hatch, not the default. Reach for it only for true text-in/text-out (a label, a one-line rewrite). Anything needing tools, state, auditability, or steering belongs in an action plus `sendToAgentChat({ background: true })`.

</Callout>

```ts
import { defineAction } from "@agent-native/core/action";
import { completeText } from "@agent-native/core/server";
import { z } from "zod";

export default defineAction({
  description: "Classify a short message",
  schema: z.object({ body: z.string() }),
  run: async ({ body }) => {
    const result = await completeText({
      systemPrompt: "Return exactly one label.",
      input: body,
      maxOutputTokens: 12,
      temperature: 0,
    });
    return { label: result.text.trim() };
  },
});
```

使用 `sendToAgentChat({ background: true, openSidebar: false })` 代替
工作需要工具、狀態、可審計性、使用者指導或多步驟
推理。
