# 同步內部機制

[即時同步](/docs/key-concepts#polling-sync)涵蓋了心智模型：一次代理寫入變成一個變更事件，`useDbSync()` 接收到它，受影響的查詢就會重新取得。此頁面涵蓋大多數應用程式從不直接碰觸的底層機制：`useDbSync()` 所遞增的變更版本計數器，以及如何將它們折疊進一個沒有經過 `useActionQuery()` 的原始 `useQuery()` 呼叫中。

`useActionQuery()` 在變異 action 完成時已經會自動重新取得（請參閱[資料與同步](/docs/client-data#fetching-mutating)）。只有在您要同步一個位於該路徑之外的原始 `useQuery()` 呼叫時，才使用 `useChangeVersion()`/`useChangeVersions()`，例如讀取整合狀態的低階用戶端輔助函式。

## 變更版本如何運作 {#how-it-works}

當伺服器端資料庫發生變異時，伺服器會記錄一個帶有 `source` 鍵標籤的變更事件。`useDbSync()` 接收該事件，並為該來源遞增一個本機計數器。將此計數器折疊進 React Query 鍵中，會讓查詢在後端回報該來源有新活動時自動重新取得。

在下方的範例中，一個原始的 `useQuery()` 呼叫直接讀取一個儀表板，並將 `"dashboards"` 來源的版本計數器折疊進其查詢鍵，使其在該來源發生變化時重新取得：

```tsx
import { useQuery } from "@tanstack/react-query";
import { useChangeVersion } from "@agent-native/core/client/hooks";

function DashboardView({ id }) {
  const version = useChangeVersion("dashboards");

  const { data } = useQuery({
    queryKey: ["dashboard", id, version],
    queryFn: () => fetchDashboard(id),
    placeholderData: (prev) => prev,
  });

  return <div>{data?.title}</div>;
}
```

`placeholderData: (prev) => prev` 讓重新取得期間畫面上保留先前的資料，因此檢視畫面不會閃爍到載入狀態。

## 重新取得的兩條路徑 {#latency-models}

一次變異透過兩種方式到達 UI，而它們的延遲不同。

一次本機變異，也就是您自己的 `useActionMutation()` 呼叫剛剛所做的變異，會在成功後立即發出一個 `source: "action"` 事件。每個依賴該 action 的查詢都會立即重新取得。沒有來回延遲，因為進行寫入的分頁已經知道這件事。

一次遠端變異，來自代理、webhook、另一個分頁或另一位使用者，必須先傳達到這個分頁。`useDbSync()` 幾乎立即透過 SSE 接收到它，或若 SSE 不可用，則在約兩秒內透過輪詢備援接收到它。只有在該事件到達之後，相關的版本計數器才會遞增，查詢才會在背景重新取得。
