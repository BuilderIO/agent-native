# Cloudflare

## Cloudflare Workers {#cloudflare-workers}

使用 Nitro 原生的模組輸出來產生一個 Cloudflare Worker。這樣可以
保持 SSR 啟用，並在 `.output/server` 和 `.output/public` 下產生
Worker 進入點和靜態資源:

```ts filename="vite.config.ts"
export default defineConfig({
  plugins: [agentNative({ nitro: { preset: "cloudflare_module" } })],
});
```

使用 Wrangler 建置並部署產生出來的 Worker：

```bash
pnpm build
npx wrangler deploy --config .output/server/wrangler.json
```

你也可以用 `NITRO_PRESET=cloudflare_module` 明確選擇這個預設。
部署之前請設定一個持久的外部 PostgreSQL 資料庫。Worker 的檔案系統
不是一個持久的應用程式儲存。

## 排程工作 {#cloudflare-scheduled-work}

排程自動化、佇列中的事件自動化，以及被中斷執行的清理，都會在每分鐘一次的掃描中完成。建置會在產生的 `wrangler.json` 中新增一個 `* * * * *` [Cron Trigger](https://developers.cloudflare.com/workers/configuration/cron-triggers/)，並保留你已經宣告的所有 Cron Trigger。觸發時，Worker 的 `scheduled` 處理常式會使用一個以 `A2A_SECRET` 簽署的短期權杖直接呼叫掃描，因此請在部署前設定這個密鑰：

```bash
npx wrangler secret put A2A_SECRET --config .output/server/wrangler.json
```

- **CPU 時間。** 在 Workers Free 方案中，每次 Cron Trigger 呼叫只有 10 毫秒的 CPU 時間，而執行代理作業的掃描需要更多。請為排程工作使用 Workers Paid 方案。
- **觸發時間。** Cron Trigger 以 UTC 執行，新的或變更過的觸發器在部署後最多可能需要 15 分鐘才會開始觸發。
- **本機測試。** 使用 `npx wrangler dev --test-scheduled --config .output/server/wrangler.json` 執行建置好的 Worker，然後請求 `/cdn-cgi/handler/scheduled?cron=*+*+*+*+*` 來觸發一次掃描。

請參閱 [調度程式如何執行](/docs/recurring-jobs#how-scheduler-runs) 了解其他託管平台。
