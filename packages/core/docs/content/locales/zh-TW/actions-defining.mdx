# 定義 Actions

每個 action 都從呼叫 `defineAction()` 開始。它把給代理看的描述、驗證輸入的架構，以及執行實際工作的 `run` 函式綁在一起，因此 UI 和代理呼叫的是完全相同的程式碼。

## 架構選項 {#schemas}

`schema` 接受任何相容於 [Standard Schema](https://standardschema.dev) 的函式庫：

- **Zod**（v4）：最常見的選擇，具有最佳的型別推斷，並能自動轉換成 JSON Schema。
- **Valibot**：當套件大小很重要時的好選擇。
- **ArkType**：如果您偏好它的語法，這是個好選擇。

架構做兩件事：它會轉換成 JSON Schema 供 Claude API 的工具定義使用，也會在 `run()` 觸發前於執行期驗證輸入。無效的輸入永遠不會傳到您的處理常式。

## 驗證回傳值 {#output-schema}

`schema` 驗證的是*輸入*。若也想驗證一個 action **回傳**的內容，可以傳入 `outputSchema`（任何相容於 Standard Schema 的架構：Zod、Valibot、ArkType，與 `schema` 使用相同的介面）。框架會在 `run()` 執行前驗證輸入，並在 `run()` 完成後驗證結果。

```ts
export default defineAction({
  description: "Summarize a thread.",
  schema: z.object({ threadId: z.string() }),
  outputSchema: z.object({
    summary: z.string(),
    messageCount: z.number(),
  }),
  outputErrorStrategy: "warn", // default
  run: async ({ threadId }) => {
    /* ...returns { summary, messageCount } ... */
  },
});
```

`outputErrorStrategy` 控制不符時該怎麼處理：

| 策略         | 不符時的行為                                                                        |
| ------------ | ----------------------------------------------------------------------------------- |
| `"warn"`     | **預設值。** 用 `console.warn` 記錄問題，並原封不動回傳**原始**結果。不會造成中斷。 |
| `"strict"`   | 拋出明確的錯誤，讓 action 中的錯誤容易被發現。                                      |
| `"fallback"` | 回傳提供的 `outputFallback` 值，取代無效的結果。                                    |

當 `run()` 成功時，框架會回傳經過驗證的值，因此 `outputSchema` 上的任何預設值或強制轉換都會生效，就像對輸入所做的一樣。若您沒有傳入 `outputSchema`，回傳值則維持不變。

## HTTP 設定 {#http}

預設情況下，每個 action 都會以 `POST /_agent-native/actions/<name>` 的形式曝露。可以用 `http` 選項覆蓋：

```ts
export default defineAction({
  description: "Get details for a lead.",
  schema: z.object({ leadId: z.string() }),
  http: { method: "GET" },
  run: async ({ leadId }) => {
    return await db.select().from(leads).where(eq(leads.id, leadId));
  },
});
```

對於 `GET` action，`leadId` 會以查詢參數的形式傳入：`/_agent-native/actions/get-lead?leadId=abc`。

POST 是預設值，`http: { method: "GET" }` 會將它變成 GET。React 掛鉤和 `callAction()` 一律會依名稱呼叫這個路徑，無論是否有任何 `http.path` 的覆蓋設定。外部系統可以用長效的 bearer token 呼叫同一個路由。請參閱 [HTTP API](/docs/http-api)。

</Endpoint>

- **`http: { method: "GET" | "POST" | "PUT" | "DELETE" }`**：預設為 `POST`。`GET` action 會自動標記為 `readOnly`，因此成功呼叫不會觸發 UI 輪詢重新整理。
- **`http: { path: "..." }`**：覆蓋掛載於 `/_agent-native/actions/` 下的 URL，預設為檔案名稱。此覆蓋只會改變直接 HTTP 呼叫者所使用的 URL。`useActionQuery()`、`useActionMutation()` 和 `callAction()` 一律會呼叫 `/_agent-native/actions/<name>`，不受此覆蓋影響，因此覆蓋路徑會讓這些掛鉤發生 404。只有在給外部 HTTP 呼叫者使用時才覆蓋路徑。另請注意，覆蓋路徑中的 `:param` 路由片段不會被解析成 `run()` 的參數，只有查詢字串參數和 JSON 主體欄位才會。
- **`http: false`**：完全停用 HTTP 端點。只有代理和 CLI 能呼叫此 action。
- **`readOnly: true`**：明確跳過輪詢重新整理，即使是不會變更任何資料的 POST action 也一樣。這不是存取控制，它不會限制誰可以呼叫此 action，也不會影響 `useActionQuery()`、`useActionMutation()` 或任何用戶端掛鉤。它唯一的作用是抑制呼叫後的重新整理事件，並讓此 action 退出寫入稽核。若要對模型隱藏一個 action，請使用 `agentTool: false`。若要限制誰可以呼叫它，請使用[存取與授權](/docs/actions-access-control)中的驗證與存取選項。
- **`parallelSafe: true`**：允許一個變更資料的 action 與同一回合中的其他工具呼叫同時執行。只有在此 action 可以安全地並行執行、且不依賴順序時才設定此項。變更資料的 action 預設會依序執行。

## 讓 action 介面保持精簡 {#small-surface}

代理能看到的每個 action 都會佔用模型工具清單中的一個位置，而冗長、重疊的清單會讓模型更難挑選正確的工具。請把 action 介面設計成一套您自己維護的 API，而不是 UI 中每個按鈕都對應一個 action：

- 優先使用**一個 CRUD 風格的 `update` action**，接受一組可選欄位的修補內容，而不是像 `update-name`、`update-order`、`update-color` 這樣許多按欄位分開的 action。呼叫者只需要傳送有變更的欄位。
- 在為每個查詢或篩選條件新增一個讀取 action 之前，請先考慮更通用的選項：供應商資料可用[供應商 API 三件組](/docs/template-dispatch-vault-integrations#provider-api)（`provider-api-catalog`、`provider-api-docs` 與 `provider-api-request`），應用程式資料則可用開發用的 `db-query` 工具。
- 將僅供 UI 使用或程式化用途的 action 標記為 [`agentTool: false`](/docs/actions-access-control#agent-tool)。它們仍可從前端或透過 HTTP 呼叫，但不會佔用模型工具清單中的位置。
- 刪除或隱藏 UI 已不再使用的 action，而不是繼續讓它們曝露給模型。

此儲存庫包含一個建議性的輔助工具 `node scripts/audit-template-actions.mjs [template ...]`（別名 `pnpm actions:audit`）。它會掃描一個範本的 `actions/` 資料夾，標出 UI 可能已不再使用的 action，以及可以合併成一個的按欄位分開的 action 群組。它一律以代碼 0 結束，永遠不會讓 CI 失敗，而且其判斷方式偏保守，因此請把它的輸出當作建議，而非錯誤。
