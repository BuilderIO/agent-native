# 公開代理網路

公開代理網路使公開 Agent-Native 路由易於代理抓取、閱讀、引用和呼叫。目標不是公開每個應用程式端點。目標是為已經公開的頁面發布一個幹淨的公開介面，同時將私人資料和工具存取保留在顯式控制之下。

檔案站點是參考實現。今天發貨：

- `/robots.txt` 的爬蟲策略預設允許檢索但不允許訓練。
- `/sitemap.xml` 作為網站地圖索引，為每個語系指向一個 `/sitemap-<locale>.xml`；當來源檔案公開它時，具有絕對規範的 URL 和 `lastmod`。
- `/llms.txt` 和 `/llms-full.txt` 用於代理友好的內容發現。
- Markdown 鏡像，例如 `/docs/getting-started.md`。
- 正式環境建置後公開檔案頁面的 `Accept: text/markdown` 回應。
- JSON-LD 用於基礎組織、網站和頁面中繼資料。
- 審核 CLI (`npx @agent-native/core@latest audit-agent-web`)，檢查上述所有內容。

發布這些檔案永遠不會公開任何操作。操作只能透過自己的 `publicAgent` 選擇加入才能被外部代理存取；請參閱[曝露給公開代理](/docs/actions-access-control#public-agent)。

## 設定 {#config}

`@agent-native/core/vite` 中的 `createAgentWebVitePlugin` 會在正式版建置期間寫出這些檔案。把它連同代理應讀取的頁面一起加入你的 Vite 設定：

```ts
// vite.config.ts
import { defineConfig } from "vite";
import { createAgentWebVitePlugin } from "@agent-native/core/vite";

export default defineConfig({
  plugins: [
    // ...your existing plugins
    createAgentWebVitePlugin({
      siteName: "My Agent-Native App",
      siteUrl: "https://example.com",
      pages: [
        {
          path: "/pricing",
          title: "Pricing",
          description: "Plans and limits.",
          markdown: "Plans and limits.\n",
        },
      ],
      agentWeb: { crawlerPolicy: "discoverable-no-training" },
    }),
  ],
});
```

外掛只會發布你列出的頁面，不會發布其他內容。它不會讀取你的路由存取設定；除非你傳入，它也不會讀取 `package.json` 中的 `agentWeb`。要把設定保留在 `package.json` 的 `agent-native.workspaceApp.agentWeb` 下，請傳入 `agentWeb: agentWebConfigFromPackageJson(pkg)`，它從 `@agent-native/core/agent-web` 匯入。

| 選項            | 預設值                       | 作用                                                                                                                              |
| --------------- | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `discoverable`  | `pages` 非空時開啟           | 設為 `false` 時不寫出任何檔案。                                                                                                   |
| `llmsTxt`       | `true`                       | 寫出 `/llms.txt` 和 `/llms-full.txt`。                                                                                            |
| `markdownTwins` | `true`                       | 為每個帶有 `markdown` 的頁面寫出一份 `.md` 副本。                                                                                 |
| `crawlerPolicy` | `"discoverable-no-training"` | 設定 `robots.txt` 規則：`"discoverable-no-training"`、`"allow-all"` 或 `"disallow-all"`。                                         |
| `crawlers`      | 無                           | 單獨覆寫各類爬蟲：`training`、`search`、`userTriggered`、`codingAgents` 或 `autonomousAgents`，每類取 `"allow"` 或 `"disallow"`。 |

預設爬蟲政策是「可被發現，不可訓練」：允許搜尋、使用者觸發的擷取、程式設計代理和自主瀏覽代理；不允許訓練爬蟲。

`jsonLd`、`publicAgentCard` 和 `publicMcp` 會被接受，但目前沒有任何程式碼讀取它們。如需 JSON-LD，請自己把 `@agent-native/core/agent-web` 中的 `buildBaseJsonLd` 和 `buildPageJsonLd` 渲染到頁面中。

## 路由真相來源 {#route-source}

頁面清單就是事實來源：代理只會取得你傳入的頁面。請用已經公開的頁面來建立它：

- 在公開應用程式中，除 `protectedPaths` 之外的所有路由。
- 在內部應用程式中，只有 `publicPaths`。
- 代理應能讀取的公開分享頁和表單頁。
- 絕不包含提交的私人資料、需要驗證的儀表板或使用者/組織狀態，即使附近的頁面是公開的。

要從存取設定出發，`@agent-native/core/agent-web` 中的 `deriveAgentWebPublicRoutes` 接收應用程式的 `audience`、`publicPaths`、`protectedPaths` 和 `routes`，並傳回這些設定公開的路由。每個頁面仍需要自己的標題和 Markdown。

這使混合應用程式保持自然。表單應用程式可以公開公開表單頁面並保持提交的私密性。內容應用程式可以公開已發布的帖子並保持編輯者的私密性。檔案網站可以公開除管理工具之外的所有內容。

## 公開頁面不是公開工具 {#public-tools}

公開頁面存取和公開工具存取是分開的。路由僅公開意味著代理可以將該路由讀取為 HTML、Markdown、站點地圖條目、llms 條目和結構化資料。

<Callout id="doc-block-s50w8y" tone="warning">

**公開頁面不是公開工具。** 讓路由可被爬取永遠不會公開任何操作。工具存取需要在操作上明確選擇加入 `publicAgent.expose`。

</Callout>

要透過公開代理協議公開操作，該操作必須選取加入：

## 建置時檔案 {#build-time}

`@agent-native/core/agent-web` 中的框架實用程式從一頁面清單生成通用檔案：

```ts
import {
  buildAgentWebStaticFiles,
  normalizeAgentWebConfig,
} from "@agent-native/core/agent-web";

const config = normalizeAgentWebConfig(
  { crawlerPolicy: "discoverable-no-training" },
  { hasPublicRoutes: true },
);

const files = buildAgentWebStaticFiles({
  siteName: "My Agent-Native App",
  siteUrl: "https://example.com",
  description: "Public docs for my app.",
  config,
  pages: [
    {
      path: "/docs",
      title: "Docs",
      description: "Start here.",
      markdown: "# 檔案\n\n從這裡開始。\n",
      markdownPath: "/docs/getting-started.md",
      lastmod: new Date(),
    },
  ],
});
```

`createAgentWebVitePlugin` 會替你呼叫 `buildAgentWebStaticFiles`，並把檔案寫入 `public`、`dist`、`dist/client`、`dist/server/public` 和 `build/client` 中實際存在的目錄。使用其他建置工具時，請直接呼叫這些工具函式。

兩者都不會在頁面自身的 URL 上回應 `Accept: text/markdown`：Markdown 副本只在它的 `.md` URL 上。要回應這個標頭，請像文件網站那樣新增一個伺服器路由，用 `buildMarkdownResponseHeaders` 的標頭傳回頁面的 Markdown。沒有這個路由，下方的稽核會在 `Accept: text/markdown` 檢查上失敗。

向 `buildAgentWebStaticFiles` 或 `createAgentWebVitePlugin` 傳入 `sitemapGroup` 即可拆分大型網站地圖。它會將每個頁面對應到一個分組鍵（例如語系），`sitemap.xml` 隨即成為網站地圖索引，每個分組對應一個 `sitemap-<group>.xml`。

## 審核網站 {#audit}

對已部署站點或本機正式環境伺服器使用 CLI 審核：

```bash
npx @agent-native/core@latest audit-agent-web --url https://www.agent-native.com
```

審核檢查：

- SSR-可見HTML。
- 規範 URL。
- JSON-LD。
- `robots.txt` 政策和絕對站點地圖 URL。
- 絕對站點地圖條目。
- `/llms.txt` 和 `/llms-full.txt`。
- Markdown 鏡子。
- `Accept: text/markdown`.
- 公開代理檢索使用者代理不會出現意外的 401/403 阻塞。

如果缺少所需的公開表面，審核將以非零值退出。
