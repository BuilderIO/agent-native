# 功能

表單的每一項核心功能：運作方式，以及如何設定。總覽請參閱 [表單](/docs/template-forms)，完整的提示清單請參閱 [與 Agent 對話](/docs/template-forms-agent)。

## 建立表單

每份表單都從一組欄位開始。向代理描述您想要的內容，它就會為您建置表單；或者從頭開始，自行在視覺化建置器中新增欄位。這兩種路徑編輯的是同一份表單，所以在兩者之間切換絕不會造成任何內容失去同步。一旦表單建立完成，它的建置器就會有四個分頁，編輯、回覆、設定和整合，讓您在需要比聊天中描述變更更直接的控制時，手動調整標籤、預留位置、必填欄位、選項和欄位順序。

### 欄位類型 {#field-types}

表單內建 11 種欄位類型，開箱即用。您可以直接叫出任何一種類型的名稱請代理使用，或者只描述您想問的問題，讓它自行選擇合適的類型。

每個欄位都需要一個標籤和一個類型。像 `select`、`multiselect` 和 `radio` 這類欄位，還需要一份供填寫者選擇的選項清單。您可以把任何欄位標記為必填、加入最小值或最大值之類的驗證規則，並選擇這個欄位要佔滿表單整行寬度，還是與另一個欄位並排顯示。

### 條件欄位

一個欄位可以保持隱藏，直到較早的答案符合您設定的規則為止。舉例來說，您可以隱藏一個「告訴我們更多」的文字欄位，除非有人在較早的問題中選了「其他」。

您用來檢查的欄位，必須排在表單中較前面的位置。一條指向較後面欄位，或指向不存在欄位的規則，會在儲存前就被拒絕。您可以檢查較早的答案是否等於某個值、不等於某個值，或包含某個值，這對可以選擇多個選項的問題同樣適用。如果一個欄位最終因為條件而被隱藏，它的答案就永遠不會被儲存或傳送到任何地方，所以一個隱藏欄位不會在您的資料中留下舊值或預設值。

想直接用程式建立表單，而不是在聊天中描述？請參閱 [開發者指南](/docs/template-forms-developers#data-model) 中的欄位與設定 JSON 參考。

## 發布您的表單

一份表單會經歷三種狀態：

| 狀態        | 意義             | 公開存取       |
| ----------- | ---------------- | -------------- |
| `draft`     | 進行中，尚未公開 | 否             |
| `published` | 已上線並接受回覆 | 是             |
| `closed`    | 不再接受回覆     | 顯示已關閉訊息 |

如果一份表單沒有任何欄位、任何欄位缺少標籤，或是 `select`、`multiselect` 或 `radio` 欄位沒有選項，就無法發布。如果發布時被拒絕，系統會告訴您具體原因。

公開網址的格式類似 `/f/<slug>`，其中的 slug 是根據標題加上一段簡短的唯一後綴產生的，例如 `beta-signup-a1b2c3`。只要標題有變更，它就會自動重新產生，除非您設定了自訂 slug。

### 收集回覆

每一次對已發布表單的提交，都會成為一筆回覆：包含答案、到達時間，以及除非表單為匿名，還有是誰、從哪裡送出的。開啟任何表單的回覆分頁即可檢視每一筆的詳細內容，或者直接問代理：

- 「beta 註冊表單有多少筆回覆？」
- 「今天有誰提交了？」
- 「顯示客戶意見回饋表單的回覆。」

如果一筆回覆是透過嵌入在另一個應用程式中的回饋按鈕送進來的，而不是透過公開表單頁面本身，回覆表格中還會顯示它來自哪個頁面和哪個應用程式。只有在至少有一筆回覆確實帶有這項資訊時，這些欄位才會顯示出來。

## 設定

每份表單都有自己的設定，位於建置器的設定分頁中，用來控制它的行為，以及受訪者會看到什麼。

- **提交按鈕文字。** 把提交按鈕上的標籤，從預設的「提交」改成更具體的文字，例如「送出意見回饋」或「預留我的名額」。
- **成功訊息。** 選擇受訪者提交後立即看到的內容，取代預設的確認訊息。
- **重新導向網址。** 讓受訪者提交後前往另一個頁面，而不是在表單本身顯示成功訊息。
- **進度條。** 在較長的表單頂部顯示進度條，讓受訪者知道還剩多少。
- **匿名模式。** 關閉所有關於是誰回覆的追蹤，讓提交內容永遠不會擷取 IP 位址、電子郵件或地點。
- **有新回覆時寄信通知我。** 每當有人提交，就透過您設定的電子郵件服務商收到一封通知信。

## 保護並為公開表單加上品牌

### 垃圾提交防護

公開提交內容可以要求先通過 [Cloudflare Turnstile](https://www.cloudflare.com/products/turnstile/) 驗證才能送出。在設定中設定網站金鑰和密鑰即可開啟這項功能。即使沒有設定 Turnstile，仍有兩項防護會持續運作：一個會悄悄捨棄機器人提交內容的隱藏欄位，以及一項會拒絕任何送出速度快到不像是真人合理填完表單的檢查。

<Callout tone="warning">

請同時設定兩把 Turnstile 金鑰。公開表單頁面只有在設定了網站金鑰時才會顯示驗證元件，而伺服器只有在兩把金鑰都設定後才會進行檢查。只設定密鑰不會驗證任何東西，只設定網站金鑰則會顯示一個伺服器實際上從不檢查的元件。

</Callout>

### 品牌標示

每份獨立的公開表單，角落都會顯示一個小小的「Built with Agent-Native」徽章。這不是您可以逐份表單開關的選項。只有在表單被嵌入另一個頁面中時，例如一個回饋彈出視窗，它才會自動隱藏，因為那個頁面已經有自己的品牌標示。

### 限制可提交的來源

根據預設，表單的提交連結接受來自任何地方的提交，這也是一個純粹的公開表單連結原本該有的行為。如果您把表單的提交連結嵌入到另一個網站的小工具中，並想確保只有那個網站能使用它，您可以把提交內容限制在一份特定的網站來源清單中。

目前建置器中沒有這個功能的開關。請代理幫您設定，例如「只允許這份表單從 https://example.com 提交」。針對每個應該被允許的網站，請提供代理確切的來源（協定加網域，例如 `https://example.com`，不含結尾的路徑）。

## 匯出

在表單的回覆分頁中，點選**匯出 CSV**，就能立即下載目前畫面上的內容，包括您套用的任何搜尋或排序。這項功能可以立即使用，不需要任何設定。

您也可以請代理提供「這份表單的 CSV」或「所有回覆的 JSON 匯出」。這一律會匯出每一筆回覆，而不只是目前篩選出來的內容，而且需要先連接一個檔案儲存服務。如果還沒有連接任何服務，代理會告訴您，並指引您前往設定 → 檔案上傳，免費的 Builder.io 帳戶是一個快速的選項。一旦連接了儲存服務，代理會給您一個檔案連結，而不是直接下載檔案。每次匯出都會使用您的欄位標籤作為欄標題（CSV 格式），如果有人在某個欄位中選了不只一個選項，這些選項會合併顯示在同一個儲存格中。任何看起來可能是試算表公式的答案，都會先被安全處理，保護您在開啟檔案時不會被嘗試執行程式碼的提交內容影響。

## 路由提交內容

開啟自動傳送功能，讓新回覆直接出現在您團隊已經在使用的地方，而不必有人去檢查回覆分頁。這是一項逐份表單的設定，位於建置器的整合分頁中。

| 目的地        | 需要什麼                                                                         |
| ------------- | -------------------------------------------------------------------------------- |
| Slack         | 您想要的頻道的 Incoming Webhook 網址                                             |
| Discord       | 您想要的頻道的 webhook 網址                                                      |
| Google Sheets | 一個設定好用來接收提交內容的 Google Apps Script 網址。單純的試算表連結無法運作。 |
| Webhook       | 任何可以接收提交內容作為資料的網址                                               |

這與連接 Slack 讓代理直接在那裡發文是分開的兩件事，後者在 [Messaging](/docs/messaging) 中有說明。如果您想讓代理親自把更新發布到 Slack，請先連接那個部分。每個目的地位址都會被檢查，確保它沒有指向私人網路或內部位址，無論是在您儲存它的當下，還是每次有回覆進來時都會檢查，這樣一份表單就不能被用來探測您自己的網路。

您也可以開啟電子郵件通知，讓表單擁有者在每次有新回覆時收到一封電子郵件，透過已設定好的電子郵件服務傳送。傳送這封郵件屬於盡力而為的機制。即使通知信寄送失敗，提交內容仍然會順利完成。
