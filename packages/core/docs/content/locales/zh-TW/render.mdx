# Render

<Badge label="Beta" color="orange" icon="rocket" />

Render 會把你的應用程式當作 Web 服務來代管，因此不需要架設或維護伺服器。Render
執行的是 [Node.js 指南](/docs/node-js)中介紹的同一個 Node.js 伺服器，它會從你的
Git 存放庫建置應用程式，並為應用程式提供一個支援 HTTPS 的公開網址。

本指南會從頭開始示範如何部署一個獨立應用程式。你將建立應用程式並把它推送到 Git
存放庫，為它設定正式環境資料庫和驗證密鑰，準備好資料庫，然後建立一個負責建置和
執行它的 Render Web 服務。

<Callout tone="info">

需要 Node.js `22.22+`。

</Callout>

你還需要一個 Render 帳號，以及一個位於 GitHub、GitLab 或 Bitbucket 上的存放庫。請在
你自己的電腦上執行本指南中的指令。Render 會從你的存放庫建置並執行應用程式。

## 步驟 1：建立應用程式 {#step-1-create-the-app}

建立新的獨立應用程式。下面的範例以 Chat 範本建立應用程式，但你可以從任何範本開始。
進入應用程式的資料夾並安裝相依套件。`corepack enable` 會啟用應用程式所需的 `pnpm`
版本，因此你不需要自行安裝 `pnpm`。

```bash
npx --yes @agent-native/core@latest create my-app --standalone --template chat

cd my-app

corepack enable

pnpm install
```

如果你想要，可以把 `my-app` 換成你自己的應用程式名稱。本指南的其餘部分假設你位於
應用程式的資料夾中。

Render 會從 Git 存放庫建置應用程式，因此在繼續之前，請把應用程式的資料夾推送到
GitHub、GitLab 或 Bitbucket 上的一個新存放庫。也請提交 `pnpm-lock.yaml` 檔案，因為
建置會安裝其中列出的確切版本。

<Callout tone="info">

如果這些指令因對等相依性錯誤而失敗，原因可能是 npx 快取中有過時的套件副本。執行 `npx clear-npx-cache` 清除快取，然後重新執行這些指令。

</Callout>

## 步驟 2：設定環境密鑰 {#step-2-configure-environment-secrets}

應用程式會從環境變數讀取其正式環境設定：

| 變數                 | 必要 | 用途                                       |
| -------------------- | ---- | ------------------------------------------ |
| `DATABASE_URL`       | 是   | 將應用程式連線到它的 PostgreSQL 資料庫     |
| `BETTER_AUTH_SECRET` | 是   | 為使用者工作階段簽章                       |
| `BETTER_AUTH_URL`    | 否   | 設定使用者連到你的應用程式時使用的公開網址 |

下面的 export 指令讓後續指令能在目前的 shell 中正常運作。部署之前，請把這些變數
同樣儲存到主機的專案或服務環境設定中。步驟 4 會說明如何在 Render 中儲存它們。

### 資料庫 URL {#database-url}

在本機開發期間，如果未設定 `DATABASE_URL`，應用程式會把資料儲存在本機資料庫中。
已部署的應用程式需要一個真正的 PostgreSQL 資料庫，在每次部署之間保留資料。Render
會在每次部署和重新啟動時取代服務的檔案，因此資料庫必須位於 Web 服務之外。從你的
提供者複製連線字串並匯出它：

```bash
export DATABASE_URL='your-postgres-url-string'
```

[資料庫提供者指南](/docs/neon)說明了在各個提供者處找到連線字串的位置。也可以使用
Render Postgres。在這裡使用它的外部連線字串，在 Web 服務的設定中使用它的內部連線
字串。

<Callout tone="warning">

請選擇持久性的 PostgreSQL 提供者，例如 Neon、Supabase、Amazon RDS 等。

</Callout>

### 驗證密鑰 {#auth-secret}

只需要產生一次，並在每次部署之間保持不變。

應用程式使用 `BETTER_AUTH_SECRET` 為使用者工作階段簽章。如果它變更了，所有已登入的
使用者都會被登出。下面的指令會產生一個隨機值：

```bash
export BETTER_AUTH_SECRET="$(openssl rand -hex 32)"
```

請把產生的值儲存在安全的地方，例如密碼管理工具。每次部署時都使用相同的值。

### 公開 URL {#public-url}

選用。在使用自訂網域、反向代理，或需要固定公開來源的驗證/OAuth 流程時設定它。

`BETTER_AUTH_URL` 是使用者連到你的應用程式時使用的公開網址。如果沒有設定，應用程式
會根據每個傳入的請求推斷自己的網址。在 Render 提供給你的網址上，這通常沒有問題，
但當你連接自訂網域時，請設定它，讓登入連結和 OAuth 重新導向使用該網域。

```bash
export BETTER_AUTH_URL='https://your-domain.example'
```

## 步驟 3：遷移 {#step-3-migrate}

遷移會在你的資料庫中建立和更新應用程式所需的資料表。請在第一次部署之前執行此指令：

```bash
pnpm migrate:production
```

這個指令會在你的電腦上執行，並使用你在步驟 2 中匯出的 `DATABASE_URL` 連線到正式
環境資料庫。升級應用程式之後、部署新版本之前，請再執行一次。

在付費的 Render 執行個體上，你也可以把服務的 **Pre-Deploy Command** 設定為
`pnpm migrate:production`。這樣 Render 會在每次部署上線之前執行遷移。Free 執行個體
類型不提供 Pre-Deploy Command。

## 步驟 4：建立 Web 服務 {#step-4-create-the-web-service}

在 Render 資訊主頁中，建立一個新的 **Web Service**，並連接步驟 1 中的存放庫。使用
以下設定：

| 設定          | 值                                                                                        |
| ------------- | ----------------------------------------------------------------------------------------- |
| Language      | `Node`                                                                                    |
| Branch        | 你用來部署的分支，例如 `main`                                                             |
| Build Command | `corepack enable && pnpm install --frozen-lockfile && NITRO_PRESET=render_com pnpm build` |
| Start Command | `node .output/server/index.mjs`                                                           |

Build Command 會啟用應用程式的 `pnpm` 版本，安裝 `pnpm-lock.yaml` 中列出的相依套件，
並建置應用程式。`NITRO_PRESET=render_com` 會建置與 Node.js 指南中相同的 Node.js
伺服器，並將它設定為自行提供靜態檔案。Start Command 會執行這個伺服器。Render 透過
`PORT` 環境變數告訴伺服器要使用哪個連接埠，伺服器會自動讀取它。

在 **Environment Variables** 下，新增 `DATABASE_URL` 和 `BETTER_AUTH_SECRET`，值為
你在步驟 2 中匯出的值。如果你有設定 `BETTER_AUTH_URL`，請用同樣的方式新增它。

Render 會依序根據 `NODE_VERSION` 環境變數、`.node-version` 或 `.nvmrc` 檔案，以及
`package.json` 中的 `engines` 欄位選擇 Node.js 版本。新服務預設使用的版本符合上述
需求。若要固定版本，請新增 `NODE_VERSION`，例如將值設為 `24`。

## 步驟 5：部署 {#step-5-deploy}

<Steps>

### 選擇執行個體類型

為 Web 服務選擇執行個體類型。Free 執行個體類型適合試用應用程式。如果應用程式需要
立即回應，或你想使用步驟 3 中的 Pre-Deploy Command，請選擇付費執行個體類型。

### 建立 Web 服務

建立 Web 服務。Render 會從你的存放庫建置應用程式並啟動它。第一次建置需要幾分鐘，
你可以在服務的記錄中追蹤進度。

### 開啟應用程式

部署完成後，資訊主頁會顯示應用程式的網址，該網址以 `onrender.com` 結尾。開啟它並
建立第一個帳號。

</Steps>

在 Free 執行個體類型上，如果服務 15 分鐘內沒有流量，Render 會將它暫停。之後的下一次
造訪需要等待大約一分鐘，讓服務重新啟動。

## 部署更新 {#deploy-updates}

每次你推送到步驟 4 中選擇的分支時，Render 都會重新部署。若要發布新版本，請先執行
遷移，然後推送：

```bash
pnpm migrate:production

git push
```

服務設定和已儲存的變數會保持不變，因此你不需要重複步驟 4。
