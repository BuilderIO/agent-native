# 資料與同步

從用戶端應用程式讀取和寫入應用資料的主要方式是透過 [action](/docs/actions) 掛鉤。透過將請求嵌入到 actions 中，您的用戶端和代理都能以相同的方式與您的應用程式互動。

在下方的範例中，一張工單先透過下拉選單手動指派給目前使用者，然後再透過聊天代理指派。UI 和代理存取的是同一個 action。

### Action 掛鉤 {#action-hooks}

最常用到的兩個 action 掛鉤是 `useActionQuery()` 和 `useActionMutation()`。這兩個掛鉤提供了存取您應用程式 actions 的方式。

#### useActionQuery {#use-action-query}

<Signature

  params={[

    },
    {

    },
    {

      optional: true,

    },
  ]}
  returns={{
    type: "UseQueryResult<TResult>",
    description:
      '快取於 `["action", name, params]` 之下。每當一個變異 action 完成時就會自動重新取得，不需要手動失效。',
  }}
/>

此掛鉤旨在用於唯讀 actions。它是 [useQuery()](https://tanstack.com/query/latest/docs/framework/react/reference/useQuery) 函式的簡單包裝。

在下方的範例中，呼叫了 `list-tickets` action。這類似於為所有工單發出一個 GET 請求。

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery("list-tickets", {});
```

以下範例展示透過 `get-ticket` action 取得單一工單的請求。傳入 `ticketId` 以將查詢範圍限定為只回傳特定工單。額外的 `enabled` 選項用於確保查詢不會自動執行，而只在 `ticketId` 存在時才執行。

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery(
  "get-ticket",
  { ticketId: ticketId ?? "" },
  { enabled: Boolean(ticketId) },
);
```

  }}
/>

此掛鉤旨在用於變更資料的 actions，例如建立、更新或傳送某項內容。它是 [useMutation()](https://tanstack.com/query/latest/docs/framework/react/reference/useMutation) 函式的簡單包裝。

與 `useActionQuery()` 不同，此 action 的輸入不會傳給掛鉤本身，而是在您準備執行變異時傳給 `mutate()` 或 `mutateAsync()`。

在下方的範例中，呼叫了 `send-ticket-reply` action 來對一則工單發布回覆。從事件處理常式（例如按鈕的 `onClick`）呼叫 `mutate()`。

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply");

mutate({ ticketId, body: draft });
```

以下範例展示帶有 `onSuccess` 選項的相同變異。快取失效在每次變異後都會自動發生，因此 `onSuccess` 只在需要本機副作用時才需要，例如在回覆傳送後清空回覆編輯器。

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply", {
  onSuccess: () => setDraft(""),
});

mutate({ ticketId, body: draft });
```

  ]}
  returns={{
    type: "Promise<TResult>",
    description:
      "與上方的掛鉤不同，這裡沒有快取也沒有自動重新取得。若其他 UI 依賴此結果，請搭配手動失效。",
  }}
/>

此函式用於 React 渲染流程之外的指令式一次性 action 呼叫，例如純粹的事件處理常式、腳本，或任何其他非 React 程式碼路徑。它直接回傳一個 promise，而不是掛鉤結果。

在下方的範例中，`update-ticket` action 從一個鍵盤快速鍵處理常式中被呼叫，該處理常式位於 React 的渲染流程之外，將工單指派給一位代表。

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction("update-ticket", {
  ticketId,
  assignedToEmail: "jordan@example.com",
});
```

以下範例展示帶有 `timeoutMs` 選項的相同呼叫，適用於合理需要超過預設 60 秒逾時的 actions。

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction(
  "update-ticket",
  { ticketId, assignedToEmail: "jordan@example.com" },
  { timeoutMs: 120_000 },
);
```

每個 `useActionQuery()`、`useActionMutation()` 和 `callAction()` 請求都受限於 60 秒逾時，逾時會以錯誤形式呈現，而不會靜默重試。`useActionQuery()` 也會使用 React Query 的中止信號自動取消被取代的請求。

此掛鉤旨在讓 UI 與發生在您自己的 actions 之外的資料庫變更保持同步，例如代理的寫入、webhook，或來自另一個瀏覽器分頁的變更。它透過伺服器傳送事件監聽變更，並在伺服器傳送事件不可用時回退為輪詢。

```ts
import { useDbSync } from "@agent-native/core/client/hooks";
import { useQueryClient } from "@tanstack/react-query";

function App() {
  const queryClient = useQueryClient();

  useDbSync({
    queryClient,
    pollUrl: "/_agent-native/poll",
    onEvent: (data) => console.log("Data changed:", data),
  });

  return <div>...</div>;
}
```

對於一般的 CRUD，優先使用 `useActionQuery()` 和 `useActionMutation()`。變異 actions 會發出 `source: "action"`，因此這些掛鉤會立即重新取得。來自代理、webhook 或另一個分頁的變更則透過 `useDbSync()` 到來，經由 SSE 或輪詢備援。若原始的 `useQuery()` 呼叫需要以自訂鍵同步，請參閱[同步內部機制](/docs/client-sync-internals)。若您需要直接寫入 `application_state`，請參閱[進階](/docs/client-advanced)。
