# Doctor

產生的應用程式與 workspace 包含可透過儲存庫開發工作流程變更的原始碼，也可由被有意授予工作區與寫入工具的代理 frame 變更。`agent-native doctor` 會掃描原始碼中的關鍵程式碼安全不變條件。它是唯讀的：doctor 從不編輯程式碼，只回報結果。

`agent-native doctor` 會檢查安全與遷移問題。`migration-manifest` 會找出已安裝 `migration-manifest.json` 中列出的 import，且無法停用。`feature-dependencies` 會回報已設定功能所需的 optional peer package 無法解析的情況。

執行遷移預檢：

```bash
agent-native doctor --only migration-manifest
```

預覽 upgrade 和 codemod diff，不寫入檔案：

```bash
npx agent-native upgrade --codemods --dry-run
```

套用支援的 import 重寫：

```bash
npx agent-native upgrade --codemods
```

`--codemods` 預設會套用支援的重寫。加入 `--dry-run` 可只預覽而不寫入檔案。套用前請檢查 diff 和警告。`--yes` 為相容性保留，不會改變行為。`migration-manifest` 無法停用。`planned` 項目只會顯示為警告，不會被重寫。active 項目會列為問題；codemod 只有在目標 export 已安裝時才會重寫。已移除的 export 需要手動遷移。請遵循 finding 中連結的指南，或參閱列出 `ts-morph` 和可選功能套件的 [Core 0.197.0 遷移指南](/docs/upgrading-to-0-197)。JSON `guardsRun` 會列出實際執行的 guard。

CLI 會為每個新建的 app 與 workspace 加入 `pnpm doctor` 及 `pnpm agent-native:doctor` 指令。從 workspace 根目錄執行時，會檢查 `apps/<name>` 下的每個 app。發現問題時，build 預設會失敗；只有經過審查的例外才應使用 `failOnBuild: false`。

標記為 `planned` 的項目只會顯示為警告，不會被重寫。active 項目會列為問題；codemod 只有在目標 export 已安裝時才會重寫。
