# 部署

Agent-Native 應用程式執行於 [Nitro](https://nitro.build)，因此同一個應用程式可以部署到
Node.js、無伺服器函式、邊緣 worker 或代管主機。請選擇符合部署內容的路徑：

<Cards columns={2}>

### :server: [部署應用程式](/docs/deploy-an-app)

建置並發布一個獨立應用程式，執行於 Node.js、Docker、Vercel、Netlify 或
Cloudflare Workers。

### :network: [部署工作區](/docs/workspace-deployment)

在單一來源下建置多個應用程式，共用登入狀態，並支援同源的應用程式間通訊。

</Cards>

## 部署前：選擇持久性資料庫 {#persistent-database}

每個已部署的應用程式都需要持久性的 PostgreSQL 資料庫。本機開發可以使用位於 `data/pglite`
的 PGlite 資料庫，但容器、預覽和無伺服器環境的檔案系統隨時可能被重設。

<Steps>

### 選擇提供者

請使用代管的 PostgreSQL 提供者，例如 [Neon](/docs/neon)、
[Supabase](/docs/supabase)、Railway、Render、[Amazon RDS for PostgreSQL](/docs/aws-rds)、
[Cloud SQL for PostgreSQL](/docs/cloud-sql) 或 [Azure Database for PostgreSQL](/docs/azure-postgresql)。
其他代管服務與自行託管的 PostgreSQL 伺服器請參閱 [Plain Postgres](/docs/postgres) 指南。
框架會根據連線 URL 設定 PostgreSQL。

### 設定連線字串

在第一次正式環境部署之前，請在代管提供者的環境變數或密鑰設定中設定 `DATABASE_URL`。
本機 `.env` 只會設定你自己的電腦，部署指令不會上傳它。

### 新增正式環境密鑰

使用 `openssl rand -hex 32` 產生一個穩定的簽章密鑰，然後在獨立應用程式中將它設定為
`BETTER_AUTH_SECRET`。如果工作區使用簽章的跨應用程式請求或背景交接，還需要設定
`A2A_SECRET`。[部署環境變數參考](/docs/deployment-environment-variables)說明了
其餘的正式環境設定。

### 執行遷移

在第一次造訪之前，針對正式環境資料庫執行 `pnpm migrate:production`。它會建立應用程式所需的
資料表。每次升級之後、新版本上線之前，請再執行一次。每篇代管指南都會說明這個步驟在流程中的
位置。

</Steps>

<Callout tone="info">

在工作區中，每個應用程式預設會繼承根目錄的 `DATABASE_URL`。只有當某個應用程式需要不同的
資料庫時，才需要設定 `<APP_NAME>_DATABASE_URL`。

</Callout>

## 電子郵件傳送是選用功能，但建議設定 {#email-provider}

電子郵件供應商不是電子郵件/密碼驗證的必要條件。沒有供應商時，已部署的應用程式會使用電子郵件/
密碼註冊與登入，略過註冊時的電子郵件驗證，也不會提供魔術連結驗證。

Agent-Native 不包含電子郵件傳送帳戶。如果需要魔術連結、電子郵件驗證、密碼重設、邀請或分享
通知，請在部署前連接 Resend 或 SendGrid。在部署環境設定 `RESEND_API_KEY` 或
`SENDGRID_API_KEY`。SendGrid 也需要 `EMAIL_FROM`。如需了解可用的驗證模式，請參閱
[驗證](/docs/authentication)。

### 自訂框架郵件 {#email-templates}

框架寄出的每封郵件都有預設範本。若要使用自己的設計，請在伺服器外掛中註冊 override。
收件人、寄件人與投遞仍由框架負責。郵件的內容與外觀由你的 override 決定。

```ts
// server/plugins/email-templates.ts
import {
  escapeEmailHtml,
  overrideTransactionalEmail,
} from "@agent-native/core/server";

export default function registerEmailTemplates(): void {
  overrideTransactionalEmail("core.resource-shared", (props) => ({
    subject: `${props.sender.name} shared "${props.resource.title}"`,
    html: `<p>${escapeEmailHtml(props.sender.name)} invited you to
      <a href="${escapeEmailHtml(props.resource.url)}">${escapeEmailHtml(props.resource.title)}</a>
      in ${escapeEmailHtml(props.app.name)}.</p>`,
  }));
}
```

| Email id                         | Props                                                                              |
| -------------------------------- | ---------------------------------------------------------------------------------- |
| `core.verify-signup`             | `email`, `verifyUrl`                                                               |
| `core.reset-password`            | `email`, `resetUrl`                                                                |
| `core.magic-link`                | `email`, `magicLinkUrl`                                                            |
| `core.change-email-confirmation` | `email`, `newEmail`, `confirmationUrl`                                             |
| `core.change-email-verification` | `email`, `verifyUrl`                                                               |
| `core.organization-invite`       | `invitee`, `orgName`, `inviter`, `acceptUrl`                                       |
| `core.builder-credit-limit`      | `subject`, `heading`, `body`, `upgradeLabel`, `upgradeUrl`                         |
| `core.resource-shared`           | `recipientEmail`, `sender`, `resource` (`type`, `title`, `url`), `role`, `message` |

每個 override 也會收到 `app`（`name`、`logoUrl`）。第二個參數是預設的渲染結果，方便重用其主旨或文字。

- Props 是未跳脫的原始值。放入 HTML 字串前，請用 `escapeEmailHtml` 跳脫。
- 回傳帶有 React 元素的 `react`（而非 `html`）即可渲染元件。React 會自動跳脫 props。
- 省略 `subject` 會保留預設主旨。省略 `text` 會從你的 HTML 產生純文字內容。
- 如果 override 擲出錯誤，寄送就會失敗。框架不會退回預設設計。交易郵件預覽會渲染你的
  override，請在那裡檢查。

- [**Node.js**](/docs/node-js) - 執行預設的 Nitro 伺服器預設

- [**Vercel**](/docs/vercel)、[**Netlify**](/docs/netlify) 和 [**Cloudflare Workers**](/docs/cloudflare#cloudflare-workers) - 設定代管目標
- [**SSR 快取**](/docs/ssr-caching) - 設定公開外殼快取
- [**部署環境變數**](/docs/deployment-environment-variables) - 正式環境密鑰、執行階段旗標和工作區繼承
- [**正式環境代理存取權**](/docs/actions-agent-tools) - 控制框架工具和程式碼執行
- [**在正式環境中更新 UI**](/docs/updating-ui-in-production) - 了解代管的視覺化編輯工作流程
