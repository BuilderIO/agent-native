# 嵌入剪輯

把託管的剪輯當作您產品的錄製後端使用。使用者可以從一個 iframe 中錄製，不需要登入剪輯。您的後端會使用一個組織服務權杖來建立一個短期有效的接收網址，而剪輯會把產生的錄音儲存在該組織設定好的儲存空間中。

本指南涵蓋託管的嵌入流程。它不需要進行錄製的人擁有剪輯帳戶。

## 整合如何運作

這個整合有四個部分：

1. 組織管理員在剪輯中設定影片儲存。
2. 您的後端會儲存組織服務權杖，並請求一個接收網址。
3. 您的產品只會把這個短期有效的接收網址傳給一個 iframe。
4. 剪輯會把錄音上傳到該組織的儲存空間，並向您的產品發送一則完成訊息。

組織服務權杖絕不應該出現在 iframe 中。它與發行它的組織綁定，所以權杖本身就提供了組織的脈絡。組織 ID 對您自己的租戶對應很有用，但它本身並不是一個憑證。

## 設定剪輯組織

建立或選擇應該擁有這些錄音的剪輯組織。組織管理員接著透過剪輯的入門流程或剪輯設定，設定影片儲存：

- **Builder.io Connect** 提供託管的影片儲存和 AI 額度。
- **S3 相容儲存**使用組織設定好的端點、儲存桶、存取金鑰、密鑰，以及可選的區域或公開基底網址。Cloudflare R2 和 DigitalOcean Spaces 使用相同的儲存設定，只是名稱各自對應提供者。

儲存設定的範圍是整個組織。每一段透過該組織服務權杖建立的錄音，都會使用已經連接到該組織的儲存空間。嵌入方的產品不需要 Builder.io 或 S3 的憑證。

影片會儲存在設定好的物件儲存中。剪輯會把錄音的中繼資料、擁有權、處理狀態，以及儲存參考，儲存在自己的資料庫中。

## 建立組織服務權杖

以組織擁有者或管理員的身分執行既有的 `connect` 指令。這個指令會開啟瀏覽器登入畫面，為目前啟用的組織建立一個具名的服務權杖，並只會印出這個權杖一次：

```bash
npx @agent-native/core@latest connect https://clips.agent-native.com \
  --service-token support-desk --ttl-days 365
```

把印出的權杖直接複製到您產品的伺服器端密鑰管理系統中。這個權杖歸屬於組織，所以即使發行它的人離開組織，或撤銷了自己的個人權杖，它仍會繼續運作。它絕不會被寫入本機用戶端設定。請為每個整合使用不同的服務名稱，這樣撤銷一個呼叫者時，才不會影響到另一個。

`--ttl-days` 接受 1 到 365 天，預設為 365。這個權杖的行為就像一個組織成員。它無法建立或撤銷其他服務權杖，也無法變更組織設定。

## 請求一個接收網址

您受信任的後端會呼叫剪輯的接收 action。託管帳戶請使用託管的剪輯來源，自行架設時則使用您自己的剪輯來源。

```ts
const clipsBaseUrl = "https://clips.agent-native.com";
const clipsServiceToken = process.env.CLIPS_SERVICE_TOKEN;

const response = await fetch(
  `${clipsBaseUrl}/_agent-native/actions/create-recording-intake-link`,
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${clipsServiceToken}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      ttlSeconds: 3600,
    }),
  },
);

if (!response.ok) {
  throw new Error("Could not create a Clips intake URL");
}

const intake = await response.json();
// intake.url is safe to pass to the recording iframe.
```

服務權杖已簽署的組織脈絡，決定了這個接收流程歸屬於哪個組織。這個 action 的回應本身就是位於最上層的接收物件。預設的接收生命週期是一小時，最長是四小時。每個接收網址只能建立一段錄音。

請不要從匿名瀏覽器發出這個請求。請不要把服務權杖、儲存憑證，或長期有效的剪輯登入狀態回傳給瀏覽器。

## 嵌入錄製工具

把回傳的網址直接傳給一個 iframe。這個網址包含一個範圍狹窄、已簽署的能力，讓訪客可以建立並上傳一段私人錄音。

```tsx
<iframe
  data-clips-recorder
  src={intake.url}
  allow="display-capture; camera; microphone"
  title="Report a problem"
  style={{ width: 420, height: 560, border: 0 }}
/>
```

在渲染之前，您可以在接收網址中加入一些小型、非敏感的脈絡值，例如專案 ID、頁面標題、應用程式版本，或環境。請不要把密碼、API 金鑰、客戶紀錄，或其他敏感值放進網址中。網址可能會出現在瀏覽器歷史紀錄、日誌、分析工具，以及 referrer 中。

當訪客開始捕捉時，錄製工具會開啟一個最上層的彈出視窗。瀏覽器的媒體權限和螢幕捕捉，都需要在最上層瀏覽情境中的使用者手勢才能觸發。測試期間請允許主機產品開啟彈出視窗。

## 接收完成訊息

當錄音儲存完成後，完成頁面會把 `agent-native.clips.bug-report.submitted` 傳送給嵌入方的父視窗。請在使用這個負載之前，先驗證剪輯的來源和訊息來源。

```ts
const clipsOrigin = new URL(clipsBaseUrl).origin;
const recorderFrame = document.querySelector<HTMLIFrameElement>(
  "iframe[data-clips-recorder]",
);

window.addEventListener("message", (event) => {
  if (event.origin !== clipsOrigin) return;
  if (recorderFrame && event.source !== recorderFrame.contentWindow) return;
  if (event.data?.type !== "agent-native.clips.bug-report.submitted") return;

  const { recordingId, recordingUrl, embedUrl, agentAccessStatus } = event.data;
  if (!recordingId) return;

  // Send recordingId to your trusted backend and attach it to the support case.
  console.log({ recordingId, recordingUrl, embedUrl, agentAccessStatus });
});
```

完成負載可能包含 `recordingId`、`recordingUrl`、`embedUrl`、`agentShareUrl`、`agentContextUrl`、`agentAccessExpiresAt`，以及 `agentAccessStatus`。請把 `recordingId` 當作這個支援案例的持久識別碼。在您已驗證的後端建立另一個範圍受限的代理連結之前，一個僅寫入的接收流程可能會回報 `agentAccessStatus: "unavailable"`。這個狀態並不代表這段錄音是空的。

這則瀏覽器訊息只是一個通知，不是一個授權許可。當您的後端需要讀取或分享已完成的錄音時，應該使用它自己與剪輯之間已驗證的連線。

## 錄音儲存在哪裡

透過服務權杖建立的錄音，歸屬於與該權杖關聯的組織。剪輯會透過它一般的上傳和完成處理管線來傳送媒體檔案。這個管線會使用該組織設定好的 Builder.io 或 S3 相容儲存空間。

這個 iframe 不會直接上傳到您的儲存桶，也不需要儲存桶的憑證。您的產品會從剪輯那裡收到錄音識別碼和範圍受限的網址。請只在您自己的支援系統中儲存您需要的識別碼或網址。

## 自行架設剪輯

自行架設使用相同的組織契約：

1. 使用一個持久性資料庫和一個公開的 `BETTER_AUTH_URL` 部署剪輯。
2. 建立將會擁有嵌入式錄音的組織。
3. 在該組織中一次性設定 Builder.io Connect 或 S3 相容儲存。
4. 針對自行架設的剪輯來源執行 `connect`，建立該組織的服務權杖。
5. 把這個權杖以部署或密鑰管理系統的值，提供給您的嵌入後端一次。
6. 當您的後端請求接收網址時，使用自行架設的剪輯來源。

```bash
npx @agent-native/core@latest connect https://clips.example.com \
  --service-token support-desk --ttl-days 365
```

例如，嵌入方的後端可以把這些值保留在它的伺服器端設定中：

```text
CLIPS_BASE_URL=https://clips.example.com
CLIPS_SERVICE_TOKEN=<secret>
```

這個權杖只會提供給後端一次。每位訪客仍然會收到一個新的短期有效接收網址。iframe 中不會加入任何權杖或儲存憑證，而且在權杖輪換時，也不需要變更 iframe 的程式碼。

一般的自行架設需求，請參閱 [部署](/docs/deployment)。

## 安全檢查清單

- 把組織服務權杖保存在伺服器端密鑰管理系統中。
- 主機產品和剪輯都要使用 HTTPS。
- 把每個接收網址都當作一個持有者憑證。不要讓它出現在日誌和 referrer 資料中。
- 使用能滿足需求的最短接收生命週期。
- 在完成監聽器中同時驗證 `event.origin` 和 `event.source`。
- 絕不要把剪輯擁有者範圍的上傳端點直接暴露給匿名使用者。
- 輪換服務權杖的方式是：用 `connect` 建立一個替代權杖，部署它，驗證流程，然後用 `revoke-org-service-token` 撤銷舊的權杖。
- 把組織 ID 和接收 ID 留在受信任的後端，而不是信任訪客提供的值。

## 疑難排解

**接收請求未經授權。** 請確認後端使用的是一個尚未過期、尚未撤銷，且是為目標剪輯來源所發行的服務權杖。這個權杖的組織綁定關係，決定了接收流程會在哪裡建立。

**iframe 開啟了一個登入頁面。** 請確認 iframe 使用的是 `create-recording-intake-link` 回傳的短期有效網址。請不要為匿名訪客嵌入 `/record` 或一般的剪輯媒體庫網址。

**錄音沒有完成。** 請檢查該組織是否已設定 Builder.io 或 S3 相容儲存。匿名訪客無法從 iframe 中設定儲存空間。

**完成結果中沒有代理連結。** 對於僅寫入的接收流程來說，這是預期中的情況。如果您的支援工作流程需要代理可讀的逐字稿和畫格資料，請讓您已驗證的後端另外建立一個範圍受限的代理連結。
