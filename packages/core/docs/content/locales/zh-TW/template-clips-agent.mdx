# 與 Agent 對話

剪輯中的每一項功能，代理都能透過 UI 所使用的相同 actions 取得，所以只要是您能點選的操作，也都可以直接用簡單的文字提出請求。本頁涵蓋代理如何看到您的畫面、依任務分類的實用提示，以及它在哪些情況下會取用較不常見的 actions。總覽請參閱 [剪輯](/docs/template-clips)。

## 代理如何看到您的畫面

當您開啟一段錄音時，代理清楚知道是哪一段，甚至細到您正在看的側邊面板（留言、逐字稿，或洞察），以及您暫停的時間點。這就是為什麼「在這裡加個留言」或「把這段修剪到精華部分」能夠正確解析，不需要您說出錄音的名稱或時間。

如果您正在瀏覽媒體庫，代理同樣知道您在那裡看的是什麼：目前的資料夾、您的搜尋內容，以及如果您處於選取模式，您選取了哪些錄音。

有一件事代理無法代您完成：開始錄製。瀏覽器只有在有人點選了某個東西之後，才會授予麥克風和螢幕的存取權，所以「錄下我的螢幕」會直接把您帶到錄製工具，而不是在背景無形地開始捕捉。

## 依任務分類的實用提示

以下每個提示都會對您真實的媒體庫執行一個真正的 action，就是 UI 讀寫的同一個媒體庫。這裡有一個實際範例：

<Comparison>

### :blue: 您的提問

「幫這段剪輯寫個摘要，用於產品更新。」

### :green: 發生的事

這是一個唯讀問題。代理會讀取您目前開啟的錄音的逐字稿，然後直接在聊天中回答。畫面上什麼都不會改變，因為沒有建立或移動任何東西。

</Comparison>

<Cards columns={2}>

### 捕捉和匯入

- **「錄下我的螢幕。」** 代理會為您開啟錄製工具。實際開始捕捉仍然需要您親自點選，因為瀏覽器要求如此。
- **「匯入這個 Loom 連結。」** 貼上網址，匯入完成後這段錄音就會加入您的媒體庫。

### 清理和整理

- **「重新產生標題和摘要。」** 代理會根據目前的逐字稿重寫這兩者。
- **「加上章節。這段很長。」** 章節標記會立即出現在時間軸上。
- **「修正 1:42 處轉錄錯誤的單字。」** 代理會就地修正逐字稿。
- **「找到我們討論推出計畫的那段剪輯。」** 這是一個唯讀問題。代理會搜尋您媒體庫中的每一份逐字稿，並在聊天中回答。

### 編輯

_當您開啟一段錄音時，「這個」會解析成您正在看的那段剪輯。_

- **「修剪掉前 10 秒。」** 剪切會立即出現在時間軸上，在您匯出之前不會重新編碼任何東西。
- **「移除嗯和啊，然後重新拼接。」** 代理會在逐字稿中找出填充詞，並套用同一種修剪。
- **「按這個順序把這三段剪輯合併成一段。」** 代理會把它們拼接在一起，同時保留逐字稿和章節。

### 分享和檢視

- **「誰在看這段剪輯？」** 這是一個唯讀問題。代理會回答觀看次數，區分為人類和讀取逐字稿的其他代理。
- **「把這個分享給設計團隊，僅供檢視。」** 這段錄音的可見性和存取權會立即更新。

</Cards>

## 較不常見的 actions

不是每一項剪輯的能力都是代理事先預載的第一線 action。Rewind 的螢幕記憶 actions 就是一個好例子，因為它們只有在您開啟 Rewind 之後才有意義。當一個請求需要用到其中之一時，代理會先依名稱搜尋正確的工具，再呼叫它，就像您可能會搜尋命令面板，而不是把每個快捷鍵都背下來一樣。您通常會在超出日常媒體庫和編輯任務範圍的請求上，注意到這種短暫的停頓。
