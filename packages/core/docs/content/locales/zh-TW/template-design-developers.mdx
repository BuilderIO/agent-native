# 開發者指南

本頁面適用於任何要自訂 Design 範本，或直接在它之上建置的人：快速入門、每個 action、資料模型、一個逐步解析的 action、路由介面，以及如何新增內容。這個應用程式的功能說明請參閱[Design](/docs/template-design)。

## 快速入門

<Steps>

### 建立應用程式

```bash
npx @agent-native/core@latest create my-design --standalone --template design
cd my-design
pnpm install
```

這需要先安裝 [Node.js](https://nodejs.org) 22.22 或更新版本，以及
[pnpm](https://pnpm.io)。如果您還沒有安裝，或還沒有設定 LLM 連線
（Builder.io、Anthropic/OpenAI 金鑰，或本機 Ollama），請參閱[開始使
用](/docs/getting-started)。若想建立一個讓 Design 與其他應用程式並存的工
作區，請改為執行 `npx @agent-native/core@latest create my-platform`，
並在設定過程中選擇 Design。

### 啟動開發伺服器

```bash
pnpm dev
```

應用程式會在 `http://localhost:8099` 開啟，這是 Design 的預設開發連接
埠。Design 在沒有任何外部連線的情況下也能完全正常運作。只有在您嘗試 Figma
匯入或完整應用程式建置，卻還沒設定好之前，才會遇到連線提示。

</Steps>

## Action 清單

每一個 Design 專屬的操作，都是 `templates/design/actions/` 中的一個
TypeScript 檔案，會自動掛載到 `POST /_agent-native/actions/:name`，也
可以用 `pnpm action <name>` 從 CLI 執行。

### 設計

| Action                    | 功能說明                                         |
| ------------------------- | ------------------------------------------------ |
| `create-design`           | 建立空的設計外殼                                 |
| `generate-design`         | 寫入產生的 HTML/JSX 檔案內容                     |
| `edit-design`             | 對既有檔案進行精準的搜尋／取代編輯               |
| `update-design`           | 更新一個設計的中繼資料，例如標題或連結的設計系統 |
| `get-design`              | 依 id 讀取一個設計                               |
| `list-designs`            | 列出可存取的設計                                 |
| `duplicate-design`        | 複製一個設計及其檔案                             |
| `delete-design`           | 刪除一個設計                                     |
| `apply-tweaks`            | 持久儲存即時的 tweak 控制項數值                  |
| `present-design-variants` | 把幾個方向儲存成畫面，並顯示並排選擇器           |
| `show-design-questions`   | 為一個模糊的提示顯示釐清問題覆蓋層               |

## 資料模型

所有資料透過 Drizzle ORM 儲存在 SQL 中。架構：`templates/design/server/db/schema.ts`。設計和設計系統都帶有標準的 `ownableColumns`，以及一個對應的框架共用表，因此它們可以套入每使用者／每組織的共用模型。

下表涵蓋核心的可擁有資源：設計、檔案、範本、版本，以及設計系統。

| 資料表                                   | 它包含什麼                                                                                                                               |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `designs`                                | 一個設計專案 — `title`、`description`、`project_type`（`prototype` / `other`）、`data` JSON blob，以及一個選填的 `design_system_id` 連結 |
| `design_files`                           | 屬於某個設計的個別檔案（`filename`、`content`、預設為 `html` 的 `file_type`）                                                            |
| `design_templates`                       | 可重複使用的範本中繼資料、尺寸、預設值、來源設計參照，以及鎖定圖層數量                                                                   |
| `design_template_files`                  | 當使用者從一個範本開始時，複製到一個普通可編輯設計中的快照範本檔案                                                                       |
| `design_template_shares`                 | 供私人、組織、明確共用，以及公開範本探索使用的框架共用表                                                                                 |
| `design_versions`                        | 一個設計在某個時間點的 `snapshot`，附有一個選填的 `label`，用於歷史紀錄和回滾                                                            |
| `design_systems`                         | 可重複使用的品牌代幣 — `data`（顏色/版式/間距）、`assets`、`custom_instructions`，以及一個 `is_default` 旗標                             |
| `design_shares` / `design_system_shares` | 把主體（使用者或組織）對應到角色（檢視者、編輯者、管理員）的框架共用表                                                                   |

/>

一個設計專案在有內容之前只是一個外殼：`create-design` 會建立一個空行
（`data: "{}"`），然後 `generate-design` 會寫入真正獨立的 HTML/JSX 檔
案。產生的成品、可編輯的來源，以及每一次匯出，全部都來自同一份 HTML，
因此沒有一種獨立的「AI 模型」格式需要翻譯。一個已連結的設計系統會提供
代幣和 `custom_instructions`，代理會在每一次產生時遵循它們。

另外七個資料表支援本頁其他部分涵蓋的功能，而不是核心資源模型：
`design_localhost_connections` 和 `design_localhost_write_grants` 支援
[本機應用程式匯入](/docs/template-design-features#import)，
`component_index` 支援[Design 分頁的元件區塊](/docs/template-design-features#design-tab)，
`motion_timeline` 支援每個元素可編輯的動效時間軸（編輯器裡的動效
dock），`design_state` 保存一個設計的具名替代狀態、靜態測試資料，以及
真實應用程式的擷取畫面，`design_fusion_edits` 支援上方[完整應用程式建
置](#full-app-building)所描述的 fusion 編輯佇列，`design_review_snapshot`
則快取上方[品質](#quality)所描述、`get-design-review` 背後的無障礙檢查
結果和視覺差異。

持久化的審閱留言和討論串（`get-review-feedback`、
`resolve-review-thread`，以及其他相關 action）完全不是一個 Design 專屬的
資料表：它們是來自 `@agent-native/core/review` 的共用框架審閱系統
（`agent_review_comments` / `agent_review_statuses`），以任何應用程式都
能掛接的相同方式，範圍限定在一個設計上。使用者面的行為請參閱[留言分
頁](/docs/template-design-features#comments-tab)。

## 逐步解析一個 action

`save-design-as-template` 展示了值得在任何 action 中重複使用的模式：在
做任何工作之前先拒絕一個不支援的輸入形狀、防止儲存空內容、只重新對應

## 編輯器模型

Design 對多畫面工作採用總覽優先的方式。產生或進行大範圍更新後，編輯器會
開啟畫面總覽：一個無限畫布，其中每個畫面都是可以選取、移動、調整大
小、拖放，或複製的靜態框架。當某個畫面需要聚焦捲動或原型互動時，請使
用該框架的完整檢視按鈕。

單畫面模式用於捲動、與原型行為互動，以及編輯一個已渲染檔案內的
DOM/程式碼圖層。圖層面板也反映這種分工：畫面是頂層框架，作用中畫面
下方嵌套著 DOM/程式碼圖層。

每個畫面都是同一份文件在不同寬度下的渲染結果，而不是每個中斷點各自的
獨立副本：一個基準（最寬）框架會向下串聯，在一個較窄的作用中中斷點所
做的編輯，會以寬度範圍的覆寫形式疊加在它上面並保留下來。

## 編輯器擴充功能

編輯器在 **Tweaks** 之後包含一個 **擴充功能**檢查器分頁。它就像一個 Design
專屬的外掛通道：使用者可以點擊 **+ 擴充功能**，讓代理建立一個擴充功
能，或安裝一個宣告 `design.editor.inspector` 插槽的擴充功能，使用框架
的 `create-extension`、`add-extension-slot-target`，和 `install-extension`
actions，而不是一個 Design 專屬的 action。

Design 的擴充功能會透過標準的擴充功能沙盒，內嵌渲染在畫板旁邊。host 會透
過 `window.slotContext` 和 `window.onSlotContext(...)` 更新，傳入目前的
`designId`、作用中的檔案、畫面清單、已選取的畫面 id、已選取元素的中繼
資料、檢視模式、縮放比例、作用中的工具，以及 tweak 值。這讓擴充功能可
以顯示目前選取項目的資訊、提供樣式控制項，或圍繞著開啟中的設計，建立
精簡的工作流程。

對於確定性的工作，擴充功能可以透過擴充功能橋接呼叫應用程式的
actions。對於由 AI 驅動的變更，讓擴充功能呼叫
`agentNative.chat.send(...)`，並附上選取元素的 selector/source id 和要
求的變更。代理應該先呼叫 `view-screen`，然後對元素的樣式、class、文
字，或移動變更使用 `apply-visual-edit`，或對畫板放置變更，使用帶有
`canvasFrames` 的 `update-design` / `generate-design`。sandbox、持久狀
態，以及橋接 API，請參閱[擴充功能](/docs/extensions#capabilities)。

## 自訂它

Design 是一個完整、可複製的範本。一些實際的擴充想法：

- 「新增一個使用我們代幣和範例元件的可重複使用電子商務設計系統。」
- 「新增一個匯出步驟，把 ZIP 上傳到我們的內部審核系統。」
- 「讓我貼上既有的到達頁面 HTML，並向代理要求三個更強的版本。」
- 「為產品頁面、儀表板和入門畫面簡報，新增一個已儲存的提示庫。」
- 「新增一個自訂的 PDF 匯出預設，供利害關係人審核。」

代理會視需要編輯路由、元件、actions，以及 SQL 支援的模型。完整的複
製、自訂、部署流程請參閱[範本](/docs/cloneable-saas)，如果這是您第一
個 Agent-Native 範本，請參閱[開始使用](/docs/getting-started)。
