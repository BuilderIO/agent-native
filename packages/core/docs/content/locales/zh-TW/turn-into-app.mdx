# 轉換為應用程式

`/turn-into-app` 是一個 skill，可將你已驗證的工作流程轉換為 Agent-Native 應用程式。來源可以是對話、skill、試算表，或 Claude 或 ChatGPT 專案。應用程式會在你的業務情境中開啟，填入與來源結構一致的範例資料，應用程式內的代理在其操作物件的控制項背後運作。步驟列下方的一個表單，正是這個 skill 想要避免的結果。

## 安裝 {#install}

```bash
npx @agent-native/skills@latest add --skill turn-into-app
```

同一個 skill 也隨核心 CLI 一起提供：

```bash
npx @agent-native/core@latest skills add turn-into-app
```

在已有 Agent-Native CLI 的專案中，`agent-native skills add turn-into-app` 的效果相同。有關 skills 的安裝與載入方式，請參閱 [Skills 指南](/docs/skills-guide)。

## 呼叫方式 {#invoke}

| 指令                               | 來源                                       |
| ---------------------------------- | ------------------------------------------ |
| `/turn-into-app`                   | 可見的專案脈絡，否則為目前對話             |
| `/turn-into-app /some-skill`       | 指定的 skill，即使在對話開始時也會立即打包 |
| `/turn-into-app ./forecast.xlsx`   | 試算表，轉換為工作台                       |
| `/turn-into-app ./project-export/` | Claude 或 ChatGPT 專案匯出                 |

不帶參數時，skill 會建構最近一次成功且可重複的工作，並為其命名。具體的範例，例如某個帳戶或某筆交易，只是該工作的佐證，而不是它的資料結構。如果無法確定任何工作，它會說明缺少什麼，而不是提出「你想要什麼應用程式？」這類籠統的問題。

## 執行位置 {#hosts}

| 主機                                          | 發生的事情                                                                         |
| --------------------------------------------- | ---------------------------------------------------------------------------------- |
| Claude Code、Codex、Cursor 及其他本機編碼代理 | 在你的檢出目錄中建構、執行並審查應用程式。                                         |
| 網頁版 Claude 或 ChatGPT                      | 撰寫一份範圍明確的簡報，並透過 Dispatch 連接器交給 Builder。它自己不執行任何內容。 |

當主機具有真實的工作目錄、終端機和工作區時，才算本機主機。擁有 Builder 或 Dispatch 連接器並不會讓主機成為瀏覽器主機。

在瀏覽器主機上，skill 需要 Agent-Native Dispatch MCP 連接器（`https://dispatch.agent-native.com/mcp`，OAuth），並呼叫其 `start-workspace-app-creation` 動作。主機無法執行或檢查應用程式，因此在 Dispatch 回傳的分支建構完成之前，報告會維持待處理或未驗證狀態。skill 只會回報 Dispatch 實際回傳的內容，絕不捏造分支 URL。對於 ChatGPT 專案，或任何僅公開 MCP 的主機，請將 skill 指示放入專案指示或知識檔案中。

## 來源 {#sources}

- **對話。** 最近一次具體且可重複的工作就是產品。
- **Skills。** skill 的步驟、需要人工決策的節點和唯讀規則會成為應用程式。如果 skill 保留了計畫檔案，這些檔案將透過 Local File Mode 繼續作為事實來源，且應用程式僅限本機。
- **試算表。** 先盤點每個工作表。由結構決定哪些儲存格是輸入、哪些是輸出；顏色只是一個較弱的提示。活頁簿絕不會被複製到提示詞、SQL 或應用程式狀態中。只有可透過已驗證的 Sheets 或 Drive 連線讀取時，Google Sheets 連結才算來源；否則 skill 會要求提供匯出檔。
- **Claude 和 ChatGPT 專案。** 可見的指示、知識檔案以及提供的過往執行紀錄是來源。連接器不會讀取隱藏的專案對話、私人 URL 或憑證，也沒有分享連結匯入功能。當脈絡不可見時，請附上匯出檔。

## 你將獲得什麼 {#what-you-get}

- **根據來源選定的形態。** skill 會從 13 種原型中選擇一種，例如分流佇列、管線看板、即時工作台、排程網格、審查 diff 或監控面板。原型是使用者檢視的物件，而不是使用者遵循的流程，因此來源中的步驟會變成物件上的狀態（草稿、已檢查、已核准），而不是步進器或精靈。
- **命名的視覺方向。** 六種方向之一（`ledger`、`control-room`、`paper-desk`、`studio-canvas`、`tidepool`、`signal-board`），附有淺色與深色 token，依據原型和來源所屬領域選定。既有的品牌或你明確指定的方向優先。
- **已填入內容的首屏。** `/` 會進入一個命名的領域路由，其中包含標示為範例、與來源結構一致的合成範例資料。除非來源本身就是表單形態，否則空狀態、主視覺、流程的第一步或表單都屬於缺陷。
- **物件上的代理時刻。** 每個帶有 AI 標籤的控制項都會將一則範圍明確的提示詞交給代理側邊欄。物件會立即顯示工作狀態，結果會帶著接受、編輯和重試按鈕回到該物件上。後續對話保持在同一討論串中。
- **真正的 Agent-Native 應用程式。** 確定性的工作是 UI 和代理都會呼叫的 `defineAction` 檔案。應用程式使用標準的 Use Builder.io 或 Custom keys 設定，將目前檢視和選取項目寫入應用程式狀態，並附有 `AGENTS.md`，向應用程式內代理介紹這個新應用程式。

skill 會將來源簡報儲存為 `docs/brief.md`，並將介面設計附加到 `DESIGN.md`。

## 一次執行的流程 {#how-it-works}

1. **簡報。** 讀取完整來源，並撰寫一份簡短的簡報：工作內容、最多三個代理時刻、不變條件、資料風險、事實來源和假設。
2. **設計。** 決定原型、方向、外殼、首屏視埠與範例資料以及代理時刻，並將簡報作為檢查點發布一次。無需等待，直接繼續。
3. **腳手架。** 使用 chat 範本建立真正的應用程式，且絕不覆寫現有應用程式。

   ```bash
   npx --yes @agent-native/core@latest create <slug> --standalone --template chat
   ```

   在現有的 Agent-Native 工作區內，則改為從工作區根目錄執行 `pnpm exec agent-native add-app <slug> --template chat`。

4. **建構。** 同時建構動作、領域介面、範例資料、代理時刻和代理指示。
5. **審查。** 執行應用程式並審查螢幕截圖。見下文。
6. **驗證。** 執行 `pnpm typecheck`、`pnpm agent-native:doctor` 和 `pnpm build`，然後撰寫最終報告。

skill 的目標耗時約為 45 分鐘。如果審查開始時已過了 35 分鐘，則只執行一輪，並列出未滿足的標準。

## 螢幕截圖審查迴圈 {#review-loop}

交付之前，skill 會啟動開發伺服器，在桌面和手機尺寸下的淺色與深色模式中對 `/` 截圖，並在點擊後對主要代理控制項截圖。它依照包含 12 項的評分標準為截圖打分，涵蓋首屏視埠衝擊力、領域契合度、層次結構、介面裝飾克制度、範例資料、字體排印、色彩、細節打磨、代理與 UI 的整體配合、390px 版面、深色模式和無障礙。

無論平均分數多少，有些問題都會導致審查失敗：步進器或精靈式外殼、`/` 沒有開啟到領域路由、首屏為空或僅有表單、腳手架預設 token、文字被裁切、原始 markdown、390px 下出現橫向捲動，或主控台錯誤。skill 會一次性修復所有問題，重設點擊所改變的內容，然後重新截圖。預設進行兩輪，只有在第二輪仍未達標且時間允許時才進行第三輪。達標線是平均分數 4.0 或更高，沒有任何標準低於 3，且沒有自動失敗項。

螢幕截圖儲存在應用程式的 `.tmp/ui-review/out/` 中，最終報告會列出它們的路徑和分數。UI 中呈現的結果只有在連接了 AI 供應商時才能實際驗證；未連接時，報告會說明該結果未經驗證。

## 執行與部署 {#run-deploy}

為了進行本機審查，skill 會在應用程式被忽略的 `.env` 中設定 `AUTH_DISABLED=1`，因為全新的截圖瀏覽器並未登入。這僅用於迴路位址的開發。它會在最終的 `pnpm build` 之前被移除，絕不能提交或部署。沒有它時，開啟應用程式會顯示一張 "Continue as local dev" 卡片。

若要自行執行應用程式：

```bash
pnpm dev
```

若要在本機使用你自己的模型供應商，請在同一個 `.env` 中放入諸如 `ANTHROPIC_API_KEY` 之類的金鑰。否則，代理側邊欄會顯示共用的 Use Builder.io 或 Custom keys 設定。

只有在你要求部署或供應商已設定時，skill 才會部署。一次正常的本機建構仍會印出一個 "production configuration errors" 區塊，結束碼為 0。這就是部署清單：穩定的 `BETTER_AUTH_SECRET` 和持久的 `DATABASE_URL`，以及工作區內應用程式所需的 `A2A_SECRET`。skill 會將這些回報為待辦步驟，並且不會建立預留值。請參閱[部署應用程式](/docs/deploy-an-app)和[部署工作區](/docs/workspace-deployment)。

最終報告會分別標註各項證據：本機執行中、本機已驗證、可建構、已部署和線上已驗證是不同的狀態，報告絕不會讓其中一個取代另一個。

## 已知限制 {#limits}

- **開發伺服器執行時編輯 `.env`。** 修改 `.env` 後原地重新載入會在本機資料庫鎖上陷入迴圈並回傳 500。請停止伺服器，編輯 `.env`，然後重新啟動。
- **含糊不清的試算表。** 如果在有限的審查之後，候選工作流程或輸入與輸出的對應仍然嚴重含糊，skill 會提出一個簡潔的問題並附上它建議的解讀。在無頭執行中，它會印出該問題，在簡報中記錄假設，並繼續建構。
- **瀏覽器主機上的試算表。** 無法附加活頁簿；主機會以文字形式傳遞有限的 CSV 轉譯結果或刻意公開的 URL，並且交接內容會說明遺漏了什麼。 指向私人試算表的連結不是來源；技能會要求經過驗證的 Sheets 或 Drive 連線，或要求匯出檔案，絕不會使用公開匯出 URL 來繞過存取控制。
- **儲存格顏色。** 文字預覽無法證明顏色，因此在本機主機上，skill 會同時讀取公式和快取值，並將顏色視為較弱的提示。
- **Local File Mode 應用程式。** 事實來源是主機檔案的應用程式僅限本機，不會被部署。
- **瀏覽器主機交接。** 在 Dispatch 回傳已建構的分支之前，結果處於未驗證狀態。skill 無法在那裡執行應用程式或對其截圖。
