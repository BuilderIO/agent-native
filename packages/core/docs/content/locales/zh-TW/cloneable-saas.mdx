# 應用程式

想要發布您自己的人工智慧分析工具嗎？郵件用戶端？表格生成器？選取一個範例應用程式，您只需幾分鐘即可獲得一個可執行的 SaaS — 代理、資料庫、驗證和部署管道已連線完畢。

大多數入門範本都會為您提供一個空白的腳手架和一個很長的 TODO 清單。Agent-Native 翻轉了這一點。每個範例應用程式都是**完整的 SaaS 級產品** - 在第一天就已經可以執行，已經可以發貨，並且完全由您來定制、品牌化和部署。將它們視為可克隆的 SaaS，而不是入門工具包：您正在分叉成品，而不是盯著樣板檔案。

## 範例應用程式 {#catalog}

每一個都是您今天可以使用的真實應用程式，以及您自己版本的啟動板。

| 應用程式                                  | 它是什麼                                                                                        |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------- |
| [**Chat**](/docs/template-chat)           | 最小的聊天優先應用程式，具有持久對話串、actions、驗證以及通往自訂 UI 或您自己的後端的幹淨路徑。 |
| [**Mail**](/docs/template-mail)           | Agent-Native 超人。收件箱、標籤、人工智慧分類、鍵盤優先、透過代理起草和傳送。                   |
| [**Calendar**](/docs/template-calendar)   | 本機代理 Google Calendar。活動、同步、公開預訂連結、代理驅動的調度。                            |
| [**Content**](/docs/template-content)     | MDX 的開放原始碼黑曜石。本機 Markdown/MDX、Tiptap 編輯器、Notion 同步、即時多使用者協作。       |
| [**Brain**](/docs/template-brain)         | 幹淨的公司聊天由引用的機構記憶、核准的來源、審查門和引文支援。                                  |
| [**Assets**](/docs/template-assets)       | 用於品牌庫、上傳、參考和品牌圖片/影片產生的數位資產管理器。                                     |
| [**Slides**](/docs/template-slides)       | Agent-Native Google 幻燈片。基於 React 的簡報由代理直接生成和編輯。                             |
| [**Analytics**](/docs/template-analytics) | Agent-Native 振幅/混合面板。連線資料來源、提示圖表、固定到儀表板。                              |
| [**Clips**](/docs/template-clips)         | 非同步螢幕+攝影機錄製，包含轉錄、章節和 AI 摘要。                                               |
| [**Design**](/docs/template-design)       | Agent 原生 HTML 原型工作室，用於互動式 Alpine/Tailwind 設計。                                   |
| [**Forms**](/docs/template-forms)         | Agent-Native Typeform。建置、共用、收集提交內容並將其路由到 Slack、表格、webhooks 或 Discord。  |
| [**Plan**](/docs/template-plan)           | 帶有圖表、線框圖和註解的視覺計畫和 PR 概述。                                                    |
| [**Dispatch**](/docs/template-dispatch)   | 工作區控制平面：共用秘密、可重用整合、Slack/Telegram、計畫作業。                                |

不需要域應用程式？當您想要一個使用者可以立即交談，並可繼續擴展 actions、原生結果和頁面的基本應用程式時，請使用 [Chat](/docs/template-chat)。只有在暫時不需要瀏覽器 UI 的自動化工作流程中，才使用 [Automation-First Apps](/docs/pure-agent-apps)。

檢視 [Apps](/apps) 下的完整目錄，或直接跳到其中一個 - 例如，如果您想要一款工作區風格的應用，[Dispatch](/docs/template-dispatch) 是一個很好的起點。

## 社群模板 {#community-templates}

CLI 選擇器中按名稱提供的模板是**第一方模板**：Agent Native 會隨框架一起
維護、測試、記錄和發佈它們。**社群模板**由其儲存庫擁有者負責維護和版本
管理。它可以使用相同的框架能力，但進入社群清單並不表示 Agent Native 對其
背書或承諾提供支援。

執行 `create`，選擇**社群模板**，然後貼上公開 GitHub 儲存庫的簡單 URL：

```bash
https://github.com/owner/repo
```

如果儲存庫根目錄是單一 Agent Native 應用程式，CLI 會直接安裝，不再顯示
其他選擇器。如果儲存庫是 Agent Native 工作區，CLI 會發現 `apps/*` 的有效
直接子項，排除 `dispatch`，並詢問要安裝哪個應用程式。

非空的 `agent-native.workspaceCore` 標記會使儲存庫被視為工作區，即使根
package 也相依於 `@agent-native/core`；格式錯誤的標記會被拒絕。

在指令碼中，將相同的簡單 URL 傳給 `--template`，或使用較短的
`community:` 形式。如果需要可重現的起點，請在 `#` 後固定 branch、tag
或 commit。如果未提供 ref，CLI 會先嘗試 `main`，再嘗試 `master`：

```bash
npx @agent-native/core@latest create my-app --template community:owner/repo#v1.2.0
npx @agent-native/core@latest create my-app --template https://github.com/owner/repo#v1.2.0
```

若要以非互動方式選擇工作區儲存庫中的來源應用程式，請使用
`?app=<app-name>`。選擇器位於選用的 `#ref` 之前。請為整個值加上引號，
因為 zsh 等 shell 會將 `?` 視為 glob：

```bash
npx @agent-native/core@latest create my-app --template 'community:owner/repo?app=analytics#v1.2.0'
npx @agent-native/core@latest create my-app --template 'https://github.com/owner/repo?app=analytics#v1.2.0'
```

在工作區外，`create` 會將所選來源應用程式建立為獨立應用程式。若要將其
新增到現有工作區，請明確傳入社群儲存庫，因為 `add-app` 選擇器只列出
第一方模板。省略 `?app` 可從來源工作區進行互動式選擇；包含它則可用於
指令碼化安裝：

```bash
npx @agent-native/core@latest add-app my-app --template community:owner/repo#v1.2.0
npx @agent-native/core@latest add-app my-app --template 'community:owner/repo?app=analytics#v1.2.0'
```

只接受公開 GitHub 儲存庫。不支援私人儲存庫、非 GitHub 主機、GitHub tree
或子目錄 URL，以及巢狀應用程式路徑。根應用程式必須包含可讀取的
`package.json`，其中在 `dependencies`、`devDependencies` 或
`peerDependencies` 中列出 `@agent-native/core`。在工作區儲存庫中，每個
可選擇的來源應用程式都必須直接位於 `apps/<app-name>/` 並滿足相同要求；
`dispatch` 永遠不可選擇。

社群工作區應用程式必須是可攜式的獨立單元，而不是 monorepo 的任意切片：

- 預設 `catalog:` 相依性參照會從來源儲存庫根目錄的
  `pnpm-workspace.yaml` 解析；不支援具名 catalog 參照；
- 對 `@agent-native/core`、`@agent-native/dispatch` 和
  `@agent-native/toolkit` 的 `workspace:*` 參照會改寫為已發佈版本。其他
  同層工作區 package 不會被複製；請發佈它們並使用具體版本；
- 來源 `workspaceCore` 相依性會被移除。繼承的標準工作區 auth 和
  agent-chat plugin 會在獨立安裝時解除綁定，或重新綁定到目標工作區。對
  來源 `workspaceCore` package 的任何其他 import 都會明確失敗；請將該
  程式碼移入應用程式，或將其發佈為具體相依性。

每個完整應用程式的其餘內容都應與其 `package.json` 放在一起，包括使用時
的 `agent-native.json`、原始碼、actions、代理程式指示和資料庫設定。準備
列入目錄的儲存庫還應包括：

- 授權以及維護者或支援連結；
- 包含設定步驟、必要環境變數和準確 CLI 命令的 README；
- 只包含預留位置的 `.env.example`，不得包含 secrets、客戶資料、執行階段
  資料庫或產生的建置輸出；
- 可正常運作的安裝和開發命令、typecheck，以及適合該模板的測試。

安裝程式會將解析後的 `source` 和 `ref` 記錄在已安裝應用程式的
`package.json` 中的 `agent-native.communityTemplate` 下。從工作區儲存庫
選擇的應用程式還會將來源應用程式記錄為
`agent-native.communityTemplate.app`。`agent-native template sync` 仍然
只適用於第一方模板；更新社群模板時，請檢查較新的 upstream ref 並自行合併
其變更。

有關應用程式、action、state、安全性和發佈的完整檢查清單，請參閱
[Creating Templates](/docs/creating-templates)。

> **安裝相依項目或執行社群程式碼之前，請先進行審查。** 社群模板從第三方
> 儲存庫下載；Agent Native 不會對其進行 sandbox、稽核或維護。CLI 只下載
> 原始碼，不會安裝相依項目或執行模板指令碼。請檢查原始碼、授權、相依項目
> 和 package install scripts，並優先使用已固定且可信的 ref。

託管 demo 是選用的。如果提供，請使用公開的試用連結，並說明登入、範例資料
或 provider 要求。儲存庫仍然是安裝內容的事實來源，儲存庫擁有者仍然對
模板和 demo 負責。

希望加入清單？請提交[社群模板](https://github.com/BuilderIO/agent-native/issues/new?template=community-template.yml)，
並附上儲存庫 URL、一句話描述、維護者和授權資訊、已測試的 CLI 命令，以及
選用的託管 demo URL。

## 開箱即用的東西 {#what-you-get}

每個範例應用程式都附帶通常需要數月才能建置的部件：

- **工作代理** — 已經連線到應用程式，已經能夠在您的資料上取得 actions，已經能夠了解您正在檢視的內容。請參閱 [Messaging the agent](/docs/messaging) 了解其工作原理。
- **Auth** — 登入、工作階段、組織、多租戶隔離。已經完成了。
- **資料庫** — 每個範例應用程式都有其架構、查詢和遷移準備就緒。帶上您自己的 SQL 資料庫（Postgres、SQLite、Turso、D1）——框架會進行調整。
- **即時 UI** — 螢幕與代理的操作保持同步。在聊天中點選“草稿電子郵件”，草稿立即出現在您的收件箱中。
- **部署就緒** — 推送到 Netlify、Vercel、Cloudflare、AWS 或執行 Node.js 的任何其他地方。沒有供應商鎖定。
- **品牌掛鉤** - 名稱、顏色、徽標、文案都很容易更改。

這不是理論上的主張。此框架的作者在 Mail 應用程式上執行他的實際收件箱，在 Calendar 應用程式上執行他的實際行事曆，在 Analytics 應用程式上執行他的實際分析。這些都是日常使用的應用程式。

1. **選取一個範例應用程式。**使用 CLI 選取器，或瀏覽檔案並選取一個開始。
2. **打造品牌。**更改名稱、顏色、徽標和文案。大多數範例應用程式都將其公開在單一設定檔案中。
3. **自訂它。** 在自己的儲存庫與開發工作流程中變更原始碼。如果代理 frame 被有意授予工作區與寫入工具，它可以提供協助；否則嵌入式代理會透過 actions、資料和已設定的整合來操作應用程式。
4. **發貨。**執行部署指令。您現在在自己的域中擁有自己的正式環境 SaaS。

步驟 2-4 通常需要幾天而不是幾個月。第 3 步是開放式的，因為應用程式歸您所有並可持續演進；嵌入式代理仍可操作已部署的產品，並在明確啟用程式碼存取時協助變更原始碼。

## 為什麼這是實用的 {#why}

傳統的程式碼庫分叉模型會大規模當機：每個使用者維護自己的收件箱聽起來像是一場維護噩夢。兩個框架決策使其發揮作用：

1. **應用程式保持框架合約。** 原始碼擁有領域行為，而 Core 會隨著應用程式演進保持 actions、SQL、狀態與同步的一致性。
2. **每使用者自訂，無需每使用者程式碼。** Skills、記憶、指令、連線的 MCP 伺服器和子代理都位於 SQL 中。每個使用者都有自己的定制層；共用程式碼庫同時託管所有這些內容。

結果：Claude - 每個使用者的程式碼級靈活性，以及正常的 SaaS 部署經濟性。

## 不想自訂？ {#hosted}

你不必這樣做。每個範例應用程式還可以作為 `agent-native.com` 上的託管應用程式使用 - `mail.agent-native.com`、`calendar.agent-native.com` 等。免費或付費使用託管版本；僅當您想要更改託管版本未公開的內容時才進行分叉。

### 對於開發者 {#dev-details}

如果您現在正在搭建腳手架，則 CLI 指令為：

```bash
npx @agent-native/core@latest create my-platform
```

您將獲得一個多選選取器。選取一個應用程式（獨立）或多個應用程式（工作區 - 應用程式共用驗證、品牌、代理設定和資料庫）。每個挑選的應用程式都與您需要的每個檔案一起建置到 `apps/<name>/` 中。對於沒有瀏覽器 UI 的自動化應用程式，而不是應用程式 UI，請使用 `npx @agent-native/core@latest create my-agent --headless`。

填寫`.env`（主要是`ANTHROPIC_API_KEY`和`DATABASE_URL`）、`pnpm install`、`pnpm dev`，就可以了。沒有“TODO：實現登入”，沒有預留位置路由。

部署目標：任何 Nitro 相容主機（Node、Cloudflare、Netlify、Vercel、Deno、Lambda、Bun）和任何 Drizzle 相容 SQL 資料庫（SQLite、Postgres、Turso、D1、Supabase、Neon）。對於工作區，`npx @agent-native/core@latest deploy` 一次建置每個應用程式並將它們傳送到單一來源。參見[Deployment](/docs/deployment)。

要創作和發布您自己的應用程式範本，請參閱 [Creating Templates](/docs/creating-templates)。
