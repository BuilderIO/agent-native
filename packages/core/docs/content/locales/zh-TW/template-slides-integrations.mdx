# 幻燈片的跨應用使用

幻燈片是[調度](/docs/template-dispatch)工作區中眾多應用程式之一。本頁涵蓋
這在實務上究竟意味著什麼：連接如何運作，以及其他應用程式可以對您的簡報
採取動作，或重複使用簡報內容的具體方式。總覽請參閱
[幻燈片](/docs/template-slides)。

## 幻燈片如何連接到調度

這是否自動運作，取決於幻燈片和調度當初是如何一起設定的，而不是取決於其中
任何一個是託管執行還是在本機執行。

### 相同工作區：自動運作

如果幻燈片和調度是一起產生或加入到同一個 Agent-Native 工作區中（透過
`create` 或 `add-app`），並部署為一個整體單元，它們就已經共用同一個
`.env`、同一個 `A2A_SECRET`，以及同一個工作區登錄。無論這個工作區是在您的
機器上執行，還是在生產環境中執行，發現機制和已驗證的 A2A 呼叫都能直接運
作，不需要任何額外設定。對於以幻燈片為基礎打造的真正多應用產品來說，這是
預期的設定方式。

### 各自部署：一個手動步驟

如果幻燈片和調度是兩個各自獨立建立的 Agent-Native 專案，它們就不會共用
密鑰，也還無法互相呼叫。連接它們需要在雙方各執行一個手動步驟：透過**Settings → Agent → Sub-agents**（Connect agent），或**調度 → 代理 → 新增外部
代理**，加入一個帶有共用密鑰的 `remote-agents/<id>.json` 資源。完整操作
步驟請參閱 [A2A 協議](/docs/a2a-protocol)。

若要確認您目前是哪種情況，可以詢問任一應用程式的代理「你能看到哪些應用
程式？」如果調度的回答中沒有出現幻燈片，就代表您屬於第二種情況。

## 整合策略

**透過 Creative Context Library 分享簡報。**提交一份簡報會在共用的
Creative Context Library 中凝結一個精確的版本，工作區中的任何應用程式，
不只是幻燈片，之後都能搜尋並重複使用這些投影片。一個會議記錄應用程式可以
把一張已核准的指標投影片直接拉進自己的輸出內容中，而不必用提示描述它。

**透過調度進行自然語言委派。**姊妹應用程式不需要任何特殊整合就能與幻燈片
協作。它可以像您在聊天中一樣，把一個用簡單文字描述的請求，例如「幫我做一
份這個季度數字的 5 張投影片摘要」，直接交給幻燈片的代理，而幻燈片會直接
回答或執行這個請求。這正是「郵件中收到的報告請求變成一份完成的簡報」這類
情境背後真正的機制：調度（或收到訊息的應用程式）把請求委派給幻燈片的代
理，幻燈片就會像處理其他提示一樣處理它。

**保持解耦。**對於以上這些，幻燈片完全不需要知道姊妹應用程式的憑證，反過
來也是如此。A2A 協定和共用的 Creative Context Library 位於應用程式之間，
因此幻燈片只需要回應真實的請求，或公開一個真實的共用資源，不需要知道是誰
在呼叫，或如何呼叫。
