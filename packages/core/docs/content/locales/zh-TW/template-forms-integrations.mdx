# 表單的跨應用使用

表單是[調度](/docs/template-dispatch)工作區中眾多應用程式之一。本頁涵蓋這在實務上究竟意味著什麼：連接如何運作，以及其他應用程式可以對一份表單採取動作，或把資料送進表單的具體方式。總覽請參閱 [表單](/docs/template-forms)。

## 表單如何連接到調度

這是否自動運作，取決於表單和調度當初是如何一起設定的，而不是取決於其中任何一個是託管執行還是在本機執行。

### 相同工作區：自動運作

如果表單和調度是一起產生或加入到同一個 Agent-Native 工作區中（透過 `create` 或 `add-app`），並部署為一個整體單元，它們就已經共用同一個 `.env`、同一個 `A2A_SECRET`，以及同一個工作區登錄。無論這個工作區是在您的機器上執行，還是在生產環境中執行，發現機制和已驗證的 A2A 呼叫都能直接運作，不需要任何額外設定。對於以表單為基礎打造的真正多應用產品來說，這是預期的設定方式。

### 各自部署：一個手動步驟

如果表單和調度是兩個各自獨立建立的 Agent-Native 專案，它們就不會共用密鑰，也還無法互相呼叫。連接它們需要在雙方各執行一個手動步驟：透過**設定 → 已連接的代理**、Agent 頁面的**連線**分頁，或**調度 → 代理 → 新增外部代理**，加入一個帶有共用密鑰的 `remote-agents/<id>.json` 資源。完整操作步驟請參閱 [A2A 協議](/docs/a2a-protocol)。

若要確認您目前是哪種情況，可以詢問任一應用程式的代理「你能看到哪些應用程式？」如果調度的回答中沒有出現表單，就代表您屬於第二種情況。

## 整合策略

**透過調度進行自然語言委派。** 姊妹應用程式不需要任何特殊整合就能與表單協作。它可以像您在聊天中一樣，把一個用簡單文字描述的請求，例如「beta 註冊表單有多少筆回覆」，直接交給表單的代理，而表單會直接回答或執行這個請求。這正是「Slack 或郵件中收到的問題變成表單給出的真正答案」這類情境背後真正的機制：調度（或收到訊息的應用程式）把請求委派給表單的代理，表單就會像處理其他提示一樣處理它。

**其他應用程式直接提交進表單。** 對於其他應用程式要傳送資料給表單來說，完全不需要 A2A 或調度。任何應用程式都可以向一份表單的公開提交位址發出一個純粹的網路請求，就像一位匿名受訪者填寫公開頁面時一樣。框架自帶的回饋按鈕正是以這種方式運作的。它會從另一個應用程式的側邊欄，把一筆提交送到已部署的表單應用程式，並附上這則回饋來自哪個頁面、哪個應用程式，而表單會把它記錄為一筆一般的回覆。這代表您工作區中的任何應用程式，都可以在完全沒有 A2A 連線的情況下，只靠一個純粹的網路請求，把結構化資料送進一份表單。

**保持解耦。** 無論表單是在回答一個被委派的問題，還是在接收一筆直接提交，它都完全不需要知道呼叫端應用程式的憑證，而呼叫端應用程式也完全不需要知道表單如何儲存它的資料。委派和其他提示一樣透過代理進行，而直接提交則透過與真人受訪者相同的公開位址進行。
