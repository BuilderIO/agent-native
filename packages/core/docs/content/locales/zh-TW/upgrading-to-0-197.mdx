# 將現有應用程式升級至 Core 0.197.0

依照本指南將現有應用程式升級至 Core 0.197.0。請在應用程式或 workspace
根目錄執行命令，並在開始前保留可供審閱的原始碼差異。請另外檢查遠端
部署設定：CLI 可以讀取本機環境檔案，但無法查看遠端環境或儲存在資料庫
中的功能設定。

## 1. 預覽升級和 import codemod

使用 Core 0.197.0 隨附的 CLI，載入該版本的 migration manifest：

    npx @agent-native/core@0.197.0 upgrade --codemods --dry-run

在應用程式安裝 Core 0.197.0 後，也可透過本機 CLI 執行檔執行相同的預覽：

    npx agent-native upgrade --codemods --dry-run

`--codemods` 命令使用 `ts-morph`。如果應用尚無法解析此套件，請先將它安裝為開發相依套件：`pnpm add -D ts-morph`。

`--codemods` 預設會套用支援的 import 修改。加入 `--dry-run` 可預覽預定的相依套件變更、
檔案差異和警告。現在不再需要 `--yes`。

codemod 使用有效的 Core 和 Toolkit migration manifest。它會僅掃描 .ts 和
.tsx 檔案（略過宣告檔、產生檔和相依目錄），並改寫支援的 import 和
re-export specifier。如果具名 export 移至不同模組，它可以依 symbol 拆分
宣告，同時保留 alias 和 type-only import。它也會改寫簡單的 CSS @import
路徑，並在已解析的改寫跨越 package 邊界時加入缺少的相依套件。

診斷也會偵測 CommonJS `require()` 與動態 `import()` 形式，但 codemod 不會重寫這些呼叫運算式。請依照報告中的新位置替換它們，然後重新執行 Vite 或 `agent-native doctor`。CSS `@import url(...)` 路徑無論是否加上引號，codemod 都會重寫。

它不會改變呼叫位置或移動檔案。無法解析或標記為 planned 的遷移會保留
原狀並顯示警告。它不能拆分 default、namespace、side-effect 或 star
import/export；也不能依 symbol 拆分 CSS import。
請手動檢查這些情況。已移除的 export 可能需要修改程式碼；請依照 CLI
警告中的 migration guide 處理。

預覽也會顯示完整升級計畫：阻止升級的 framework override 或 patch、待
更新的 @agent-native/\* 版本、根據本機設定判定的功能相依套件、package
manager 安裝、scaffold skill 更新，以及根 package 有 typecheck script
時的 typecheck。命令會將 package spec 改為 registry 目前的 latest，接著
固定安裝解析出的版本。請在 0.197.0 是預期使用的目前版本時執行；日後
若需要精確版本，請確認解析後的 pin。

## 2. 確認 Toolkit 和選用套件

移至 `@agent-native/toolkit/*` 的匯入需要安裝 `@agent-native/toolkit`。codemod 會在將受支援且可解析的匯入或匯出移至 Toolkit 時加入該相依套件。若應用程式使用 Toolkit 匯出但未加入相依套件，請安裝與 Core 0.197.0 相符的 Toolkit 版本：

    pnpm add @agent-native/toolkit@0.197.0
    # npm install @agent-native/toolkit@0.197.0
    # yarn add @agent-native/toolkit@0.197.0

### 由升級 CLI 選取的相依套件

本機環境檢查符合條件時，CLI 會加入以下相依套件。對於 PGlite，它會先檢查正規化應用程式名稱的 `${APP_NAME}_DATABASE_URL`，再檢查 `DATABASE_URL`；若沒有 URL 或 URL 以 `pglite:` 開頭，就會選取 PGlite。CLI 無法檢查遠端環境或儲存在資料庫中的功能設定，請另外確認正式環境與預覽環境。

| 功能                         | 選用套件                     | 版本                | CLI 檢查的本機設定                                                                    |
| ---------------------------- | ---------------------------- | ------------------- | ------------------------------------------------------------------------------------- |
| PGlite 資料庫                | @electric-sql/pglite         | ^0.5.8              | 正規化的 `${APP_NAME}_DATABASE_URL`，接著是 `DATABASE_URL`；未設定或以 `pglite:` 開頭 |

## 3. 套用升級

檢查預覽並確認功能套件後，套用計畫：

    npx agent-native upgrade --codemods

這個命令會更新符合條件的 @agent-native/\* dependency spec，調整偵測到的
功能相依套件、執行 package manager、固定解析後的 Agent-Native 版本、
套用支援的 codemod、更新 scaffold skill，並在根目錄有 typecheck script
時執行。無須為了套用 codemod 再執行一次 upgrade。請在應用程式程式碼中
處理警告和應用程式層級錯誤；不要加入 framework override 或 patch。

## 4. 驗證結果

檢查完整差異，尤其是略過的 codemod 警告和相依套件版本，然後執行：

    npx @agent-native/core@0.197.0 upgrade check
    pnpm typecheck

npm 或 Yarn 請使用對應的 typecheck 命令，並執行應用程式相關的測試和
build。確認選用 peer 表涵蓋本機與部署環境的功能設定。搜尋下表中的舊
import；剩餘結果應為刻意保留、manifest 不支援，或已有警告說明。
