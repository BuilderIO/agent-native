# 剪輯的跨應用使用

剪輯是[調度](/docs/template-dispatch)工作區中眾多應用程式之一。本頁涵蓋這在實務上究竟意味著什麼：連接如何運作，以及其他應用程式和代理可以對您的剪輯採取動作，或針對其上發生的事情做出反應的具體方式。總覽請參閱 [剪輯](/docs/template-clips)。

## 剪輯如何連接到調度

這是否自動運作，取決於剪輯和調度當初是如何一起設定的，而不是取決於其中任何一個是託管執行還是在本機執行。

### 相同工作區：自動運作

如果剪輯和調度是一起產生或加入到同一個 Agent-Native 工作區中（透過 `create` 或 `add-app`），並部署為一個整體單元，它們就已經共用同一個 `.env`、同一個 `A2A_SECRET`，以及同一個工作區登錄。無論這個工作區是在您的機器上執行，還是在生產環境中執行，發現機制和已驗證的 A2A 呼叫都能直接運作，不需要任何額外設定。對於以剪輯為基礎打造的真正多應用產品來說，這是預期的設定方式。

### 各自部署：一個手動步驟

如果剪輯和調度是兩個各自獨立建立的 Agent-Native 專案，它們就不會共用密鑰，也還無法互相呼叫。連接它們需要在雙方各執行一個手動步驟：透過**Settings → Agent → Sub-agents**（Connect agent），或**調度 → 代理 → 新增外部代理**，加入一個帶有共用密鑰的 `remote-agents/<id>.json` 資源。完整操作步驟請參閱 [A2A 協議](/docs/a2a-protocol)。

若要確認您目前是哪種情況，可以詢問任一應用程式的代理「你能看到哪些應用程式？」如果調度的回答中沒有出現剪輯，就代表您屬於第二種情況。

## 整合策略

### 代理可讀的剪輯

把一個公開的剪輯分享連結貼進代理裡，或是針對私人剪輯，在**分享給代理**這一列使用**分享 → 複製**。無論哪種方式，代理都能讀取逐字稿並看到關鍵畫格，不需要下載影片，使用的是一個兩小時後就會失效的連結。

大多數能檢視圖片的代理都能自行處理這件事，包括 ChatGPT、Claude Code、Cursor 和 Codex。少數純文字聊天可以讀取逐字稿，但無法讀取畫格，這種情況請在支援圖片的代理中開啟剪輯。

| 端點                                              | 代理可以取得的內容                                                            |
| ------------------------------------------------- | ----------------------------------------------------------------------------- |
| `/api/agent-context.json?id=<recordingId>`        | 剪輯中繼資料、逐字稿狀態、章節、CTA、推薦畫格，以及指向逐字稿/畫格 API 的連結 |
| `/api/agent-transcript.json?id=<recordingId>`     | 帶有 `startMs`、`endMs`、可讀時間戳、文字和可選來源標籤的時間戳逐字稿片段     |
| `/api/agent-frame.jpg?id=<recordingId>&atMs=<ms>` | 以原始影片時間戳從影片中擷取的 JPEG 畫格                                      |

這些端點遵循與分享頁面相同的公開/密碼/到期規則，或是接受來自臨時代理連結、範圍受限的 `agent_access` 權杖。受密碼保護的剪輯需要輸入密碼一次；成功的回應會回傳短期有效的標記化連結，因此下游代理不需要明文密碼。

### 匯出到 Brain

一旦您的工作區連接了 Brain，每段錄音完成後，剪輯就會自動把已就緒的逐字稿傳送過去。您也可以請代理回填較舊的錄音，例如過去 28 天內的所有內容，而不必等新的內容慢慢累積。它會回報有多少份逐字稿被匯出、被略過，或被標記。

### CRM 通話證明

CRM 工具有時需要證明一通電話確實發生過，但不需要完整的錄音。剪輯只會交出一個不透明的剪輯 ID 和一個持久連結，絕不會交出影片或逐字稿。這只適用於您已經能看到的錄音，而且只有在您提出要求，或核准的自動化觸發時才會發生。

### 透過調度進行自然語言委派

姊妹應用程式不需要任何特殊整合就能與剪輯協作。它可以像您在聊天中一樣，把一個用簡單文字描述的請求，例如「找到我們討論定價的那段剪輯」，直接交給剪輯的代理，而剪輯會直接回答或執行這個請求。

### 保持解耦

剪輯完全不需要知道 Brain 或 CRM 的憑證，反過來也是如此。`clip.created` 事件和代理可讀連結位於應用程式之間，因此剪輯只需要發出事件，或回應請求，不需要知道是誰在監聽。
