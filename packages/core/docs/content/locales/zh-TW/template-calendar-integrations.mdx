# 行事曆的跨應用使用

行事曆是[調度](/docs/template-dispatch)工作區中眾多應用程式之一。本頁涵蓋
這在實務上究竟意味著什麼：連接如何運作，以及其他應用程式可以對您的行事曆
採取動作，或針對其上發生的事情做出反應的具體方式。總覽請參閱
[行事曆](/docs/template-calendar)。

## 行事曆如何連接到調度

這是否自動運作，取決於行事曆和調度當初是如何一起設定的，而不是取決於其中
任何一個是託管執行還是在本機執行。

### 相同工作區：自動運作

如果行事曆和調度是一起產生或加入到同一個 Agent-Native 工作區中（透過
`create` 或 `add-app`），並部署為一個整體單元，它們就已經共用同一個
`.env`、同一個 `A2A_SECRET`，以及同一個工作區登錄。無論這個工作區是在您的
機器上執行，還是在生產環境中執行，發現機制和已驗證的 A2A 呼叫都能直接運
作，不需要任何額外設定。對於以行事曆為基礎打造的真正多應用產品來說，這是
預期的設定方式。

### 各自部署：一個手動步驟

如果行事曆和調度是兩個各自獨立建立的 Agent-Native 專案，它們就不會共用
密鑰，也還無法互相呼叫。連接它們需要在雙方各執行一個手動步驟：透過**設定
→ 已連接的代理**、Agent 頁面的**連線**分頁，或**調度 → 代理 → 新增外部
代理**，加入一個帶有共用密鑰的 `remote-agents/<id>.json` 資源。完整操作
步驟請參閱 [A2A 協議](/docs/a2a-protocol)。

若要確認您目前是哪種情況，可以詢問任一應用程式的代理「你能看到哪些應用
程式？」如果調度的回答中沒有出現行事曆，就代表您屬於第二種情況。

## 整合策略

**依行事曆事件觸發自動化。** 建立活動和建立預訂都會在共用的框架事件匯流排
上觸發真實事件（`calendar.event.created`、`calendar.booking.created`）。
任何應用程式的[自動化](/docs/automations)都可以訂閱其中任一個事件，無論是
哪個應用程式定義了這個自動化。一筆進入您行事曆的預訂，可以觸發郵件中的一份
歡迎信件草稿，或是在會議發生之前，於 Slides 中建立一份會議議程。行事曆本身
並未內建這類自動化，但這個事件是真實存在的，隨時可以在您想建立自動化時掛接
使用。

**透過調度進行自然語言委派。** 姊妹應用程式不需要任何特殊整合就能與行事曆
協作。它可以像您在聊天中一樣，把一個用簡單文字描述的請求，例如「下週找 Sam
空 30 分鐘」，直接交給行事曆的代理，而行事曆會直接回答或執行這個請求。這正
是「郵件或 Slack 收到的排程請求變成一筆已預訂活動」這類情境背後真正的機制：
調度（或收到訊息的應用程式）把請求委派給行事曆的代理，行事曆就會像處理其他
提示一樣處理它。

**保持解耦。** 行事曆完全不需要知道郵件或 Slack 的憑證，反過來也是如此。事
件匯流排以及訂閱它的自動化位於應用程式之間，因此行事曆只需要發出真實的事
件，或回應真實的請求，不需要知道是誰在監聽，或如何監聽。
