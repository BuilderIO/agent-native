# アプリに変換する

`/turn-into-app` は、すでに実績のあるワークフローを Agent-Native アプリに変換するスキルです。ソースには、スレッド、スキル、スプレッドシート、または Claude や ChatGPT のプロジェクトを使えます。アプリはあなたの世界を表す画面で開き、ソースに合わせたサンプルデータが入っています。アプリ内エージェントは、操作対象のオブジェクト上のコントロールの裏側で動きます。ステップバーの下にフォームが並ぶだけの画面は、このスキルが避けようとしている結果です。

## インストール {#install}

```bash
npx @agent-native/skills@latest add --skill turn-into-app
```

同じスキルはコア CLI にも同梱されています。

```bash
npx @agent-native/core@latest skills add turn-into-app
```

すでに Agent-Native CLI があるプロジェクト内では、`agent-native skills add turn-into-app` でも同じ結果になります。スキルのインストールと読み込みの仕組みについては、[スキルガイド](/docs/skills-guide)を参照してください。

## 呼び出し方 {#invoke}

| コマンド                           | ソース                                                         |
| ---------------------------------- | -------------------------------------------------------------- |
| `/turn-into-app`                   | 見えているプロジェクトコンテキスト。なければ現在のスレッド     |
| `/turn-into-app /some-skill`       | 指定したスキル。スレッドの開始直後でもすぐにパッケージ化される |
| `/turn-into-app ./forecast.xlsx`   | スプレッドシート。ワークベンチに変換される                     |
| `/turn-into-app ./project-export/` | Claude または ChatGPT のプロジェクトのエクスポート             |

引数がない場合、スキルは直近で成功した再現可能なジョブを構築し、その名前を付けます。1 つのアカウントや 1 件の案件のような具体例は、ジョブの根拠であってスキーマではありません。ジョブを特定できない場合は、「どんなアプリが欲しいですか？」という一般的な質問をする代わりに、何が足りないかを伝えます。

## 実行される場所 {#hosts}

| ホスト                                                               | 動作                                                                                               |
| -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Claude Code、Codex、Cursor、その他のローカルコーディングエージェント | お使いのチェックアウト内でアプリを構築、実行、レビューします。                                     |
| Web 上の Claude または ChatGPT                                       | 範囲を絞ったブリーフを書き、Dispatch コネクタ経由で Builder に渡します。自分では何も実行しません。 |

実際の作業ディレクトリ、ターミナル、ワークスペースがあるホストはローカルとして扱われます。Builder や Dispatch のコネクタがあっても、そのホストがブラウザホストになるわけではありません。

ブラウザホストでは、スキルは Agent-Native Dispatch MCP コネクタ（`https://dispatch.agent-native.com/mcp`、OAuth）を必要とし、その `start-workspace-app-creation` アクションを呼び出します。ホストはアプリを実行も検査もできないため、Dispatch が返したブランチがビルドされるまで、レポートは保留または未検証のままです。スキルは Dispatch が実際に返した内容をそのまま報告し、ブランチ URL を作り出すことはありません。ChatGPT のプロジェクト、または MCP しか公開していないホストでは、スキルの指示をプロジェクトの指示またはナレッジファイルに入れてください。

## ソース {#sources}

- **スレッド。** 直近の具体的で再現可能なジョブがプロダクトになります。
- **スキル。** スキルのステップ、人間の判断ポイント、読み取り専用ルールがアプリになります。スキルがプランファイルを保持している場合、それらのファイルは Local File Mode を通じて引き続き信頼できる情報源となり、アプリはローカル専用になります。
- **スプレッドシート。** まず全ワークシートを棚卸しします。どのセルが入力でどれが出力かは構造で判断し、色は弱いヒントにすぎません。ワークブックがプロンプト、SQL、アプリケーション状態にコピーされることはありません。Google Sheets のリンクがソースになるのは、認証済みの Sheets または Drive 接続で読み取れる場合だけです。それ以外の場合、スキルはエクスポートを求めます。
- **Claude と ChatGPT のプロジェクト。** 見えている指示、ナレッジファイル、提供された過去の実行履歴がソースです。コネクタは、非表示のプロジェクトチャット、非公開 URL、認証情報を読み取らず、共有リンクのインポーターもありません。コンテキストが見えない場合は、エクスポートを添付してください。

## 得られるもの {#what-you-get}

- **ソースから選ばれる形。** スキルは 13 種類のアーキタイプ（トリアージキュー、パイプラインボード、ライブワークベンチ、スケジュールグリッド、レビュー差分、モニターなど）から 1 つを選びます。アーキタイプはユーザーが見るオブジェクトであり、たどる手順ではありません。そのため、ソースのステップはステッパーやウィザードではなく、オブジェクト上の状態（下書き、確認済み、承認済み）になります。
- **名前付きのビジュアルの方向性。** 6 つの方向性（`ledger`、`control-room`、`paper-desk`、`studio-canvas`、`tidepool`、`signal-board`）のいずれかで、ライトとダークのトークンを備え、アーキタイプとソースのドメインから選ばれます。既存のブランドや明示した方向性が優先されます。
- **データが入った最初の画面。** `/` は、ソースに合わせた合成サンプルデータ（サンプルと明示されます）が入った名前付きのドメインルートに着地します。空の状態、ヒーロー、手順の最初のステップ、フォームは、ソース自体がフォーム型でない限り欠陥とみなされます。
- **オブジェクト上のエージェントモーメント。** AI ラベル付きの各コントロールは、範囲を絞ったプロンプトをエージェントのサイドバーに渡します。オブジェクトはすぐに作業中の状態を表示し、結果は承認、編集、再試行のボタンとともにそのオブジェクトに戻ります。フォローアップは同じスレッド内で行われます。
- **本物の Agent-Native アプリ。** 決定的な処理は `defineAction` ファイルで、UI とエージェントの両方から呼び出されます。アプリは標準の Use Builder.io または Custom keys の設定を使い、現在のビューと選択をアプリケーション状態に書き込み、アプリ内エージェントに新しいアプリを説明する `AGENTS.md` を持ちます。

スキルはソースのブリーフを `docs/brief.md` に保存し、画面のデザインを `DESIGN.md` に追記します。

## 実行の流れ {#how-it-works}

1. **ブリーフ。** ソース全体を読み、短いブリーフを書きます。内容は、ジョブ、最大 3 つのエージェントモーメント、不変条件、データ上のリスク、信頼できる情報源、前提です。
2. **デザイン。** アーキタイプ、方向性、シェル、最初のビューポートとサンプルデータ、エージェントモーメントを決め、ブリーフをチェックポイントとして一度投稿します。待たずに続行します。
3. **スキャフォールド。** chat テンプレートで本物のアプリを作成し、既存のアプリを上書きすることはありません。

   ```bash
   npx --yes @agent-native/core@latest create <slug> --standalone --template chat
   ```

   既存の Agent-Native ワークスペース内では、代わりにワークスペースのルートから `pnpm exec agent-native add-app <slug> --template chat` を実行します。

4. **ビルド。** アクション、ドメインの画面、サンプルデータ、エージェントモーメント、エージェントへの指示をまとめて構築します。
5. **レビュー。** アプリを実行し、スクリーンショットをレビューします。詳しくは下記を参照してください。
6. **検証。** `pnpm typecheck`、`pnpm agent-native:doctor`、`pnpm build` を実行してから、最終レポートを書きます。

スキルの目安は約 45 分です。レビュー開始時にすでに 35 分が経過している場合は、1 回だけ実行して未達成の基準を列挙します。

## スクリーンショットレビューのループ {#review-loop}

引き渡しの前に、スキルは開発サーバーを起動し、`/` をデスクトップとスマートフォンのサイズ、ライトとダークで撮影し、さらにクリック後のメインのエージェントコントロールも撮影します。スクリーンショットは 12 行のルーブリックで採点されます。対象は、最初のビューポートのインパクト、ドメインへの適合、階層、クロームの抑制、サンプルデータ、タイポグラフィ、色、仕上げ、エージェントと UI の一体感、390px のレイアウト、ダークモード、アクセシビリティです。

平均スコアにかかわらずレビュー不合格となる指摘があります。ステッパーやウィザード形式のシェル、`/` がドメインルートで開かないこと、空またはフォームだけの最初のビューポート、スキャフォールドのデフォルトトークン、切れたテキスト、生の Markdown、390px での横スクロール、コンソールエラーです。すべての指摘を 1 回にまとめて修正し、クリックで変わったものをリセットしてから再撮影します。デフォルトは 2 回で、2 回目でも基準に届かず時間に余裕がある場合に限り 3 回目を行います。基準は、平均 4.0 以上、3 未満の項目がなく、自動不合格がないことです。

スクリーンショットはアプリの `.tmp/ui-review/out/` に保存され、最終レポートにそのパスとスコアが載ります。UI に反映される結果は、AI プロバイダーが接続されている場合にのみ動作確認できます。接続されていない場合、レポートには結果を確認していないと記載されます。

## 実行とデプロイ {#run-deploy}

ローカルレビューのために、スキルはアプリの無視される `.env` に `AUTH_DISABLED=1` を設定します。新しいスクリーンショット用ブラウザはサインインしていないためです。これはループバックでの開発専用です。最終的な `pnpm build` の前に削除され、コミットもデプロイも決してしてはいけません。これがない場合、アプリを開くと「Continue as local dev」カードが表示されます。

自分でアプリを実行するには次のようにします。

```bash
pnpm dev
```

ローカルで自分のモデルプロバイダーを使うには、同じ `.env` に `ANTHROPIC_API_KEY` などのキーを入れます。そうしない場合、エージェントのサイドバーには共通の Use Builder.io または Custom keys の設定が表示されます。

スキルがデプロイするのは、あなたが依頼したとき、またはプロバイダーがすでに設定済みのときだけです。正常なローカルビルドでも、終了コード 0 で「production configuration errors」ブロックが表示されます。これがデプロイのチェックリストで、安定した `BETTER_AUTH_SECRET` と永続的な `DATABASE_URL`、さらにワークスペース内のアプリでは `A2A_SECRET` が必要です。スキルはこれらを保留中のステップとして報告し、プレースホルダーの値は作成しません。[アプリをデプロイする](/docs/deploy-an-app)と[ワークスペースをデプロイする](/docs/workspace-deployment)を参照してください。

最終レポートでは、証跡を個別にラベル付けします。ローカルで実行中、ローカルで検証済み、ビルド可能、デプロイ済み、本番で検証済みは別々の状態であり、レポートがどれかを別のものの代わりにすることはありません。

## 既知の制限 {#limits}

- **開発サーバーの実行中に `.env` を編集する場合。** `.env` の変更後にその場でリロードすると、ローカルデータベースのロックでループし、500 を返します。サーバーを停止し、`.env` を編集してから、再起動してください。
- **曖昧なスプレッドシート。** 範囲を絞ったレビューの後も、候補となるワークフローや入力と出力の対応が大きく曖昧なままの場合、スキルは推奨する解釈を添えて簡潔な質問を 1 つだけします。ヘッドレス実行では、質問を出力し、前提をブリーフに記録して、構築を続けます。
- **ブラウザホストでのスプレッドシート。** ワークブックは添付できません。ホストは範囲を絞った CSV 表現をテキストとして、または公開 URL を渡し、引き渡しでは省略した内容を明記します。
- **セルの色。** テキストのプレビューでは色を確認できないため、ローカルホストではスキルは数式とキャッシュされた値の両方を読み取り、色は弱いヒントとして扱います。
- **Local File Mode のアプリ。** 信頼できる情報源がホストのファイルであるアプリはローカル専用で、デプロイされません。
- **ブラウザホストからの引き渡し。** Dispatch がビルド済みのブランチを返すまで、結果は未検証です。スキルはそこでアプリを実行することも、スクリーンショットを撮ることもできません。
