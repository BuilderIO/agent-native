# Plan プラグインとマーケットプレイス

Agent-Native の **Plan** アプリは、1 つのインストール可能なバンドルとして提供されます。1 回の
インストールで、Plan のスラッシュコマンドスキル**と**、ホスト型の Plan MCP コネクタ (エージェ
ントが対話するリモートツールサーバー) の両方が設定されるため、エージェントは 1 つのステップで
Plan を生成し、そのまま Plan アプリへ公開できます。このページは、インストール経路を選ぶ人、
インストールのトラブルシューティングをする人、Plan を厳選プラグインカタログに申請するかどうかを
検討する人向けです。スキルが実際に何をするかについては [Visual Plans](/docs/template-plan) を
参照してください。

## 手に入るもの {#what-you-get}

1 回のインストールで、次のものが手に入ります。

- **3 つのスキル** — `/visual-plan` (正規のエントリーポイント)、`/visual-recap`、`/visualize-repo`。
- **Plan MCP コネクタ** — `https://plan.agent-native.com` にあるホスト型アプリに対して登録されます (MCP エンドポイント `https://plan.agent-native.com/mcp`、サーバー名 `plan`)。

デフォルトでは、`/visual-plan` と `/visual-recap` はホスト型の Plan アプリに公開します —
MCP コネクタ経由で Plan を作成し、レビュー用のリンクまたはインラインの Plan を渡してくれます。
成果物としてインラインの Markdown/ASCII の Plan をチャットにそのまま出力することはありません。
Plan のツールが `needs auth`、`Unauthorized`、`Session terminated` のいずれかを返した場合は、
インライン出力にフォールバックするのではなく、コネクタを再認証してください。アクセストークン
は長寿命 (デフォルト 30 日、365 日のスライディングリフレッシュ) であるため、これはめったに
起きないはずです。起きた場合の簡単な修正方法は次のとおりです。

```bash
npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex
```

`reconnect` は、選択したローカルクライアントについて URL からコネクタを見つけて更新します —
再インストールは不要です。再接続した後は、ツールレジストリが再読み込みされるよう新しい Codex
スレッドを開始してください。Claude Code では、同等の操作は `/mcp` →
**Authenticate / Reconnect**、または `--client claude-code` を付けた同じコマンドです。

例外は、明示的な**ローカルファイルプライバシーモード**です。DB への書き込みを行わないよう
頼んだ場合、または `AGENT_NATIVE_PLANS_MODE=local-files` を設定した場合、スキルは Plan MCP
コネクタを呼び出してはいけません。代わりに `plans/<slug>/plan.mdx` と、任意で `canvas.mdx`、
`prototype.mdx`、`.plan-state.json` を書き出し、次のコマンドでローカルにプレビューします。

```bash
npx @agent-native/core@latest plan local serve --dir plans/<slug> --kind plan --open
```

これは小さな localhost ブリッジを起動し、ローカルフォルダーに対して Plan の UI を開きます。
(`plan local preview` は代わりにローカルの Plan 開発サーバールートを実行し、
`plan local preview --out preview.html` は単体の静的 HTML ファイルを書き出すレガシーな
逃げ道です。`plan serve` は `plan local serve` の短いエイリアスとして使えます。)

ローカルファイルモードで知っておくべき、いくつかの注意点があります。

- **Chromium ベースのブラウザを使う。** Safari は、ホスト型の HTTPS Plan ページが
  `http://127.0.0.1` の localhost ブリッジを読み取ることをブロックする (混在コンテンツ/
  プライベートネットワークの制約) ため、ページが「Loading plan.」のまま止まってしまいます。
  macOS では `--open` がすでに Chrome/Chromium/Edge/Brave を優先しますが、それでも Safari が
  開いてしまった場合は、表示された URL を Chromium ベースのブラウザで開き直してください。
- **配信された URL は `plans/<slug>/.plan-url` に書き出されます** (`--url-file` で変更可能)。
  バックグラウンドやヘッドレスのエージェントは、長時間実行される `serve` の標準出力を
  スクレイピングする代わりに、このファイルを読み取れます。ローカルのトークンファイルとして
  扱い、コミットしないでください。
- ブラウザが使えない場合は、**ヘッドレスで検証します**。
  `npx @agent-native/core@latest plan local verify --dir plans/<slug>` はブリッジを起動し、
  プライベートネットワークのプリフライトと JSON ペイロードを確認し、診断情報を出力し、
  失敗時には非ゼロで終了します — 人の目は必要ありません。
- **まず `plan local check` を実行します。** これは、MDX を Plan レンダラーのブロックスキーマ
  (`checklist` 項目の `id`/`label`、`question-form` の質問の `id`/`title`/`mode` などの必須
  フィールドを含む) に照らして検証するため、執筆ミスは止まったローダーとしてではなく、
  ブラウザに渡す前に表面化します。

現在のリポジトリ内のフォルダーについては、直接のローカル経路に `?path=...` が含まれるため、
ローカルの Plan アプリはブラウザでの編集をリポジトリのフォルダーに保存し続けられます。Plan
アプリは、`agent-native.json` の `apps.plan.roots[0].path` を、昇格させたローカル Plan を
保存するデフォルトの場所として使い、なければ `plans/` にフォールバックします。

これにより、Plan の内容は Agent-Native の Plan データベースの外に保たれます。ホスト型の共有、
コメント、スクリーンショット、Plan の履歴は、後で明示的に公開するまでは利用できません。

Agent-Native Desktop には、ホスト型 Plan 向けの別のローカルファイル同期経路があります。
Desktop アプリは、Plan アプリを clone したり CLI を実行したりせずに、ホスト型の Plan を
ローカルの MDX ファイルにミラーリングし、編集内容を取り込み直せます。このワークフローでは、
ホスト型の Plan データベースが正規のソースであり続けます。目的が Plan DB への書き込みを
なくすことであれば、ローカルファイルプライバシーモードを使ってください。

> プラグイン (`agent-native-visual-plans`) はアプリ ID `visual-plans` を持っています。そのため、Claude Code のプラグイン名と Codex のプラグイン名はどちらも `agent-native-visual-plans` になります。Plan アプリの表示名は「Agent-Native Plan」です。

## インストール経路 {#install}

入り口は 3 つあります。**汎用 CLI 経路**はデフォルトで推奨する方法です。スキルをインストール
**しつつ**、ホスト型・ローカルファイル・セルフホストのいずれのモードにするかを 1 つのフローで
選べるためです。プラグイン経路は、本格的なプラグイン/マーケットプレイスの仕組みを持つホスト
向けで、デフォルトではホスト型 Plans を使います。

### 汎用スキル経路 (あらゆる MCP ホスト) {#universal}

Claude Code、Codex、Cursor、Cline、Goose、ChatGPT のカスタム MCP アプリ、Claude Cowork など、
MCP 互換のあらゆるホストで動作します。Agent-Native CLI は、Plan のスキルをインストールし、
ホスト型の Plan MCP コネクタを登録し、**同じステップで選択したローカルクライアントの認証まで
実行する**ため、最初のツール呼び出しが OAuth の壁にぶつかることはありません。

```bash
npx @agent-native/core@latest skills add visual-plan
```

これにより `visual-plan` と、付随する `visual-recap`、`visualize-repo` のスキルがインストール
され、続いて `plan` コネクタが登録され、その後認証が実行されます (ホスト型/アカウント連携の
共有のための OAuth プロンプト)。便利なフラグ:

- `--client codex|claude-code|claude-code-cli|cowork|all` — MCP 設定をどのローカルエージェント向けに書き出すか (デフォルトは `all`)。
- `--no-connect` — 認証せずにコネクタだけを登録します。後で `npx @agent-native/core@latest connect https://plan.agent-native.com --client all` を実行するか、より絞った `--client` を選んでください。
- `--mode hosted|local-files|self-hosted` — ホスト型の共有、すべてローカルの MDX ファイル、自分専用の Plan アプリのいずれかを選びます。
- `--mcp-url <url>` — デフォルトのホスト型の代わりに、コネクタをカスタムのオリジン (ngrok トンネル、ローカル開発サーバー、セルフホストのデプロイなど) に向けます。
- `--with-github-action` — PR Visual Recap の GitHub Action も書き出します ([PR Visual Recap](/docs/pr-visual-recap) を参照)。

対話的なインストールでは、ワークフローがまだ存在しない場合に PR Visual Recap Action の追加も
提案されます。スキルのセットアップ中に「はい」と答えて追加するか、後で上記のコマンドに
`--with-github-action` を付けて実行してください。ワークフローが書き出された後は、次を実行
します。

```bash
npx @agent-native/core@latest recap setup
npx @agent-native/core@latest recap doctor
```

`recap setup` は可能な範囲で GitHub Action のシークレットと変数を設定し、`recap doctor` は
ワークフロー、ローカルの公開トークン、GitHub リポジトリへのアクセス、必要な Actions の設定を
検証します。インストールが完了したら、新しいスキルとツールが読み込まれるようエージェント
クライアントを再起動または再読み込みしてから、`/visual-plan` を実行してください。

> 注: 素の `npx skills@latest add BuilderIO/agent-native --skill visual-plan` (Vercel/open Skills CLI) は**指示のみ**をインストールし、MCP コネクタは登録しません。コネクタも設定したい場合は、上記の Agent-Native CLI を使ってください。

### Claude Code (プラグイン) {#claude-code}

パブリックな `BuilderIO/agent-native` リポジトリはそれ自体が Claude Code のプラグイン
マーケットプレイスなので、ビルド不要でそのまま追加できます。Claude Code 内で:

```text
/plugin marketplace add BuilderIO/agent-native
/plugin install agent-native-visual-plans@agent-native-apps
/reload-plugins
/mcp        # authenticate the Plan connector (one OAuth approval)
```

`/plugin install` は Plan のスキルと、**URL のみ**の MCP 設定 (パッケージにシークレットは
含まれません) を追加します。`/mcp` → **Authenticate** で OAuth のハンドシェイクが完了します。
ローカルファイルモードやセルフホストモードにしたい場合は、代わりに汎用 CLI 経路を使って
ください。

> マーケットプレイスのカタログは `agent-native-apps` という名前で、Plan のプラグインは `agent-native-visual-plans` です。そのため、インストール対象は常に `agent-native-visual-plans@agent-native-apps` になります。

### Codex (プラグイン) {#codex}

同じリポジトリは Codex のプラグインマーケットプレイスでもあります。追加してプラグインを
インストールし、コネクタを認証します。

```bash
codex plugin marketplace add BuilderIO/agent-native
codex plugin add agent-native-visual-plans@agent-native-apps
codex mcp login plan   # OAuth in the browser
```

インストール後は、スキルと MCP ツールがセッションに読み込まれるよう、**新しい Codex
スレッドを開始してください**。このプラグインは URL のみのコネクタ (`[mcp_servers.plan]` →
`https://plan.agent-native.com/mcp`) を同梱しており、`codex mcp login plan` で OAuth フロー
が実行されます。インストールと認証を 1 つのコマンドで済ませたい場合や、ローカルファイル
モード・セルフホストモードにしたい場合は、上記の汎用 CLI 経路
(`npx @agent-native/core@latest skills add visual-plan --client codex`) も Codex で使えます。

<Callout tone="info">

**古いインストールをお使いの場合:** 設定に同じ URL を指す `agent-native-plans` というエントリがまだ残っている場合、Codex では `npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex` を、それ以外では対象の `--client` を指定した同じコマンドを実行すると、正規の `plan` という名前に統合されます。

</Callout>

## 更新 {#updates}

プラグイン経路は自動更新されます — 通常のスキル変更のために、パッケージを作り直したり
マーケットプレイスを追加し直したりする必要はありません。

- **Claude Code** — マーケットプレイスのエントリは `autoUpdate: true` を設定しており、
  プラグインはコミット SHA によるバージョニングを使うため、Claude Code は起動時にリポジトリ
  から新しいバージョンを取得します。反映するには `/reload-plugins` を実行してください。
  リポジトリのデフォルトブランチへのすべてのプッシュは、インストール済みのユーザーに
  自動的に届きます。
- **Codex** — プラグインの `version` には、同梱されたスキルと MCP エンドポイントのコンテンツ
  ハッシュが埋め込まれており (例: `1.0.0+codex.<hash>`)、スキルやエンドポイントに変更がある
  たびに新しいバージョンになります。Codex は起動時の自動アップグレードで、設定済みの git
  マーケットプレイスを自動的に再インストールします。変更を反映するには、**新しいスレッドを
  開始する**だけで済みます。通常の更新のために手動で `codex plugin marketplace upgrade` を
  実行する必要はありません。
- **汎用 CLI 経路** — コピーされたスキルフォルダーを確認するには
  `npx @agent-native/core@latest skills status visual-plan` を、その場で更新するには
  `npx @agent-native/core@latest skills update visual-plan` を実行します。コネクタの
  再登録/再認証も行いたい場合は、`skills add visual-plan` を再実行しても問題ありません。
  `@latest` は常に、公開されている `@agent-native/core` パッケージから現在のスキルを
  取得します。

コネクタは**ホスト型**のアプリを指しているため、Plan アプリの actions とライブのツール
サーフェスは、いつインストールしたかに関わらず、常にデプロイ済みのバージョンを反映します。
上記の更新の仕組みに従うのは、同梱されたスキルの指示だけです。

<Callout tone="info">

**メンテナー向け:** マーケットプレイスのバンドル (`.claude-plugin/`、`.agents/plugins/`) は、正規の plan スキルから `pnpm sync:plan-marketplace` によって生成され、CI では `pnpm guard:plan-marketplace` によって検証されるため、公開されているマーケットプレイスは常に正規のスキルと一致します。スキルを編集し、`pnpm sync:plan-marketplace` を実行して、コミットしてください。

</Callout>

## 何かを申請する必要はありますか? {#submission}

**これを配布・インストールするのに、申請やレビューは一切必要ありません。**
`BuilderIO/agent-native` はセルフホスト型の公開 git マーケットプレイスであるため、ユーザーは
**Claude Code と Codex の両方**で、上記のコマンドを使って直接追加できます — 申請も承認も
不要です。汎用 CLI 経路にはマーケットプレイス自体が必要ありません。

公開リスティングを望む場合の、任意の発見しやすさの向上策です。

- **Claude Code** には、掲載のために _任意で_ 申請できるコミュニティマーケットプレイスが
  あります (申請と自動レビュー)。公式の Anthropic 厳選マーケットプレイスへの掲載は Anthropic
  の裁量によるもので、オープンなセルフサービスの申請はありません。どちらも、上記の
  インストールコマンドを使うために必須ではありません。
- **Codex** には OpenAI 厳選のプラグインカタログがあります (クローズドな許可リストで、
  セルフサービスの申請ではなくパートナーシップとして選定されます)。セルフホスト型の git
  マーケットプレイスと CLI 経路は、動作させるのに申請を必要としません。

つまり、セルフホスト型/公開の git マーケットプレイスとして出荷すればユーザーは直接
インストールでき、発見されやすくするために掲載したい場合にのみ、厳選カタログへ申請すれば
よいということです。

## プラグイン vs. スキル {#plugin-vs-skill}

**スキル**とは、タスクが一致したときにエージェントが読み込む、単一の `SKILL.md` 指示
ファイルです。**プラグイン** (Claude Code のマーケットプレイスプラグインや Codex のプラグイン)
は、1 つ以上のスキル**と** MCP コネクタ、メタデータをまとめたパッケージであり、ホストは
1 ステップですべてをインストールできます。

内部的には、3 つの経路はすべて `npx @agent-native/core@latest app-skill` CLI によって同じ
ソースから作られます。`app-skill pack` はマーケットプレイス/プラグインのアダプターをビルド
し、`skills add` は MCP コネクタの登録と認証も行う、扱いやすい 1 ステップのインストーラー
です。app-skill マニフェストの形式については [スキルガイド](/docs/skills-guide) を、あらゆる
MCP ホストへの接続と `npx @agent-native/core@latest connect` のフローについては
[外部エージェント](/docs/external-agents) を参照してください。
