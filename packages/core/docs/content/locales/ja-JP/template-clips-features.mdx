# 機能

クリップのすべての中核機能について、その仕組みと設定方法を説明します。概要は
[クリップ](/docs/template-clips) を、プロンプトの全リストは
[Agent との対話](/docs/template-clips-agent) を参照してください。

## ライブラリ

### クリップを表示する {#library-view-clips}

ライブラリは、まずフォルダ、続いて録画を、再生時間、タイトル、所有者、視聴回数、公開範囲が一目で分かるサムネイルのグリッドとして表示します。新しい順、古い順、タイトルで並べ替えたり、タグで絞り込んだり、これまでに作成したすべてのトランスクリプトを横断して検索し、タイトルを覚えている録画だけでなく、何かを話し合ったクリップそのものを見つけたりできます。

### クリップを作成する {#create-a-clip}

ライブラリにクリップを追加する方法は 3 つあり、いずれも **録画** ボタンとその横の **インポート** メニューから行えます。ライブラリの空白部分を右クリックしても同じ 3 つに加えて **新規フォルダ** が表示されます。

- **録画。** クリップ内蔵の画面レコーダーで、ウェブカメラのオーバーレイ、音声キャプチャ、一時停止/トリムのコントロールを備えています。
- **動画ファイルをアップロードする。** パソコンにある既存の動画をそのまま追加するか、ライブラリまたはスペースのグリッドにドロップします。録画は不要です。
- **Loom をインポートする。** 公開されている Loom の動画を、再録画せずに取り込みます。**録画** の横にある **インポート** を開き、**Loom をインポート** を選び、Loom の共有 URL または埋め込み URL を貼り付けます。クリップはライブラリにコピーを保存し、Loom が公開トランスクリプトを提供している場合はそれもインポートします。

### クリップを管理する

どのクリップの三点メニューも、ライブラリからでもカードを直接右クリックしても、同じ 4 つの操作を持ちます: **共有**、**フォルダに移動**、**アーカイブ**、**ゴミ箱に移動**。

#### 共有 {#share}

クリップごとの権限 (公開、チーム/組織、非公開) でクリップを共有します。リンクの追跡やスレッド形式のコメントも機能します。共有ダイアログから、どのクリップにもパスワードや有効期限を追加できます。どちらもアクセスを絞ることしかできません。それより上位の共有ルールが拒否するアクセスを、どちらも許可することはできません。

組織の管理者は、誰も明示的に選ばなかったときに新しい録画が得るデフォルトの公開範囲を設定します。詳しくは以下の [組織とチーム](#organizations-and-teams) を参照してください。管理者が変更しない限り、録画のデフォルトは公開です。公開範囲を明示的に選んだ場合、常にそれがデフォルトより優先されます。

クリップの埋め込み URL を作成すれば、Wiki ページ、社内ツール、その他 `<iframe>` を受け付ける場所ならどこにでも配置できます。

| Param             | Meaning                                                                                   |
| ----------------- | ----------------------------------------------------------------------------------------- |
| `?t=80`           | 80 秒地点から再生を開始する                                                               |
| `?autoplay=1`     | 自動再生する (ブラウザがミュートなしの自動再生をブロックするため、ミュートで再生されます) |
| `?hideControls=1` | プレーヤーのコントロールを非表示にする                                                    |
| `?loop=1`         | 再生をループする                                                                          |

ワークスペースにクリップの Slack アプリをインストールすると、公開共有リンクは Loom 風の再生可能な動画としてもプレビューされます。再生可能な Slack プレビューになるのは、準備が完了していて公開されており、パスワードも有効期限切れも、アーカイブ/ゴミ箱マーカーもないクリップだけです。それ以外は通常のタイトルとサムネイルのリンク メタデータにフォールバックします。

共有したクリップのトランスクリプトとフレームを、人だけでなく ChatGPT や Claude Code のような外部のエージェントにも読み取らせたいですか? [マルチアプリ ワークスペースでのクリップのクロスアプリ利用](/docs/template-clips-integrations) を参照してください。

クリップが共有されると、所有者は実際に誰が視聴しているかを確認できます。

| What                 | Shows you                                                                                                                                |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| **録画のインサイト** | 視聴回数 (人間とクリップの agent-context API を読み取る外部エージェントで別々に集計)、ユニーク視聴者数、完了率、離脱曲線、CTA クリック率 |
| **組織のインサイト** | 期間内の組織全体の合計、視聴回数・リアクション・コメント別の上位クリップ、上位の作成者、日別のエンゲージメント トレンド、インサイト ハブ |
| **CSV エクスポート** | 組織内のすべての録画について、視聴数とエンゲージメント数を含むダウンロード可能な CSV。直近 5,000 件の録画まで                            |

人間による視聴とエージェントによる視聴は意図的に別のカウンターで追跡されるため、共有クリップのトランスクリプトをポーリングするエージェントが、実際に視聴した人の数を水増しすることはありません。

#### フォルダに移動

フォルダはライブラリを整理するためのもので、入れ子にできます。フォルダは録画だけでなく、他のフォルダも保持できます。

<Steps>

### フォルダを作成する

クリップの **フォルダに移動** サブメニュー、またはライブラリの右クリック メニューから **新規フォルダ** を選びます。

### クリップを移動する

クリップの三点メニューの **フォルダに移動** から移動先のフォルダを選びます。これは複数選択したクリップに対しても一度に機能します。

</Steps>

フォルダはいつでもそれ自身のオプション メニューから名前を変更できます。フォルダを削除しても、その中身が削除されることはありません。フォルダ内のすべての録画と、入れ子になったサブフォルダ内のすべての録画は、親フォルダに、削除したフォルダがすでに最上位にあった場合はライブラリのルートに移動します。

#### アーカイブとゴミ箱への移動

アーカイブとゴミ箱への移動は、どちらも何も削除せずにクリップをメインのライブラリから隠します。

- **アーカイブ** はクリップのデータをすべてそのまま保持しながら、日常のビューから外します。もう見たくないけれど再び必要になるかもしれない完了したプロジェクトに便利です。いつでも復元できます。
- **ゴミ箱に移動** はソフト削除です。クリップはライブラリとアーカイブの両方から消えますが、誰かが完全に削除するまで実際には何も失われません。自動的なクリーンアップはありません。ゴミ箱に入れたクリップは、あなたか管理者が完全に削除するまでそこに残り続けます。
- **復元** は、アーカイブまたはゴミ箱のどちらからでもクリップを一手順で戻します。
- **完全に削除** は唯一取り消せない操作で、録画とそれに紐づくすべてのもの (コメント、リアクション、視聴履歴、トランスクリプト、共有、元のメディア) を削除します。

## 共有されたもの

### クリップを表示する {#shared-view-clips}

このビューには、誰かがあなたや組織に名前を指定して、または組織全体の公開範囲設定によって直接共有したすべての録画が一覧表示されます。誰かが偶然持っている公開リンクはこのリストには含まれません。

共有されたクリップを視聴してシークしたり、サイドバーを折りたたんで動画により広いスペースを与えたりできます。ここでコメントはできますが、三点メニューはありません。クリップの管理 (移動、アーカイブ、さらなる共有) は所有者の判断のままです。

### クリップにコメントする

録画全体だけでなく、視聴している動画のまさにその時点にコメントを追加できます。コメントは返信としてスレッド化され、太字、斜体、インライン コード、リンクに対応します (見出しはプレーンテキストに変換されます)。@メンションでチームメイトに通知することもできます。コメント欄は入力するにつれて広がり、フィードは長いコメントを表示するために拡大します。

## スペース

スペースは、1 つの組織に属するトピック単位のコンテナで、「Q3 ローンチ」や「サポートチーム」のようなものです。そのメンバーは誰でも録画をそこに入れられます。録画は 0 個、1 個、または複数のスペースに同時に属せるため、クリップをスペースに追加することは移動するというより、タグ付けに近い動作です。録画をちょうど 1 か所に保持するフォルダとは異なり、スペースは単にリンクするだけです。スペースには専用のフォルダもあり、個人のライブラリのフォルダとは別に管理されます。

組織の管理者がスペースを作成し、メンバーを個別に追加します。スペースのメンバーシップには専用のロールがあります。

| Role                   | Can do                                         |
| ---------------------- | ---------------------------------------------- |
| **管理者**             | メンバーの追加・削除、スペース内のロールの変更 |
| **コントリビューター** | スペースへの録画の追加・削除                   |
| **閲覧者**             | スペース内のものを見る                         |

スペースを削除すると、そのスペースとメンバーシップの一覧が削除されます。中にあった録画には影響しません。単に、そこに表示されなくなるだけです。

## どこからでもキャプチャする

Rewind を除くすべてのキャプチャ手段は、同じ共有ライブラリに保存されます。Rewind は、そこからの一場面を共有すると承認するまで、あなたのデバイスにとどまります。

### デスクトップ トレイ アプリ

デスクトップ アプリは、日常のキャプチャを最もスムーズにするために作られています。ドラッグ可能なカメラ バブルを使った画面とウェブカメラの録画、録画中のライブ文字起こしまで、ブラウザのタブを開いたままにする必要はありません。[clips.agent-native.com/download](https://clips.agent-native.com/download) からダウンロードでき、macOS、Windows、Linux に対応しています。

<Callout tone="info">

初めて画面を録画するとき、OS が画面録画の権限を求めます (Mac の場合: システム設定 → プライバシーとセキュリティ → 画面録画)。これはクリップの設定ではなく OS レベルの権限であり、この権限がなければクリップは録画できません。

</Callout>

### Rewind

Rewind は任意で使えるローカル メモリ機能で、画面 (オンにすれば音声も) のローリング録画をデバイス上にローカルに保存します。

<Callout tone="info">

Rewind はデフォルトでオフです。デスクトップ トレイの設定でオンにするまで何もキャプチャされず、あなたが承認しない限り何もデバイスの外に出ません (リクエストごとの確認はデフォルトでオンで、Rewind の設定でオフにできます)。バッファはいつでも自分でエクスポート、検索、消去できます。

</Callout>

設定の Rewind タブから Rewind をオンにします。オンにすると、「20 分前に何を見ていた?」のようにエージェントに尋ねられるようになり、エージェントは画面上のテキスト、アプリとウィンドウのコンテキスト、トランスクリプトの断片といったローカル バッファからテキストの抜粋を読み取ります。エージェントが録画そのものを受け取ることは一切ありません。ただし 1 つ例外があり、あなたが確認して承認したリクエストは、正確な範囲を非公開クリップに変換します。

#### 直前の出来事を追加する

クリップのエディターで、**直前の出来事を追加** は、ローカルの Rewind 履歴から直前の 30 秒または 5 分を取り出し、クリップの先頭に追加します。クリップはこのデバイスで、Rewind がオンの状態で録画されている必要があり、その場面がまだ Rewind の保持履歴内に残っている必要があります。

- クリップは非公開で、他の誰にも直接アクセス権が付与されていない必要があります。Rewind の履歴には、録画を選択する前のコンテキストが含まれる可能性があるため、クリップはまず対象のクリップを非公開にし、他に誰かがまだアクセス権を持っている場合は処理を止めます。
- クリップのメディアは、結合された録画に置き換えられます。トランスクリプト、チャプター、コメント、リアクションはタイムスタンプが引き続き一致するようにシフトし、タイムライン上には元のクリップが始まった位置が示されます。
- これはクリップごとに 1 回だけ、あなたが頼んだときにのみ実行されます。Rewind から自動的に何かが追加されることはありません。

### Chrome 拡張機能によるブラウザログ

クリップの Chrome 拡張機能をインストールすると、録画に加えて、デバッグ中のタブのブラウザ ログとネットワーク アクティビティも取得できます。プロダクトのバグ報告やブラウザだけで再現する不具合の報告に役立ちます。

これは、実際に録画しているタブだけを、録画が実行されている間だけ監視します。保存されるのは、コンソール メッセージと、リクエストごとの基本情報 (メソッド、編集済みの URL、ステータス、所要時間、失敗したかどうか) だけで、リクエストやレスポンスの本文、ヘッダー、クッキーは保存しません。日常的な録画にはデスクトップ アプリを使い、そのブラウザ ログを添付する必要があるときだけ Chrome 拡張機能を使ってください。

## 文字起こしと AI メタデータ {#transcription-and-ai-metadata}

文字起こしは、まず最も速い無料の選択肢を試し、必要な場合にのみ有料の選択肢にフォールバックします。文字起こし履歴には、完全なトランスクリプトと対応する action に展開できるトランスクリプトのプレビューが表示されます。

| Order | Provider                        | Notes                                                                                                                                                                          |
| ----- | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1     | ネイティブ (デバイス上)         | ブラウザの Web Speech API、またはデスクトップのローカル Whisper/macOS の音声認識。即時で、API キーは不要です。                                                                 |
| 2     | Builder.io マネージド (Gemini)  | ネイティブのテキストが得られないときのクラウド フォールバック。Builder を接続していれば追加のキーは不要です。Builder.io の無料プランにはマネージド AI クレジットが含まれます。 |
| 3     | Groq (`whisper-large-v3-turbo`) | 自分のキーを使いたい場合の任意のバックアップです。                                                                                                                             |

トランスクリプトが準備できると、エージェントが自動的にタイトル、概要、チャプター マーカーを入力し、編集するたびに最新の状態を保ちます。再生中は、トランスクリプトが現在の再生位置に追従します。直接頼むこともできます。

- 「タイトルと概要を作り直して。」
- 「チャプターを追加して。これは長いから。」
- 「ブログ投稿用に 3 つ引用を抜き出して。」
- 「1:42 の誤って文字起こしされた単語を直して。」

音声だけでは誤解を招くような無音の画面録画では、AI ツール メニューで **動画全体を含める** をオンにすると、エージェントはトランスクリプトだけに頼らず、録画そのものを見るようになります (これには Gemini が必要です)。

バックアップの文字起こし、トランスクリプトのクリーンアップ、AI によるタイトルと概要は、無料プランのクレジットを含め、デフォルトで Builder.io のマネージド AI クレジットを使って実行されます。これらのいずれかが動かなくなったら、エージェントに聞いてください。エージェントは現在のクレジット状況を確認し、バグとして扱うのではなく、クレジットが一時停止しているかどうかを説明します。対処法は、Builder.io のクレジットを追加すること、プランをアップグレードすること、または文字起こしのフォールバックとして個人の Groq キーを接続することのいずれかです。

## 非破壊編集 {#non-destructive-editing}

タイムラインを使って、クリップのトリムと分割、無音部分やつなぎ言葉の削除、クリップの結合を行います。カット境界をドラッグして調整し、取り消しとやり直しで編集内容を確認できます。こうした変更は元の録画の上に重ねられたまま保持され、書き出すまで新しいファイルに焼き込まれることはありません。

レダクションはこれとは仕組みが異なります。レダクションボックスを描いても、エディタ上でその部分を覆っているだけで、元のピクセルはファイルにそのまま残っています。実際に隠されるのは、レダクションを**焼き込む**操作を行ったときだけです。これにより動画が再エンコードされ、覆われたピクセルが完全に破棄され、元のファイルが削除されます。焼き込んだ後は元に戻せないので、ここで本当に取り消しのきかない唯一のステップとして扱ってください。

エージェントに、こうした編集をしてもらうよう頼んでみましょう。

- 「えーとあーを削除して、つなぎ直して。」
- 「最初の 10 秒をトリムして。」
- 「この 3 つのクリップを、この順番で 1 つに結合して。」

録画のオプション メニューからは、**無音部分を削除** と **つなぎ言葉を削除** で、同じことをタイプせずにワンクリックで行えます。どちらの場合も、実際の作業はエージェントが行っており、トランスクリプトを読み、範囲を見つけ、トリムの指示を適用しています。

## 組織とチーム {#organizations-and-teams}

誰でも組織を作成して、クリップのワークスペースをチームと共有できます。組織を作成すると、あなたが最初の管理者になります。

- **ブランディング。** 管理者は、共有ワークスペース全体に表示されるブランド カラーとロゴを設定します。
- **デフォルトの公開範囲。** 管理者は、誰も明示的に選ばなかったときに新しい録画が既定でどうなるか (公開、組織、非公開) を選びます。
- **メンバーをメールで招待します。** 招待は承認または辞退され、管理者は後からメンバーのロールを変更したり、メンバーを削除したりできます。

| Role         | Can do                                                                                                           |
| ------------ | ---------------------------------------------------------------------------------------------------------------- |
| **管理者**   | メンバーの招待・削除、ロールの変更、ブランディングとデフォルトの公開範囲の設定、およびメンバーができることすべて |
| **メンバー** | 自分のクリップの録画・編集・共有、追加されているスペースでの作業                                                 |
