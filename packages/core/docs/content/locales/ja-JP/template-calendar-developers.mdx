# 開発者ガイド

このページは、カレンダー テンプレートをカスタマイズしたり拡張したりする人のための
ものです。クイックスタート、すべての action、データモデル、ルートのサーフェス、
そして追加の仕方を扱います。アプリが何をするかについては
[カレンダー](/docs/template-calendar) を参照してください。

## クイックスタート

これは、何もインストールされていない状態から Google Calendar が接続された状態
まで、カレンダーを動かす手順を説明します。macOS の Terminal でも Windows の
PowerShell/コマンド プロンプトでも、コマンドは同一です。単純な Node.js の
ツール群だからです。

<Steps>

### アプリを作成する

```bash
npx @agent-native/core@latest create my-calendar --standalone --template calendar
cd my-calendar
pnpm install
```

これには [Node.js](https://nodejs.org) 22 以降と [pnpm](https://pnpm.io) が
事前にインストールされている必要があります。どちらもまだインストールしていない
場合や、LLM 接続 (Builder.io、Anthropic/OpenAI のキー、またはローカルの Ollama)
を設定していない場合は、[はじめに](/docs/getting-started) を参照してください。

### 開発サーバーを起動する

```bash
pnpm dev
```

アプリは `http://localhost:8082` で開きます。自動的に開かない場合は、その
URL をブラウザで開いてください。カレンダーは Google が未接続の状態でも完全に
動作します。接続する前にそれを必要とする action を試したときだけエラーになります。

### Google Calendar を接続する

アプリ内で **設定** を開き、**一般** タブで **Google Calendar** カードを見つけて、
**Google Calendar に接続** をクリックします。これでセットアップ ウィザードが
開きます。

1. **Google Cloud プロジェクトを作成する** (すでに使えるプロジェクトがない場合):
   [Google Cloud Console](https://console.cloud.google.com/) で、ページ上部
   近くのプロジェクト ドロップダウンをクリックし、**New Project** を選びます。
   任意の名前を付けて **Create** をクリックし、準備完了の通知を待ちます。続ける
   前に、同じドロップダウンでそのプロジェクトが選択されていることを確認してください。
2. **API を有効にする**: プロジェクトを選択した状態で **APIs & Services →
   Library** に移動し、「Google Calendar API」を検索して開き、**Enable** を
   クリックします。
3. **同意画面を設定する**: **APIs & Services → OAuth consent screen** で設定を
   行います (開発用途であれば「External」で構いません)。
4. **認証情報を作成する**: **APIs & Services → Credentials** で「Web
   application」タイプの OAuth クライアント ID を作成し、
   `http://localhost:8082/_agent-native/google/callback` を承認済みのリダイレクト
   URI として追加します (8082 はカレンダーの既定の開発用ポートです)。
5. **認証情報を追加する**: 認証情報の JSON をダウンロードしてウィザードに
   アップロードするか、「Paste manually」を切り替えてクライアント ID とクライアント
   シークレットを直接入力します。

カレンダーはこれらを `.env` ファイルではなく専用のシークレット ストアに保存する
ので、この手順は Windows と macOS で同一です。接続すると、トークンは自動的に
更新されます。

### Zoom を接続する (任意)

Google とは異なり、Zoom には設定フォームがありません。プロジェクトのルートに
`.env` ファイルを作成 (または既存のものに追加) し、以下を記述します。

```text
ZOOM_CLIENT_ID=your-client-id
ZOOM_CLIENT_SECRET=your-client-secret
```

[Zoom OAuth アプリ](https://marketplace.zoom.us/) (Zoom Marketplace →
Develop → Build App → OAuth) からクライアント ID とシークレットを取得し、
リダイレクト URI に `/_agent-native/zoom/callback` を設定してください。その後、
新しい値を反映させるために `pnpm dev` を再起動します。Zoom を接続していなくても、
予約リンクは Google Meet を提供できます。Zoom だけが使えなくなります。

</Steps>

<Callout tone="warning">

Windows では、一部のエディタが `.env` という名前のファイルを保存する際に隠れた
`.txt` 拡張子を追加してしまい、カレンダーが読み取らない `.env.txt` が残ることが
あります。エクスプローラーで「ファイル名拡張子」(表示タブ) を有効にして、保存
されたファイルの名前が `.env` そのままで、それ以降に何も付いていないことを
確認してください。

</Callout>

<Callout tone="info">

**イベントは Google Calendar に存在し、SQL には存在しません。** すべてのイベント
action は Google Calendar API を直接呼び出します。ローカルのイベントテーブルは
ありません。ローカルに保存されるのは予約リンク、予約、空き状況、接続状態だけです。
イベントデータを生の SQL で読み書きすることは絶対にしないでください。

</Callout>

## Action 一覧

すべての操作は `templates/calendar/actions/` にある TypeScript ファイルであり、
`POST /_agent-native/actions/:name` に自動的にマウントされます。

### イベントと出席者

イベント データは Google Calendar に存在し、SQL には決して存在しません。

| Action                   | 何をするか                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------------------ |
| `list-events`            | 指定した日付範囲のイベントを一覧表示する                                                               |
| `search-events`          | クエリでイベントを検索する                                                                             |
| `get-event`              | id で 1 件のイベントを読み取る                                                                         |
| `create-event`           | 繰り返し (RRULE)、勤務場所、ステータス種別 (`outOfOffice`、`focusTime`) を含め、イベントを作成する     |
| `update-event`           | 繰り返し、勤務場所、ステータス種別を含め、イベントを更新する                                           |
| `delete-event`           | イベントを削除する                                                                                     |
| `manage-event-draft`     | 何かが書き込まれたりゲストに通知されたりする前に、未送信の招待をユーザーのレビュー用にステージングする |
| `rsvp-event`             | 招待を承認、辞退、または未定としてマークする                                                           |
| `get-attendee-timezones` | ゲストごとのタイムゾーン オーバーライドを読み取る                                                      |
| `set-attendee-timezone`  | 現地時間が正しく表示され続けるように、ゲストごとのタイムゾーン オーバーライドを設定する                |

### 空き状況と時間の検索

| Action                | 何をするか                                                                                                     |
| --------------------- | -------------------------------------------------------------------------------------------------------------- |
| `get-availability`    | 週次スケジュール、タイムゾーン、バッファ、通知、事前予約可能期間の設定を読み取る                               |
| `update-availability` | 週次スケジュール、タイムゾーン、バッファ、通知、事前予約可能期間の設定を更新する                               |
| `check-availability`  | 1 日分の空きスロットを見つける                                                                                 |
| `find-a-time`         | 主催者と指定された出席者をまとめた共有の空きスロット検索。Google の空き/予定状況とローカルの競合を組み合わせる |

### 予約リンクと予約

| Action                   | 何をするか                                        |
| ------------------------ | ------------------------------------------------- |
| `create-booking-link`    | 予約リンクを作成する                              |
| `update-booking-link`    | 予約リンクを更新する                              |
| `duplicate-booking-link` | 共同ホスト (`hosts`) を含め、予約リンクを複製する |
| `list-booking-links`     | アクセス可能な予約リンクを一覧表示する            |
| `list-bookings`          | 確定した予約を一覧表示する                        |

### 外部カレンダー

読み取り専用の ICS フィード。

| Action                      | 何をするか                                   |
| --------------------------- | -------------------------------------------- |
| `add-external-calendar`     | 読み取り専用の ICS/webcal フィードを購読する |
| `list-external-calendars`   | 購読済みのフィードを一覧表示する             |
| `remove-external-calendar`  | 購読済みのフィードを削除する                 |
| `update-external-calendars` | 購読済みのフィードを更新する                 |

### 人物とオーバーレイ

| Action                  | 何をするか                                                     |
| ----------------------- | -------------------------------------------------------------- |
| `search-people`         | Google Contacts とワークスペースのディレクトリを検索する       |
| `get-overlay-people`    | あなたのビューに固定表示されている他の人のカレンダーを読み取る |
| `update-overlay-people` | あなたのビューに固定表示されている他の人のカレンダーを更新する |

### Zoom

| Action            | 何をするか                                                                                                                                                                       |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `get-zoom-status` | 現在のユーザーの Zoom 接続状態を読み取る。OAuth にはサインイン済みのブラウザ セッションが必要なため、接続と切断は action ではなく `/_agent-native/zoom/*` ルートを通じて行われる |

### Google Calendar の接続と同期

| Action                    | 何をするか                                                    |
| ------------------------- | ------------------------------------------------------------- |
| `connect-google-calendar` | サインイン済みのブラウザ セッション用の OAuth 接続 URL を返す |
| `sync-google-calendar`    | 再同期を強制する                                              |

### 設定と環境設定

| Action                               | 何をするか                                                                                       |
| ------------------------------------ | ------------------------------------------------------------------------------------------------ |
| `get-settings`                       | ユーザーレベルの設定を読み取る                                                                   |
| `update-settings`                    | ユーザーレベルの設定を更新する                                                                   |
| `update-calendar-visual-preferences` | ローカル限定の表示設定 (イベントの色、週末の非表示) を更新する。Google Calendar には一切触れない |

### ナビゲーションと UI 状態

| Action        | 何をするか                                  |
| ------------- | ------------------------------------------- |
| `navigate`    | UI をビュー、日付、またはイベントに移動する |
| `view-screen` | エージェントのために現在のビューを読み返す  |

### プロバイダー API へのエスカレーション

上記の actions では狭すぎる場合のための、生の Google Calendar (および接続された
CRM) API。

| Action                  | 何をするか                                                                     |
| ----------------------- | ------------------------------------------------------------------------------ |
| `provider-api-catalog`  | 直接呼び出せる生のプロバイダー API を一覧表示する                              |
| `provider-api-docs`     | 生のプロバイダー API エンドポイントのドキュメントを読み取る                    |
| `provider-api-request`  | 生の Google Calendar (または接続された CRM) API を直接呼び出す                 |
| `list-staged-datasets`  | 生の結果を返す代わりにクエリ用にステージングされた大規模スキャンを一覧表示する |
| `query-staged-dataset`  | ステージングされたデータセットをクエリする                                     |
| `delete-staged-dataset` | ステージングされたデータセットを削除する                                       |

## 1 つの action を詳しく見る

`create-booking-link` は、どの action でも再利用する価値のあるパターンを示して
います。データベースに触れる前に入力を検証すること、2 つのテーブルにわたって
ルールを強制すること、サインイン済みのユーザーを安全に解決すること、そして
柔軟な入力の形を各読み取り側でではなく一度だけ正規化することです。

## カスタマイズする

アプリのすべての部分は編集可能なソースです。ここから始めてください。

- `templates/calendar/actions/` — `defineAction` を使った新しいファイルを追加して、エージェントとフロントエンドの両方に新しい機能を公開します。
- `templates/calendar/app/routes/` — UI です。上に一覧があります。
- `templates/calendar/server/db/schema.ts` — Drizzle で列やテーブルを追加します。PGlite と Postgres で動作するよう、コードは PostgreSQL 対応にしてください。
- `templates/calendar/server/lib/` — プロバイダー統合: `google-calendar.ts`、`zoom.ts`、`people-search.ts`、`ical-fetcher.ts`、`find-time.ts`、`provider-api.ts`。
- `templates/calendar/AGENTS.md` — エージェントへの指示。エージェントに新しい機能や規則を教えるときはこれを更新してください。
- `templates/calendar/.agents/skills/` — エージェントが従う詳細なパターン。関連する skills: `event-management`、`availability-booking`、`real-time-sync`、`storing-data`、`delegate-to-agent`、`frontend-design`。
- `templates/calendar/shared/api.ts` — サーバーとクライアントの両方で使用される共有 TypeScript 型 (`CalendarEvent`、`BookingLink`、`ExternalCalendar`、`ConferencingConfig` など)。

機能を追加する場合は、UI、action、skill または AGENTS.md エントリ、そして
エージェントが確認する必要のあるアプリケーション状態という 4 つの領域すべてを
更新することを忘れないでください。それが、エージェントと UI を同等に保つ理由です。
