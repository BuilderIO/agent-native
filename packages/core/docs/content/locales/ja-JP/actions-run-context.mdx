# 実行コンテキスト

`run` は、オプションの第二引数 `ctx` を受け取ります。これは、解決済みのリクエスト ID と、そのアクションを呼び出したサーフェスを保持しています。`getRequestUserEmail()` / `getRequestOrgId()` を手動で呼び出す代わりにこれを読み取り、トラッキングには `ctx` 全体を渡してください。

```ts
export default defineAction({
  description: "Log an audit entry for the current request.",
  schema: z.object({ event: z.string() }),
  run: async (args, ctx) => {
    // ctx is undefined-safe: a 1-arg `run(args)` is still valid.
    const actor = ctx?.userEmail ?? "system";
    if (ctx?.caller === "frontend") {
      // tighter rules for browser-initiated calls, looser for "tool"/"cli"
    }
    await db.insert(audit).values({
      actor,
      orgId: ctx?.orgId ?? null,
      source: ctx?.caller ?? "unknown",
      event: args.event,
    });
    return { ok: true };
  },
});
```

ほとんどのアクションが読み取るのは `ctx?.userEmail` と `ctx?.orgId` だけで、これはほぼすべての実際のアクションで使われる[アクセス制御のスコープ設定](/docs/actions-access-control#access-control)です。このページの残りは、トラッキングや自動化の帰属といった横断的関心事を扱いますが、これらを必要とするアクションはより少数です。

## `ctx` 引数 {#ctx}

`ctx` は2種類の情報を運びます。ほぼすべての呼び出しに存在する解決済みのリクエスト ID (`userEmail`、`orgId`) と、アクションを呼び出したサーフェスに関するメタデータ (`caller`、および `threadId` や `automation` のような、特定の呼び出し元でのみ設定されるサーフェス固有のフィールド) です。`run()` の第二引数としての完全な形は次のとおりです。

`run()` は後方互換性を保ちます。既存の引数1つのハンドラーや、`{ send }` だけを分割代入するハンドラーは、変更なく動作し続けます。

### `caller` のユニオン型 {#caller}

`caller` は、`"tool" | "http" | "frontend" | "cli" | "mcp" | "a2a" | "automation"` のユニオン型です。

| `caller`       | 設定される条件                                                                                                                                                                                                |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `"tool"`       | アプリ内エージェント ループ、サブエージェントやエージェント チーム、または同じエージェント ループを駆動する自然言語のクロスアプリ A2A 委任。そのため、そのツール呼び出しは `"tool"` になります。              |
| `"frontend"`   | `useActionMutation()`、`useActionQuery()`、`callAction()` を介したブラウザからの呼び出し (`X-Agent-Native-Frontend: 1` ヘッダーでタグ付けされます)。                                                          |
| `"http"`       | フロントエンド マーカーのない、`/_agent-native/actions/<name>` への素のプログラム的な `POST` または `GET`。                                                                                                   |
| `"cli"`        | `pnpm action <name>` (CLI ランナー)。                                                                                                                                                                         |
| `"mcp"`        | MCP の `tools/call` エンドポイント経由の外部エージェント。                                                                                                                                                    |
| `"a2a"`        | 署名された A2A 委任トークンを伴う、`/_agent-native/actions/<name>` への直接の HTTP 呼び出し。これは明示的に公開された、クロスアプリのディスパッチであり、上記の自然言語による `"tool"` 経路とは区別されます。 |
| `"automation"` | 保存されたワークスペース トリガーからディスパッチされる、イベント トリガー型の自動化。`ctx.automation` がトリガーの系譜を保持します。[自動化](/docs/automations) を参照してください。                         |
