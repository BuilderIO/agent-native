# AIエージェントでアプリを作成する

AIエージェントにAgent-Nativeアプリの作成を依頼できます。プロンプトを1つ貼り付けると、エージェントがセットアップのコマンドを実行し、完了時に動作中のアプリを見せてくれます。

コマンドを自分で入力したい場合は、代わりに[はじめに](/docs/getting-started)に従ってください。

## 始める前に

- ターミナルコマンドを実行できるAIエージェント。たとえばClaude Code、Codex、Cursorです。ChatGPTやWeb版Claudeのようにチャットしかできないエージェントでも手伝えます。[コマンドを実行できないエージェント](#chat-only-agents)を参照してください。
- [Node.js](https://nodejs.org) 22.22以降。
- 新しいアプリを置くための空のフォルダ。

アプリを作成するのにAPIキーは必要ありません。アプリ自身のエージェントに回答してほしいときにだけ必要です。[LLMを接続する](/docs/getting-started#connect-an-llm)を参照してください。

## このプロンプトを貼り付ける

空のフォルダでエージェントを開き、下のプロンプトを貼り付けます。最初の行の`my-app`を好きな名前に変更してください。変更するのは1回だけです。

```markdown
my-app という名前の新しいフォルダに、新しい Agent-Native アプリを
作成して、起動してください。以下の手順の APP_NAME は、その名前に
読み替えてください。

1. Node.js がバージョン 22.22 以降であること、pnpm が使えることを
   確認してください。pnpm がない場合は `corepack enable` を実行
   してください。corepack も使えない場合は `npm install -g pnpm`
   を実行してください。Node.js が古い場合は、インストールせずに
   作業を止めて私に知らせてください。
2. 次のコマンドを実行してください:
   npx --yes @agent-native/core@latest create APP_NAME \
    --standalone --template chat
3. 新しくできた APP_NAME フォルダで `pnpm install` を実行して
   ください。
4. アプリの構成を把握するために APP_NAME/AGENTS.md を読んで
   ください。
5. `pnpm dev` でアプリを起動し、バックグラウンドで動かし続けて
   ください。
6. `pnpm dev` が表示するローカル URL を読み取ってください。
   `curl -I <url>` などで応答があることを確認してください。ブラウザは
   開かず、ヘッドレスブラウザのツールも使わないでください。アプリは
   私が自分で開きます。
7. 結果を見せてください。ローカル URL と、そこから得た応答を教えて
   ください。セットアップが完了したと言うだけで終わらせないで
   ください。

ルール:

- API キーを作り出したり、私に貼り付けるよう求めたりしないで
  ください。LLM の接続は任意で、私が自分で行います。
- どの .env ファイルの秘密情報も表示しないでください。
- コマンドが失敗したら、エラーと試したことを見せてください。
  隠さないでください。
```

## エージェントが行うこと

うまくいった場合は次の結果になります。それぞれ自分で確認できます。

- 新しいアプリのフォルダ。名前は変更していなければ`my-app`で、`actions/`、`app/`、`AGENTS.md`ファイルを含みます。
- エラーなく動作している`pnpm dev`。
- エージェントが応答することを確認したローカルURL。通常は`http://localhost:8080`です。

次に、ローカルURLを自分のブラウザで開きます。Welcome画面で**Continue as local dev**を選んでください。Get startedページが表示されます。

どれかが足りない場合は、エージェントに最後に実行したコマンドとその出力を見せるよう頼んでください。

<Callout tone="info">

コマンドがピア依存関係のエラーで失敗する場合は、npxキャッシュ内の古いパッケージが原因かもしれません。エージェントに`npx clear-npx-cache`を実行してもう一度試すよう頼んでください。

</Callout>

## エージェントに合ったセットアップを選ぶ

| エージェントの種類              | 例                                                  | 仕組み                                                                 |
| ------------------------------- | --------------------------------------------------- | ---------------------------------------------------------------------- |
| ターミナル型・IDE型エージェント | Claude Code、Codex、Cursor、VS CodeのGitHub Copilot | プロンプトを貼り付けます。エージェントがすべてのコマンドを実行します。 |
| チャット専用エージェント        | ChatGPT、Web版Claude                                | コマンドを教えてもらい、自分で実行します。                             |

### コマンドを実行できないエージェント {#chat-only-agents}

チャット専用エージェントはターミナルを開けないため、アプリを作成できません。それでもプロンプトを貼り付け、先頭に次の1行を追加してください。

```markdown
あなたはコマンドを実行できません。ターミナルで実行するコマンドを
1つずつ教えてください。次に進む前に、私が結果を伝えるのを
待ってください。
```

エージェントが同じ手順を案内し、問題が起きたときは助けてくれます。

## あなたのエージェントとアプリのエージェント

アプリには2つのエージェントが関わり、それぞれ役割が異なります。

- **あなた自身のエージェント**は、プロンプトを貼り付けたエージェントです。たとえばClaude Code、Codex、Cursorです。アプリの外側にあり、ターミナルやエディタで動きます。
- **アプリのエージェント**は、アプリに最初から組み込まれているチャットです。アプリの実行中にブラウザで開きます。

|                           | あなた自身のエージェント(アプリの外)                                                                                                 | アプリのエージェント(アプリの中)                                                                     |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| 使う場所                  | ターミナルまたはエディタ                                                                                                             | ブラウザ上のアプリのチャット                                                                         |
| 扱う対象                  | プロジェクトのファイル                                                                                                               | アプリのデータと、いま見ている画面                                                                   |
| できること                | プロジェクトの作成、パッケージのインストール、`pnpm dev`の実行、アクション・ページ・データベーステーブルの作成と変更、デプロイの準備 | アプリのアクションをツールとして呼び出し、アプリのデータを読み書きし、画面の内容について質問に答える |
| アプリにLLMの接続が必要か | 不要です。自分のモデルを使います                                                                                                     | 必要です。[LLMを接続する](/docs/getting-started#connect-an-llm)を参照してください                    |
| 向いている用途            | アプリの構築と変更                                                                                                                   | アプリの利用と日々の作業                                                                             |

あなた自身のエージェントがアプリを作り、アプリのエージェントがアプリを動かします。あなた自身のエージェントがアクションを追加すると、両者が同じアクションを使うため、アプリのエージェントはすぐにそのアクションを呼び出せます。

### あなた自身のエージェントがうまく作れるようにする

生成されたアプリは、追加の指示なしでもあなた自身のエージェントがうまく作業できるように設定されています。

- アプリのルートにある`AGENTS.md`は、アプリの構成と従うべきルールをエージェントに伝えます。
- `.agents/skills/`には、機能の追加やアクションの作成といった一般的な作業向けの短いガイドが入っています。
- お使いのフレームワークのバージョンに合ったドキュメントがアプリに同梱されています。エージェントは`pnpm action docs-search --query "<topic>"`で検索できます。

新しいことを依頼するときは、これらを先に読むようエージェントに伝えられます。たとえば「何かを変更する前に、AGENTS.mdと該当するスキルを読んでください」と伝えます。

あなた自身のエージェントに、コードではなく実行中のアプリのツールを使わせたい場合は、[外部エージェント](/docs/external-agents)を参照してください。

## 最初の変更を依頼する

アプリを動かした状態で、エージェントに小さな変更を依頼し、作業の様子を見てみましょう。例をいくつか紹介します。

```markdown
空のリストを返す list-notes という名前のアクションを追加し、
新しい /notes ページに表示してください。
```

```markdown
hello アクションを、"Hello" ではなく "Welcome" であいさつする
ように変更し、Alex を指定して呼び出して確認してください。
```

```markdown
アプリのデプロイに関するドキュメントを読んで、このアプリを
公開するために必要な手順を教えてください。
```

エージェントは、UIとアプリ自身のエージェントが使うのと同じアクションを変更します。この共有アクションモデルがあるため、1つの変更があらゆる場所に反映されます。全体のつながりは[主要な概念](/docs/key-concepts)で説明しています。
