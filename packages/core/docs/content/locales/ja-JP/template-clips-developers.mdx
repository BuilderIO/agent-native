# 開発者ガイド

このページは、クリップ テンプレートをカスタマイズしたり拡張したりする人のためのものです。クイックスタート、すべての action、データモデル、ルート サーフェス、そしてそれらを拡張する方法を説明します。アプリが何をするかについては [クリップ](/docs/template-clips) を参照してください。

## クイックスタート

<Steps>

### アプリを作成する

```bash
npx @agent-native/core@latest create my-clips --standalone --template clips
cd my-clips
pnpm install
```

これには、先に [Node.js](https://nodejs.org) 22.22 以降と [pnpm](https://pnpm.io) をインストールしておく必要があります。まだどちらもインストールしていない場合や、LLM 接続 (Builder.io、Anthropic/OpenAI のキー、またはローカルの Ollama) を設定していない場合は、[はじめに](/docs/getting-started) を参照してください。

### 開発サーバーを起動する

```bash
pnpm dev
```

アプリはブラウザで自動的に開きます。ブラウザまたはデスクトップ アプリがローカルでキャプチャするため、録画には追加の設定は不要です。ファイル ストレージや AI クレジットのどちらかが未設定のうちは、それを必要とする action でのみエラーになります。

</Steps>

<Callout tone="info">

録画、文字起こし、AI によるタイトル/概要が最初から最後まで機能するには、ファイル ストレージと AI クレジットの設定が必要です。**設定** から Builder.io を接続すると両方を一度に用意できます (無料プランにはマネージド AI クレジットが含まれます)。あるいは、S3 互換ストレージを別途接続し、文字起こし用に自分の Groq キーを持ち込むこともできます。[文字起こしと AI メタデータ](/docs/template-clips-features#transcription-and-ai-metadata) を参照してください。

</Callout>

## アクション一覧

すべての操作は `templates/clips/actions/` にある TypeScript ファイルで、`POST /_agent-native/actions/:name` に自動マウントされます。

### ライブラリと録画

| Action                                                                                    | 内容                                                         |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `list-recordings`、`search-recordings`                                                    | ライブラリ、共有されたもの、ゴミ箱、スペース単位での一覧表示 |
| `create-recording`、`finalize-recording`                                                  | 行の作成、アップロードの完了                                 |
| `import-loom-recording`                                                                   | Loom の動画、または直接の MP4/WebM URL をインポート          |
| `update-recording`                                                                        | タイトル、説明、パスワード、有効期限、公開範囲               |
| `move-recording`                                                                          | 1 件または複数の録画をフォルダやルートに移動                 |
| `archive-recording`、`trash-recording`、`restore-recording`、`delete-recording-permanent` | ライフサイクル: 隠す、ソフト削除、取り消し、完全に削除       |
| `reprocess-recording`                                                                     | シークできない、またはフリーズしたメディアの修復             |
| `generate-filmstrip`                                                                      | エディターのタイムライン フレーム スプライト                 |
| `tag-recording`、`set-thumbnail`                                                          | タグ付けと、手動で選んだサムネイル フレーム                  |

### フォルダとスペース

| Action                                            | 内容                                                     |
| ------------------------------------------------- | -------------------------------------------------------- |
| `create-folder`、`rename-folder`、`delete-folder` | 入れ子フォルダ。削除すると中身は上位に移動               |
| `create-space`、`rename-space`、`delete-space`    | 組織単位の、トピックベースの録画コンテナ                 |
| `add-recording-to-space`                          | スペースへの録画の追加・削除 (多対多)                    |
| `add-space-member`、`remove-space-member`         | スペース単位の閲覧者、コントリビューター、管理者のロール |

### 編集

| Action                                   | 内容                                                                     |
| ---------------------------------------- | ------------------------------------------------------------------------ |
| `trim-recording`、`split-recording`      | カットの指示を重ねる。元のメディアには一切触れない                       |
| `remove-silences`、`remove-filler-words` | エージェントが実行: トランスクリプトを読み取り、代わりにトリムを適用する |
| `stitch-recordings`                      | 複数の録画を順番どおりに 1 つに結合する                                  |
| `undo-edit`、`clear-edits`               | 直前の編集を取り消す、または元の状態にリセットする                       |

### 文字起こしと AI メタデータ

| Action                                                                          | 内容                                                    |
| ------------------------------------------------------------------------------- | ------------------------------------------------------- |
| `request-transcript`、`cleanup-transcript`                                      | 文字起こしを行う。`force`/`regenerate` で新規にやり直す |
| `regenerate-title`、`regenerate-summary`、`regenerate-chapters`、`set-chapters` | AI メタデータの生成、またはチャプターを手動で設定       |
| `get-builder-credit-status`                                                     | Builder.io の AI クレジットが一時停止しているかどうか   |

### コメントとリアクション

| ---------------------------------------------------------------------------------------- | ----------------------------------------------- |

## action を読み解く

`create-recording-agent-link` は、スコープ付きの認証情報を発行するどの action にも再利用する価値のあるパターンを示しています。何かを渡す前にリソースの実際の状態を確認すること、実際のトークン発行を自前で作るのではなく共有フレームワークのヘルパーに委譲すること、そして呼び出し元が必要とするすべての URL をその 1 つの grant から導出することです。

  title="スコープ付き agent-access リンクの発行"
  filename="templates/clips/actions/create-recording-agent-link.ts"

  code={
    'import { defineAction } from "@agent-native/core/action";\nimport {\n  buildAgentAccessUrl,\n  createScopedAgentAccessGrant,\n  getRequestContext,\n  getRequestUserEmail,\n} from "@agent-native/core/server";\nimport { ForbiddenError, resolveAccess } from "@agent-native/core/sharing";\nimport { z } from "zod";\n\nimport {\n  CLIPS_AGENT_ACCESS_TTL_SECONDS,\n  getServerAppBasePath,\n} from "../server/lib/public-agent-context.js";\nimport {\n  buildAgentApiUrls,\n  CLIP_AGENT_ACCESS_TOKEN_PREFIX,\n} from "../shared/agent-context.js";\nimport { BUG_REPORT_AGENT_ACCESS_TTL_SECONDS } from "../shared/bug-report.js";\n\nfunction appOrigin(): string {\n  const origin =\n    getRequestContext()?.requestOrigin ||\n    process.env.APP_URL ||\n    process.env.BETTER_AUTH_URL ||\n    "http://localhost:3000";\n  try {\n    return new URL(origin).origin;\n  } catch {\n    return "http://localhost:3000";\n  }\n}\n\nexport default defineAction({\n  description:\n    "Create a temporary private agent-readable link for one Clips recording. The URL is scoped to that recording and expires after two hours.",\n  schema: z.object({\n    recordingId: z.string().describe("Recording ID"),\n    agentLabel: z\n      .string()\n      .trim()\n      .min(1)\n      .max(60)\n      .optional()\n      .describe(\n        "Name of the agent that will read this link (e.g. \'Fusion\', \'Claude Code\'). Recorded against every read the link produces, so the owner sees a name instead of an unidentified agent.",\n      ),\n    ttlSeconds: z\n      .number()\n      .int()\n      .positive()\n      .max(BUG_REPORT_AGENT_ACCESS_TTL_SECONDS)\n      .optional()\n      .describe(\n        "Optional scoped-link lifetime in seconds, capped at seven days. Defaults to two hours.",\n      ),\n  }),\n  readOnly: true,\n  run: async (args) => {\n    const access = await resolveAccess("recording", args.recordingId);\n    if (!access) {\n      throw new ForbiddenError(`No access to recording ${args.recordingId}`);\n    }\n\n    const recording = access.resource as {\n      id: string;\n      archivedAt?: string | null;\n      trashedAt?: string | null;\n    };\n    if (recording.archivedAt || recording.trashedAt) {\n      throw new ForbiddenError(\n        `Recording ${args.recordingId} is not shareable`,\n      );\n    }\n\n    const grant = createScopedAgentAccessGrant({\n      resourceKind: CLIP_AGENT_ACCESS_TOKEN_PREFIX,\n      resourceId: recording.id,\n      viewerEmail: getRequestUserEmail() || undefined,\n      agentLabel: args.agentLabel,\n      ttlSeconds: args.ttlSeconds ?? CLIPS_AGENT_ACCESS_TTL_SECONDS,\n    });\n    const origin = appOrigin();\n    const basePath = getServerAppBasePath();\n    const pageUrl = buildAgentAccessUrl({\n      path: `/share/${encodeURIComponent(recording.id)}`,\n      origin,\n      basePath,\n      token: grant.token,\n    });\n    const api = buildAgentApiUrls(recording.id, {\n      origin,\n      basePath,\n      token: grant.token,\n    });\n\n    return {\n      recordingId: recording.id,\n      url: pageUrl,\n      contextUrl: api.contextUrl,\n      expiresAt: grant.expiresAt,\n      ttlSeconds: grant.ttlSeconds,\n    };\n  },\n});\n'

## カスタマイズする

アプリのあらゆる部分が編集可能なソースです。ここから始めましょう。

- `templates/clips/actions/` — `defineAction` を使って新しいファイルを追加すると、エージェントとフロントエンドの両方に新しい機能を公開できます。
- `templates/clips/app/routes/` — UI。上に一覧があります。
- `templates/clips/server/db/schema.ts` — Drizzle でカラムやテーブルを追加します。テンプレートがローカルの PGlite とホスト型 Postgres の両方で動作するように、スキーマは PostgreSQL 互換に保ってください。
- `templates/clips/server/lib/` — プロバイダー連携: `google-calendar-client.ts`、`s3-upload-provider.ts`、`slack-oauth.ts`、`video-remux.ts`、`video-filmstrip-sprite.ts`。
- `templates/clips/AGENTS.md` — エージェントへの指示。エージェントに新しい機能や規約を教えるときは、これを更新してください。
- `templates/clips/.agents/skills/` — エージェントが従う詳細なパターン。関連する skills: `recording`、`ai-video-tools`、`video-editing`、`video-sharing`、`screen-memory`。
- `templates/clips/shared/api.ts` — サーバーとクライアントの両方で使われる共有 TypeScript 型。
- `templates/clips/desktop/` と `templates/clips/chrome-extension/` — ネイティブ キャプチャ サーフェス用の独立したパッケージで、それぞれ独自の `package.json` とビルドを持ちます。

機能を追加するときは、4 つの領域すべてを更新することを忘れないでください: UI、action、skill または AGENTS.md の項目、そしてエージェントが見る必要のあるアプリケーション状態です。これが、エージェントと UI を対等に保つ方法です。
