# 開発者ガイド

このページは、スライド テンプレートをカスタマイズしたり拡張したりする人のためのものです。SQL データモデル、同時に書き込む相手を安全に保つ方法、エージェントが呼び出せるすべての action、ルート マップ、そしてよく変更する場所を扱います。

## クイックスタート

```bash
npx @agent-native/core@latest create my-slides --standalone --template slides
```

残りのセットアップ (`cd`、`pnpm install`、`pnpm dev`) とフレームワークの基礎については、[はじめに](/docs/getting-started) を参照してください。

## 永続化モデル

各デッキは `decks.data` の中の 1 つの JSON ブロブです。すべての書き込みは、デッキごとのロックを保持するサーバー側の read-modify-write action を経由します。そのため、同じデッキの異なるスライドに触れる複数の書き込み者、つまり人間とエージェント、あるいは 2 人の人間が、互いの作業を上書きすることはありません。

- **エージェントの actions** (`add-slide`、`update-slide`) は、それぞれ専用の細粒度の action を使い、同じロックを共有します。
- **ブラウザ エディター** は、デッキ全体を PUT する代わりに、`patch-deck` を通じて細粒度の操作 (`patch-slide`、`delete-slide`、`reorder-slides`、`add-slide`、`patch-deck-fields`) をキューに入れます。

<Callout id="doc-block-slides10" tone="warning">

エディターの保存パスを拡張する場合は、`patch-deck` を通じて新しい操作をキューに入れてください。デッキ全体の新しい PUT を追加しないでください。それでは、このロックが防いでいる「最後に書いた者が勝つ」競合を再び持ち込んでしまいます。

</Callout>

フレームワークの共有テーブル (`deck_shares`、`design_system_shares`) は、リソースごとにプリンシパル (ユーザーまたは組織) を閲覧者/編集者/管理者の役割にマッピングし、手書きではなく共有の `createSharesTable` ヘルパーを通じて作成されます。

#### スライドの構造

`decks.data` の中の各スライドは次のとおりです。

```json
{
  "id": "slide-1",
  "layout": "title",
  "content": "<div class=\"fmd-slide\" style=\"...\">...</div>"
}
```

`content` は生の HTML です。レンダラーは固定のアスペクト比と背景を提供し、HTML はその内側のすべてを提供します。豊富な埋め込みもサポートされています。手描きの図やライブでレンダリングされるチャートを、通常の HTML と並べてスライドの中に置くことができます。

## Action 一覧

### デッキのライフサイクル

- `create-deck` — 新しいデッキ。任意でスライドを事前に入れておくことも、既存デッキのスライドをアトミックに一括置換することもできます。空のデッキにするには `slides` を省略するか `[]` を渡します。この action はアプリケーション状態を通じて新しいデッキを開きます。
- `get-deck` — デッキ全体の JSON、またはコンパクトなスライド概要ビュー
- `list-decks` — 呼び出し元が見られるすべてのデッキ。安価なポーリングのための light/compact/full-slide の射影付き
- `duplicate-deck` — 新しいスライド id でデッキを複製する
- `update-deck-aspect-ratio` — 16:9、1:1、9:16、または 4:5

`add-deck`、`save-deck`、`delete-deck` は、ブラウザ エディターの楽観的な作成、取り消し/やり直し、削除のフローを支えています。エージェントは代わりに `create-deck`、`add-slide`/`update-slide`/`patch-deck`、そしてフレームワーク自体の共有 actions を使います。

### アクセス リクエスト

- `request-deck-access`、`approve-deck-access-request`、`get-deck-access-status` — 非公開デッキへのアクセス リクエスト フローです。アクセス権のない訪問者がリクエストし、所有者がアプリまたは `/access-request/approve` ルートから承認または拒否し、どちらの側からも現在の状態をポーリングできます。

### スライドの編集

- `add-slide` — 1 つのスライドを末尾に追加する (または指定した位置に挿入する)。エディターが進行状況を表示できるように、空の `create-deck` の後に順番に呼び出します。
- `update-slide` — 外科的な検索/置換、またはスライド全体のコンテンツ編集
- `patch-deck` — デッキ全体の PUT の代わりにブラウザ エディターが使う、細粒度の操作キュー
- `get-layout-overflows` — ブラウザで計測されたスライドの収まり具合の結果を読み取り、レイアウトに収まらなくなった編集を検知して修正できるようにする

### 履歴

- `list-deck-versions`、`get-deck-version`、`restore-deck-version` — すべての書き込みは先にスナップショットを取るので、どの時点でも一覧表示し、復元できます

### コメント

- `list-slide-comments`、`add-slide-comment`、`update-slide-comment`、`delete-slide-comment`

### インポート

- `import-pptx`、`import-docx`、`import-google-doc` — 単一形式専用のインポーター
- `import-google-slides-reference` — Google Slides のデッキを、作業中のデッキにコンテンツを取り込むのではなく、再利用可能な参照デッキとしてインポートする
- `import-file` — PPTX、DOCX、PDF、または Figma の `.fig` ファイル (これはスライドのインポートではなく Builder のデザイン システム インデックス作成に振り分けられます) のための単一のエントリ ポイント
- `extract-pdf` — PDF の生テキストを取り出す CLI 専用の機能で、主にローカルでのデバッグ用

### エクスポート

- `export-pptx` — ネイティブで編集可能な PowerPoint
- `export-google-slides` — 同じ PPTX と、すぐに使える Google Slides インポート用リンクを生成する
- `export-html` — キーボード ナビゲーションを内蔵した、スタンドアロンの自己完結型 HTML ファイル

### デザイン システム

- `create-design-system`、`update-design-system`、`delete-design-system`、`get-design-system`、`list-design-systems`、`set-default-design-system`、`apply-design-system` (デッキに 1 つをリンクする)
- `get-workspace-defaults`、`set-workspace-defaults` — ワークスペース全体の既定デッキと既定デザイン システム。設定できるのは管理者だけです
- `analyze-brand-assets`、`import-document`、`import-from-url`、`import-code` — **ローカル** で、エージェントが草案を作るデザイン システムのために、生のブランド情報 (Web サイトの CSS/フォント、アップロードされたドキュメントやコード ファイルの内容) を収集する
- `index-design-system-with-builder`、`sync-design-system-with-builder`、`import-design-project` — Figma ファイル、接続されたコード/GitHub リポジトリ、`design.md` のための Builder インデックス化パス。`import-design-project` は、生のソースではなく既存のデザイン システムから始まります

### Creative Context

- `clone-context-slide` — Creative Context ライブラリに固定された 1 枚のスライドを、HTML/CSS を再生成せずにそのままデッキに挿入する
- `clone-creative-context-deck` — 統制された正確な 1 つのデッキ バージョンを再現する
- `get-deck-reference-context` — 既存デッキのビジュアル言語を、再利用可能なパターン ライブラリとして抽出する
- 検索や、Creative Context ライブラリへの提出 (検索、コンテキスト項目の取得、ライブラリ メンバーシップの管理) は、Creative Context をサポートするすべてのアプリでエージェントが同じ方法で呼び出す、フレームワーク共有の actions です。検索手順と再利用のはしごについては `creative-context` skill を参照してください。

### エスカレーションとステージング済みデータ

- `provider-api-catalog`、`provider-api-docs`、`provider-api-request` — 用意された import/export の action では狭すぎる場合の、生の Google Drive API アクセス。スライドは、ユーザーが接続した Google ドキュメント アカウントから認証を解決します
- `list-staged-datasets`、`query-staged-dataset`、`delete-staged-dataset` — 大きなプロバイダーの結果を再取得せずに集計する、ステージング機能

### ナビゲーションとコンテキスト

- `view-screen` — ユーザーが現在見ているもの。開いているデッキ、現在のスライド、アクティブな視覚的選択
- `navigate` — UI をデッキ、スライド、またはビューに移動する

## カスタマイズする

スライド テンプレートは完全にカスタマイズ可能です。拡張するときに確認すべき主な場所は次のとおりです。

#### Actions — `templates/slides/actions/`

エージェントが呼び出し可能なすべての操作は、TypeScript ファイルとしてここに存在します。`POST /_agent-native/actions/:name` に自動的にマウントされ、CLI から `pnpm action <name>` として呼び出せます。ここに新しいファイルを追加して、エージェントに新しい機能を与えます。

エディターの UI カスタマイズの大部分は `app/components/editor/` の下で行われます。スライド キャンバス、ツールバー、サイドバー、バブル メニュー、スラッシュ メニュー、履歴パネルです。

#### Skills — `templates/slides/.agents/skills/`

エージェントがコードを変更する必要があるときにパターンを説明する、エージェント skills です。

- `create-deck` — 新しいデッキの作成方法。すべてのレイアウトの正確なスライド HTML テンプレート付き
- `slide-editing` — 個々のスライドの編集方法
- `deck-management` — デッキの保存方法とアクセス方法
- `design-systems` — デザイン システムのデータ形式と、トークンが生成されたスライドにどのように適用されるか
- `creative-context` — 再利用のはしご、検索手順、Creative Context ライブラリへの提出

#### AGENTS.md

`templates/slides/AGENTS.md` は、エージェントがすべての会話で読み取る短いルーターです。これは `.agents/skills/` の下の skills を指し、コア ルール、永続化モデル、アプリケーション状態のコントラクトをレイアウトします。スライドのレイアウトやデザイン システムのソースを追加または変更するたびに、関連する skill を更新してください。
