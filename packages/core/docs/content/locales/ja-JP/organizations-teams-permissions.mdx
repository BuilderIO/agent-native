# 組織、チーム、権限

組織はチームメンバーとテナント境界を定義します。ワークスペースはアプリとデプロイ設定をまとめますが、組織の代わりにはなりません。権限はサーバーで確認します。ボタンを隠すだけではアクセス制御になりません。

## 3 つのロール範囲

- 組織の `owner`、`admin`、`member` はチーム管理を制御します。メールドメインによる自動参加はオーナーと管理者が管理し、アプリ間で共有する A2A シークレットはオーナーだけが管理します。
- アプリロールは 1 つのアプリ内の操作を制御します。メンバーは複数のロールを持てます。
- リソースロール `viewer`、`editor`、`admin` は 1 レコードへのアクセスを制御します。

アプリのコードでロールと権限キーを宣言します。管理者はチーム画面でメンバーのロールセットを置き換え、宣言済みの権限をロールに割り当てられます。上書きがない場合はアプリの既定値が使われます。招待にはアプリロールを含められます。アプリ管理者になっても組織管理権限は付与されません。

招待と設定は[管理デプロイ](/docs/administered-deployments)、データアクセスは[データスコープ](/docs/security#data-scoping)を参照してください。

## 任意で有効にする権限ポリシー

既定では、権限チェックを通過するにはアプリロールの割り当てが必要です。`defineAppRoles` の任意の第2引数で、サーバー側のポリシーを変更できます。Forms は次の設定を使用します。

```ts
const formsAccess = defineAppRoles(
  {
    appId: "forms",
    roles: ["editor", "reviewer"] as const,
    permissions: {
      "forms.edit": ["editor"],
      "forms.review": ["editor", "reviewer"],
    },
  },
  { unassignedRole: "editor", allowOrgAdmins: true },
);
```

- `unassignedRole` は、アプリロールの割り当てがない有効なメンバーに、宣言済みロールの権限を適用します。権限の上書き設定も引き続き適用されます。割り当ては作成されず、削除されたメンバーや、廃止されたロールだけを含む割り当てには適用されません。すべての割り当てを削除すると、この既定の動作に戻ります。
- `allowOrgAdmins: true` は、組織の有効な所有者と管理者が、アプリロールや権限の上書き設定に関係なく、宣言済みアプリ権限のチェックを通過できるようにします。アプリ管理者に組織の管理権限を与えるものではありません。

これらのオプションが影響するのは `requirePermission` と `assertPermission` だけです。`resolve`、`requireAny`、`assertAny` は引き続き明示的な割り当てを使用し、`defaultRole` は表示専用です。オプションを省略すると厳格なポリシーが維持されます。どちらもリソースの認可を置き換えません。`accessFilter` と `assertAccess` のチェックを維持してください。

Forms は、ロール未割り当ての既存メンバーの編集アクセスを維持します。明示的に割り当てられた Reviewer は送信内容をレビューできますが、フォームは編集できません。Editor は両方を行えます。アクセスできるフォームと送信内容は、引き続きリソース共有によって決まります。

## ユーザーグループ {#user-groups}

組織には、現在のメンバーで構成する再利用可能なユーザーグループを作成できます。オーナーと管理者がメンバーを管理し、1 人のユーザーが複数のグループに所属できます。アプリは、グループ共有に対応したリソースの共有や、ワークスペース接続へのアクセス制限にグループを使えます。

グループはアクセスリストであり、子チームではありません。独自の組織ロールやアプリロール、別のデータ境界、チーム固有の設定、指示、コンテキスト、スキル、メモリ、作業ビューはありません。グループにリソースを共有すると、そのリソースの共有ロールが現在の全メンバーに適用されます。アクセスには引き続き、そのリソースの組織への所属が必要です。

詳しくは[共有とプライバシー → グループ共有](/docs/sharing#group-grants)と[ワークスペース接続](/docs/workspace-connections)を参照してください。
