# 既存アプリをCore 0.197.0へアップグレードする

この手順に沿って、既存アプリをCore 0.197.0へ移行します。アプリまたは
workspaceのルートでコマンドを実行し、開始前にレビュー可能な差分を
用意してください。リモートのデプロイ設定は別途確認します。CLIは
ローカルの環境ファイルを読み取れますが、リモート環境やデータベースに
保存された機能設定は確認できません。

## 1. アップグレードとimport codemodをプレビューする

Core 0.197.0に含まれるCLIを使い、このreleaseのmigration manifestを
読み込みます。

    npx @agent-native/core@0.197.0 upgrade --codemods --dry-run

アプリに Core 0.197.0 をインストールした後は、同じプレビューをローカル CLI バイナリから実行できます。

    npx agent-native upgrade --codemods --dry-run

`--codemods` コマンドは `ts-morph` を使います。アプリからまだ解決できない場合は、先に開発依存関係としてインストールしてください: `pnpm add -D ts-morph`。

`--codemods` は、サポートされる import の変更を既定で適用します。依存関係の変更案、
ファイル差分、警告を事前に確認するには `--dry-run` を追加してください。`--yes` は不要になりました。

codemodはCoreとToolkitの有効なmigration manifestを使います。.tsと
.tsxファイルだけ（宣言ファイル、生成物、依存関係ディレクトリを除く）を
走査し、対応するimportとre-exportのspecifierを書き換えます。named
exportが複数のmoduleへ移動する場合、symbolごとに宣言を分割し、aliasと
type-only importを保持できます。単純なCSSの@import pathも書き換え、
解決できた移動でpackage境界を越える場合は不足するdependencyを追加
します。

呼び出し箇所は変更せず、ファイルも移動しません。解決できない移動や
plannedの移動は警告を出してそのまま残します。default、namespace、
side-effect、star形式のimport/exportは分割できません。symbol単位のCSS importも分割できません。これらは手動で
確認してください。削除されたexportにはコード変更が必要な場合が
あります。CLIの警告に記載されたmigration guideを確認してください。

プレビューにはupgrade全体の計画も含まれます。upgradeを止めるframework
overrideやpatch、保留中の@agent-native/\* version更新、ローカル設定から
判定されたfeature dependency、package managerによるinstall、scaffold
skillの更新、root packageにscriptがある場合のtypecheckが表示されます。
コマンドはpackage specをregistryの現在のlatestに変更し、install後に
解決されたversionをpinします。0.197.0が意図する最新releaseである
タイミングで実行してください。後日、正確なversionが必要な場合は
解決されたpinを確認します。

## 2. Toolkit とオプションパッケージを確認する

`@agent-native/toolkit/*` に移動した import には `@agent-native/toolkit` が必要です。対応済みで解決可能な import または export を移動すると、codemod が Toolkit を追加します。アプリが Toolkit の export を使っていて依存関係が追加されなかった場合は、Core 0.197.0 に対応する Toolkit のバージョンをインストールしてください。

    pnpm add @agent-native/toolkit@0.197.0
    # npm install @agent-native/toolkit@0.197.0
    # yarn add @agent-native/toolkit@0.197.0

### アップグレード CLI が選択する依存関係

ローカル環境の検査条件に一致すると、CLI は次の依存関係を追加します。PGlite では、正規化したアプリ名の `${APP_NAME}_DATABASE_URL` を先に確認し、次に `DATABASE_URL` を確認します。URL がないか `pglite:` で始まる場合に PGlite を選びます。リモート環境やデータベース内の機能設定は確認できないため、本番環境とプレビュー環境を別途確認してください。

| 機能                                      | オプションパッケージ         | バージョン              | CLI が確認するローカル設定                                                                  |
| ----------------------------------------- | ---------------------------- | ----------------------- | ------------------------------------------------------------------------------------------- |
| PGlite データベース                       | @electric-sql/pglite         | ^0.5.8                  | 正規化した `${APP_NAME}_DATABASE_URL`、次に `DATABASE_URL`。未設定または `pglite:` で始まる |
| サーバー Sentry                           | @sentry/node                 | ^10.60.0 または ^11.0.0 | `SENTRY_SERVER_DSN`、`SENTRY_DSN`、または Sentry のキー一式                                 |
| ブラウザー Sentry                         | @sentry/browser              | ^10.60.0 または ^11.0.0 | クライアント Sentry DSN、`SENTRY_DSN`、またはキー一式                                       |
| ビルド時の Sentry source map アップロード | @sentry/vite-plugin          | ^5.4.0                  | `SENTRY_AUTH_TOKEN`、organization、project が設定済み                                       |

組み込みテンプレートのソース検索を使う場合は、対応するバージョンのコーパスパッケージを開発依存関係として追加します: `pnpm add -D @agent-native/core-corpus@0.197.0`。

## 3. アップグレードを適用する

プレビューとfeature packageを確認したら計画を適用します。

    npx @agent-native/core@0.197.0 upgrade --codemods --yes

この1つのcommandで、対象となる@agent-native/\* dependency specを更新し、
検出したfeature dependencyを調整し、package managerを実行し、解決した
Agent-Native versionをpinし、対応codemodを適用します。さらにscaffold
skillを更新し、rootにtypecheck scriptがあれば実行します。codemod適用
だけを目的にupgradeをもう一度実行する必要はありません。警告や
アプリ固有のエラーはアプリのコードで修正してください。frameworkの
overrideやpatchは追加しないでください。

## 4. 結果を検証する

差分全体、特にcodemodがスキップした警告とdependency versionを確認し、
次を実行します。

    npx @agent-native/core@0.197.0 upgrade check
    pnpm typecheck

npmまたはYarnでは対応するtypecheck commandを使い、アプリに必要な
testとbuildも実行します。ローカルおよびデプロイ済みのfeature設定が
任意peerの表で網羅されていることを確認します。次の表にある旧importを
検索してください。残った一致は意図的なもの、manifest非対応のもの、
または警告で説明されたものに限ります。
