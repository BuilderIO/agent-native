# アプリ間 SSO

ブラウザ向けの「Sign in with Agent-Native」オプションと自動ブラウザ転送は
削除されました。Web ユーザーにはアプリごとの通常ログインが引き続き
既定の動作です。このページでは、残る Desktop とサーバー側フェデレーション
の契約だけを説明します。

## 残る機能

### Desktop ワークスペース

ワークスペースへのログインは Desktop 設定で明示的に実行します。有効に
すると、Desktop は専用ブローカーを通じて条件を満たす登録済みアプリを
プロビジョニングできます。各対象アプリは独自のユーザーストア、セッション、
アクセスチェックを保持します。Desktop はアプリのログインページへの
匿名ブラウザナビゲーションを横取りしません。

アプリが対象になるには、次の条件をすべて満たす必要があります。

- Desktop がそのアプリのワークスペース SSO を有効にしている。
- 本番 URL が正確な HTTPS である。
- Dispatch にそのアプリの正確なサーバー登録がある。
- <code>desktop.workspace-sso</code> ロールアウトフラグが有効である。

デバイス単位の <code>desktopSsoEnabled</code> は既定で有効です。明示的な
false はオプトアウトとして残ります。フラグ、設定、登録、または適格性
チェックが利用できない場合は、通常のアプリ別ログインを利用できます。

### サーバー側フェデレーション

残るブローカーとサーバー側の呼び出し元は、短時間だけ有効なサーバー検証
プロトコルを使います。ブラウザのログイン操作として公開されません。

1. 呼び出し元が登録済みアプリへの正確なバインディングを要求します。
2. Dispatch がワークスペース ID を認証し、短時間だけ有効な一回限りの
   認可コードを返します。
3. 対象アプリのサーバーが PKCE 検証子でコードを交換します。
4. 対象アプリが署名済みアサーション、アプリ、コールバック、スコープ、
   nonce、有効期限を検証します。
5. 検証済みメールアドレスでローカルユーザーをリンクまたは作成し、通常の
   ローカルセッションを発行します。

アサーションはサーバー間交換でのみ返されます。ブラウザ URL には現れず、
再利用可能な bearer token でもありません。

## 組織フェデレーション

<code>organization.cross-app-federation</code> フラグは既定で無効です。有効に
すると、ソースアプリは Dispatch にローカル組織を登録し、正確な
<code>(identity_authority, identity_id)</code> マッピングを保存します。
ターゲットアプリは、サーバー検証済みアサーションからの正規組織 ID、名前、
検証済みメンバー役割だけを受け入れます。

組織名、メールドメイン、ブラウザ Cookie は結合キーではありません。マッピング
のないローカル組織は明示的な移行まで変更されません。リンク済みメンバーシップ
にはターゲットアプリの通常のアクセスチェックが適用されます。

組織フェデレーションでは登録済みソースアプリごとに別の認証情報を使います。

- ソースアプリに <code>AGENT_NATIVE_IDENTITY_FEDERATION_SECRET</code> を設定します。
- Dispatch に対応する
  <code>AGENT_NATIVE_IDENTITY_FEDERATION_SECRET_&lt;APP_ID&gt;</code> を設定します。
- この権限境界で <code>A2A_SECRET</code> を再利用しないでください。

ID と組織の書き込みは追加のみです。同じメールアドレスの既存ユーザーは変更
せずに再利用されます。新しい検証済みメールアドレスではローカルユーザーを
作成します。フェデレーションを無効にしてもデータは削除されません。

## 設定

<code>AGENT_NATIVE_IDENTITY_HUB_URL</code> は、自ホストアプリが明示的な
Dispatch デプロイメントを必要とする場合に、残るサーバー側と Desktop の
経路だけで使います。ブラウザログインの選択肢や自動転送は追加しません。

自ホストの Dispatch では、<code>IDENTITY_SSO_APP_REGISTRY_JSON</code> を使って
各カスタムアプリに正確なアプリ ID、クライアント ID、HTTPS オリジン、
コールバックパス、<code>identity-sso</code> 機能を登録します。

本番登録では HTTPS と正確なコールバックパスを使う必要があります。Localhost
はローカル開発だけで許可されます。不明なサブドメイン、不一致のアプリ ID、
任意のパス、クロスオリジンのコールバックは拒否されます。

## 検証とロールバック

デプロイ後:

1. ブラウザでメール、パスワード、マジックリンク、設定済みプロバイダーの
   ログインが引き続き機能することを確認します。
2. ブラウザの認証画面に Agent-Native ログインの選択肢がないことを確認します。
3. Desktop SSO を有効にした場合は、Desktop 設定の明示的な操作から正確に
   登録されたアプリを 1 つ確認します。
4. 組織フェデレーションを有効にした場合は、対象アプリで正確な組織 ID と
   メンバー役割を確認します。

残る経路を戻すには、該当する機能フラグを無効にし、自ホストのデプロイメント
から <code>AGENT_NATIVE_IDENTITY_HUB_URL</code> を削除して再デプロイします。
追加された ID と組織のレコードは通常のローカル認証で引き続き利用できます。
