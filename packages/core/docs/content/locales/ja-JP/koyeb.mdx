# Koyeb

<Badge label="Beta" color="orange" icon="rocket" />

Koyeb がアプリを Web サービスとしてホストしてくれるため、サーバーを用意したり動かし続けたりする必要はありません。Koyeb は [Node.js ガイド](/docs/node-js)で説明しているものと同じ Node.js サーバーを実行し、GitHub リポジトリからそれをビルドします。また、Koyeb はアプリに HTTPS 対応の公開アドレスを割り当てます。

このガイドでは、スタンドアロン アプリを 1 つ、ゼロからデプロイする手順を説明します。アプリを作成して GitHub にプッシュし、本番用のデータベースと認証シークレットを用意し、データベースを準備してから、アプリをビルドして実行する Koyeb の Web サービスを作成します。

<Callout tone="info">

Node.js `22.22+` が必要です。

</Callout>

Koyeb アカウントと GitHub リポジトリも必要です。このガイドのコマンドは自分のコンピューター上で実行してください。アプリのビルドと実行は、Koyeb がリポジトリから行います。

## ステップ 1: アプリを作成する {#step-1-create-the-app}

新しいスタンドアロン アプリを作成します。以下の例では Chat テンプレートからアプリを作成していますが、どのテンプレートから始めてもかまいません。アプリのフォルダーに移動し、依存関係をインストールします。`corepack enable` はアプリが想定する `pnpm` のバージョンを有効にするため、`pnpm` を自分でインストールする必要はありません。

```bash
npx --yes @agent-native/core@latest create my-app --standalone --template chat

cd my-app

corepack enable

pnpm install
```

必要に応じて、`my-app` を自分のアプリ名に置き換えてください。このガイドの以降の手順は、アプリのフォルダー内にいることを前提としています。

Koyeb は GitHub からアプリをビルドするため、先に進む前に、アプリのフォルダーを新しい GitHub リポジトリにプッシュしてください。`pnpm-lock.yaml` ファイルもコミットしてください。Koyeb はこのファイルと `package.json` の `packageManager` フィールドを使って、`pnpm` でアプリをインストールします。また、Node.js のバージョンは `package.json` の `engines` フィールドから読み取ります。新しいアプリでは、どちらのフィールドもすでに設定されています。

<Callout tone="info">

これらのコマンドがピア依存関係のエラーで失敗する場合は、npx キャッシュ内の古いパッケージが原因の可能性があります。`npx clear-npx-cache` を実行してキャッシュを消去してから、もう一度コマンドを実行してください。

</Callout>

## ステップ 2: 環境シークレットを設定する {#step-2-configure-environment-secrets}

アプリは本番用の設定を環境変数から読み取ります。

| 変数                 | 必須   | 用途                                                 |
| -------------------- | ------ | ---------------------------------------------------- |
| `DATABASE_URL`       | はい   | アプリを PostgreSQL データベースに接続する           |
| `BETTER_AUTH_SECRET` | はい   | ユーザー セッションに署名する                        |
| `BETTER_AUTH_URL`    | いいえ | ユーザーがアプリにアクセスする公開アドレスを設定する |

以下の export により、このシェルで後続のコマンドが動作するようになります。デプロイする前に、同じ変数をホストのプロジェクトまたはサービスの環境設定にも保存してください。Koyeb に保存する方法はステップ 4 で説明します。

### データベース URL {#database-url}

ローカル開発中、`DATABASE_URL` が設定されていない場合、アプリはデータをローカル データベースに保存します。デプロイしたアプリには、デプロイ後もデータを保持する本物の PostgreSQL データベースが必要です。Koyeb はデプロイや再起動のたびにサービスのファイルを置き換えるため、データベースは Web サービスの外に置く必要があります。プロバイダーから接続文字列をコピーし、export します。

```bash
export DATABASE_URL='your-postgres-url-string'
```

各プロバイダーで接続文字列を確認する場所は、[データベース プロバイダー ガイド](/docs/neon)で説明しています。

<Callout tone="warning">

Neon、Supabase、Amazon RDS などの永続的な PostgreSQL プロバイダーを選択してください。

</Callout>

### 認証シークレット {#auth-secret}

この値は一度だけ生成し、デプロイ間で変更しないでください。

アプリは `BETTER_AUTH_SECRET` を使ってユーザー セッションに署名します。この値が変わると、サインイン中のすべてのユーザーがサインアウトされます。以下のコマンドでランダムな値を生成します。

```bash
export BETTER_AUTH_SECRET="$(openssl rand -hex 32)"
```

生成した値は、パスワード マネージャーなど、安全な場所に保存してください。デプロイのたびに同じ値を使用します。

### 公開 URL {#public-url}

省略可能です。カスタム ドメイン、リバース プロキシ、または固定の公開オリジンを必要とする認証や OAuth のフローを使う場合に設定します。

`BETTER_AUTH_URL` は、ユーザーがアプリにアクセスする公開アドレスです。設定しない場合、アプリは受信したリクエストごとに自身のアドレスを判断します。Koyeb が割り当てるアドレスでは通常それで問題ありませんが、カスタム ドメインを接続する場合は、サインイン リンクや OAuth のリダイレクトがそのドメインを使うように設定してください。

```bash
export BETTER_AUTH_URL='https://your-domain.example'
```

## ステップ 3: マイグレーション {#step-3-migrate}

マイグレーションは、アプリに必要なテーブルをデータベースに作成し、更新します。最初のデプロイの前にこれを実行してください。

```bash
pnpm migrate:production
```

このコマンドは自分のコンピューター上で実行され、ステップ 2 で export した `DATABASE_URL` を使って本番データベースに接続します。アプリをアップグレードした後は、新しいバージョンをデプロイする前にもう一度実行してください。

## ステップ 4: Web サービスを作成する {#step-4-create-the-web-service}

Koyeb のコントロール パネルで新しい **Web Service** を作成し、デプロイ方法として **GitHub** を選び、ステップ 1 のリポジトリとブランチを選択します。ビルダーは **Buildpack** のままにして、ビルド コマンドと実行コマンドを次の値で上書きします。

| 設定          | 値                              |
| ------------- | ------------------------------- |
| Build command | `NITRO_PRESET=koyeb pnpm build` |
| Run command   | `node .output/server/index.mjs` |

`NITRO_PRESET=koyeb` は、Node.js ガイドと同じ Node.js サーバーを、自身の静的ファイルも配信するように設定してビルドします。実行コマンドはそのサーバーを起動します。Koyeb はデフォルトでポート `8000` を公開し、それに合わせて `PORT` 環境変数を設定します。サーバーは `PORT` を自動的に読み取るため、ポートの設定を変更する必要はありません。

**Environment variables** で、`DATABASE_URL` と `BETTER_AUTH_SECRET` を追加します。このような値については、Koyeb はそれぞれを **Secret** として保存し、変数からその Secret を参照することを推奨しています。たとえば、接続文字列を `DATABASE_URL` という名前の Secret として保存し、変数の値を `{{ secret.DATABASE_URL }}` に設定します。`BETTER_AUTH_URL` を設定した場合は、同じ方法で追加してください。

## ステップ 5: デプロイ {#step-5-deploy}

<Steps>

### インスタンス タイプを選ぶ

Web サービスのインスタンス タイプを選びます。アプリを試すだけなら Free インスタンス タイプで十分です。アプリがすぐに応答する必要がある場合は、有料のインスタンス タイプを選んでください。

### Web サービスを作成する

サービスとアプリに名前を付けてから、デプロイします。Koyeb はリポジトリからアプリをビルドし、起動します。最初のビルドには数分かかります。その進行状況はサービスのビルド ログとランタイム ログで確認できます。

### アプリを開く

デプロイが完了すると、コントロール パネルにアプリのアドレスが表示されます。このアドレスは `koyeb.app` で終わります。そのアドレスを開き、最初のアカウントを作成します。

</Steps>

Free インスタンス タイプでは、トラフィックが 1 時間ないと Koyeb がサービスをゼロまでスケールダウンします。その後の最初のアクセスでは、サービスが再び起動するまで待つことになります。Free インスタンスは、組織ごとに 1 つまで実行できます。

## 更新をデプロイする {#deploy-updates}

Koyeb は、ステップ 4 で選んだブランチにプッシュするたびに再デプロイします。新しいバージョンをリリースするには、先にマイグレーションを実行してからプッシュします。

```bash
pnpm migrate:production

git push
```

サービスの設定と保存した変数はそのまま残るため、ステップ 4 を繰り返す必要はありません。
