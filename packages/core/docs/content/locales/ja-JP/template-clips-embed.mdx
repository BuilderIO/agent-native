# クリップを埋め込む

ホスト型のクリップを、あなたのプロダクトの録画バックエンドとして使います。人はクリップにサインインせずに、iframe から録画できます。あなたのバックエンドは組織のサービス トークンを使って短命の受付 URL を作成し、クリップはできた録画をその組織の設定済みストレージに保存します。

このガイドでは、ホスト型の埋め込みフローを説明します。録画する人がクリップのアカウントを持っている必要はありません。

## 連携の仕組み

この連携には 4 つの部分があります。

1. 組織の管理者がクリップで動画ストレージを設定します。
2. あなたのバックエンドが組織のサービス トークンを保存し、受付 URL をリクエストします。
3. あなたのプロダクトは、短命の受付 URL だけを iframe に渡します。
4. クリップが録画を組織のストレージにアップロードし、完了メッセージをあなたのプロダクトに送信します。

組織のサービス トークンは、iframe に置くべきものではありません。トークンはそれを発行した組織に紐づいているため、トークン自体が組織のコンテキストを与えます。組織 ID は、あなた自身のテナント マッピングには有用ですが、それ単体では認証情報にはなりません。

## クリップの組織を設定する

録画を所有すべきクリップの組織を作成または選択します。続いて、組織の管理者がクリップのオンボーディングまたはクリップの設定から動画ストレージを設定します。

- **Builder.io Connect** は、マネージドの動画ストレージと AI クレジットを提供します。
- **S3 互換ストレージ** は、組織で設定されたエンドポイント、バケット、アクセス キー、シークレット キー、および任意のリージョンまたは公開ベース URL を使います。Cloudflare R2 と DigitalOcean Spaces も、プロバイダー固有の名前で同じストレージ設定を使います。

ストレージの設定は組織単位です。その組織のサービス トークンを通じて作成されたすべての録画は、その組織にすでに接続されているストレージを使います。埋め込み先のプロダクトは、Builder.io や S3 の認証情報を必要としません。

動画は、設定されたオブジェクト ストレージに保存されます。クリップは、録画のメタデータ、所有権、処理状態、ストレージへの参照をデータベースに保存します。

## 組織のサービス トークンを作成する

組織の所有者または管理者として、既存の `connect` コマンドを実行します。このコマンドはブラウザのサインインを開き、アクティブな組織向けに名前付きのサービス トークンを作成し、トークンを一度だけ表示します。

```bash
npx @agent-native/core@latest connect https://clips.agent-native.com \
  --service-token support-desk --ttl-days 365
```

表示されたトークンを、あなたのプロダクトのサーバー側シークレット マネージャーに直接コピーしてください。トークンは組織が所有するため、発行した人が組織を離れたり、自分の個人トークンを取り消したりしても機能し続けます。ローカルのクライアント設定に書き込まれることは一切ありません。連携ごとに異なるサービス名を使うと、1 つの呼び出し元を取り消しても他を壊さずに済みます。

`--ttl-days` は 1 から 365 日を受け付け、デフォルトは 365 です。トークンは組織のメンバーとして動作します。他のサービス トークンを作成・取り消したり、組織の設定を変更したりすることはできません。

## 受付 URL をリクエストする

あなたの信頼されたバックエンドが、クリップの受付 action を呼び出します。ホスト型アカウントの場合はホスト型のクリップのオリジンを、セルフホストの場合は自分のクリップのオリジンを使います。

```ts
const clipsBaseUrl = "https://clips.agent-native.com";
const clipsServiceToken = process.env.CLIPS_SERVICE_TOKEN;

const response = await fetch(
  `${clipsBaseUrl}/_agent-native/actions/create-recording-intake-link`,
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${clipsServiceToken}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      ttlSeconds: 3600,
    }),
  },
);

if (!response.ok) {
  throw new Error("Could not create a Clips intake URL");
}

const intake = await response.json();
// intake.url is safe to pass to the recording iframe.
```

サービス トークンの署名済み組織コンテキストが、その受付をどの組織が所有するかを決めます。action の応答は、トップレベルの受付オブジェクトです。既定の受付の有効期間は 1 時間です。最大は 4 時間です。1 つの受付 URL につき、作成できる録画は 1 件だけです。

このリクエストを匿名のブラウザから行わないでください。サービス トークン、ストレージの認証情報、長期間有効なクリップのセッションをブラウザに返さないでください。

## レコーダーを埋め込む

返された URL を、そのまま iframe に渡します。この URL には、訪問者が 1 件の非公開録画を作成してアップロードできる、狭い範囲の署名付き権限が含まれています。

```tsx
<iframe
  data-clips-recorder
  src={intake.url}
  allow="display-capture; camera; microphone"
  title="Report a problem"
  style={{ width: 420, height: 560, border: 0 }}
/>
```

レンダリングする前に、受付 URL にプロジェクト ID、ページ タイトル、アプリケーションのバージョン、環境など、小さく機密性のないコンテキスト値を追加できます。パスワード、API キー、顧客レコード、その他の機密性の高い値を URL に入れないでください。URL はブラウザの履歴、ログ、分析、リファラーに現れる可能性があります。

レコーダーは、訪問者がキャプチャを開始するとトップレベルのポップアップを開きます。ブラウザのメディア権限と画面キャプチャには、トップレベルの閲覧コンテキストでのユーザー ジェスチャーが必要です。テスト中は、ホスト プロダクトのポップアップを許可してください。

## 完了メッセージを受け取る

録画が保存されると、完了ページは `agent-native.clips.bug-report.submitted` を埋め込み元の親ウィンドウに送信します。ペイロードを使う前に、クリップのオリジンとメッセージの送信元を検証してください。

```ts
const clipsOrigin = new URL(clipsBaseUrl).origin;
const recorderFrame = document.querySelector<HTMLIFrameElement>(
  "iframe[data-clips-recorder]",
);

window.addEventListener("message", (event) => {
  if (event.origin !== clipsOrigin) return;
  if (recorderFrame && event.source !== recorderFrame.contentWindow) return;
  if (event.data?.type !== "agent-native.clips.bug-report.submitted") return;

  const { recordingId, recordingUrl, embedUrl, agentAccessStatus } = event.data;
  if (!recordingId) return;

  // Send recordingId to your trusted backend and attach it to the support case.
  console.log({ recordingId, recordingUrl, embedUrl, agentAccessStatus });
});
```

完了ペイロードには、`recordingId`、`recordingUrl`、`embedUrl`、`agentShareUrl`、`agentContextUrl`、`agentAccessExpiresAt`、`agentAccessStatus` が含まれます。`recordingId` は、サポート ケースの確かな識別子として扱ってください。書き込み専用の受付では、あなたの認証済みバックエンドが別のスコープ付きエージェント リンクを作成するまで、`agentAccessStatus: "unavailable"` と報告される場合があります。このステータスは、録画が空であることを意味しません。

ブラウザ メッセージは通知であり、認可の許可ではありません。完了した録画を読み取ったり共有したりする必要があるときは、あなたのバックエンドが自身の認証済み接続でクリップにアクセスするべきです。

## 録画の保存先

サービス トークンを通じて作成された録画は、そのトークンに紐づく組織が所有します。クリップは、通常のアップロードと確定のパイプラインを通じてメディアを送信します。このパイプラインは、その組織用に設定された Builder.io または S3 互換ストレージを使います。

iframe はあなたのバケットに直接アップロードすることはなく、バケットの認証情報も必要としません。あなたのプロダクトは、クリップから録画の識別子とスコープ付きの URL を受け取ります。自分のサポート システムには、必要な識別子または URL だけを保存してください。

## クリップをセルフホストする

セルフホストでも、同じ組織の契約が使われます。

1. 永続的なデータベースと公開の `BETTER_AUTH_URL` を使って、クリップをデプロイします。
2. 埋め込まれた録画を所有する組織を作成します。
3. その組織で、Builder.io Connect または S3 互換ストレージを一度だけ設定します。
4. セルフホストしたクリップのオリジンに対して `connect` を実行し、組織のサービス トークンを作成します。
5. そのトークンを、デプロイまたはシークレット マネージャーの値として、埋め込み先のバックエンドに一度だけ提供します。
6. あなたのバックエンドが受付 URL をリクエストするときは、セルフホストしたクリップのオリジンを使います。

```bash
npx @agent-native/core@latest connect https://clips.example.com \
  --service-token support-desk --ttl-days 365
```

例えば、埋め込み先のバックエンドは、これらの値をサーバー側の設定に保持できます。

```text
CLIPS_BASE_URL=https://clips.example.com
CLIPS_SERVICE_TOKEN=<secret>
```

トークンはバックエンドに一度だけ提供されます。それでも訪問者ごとに、新しい短命の受付 URL が発行されます。iframe にはトークンやストレージの認証情報は一切追加されず、トークンをローテーションしても iframe 側のコード変更は不要です。

一般的なセルフホスト要件については [デプロイ](/docs/deployment) を参照してください。

## セキュリティ チェックリスト

- 組織のサービス トークンは、サーバー側のシークレット マネージャーに保管してください。
- ホスト プロダクトとクリップの両方で HTTPS を使ってください。
- 各受付 URL は、ベアラー認証情報として扱ってください。ログやリファラー データには残さないでください。
- 実用的な範囲で最も短い受付の有効期間を使ってください。
- 完了リスナーでは、`event.origin` と `event.source` の両方を検証してください。
- クリップの所有者スコープのアップロード エンドポイントを、匿名ユーザーに直接公開しないでください。
- サービス トークンをローテーションするときは、`connect` で新しいトークンを作成し、デプロイし、フローを確認したうえで、`revoke-org-service-token` で古いトークンを取り消してください。
- 組織 ID と受付 ID は、訪問者から渡された値を信頼するのではなく、信頼されたバックエンド側で保持してください。

## トラブルシューティング

**受付リクエストが unauthorized になる。** バックエンドが、意図したクリップのオリジン向けに発行された、期限切れでも取り消されてもいないサービス トークンを使っているか確認してください。トークンの組織バインディングが、受付がどこに作成されるかを決めます。

**iframe がサインイン ページを開く。** iframe が `create-recording-intake-link` から返された短命の URL を使っているか確認してください。匿名の訪問者に対して `/record` や通常のクリップのライブラリ URL を埋め込まないでください。

**録画が完了しない。** 組織に Builder.io または S3 互換ストレージが設定されているか確認してください。匿名の訪問者は、iframe からストレージを設定できません。

**完了にエージェント リンクがない。** これは書き込み専用の受付では想定どおりの動作です。サポート ワークフローがエージェントが読み取れるトランスクリプトとフレーム データを必要とする場合は、認証済みバックエンドに別のスコープ付きエージェント リンクを作成させてください。
