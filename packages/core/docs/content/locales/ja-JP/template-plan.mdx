# Visual Plans

Agent-Native Plans は、コーディングエージェント向けのビジュアルプランモードです。ふつうの
Codex、Claude Code、Markdown、または貼り付けた実装プランを、リッチテキスト、図、
ワイヤーフレーム、注釈付きコードのウォークスルーやファイルツリー、コメント、共有可能な
リンクを備えた構造化されたレビュー画面に変えます。

つまるところ、コマンドは 2 つだけです。`/visual-plan` は、エージェントがコードを書く
**前**に Plan を作成します。`/visual-recap` は、PR、コミット、ブランチ、git diff など
**すでに起きた**変更を、俯瞰的なビジュアルコードレビューに変えます。どちらも同じレビュー
画面を開くので、注釈を付けたり、コメントしたり、フィードバックをエージェントに返したり
する方法は、どちらの場合も変わりません。

## 置き換えるもの

<Comparison>

### 導入前

- プランがチャットや Markdown ファイルの中の長い文章として存在し、レビューするには
  反対意見のある一段落を見つけるために最初から最後まで読み通す必要があります。
- フィードバックは Slack のスレッドやばらばらのコメントとして行われ、プラン自体とは
  切り離されています。
- 完成した PR をレビューするには、生の diff を 1 行ずつ読んで、何がどう変わったのかを
  再構築する必要があります。

### 導入後

- プランは、図、ワイヤーフレーム、注釈付きコード、そして直接反応できる Open Questions
  フォームとして描画されます。
- コメントは、正確なテキスト、画像、ワイヤーフレームの位置にピン留めされ、エージェントか
  人間のレビュアーのどちらかを対象にできます。
- `/visual-recap` は、PR、コミット、diff を、生の diff の代わりに同じビジュアルレビューに
  変えます。

</Comparison>

結果を HTML、Markdown、JSON としてエクスポートすれば、ソース管理に馴染みやすいコピーを
残せます。あるいはローカルファイルモードを使えば、ホスト型データベースには一切残さずに
済みます。それぞれの詳細については、
[Plan のレビューとコメント](/docs/template-plan-review-workflow) と
[ローカルファイルモードとデスクトップ同期](/docs/template-plan-local-and-desktop)
を参照してください。

## はじめに {#get-started}

<Steps>

### スキルをインストールする {#install}

ほとんどの人は、Plan をスキャフォールディングされたアプリとしてではなく、既存の
コーディングエージェント向けの**スキル**としてインストールします。このコマンド 1 つで、
スキルの指示がインストールされ、ホスト型の Plans MCP コネクタが登録され、サインインまで
完了します。

```bash
npx @agent-native/core@latest skills add visual-plan
```

これにより、`/visual-plan`、`/visual-recap`、`/visualize-repo` の 3 つのスラッシュコマンドに
加えて、`https://plan.agent-native.com/mcp` にある `plan` MCP コネクタ (エージェントが対話
するリモートツールサーバー) がインストールされます。フラグの完全なリファレンス、Claude Code
と Codex 向けのプラグイン/マーケットプレイスのインストール経路、そして VS Code 拡張機能に
ついては、
[Plan プラグインとマーケットプレイス → インストール経路](/docs/plan-plugin#install) を
参照してください。

Plan テンプレート自体をカスタマイズすること — セルフホストしたり、直接その上に構築したり
すること — は、[Plan の拡張](/docs/template-plan-developers) で扱う別の副次的な経路です。
ほとんどの人はこれを必要としません。

### その作業に合ったコマンドをエージェントに尋ねる

- 「認証フローを変更する前に `/visual-plan` を使って」
- 「モバイルとデスクトップの両方の状態を持つ、新しいオンボーディング画面用に
  `/visual-plan` を作成して」
- 「この PR に `/visual-recap` を実行して、まず変更の全体像を確認させて」
- 「`main` とこのブランチの diff に `/visual-recap` を使って」
- 「`/visualize-repo` を実行して、公開 API の actions とスキーマから始めて」

`/visual-plan` は、作業の内容に応じて図、ワイヤーフレーム、モックアップ、クリック可能な
プロトタイプ、注釈付きコードを取り込みます。エージェントはまずコードベースを調べ、その後
返ってきたリンクがブラウザや VS Code でレビュー UI を開きます。

### アカウント不要のゲストとしてレビューする

Plan を共有された相手は、何もインストールする必要がありません。Plans エディターを開いて、
**サインアップなしで作成・編集**します — つまりゲストとして作業します。サインインが
必要になるのは、自分の作業を**保存または共有**するときだけです。そして、ゲストが後から
サインインすると、そのゲストが作成したすべての Plan は自動的にアカウントに**紐づけられ**ます。

</Steps>

すでに Codex、Claude Code、Markdown、または貼り付けたプランがある場合は `/visual-plan` を
使います。エージェントはその元のプランを保持したまま、ゼロから作り直すのではなく、そこから
より充実したレビュー画面を構築します。最初のパスにまだ未決定の判断が残っている場合、
エージェントは Plan の末尾に **Open Questions** フォームを追加できます。それに答えて送り
返すと、改訂のターンが始まります。

<Callout tone="info">

**ゲストとサインイン済みの違いを一目で**

- **ゲストとして**は、共有リンクを開く、新しい Plan を作成する、本文を編集する、レビュー
  注釈モードを使う、といったことがアカウントなしで行えます。
- **サインイン**すると、これに加えて自分の Plan を永続的に保存し、Plan を共有可能なリンクで
  公開し、他の人に閲覧者/編集者/管理者アクセスを付与し、メールで人に通知が届くコメントを
  投稿し、自分が所有する Plan を削除・復元できるようになります。

</Callout>

## コストとモデルの選択

Plan やリキャップの生成は、軽量なテンプレートの埋め込みではなく、コーディングエージェント
の LLM に対するフルエージェンティックセッションを実行します — コストは、diff や Plan の
大きさと選んだモデルに応じて変わります。

- アプリのデフォルトのチャットモデルは GPT-5.6 Luna です。Anthropic への直接接続では、
  デフォルトとして Claude Sonnet 5 が使われ続けます。モデルは **Settings** でいつでも変更
  できます。Haiku はより安価な Claude の選択肢です。
- GitHub Action による自動 PR リキャップは、対話型アプリとは別に実行され、独自のモデルと
  コストの設定を持ちます。`VISUAL_RECAP_MODEL`、`VISUAL_RECAP_AGENT`、
  `VISUAL_RECAP_REASONING` については [PR Visual Recap](/docs/pr-visual-recap) を参照して
  ください。

## 非公開の Plan へのアクセスをリクエストする {#request-access}

閲覧権限を持たない Plan のリンクを誰かが開いた場合、Plans は単に行き止まりを表示するだけ
ではありません。ページはその Plan が非公開であることを伝え、**アクセスをリクエスト**する
アクションを提示します。これは:

- サインインしていることが必要です (ゲストはまずサインインを促されます)。
- リクエストをその Plan に対して記録し、デプロイでメールが設定されている場合は、
  リクエスト元の名前と、承認すればその Plan を開いて共有し返せるリンクを添えて、
  Plan の所有者にメッセージを送ります。
- 何度クリックしても安全です。Plans はまず、すでにアクセス権を持っていないかを確認する
  ため、同じ人からの 2 回目のリクエストが重複したメールで所有者に迷惑をかけることは
  ありません。

Plan の公開範囲が完全な非公開ではなく **org** に設定されていて、あなたのアカウントに
その組織への招待が保留中であるか、その組織と一致するメールドメインを持っている場合、
Plans はリクエストを送る代わりに、その組織に直接参加することを提案します。

<Callout tone="warning">

Plans のツールが `needs auth`、`Unauthorized`、`Session terminated` のいずれかを返した
場合は、そのまま再試行し続けないでください。
`npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex`
で再認証するか、OAuth 対応のホストでは `/mcp` → **Authenticate** を再実行してください。
その後は新しい Codex スレッドを開始するか、クライアントを再起動/再読み込みしてください —
ツールレジストリは新しいセッションでのみ変更を反映します。

</Callout>
