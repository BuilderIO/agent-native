# Design

Design は、エージェントネイティブのプロトタイピング スタジオです。レイヤー化
された描画キャンバスの代わりに、エージェントが完全な自己完結型の Alpine と
Tailwind の HTML プロトタイプを生成し、ライブ プレビューで表示し、プロンプトと
調整コントロールを通じて結果を磨き上げます。プレビューに映るものはすでに本物の、
動作するコードなので、静的なモックアップ ツールと、その後に続く引き渡し作業を
置き換えます。

生成、調整、エクスポートはすべて同じ HTML ファイルを読み書きするので、
プレビューとダウンロードするものの間で何かが失われることはありません。

## 置き換えるもの

<Comparison>

### 導入前

- 静的なモックアップには Figma やそれに類するツールを使い、それを実際の
  マークアップに変える別の開発者が必要
- ライブのブラウザ レンダリングではなく、アートボードのサイズを変えてデザインの
  応答性を推測する
- エクスポートした仕様と、それを手作業で合わせる人との間の遅い引き渡し
- デザイン ファイルと実際にリリースされたコードが、時間とともに乖離していく

### 導入後

- エージェントが生成、プレビュー、改良する 1 つの HTML プロトタイプ。別の
  ビルド手順は不要
- どのブレークポイントでもライブでプレビューできる、本物の Alpine と Tailwind
  のマークアップ
- エージェントにレイアウト、コピー、インタラクションの変更を頼めば、同じ
  ファイルが更新される
- HTML、ZIP、PDF、またはコーディング用の引き渡しバンドルへ直接エクスポート
  できるので、デザインとコードは 1 つの成果物のままになる

</Comparison>

## マルチアプリ ワークスペースでの Design

[Dispatch](/docs/template-dispatch) のもとで他のアプリと一緒に Design を動かして
いる場合、それに到達する方法はそれだけではありません。Design は、ワークスペース
アプリがすでに公開しているのと同じ種類の接続ポイントを通じて、Claude Code や
Claude Desktop を含む他のエージェントが直接呼び出せるホスト型ツールとしても
動作します。この連携が実際にどう機能するのか、その裏にある本当の仕組みについては
[マルチアプリ ワークスペースでの Design のクロスアプリ利用](/docs/template-design-integrations)
を参照してください。

## それを使って何ができるか

- **完全なプロトタイプを生成する。** 必要な画面やページを説明すると、エージェントが Tailwind のスタイリングと Alpine のインタラクションを備えた、動作する HTML ドキュメントを書き上げます。
- **バリアントを比較する。** いくつか異なる方向性を生成し、最も強力なものを選んで、最初からやり直す代わりに改良を続けます。
- **ブランドを適用する。** デザイン システムをリンクしたり、サイトやコードベースからブランドをインポートしたり、ピクセル単位で正確な出発点として Figma のフレームを取り込んだりできます。[機能](/docs/template-design-features) を参照してください。
- **品質を一貫させる。** エージェントはプロトタイプを完成と呼ぶ前にアクセシビリティと視覚的なチェックを実行し、繰り返し使われるパターンは再利用可能なコンポーネントにできます。[機能](/docs/template-design-features) を参照してください。
- **実際のファイルをエクスポートする。** HTML、ZIP、PDF、または本物のベクター形式の Figma SVG をエクスポートしたり、すぐに使える引き渡しバンドルと一緒にプロトタイプをコーディング エージェントに渡したりできます。[機能](/docs/template-design-features) を参照してください。

## 次は何ですか

- [**機能**](/docs/template-design-features) — 生成、品質、ブランドと Figma のインポート、コンポーネント、エクスポートと、それぞれの設定手順
- [**Agent との対話**](/docs/template-design-agent) — タスク別のプロンプトと、エージェントがあなたの画面をどう見ているか
- [**マルチアプリ ワークスペースでの Design のクロスアプリ利用**](/docs/template-design-integrations) — Dispatch への接続と、Claude Code、Claude Desktop、その他のエージェントから MCP 経由で Design を呼び出す方法
- [**開発者ガイド**](/docs/template-design-developers) — クイックスタート、actions、データモデル、ルート
- [**テンプレート**](/docs/cloneable-saas) — Cloneable SaaS モデルと、出発点となるその他すべてのドメインテンプレート
- [**はじめに**](/docs/getting-started) — actions、アプリケーション状態、ライブ同期というフレームワークの基礎
- [**コンテキスト認識**](/docs/context-awareness) — ユーザーが何を見ているかをエージェントがどう把握するか
- [**外部エージェント**](/docs/external-agents) — Claude Code、Claude Desktop、その他の MCP ホストをエージェントネイティブ アプリに接続する
