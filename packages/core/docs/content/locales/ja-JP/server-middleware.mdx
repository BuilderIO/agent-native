# ミドルウェア

ミドルウェアは、ルート ハンドラーに到達する前に、受信するすべてのリクエストに対して実行されるコードです。呼び出し元とルートの間に位置するため、認証、ロギング、CORS ヘッダー、レート制限など、どのルートが処理するかにかかわらず適用すべき横断的な関心事に適した置き場所です。

`server/middleware/` 内のファイルは Nitro によって自動的に検出されます。登録は不要です。そのディレクトリ内のすべてのファイルが、アルファベット順にすべてのリクエストで実行されます。

## ミドルウェアを書く {#writing-middleware}

ミドルウェア ファイルは `defineEventHandler` をエクスポートします。リクエストを先へ進めるには何も返さず、ブロックするには `createError` を throw するか、`sendRedirect` でリダイレクトを返します。

```ts filename="server/middleware/cors.ts"
import { defineEventHandler, setResponseHeader } from "h3";

export default defineEventHandler((event) => {
  setResponseHeader(event, "Access-Control-Allow-Origin", "*");
  // returning nothing passes the request through to the route handler
});
```

複数のミドルウェア ファイルは、一致したルート ハンドラーが実行される前に、ファイル名のアルファベット順で実行されます。各ミドルウェアは、リクエストの検査や変更、レスポンス ヘッダーの設定、あるいはレスポンスを完全にショートサーキットすることができます。

条件分岐、非同期処理、レスポンスの傍受といった、さらなるミドルウェアのパターンについては、[Nitro ミドルウェアのドキュメント](https://nitro.build/guide/routing#middleware) と [H3 のドキュメント](https://h3.unjs.io) を参照してください。

## 認証ミドルウェア {#auth-middleware}

すべてのエージェント ネイティブ アプリは `server/middleware/auth.ts` を備えています。これは、公開ページ ルートやカスタム `/api/*` ルートを含む、すべてのルートに対して認証を強制します。これらは本来、フレームワーク組み込みの認証を回避してしまう可能性があるものです。

### 認証ガード {#auth-guard}

```ts filename="server/middleware/auth.ts"
import { runAuthGuard } from "@agent-native/core/server";
import { defineEventHandler } from "h3";

export default defineEventHandler(async (event) => {
  return runAuthGuard(event);
});
```

`runAuthGuard` は、[認証プラグイン](/docs/server-plugins#auth-plugin) によって構成された認証設定に対して、すべてのリクエストをチェックします。リクエストが未認証で、そのパスが `publicPaths` に含まれていない場合は、サインイン ページへリダイレクトします。

### なぜプラグインやルート ガードではなくミドルウェアなのか {#why-middleware}

フレームワーク ハンドラーの組み込みミドルウェア レジストリは、`/_agent-native/*` ルートに限定されています。専用のミドルウェア ファイルがなければ、ページ ルート (`/`、`/settings`) やカスタム API ルート (`/api/*`) は認証を完全に迂回してしまいます。

プラグインはリクエストごとではなく起動時に実行されるため、リクエストごとの認証を強制できません。各カスタム ルート ハンドラーでのルート レベルのガードはエラーが起きやすく、うっかり忘れがちです。`server/middleware/` にあるミドルウェアは、パスにかかわらずすべてのリクエストで実行される唯一の場所です。

### パブリック パスの追加 {#public-paths}

特定のパスへの未認証アクセスを許可するには、ミドルウェアに直接渡すのではなく、`server/plugins/auth.ts` の `createAuthPlugin` に渡します。

```ts filename="server/plugins/auth.ts"
import { createAuthPlugin } from "@agent-native/core/server";

export default createAuthPlugin({
  publicPaths: ["/public", "/api/webhooks/stripe"],
  marketing: { appName: "My App", tagline: "..." },
});
```

`runAuthGuard` は、リクエスト時に認証プラグインから構成済みのパブリック パスを読み取ります。
