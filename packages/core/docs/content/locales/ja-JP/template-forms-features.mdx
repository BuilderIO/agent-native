# 機能

フォームのすべての中核機能について、その仕組みと設定方法を説明します。概要は [フォーム](/docs/template-forms) を、[Agent との対話](/docs/template-forms-agent) ではすべてのプロンプトの一覧を参照してください。

## フォームを作成する

すべてのフォームは、一連のフィールドから始まります。欲しいものをエージェントに説明すればフォームを作ってくれますし、ゼロから始めてビジュアルビルダーで自分でフィールドを追加することもできます。どちらの方法も同じフォームを編集するので、切り替えても何かがずれてしまうことはありません。フォームができると、そのビルダーには編集、回答、設定、連携という 4 つのタブがあり、より直接的な制御をしたいときはいつでもラベル、プレースホルダー、必須項目、選択肢、フィールドの順序を手作業で調整できます。

### フィールドタイプ {#field-types}

フォームには標準で 11 種類のフィールドタイプが用意されています。名前を指定してエージェントに頼むこともできますし、聞きたい質問を説明するだけで適切なタイプを選んでもらうこともできます。

すべてのフィールドにはラベルとタイプが必要です。`select`、`multiselect`、`radio` のようなフィールドには、選んでもらう選択肢のリストも必要です。任意のフィールドを必須にしたり、最小値や最大値のような検証を追加したり、フォームの全幅を使うか別のフィールドと横並びにするかを選ぶことができます。

### 条件付きフィールド

フィールドは、あなたが設定したルールに前の回答が一致するまで非表示のままにできます。例えば、前の質問で「その他」が選ばれない限り「詳しく教えてください」というテキストフィールドを隠しておく、といった使い方ができます。

チェック対象となるフィールドは、フォーム内でそれより前になければなりません。後にあるフィールドや存在しないフィールドを指すルールは、保存される前に拒否されます。前の回答がある値と等しいか、等しくないか、ある値を含むかをチェックでき、これは複数選択できる質問にも使えます。フィールドが条件によって非表示になっている場合、その回答は決して保存も送信もされないので、非表示のフィールドが古い値や既定値をデータに残すことはありません。

チャットで説明する代わりにフォーム作成を直接スクリプト化する場合は、[開発者ガイド](/docs/template-forms-developers#data-model) のフィールドと設定の JSON リファレンスを参照してください。

## フォームを公開する

フォームは 3 つのステータスを移り変わります。

| ステータス  | 意味                           | 公開アクセス         |
| ----------- | ------------------------------ | -------------------- |
| `draft`     | 作業中で、公開されていない     | いいえ               |
| `published` | 公開中で、回答を受け付けている | はい                 |
| `closed`    | 回答の受け付けを終了した       | 終了メッセージを表示 |

フィールドが 1 つもない、いずれかのフィールドにラベルがない、または `select`、`multiselect`、`radio` のフィールドに選択肢がない場合、フォームは公開できません。公開が拒否された場合は、具体的な理由が示されます。

公開 URL は `/f/<slug>` のような形式で、スラッグはタイトルと短い一意のサフィックスから生成されます。例えば `beta-signup-a1b2c3` のようになります。カスタムスラッグを設定していない限り、タイトルを変更するたびに自動的に再生成されます。

### 回答を収集する

公開されたフォームへの送信はすべて 1 件の回答になります。回答内容、届いた日時、そしてフォームが匿名でない限りは、誰がどこから送信したかも記録されます。任意のフォームの回答タブを開けば各回答の詳細を確認できますし、エージェントに直接尋ねることもできます。

- 「ベータ登録フォームの回答は何件ありますか?」
- 「今日誰が送信しましたか?」
- 「カスタマーフィードバックフォームの回答を見せてください。」

公開フォームのページそのものではなく、他のアプリに埋め込まれたフィードバックボタン経由で送信が届いた場合、回答テーブルにはどのページとどのアプリから届いたかも表示されます。これらの列は、その情報を実際に持つ回答が少なくとも 1 件届いたときに初めて表示されます。

## 設定

各フォームには、ビルダーの設定タブに、動作と回答者に表示される内容を決める独自の設定があります。

- **送信ボタンのテキスト。** 送信ボタンのラベルを既定の「送信」から、「フィードバックを送る」や「予約する」のようなより具体的なものに変更できます。
- **完了メッセージ。** 既定の確認メッセージの代わりに、送信直後に回答者へ表示する内容を選べます。
- **リダイレクト URL。** 送信後にフォーム自体で完了メッセージを表示する代わりに、回答者を別のページへ送ることができます。
- **プログレスバー。** 長いフォームの上部にプログレスバーを表示し、回答者に残りの量が分かるようにできます。
- **匿名モード。** 誰が回答したかの追跡をすべてオフにし、送信が IP アドレス、メールアドレス、位置情報を一切記録しないようにします。
- **新しい回答をメールで通知。** 誰かが送信するたびに、設定済みのメールプロバイダーを通じてメールを受け取れます。

## 公開フォームを保護し、ブランドを付ける

### スパム保護

公開の送信は、通過する前に [Cloudflare Turnstile](https://www.cloudflare.com/products/turnstile/) による検証を必須にできます。設定でサイトキーとシークレットキーを設定すればオンになります。Turnstile がなくても常に有効な保護が 2 つあります。ボット送信を静かに破棄するための非表示フィールドと、人間が現実的に入力できるより速く送信されたものを拒否するチェックです。

<Callout tone="warning">

Turnstile の 2 つのキーは必ずセットで設定してください。公開フォームのページは、サイトキーが設定されている場合にのみ検証ウィジェットを表示し、サーバーは両方のキーが設定されている場合にのみそれを検証します。シークレットキーだけを設定しても何も検証されず、サイトキーだけを設定してもサーバーが決してチェックしないウィジェットが表示されるだけです。

</Callout>

### ブランディング

独立した公開フォームにはすべて、隅に小さな「Built with Agent-Native」バッジが表示されます。これはフォームごとにオン・オフを切り替えられるものではありません。フィードバックポップオーバーのように別のページに埋め込まれている場合にだけ、そのページがすでに自身のブランディングを持っているため、自動的に非表示になります。

### 送信元オリジンを制限する

既定では、フォームの送信リンクはどこからの送信でも受け付けます。これは、ふつうの公開フォームリンクとしてはあるべき挙動です。フォームの送信リンクを別のサイトのウィジェット内に埋め込んでいて、そのサイトだけに使わせたい場合は、送信を特定のウェブサイトオリジンのリストに制限できます。

今日時点では、ビルダー内にこれを切り替えるトグルはありません。エージェントに設定を頼んでください。例えば「このフォームの送信を https://example.com からだけ許可して」のように依頼します。許可したい各サイトについて、正確なオリジン(スキームとドメイン、例えば `https://example.com` のように、末尾のパスなし)をエージェントに伝えてください。

## エクスポート

フォームの回答タブから **CSV をエクスポート** をクリックすると、現在画面に表示されている内容(適用した検索やソートも含む)の CSV をすぐにダウンロードできます。これは設定不要で即座に動作します。

エージェントに「このフォームの CSV」や「すべての回答の JSON エクスポート」を頼むこともできます。これは常にフィルタ後ではなくすべての回答をエクスポートし、事前にファイルストレージプロバイダーの接続が必要です。まだ接続されていない場合、エージェントがその旨を伝え、設定 → ファイルアップロードへ案内します。そこでは無料の Builder.io アカウントが手軽な選択肢になります。ストレージが接続されると、エージェントは直接ダウンロードする代わりにファイルへのリンクを返します。各エクスポートは(CSV の場合)フィールドラベルを列見出しとして使い、あるフィールドで複数の選択肢が選ばれていた場合、それらの選択肢は 1 つのセル内にまとめて結合されます。スプレッドシートの数式に見える回答はすべて事前に無害化されるので、ファイルを開いたときにコードを実行しようとする送信からあなたを守ります。

## 送信をルーティングする

自動配信をオンにすれば、誰かが回答タブを確認しなくても、新しい回答はすでにチームが使っている場所に届きます。これはフォームごとの設定で、ビルダーの連携タブで設定します。

| 送信先        | 必要なもの                                                                                               |
| ------------- | -------------------------------------------------------------------------------------------------------- |
| Slack         | 対象チャンネルの Incoming Webhook URL                                                                    |
| Discord       | 対象チャンネルの webhook URL                                                                             |
| Google Sheets | 送信を受け取るために設定した Google Apps Script の URL。単なるスプレッドシートのリンクでは機能しません。 |
| Webhook       | 送信をデータとして受け取れる任意のウェブアドレス                                                         |

これは、エージェントが Slack に直接投稿できるようにする Slack 接続とは別のものです。それについては [メッセージング](/docs/messaging) を参照してください。エージェント自身に Slack へ更新を投稿させたい場合は、まずそちらを接続してください。すべての送信先アドレスは、保存する時点と回答が届くたびの両方で、プライベートネットワークや内部アドレスを指していないか必ずチェックされるので、フォームが自分のネットワークを探るための手段に使われることはありません。

新しい回答が届くたびにフォームの所有者にメールを送る通知をオンにすることもできます。これは既に設定済みのメールサービスを通じて送られます。このメール送信はベストエフォートです。通知メールの送信に失敗しても、送信自体はそのまま成立します。
