# データと同期

クライアント アプリケーションからアプリ データを読み書きする主な方法は、[アクション](/docs/actions-overview) フックを通すことです。リクエストをアクションに埋め込むことで、クライアントとエージェントの両方が同じ方法でアプリケーションを操作できます。

以下の例では、チケットがドロップダウンから手動で、続いてチャット エージェント経由で現在のユーザーに割り当てられます。UI とエージェントはどちらも同じアクションにアクセスします。

### アクション フック {#action-hooks}

最もよく使うことになるアクション フックは 2 つあります。`useActionQuery()` と `useActionMutation()` です。これら 2 つのフックは、アプリのアクションへのアクセスを提供します。

#### useActionQuery {#use-action-query}

<Signature
  id="doc-block-client-data-1"
  name="useActionQuery"
  params={[
    {
      name: "actionName",
      type: "TName",
      description: "アクションの登録名。",
    },
    {
      name: "params",
      type: "ActionParams<TName>",
      optional: true,
      description:
        "アクションの入力。`defineAction()` のスキーマから型付けされます。",
    },
    {
      name: "options",
      type: "UseQueryOptions",
      optional: true,
      description:
        "[useQuery オプション](https://tanstack.com/query/latest/docs/framework/react/reference/useQuery) のすべて (`queryKey` と `queryFn` を除く。これらはフック自体が設定します)。",
    },
  ]}
  returns={{
    type: "UseQueryResult<TResult>",
    description:
      '`["action", name, params]` の下にキャッシュされます。手動の無効化なしで、変更アクションが完了するたびに自動的に再フェッチされます。',
  }}
/>

このフックは、読み取り専用のアクションで使用することを意図しています。[useQuery()](https://tanstack.com/query/latest/docs/framework/react/reference/useQuery) 関数の薄いラッパーです。

以下の例では、`list-tickets` アクションが呼び出されます。これは、すべてのチケットに対して GET リクエストを行うのと似ています。

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery("list-tickets", {});
```

以下の例は、`get-ticket` アクションを通じて単一のチケットをフェッチするリクエストを示しています。クエリを特定のチケットのみに絞るために `ticketId` が渡されます。追加の `enabled` オプションは、クエリが自動的には実行されず、`ticketId` が存在する場合にのみ実行されるようにするために渡されます。

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery(
  "get-ticket",
  { ticketId: ticketId ?? "" },
  { enabled: Boolean(ticketId) },
);
```

#### useActionMutation {#use-action-mutation}

<Signature

      description:
        "[useMutation オプション](https://tanstack.com/query/latest/docs/framework/react/reference/useMutation) のすべて (`mutationFn` を除く。これはフック自体が設定します)。",
      fields: [
        {
          name: "method",
          type: '"POST" | "PUT" | "DELETE"',
          optional: true,
          default: '"POST"',
          description: "デフォルトのリクエスト メソッドを上書きします。",
        },
        {
          name: "skipActionQueryInvalidation",
          type: "boolean",
          optional: true,

        },
      ],
    },
  ]}
  returns={{
    type: "UseMutationResult",
    description:
      '成功すると `source: "action"` で変更イベントを発行するため、変更されたデータを読み取っているすべての `useActionQuery()` が自動的に再フェッチされます。手動の無効化は不要です。',
  }}
/>

このフックは、作成、更新、送信など、データを変更するアクションで使用することを意図しています。[useMutation()](https://tanstack.com/query/latest/docs/framework/react/reference/useMutation) 関数の薄いラッパーです。

`useActionQuery()` とは異なり、アクションの入力はフック自体には渡されません。ミューテーションを実行する準備ができたときに `mutate()` または `mutateAsync()` に渡します。

以下の例では、`send-ticket-reply` アクションが呼び出されて、チケットに返信が投稿されます。ボタンの `onClick` などのイベント ハンドラーから `mutate()` を呼び出します。

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply");

mutate({ ticketId, body: draft });
```

以下の例は、同じミューテーションを `onSuccess` オプション付きで示しています。キャッシュの無効化はすべてのミューテーションの後に自動的に発生するため、`onSuccess` は返信が送信された後に返信コンポーザーをクリアするなど、ローカルな副作用にのみ必要です。

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply", {
  onSuccess: () => setDraft(""),
});

mutate({ ticketId, body: draft });
```

### callAction {#call-action}

<Signature

        {

          default: "60000",

        },
      ],
    },
  ]}
  returns={{
    type: "Promise<TResult>",
    description:
      "上記のフックとは異なり、キャッシュも自動再フェッチもありません。結果に依存する他の UI がある場合は、手動の無効化と組み合わせてください。",
  }}
/>

この関数は、プレーンなイベント ハンドラー、スクリプト、その他の非 React コード パスなど、React のレンダー フローの外側での命令的な単発アクション呼び出しのためのものです。フックの結果ではなく、直接プロミスを返します。

以下の例では、`update-ticket` アクションがキーボード ショートカット ハンドラーから React のレンダー フローの外で呼び出され、チケットを担当者に割り当てます。

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction("update-ticket", {
  ticketId,
  assignedToEmail: "jordan@example.com",
});
```

以下の例は、`timeoutMs` オプション付きの同じ呼び出しを示しています。デフォルトの 60 秒のタイムアウトより正当に長くかかるアクションに便利です。

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction(
  "update-ticket",
  { ticketId, assignedToEmail: "jordan@example.com" },
  { timeoutMs: 120_000 },
);
```

すべての `useActionQuery()`、`useActionMutation()`、`callAction()` のリクエストは 60 秒のタイムアウトで制限されており、タイムアウトは黙って再試行されるのではなくエラーとして表面化します。`useActionQuery()` は、React Query の abort シグナルを使用して、上書きされたリクエストも自動的にキャンセルします。

`useDbSync()` はローカルなチャット実行中のツール完了と実行終了時の更新を常に処理します。そのため、単一ユーザーのエージェント変更にバックグラウンド要求は不要です。他のタブ、ユーザー、Webhook、ジョブによる変更の同期は、短い理由を付けて有効にするまでオフです。タブごとに接続を共有し、非表示時は停止し、アイドル間隔を 1、2、5 分へ延長します。

```ts
import { useDbSync } from "@agent-native/core/client/hooks";
import { useQueryClient } from "@tanstack/react-query";

function App() {
  const queryClient = useQueryClient();

  useDbSync({
    queryClient,
    realtime: { reason: "teammates can edit this shared record" },
    pollUrl: "/_agent-native/poll",
    onEvent: (data) => console.log("Data changed:", data),
  });

  return <div>...</div>;
}
```

現在のユーザー操作なしにデータが変わり、更新前にユーザーがその変更を見る必要がある場合だけリアルタイムを有効にします。共同編集する Slides と Mail の受信トレイが適した例です。公開ページ、Docs、設定、フォーム、変更の少ない一覧、単一ユーザーのエージェント変更では無効にし、フォーカスまたはナビゲーション時に再取得します。開いている opt-in タブごとに、アイドル間隔ごとのポーリングが 1 回追加されます。
