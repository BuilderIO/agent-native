# Agent-Nativeとは？

Agent-Nativeは、直感的なUIを備えた自律型エージェントを構築するための
オープンソースTypeScriptフレームワークです。各機能を一度だけ
[アクション](/docs/actions-overview)として定義します。アクションは、エージェントが
ツールとして使用し、UIがコードから呼び出す型付き関数です。

## UIを備えたエージェントを構築する理由

コーディングエージェントを見ると、テキストボックスだけで十分に思えるかもしれません。しかし、テキストボックスは作業環境の一部にすぎません。コードベースがコンテキストを提供し、ツールが明確な実行手段を与え、ファイル、テスト、プレビューが結果を可視化します。

多くのナレッジワークには、このような構造がありません。空のテキストボックスでは、エージェントに何ができるのか、どのようなコンテキストを持っているのか、何を頼めばよいのかを人が推測する必要があります。

UIは、テキストボックスに欠けているものを提供します。エージェントの機能を見えるようにし、コンテキストとワークフローを体験に組み込み、作業の進行を見ながら形にできるようにします。

Agent-Nativeでは、このようなエージェントを構築できます。UIは、エージェントを固定されたワークフローに制限することなく、明確な出発点を提供します。エージェントとUIは同じ機能を使用するため、人は作業をエージェントに委任し、UIで確認または変更し、進行を失うことなく両者を行き来できます。

Agent-Nativeは、3つの共有基盤を通じてエージェントとUIをつなぎます。

- **[共有アクション](/docs/actions-overview)。** 各機能を一度だけ定義します。エージェントはツールとして呼び出し、UIはコードから呼び出します。どちらの経路も同じ検証、権限、実装を使用します。
- **[共有データ](/docs/server-database)。** アクションは同じデータを読み取り、更新します。そのため、エージェントが行った作業はUIに表示され、UIで行った作業はエージェントから利用できます。
- **[共有アプリケーション状態](/docs/context-awareness)。** アプリケーション状態は、現在のページ、選択中のレコード、アクティブなビューなど、UIで起きていることを表します。Agent-Nativeは関連する状態をコンテキストとしてエージェントに渡すため、人が何に取り組んでいるかを理解できます。

エージェントはUIをクリックして操作するわけではありません。UIと同じアクションレイヤーを通じて作業します。

たとえば、人はUIからサポートチケットを担当者に割り当てることも、エージェントに依頼することもできます。どちらの経路でも同じアクションが実行され、同じチケットが更新されます。人はUIで結果を確認または変更してから、エージェントにそこから作業を続けさせられます。

## Agent-Nativeを使うべきとき

次の場合、Agent-Nativeは適しています。

- エージェントに、質問への回答だけでなく実際の作業をさせたい。
- エージェントに何ができるかを確認し、その作業を確認、編集、承認、共有するためのUIが必要である。
- 進行やコンテキストを失わずに、エージェントとUIの間を移動できるようにしたい。

生成された応答が1つだけ必要なら、モデルを直接呼び出してください。作業が固定された予測可能な手順に従うなら、通常のアプリケーションロジックまたは自動化の方がシンプルです。エージェントとUIの両方が同じ作業で継続的な役割を持つ場合に、Agent-Nativeを使ってください。
