# Content: ローカルフォルダーソース

Content のデータモデルは 1 つです。すべてのページは SQL に保存され、
**スペース**に属し、そのスペースのシステムデータベース **Files** の項目に
なります。ローカルフォルダーは Files に接続するソースであり、他のすべての
ページと同じコラボレーション、共有、コメント、履歴、検索、データベース
プロパティ、アクションサーフェスを利用します。

ユーザーには個人スペース、アクセス可能な組織には組織スペースがあり、個人の
**Workspaces** カタログが表示対象を決めます。Files は通常の Content
データベースなので、プロパティ、フィルター、並べ替え、グループ、保存ビューを
サイドバー表示にも利用できます。

## フォルダーを接続する

<Steps>

### ローカルフォルダー画面を開く

ブラウザーの File System Access API または Agent-Native Desktop でフォルダー
を選びます。SQL に保存されるのは不透明な接続 ID、相対パス、ハッシュ、ソース
メタデータのみです。絶対パス、ブラウザーハンドル、ファイル本文は保存されません。

### フォルダーの接続先を選ぶ

既存の個人または組織スペースの Files データベースに接続するか、専用の Files
データベースを持つ非公開のフォルダーバックドスペースを作成します。

### 信頼できる情報源ポリシーを選ぶ

| ポリシー                 | 動作                                                       |
| ------------------------ | ---------------------------------------------------------- |
| `database_primary`       | Content が正であり、フォルダーの変更は使用前にレビューされます |
| `source_primary`         | 同時に行われた Content の編集がない場合、フォルダーが正になります |
| `reviewed_bidirectional` | どちらの方向の変更も、競合時にレビューが必要です             |

</Steps>

同期はファイルを通常の SQL ページとして実体化します。両側が同時に変わった
場合は上書きせず、レビュー対象の変更を作成します。切断してもページとローカル
ファイルは残ります。

## リポジトリから起動

```bash
npx @agent-native/core@latest content .
```

通常のデータベース版 Content が起動し、フォルダーをソースとして登録して接続
画面を開きます。

## 設定

```json
{
  "version": 1,
  "apps": {
    "content": {
      "roots": [
        {
          "name": "Docs",
          "path": "docs",
          "kind": "docs",
          "extensions": [".md", ".mdx"],
          "source": {
            "type": "local-folder",
            "connectionId": "local-folder:<opaque-id>",
            "truthPolicy": "source_primary"
          }
        }
      ],
      "components": "components",
      "extensions": "extensions"
    }
  }
}
```

移行時は `mode: "local-files"` と `AGENT_NATIVE_MODE=local-files` を
削除し、roots を残して `source` を追加します。frontmatter の ID は名前変更や
移動でもページ識別を保ちます。ローカルコンポーネントと拡張機能は引き続き信頼
されたローカルブリッジ経由で読み込まれます。
