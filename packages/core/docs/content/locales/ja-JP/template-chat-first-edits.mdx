# 最初の機能

このページは [Chat テンプレート](/docs/template-chat) を拡張する開発者向けです。スタート画面をレンダリングするファイルを紹介し、実際の機能を依頼したときにエージェントが通常触れるすべてを順に説明します。

## 最初に確認するコード {#first-code}

- `actions/hello.ts` はエージェントが呼び出せるスターターの動作です。置き換えるか、その隣に action を追加します。
- `app/components/chat/ChatRouteContent.tsx` は `/chat/<threadId>` でフルページのチャット画面をレンダリングします。空の状態、コンポーザー、メッセージのスロットはここで調整します。
- `app/components/home/HomePage.tsx` は、開発環境の `/home` に表示される編集可能な「はじめに」ページです。本番環境の `/home` では新しいチャットが始まります。
- `AGENTS.md` は、組み込みエージェントにこのアプリ内での作業方法を伝えます。

## 最初の編集 {#first-edits}

最初に追加する機能の多くは、同じ形をたどります。テーブル、1 つか 2 つの action、ルート、ナビゲーション エントリ、そして `AGENTS.md` の更新です。エージェントに次のように頼んでみましょう。

> `notes` のデータ モデルを追加してください。note には id、title、body、owner があります。`/notes` に notes ページをレンダリングし、作成/一覧の action を追加して、チャットからも note を作成できるようにしてください。

チャットには `server/db/schema.ts` がまったく同梱されていません ([同梱内容](/docs/template-chat#what-ships) を参照)。そのため、最初の変更は新しいファイルの追加であり、他のすべてのテンプレートが使用している同じ `table`/`text`/`ownableColumns` の形に従います。

残りの機能はそこから続きます。

- `actions/create-note.ts` — `actions/hello.ts` と同じ形をした、Zod スキーマ (`title`、`body`) を持つ `defineAction`。
- `actions/list-notes.ts` — `accessFilter` を通じて新しいテーブルをクエリする、読み取り専用の action (`actions/view-screen.ts` と同様の `readOnly: true`)。
- `app/routes/notes.tsx` — 新しいルート。このアプリはファイルシステム ルーティング (`app/routes.ts` の `flatRoutes()`) を使用しているため、ファイルを追加するだけで `/notes` がマウントされます。
- `app/components/layout/Sidebar.tsx` の `ChatThreadsSection` の前に追加する、`/notes` を指すリンク。
- notes が存在すること、そしてどの action がそれらを管理するかをエージェントに伝える `AGENTS.md` への追記。

新しい action は、存在すればすぐにチャットから呼び出し可能になります。`agentTool: false` を設定しない限り、すべての `defineAction` は既定でツールになります。ただし、モデルの最初のリクエストに必ず含まれるわけではありません。`server/plugins/agent-chat.ts` は `INITIAL_TOOL_NAMES = ["view-screen", "navigate", "hello", "provider-api-request"]` を設定しており、これは最初のターンで送信されるツール スキーマだけを制御します。新しく追加した `create-note` を含む他のすべては、`tool-search` を通じて到達可能であり、オンデマンドでロードされます。最初のメッセージからモデルの既定のツールセットに含めたい場合にのみ、そのリストに名前を追加してください。

## 独自のエージェント バックエンドを使う {#own-agent-backend}

このテンプレートは既定で組み込みのアプリエージェント ループを使用します。カスタム バックエンドに接続するには、UI を書き換えるのではなく、エージェント チャット プラグインの背後にあるチャット ランタイムを交換してください。チャット ルートは、共有チャット サーフェスの薄いレンダラーのままであるべきです。バックエンドの選択はサーバー プラグイン/ランタイム アダプターに属します。

モデルのオーケストレーションが既に別の場所にあるものの、それでも認証、スレッド、action、UI 状態、デプロイ可能なページを備えたアプリが欲しい場合に、これを使用してください。
