# マルチアプリ ワークスペースでのクリップのクロスアプリ利用

クリップは、[Dispatch](/docs/template-dispatch) ワークスペース内にある数多くのアプリの中の 1 つです。このページでは、それが実際に何を意味するのかを具体的に説明します。連携がどのように機能するか、そして他のアプリやエージェントがあなたのクリップに働きかけたり、そこで起きたことに反応したりする具体的な方法についてです。概要は [クリップ](/docs/template-clips) を参照してください。

## クリップが Dispatch と連携する仕組み

これが自動的に行われるかどうかは、クリップと Dispatch がどちらもホストされているか、ローカルで動いているかではなく、両者がどのように一緒に設定されたかに依存します。

### 同じワークスペース: 自動

クリップと Dispatch が (`create` または `add-app` を通じて) 1 つの Agent-Native ワークスペースに一緒に生成または追加され、1 つの単位としてデプロイされている場合、両者はすでに 1 つの `.env`、1 つの `A2A_SECRET`、1 つのワークスペース レジストリを共有しています。発見と認証済み A2A 呼び出しは、そのワークスペースがあなたのマシンで動いているか本番環境で動いているかにかかわらず、何も設定せずにそのまま機能します。これは、クリップを土台にした実際のマルチアプリ プロダクトで想定されるセットアップです。

### 別々のデプロイ: 手動の手順が 1 つ

クリップと Dispatch が独立して作成された 2 つの Agent-Native プロジェクトである場合、両者はシークレットを共有しておらず、まだお互いを呼び出せません。接続するには、それぞれの側で手動の手順が 1 つ必要です。Settings → Agent → Sub-agents (Connect agent)、または Dispatch → エージェント → 外部エージェントを追加のいずれかから、共有シークレットを持つ `remote-agents/<id>.json` リソースを追加します。全体の手順については [A2A プロトコル](/docs/a2a-protocol) を参照してください。

どちらの状況にあるかを確認するには、いずれかのアプリのエージェントに「どのアプリが見える?」と尋ねてください。Dispatch の回答にクリップが含まれていなければ、2 番目のケースに当たります。

## 連携戦略

### エージェントが読み取れるクリップ

公開のクリップ共有リンクをエージェントに貼り付けるか、非公開クリップの場合は **エージェントと共有** の行にある **共有 → コピー** を使います。どちらの方法でも、エージェントは動画をダウンロードせずに、2 時間で期限切れになるリンクを使ってトランスクリプトを読み取り、キーフレームを見ることができます。

画像を見られるほとんどのエージェント (ChatGPT、Claude Code、Cursor、Codex を含む) は、これを自分だけで処理できます。いくつかのテキストのみのチャットはトランスクリプトを読み取れますが、フレームは読み取れません。その場合は、画像に対応したエージェントでクリップを開いてください。

| Endpoint                                          | What agents get                                                                                                                          |
| ------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `/api/agent-context.json?id=<recordingId>`        | クリップのメタデータ、トランスクリプトのステータス、チャプター、CTA、推奨フレーム、トランスクリプト/フレーム API へのリンク              |
| `/api/agent-transcript.json?id=<recordingId>`     | `startMs`、`endMs`、読み取り可能なタイムスタンプ、テキスト、オプションのソース ラベルを含むタイムスタンプ付きトランスクリプト セグメント |
| `/api/agent-frame.jpg?id=<recordingId>&atMs=<ms>` | 元の動画のタイムスタンプでビデオから抽出された JPEG フレーム                                                                             |

これらのエンドポイントは、共有ページと同じ公開/パスワード/有効期限のルールに従うか、一時的なエージェント リンクからのスコープ付き `agent_access` トークンを受け付けます。パスワードで保護されたクリップは 1 回だけパスワードを求められます。成功した応答は有効期間の短いトークン付きリンクを返すため、下流のエージェントは平文のパスワードを必要としません。

トランスクリプトがまだ準備できていない場合、行儀の良いエージェントはすぐに諦めず、少し待ってから再試行します。長い録画では数分かかることがあります。Builder のクレジットが尽きて文字起こしが失敗した場合、エージェントはそのことを伝え、[文字起こしと AI メタデータ](/docs/template-clips-features#transcription-and-ai-metadata) を案内する必要があります。

### Brain へのエクスポート

ワークスペースが Brain を接続すると、クリップはすべての録画が完了するたびに、準備が整ったトランスクリプトを自動的に送信します。新しい録画が少しずつ届くのを待つ代わりに、過去 28 日分すべてのような古い録画をバックフィルするようエージェントに頼むこともできます。エージェントは、何件のトランスクリプトがエクスポートされ、スキップされ、フラグ付けされたかを報告します。

### CRM の通話証拠

CRM ツールには、完全な録画なしで通話が行われた証拠が必要になることがあります。クリップが渡すのは不透明なクリップ ID と確かなリンクだけで、動画やトランスクリプトを渡すことはありません。これは、あなたが既に見られる録画に対してのみ機能し、あなたが頼んだとき、または承認された自動化がトリガーしたときにのみ機能します。

### Dispatch を介した自然言語での委任

姉妹アプリがクリップと連携するために、特別な統合は必要ありません。チャットで頼むのと同じように、「価格について話し合ったクリップを見つけて」のような平易な言葉のリクエストをクリップのエージェントに渡すことができ、クリップはそれに直接答えたり、実行したりします。

### 分離されたままでいる

クリップが Brain や CRM の認証情報を知る必要はなく、その逆も同様です。`clip.created` イベントとエージェントが読み取れるリンクがアプリ同士の間に立つので、クリップは誰が、どのように聞いているかを知る必要なく、イベントを発行したりリクエストに答えたりするだけで済みます。
