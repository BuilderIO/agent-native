# 概要

アクションは、アプリが行うすべてのことの唯一の信頼できる情報源です。`defineAction()` で1つ定義し、`actions/` に配置してください。以下のすべてのサーフェスが自動的にそれを拾い上げます。ロジックを書くのは一度だけです。どのサーフェスも独自のコピーを持たず、他と食い違うこともありません。

<Cards columns={2}>

### :robot: [エージェント ツール](/docs/agent-surfaces)

エージェントは description とスキーマを、呼び出し可能なツールとして読み取ります。「このチケットに返信して」や「このスレッドを要約して」のように、チャットで頼むだけです。

### :components: [UI フック](/docs/client-data)

`useActionQuery()`、`useActionMutation()`、`callAction()` は、React から同じアクションを呼び出します。クリックとチャット メッセージは、まったく同じ操作を実行します。

### :server: [フレームワーク トランスポート](/docs/http-api)

起動時に `/_agent-native/actions/<name>` に自動マウントされます。UI フックは内部でこのルートを呼び出しており、外部の HTTP クライアントも直接呼び出せます。

### :plug: [MCP ツール](/docs/actions-other-surfaces#mcp)

Claude、Claude Desktop、Cursor、Codex など、あらゆる MCP ホストにツールとして表示されます。別の AI クライアントにアプリを操作させたい場合に使用します。

### :network: [A2A ツール](/docs/actions-other-surfaces#a2a)

他の agent-native アプリが A2A 経由でこれを発見し、呼び出します。ワークスペース内の別のアプリが、このアプリに代わって操作する必要がある場合に使用します。

### :terminal: [CLI コマンド](/docs/actions-other-surfaces#cli)

`pnpm action <name>` でターミナルから実行できます。スクリプト、cron ジョブ、素早い手動テストに使用します。

</Cards>

ほとんどのアプリは、フロントエンドとデータベースの間に、ブラウザだけが呼び出せる独自の API 層を構築します。同じ機能をエージェントにも持たせたい場合、別途の統合を書いて、また保守し続ける必要があります。Agent-native アプリはこの分断を回避します。UI とエージェントはまったく同じアクションを呼び出すため、実装すべき箇所は1つだけであり、バグが隠れる場所も1つだけです。

UI とエージェントの両方が何かを行う必要がある場合は、カスタム ルートではなくアクションを使いましょう。ルート形式のプロトコルが適している稀なケースについては、[まず Actions をデフォルトにする](/docs/server-overview#actions-first) を参照してください。

## アクションの役割 {#role}

`app/`([概要](/docs/client-overview#role) を参照)とエージェントは、どちらも同じアクションと同じ SQL データベースに解決されます。エージェントが到達できない別個の「アプリのバックエンド」に、この層が話しかけることはありません。機能を構築するということは、ここで操作を定義し、それと同時に UI、エージェント ツール、その他すべてのサーフェスを手に入れることを意味します。

`actions/` はフラットなフォルダです。各ファイルは1つのアクションであり、`defineAction()` の呼び出しをファイルのデフォルト エクスポートとしてエクスポートします。フレームワークは起動時にこのフォルダをスキャンし、見つかったすべてのファイルをマウントします。登録手順や、最新の状態に保つべきインデックス ファイルはありません。

アクションの `run()` の本体は通常のサーバー コードなので、他のいくつかのディレクトリにも手を伸ばすのが一般的です。

`actions/` の外側から、アクションの `run` 関数を直接インポートすべきではありません。代わりに、上記のいずれかのサーフェス、つまりエージェント ツール、UI フック、HTTP、MCP、A2A、CLI のいずれかを通じて呼び出してください。これらの経路はすべて、同じスキーマ検証、アクセス チェック、監査証跡を実行します。

## 最初のアクションから始める {#hello-action}

チャットファーストのアプリにおける最初の操作は、ごく小さなものでかまいません。Chat テンプレートでは、`actions/hello.ts` を置き換えるか、その隣に新しいファイルを追加してください。

```ts
// actions/hello.ts
import { defineAction } from "@agent-native/core/action";
import { z } from "zod";

export default defineAction({
  description: "Say hello from the local agent.",
  schema: z.object({
    name: z.string().default("world"),
  }),
  http: { method: "GET" },
  readOnly: true,
  run: async ({ name }) => {
    return { message: `Hello, ${name}!` };
  },
});
```

同じフォルダから実行します。

```bash
pnpm action hello '{"name":"Steve"}'
```

CLI は、アクションの入力として JSON オブジェクトを受け付けます。これは、エージェントが既に行っている構造化されたツール呼び出しと一致する形式です。手早い手動実行には、シンプルなフラグも引き続き使えます。

```bash
pnpm action hello --name Steve
```

続いて、フォルダに対してアプリ エージェント ループを実行します。

```bash
npx agent-native agent "Call hello for Steve and explain the result"
```

これは、スケジュール済みジョブ、チャット UI、外部の MCP ツール、そして将来の画面が使うのと同じアプリ エージェント ループです。Chat やドメイン テンプレートは、アクションの周りに UI を追加するためのものであり、アクションそのものに必要な前提条件ではありません。
