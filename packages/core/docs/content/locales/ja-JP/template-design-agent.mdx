# Agent との対話

Design のすべての機能は、UI が使うのと同じ actions を通じてエージェントも
利用できるので、クリックできることは何でも、平易な言葉で頼むこともできます。
このページでは、エージェントがあなたの画面をどう見ているか、そしてタスク別の
便利なプロンプトを扱います。概要は [Design](/docs/template-design) を
参照してください。

## エージェントがあなたの画面をどう見ているか

何かをする前に、エージェントはあなたが何を見ているかを確認します。開いている
デザインやテンプレート、いまいるビュー (デザイン一覧、テンプレート、エディター、
デザイン システム、または公開のプレゼン ビュー)、選択している画面と要素、
アクティブなインスペクター タブ (Design、コメント、またはコードと計測)、
そして開いている左レール パネル (ファイル、エージェント、アセット、インポート、
ツール、またはトークン) です。だからこそ、「これをもっと密にして」や
「このボタンのコントラストを直して」は、画面や要素の名前を挙げなくても正しく
解決されます。エージェントはすでに「これ」が何を指すか分かっています。

いくつかの状況は、エージェントが次に行うことを変えます。

- **あいまいなプロンプト。** リクエストがエージェントにとって手がかりとして
  不十分な場合、エージェントは推測する代わりに全画面のキャンバス オーバーレイ
  で確認の質問を表示し、何かを生成する前にチャットでの回答を待ちます。
- **テンプレートから作られたデザイン。** エージェントはすでにテンプレートの
  ロックされた寸法とフォントを把握しており、既存の画面を再生成したりサイズを
  変えたりするのではなく、その場で改良します。
- **比較の途中にあるバリアント。** いくつか提案された調整案の間で選んでいる
  最中であれば、エージェントはどれがまだ保留中で、どれをすでに選んだかを
  把握しているので、「2 番目のを使って」は正しく解決されます。
- **未解決のレビュー コメント。** エージェントは、現在の画面に未解決の
  コメントがいくつあり、そのうちどれがすでに対応待ちのキューに入っているかを
  把握しているので、あなたが残したフィードバックを見失うことはありません。

## タスク別の便利なプロンプト

以下のプロンプトはすべて、UI が読み書きしているのと同じ、あなたの実際の
デザインに対する本物の action になります。まずは 1 つの実例を見てみましょう。

<Comparison>

### :blue: あなたが尋ねる

「この画面に未解決のコメントはありますか?」

### :green: 何が起こるか

これは読み取り専用の質問です。エージェントは、いま見ている画面の実際の
コメント スレッド数を確認し、たとえば「未解決のコメントが 2 件、そのうち
1 件はすでに対応待ちのキューに入っています」のように、チャット内で直接
答えます。何も作成や編集がされていないため、あなたの画面上には何も変化が
ありません。

</Comparison>

<Cards columns={2}>

### 生成して調整する

- **「テクニカルな分析製品向けに、ランディング ページの方向性を 3 つ作成して。」** 比較して選べる、本当に異なるいくつかのバリアントが表示されます。
- **「このダッシュボードを、運用チームがスキャンしやすいようにもっと密にして。」** 選択した画面がライブで更新されます。
- **「この繰り返し使われているカードを、再利用可能なコンポーネントにして。」** 1 つのインスタンスへの今後の編集は、すべてまとめて更新するよう頼まない限り、他のものとは別のままになります。
- **「このボタンにホバー アニメーションを追加して。」** 自分で Motion ドックを開かなくても、モーション トラックが作成されます。
- **「ヒーローの背景に波形のシェーダーを追加して。」** エフェクト メニューのピッカーを経由せずに、直接エフェクトを適用します。

### 品質を確認する

- **「この画面のアクセシビリティ監査を実行して。」** エージェントがチェックして、見つけたことを報告します。
- **「さっき見つけたコントラストの問題を直して。」** 修正が直接デザインに適用されます。

### 外部コンテンツを取り込む

- **「この Figma フレームをインポートして: [link]。」** そのフレームが、新しい編集可能な画面として表示されます。
- **「この HTML を新しい画面として貼り付けて。」** 自分でインポート パネルを開かなくても追加されます。
- **「Figma から価格ページを取り込んで、正確に一致させて。」** ピクセル単位で正確なインポートと、構造的に再現できなかった部分についての忠実度レポート。

### ブランドとデザイン システム

- **「保存したデザイン システムを適用して、モバイル レイアウトを簡素化して。」** これ以降のすべての生成はブランドに沿ったものになります。
- **「自分たちの GitHub リポジトリからデザイン システムを始めて。」** 推測ではなく、実際にデプロイされたトークンをインデックスします。
- **「Material 3 をベースにデザイン システムを作成して。」** 模倣品ではなく、実在するメンテナンスされている公開システムから始めます。

### テンプレート

- **「ランディング ページのテンプレートから新しいデザインを始めて。」** そのファイル、寸法、ロックされたレイヤーを新しいデザインにコピーします。
- **「これを『Product launch』という名前のテンプレートとして保存して。」** 次回からは、あなたや共有した相手がテンプレートから利用できるようになります。

### 移動して整理する

- **「概要キャンバスに切り替えて。」** 単一画面ビューから抜け出します。
- **「コメント タブを開いて。」** インスペクター内のそのタブにフォーカスします。
- **「このデザインを『Q3 launch page』に名前変更して。」** デザインが一覧表示されているどこでも、即座に更新されます。

### エクスポートと履歴

- **「これを ZIP としてエクスポートして。」** 自分でプロジェクト メニューを開かなくてもダウンロードされます。
- **「この画面のコーディング ハンドオフ プロンプトをコピーして。」** 外部のコーディング エージェントにそのまま貼り付けられます。
- **「1 時間前のバージョンを復元して。」** デザインを、その正確な保存状態に戻します。

</Cards>

## 拡張機能

Design は拡張機能をサポートしています。あなたやエージェントが作成し、
エディターに組み込める小さなサンドボックス化されたウィジェットです。
インスペクターの左レールには、拡張機能がレンダリングできるスロットが
用意されており、開いているデザインの id とタイトル、アクティブな画面の
ファイル名と内容、現在の表示モードとズーム、選択中の画面と要素、そして
アクティブなツールがすでに利用できる状態で渡されます。今日エディターで
目にするアセット ライブラリ、シェーダー塗りピッカー、ブランド トークン
監査ツール、モーション プリセットは、すべて同じこのスロットの上に構築
されています。作り方については [拡張機能](/docs/extensions) を参照して
ください。
