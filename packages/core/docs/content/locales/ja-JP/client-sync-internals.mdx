# 同期の内部

[Live Sync](/docs/key-concepts#polling-sync) はメンタル モデルをカバーしています: エージェントの書き込みが変更イベントになり、`useDbSync()` がそれを取り込み、影響を受けるクエリが再フェッチされる、という流れです。このページでは、ほとんどのアプリが直接触れることのない、その下にある仕組みをカバーします。`useDbSync()` がインクリメントする変更バージョン カウンターと、`useActionQuery()` を経由していない生の `useQuery()` 呼び出しにそれらを組み込む方法です。

`useActionQuery()` は、変更アクションが完了すると既に自動的に再フェッチします ([データと同期](/docs/client-data#fetching-mutating) を参照)。`useChangeVersion()`/`useChangeVersions()` に手を伸ばすのは、統合ステータスを読み取る低レベルのクライアント ヘルパーなど、そのパスの外で生の `useQuery()` 呼び出しを同期させている場合だけです。

## 変更バージョンの仕組み {#how-it-works}

サーバー側のデータベースの変更が発生すると、サーバーは `source` キーでタグ付けされた変更イベントを記録します。`useDbSync()` はそのイベントを受け取り、そのソースのローカル カウンターをインクリメントします。カウンターを React Query のキーに組み込むことで、バックエンドがそのソースの新しいアクティビティを報告するたびに、クエリが自動的に再フェッチされます。

以下の例では、生の `useQuery()` 呼び出しがダッシュボードを直接読み取り、そのソースが変更されるたびに再フェッチされるように `"dashboards"` ソースのバージョン カウンターをクエリ キーに組み込んでいます。

```tsx
import { useQuery } from "@tanstack/react-query";
import { useChangeVersion } from "@agent-native/core/client/hooks";

function DashboardView({ id }) {
  const version = useChangeVersion("dashboards");

  const { data } = useQuery({
    queryKey: ["dashboard", id, version],
    queryFn: () => fetchDashboard(id),
    placeholderData: (prev) => prev,
  });

  return <div>{data?.title}</div>;
}
```

`placeholderData: (prev) => prev` は、再フェッチ中に前のデータを画面に残すため、ビューが読み込み状態にちらつきません。

## 再フェッチへの 2 つのパス {#latency-models}

ミューテーションは 2 つの方法のいずれかで UI に到達し、それぞれレイテンシが異なります。

自分の `useActionMutation()` 呼び出しが行ったローカルなミューテーションは、成功するとすぐに `source: "action"` イベントを発行します。そのアクションに依存するすべてのクエリはすぐに再フェッチされます。書き込みを行ったタブが既にその変更を知っているため、往復の遅延はありません。

エージェント、webhook、別のタブ、別のユーザーによるリモートなミューテーションは、まずこのタブに到達する必要があります。`useDbSync()` は、SSE 経由でほぼ即座にそれを取り込むか、SSE が利用できない場合はポーリング フォールバックで約 2 秒以内に取り込みます。そのイベントが到着してからようやく、関連するバージョン カウンターがインクリメントされ、クエリがバックグラウンドで再フェッチされます。
