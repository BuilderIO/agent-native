# アクションを定義する

すべてのアクションは `defineAction()` の呼び出しから始まります。これは、エージェント向けの description、入力を検証するスキーマ、実際の処理を行う `run` 関数を1つにまとめたもので、UI とエージェントはまったく同じコードを呼び出すことになります。

## スキーマ オプション {#schemas}

`schema` は、[Standard Schema](https://standardschema.dev) 互換のライブラリであれば何でも受け付けます。

- **Zod** (v4): もっとも一般的な選択肢で、型推論が最も優れており、JSON Schema への自動変換にも対応しています。
- **Valibot**: バンドル サイズが重要な場合に適した選択肢です。
- **ArkType**: その構文が好みであれば良い選択肢です。

スキーマは2つの役割を果たします。Claude API のツール定義向けに JSON Schema へ変換されることと、`run()` が発火する前に実行時に入力を検証することです。無効な入力がハンドラーに届くことはありません。

## 戻り値を検証する {#output-schema}

`schema` は _入力_ を検証します。アクションが **返す値** も検証したい場合は、`outputSchema` を渡してください (Zod、Valibot、ArkType など、`schema` と同じく任意の Standard Schema 互換スキーマを使えます)。フレームワークは `run()` の前に入力を検証し、`run()` が解決した後に結果を検証します。

```ts
export default defineAction({
  description: "Summarize a thread.",
  schema: z.object({ threadId: z.string() }),
  outputSchema: z.object({
    summary: z.string(),
    messageCount: z.number(),
  }),
  outputErrorStrategy: "warn", // default
  run: async ({ threadId }) => {
    /* ...returns { summary, messageCount } ... */
  },
});
```

`outputErrorStrategy` は、不一致が起きたときの挙動を制御します。

| 戦略         | 不一致時の挙動                                                                                      |
| ------------ | --------------------------------------------------------------------------------------------------- |
| `"warn"`     | **デフォルト。** 問題点を `console.warn` に出力し、**元の**結果をそのまま返します。破壊的変更なし。 |
| `"strict"`   | 明確なエラーをスローするため、アクションのバグに気づきやすくなります。                              |
| `"fallback"` | 無効な結果の代わりに、指定された `outputFallback` の値を返します。                                  |

`run()` が成功すると、フレームワークは検証済みの値を返すため、`outputSchema` に設定されたデフォルト値や型変換が、入力の場合と同じように反映されます。`outputSchema` を渡さない場合、戻り値は変更されません。

## HTTP 設定 {#http}

デフォルトでは、すべてのアクションが `POST /_agent-native/actions/<name>` として公開されます。`http` オプションで上書きできます。

```ts
export default defineAction({
  description: "Get details for a lead.",
  schema: z.object({ leadId: z.string() }),
  http: { method: "GET" },
  run: async ({ leadId }) => {
    return await db.select().from(leads).where(eq(leads.id, leadId));
  },
});
```

`GET` アクションの場合、`leadId` はクエリ パラメータとして渡されます: `/_agent-native/actions/get-lead?leadId=abc`。

POST がデフォルトで、`http: { method: "GET" }` を指定すると GET になります。React のフックと `callAction()` は、`http.path` の上書きに関わらず、常に名前でこのパスを呼び出します。外部システムは、長期間有効なベアラー トークンを使って同じルートを呼び出せます。[HTTP API](/docs/http-api) を参照してください。

</Endpoint>

- **`http: { method: "GET" | "POST" | "PUT" | "DELETE" }`**: デフォルトは `POST` です。`GET` アクションは自動的に `readOnly` としてマークされるため、成功した呼び出しが UI のポーリング再フェッチをトリガーすることはありません。
- **`http: { path: "..." }`**: `/_agent-native/actions/` 配下にマウントされる URL を上書きします。デフォルトはファイル名です。この上書きは、直接 HTTP を呼び出す相手に対してのみ URL を変更します。`useActionQuery()`、`useActionMutation()`、`callAction()` は、この上書きに関わらず常に `/_agent-native/actions/<name>` を呼び出すため、パスを上書きするとこれらのフックは 404 になります。パスの上書きは、外部の HTTP 呼び出し元向けにのみ使用してください。また、上書きしたパス内の `:param` ルート セグメントは `run()` の引数として解析されない点にも注意してください。解析されるのは、クエリ文字列のパラメータと JSON ボディのフィールドのみです。
- **`http: false`**: HTTP エンドポイントを完全に無効化します。呼び出せるのはエージェントと CLI のみになります。
- **`readOnly: true`**: 何も変更しない `POST` アクションであっても、明示的にポーリング再フェッチをスキップします。これはアクセス制御ではありません。誰がこのアクションを呼び出せるかを制限するものではなく、`useActionQuery()`、`useActionMutation()`、その他どのクライアント フックにも影響しません。唯一の効果は、呼び出し後のリフレッシュ イベントを抑制することと、書き込み監査からアクションを除外することです。モデルからアクションを隠すには `agentTool: false` を使ってください。呼び出せる相手を制御するには、[アクセスと認可](/docs/actions-access-control) の認証・アクセス オプションを使ってください。
- **`parallelSafe: true`**: 変更を伴うアクションを、同じターン内の他のツール呼び出しと同時に実行できるようにします。同時実行しても安全で、順序に依存しない場合にのみ設定してください。変更を伴うアクションは、デフォルトでは直列に実行されます。

## アクション サーフェスを小さく保つ {#small-surface}

エージェントから見えるアクションはすべて、モデルのツール一覧の枠を1つ消費します。一覧が長く、重複が多いほど、モデルが正しいツールを選ぶのが難しくなります。UI のボタン1つにつきアクション1つを作るのではなく、自分たちが保守する API のようにアクション サーフェスを設計してください。

- `update-name`、`update-order`、`update-color` のようなフィールドごとの複数のアクションよりも、オプション フィールドのパッチを受け取る **CRUD スタイルの `update` アクションを1つ** 用意することを優先してください。呼び出し元は、変更されたフィールドだけを送信すればよくなります。
- クエリやフィルターごとに新しい読み取りアクションを追加する前に、まずより汎用的な選択肢を検討してください。プロバイダー データには [provider API トリオ](/docs/template-dispatch-vault-integrations#provider-api) (`provider-api-catalog`、`provider-api-docs`、`provider-api-request`)、アプリ データには開発用の `db-query` ツールがあります。
- UI 専用またはプログラム的なアクションには、[`agentTool: false`](/docs/actions-access-control#agent-tool) を付けてください。フロントエンドや HTTP からは引き続き呼び出せますが、モデルのツール一覧の枠は消費しません。
- UI がもう使わなくなったアクションは、モデルに公開したままにせず、削除するか非表示にしてください。

このリポジトリには、助言用のヘルパー `node scripts/audit-template-actions.mjs [template ...]` (エイリアス `pnpm actions:audit`) が含まれています。これはテンプレートの `actions/` フォルダをスキャンし、UI がもう使っていない可能性のあるアクションと、1つにまとめられそうなフィールドごとのアクション群にフラグを立てます。常に終了コード 0 を返して CI を落とすことはなく、そのヒューリスティックは控えめなので、その出力はエラーではなく提案として扱ってください。
