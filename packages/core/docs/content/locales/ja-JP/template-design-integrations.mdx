# マルチアプリ ワークスペースでの Design のクロスアプリ利用

Design は、[Dispatch](/docs/template-dispatch) ワークスペース内にある数多くの
アプリの中の 1 つであり、そのワークスペースの外にいるエージェントからも直接
到達できます。このページでは両方を扱います。Dispatch との接続がどう機能するか、
そして外部のエージェントが MCP 経由で Design 自身の actions をどう呼び出せるか
です。概要は [Design](/docs/template-design) を参照してください。

## Design が Dispatch と連携する仕組み

これが自動的に行われるかどうかは、Design と Dispatch がどちらもホストされて
いるか、ローカルで動いているかではなく、両者がどのように一緒に設定されたかに
依存します。

### 同じワークスペース: 自動

Design と Dispatch が (`create` または `add-app` を通じて) 1 つの Agent-Native ワークスペースに一緒に生成または追加され、1 つの単位としてデプロイ
されている場合、両者はすでに 1 つの `.env`、1 つの `A2A_SECRET`、1 つの
ワークスペース レジストリを共有しています。発見と認証済み A2A 呼び出しは、
そのワークスペースがあなたのマシンで動いているか本番環境で動いているかに
かかわらず、何も設定せずにそのまま機能します。

### 別々のデプロイ: 手動の手順が 1 つ

Design と Dispatch が独立して作成された 2 つの Agent-Native プロジェクトで
ある場合、両者はシークレットを共有しておらず、まだお互いを呼び出せません。
接続するには、それぞれの側で手動の手順が 1 つ必要です。Settings → Agent → Sub-agents (Connect agent)、または Dispatch → エージェント →
外部エージェントを追加のいずれかから、共有シークレットを持つ
`remote-agents/<id>.json` リソースを追加します。全体の手順については
[A2A プロトコル](/docs/a2a-protocol) を参照してください。

どちらの状況にあるかを確認するには、いずれかのアプリのエージェントに
「どのアプリが見える?」と尋ねてください。Dispatch の回答に Design が
含まれていなければ、2 番目のケースに当たります。

## ワークスペースの外から Design を呼び出す

Design は、あなたの Dispatch ワークスペースの一部であるかどうかにかかわらず、
他のエージェントが直接接続できるホスト型 MCP サーバーとしても動作します。
Claude、Claude Code、Claude Desktop、Codex、その他 MCP 互換のホストはすべて、
次へ接続できます。

```
https://design.agent-native.com/mcp
```

Claude と Claude Desktop は、これをカスタム コネクタとして追加し、サインイン
してアクセスを承認します。Claude Code は同じ URL を追加した後、`/mcp` を
実行して認証します。Codex やその他の CLI/stdio クライアントは、代わりに
`npx @agent-native/core@latest connect https://design.agent-native.com` を
実行します。これによりブラウザ タブが開いて承認を行い、共有シークレットを
一切使わずに、ユーザーごとの取り消し可能なトークンが発行されます。

接続すると、外部のエージェントは [Agent との対話](/docs/template-design-agent)
で扱った同じ中核ワークフローを利用できます。デザインを作成する、比較用に
いくつかの方向性を生成する、画面の現在の状態を取得する、範囲を絞った編集を
行う、そして結果を実際のコードに変えるときにコーディング ハンドオフ バンドル
をエクスポートする、といったことです。エージェントは、生の HTML を会話に
貼り付けるのではなく、インライン プレビューや、本物のエディターへ戻る
「デザインを開く」リンクを表示します。

<Callout tone="info">

外部のエージェントで Design のツール呼び出しがセッション エラーや認証エラーを
返すようになった場合、そのまま再試行し続けないでください。Claude Code で
`/mcp` を実行して再接続するか、任意のターミナルから `npx -y
@agent-native/core@latest reconnect https://design.agent-native.com` を実行して
ください。どちらも、何も再インストールすることなく再認証できます。

</Callout>

## Dispatch を介して Design に委任する

姉妹アプリは、Design と連携するために特別な統合を必要としません。あなたが
チャットで頼むのと同じように、「この新機能のランディング ページを作って」の
ような平易な英語のリクエストを Design のエージェントに渡すことができ、
Design はそれに直接答えたり、実行したりします。

これらのいずれについても、Design がリクエスト元アプリの認証情報を知る必要は
なく、その逆も同様です。Design は本物のリクエストに答えるだけで済みます。
誰が、なぜ尋ねているかを知る必要はありません。

## 次は何ですか

- [**Design**](/docs/template-design) — 概要と使い始めの手順
- [**機能**](/docs/template-design-features) — デザイン、デザインを編集する、テンプレート、デザイン システム
- [**Agent との対話**](/docs/template-design-agent) — タスク別のプロンプトと、エージェントがあなたの画面をどう見ているか
- [**開発者ガイド**](/docs/template-design-developers) — クイックスタート、actions、データモデル、ルート
- [**Dispatch**](/docs/template-dispatch) — これらのパターンが動作する土台となるワークスペース コントロール プレーン
- [**A2A プロトコル**](/docs/a2a-protocol) — アプリがどのようにお互いを発見し、認証し、呼び出すか
- [**外部エージェント**](/docs/external-agents) — Claude Code、Claude Desktop、その他の MCP ホストをエージェントネイティブ アプリに接続する
- [**マルチアプリ ワークスペース**](/docs/multi-app-workspace) — アプリを入れ子にする代わりにファーストパーティ アプリを組み合わせる一般的なパターン
