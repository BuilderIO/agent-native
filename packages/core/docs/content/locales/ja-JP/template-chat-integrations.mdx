# マルチアプリ ワークスペースでの Chat

Chat は、[Dispatch](/docs/template-dispatch) ワークスペース内にある数多くのアプリの
中の 1 つです。このページでは、それが実際に何を意味するのかを具体的に説明します。
連携がどのように機能するか、そして Chat のエージェントが周囲の他のアプリにどのように
手を伸ばせるかについてです。概要は [Chat](/docs/template-chat) を参照してください。

## Chat が Dispatch と連携する仕組み

これが自動的に行われるかどうかは、Chat と Dispatch がどちらもホストされているか、
ローカルで動いているかではなく、両者がどのように一緒に設定されたかに依存します。

### 同じワークスペース: 自動

Chat と Dispatch が (`create` または `add-app` を通じて) 1 つの Agent-Native
ワークスペースに一緒に生成または追加され、1 つの単位としてデプロイされている場合、
両者はすでに 1 つの `.env`、1 つの `A2A_SECRET`、1 つのワークスペース レジストリを
共有しています。発見と認証済み A2A 呼び出しは、そのワークスペースがあなたのマシンで
動いているか本番環境で動いているかにかかわらず、何も設定せずにそのまま機能します。

### 別々のデプロイ: 手動の手順が 1 つ

Chat と Dispatch が独立して作成された 2 つの Agent-Native プロジェクトである場合、
両者はシークレットを共有しておらず、まだお互いを呼び出せません。接続するには、
それぞれの側で手動の手順が 1 つ必要です。設定 → エージェント → サブエージェント
(エージェントを接続)、または Dispatch → エージェント → 外部エージェントを追加の
いずれかから、共有シークレットを持つ `remote-agents/<id>.json` リソースを追加します。
全体の手順については [A2A プロトコル](/docs/a2a-protocol) を参照してください。

どちらの状況にあるかを確認するには、いずれかのアプリのエージェントに「どのアプリが
見える?」と尋ねてください。Dispatch の回答に Chat が含まれていなければ、2 番目の
ケースに当たります。

## 連携戦略

**他のアプリに助けを求める。** Chat のエージェントは、ワークスペースにどのアプリが
あり、それぞれが何をできるかを調べられます。そのうえで、そのうちの 1 つに特定の
action を実行するよう依頼し、その答えを会話の中で使えます。たとえば、カレンダーが
あるワークスペースで Chat に「明日の予定は?」と尋ねると、エージェントは推測せずに
その質問をカレンダーに渡します。Chat が Google へのカレンダーの接続を持つ必要は
ありません。カレンダーがすでに持っているからです。

**玄関口としての Chat。** どのアプリのエージェントも同じ方法で呼び出せるため、Chat の
会話は、他のアプリにある作業を始める自然な場所になります。欲しいものを 1 か所で
説明すれば、どのアプリが対応すべきかをエージェントが判断します。Chat には邪魔になる
独自のドメインがないので、この役割によく向いています。

**分離されたままでいる。** Chat が他のアプリの認証情報を必要とすることはなく、他の
アプリが Chat の認証情報を必要とすることもありません。各アプリは、自分の接続と自分の
データを保持します。Chat はリクエストを渡し、答えを受け取るだけです。
