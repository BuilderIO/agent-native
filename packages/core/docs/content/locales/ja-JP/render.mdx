# Render

<Badge label="Beta" color="orange" icon="rocket" />

Render がアプリを Web サービスとしてホストしてくれるため、サーバーを用意したり動かし続けたりする必要はありません。Render は [Node.js ガイド](/docs/node-js)で説明しているものと同じ Node.js サーバーを実行し、Git リポジトリからそれをビルドします。また、Render はアプリに HTTPS 対応の公開アドレスを割り当てます。

このガイドでは、スタンドアロン アプリを 1 つ、ゼロからデプロイする手順を説明します。アプリを作成して Git リポジトリにプッシュし、本番用のデータベースと認証シークレットを用意し、データベースを準備してから、アプリをビルドして実行する Render の Web サービスを作成します。

<Callout tone="info">

Node.js `22.22+` が必要です。

</Callout>

Render アカウントと、GitHub、GitLab、Bitbucket のいずれかにあるリポジトリも必要です。このガイドのコマンドは自分のコンピューター上で実行してください。アプリのビルドと実行は、Render がリポジトリから行います。

## ステップ 1: アプリを作成する {#step-1-create-the-app}

新しいスタンドアロン アプリを作成します。以下の例では Chat テンプレートからアプリを作成していますが、どのテンプレートから始めてもかまいません。アプリのフォルダーに移動し、依存関係をインストールします。`corepack enable` はアプリが想定する `pnpm` のバージョンを有効にするため、`pnpm` を自分でインストールする必要はありません。

```bash
npx --yes @agent-native/core@latest create my-app --standalone --template chat

cd my-app

corepack enable

pnpm install
```

必要に応じて、`my-app` を自分のアプリ名に置き換えてください。このガイドの以降の手順は、アプリのフォルダー内にいることを前提としています。

Render は Git リポジトリからアプリをビルドするため、先に進む前に、アプリのフォルダーを GitHub、GitLab、Bitbucket のいずれかの新しいリポジトリにプッシュしてください。ビルドは `pnpm-lock.yaml` ファイルに記載された正確なバージョンをインストールするため、このファイルもコミットしてください。

## ステップ 2: 環境シークレットを設定する {#step-2-configure-environment-secrets}

アプリは本番用の設定を環境変数から読み取ります。

| 変数                 | 必須   | 用途                                                 |
| -------------------- | ------ | ---------------------------------------------------- |
| `DATABASE_URL`       | はい   | アプリを PostgreSQL データベースに接続する           |
| `BETTER_AUTH_SECRET` | はい   | ユーザー セッションに署名する                        |
| `BETTER_AUTH_URL`    | いいえ | ユーザーがアプリにアクセスする公開アドレスを設定する |

以下の export により、このシェルで後続のコマンドが動作するようになります。デプロイする前に、同じ変数をホストのプロジェクトまたはサービスの環境設定にも保存してください。Render に保存する方法はステップ 4 で説明します。

### データベース URL {#database-url}

ローカル開発中、`DATABASE_URL` が設定されていない場合、アプリはデータをローカル データベースに保存します。デプロイしたアプリには、デプロイ後もデータを保持する本物の PostgreSQL データベースが必要です。Render はデプロイや再起動のたびにサービスのファイルを置き換えるため、データベースは Web サービスの外に置く必要があります。プロバイダーから接続文字列をコピーし、export します。

```bash
export DATABASE_URL='your-postgres-url-string'
```

各プロバイダーで接続文字列を確認する場所は、[データベース プロバイダー ガイド](/docs/neon)で説明しています。Render Postgres も使用できます。ここでは外部接続文字列を使い、Web サービスの設定では内部接続文字列を使ってください。

<Callout tone="warning">

Neon、Supabase、Amazon RDS などの永続的な PostgreSQL プロバイダーを選択してください。

</Callout>

### 認証シークレット {#auth-secret}

この値は一度だけ生成し、デプロイ間で変更しないでください。

アプリは `BETTER_AUTH_SECRET` を使ってユーザー セッションに署名します。この値が変わると、サインイン中のすべてのユーザーがサインアウトされます。以下のコマンドでランダムな値を生成します。

```bash
export BETTER_AUTH_SECRET="$(openssl rand -hex 32)"
```

生成した値は、パスワード マネージャーなど、安全な場所に保存してください。デプロイのたびに同じ値を使用します。

### 公開 URL {#public-url}

省略可能です。カスタム ドメイン、リバース プロキシ、または固定の公開オリジンを必要とする認証や OAuth のフローを使う場合に設定します。

`BETTER_AUTH_URL` は、ユーザーがアプリにアクセスする公開アドレスです。設定しない場合、アプリは受信したリクエストごとに自身のアドレスを判断します。Render が割り当てるアドレスでは通常それで問題ありませんが、カスタム ドメインを接続する場合は、サインイン リンクや OAuth のリダイレクトがそのドメインを使うように設定してください。

```bash
export BETTER_AUTH_URL='https://your-domain.example'
```

## ステップ 3: マイグレーション {#step-3-migrate}

マイグレーションは、アプリに必要なテーブルをデータベースに作成し、更新します。最初のデプロイの前にこれを実行してください。

```bash
pnpm migrate:production
```

このコマンドは自分のコンピューター上で実行され、ステップ 2 で export した `DATABASE_URL` を使って本番データベースに接続します。アプリをアップグレードした後は、新しいバージョンをデプロイする前にもう一度実行してください。

有料の Render インスタンスでは、代わりにサービスの **Pre-Deploy Command** に `pnpm migrate:production` を設定することもできます。そうすると、Render は各デプロイが公開される前にマイグレーションを実行します。Pre-Deploy Command は Free インスタンス タイプでは使用できません。

## ステップ 4: Web サービスを作成する {#step-4-create-the-web-service}

Render ダッシュボードで新しい **Web Service** を作成し、ステップ 1 のリポジトリを接続します。次の設定を使用してください。

| 設定          | 値                                                                                        |
| ------------- | ----------------------------------------------------------------------------------------- |
| Language      | `Node`                                                                                    |
| Branch        | デプロイ元のブランチ (`main` など)                                                        |
| Build Command | `corepack enable && pnpm install --frozen-lockfile && NITRO_PRESET=render_com pnpm build` |
| Start Command | `node .output/server/index.mjs`                                                           |

Build Command は、アプリの `pnpm` のバージョンを有効にし、`pnpm-lock.yaml` に記載された依存関係をインストールして、アプリをビルドします。`NITRO_PRESET=render_com` は、Node.js ガイドと同じ Node.js サーバーを、自身の静的ファイルも配信するように設定してビルドします。Start Command はそのサーバーを実行します。Render は使用するポートを `PORT` 環境変数でサーバーに伝え、サーバーはそれを自動的に読み取ります。

**Environment Variables** で、ステップ 2 で export した値を使って `DATABASE_URL` と `BETTER_AUTH_SECRET` を追加します。`BETTER_AUTH_URL` を設定した場合は、同じ方法で追加してください。

Render は、`NODE_VERSION` 環境変数、`.node-version` または `.nvmrc` ファイル、`package.json` の `engines` フィールドの順に参照して Node.js のバージョンを選びます。新しいサービスでは、デフォルトで上記の要件を満たすバージョンが使われます。バージョンを固定するには、`NODE_VERSION` を追加し、たとえば `24` という値を設定します。

## ステップ 5: デプロイ {#step-5-deploy}

<Steps>

### インスタンス タイプを選ぶ

Web サービスのインスタンス タイプを選びます。アプリを試すだけなら Free インスタンス タイプで十分です。アプリがすぐに応答する必要がある場合や、ステップ 3 の Pre-Deploy Command を使いたい場合は、有料のインスタンス タイプを選んでください。

### Web サービスを作成する

Web サービスを作成します。Render はリポジトリからアプリをビルドし、起動します。最初のビルドには数分かかります。その進行状況はサービスのログで確認できます。

### アプリを開く

デプロイが完了すると、ダッシュボードにアプリのアドレスが表示されます。このアドレスは `onrender.com` で終わります。そのアドレスを開き、最初のアカウントを作成します。

</Steps>

Free インスタンス タイプでは、トラフィックが 15 分間ないと Render がサービスを一時停止します。その後の最初のアクセスでは、サービスが再び起動するまで 1 分ほど待つことになります。

## 更新をデプロイする {#deploy-updates}

Render は、ステップ 4 で選んだブランチにプッシュするたびに再デプロイします。新しいバージョンをリリースするには、先にマイグレーションを実行してからプッシュします。

```bash
pnpm migrate:production

git push
```

サービスの設定と保存した変数はそのまま残るため、ステップ 4 を繰り返す必要はありません。
