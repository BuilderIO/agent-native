# ファイルのアップロード

このフレームワークは、構成可能なプロバイダーを通じてアップロードをルーティングするファイルアップロードの抽象化を提供します。テンプレートは `uploadFile()` を呼び出し、URL を受け取ります。ストレージバックエンドは、アプリケーションコードを変更することなく交換できます。

## 仕組み {#how-it-works}

アップロードリクエストは `POST /_agent-native/file-upload` に送信され、アクティブなプロバイダーにディスパッチされます。どのプロバイダーが構成されているかは `GET /_agent-native/file-upload/status` で確認できます。

プロバイダーの解決順序は次のとおりです:

1. **ユーザー登録プロバイダー**: `registerFileUploadProvider()` 経由で登録されたカスタムプロバイダーです。
2. **Builder.io プロバイダー**: 組み込みで、Builder.io が接続されると自動的に有効化されます。
3. **プロバイダーなし**: アップロードは拒否され、チャットにストレージ設定の CTA が表示されます。バイナリデータが SQL に永続化されることはありません。

ユーザー登録プロバイダーの中では、最初に登録され、かつ自身が構成済みであると報告したプロバイダーが優先されます。`registerFileUploadProvider()` は `id` ごとにべき等です。すでに使用されている id で登録すると、既存のプロバイダーが置き換えられます。

UI は、アップロードが試行される前に、同期的な `isConfigured()` チェックのみを使ってストレージ設定プロンプトを表示するかどうかを判断します。実際のアップロードでは `isConfigured()` と `isConfiguredForRequest()` の両方がチェックされます。`isConfiguredForRequest()` を通じてのみ自身が構成済みであると報告するプロバイダーは、そのプロバイダーを通じたアップロードが成功する場合でも、設定プロンプトには表示されません。

## 永続的なアップロードに必要なストレージ {#storage-required}

プロバイダーが構成されていない場合、`uploadFile()` は `null` を返し、マルチパートルートは `503` を返します。チャットの添付ファイルは現在のリクエストでのみ利用可能で、エージェントはストレージ設定のヒントを受け取り、トランスクリプトにはバイナリペイロードの代わりに設定マーカーが保存されます。このフェイルクローズの動作により、SQL は小さく保たれ、構成が不足していることが可視化されます。

## Builder.io ホスティング {#builder-hosting}

アプリが Builder.io に接続されている場合、ファイルのアップロードは自動的に Builder のアセットホスティングにルーティングされます。Builder.io の無料プランには、このマネージドストレージが含まれています。ファイルは構成不要で CDN から配信され、永続的な URL はチャットスレッドに保存されるため、後続のターンで再利用できます。これが推奨される本番環境の構成です。

## カスタムプロバイダー {#custom-providers}

このフレームワークには、S3 互換ストレージ (AWS S3、Cloudflare R2、MinIO など) 用の組み込みプロバイダーがすでに用意されています。環境変数、またはサイドバーのオンボーディングチェックリストから接続できます。コードは不要です。[オンボーディング](/docs/onboarding) を参照してください。

異なる種類のバックエンドの場合にのみ、カスタムプロバイダーを登録してください。次の例では、`fetch()` を使用して汎用の HTTP API 経由でアップロードします。

```ts filename="server/plugins/file-upload.ts"
import { registerFileUploadProvider } from "@agent-native/core/file-upload";
import { defineNitroPlugin } from "@agent-native/core/server";

export default defineNitroPlugin(() => {
  registerFileUploadProvider({
    id: "my-storage",
    name: "My Storage",
    isConfigured: () => !!process.env.UPLOAD_ENDPOINT,
    upload: async ({ data, filename, mimeType }) => {
      const endpoint = process.env.UPLOAD_ENDPOINT!;
      const body = new FormData();
      body.append("file", new Blob([data], { type: mimeType }), filename);

      // This example assumes an upload API that accepts a multipart file
      // and returns { url }. Adjust the request and response handling to
      // match your own provider's actual contract.
      const response = await fetch(endpoint, { method: "POST", body });
      if (!response.ok) {
        throw new Error(`Upload failed with status ${response.status}`);
      }

      const { url } = await response.json();
      return { url, provider: "my-storage" };
    },
  });
});
```

プロバイダーが API キーなどの実際の認証情報を必要とする場合は、環境変数の代わりに `@agent-native/core/server` の `resolveSecret()` を使用してください。[セキュリティ — シークレット管理](/docs/security#secrets) を参照してください。

## アップロード API {#upload-api}

`FileUploadProvider` インターフェース:

```ts
interface FileUploadProvider {
  id: string; // Unique id, e.g. "s3"
  name: string; // Human-readable name
  isConfigured: () => boolean; // True when ready from sync runtime state
  isConfiguredForRequest?: () => Promise<boolean>; // True from scoped DB secrets
  upload: (input: FileUploadInput) => Promise<FileUploadResult>;
}

interface FileUploadInput {
  data: Uint8Array | Buffer; // File contents
  filename?: string; // Original filename
  mimeType?: string; // MIME type, e.g. "image/png"
  ownerEmail?: string; // For request-scoped provider credentials
  stableUrl?: boolean; // Builder.io hint: one stable URL while compression finishes
  recordAsset?: boolean; // Builder.io hint: set false to skip the asset library
}

interface FileUploadResult {
  url: string; // Public URL for the uploaded file
  id?: string; // Provider-specific id
  provider: string; // Which provider handled it
}
```

actions またはサーバーコードで `@agent-native/core/file-upload` の `uploadFile()` を使用します。

```ts
import { uploadFile } from "@agent-native/core/file-upload";

const result = await uploadFile({
  data: fileBuffer,
  filename: "photo.jpg",
  mimeType: "image/jpeg",
});

if (result) {
  // Provider handled it. result.url is the public URL.
} else {
  // No provider configured. Show the storage setup CTA, or skip.
}
```

## 再開可能 / ストリーミングアップロード {#resumable}

プロバイダーは、ファイル全体を先にバッファリングするのではなく、データが到着するたびにストレージへストリーミングする必要があるアップロードのために、`FileUploadProvider` に `resumable` ブロックをオプションで実装できます。Clips テンプレートはこれを使用して、レコーダーが停止した後に完全な blob を組み立てるのではなく、録画中にチャンクごとに録画データをストレージへ中継します。

```ts
interface FileUploadProvider {
  // ...id, name, isConfigured, upload...

  resumable?: {
    startSession(
      filename: string,
      mimeType: string,
      maxBytes: number,
    ): Promise<ResumableUploadSession>;
    relayChunk(
      session: ResumableUploadSession,
      contentRange: string,
      bytes: Uint8Array,
      options?: { mimeType?: string },
    ): Promise<ResumableChunkResult>;
    completeSession(
      session: ResumableUploadSession,
      filename: string,
      options?: { stableUrl?: boolean; recordAsset?: boolean },
    ): Promise<string>;
    // Best-effort provider cleanup for a session the caller will not resume.
    abortSession?(session: ResumableUploadSession): Promise<void>;
  };
}

interface ResumableUploadSession {
  sessionId: string; // Provider-specific: GCS Location URI, S3 UploadId, etc.
  meta: Record<string, unknown>; // Provider state carried between calls
}

interface ResumableChunkResult {
  ok: boolean;
  status: number;
  updatedMeta?: Record<string, unknown>; // Merged back into the stored session
}
```

`resumable` が存在する場合、レコーダーのようにデータをストリーミングして送り込む呼び出し元は、`startSession` を一度呼び出し、バイトが到着するたびに `relayChunk` を繰り返し呼び出し、ストリームが終了したら `completeSession` を呼び出します。これは、単一のバッファリングされた `upload()` 呼び出しを置き換えるものです。`resumable` ブロックを持たないプロバイダーは、常にバッファリングされたパスのみを利用します。ストレージバックエンドに、公開する価値のあるネイティブなチャンク/再開可能アップロード API (S3 のマルチパート、GCS の再開可能アップロードなど) がある場合にのみ実装してください。

## 次は何ですか

- [**データベース**](/docs/server-database) — `uploadFile()` が返す URL を永続化するための `getDb()`/スキーマパターン
- [**セキュリティ — シークレット管理**](/docs/security#secrets) — `resolveSecret()` と資格情報ボールトがプロバイダーキーを保存時にどのように暗号化するか
- [**オンボーディング**](/docs/onboarding) — サイドバーのチェックリストにカスタムプロバイダーの設定ステップを登録する
