# アプリ

エージェントネイティブアプリには 2 つの形態があります。フルブラウザ UI を備えたテンプレートと、UI を持たない automation-first アプリ (Slack ボット、夜間レポート、webhook レスポンダーなど) です。このページではテンプレートを扱います。もう一方の形態については [Automation-First Apps](/docs/pure-agent-apps) を参照してください。

テンプレートは、UI、データベース、認証、エージェントがすでに構築され組み込まれた、完全な SaaS 製品です。1 つを選んでブランド化し、空の足場から始める代わりに独自の製品としてデプロイします。このモデルは複製可能な SaaS と呼ばれます。足場ではなく、完成した製品から始めるのです。

## サンプルアプリ {#catalog}

各アプリは、今日すぐに実行でき、自分用にカスタマイズできる完成した製品です。

| アプリ                                    | それは何ですか                                                                                                                          |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| [**Chat**](/docs/template-chat)           | 耐久性のあるスレッド、actions、認証、カスタム UI または独自のバックエンドへのクリーン パスを備えた最小限のチャット ファースト アプリ。  |
| [**Mail**](/docs/template-mail)           | エージェント出身のスーパーヒューマン。受信箱、ラベル、AI トリアージ、キーボードファースト、下書き、エージェント経由の送信。             |
| [**Calendar**](/docs/template-calendar)   | エージェントネイティブの Google Calendar。イベント、同期、公開予約リンク、エージェント主導のスケジューリング。                          |
| [**Content**](/docs/template-content)     | MDX 用のオープンソース Obsidian。ローカル Markdown/MDX、Tiptap エディター、Notion 同期、リアルタイム マルチユーザー コラボレーション。  |
| [**Brain**](/docs/template-brain)         | 引用された機関の記憶、承認された情報源、レビューゲート、および引用に裏付けられたクリーンな社内チャット。                                |
| [**Assets**](/docs/template-assets)       | ブランド ライブラリ、アップロード、参照、ブランド上の画像/動画生成のためのデジタル アセット マネージャー。                              |
| [**Slides**](/docs/template-slides)       | エージェントネイティブの Google スライド。エージェントが直接生成および編集する React ベースのデッキ。                                   |
| [**Analytics**](/docs/template-analytics) | エージェントネイティブの振幅/ミックスパネル。データ ソースを接続し、グラフのプロンプトを表示し、ダッシュボードに固定します。            |
| [**Clips**](/docs/template-clips)         | 文字起こし、チャプター、AI 概要を含む非同期画面 + カメラ録画。                                                                          |
| [**Design**](/docs/template-design)       | インタラクティブな Alpine/Tailwind 設計のためのエージェントネイティブの HTML プロトタイピング スタジオ。                                |
| [**Forms**](/docs/template-forms)         | エージェントネイティブの Typeform。提出物を作成、共有、収集し、Slack、スプレッドシート、webhooks、または Discord にルーティングします。 |
| [**Plan**](/docs/template-plan)           | 図、ワイヤーフレーム、注釈を使用した視覚的な計画と PR の要約。                                                                          |
| [**Dispatch**](/docs/template-dispatch)   | ワークスペース コントロール プレーン: 共有シークレット、再利用可能な統合、Slack/テレグラム、スケジュールされたジョブ。                  |

これらのいずれもドメインに合わない場合は、[Chat](/docs/template-chat) から始めて、actions、ネイティブ結果、画面で拡張してください。workflow にブラウザー UI が不要な場合は [Automation-First Apps](/docs/pure-agent-apps) を使用します。

各アプリには、アーキテクチャ、actions、カスタマイズについて説明する独自のドキュメントがあります。ホストされているライブ版は [agent-native.com/apps](/apps) で参照できます。ワークスペース スタイルのアプリが必要な場合は [Dispatch](/docs/template-dispatch) から始めてください。

## コミュニティテンプレート {#community-templates}

CLI ピッカーに名前が表示されるテンプレートは**ファーストパーティ**です。
Agent Native がフレームワークとともに保守、テスト、文書化、リリースします。
**コミュニティテンプレート**の保守とバージョン管理は、そのリポジトリの
所有者が行います。同じフレームワーク機能を利用できますが、コミュニティ
一覧への掲載は、Agent Native による推奨やサポートの保証ではありません。

`create` を実行し、**コミュニティテンプレート** を選び、公開 GitHub
リポジトリのシンプルな URL を貼り付けます。

```bash
https://github.com/owner/repo
```

リポジトリのルートが単一の Agent Native アプリなら、CLI は別のピッカーを
表示せず直接インストールします。Agent Native ワークスペースなら、CLI は
`apps/*` の有効な直接の子を検出し、`dispatch` を除外して、インストールする
アプリを尋ねます。

空でない `agent-native.workspaceCore` マーカーがあるリポジトリは、ルート
package も `@agent-native/core` に依存していてもワークスペースとして扱われ
ます。不正なマーカーは拒否されます。

スクリプトでは同じシンプルな URL を `--template` に渡すか、短い
`community:` 形式を使用します。再現可能な開始点が必要な場合は、`#` の後に
branch、tag、または commit を固定します。ref を省略すると、CLI は `main`、
次に `master` を試します。

```bash
npx @agent-native/core@latest create my-app --template community:owner/repo#v1.2.0
npx @agent-native/core@latest create my-app --template https://github.com/owner/repo#v1.2.0
```

ワークスペースリポジトリのソースアプリを非対話形式で選ぶには、
`?app=<app-name>` を使用します。このセレクターは省略可能な `#ref` の前に
置きます。zsh などの shell は `?` を glob として扱うため、値全体を引用符で
囲んでください。

```bash
npx @agent-native/core@latest create my-app --template 'community:owner/repo?app=analytics#v1.2.0'
npx @agent-native/core@latest create my-app --template 'https://github.com/owner/repo?app=analytics#v1.2.0'
```

ワークスペース外では、`create` は選択したソースアプリをスタンドアロンに
します。既存のワークスペースに追加する場合は、`add-app` ピッカーには
ファーストパーティテンプレートしか表示されないため、コミュニティリポジトリを
明示的に渡します。ソースワークスペースから対話形式で選ぶ場合は `?app` を
省略し、スクリプト化する場合は指定します。

```bash
npx @agent-native/core@latest add-app my-app --template community:owner/repo#v1.2.0
npx @agent-native/core@latest add-app my-app --template 'community:owner/repo?app=analytics#v1.2.0'
```

公開 GitHub リポジトリだけが使用できます。非公開リポジトリ、GitHub 以外の
ホスト、GitHub の tree URL やサブディレクトリ URL、ネストしたアプリパスは
サポートされません。ルートアプリには、`dependencies`、`devDependencies`、
または `peerDependencies` に `@agent-native/core` を記載した、読み取り可能な
`package.json` が必要です。ワークスペースリポジトリでは、選択可能な各
ソースアプリが `apps/<app-name>/` の直下で同じ要件を満たす必要があります。
`dispatch` は選択できません。

コミュニティワークスペースアプリは、monorepo の任意の一部分ではなく、
移植可能な単独の単位である必要があります。

- デフォルトの `catalog:` 依存関係は、ソースリポジトリのルートにある
  `pnpm-workspace.yaml` から解決されます。名前付き catalog 参照は
  サポートされません。
- `@agent-native/core`、`@agent-native/dispatch`、
  `@agent-native/toolkit` への `workspace:*` 参照は公開済みバージョンに
  書き換えられます。他の sibling workspace package はコピーされないため、
  公開して具体的なバージョンを使用してください。
- ソース `workspaceCore` への依存関係は削除されます。継承された標準の
  workspace auth と agent-chat plugin は、スタンドアロンインストールでは
  切り離され、対象ワークスペースでは再接続されます。ソース
  `workspaceCore` package のその他の import は明確なエラーになります。
  そのコードをアプリへ移すか、具体的な依存関係として公開してください。

各アプリの残りもその `package.json` と一緒に配置します。使用する場合の
`agent-native.json`、ソース、actions、エージェントの指示、データベース
設定です。カタログ掲載に適したリポジトリには、さらに次のものを含めます。

- ライセンスと、メンテナーまたはサポートへのリンク
- セットアップ手順、必要な環境変数、正確な CLI コマンドを記載した README
- プレースホルダーだけを含み、secret、顧客データ、実行時データベース、
  生成されたビルド出力を含まない `.env.example`
- 正常に動作するインストールと開発コマンド、typecheck、テンプレートに
  適したテスト

インストーラーは解決した `source` と `ref` を、インストールしたアプリの
`package.json` にある `agent-native.communityTemplate` に記録します。
ワークスペースリポジトリから選択したアプリは、ソースアプリも
`agent-native.communityTemplate.app` に記録します。`agent-native template
sync` は引き続きファーストパーティ専用です。コミュニティテンプレートを
更新する場合は、新しい upstream ref を確認し、自分で変更をマージします。

アプリ、action、state、security、公開に関する完全なチェックリストは
[Creating Templates](/docs/creating-templates) を参照してください。

> **依存関係をインストールしたり実行したりする前に、コミュニティコードを
> 確認してください。** コミュニティテンプレートは第三者のリポジトリから
> ダウンロードされます。Agent Native はそれらを sandbox 化、監査、保守
> しません。CLI はソースをダウンロードするだけで、依存関係のインストールや
> テンプレートスクリプトの実行は行いません。ソース、ライセンス、依存関係、
> package install scripts を確認し、信頼できる ref を固定してください。

ホストされたデモは任意です。提供する場合は、一般公開された試用リンクにし、
sign-in、seed data、provider の要件を記載してください。インストール元の
正本はリポジトリであり、テンプレートとデモの両方に対する責任はリポジトリ
所有者にあります。

掲載を希望しますか？リポジトリ URL、1 文の説明、メンテナーとライセンスの
詳細、テスト済みの CLI コマンド、任意のホスト済みデモ URL を添えて、
[コミュニティテンプレートを送信](https://github.com/BuilderIO/agent-native/issues/new?template=community-template.yml)
してください。

## 箱から出してすぐに手に入るもの {#what-you-get}

すべてのサンプルアプリには次が含まれます:

- **機能するエージェント** — アプリに組み込まれ、データに対して actions を実行でき、見ているものを認識しています。[Messaging the agent](/docs/messaging) を参照してください。
- **認証** — サインイン、セッション、組織、マルチテナント分離。
- **データベース** — すぐに使えるスキーマ、クエリ、マイグレーション。独自の SQL データベース (Postgres、SQLite、Turso、D1) を持ち込めます。フレームワークが適応します。
- **リアルタイム UI** — 画面はエージェントと同期したままになります。たとえば、チャットでメールを下書きすると、受信トレイがすぐに更新されます。
- **デプロイ準備完了** — Netlify、Vercel、Cloudflare、AWS、または Node を実行する任意のホストにデプロイできます。
- **ブランディングフック** — 名前、色、ロゴ、コピーを変更できます。

フレームワークのメンテナーは、メール、カレンダー、分析を Mail、Calendar、Analytics アプリで運用しています。

1. **アプリを選択します。** CLI ピッカーを使用するか、ドキュメントを参照してください。
2. **ブランド化します。** 名前、色、ロゴ、コピーを変更します。ほとんどのサンプルアプリは、これを単一の構成ファイルで公開します。
3. **カスタマイズします。** 自分のリポジトリと開発ワークフローでソースを変更します。エージェントの frame に workspace と書き込みツールが意図的に与えられていれば支援でき、それ以外では埋め込みエージェントが actions、データ、設定済みの統合を通じてアプリを操作します。
4. **出荷します。** デプロイ コマンドを実行します。これで、独自のドメインに実稼働アプリができました。

ステップ 2 ～ 4 は通常数日で終わります。ステップ 3 には決まった終わりがありません。アプリは自分のものとして進化させられ、埋め込みエージェントはデプロイ済み製品を操作し続け、コードアクセスが明示的に有効な場合はソース変更も支援できます。

## これが実用的な理由 {#why}

ユーザーごとに別のコードベースを持つ方法はスケールしません。すべてのユーザーのためにアプリのフォークを維持するのは管理できなくなります。2 つのフレームワークの決定がそれを回避します。

1. **アプリがフレームワーク契約を維持します。** ソースがドメイン動作を所有し、Core はアプリの進化に合わせて actions、SQL、状態、同期の一貫性を保ちます。
2. **ユーザーごとのコードを使用しないユーザーごとのカスタマイズ。** Skills、メモリ、命令、接続された MCP サーバー、およびサブエージェントはすべて SQL に存在します。すべてのユーザーは独自のカスタマイズ レイヤーを取得します。共有コードベースはそれらすべてを一度にホストします。

結果: ユーザーごとのデプロイなしで、ユーザーごとのカスタマイズを実現します。

## カスタマイズしたくないですか? {#hosted}

すべてのサンプルアプリは、`agent-native.com` — `mail.agent-native.com`、`calendar.agent-native.com` など — でホストされる製品としても利用できます。ホストされたバージョンを無料または有料で使用してください。ホストされたバージョンが公開していないものを変更したい場合は、テンプレートから自分の app を作成してください。

## スキルを使って試してみましょう {#try-with-a-skill}

アプリを足場立てせずに、すでに使用しているコーディング エージェントにエージェントネイティブの機能を追加できます。[Skills Guide](/docs/skills-guide#app-backed-skills) を参照してください。

### 開発者向け {#dev-details}

新しいアプリをスキャフォールディングするには:

```bash
npx @agent-native/core@latest create my-platform
```

CLI は最初に **どのように始めますか？** と尋ねます。Chat と Dispatch を含む最小ワークスペースには **Chat** を、複数選択ピッカーを開くには **First-party template(s)** を選択します。Community と Headless はスタンドアロン アプリの選択肢です。ワークスペースのアプリは認証、ブランド、エージェント構成、データベースを共有し、各アプリは必要なすべてのファイルとともに `apps/<name>/` にスキャフォールディングされます。アプリ UI の代わりにブラウザー UI のない automation を作る場合は、`npx @agent-native/core@latest create my-agent --headless` を使用します。

`.env` (`ANTHROPIC_API_KEY` と `DATABASE_URL`) を入力し、`pnpm install` と `pnpm dev` を実行してください。実装が必要なログインやプレースホルダー ルートはありません。

デプロイターゲット: Nitro 互換ホスト (Node、Cloudflare、Netlify、Vercel、Deno、Lambda、Bun) および Drizzle 互換 SQL データベース (SQLite、Postgres、Turso、D1、Supabase、Neon)。ワークスペースの場合、`npx @agent-native/core@latest deploy` はすべてのアプリを一度に構築し、単一のオリジンの背後で出荷します。 [Deployment](/docs/deployment) を参照してください。

独自のアプリテンプレートを作成して公開するには、[Creating Templates](/docs/creating-templates) を参照してください。
