# Vercel

Vercel がアプリをホストしてくれるため、サーバーを用意したり動かし続けたりする必要はありません。ビルドによって、アプリは Vercel が直接配信するファイルと、Vercel が必要に応じて実行する関数に変換されます。また、Vercel はアプリに HTTPS 対応の公開アドレスを割り当てます。

このガイドでは、スタンドアロン アプリを 1 つ、ゼロからデプロイする手順を説明します。アプリを作成し、本番用のデータベースと認証シークレットを用意し、Vercel プロジェクトにリンクし、データベースを準備してから、ビルドしてデプロイします。

<Callout tone="info">

Node.js `22.22+` が必要です。

</Callout>

Vercel アカウントも必要です。このガイドのコマンドは自分のコンピューター上で実行してください。完成したビルドは Vercel CLI が Vercel にアップロードします。

## ステップ 1: アプリを作成する {#step-1-create-the-app}

新しいスタンドアロン アプリを作成します。以下の例では Chat テンプレートからアプリを作成していますが、どのテンプレートから始めてもかまいません。アプリのフォルダーに移動し、依存関係をインストールします。`corepack enable` はアプリが想定する `pnpm` のバージョンを有効にするため、`pnpm` を自分でインストールする必要はありません。

```bash
npx --yes @agent-native/core@latest create my-app --standalone --template chat

cd my-app

corepack enable

pnpm install
```

必要に応じて、`my-app` を自分のアプリ名に置き換えてください。このガイドの以降の手順は、アプリのフォルダー内にいることを前提としています。

<Callout tone="info">

これらのコマンドがピア依存関係のエラーで失敗する場合は、npx キャッシュ内の古いパッケージが原因の可能性があります。`npx clear-npx-cache` を実行してキャッシュを消去してから、もう一度コマンドを実行してください。

</Callout>

## ステップ 2: 環境シークレットを設定する {#step-2-configure-environment-secrets}

アプリは本番用の設定を環境変数から読み取ります。

| 変数                 | 必須   | 用途                                                 |
| -------------------- | ------ | ---------------------------------------------------- |
| `DATABASE_URL`       | はい   | アプリを PostgreSQL データベースに接続する           |
| `BETTER_AUTH_SECRET` | はい   | ユーザー セッションに署名する                        |
| `BETTER_AUTH_URL`    | いいえ | ユーザーがアプリにアクセスする公開アドレスを設定する |

以下の export により、このシェルで後続のコマンドが動作するようになります。デプロイする前に、同じ変数をホストのプロジェクトまたはサービスの環境設定にも保存してください。Vercel に保存する方法は次のステップで説明します。

### データベース URL {#database-url}

ローカル開発中、`DATABASE_URL` が設定されていない場合、アプリはデータをローカル データベースに保存します。デプロイしたアプリには、デプロイ後もデータを保持する本物の PostgreSQL データベースが必要です。Vercel はリクエスト間でファイルを保持しないため、データベースは Vercel の関数の外に置く必要があります。プロバイダーから接続文字列をコピーし、export します。

```bash
export DATABASE_URL='your-postgres-url-string'
```

各プロバイダーで接続文字列を確認する場所は、[データベース プロバイダー ガイド](/docs/neon)で説明しています。

<Callout tone="warning">

Neon、Supabase、Amazon RDS などの永続的な PostgreSQL プロバイダーを選択してください。

</Callout>

### 認証シークレット {#auth-secret}

この値は一度だけ生成し、デプロイ間で変更しないでください。

アプリは `BETTER_AUTH_SECRET` を使ってユーザー セッションに署名します。この値が変わると、サインイン中のすべてのユーザーがサインアウトされます。以下のコマンドでランダムな値を生成します。

```bash
export BETTER_AUTH_SECRET="$(openssl rand -hex 32)"
```

生成した値は、パスワード マネージャーなど、安全な場所に保存してください。デプロイのたびに同じ値を使用します。

### 公開 URL {#public-url}

省略可能です。カスタム ドメイン、リバース プロキシ、または固定の公開オリジンを必要とする認証や OAuth のフローを使う場合に設定します。

`BETTER_AUTH_URL` は、ユーザーがアプリにアクセスする公開アドレスです。設定しない場合、アプリは受信したリクエストごとに自身のアドレスを判断します。Vercel が割り当てるアドレスでは通常それで問題ありませんが、カスタム ドメインを接続する場合は、サインイン リンクや OAuth のリダイレクトがそのドメインを使うように設定してください。

```bash
export BETTER_AUTH_URL='https://your-domain.example'
```

## ステップ 3: プロジェクトをリンクしてシークレットを保存する {#step-3-link-the-project-and-save-the-secrets}

コマンドラインから Vercel にサインインします。

```bash
npx vercel login
```

アプリのフォルダーを Vercel プロジェクトにリンクします。新しいプロジェクトを作成してください。その設定をカスタマイズする必要はありません。

```bash
npx vercel link
```

CLI はフォルダー名に基づいてプロジェクト名を提案します。提案された設定をそのまま受け入れてかまいません。アプリはステップ 5 で自分でビルドするため、Vercel 側のビルド設定は必要ないからです。

必須の 2 つの変数を、プロジェクトの本番環境に保存します。

```bash
printf '%s' "$DATABASE_URL" | npx vercel env add DATABASE_URL production

printf '%s' "$BETTER_AUTH_SECRET" | npx vercel env add BETTER_AUTH_SECRET production
```

各コマンドはステップ 2 で export した値を読み取って Vercel に保存するため、シークレットを手で貼り付ける必要はありません。`BETTER_AUTH_URL` を設定した場合は、同じ方法で保存してください。これらの値は、後から Vercel ダッシュボードのプロジェクト設定で確認したり変更したりすることもできます。

## ステップ 4: マイグレーション {#step-4-migrate}

マイグレーションは、アプリに必要なテーブルをデータベースに作成し、更新します。最初のデプロイの前にこれを実行してください。

```bash
pnpm migrate:production
```

このコマンドは自分のコンピューター上で実行され、ステップ 2 で export した `DATABASE_URL` を使って本番データベースに接続します。アプリをアップグレードした後は、新しいバージョンをデプロイする前にもう一度実行してください。

## ステップ 5: デプロイ {#step-5-deploy}

Vercel 向けにアプリをビルドします。

```bash
NITRO_PRESET=vercel pnpm build
```

`NITRO_PRESET=vercel` は、Vercel が想定する形式でアプリをビルドし、`.vercel/output` フォルダーに書き出します。

ビルドをアップロードして公開します。

```bash
npx vercel deploy --prebuilt --prod
```

`--prebuilt` は、Vercel 上でアプリを再ビルドせずに、作成したばかりのビルドをアップロードします。`--prod` はそれを本番アドレスに公開します。本番アドレスでは、本番環境に保存した変数が使われます。

コマンドが完了すると、アプリの本番アドレスが表示されます。そのアドレスを開き、最初のアカウントを作成します。

## 更新をデプロイする {#deploy-updates}

新しいバージョンをリリースするには、アプリのフォルダーからマイグレーション、ビルド、デプロイのコマンドをもう一度実行します。

```bash
pnpm migrate:production

NITRO_PRESET=vercel pnpm build

npx vercel deploy --prebuilt --prod
```

プロジェクトのリンクと保存した変数はそのまま残るため、ステップ 3 を繰り返す必要はありません。

## スケジュールされた作業 {#vercel-scheduled-work}

スケジュールされた自動化、キューに入ったイベント自動化、中断された実行のクリーンアップは、すべて 1 分に 1 回のスイープで行われます。ビルドは、`/_agent-native/jobs/_process-sweep` のスイープを呼び出す [Vercel cron job](https://vercel.com/docs/cron-jobs) を追加します。ワークスペースビルドでは、アプリごとに 1 つの cron job が `/<app-id>/_agent-native/jobs/_process-sweep` に追加されます。

デプロイ前に、プロジェクトの環境変数に `CRON_SECRET` を設定してください。Vercel は各 cron リクエストでこれを bearer トークンとして送信し、スイープはこれを持たないリクエストをすべて拒否します。値は `openssl rand -hex 32` で生成してください。

- **本番のみ。** Vercel は cron job を本番デプロイでのみ実行し、プレビューでは実行しないため、プレビューではスケジュールが起動しません。**Automations** ページにもその旨が表示されます。
- **Hobby は 1 日 1 回。** Vercel は、cron job が 1 日に複数回実行される Hobby デプロイを拒否します。ビルド環境で `AGENT_NATIVE_VERCEL_CRON_SCHEDULE` を `0 9 * * *` のような 1 日 1 回の式に設定してください。また Hobby では、その 1 時間内の任意の時刻に実行されることがあります。スイープが 1 日 1 回の場合、スケジュールされた自動化とイベントトリガーの自動化は最大 1 日待つことになるため、タイミングが重要な場合は Pro または別のホストを使用してください。
- **関数の実行時間。** スイープは実行時刻を迎えたジョブを cron job の関数呼び出しの中で実行するため、ジョブは関数の最大実行時間 (デフォルトは 300 秒) で打ち切られます。
- **再試行なし。** Vercel は失敗した cron 呼び出しを再試行しません。スイープは次のスケジュール時刻に再び実行されます。

他のホストについては、[スケジューラの実行方法](/docs/recurring-jobs#how-scheduler-runs) を参照してください。
