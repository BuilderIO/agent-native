# 開発者ガイド

このページは、Chat テンプレートを動かしたり拡張したりする開発者のためのものです。
クイックスタート、組み込みのすべての action、データモデル、action の実例、ルート、
そして最初の機能の追加方法を扱います。アプリが何をするかについては
[Chat](/docs/template-chat) を参照してください。

## クイックスタート {#quick-start}

何もインストールされていない状態から、エージェントとのライブの会話までを通して
Chat を動かす手順を説明します。macOS の Terminal でも Windows の
PowerShell/コマンド プロンプトでも、コマンドは同一です。単純な
Node.js のツール群だからです。

<Steps>

### アプリを作成する

```bash
npx --yes @agent-native/core@latest create my-chat-app --standalone --template chat
cd my-chat-app
corepack enable
pnpm install
```

これには [Node.js](https://nodejs.org) 22.22 以降が必要です。`pnpm` が `PATH` に
ない場合は、生成されたアプリで `corepack enable` を実行してください。Node.js をまだ
インストールしていない場合は、[はじめに](/docs/getting-started) を参照してください。

### 開発サーバーを起動する

```bash
pnpm dev
```

アプリは、`pnpm dev` が表示するローカル URL で開きます。自動的に開かない場合は、
その URL をブラウザで開いてください。8080 がすでに使用中の場合は、ポートが変わる
ことがあります。

### サインインして LLM を接続する

Welcome 画面で **Continue as local dev** を選択します。ローカル開発ではメール
アドレスもパスワードも不要です。次に LLM を接続します。無料クレジットを使うには
**Builder.io を使用** を、お持ちのモデル プロバイダーのキーを使うには
**Add your own keys** を選択します。Chat にはシードするドメイン データがないため、
LLM を接続すれば、チャットを始める前にほかに設定するものはありません。

</Steps>

Chat はブラウザ UI 向けに作られています。スケジュール ジョブ、キュー、CLI ループ、
外部エージェントのワークフローなど、画面のないエージェントが必要な場合は、
代わりに `--headless` でスキャフォールドしてください。

```bash
npx --yes @agent-native/core@latest create my-agent --headless
```

重要な考え方は変わりません。actions は、チャット、UI、HTTP、MCP、A2A、CLI に共通の
サーフェスです。この道筋の詳細は [オートメーション ファースト アプリ](/docs/pure-agent-apps)
を参照してください。

## Action 一覧 {#actions}

すべての操作は `actions/` 内の TypeScript ファイルで、action が `http: false` を
設定していない限り、`POST /_agent-native/actions/:name` に自動的にマウントされます。

| Action                 | 内容                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------- |
| `hello`                | サンプル action。あいさつを返します。置き換えるか、隣に action を追加してください。 |
| `view-screen`          | 標準のコンテキスト action。現在のビューをエージェントに読み返します。               |
| `navigate`             | 標準のナビゲーション action。UI をルートに移動します。                              |
| `provider-api-request` | 接続された Slack ワークスペースを通じて Slack Web API を呼び出します。              |

### チャット ランタイム {#chat-runtime}

`server/plugins/agent-chat.ts` は、チャット ランタイムを設定する場所です。次の
4 つを行います。

- `loadActionsFromStaticRegistry` で、`actions/` 内のすべての action を呼び出し可能な
  ツールとして登録します。
- `resolveOrgId` で、スコープ設定のために現在の組織を解決します。
- システム プロンプトを設定します。
- `initialToolNames` で、最初のターンでモデルに見えるツールを宣言します。

### action がツールになる仕組み {#actions-as-tools}

すべての `defineAction` は、既定でツールになります。action を画面からは使えるまま
エージェントからは隠したい場合は、`agentTool: false` を設定してください。

### モデルが最初に見るもの {#initial-tools}

`INITIAL_TOOL_NAMES` には `view-screen`、`navigate`、`hello`、
`provider-api-request` が並んでいます。最初のターンで送られるツールはこれだけです。
追加した action を含め、それ以外はすべて `tool-search` を通じて利用でき、必要に応じて
読み込まれます。

最初のメッセージからモデルの既定のツールセットにその action を入れたい場合にだけ、
そのリストに名前を追加してください。

## データモデル {#data-model}

Chat には独自のテーブルがありません。自分で追加するまで `server/db/schema.ts`
もありません。アプリは、チャット スレッドとメッセージ、アプリケーション状態、
設定、セッション、リソース、実行履歴のためのフレームワークのコア テーブル上で
動作します。これらはフレームワークのものなので、編集しないでください。接続モデルと
新しいデータの置き場所については [データベース](/docs/server-database) を参照して
ください。

`useDbSync()` はすでにアプリ シェルに組み込まれています。エージェントや他の誰かが
SQL に書き込むと、クライアントは SSE、または 2 秒間隔のポーリング フォールバックで
その変更を受け取り、対応する React Query のキャッシュを無効化します。フックの API の
詳細は [`useDbSync`](/docs/client-data#usedbsync) を参照してください。

最初のテーブルは新しいファイルです。[最初の機能を追加する](#first-feature) を参照してください。

## 認証 {#auth}

認証は Better Auth で動作します。ログイン、サインアップ、セッション、組織があります。Chat は `server/plugins/auth.ts` で `createToolkitAuthPlugin` を使って設定しています。このファイルは `/` を公開にしてサインインのランディングを読み込めるようにし、`marketing: false` を設定しているので、サインイン ページにマーケティング文言はありません。アプリ名、キャッチコピー、機能の箇条書きを表示したい場合は、代わりに `marketing` オブジェクトを渡します。ローカルでも本番でも同じフローが動きますが、開発ではメール認証をスキップするので、すぐにサインアップして構築を始められます。認証モデルの全体 (セッション、組織、保護されたルート) については [認証](/docs/authentication) を参照してください。

**Database** (`/database`) は、すべてのテンプレートに付属するものと同じ
`DbAdminPage` です。アプリの SQL データベースに対する、直接的なテーブル ブラウザー
兼エディターです。その背後にある接続モデルについては
[データベース](/docs/server-database) を参照してください。

**Observability** (`/observability`) は、すべてのテンプレートに付属するものと同じ、
設定不要の `ObservabilityDashboard` です。あなた自身のデータベースにすでにある
データから計算された、すべてのエージェント実行のトレース、コスト、評価、
フィードバックを表示します。[エージェントの可観測性](/docs/observability) を
参照してください。

**拡張機能** は、サンドボックス化された Alpine.js のミニアプリです。Chat は、それらを
表示して実行するルート (`/extensions/:id`) をマウントし、`/extensions` を
`/settings/extensions` にリダイレクトします。Chat では Extensions が 2 か所でオフになっています。
Settings のページは、`app/routes/settings.tsx` が `useAgentSettingsTabs()` に
`extensionTools: true` を渡した場合にだけ表示されます。エージェントが拡張機能を作成できるのは、
`server/plugins/agent-chat.ts` で `frameworkTools.extensions` をオンにした場合だけです。
できることとできないことについては [拡張機能](/docs/extensions) を参照してください。

## カスタマイズする {#customizing}

アプリのすべての部分は編集可能なソースです。ここから始めてください。

- `actions/`: `defineAction` を使った新しいファイルを追加して、エージェントと
  フロントエンドの両方に新しい action を公開します。
- `app/routes/`: UI です。ルート ファイルを追加してページをマウントします。
- `server/db/schema.ts`: コア テーブルでは足りなくなったら、Drizzle で自分のテーブルを
  追加します。ローカルの PGlite とホスト型の Postgres で同じセマンティクスになるよう、
  コードは PostgreSQL 対応にしてください。
- `AGENTS.md`: エージェントへの指示。エージェントに新しい action や規則を教える
  ときはこれを更新してください。
- `.agents/skills/`: エージェントが従う詳細なパターン。

機能を追加する場合は、UI、action、skill または `AGENTS.md` のエントリ、そして
エージェントが確認する必要のあるアプリケーション状態という 4 つの領域すべてを
更新することを忘れないでください。それが、エージェントと UI を同等に保つ理由です。

### 独自のエージェント バックエンドを使う {#own-agent-backend}

このテンプレートは、既定で組み込みのアプリ エージェント ループを使います。カスタム
バックエンドを接続するには、UI を書き直す代わりに、エージェント チャット プラグインの
背後にあるチャット ランタイムを差し替えてください。チャット ルートは共有の
チャット サーフェスを囲む薄いレンダラーにとどめ、バックエンドの選択はサーバー
プラグインとランタイム アダプターに置きます。

モデルのオーケストレーションがすでに別の場所にあっても、認証、スレッド、actions、
UI 状態、デプロイ可能なページを備えたアプリが欲しい場合に使ってください。ランタイムの
選択肢については [ネイティブ チャット UI](/docs/native-chat-ui#byo-agent-runtimes) を
参照してください。

## 最初の機能を追加する {#first-feature}

ほとんどの最初の機能は同じ形をしています。テーブル、1 つか 2 つの actions、ページ、
ナビゲーション エントリ、そして `AGENTS.md` の更新です。このセクションでは、メモ機能を
4 つのパートで構築し、各ファイルの完全なコードを示します。エージェントにそのすべてを
任せることもできます。

> `notes` のデータモデルを追加して。メモには id、タイトル、本文、所有者がある。`/notes` にメモのページを表示し、作成と一覧の actions を追加して、チャットでもメモを作成できるようにして。

### 1. データ レイヤーを追加する

Chat には `server/db` フォルダーがないため、ここにある 3 つのファイルはすべて新規です。

スキーマがテーブルを定義します。`ownableColumns()` は所有者、組織、公開範囲の列を
追加し、`createSharesTable()` は共有用の対応するテーブルを追加します。

```ts filename="server/db/schema.ts"
import { sql } from "drizzle-orm";
import { pgTable, text } from "drizzle-orm/pg-core";
import {
  createSharesTable,
  ownableColumns,
} from "@agent-native/core/db/schema";

export const notes = pgTable("notes", {
  id: text("id").primaryKey(),
  title: text("title").notNull(),
  body: text("body").notNull(),
  createdAt: text("created_at")
    .notNull()
    .default(sql`now()`),
  ...ownableColumns(),
});

export const noteShares = createSharesTable("note_shares");
```

データベース クライアントは、actions に `getDb()` を提供し、メモを共有システムに
登録します。メモには詳細ページがないので、共有リンクは一覧を指します。

```ts filename="server/db/index.ts"
import { createGetDb } from "@agent-native/core/db";
import { registerShareableResource } from "@agent-native/core/sharing";

import * as schema from "./schema.js";

export const getDb = createGetDb(schema);
export { schema };

registerShareableResource({
  type: "note",
  resourceTable: schema.notes,
  sharesTable: schema.noteShares,
  displayName: "Note",
  titleColumn: "title",
  getResourcePath: () => "/notes",
  getDb,
});
```

マイグレーションは、アプリの起動時にテーブルを作成します。後の変更には新しい
エントリを追加し、すでに実行されたものは編集しないでください。

```ts filename="server/plugins/db.ts"
import { runMigrations } from "@agent-native/core/db";

export default runMigrations(
  [
    {
      version: 1,
      name: "notes",
      sql: `CREATE TABLE IF NOT EXISTS notes (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  body TEXT NOT NULL,
  created_at TEXT NOT NULL DEFAULT (now()),
  owner_email TEXT NOT NULL DEFAULT 'local@localhost',
  org_id TEXT,
  visibility TEXT NOT NULL DEFAULT 'private'
);
CREATE TABLE IF NOT EXISTS note_shares (
  id TEXT PRIMARY KEY,
  resource_id TEXT NOT NULL,
  principal_type TEXT NOT NULL,
  principal_id TEXT NOT NULL,
  role TEXT NOT NULL DEFAULT 'viewer',
  created_by TEXT NOT NULL DEFAULT '',
  created_at TEXT NOT NULL DEFAULT (now()),
  notified_at TEXT
);
CREATE INDEX IF NOT EXISTS notes_owner_org_idx ON notes (owner_email, org_id, created_at);
CREATE INDEX IF NOT EXISTS note_shares_resource_idx ON note_shares (resource_id, principal_type, principal_id)`,
    },
  ],
  { table: "notes_app_migrations" },
);
```

### 2. actions を追加する

各 action は `actions/` 内のファイルで、ファイル名がツール名になります。エージェントと
あなたのページは、同じ 2 つの actions を呼び出します。

`create-note` は、サインインしているユーザーを所有者として記録します。メモは、組織が
アクティブな場合はその組織に表示され、そうでない場合は作成者だけに表示されます。

```ts filename="actions/create-note.ts"
import { defineAction, fail } from "@agent-native/core/action";
import { z } from "zod";

import { getDb, schema } from "../server/db/index.js";

export default defineAction({
  description:
    "Create a note with a title and body. It is visible to the organization when one is active, otherwise only to its creator.",
  schema: z.object({
    title: z.string().min(1).describe("Short title for the note"),
    body: z.string().describe("Full text of the note"),
  }),
  run: async (args, ctx) => {
    const ownerEmail =
      ctx?.userEmail ?? fail("Sign in to create notes.", { statusCode: 401 });
    const orgId = ctx?.orgId ?? null;
    const note = {
      id: crypto.randomUUID(),
      title: args.title,
      body: args.body,
      ownerEmail,
      orgId,
      visibility: orgId ? ("org" as const) : ("private" as const),
    };
    await getDb().insert(schema.notes).values(note);
    return { id: note.id, title: note.title };
  },
});
```

`list-notes` は読み取り専用で、`accessFilter` が結果を現在のユーザーが閲覧できる
メモに限定します。

```ts filename="actions/list-notes.ts"
import { defineAction } from "@agent-native/core/action";
import { accessFilter } from "@agent-native/core/sharing";
import { desc } from "drizzle-orm";
import { z } from "zod";

import { getDb, schema } from "../server/db/index.js";

export default defineAction({
  description: "List the notes the current user can see, newest first.",
  schema: z.object({}),
  http: { method: "GET" },
  readOnly: true,
  run: async () => {
    const { notes, noteShares } = schema;
    const rows = await getDb()
      .select({
        id: notes.id,
        title: notes.title,
        body: notes.body,
        createdAt: notes.createdAt,
      })
      .from(notes)
      .where(accessFilter(notes, noteShares))
      .orderBy(desc(notes.createdAt))
      .limit(200);
    return { notes: rows };
  },
});
```

新しい action は、作られた時点でチャットから呼び出せます。モデルの既定のツールセットに
入れたい場合は、[モデルが最初に見るもの](#initial-tools) を参照してください。

### 3. ページとサイドバーのリンクを追加する

アプリはファイル システム ルーティングを使うため、このファイルを追加すると `/notes` が
マウントされます。ページは `useActionQuery()` と `useActionMutation()` で、エージェントと
同じ actions を呼び出し、ミューテーションが成功すると一覧は自動的に更新されます。

```tsx filename="app/routes/notes.tsx"
import {
  useActionMutation,
  useActionQuery,
} from "@agent-native/core/client/hooks";
import { useSetPageTitle } from "@agent-native/toolkit/app-shell";
import { useState, type FormEvent } from "react";
import { toast } from "sonner";

import { Button } from "@/components/ui/button";
import { Input } from "@/components/ui/input";
import { Skeleton } from "@/components/ui/skeleton";
import { APP_TITLE } from "@/lib/app-config";

export function meta() {
  return [{ title: `Notes - ${APP_TITLE}` }];
}

export default function NotesRoute() {
  useSetPageTitle("Notes");
  const { data, isLoading } = useActionQuery("list-notes");
  const createNote = useActionMutation("create-note", {
    onError: (error) => toast.error(error.message),
  });
  const [title, setTitle] = useState("");
  const [body, setBody] = useState("");

  function handleSubmit(event: FormEvent) {
    event.preventDefault();
    createNote.mutate(
      { title, body },
      {
        onSuccess: () => {
          setTitle("");
          setBody("");
        },
      },
    );
  }

  return (
    <div className="mx-auto flex h-full max-w-2xl flex-col gap-6 overflow-auto p-6">
      <form onSubmit={handleSubmit} className="flex flex-col gap-2">
        <Input
          value={title}
          onChange={(event) => setTitle(event.target.value)}
          placeholder="Title"
          required
        />
        <Input
          value={body}
          onChange={(event) => setBody(event.target.value)}
          placeholder="Write a note"
        />
        <Button type="submit" disabled={createNote.isPending}>
          Add note
        </Button>
      </form>
      <ul className="flex flex-col gap-2">
        {isLoading && (
          <>
            <Skeleton className="h-16 w-full" />
            <Skeleton className="h-16 w-full" />
          </>
        )}
        {data?.notes.map((note) => (
          <li key={note.id} className="rounded-lg border p-3">
            <p className="font-medium">{note.title}</p>
            <p className="text-sm text-muted-foreground">{note.body}</p>
          </li>
        ))}
      </ul>
    </div>
  );
}
```
