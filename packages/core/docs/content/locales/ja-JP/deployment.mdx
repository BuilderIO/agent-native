# デプロイ

Agent-Native アプリは [Nitro](https://nitro.build) で動作するため、同じアプリを
Node.js、サーバーレス関数、エッジ ワーカー、マネージド ホストのいずれにもデプロイできます。
デプロイするものに合ったパスを選んでください。

<Cards columns={2}>

### :server: [アプリをデプロイ](/docs/deploy-an-app)

スタンドアロンのアプリを 1 つビルドし、Node.js、Docker、Vercel、Netlify、
Cloudflare Workers のいずれかで起動します。

### :network: [ワークスペースのデプロイ](/docs/workspace-deployment)

複数のアプリを 1 つのオリジンの下でビルドし、共有ログインと同一オリジンでのアプリ間通信を
利用します。

</Cards>

## デプロイ前に: 永続データベースを選択する {#persistent-database}

デプロイするすべてのアプリには、永続 PostgreSQL データベースが必要です。ローカル開発では
`data/pglite` にある PGlite データベースを使えますが、コンテナ、プレビュー、サーバーレスの
ファイルシステムはいつでもリセットされる可能性があります。

<Steps>

### プロバイダーを選ぶ

[Neon](/docs/neon)、[Supabase](/docs/supabase)、Railway、Render、[Amazon RDS for PostgreSQL](/docs/aws-rds)、
[Cloud SQL for PostgreSQL](/docs/cloud-sql)、[Azure Database for PostgreSQL](/docs/azure-postgresql) などの
ホスト型 PostgreSQL プロバイダーを使ってください。その他のマネージド サービスやセルフホスト型の
PostgreSQL サーバーについては、[Plain Postgres](/docs/postgres) ガイドを参照してください。
フレームワークは接続 URL から PostgreSQL を構成します。

### 接続文字列を設定する

最初の本番デプロイの前に、ホスティング プロバイダーの環境変数またはシークレットの設定で
`DATABASE_URL` を設定してください。ローカルの `.env` は自分のマシンだけを構成するもので、
デプロイ コマンドではアップロードされません。

### 本番用のシークレットを追加する

`openssl rand -hex 32` で安定した署名シークレットを生成し、スタンドアロン アプリでは
`BETTER_AUTH_SECRET` として設定します。署名付きのアプリ間リクエストやバックグラウンドでの
引き継ぎを使うワークスペースでは、`A2A_SECRET` も必要です。その他の本番設定については、
[デプロイ環境変数のリファレンス](/docs/deployment-environment-variables)で説明しています。

### マイグレーションを実行する

最初のアクセスの前に、本番データベースに対して `pnpm migrate:production` を実行してください。
これにより、アプリに必要なテーブルが作成されます。アップグレードのたびに、新しいバージョンを公開する前に
もう一度実行してください。このステップをどこで行うかは、各ホスティング ガイドで紹介しています。

</Steps>

<Callout tone="info">

ワークスペースでは、すべてのアプリがデフォルトでルートの `DATABASE_URL` を引き継ぎます。
1 つのアプリだけ別のデータベースが必要な場合にのみ、`<APP_NAME>_DATABASE_URL` を設定してください。

</Callout>

## メール配信は任意ですが、推奨されます {#email-provider}

メールプロバイダーはメール/パスワード認証に必須ではありません。プロバイダーがない場合、
デプロイしたアプリはメール/パスワードでサインアップとサインインを行い、サインアップ時の
メール確認をスキップし、マジックリンク認証を提供しません。

Agent-Native にはメール配信アカウントは含まれていません。マジックリンク、メール確認、
パスワードリセット、招待、共有通知が必要な場合は、デプロイ前に Resend または SendGrid を
接続してください。デプロイ環境に `RESEND_API_KEY` または `SENDGRID_API_KEY` を設定し、
SendGrid では `EMAIL_FROM` も設定します。利用できる認証モードについては、
[認証](/docs/authentication)を参照してください。

### フレームワークのメールをカスタマイズする {#email-templates}

フレームワークが送信するすべてのメールにはデフォルトのテンプレートがあります。独自のデザインを
使うには、サーバープラグインから override を登録します。宛先と送信者の決定、およびメッセージの
配信は引き続きフレームワークが担当します。メッセージの内容と見た目は override が決めます。

```ts
// server/plugins/email-templates.ts
import {
  escapeEmailHtml,
  overrideTransactionalEmail,
} from "@agent-native/core/server";

export default function registerEmailTemplates(): void {
  overrideTransactionalEmail("core.resource-shared", (props) => ({
    subject: `${props.sender.name} shared "${props.resource.title}"`,
    html: `<p>${escapeEmailHtml(props.sender.name)} invited you to
      <a href="${escapeEmailHtml(props.resource.url)}">${escapeEmailHtml(props.resource.title)}</a>
      in ${escapeEmailHtml(props.app.name)}.</p>`,
  }));
}
```

| メール ID                        | Props                                                                              |
| -------------------------------- | ---------------------------------------------------------------------------------- |
| `core.verify-signup`             | `email`, `verifyUrl`                                                               |
| `core.reset-password`            | `email`, `resetUrl`                                                                |
| `core.magic-link`                | `email`, `magicLinkUrl`                                                            |
| `core.change-email-confirmation` | `email`, `newEmail`, `confirmationUrl`                                             |
| `core.change-email-verification` | `email`, `verifyUrl`                                                               |
| `core.organization-invite`       | `invitee`, `orgName`, `inviter`, `acceptUrl`                                       |
| `core.builder-credit-limit`      | `subject`, `heading`, `body`, `upgradeLabel`, `upgradeUrl`                         |
| `core.resource-shared`           | `recipientEmail`, `sender`, `resource` (`type`, `title`, `url`), `role`, `message` |

すべての override は `app`（`name`、`logoUrl`）も受け取ります。第 2 引数にはデフォルトの
レンダリング結果が入っているので、その件名やテキストを再利用できます。

- Props はエスケープされていない値です。HTML 文字列に入れる前に `escapeEmailHtml` で
  エスケープしてください。
- コンポーネントをレンダリングするには、`html` の代わりに React 要素を `react` で返します。
  React が props をエスケープします。
- `subject` を省略するとデフォルトの件名が使われます。`text` を省略すると、HTML から
  プレーンテキスト本文が生成されます。
- override が例外を投げると、送信は失敗します。フレームワークはデフォルトのデザインに
  フォールバックしません。トランザクションメールのプレビューで override が表示されるので、
  そこで確認してください。

## 高度なデプロイ {#advanced-deployment}

まずは上記のパスから始めてください。プロバイダー固有の設定や本番環境の制御が必要な場合は、
次のページを参照してください。

- [**Node.js**](/docs/node-js) - デフォルトの Nitro サーバー プリセットを実行する
- [**Docker**](/docs/docker) - Node.js サーバーをコンテナにパッケージ化する
- [**Vercel**](/docs/vercel)、[**Netlify**](/docs/netlify)、[**Cloudflare Workers**](/docs/cloudflare#cloudflare-workers) - ホスト型ターゲットを構成する
- [**SSR キャッシュ**](/docs/ssr-caching) - 公開シェルのキャッシュを構成する
- [**デプロイ環境変数**](/docs/deployment-environment-variables) - 本番用のシークレット、ランタイム フラグ、ワークスペースでの引き継ぎ
- [**本番エージェントアクセス**](/docs/actions-agent-tools) - フレームワークのツールとコード実行を制御する
- [**本番環境での UI 更新**](/docs/updating-ui-in-production) - マネージドなビジュアル編集のワークフローを理解する

<a id="self-host-quickstart"></a>
<a id="skip-ensure-tables"></a>

これらのアンカーは、以前のリンクが引き続き機能するように残しています。コンテナを使ったセルフホストについては、
[Docker ガイド](/docs/docker)で説明しています。スキーマのセットアップとコールド スタートに関するガイダンスは、
[デプロイ環境変数のリファレンス](/docs/deployment-environment-variables#skip-ensure-tables)にあります。
