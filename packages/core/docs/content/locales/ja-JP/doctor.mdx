# Doctor

生成されたアプリと workspace のソースコードは、リポジトリの開発ワークフローで変更できます。意図的に workspace と書き込みツールを与えられたエージェント frame も変更できます。`agent-native doctor` はソースのセキュリティ上重要なコード不変条件を検査します。読み取り専用であり、コードを編集せず結果だけを報告します。

`agent-native doctor` はセキュリティと移行に関する問題を検査します。`migration-manifest` はインストール済み `migration-manifest.json` に記載された import を検出し、無効化できません。`feature-dependencies` は、設定された機能に必要な optional peer package を解決できない場合に報告します。

移行の事前確認を実行します。

```bash
agent-native doctor --only migration-manifest
```

ファイルを書き換えずに upgrade と codemod の差分をプレビューします。

```bash
npx agent-native upgrade --codemods --dry-run
```

対応する import の書き換えを適用します。

```bash
npx agent-native upgrade --codemods
```

`--codemods` は対応する書き換えをデフォルトで適用します。ファイルを書き換えずにプレビューするには `--dry-run` を追加してください。適用前に差分と警告を確認してください。`--yes` は互換性のために受け付けますが、動作には影響しません。`migration-manifest` は無効化できません。`planned` の項目は警告のみで、書き換えません。active な項目は finding になり、codemod は移行先の export がインストール済みの場合にだけ書き換えます。削除された export は手動で移行してください。finding に記載された guide、または `ts-morph` と optional feature package を記載した [Core 0.198.0 移行ガイド](/docs/upgrading-core-ui)を参照してください。JSON の `guardsRun` には実際に実行された guard が記載されます。

CLI は新しいすべての app と workspace に `pnpm doctor` と `pnpm agent-native:doctor` を追加します。workspace root から実行すると `apps/<name>` の各 app を検査します。finding がある場合、build はデフォルトで失敗します。`failOnBuild: false` はレビュー済みの例外に限り使用してください。

`planned` と記されたエントリは警告としてのみ表示され、書き換えられません。active なエントリは finding となり、codemod は移行先の export がインストール済みの場合にだけ書き換えます。
