# 機能

スライドのすべての中核機能について、その仕組みと設定方法を説明します。概要は
[スライド](/docs/template-slides) を、プロンプトの全リストは [Agent との対話](/docs/template-slides-agent) を参照してください。

## デッキ

個々のデッキの作成、編集、プレゼン、共有に関するすべてです。

### プロンプトからデッキを生成する

<Steps>

### 人に説明するのと同じようにエージェントに説明する

「コーヒーのサブスクリプション サービス向けに 10 枚のスライドのピッチデッキを生成して。対象は投資家です。」トピック、長さ、対象を伝えれば、それに沿ってアウトラインを組み立てます。

### スライドごとに組み立てられる様子を見る

エージェントは最初にアウトラインを計画し、その後デッキを 1 枚ずつ組み立てます。そのため、全体が一度に出来上がるのを待つのではなく、エディターに現れていく様子を見ることができます。

### 同じ会話の中で調整を続ける

「スライド 3 の後に価格スライドを追加して。」「このセクションを短くして。」頼んだスライドだけが変わります。

</Steps>

新しいデッキはすべて既定で 16:9 のワイドスクリーン キャンバスになります。別の形が必要なときは、1:1 (正方形)、9:16 (縦向き、ストーリーズ風)、4:5 (縦長) にエージェントに切り替えてもらいましょう。変更するとエディターのキャンバス、プレゼンテーション モード、PDF/PPTX エクスポートがまとめて更新されるので、作ったものと合わないエクスポートになることはありません。

### スライドを視覚的に編集する

- **インライン テキスト編集。** どのテキストもダブルクリックすれば、スライド上で直接編集できます。
- **バブル メニュー。** ブロック、見出し、箇条書き、画像をクリックすると、そのブロックだけに対するすばやい書式設定オプションが表示されます。
- **スラッシュ メニュー。** `/` を入力すると、キーボードから手を離さずに、見出し、箇条書き、表、コード ブロック、画像プレースホルダーなどの新しいブロックを挿入できます。
- **並べ替え。** フィルムストリップでスライドをドラッグして並べ替えます。取り消しとやり直しも期待どおりに動作します。
- **豊富な埋め込み。** スライドには、テキストや画像と並べて、手描きの図やライブでレンダリングされるチャートを含めることができます。静的な HTML だけではありません。
- **生成されたコンテンツの移動とサイズ変更。** オブジェクトをドラッグして移動するか、そのリサイズ ハンドルをドラッグしてサイズを変更します。枠線付きセクションを移動するには、そのテキストをドラッグします。

スライド上のテキストを選択し、バブル メニューの **AI で修正** ボタンをクリックすると、選択した内容をそのままエージェントに渡せます。または、スライド上の複数の要素を選択して **エージェントに送信** をクリックします。その後、右側のチャット ウィンドウでプロンプトを入力します。選択内容を認識した編集の仕組みについては [Agent との対話](/docs/template-slides-agent) を参照してください。

### 全画面でプレゼンする

**プレゼンテーション** をクリックすると、デッキが全画面で開きます。マウスを動かすまでコントロールはフェードアウトし、スピーカー ノートはあなただけに表示されたままになります。プレゼン中は、次のショートカットが使えます。

| キー                     | 操作                                  |
| ------------------------ | ------------------------------------- |
| `→`、`↓`、または `Space` | 次のスライド                          |
| `←` または `↑`           | 前のスライド                          |
| `F`                      | 全画面表示の切り替え                  |
| `S`                      | スピーカー ノートを別ウィンドウで開く |
| `Esc`                    | プレゼンテーション モードを終了       |

### リアルタイムでコメントし、共同作業する

ツールバーから **コメント** パネルを開くと、表示しているスライドのコメントを確認したり、追加したりできます。このパネルは、そのスライドだけに絞り込まれています。別のスライドに切り替えると、内容もそれに合わせて入れ替わるので、デッキ全体のコメントが一度に表示されることはありません。先にテキストを選択して新しいコメントで引用することもできますし、ツールバーの **コメントを固定** ツールを使って要素に直接、消えないピンを置くこともできます。

編集アクセス権があれば、誰でもコメントし、スレッドに返信できます。対応が終わったスレッドは解決済みにします。複数の人 (とエージェント) が同じデッキを同時に編集しても、互いの変更を上書きすることはありません。裏側の仕組みについては [リアルタイム コラボレーション](/docs/real-time-collaboration) を参照してください。

### デッキを共有する

デッキの共有方法は、他の Agent-Native リソースの共有と同じです。非公開のままにしたり、特定のチームメイトに閲覧者または編集者として共有したり、アカウントなしで誰でも開ける公開の読み取り専用リンクを生成したりできます。全体の仕組みについては [共有](/docs/sharing) を参照してください。

### 以前のバージョンを復元する

あなたによるものでもエージェントによるものでも、意味のある変更は必ず先にデッキをスナップショットするので、何かが黙って失われることはありません。バージョン履歴を開くと、過去のスナップショットのタイムラインが表示され、そのいずれかを復元できます。復元自体も先にスナップショットを取るので、復元が行き止まりになることはありません。

### デッキを他の形式とやり取りする

| 方向         | 形式                                 | 何が起こるか                                                                                                                                                    |
| ------------ | ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| インポート   | PPTX、DOCX、PDF、Google ドキュメント | 編集可能なスライドに変換されます。PDF や DOCX はページまたはセクションごとに 1 スライドになり、PPTX は元のスライド構成とスピーカー ノートをそのまま保持します。 |
| エクスポート | PPTX                                 | ネイティブで編集可能なテキスト、図形、画像です。各スライドを画像として平坦化したものではありません。                                                            |
| エクスポート | Google Slides                        | Google Slides には URL を直接開いてインポートする機能がないため、スライドは同じ PPTX を生成し、すぐに使えるインポート用リンクを渡します。                       |
| エクスポート | スタンドアロン HTML                  | キーボード ナビゲーションを内蔵した単一の自己完結型ファイルで、どこでもホストしたりメールで送ったりできます。表示にアプリは不要です。                           |

GitHub リポジトリ、コードベース、Web サイトの URL を取り込むのは、デッキのコンテンツをインポートするのとは別の機能です。これら 3 つは、[デザイン システム](#design-systems) で説明されているデザイン システムのインデックス作成に使われるものであり、スライド単位のコンテンツ インポートではありません。

## デザイン システム {#design-systems}

デザイン システムとは、プライマリ/アクセント/背景の色、見出しと本文のフォント、間隔、ロゴ、そして自由形式のカスタム指示 (「セクション ラベルは常に小文字にする」「ストック フォトは絶対に使わない」など) をまとめた、再利用可能なブランド アイデンティティの集合です。これは個々のデッキとは別のリソースです。1 つ保存しておけば、新しいデッキはどれも汎用的な既定値の代わりにそれを使えます。

### デザイン システムを追加する

<Steps>

### デザイン システムを開く

サイドバーから **デザイン システム** を開き、**新しいデザイン システム** をクリックします。

### ブランド素材を追加する

会社名と Web サイト、GitHub リポジトリ、コード ファイル、ドキュメント、参考画像やロゴ、メモ、カスタム指示など、持っているものを入力します。

### 「生成へ進む」をクリックする

これでデザイン システムの構築が始まります。次に何が起こるかは、何を提供したかによって変わります。

</Steps>

#### 次に何が起こるかはソースによって決まる

Figma ファイルをアップロードするか、GitHub リポジトリだけを入力すると、デザイン システムはすぐに構築されます。それ以外の場合は、代わりにサイドバーでエージェントが開き、そこで仕上げます。カラー ピッカーやフォント ピッカーはありません。ブランドカラーとフォントは、常にエージェントが解釈するソースから、またはメモやカスタム指示に入力した内容から得られます。

#### 既定値を設定する

1 つのデザイン システムを既定として設定すると、新しいデッキはすべて自動的にそれを使います。あるいは、新しいデッキを開始するときに明示的に選ぶこともできます。

### Builder との連携

Figma ファイル、接続されたコードベースや GitHub リポジトリ、または `design.md` には本格的な解析が必要なため、これらはローカルでの一発の推測ではなく Builder Design System Intelligence を経由します。

#### Builder を接続する

これには接続済みの Builder.io アカウントが必要です (無料プランがあります)。まだ接続していない場合、必要になった時点でエージェントが接続を促します。

#### Builder が信頼できる情報源のまま

ソースをインデックス化し、生成されたドキュメント、抽出されたトークン、使用ガイダンスを保持するのは Builder であり、スライドではありません。スライドはローカルに結果への軽量なポインターだけを保持するので、エージェントはデザイン システムを適用するたびに、Builder から最新のドキュメントを取得します。

### Figma ファイル

`.fig` ファイルは、ドロップした瞬間にインデックス作成が始まる唯一のソースで、エージェントとのチャット手順は不要です。セットアップ ダイアログの Figma パネルにファイルをドラッグするか、クリックして参照してください。スライドがそれをアップロードし、Builder Design System Intelligence のインデックス作成ジョブをすぐに開始します。インデックス作成が完了すると、その結果はどのデッキにも適用できるデザイン システムになります。

### デッキごとに適用して微調整する

デザイン システムがデッキにリンクされると、**微調整** パネルから、保存されたシステムを直接編集せずに、アクセントカラーのスウォッチ、タイトルの大文字/小文字、背景の色温度といった、その場で反映されるすばやい上書きができます。保持した変更は、デザイン システムへと反映されて残ります。
