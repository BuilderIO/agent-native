# وصول الوكيل الإنتاجي

## أدوات الوكيل الإنتاجي {#production-agent-tools}

يحصل الوكلاء الإنتاجيون على الإجراءات المسجَّلة الخاصة بالتطبيق بالإضافة إلى
أدوات الإطار نفسه. يحدد `frameworkTools` أي من أدوات الإطار هذه يعرضها
هذا التطبيق. كل مجموعة تعتمد افتراضيًا سلوك اليوم، لذا حذف الخيار لا
يغيّر شيئًا:

```ts filename="server/plugins/agent-chat.ts"
export default createAgentChatPlugin({
  frameworkTools: {
    database: "read", // "write" | "read" | "off", default "read"
    extensions: true, // default false
    sharing: false, // this app has no share surface
    review: false,
  },
});
```

```ts filename="server/plugins/core-routes.ts"
export default createCoreRoutesPlugin({
  extensionTools: true,
});
```

يقبل `database` و`extensions` نفس القيم التي كانت تقبلها الأعلام القديمة على المستوى الأعلى:

- `database: "read"`. الافتراضي. يسجّل فقط `db-schema` و`db-query`.
  يفحص الوكلاء البيانات باستخدام SQL ولكن يجب أن يستخدموا إجراءات التطبيق
  المُكتوبة للكتابة.
- `database: "write"` أو `true`. يسجّل بالإضافة إلى ذلك `db-exec` و
  `db-patch` لصيانة SQL خام متعمَّدة. الكتابات مقيَّدة بالمستخدم/المؤسسة
  الحالية وتغييرات المخطط محظورة.
- `database: "off"` أو `false`. يزيل أدوات قاعدة البيانات الخام من
  سطح الوكيل بحيث تكون إجراءات التطبيق هي مسار الوصول الوحيد للبيانات.
- `extensions: true`. يُدخل التطبيق في إجراءات إدارة الإضافات الخاصة
  بالإطار وتوجيهات المطالبة (`create-extension`، و`update-extension`، وما إلى ذلك).
  اضبط `extensionTools: true` على إضافة core-routes أيضًا للسماح
  بإنشاء REST مصادَق عليه. الإضافات مُعطَّلة افتراضيًا.

المجموعات المتبقية هي قيم منطقية، جميعها مُفعَّلة افتراضيًا: `sharing`، و`review`،
و`history`، و`featureFlags`، و`localization`، و`audit`، و`contextXray`،
و`userProfile`، و`automation`، و`docs`، و`resources`، و`web`، و`workspaceApps`،
و`chat`، و`email`. استخدم `frameworkTools: "minimal"` لإيقاف كل مجموعة دفعة
واحدة لتطبيق صوتي أولاً أو أحادي الغرض، أو
`frameworkTools: { preset: "minimal", resources: true }` للاحتفاظ بواحدة فقط. مفتاح
مجموعة صريح يفوز دائمًا على الإعداد المسبق.

يؤدي إيقاف مجموعة إلى إزالتها من أسطح **الوكيل** فقط: الدردشة التفاعلية،
وMCP، وA2A، والتشغيلات في الخلفية. تبقى مسارات إجراءات HTTP المطابقة
مُثبَّتة، لأن الواجهة تصل إليها من خلال خطافات العميل. تعطيل `sharing`
يجب ألا يُرجع 404 لمربع حوار مشاركة لا يزال على الشاشة. زِن تكلفة
التكافؤ هذه قبل استخدامه: عقد الإطار هو أن أي شيء يمكن للواجهة فعله
يمكن للوكيل فعله، لذا فإن `sharing: false` بجانب زر مشاركة مرئي هو
كسر متعمَّد، ولا يكون منطقيًا إلا عندما لا يملك التطبيق مثل هذا السطح
على الإطلاق.

لم تعد أدوات الإطار تُرقَّى إلى طلب النموذج الأول افتراضيًا، بغضّ النظر
عن هذا الخيار. تبقى في السجل القابل للبحث وتُحمَّل من خلال `tool-search`،
أو فورًا إذا سمّاها التطبيق في `initialToolNames`.

<Callout tone="warning">
  الخياران `databaseTools` و`extensionTools` على المستوى الأعلى مهجوران لصالح
  `frameworkTools.database` و`frameworkTools.extensions`. لا يزالان مدعومين،
  ولكن ضبط علم على المستوى الأعلى ومكافئه في `frameworkTools` على قيم متعارضة
  يرمي خطأً عند بدء تشغيل الإضافة بدلاً من الإقلاع بسطح أدوات لم يختره أحد.
</Callout>

## تنفيذ الكود الإنتاجي {#production-code-execution}

افتراضيًا، يعمل الوكلاء الإنتاجيون بدون أدوات تنفيذ الكود. يمكنهم استدعاء إجراءات التطبيق، وأدوات قاعدة البيانات، وأدوات MCP، وأدوات المتصفح/الجلسة، وأدوات الإطار المسجَّلة الأخرى، ولكنهم لا يحصلون على وصول إلى الصدفة أو نظام الملفات.

يمكن لعمليات النشر المتوافقة مع Node الانضمام إلى تنفيذ الكود الإنتاجي من خلال إضافة دردشة الوكيل أو تجاوز بيئة:

```ts filename="server/plugins/agent-chat.ts"
export default createAgentChatPlugin({
  codeExecution: { production: "sandboxed" },
});
```

الأوضاع المتاحة هي:

- `off`. الافتراضي. لا تُسجَّل أدوات تنفيذ كود في الإنتاج.
- `sandboxed`. يسجّل `run-code`، وهو مشغّل JavaScript Node.js معزول ببيئة مُنظَّفة، ودليل مؤقت جديد، وحدود للمخرجات/الوقت، وجسر localhost إلى أدوات مسجَّلة مسموح بها مثل `provider-api-request`، و`provider-api-docs`، و`provider-api-catalog`، و`web-request`، وجسر ملفات مساحة العمل المدعوم بالموارد المستخدَم بواسطة `workspaceRead` / `workspaceWrite`.
- `trusted`. يسجّل `run-code` بالإضافة إلى سجل أدوات الترميز الكامل (`bash`، و`read`، و`edit`، و`write`). استخدم هذا فقط لعمليات النشر أحادية المستأجر أو التي يتحكم فيها المشغّل حيث يكون الوصول الكامل للصدفة إلى المضيف متعمَّدًا.

اضبط `AGENT_PROD_CODE_EXECUTION=sandboxed` أو `AGENT_PROD_CODE_EXECUTION=trusted` لتجاوز خيار الإضافة لعملية نشر محددة دون تغيير في الكود. يفرض `AGENT_PROD_CODE_EXECUTION=off` إيقاف تنفيذ الكود حتى عندما يُفعِّله خيار الإضافة.

صندوق `run-code` المعزول هو عزل على مستوى العملية، وليس حاوية نظام تشغيل. إنه يزيل أسرار التطبيق من بيئة العملية الفرعية ويستخدم نموذج أذونات Node عند توفره، ولكن الشبكة الصادرة لا تُحظر بواسطة Node نفسه. يجب أن تمر الاستدعاءات المصادَق عليها عبر دوال مساعدة الجسر التي تعرضها الأداة.
