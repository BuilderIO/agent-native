# Netlify

يستضيف Netlify تطبيقك نيابةً عنك، لذلك لا يوجد خادم تحتاج إلى إعداده أو إبقائه
قيد التشغيل. يحوّل البناء التطبيق إلى ملفات ثابتة يقدّمها Netlify مباشرةً ودوال
يشغّلها Netlify عند الطلب، ويمنح Netlify التطبيق عنوانًا عامًا مع HTTPS.

يشرح هذا الدليل نشر تطبيق مستقل واحد من البداية. ستنشئ التطبيق، وتمنحه قاعدة
بيانات إنتاجية وسر مصادقة، وتنشئ موقع Netlify له، وتجهّز قاعدة البيانات، ثم تبني
التطبيق وتنشره.

<Callout tone="info">

يلزم Node.js `22.22+`.

</Callout>

تحتاج أيضًا إلى حساب Netlify. شغّل الأوامر في هذا الدليل على حاسوبك الخاص. يرفع
Netlify CLI البناء النهائي إلى Netlify نيابةً عنك.

## الخطوة 1: إنشاء التطبيق {#step-1-create-the-app}

أنشئ تطبيقك المستقل الجديد. ينشئ المثال أدناه تطبيقًا من قالب Chat، لكن يمكنك
البدء من أي قالب. انتقل إلى مجلد التطبيق وثبّت تبعياته. يفعّل الأمر
`corepack enable` إصدار `pnpm` الذي يتوقعه التطبيق، لذلك لا تحتاج إلى تثبيت
`pnpm` بنفسك.

```bash
npx --yes @agent-native/core@latest create my-app --standalone --template chat

cd my-app

corepack enable

pnpm install
```

استبدل `my-app` باسم تطبيقك إذا أردت. يفترض باقي هذا الدليل أنك داخل مجلد
التطبيق.

## الخطوة 2: ضبط أسرار البيئة {#step-2-configure-environment-secrets}

يقرأ التطبيق إعدادات الإنتاج من متغيرات البيئة:

| المتغير              | مطلوب | الغرض                                              |
| -------------------- | ----- | -------------------------------------------------- |
| `DATABASE_URL`       | نعم   | يربط التطبيق بقاعدة بيانات PostgreSQL الخاصة به    |
| `BETTER_AUTH_SECRET` | نعم   | يوقّع جلسات المستخدمين                             |
| `BETTER_AUTH_URL`    | لا    | يحدد العنوان العام الذي يستخدمه الناس للوصول إلى تطبيقك |

تجعل أوامر التصدير أدناه الأوامر التالية تعمل في هذه الصدفة. قبل النشر، احفظ
المتغيرات نفسها في إعدادات بيئة المشروع أو الخدمة لدى موفر الاستضافة. توضح الخطوة
التالية كيفية حفظها في Netlify.

### عنوان URL لقاعدة البيانات {#database-url}

أثناء التطوير المحلي، يخزّن التطبيق البيانات في قاعدة بيانات محلية عندما يكون
`DATABASE_URL` غير مضبوط. يحتاج التطبيق المنشور إلى قاعدة بيانات PostgreSQL
حقيقية تحتفظ ببياناتها بين عمليات النشر. لا يحتفظ Netlify بالملفات بين الطلبات،
لذلك يجب أن توجد قاعدة البيانات خارج دوال Netlify. انسخ سلسلة الاتصال من موفر
قاعدة البيانات وصدّرها:

```bash
export DATABASE_URL='your-postgres-url-string'
```

توضح [أدلة موفري قواعد البيانات](/docs/neon) مكان العثور على سلسلة الاتصال لدى
كل موفر.

<Callout tone="warning">

اختر موفر PostgreSQL دائمًا: Neon أو Supabase أو Amazon RDS أو غيرها.

</Callout>

### سر المصادقة {#auth-secret}

أنشئ هذه القيمة مرة واحدة وأبقها ثابتة عبر عمليات النشر.

يستخدم التطبيق `BETTER_AUTH_SECRET` لتوقيع جلسات المستخدمين. إذا تغيّرت القيمة،
يُسجَّل خروج كل مستخدم مسجّل الدخول. ينشئ الأمر أدناه قيمة عشوائية:

```bash
export BETTER_AUTH_SECRET="$(openssl rand -hex 32)"
```

احفظ القيمة المُنشأة في مكان آمن، مثل مدير كلمات المرور. استخدم القيمة نفسها في
كل مرة تنشر فيها.

### عنوان URL العام {#public-url}

اختياري. اضبطه عند استخدام نطاق مخصص، أو وكيل عكسي، أو تدفق مصادقة أو OAuth يحتاج
إلى أصل عام ثابت.

`BETTER_AUTH_URL` هو العنوان العام الذي يستخدمه الناس للوصول إلى تطبيقك. بدونه،
يستنتج التطبيق عنوانه من كل طلب وارد. يكون ذلك مناسبًا عادةً على العنوان الذي
يمنحك إياه Netlify، لكن اضبطه عندما تربط نطاقًا مخصصًا حتى تستخدم روابط تسجيل
الدخول وعمليات إعادة توجيه OAuth ذلك النطاق.

```bash
export BETTER_AUTH_URL='https://your-domain.example'
```

## الخطوة 3: ربط الموقع وحفظ الأسرار {#step-3-link-the-site-and-save-the-secrets}

سجّل الدخول إلى Netlify من سطر الأوامر، ثم أنشئ موقعًا جديدًا للتطبيق. يمكنك ترك
اسم المشروع على قيمته الافتراضية وترك مستودع GitHub فارغًا في الوقت الحالي.

```bash
npx netlify login

npx netlify sites:create --name my-app
```

ينشئ `sites:create` الموقع ويربطه بمجلد التطبيق، حتى تعرف الأوامر اللاحقة أي موقع
تستخدم. يصبح الاسم أيضًا عنوان الموقع، مثل `my-app.netlify.app`. أسماء المواقع
مشتركة عبر Netlify بالكامل، لذلك اختر اسمًا مختلفًا إذا كان `my-app` مستخدمًا
بالفعل. لا تحتاج إلى مستودع GitHub، لأنك تنشر التطبيق من حاسوبك في الخطوة 5.

احفظ المتغيرين المطلوبين في بيئة الموقع:

```bash
npx netlify env:set DATABASE_URL "$DATABASE_URL"

npx netlify env:set BETTER_AUTH_SECRET "$BETTER_AUTH_SECRET"
```

يقرأ كل أمر القيمة التي صدّرتها في الخطوة 2 ويحفظها في Netlify، لذلك لا تحتاج إلى
لصق الأسرار يدويًا. إذا ضبطت `BETTER_AUTH_URL`، فاحفظه بالطريقة نفسها. يمكنك
أيضًا عرض هذه القيم وتغييرها لاحقًا في إعدادات الموقع على لوحة تحكم Netlify.

## الخطوة 4: الترحيل {#step-4-migrate}

تنشئ عمليات الترحيل الجداول التي يحتاجها التطبيق في قاعدة البيانات وتحدّثها.
شغّل هذا الأمر قبل أول عملية نشر:

```bash
pnpm migrate:production
```

يعمل الأمر على حاسوبك ويتصل بقاعدة بيانات الإنتاج باستخدام `DATABASE_URL` الذي
صدّرته في الخطوة 2. شغّله مرة أخرى بعد ترقية التطبيق، وقبل نشر الإصدار الجديد.

## الخطوة 5: النشر {#step-5-deploy}

ابنِ التطبيق لـ Netlify:

```bash
NITRO_PRESET=netlify pnpm build
```

يبني `NITRO_PRESET=netlify` التطبيق بالتنسيق الذي يتوقعه Netlify. يكتب البناء
الملفات الثابتة للتطبيق في المجلد `dist` ودوال الخادم الخاصة به في المجلد
`.netlify/functions-internal`.

ارفع البناء وانشره:

```bash
npx netlify deploy --prod --dir=dist --functions=.netlify/functions-internal
```

يخبر `--dir` و`--functions` CLI بمكان الملفات الثابتة والدوال التي بنيتها للتو.
وينشرها `--prod` على عنوان الإنتاج الخاص بك بدلًا من معاينة مسودة.

عندما ينتهي الأمر، يطبع عنوان الإنتاج الخاص بالتطبيق. افتحه وأنشئ الحساب الأول.

## نشر التحديثات {#deploy-updates}

لإصدار نسخة جديدة، شغّل أوامر الترحيل والبناء والنشر مرة أخرى من مجلد التطبيق:

```bash
pnpm migrate:production

NITRO_PRESET=netlify pnpm build

npx netlify deploy --prod --dir=dist --functions=.netlify/functions-internal
```

يبقى ربط الموقع والمتغيرات المحفوظة كما هي، لذلك لا تحتاج إلى تكرار الخطوة 3.

## الإبقاء دافئًا وقواعد البيانات ذات التوسع إلى صفر {#netlify-keep-warm}

بعد فترة هادئة، قد يكون الطلب الأول بطيئًا بينما يبدأ Netlify تشغيل الدالة وتستيقظ
قاعدة بيانات ذات توسع إلى صفر، مثل المستوى المجاني من Neon. يمكن لـ Agent-Native
تقليل هذا الانتظار عبر الإبقاء دافئًا. عند تشغيله، يضيف البناء دالة Netlify
مجدولة تستدعي نقطة النهاية `/_agent-native/health` الخاصة بالتطبيق **كل دقيقة**،
مما يُبقي دالة الخادم وقاعدة بياناتها مستيقظتين.

الإبقاء دافئًا **مُعطَّل افتراضيًا**. إبقاء قاعدة البيانات مستيقظة يمنعها من
التوقف المؤقت، وهذا يستهلك حصة الحوسبة في الخطط المجانية أو المقاسة. إذا نفدت
الحصة، ترفض قاعدة البيانات **جميع** القراءات ويتوقف التطبيق عن العمل. اضبط
`AGENT_NATIVE_ENABLE_KEEP_WARM=1` عندما تستحق الزيارة الأولى الأسرع وقت قاعدة
البيانات الإضافي.

تتحكم هذه المتغيرات في الإبقاء دافئًا. لا تُطبَّق إعدادات الجدول والخلفية إلا بعد
تشغيل `AGENT_NATIVE_ENABLE_KEEP_WARM`:

| المتغير                                     | التأثير                                                                                                                                                                          |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AGENT_NATIVE_ENABLE_KEEP_WARM`             | يشغّل التدفئة المجدولة لدالة الخادم وقاعدة البيانات. غير مضبوط افتراضيًا.                                                                                          |
| `AGENT_NATIVE_DISABLE_KEEP_WARM`            | يوقف الإبقاء دافئًا حتى عند ضبط `AGENT_NATIVE_ENABLE_KEEP_WARM`. مُبقى عليه للتوافق مع الإعدادات الأقدم.                                                                 |
| `AGENT_NATIVE_KEEP_WARM_SCHEDULE`           | يغيّر عدد مرات تشغيل التدفئة، بتعبير cron مكون من 5 حقول مثل `*/5 * * * *`. القيمة الافتراضية هي `* * * * *`، أي كل دقيقة. القيمة التي ليست تعبير cron صالحًا **تُفشل البناء**. |
| `AGENT_NATIVE_DISABLE_KEEP_WARM_BACKGROUND` | يتخطى تدفئة دالة الخلفية ويواصل تدفئة دالة الخادم. تدفئة الخادم طلب واحد. تدفئة دالة الخلفية تبدأ حاوية جديدة تفحص مخطط قاعدة البيانات مرة أخرى. |

إذا كانت قاعدة بياناتك على خطة مجانية أو محدودة بطريقة أخرى، اترك
`AGENT_NATIVE_ENABLE_KEEP_WARM` غير مضبوط. إذا شغّلته، اختر جدولًا أبطأ أو اضبط
`AGENT_NATIVE_DISABLE_KEEP_WARM_BACKGROUND=1` لتخطي تدفئة الخلفية الأكثر تكلفة.

يقرأ البناء هذه المتغيرات، وليس التطبيق قيد التشغيل. لأنك تبني على حاسوبك الخاص في
الخطوة 5، اضبطها في الصدفة نفسها قبل البناء. حفظها في إعدادات موقع Netlify ليس له
أي تأثير على بناء يعمل محليًا. على سبيل المثال، لتشغيل الإبقاء دافئًا بجدول كل خمس
دقائق:

```bash
export AGENT_NATIVE_ENABLE_KEEP_WARM=1

export AGENT_NATIVE_KEEP_WARM_SCHEDULE='*/5 * * * *'

NITRO_PRESET=netlify pnpm build
```

ثم انشر كالمعتاد.
