# التطبيقات

تأتي تطبيقات Agent-Native بشكلين: القوالب، التي تضم UI كاملاً في المتصفح، وتطبيقات automation-first، التي لا تضمه — بوت Slack، أو تقرير ليلي، أو معالج webhook. تتناول هذه الصفحة القوالب؛ راجع [Automation-First Apps](/docs/pure-agent-apps) للتعرف على الشكل الآخر.

القالب هو منتج SaaS كامل: UI، وقاعدة بيانات، ومصادقة، ووكيل، مبنيون ومتصلون ببعضهم بالفعل. اختر واحدًا، وضع عليه علامتك التجارية، وانشره كمنتجك الخاص بدلاً من البدء من سقالة فارغة. يُسمى هذا النموذج SaaS قابلة للاستنساخ: فأنت تبدأ من منتج نهائي، لا من سقالة.

## تطبيقات نموذجية {#catalog}

كل تطبيق هو منتج كامل يمكنك تشغيله اليوم وتخصيصه ليصبح نسختك الخاصة.

| التطبيق                                   | ما هو                                                                                                                                      |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| [**Chat**](/docs/template-chat)           | الحد الأدنى من تطبيق الدردشة الأول مع سلاسل المحادثات الدائمة، وactions، والمصادقة، ومسار نظيف إلى UI المخصص أو الواجهة الخلفية الخاصة بك. |
| [**Mail**](/docs/template-mail)           | عميل خارق للطبيعة. البريد الوارد، والتسميات، وفرز الذكاء الاصطناعي، ولوحة المفاتيح أولاً، والمسودات والإرسالات من خلال الوكيل.             |
| [**Calendar**](/docs/template-calendar)   | Google Calendar الوكيل الأصلي. الأحداث، والمزامنة، وروابط الحجز العامة، والجدولة التي يحركها الوكيل.                                       |
| [**Content**](/docs/template-content)     | سبج مفتوح المصدر لـ MDX. Markdown/MDX محلي، محرر Tiptap، مزامنة Notion، تعاون متعدد المستخدمين في الوقت الفعلي.                            |
| [**Brain**](/docs/template-brain)         | دردشة واضحة للشركة مدعومة بالذاكرة المؤسسية المستشهد بها، والمصادر المعتمدة، وبوابات المراجعة، والاستشهادات.                               |
| [**Assets**](/docs/template-assets)       | مدير الأصول الرقمية لمكتبات العلامات التجارية، والتحميلات، والمراجع، وإنشاء الصور/مقاطع الفيديو المتعلقة بالعلامة التجارية.                |
| [**Slides**](/docs/template-slides)       | عروض Google التقديمية الأصلية للوكيل. التشكيلات المستندة إلى React يقوم الوكيل بإنشائها وتحريرها مباشرة.                                   |
| [**Analytics**](/docs/template-analytics) | السعة/Mixpanel الأصلية للوكيل. قم بتوصيل مصادر البيانات، والمطالبة بالمخططات، والتثبيت على لوحات المعلومات.                                |
| [**Clips**](/docs/template-clips)         | شاشة غير متزامنة + تسجيل بالكاميرا مع النسخ والفصول وملخصات الذكاء الاصطناعي.                                                              |
| [**Design**](/docs/template-design)       | استوديو النماذج الأولية HTML للوكيل الأصلي لتصميمات Alpine/Tailwind التفاعلية.                                                             |
| [**Forms**](/docs/template-forms)         | نموذج أصلي للوكيل. يمكنك إنشاء عمليات الإرسال ومشاركتها وجمعها وتوجيهها إلى Slack أو جداول البيانات أو webhooks أو Discord.                |
| [**Plan**](/docs/template-plan)           | الخطط المرئية وملخصات العلاقات العامة مع المخططات والإطارات السلكية والتعليقات التوضيحية.                                                  |
| [**Dispatch**](/docs/template-dispatch)   | مستوى التحكم في مساحة العمل: الأسرار المشتركة، عمليات التكامل القابلة لإعادة الاستخدام، Slack/Telegram، المهام المجدولة.                   |

إذا لم يتطابق أي منها مع مجالك، ابدأ بـ [Chat](/docs/template-chat) ووسّعه بـ actions ونتائج أصلية وصفحات. استخدم [Automation-First Apps](/docs/pure-agent-apps) إذا لم يحتج workflow إلى UI في المتصفح.

لكل تطبيق مستنداته الخاصة التي تغطي بنيته وactions والتخصيص. تصفح الإصدارات المستضافة المباشرة على [agent-native.com/apps](/apps)، أو ابدأ بـ [Dispatch](/docs/template-dispatch) للحصول على تطبيق على طراز مساحة العمل.

## قوالب المجتمع {#community-templates}

القوالب المسماة في منتقي CLI هي قوالب **رسمية**: تتولى Agent Native صيانتها
واختبارها وتوثيقها وإصدارها مع إطار العمل. أما **قالب المجتمع** فيتولى مالك
مستودعه صيانته وإدارة إصداراته. ويمكنه استخدام سطح إطار العمل نفسه، لكن إدراجه
في قائمة المجتمع لا يعني أن Agent Native توصي به أو تعد بدعمه.

شغّل `create` واختر **قالب المجتمع** ثم الصق عنوان URL بسيطًا لمستودع GitHub عام:

```bash
https://github.com/owner/repo
```

إذا كان جذر المستودع تطبيق Agent Native واحدًا، تثبته CLI مباشرة من دون منتقي
آخر. وإذا كان المستودع مساحة عمل Agent Native، تكتشف CLI العناصر الفرعية
المباشرة الصالحة في `apps/*`، وتستبعد `dispatch`، وتسأل عن التطبيق المراد تثبيته.

تجعل علامة `agent-native.workspaceCore` غير الفارغة المستودع مساحة عمل حتى إذا
كانت حزمة الجذر تعتمد أيضًا على `@agent-native/core`؛ وتُرفض العلامة غير الصالحة.

مرر عنوان URL البسيط نفسه إلى `--template` في البرامج النصية، أو استخدم الصيغة
الأقصر `community:`. ثبّت فرعًا أو علامة إصدار أو commit بعد `#` للحصول على نقطة
بداية قابلة لإعادة الإنتاج. ومن دون مرجع، تجرب CLI الفرع `main` ثم `master`:

```bash
npx @agent-native/core@latest create my-app --template community:owner/repo#v1.2.0
npx @agent-native/core@latest create my-app --template https://github.com/owner/repo#v1.2.0
```

لاختيار تطبيق المصدر من مستودع مساحة عمل دون تفاعل، استخدم
`?app=<app-name>`. يأتي المحدد قبل `#ref` الاختياري. ضع القيمة كاملة بين
علامات اقتباس لأن shells مثل zsh تتعامل مع `?` كنمط glob:

```bash
npx @agent-native/core@latest create my-app --template 'community:owner/repo?app=analytics#v1.2.0'
npx @agent-native/core@latest create my-app --template 'https://github.com/owner/repo?app=analytics#v1.2.0'
```

خارج مساحة العمل، يحول `create` تطبيق المصدر المحدد إلى تطبيق مستقل. لإضافته
إلى مساحة عمل موجودة، مرر مستودع المجتمع صراحة لأن منتقي `add-app` لا يعرض إلا
القوالب الرسمية. احذف `?app` للاختيار تفاعليًا من مساحة عمل المصدر، أو أدرجه
لتثبيت يمكن تشغيله ضمن برنامج نصي:

```bash
npx @agent-native/core@latest add-app my-app --template community:owner/repo#v1.2.0
npx @agent-native/core@latest add-app my-app --template 'community:owner/repo?app=analytics#v1.2.0'
```

تُقبل مستودعات GitHub العامة فقط. ولا تُدعم المستودعات الخاصة أو المضيفون غير
GitHub أو عناوين URL لأشجار GitHub أو أدلتها الفرعية أو مسارات التطبيقات
المتداخلة. يجب أن يحتوي تطبيق الجذر على `package.json` صالح للقراءة يدرج
`@agent-native/core` ضمن `dependencies` أو `devDependencies` أو
`peerDependencies`. وفي مستودع مساحة عمل، يجب أن يستوفي كل تطبيق مصدر قابل
للاختيار الشرط نفسه مباشرة ضمن `apps/<app-name>/`؛ ولا يمكن اختيار `dispatch`.

يجب أن تكون تطبيقات مساحة عمل المجتمع وحدات مستقلة قابلة للنقل، وليست أجزاء
عشوائية من monorepo:

- تُحل مراجع التبعيات الافتراضية `catalog:` من ملف `pnpm-workspace.yaml` في جذر
  المستودع المصدر؛ ولا تُدعم مراجع الكتالوج المسماة؛
- تُعاد كتابة مراجع `workspace:*` إلى `@agent-native/core` و
  `@agent-native/dispatch` و`@agent-native/toolkit` لتستخدم إصدارات منشورة.
  ولا تُنسخ حزم مساحة العمل الشقيقة الأخرى؛ فانشرها واستخدم إصدارًا محددًا؛
- تُزال تبعية `workspaceCore` المصدر. وتُفصل plugins القياسية الموروثة للمصادقة
  وagent chat في التثبيت المستقل أو يُعاد ربطها بمساحة العمل الوجهة. وأي import
  آخر لحزمة `workspaceCore` المصدر يفشل برسالة واضحة؛ انقل ذلك الكود إلى
  التطبيق أو انشره كتبعية محددة.

احتفظ ببقية كل تطبيق كامل بجوار `package.json` الخاص به: `agent-native.json`
عند استخدامه، والمصدر وactions وتعليمات الوكيل وإعداد قاعدة البيانات. ويجب أن
يتضمن المستودع الجاهز للكتالوج أيضًا:

- ترخيصًا ورابطًا إلى المشرف أو الدعم؛
- ملف README يوضح خطوات الإعداد ومتغيرات البيئة المطلوبة وأمر CLI الدقيق؛
- ملف `.env.example` يحتوي على عناصر نائبة فقط، بلا أسرار أو بيانات عملاء أو
  قواعد بيانات وقت التشغيل أو مخرجات بناء مولّدة؛
- تثبيتًا وأمر تطوير يعملان، وtypecheck واختبارات مناسبة للقالب.

يسجل المثبت قيمتي `source` و`ref` اللتين تم حلهما ضمن
`agent-native.communityTemplate` في `package.json` للتطبيق المثبت. وتسجل
التطبيقات المختارة من مستودع مساحة عمل تطبيق المصدر أيضًا في
`agent-native.communityTemplate.app`. ويظل `agent-native template sync` خاصًا
بالقوالب الرسمية؛ لتحديث قالب مجتمع، راجع مرجع upstream أحدث وادمج تغييراته
بنفسك.

راجع [Creating Templates](/docs/creating-templates) للاطلاع على قائمة التحقق
الكاملة للتطبيق وactions والحالة والأمان والنشر.

> **راجع كود المجتمع قبل تثبيت تبعياته أو تشغيله.** تُنزّل قوالب المجتمع من
> مستودعات جهات خارجية؛ ولا تعزلها Agent Native أو تدققها أو تصونها. تنزّل CLI
> المصدر فقط؛ فهي لا تثبت التبعيات ولا تشغّل برامج القالب النصية. افحص
> المصدر والترخيص والتبعيات وبرامج تثبيت الحزم، ويفضل استخدام مرجع موثوق ومثبّت.

العرض التوضيحي المستضاف اختياري. إذا قدمت واحدًا، فاجعله رابطًا عامًا للتجربة
ووثّق أي متطلبات لتسجيل الدخول أو بيانات نموذجية أو موفري خدمات. يظل المستودع
مصدر الحقيقة للتثبيت، ويظل مالكه مسؤولًا عن القالب والعرض التوضيحي.

هل تريد إدراج قالبك؟ [أرسل قالب مجتمع](https://github.com/BuilderIO/agent-native/issues/new?template=community-template.yml)
مع عنوان URL للمستودع ووصف من جملة واحدة وتفاصيل المشرف والترخيص وأمر CLI
المختبر وعنوان URL اختياري لعرض توضيحي مستضاف.

## ما الذي تحصل عليه خارج الصندوق {#what-you-get}

يتضمن كل تطبيق نموذجي:

- **وكيل عامل** — متصل بالتطبيق، وقادر على تنفيذ actions على بياناتك، ويعرف ما تنظر إليه. راجع [Messaging the agent](/docs/messaging).
- **المصادقة** — تسجيل الدخول، والجلسات، والمؤسسات، وعزل المستأجرين المتعددين.
- **قاعدة بيانات** — المخطط والاستعلامات وعمليات الترحيل، جاهزة للاستخدام. أحضر قاعدة بيانات SQL الخاصة بك (Postgres، SQLite، Turso، D1)؛ يتكيف إطار العمل معها.
- **UI في الوقت الفعلي** — تظل الشاشة متزامنة مع الوكيل. على سبيل المثال، تؤدي صياغة رسالة بريد إلكتروني في الدردشة إلى تحديث البريد الوارد فورًا.
- **جاهز للنشر** — انشر على Netlify، أو Vercel، أو Cloudflare، أو AWS، أو أي مضيف يشغّل Node.
- **عناصر ربط العلامة التجارية** — غيّر الاسم والألوان والشعار والنسخة.

يشغّل مشرف إطار العمل بريده الإلكتروني وتقويمه وتحليلاته على تطبيقات Mail وCalendar وAnalytics.

## لماذا يعد هذا أمرًا عمليًا {#why}

لا تتوسع قاعدة تعليمات برمجية مستقلة لكل مستخدم — تصير صيانة نسخة fork من التطبيق لكل مستخدم غير قابلة للإدارة. هناك قراران إطاريان يتجنبان ذلك:

1. **يحافظ التطبيق على عقد الإطار.** يملك مصدرك سلوك المجال، بينما يحافظ Core على اتساق actions وSQL والحالة والمزامنة مع تطور التطبيق.
2. **التخصيص لكل مستخدم بدون رمز لكل مستخدم.** Skills والذاكرة والتعليمات وخوادم MCP المتصلة والوكلاء الفرعيين جميعهم يعيشون في SQL. يحصل كل مستخدم على طبقة التخصيص الخاصة به؛ تستضيف قاعدة التعليمات البرمجية المشتركة كل هذه العناصر مرة واحدة.

النتيجة: تخصيص لكل مستخدم بدون عمليات نشر لكل مستخدم.

## لا تريد التخصيص؟ {#hosted}

كل تطبيق نموذجي متاح أيضًا كمنتج مستضاف على `agent-native.com` — `mail.agent-native.com`، `calendar.agent-native.com`، وما إلى ذلك. استخدم الإصدار المستضاف مجانًا أو مدفوع؛ أنشئ تطبيقك الخاص من قالب عندما تريد تغيير شيء لا يكشفه الإصدار المستضاف.

## جرب ذلك بمهارة {#try-with-a-skill}

يمكنك إضافة قدرات Agent-Native إلى وكيل الترميز الذي تستخدمه بالفعل، دون الحاجة إلى إنشاء سقالة تطبيق. شاهد [Skills Guide](/docs/skills-guide#app-backed-skills).

## البناء على هذا

### للمطورين {#dev-details}

لإنشاء سقالة تطبيق جديد:

```bash
npx @agent-native/core@latest create my-platform
```

يسأل CLI أولًا **كيف تريد البدء؟** اختر **Chat** لمساحة عمل بسيطة تضم Chat وDispatch، أو **First-party template(s)** لفتح منتقي التطبيقات المتعدد. أما Community وHeadless فهما مساران لتطبيق مستقل. تشارك تطبيقات مساحة العمل المصادقة والعلامة التجارية وتكوين الوكيل وقاعدة البيانات، ويُضاف كل تطبيق إلى `apps/<name>/` مع كل ملف تحتاجه. بالنسبة إلى automation بلا UI في المتصفح بدلاً من UI التطبيق، استخدم `npx @agent-native/core@latest create my-agent --headless`.

املأ `.env` (`ANTHROPIC_API_KEY` و`DATABASE_URL`)، ثم شغّل `pnpm install` و`pnpm dev`. لا يوجد تسجيل دخول يجب تنفيذه ولا مسارات نائبة.

أهداف النشر: أي مضيف متوافق مع Nitro (Node وCloudflare وNetlify وVercel وDeno وLambda وBun) وأي قاعدة بيانات SQL متوافقة مع SQL (SQLite وPostgres وTurso وD1 وSupabase وNeon). بالنسبة لمساحات العمل، تقوم `npx @agent-native/core@latest deploy` بإنشاء كل تطبيق في وقت واحد وشحنه خلف مصدر واحد. انظر [Deployment](/docs/deployment).

لتأليف ونشر قالب التطبيق الخاص بك، راجع [Creating Templates](/docs/creating-templates).
