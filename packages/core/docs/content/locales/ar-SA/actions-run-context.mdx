# سياق التشغيل

تستقبل `run` وسيطة ثانية اختيارية، `ctx`، تحمل هوية الطلب المحلولة والسطح الذي استدعى الـ action. اقرأها بدلاً من استدعاء `getRequestUserEmail()` / `getRequestOrgId()` يدويًا، ومرّر `ctx` بأكملها إلى التتبع:

```ts
export default defineAction({
  description: "Log an audit entry for the current request.",
  schema: z.object({ event: z.string() }),
  run: async (args, ctx) => {
    // ctx is undefined-safe: a 1-arg `run(args)` is still valid.
    const actor = ctx?.userEmail ?? "system";
    if (ctx?.caller === "frontend") {
      // tighter rules for browser-initiated calls, looser for "tool"/"cli"
    }
    await db.insert(audit).values({
      actor,
      orgId: ctx?.orgId ?? null,
      source: ctx?.caller ?? "unknown",
      event: args.event,
    });
    return { ok: true };
  },
});
```

لا تقرأ معظم actions سوى `ctx?.userEmail` و`ctx?.orgId`، وهو [نطاق التحكم في الوصول](/docs/actions-access-control#access-control) المستخدم في كل action حقيقي تقريبًا. تغطي بقية هذه الصفحة اهتمامات متقاطعة مثل التتبع وإسناد الأتمتة، وهو ما تحتاجه actions أقل.

## وسيطة `ctx` {#ctx}

تبقى `run()` متوافقة مع الإصدارات السابقة: تستمر المعالجات الحالية بوسيطة واحدة، والمعالجات التي تُفكِّك `{ send }` فقط، في العمل دون تغيير.

### اتحاد `caller` {#caller}

`caller` هو الاتحاد `"tool" | "http" | "frontend" | "cli" | "mcp" | "a2a" | "automation"`:

| `caller`       | يُضبط عندما...                                                                                                                                                          |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `"tool"`       | حلقة الوكيل داخل التطبيق، أو وكيل فرعي أو فريق وكلاء، أو تفويض A2A بلغة طبيعية عبر التطبيقات، والذي يشغّل حلقة الوكيل نفسها، لذا فإن استدعاءات أدواته هي `"tool"`.      |
| `"frontend"`   | استدعاء من المتصفح عبر `useActionMutation()` أو `useActionQuery()` أو `callAction()` (مُعلَّم برأس `X-Agent-Native-Frontend: 1`).                                       |
| `"http"`       | طلب `POST` أو `GET` برمجي مجرد إلى `/_agent-native/actions/<name>` دون علامة الواجهة الأمامية.                                                                          |
| `"cli"`        | `pnpm action <name>` (مُشغِّل CLI).                                                                                                                                     |
| `"mcp"`        | وكيل خارجي عبر نقطة نهاية `tools/call` الخاصة بـ MCP.                                                                                                                   |
| `"a2a"`        | استدعاء HTTP مباشر إلى `/_agent-native/actions/<name>` يحمل رمز تفويض A2A موقَّعًا. هذا إرسال مكشوف صراحة وعبر التطبيقات، مختلف عن مسار `"tool"` باللغة الطبيعية أعلاه. |
| `"automation"` | أتمتة مُشغَّلة بحدث تم إرسالها من مشغِّل مخزَّن في مساحة العمل. تحمل `ctx.automation` سلسلة نسب المشغِّل. راجع [الأتمتة](/docs/automations).                           |

## ما هي الخطوة التالية

- [**الوصول والتخويل**](/docs/actions-access-control) — نمط تحديد النطاق `ctx.userEmail`/`ctx.orgId` الذي يتيحه هذا السياق
- [**تعريف Actions**](/docs/actions-defining) — تشريح `defineAction()` وإعداد HTTP
- [**أسطح أخرى**](/docs/actions-other-surfaces) — كيف تضبط استدعاءات CLI وA2A وMCP والأتمتة قيمة `caller`
- [**سجل التدقيق**](/docs/audit-log) — كيف تربط `threadId`/`runId`/`turnId` تغييرًا بتشغيل الوكيل الخاص به
- [**الأتمتة**](/docs/automations) — سلسلة نسب المشغِّل في `ctx.automation`
