# Plans المرئية

Agent-Native Plans هو وضع الخطة المرئية لوكلاء الترميز. يحوّل خطة تنفيذ عادية
من Codex أو Claude Code أو Markdown أو خطة ملصقة إلى سطح مراجعة منظّم يحتوي
على نص منسّق، ومخططات، وإطارات سلكية، وجولات كود موضّحة بالتعليقات وأشجار
ملفات، وتعليقات، وروابط قابلة للمشاركة.

يتلخص الأمر في أمرين. يبني `/visual-plan` خطة **قبل** أن يكتب الوكيل الكود.
ويحوّل `/visual-recap` تغييرًا **حدث بالفعل** — طلب سحب، أو التزام (commit)،
أو فرع، أو git diff — إلى مراجعة كود مرئية على ارتفاع عالٍ. يفتح كلا الأمرين
سطح المراجعة نفسه، بحيث تضيف الشروح والتعليقات وتُعيد الملاحظات إلى الوكيل
بالطريقة نفسها في كل مرة.

## ما الذي يحل محله

<Comparison>

### قبل

- تعيش الخطة كجدار من النثر في الدردشة أو في ملف Markdown، ومراجعتها تعني
  قراءتها من البداية إلى النهاية للعثور على الفقرة الوحيدة التي تختلف معها.
- تحدث الملاحظات في خيط على Slack أو في تعليقات متناثرة، منفصلة عن الخطة
  نفسها.
- مراجعة طلب سحب مكتمل تعني قراءة فرق (diff) خام سطرًا بسطر لإعادة تكوين ما
  تغيّر ولماذا.

### بعد

- تُعرض الخطة كمخططات، وإطارات سلكية، وكود موضّح بالتعليقات، ونموذج أسئلة
  مفتوحة يمكنك التفاعل معه مباشرة.
- تُثبَّت التعليقات على الموضع الدقيق من النص أو الصورة أو الإطار السلكي،
  وتستهدف إما الوكيل أو مراجعًا بشريًا.
- يحوّل `/visual-recap` طلب سحب أو التزامًا أو فرقًا (diff) إلى المراجعة
  المرئية نفسها بدلاً من فرق خام.

</Comparison>

صدِّر النتيجة بصيغة HTML أو Markdown أو JSON للحصول على نسخة متوافقة مع
أنظمة التحكم بالمصدر، أو أبقِها بالكامل خارج قاعدة البيانات المستضافة
باستخدام وضع الملفات المحلية. راجع
[مراجعة الخطط والتعليق عليها](/docs/template-plan-review-workflow) و
[وضع الملفات المحلية ومزامنة سطح المكتب](/docs/template-plan-local-and-desktop)
للاطلاع على كل منهما بالتفصيل.

## البدء {#get-started}

<Steps>

### ثبِّت المهارة {#install}

يثبّت معظم الأشخاص Plan كـ **مهارة** لوكيل الترميز الحالي لديهم، وليس كتطبيق
داعم مُنشأ من قالب. يثبّت هذا الأمر الواحد تعليمات المهارة، ويسجّل موصل
Plans MCP المستضاف، ويسجّل الدخول إليه:

```bash
npx @agent-native/core@latest skills add visual-plan
```

يثبّت هذا ثلاثة أوامر شرطة مائلة — `/visual-plan` و`/visual-recap`
و`/visualize-repo` — بالإضافة إلى موصل `plan` MCP (خادم أدوات عن بُعد يتواصل
معه وكيلك) على `https://plan.agent-native.com/mcp`. للاطلاع على المرجع
الكامل للخيارات، ومسارات تثبيت المكوّن الإضافي/السوق لـ Claude Code وCodex،
وامتداد VS Code، راجع
[مكوّن Plan الإضافي والسوق ← مسارات التثبيت](/docs/plan-plugin#install).

تخصيص قالب Plan نفسه — استضافته ذاتيًا، أو البناء عليه مباشرة — مسار منفصل
وثانوي مشروح في [توسيع Plan](/docs/template-plan-developers). معظم الأشخاص
لا يحتاجون إليه إطلاقًا.

### اطلب من وكيلك الأمر المناسب للعمل

- "استخدم `/visual-plan` قبل تغيير تدفق المصادقة."
- "أنشئ `/visual-plan` لشاشة الإعداد الجديدة بحالتي الجوال وسطح المكتب."
- "شغّل `/visual-recap` على طلب السحب هذا حتى أراجع شكل التغيير أولاً."
- "استخدم `/visual-recap` على الفرق (diff) بين `main` وهذا الفرع."
- "شغّل `/visualize-repo` وابدأ بإجراءات (actions) الـ API العامة والمخطط
  لدينا."

يستحضر `/visual-plan` المخططات، والإطارات السلكية، والنماذج التصميمية،
والنماذج الأولية القابلة للنقر، والكود الموضّح بالتعليقات حسبما يتطلبه
العمل. يفحص الوكيل قاعدة الكود أولاً، ثم يفتح الرابط المُعاد واجهة المراجعة
في متصفحك أو في VS Code.

### راجع كضيف، دون الحاجة إلى حساب

لا يحتاج الأشخاص الذين تشاركهم خطة إلى تثبيت أي شيء. يفتحون محرر Plans
و**ينشئون ويعدّلون دون تسجيل** — يعملون كضيف. لا يُطلب تسجيل الدخول إلا لـ
**حفظ عملك الخاص أو مشاركته**، وإذا سجّل الضيف الدخول لاحقًا، تُنسَب
(claimed) كل خطة أنشأها كضيف إلى حسابه.

</Steps>

عندما تكون هناك بالفعل خطة من Codex أو Claude Code أو Markdown أو خطة
ملصقة، استخدم `/visual-plan`؛ يحافظ الوكيل على تلك الخطة المصدر ويبني منها
سطح المراجعة الأغنى بدلاً من البدء من جديد. إذا كانت هناك قرارات لا تزال
مفتوحة بعد المحاولة الأولى، يمكن للوكيل إضافة نموذج **أسئلة مفتوحة** أسفل
الخطة — والإجابة عليه وإرساله يبدأ جولة مراجعة جديدة.

<Callout tone="info">

**الضيف مقابل المسجَّل الدخول، بنظرة سريعة**

- **كضيف** يمكنك فتح رابط مشترك، وإنشاء خطة جديدة، وتحرير النثر، واستخدام
  وضع شروح المراجعة — دون الحاجة إلى حساب.
- **تسجيل الدخول** يتيح لك إضافة إلى ذلك حفظ خططك الخاصة بشكل دائم، ونشر
  خطة على رابط قابل للمشاركة، ومنح صلاحيات المشاهدة/التحرير/الإدارة
  للآخرين، ونشر تعليقات تُخطر الأشخاص عبر البريد الإلكتروني، وحذف أو
  استعادة الخطط التي تملكها.

</Callout>

## التكلفة واختيار النموذج

يؤدي إنشاء خطة أو ملخّص إلى تشغيل جلسة وكيلية كاملة على نموذج LLM الخاص
بوكيل الترميز لديك، وليس مجرد ملء قالب خفيف — وتتناسب التكلفة مع حجم الفرق
(diff) أو الخطة ومع النموذج الذي تختاره.

- نموذج الدردشة الافتراضي للتطبيق هو GPT-5.6 Luna. وتحتفظ اتصالات Anthropic
  المباشرة بـ Claude Sonnet 5 كنموذج افتراضي لها. يمكنك تغيير النماذج في أي
  وقت من **الإعدادات**؛ ويظل Haiku خيار Claude الأرخص.
- تعمل ملخّصات طلبات السحب الآلية من إجراء GitHub بشكل منفصل عن التطبيق
  التفاعلي، ولها إعدادات النموذج والتكلفة الخاصة بها — راجع
  [الملخص المرئي لطلبات السحب](/docs/pr-visual-recap) للاطلاع على
  `VISUAL_RECAP_MODEL` و`VISUAL_RECAP_AGENT` و`VISUAL_RECAP_REASONING`.

## طلب الوصول إلى خطة خاصة {#request-access}

إذا فتح أحدهم رابط خطة لا يملك إذنًا لعرضها، فإن Plans لا يكتفي بعرض طريق
مسدود. تخبره الصفحة بأن الخطة خاصة، وتعرض عليه إجراء **طلب الوصول**، الذي:

- يتطلّب تسجيل الدخول (يُطلَب من الضيف تسجيل الدخول أولاً).
- يسجّل الطلب على الخطة، وعندما يكون البريد الإلكتروني مُهيَّأً في عملية
  النشر، يُرسِل رسالة إلى مالك الخطة تتضمن اسم مقدّم الطلب ورابطًا لفتح
  الخطة ومشاركتها معه في حال الموافقة.
- آمن للنقر عليه أكثر من مرة — يتحقق Plans أولاً مما إذا كان لديك حق الوصول
  بالفعل، بحيث لا يؤدي طلب ثانٍ من الشخص نفسه إلى إغراق المالك برسائل بريد
  إلكتروني مكررة.

إذا كانت رؤية الخطة مضبوطة على **المؤسسة** بدلاً من الخصوصية الكاملة، وكان
لحسابك بالفعل دعوة معلّقة إلى تلك المؤسسة أو نطاق بريد إلكتروني يطابقها،
يعرض عليك Plans الانضمام إلى المؤسسة مباشرة بدلاً من إرسال طلب.

<Callout tone="warning">

إذا أرجعت أداة من أدوات Plans في أي وقت `needs auth` أو `Unauthorized` أو
`Session terminated`، فلا تستمر في إعادة المحاولة. أعِد المصادقة باستخدام
`npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex`،
أو أعد تشغيل `/mcp` ← **Authenticate** لمضيف قادر على OAuth. ابدأ محادثة
Codex جديدة أو أعد تشغيل/تحميل العميل بعد ذلك — إذ لا يلتقط سجل الأدوات
التغيير إلا في جلسة جديدة.

</Callout>
