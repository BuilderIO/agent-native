# الخادم

يمثّل دليل `server/` طبقة البنية التحتية لتطبيق أصلي للوكيل. فهو يتولى مهام بدء التشغيل، والمصادقة، وواجهات HTTP التي لا تغطيها Actions. يعيش معظم سلوك المنتج في [Actions](/docs/actions). والخادم هو ما يجعل تلك Actions متاحة.

## أين يتناسب الخادم {#role}

في تطبيق ويب تقليدي، يعيش معظم المنطق في الخادم. تحدث قواعد الأعمال، والوصول إلى البيانات، والعرض كلها داخل معالجات المسارات. تعمل التطبيقات الأصلية للوكيل بشكل مختلف. يعيش المنطق في Actions، التي يتشاركها الوكيل وواجهة المستخدم كشريكين متكافئين. مهمة الخادم هي التنسيق: تشغيل عمليات ترحيل قاعدة البيانات، وتكوين المصادقة، وتثبيت حلقة الوكيل، والتعامل مع مجموعة ضيقة من اهتمامات HTTP التي لا يمكن لـ Actions التعبير عنها بمفردها.

تمر طلبات المتصفح، وحلقة الوكيل، وعملاء API الخارجيون جميعها عبر خادم Nitro نفسه، وتقرأ من قاعدة بيانات SQL نفسها. لا توجد خلفية منفصلة للوكيل أو خلفية منفصلة لواجهة المستخدم. طبقة الخادم هي ما يكشف Actions للعالم الخارجي.

## ما الذي يحتويه دليل server/ {#server-directory}

هذه هي الأدلة والملفات داخل `server/` التي يشحنها كل تطبيق أصلي للوكيل. يقابل كل منها جزءًا محددًا من طبقة الخادم: ماذا يفعل، ومتى تلجأ إليه، وكيف يتصل ببقية إطار العمل.

| الصفحة                                           | ما تغطيه                                                                                                |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| **[قاعدة البيانات](/docs/server-database)**      | تعريف المخطط باستخدام مساعدات `table()`، و`getDb`، وأنماط الجداول القابلة للامتلاك                      |
| **[البرمجيات الوسيطة](/docs/server-middleware)** | حراس المصادقة في `server/middleware/` ولماذا تعمل هناك بدلاً من داخل إضافة (plugin)                     |
| **[الإضافات](/docs/server-plugins)**             | إضافات بدء التشغيل الثلاث التي يشحنها كل تطبيق: ترحيلات قاعدة البيانات، والمصادقة، ودردشة الوكيل        |
| **[المسارات](/docs/server-routes)**              | المسارات المستندة إلى الملفات، ومسار SSR الشامل (catch-all)، وتحديد نطاق المسارات المخصصة لمستخدم الطلب |

## طبقة Nitro {#nitro}

[Nitro](https://nitro.build) هو مجموعة أدوات الخادم التي تُشغّل طبقة HTTP الخاصة بالتطبيق الأصلي للوكيل. معظم ما ستُكوّنه في `server/` هو Nitro: المسارات المستندة إلى الملفات، وإضافات بدء التشغيل، والبرمجيات الوسيطة.

- **التوجيه المستند إلى الملفات**: يُترجم اسم الملف مباشرةً إلى طريقة HTTP ومسار URL، دون الحاجة إلى أي تسجيل. يصبح `server/routes/api/health.get.ts` تلقائيًا `GET /api/health`. راجع [المسارات](/docs/server-routes) لمزيد من التفاصيل.
- **الإضافات**: رمز يعمل مرة واحدة عند بدء تشغيل الخادم، قبل خدمة أي طلب. تحدث عمليات ترحيل قاعدة البيانات، وتكوين المصادقة، وتثبيت دردشة الوكيل جميعها في `server/plugins/`. راجع [الإضافات](/docs/server-plugins) لمزيد من التفاصيل.
- **البرمجيات الوسيطة**: رمز يعمل مع كل طلب وارد قبل وصوله إلى مسار. يعيش حارس المصادقة في `server/middleware/`. راجع [البرمجيات الوسيطة](/docs/server-middleware) لمزيد من التفاصيل.

Nitro مستقل أيضًا عن بيئة النشر. يُنشر التطبيق نفسه على Node.js، وCloudflare Workers، وNetlify، وVercel، وبيئات تشغيل أخرى دون أي تغييرات في الرمز. فقط اضبط إعدادًا مسبقًا (preset). راجع [النشر](/docs/deployment).

واجهة الطلب/الاستجابة الأساسية هي [H3](https://h3.unjs.io). عندما ترى `defineEventHandler`، أو `createError`، أو `getQuery` في مسارات مخصصة، فذلك هو H3. تُعد [وثائق Nitro](https://nitro.build/guide) و[وثائق H3](https://h3.unjs.io) المرجع لأي شيء لا يغطيه إطار العمل مباشرةً.

## Actions أولاً بشكل افتراضي {#actions-first}

بنية التطبيق الأصلي للوكيل مختلفة. كلما فكرت في ميزة جديدة لتطبيقك، ضع في اعتبارك أولاً ما إذا كان يمكن أن تكون action. على سبيل المثال، إذا كانت واجهة المستخدم والوكيل يحتاجان كلاهما إلى فعل شيء ما، عرّف action بدلاً من مسار API مخصص. تتحول Actions تلقائيًا إلى:

- أدوات للوكيل.
- خطافات (hooks) مكتوبة لواجهة المستخدم.
- نقاط نهاية HTTP تحت `/_agent-native/actions/:name`.
- أدوات قابلة للاستدعاء عبر MCP وA2A.
- أوامر CLI للتطوير.

استخدم مسارات `/api/*` المخصصة فقط عندما تحتاج إلى بروتوكول على شكل مسار أو سلوك ثنائي/بث. لمزيد من التفاصيل، راجع [Actions](/docs/actions).

## ما هي الخطوة التالية {#whats-next}

- [**Actions**](/docs/actions): سطح العملية الافتراضي. لا تلجأ إلى مسار مخصص إلا عندما لا يناسب.
- [**قاعدة البيانات**](/docs/server-database): نمط `getDb()`/المخطط الذي تستورده المسارات المخصصة وActions على حد سواء
- [**البرمجيات الوسيطة**](/docs/server-middleware): حراس المصادقة ودليل `server/middleware/`
- [**الإضافات**](/docs/server-plugins): إضافات بدء التشغيل للترحيلات، والمصادقة، والوكيل
- [**المسارات**](/docs/server-routes): المسارات المستندة إلى الملفات، وسياق الطلب، ومسار SSR الشامل
