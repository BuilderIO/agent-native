# النشر

تعمل تطبيقات Agent-Native على [Nitro](https://nitro.build)، لذلك يمكن نشر التطبيق
نفسه على Node.js أو الدوال بدون خوادم أو عمّال الحافة أو موفر استضافة مُدار. اختر
المسار الذي يناسب ما تريد شحنه:

<Cards columns={2}>

### :server: [نشر تطبيق](/docs/deploy-an-app)

ابنِ تطبيقًا مستقلًا واحدًا وشغّله على Node.js أو Docker أو Vercel أو Netlify أو
Cloudflare Workers.

### :network: [نشر مساحة العمل](/docs/workspace-deployment)

ابنِ عدة تطبيقات خلف أصل واحد مع تسجيل دخول مشترك واتصال بين التطبيقات من الأصل
نفسه.

</Cards>

## قبل النشر: اختر قاعدة بيانات دائمة {#persistent-database}

كل تطبيق منشور يحتاج إلى قاعدة بيانات PostgreSQL دائمة. يمكن للتطوير المحلي استخدام
قاعدة بيانات PGlite في `data/pglite`، لكن أنظمة ملفات الحاويات وبيئات المعاينة
والبيئات بدون خوادم قد تُعاد تهيئتها في أي وقت.

<Steps>

### اختيار موفر

استخدم موفر PostgreSQL مستضافًا مثل [Neon](/docs/neon) أو
[Supabase](/docs/supabase) أو Railway أو Render أو [Amazon RDS for PostgreSQL](/docs/aws-rds)
أو [Cloud SQL for PostgreSQL](/docs/cloud-sql) أو [Azure Database for PostgreSQL](/docs/azure-postgresql).
استخدم دليل [Plain Postgres](/docs/postgres) للخدمات المُدارة الأخرى وخوادم
PostgreSQL ذاتية الاستضافة. يضبط الإطار PostgreSQL من عنوان URL
للاتصال.

### ضبط سلسلة الاتصال

اضبط `DATABASE_URL` في إعدادات متغيرات البيئة أو الأسرار لدى موفر الاستضافة قبل
أول نشر إنتاجي. يضبط ملف `.env` المحلي جهازك فقط، ولا يرفعه أمر
النشر.

### إضافة أسرار الإنتاج

أنشئ سر توقيع ثابتًا باستخدام `openssl rand -hex 32`، ثم اضبطه في
`BETTER_AUTH_SECRET` للتطبيق المستقل. تحتاج مساحة العمل أيضًا إلى `A2A_SECRET`
عندما تستخدم طلبات موقّعة بين التطبيقات أو عمليات تسليم في الخلفية. يغطي [مرجع بيئة
النشر](/docs/deployment-environment-variables) بقية
إعدادات الإنتاج.

### تشغيل عمليات الترحيل

شغّل `pnpm migrate:production` مقابل قاعدة بيانات الإنتاج قبل أول
زيارة. ينشئ هذا الأمر الجداول التي يحتاجها التطبيق. شغّله مرة أخرى بعد كل ترقية،
قبل أن يصبح الإصدار الجديد متاحًا. يوضح كل دليل استضافة موضع هذه الخطوة.

</Steps>

<Callout tone="info">

في مساحة العمل، يرث كل تطبيق `DATABASE_URL` الجذري افتراضيًا. اضبط
`<APP_NAME>_DATABASE_URL` فقط عندما يحتاج تطبيق واحد إلى قاعدة بيانات مختلفة.

</Callout>

## تسليم البريد الإلكتروني اختياري، لكنه موصى به {#email-provider}

موفر البريد الإلكتروني ليس مطلوبًا لمصادقة البريد الإلكتروني وكلمة المرور. بدونه،
يستخدم التطبيق المنشور التسجيل وتسجيل الدخول بالبريد الإلكتروني وكلمة المرور،
ويتخطى التحقق من البريد عند التسجيل، ولا يعرض مصادقة الروابط السحرية.

لا يتضمن Agent-Native حسابًا لإرسال البريد. اربط Resend أو SendGrid قبل النشر إذا
أردت الروابط السحرية أو التحقق من البريد أو إعادة تعيين كلمات المرور أو الدعوات أو
إشعارات المشاركة. اضبط `RESEND_API_KEY` أو `SENDGRID_API_KEY` في بيئة النشر.
ويحتاج SendGrid أيضًا إلى `EMAIL_FROM`. راجع [المصادقة](/docs/authentication)
لأنماط المصادقة المتاحة.

### تخصيص رسائل البريد في الإطار {#email-templates}

لكل رسالة بريد يرسلها الإطار قالب افتراضي. لاستخدام تصميمك الخاص، سجّل override من
إضافة خادم. يظل الإطار هو من يحدد المستلم والمرسل ويسلّم الرسالة. أما الـ override
فيحدد محتوى الرسالة وشكلها.

```ts
// server/plugins/email-templates.ts
import {
  escapeEmailHtml,
  overrideTransactionalEmail,
} from "@agent-native/core/server";

export default function registerEmailTemplates(): void {
  overrideTransactionalEmail("core.resource-shared", (props) => ({
    subject: `${props.sender.name} shared "${props.resource.title}"`,
    html: `<p>${escapeEmailHtml(props.sender.name)} invited you to
      <a href="${escapeEmailHtml(props.resource.url)}">${escapeEmailHtml(props.resource.title)}</a>
      in ${escapeEmailHtml(props.app.name)}.</p>`,
  }));
}
```

| معرّف البريد                     | Props                                                                              |
| -------------------------------- | ---------------------------------------------------------------------------------- |
| `core.verify-signup`             | `email`, `verifyUrl`                                                               |
| `core.reset-password`            | `email`, `resetUrl`                                                                |
| `core.magic-link`                | `email`, `magicLinkUrl`                                                            |
| `core.change-email-confirmation` | `email`, `newEmail`, `confirmationUrl`                                             |
| `core.change-email-verification` | `email`, `verifyUrl`                                                               |
| `core.organization-invite`       | `invitee`, `orgName`, `inviter`, `acceptUrl`                                       |
| `core.builder-credit-limit`      | `subject`, `heading`, `body`, `upgradeLabel`, `upgradeUrl`                         |
| `core.resource-shared`           | `recipientEmail`, `sender`, `resource` (`type`, `title`, `url`), `role`, `message` |

يتلقى كل override أيضًا `app` (`name`، `logoUrl`). يحمل الوسيط الثاني العرض
الافتراضي، لتتمكن من إعادة استخدام العنوان أو النص.

- قيم الـ props خام. اهرب منها باستخدام `escapeEmailHtml` قبل وضعها
  في سلسلة HTML.
- أعد `react` مع عنصر React بدلًا من `html` لعرض مكوّن.
  يتولى React الهروب من الـ props.
- احذف `subject` للإبقاء على العنوان الافتراضي. احذف `text` لاشتقاق
  النص العادي من HTML الخاص بك.
- إذا رمى الـ override خطأ، يفشل الإرسال. لا يعود الإطار إلى
  التصميم الافتراضي. تعرض معاينة رسائل البريد المعاملاتية الـ override الخاص بك،
  فتحقق منه هناك.

## النشر المتقدم {#advanced-deployment}

ابدأ بالمسار أعلاه. استخدم هذه الصفحات عندما تحتاج إلى إعدادات خاصة بموفر معيّن
أو عناصر تحكم للإنتاج:

- [**Node.js**](/docs/node-js) - شغّل إعداد خادم Nitro المسبق الافتراضي
- [**Docker**](/docs/docker) - احزم خادم Node.js في حاوية
- [**Vercel**](/docs/vercel) و[**Netlify**](/docs/netlify) و[**Cloudflare Workers**](/docs/cloudflare#cloudflare-workers) - اضبط الأهداف المستضافة
- [**التخزين المؤقت SSR**](/docs/ssr-caching) - اضبط ذاكرة التخزين المؤقت للهيكل العام
- [**النشر: متغيرات البيئة**](/docs/deployment-environment-variables) - أسرار الإنتاج وأعلام وقت التشغيل والوراثة في مساحة العمل
- [**وصول الوكيل الإنتاجي**](/docs/actions-agent-tools) - تحكّم في أدوات الإطار وتنفيذ الشيفرة
- [**تحديث الواجهة في الإنتاج**](/docs/updating-ui-in-production) - افهم سير عمل التحرير المرئي المُدار

<a id="self-host-quickstart"></a>
<a id="skip-ensure-tables"></a>

تُبقي هذه المراسي الروابط القديمة عاملة. يغطي [دليل Docker](/docs/docker) الاستضافة
الذاتية باستخدام حاوية. توجد إرشادات إعداد المخطط وبدء التشغيل البارد
في [مرجع بيئة النشر](/docs/deployment-environment-variables#skip-ensure-tables).
