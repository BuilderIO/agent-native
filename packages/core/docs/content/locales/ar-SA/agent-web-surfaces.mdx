# موقع الوكيل العام

تجعل شبكة الوكيل العام مسارات Agent-Native العامة سهلة على الوكلاء للزحف إليها وقراءتها والاستشهاد بها والاتصال بها. الهدف ليس جعل نقطة نهاية كل تطبيق عامة. الهدف هو نشر سطح عام نظيف للصفحات العامة بالفعل، مع الاحتفاظ بالبيانات الخاصة والوصول إلى الأدوات خلف ضوابط واضحة.

موقع المستندات هو التنفيذ المرجعي. واليوم يتم شحنه:

- `/robots.txt` مع سياسة الزاحف التي تسمح بالاسترداد ولكنها لا تسمح بالتدريب بشكل افتراضي.
- `/sitemap.xml` كفهرس لخرائط الموقع يشير إلى ملف `/sitemap-<locale>.xml` واحد لكل لغة، مع URLs الأساسية المطلقة و`lastmod` عندما يعرضها الملف المصدر.
- `/llms.txt` و`/llms-full.txt` لاكتشاف المحتوى المناسب للوكلاء.
- مرايا Markdown مثل `/docs/getting-started.md`.
- استجابات `Accept: text/markdown` لصفحات المستندات العامة بعد إنشاء الإنتاج.
- JSON-LD للمؤسسة الأساسية وموقع الويب والبيانات الوصفية للصفحة.
- تدقيق CLI (`npx @agent-native/core@latest audit-agent-web`) يتحقق من كل ما سبق.

نشر هذه الملفات لا يكشف أي إجراء أبدًا. يصل الإجراء إلى الوكلاء الخارجيين فقط من خلال اشتراكه الخاص في `publicAgent`؛ راجع [التعريض للوكلاء العامين](/docs/actions-access-control#public-agent).

## التكوين {#config}

يكتب `createAgentWebVitePlugin` من `@agent-native/core/vite` هذه الملفات أثناء بناء الإنتاج. أضفه إلى إعدادات Vite مع الصفحات التي يجب أن يقرأها الوكلاء:

```ts
// vite.config.ts
import { createAgentWebVitePlugin } from "@agent-native/core/vite";

export default defineConfig({
  plugins: [
    // ...your existing plugins
    createAgentWebVitePlugin({
      siteName: "My Agent-Native App",
      siteUrl: "https://example.com",
      pages: [
        {
          path: "/pricing",
          title: "Pricing",
          description: "Plans and limits.",
          markdown: "Plans and limits.\n",
        },
      ],
      agentWeb: { crawlerPolicy: "discoverable-no-training" },
    }),
  ],
});
```

ينشر المكوّن الإضافي الصفحات التي تدرجها فقط، ولا شيء غيرها. لا يقرأ إعدادات الوصول إلى المسارات، ولا يقرأ `agentWeb` من `package.json` ما لم تمرره إليه. لإبقاء الإعدادات في `package.json` تحت `agent-native.workspaceApp.agentWeb`، مرّر `agentWeb: agentWebConfigFromPackageJson(pkg)` المستورد من `@agent-native/core/agent-web`.

| الخيار          | الافتراضي                         | ما يفعله                                                                                                                                       |
| --------------- | --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `discoverable`  | مفعّل عندما لا تكون `pages` فارغة | القيمة `false` لا تكتب أي ملفات.                                                                                                               |
| `llmsTxt`       | `true`                            | يكتب `/llms.txt` و`/llms-full.txt`.                                                                                                            |
| `markdownTwins` | `true`                            | يكتب نسخة `.md` من كل صفحة لها `markdown`.                                                                                                     |
| `crawlerPolicy` | `"discoverable-no-training"`      | يحدد قواعد `robots.txt`: `"discoverable-no-training"` أو `"allow-all"` أو `"disallow-all"`.                                                    |
| `crawlers`      | لا شيء                            | يتجاوز فئة زواحف واحدة: `training` أو `search` أو `userTriggered` أو `codingAgents` أو `autonomousAgents`، وكل منها `"allow"` أو `"disallow"`. |

سياسة الزواحف الافتراضية هي "قابل للاكتشاف، غير قابل للتدريب": يُسمح بالبحث والاسترجاع الذي يبدأه المستخدم ووكلاء البرمجة ووكلاء التصفح المستقلين؛ ولا يُسمح بزواحف التدريب.

يُقبل `jsonLd` و`publicAgentCard` و`publicMcp`، لكن لا شيء يقرؤها حتى الآن. للحصول على JSON-LD، اعرض `buildBaseJsonLd` و`buildPageJsonLd` من `@agent-native/core/agent-web` في صفحاتك بنفسك.

## توجيه مصدر الحقيقة {#route-source}

قائمة الصفحات هي مصدر الحقيقة: يحصل الوكلاء على الصفحات التي تمررها، وعليها فقط. ابنِها من صفحات عامة بالفعل:

- في التطبيق العام، كل مسار باستثناء `protectedPaths`.
- في التطبيق الداخلي، `publicPaths` فقط.
- صفحات المشاركة والنماذج العامة التي ينبغي أن يتمكن الوكلاء من قراءتها.
- لا تُدرج أبدًا البيانات الخاصة المرسلة أو لوحات المعلومات التي تتطلب مصادقة أو حالة المستخدم أو المؤسسة، حتى لو كانت صفحة قريبة عامة.

للبدء من إعدادات الوصول، يأخذ `deriveAgentWebPublicRoutes` من `@agent-native/core/agent-web` قيم `audience` و`publicPaths` و`protectedPaths` و`routes` لتطبيقك، ويعيد المسارات التي تجعلها تلك الإعدادات عامة. ولا تزال كل صفحة تحتاج إلى عنوانها الخاص وMarkdown الخاص بها.

يؤدي هذا إلى إبقاء التطبيقات المختلطة طبيعية. يمكن لتطبيق النماذج الكشف عن صفحة نموذج عامة والحفاظ على خصوصية عمليات الإرسال. يمكن لتطبيق المحتوى أن يكشف المنشورات المنشورة ويحافظ على خصوصية المحرر. يمكن لموقع المستندات أن يكشف كل شيء باستثناء أدوات الإدارة.

## الصفحات العامة ليست أدوات عامة {#public-tools}

الوصول إلى الصفحة العامة والوصول إلى الأداة العامة منفصلان. كون المسار عامًا فقط يعني أن الوكلاء يمكنهم قراءة هذا المسار مثل HTML، وMarkdown، وإدخالات خريطة الموقع، وإدخالات llms، والبيانات المنظمة.

<Callout id="doc-block-s50w8y" tone="warning">

**الصفحة العامة ليست أداة عامة.** جعل المسار قابلاً للزحف لا يكشف أي إجراء أبدًا. يتطلب الوصول إلى الأداة اشتراكًا صريحًا في `publicAgent.expose` على الإجراء.

</Callout>

## ملفات وقت البناء {#build-time}

تقوم أدوات إطار العمل المساعدة في `@agent-native/core/agent-web` بإنشاء الملفات الشائعة من قائمة صفحات واحدة:

```ts
import {
  buildAgentWebStaticFiles,
  normalizeAgentWebConfig,
} from "@agent-native/core/agent-web";

const config = normalizeAgentWebConfig(
  { crawlerPolicy: "discoverable-no-training" },
  { hasPublicRoutes: true },
);

const files = buildAgentWebStaticFiles({
  siteName: "My Agent-Native App",
  siteUrl: "https://example.com",
  description: "Public docs for my app.",
  config,
  pages: [
    {
      path: "/docs",
      title: "Docs",
      description: "Start here.",
      markdown: "# المستندات\n\nابدأ هنا.\n",
      markdownPath: "/docs/getting-started.md",
      lastmod: new Date(),
    },
  ],
});
```

يستدعي `createAgentWebVitePlugin` الدالة `buildAgentWebStaticFiles` نيابةً عنك ويكتب الملفات في المجلدات الموجودة من بين `public` و`dist` و`dist/client` و`dist/server/public` و`build/client`. مع أداة بناء أخرى، استدعِ الأدوات المساعدة مباشرة.

لا يستجيب أي منهما لـ `Accept: text/markdown` على عنوان URL الخاص بالصفحة: نسخة Markdown موجودة فقط على عنوان `.md` الخاص بها. للاستجابة لهذا الترويسة، أضف مسار خادم يعيد Markdown الصفحة مع الترويسات من `buildMarkdownResponseHeaders`، كما يفعل موقع التوثيق. من دون هذا المسار، يفشل التدقيق أدناه في فحص `Accept: text/markdown`.

مرِّر `sitemapGroup` إلى `buildAgentWebStaticFiles` أو `createAgentWebVitePlugin` لتقسيم خريطة موقع كبيرة. يربط الخيار كل صفحة بمفتاح مجموعة، مثل لغتها، فيصبح `sitemap.xml` فهرسًا لخرائط الموقع يضم ملف `sitemap-<group>.xml` واحدًا لكل مجموعة.

## تدقيق الموقع {#audit}

استخدم تدقيق CLI مقابل موقع منشور أو خادم إنتاج محلي:

```bash
npx @agent-native/core@latest audit-agent-web --url https://www.agent-native.com
```

يقوم التدقيق بالتحقق من:

- SSR-HTML المرئي.
- URLs الأساسية.
- JSON-LD.
- سياسة `robots.txt` وخريطة الموقع المطلقة URL.
- إدخالات خريطة الموقع المطلقة.
- `/llms.txt` و`/llms-full.txt`.
- مرايا Markdown.
- `Accept: text/markdown`.
- لا توجد عمليات حظر غير مقصودة 401/403 لوكلاء مستخدم استرداد الوكيل المشترك.

تخرج عملية التدقيق من الصفر إذا كان السطح العام المطلوب مفقودًا.
