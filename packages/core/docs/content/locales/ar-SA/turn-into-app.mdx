# التحويل إلى تطبيق

`/turn-into-app` هي مهارة تحوّل سير عمل أثبتّ نجاحه بالفعل إلى تطبيق Agent-Native. يمكن أن يكون المصدر محادثة أو مهارة أو جدول بيانات أو مشروع Claude أو ChatGPT. يفتح التطبيق على عالمك الخاص، مأهولاً ببيانات نموذجية بشكل المصدر، بينما يعمل الوكيل داخل التطبيق خلف عناصر تحكم على الكائنات التي يتصرف عليها. أما نموذج أسفل شريط خطوات فهو النتيجة التي صُممت المهارة لتجنبها.

## التثبيت {#install}

```bash
npx @agent-native/skills@latest add --skill turn-into-app
```

تأتي المهارة نفسها مع واجهة سطر الأوامر الأساسية:

```bash
npx @agent-native/core@latest skills add turn-into-app
```

داخل مشروع يحتوي بالفعل على واجهة سطر أوامر Agent-Native، يؤدي `agent-native skills add turn-into-app` الغرض نفسه. راجع [دليل Skills](/docs/skills-guide) لمعرفة كيفية تثبيت المهارات وتحميلها.

## استدعاؤها {#invoke}

| الأمر                              | المصدر                                               |
| ---------------------------------- | ---------------------------------------------------- |
| `/turn-into-app`                   | سياق المشروع المرئي، وإلا المحادثة الحالية           |
| `/turn-into-app /some-skill`       | المهارة المحددة، تُحزَّم فوراً حتى في بداية المحادثة |
| `/turn-into-app ./forecast.xlsx`   | جدول بيانات، يُحوَّل إلى منضدة عمل                   |
| `/turn-into-app ./project-export/` | تصدير مشروع Claude أو ChatGPT                        |

بدون وسيط، تبني المهارة آخر مهمة ناجحة وقابلة للتكرار وتسميها. المثال التطبيقي، مثل حساب واحد أو صفقة واحدة، دليل على المهمة وليس مخططها. وإذا تعذّر تحديد أي مهمة، تذكر ما ينقص بدلاً من طرح السؤال العام "ما التطبيق الذي تريده؟".

## أين تعمل {#hosts}

| المضيف                                                     | ما يحدث                                                                            |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Claude Code وCodex وCursor ووكلاء البرمجة المحليون الآخرون | يبني التطبيق ويشغّله ويراجعه في نسخة العمل لديك.                                   |
| Claude أو ChatGPT على الويب                                | يكتب موجزاً محدوداً ويسلّمه إلى Builder عبر موصل Dispatch. ولا يشغّل أي شيء بنفسه. |

يُعد المضيف محلياً عندما يكون لديه دليل عمل حقيقي وطرفية ومساحة عمل. وجود موصل Builder أو Dispatch لا يجعل المضيف مضيف متصفح.

على مضيف المتصفح، تتطلب المهارة موصل Agent-Native Dispatch MCP (`https://dispatch.agent-native.com/mcp`، OAuth) وتستدعي إجراءه `start-workspace-app-creation`. لا يستطيع المضيف تشغيل التطبيق أو فحصه، لذا يبقى التقرير معلّقاً أو غير متحقق منه حتى يُبنى الفرع الذي يعيده Dispatch. تبلّغ المهارة بما أعاده Dispatch فعلاً ولا تختلق رابط فرع أبداً. بالنسبة إلى مشروع ChatGPT، أو أي مضيف يوفر MCP فقط، ضع تعليمات المهارة في تعليمات المشروع أو ملفات المعرفة.

## المصادر {#sources}

- **المحادثات.** آخر مهمة محددة وقابلة للتكرار هي المنتج.
- **المهارات.** تصبح خطوات المهارة ونقاط القرار البشرية فيها وقواعد القراءة فقط هي التطبيق. وإذا كانت المهارة تحتفظ بملفات خطة، تبقى هذه الملفات مصدر الحقيقة عبر Local File Mode ويكون التطبيق محلياً فقط.
- **جداول البيانات.** تُجرد كل ورقة عمل أولاً. تحدد البنية الخلايا التي تمثل مدخلات ومخرجات؛ أما اللون فمجرد تلميح ضعيف. لا يُنسخ المصنف أبداً إلى موجّه أو SQL أو حالة التطبيق. ولا يكون رابط Google Sheets مصدراً إلا إذا كان قابلاً للقراءة عبر اتصال Sheets أو Drive موثّق؛ وإلا تطلب المهارة تصديراً.
- **مشاريع Claude وChatGPT.** المصدر هو التعليمات المرئية وملفات المعرفة وعمليات التشغيل السابقة المقدَّمة. لا يقرأ الموصل محادثات المشروع المخفية أو الروابط الخاصة أو بيانات الاعتماد، ولا توجد أداة استيراد من الروابط المشتركة. أرفق تصديراً عندما لا يكون السياق مرئياً.

## ما الذي تحصل عليه {#what-you-get}

- **شكل مختار من المصدر.** تختار المهارة واحداً من 13 نمطاً أصلياً، مثل طابور فرز أو لوحة خط أنابيب أو منضدة عمل حية أو شبكة جدولة أو فرق مراجعة أو مراقب. النمط الأصلي هو الكائن الذي ينظر إليه المستخدم وليس الإجراء الذي يتبعه، لذا تصبح خطوات المصدر حالات للكائنات (مسودة، تم التحقق، معتمد) بدلاً من معالج خطوات.
- **اتجاه بصري مسمّى.** واحد من ستة اتجاهات (`ledger` و`control-room` و`paper-desk` و`studio-canvas` و`tidepool` و`signal-board`) مع رموز فاتحة وداكنة، يُختار وفق النمط الأصلي ومجال المصدر. وتتقدم العلامة التجارية القائمة أو اتجاهك الصريح عليه.
- **شاشة أولى مأهولة.** تهبط `/` على مسار مجال مسمّى ببيانات نموذجية اصطناعية موسومة كنموذج وبشكل المصدر. وتُعد الحالة الفارغة أو الواجهة البطولية أو الخطوة الأولى من الإجراء أو النموذج عيباً ما لم يكن المصدر نفسه على شكل نموذج.
- **لحظات الوكيل على الكائنات.** يسلّم كل عنصر تحكم موسوم بالذكاء الاصطناعي موجّهاً محدوداً إلى الشريط الجانبي للوكيل. يعرض الكائن حالة عمل فوراً، وتعود النتيجة إليه مع قبول وتعديل وإعادة المحاولة. وتبقى الأسئلة اللاحقة في المحادثة نفسها.
- **تطبيق Agent-Native حقيقي.** العمل الحتمي هو ملفات `defineAction` يستدعيها كل من الواجهة والوكيل. يستخدم التطبيق إعداد Use Builder.io أو Custom keys القياسي، ويكتب العرض والتحديد الحاليين في حالة التطبيق، ويضم `AGENTS.md` يعرّف الوكيل داخل التطبيق بالتطبيق الجديد.

تحفظ المهارة موجز مصدرها في `docs/brief.md` وتُلحق تصميم الواجهة بـ `DESIGN.md`.

## كيف تعمل عملية التشغيل {#how-it-works}

1. **الموجز.** تقرأ المصدر كاملاً وتكتب موجزاً قصيراً: المهمة، وثلاث لحظات وكيل على الأكثر، والثوابت، ومخاطر البيانات، ومصدر الحقيقة، والافتراضات.
2. **التصميم.** تقرر النمط الأصلي والاتجاه والغلاف ونافذة العرض الأولى والبيانات النموذجية ولحظات الوكيل، وتنشر الموجز مرة واحدة كنقطة تحقق. وتتابع دون انتظار.
3. **الهيكل.** تنشئ التطبيق الحقيقي بقالب chat ولا تكتب فوق تطبيق موجود أبداً.

   ```bash
   npx --yes @agent-native/core@latest create <slug> --standalone --template chat
   ```

   وداخل مساحة عمل Agent-Native قائمة، تشغّل بدلاً من ذلك `pnpm exec agent-native add-app <slug> --template chat` من جذر مساحة العمل.

4. **البناء.** تُبنى الإجراءات وواجهة المجال والبيانات النموذجية ولحظات الوكيل وتعليمات الوكيل معاً.
5. **المراجعة.** تشغّل التطبيق وتراجع لقطات الشاشة. انظر أدناه.
6. **التحقق.** تشغّل `pnpm typecheck` و`pnpm agent-native:doctor` و`pnpm build`، ثم تكتب التقرير النهائي.

تستهدف المهارة نحو 45 دقيقة. وإذا كانت 35 دقيقة قد مضت عند بدء المراجعة، فإنها تجري جولة واحدة وتسرد المعايير المفتوحة.

## حلقة مراجعة لقطات الشاشة {#review-loop}

قبل التسليم، تشغّل المهارة خادم التطوير وتلتقط `/` بحجمي سطح المكتب والهاتف في الوضعين الفاتح والداكن، إضافة إلى عنصر تحكم الوكيل الرئيسي بعد نقرة. وتقيّم اللقطات وفق معيار من 12 صفاً يغطي أثر نافذة العرض الأولى، وملاءمة المجال، والتسلسل الهرمي، وانضباط عناصر الواجهة، والبيانات النموذجية، والطباعة، واللون، والإتقان، والوكيل والواجهة معاً، وتخطيط 390 بكسل، والوضع الداكن، وإمكانية الوصول.

بعض الملاحظات تُفشل المراجعة مهما كان متوسط الدرجات: غلاف معالج خطوات، أو عدم فتح `/` على مسار المجال، أو نافذة عرض أولى فارغة أو نموذجية فقط، أو رموز افتراضية للهيكل، أو نص مقصوص، أو markdown خام، أو تمرير جانبي عند 390 بكسل، أو خطأ في وحدة التحكم. وتصلح كل ملاحظة في دفعة واحدة، وتعيد ضبط ما غيّرته النقرة، وتلتقط من جديد. الافتراضي جولتان، وثالثة فقط إذا ظلت الثانية دون المستوى المطلوب وسمح الوقت. والمستوى المطلوب هو متوسط 4.0 أو أعلى دون أي معيار أقل من 3 ودون إخفاق تلقائي.

تُحفظ لقطات الشاشة في `.tmp/ui-review/out/` داخل التطبيق، ويسرد التقرير النهائي مساراتها ودرجاتها. ولا يمكن اختبار نتيجة تصل إلى الواجهة إلا بوجود مزوّد ذكاء اصطناعي متصل؛ وبدونه يذكر التقرير أن النتيجة لم تُختبر.

## التشغيل والنشر {#run-deploy}

للمراجعة المحلية، تضبط المهارة `AUTH_DISABLED=1` في ملف `.env` المتجاهَل الخاص بالتطبيق، لأن متصفح لقطات الشاشة الجديد غير مسجّل الدخول. وهذا للتطوير على loopback فقط. يُزال قبل `pnpm build` الأخير، ويجب ألا يُرسَل إلى المستودع أو يُنشر أبداً. وبدونه تظهر عند فتح التطبيق بطاقة "Continue as local dev".

لتشغيل التطبيق بنفسك:

```bash
pnpm dev
```

لاستخدام مزوّد النماذج الخاص بك محلياً، ضع مفتاحاً مثل `ANTHROPIC_API_KEY` في ملف `.env` نفسه. وإلا يعرض الشريط الجانبي للوكيل إعداد Use Builder.io أو Custom keys المشترك.

لا تنشر المهارة إلا عندما تطلب ذلك أو يكون المزوّد مهيأً بالفعل. ولا يزال البناء المحلي السليم يطبع كتلة "production configuration errors" برمز خروج 0. وهذه هي قائمة التحقق للنشر: `BETTER_AUTH_SECRET` ثابت و`DATABASE_URL` دائم، إضافة إلى `A2A_SECRET` لتطبيق داخل مساحة عمل. تبلّغ المهارة بها كخطوة معلّقة ولا تنشئ قيماً بديلة. راجع [نشر تطبيق](/docs/deploy-an-app) و[نشر مساحة عمل](/docs/workspace-deployment).

يصنّف التقرير النهائي الأدلة على حدة: قيد التشغيل محلياً، وتم التحقق منه محلياً، وجاهز للبناء، ومنشور، وتم التحقق منه مباشرةً هي حالات مختلفة، ولا يسمح التقرير أبداً بأن تحل إحداها محل الأخرى.

## الحدود المعروفة {#limits}

- **تعديل `.env` أثناء تشغيل خادم التطوير.** تدخل إعادة التحميل الفورية بعد تغيير `.env` في حلقة على قفل قاعدة البيانات المحلية وتعرض أخطاء 500. أوقف الخادم، وعدّل `.env`، ثم شغّله من جديد.
- **جداول البيانات الملتبسة.** إذا بقيت مسارات العمل المرشحة أو ربط المدخلات والمخرجات ملتبسة جوهرياً بعد مراجعة محدودة، تطرح المهارة سؤالاً موجزاً واحداً مع تفسيرها الموصى به. وفي التشغيل بلا واجهة تطبع السؤال، وتسجّل الافتراض في الموجز، وتواصل البناء.
- **جداول البيانات على مضيف المتصفح.** لا يمكن إرفاق مصنف؛ يمرر المضيف تمثيل CSV محدوداً كنص، أو رابطاً عاماً عن قصد، ويذكر التسليم ما تُرك خارجاً. رابط ورقة خاصة ليس مصدراً؛ تطلب المهارة اتصال Sheets أو Drive موثقاً أو ملف تصدير، ولا تستخدم أبداً رابط تصدير عاماً لتجاوز ضوابط الوصول.
- **ألوان الخلايا.** لا تستطيع المعاينة النصية إثبات الألوان، لذا تقرأ المهارة على مضيف محلي الصيغ والقيم المخزّنة مؤقتاً معاً، وتعامل اللون كتلميح ضعيف.
- **تطبيقات Local File Mode.** التطبيق الذي يكون مصدر حقيقته ملفات المضيف محلي فقط ولا يُنشر.
- **عمليات التسليم من مضيفات المتصفح.** تبقى النتيجة غير متحقق منها حتى يعيد Dispatch فرعاً مبنياً. ولا تستطيع المهارة تشغيل التطبيق هناك أو التقاط لقطات له.
