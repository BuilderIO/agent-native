# عمليات النشر المُدارة

عند تعطيل مستخدم عبر SCIM، تُعلَّم العضوية الموفَّرة كقيد الانتظار وتُزال أدوار التطبيق فوراً. يجب على المسؤول اختيار خلف لإكمال نقل الملكية؛ وعند الإكمال يُكتب حدث تدقيق غير قابل للتغيير.

استخدم مساحة عمل للتطبيقات الداخلية لمؤسسة واحدة. المؤسسة هي حد العضوية والبيانات. تجمع مساحة العمل إعدادات النشر لتطبيق واحد أو أكثر.

## إغلاق التسجيل وإنشاء المؤسسات

```dotenv
AUTH_SIGNUP=invited
ORG_CREATION=closed
AUTO_CREATE_DEFAULT_ORG=0
AUTH_BOOTSTRAP_ADMINS=admin@example.com
AUTH_REQUIRE_EMAIL_VERIFICATION=1
```

مع `AUTH_SIGNUP=invited` يحتاج الحساب الجديد إلى دعوة معلقة أو نطاق بريد موثّق ومسموح أو عنوان ضمن `AUTH_BOOTSTRAP_ADMINS`. ينطبق الفحص على كلمة المرور والرابط السحري وتسجيل الدخول الاجتماعي. الانضمام حسب النطاق ليس دعوة ولا يحدد دور التطبيق.

ينشئ أول مسؤول تهيئة يسجل الدخول المؤسسة الأساسية ويصبح مالكها. إذا كانت هناك مؤسسة واحدة، يُضاف إليها كمالك. إذا تعددت المؤسسات، لا يختار النظام بينها. بعد ذلك اضبط النطاق المسموح وادعُ الفريق من إعدادات الفريق.

مع `ORG_CREATION=closed`، يُرفض إنشاء المؤسسات إلى أن تحتوي `AUTH_BOOTSTRAP_ADMINS` على مسؤول موثّق واحد على الأقل، يقوم بإنشاء المؤسسة الأساسية عند أول تسجيل دخول له.

احتفظ بعنوان مسؤول تهيئة موثّق متاح للإعداد الأولي والاسترداد.

## مفاتيح الشركة والأدوار

يمكن للمالك أو المسؤول حفظ مفتاح LLM للمؤسسة. تحفظ شاشة إعداد المزوّد المفاتيح للمؤسسة فقط، لذلك يستخدم الأعضاء مفتاح الشركة نفسه. تُزال الصفوف الشخصية القديمة عند حفظ مفتاح المؤسسة، أو يمكن حذفها من شاشة إعداد المزوّد قبل التبديل.

تعرض خانة النموذج النماذج الحالية كاقتراحات، ويمكن إدخال أي معرّف نموذج يدعمه المزوّد أو البوابة مباشرة.

أدوار التطبيق خاصة بتطبيق واحد، ويمكن للعضو امتلاك عدة أدوار. يستطيع المسؤول ربط الأذونات المعرّفة في الشيفرة بالأدوار دون إعادة نشر التطبيق.

## تغيير البريد وإعادة ربط الهوية

يغيّر المستخدم البريد من إعدادات الحساب بعد التحقق. لترحيل إداري شغّل `agent-native identity rekey --from old@example.com --to new@example.com` لكل تطبيق. راجع الجداول وعدد الصفوف قبل `--yes`. تبقى سجلات التدقيق السابقة كما هي. ترحيل الهوية إلى معرّف ثابت مخطط لما بعد 1.0.

## تسجيل الدخول الموحّد للمؤسسة وتهيئة الدليل

تسجيل الدخول الموحّد للمؤسسة وSCIM ميزتان اختياريتان. فعّل `AUTH_SSO=1` و`AUTH_SCIM=1` لإظهار عناصر التحكم في إعدادات الفريق. اضبط العلامات في بيئة الإنشاء وبيئة التشغيل معًا؛ يتطلب تغييرها بعد النشر إعادة الإنشاء. اضبط نطاق بريد المؤسسة أولا. أضف موفر OIDC أو SAML باستخدام بيانات المُصدر ومعرّف العميل والسر أو نقطة دخول SAML ومعرّف الكيان وبيانات XML الوصفية. يعرض الإعداد عنوان إعادة التوجيه وبيانات تعريف موفر الخدمة. أنشئ سجل DNS TXT للاسم `_better-auth-token-<provider-id>.<organization-domain>` بالقيمة المعروضة، وانتظر انتشار DNS ثم تحقّق من النطاق. بعد التحقق، يمكن للمسؤول فرض Google أو موفر SSO. أنشئ اتصال SCIM وانسخ الرمز الذي يظهر مرة واحدة إلى موفر الهوية مع نقطة النهاية المعروضة. في Okta أو Microsoft Entra ID أنشئ تطبيق OIDC أو SAML، وأدخل القيم المعروضة. للتهيئة، اضبط عميل SCIM واختبر إنشاء مستخدم وتحديثه وتعطيله مع مجموعة صغيرة قبل تعميمه. إعدادهما منفصل عن اتحاد الهوية بين التطبيقات.

استخدم `accessFilter()` و`assertAccess()` لعمليات الخادم. يستخدم SQL الخاص بالوكيل طرق عرض مؤقتة ومفلترة. يتضمن `pnpm guards` فحص الاستعلامات غير المقيدة. RLS غير مفعّل ومخطط كتعزيز بعد 1.0. اختر مساحة عمل لعدة تطبيقات داخلية، وتطبيقاً مستقلاً لأداة منفردة أو نموذج أولي. راجع [اختيار مساحة عمل أو تطبيق مستقل](/docs/multi-app-workspace#standalone-or-workspace) و[الإصدار والاستقرار](/docs/versioning-and-stability).
