# دليل المطور

هذه الصفحة لأي شخص يخصص قالب التقويم أو يوسّعه: البدء السريع، وكل إجراء،
ونموذج البيانات، وسطح المسارات، وكيفية الإضافة إليه. راجع
[التقويم](/docs/template-calendar) لمعرفة ما يفعله التطبيق.

## البدء السريع

يشرح هذا تشغيل التقويم من عدم وجود أي تثبيت إلى الاتصال بـ Google Calendar.
الأوامر متطابقة سواء كنت في Terminal على macOS أو PowerShell/Command Prompt
على Windows، فهي أدوات Node.js عادية.

<Steps>

### أنشئ التطبيق

```bash
npx @agent-native/core@latest create my-calendar --standalone --template calendar
cd my-calendar
pnpm install
```

يتطلب هذا تثبيت [Node.js](https://nodejs.org) الإصدار 22 أو أحدث و
[pnpm](https://pnpm.io) أولًا. راجع [بدء الاستخدام](/docs/getting-started)
إذا لم تكن قد ثبّت أيًا منهما بعد، أو لم يكن لديك اتصال بنموذج لغوي
(Builder.io، أو مفتاح Anthropic/OpenAI، أو Ollama محلي) مُعد.

### شغّل خادم التطوير

```bash
pnpm dev
```

يُفتح التطبيق على `http://localhost:8082`. إذا لم يُفتح تلقائيًا، فزُر هذا
العنوان في متصفحك. يعمل التقويم بشكل كامل مع كون Google غير متصل. لن تواجه
خطأ إلا إذا جرّبت إجراءً يحتاجه قبل الاتصال.

### وصّل Google Calendar

في التطبيق، افتح **الإعدادات**، وفي تبويب **General** ابحث عن بطاقة
**Google Calendar**، ثم انقر على **الاتصال بتقويم Google**. يفتح هذا
معالج إعداد:

1. **أنشئ مشروع Google Cloud**، إذا لم يكن لديك مشروع جاهز للاستخدام بالفعل:
   في [Google Cloud Console](https://console.cloud.google.com/)، انقر على
   القائمة المنسدلة للمشروع بالقرب من أعلى الصفحة، ثم **New Project**. أعطه
   أي اسم، وانقر على **Create**، وانتظر الإشعار بأنه جاهز. تأكد من أنه محدد
   في نفس القائمة المنسدلة قبل الاستمرار.
2. **فعّل واجهة برمجة التطبيقات**: مع تحديد مشروعك، اذهب إلى **APIs &
   Services → Library**، وابحث عن "Google Calendar API"، وافتحها، وانقر على
   **Enable**.
3. **اضبط شاشة الموافقة**: ضمن **APIs & Services → OAuth consent screen**،
   أعدّ واحدة ("External" مناسبة للتطوير).
4. **أنشئ بيانات الاعتماد**: ضمن **APIs & Services → Credentials**، أنشئ
   معرّف عميل OAuth من نوع "Web application"، وأضف
   `http://localhost:8082/_agent-native/google/callback` كعنوان URI
   لإعادة توجيه معتمد (8082 هو منفذ التطوير الافتراضي للتقويم).
5. **أضف بيانات الاعتماد**: نزّل ملف JSON لبيانات الاعتماد وحمّله في
   المعالج، أو فعّل "Paste manually" وأدخل Client ID وClient Secret مباشرة.

يحفظ التقويم هذه البيانات في مخزن أسراره الخاص، لا في ملف `.env`، لذا فإن
هذه الخطوة متطابقة على Windows وmacOS. تُحدَّث الرموز المميزة تلقائيًا بعد
الاتصال.

### وصّل Zoom (اختياري)

بخلاف Google، لا يملك Zoom نموذج إعدادات. أنشئ ملف `.env` في جذر المشروع
(أو أضف إلى الملف الموجود) بما يلي:

```text
ZOOM_CLIENT_ID=your-client-id
ZOOM_CLIENT_SECRET=your-client-secret
```

احصل على Client ID وSecret من [تطبيق Zoom OAuth](https://marketplace.zoom.us/)
(Zoom Marketplace → Develop → Build App → OAuth)، مع
`/_agent-native/zoom/callback` كعنوان إعادة التوجيه، ثم أعد تشغيل `pnpm dev`
حتى يأخذ القيم الجديدة. بدون اتصال Zoom، يمكن لروابط الحجز أن تقدّم Google
Meet، لكن ليس Zoom.

</Steps>

<Callout tone="warning">

على Windows، تضيف بعض المحررات لاحقة `.txt` مخفية عند حفظ ملف باسم `.env`،
مما يترك `.env.txt` لا يقرأه التقويم أبدًا. في File Explorer، فعّل "File
name extensions" (تبويب View) وتأكد من أن الملف المحفوظ يُسمى بالضبط `.env`،
دون أي شيء بعده.

</Callout>

<Callout tone="info">

**تعيش الأحداث في Google Calendar، لا في SQL.** يستدعي كل إجراء متعلق
بالأحداث واجهة برمجة تطبيقات Google Calendar مباشرة، فلا يوجد جدول أحداث
محلي. يتم تخزين روابط الحجز والحجوزات والتوفر وحالة الاتصال محليًا فقط. لا
تقرأ أو تكتب بيانات الأحداث باستخدام SQL خام مطلقًا.

</Callout>

## قائمة الإجراءات

كل عملية هي ملف TypeScript في `templates/calendar/actions/`، يتم تركيبه
تلقائيًا على `POST /_agent-native/actions/:name`.

### الأحداث والحاضرون

تعيش بيانات الأحداث في Google Calendar، لا في SQL مطلقًا.

| الإجراء                  | ما يفعله                                                                                        |
| ------------------------ | ----------------------------------------------------------------------------------------------- |
| `list-events`            | سرد الأحداث في نطاق زمني                                                                        |
| `search-events`          | البحث في الأحداث باستعلام                                                                       |
| `get-event`              | قراءة حدث واحد بحسب المعرّف                                                                     |
| `create-event`           | إنشاء حدث، بما في ذلك التكرار (RRULE)، ومواقع العمل، وأنواع الحالة (`outOfOffice`، `focusTime`) |
| `update-event`           | تحديث حدث، بما في ذلك التكرار، ومواقع العمل، وأنواع الحالة                                      |
| `delete-event`           | حذف حدث                                                                                         |
| `manage-event-draft`     | تجهيز دعوة غير مُرسلة لمراجعة المستخدم قبل كتابة أي شيء أو إشعار الحاضرين                       |
| `rsvp-event`             | القبول أو الرفض أو التأشير كمؤقت على دعوة                                                       |
| `get-attendee-timezones` | قراءة إعدادات المناطق الزمنية المخصصة لكل ضيف                                                   |
| `set-attendee-timezone`  | ضبط إعداد منطقة زمنية مخصص لضيف بحيث يظل وقته المحلي يظهر بشكل صحيح                             |

### التوفر والعثور على وقت

| الإجراء               | ما يفعله                                                                                                      |
| --------------------- | ------------------------------------------------------------------------------------------------------------- |
| `get-availability`    | قراءة الجدول الأسبوعي، والمنطقة الزمنية، والفاصل الزمني، والإشعار المسبق، وإعدادات نافذة الحجز المسبق         |
| `update-availability` | تحديث الجدول الأسبوعي، والمنطقة الزمنية، والفاصل الزمني، والإشعار المسبق، وإعدادات نافذة الحجز المسبق         |
| `check-availability`  | العثور على فترات متاحة ليوم واحد                                                                              |
| `find-a-time`         | بحث مشترك عن فترة متاحة بين منظّم وحاضرين محدّدين بالاسم، يجمع بين حالة تفرغ/انشغال Google والتعارضات المحلية |

### روابط الحجز والحجوزات

### الأشخاص والتراكبات

| الإجراء                 | ما يفعله                                               |

| `update-overlay-people` | تحديث الأشخاص الآخرين الذين تم تثبيت تقويماتهم في عرضك |

### Zoom

| الإجراء                   | ما يفعله                                                         |

### الإعدادات والتفضيلات

| الإجراء                              | ما يفعله                                                                                                   |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| `get-settings`                       | قراءة إعدادات المستخدم                                                                                     |
| `update-settings`                    | تحديث إعدادات المستخدم                                                                                     |
| `update-calendar-visual-preferences` | تحديث تفضيلات العرض المحلية فقط (ألوان الأحداث، إخفاء عطلات نهاية الأسبوع). لا تلمس Google Calendar مطلقًا |

### التنقل وحالة واجهة المستخدم

| الإجراء       | ما يفعله                                   |
| ------------- | ------------------------------------------ |
| `navigate`    | نقل واجهة المستخدم إلى عرض أو تاريخ أو حدث |
| `view-screen` | قراءة العرض الحالي للوكيل                  |

### التصعيد إلى واجهة برمجة تطبيقات المزوّد

واجهة برمجة تطبيقات Google Calendar الخام (وأي CRM متصل)، لاستخدامها عندما
تكون الإجراءات أعلاه ضيقة جدًا.

| الإجراء                 | ما يفعله                                                               |
| ----------------------- | ---------------------------------------------------------------------- |
| `provider-api-catalog`  | سرد واجهات برمجة تطبيقات المزوّد الخام المتاحة للاستدعاء المباشر       |
| `provider-api-docs`     | قراءة وثائق نقطة نهاية خام لواجهة برمجة تطبيقات المزوّد                |
| `provider-api-request`  | استدعاء واجهة برمجة تطبيقات Google Calendar الخام (أو CRM متصل) مباشرة |
| `list-staged-datasets`  | سرد الفحوصات الكبيرة المُدرجة للاستعلام بدلاً من إرجاع نتائج خام       |
| `query-staged-dataset`  | الاستعلام عن مجموعة بيانات مُدرجة                                      |
| `delete-staged-dataset` | حذف مجموعة بيانات مُدرجة                                               |

## استعراض إجراء واحد بالتفصيل

يُظهر `create-booking-link` أنماطًا تستحق إعادة استخدامها في أي إجراء:
التحقق من صحة المدخلات قبل أن تلمس قاعدة البيانات، وتطبيق قاعدة عبر جدولين،
وتحديد المستخدم المسجّل الدخول بأمان، وتوحيد شكل مدخل مرن مرة واحدة بدلاً من
تكراره في كل قارئ.

## تخصيصه

كل جزء من التطبيق مصدر قابل للتحرير. ابدأ من هنا:

- `templates/calendar/actions/` — أضف ملفًا جديدًا باستخدام `defineAction`
  لكشف قدرة جديدة لكل من الوكيل والواجهة الأمامية.
- `templates/calendar/app/routes/` — واجهة المستخدم، المذكورة أعلاه.
- `templates/calendar/server/db/schema.ts` — أضف أعمدة أو جداول باستخدام Drizzle. حافظ على توافق الكود مع PostgreSQL ليعمل القالب مع PGlite وPostgres.
- `templates/calendar/server/lib/` — تكاملات المزوّدين: `google-calendar.ts`،
  و`zoom.ts`، و`people-search.ts`، و`ical-fetcher.ts`، و`find-time.ts`،
  و`provider-api.ts`.
- `templates/calendar/AGENTS.md` — تعليمات الوكيل. حدّث هذا الملف عندما
  تعلّم الوكيل قدرات أو اصطلاحات جديدة.
- `templates/calendar/.agents/skills/` — الأنماط التفصيلية التي يتبعها
  الوكيل. skills ذات الصلة: `event-management`، و`availability-booking`،
  و`real-time-sync`، و`storing-data`، و`delegate-to-agent`،
  و`frontend-design`.
- `templates/calendar/shared/api.ts` — أنواع TypeScript المشتركة
  (`CalendarEvent`، و`BookingLink`، و`ExternalCalendar`،
  و`ConferencingConfig`، وغيرها) التي يستخدمها كل من الخادم والعميل.

إذا أضفت ميزة، تذكّر تحديث المجالات الأربعة كلها: واجهة المستخدم، والإجراء،
وskill أو إدخال AGENTS.md، وأي حالة تطبيق يحتاج الوكيل إلى رؤيتها. هذا ما
يحافظ على تكافؤ الوكيل وواجهة المستخدم.
