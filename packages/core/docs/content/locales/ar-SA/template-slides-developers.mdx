# دليل المطور

هذه الصفحة لأي شخص يخصص قالب الشرائح أو يوسّعه: نموذج بيانات SQL، وكيف تُحفظ
سلامة الكتابات المتزامنة، وكل إجراء يمكن للوكيل استدعاءه، وخريطة المسارات،
وأين تُجرى التغييرات الشائعة.

## البدء السريع

```bash
npx @agent-native/core@latest create my-slides --standalone --template slides
```

راجع [بدء الاستخدام](/docs/getting-started) لمعرفة بقية خطوات الإعداد (`cd`، `pnpm install`، `pnpm dev`) وأساسيات إطار العمل.

## نموذج الاستمرارية

كل مجموعة هي كائن JSON واحد في `decks.data`. تمر كل عملية كتابة عبر إجراء من
نوع قراءة-تعديل-كتابة على الخادم يحتفظ بقفل خاص بكل مجموعة، لذا لا تتلف
الكتابات المتزامنة أبدًا عمل بعضها، سواء كانت من إنسان والوكيل، أو من
إنسانين، يعدّلان شرائح مختلفة من نفس المجموعة.

- **إجراءات الوكيل** (`add-slide`، `update-slide`) تستخدم إجراءاتها الخاصة الدقيقة المخصصة وتتشارك في نفس القفل.
- **محرر المتصفح** يُدرج عمليات دقيقة (`patch-slide`، `delete-slide`، `reorder-slides`، `add-slide`، `patch-deck-fields`) في قائمة انتظار عبر `patch-deck` بدلاً من عملية PUT لكل المجموعة.

<Callout id="doc-block-slides10" tone="warning">

إذا كنت توسّع مسار الحفظ في المحرر، أدرج عملية جديدة في قائمة الانتظار عبر
`patch-deck`. لا تُضِف عملية PUT جديدة لكل المجموعة. فذلك يعيد سباق "آخر كتابة
تفوز" الذي وُجد القفل لمنعه.

</Callout>

#### بنية الشريحة

كل شريحة داخل `decks.data` هي:

```json
{
  "id": "slide-1",
  "layout": "title",
  "content": "<div class=\"fmd-slide\" style=\"...\">...</div>"
}
```

`content` هو HTML خام. يوفّر العارض نسبة العرض إلى الارتفاع الثابتة والخلفية،
ويوفّر HTML كل ما بداخلها. يُدعم التضمين الغني أيضًا: يمكن أن تعيش رسوم
تخطيطية مرسومة باليد ومخططات بيانية مُعرَّضة مباشرة داخل شريحة إلى جانب HTML
عادي.

## قائمة الإجراءات

### دورة حياة المجموعة

- `create-deck` — مجموعة جديدة، مع تعبئة مسبقة اختيارية بالشرائح، أو استبدال مجمّع وذري لشرائح مجموعة موجودة. حذف `slides` أو تمرير `[]` لإنشاء مجموعة فارغة. يفتح الإجراء المجموعة الجديدة من خلال حالة التطبيق.
- `get-deck` — كائن JSON الكامل للمجموعة، أو عرض ملخّص مضغوط للشرائح
- `list-decks` — كل مجموعة يمكن للمستدعي رؤيتها، مع عروض خفيفة/مضغوطة/كاملة للشرائح لاستقصاء رخيص التكلفة
- `duplicate-deck` — نسخ مجموعة بمعرّفات شرائح جديدة
- `update-deck-aspect-ratio` — 16:9 أو 1:1 أو 9:16 أو 4:5

تدعم `add-deck` و`save-deck` و`delete-deck` مسارات الإنشاء المتفائل
والتراجع/الإعادة والحذف في محرر المتصفح. يستخدم الوكيل بدلاً منها
`create-deck`، و`add-slide`/`update-slide`/`patch-deck`، وإجراءات المشاركة
الخاصة بإطار العمل.

### طلبات الوصول

- `request-deck-access`، `approve-deck-access-request`، `get-deck-access-status` — مسار طلب الوصول لمجموعة خاصة: يطلبه زائر لا يملك صلاحية وصول، ويوافق المالك عليه أو يرفضه من التطبيق أو من مسار `/access-request/approve`، ويمكن لأي من الجانبين استقصاء الحالة الراهنة

### تعديلات الشرائح

- `add-slide` — إلحاق شريحة واحدة (أو إدراجها في موضع معين). استدعِه بالتتابع بعد `create-deck` فارغ حتى يستطيع المحرر إظهار التقدّم.
- `update-slide` — تعديل دقيق بالبحث والاستبدال أو تعديل كامل لمحتوى الشريحة
- `patch-deck` — قائمة انتظار العمليات الدقيقة التي يستخدمها محرر المتصفح بدلاً من عملية PUT لكل المجموعة
- `get-layout-overflows` — قراءة نتائج مقاسة في المتصفح لمدى ملاءمة الشريحة لتخطيطها، حتى يمكن اكتشاف تعديل لم يعد يناسب تخطيطه وتنقيحه

### السجل

- `list-deck-versions`، `get-deck-version`، `restore-deck-version` — تأخذ كل عملية كتابة لقطة أولًا، لذا يمكن سرد أي لحظة زمنية واستعادتها

### التعليقات

- `list-slide-comments`، `add-slide-comment`، `update-slide-comment`، `delete-slide-comment`

### الاستيراد

- `import-pptx`، `import-docx`، `import-google-doc` — مستوردات مخصصة لتنسيق واحد
- `import-google-slides-reference` — استيراد مجموعة Google Slides كمجموعة مرجعية قابلة لإعادة الاستخدام، بدلاً من سحب محتواها إلى المجموعة العاملة
- `import-file` — نقطة دخول واحدة لـ PPTX أو DOCX أو PDF، أو ملف Figma بصيغة `.fig` (والذي يوجَّه إلى فهرسة نظام تصميم Builder بدلاً من استيراد شرائح)
- `extract-pdf` — تفريغ نص خام من PDF، متاح فقط عبر CLI، ويُستخدم غالبًا للتصحيح المحلي

### التصدير

- `export-pptx` — ملف PowerPoint أصلي قابل للتحرير
- `export-google-slides` — إنشاء نفس ملف PPTX بالإضافة إلى رابط استيراد جاهز إلى Google Slides
- `export-html` — ملف HTML مستقل وذاتي الاحتواء بتنقّل مدمج بلوحة المفاتيح

### أنظمة التصميم

- `create-design-system`، `update-design-system`، `delete-design-system`، `get-design-system`، `list-design-systems`، `set-default-design-system`، `apply-design-system` (ربط نظام بمجموعة)
- `get-workspace-defaults`، `set-workspace-defaults` — المجموعة ونظام التصميم الافتراضيان على مستوى مساحة العمل بأكملها. تعيين أي منهما مقصور على المسؤول
- `analyze-brand-assets`، `import-document`، `import-from-url`، `import-code` — جمع إشارات علامة تجارية خام (CSS/خطوط الموقع، أو محتوى مستند أو ملف كود مرفوع) لنظام تصميم **محلي** تصوغه الوكيل
- `index-design-system-with-builder`، `sync-design-system-with-builder`، `import-design-project` — المسار المفهرس عبر Builder لملفات Figma، وقواعد الكود/مستودعات GitHub المتصلة، وملف `design.md`. يبدأ `import-design-project` من نظام تصميم موجود بدلاً من مصدر خام

### السياق الإبداعي

- `clone-context-slide` — إدراج شريحة واحدة مثبَّتة من المكتبة في مجموعة دون تغيير، بلا إعادة إنشاء HTML/CSS الخاصة بها
- `clone-creative-context-deck` — إعادة إنشاء نسخة محددة بدقة من مجموعة محكومة
- `get-deck-reference-context` — استخراج اللغة البصرية لمجموعة موجودة كمكتبة أنماط قابلة لإعادة الاستخدام
- الاسترجاع وتقديم المحتوى إلى المكتبة (البحث، وجلب عنصر سياق، وإدارة عضوية المكتبة) إجراءات مشتركة من إطار العمل يستدعيها الوكيل بالطريقة نفسها في كل تطبيق يدعم السياق الإبداعي. راجع مهارة `creative-context` لمعرفة إجراء الاسترجاع وسلّم إعادة الاستخدام.

### التصعيد والبيانات المُدرجة

- `provider-api-catalog`، `provider-api-docs`، `provider-api-request` — وصول خام إلى واجهة برمجة تطبيقات Google Drive عندما يكون إجراء استيراد/تصدير جاهز ضيقًا جدًا. تحلّ الشرائح المصادقة من حساب Google Docs المتصل بالمستخدم
- `list-staged-datasets`، `query-staged-dataset`، `delete-staged-dataset` — تجميع نتيجة مزوّد كبيرة مُدرجة دون إعادة جلبها

### التنقل والسياق

- `view-screen` — ما ينظر إليه المستخدم حاليًا: المجموعة المفتوحة، والشريحة الحالية، وأي تحديد بصري نشط
- `navigate` — نقل واجهة المستخدم إلى مجموعة، أو شريحة، أو عرض

#### المهارات (Skills) — `templates/slides/.agents/skills/`

مهارات الوكيل التي تشرح الأنماط عندما يحتاج الوكيل إلى تعديل الكود:

- `create-deck` — كيفية إنشاء مجموعة جديدة، مع قوالب HTML دقيقة للشرائح لكل تخطيط
- `slide-editing` — كيفية تحرير الشرائح الفردية
- `deck-management` — كيفية تخزين المجموعات والوصول إليها
- `design-systems` — شكل بيانات نظام التصميم وكيفية تطبيق الرموز المميزة على الشرائح المُنشأة
- `creative-context` — سلّم إعادة الاستخدام، وإجراء الاسترجاع، وتقديم المحتوى إلى المكتبة

#### AGENTS.md

`templates/slides/AGENTS.md` هو جهاز التوجيه القصير الذي يقرأه الوكيل في كل
محادثة. يشير إلى المهارات ضمن `.agents/skills/` ويضع القواعد الأساسية، ونموذج
الاستمرارية، وعقد حالة التطبيق. حدّث المهارة المعنية كل مرة تضيف أو تغيّر
فيها تخطيط شريحة أو مصدر نظام تصميم.
