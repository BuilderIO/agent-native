# WebMCP

WebMCP واجهة متصفح تجريبية تتيح للصفحات تسجيل أدوات يمكن لوكيل مصرح له
اكتشافها وتشغيلها. يشرح [الدليل الإنجليزي لـ WebMCP](/docs/webmcp) كيفية
استخدام التسجيل والاستهلاك وجلسات المتصفح وحواجز الأمان.
تسجّل الصفحات الموثّقة إجراءات الخلفية المؤهلة تلقائيًا من سجل الإجراءات نفسه.
وتُستبعد الإجراءات التي تتطلب موافقة، كما يُعاد التحقق من الأدوات الحية قبل التشغيل.
كما تسجّل الأسطح الموثّقة التي تستخدم `sessionBypass`، مثل مسارات تضمين MCP، أدوات
إجراءات الخلفية. أما الصفحات العامة والصفحات التي لم يسجّل المستخدم الدخول إليها فلا
تسجّلها.

يهيّئ قلب Agent-Native حشو `@mcp-b/webmcp-polyfill` عندما لا يوفّر المتصفح سطح WebMCP أصليًا قابلًا للاستخدام. يظل الحشو محليًا للصفحة ولا ينشئ اتصال MCP عبر الشبكة.

## اكتشاف HTTP وبديل fetch

للوكلاء الذين لا يشغّلون متصفحًا، يوفّر Agent-Native أيضًا مستند توافق HTTP
قابلًا للجلب في `GET /.well-known/mcp.json`. يعرض المستند نقاط نهاية الإجراءات
ومخططاتها وما إذا كانت للقراءة فقط أو تتطلب مصادقة. هذا اصطلاح للتوافق في
Agent-Native، وليس جزءًا من مواصفة WebMCP أو بديلًا عن MCP القياسي.

يمكن استدعاء الأدوات عبر `POST /mcp/tool/:name` باستخدام `fetch` أو `curl`،
وتظل المصادقة والتفويض والتحقق ونطاق المستأجر على الخادم. يرتبط المستند أيضًا
بنقطة `/mcp` القياسية، وببيان WebMCP الموثّق، وببطاقة A2A.

تحتاج أدوات الصفحة المحلية إلى متصفح WebMCP مفتوح. أما صفحات الموارد فتستطيع
نشر رابط JSON خاص بالعنصر. تفعل Clips ذلك عبر `agentContextUrl` الذي يعلن روابط
النص الكامل وإطارات JPEG، لتظل طريقة HTTP المباشرة متاحة دون فتح المشغّل.
