# نشر تطبيق

يضع نشر تطبيق Agent-Native مستقل التطبيقَ على الإنترنت مع قاعدة بيانات حقيقية،
حتى يتمكن أشخاص آخرون من التسجيل واستخدامه. يتبع كل دليل استضافة الخطوات الخمس
نفسها. تشرح هذه الصفحة ما تفعله كل خطوة وتساعدك على اختيار موفر استضافة. ثم يقدّم
دليل كل موفر الأوامر الدقيقة.

<Callout tone="info">

يلزم Node.js `22.22+`.

</Callout>

## اختيار موفر استضافة {#choose-a-host}

| موفر الاستضافة                                            | أين يعمل التطبيق                                  |
| --------------------------------------------------------- | ------------------------------------------------- |
| [Node.js](/docs/node-js)                                  | خادم تديره بنفسك، مثل جهاز افتراضي                |
| [Docker](/docs/docker)                                    | حاوية على خادم أو موفر استضافة حاويات تديره بنفسك |
| [Vercel](/docs/vercel)                                    | استضافة Vercel، بدون خادم تحتاج إلى إدارته        |
| [Netlify](/docs/netlify)                                  | استضافة Netlify، بدون خادم تحتاج إلى إدارته       |
| [Cloudflare Workers](/docs/cloudflare#cloudflare-workers) | شبكة Cloudflare، بدون خادم تحتاج إلى إدارته       |

اختر Node.js أو Docker عندما تريد تحكمًا كاملًا في الجهاز الذي يعمل عليه التطبيق.
اختر Vercel أو Netlify أو Cloudflare Workers عندما تريد أن يشغّل موفر الاستضافة
التطبيق نيابةً عنك ويمنحه عنوانًا عامًا مع HTTPS.

## الخطوات التي يتبعها كل نشر {#the-steps-every-deployment-follows}

### الخطوة 1: إنشاء التطبيق {#step-1-create-the-app}

أنشئ تطبيقًا مستقلًا وثبّت تبعياته. تستخدم الأدلة قالب Chat كمثال، لكن يمكنك
البدء من أي قالب أو استخدام تطبيق لديك بالفعل. يشرح [البدء](/docs/getting-started)
كيفية إنشاء تطبيق وتشغيله محليًا.

### الخطوة 2: ضبط أسرار البيئة {#step-2-configure-environment-secrets}

يقرأ التطبيق إعدادات الإنتاج من متغيرات البيئة:

| المتغير              | مطلوب | الغرض                                                   |
| -------------------- | ----- | ------------------------------------------------------- |
| `DATABASE_URL`       | نعم   | يربط التطبيق بقاعدة بيانات PostgreSQL الخاصة به         |
| `BETTER_AUTH_SECRET` | نعم   | يوقّع جلسات المستخدمين                                  |
| `BETTER_AUTH_URL`    | لا    | يحدد العنوان العام الذي يستخدمه الناس للوصول إلى تطبيقك |

احفظ هذه المتغيرات في إعدادات البيئة لدى موفر الاستضافة، وليس فقط في ملف `.env`
المحلي الخاص بالتطبيق. يوضح كل دليل كيفية فعل ذلك لدى موفر الاستضافة الخاص به.

يجب أن يشير `DATABASE_URL` إلى قاعدة بيانات PostgreSQL دائمة، مثل Neon أو
Supabase أو Amazon RDS. توضح [أدلة موفري قواعد البيانات](/docs/neon) مكان العثور
على سلسلة الاتصال. يجب أن يبقى `BETTER_AUTH_SECRET` ثابتًا عبر عمليات النشر، لأن
تغييره يؤدي إلى تسجيل خروج كل مستخدم. اضبط `BETTER_AUTH_URL` عند استخدام نطاق
مخصص أو وكيل عكسي.

يسرد [مرجع بيئة النشر](/docs/deployment-environment-variables) كل إعدادات الإنتاج
الأخرى.

### الخطوة 3: الترحيل {#step-3-migrate}

تنشئ عمليات الترحيل الجداول التي يحتاجها التطبيق في قاعدة البيانات وتحدّثها.
شغّلها مقابل قاعدة بيانات الإنتاج قبل أول زيارة، ومرة أخرى بعد كل ترقية:

```bash
pnpm migrate:production
```

لا تتخطَّ هذه الخطوة. في الإنتاج، وخاصةً لدى موفري الاستضافة بدون خوادم، لا ينشئ
التطبيق دائمًا الجداول الناقصة بنفسه. عندها يؤدي الجدول الناقص إلى فشل أول استعلام
حقيقي.

### الخطوة 4: البناء {#step-4-build}

ابنِ التطبيق لموفر الاستضافة لديك. يضبط كل دليل `NITRO_PRESET` حتى ينتج البناء
التنسيق الذي يتوقعه موفر الاستضافة، مثل `node` أو `vercel` أو `netlify` أو
`cloudflare_module`.

### الخطوة 5: النشر {#step-5-deploy}

شغّل البناء أو ارفعه. على Node.js وDocker، تشغّل الخادم أو الحاوية بنفسك. على
Vercel وNetlify وCloudflare Workers، ترفع أداة سطر أوامر البناء وتطبع العنوان العام
للتطبيق.

<Callout tone="warning">

لا تستخدم قاعدة بيانات التطوير المحلية في الإنتاج. فهي تخزّن البيانات على الجهاز
الذي يشغّل التطبيق، لذلك تُفقد لدى معظم موفري الاستضافة. ويعمل اختصار **Continue as local
dev** أيضًا أثناء التطوير المحلي فقط. يستخدم التطبيق المنشور تدفق التسجيل وتسجيل
الدخول المدعوم بقاعدة بيانات الإنتاج وسر المصادقة الخاصين بك.

</Callout>

## التحقق من النشر {#check-the-deployment}

بعد أول عملية نشر، افتح العنوان العام للتطبيق وتحقق مما يلي:

- يمكنك إنشاء حساب وتسجيل الدخول.
- تبقى البيانات التي تنشئها موجودة بعد إعادة تحميل الصفحة.
- يشير أي تسجيل دخول عبر OAuth أو webhook يستخدمه تطبيقك إلى العنوان العام.
