# البيانات والمزامنة

الطريقة الأساسية لقراءة بيانات التطبيق وكتابتها من تطبيق العميل هي من خلال خطافات [action](/docs/actions). من خلال تضمين الطلبات في actions، يمكن لعميلك ووكيلك التفاعل مع تطبيقك بالطريقة نفسها.

في المثال أدناه، يتم تعيين تذكرة للمستخدم الحالي يدويًا من خلال قائمة منسدلة، ثم من خلال وكيل المحادثة. يصل كل من واجهة المستخدم والوكيل إلى نفس action.

### خطافات Action {#action-hooks}

هناك خطافا action من الأرجح أن تستخدمهما: `useActionQuery()` و`useActionMutation()`. يوفر هذان الخطافان الوصول إلى actions تطبيقك.

#### useActionQuery {#use-action-query}

  returns={{
    type: "UseQueryResult<TResult>",
    description:
      'مخزّن مؤقتًا تحت `["action", name, params]`. يُعاد جلبه تلقائيًا كل مرة تكتمل فيها action تُغيّر البيانات، دون الحاجة إلى إبطال يدوي.',
  }}
/>

يُقصد استخدام هذا الخطاف مع actions للقراءة فقط. إنه غلاف رقيق حول دالة [useQuery()](https://tanstack.com/query/latest/docs/framework/react/reference/useQuery).

في المثال أدناه، يتم استدعاء action `list-tickets`. هذا مشابه لإجراء طلب GET لجميع التذاكر.

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery("list-tickets", {});
```

يوضح المثال التالي طلبًا لجلب تذكرة واحدة، من خلال action `get-ticket`. يتم تمرير `ticketId` لتحديد نطاق الاستعلام لإرجاع تذكرة معينة فقط. يتم توفير خيار `enabled` الإضافي للتأكد من أن الاستعلام لا يعمل تلقائيًا، وإنما يعمل فقط عند وجود `ticketId`.

```ts
import { useActionQuery } from "@agent-native/core/client/hooks";

const { data, isLoading } = useActionQuery(
  "get-ticket",
  { ticketId: ticketId ?? "" },
  { enabled: Boolean(ticketId) },
);
```

  }}
/>

يُقصد استخدام هذا الخطاف مع actions التي تغيّر البيانات، مثل الإنشاء أو التحديث أو الإرسال. إنه غلاف رقيق حول دالة [useMutation()](https://tanstack.com/query/latest/docs/framework/react/reference/useMutation).

على عكس `useActionQuery()`، لا يتم تمرير مدخلات action إلى الخطاف نفسه. يتم تمريرها إلى `mutate()` أو `mutateAsync()` عندما تكون جاهزًا لتشغيل الطفرة (mutation).

في المثال أدناه، يتم استدعاء action `send-ticket-reply` لنشر رد على تذكرة. استدعِ `mutate()` من معالج حدث، مثل `onClick` لزر.

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply");

mutate({ ticketId, body: draft });
```

يوضح المثال التالي نفس الطفرة مع خيار `onSuccess`. يحدث إبطال ذاكرة التخزين المؤقت تلقائيًا بعد كل طفرة، لذا لا يُحتاج إلى `onSuccess` إلا للتأثيرات الجانبية المحلية، مثل مسح مؤلف الرد بعد إرسال الرد.

```ts
import { useActionMutation } from "@agent-native/core/client/hooks";

const { mutate, isPending } = useActionMutation("send-ticket-reply", {
  onSuccess: () => setDraft(""),
});

mutate({ ticketId, body: draft });
```

  }}
/>

هذه الدالة مخصصة لاستدعاءات action الفورية لمرة واحدة خارج تدفق عرض React، مثل معالج حدث عادي، أو نص برمجي، أو أي مسار كود آخر غير React. تُرجع وعدًا (promise) مباشرة بدلاً من نتيجة خطاف.

في المثال أدناه، يتم استدعاء action `update-ticket` من معالج اختصار لوحة مفاتيح خارج تدفق عرض React، لتعيين التذكرة لممثل.

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction("update-ticket", {
  ticketId,
  assignedToEmail: "jordan@example.com",
});
```

يوضح المثال التالي نفس الاستدعاء مع خيار `timeoutMs`، وهو مفيد لـ actions التي تستغرق وقتًا أطول بشكل مشروع من المهلة الافتراضية البالغة 60 ثانية.

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction(
  "update-ticket",
  { ticketId, assignedToEmail: "jordan@example.com" },
  { timeoutMs: 120_000 },
);
```

كل طلب من `useActionQuery()` و`useActionMutation()` و`callAction()` محكوم بمهلة 60 ثانية، وتظهر انتهاءات المهلة كأخطاء بدلاً من إعادة المحاولة بصمت. يلغي `useActionQuery()` أيضًا الطلبات المتجاوَزة تلقائيًا، باستخدام إشارة الإلغاء (abort signal) الخاصة بـ React Query.

يُقصد استخدام هذا الخطاف للحفاظ على واجهة المستخدم متزامنة مع تغييرات قاعدة البيانات التي تحدث خارج actions الخاصة بك، مثل كتابة من الوكيل، أو خطاف ويب (webhook)، أو تغيير تم إجراؤه من علامة تبويب متصفح أخرى. يستمع للتغييرات عبر الأحداث المرسلة من الخادم، ويعود إلى الاستقصاء عندما لا تكون الأحداث المرسلة من الخادم متاحة.

```ts
import { useDbSync } from "@agent-native/core/client/hooks";
import { useQueryClient } from "@tanstack/react-query";

function App() {
  const queryClient = useQueryClient();

  useDbSync({
    queryClient,
    pollUrl: "/_agent-native/poll",
    onEvent: (data) => console.log("Data changed:", data),
  });

  return <div>...</div>;
}
```

بالنسبة إلى CRUD العادي، يُفضَّل `useActionQuery()` و`useActionMutation()`. تُصدر actions المُغيّرة `source: "action"`، لذا تُعيد هذه الخطافات الجلب فورًا. تصل التغييرات من الوكيل، أو خطاف ويب، أو علامة تبويب أخرى من خلال `useDbSync()` بدلاً من ذلك، عبر SSE أو الرجوع إلى الاستقصاء. إذا كان استعلام `useQuery()` خام يحتاج إلى المزامنة على مفتاح مخصص، راجع [آليات المزامنة الداخلية](/docs/client-sync-internals). إذا كنت تحتاج إلى الكتابة مباشرة إلى `application_state`، راجع [متقدم](/docs/client-advanced).

## ما هي الخطوة التالية

- [**نظرة عامة**](/docs/client-overview) — تخطيط دليلَي `app/` و`public/` الذي تعيش فيه خطافات هذه الصفحة
- [**محادثة الوكيل**](/docs/client-agent-chat) — إرسال المطالبات وتهيئة السياق للوكيل
- [**Actions**](/docs/actions) — سطح `defineAction` الذي يقف خلف كل خطاف في هذه الصفحة
- [**متقدم**](/docs/client-advanced) — الوصول المباشر إلى `application_state`
- [**آليات المزامنة الداخلية**](/docs/client-sync-internals) — مزامنة `useQuery` خام باستخدام `useChangeVersion`
- [**المزامنة المباشرة**](/docs/key-concepts#polling-sync) — كيف يحافظ `useDbSync` على تحديث واجهة المستخدم
