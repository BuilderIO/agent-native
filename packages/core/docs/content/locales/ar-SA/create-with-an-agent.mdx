# إنشاء تطبيق باستخدام وكيل ذكاء اصطناعي

يمكنك أن تطلب من وكيل ذكاء اصطناعي إنشاء تطبيق Agent-Native الخاص بك. تلصق موجّهًا واحدًا، فينفّذ الوكيل أوامر الإعداد، ثم يعرض لك تطبيقًا قيد التشغيل عند الانتهاء.

إذا كنت تفضّل كتابة الأوامر بنفسك، فاتبع دليل [البدء](/docs/getting-started) بدلًا من ذلك.

## قبل أن تبدأ

- وكيل ذكاء اصطناعي قادر على تشغيل أوامر الطرفية، مثل Claude Code أو Codex أو Cursor. الوكلاء الذين يقتصرون على المحادثة، مثل ChatGPT أو Claude على الويب، يمكنهم المساعدة أيضًا. راجع [الوكلاء الذين لا يستطيعون تشغيل الأوامر](#chat-only-agents).
- [Node.js](https://nodejs.org) 22.22 أو أحدث.
- مجلد فارغ يمكن أن يوضع فيه التطبيق الجديد.

لا تحتاج إلى مفتاح API لإنشاء التطبيق. تحتاج إليه فقط عندما تريد أن يجيبك الوكيل المدمج في التطبيق نفسه. راجع [ربط LLM](/docs/getting-started#connect-an-llm).

## الصق هذا الموجّه

افتح الوكيل داخل المجلد الفارغ والصق الموجّه أدناه. غيّر `my-app` في السطر الأول إلى الاسم الذي تريده. تحتاج إلى تغييره مرة واحدة فقط.

```markdown
أنشئ تطبيق Agent-Native جديدًا في مجلد جديد باسم my-app
وشغّله. استخدم هذا الاسم أينما تقول خطوة أدناه APP_NAME.

1. تحقق من أن إصدار Node.js هو 22.22 أو أحدث وأن pnpm متاح.
   إذا كان pnpm غير موجود، شغّل `corepack enable`. وإذا لم يكن
   corepack متاحًا أيضًا، شغّل `npm install -g pnpm`. وإذا كان
   Node.js قديمًا جدًا، فتوقف وأخبرني بدلًا من تثبيته.
2. شغّل:
   npx --yes @agent-native/core@latest create APP_NAME \
    --standalone --template chat
3. في المجلد الجديد APP_NAME، شغّل `pnpm install`.
4. اقرأ APP_NAME/AGENTS.md لتعرف كيف ينظَّم التطبيق.
5. شغّل التطبيق بالأمر `pnpm dev` واتركه يعمل في الخلفية.
6. اقرأ عنوان URL المحلي الذي يطبعه `pnpm dev`. تحقق من أنه
   يستجيب، على سبيل المثال بالأمر `curl -I <url>`. لا تفتح
   متصفحًا ولا تستخدم أدوات متصفح بلا واجهة. سأفتح التطبيق
   بنفسي.
7. أرني النتيجة. أعطني عنوان URL المحلي والاستجابة التي
   حصلت عليها منه. لا تكتفِ بالقول إن الإعداد اكتمل.

القواعد:

- لا تخترع مفاتيح API ولا تطلب مني لصقها. ربط LLM اختياري
  وسأقوم به بنفسي.
- لا تطبع الأسرار من أي ملف .env.
- إذا فشل أي أمر، فأرني الخطأ وما جرّبته. لا تخفِه.
```

## ما الذي ينبغي أن يفعله الوكيل

تنتهي المحاولة الناجحة بهذه النتائج، ويمكنك التحقق من كل واحدة منها بنفسك:

- مجلد تطبيق جديد، باسم `my-app` ما لم تغيّره، يحتوي على `actions/` و`app/` وملف `AGENTS.md`.
- تشغيل `pnpm dev` من دون أخطاء.
- عنوان URL محلي، وهو عادةً `http://localhost:8080`، تحقق الوكيل من أنه يستجيب.

بعد ذلك افتح عنوان URL المحلي في متصفحك أنت. في شاشة الترحيب، اختر **Continue as local dev**. ستظهر صفحة البدء.

إذا كان أي منها مفقودًا، فاطلب من الوكيل أن يعرض آخر أمر شغّله ومخرجاته.

<Callout tone="info">

إذا فشلت الأوامر بأخطاء في التبعيات النظيرة، فقد يكون السبب نسخة قديمة من حزمة في ذاكرة npx المؤقتة. اطلب من الوكيل تشغيل `npx clear-npx-cache` ثم المحاولة مرة أخرى.

</Callout>

## اختر الإعداد المناسب لوكيلك

| نوع الوكيل               | أمثلة                                                 | طريقة العمل                                       |
| ------------------------ | ----------------------------------------------------- | ------------------------------------------------- |
| وكلاء الطرفية وبيئات IDE | Claude Code وCodex وCursor وGitHub Copilot في VS Code | الصق الموجّه. ينفّذ الوكيل كل الأوامر نيابةً عنك. |
| وكلاء المحادثة فقط       | ChatGPT وClaude على الويب                             | اطلب منه الأوامر ثم شغّلها بنفسك.                 |

### الوكلاء الذين لا يستطيعون تشغيل الأوامر {#chat-only-agents}

لا يستطيع وكيل المحادثة فقط فتح طرفية، لذلك لا يمكنه إنشاء التطبيق. الصق الموجّه مع ذلك وأضف هذا السطر في أعلاه:

```markdown
لا يمكنك تشغيل الأوامر. أعطني كل أمر لأشغّله في الطرفية لدي،
أمرًا واحدًا في كل مرة، وانتظر حتى أخبرك بما حدث قبل أن
تنتقل إلى التالي.
```

سيرشدك الوكيل عبر الخطوات نفسها ويساعدك إذا حدث خطأ.

## وكيلك الخاص ووكيل التطبيق

يمكن لوكيلين أن يعملا على تطبيقك، ولكل منهما مهمة مختلفة.

- **وكيلك الخاص** هو الذي لصقت فيه الموجّه، مثل Claude Code أو Codex أو Cursor. يعمل خارج التطبيق، في الطرفية أو المحرر لديك.
- **وكيل التطبيق** هو المحادثة المدمجة في التطبيق. تفتحها في المتصفح أثناء تشغيل التطبيق.

|                                 | وكيلك الخاص (خارج التطبيق)                                                                                         | وكيل التطبيق (داخل التطبيق)                                                                       |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| أين تستخدمه                     | الطرفية أو المحرر لديك                                                                                             | محادثة التطبيق في المتصفح                                                                         |
| على ماذا يعمل                   | ملفات مشروعك                                                                                                       | بيانات التطبيق والشاشة التي تنظر إليها                                                            |
| ما الذي يستطيع فعله             | إنشاء المشروع وتثبيت الحزم وتشغيل `pnpm dev` وكتابة الإجراءات والصفحات وجداول قاعدة البيانات وتعديلها وتجهيز النشر | استدعاء إجراءات التطبيق كأدوات وقراءة بيانات التطبيق وتحديثها والإجابة عن أسئلة حول ما على الشاشة |
| هل يحتاج إلى LLM مربوط بالتطبيق | لا، فهو يستخدم نموذجه الخاص                                                                                        | نعم. راجع [ربط LLM](/docs/getting-started#connect-an-llm)                                         |
| الأنسب لـ                       | بناء التطبيق وتغييره                                                                                               | استخدام التطبيق وإنجاز عمله اليومي                                                                |

وكيلك الخاص يبني التطبيق، ووكيل التطبيق يشغّله. عندما يضيف وكيلك الخاص إجراءً، يستطيع وكيل التطبيق استدعاءه فورًا لأن كليهما يستخدم الإجراء نفسه.

### ساعد وكيلك الخاص على البناء جيدًا

التطبيق الذي يُنشأ مهيّأ بحيث يعمل وكيلك الخاص فيه جيدًا دون تعليمات إضافية.

- يخبر ملف `AGENTS.md` في جذر التطبيق الوكيل بكيفية تنظيم التطبيق والقواعد التي يجب اتباعها.
- يضم `.agents/skills/` أدلة قصيرة للمهام الشائعة، مثل إضافة ميزة أو كتابة إجراء.
- تأتي مع التطبيق وثائق مطابقة لإصدار إطار العمل لديك تمامًا. يمكن للوكيل البحث فيها بالأمر `pnpm action docs-search --query "<topic>"`.

عندما تطلب شيئًا جديدًا، يمكنك أن تطلب من الوكيل قراءة هذه الملفات أولًا. على سبيل المثال: "اقرأ AGENTS.md والمهارة المناسبة قبل أن تغيّر أي شيء."

لتجعل وكيلك الخاص يستخدم أدوات تطبيق قيد التشغيل بدلًا من شيفرته، راجع [الوكلاء الخارجيون](/docs/external-agents).

## اطلب أول تغيير

بعد تشغيل التطبيق، اطلب من وكيلك إجراء تغيير صغير وراقبه وهو يعمل. إليك بعض الأمثلة:

```markdown
أضف إجراءً باسم list-notes يعيد قائمة فارغة، ثم اعرضه في صفحة
جديدة على المسار /notes.
```

```markdown
غيّر إجراء hello بحيث يحيّي الناس بعبارة "Welcome" بدلًا من
"Hello"، ثم استدعِه لـ Alex للتأكد.
```

```markdown
اقرأ وثائق نشر التطبيق، ثم أخبرني بالخطوات التي أحتاج إلى اتخاذها
لنشر هذا التطبيق على الإنترنت.
```

يعدّل الوكيل الإجراءات نفسها التي تستخدمها واجهة المستخدم والوكيل المدمج في التطبيق. نموذج الإجراءات المشترك هذا هو السبب في ظهور تغيير واحد في كل مكان. يشرح [المفاهيم الأساسية](/docs/key-concepts) كيف يتكامل كل ذلك.
