# Deno Deploy

<Badge label="Beta" color="orange" icon="rocket" />

يشغّل Deno Deploy تطبيقك على شبكة Deno العالمية، لذلك لا يوجد خادم تحتاج إلى
إعداده أو إبقائه قيد التشغيل. يحوّل البناء التطبيق إلى خادم Deno واحد يتولى صفحات
التطبيق وواجهته البرمجية، ويمنح Deno Deploy التطبيق عنوانًا عامًا مع HTTPS.

يشرح هذا الدليل نشر تطبيق مستقل واحد من البداية. ستنشئ التطبيق، وتمنحه قاعدة
بيانات إنتاجية وسر مصادقة، وتجهّز قاعدة البيانات، وتبنيه لـ Deno، ثم ترفع البناء
النهائي باستخدام الأمر `deno deploy`.

<Callout tone="info">

يلزم Node.js `22.22+`.

</Callout>

تحتاج أيضًا إلى حساب Deno Deploy وإلى تثبيت [Deno](https://docs.deno.com/runtime/getting_started/installation/)
على حاسوبك. شغّل الأوامر في هذا الدليل على حاسوبك الخاص. تبني التطبيق باستخدام
Node.js، ويرفع الأمر `deno deploy` البناء النهائي إلى Deno Deploy.

## الخطوة 1: إنشاء التطبيق {#step-1-create-the-app}

أنشئ تطبيقك المستقل الجديد. ينشئ المثال أدناه تطبيقًا من قالب Chat، لكن يمكنك
البدء من أي قالب. انتقل إلى مجلد التطبيق وثبّت تبعياته. يفعّل الأمر
`corepack enable` إصدار `pnpm` الذي يتوقعه التطبيق، لذلك لا تحتاج إلى تثبيت
`pnpm` بنفسك.

```bash
npx --yes @agent-native/core@latest create my-app --standalone --template chat

cd my-app

corepack enable

pnpm install
```

استبدل `my-app` باسم تطبيقك إذا أردت. يفترض باقي هذا الدليل أنك داخل مجلد
التطبيق.

<Callout tone="info">

إذا فشلت هذه الأوامر بأخطاء في التبعيات النظيرة، فقد يكون السبب نسخة قديمة من حزمة في ذاكرة npx المؤقتة. شغّل `npx clear-npx-cache` لمسح الذاكرة المؤقتة، ثم شغّل الأوامر مرة أخرى.

</Callout>

## الخطوة 2: ضبط أسرار البيئة {#step-2-configure-environment-secrets}

يقرأ التطبيق إعدادات الإنتاج من متغيرات البيئة:

| المتغير              | مطلوب | الغرض                                                   |
| -------------------- | ----- | ------------------------------------------------------- |
| `DATABASE_URL`       | نعم   | يربط التطبيق بقاعدة بيانات PostgreSQL الخاصة به         |
| `BETTER_AUTH_SECRET` | نعم   | يوقّع جلسات المستخدمين                                  |
| `BETTER_AUTH_URL`    | لا    | يحدد العنوان العام الذي يستخدمه الناس للوصول إلى تطبيقك |

تجعل أوامر التصدير أدناه الأوامر التالية تعمل في هذه الصدفة. قبل النشر، احفظ
المتغيرات نفسها في إعدادات بيئة المشروع أو الخدمة لدى موفر الاستضافة. توضح الخطوة
5 كيفية حفظها في Deno Deploy.

### عنوان URL لقاعدة البيانات {#database-url}

أثناء التطوير المحلي، يخزّن التطبيق البيانات في قاعدة بيانات محلية عندما يكون
`DATABASE_URL` غير مضبوط. يحتاج التطبيق المنشور إلى قاعدة بيانات PostgreSQL
حقيقية تحتفظ ببياناتها بين عمليات النشر. لا يحتفظ Deno Deploy بالملفات بين
الطلبات، لذلك يجب أن توجد قاعدة البيانات خارج Deno Deploy. انسخ سلسلة الاتصال من
موفر قاعدة البيانات وصدّرها:

```bash
export DATABASE_URL='your-postgres-url-string'
```

توضح [أدلة موفري قواعد البيانات](/docs/neon) مكان العثور على سلسلة الاتصال لدى
كل موفر.

<Callout tone="warning">

اختر موفر PostgreSQL دائمًا: Neon أو Supabase أو Amazon RDS أو غيرها.

</Callout>

### سر المصادقة {#auth-secret}

أنشئ هذه القيمة مرة واحدة وأبقها ثابتة عبر عمليات النشر.

يستخدم التطبيق `BETTER_AUTH_SECRET` لتوقيع جلسات المستخدمين. إذا تغيّرت القيمة،
يُسجَّل خروج كل مستخدم مسجّل الدخول. ينشئ الأمر أدناه قيمة عشوائية:

```bash
export BETTER_AUTH_SECRET="$(openssl rand -hex 32)"
```

احفظ القيمة المُنشأة في مكان آمن، مثل مدير كلمات المرور. استخدم القيمة نفسها في
كل مرة تنشر فيها.

### عنوان URL العام {#public-url}

اختياري. اضبطه عند استخدام نطاق مخصص، أو وكيل عكسي، أو تدفق مصادقة أو OAuth يحتاج
إلى أصل عام ثابت.

`BETTER_AUTH_URL` هو العنوان العام الذي يستخدمه الناس للوصول إلى تطبيقك. بدونه،
يستنتج التطبيق عنوانه من كل طلب وارد. يكون ذلك مناسبًا عادةً على العنوان الذي
يمنحك إياه Deno Deploy، لكن اضبطه عندما تربط نطاقًا مخصصًا حتى تستخدم روابط تسجيل
الدخول وعمليات إعادة توجيه OAuth ذلك النطاق.

```bash
export BETTER_AUTH_URL='https://your-domain.example'
```

## الخطوة 3: الترحيل {#step-3-migrate}

تنشئ عمليات الترحيل الجداول التي يحتاجها التطبيق في قاعدة البيانات وتحدّثها.
شغّل هذا الأمر قبل أول عملية نشر:

```bash
pnpm migrate:production
```

يعمل الأمر على حاسوبك ويتصل بقاعدة بيانات الإنتاج باستخدام `DATABASE_URL` الذي
صدّرته في الخطوة 2. شغّله مرة أخرى بعد ترقية التطبيق، وقبل نشر الإصدار الجديد.

## الخطوة 4: البناء {#step-4-build}

ابنِ التطبيق لـ Deno Deploy:

```bash
NITRO_PRESET=deno_deploy pnpm build
```

يبني `NITRO_PRESET=deno_deploy` التطبيق بصفته خادم Deno يستخدم `Deno.serve()`،
وهو ما يتطلبه Deno Deploy. يكتب البناء الخادم في `.output/server/index.ts`
والملفات الثابتة في `.output/public`. ويضمّ تبعيات التطبيق داخل الخادم، لذلك يعمل
المجلد `.output` بمفرده دون تثبيت أي شيء.

## الخطوة 5: إنشاء التطبيق على Deno Deploy وحفظ الأسرار {#step-5-create-the-app-on-deno-deploy-and-save-the-secrets}

انتقل إلى مخرجات البناء، ثم أنشئ التطبيق على Deno Deploy من ذلك المجلد:

```bash
cd .output

deno deploy create --source local --runtime-mode dynamic --entrypoint server/index.ts
```

يفتح الأمر إعدادًا تفاعليًا يسجّل دخولك، ويسألك عن المؤسسة التي تريد استخدامها،
ويطلب اسم التطبيق. يرفع `--source local` المجلد الحالي بدلًا من البناء من GitHub.
ويخبر `--runtime-mode dynamic` و`--entrypoint server/index.ts` منصة Deno Deploy
بتشغيل الخادم من الخطوة 4. لا توجد خطوة بناء تحتاج إلى ضبطها، لأنك بنيت التطبيق
مسبقًا.

احفظ المتغيرين المطلوبين بصفتهما أسرارًا على التطبيق:

```bash
deno deploy env add DATABASE_URL "$DATABASE_URL" --secret

deno deploy env add BETTER_AUTH_SECRET "$BETTER_AUTH_SECRET" --secret
```

يقرأ كل أمر القيمة التي صدّرتها في الخطوة 2 ويحفظها في Deno Deploy، لذلك لا تحتاج
إلى لصق الأسرار يدويًا. يحدّد `--secret` كل قيمة بصفتها سرًا. إذا ضبطت
`BETTER_AUTH_URL`، فاحفظه بالطريقة نفسها. يمكنك أيضًا عرض هذه القيم وتغييرها لاحقًا
في إعدادات التطبيق على لوحة تحكم Deno Deploy.

## الخطوة 6: النشر {#step-6-deploy}

<Steps>

### النشر إلى الإنتاج

من المجلد `.output`، انشر البناء إلى عنوان الإنتاج الخاص بك:

```bash
deno deploy --prod
```

يضمن النشر مرة أخرى بعد حفظ الأسرار أن التطبيق قيد التشغيل يحصل عليها.

### فتح التطبيق

عندما ينتهي الأمر، يطبع عنوان التطبيق، الذي يبدو مثل
`my-app.your-org.deno.net`. افتحه وأنشئ الحساب الأول.

</Steps>

## نشر التحديثات {#deploy-updates}

لإصدار نسخة جديدة، شغّل عمليات الترحيل، وابنِ التطبيق مرة أخرى، ثم انشر من المجلد
`.output`:

```bash
pnpm migrate:production

NITRO_PRESET=deno_deploy pnpm build

cd .output

deno deploy --prod --org your-org --app my-app
```

يستبدل كل بناء المجلد `.output`، لذلك مرّر اسمي المؤسسة والتطبيق باستخدام `--org`
و`--app`. تبقى الأسرار المحفوظة على التطبيق، لذلك لا تحتاج إلى تكرار الخطوة 5.
