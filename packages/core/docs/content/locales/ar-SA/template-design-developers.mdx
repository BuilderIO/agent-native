# دليل المطور

هذه الصفحة لأي شخص يخصص قالب Design أو يبني فوقه مباشرة: البدء السريع، وكل
إجراء، ونموذج البيانات، واستعراض إجراء واحد بالتفصيل، وسطح المسارات، وكيفية
الإضافة إليه. راجع [Design](/docs/template-design) لمعرفة ما يفعله التطبيق.

## البدء السريع

<Steps>

### أنشئ التطبيق

```bash
npx @agent-native/core@latest create my-design --standalone --template design
cd my-design
pnpm install
```

يتطلب هذا تثبيت [Node.js](https://nodejs.org) الإصدار 22.22 أو أحدث
و[pnpm](https://pnpm.io) أولًا. راجع [بدء الاستخدام](/docs/getting-started)
إذا لم تكن قد ثبّت أيًا منهما بعد، أو لم يكن لديك اتصال بنموذج لغوي
(Builder.io، أو مفتاح Anthropic/OpenAI، أو Ollama محلي) مُعد. لمساحة عمل تضم
Design إلى جانب تطبيقات أخرى، شغّل `npx @agent-native/core@latest create
my-platform` واختر Design أثناء الإعداد بدلاً من ذلك.

### شغّل خادم التطوير

```bash
pnpm dev
```

يُفتح التطبيق على `http://localhost:8099`، منفذ التطوير الافتراضي لـ Design.
يعمل Design بشكل كامل دون أي اتصالات خارجية. لن تواجه طلب اتصال إلا إذا
جرّبت استيراد Figma أو بناء التطبيق الكامل قبل إعداد ذلك.

</Steps>

## قائمة الإجراءات

كل عملية خاصة بـ Design هي ملف TypeScript في `templates/design/actions/`،
مثبّت تلقائيًا على `POST /_agent-native/actions/:name` وقابل للتشغيل من CLI
كـ `pnpm action <name>`.

## نموذج البيانات

تعيش جميع البيانات في SQL عبر Drizzle ORM. المخطط:
`templates/design/server/db/schema.ts`. تحمل التصميمات وأنظمة التصميم معيار
`ownableColumns` وجدول مشاركات إطار عمل مطابق، بحيث تنسجم مع نموذج المشاركة
لكل مستخدم / لكل مؤسسة.

يغطي الجدول أدناه الموارد الأساسية القابلة للملكية: التصميمات، والملفات،
والقوالب، والإصدارات، وأنظمة التصميم.

| الجدول                                   | ما يحمله                                                                                                                                     |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `designs`                                | مشروع تصميم — `title`، و`description`، و`project_type` (`prototype` / `other`)، وكتلة `data` من نوع JSON، ورابط `design_system_id` الاختياري |
| `design_files`                           | ملفات فردية تنتمي إلى تصميم (`filename`، و`content`، و`file_type` بقيمة افتراضية `html`)                                                     |
| `design_templates`                       | بيانات وصفية لقالب قابل لإعادة الاستخدام، وأبعاد، وقيم افتراضية، ومرجع تصميم المصدر، وعدد الطبقات المقفلة                                    |
| `design_template_files`                  | ملفات قالب مأخوذة كلقطة، تُنسخ إلى تصميم عادي قابل للتحرير عندما يبدأ المستخدم من قالب                                                       |
| `design_template_shares`                 | جدول مشاركات إطار العمل لاكتشاف القوالب الخاصة، والخاصة بالمؤسسة، والمشتركة صراحة، والعامة                                                   |
| `design_versions`                        | لقطات `snapshot` في نقطة زمنية معينة لتصميم مع `label` اختياري، للتاريخ والتراجع                                                             |
| `design_systems`                         | رموز علامة تجارية قابلة لإعادة الاستخدام — `data` (الألوان/الطباعة/التباعد)، و`assets`، و`custom_instructions`، وعلامة `is_default`          |
| `design_shares` / `design_system_shares` | جداول مشاركات إطار العمل التي تربط المبادئ الأساسية (المستخدمين أو المؤسسات) بالأدوار (عارض، محرر، مشرف)                                     |

يظل مشروع التصميم غلافًا فارغًا حتى يحتوي على محتوى: يُنشئ `create-design`
صفًا فارغًا (`data: "{}"`)، ثم يكتب `generate-design` ملفات HTML/JSX
المستقلة الفعلية. يأتي العنصر المُنشأ، والمصدر القابل للتحرير، وكل عملية
تصدير، كلها من نفس HTML، لذا لا يوجد تنسيق "نموذج أولي بالذكاء الاصطناعي"
منفصل لترجمته. يوفر نظام تصميم مرتبط الرموز و`custom_instructions` التي
يلتزم بها الوكيل في كل عملية إنشاء.

تدعم سبعة جداول أخرى ميزات مغطاة في مواضع أخرى من هذه الصفحة بدلاً من نموذج
الموارد الأساسي: يدعم `design_localhost_connections`
و`design_localhost_write_grants` [استيراد التطبيق
المحلي](/docs/template-design-features#import)، ويدعم `component_index`
[قسم المكوّن في تبويب Design](/docs/template-design-features#design-tab)،
ويدعم `motion_timeline` الجدول الزمني القابل للتحرير لحركة كل عنصر (لوحة
Motion في المحرر)، ويحمل `design_state` حالات بديلة مسماة، وبيانات ثابتة،
والتقاطات من تطبيق مباشر لتصميم، ويدعم `design_fusion_edits` قائمة انتظار
تعديلات fusion الموضحة تحت [بناء التطبيق الكامل](#full-app-building) أعلاه،
ويخزّن `design_review_snapshot` مؤقتًا نتائج إمكانية الوصول والفرق البصري
وراء `get-design-review`، الموضح تحت [الجودة](#quality) أعلاه.

تعليقات وسلاسل المراجعة المخزَّنة (`get-review-feedback`،
و`resolve-review-thread`، وبقيتها) ليست جدولاً خاصًا بـ Design على الإطلاق:
إنها نظام المراجعة المشترك لإطار العمل من `@agent-native/core/review`
(`agent_review_comments` / `agent_review_statuses`)، محدد النطاق لتصميم
بالطريقة نفسها التي يمكن بها لأي تطبيق إرفاقه. راجع [تبويب
التعليقات](/docs/template-design-features#comments-tab) للاطلاع على السلوك
الذي يظهر للمستخدم.

## نموذج المحرر

يعتمد Design على النظرة العامة أولاً للعمل على شاشات متعددة. بعد الإنشاء
أو التحديثات الواسعة، يفتح المحرر النظرة العامة للشاشات: لوحة لا نهائية
تكون فيها كل شاشة إطارًا ثابتًا يمكن تحديده أو نقله أو تغيير حجمه أو إسقاطه
أو تكراره. استخدم زر العرض الكامل لإطار عندما تحتاج شاشة واحدة إلى تمرير
مركّز أو تفاعل نموذج أولي.

وضع الشاشة الواحدة مخصص للتمرير، والتفاعل مع سلوك النموذج الأولي، وتحرير
طبقات DOM/الكود داخل ملف واحد معروض. تعكس لوحة الطبقات هذا التقسيم: الشاشات
إطارات من المستوى الأعلى، وتحت الشاشة النشطة تظهر طبقات DOM/الكود المتداخلة.

كل شاشة هي مستند واحد يُعرض بعروض مختلفة، لا نسخ منفصلة لكل نقطة توقف: يتدفق
إطار أساسي (الأعرض) إلى الأسفل، وتُحفظ التعديلات التي تُجرى عند نقطة توقف
نشطة أضيق كتجاوزات محدَّدة النطاق حسب العرض فوقه.

## امتدادات المحرر

يتضمن المحرر تبويب مفتش **الامتدادات** بعد **Tweaks**. يعمل كمسار امتدادات
خاص بـ Design: يمكن للمستخدمين النقر على **+ امتداد** ليطلبوا من الوكيل بناء
امتداد، أو تثبيت امتداد يعلن فتحة `design.editor.inspector`، باستخدام
إجراءات إطار العمل `create-extension`، و`add-extension-slot-target`،
و`install-extension`، لا إجراء خاص بـ Design.

تُعرض امتدادات Design مضمَّنة بجانب لوحة العمل عبر صندوق الرمل القياسي
للامتدادات. يمرر المضيف تحديثات `window.slotContext`
و`window.onSlotContext(...)` مع `designId` الحالي، والملف النشط، وقائمة
الشاشات، ومعرّفات الشاشات المحددة، وبيانات العنصر المحدد الوصفية، ووضع
العرض، والتكبير، والأداة النشطة، وقيم التعديلات. يتيح ذلك للامتداد عرض
معلومات عن التحديد الحالي، أو تقديم عناصر تحكم في النمط، أو بناء تدفقات عمل
مدمجة حول التصميم المفتوح.

للعمل الحتمي، يمكن للامتدادات استدعاء إجراءات التطبيق عبر جسر الامتدادات.
أما للتغييرات المدفوعة بالذكاء الاصطناعي، فاجعل الامتداد يستدعي
`agentNative.chat.send(...)` مع محدد/معرّف مصدر العنصر المحدد والتغيير
المطلوب. يجب أن يستدعي الوكيل `view-screen` أولاً، ثم يستخدم
`apply-visual-edit` لتغييرات نمط العنصر أو الصنف أو النص أو الحركة، أو
يستخدم `update-design` / `generate-design` مع `canvasFrames` لتغييرات موضع
لوحة العمل. راجع [الامتدادات](/docs/extensions#capabilities) لمعرفة صندوق
الرمل، والحالة المستمرة، وواجهات برمجة الجسر.

## تخصيصه

Design قالب كامل وقابل للاستنساخ. بعض أفكار التوسيع العملية:

- "أضف نظام تصميم للتجارة الإلكترونية قابل لإعادة الاستخدام باستخدام رموزنا
  ومكونات نموذجية."
- "أضف خطوة تصدير ترفع ملف ZIP إلى نظام المراجعة الداخلي لدينا."
- "دعني ألصق HTML حالي لصفحة هبوط واطلب من الوكيل ثلاث نسخ أقوى."
- "أضف مكتبة مطالبات محفوظة لملخصات صفحة المنتج، ولوحة التحكم، وشاشة
  التهيئة."
- "أضف إعدادًا مسبقًا مخصصًا لتصدير PDF لمراجعة أصحاب المصلحة."

يحرّر الوكيل المسارات، والمكونات، والإجراءات، والنماذج المدعومة بـ SQL حسب
الحاجة. راجع [القوالب](/docs/cloneable-saas) لمعرفة تدفق الاستنساخ والتخصيص
والنشر الكامل، و[بدء الاستخدام](/docs/getting-started) إذا كان هذا أول قالب
أصلي للوكيل بالنسبة لك.
