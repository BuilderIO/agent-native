# Vercel

```ts filename="vite.config.ts"
export default defineConfig({
  plugins: [agentNative({ nitro: { preset: "vercel" } })],
});
```

انشر عبر Vercel CLI أو عبر git push:

```bash
npx vercel deploy
```

لإنشاء معاينة مؤقتة بدون تسجيل الدخول إلى Vercel، شغّل
`npx vercel deploy --temporary`. لا تحتفظ عمليات النشر المؤقتة بمتغيرات بيئة
المشروع، لذا مرّر قيم قاعدة البيانات والأسرار عبر خياري `--env` و`--build-env`
عندما تحتاج إلى أكثر من معاينة للواجهة.

بالنسبة لمساحة عمل، قم ببناء كل تطبيق في حزمة واحدة من Vercel Build Output API:

```bash
npx @agent-native/core@latest deploy --preset vercel
```

بالنسبة لعمليات نشر Vercel Git، اضبط أمر البناء على:

```bash
npx @agent-native/core@latest deploy --preset vercel --build-only
```

ينسخ بناء مساحة العمل مخرجات `vercel` الخاصة بـ Nitro لكل تطبيق إلى `.vercel/output` الجذر، ويمنح كل دالة بيئة مسار تثبيت خاصة بها، ويكتب تكوين المسارات الذي يخدم التطبيقات على `/<app-id>`.

## العمل المجدول {#vercel-scheduled-work}

تتم الأتمتة المجدولة، والأتمتة المُشغَّلة بالأحداث المنتظرة في قائمة الانتظار،
وتنظيف عمليات التشغيل المنقطعة، جميعها عبر عملية مسح تعمل مرة كل دقيقة. يضيف
البناء [مهمة cron في Vercel](https://vercel.com/docs/cron-jobs) تستدعي عملية
المسح على `/_agent-native/jobs/_process-sweep`. ويضيف بناء مساحة العمل مهمة
cron واحدة لكل تطبيق، على `/<app-id>/_agent-native/jobs/_process-sweep`.

اضبط `CRON_SECRET` في متغيرات بيئة المشروع قبل النشر. يرسله Vercel كرمز
bearer مع كل طلب cron، وترفض عملية المسح كل طلب لا يتضمنه. أنشئ قيمة باستخدام
`openssl rand -hex 32`.

- **الإنتاج فقط.** يشغّل Vercel مهام cron على نشر الإنتاج، وليس على المعاينات
  أبدًا، لذا لا تنطلق الجداول في المعاينة. وتذكر صفحة **Automations** ذلك.
- **Hobby يعمل مرة واحدة يوميًا.** يرفض Vercel نشر Hobby الذي تعمل فيه مهمة
  cron أكثر من مرة يوميًا. اضبط `AGENT_NATIVE_VERCEL_CRON_SCHEDULE` في بيئة
  البناء على تعبير يومي مثل `0 9 * * *`. وقد يشغّلها Hobby أيضًا في أي وقت خلال
  تلك الساعة. ومع عملية مسح واحدة يوميًا، تنتظر الأتمتة المجدولة والمُشغَّلة
  بالأحداث ما يصل إلى يوم كامل، لذا استخدم Pro أو مضيفًا آخر عندما يكون التوقيت
  مهمًا.
- **مدة الدالة.** تشغّل عملية المسح المهام المستحقة داخل استدعاء دالة مهمة
  cron، لذا تنقطع المهمة عند بلوغ الحد الأقصى لمدة الدالة (300 ثانية
  افتراضيًا).
- **لا إعادة محاولة.** لا يعيد Vercel محاولة استدعاء cron الفاشل. تعمل عملية
  المسح مجددًا في الموعد المجدول التالي.

راجع [كيفية تشغيل المجدول](/docs/recurring-jobs#how-scheduler-runs) لمعرفة
المضيفات الأخرى.
