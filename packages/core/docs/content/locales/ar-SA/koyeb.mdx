# Koyeb

<Badge label="Beta" color="orange" icon="rocket" />

يستضيف Koyeb تطبيقك كخدمة ويب، لذلك لا يوجد خادم تحتاج إلى إعداده أو إبقائه
قيد التشغيل. يشغّل Koyeb خادم Node.js نفسه الموضح في
[دليل Node.js](/docs/node-js)، ويبنيه من مستودع GitHub الخاص بك، ويمنح التطبيق
عنوانًا عامًا مع HTTPS.

يشرح هذا الدليل نشر تطبيق مستقل واحد من البداية. ستنشئ التطبيق وترفعه إلى
GitHub، وتمنحه قاعدة بيانات إنتاجية وسر مصادقة، وتجهّز قاعدة البيانات، ثم تنشئ
خدمة ويب على Koyeb تبنيه وتشغّله.

<Callout tone="info">

يلزم Node.js `22.22+`.

</Callout>

تحتاج أيضًا إلى حساب Koyeb ومستودع على GitHub. شغّل الأوامر في هذا الدليل على
حاسوبك الخاص. يبني Koyeb التطبيق ويشغّله من مستودعك.

## الخطوة 1: إنشاء التطبيق {#step-1-create-the-app}

أنشئ تطبيقك المستقل الجديد. ينشئ المثال أدناه تطبيقًا من قالب Chat، لكن يمكنك
البدء من أي قالب. انتقل إلى مجلد التطبيق وثبّت تبعياته. يفعّل الأمر
`corepack enable` إصدار `pnpm` الذي يتوقعه التطبيق، لذلك لا تحتاج إلى تثبيت
`pnpm` بنفسك.

```bash
npx --yes @agent-native/core@latest create my-app --standalone --template chat

cd my-app

corepack enable

pnpm install
```

استبدل `my-app` باسم تطبيقك إذا أردت. يفترض باقي هذا الدليل أنك داخل مجلد
التطبيق.

يبني Koyeb التطبيق من GitHub، لذلك ارفع مجلد التطبيق إلى مستودع GitHub جديد قبل
أن تتابع. أضف الملف `pnpm-lock.yaml` إلى الإيداع أيضًا. يستخدمه Koyeb، مع الحقل
`packageManager` في `package.json`، لتثبيت التطبيق باستخدام `pnpm`. ويقرأ أيضًا
إصدار Node.js من الحقل `engines` في `package.json`. يضبط التطبيق الجديد كلا
الحقلين مسبقًا.

<Callout tone="info">

إذا فشلت هذه الأوامر بأخطاء في التبعيات النظيرة، فقد يكون السبب نسخة قديمة من حزمة في ذاكرة npx المؤقتة. شغّل `npx clear-npx-cache` لمسح الذاكرة المؤقتة، ثم شغّل الأوامر مرة أخرى.

</Callout>

## الخطوة 2: ضبط أسرار البيئة {#step-2-configure-environment-secrets}

يقرأ التطبيق إعدادات الإنتاج من متغيرات البيئة:

| المتغير              | مطلوب | الغرض                                                   |
| -------------------- | ----- | ------------------------------------------------------- |
| `DATABASE_URL`       | نعم   | يربط التطبيق بقاعدة بيانات PostgreSQL الخاصة به         |
| `BETTER_AUTH_SECRET` | نعم   | يوقّع جلسات المستخدمين                                  |
| `BETTER_AUTH_URL`    | لا    | يحدد العنوان العام الذي يستخدمه الناس للوصول إلى تطبيقك |

تجعل أوامر التصدير أدناه الأوامر التالية تعمل في هذه الصدفة. قبل النشر، احفظ
المتغيرات نفسها في إعدادات بيئة المشروع أو الخدمة لدى موفر الاستضافة. توضح الخطوة
4 كيفية حفظها في Koyeb.

### عنوان URL لقاعدة البيانات {#database-url}

أثناء التطوير المحلي، يخزّن التطبيق البيانات في قاعدة بيانات محلية عندما يكون
`DATABASE_URL` غير مضبوط. يحتاج التطبيق المنشور إلى قاعدة بيانات PostgreSQL
حقيقية تحتفظ ببياناتها بين عمليات النشر. يستبدل Koyeb ملفات الخدمة في كل عملية
نشر وإعادة تشغيل، لذلك يجب أن توجد قاعدة البيانات خارج خدمة الويب. انسخ سلسلة
الاتصال من موفر قاعدة البيانات وصدّرها:

```bash
export DATABASE_URL='your-postgres-url-string'
```

توضح [أدلة موفري قواعد البيانات](/docs/neon) مكان العثور على سلسلة الاتصال لدى
كل موفر.

<Callout tone="warning">

اختر موفر PostgreSQL دائمًا: Neon أو Supabase أو Amazon RDS أو غيرها.

</Callout>

### سر المصادقة {#auth-secret}

أنشئ هذه القيمة مرة واحدة وأبقها ثابتة عبر عمليات النشر.

يستخدم التطبيق `BETTER_AUTH_SECRET` لتوقيع جلسات المستخدمين. إذا تغيّرت القيمة،
يُسجَّل خروج كل مستخدم مسجّل الدخول. ينشئ الأمر أدناه قيمة عشوائية:

```bash
export BETTER_AUTH_SECRET="$(openssl rand -hex 32)"
```

احفظ القيمة المُنشأة في مكان آمن، مثل مدير كلمات المرور. استخدم القيمة نفسها في
كل مرة تنشر فيها.

### عنوان URL العام {#public-url}

اختياري. اضبطه عند استخدام نطاق مخصص، أو وكيل عكسي، أو تدفق مصادقة أو OAuth يحتاج
إلى أصل عام ثابت.

`BETTER_AUTH_URL` هو العنوان العام الذي يستخدمه الناس للوصول إلى تطبيقك. بدونه،
يستنتج التطبيق عنوانه من كل طلب وارد. يكون ذلك مناسبًا عادةً على العنوان الذي
يمنحك إياه Koyeb، لكن اضبطه عندما تربط نطاقًا مخصصًا حتى تستخدم روابط تسجيل
الدخول وعمليات إعادة توجيه OAuth ذلك النطاق.

```bash
export BETTER_AUTH_URL='https://your-domain.example'
```

## الخطوة 3: الترحيل {#step-3-migrate}

تنشئ عمليات الترحيل الجداول التي يحتاجها التطبيق في قاعدة البيانات وتحدّثها.
شغّل هذا الأمر قبل أول عملية نشر:

```bash
pnpm migrate:production
```

يعمل الأمر على حاسوبك ويتصل بقاعدة بيانات الإنتاج باستخدام `DATABASE_URL` الذي
صدّرته في الخطوة 2. شغّله مرة أخرى بعد ترقية التطبيق، وقبل نشر الإصدار الجديد.

## الخطوة 4: إنشاء خدمة الويب {#step-4-create-the-web-service}

في لوحة تحكم Koyeb، أنشئ **Web Service** جديدة، واختر **GitHub** كطريقة للنشر،
وحدد المستودع والفرع من الخطوة 1. أبقِ أداة البناء **Buildpack**، ثم استبدل أمري
البناء والتشغيل بهذه القيم:

| الإعداد       | القيمة                          |
| ------------- | ------------------------------- |
| Build command | `NITRO_PRESET=koyeb pnpm build` |
| Run command   | `node .output/server/index.mjs` |

يبني `NITRO_PRESET=koyeb` خادم Node.js نفسه الموجود في دليل Node.js، مُعدًّا
لتقديم ملفاته الثابتة بنفسه. يشغّل أمر التشغيل ذلك الخادم. يفتح Koyeb المنفذ
`8000` افتراضيًا ويضبط متغير البيئة `PORT` ليطابقه، ويقرأ الخادم `PORT`
تلقائيًا، لذلك لا تحتاج إلى تغيير إعدادات المنفذ.

ضمن **Environment variables**، أضف `DATABASE_URL` و`BETTER_AUTH_SECRET`. لقيم
مثل هذه، يوصي Koyeb بتخزين كل منها كـ **Secret** والإشارة إليه من المتغير. على
سبيل المثال، احفظ سلسلة الاتصال كـ Secret باسم `DATABASE_URL`، ثم اضبط قيمة
المتغير على `{{ secret.DATABASE_URL }}`. إذا ضبطت `BETTER_AUTH_URL`، فأضفه
بالطريقة نفسها.

## الخطوة 5: النشر {#step-5-deploy}

<Steps>

### اختيار نوع المثيل

اختر نوع المثيل لخدمة الويب. يكفي نوع المثيل Free لتجربة التطبيق. اختر نوع مثيل
مدفوعًا إذا كان التطبيق يحتاج إلى الاستجابة فورًا.

### إنشاء خدمة الويب

سمِّ الخدمة والتطبيق، ثم انشر. يبني Koyeb التطبيق من مستودعك ويشغّله. يستغرق
البناء الأول بضع دقائق، ويمكنك متابعته في سجلات البناء والتشغيل الخاصة بالخدمة.

### فتح التطبيق

عندما تنتهي عملية النشر، تعرض لوحة التحكم عنوان التطبيق، الذي ينتهي بـ
`koyeb.app`. افتحه وأنشئ الحساب الأول.

</Steps>

على نوع المثيل Free، يقلّص Koyeb الخدمة إلى الصفر بعد ساعة بدون حركة مرور. ثم
تنتظر الزيارة التالية بينما تبدأ الخدمة من جديد. يمكن لكل مؤسسة تشغيل مثيل Free
واحد.

## نشر التحديثات {#deploy-updates}

ينشر Koyeb من جديد في كل مرة ترفع فيها إلى الفرع الذي اخترته في الخطوة 4.
لإصدار نسخة جديدة، شغّل عمليات الترحيل أولًا، ثم ارفع التغييرات:

```bash
pnpm migrate:production

git push
```

تبقى إعدادات الخدمة والمتغيرات المحفوظة كما هي، لذلك لا تحتاج إلى تكرار الخطوة 4.
