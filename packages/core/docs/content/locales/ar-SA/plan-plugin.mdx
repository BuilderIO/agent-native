# مكوّن Plan الإضافي والسوق

يُشحَن تطبيق Agent-Native **Plan** كحزمة واحدة قابلة للتثبيت. يضيف تثبيت واحد
مهارات أوامر الشرطة المائلة الخاصة بـ Plan **و** يوصّل موصل Plan MCP المستضاف
(خادم أدوات عن بُعد يتواصل معه وكيلك)، حتى يتمكن الوكيل من إنشاء الخطط ونشرها
مباشرة في تطبيق Plan في خطوة واحدة. هذه الصفحة موجَّهة لأي شخص يختار مسار
تثبيت، أو يستكشف مشكلة في التثبيت، أو يقرر ما إذا كان سيقدّم Plan إلى كتالوج
مكوّنات إضافية منسَّق — راجع [Plans المرئية](/docs/template-plan) للاطلاع على
ما تفعله المهارات فعليًا.

## ما الذي تحصل عليه {#what-you-get}

يمنحك تثبيت واحد ما يلي:

- **ثلاث مهارات** — `/visual-plan` (نقطة الدخول الأساسية)، و`/visual-recap`، و`/visualize-repo`.
- **موصل Plan MCP** — مسجَّل في التطبيق المستضاف على `https://plan.agent-native.com` (نقطة نهاية MCP هي `https://plan.agent-native.com/mcp`، واسم الخادم `plan`).

افتراضيًا، ينشر `/visual-plan` و`/visual-recap` إلى تطبيق Plan المستضاف —
فهما ينشئان خطة عبر موصل MCP ويسلّمانك رابطًا أو خطة مضمّنة للمراجعة. لا
يُلقيان أبدًا خطة Markdown/ASCII مضمّنة في الدردشة كتسليم نهائي. إذا أرجعت
أداة من أدوات Plan `needs auth` أو `Unauthorized` أو `Session terminated`،
أعِد مصادقة الموصل بدلاً من الرجوع إلى مخرجات مضمّنة. رموز الوصول طويلة الأمد
(افتراضيًا 30 يومًا، مع تحديث متدرج لمدة 365 يومًا)، لذا يجب أن يكون هذا
نادرًا؛ وعند حدوثه، فالإصلاح البسيط هو:

```bash
npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex
```

يبحث `reconnect` عن الموصل ويحدّثه حسب الـ URL للعميل المحلي المحدد — دون
الحاجة إلى إعادة التثبيت. ابدأ محادثة Codex جديدة بعد إعادة الاتصال حتى يُعاد
تحميل سجل الأدوات. في Claude Code، المكافئ هو `/mcp` ← **Authenticate /
Reconnect**، أو الأمر نفسه مع `--client claude-code`.

الاستثناء هو **وضع خصوصية الملفات المحلية** الصريح. عندما تطلب عدم الكتابة في
قاعدة البيانات أو تضبط `AGENT_NATIVE_PLANS_MODE=local-files`، يجب ألا تستدعي
المهارات موصل Plan MCP. فهي تكتب `plans/<slug>/plan.mdx` بالإضافة إلى
`canvas.mdx` و`prototype.mdx` و`.plan-state.json` الاختيارية، ثم تعاين محليًا
باستخدام:

```bash
npx @agent-native/core@latest plan local serve --dir plans/<slug> --kind plan --open
```

يبدأ هذا جسر localhost صغيرًا ويفتح واجهة Plan مقابل المجلد المحلي. (يشغّل
`plan local preview` بدلاً من ذلك مسار خادم تطوير محلي لـ Plan، بينما
`plan local preview --out preview.html` مخرج طوارئ قديم يكتب ملف HTML ثابتًا
مستقلاً. يُقبَل `plan serve` كاسم مستعار قصير لـ `plan local serve`.)

بعض الأمور الدقيقة في وضع الملفات المحلية تستحق المعرفة:

- **استخدم متصفحًا قائمًا على Chromium.** يحظر Safari صفحة Plan المستضافة عبر
  HTTPS من قراءة جسر localhost على `http://127.0.0.1` (محتوى مختلط/شبكة
  خاصة)، لذا تبقى الصفحة معلّقة عند "Loading plan." على نظام macOS، يُفضّل
  `--open` بالفعل Chrome/Chromium/Edge/Brave؛ وإذا فُتح Safari رغم ذلك، أعد
  فتح الـ URL المطبوع في متصفح قائم على Chromium.
- **يُكتَب الـ URL المُقدَّم إلى `plans/<slug>/.plan-url`** (يمكن تجاوز ذلك
  بـ `--url-file`). يمكن لوكيل يعمل في الخلفية أو بدون واجهة قراءة هذا الملف
  بدلاً من مراقبة مخرجات `serve` طويلة الأمد. عامله كملف رمز محلي ولا تُدرجه
  في الالتزامات (commit).
- **تحقّق دون واجهة** عند عدم توفر متصفح:
  يبدأ `npx @agent-native/core@latest plan local verify --dir plans/<slug>`
  الجسر، ويتحقق من الفحص المبدئي للشبكة الخاصة وحمولة JSON، ويطبع
  التشخيصات، ويخرج برمز غير صفري عند الفشل — دون الحاجة إلى عين بشرية.
- **شغّل `plan local check` أولاً.** فهو يتحقق من صحة MDX مقابل مخطط الكتل
  الخاص بمُصيِّر Plan (بما في ذلك الحقول المطلوبة مثل `id`/`label` لعنصر
  `checklist` و`id`/`title`/`mode` لسؤال `question-form`)، بحيث تظهر أخطاء
  التأليف قبل التسليم إلى المتصفح بدلاً من ظهورها كأداة تحميل عالقة.

بالنسبة للمجلدات الموجودة في الريبو الحالي، يتضمن المسار المحلي المباشر
`?path=...` حتى يتمكّن تطبيق Plan المحلي من إبقاء تعديلات المتصفح محفوظة في
مجلد الريبو. يستخدم تطبيق Plan القيمة `apps.plan.roots[0].path` في
`agent-native.json` كمكان افتراضي لحفظ الخطط المحلية التي تُرفَع، مع الرجوع
إلى `plans/`.

يُبقي هذا محتوى الخطة خارج قاعدة بيانات Agent-Native Plan. تظل المشاركة
المستضافة، والتعليقات، ولقطات الشاشة، وسجل الخطة غير متاحة حتى تنشرها صراحةً
لاحقًا.

بيانات Plan المستضافة كمصدر للحقيقة؛ استخدم وضع خصوصية الملفات المحلية عندما
يكون الهدف عدم الكتابة في قاعدة بيانات Plan إطلاقًا.

> "Agent-Native Plan".

## مسارات التثبيت {#install}

هناك ثلاث طرق للدخول. **مسار الـ CLI العام** هو الذي نوصي به افتراضيًا، لأنه
يثبّت المهارات **و** يتيح لك اختيار الوضع المستضاف أو الملفات المحلية أو
الاستضافة الذاتية في تدفق واحد. أما مسارات المكوّنات الإضافية فمخصصة
للمضيفين الذين لديهم نظام مكوّنات إضافية/سوق من الدرجة الأولى، وتستخدم Plans
المستضاف افتراضيًا.

### مسار المهارة العام (أي مضيف MCP) {#universal}

يعمل مع أي مضيف — Claude Code، وCodex، وCursor، وCline، وGoose، وتطبيقات
ChatGPT المخصصة لـ MCP، وClaude Cowork، وأي شيء آخر متوافق مع MCP. تقوم
Agent-Native CLI بتثبيت مهارات Plan، وتسجيل موصل Plan MCP المستضاف، **وتشغيل
المصادقة للعميل (العملاء) المحليين المحددين في الخطوة نفسها**، حتى لا يصطدم
أول استدعاء للأداة بجدار OAuth:

```bash
npx @agent-native/core@latest skills add visual-plan
```

يثبّت هذا `visual-plan` بالإضافة إلى مهارتَي `visual-recap` و`visualize-repo`
المصاحبتين، ثم يسجّل موصل `plan`، ثم يشغّل المصادقة (مطالبة OAuth للمشاركة
المستضافة/المدعومة بحساب). الخيارات المفيدة:

- `--client codex|claude-code|claude-code-cli|cowork|all` — أي الوكلاء المحليين تُكتَب تهيئة MCP لهم (الافتراضي `all`).
- `--no-connect` — سجّل الموصل دون مصادقة؛ شغّل `npx @agent-native/core@latest connect https://plan.agent-native.com --client all` لاحقًا، أو اختر `--client` أضيق.
- `--mode hosted|local-files|self-hosted` — اختر المشاركة المستضافة، أو ملفات MDX المحلية بالكامل، أو تطبيق Plan الخاص بك.
- `--mcp-url <url>` — وجّه الموصل إلى مصدر مخصص (نفق ngrok، أو خادم تطوير محلي، أو نشر مستضاف ذاتيًا) بدلاً من الافتراضي المستضاف.
- `--with-github-action` — اكتب أيضًا إجراء GitHub الخاص بالملخص المرئي لطلبات السحب (راجع [الملخص المرئي لطلبات السحب](/docs/pr-visual-recap)).

تعرض عمليات التثبيت التفاعلية أيضًا إجراء الملخص المرئي لطلبات السحب عندما لا
يوجد سير عمل بعد. وافق لإضافته أثناء إعداد المهارة، أو شغّل الأمر أعلاه لاحقًا
مع `--with-github-action`. بعد كتابة سير العمل، شغّل:

```bash
npx @agent-native/core@latest recap setup
npx @agent-native/core@latest recap doctor
```

يهيّئ `recap setup` أسرار ومتغيرات إجراء GitHub حيثما أمكن، ويتحقق
`recap doctor` من سير العمل، ورمز النشر المحلي، والوصول إلى مستودع GitHub،
وتهيئة Actions المطلوبة. بعد انتهاء التثبيت، أعد تشغيل عميل الوكيل أو أعد
تحميله حتى تُحمَّل المهارات والأدوات الجديدة، ثم شغّل `/visual-plan`.

> ملاحظة: يثبّت الأمر المجرد
> `npx skills@latest add BuilderIO/agent-native --skill visual-plan`
> (Vercel/Skills CLI المفتوح) **التعليمات فقط** — ولا يسجّل موصل MCP. استخدم
> Agent-Native CLI أعلاه عندما تريد توصيل الموصل أيضًا.

### Claude Code (مكوّن إضافي) {#claude-code}

مستودع `BuilderIO/agent-native` العام هو في حد ذاته سوق مكوّنات إضافية لـ
Claude Code، لذا تضيفه مباشرة — دون خطوة بناء. داخل Claude Code:

```text
/plugin marketplace add BuilderIO/agent-native
/plugin install agent-native-visual-plans@agent-native-apps
/reload-plugins
/mcp        # authenticate the Plan connector (one OAuth approval)
```

يضيف `/plugin install` مهارات Plan وتهيئة MCP **قائمة على URL فقط** (لا أسرار
في الحزمة)؛ ويكمل `/mcp` ← **Authenticate** مصافحة OAuth. استخدم مسار الـ CLI
العام بدلاً من ذلك عندما تريد وضع الملفات المحلية أو الاستضافة الذاتية.

> يُسمَّى كتالوج السوق `agent-native-apps` ومكوّن Plan الإضافي هو
> `agent-native-visual-plans`، لذا فإن هدف التثبيت هو دائمًا
> `agent-native-visual-plans@agent-native-apps`.

### Codex (مكوّن إضافي) {#codex}

المستودع نفسه هو سوق مكوّنات إضافية لـ Codex. أضِفه، وثبِّت المكوّن الإضافي،
ثم صادق على الموصل:

```bash
codex plugin marketplace add BuilderIO/agent-native
codex plugin add agent-native-visual-plans@agent-native-apps
codex mcp login plan   # OAuth in the browser
```

بعد التثبيت، **ابدأ محادثة Codex جديدة** حتى تُحمَّل المهارات وأدوات MCP في
الجلسة. يشحن المكوّن الإضافي موصلاً قائمًا على URL فقط
(`[mcp_servers.plan]` ← `https://plan.agent-native.com/mcp`)؛ ويشغّل
`codex mcp login plan` تدفق OAuth. يعمل مسار الـ CLI العام أعلاه أيضًا مع
Codex (`npx @agent-native/core@latest skills add visual-plan --client codex`)
إذا كنت تفضّل أمرًا واحدًا يثبّت ويصادق معًا، أو عندما تريد وضع الملفات
المحلية أو الاستضافة الذاتية.

<Callout tone="info">

**عمليات التثبيت الأقدم:** إذا كان التكوين لديك لا يزال يحتوي على إدخال
`agent-native-plans` يشير إلى الـ URL نفسه، فإن تشغيل
`npx -y @agent-native/core@latest reconnect https://plan.agent-native.com --client codex`
لـ Codex، أو الأمر نفسه مع `--client` المستهدف لديك، يوحّده إلى الاسم
المتعارف عليه `plan`.

</Callout>

## التحديثات {#updates}

تحدّث مسارات المكوّنات الإضافية نفسها تلقائيًا — فلا تحتاج إلى إعادة تعبئة
السوق أو إعادة إضافته لتغييرات المهارات الروتينية:

- **Claude Code** — يضبط إدخال السوق `autoUpdate: true` ويستخدم المكوّن الإضافي ترقيمًا بإصدارات commit-SHA، لذا يسحب Claude Code الإصدارات الجديدة من المستودع عند بدء التشغيل؛ شغّل `/reload-plugins` للتفعيل. تصل كل دفعة (push) إلى الفرع الافتراضي للمستودع إلى المستخدمين المثبِّتين تلقائيًا.
- **Codex** — يضمّن `version` الخاص بالمكوّن الإضافي تجزئة (hash) لمحتوى المهارات المجمَّعة ونقطة نهاية MCP (مثلاً `1.0.0+codex.<hash>`)، لذا يؤدي أي تغيير في المهارة أو نقطة النهاية إلى إصدار جديد. تعيد الترقية التلقائية عند بدء تشغيل Codex تثبيت أسواق git المهيَّأة من تلقاء نفسها؛ فقط **ابدأ محادثة جديدة** لالتقاط التغيير. لا حاجة إلى `codex plugin marketplace upgrade` يدويًا للتحديثات الروتينية.
- **مسار الـ CLI العام** — شغّل `npx @agent-native/core@latest skills status visual-plan` للتحقق من مجلدات المهارات المنسوخة، أو `npx @agent-native/core@latest skills update visual-plan` لتحديثها في مكانها. لا تزال إعادة تشغيل `skills add visual-plan` تعمل عندما تريد أيضًا إعادة تسجيل/مصادقة الموصل. يسحب `@latest` دائمًا المهارات الحالية من حزمة `@agent-native/core` المنشورة.

يشير الموصل إلى تطبيق **مستضاف**، لذا فإن إجراءات (actions) تطبيق Plan وسطح
الأدوات المباشر يعكسان دائمًا الإصدار المنشور بغض النظر عن وقت التثبيت؛ فقط
تعليمات المهارات المجمَّعة هي التي تتبع آليات التحديث أعلاه.

<Callout tone="info">

**للمشرفين:** يُنشأ حزمة السوق (`.claude-plugin/`، و`.agents/plugins/`) من
مهارات Plan المرجعية بواسطة `pnpm sync:plan-marketplace` ويُتحقَّق منها في CI
بواسطة `pnpm guard:plan-marketplace`، لذا تتطابق السوق المنشورة دائمًا مع
المهارات المرجعية. عدّل المهارة، وشغّل `pnpm sync:plan-marketplace`، ثم قم
بالالتزام (commit).

</Callout>

## هل تحتاج إلى تقديم أي شيء؟ {#submission}

**لا حاجة إلى أي تقديم أو مراجعة لتوزيع هذا أو تثبيته.**
`BuilderIO/agent-native` سوق git عام ومستضاف ذاتيًا، لذا يضيفه المستخدمون
مباشرة بالأوامر أعلاه على **كل من Claude Code وCodex** — دون طلب أو موافقة.
لا يحتاج مسار الـ CLI العام إلى سوق على الإطلاق.

قابلية اكتشاف اختيارية، إذا أردت إدراجًا عامًا:

- لدى **Claude Code** سوق مجتمعي يمكنك _اختياريًا_ التقديم إليه للإدراج (تقديم بالإضافة إلى مراجعة آلية). أما السوق الرسمي المنسَّق من قِبل Anthropic فيُدرَج وفق تقدير Anthropic — ولا يوجد تطبيق مفتوح للخدمة الذاتية. لا حاجة إلى أيٍّ منهما لاستخدام أوامر التثبيت أعلاه.
- لدى **Codex** كتالوج مكوّنات إضافية منسَّق من قِبل OpenAI (قائمة سماح مغلقة، تُشكَّل عبر شراكة وليست تقديمًا للخدمة الذاتية). لا تحتاج أسواق git المستضافة ذاتيًا ومسار الـ CLI إلى أي تقديم للعمل.

باختصار: اشحنه كسوق git عام/مستضاف ذاتيًا ليثبّته المستخدمون مباشرة؛ وقدِّمه
إلى كتالوج منسَّق فقط إذا أردت إدراجه للاكتشاف.

## المكوّن الإضافي مقابل المهارة {#plugin-vs-skill}

**المهارة** هي ملف تعليمات `SKILL.md` واحد يقرأه الوكيل عندما تتطابق مهمة
معه. **المكوّن الإضافي** (مكوّن سوق Claude Code الإضافي أو مكوّن Codex
الإضافي) هو حزمة تضم مهارة واحدة أو أكثر **بالإضافة إلى** موصل MCP وبيانات
وصفية، بحيث يمكن للمضيف تثبيت كل شيء في خطوة واحدة.

تحت الغطاء، تُنتَج المسارات الثلاثة جميعها من المصدر نفسه بواسطة CLI الخاص
بـ `npx @agent-native/core@latest app-skill`: يبني `app-skill pack` محوّلات
السوق/المكوّنات الإضافية، و`skills add` هو المثبِّت السهل بخطوة واحدة الذي
يسجّل موصل MCP ويصادق عليه أيضًا. راجع [دليل المهارات](/docs/skills-guide)
للاطلاع على تنسيق بيان app-skill، و[الوكلاء الخارجيون](/docs/external-agents)
لتوصيل أي مضيف MCP وتدفق `npx @agent-native/core@latest connect`.
