# Developer Guide

This page is for anyone customizing the Clips template or extending it: the quick start, every action, the data model, the route surface, and how to add to it. See [Clips](/docs/template-clips) for what the app does.

## Quick start

<Steps>

### Create the app

```bash
npx @agent-native/core@latest create my-clips --standalone --template clips
cd my-clips
pnpm install
```

This needs [Node.js](https://nodejs.org) 22.22 or later and [pnpm](https://pnpm.io) installed first. See [Getting started](/docs/getting-started) if you haven't installed either yet, or don't have an LLM connection (Builder.io, an Anthropic/OpenAI key, or local Ollama) set up.

### Start the dev server

```bash
pnpm dev
```

The app opens automatically in your browser. Recording works without any extra setup, since the browser or desktop app captures locally. You'll only hit an error on an action that needs file storage or AI credits before either is configured.

</Steps>

<Callout tone="info">

Recording, transcription, and AI titles/summaries need file storage and AI credits configured before they'll work end to end. Connect Builder.io from **Settings** for both at once (its free tier includes managed AI credits), or connect S3-compatible storage separately and bring your own Groq key for transcription. See [Transcription and AI metadata](/docs/template-clips-features#transcription-and-ai-metadata).

</Callout>

## Action inventory

Every operation is a TypeScript file in `templates/clips/actions/`, auto-mounted at `POST /_agent-native/actions/:name`.

### Library & recordings

| Action                                                                                    | What it does                                             |
| ----------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| `list-recordings`, `search-recordings`                                                    | Library, shared-with-me, trash, and space-scoped listing |
| `create-recording`, `finalize-recording`                                                  | Create the row; finish the upload                        |
| `import-loom-recording`                                                                   | Import a Loom video or a direct MP4/WebM URL             |
| `update-recording`                                                                        | Title, description, password, expiry, visibility         |
| `move-recording`                                                                          | Move one or several recordings to a folder or root       |
| `archive-recording`, `trash-recording`, `restore-recording`, `delete-recording-permanent` | Lifecycle: hide, soft-delete, undo, or delete forever    |
| `reprocess-recording`                                                                     | Repair unseekable or frozen media                        |
| `generate-filmstrip`                                                                      | Editor timeline frame sprite                             |
| `tag-recording`, `set-thumbnail`                                                          | Tagging and a manually chosen thumbnail frame            |

### Folders & spaces

| Action                                            | What it does                                          |
| ------------------------------------------------- | ----------------------------------------------------- |
| `create-folder`, `rename-folder`, `delete-folder` | Nested folders; deleting one moves its contents up    |
| `create-space`, `rename-space`, `delete-space`    | Org-scoped, topic-based recording containers          |
| `add-recording-to-space`                          | Add or remove a recording from a space (many-to-many) |
| `add-space-member`, `remove-space-member`         | Space-level viewer, contributor, and admin roles      |

### Editing

| Action                                   | What it does                                                |
| ---------------------------------------- | ----------------------------------------------------------- |
| `trim-recording`, `split-recording`      | Layer a cut instruction; never touches the source media     |
| `remove-silences`, `remove-filler-words` | Agent-executed: reads the transcript, applies trims for you |
| `stitch-recordings`                      | Combine several recordings into one, in order               |
| `undo-edit`, `clear-edits`               | Remove the most recent edit, or reset to the original       |

### Transcription & AI metadata

| Action                                                                          | What it does                                      |
| ------------------------------------------------------------------------------- | ------------------------------------------------- |
| `request-transcript`, `cleanup-transcript`                                      | Transcribe; `force`/`regenerate` for a fresh pass |
| `regenerate-title`, `regenerate-summary`, `regenerate-chapters`, `set-chapters` | AI metadata, or set chapters manually             |
| `get-builder-credit-status`                                                     | Whether Builder.io AI credits are paused          |

| `list-comments`, `list-recording-mention-members`                                        | Read comments; look up who can be @mentioned |

### Screen Memory (Rewind)

## Data model

Defined in `templates/clips/server/db/schema.ts`.

<Callout tone="warning">

Team, member, and invitation rows live in the framework's own `organizations`, `org_members`, and `org_invitations` tables, not a Clips-specific one. `organization_settings` is Clips' own sidecar: brand color, logo, and default visibility, one row per organization. An older `workspaces`/`workspace_members` pair still exists only so a one-time startup migration can backfill the framework tables on an existing deployment. Don't build new features against them.

</Callout>

## An action walked through

`create-recording-agent-link` shows patterns worth reusing in any action that mints a scoped credential: checking the resource's real state before handing anything out, delegating the actual token minting to a shared framework helper instead of rolling your own, and deriving every URL a caller needs from that one grant.

  id="doc-block-clips-agent-link"
  title="Minting a scoped agent-access link"

    'import { defineAction } from "@agent-native/core/action";\nimport {\n  buildAgentAccessUrl,\n  createScopedAgentAccessGrant,\n  getRequestContext,\n  getRequestUserEmail,\n} from "@agent-native/core/server";\nimport { ForbiddenError, resolveAccess } from "@agent-native/core/sharing";\nimport { z } from "zod";\n\nimport {\n  CLIPS_AGENT_ACCESS_TTL_SECONDS,\n  getServerAppBasePath,\n} from "../server/lib/public-agent-context.js";\nimport {\n  buildAgentApiUrls,\n  CLIP_AGENT_ACCESS_TOKEN_PREFIX,\n} from "../shared/agent-context.js";\nimport { BUG_REPORT_AGENT_ACCESS_TTL_SECONDS } from "../shared/bug-report.js";\n\nfunction appOrigin(): string {\n  const origin =\n    getRequestContext()?.requestOrigin ||\n    process.env.APP_URL ||\n    process.env.BETTER_AUTH_URL ||\n    "http://localhost:3000";\n  try {\n    return new URL(origin).origin;\n  } catch {\n    return "http://localhost:3000";\n  }\n}\n\nexport default defineAction({\n  description:\n    "Create a temporary private agent-readable link for one Clips recording. The URL is scoped to that recording and expires after two hours.",\n  schema: z.object({\n    recordingId: z.string().describe("Recording ID"),\n    agentLabel: z\n      .string()\n      .trim()\n      .min(1)\n      .max(60)\n      .optional()\n      .describe(\n        "Name of the agent that will read this link (e.g. \'Fusion\', \'Claude Code\'). Recorded against every read the link produces, so the owner sees a name instead of an unidentified agent.",\n      ),\n    ttlSeconds: z\n      .number()\n      .int()\n      .positive()\n      .max(BUG_REPORT_AGENT_ACCESS_TTL_SECONDS)\n      .optional()\n      .describe(\n        "Optional scoped-link lifetime in seconds, capped at seven days. Defaults to two hours.",\n      ),\n  }),\n  readOnly: true,\n  run: async (args) => {\n    const access = await resolveAccess("recording", args.recordingId);\n    if (!access) {\n      throw new ForbiddenError(`No access to recording ${args.recordingId}`);\n    }\n\n    const recording = access.resource as {\n      id: string;\n      archivedAt?: string | null;\n      trashedAt?: string | null;\n    };\n    if (recording.archivedAt || recording.trashedAt) {\n      throw new ForbiddenError(\n        `Recording ${args.recordingId} is not shareable`,\n      );\n    }\n\n    const grant = createScopedAgentAccessGrant({\n      resourceKind: CLIP_AGENT_ACCESS_TOKEN_PREFIX,\n      resourceId: recording.id,\n      viewerEmail: getRequestUserEmail() || undefined,\n      agentLabel: args.agentLabel,\n      ttlSeconds: args.ttlSeconds ?? CLIPS_AGENT_ACCESS_TTL_SECONDS,\n    });\n    const origin = appOrigin();\n    const basePath = getServerAppBasePath();\n    const pageUrl = buildAgentAccessUrl({\n      path: `/share/${encodeURIComponent(recording.id)}`,\n      origin,\n      basePath,\n      token: grant.token,\n    });\n    const api = buildAgentApiUrls(recording.id, {\n      origin,\n      basePath,\n      token: grant.token,\n    });\n\n    return {\n      recordingId: recording.id,\n      url: pageUrl,\n      contextUrl: api.contextUrl,\n      expiresAt: grant.expiresAt,\n      ttlSeconds: grant.ttlSeconds,\n    };\n  },\n});\n'

## Customizing it

Every part of the app is editable source. Start here:

- `templates/clips/actions/` — add a new file with `defineAction` to expose new capability to both the agent and the frontend.
- `templates/clips/app/routes/` — the UI, listed above.
- `templates/clips/server/db/schema.ts` — add columns or tables with Drizzle. Keep the schema PostgreSQL-compatible so the template runs with local PGlite and hosted Postgres.
- `templates/clips/server/lib/` — provider integrations: `google-calendar-client.ts`, `s3-upload-provider.ts`, `slack-oauth.ts`, `video-remux.ts`, `video-filmstrip-sprite.ts`.
- `templates/clips/AGENTS.md` — agent instructions. Update this when you teach the agent new capabilities or conventions.
- `templates/clips/.agents/skills/` — detailed patterns the agent follows. Relevant skills: `recording`, `ai-video-tools`, `video-editing`, `video-sharing`, `screen-memory`.
- `templates/clips/shared/api.ts` — the shared TypeScript types used by both the server and the client.
- `templates/clips/desktop/` and `templates/clips/chrome-extension/` — separate packages for the native capture surfaces, each with their own `package.json` and build.

If you add a feature, remember to update all four areas: UI, action, skill or AGENTS.md entry, and any application state the agent needs to see. That is what keeps the agent and the UI in parity.
