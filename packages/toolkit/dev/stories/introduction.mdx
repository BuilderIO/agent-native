# Agent-Native design system

One system for every Agent-Native app: tokens and component styles in `@agent-native/design-system`, components in `@agent-native/toolkit`. Behavior comes from [Base UI](https://base-ui.com/react/components). The props and their styling follow [Radix Themes](https://www.radix-ui.com/themes/docs/overview/getting-started), drawn on our own scale and tokens.

## How it is organized

- **Foundations** are the tokens: color, type, space, sizing, radius, elevation, motion, and the app themes built from them.
- **Components** are single controls and elements. Each has a page with its props, sizes, variants and states.
- **Patterns** compose components into layouts: the app shell, the sidebar, the page header, settings.
- **Migration status** counts, per app, the files that still use an older source for each component.

## Names

A component takes Base UI's name wherever Base UI has it: Menu, Preview Card, Input, Meter, Toast. Where Base UI has none, it takes Radix Themes' name: Kbd, Callout, Text Area, Segmented Control, Icon Button.

## Props

Every component speaks the same five props, as Radix Themes names them. A component supports a subset of each list, and none adds its own spelling of one.

| Prop           | Values                                                   |                                                                                                    |
| -------------- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `variant`      | `solid`, `soft`, `surface`, `outline`, `ghost`           | How the color applies, from the strongest fill to none.                                            |
| `color`        | `accent`, `gray`, `danger`, `warning`, `success`, `info` | Which scale it draws from. Unset, it inherits the nearest one, and the theme's accent at the root. |
| `size`         | `"1"` to `"4"`                                           | Control heights of 16, 20, 24 and 32px. Text components use the type scale's `"1"` to `"9"`.       |
| `radius`       | `none`, `small`, `medium`, `large`, `full`               | Overrides the theme's corners for one component.                                                   |
| `highContrast` | boolean                                                  | Uses the scale's darkest steps.                                                                    |

The props are defined once, in the catalog. The components' types, these pages' controls, the agent manifest and the Figma parity check all read those definitions, so they can't drift apart.

## Color

Each scale has 12 steps, as in Radix Colors. `data-color` on any element binds that element's `--accent-*` steps to a scale, and a component reads only those, so `color="danger"` needs no rule of its own. Where Radix's step 9 or step 11 falls under WCAG AA at our 12px text, each palette picks the nearest step that passes, as `--accent-solid` and `--accent-text`.

Each app theme generates its scales from its own colors, so a component draws that app's palette wherever its theme applies.

## Using a component

```tsx
import { Button } from "@agent-native/toolkit/ui/base-ui/button";

<Button variant="soft" color="gray" size="sm">
  Cancel
</Button>;
```

Component styles are plain CSS, one file per component, in `@agent-native/design-system/styles.css`. Tailwind is for an app's own layout and chrome, never inside a component.
